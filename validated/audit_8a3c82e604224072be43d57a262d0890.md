Audit Report

## Title
Staking-async marks era reward page as claimed before payout succeeds, permanently losing staker/nominator rewards on pot-transfer failure - (File: substrate/frame/staking-async/src/pallet/impls.rs)

## Summary
`do_payout_stakers_by_page` calls `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` before any currency transfer is attempted. The subsequent payout via `make_payout_from_provider` (non-minting mode) can fail the actual transfer, but the failure is only logged and swallowed (`return None`), while the extrinsic still returns `Ok`, leaving the claimed-flag permanently set with no reward ever delivered.

## Finding Description
The claimed-page flag is set unconditionally based only on era/page bounds and reward-point validation, prior to any transfer: [1](#0-0) 

Mode selection then dispatches to either the transfer-based or mint-based payout path: [2](#0-1) 

In non-minting mode, `make_payout_from_provider` performs a real transfer out of the era-specific pot account; on failure it logs the error and returns `None` without propagating any error to the caller: [3](#0-2) 

The era pot itself is populated by `snapshot_era_rewards`, which has the identical fail-silent pattern — if the transfer from the general pot to the era-specific pot fails, the allocation is simply zeroed and logged rather than blocking or retrying: [4](#0-3) 

Since `set_rewards_as_claimed` runs unconditionally before the transfer attempt, and the transfer's failure path never surfaces an error back to `do_payout_stakers_by_page` (which still returns `Ok(...)`), a stash whose era-pot transfer fails receives zero funds while `ClaimedRewards` storage records the page as paid. Any retry against the same era/page will fail the earlier `is_rewards_claimed` guard, making the loss permanent rather than merely delayed.

## Impact Explanation
This matches the "duplicate settlement or payout" / "permanent user-fund lock" impact category: a validator's and its nominators' entire era reward allocation for a page can be permanently lost with no error surfaced anywhere except a log line, because claim-state bookkeeping (`ClaimedRewards`) is updated unconditionally regardless of whether the transfer actually succeeded.

## Likelihood Explanation
Triggering requires the era-specific reward pot to be underfunded or the transfer at payout time to fail — a state condition reachable through legitimate `Preservation::Preserve`/`Preservation::Expendable` interactions with existential deposits, partial funding from a prior `snapshot_era_rewards` failure, or `PotAccountProvider` misconfiguration. No malicious peer, validator, or privileged actor is required; it is reachable via the ordinary public `payout_stakers`/`payout_stakers_by_page` extrinsics under legitimate era-boundary and reward-provider conditions.

## Recommendation
Defer the call to `Eras::<T>::set_rewards_as_claimed` until after `payout_from_provider`/`payout_legacy_mint` confirm the transfer(s) succeeded, or roll back the claimed marker and return an explicit error (allowing retry) when the underlying transfer fails, instead of silently logging and returning `None` while the extrinsic exits `Ok`.

## Proof of Concept
1. Configure `pallet-staking-async` with `DisableMinting = true` (non-minting mode) and a `PotAccountProvider`/`Currency` setup where the era-specific pot's reducible balance can legitimately fall short of the computed payout amount (e.g., via a partial `snapshot_era_rewards` transfer failure or ED/`Preservation` interaction).
2. Advance to an era boundary; `snapshot_era_rewards` logs a transfer failure and allocates less than the full amount to the era pot, with no on-chain error raised.
3. Call `payout_stakers`/`payout_stakers_by_page` for the affected validator/era/page: `set_rewards_as_claimed` executes at `impls.rs:386` before the transfer runs; `make_payout_from_provider` then fails the transfer, logs the error, returns `None`, and the extrinsic still returns `Ok`.
4. Re-invoke `payout_stakers_by_page` for the same era/page: it now returns `Error::<T>::AlreadyClaimed`, confirming the reward is permanently unclaimable despite never having been paid.
