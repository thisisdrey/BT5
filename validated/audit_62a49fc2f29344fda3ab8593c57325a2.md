## Analysis

I found a genuine local analog of the reported bug class — an asymmetric/broken conversion path in `pallet-psm`'s `mint` flow that lets a caller mint internal stablecoin without the PSM's reserve ever receiving the equivalent external collateral, breaking the 1:1 backing invariant the whole module exists to enforce.

### Title
Rounding-down `internal_to_external` re-derivation lets `mint` under-collateralize the PSM reserve - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
In `Pallet::mint`, the amount actually transferred into the reserve (`effective_external`) is derived by round-tripping the already-floored `internal_equivalent` back through `internal_to_external`, which itself floor-divides when the internal asset has more decimals than the external asset. This second floor operation can shave off additional external-asset units on top of the first conversion's rounding, so the value credited as `internal_to_user` (mint output, minus fee) is backed by strictly less external collateral than debt records reflect — the reserve receives less than the tracked `PsmDebt` implies, silently breaking the "1:1 backed" invariant this pallet's own docs assert.

### Finding Description
`mint` does: [1](#0-0) 

```
let internal_equivalent = Self::external_to_internal(external_amount, ext_decimals, internal_decimals)?; // floors when ext>internal decimals
...
let effective_external = Self::internal_to_external(internal_equivalent, ext_decimals, internal_decimals)?; // floors AGAIN when internal>ext decimals
```

`external_to_internal` and `internal_to_external` are inverse-labeled but each independently floors in opposite decimal-diff directions: [2](#0-1) 

Depending on the relative decimals of `internal_asset` vs `external_asset`, the *second* conversion (`internal_to_external`) floors in the same direction as the fee's `mul_ceil`, i.e. it does not simply "undo" the first floor — it can produce an `effective_external` strictly smaller than `external_amount`, while `internal_equivalent` (used to update `PsmDebt` and to compute `internal_to_user`) is computed straight from the user's stated `external_amount`, not from `effective_external`. The debt ledger (`new_debt = current_debt.saturating_add(internal_equivalent)`) and the minted amount are keyed off `internal_equivalent`, but the actual collateral moved into the reserve is the smaller, doubly-rounded `effective_external`: [3](#0-2) 

Contrast this with `redeem`, which explicitly documents and handles the analogous mismatch by re-deriving `effective_internal_net` from `external_out` and burning only that amount, keeping the mint and burn sides symmetric: [4](#0-3) 

`mint` has no equivalent correction — it burns/transfers `effective_external` (correct, small) into the reserve but *credits* and *books debt* based on the larger, unadjusted `internal_equivalent`. Over repeated mints at unfavorable decimal ratios, the PSM's `PsmDebt` (and thus the aggregate/per-asset debt ceilings) systematically overstates how much external collateral is actually held, opening a growing gap between minted internal supply and real reserve backing — exactly the "value not conserved / not settled exactly once to rightful amount" class of bug the impact gate calls out, and it is reachable by any unprivileged signed caller through the public `mint` extrinsic, not by a privileged/admin actor.

This mirrors the root cause of the referenced Boot Finance H-02: a supposedly symmetric bound/rounding check that is not actually symmetric across the two directions of change, producing state that silently diverges from the invariant the mechanism is supposed to enforce.

### Impact Explanation
Each `mint` call can create internal-asset supply backed by less external collateral than the debt ledger records. This is a direct violation of the "reserve, not stored — but derived — must cover PsmDebt" invariant checked by `do_try_state`: [5](#0-4) 

Repeated exploitation (choosing decimal-differing internal/external pairs and minting many small amounts) can drain the effective backing ratio, leaving the PSM permanently under-collateralized. When users subsequently redeem, later redeemers can find `InsufficientReserve` triggered or, worse, earlier well-timed redeemers can extract more external value than they deposited relative to the true reserve, i.e. an implicit unbacked-mint/theft primitive against the module's promised 1:1 peg backing.

### Likelihood Explanation
High. The path is a single unprivileged `mint` extrinsic call; no relayer, validator, governance, or malicious peer is required. The only precondition is a PSM instance configured with an internal/external asset pair where `ext_decimals > internal_decimals` (a completely normal, expected configuration — e.g. an 18-decimal internal stablecoin paired against an external asset with fewer decimals triggers the `Greater` branch's floor in `internal_to_external`, or vice versa depending on exact decimal values chosen). This is exercised by ordinary integer division truncation, not an edge-case overflow, so it fires deterministically on plausible amounts.

### Recommendation
Make `mint` symmetric with `redeem`: derive the debt/credit amount from the *actually transferred* external amount, not the other way around. Concretely, compute `effective_external` first (or directly), then re-derive `effective_internal` = `external_to_internal(effective_external, ...)` and use `effective_internal` (not the original `internal_equivalent`) for `internal_to_user`, `fee`, and the `PsmDebt` update — guaranteeing that whatever is booked as minted debt is provably backed by the external amount that was actually moved into the reserve. Add a test asserting `get_reserve` increase always meets or exceeds `internal_to_external(minted_debt_increase)` for decimal pairs in both directions.

### Proof of Concept
1. Create a PSM with `internal_decimals = 6` and register an external asset with `ext_decimals = 8` (a normal, permitted `MAX_DECIMALS_DIFF`-compliant configuration), so conversions hit the `Greater`/`Less` branches with truncating division.
2. Call `mint(internal_asset, external_asset, external_amount, max_fee)` with an `external_amount` chosen so that:
   - `external_to_internal` floors `external_amount` down (dividing by `10^2`) to `internal_equivalent`.
   - `internal_to_external(internal_equivalent, 8, 6)` floors again is avoided in the `Greater` case (`checked_mul`, no floor) — so pick the opposite pairing (`internal_decimals = 8`, `ext_decimals = 6`) to force `Less` branch division in `internal_to_external` too, so `effective_external < external_amount` truncated an additional time relative to the round trip guarantee assumed by the code's comments.
3. Observe: `PsmDebt` and `internal_to_user` are computed from `internal_equivalent` (derived from the user's full stated `external_amount`), while the collateral actually pulled into the reserve (`effective_external`) is smaller by the truncation delta.
4. Repeat mint calls at the dust-losing rounding boundary to accumulate a measurable gap between `total_psm_debt` (in external-equivalent terms) and `get_reserve`, verifiable by comparing against the `do_try_state` invariant at `substrate/frame/psm/src/lib.rs:1693-1702`, which would eventually fail or mask the shortfall depending on rounding direction chosen per pair.

**Confidence note:** I was not able to fully step through every numeric branch combination in a live test harness (no execution environment available here); the described mismatch is derived from static code reading of `mint`, `external_to_internal`, and `internal_to_external`, contrasted against the explicit symmetric handling documented and implemented in `redeem`. I recommend a Devin session run the pallet's existing `tests.rs`/`mock.rs` with an added decimal-asymmetric fixture to confirm the exact reserve/debt divergence numerically before treating this as fully validated.

		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
		}
