### Title
`AttachmentsDownloader` stores attacker-served attachment content in `AtlasDB` under an unvalidated hash, breaking the confirmed-`AttachmentInstance` binding - ([File: stackslib/src/net/atlas/download.rs])

### Summary
When the P2P attachment downloader fetches an attachment from a peer to satisfy a queued `AttachmentInstance.content_hash`, it never checks that the returned bytes actually hash to the requested `content_hash` before persisting them. A malicious peer can respond to a `GET /v2/attachments/<hash>` fetch with arbitrary, unrelated content, and the node will unconditionally call `AtlasDB::insert_instantiated_attachment`, writing a "validated" (`was_instantiated = 1`) row keyed by the *attacker's* content hash even though zero confirmed `AttachmentInstance` rows reference it.

### Finding Description
The invariant the question is auditing is: every row in the `attachments` table with `was_instantiated = 1` should correspond to the `content_hash` of some queued/confirmed `AttachmentInstance` recorded from an on-chain contract event [1](#0-0) .

The download flow is:
1. `AttachmentsBatchStateContext::get_prioritized_attachments_requests` builds an `AttachmentRequest{content_hash, sources, ...}` for a specific missing `content_hash` taken from `attachments_batch.attachments_instances` [2](#0-1) .
2. The response is decoded and inserted into `self.attachments: HashSet<Attachment>` with **no comparison** between `response.attachment.hash()` and `request.content_hash`: [3](#0-2) 
3. In `AttachmentsDownloader::run`, every attachment drained from that set is looked up by its *own* (attacker-controlled) hash, and regardless of whether any matching confirmed instance exists, it is unconditionally persisted: [4](#0-3) 
4. `AtlasDB::insert_instantiated_attachment` performs the raw `INSERT OR REPLACE` keyed by `attachment.hash()` with no check that this hash matches any row in `attachment_instances`: [5](#0-4) 

Contrast this with `insert_uninstantiated_attachment`, which is size-bounded and subject to LRU eviction via `max_uninstantiated_attachments`/`evict_k_oldest_uninstantiated_attachments` [6](#0-5) . The "instantiated" (validated) table has **no eviction routine at all** — only `evict_expired_uninstantiated_attachments` and `evict_expired_unresolved_attachment_instances` exist, and neither touches `was_instantiated = 1` rows [7](#0-6) .

The attacker's exact message: respond to the victim's `GET /v2/attachments/<requested_hash>` request (sent because the victim is trying to resolve a real, on-chain-confirmed `AttachmentInstance`) with a `GetAttachmentResponse` whose `attachment.content` is arbitrary bytes not equal to the preimage of `requested_hash`. The response is parsed generically via JSON with no field-level hash check [8](#0-7) , and `decode_atlas_get_attachment` performs no cross-check either [9](#0-8) .

### Impact Explanation
The victim node's `AtlasDB` `attachments` table accumulates permanent, unevictable rows keyed by attacker-chosen hashes that no on-chain name/BNS operation ever committed to. This is a storage-integrity break: the DB now contains data claimed as "validated" (`was_instantiated=1`) that has no corresponding confirmed `AttachmentInstance`, i.e., an attachment/BNS mismatch — data is stored that no canonical block committed. It is repeatable per outstanding `AttachmentInstance` that the victim is trying to resolve, and any peer the victim treats as an "outbound sync peer" data source can do this (no privileged role, no secret required, matches the assumed threat model of a remote peer with only the ability to run its own node and answer HTTP GETs).

### Likelihood Explanation
Preconditions: the victim node must have at least one pending/queued `AttachmentInstance` (routine for any active Atlas-enabled deployment, e.g., BNS name updates) and must select the attacker's peer as one of its outbound-sync/data-url sources — both are ordinary, low-cost conditions requiring no special privilege, secret, or admin role. The attacker only needs to run a normal peer that participates in the P2P network and responds to attachment inventory/attachment HTTP requests, which is explicitly within the assumed unprivileged-attacker capabilities.

### Recommendation
In `AttachmentsBatchStateContext::extend_with_attachments` (or immediately before `insert_instantiated_attachment` is called in `AttachmentsDownloader::run`), verify `attachment.hash() == request.content_hash` (or verify against `attachment_instance.content_hash` before insertion) and discard/penalize the peer on mismatch instead of storing the content. Additionally, add a size/count cap and eviction policy for `was_instantiated = 1` rows analogous to the uninstantiated-attachment eviction logic, so that even validated-looking entries cannot grow the DB unboundedly.

### Proof of Concept
Rust test plan (extends existing `stackslib/src/net/atlas/tests.rs` patterns):
1. Construct an `AtlasDB` and a `AttachmentInstance` with `content_hash = Hash160::from_data(b"real")`, insert via `queue_attachment_instance`.
2. Simulate `AttachmentsBatchStateContext::extend_with_attachments` being fed a `BatchedRequestsResult` whose succeeded response for that `AttachmentRequest{content_hash: Hash160::from_data(b"real"), ..}` contains `GetAttachmentResponse{ attachment: Attachment::new(b"forged".to_vec()) }` (i.e., content whose hash ≠ requested `content_hash`).
3. Call the equivalent of the `run()` store loop: `atlas_db.find_all_attachment_instances(&Attachment::new(b"forged".to_vec()).hash())` (assert it returns empty — no confirmed instance references this hash), then call `atlas_db.insert_instantiated_attachment(&Attachment::new(b"forged".to_vec()))`.
4. Assert: `atlas_db.find_attachment(&Hash160::from_data(b"forged")).unwrap().is_some()` — the DB accepted and stores a standalone attachment under a hash with zero corresponding `AttachmentInstance`, proving the broken equality.

    pub fn get_prioritized_attachments_requests(&self) -> BinaryHeap<AttachmentRequest> {
        let mut queue = BinaryHeap::new();
        let mut enqueued = HashSet::new();
        for ((contract_id, pages, _), peers_responses) in self.inventories.iter() {
            let missing_attachments = match self
                .attachments_batch
                .attachments_instances
                .get(contract_id)
            {
                None => continue,
                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);
            }

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }

    pub fn insert_uninstantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        // Insert the new attachment
        let uninstantiated_attachments = self.count_uninstantiated_attachments()?;
        if uninstantiated_attachments >= self.atlas_config.max_uninstantiated_attachments {
            let to_delete =
                1 + uninstantiated_attachments - self.atlas_config.max_uninstantiated_attachments;
            self.evict_k_oldest_uninstantiated_attachments(to_delete)?;
        }

        let tx = self.tx_begin()?;
        let now = util::get_epoch_time_secs() as i64;
        let res = tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 0, ?)",
            params![
                attachment.hash(),
                attachment.content,
                now,
            ],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }

    pub fn evict_k_oldest_uninstantiated_attachments(&mut self, k: u32) -> Result<(), db_error> {
        let tx = self.tx_begin()?;
        let res = tx.execute(
            "DELETE FROM attachments WHERE hash IN (SELECT hash FROM attachments WHERE was_instantiated = 0 ORDER BY created_at ASC LIMIT ?)",
            params![k],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }

    pub fn evict_expired_uninstantiated_attachments(&mut self) -> Result<(), db_error> {

    pub fn insert_instantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        let now = util::get_epoch_time_secs() as i64;
        let tx = self.tx_begin()?;
        tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 1, ?)",
            params![attachment.hash(), attachment.content, now],
        )?;
        tx.execute(
            "UPDATE attachment_instances SET is_available = 1 WHERE content_hash = ?1 AND status = ?2",
            params![attachment.hash(), AttachmentInstanceStatus::Checked],
        )?;
        tx.commit()?;
        Ok(())
    }
