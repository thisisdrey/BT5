### Title
SyntheticToken mints/burns/transfers never checkpoint RewardsDistributor, so reward accrual ignores balance changes - (contracts/SyntheticToken.sol)

### Summary
The reported Convergence bug is a "reward amount not recomputed when position parameters change" class: a state transition alters what an account should earn, but the reward/checkpoint logic is skipped, so the stale amount is applied. In Metronome, `RewardsDistributor` distributes reward tokens over any `IERC20` registered via `updateTokenSpeed`, and its accounting is only correct if every balance-changing call is preceded by `updateBeforeMintOrBurn`/`updateBeforeTransfer`. `DepositToken` and `DebtToken` enforce this via modifiers (`contracts/DepositToken.sol:124-144`, `contracts/DebtToken.sol:114-121`), but `SyntheticToken` performs `mint`, `burn`, `seize`, `transfer`/`transferFrom` with no such hook. If a `RewardsDistributor` is configured to reward a synthetic token (e.g. MET/OP rewards on msUSD/msETH supply — `deployments/mainnet/MetRewardsDistributor.json` and `deployments/optimism/OpRewardsDistributor.json` exist for exactly this purpose), all synthetic-token balance changes silently bypass the index/accrued checkpoint.

### Finding Description
`RewardsDistributor._updateTokensAccruedOf` computes `tokensDelta = balanceOf(account) * (tokenIndex - accountIndexOf)` (`contracts/RewardsDistributor.sol:217-231`). This formula is only valid when the account's index is synced at every balance change. For `DepositToken`/`DebtToken`, `_mint`, `_burn`, and `_transfer` all carry `updateRewardsBeforeMintOrBurn`/`updateRewardsBeforeTransfer`. `SyntheticToken` has no equivalent calls — searching the contract shows no reference to `IRewardsDistributor` at all. Consequently, an account that mints synths via `DebtToken.issue`, receives them via `flashIssue`/leverage through `SmartFarmingManager`, or transfers them, changes its reward-bearing balance without any checkpoint.

### Impact Explanation
Because `_calculateTokenDelta` multiplies the *current* `balanceOf` by the *entire* index delta since the account's last sync, an attacker who holds 0 synths, lets the index grow, then mints a large position (via `DebtToken.issue` — fully permissionless given collateral) and calls the public `updateBeforeMintOrBurn(synthToken, attacker)` is credited rewards as if the newly minted balance existed for the whole un-synced period. This directly steals unclaimed yield from honest holders — analogous to `increaseLockTime` crediting a full-duration ys multiplier to a partially-extended lock. Conversely, users who burn/transfer before a sync lose accrued rewards on the old balance.

### Likelihood Explanation
Reachability requires only that a `RewardsDistributor`'s `tokens` list includes a `SyntheticToken` — a plausible deployed configuration given dedicated `MetRewardsDistributor`/`OpRewardsDistributor` deployments exist to incentivize synth adoption. All entry points used (`Pool`/`DebtToken.issue`, `SyntheticToken.transfer`, public `updateBeforeMintOrBurn`) are unprivileged. Caveat: I could not confirm from the indexed repo which concrete tokens are registered in each deployed distributor's `tokenSpeeds`; if no distributor tracks a synthetic token, the impact does not materialize.

### Recommendation
Add `updateRewardsBeforeMintOrBurn(account)` / `updateRewardsBeforeTransfer(from, to)` modifiers to `SyntheticToken`'s `mint`, `burn`, `seize`, `transfer`, and `transferFrom`, mirroring `DepositToken`. Alternatively, document and enforce (via `RewardsDistributor._updateTokenSpeed`) that synthetic tokens must never be registered as reward tokens.

### Proof of Concept
Foundry fork sketch (mainnet, assuming `MetRewardsDistributor` tracks `msUSD`):

```solidity
// setup: attacker supplies collateral via DepositToken.deposit to gain issuable USD
// 1. Let reward index accrue for time T while attacker holds 0 msUSD.
vm.warp(block.timestamp + 30 days);
// 2. Attacker mints large msUSD position.
debtToken.issue(amount, attacker); // SyntheticToken.mint: no rewards checkpoint
// 3. Attacker manually syncs (function is permissionless).
rewardsDistributor.updateBeforeMintOrBurn(msUSD, attacker);
// 4. attacker accrued = attackerBalance * fullDeltaIndex — credited for the whole
//    30-day period despite holding the tokens for 0 seconds.
rewardsDistributor.claimRewards(attacker, tokens);
```

Assert that `tokensAccruedOf[attacker]` equals `amount * deltaIndex` rather than ~0, demonstrating theft of yield accrued by other holders.
