### Title
Downloaded attachment content is stored without verifying it matches the requested `content_hash`, letting any peer inject unbounded, uncommitted data into `AtlasDB` - (File: `stackslib/src/net/atlas/download.rs`)

### Summary
`AttachmentsBatchStateContext::extend_with_attachments` accepts a peer's `GetAttachmentResponse` and stores the returned `Attachment` bytes without checking that `response.attachment.hash()` equals the `AttachmentRequest.content_hash` that was actually requested. `AttachmentsDownloader::run` then unconditionally calls `atlasdb.insert_instantiated_attachment(&attachment)` for every attachment returned, regardless of whether any `attachment_instances` row exists for that hash, permanently persisting attacker-chosen bytes under an attacker-chosen hash with `was_instantiated = 1` (a state that is never evicted by `evict_expired_uninstantiated_attachments`).

### Finding Description
The claimed equality — every attachment in `AtlasDB` corresponds to a hash referenced by a confirmed `AttachmentInstance` — is broken.

Request generation is legitimately gated: `AttachmentsBatchStateContext::get_prioritized_attachments_requests` only builds `AttachmentRequest { content_hash, .. }` entries for `content_hash` values pulled from `attachments_batch.attachments_instances`, which originate from real on-chain `AttachmentInstance` rows queued via `AtlasDB::queue_attachment_instance` during block processing [1](#0-0) .

However, once a node sends `GET /v2/attachments/<hash>` to a malicious peer for that legitimate `content_hash`, the response is processed by `extend_with_attachments`, which decodes the response and inserts `response.attachment` into `self.attachments` with **no check that `response.attachment.hash() == request.content_hash`**: [2](#0-1) 

Then in `AttachmentsDownloader::run`, every attachment drained from `context.attachments` is persisted via `insert_instantiated_attachment` unconditionally — the code looks up `find_all_attachment_instances(&attachment.hash())` only to decide what to report as "resolved", but calls `insert_instantiated_attachment` regardless of whether that lookup returned anything: [3](#0-2) 

`insert_instantiated_attachment` writes the row with `was_instantiated = 1` keyed by `attachment.hash()` (computed from the attacker-supplied bytes, not the originally requested hash), and does not enforce `attachments_max_size` or contract membership (those checks live only in `AtlasDB::should_keep_attachment`, which is not called anywhere in this download path): [4](#0-3) [5](#0-4) 

Crucially, `was_instantiated = 1` rows are excluded from both eviction routines, which only delete `was_instantiated = 0` rows: [6](#0-5) 

So the actual exploitable path is worse than the question's literal framing (uninstantiated-attachment cap bypass): a malicious peer, when responding to *any* legitimate attachment-inventory-driven request, can substitute arbitrary bytes with an arbitrary resulting hash that has zero relationship to any `AttachmentInstance`/on-chain commitment, and that data is written straight into the "instantiated" (never-evicted) portion of `AtlasDB`, with no size cap and no expiry.

### Impact Explanation
A single malicious/misbehaving peer that a victim node queries for an attachment (having advertised the hash in a `GetAttachmentsInvResponse`, or simply being one of the `sources` for a real pending request) can, on every completed request cycle, cause the victim to durably write attacker-controlled bytes into its `attachments` table as "instantiated" data. Because eviction never touches `was_instantiated = 1` rows and no max-size/contract check gates this path, this is unbounded, repeatable disk-write amplification driven by a single unprivileged peer with no on-chain action and no admin/secret — this is unauthenticated write to persistent node state, matching the Critical impact bar (storage exhaustion / unauthenticated write to state).

### Likelihood Explanation
Preconditions are low: the attacker only needs to be a normal outbound/inbound peer that the victim's `AttachmentsDownloader` selects as a source for some real, on-chain-driven attachment request (which happens routinely as part of ordinary Atlas/BNS syncing), and then answer `GET /v2/attachments/<hash>` with different bytes than requested. No node secret, no privileged role, no local access, fully remote and repeatable across every batch cycle.

### Recommendation
In `AttachmentsBatchStateContext::extend_with_attachments`, verify `response.attachment.hash() == request.content_hash` before inserting into `self.attachments`; discard/penalize the peer (bump `report.bump_failed_requests()` / mark faulty) on mismatch. In `AttachmentsDownloader::run`, only call `insert_instantiated_attachment` when `find_all_attachment_instances(&attachment.hash())` returns a non-empty result (i.e., only persist attachments that resolve a real, tracked `AttachmentInstance`), and additionally enforce `AtlasDB::should_keep_attachment` (size/contract checks) on this path.

### Proof of Concept
Rust test in `stackslib/src/net/atlas/tests.rs` (or a new test module) plan:
1. Construct an `AttachmentsBatchStateContext` with one real `AttachmentInstance`/`AttachmentRequest` for `content_hash = H1` (as would come from a legitimately queued on-chain instance).
2. Simulate a peer response via `extend_with_attachments` where `response.attachment` contains bytes `B2` whose `hash()` is `H2 != H1` and for which no `attachment_instances` row with `content_hash = H2` exists in `AtlasDB`.
3. Drive `AttachmentsBatchStateMachine` to `Done` and run the `Done` handling block from `AttachmentsDownloader::run` (lines 153-169).
4. Assert that `atlasdb.find_attachment(&H2)` now returns `Some(B2)` with `was_instantiated = 1`, even though `atlasdb.find_all_attachment_instances(&H2)` returns an empty vector — proving persisted content with zero on-chain commitment and no corresponding `attachment_instances` row, and that repeated runs never evict it via `evict_expired_uninstantiated_attachments`/`evict_expired_unresolved_attachment_instances`.

    pub fn get_prioritized_attachments_requests(&self) -> BinaryHeap<AttachmentRequest> {
        let mut queue = BinaryHeap::new();
        let mut enqueued = HashSet::new();
        for ((contract_id, pages, _), peers_responses) in self.inventories.iter() {
            let missing_attachments = match self
                .attachments_batch
                .attachments_instances
                .get(contract_id)
            {
                None => continue,
                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }

    pub fn should_keep_attachment(
        &self,
        contract_id: &QualifiedContractIdentifier,
        attachment: &Attachment,
    ) -> bool {
        if !self.atlas_config.contracts.contains(contract_id) {
            info!(
                "Atlas: will discard posted attachment - {} not in supported contracts",
                contract_id
            );
            return false;
        }
        if attachment.content.len() as u32 > self.atlas_config.attachments_max_size {
            info!("Atlas: will discard posted attachment - attachment too large");
            return false;
        }
        true
    }

    pub fn evict_k_oldest_uninstantiated_attachments(&mut self, k: u32) -> Result<(), db_error> {
        let tx = self.tx_begin()?;
        let res = tx.execute(
            "DELETE FROM attachments WHERE hash IN (SELECT hash FROM attachments WHERE was_instantiated = 0 ORDER BY created_at ASC LIMIT ?)",
            params![k],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }

    pub fn evict_expired_uninstantiated_attachments(&mut self) -> Result<(), db_error> {
        let now = util::get_epoch_time_secs() as i64;
        let cut_off = now - self.atlas_config.uninstantiated_attachments_expire_after as i64;
        let tx = self.tx_begin()?;
        let res = tx.execute(
            "DELETE FROM attachments WHERE was_instantiated = 0 AND created_at < ?",
            params![cut_off],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }

    pub fn insert_instantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        let now = util::get_epoch_time_secs() as i64;
        let tx = self.tx_begin()?;
        tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 1, ?)",
            params![attachment.hash(), attachment.content, now],
        )?;
        tx.execute(
            "UPDATE attachment_instances SET is_available = 1 WHERE content_hash = ?1 AND status = ?2",
            params![attachment.hash(), AttachmentInstanceStatus::Checked],
        )?;
        tx.commit()?;
        Ok(())
    }
