### Title
`SmartFarmingManager.leverage()` checks the minimum deposit before the deposit fee is deducted - (File: contracts/SmartFarmingManager.sol)

### Summary
`SmartFarmingManager.leverage()` treats the pre-deposit collateral amount as the final deposit amount, allowing `depositAmountMin_` to pass while the user ultimately receives fewer deposit tokens after `DepositToken.deposit()` deducts the configured deposit fee. [1](#0-0) [2](#0-1) 

### Finding Description
The `depositAmountMin_` parameter is documented as the minimum final deposit amount, but the slippage check compares it against `_depositAmount` before `depositToken_.deposit()` is executed. [3](#0-2) [1](#0-0) 

`DepositToken.deposit()` calls `quoteDepositOut()` and mints only `_deposited`, while `_fee` is minted to the fee collector. [2](#0-1)  `quoteDepositOut()` calculates the fee as `amount_ * depositFee` and returns `amount_ - fee` as the amount deposited. [4](#0-3) 

Therefore, if `_depositAmount == depositAmountMin_` and `depositFee > 0`, the caller's actual `_deposited` amount is strictly below the requested minimum. [1](#0-0) [5](#0-4) 

### Impact Explanation
A user can receive less collateral exposure than the explicit `depositAmountMin_` bound while still receiving the full newly minted debt from the leverage operation. [6](#0-5)  The shortfall is up to the configured deposit fee, which the protocol allows to be as high as 25%. [7](#0-6) [8](#0-7) 

The final health check only verifies that the resulting position satisfies the protocol collateral factor; it does not enforce the user's requested minimum deposit amount. [9](#0-8) 

### Likelihood Explanation
The function is externally callable by an unprivileged account and is only gated by shutdown, reentrancy, and token-registration checks. [10](#0-9)  The condition is reachable whenever the pool's governor-configured deposit fee is nonzero and the user selects a minimum equal to or slightly above the expected net deposit amount. [8](#0-7) [4](#0-3) 

### Recommendation
Quote the expected net deposit before performing the minimum check, for example by calling `depositToken_.quoteDepositOut(_depositAmount)` and comparing its `_amountToDeposit` return value against `depositAmountMin_`. [4](#0-3)  Alternatively, move the comparison after `depositToken_.deposit()` and compare `depositAmountMin_` against the returned `_deposited`. [1](#0-0) 

### Proof of Concept
The following Hardhat test demonstrates that a minimum of `110` gross collateral units passes, while a 10% deposit fee leaves the user with only `99` deposit tokens.

```solidity
// test/SmartFarmingManager.slippage.t.sol
function testLeverageMinimumCheckedBeforeDepositFee() public {
    uint256 amountIn = 100 ether;
    uint256 leverage = 1.1 ether;
    uint256 depositAmountMin = 110 ether;

    feeProvider.updateDepositFee(0.1 ether); // 10%

    deal(address(met), alice, amountIn);
    vm.startPrank(alice);
    met.approve(address(smartFarmingManager), amountIn);

    (uint256 deposited, ) = smartFarmingManager.leverage(
        met,
        msdMET,
        msUSD,
        amountIn,
        leverage,
        depositAmountMin
    );
    vm.stopPrank();

    // The check uses 110e18 pre-fee collateral.
    // DepositToken mints 110e18 * (1 - 10%) = 99e18.
    assertEq(deposited, 99 ether);
    assertLt(deposited, depositAmountMin);
}
```

The assertion is based on the contract's ordering: `_depositAmount` is checked at line 198, while `depositToken_.deposit()` is not called until line 203. [1](#0-0)

    function quoteDepositOut(uint256 amount_) public view override returns (uint256 _amountToDeposit, uint256 _fee) {
        uint256 _depositFee = pool.feeProvider().depositFee();
        if (_depositFee == 0) {
            return (amount_, _fee);
        }

        _fee = amount_.wadMul(_depositFee);
        _amountToDeposit = amount_ - _fee;
    }
