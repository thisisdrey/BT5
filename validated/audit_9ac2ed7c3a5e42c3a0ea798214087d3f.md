### Title
Integer-rounded EMA can suppress staked stream-load throttling activation while its timestamp keeps advancing - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
`StakedStreamLoadEMA::update_ema` in the QUIC streamer's stake-weighted QoS path computes a fixed-point EMA using integer division, and `update_ema_if_needed` advances `last_update` on every call regardless of whether the EMA value actually changed. If the recent load sampled in each 5 ms window is kept low enough, the EMA update rounds down to zero every interval even though `last_update` is continuously refreshed — structurally the same pattern as the referenced ERC20Rewards bug (`accumulated` stuck at 0 while `lastUpdated` keeps ticking).

For `current_ema == 0`, the updated value is `recent_load * 49 / 1024`, which truncates to `0` whenever `recent_load <= 20` per 5 ms sampling window.

`update_ema_if_needed` unconditionally advances the `last_update` timestamp before calling `update_ema`, independent of whether the EMA actually moved: [2](#0-1) 

`increment_load` is invoked on every staked stream open and drives this update: [3](#0-2) 

`staked_throttling_enabled` — the flag that switches staked connections from the flat `max_staked_load_in_throttling_window` budget to a stake-proportional shared budget — is only set when the EMA crosses `staked_throttling_on_load_threshold` (95% of the per-EMA-interval max): [4](#0-3) [5](#0-4) 

If aggregate staked stream traffic is paced so that no single 5 ms sampling window ever exceeds ~20 streams (while `current_load_ema` is being reset toward 0 in intervening intervals with zero load), `current_load_ema` can be kept pinned at 0 indefinitely — exactly analogous to the reported bug where the accumulator stays constant while the "last updated" state advances.

### Impact Explanation
While `staked_throttling_enabled` is false, every staked connection is granted the full, un-shared `max_staked_load_in_throttling_window` stream budget rather than a stake-proportional share, per `available_load_capacity_in_throttling_duration`: [6](#0-5) 
This is precisely the QoS evasion vector the EMA/threshold mechanism exists to prevent: it is meant to detect sustained aggregate load and switch to a fair, stake-weighted sharing scheme so no small group of staked peers can monopolize QUIC stream/TPU capacity. By pacing stream creation to stay under the per-sampling-window rounding floor, the mechanism that triggers fair-sharing can be kept dormant even while the server is at or near saturation, allowing low-stake connections to continue receiving the same unshared budget as under light load.

### Likelihood Explanation
This requires an attacker with any amount of stake (or several colluding staked peers) to pace stream creation carefully (≤20 streams per 5 ms interval), which is achievable by a moderately sophisticated, unprivileged-relative-to-validator-operators staked client sending transactions over the TPU QUIC path. It does not require any special permission beyond being a staked node establishing a normal QUIC connection to the validator.

### Recommendation
- Avoid resetting/advancing `last_update` in `update_ema_if_needed` when the underlying interval's contribution to `updated_load_ema` rounds to zero and no real progress was made, or increase the fixed-point precision (`STREAM_LOAD_EMA_MULTIPLIER`) so realistic sub-threshold loads are not truncated to zero.
- Consider basing the throttling-enable decision on a windowed sum/count of streams rather than a decaying EMA that can be perpetually reset to zero by pacing traffic just under the per-sample rounding floor.
- Add a floor/carry-over mechanism (similar to `TokenBucket`'s `credit_time_us`) so fractional load is not silently discarded across intervals.

### Proof of Concept
1. Configure `SwQos`/`StakedStreamLoadEMA` with default parameters (`STREAM_LOAD_EMA_INTERVAL_MS = 5`, `STREAM_LOAD_EMA_INTERVAL_COUNT = 40`, `STREAM_LOAD_EMA_MULTIPLIER = 1024`), giving `multiplied_smoothing_factor = 49`.
2. As a staked client, open TPU QUIC streams at a rate of ≤20 streams per 5 ms window (e.g., 4000 streams/sec, well within `max_streams_per_ms` limits), ensuring `load_in_recent_interval` sampled by `update_ema` each interval never exceeds 20.
3. Because `recent_load * 49 / 1024` truncates to 0 for `recent_load <= 20`, `current_load_ema` in `ema_function`/`update_ema` remains `0` across repeated calls (as exercised by the existing unit tests `test_ema_decay_handles_missing_intervals` and `test_staked_throttling_on_off` which show the same integer arithmetic), even though `last_update` is refreshed on each call at `streamer/src/nonblocking/stream_throttle.rs:154`.
4. `staked_throttling_enabled` therefore never transitions to `true`, so `available_load_capacity_in_throttling_duration` keeps returning the full `max_staked_load_in_throttling_window` for every staked peer instead of the stake-proportional share, regardless of how long this pattern is sustained.

    fn ema_function(current_ema: u128, recent_load: u128) -> u128 {
        // Using the EMA multiplier helps in avoiding the floating point math during EMA related calculations
        const STREAM_LOAD_EMA_MULTIPLIER: u128 = 1024;
        let multiplied_smoothing_factor: u128 =
            2 * STREAM_LOAD_EMA_MULTIPLIER / (u128::from(STREAM_LOAD_EMA_INTERVAL_COUNT) + 1);

        // The formula is
        //    updated_ema = recent_load * smoothing_factor + current_ema * (1 - smoothing_factor)
        // To avoid floating point math, we are using STREAM_LOAD_EMA_MULTIPLIER
        //    updated_ema = (recent_load * multiplied_smoothing_factor
        //                   + current_ema * (multiplier - multiplied_smoothing_factor)) / multiplier
        (recent_load * multiplied_smoothing_factor
            + current_ema * (STREAM_LOAD_EMA_MULTIPLIER - multiplied_smoothing_factor))
            / STREAM_LOAD_EMA_MULTIPLIER
    }

    fn update_ema(&self, time_since_last_update_ms: u128) {
        // if time_since_last_update_ms > STREAM_LOAD_EMA_INTERVAL_MS, there might be intervals where ema was not updated.
        // count how many updates (1 + missed intervals) are needed.
        let num_extra_updates =
            time_since_last_update_ms.saturating_sub(1) / u128::from(STREAM_LOAD_EMA_INTERVAL_MS);

        let load_in_recent_interval =
            u128::from(self.load_in_recent_interval.swap(0, Ordering::Relaxed));

        let mut updated_load_ema = Self::ema_function(
            u128::from(self.current_load_ema.load(Ordering::Relaxed)),
            load_in_recent_interval,
        );

        for _ in 0..num_extra_updates {
            updated_load_ema = Self::ema_function(updated_load_ema, 0);
            if updated_load_ema == 0 {
                break;
            }
        }

        let Ok(updated_load_ema) = u64::try_from(updated_load_ema) else {
            error!("Failed to convert EMA {updated_load_ema} to a u64. Not updating the load EMA");
            self.stats
                .stream_load_ema_overflow
                .fetch_add(1, Ordering::Relaxed);
            return;
        };

        if self.staked_throttling_on_load_threshold > 0 {
            self.staked_throttling_enabled.store(
                updated_load_ema >= self.staked_throttling_on_load_threshold,
                Ordering::Relaxed,
            );

    pub(crate) fn update_ema_if_needed(&self) {
        const EMA_DURATION: Duration = Duration::from_millis(STREAM_LOAD_EMA_INTERVAL_MS);
        // Read lock enables multiple connection handlers to run in parallel if interval is not expired
        if Instant::now().duration_since(*self.last_update.read().unwrap()) >= EMA_DURATION {
            let mut last_update_w = self.last_update.write().unwrap();
            // Recheck as some other thread might have updated the ema since this thread tried to acquire the write lock.
            let since_last_update = Instant::now().duration_since(*last_update_w);
            if since_last_update >= EMA_DURATION {
                *last_update_w = Instant::now();
                self.update_ema(since_last_update.as_millis());
            }
        }
    }

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }
