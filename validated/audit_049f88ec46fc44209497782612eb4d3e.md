### Title
Batch vesting operations abort entirely when any single contract is inactive, delaying vesting/reward unlocks for all other contracts in the batch — (`aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vest_many`, `unlock_rewards_many`, and `distribute_many` iterate over a caller-supplied list of vesting contract addresses and invoke the single-contract variant for each. Because Move's `abort` is transaction-wide with no catch mechanism, if any one contract in the list causes an abort (e.g., it has been terminated and is no longer `VESTING_POOL_ACTIVE`), the entire transaction reverts and every other contract in the batch misses its vesting period, reward unlock, or distribution.

---

### Finding Description

The three batch entry functions share the same structural pattern:

```move
// vest_many (line 707)
public entry fun vest_many(contract_addresses: vector<address>) acquires VestingContract {
    let len = contract_addresses.length();
    assert!(len != 0, error::invalid_argument(EVEC_EMPTY_FOR_MANY_FUNCTION));
    contract_addresses.for_each_ref(|contract_address| {
        let contract_address = *contract_address;
        vest(contract_address);   // <-- aborts the whole tx if this aborts
    });
}

### Impact Explanation

When a batch of N vesting contracts is submitted to `vest_many` and contract `i` has been terminated (state = `VESTING_POOL_TERMINATED`), the entire transaction aborts. Contracts `0..i-1` and `i+1..N-1` — which are still active and due for vesting — miss their vesting period entirely. Since `vest` only advances `last_vested_period` by one period per call, a missed period means shareholders receive their APT tokens later than scheduled. Repeated occurrences compound the delay. The same applies to reward unlocks (`unlock_rewards_many`) and distributions (`distribute_many`), directly affecting the APT staking balances and vesting balances of shareholders.

---

### Likelihood Explanation

The trigger is unprivileged: any account can call `vest_many`, `unlock_rewards_many`, or `distribute_many` with an arbitrary list of contract addresses. A race condition exists between batch construction and execution — the admin of any one contract in the list can call `terminate_vesting_contract` in a preceding transaction, causing the batch to fail. This can also be triggered accidentally (e.g., a contract that was already terminated being included in a stale batch). The `terminate_vesting_contract` function is callable by the contract's admin at any time: [10](#0-9) 

---

### Recommendation

Replace the hard abort with a skip-and-continue pattern inside each batch function. Check whether the contract is active before calling the single-contract function, and skip inactive contracts rather than aborting:

```move
public entry fun vest_many(contract_addresses: vector<address>) acquires VestingContract {
    assert!(contract_addresses.length() != 0, error::invalid_argument(EVEC_EMPTY_FOR_MANY_FUNCTION));
    contract_addresses.for_each_ref(|contract_address| {
        let contract_address = *contract_address;
        // Skip terminated or non-existent contracts instead of aborting
        if (exists<VestingContract>(contract_address)) {
            let vesting_contract = borrow_global<VestingContract>(contract_address);
            if (vesting_contract.state == VESTING_POOL_ACTIVE) {
                vest(contract_address);
            }
        }
    });
}
```

Apply the same guard to `unlock_rewards_many` and `distribute_many`.

---

### Proof of Concept

1. Admin A creates two vesting contracts: `contract_X` and `contract_Y`, both active.
2. A keeper (or any account) constructs a `vest_many([contract_X, contract_Y])` transaction and submits it to the mempool.
3. Before the batch executes, Admin A calls `terminate_vesting_contract(admin_A, contract_X)`, setting `contract_X.state = VESTING_POOL_TERMINATED`.
4. The `vest_many` transaction executes: `vest(contract_X)` → `unlock_rewards(contract_X)` → `total_accumulated_rewards(contract_X)` → `assert_active_vesting_contract(contract_X)` → **aborts** with `EVESTING_CONTRACT_NOT_ACTIVE`.
5. The entire transaction is reverted. `contract_Y` — which is still active and past its vesting period — does not have its `last_vested_period` advanced. Shareholders of `contract_Y` miss their APT vesting for this period. [11](#0-10) [12](#0-11)

        let last_completed_period =
            (timestamp::now_seconds() - vesting_schedule.start_timestamp_secs) / vesting_schedule.period_duration;
        if (last_completed_period < next_period_to_vest) {
            return
        };

        // Calculate how much has vested, excluding rewards.
        // Index is 0-based while period is 1-based so we need to subtract 1.
        let schedule = &vesting_schedule.schedule;
        let schedule_index = next_period_to_vest - 1;
        let vesting_fraction = if (schedule_index < schedule.length()) {
            schedule[schedule_index]
        } else {
            // Last vesting schedule fraction will repeat until the grant runs out.
            schedule[schedule.length() - 1]
        };
        let total_grant = vesting_contract.grant_pool.total_coins();
        let vested_amount = fixed_point32::multiply_u64(total_grant, vesting_fraction);

        vested_amount = min(vested_amount, vesting_contract.remaining_grant);
        vesting_contract.remaining_grant -= vested_amount;
        vesting_schedule.last_vested_period = next_period_to_vest;

    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
