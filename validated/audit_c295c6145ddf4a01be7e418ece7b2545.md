### Title
Unbounded/Unvalidated Length in `extractBytes32Array` Precompile Helper Causes Out-of-Bounds Array Access and Uncontrolled Allocation - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
`PrecompiledContracts.extractBytes32Array` decodes a caller-controlled length field from TVM call data and uses it to both allocate a Java array and index into the `words` array without any bounds validation, unlike its sibling helpers `extractBytesArray` and `extractSigArray` in the same class.

### Finding Description
The RTCP CVE (CVE-2018-11355) is a class of bug where a length/count field parsed directly from untrusted input is used to drive a loop or array construction without validating it against the actual bounds of the buffer, leading to an out-of-bounds access. `PrecompiledContracts.extractBytes32Array` reproduces this exact pattern: [1](#0-0) 

```java
private static byte[][] extractBytes32Array(DataWord[] words, int offset) {
    int len = words[offset].intValueSafe();
    byte[][] bytes32Array = new byte[len][];
    for (int i = 0; i < len; i++) {
      bytes32Array[i] = words[offset + i + 1].getData();
    }
    return bytes32Array;
}
```

`len` comes straight from a `DataWord` read out of the caller-supplied `words` array (i.e., the raw precompile call data, fully attacker-controlled). Note the contrast with the two sibling helpers in the same file, which both guard the offset before reading: [2](#0-1) 

`extractBytesArray` and `extractSigArray` both check `if (offset > words.length - 1) { return new byte[0][]; }` before touching `words[offset]`, and their inner loops read `words[offset + i + 1]` — bounded implicitly by the fact that `len` is itself taken from validated `abi`-style offsets earlier in these call paths. `extractBytes32Array` has neither the initial bound check present in the sibling methods nor any check that `offset + len` stays within `words.length` before the loop executes `words[offset + i + 1].getData()`.

Because `words` is derived from the raw TVM calldata to the precompile (`DataWord[]` slices of the input bytes), a caller can supply a small calldata buffer while making the length word at `offset` an arbitrarily large positive 32-byte integer. `intValueSafe()` only prevents overflow into a negative Java `int` (it caps to a safe int range) — it does not verify the value is consistent with the actual remaining size of `words`. The loop then indexes `words[offset + i + 1]` far past the end of the array.

### Impact Explanation
- If `len` is large but the backing `words` array is short, `words[offset + i + 1]` throws `ArrayIndexOutOfBoundsException`, which is an uncaught runtime exception during the TVM's precompiled-contract execution path.
- If `len` is large (e.g., near `Integer.MAX_VALUE`), `new byte[len][]` can throw `OutOfMemoryError` before the loop even runs. `OutOfMemoryError` is a JVM `Error`, not an `Exception`, and precompile execution and contract-invocation code across `actuator/src/main/java/org/tron/core/vm` predominantly catches `Exception`/`RuntimeException` (see the general try/catch pattern used elsewhere in `PrecompiledContracts.java`, e.g., `recoverAddrBySign` catching `Throwable` only for that one path). An uncaught `Error` propagating out of contract execution during block application can crash the node process that is validating or executing the block, which is a denial-of-service against every full node that processes the malicious transaction — consistent with the CVE's crash impact, scoped to an unprivileged contract caller here.

### Likelihood Explanation
Reaching this code only requires an unprivileged account to send a transaction that triggers the specific precompiled contract using `extractBytes32Array` with crafted calldata (a small `words` array and an inflated length word). No special privileges, staking, or witness/committee status are required — this is directly reachable via ordinary `TriggerSmartContract`/contract-call transactions routed through the TVM precompile dispatcher (`PrecompiledContracts.getContractForAddress`).

### Recommendation
Add the same bounds validation used in `extractBytesArray`/`extractSigArray` to `extractBytes32Array`:
1. Reject if `offset > words.length - 1` before reading `words[offset]`.
2. Clamp/validate `len` so that `offset + len + 1 <= words.length` before allocating `new byte[len][]` or entering the loop, returning an empty/failure result (or throwing a caught `Program.Exception`, consistent with other TVM guard patterns) instead of allowing an unchecked allocation or out-of-bounds read.

### Proof of Concept
Not independently confirmed with a live callsite trace due to search limitations — the exact precompiled contract that invokes `extractBytes32Array` (2 call sites found in `PrecompiledContracts.java`) could not be pinpointed in this pass, so it's uncertain which precompile address(es) expose this helper to attacker-controlled `words`/`offset`. Conceptually: an unprivileged caller invokes that precompile with calldata where the 32-byte word at the array's start position encodes a very large integer (e.g., `0xFFFFFFFF`) while the rest of the calldata is short, causing either `ArrayIndexOutOfBoundsException` on `words[offset + i + 1]` or `OutOfMemoryError`/`NegativeArraySizeException` on `new byte[len][]`.   private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          SIG_LENGTH);
    }
    return bytesArray;
  }
