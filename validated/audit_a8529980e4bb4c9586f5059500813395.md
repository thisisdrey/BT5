### Title
`TokenDiff::token_fee`'s `amount > 1` exemption is evaluated per-intent, letting fungible `Imt` transfers be split into unit-delta intents to bypass protocol fees - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives the protocol fee whenever `|delta| <= 1` for `TokenIdType::Imt` (and `Nep245`), a carve-out intended for indivisible NFT/MT unit transfers. Because `Imt` tokens are ordinary fungible balances (minted via `ImtMint`, no uniqueness constraint) and the fee is computed independently per `TokenDiff` intent inside `TokenDiff::execute_intent`, an attacker can split an `Imt` transfer of size `N` into `N` separate `TokenDiff` intents each with `delta = ±1`, causing the total fee collected to be `0` instead of `protocol_fee.fee_ceil(N)`.

### Finding Description
The binding that should hold is:
`sum(fee_collected for Imt token across all TokenDiff intents in a batch moving total amount N) == protocol_fee.fee_ceil(N)` (i.e. splitting should not change the total fee owed on the same net negative delta by the same signer).

The code that computes the fee is: [1](#0-0) 

and it is invoked once per `(token_id, delta)` pair inside a single `TokenDiff.diff` map, and once per `TokenDiff` intent in `execute_intent`: [2](#0-1) 

`DefuseIntents::execute_intent` iterates every `Intent` in the `intents: Vec<Intent>` list of a signed payload and dispatches each `TokenDiff` independently, with no cross-intent aggregation of `amount` for fee purposes: [3](#0-2) 

`Engine::execute_signed_intent` also processes one `MultiPayload` at a time, and multiple signed payloads (each with its own valid nonce for the same signer) can be submitted in the same `execute_intents(signed: Vec<MultiPayload>)` call: [4](#0-3) [5](#0-4) 

Matching across the whole batch is done later, at the aggregate `TokenId` level, via `TransferMatcher`/`finalize`, independent of how many intents contributed to the net delta: [6](#0-5) 

Root cause: `token_fee`'s `amount > 1` threshold treats `Imt` the same as `Nep171`/`Nep245`, i.e. as an indivisible-unit token type where a single unit move shouldn't be fee-liable. But `ImtTokenId` (`crates/primitives/token-id/src/imt.rs`) has no such uniqueness constraint - it is an ordinary fungible balance identified by `(minter_id, token_id)`: [7](#0-6) 

Because the fee determination is local to each `TokenDiff.execute_intent` call and keyed only on that single intent's `delta.unsigned_abs()`, an attacker who holds `N` units of an `Imt` token can sign one `MultiPayload` (or several, since nonces are independent) containing `N` `TokenDiff` intents, each with `diff = { imt_token: -1 }` (matched by a counterparty's NEP-141/other legs summing to the same aggregate), and every one of the `N` calls hits `TokenIdType::Imt` with `amount == 1`, returning `Pips::ZERO`: [8](#0-7) 

whereas a single `TokenDiff` intent with `delta = -N` on the same token would compute `Self::token_fee(token_id, N, protocol_fee)` with `amount > 1`, falling into the `fee` branch and owing `protocol_fee.fee_ceil(N) > 0` whenever `protocol_fee != Pips::ZERO`.

No existing guard (nonce commitment, signature verification, `TransferMatcher::finalize`, balance invariants) checks or aggregates the cumulative `amount` moved on the same `TokenId` by the same signer across multiple `TokenDiff` intents/payloads before applying the `amount > 1` exemption test — the exemption is purely local per intent.

### Impact Explanation
Value that should be credited to `fee_collector` on `Imt` legs of a swap is under-collected: the attacker (in cooperation with, or unilaterally as, either counterparty of a matched trade) pays `0` fee on the `Imt` leg instead of `protocol_fee.fee_ceil(N)`, for any `N` and any nonzero `protocol_fee`. This is directly a "protocol fees bypassed" condition. The technique is fully repeatable: any account holding an `Imt` balance can always express any negative `Imt` delta as `N` intents of `delta=-1` rather than one intent of `delta=-N`, at the cost of larger payloads/gas but zero extra funds. It applies to every `Imt` token and every account, and generalizes analogously to `Nep245` amounts, though the question scopes to `Imt`.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged attacker's control: they need only an `Imt` balance `>= N` in the Verifier and a counterparty willing to supply the complementary legs (the counterparty need not split anything — `TransferMatcher` matches on aggregate net deltas per `TokenId`, not per-intent, so a normal single-intent counterparty leg suffices). The attacker signs `N` `TokenDiff` intents with unit deltas instead of one intent with delta `N`; this is a pure client-side payload-construction choice, costs nothing extra besides marginally larger payload/gas, and is trivially repeatable across any batch, account, or `Imt` token.

### Recommendation
Compute the fee-exemption/`amount` threshold on the net aggregate delta per `(signer, token_id)` across all `TokenDiff` intents in the execution (or, at minimum, disallow multiple `TokenDiff` intents from the same signer that reference the same `TokenId` within one execution/nonce, and require aggregation across a batch before applying the `amount > 1` check), and/or drop `Imt` from the "indivisible unit, no fee at |delta|<=1" carve-out entirely, since `Imt` tokens are fungible and have no unit-indivisibility guarantee.

    pub fn execute_signed_intents(
        mut self,
        signed: impl IntoIterator<Item = MultiPayload>,
    ) -> Result<Transfers> {
        for signed in signed {
            self.execute_signed_intent(signed)?;
        }
        self.finalize()
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    #[inline]
    pub fn add_delta(&mut self, owner_id: AccountId, token_id: TokenId, delta: i128) -> bool {
        self.0.entry_or_default(token_id).add_delta(owner_id, delta)
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}
