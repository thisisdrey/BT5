### Title
Global `overall_connection_rate_limiter` in `run_server` is stake-agnostic and can be exhausted by a distributed low-rate-per-IP unstaked flood, denying staked peers a QUIC handshake token - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`run_server` gates every incoming QUIC connection through a single shared `TokenBucket` (`overall_connection_rate_limiter`, `MAX_CONNECTION_BURST=1000`, `TOTAL_CONNECTIONS_PER_SECOND=2500`) before any peer-stake information is known. Because stake-based prioritization (`SwQos`/`SimpleQos`) only happens after a connection has already consumed a token from this global bucket, an attacker who spreads connection attempts across many distinct real (non-spoofed) source addresses — each individually staying under the per-IP `ConnectionRateLimiter` limit — can continuously saturate the shared bucket and starve legitimate staked peers of a chance to even complete the handshake.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:254-412`), for every accepted incoming connection the code first peeks the *global* bucket: [1](#0-0) 
and only afterwards performs per-IP filtering: [2](#0-1) 

The global bucket is created without any notion of stake: [3](#0-2) 

After the TLS handshake completes, `setup_connection` actually consumes one token from the same global bucket: [4](#0-3) 

Peer stake is only determined afterward, in `QosController::build_connection_context`/`try_add_connection` (e.g. `SwQos::try_add_connection`), which runs *after* both the per-IP and the global rate limiter have already been passed: [5](#0-4) 

The per-IP `ConnectionRateLimiter` is keyed by exact `IpAddr` with no CIDR/subnet aggregation, so an attacker who controls a large but cheap pool of distinct real addresses (e.g. a rotating IPv6 /64 or /56 delegation, which is trivially obtained from many cloud/VPS providers) can keep each individual IP's rate under the default `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE = 8` (`streamer/src/quic.rs:56`) while collectively exceeding `TOTAL_CONNECTIONS_PER_SECOND = 2500` connections/sec in aggregate. Because these are real, reachable addresses (not spoofed), each can complete the QUIC handshake and legitimately consume a token from `overall_connection_rate_limiter` before the server can classify or prioritize the connection by stake. Since token consumption in `overall_connection_rate_limiter.consume_tokens(1)` is a simple race (first-come-first-served, no reservation/weighting for staked identities), a sufficiently parallel unstaked flood can keep the shared bucket persistently empty, causing legitimate staked connection attempts hitting `overall_connection_rate_limiter.current_tokens() == 0` in the accept loop, or losing the race in `consume_tokens` in `setup_connection`, to be rejected with `CONNECTION_CLOSE_CODE_DISALLOWED` regardless of their stake.

The existing mitigations (per-IP `ConnectionRateLimiter`, `ClientConnectionTracker` concurrency cap, and stake-weighted `SwQos`/`SimpleQos` connection tables) do not protect against this because they either operate on a per-IP granularity that a distributed attacker can trivially stay under, or only activate after the global gate has already been consumed.

### Impact Explanation
This is a network-reachable, unauthenticated denial-of-service against the QUIC/TPU ingress path of whichever node is currently leader (and any node serving TPU/TPU-forward/vote QUIC ports, since each `run_server` instance has its own independent `overall_connection_rate_limiter`). While the attack window is bounded to that node's leader slot(s), a sustained distributed flood can deny staked validators/forwarders the ability to establish new QUIC connections to submit transactions/votes during that window, degrading transaction ingestion and potentially causing missed/degraded blocks — a scoped availability/DoS impact on the TPU network layer, not requiring any staked/validator/config control by the attacker.

### Likelihood Explanation
Feasibility requires the attacker to control enough distinct source IP addresses to sustain >2500 real handshake completions/sec while each individual IP stays below ~0.13 conn/sec (8/min). This is realistic given IPv6 address abundance (a single /64 or /56 allocation, common with many hosting providers, provides effectively unlimited distinct addresses) combined with modest bandwidth/compute, and does not require spoofing (QUIC's handshake requires a real return path, so pure spoofing would not work — but attacker-controlled rotating real addresses satisfy the same effect). No validator, leader, gossip, or staked-node control is needed — only network access to the target's public TPU QUIC port.

### Recommendation
Make the global connection-acceptance budget stake-aware rather than purely first-come-first-served: e.g., reserve a portion of `overall_connection_rate_limiter` tokens for previously-seen staked identities/IP ranges, or move the global admission check to occur after (or weighted by) a lightweight authentication/stake check, or apply CIDR-based (not just exact-IP) aggregation in `ConnectionRateLimiter` so that an address block cannot bypass throttling by rotating within it. Alternatively, split the single global bucket into separate global buckets for "connections whose IP has previously registered a staked pubkey" vs "unseen/unstaked", ensuring unstaked flood cannot fully deplete the token supply available to staked reconnections.

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }
