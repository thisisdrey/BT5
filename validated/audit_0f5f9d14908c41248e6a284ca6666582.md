### Title
`liquidate()` can revert for positions reported liquidatable — `quoteLiquidateMax` uses the opposite oracle-quote direction than `liquidate`, and dust debt below `debtFloorInUsd` blocks all liquidation - ([File: contracts/Pool.sol])

### Summary
Metronome's liquidation surface has the same "view says liquidatable, execution reverts" class as the Arcadia report. The quoting path used to compute the maximum repayable amount (`quoteLiquidateMax` → `quoteLiquidateIn`, collateral→debt direction via `wadDiv` and `masterOracle.quote(underlying → synth)`) is not the same computation `liquidate()` performs (`quoteLiquidateOut`, debt→collateral direction via `masterOracle.quote(synth → underlying)` plus `wadMul` fees). Rounding is not symmetric between the two directions, so the repay amount suggested by `quoteLiquidateMax` can produce `_totalToSeize > depositToken_.balanceOf(account_)` and revert with `AmountIsTooHigh` (Pool.sol:583-584). Additionally, when a deeply underwater account's collateral bounds the repay below its full debt, the remaining debt can be a positive amount below `debtFloorInUsd`, causing every liquidation attempt to revert with `RemainingDebtIsLowerThanTheFloor` (Pool.sol:571-579).

### Finding Description
- `quoteLiquidateMax` (Pool.sol:419-440) computes `_maxAmountToRepay` by calling `quoteLiquidateIn`, which divides the collateral balance by `1e18 + fees` (`wadDiv`, rounds down) and then quotes collateral→synth.
- `liquidate` (Pool.sol:581-585) instead calls `quoteLiquidateOut`, which quotes synth→collateral and multiplies fees up (`wadMul`), then requires `_totalToSeize <= balanceOf(account_)`.
- `masterOracle().quote` round-trips are not guaranteed inverse at wei precision (price*amount/divisor truncation in each direction). A repay computed as "everything the collateral can cover" in the In-direction can translate back to a seize amount 1+ wei above the actual balance in the Out-direction → revert.
- Independently, `debtFloorInUsd` (Pool.sol:571-579) reverts whenever `0 < remainingDebt < floor`. If `maxLiquidable` (50%) or the collateral balance caps `amountToRepay_` so the leftover debt is dust under the floor, there is no legal `amountToRepay_`: repaying more violates `maxLiquidable`/`AmountIsTooHigh`, repaying less violates the floor. The account is unhealthy yet cannot be liquidated at all.

### Impact Explanation
Unhealthy positions (including bad-debt positions) cannot be liquidated despite `debtPositionOf` reporting `_isHealthy == false`. Liquidators calling the documented quoting function get a revert; positions linger and accrue interest, worsening protocol insolvency. Temporary-to-permanent freezing of liquidation = liveness failure on the liquidation path, matching the Arcadia medium.

### Likelihood Explanation
Requires no privileged action: any EOA liquidator hits this when (a) wei-level rounding drift between the two quote directions pushes `_totalToSeize` 1 wei over the account balance, or (b) a position's collateral covers less than `debt - debtFloorInUsd` worth of repay while `maxLiquidable` also caps repayment. Scenario (b) is deterministic for any underwater account whose debt is close to the floor or whose collateral is nearly exhausted. No oracle manipulation needed — just normal truncation.

### Recommendation
- Make `liquidate` clamp instead of revert: compute `_maxAmountToRepay` via the same `quoteLiquidateIn` logic inside `liquidate` and use `min(amountToRepay_, _maxAmountToRepay)`, or derive the seize amount from the same quote direction used for the cap.
- Skip the `debtFloorInUsd` check when `amountToRepay_` equals the full remaining debt or when the collateral balance is the binding constraint (i.e., allow liquidation that leaves dust debt if the position is insolvent).
- Round `_repayAmountInCollateral`/`_toLiquidator` conservatively (round the seize down) so the Out quote never exceeds the balance the In quote was derived from.

### Proof of Concept
Foundry/Hardhat fork sketch:

```ts
// Setup: alice deposits msdMET collateral, mints msETH; drop MET price so position is unhealthy.
await masterOracle.updatePrice(met.address, toUSD('0.50'))

// 1) View says liquidatable
const {_isHealthy} = await pool.debtPositionOf(alice.address)
expect(_isHealthy).to.be.false

// 2) Protocol-endorsed max repay quote
const amountToRepay = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)
expect(amountToRepay).to.be.gt(0)

// 3) Liquidator uses exactly the quoted amount -> reverts when
//    quoteLiquidateOut(amountToRepay) > balanceOf(alice) by rounding
await expect(
  pool.connect(liquidator).liquidate(msEth.address, alice.address, amountToRepay, msdMET.address)
).to.be.revertedWithCustomError(pool, 'AmountIsTooHigh') // or RemainingDebtIsLowerThanTheFloor
```

Fuzz variant (mirrors the Arcadia PoC): for random `collateralAmount`, `debtAmount`, and prices, assert `quoteLiquidateOut(quoteLiquidateIn(balance)) <= balance`; the inequality fails whenever the two quote directions truncate differently, and the floor check fails whenever `0 < debt - maxRepay < debtFloorInUsd`.
