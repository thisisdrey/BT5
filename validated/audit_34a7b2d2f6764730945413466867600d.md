Audit Report

## Title
`swap_and_burn` performs the tip/fee-asset-to-Ether swap with `amount_out_min = None`, exposing `register_token`/`add_tip` callers to unbounded price-impact loss - (File: `bridges/snowbridge/pallets/system-frontend/src/lib.rs`)

## Summary
`pallet_snowbridge_system_frontend`'s `register_token` and `add_tip` extrinsics allow any signed origin to pay Snowbridge fees/tips in an arbitrary asset, which is swapped into Ether via `pallet_asset_conversion::Swap::swap_exact_tokens_for_tokens` before being burned for teleport to Ethereum. `swap_and_burn` hard-codes the slippage-protection parameter `amount_out_min` to `None`, so the swap executes at whatever spot price the AMM pool reports at execution time, with no floor on the output.

## Finding Description
`swap_and_burn` is invoked by both `register_token` (whenever the caller is not the root location) and `add_tip` (unconditionally, for any signed origin), via `swap_fee_asset_and_burn`. The swap call is:

```rust
let ether_gained = T::Swap::swap_exact_tokens_for_tokens(
    who.clone(),
    swap_path,
    tip_amount,
    None, // No minimum amount required
    who,
    true,
)?;
```

`T::Swap` is concretely bound to the real `pallet_asset_conversion::Pallet` (`AssetConversion`) in the Asset Hub Westend runtime configuration, confirming this is not a mock-only issue. `pallet-asset-conversion`'s `swap_exact_tokens_for_tokens` supports an `amount_out_min` parameter specifically designed to bound slippage (returning `ProvidedMinimumNotSufficientForSwap` if the trade doesn't meet it), but this pallet never uses it. There is no other bound anywhere in the call path (`swap_fee_asset_and_burn` simply passes the raw fee/tip amount through without any prior quote or price check). `ether_gained` — whatever the manipulated/execution-time pool state yields — is used directly as the registration/tip amount forwarded to BridgeHub via `build_register_token_call`/`build_add_tip_call`.

This contrasts with other swap-consuming code in the same repository, such as `SwapAssetAdapter` in `substrate/frame/transaction-payment/asset-conversion-tx-payment/src/payment.rs`, which always quotes the exact price via `quote_price_tokens_for_exact_tokens` before committing user funds to a swap, ensuring the user never loses more than the fair-market-quoted amount.

## Impact Explanation
Any unprivileged, signed caller invoking `register_token` (for a non-root/non-"here" origin) or `add_tip` with a non-Ether asset has that asset unconditionally exchanged at whatever price the pool reports at execution time, with zero protection against price impact, thin liquidity, or adverse pool-state at the moment of dispatch. The corrupted value is `ether_gained`, which both determines how much value is burned/removed from the user's custody and is forwarded as the registration/tip amount to BridgeHub — i.e., a cost-correctness violation for the caller with no on-chain guard, falling under "runtime bugs that compromise intended behavior" for fee/reward accounting in the bridge frontend pallet.

## Likelihood Explanation
Both extrinsics are public, unprivileged, and reachable by any signed account. `add_tip` requires no origin check beyond `ensure_signed`. `register_token` is guarded only by `RegisterTokenOrigin` (an asset owner or governance-style check), but ordinary asset owners can call it directly with an arbitrary `fee_asset`. The condition needed — a pool with non-trivial spread or shallow depth for the `(fee_asset, Ether)` pair — is common for newly listed or thinly traded assets and requires no relayer/validator/governance compromise, only ordinary AMM price dynamics or an adversary trading against the pool beforehand.

## Recommendation
Add a caller-supplied minimum-output parameter (or derive a bound internally via `QuotePrice::quote_price_exact_tokens_for_tokens` with an acceptable tolerance) to `register_token`/`add_tip`, and pass `Some(min_ether_out)` into `Swap::swap_exact_tokens_for_tokens` in `swap_and_burn`, mirroring the quoting/bounding pattern used by `SwapAssetAdapter` in `asset-conversion-tx-payment`.

## Proof of Concept
1. Deploy a runtime with the `(FeeAsset, Ether)` pool in `pallet-asset-conversion` at modest/thin liquidity.
2. Move the pool's spot price unfavorably for `FeeAsset → Ether` (e.g., via a prior swap in the same or an earlier block).
3. Call `add_tip(message_id, Asset{ id: FeeAsset, fun: Fungible(tip_amount) })` as any signed account holding `FeeAsset`.
4. Observe in `swap_and_burn` that `T::Swap::swap_exact_tokens_for_tokens(..., tip_amount, None, ...)` succeeds and returns an `ether_gained` far below the pre-manipulation fair value quote (verifiable by comparing against `AssetConversion::quote_price_exact_tokens_for_tokens` computed before the price move).
5. Confirm `ether_gained` is burned via `burn_for_teleport` and forwarded as the tip amount in the `AddTip` XCM `Transact` call to BridgeHub — demonstrating the caller permanently loses the price-impact difference with no on-chain minimum-output check, unlike `pallet-asset-conversion`'s own `swap_exact_tokens_for_tokens` extrinsic which would revert with `ProvidedMinimumNotSufficientForSwap` if a minimum were supplied.

		fn swap_and_burn(
			origin: Location,
			tip_asset_location: Location,
			ether_location: Location,
			tip_amount: u128,
		) -> Result<u128, DispatchError> {
			// Swap tip asset to ether
			let swap_path = vec![tip_asset_location.clone(), ether_location.clone()];
			let who = T::AccountIdConverter::convert_location(&origin)
				.ok_or(Error::<T>::LocationConversionFailed)?;

			let ether_gained = T::Swap::swap_exact_tokens_for_tokens(
				who.clone(),
				swap_path,
				tip_amount,
				None, // No minimum amount required
				who,
				true,
			)?;

			// Burn the ether
			let ether_asset = Asset::from((ether_location.clone(), ether_gained));

			burn_for_teleport::<T::AssetTransactor>(&origin, &ether_asset)
				.map_err(|_| Error::<T>::BurnError)?;

			Ok(ether_gained)
		}

		fn swap_fee_asset_and_burn(
			origin: Location,
			fee_asset: Asset,
		) -> Result<u128, DispatchError> {
			let ether_location = T::EthereumLocation::get();
			let (fee_asset_location, fee_amount) = match fee_asset {
				Asset { id: AssetId(ref loc), fun: Fungible(amount) } => (loc, amount),
				_ => {
					tracing::debug!(target: LOG_TARGET, ?fee_asset, "error matching fee asset");
					return Err(Error::<T>::UnsupportedAsset.into());
				},
			};
			if fee_amount == 0 {
				return Ok(0);
			}

			let ether_gained = if *fee_asset_location != ether_location {
				Self::swap_and_burn(
					origin.clone(),
					fee_asset_location.clone(),
					ether_location,
					fee_amount,
				)
				.inspect_err(|&e| {
					tracing::debug!(target: LOG_TARGET, ?e, "error swapping asset");
				})?
			} else {
				burn_for_teleport::<T::AssetTransactor>(&origin, &fee_asset)
					.map_err(|_| Error::<T>::BurnError)?;
				fee_amount
			};
			Ok(ether_gained)
		}
