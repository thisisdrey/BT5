### Title
NULL Pointer Dereference in `TransactionTrace.checkIsConstant()` from unchecked `Any.unpack()` result - ([File: chainbase/src/main/java/org/tron/core/db/TransactionTrace.java])

### Summary
`TransactionTrace.checkIsConstant()` calls `ContractCapsule.getTriggerContractFromTransaction()`, which returns `null` on `InvalidProtocolBufferException` instead of propagating an error, and then immediately dereferences the result without a null check — the same bug class as CVE-2021-3596 (unchecked return value of a parser call leading to a NULL pointer dereference / crash).

### Finding Description
`ContractCapsule.getTriggerContractFromTransaction()` unpacks the `Any` parameter of a transaction contract into a `TriggerSmartContract`, and explicitly returns `null` if unpacking fails: [1](#0-0) 

`TransactionTrace.checkIsConstant()` calls this method and, when `trxType == TRX_CONTRACT_CALL_TYPE`, immediately dereferences the returned value via `triggerContractFromTransaction.getContractAddress()` without checking for `null`: [2](#0-1) 

Compare this to `VMActuator.call()`, which correctly checks the same accessor for `null` before use: [3](#0-2) 

The difference between these two call sites (one checked, one unchecked) is the exact analog of the ImageMagick bug: `xmlCreatePushParserCtxt()`'s return value is checked in some call paths but not others, and the unchecked path dereferences a null pointer.

An attacker can trigger this by broadcasting a `Transaction` whose contract `type` field is set to `TriggerSmartContract`, but whose `Any` payload bytes are malformed/truncated such that `Any.unpack(TriggerSmartContract.class)` throws `InvalidProtocolBufferException` (the type URL can still match the expected type while the payload bytes fail to parse as valid protobuf wire format for that message). `getTriggerContractFromTransaction()` swallows the exception and returns `null`, and `checkIsConstant()` then throws an unchecked `NullPointerException`.

### Impact Explanation
`checkIsConstant()` is invoked from `Manager.java` in the pre-execution/validation path for `TRX_CONTRACT_CALL_TYPE` transactions [4](#0-3) . Because it declares only `ContractValidateException, VMIllegalException` in its signature, callers are not necessarily prepared to catch a `RuntimeException`/`NullPointerException` originating here. Depending on how far up the call stack the exception is caught, this can crash transaction processing for a broadcast or block-application path, causing a denial-of-service against the node processing the malformed transaction (single node crash / inability to process transactions, potentially affecting block application if reached during block validation).

### Likelihood Explanation
The trigger condition (a `TriggerSmartContract`-typed transaction with a corrupted `Any` payload) is fully attacker-controlled and requires no special privileges — any transaction broadcaster can construct such a transaction. The only precondition is `getAllowTvmConstantinople() == 0` (i.e., this validation path is only active before/without that fork being enabled), which limits applicability to certain network configurations/fork states rather than being universally reachable on all currently running networks.

### Recommendation
In `TransactionTrace.checkIsConstant()`, check `triggerContractFromTransaction` for `null` immediately after calling `ContractCapsule.getTriggerContractFromTransaction()` and throw a `ContractValidateException` (consistent with the existing error-handling pattern in the method and matching how `VMActuator.call()` handles the same null case) instead of allowing the NPE to propagate.

### Proof of Concept
1. Construct a `Transaction` with `raw_data.contract[0].type = TriggerSmartContract`.
2. Set `raw_data.contract[0].parameter` to an `Any` whose `type_url` corresponds to `TriggerSmartContract`, but whose `value` bytes are corrupted/truncated such that protobuf parsing fails (e.g., truncate a valid serialized `TriggerSmartContract` mid-varint).
3. Sign and broadcast the transaction while the network has `AllowTvmConstantinople == 0`.
4. When `TransactionTrace.checkIsConstant()` is invoked, `ContractCapsule.getTriggerContractFromTransaction()` returns `null` (parse failure), and `triggerContractFromTransaction.getContractAddress()` throws a `NullPointerException`, which is uncaught by the declared exception types of `checkIsConstant()`.

  public static TriggerSmartContract getTriggerContractFromTransaction(Transaction trx) {
    try {
      Any any = trx.getRawData().getContract(0).getParameter();
      TriggerSmartContract contractTriggerContract = any.unpack(TriggerSmartContract.class);
      return contractTriggerContract;
    } catch (InvalidProtocolBufferException e) {
      return null;
    }
  }
