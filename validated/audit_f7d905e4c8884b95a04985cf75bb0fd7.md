## Title
Unauthenticated `RecvError` packets accepted by default allow a spoofing attacker to force tunnel teardown - ([File: outside.go])

### Summary
Analogous to the reviewed footgun where users can skip iCloud backup encryption and are left exposed by an insecure-but-permitted default, Nebula ships a config knob (`listen.accept_recv_error`) that defaults to `"always"`, causing the data plane to act on an entirely unauthenticated, unencrypted control packet (`header.RecvError`) from any UDP source. The permissive default converts what should be an authenticated-only signal into a remotely triggerable tunnel-teardown primitive for any attacker who can guess or observe a live `RemoteIndex` and spoof (or naturally control, e.g., off-path/NAT) the corresponding source `netip.AddrPort`.

### Finding Description
`RecvError` is one of only two packet types processed entirely outside of the Noise handshake/cert-verification and AEAD-decryption path — it is handled immediately in `readOutsidePackets` before any certificate, encryption, or replay checks are applied: [1](#0-0) 

`handleRecvError` decides whether to act on the packet using `f.acceptRecvErrorConfig`, which is loaded from `listen.accept_recv_error` and **defaults to `"always"`** — i.e., accept an unauthenticated `RecvError` from anyone, not just from the peer's known/private ranges: [2](#0-1) 

The only integrity check performed is comparing the packet's source `netip.AddrPort` against the hostinfo's currently known remote address, and this check is entirely skipped if the remote isn't yet set (e.g., early in a handshake) or trivially defeated by an attacker who can spoof the source address of the legitimate peer (UDP has no source authentication) while supplying the correct `RemoteIndex` (which is observable on the wire, since it appears in the unencrypted Nebula header of every message): [3](#0-2) 

Once accepted, the packet unconditionally tears down the tunnel and deletes pending handshake state, with no re-verification of the peer's certificate: [4](#0-3) 

This is directly analogous to the reported bug class: an optional security-relevant control (whether to trust an unauthenticated signal) is shipped with an insecure default (`"always"`) rather than requiring the safer default (`"never"`/`"private"`), creating a footgun that most deployments will run with unless they know to change it — mirroring how Nebula's own CHANGELOG (`1.6.0`) explicitly calls this out as a security tradeoff: [5](#0-4) 

### Impact Explanation
An attacker with no CA-signed certificate and no participation in any handshake can force teardown of any active tunnel between two legitimate Nebula peers, provided they can (a) observe or infer the current `RemoteIndex` for a hostinfo (visible in every unencrypted Nebula header on the wire, or guessable given the sequential/limited index space) and (b) spoof or otherwise send from the same `netip.AddrPort` the target believes is its peer's remote (trivial over UDP, or immediate if the remote isn't set yet). This is a remote, unauthenticated denial-of-service / state-poisoning primitive against the mesh, reachable by an attacker holding no valid certificate.

### Likelihood Explanation
Likelihood is moderate-to-high in default configurations: `listen.accept_recv_error` defaults to `"always"`, so no explicit opt-in by the operator is required. UDP source-address spoofing over the public Internet is a well-known, low-cost technique, and `RemoteIndex` values are transmitted in the clear on every packet, making them observable to an on-path or off-path attacker capable of address spoofing.

### Recommendation
- Short term: Change the default of `listen.accept_recv_error` to `"private"` or `"never"` instead of `"always"`, so that Nebula does not act on an unauthenticated teardown signal by default, mirroring the recommendation to remove the insecure default option rather than merely warning about it.
- Long term: Require some form of authentication or rate-limited/replay-protected signature over `RecvError` packets (e.g., only accept them if they carry a valid MAC derived from the existing session keys) before honoring them as a tunnel-teardown trigger, removing the unauthenticated code path entirely.

### Proof of Concept
1. Establish a Nebula tunnel between hosts A and B.
2. From attacker-controlled host C (no Nebula certificate), craft a UDP packet: `header.Encode(..., header.RecvError, 0, <observed_or_guessed_RemoteIndex_of_A's_view_of_B>, 0)`.
3. Spoof the source address to match B's known `netip.AddrPort` as seen by A (or send it before A has recorded B's remote address, e.g. immediately after start).
4. Send to A's listening UDP port.
5. Observe `handleRecvError` on A accepts the packet under the default `"always"` policy, and `f.closeTunnel(hostinfo)` / `f.handshakeManager.DeleteHostInfo(hostinfo)` tear down A's tunnel to B without any certificate or key material from the attacker.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```

```go
func (f *Interface) reloadAcceptRecvError(c *config.C) {
	if c.InitialLoad() || c.HasChanged("listen.accept_recv_error") {
		stringValue := c.GetString("listen.accept_recv_error", "always")

		switch stringValue {
		case "always":
			f.acceptRecvErrorConfig = recvErrorAlways
		case "never":
			f.acceptRecvErrorConfig = recvErrorNever
		case "private":
			f.acceptRecvErrorConfig = recvErrorPrivate
		default:
			if c.GetBool("listen.accept_recv_error", true) {
				f.acceptRecvErrorConfig = recvErrorAlways
			} else {
				f.acceptRecvErrorConfig = recvErrorNever
			}
		}

		f.l.Info("Loaded accept_recv_error config", "acceptRecvError", f.acceptRecvErrorConfig.String())
	}
}
```
