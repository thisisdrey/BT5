### Title
Off-path replay of a captured handshake stage-0 packet from a spoofed UDP source lets an attacker force `HostInfo.SetRemoteIfPreferred` to roam a tunnel to an unverified preferred-range address - ([File: hostmap.go], [File: handshake_manager.go])

### Summary
`HostInfo.SetRemoteIfPreferred` changes a peer's remote UDP address whenever a packet's source address falls inside `preferredRanges`, without any requirement that this specific address be independently verified via handshake/session traffic. The only caller of this function is `handleCheckAndCompleteError`'s `ErrAlreadySeen` branch, which fires whenever a duplicate/retransmitted handshake stage-0 packet is received for an already-completed `HostInfo`. Because Noise IX message 1 authentication doesn't bind to the UDP source address, a captured, previously-valid stage-0 packet can be replayed byte-for-byte from a spoofed source address inside `preferredRanges`, causing the responder to roam onto that address.

### Finding Description
`SetRemoteIfPreferred` accepts a roam purely based on whether `via.UdpAddr.Addr()` is contained in one of `hm.GetPreferredRanges()`: [1](#0-0) 

The only production call site is in `handleCheckAndCompleteError`, on the `ErrAlreadySeen` branch of the handshake manager: [2](#0-1) 

`ErrAlreadySeen` here is returned by `hm.CheckAndComplete` when a freshly re-processed stage-0 handshake packet matches an already-completed `HostInfo` (i.e., the peer retransmitted its original stage-0 message because it never got the stage-2 response). This packet reaches `beginHandshake`, which builds a brand-new responder `Machine` and fully re-runs `machine.ProcessPacket` on the incoming bytes: [3](#0-2) 

Because the Noise IX message-1 authentication is a deterministic function of the message bytes and the static/ephemeral keys involved (not of the transport source address), *replaying the exact same previously-captured ciphertext* from a different, spoofed UDP source address will re-validate successfully and route into the `ErrAlreadySeen` path again, invoking `existing.SetRemoteIfPreferred(f.hostMap, via)` with the attacker's spoofed `via.UdpAddr`. If that spoofed address lies in `preferredRanges`, `SetRemoteIfPreferred` unconditionally roams the tunnel to it - there is no requirement that any traffic actually be verified as coming from the *real* device at that address, only that the presented UDP source address matches a `preferredRanges` CIDR and a previously valid packet's bytes matched.

Unlike the data-plane roaming path (`handleHostRoaming` in `outside.go`, called after `ConnectionState.Decrypt` succeeds), which is protected by a replay window (`cs.window.Check`/`cs.window.Update`) that consumes and rejects a re-used message counter: [4](#0-3) 
the handshake-retransmit roam path has no such anti-replay protection for the *specific address* switch — the "already seen" detection is precisely the condition an attacker exploits by replaying the identical bytes.

### Impact Explanation
An attacker who can (a) obtain one legitimate, previously-sent handshake stage-0 packet (e.g., via on-path observation) and (b) spoof a UDP source address inside the configured `preferredRanges`, can force the responder's `HostInfo` to roam its recorded remote address to that spoofed (attacker-influenced but not attacker-owned) address. This causes the tunnel's outbound traffic to be misdirected/blackholed to a bogus address, resulting in denial of service for the legitimate peer's data path until connection-manager timeout/re-handshake recovers it.

### Likelihood Explanation
Requires: (1) `preferredRanges` configured (a common Nebula deployment pattern for LAN-preferred routing), (2) possession of a single already-transmitted, unconsumed stage-0 handshake ciphertext for a live tunnel, and (3) the ability to spoof a UDP source address within `preferredRanges`. Given those preconditions (stated as given in the question), the replay is deterministic and repeatable — no cryptographic break is needed, only a byte-exact retransmission of already-valid bytes.

### Recommendation
Do not roam the recorded remote address based solely on receipt of a duplicate/replayed handshake retransmission. Either: (a) only allow `SetRemoteIfPreferred` roaming from data-plane traffic that has passed the anti-replay window (`ConnectionState.Decrypt`), never from the handshake-retransmission `ErrAlreadySeen` path; or (b) require a fresh challenge/response (e.g., wait for a `Test`/`RecvError` roundtrip actually acknowledged from the new address) before switching `i.remote`, rather than switching immediately upon a spoofable UDP source match.

### Proof of Concept
Unit test plan in `hostmap_test.go` / `handshake_manager_test.go`:
1. Build a `HostMap` with `preferredRanges` set to e.g. `10.0.0.0/24`.
2. Create a `HostInfo` with `remote` set to a legitimate public address (outside the preferred range) and a stored `HandshakePacket[handshakePacketStage0]`.
3. Simulate the `ErrAlreadySeen` condition by directly invoking `existing.SetRemoteIfPreferred(hostMap, via)` with `via.UdpAddr` set to a crafted/spoofed `netip.AddrPort` inside `10.0.0.0/24` that was never associated with any prior successful handshake completion from that address.
4. Assert that `SetRemoteIfPreferred` returns `true` and `existing.GetRemote()` now equals the spoofed preferred-range address — demonstrating the roam is accepted without any verification tied to that specific address (e.g., no prior successful decrypt/handshake completion from it).

// SetRemoteIfPreferred returns true if the remote was changed. The lastRoam
// time on the HostInfo will also be updated.
func (i *HostInfo) SetRemoteIfPreferred(hm *HostMap, via ViaSender) bool {
	if via.IsRelayed {
		return false
	}

	currentRemote := i.GetRemote()
	if !currentRemote.IsValid() {
		i.SetRemote(via.UdpAddr)
		return true
	}

	// NOTE: We do this loop here instead of calling `isPreferred` in
	// remote_list.go so that we only have to loop over preferredRanges once.
	newIsPreferred := false
	for _, l := range hm.GetPreferredRanges() {
		// return early if we are already on a preferred remote
		if l.Contains(currentRemote.Addr()) {
			return false
		}

		if l.Contains(via.UdpAddr.Addr()) {
			newIsPreferred = true
		}
	}

	if newIsPreferred {
		// Consider this a roaming event
		i.lastRoam = time.Now()
		i.lastRoamRemote = currentRemote

		i.SetRemote(via.UdpAddr)

		return true
	}

	return false
}
