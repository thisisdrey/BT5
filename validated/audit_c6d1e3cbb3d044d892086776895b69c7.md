### Title
Unauthenticated `RecvError` packet allows remote teardown of an active, non-expired tunnel - (File: outside.go)

### Summary
Nebula's `RecvError` message type is processed before any cryptographic authentication (no AEAD decryption, no certificate/session check), and it is used to unilaterally close an active tunnel. The only guard is an address-equality check against the tunnel's last known UDP remote, which an off-path/on-path attacker can satisfy by UDP source-address spoofing and by observing the plaintext `RemoteIndex` field carried in every unencrypted header. This lets an attacker terminate a legitimate, still-valid tunnel with no cryptographic proof that an error actually occurred — analogous to the reported bug class of "closing" an active/authorized state without verifying the precondition (here: verifying the closing party is actually authorized/the real peer) is satisfied.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` directly to `handleRecvError` before any decryption or certificate/session validation: [1](#0-0) 

`handleRecvError` then closes the tunnel based only on a rate-limit check and a plain address-equality comparison — no cryptographic proof that the sender is the genuine peer or that any real error condition occurred: [2](#0-1) 

The `RemoteIndex` used to look up the hostinfo (`QueryReverseIndex`) is carried in cleartext in every packet's header (`h.RemoteIndex`), since the Nebula header itself is not encrypted — only the payload is: [3](#0-2) [4](#0-3) 

Because the header (including `RemoteIndex`) is visible to anyone who can observe traffic between two Nebula nodes (or who can otherwise learn the value), and because UDP source addresses are trivially spoofable, an attacker with no CA-signed certificate can:
1. Observe/learn a victim's `RemoteIndex` from any packet exchanged with the target (headers are unauthenticated and unencrypted).
2. Spoof the source UDP address to match the current remote address recorded for that hostinfo (`hr != addr` check in `handleRecvError`).
3. Send a single `RecvError` packet, causing `f.closeTunnel(hostinfo)` and `handshakeManager.DeleteHostInfo(hostinfo)` to be called — tearing down a fully valid, non-expired tunnel with no involvement of the actual certificate-holding peer.

This mirrors the report's root cause pattern: a state-transition (“closing”) function that lacks a check that the actual precondition for closing (a genuine error from the authenticated peer / expiry of validity) has been met.

### Impact Explanation
This allows a remote, unauthenticated attacker to force teardown of arbitrary active tunnels between legitimate Nebula peers, causing denial of service (forced re-handshake, dropped traffic, and repeated disruption if the attack is repeated). It does not grant decryption or certificate forgery, but it is a legitimate remote-state-poisoning / DoS impact reachable without holding a valid certificate.

### Likelihood Explanation
Likelihood is moderate-to-high in an environment where the attacker can observe or infer packets on the path (e.g., a network intermediary, or via other side channels that leak the index) and can spoof UDP source addresses — both of which are commonly feasible for UDP-based protocols and don't require possessing a CA-signed certificate. The attack requires only a single crafted UDP packet with correct `RemoteIndex` and spoofed source, no cryptographic material.

### Recommendation
Require the `RecvError` packet to be authenticated/verified against the session it purports to reference — e.g., include a MAC over the header using the current session key (like `Message` packets), or otherwise cryptographically prove the sender possesses the tunnel's negotiated key, before acting on it. At minimum, do not tear down a hostinfo/tunnel purely on the basis of a cleartext, unauthenticated index+address match; require some proof tied to the current `ConnectionState`.

### Proof of Concept
1. Two legitimate Nebula peers A and B complete a handshake and exchange normal traffic, exposing plaintext headers containing `RemoteIndex` values (e.g., visible to a passive on-path observer, or leaked via other channels).
2. Attacker C, without any CA-signed certificate, crafts a UDP packet with header `Type = header.RecvError`, `RemoteIndex` set to A's known index for the B tunnel, and source-spoofs the packet to appear to come from B's current UDP address.
3. C sends this packet to A's outside listener.
4. `readOutsidePackets` routes it directly to `handleRecvError` (outside.go:81-84) without decryption.
5. `handleRecvError` finds the matching hostinfo via `QueryReverseIndex`, confirms `hr == addr` (satisfied by the spoofed source), and calls `f.closeTunnel(hostinfo)` plus `handshakeManager.DeleteHostInfo(hostinfo)` (outside.go:557-574), destroying the tunnel state on A's side even though B never sent this packet and the tunnel was still valid.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
```

```go
// Parse is a helper function to parses given bytes into new Header struct
func (h *H) Parse(b []byte) error {
	if len(b) < Len {
		return ErrHeaderTooShort
	}
	// get upper 4 bytes
	h.Version = uint8((b[0] >> 4) & 0x0f)
	// get lower 4 bytes
	h.Type = MessageType(b[0] & 0x0f)
	h.Subtype = MessageSubType(b[1])
	h.Reserved = binary.BigEndian.Uint16(b[2:4])
	h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])
	h.MessageCounter = binary.BigEndian.Uint64(b[8:16])
	return nil
}
```
