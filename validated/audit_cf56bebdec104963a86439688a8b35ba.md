### Title
State-confusion bypass of quarantine-directory verification via naming heuristic instead of a dedicated trust check - (File: internal/git/localrepo/paths.go)

### Summary
The Solidity report's root cause is that a state machine trusted a user-influenced *value* (`lowestQuote == type(uint128).max`) as a proxy for "not finalized" instead of using a dedicated, tamper-proof state flag, letting an attacker craft inputs that satisfy the sentinel and unlock post-finalization actions (`cancelAuction`/`cancelBid`) that should have been blocked. The closest reachable analog in gitaly is in `Repo.ObjectDirectoryPath`, which decides whether a client-supplied `GitObjectDirectory` path is a trusted "transaction quarantine directory" (and therefore exempt from the strict repository-scoped prefix check) purely by matching directory *names* (`"quarantine"`, `"tmp_objdir*"`) rather than a dedicated, cryptographically-tied indicator of trust.

### Finding Description
`Repo.ObjectDirectoryPath` in [1](#0-0)  computes `objectDirectoryPath` from the client-controlled `Repository.GitObjectDirectory` field, which the proto explicitly documents as attacker/caller-settable to influence `GIT_OBJECT_DIRECTORY`: [2](#0-1) .

The function's security-critical branch is:
```go
isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))
if !isTransactionQuarantineDir {
    // strict repo-specific quarantine-prefix + escape check
    ...
}
``` [3](#0-2) 

This mirrors the SIZE bug pattern exactly: instead of relying on a dedicated, unforgeable state signal that a transaction actually created this quarantine directory (e.g. verifying against the transaction's known `txn.quarantineDirectory`, as constructed in [4](#0-3) ), the code infers "this is a legitimate transaction quarantine path" solely from the base/parent directory *names* `quarantine` / `tmp_objdir*`. Any path whose last two path components happen to be named `quarantine` and `tmp_objdir-<anything>` (or just `quarantine`) is treated as trusted and skipped from the `expectedQuarantinePrefix` (`storage.QuarantineDirectoryPrefix`, which is the actual repo-bound authorization check based on a SHA1 of the relative path — see [5](#0-4) ).

Since `GitObjectDirectory`/`GitAlternateObjectDirectories` are ordinary fields on the `Repository` message accepted on `target_repository`-carrying RPCs, a caller can set `GitObjectDirectory` to any string that Git-joins to a path they fully control (e.g. `../../../tmp/attacker-owned/quarantine`) as long as it also passes the earlier `storage.ValidateRelativePath` escape check for storage-root containment (the only remaining defense once the naming heuristic is matched — note this containment check is still applied to the *final* `fullPath`, but the `expectedQuarantinePrefix` ownership binding to *this specific repository* is skipped entirely). This lets a directory located anywhere else within the storage root that merely happens to be named `.../quarantine` (or `.../quarantine/tmp_objdir-x`) be accepted as this repository's authorized object directory, even though it was never created by this repository's transaction/quarantine flow.

### Impact Explanation
If an attacker (an ordinary Gitaly RPC caller who can influence `GitObjectDirectory`, e.g. through hook/transaction-payload-adjacent code paths or any RPC that forwards a client-influenced repository message) can point their own or another repository's object directory into a directory of their choosing merely by naming it to match the `quarantine`/`tmp_objdir*` heuristic, they bypass the intended repository-scoped ownership binding (`QuarantineDirectoryPrefix`). This enables cross-repository object visibility/injection: git subprocesses invoked against the "repository" will search for objects using `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` pointed at an unrelated, attacker-influenced directory within the same storage, undermining the isolation guarantees that object quarantine and per-repository object directories are meant to provide (see design intent in [6](#0-5) ).

### Likelihood Explanation
Moderate-to-low but concrete: it requires the caller to control the `GitObjectDirectory` field to a value whose trailing components match the naming heuristic while remaining within the storage root (as enforced later by `os.Stat`/existence check and the ValidateRelativePath call for storage escape at line 38, though that check is only reached for the non-quarantine branch — for the heuristic-matched branch no further ownership/prefix binding is performed at all). Because the check relies on string equality of directory basenames rather than a cryptographic/authoritative marker tied to the specific transaction, any RPC surface that lets a client set or influence this field is directly exploitable without needing privileged access, mirroring the "carefully crafted parameters" nature of the original finding.

### Recommendation
Do not infer trust in `ObjectDirectoryPath` from directory naming conventions (`"quarantine"` / `"tmp_objdir"` prefixes). Instead, always validate the object directory against a dedicated, repository-bound value — e.g. always require the `expectedQuarantinePrefix` (`storage.QuarantineDirectoryPrefix`) check, or compare against the transaction's actual recorded `quarantineDirectory` value carried through context/transaction state — regardless of the directory's basename, so an attacker cannot forge acceptance by simply naming a directory `quarantine` or `tmp_objdir-*`.

### Proof of Concept
Conceptual PoC (exact reachable RPC surface for `GitObjectDirectory` injection would need confirmation via a live Devin session since only `internal/git/localrepo/paths_test.go` shows unit-level exercising of this code path, not the full external RPC chain):
1. Issue a request against an RPC whose `Repository` target allows the caller to set `GitObjectDirectory` to a relative path such as `some/existing/dir/quarantine` (satisfying `baseDir == "quarantine"`), located inside the storage root but outside of any directory created by this repository's actual quarantine/transaction flow, as demonstrated by the acceptance-path unit test in [7](#0-6) , which validates that any directory matching the naming pattern is accepted without checking `expectedQuarantinePrefix`.
2. Confirm `ObjectDirectoryPath` returns this attacker-chosen path without validating it belongs to the target repository's quarantine chain (skips lines 61-74 in [8](#0-7) ).
3. Subsequent git subprocess invocations that consume this object directory (e.g. `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` env vars) will search/write objects using the unrelated directory, breaking the intended repository-scoped isolation.

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}
```

// QuarantineDirectoryPrefix returns a prefix for use in the temporary directory. The prefix is
// based on the relative repository path and will stay stable for any given repository. This allows
// us to verify that a given quarantine object directory indeed belongs to the repository at hand.
// Ideally, this function would directly be located in the quarantine module, but this is not
// possible due to cyclic dependencies.
func QuarantineDirectoryPrefix(repo Repository) string {
	hash := [20]byte{}
	if repo != nil {
		hash = sha1.Sum([]byte(repo.GetRelativePath()))
	}
	return fmt.Sprintf("quarantine-%x-", hash[:8])
}
```

#### 1. Alternate object directories

The objects in a Git repository can be stored across multiple
directories: 1 main directory, usually `/objects`, and 0 or more
alternate directories. Together these act like a search path: when
looking for an object Git first checks the main directory, then each
alternate, until it finds the object.

#### 2. Config overrides via environment variables

Git can inject custom config into subprocesses via environment
variables. In the case of Git object directories, these are
`GIT_OBJECT_DIRECTORY` (the main object directory) and
`GIT_ALTERNATE_OBJECT_DIRECTORIES` (a search path of `:`-separated
alternate object directories).
