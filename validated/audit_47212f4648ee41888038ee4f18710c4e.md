### Title
Unauthenticated remote `/shutdown` POST permanently halts signer event ingestion - (`File: libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` handles the `/shutdown` HTTP path by unconditionally setting `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returning `Err(EventError::Terminated)` for any POST request that matches the URL, with no check on the connection's origin, no shared secret, and no signature. Since `EventReceiver::main_loop` treats `EventError::Terminated` as a clean exit (`break`), any TCP peer that can reach the signer's bound event-ingestion port can permanently stop the signer's event loop with a single request.

### Finding Description
The intended trust model is that only the local `SignerStopSignaler::send` (used by the node/signer process that owns this `SignerEventReceiver` instance) should be able to terminate `main_loop`, via a self-connect back to its own `local_addr`. In practice, the `/shutdown` branch performs no authentication check whatsoever: [1](#0-0) 

The path dispatch happens purely on `request.url() == "/shutdown"` and `request.method() == &HttpMethod::Post`, without verifying the request originates from `127.0.0.1`/the process's own stop-signaler, without a shared secret header, and without any cryptographic proof of origin. `HttpServer::http(listener)` (in `bind`) binds using whatever address is configured, and `tiny_http`'s `recv()` will accept requests from any TCP connection made to that socket, so if the signer's event-receiver endpoint is bound to a non-loopback interface (as `SignerStopSignaler::send`'s implementation—self-connecting via a full TCP handshake and HTTP request rather than an in-process flag—implies it must be a real network-reachable listener), a remote peer can simply do:

```
POST /shutdown HTTP/1.1
Host: <addr>
Connection: close
Content-Length: 3
Content-Type: text/plain

xyz
```

`next_event` matches `/shutdown`, sets the stop flag, and returns `Err(EventError::Terminated)`. Back in `main_loop`: [2](#0-1) 

the loop unconditionally `break`s, permanently exiting the signer's event-ingestion thread. No `Content-Length`/body validation, JSON parsing, or type check gates this branch — it fires purely off the URL/method match, unlike `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block` which at least attempt `process_event` deserialization. There is no origin-check equivalent to a node RPC secret or peer-auth handshake anywhere in this dispatch function.

### Impact Explanation
Any unauthenticated remote party capable of opening a TCP connection to the signer's event-receiver listening port can permanently disable that signer's ingestion of block proposals, burn-block events, and StackerDB chunk events with a single crafted HTTP POST. This is a Critical unauthenticated remote DoS: it silently removes the signer from block-signing rounds, since it will no longer observe miner block proposals or StackerDB gossip, without operator awareness unless external monitoring on the process is in place. It is fully repeatable and requires only one request per silenced signer instance.

### Likelihood Explanation
Preconditions: the attacker must merely be able to open a TCP connection to the signer's configured event-receiver bind address/port. No secret, peer key, or admin role is required — this fits squarely inside the unprivileged attacker model (arbitrary bytes to a reachable port). Attacker cost is a single crafted HTTP request. There is no rate limit or per-source restriction gating the `/shutdown` branch, so the exploit is deterministic and trivially repeatable against any signer whose port is reachable by the attacker.

### Recommendation
Do not gate shutdown solely on URL/method matching remote-controlled input. Options: (1) restrict acceptance of the `/shutdown` route to connections originating from a loopback address (verify the peer's `SocketAddr` via the underlying stream before honoring the request); (2) require a shared secret/token (e.g., matching a value only known to the local process, passed in a header or the body) that `SignerStopSignaler::send` includes and `next_event` verifies before honoring `/shutdown`; (3) replace the self-connect-over-TCP stop signal entirely with a purely in-process mechanism (e.g., a short listener timeout plus polling `stop_signal`, or waking the accept loop via a local Unix socket/pipe not reachable externally).

### Proof of Concept
```rust
// libsigner/src/events.rs (new test)
use std::net::TcpStream;
use std::io::Write;
use std::sync::atomic::Ordering;

#[test]
fn unauthenticated_remote_shutdown_terminates_event_receiver() {
    let mut receiver: SignerEventReceiver<crate::v0::messages::SignerMessage> =
        SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Attacker: unrelated TcpStream, NOT via SignerStopSignaler
    let mut attacker_stream = TcpStream::connect(addr).unwrap();
    let body = "attacker-controlled body";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        addr, body.len(), body
    );
    attacker_stream.write_all(req.as_bytes()).unwrap();

    // No SignerStopSignaler was used - only a raw remote TCP client hit /shutdown.
    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped()); // stop_signal flipped by an unauthenticated remote peer
}
```
This demonstrates that `next_event` returns `Err(EventError::Terminated)` and `stop_signal` is set purely from an unrelated remote TCP client's POST, with no verification against `SignerStopSignaler`'s ownership of the connection, confirming `main_loop` will `break` on the next iteration due to [2](#0-1) .
