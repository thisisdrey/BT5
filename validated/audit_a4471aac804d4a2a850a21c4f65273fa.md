### Title
Unbounded recursion in `cmd/compile/internal/syntax` expression parser via deeply nested parentheses causes stack overflow - ([File: src/cmd/compile/internal/syntax/parser.go])

### Summary
The Go compiler's own source-code parser (`cmd/compile/internal/syntax`) parses expressions with mutually recursive functions — `expr` → `binaryExpr` → `unaryExpr` → `pexpr` → `operand` → (on `(`) back into `expr` — with no recursion-depth limit. A `.go` source file containing an expression wrapped in enough nested parentheses (`((((((...1...))))))`) drives this cycle until the goroutine stack is exhausted, crashing `go build`/`gofmt`/`go vet` on that file. This mirrors exactly the KCL advisory's `expression → unnecessarily_bracketed → expression` recursive-descent pattern.

### Finding Description
Untrusted/malicious `.go` source (e.g., a file inside a fetched module, or one a developer is asked to build/format/vet) is the attacker input. The entry point is `cmd/compile/internal/syntax` parsing (used by `go build`, and equivalently `go/parser` is used by `gofmt`, `go vet`, etc.). Parenthesized operands are parsed at `operand()`'s `_Lparen` case, which calls `p.expr()` recursively: [1](#0-0) 
`expr()` flows to `binaryExpr` → `unaryExpr` → `pexpr` → `operand`, and `unaryExpr` falls through to `p.pexpr(nil, true)` with no depth counter: [2](#0-1) 

I confirmed there is **no** `nestLev`/`maxNestLev`/`incNestLev` mechanism anywhere in `src/cmd/compile/internal/syntax/*.go` — a repo-wide grep for those symbols in that package returned zero matches. By contrast, the sibling package `go/parser` (used for source analysis tooling, `gofmt`, `go vet`, etc.) *does* guard exactly this recursive pattern: it tracks `nestLev` in the parser struct and calls `incNestLev`/`decNestLev` in `parseUnaryExpr` and `parseBinaryExpr`, bailing out via `panic(bailout{})` once `nestLev > maxNestLev (1e5)`: [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

`text/template/parse` also independently added this exact guard (`maxStackDepth`) for the identical `'(' pipeline ')'` recursive case: [7](#0-6) [8](#0-7) 

This strongly indicates the pattern is a recognized, previously-fixed bug class in Go's own parsers — but the fix was never applied to `cmd/compile/internal/syntax`, the parser actually used by the `go` toolchain to compile source files.

### Impact Explanation
A crafted `.go` file with sufficiently deep parenthesis nesting causes the compiler's parser goroutine to recurse until the OS thread stack limit is hit, producing a runtime stack-overflow crash (`runtime: goroutine stack exceeds ... limit`) rather than a graceful syntax error. This is a genuine parser-panic/crash on malicious input consumable via a normal `go build` workflow (e.g., building a module that contains such a file), which the Go project's own precedent (the `go/parser` and `text/template/parse` fixes) treats as worth guarding against. This would be a PUBLIC-track denial-of-service bug in the compiler frontend, not a memory-safety or code-execution issue.

### Likelihood Explanation
Victim workflow: a developer or CI system runs `go build`, `go vet`, or any tool that invokes `cmd/compile/internal/syntax.Parse` on a source file they did not fully control (e.g., a dependency, a generated file, or a file accepted from an external contribution/PR). The attacker only needs to supply ordinary Go source text with no special privileges — matching the "ordinary published/consumed source" premise. No authentication or environment control is required.

### Recommendation
Add the same `nestLev`/`maxNestLev` (or equivalent) recursion-depth guard used in `go/parser.parseUnaryExpr`/`parseBinaryExpr` to the corresponding recursive entry points in `cmd/compile/internal/syntax/parser.go` (`expr`, `binaryExpr`, `unaryExpr`, `pexpr`/`operand`), causing the parser to emit a syntax error and bail out (e.g., via the existing `bailout`/panic-recovery mechanism already used for other parser errors) once a bounded nesting depth is exceeded, instead of recursing unboundedly.

import (
	"strings"
	"testing"

	"cmd/compile/internal/syntax"

// TestDeeplyNestedParenExprStackOverflow demonstrates that parsing an
// expression with a very large number of nested parentheses causes
// unbounded recursion (expr -> operand -> expr ...) with no depth guard,
// unlike go/parser's incNestLev/decNestLev-protected equivalent.
func TestDeeplyNestedParenExprStackOverflow(t *testing.T) {
	depth := 2_000_000
	src := "package p\nvar x = " + strings.Repeat("(", depth) + "1" + strings.Repeat(")", depth) + "\n"

	// Expected (fixed) behavior: syntax.Parse returns a syntax error
	// ("exceeded max nesting depth" or similar) instead of crashing.
	//
	// Actual (vulnerable) behavior: the parser recurses through
	// expr -> operand -> expr for each '(' with no depth counter,
	// exhausting the goroutine stack and crashing the process
	// (fatal error: stack overflow) before this assertion is reached.
	_, err := syntax.Parse(syntax.NewFileBase("test.go"), strings.NewReader(src), nil, nil, 0)
	if err == nil {
		t.Fatalf("expected a syntax error for excessively nested parentheses, got nil (process should not crash)")
	}
}

func (p *parser) unaryExpr() Expr {
	if trace {
		defer p.trace("unaryExpr")()
	}

	switch p.tok {
	case _Operator, _Star:
		switch p.op {
		case Mul, Add, Sub, Not, Xor, Tilde:
			x := new(Operation)
			x.pos = p.pos()
			x.Op = p.op
			p.next()
			x.X = p.unaryExpr()
			return x

		case And:
			x := new(Operation)
			x.pos = p.pos()
			x.Op = And
			p.next()
			// unaryExpr may have returned a parenthesized composite literal
			// (see comment in operand) - remove parentheses if any
			x.X = Unparen(p.unaryExpr())
			return x
		}

	case _Arrow:
		// receive op (<-x) or receive-only channel (<-chan E)
		pos := p.pos()
		p.next()

		// If the next token is _Chan we still don't know if it is
		// a channel (<-chan int) or a receive op (<-chan int(ch)).
		// We only know once we have found the end of the unaryExpr.

		x := p.unaryExpr()

		// There are two cases:
		//
		//   <-chan...  => <-x is a channel type
		//   <-x        => <-x is a receive operation
		//
		// In the first case, <- must be re-associated with
		// the channel type parsed already:
		//
		//   <-(chan E)   =>  (<-chan E)
		//   <-(chan<-E)  =>  (<-chan (<-E))

		if _, ok := x.(*ChanType); ok {
			// x is a channel type => re-associate <-
			dir := SendOnly
			t := x
			for dir == SendOnly {
				c, ok := t.(*ChanType)
				if !ok {
					break
				}
				dir = c.Dir
				if dir == RecvOnly {
					// t is type <-chan E but <-<-chan E is not permitted
					// (report same error as for "type _ <-<-chan E")
					p.syntaxError("unexpected <-, expected chan")
					// already progressed, no need to advance
				}
				c.Dir = RecvOnly
				t = c.Elem
			}
			if dir == SendOnly {
				// channel dir is <- but channel element E is not a channel
				// (report same error as for "type _ <-chan<-E")
				p.syntaxError(fmt.Sprintf("unexpected %s, expected chan", String(t)))
				// already progressed, no need to advance
			}
			return x
		}

		// x is not a channel type => we have a receive op
		o := new(Operation)
		o.pos = pos
		o.Op = Recv
		o.X = x
		return o
	}

	// TODO(mdempsky): We need parens here so we can report an
	// error for "(x) := true". It should be possible to detect
	// and reject that more efficiently though.
	return p.pexpr(nil, true)

// maxNestLev is the deepest we're willing to recurse during parsing
const maxNestLev int = 1e5

func incNestLev(p *parser) *parser {
	p.nestLev++
	if p.nestLev > maxNestLev {
		p.error(p.pos, "exceeded max nesting depth")
		panic(bailout{})
	}
	return p
}

// decNestLev is used to track nesting depth during parsing to prevent stack exhaustion.
// It is used along with incNestLev in a similar fashion to how un and trace are used.
func decNestLev(p *parser) {
	p.nestLev--
}

func (p *parser) parseUnaryExpr() ast.Expr {
	defer decNestLev(incNestLev(p))

	if p.trace {
		defer un(trace(p, "UnaryExpr"))
	}

	switch p.tok {
	case token.ADD, token.SUB, token.NOT, token.XOR, token.AND, token.TILDE:
		pos, op := p.pos, p.tok
		p.next()
		x := p.parseUnaryExpr()
		return &ast.UnaryExpr{OpPos: pos, Op: op, X: x}

func (p *parser) parseBinaryExpr(x ast.Expr, prec1 int) ast.Expr {
	if p.trace {
		defer un(trace(p, "BinaryExpr"))
	}

	if x == nil {
		x = p.parseUnaryExpr()
	}
	// We track the nesting here rather than at the entry for the function,
	// since it can iteratively produce a nested output, and we want to
	// limit how deep a structure we generate.
	var n int
	defer func() { p.nestLev -= n }()
	for n = 1; ; n++ {
		incNestLev(p)
		op, oprec := p.tokPrec()
		if oprec < prec1 {
			return x
		}
		pos := p.expect(op)
		y := p.parseBinaryExpr(nil, oprec+1)
		x = &ast.BinaryExpr{X: x, OpPos: pos, Op: op, Y: y}
	}
}
