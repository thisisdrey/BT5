## Title
Staking-async marks reward pages as claimed before verifying the transfer succeeded, permanently losing rewards on transfer failure - (File: `substrate/frame/staking-async/src/pallet/impls.rs`)

### Summary
`Pallet::do_payout_stakers_by_page` marks a validator/era/page combination as claimed via `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` *before* the actual reward transfers to the validator and its nominators are attempted. The transfers are performed later by `Self::payout_from_provider` → `Self::make_payout_from_provider`, which silently swallows any `Currency::transfer` failure (logging an error and returning `None`) instead of propagating it. Because the page is already marked claimed, and the dispatchable still returns `Ok(...)`, a failed transfer permanently and silently drops that staker's reward for the era/page with no possibility of retry — the exact "swallowed revert followed by state update" pattern described in the external report.

### Finding Description
In `do_payout_stakers_by_page`: [1](#0-0) 

`set_rewards_as_claimed` is invoked unconditionally right after the `AlreadyClaimed` check, well before any value is actually moved. The function then proceeds to compute payouts and dispatches them: [2](#0-1) 

The actual settlement happens in `payout_from_provider`, which loops over the validator and every nominator in the page and calls `make_payout_from_provider` for each: [3](#0-2) 

`make_payout_from_provider` performs the actual `T::Currency::transfer` from the era reward pot to the payee. If the transfer errors (e.g. `ExistentialDeposit` failure when a nominator's prorated reward is below the ED and the destination account does not yet exist, or the pot's reducible balance is insufficient), the function only logs the error and returns `None` — it does not propagate a `DispatchError` and does not revert: [4](#0-3) 

Back in the caller, a `None` return simply skips emitting the `Rewarded` event and skips incrementing `nominator_payout_count` — it does not stop or roll back the enclosing extrinsic, which still returns `Ok(...)` with the page already flagged as claimed: [5](#0-4) 

Since `ClaimedRewards`/paged claim state was already persisted at line 386 for the whole page (validator + all nominators in it), any subsequent attempt to pay out that era/page is rejected outright: [6](#0-5) 

This matches the Sherlock analog precisely: an internal, swallowed failure of an external-value-moving operation is followed by an irreversible state update (claim flag) that forecloses any retry, causing silent, permanent loss of the intended payout.

### Impact Explanation
Any nominator (or validator) whose prorated reward transfer fails for that era/page loses that reward permanently: the page is marked claimed, so `payout_stakers`/`payout_stakers_by_page` can never be called again for it (`Error::AlreadyClaimed`), and there is no other path in the pallet to re-attempt or credit the missed amount. This is a direct, silent conservation-of-value violation: staking-async's fungible pot loses less than expected but nominators receive nothing, with no on-chain error signaling failure to the caller of the dispatchable (the extrinsic returns `Ok`). This aligns with the "balances/staking/rewards must conserve value and settle exactly once to the rightful beneficiary" pivot — here it settles zero times instead of once.

### Likelihood Explanation
This does not require a malicious validator, governance actor, or privileged access — it is triggered by ordinary, permissionless calls to `payout_stakers`/`payout_stakers_by_page`, callable by any signed account for any validator/era/page. The failure condition (destination account not yet existing and reward amount below `ExistentialDeposit`, which is common for validators with many small nominators up to `MaxExposurePageSize`, or reward pot underfunded relative to `ErasValidatorReward` bookkeeping) is a realistic, naturally occurring scenario rather than a contrived edge case, making this a persistent risk across normal reward-payout activity.

### Recommendation
Reorder the logic so `set_rewards_as_claimed` (or an equivalent "settled" flag) is only persisted after all transfers for the page have been attempted and their outcomes are known. Either (a) make the extrinsic fail atomically (rolling back the whole page, including the claim flag) if any individual transfer fails, so the page can be retried later, or (b) explicitly track and expose per-account failed payouts (e.g. via a dedicated storage item / event that can be reconciled/re-driven) rather than silently discarding the failed transfer while marking the page as fully claimed. At minimum, do not allow `do_payout_stakers_by_page` to return `Ok` while `nominator_payout_count`/validator payout diverges from what was expected without a durable, retryable record of the shortfall.

### Proof of Concept
1. Set up a validator `V` in staking-async with nominators such that at least one nominator `N`'s prorated `nominator_reward` for a given page is smaller than `ExistentialDeposit`, and ensure `N`'s reward-destination account does not already exist/hold a balance (fresh `Account(N)` destination).
2. Have the era reward pot for `RewardKind::StakerRewards` funded normally via `snapshot_era_rewards`.
3. Call `Staking::payout_stakers_by_page(origin, V, era, page)`.
4. Observe: `Eras::<T>::set_rewards_as_claimed(era, &V, page)` runs at the top of `do_payout_stakers_by_page` (impls.rs:386); the extrinsic returns `Ok(...)`.
5. Inside `payout_from_provider` → `make_payout_from_provider`, `T::Currency::transfer` to `N` fails with an ED-related error (impls.rs:602-616); this is only logged, `Rewarded` is not emitted for `N`, but the function returns without error.
6. Re-invoke `payout_stakers_by_page(origin, V, era, page)`: it returns `Error::<T>::AlreadyClaimed`, confirming `N`'s reward for that era/page is permanently unclaimable and lost.

	/// Payout stakers from an era reward pot (transfer-based, no minting).
	fn payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		validator_payout: BalanceOf<T>,
		exposure: &crate::PagedExposure<T::AccountId, BalanceOf<T>>,
		overview_own: BalanceOf<T>,
		total_nominator_payout: BalanceOf<T>,
	) -> u32 {
		let mut nominator_payout_count: u32 = 0;

		if let Some((amount, dest)) = Self::make_payout_from_provider(era, stash, validator_payout)
		{
			Self::deposit_event(Event::<T>::Rewarded { stash: stash.clone(), dest, amount });
		}

		let total_nominator_stake = exposure.total().saturating_sub(overview_own);
		for nominator in exposure.others().iter() {
			let nominator_exposure_part =
				Perbill::from_rational(nominator.value, total_nominator_stake);
			let nominator_reward: BalanceOf<T> =
				nominator_exposure_part.mul_floor(total_nominator_payout);

			if let Some((amount, dest)) =
				Self::make_payout_from_provider(era, &nominator.who, nominator_reward)
			{
				nominator_payout_count.saturating_inc();
				Self::deposit_event(Event::<T>::Rewarded {
					stash: nominator.who.clone(),
					dest,
					amount,
				});
			}
		}

		nominator_payout_count
	}

	/// Make a payment to a staker from an era reward pot (transfer, not mint).
	fn make_payout_from_provider(
		era: EraIndex,
		stash: &T::AccountId,
		amount: BalanceOf<T>,
	) -> Option<(BalanceOf<T>, RewardDestination<T::AccountId>)> {
		if amount.is_zero() {
			return None;
		}

		let dest = match Self::payee(Stash(stash.clone())) {
			Some(d) => d,
			None => {
				Self::deposit_event(Event::<T>::Unexpected(UnexpectedKind::MissingPayee {
					era,
					stash: stash.clone(),
				}));
				return None;
			},
		};

		let payout_account = Self::payout_account_for_dest(stash, &dest)?;

		let staker_rewards_pot =
			T::RewardPots::pot_account(RewardPot::Era(era, RewardKind::StakerRewards));
		if let Err(e) = T::Currency::transfer(
			&staker_rewards_pot,
			&payout_account,
			amount,
			Preservation::Expendable,
		) {
			log!(
				error,
				"Failed to transfer reward from pot for era {:?}, stash {:?}: {:?}",
				era,
				stash,
				e
			);
			return None;
		}
