### Title
Old Operator's Beneficiary Bypassed in `distribute_internal` After `switch_operator` — (`File: aptos-move/framework/aptos-framework/sources/staking_contract.move`)

---

### Summary

In `staking_contract.move`, when a staker calls `switch_operator`, the function records the old operator's pending commission into the `distribution_pool` under the **old operator's address** via `request_commission_internal`. After the switch, the staking contract is keyed under the **new operator**. When `distribute` is later called (with `new_operator`), `distribute_internal` receives `operator = new_operator` and applies the beneficiary redirect only when `recipient == operator`. Because the distribution pool still holds shares attributed to `old_operator`, the equality check fails, and the commission is paid directly to `old_operator`'s raw address — **bypassing any beneficiary set by `old_operator` via `set_beneficiary_for_operator`**.

---

### Finding Description

**Step 1 — Commission recorded under old operator's address.**

Inside `switch_operator`, after distributing already-inactive stake, `request_commission_internal` is called with `old_operator`:

```move
request_commission_internal(
    old_operator,
    &mut staking_contract,
);
``` [1](#0-0) 

`request_commission_internal` calls `add_distribution(operator, staking_contract, operator, commission_amount)`, which buys shares in the `distribution_pool` keyed to `old_operator`:

```move
add_distribution(
    operator,          // old_operator
    staking_contract,
    operator,          // recipient = old_operator
    commission_amount
);
``` [2](#0-1) 

The commission is also unlocked from the stake pool (`pending_inactive`), so it will become withdrawable after the lockup expires.

**Step 2 — Staking contract re-keyed under new operator.**

```move
staking_contracts.add(new_operator, staking_contract);
``` [3](#0-2) 

The `distribution_pool` (embedded in `staking_contract`) now lives under `new_operator`'s key, but still holds shares attributed to `old_operator`.

**Step 3 — Beneficiary check uses `new_operator`, not `old_operator`.**

When `distribute(staker, new_operator)` is called after lockup expires, `distribute_internal` is invoked with `operator = new_operator`. The payout loop is:

```move
if (recipient == operator) {          // operator = new_operator
    recipient = beneficiary_for_operator(operator);
};
``` [4](#0-3) 

`recipient` is `old_operator` (from the distribution pool shares). Since `old_operator != new_operator`, the condition is **false**. `beneficiary_for_operator(old_operator)` is **never called**. The commission is deposited directly to `old_operator`'s address.

**Confirmed by existing test:**

The test `test_staker_can_switch_operator` explicitly asserts that after a switch, operator 1's commission lands at `operator_1_address` directly:

```move
let operator_1_balance = coin::balance<AptosCoin>(operator_1_address);
assert!(
    operator_1_balance == INITIAL_BALANCE + commission_for_operator_1,
    operator_1_balance
);
``` [5](#0-4) 

No test covers the case where `old_operator` has a beneficiary set at the time of the switch and commission is still pending.

---

### Impact Explanation

If `old_operator` has called `set_beneficiary_for_operator` to designate a beneficiary address (e.g., a treasury contract, a multisig, or a separate payout address), and the staker calls `switch_operator` while commission is accrued but not yet distributed, the pending commission bypasses the beneficiary and is deposited to `old_operator`'s raw address. The beneficiary loses their entitled commission. This is an unauthorized reassignment of staking commission — funds that should flow to the beneficiary are instead diverted to the operator address. [6](#0-5) 

---

### Likelihood Explanation

- `set_beneficiary_for_operator` is a live, gated-by-feature-flag public entry function callable by any operator.
- `switch_operator` is a public entry function callable by any staker at any time.
- No coordination between staker and operator is required; the staker alone can trigger the switch.
- Commission accrues every epoch, so there is almost always a non-zero pending commission at any given moment.
- The staker has no financial incentive to prevent this — the commission goes to the operator's address rather than the beneficiary, which does not benefit the staker but does harm the beneficiary.

---

### Recommendation

In `distribute_internal`, replace the narrow identity check with a lookup that covers **any** address that has a registered beneficiary, not just the current operator:

```move
// Current (broken after operator switch):
if (recipient == operator) {
    recipient = beneficiary_for_operator(operator);
};

// Fixed: check if the recipient itself has a beneficiary registered
if (exists<BeneficiaryForOperator>(recipient)) {
    recipient = beneficiary_for_operator(recipient);
};
```

This ensures that regardless of whether the recipient is the current operator or a former operator whose commission is still pending in the pool, the beneficiary redirect is applied correctly. [4](#0-3) 

---

### Proof of Concept

1. `staker` creates a staking contract with `operator_1` at 10% commission.
2. `operator_1` calls `set_beneficiary_for_operator(beneficiary)`.
3. The stake pool earns rewards over one epoch; commission accrues but is **not** distributed.
4. `staker` calls `switch_operator(operator_1, operator_2, 10)`.
   - Internally, `request_commission_internal(operator_1, ...)` adds commission shares for `operator_1` to the distribution pool.
   - The staking contract is re-keyed under `operator_2`.
5. The lockup expires; `distribute(staker, operator_2)` is called.
   - `distribute_internal` runs with `operator = operator_2`.
   - The distribution pool yields `recipient = operator_1`.
   - `operator_1 != operator_2` → beneficiary check skipped.
   - Commission is deposited to `operator_1`'s address.
6. **Result:** `beneficiary` receives 0 APT from this commission. `operator_1` receives the full commission amount that should have gone to `beneficiary`. [7](#0-6) [8](#0-7)

        staking_contract: &mut StakingContract,

        let pool_address = staking_contract.pool_address;
        // Create the Staker resource if it doesn't exist to backfill the Staker resource for each pool.
        if (!exists<Staker>(pool_address)) {
            let pool_signer =
                &account::create_signer_with_capability(&staking_contract.signer_cap);
            move_to(pool_signer, Staker { staker });
        };
        let (_, inactive, _, pending_inactive) = stake::get_stake(pool_address);
        let total_potential_withdrawable = inactive + pending_inactive;
        let coins =
            stake::withdraw_with_cap(
                &staking_contract.owner_cap, total_potential_withdrawable
            );
        let distribution_amount = coin::value(&coins);
        if (distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        let distribution_pool = &mut staking_contract.distribution_pool;
        update_distribution_pool(
            distribution_pool,
            distribution_amount,
            operator,
            staking_contract.commission_percentage
        );

        // Buy all recipients out of the distribution pool.
        while (distribution_pool.shareholders_count() > 0) {
            let recipients = distribution_pool.shareholders();
            let recipient = recipients[0];
            let current_shares = distribution_pool.shares(recipient);
            let amount_to_distribute =
                distribution_pool.redeem_shares(recipient, current_shares);
            // If the recipient is the operator, send the commission to the beneficiary instead.
            if (recipient == operator) {
                recipient = beneficiary_for_operator(operator);
