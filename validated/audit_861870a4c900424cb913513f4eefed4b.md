### Title
Cross-repository/quarantine-escape via OR-based `isTransactionQuarantineDir` check bypasses object-directory ownership validation - (File: internal/git/localrepo/paths.go)

### Summary
`Repo.ObjectDirectoryPath` in [1](#0-0)  determines whether a client-supplied `GitObjectDirectory` value is a "transaction quarantine directory" using a permissive OR condition, and when that OR is satisfied it skips the stricter ownership check that ties the object directory to the specific repository.

### Finding Description
The relevant logic is: [2](#0-1) 

`isTransactionQuarantineDir` is computed as `(baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))`. If this OR is true, the function entirely skips the `if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); ...` branch that would otherwise verify, via `storage.QuarantineDirectoryPrefix(repo)` (a SHA-1 hash of the repository's own relative path, see [3](#0-2) ), that the quarantine directory actually belongs to *this* repository.

Earlier in the function, the only bound placed on `objectDirectoryPath` is that it stays within the **storage root** (not the repository root): [4](#0-3) 

Because `storage.ValidateRelativePath` is only checked against `storagePath`, an attacker-controlled `GitObjectDirectory` such as `../../other-repo/some/quarantine` remains "valid" (it is still inside the storage), and its `filepath.Base()` is `"quarantine"`, which alone satisfies the OR condition on line 45. This causes the function to skip the repository-ownership check and directly return `filepath.Join(repoPath, objectDirectoryPath)` (line 77) as the object directory to operate on — which can point into a different repository's directory tree entirely, bypassing the quarantine-prefix isolation that this code is supposed to enforce.

This mirrors the reported bug class: a boolean check meant to gate access based on two related conditions uses OR where an AND (or an additional ownership check) is required, letting an attacker satisfy the weaker of two alternatives to bypass protection intended to apply to both.

### Impact Explanation
`GitObjectDirectory`/`GitAlternateObjectDirectories` are fields on the `Repository` protobuf message that is accepted directly by numerous RPCs (e.g. `GetObjectDirectorySize`, seen calling `ObjectDirectoryPath` directly in [5](#0-4) , plus mutator RPCs that build local repos with a quarantine directory). Any authenticated Gitaly client that can set this field (as GitLab Rails legitimately does when relaying quarantine information from `pre-receive`, and as any gRPC caller sending a crafted `Repository` message technically can) can point the "object directory" at another repository's storage path as long as the basename is literally `quarantine`. Depending on the calling RPC, this enables cross-repository object/data disclosure (e.g. computing/reading sizes of another repository's object directory) or, in RPCs that write objects, potential injection/corruption of another repository's object store — a violation of the storage isolation and quarantine sandboxing that Gitaly relies on for multi-tenant repository storage.

### Likelihood Explanation
The `ValidateRelativePath` bound only protects against escaping the *storage root*, not the *repository root*, so exploitation only requires crafting a relative path whose final path component is `quarantine` and which resolves to a sibling repository directory under the same storage — a straightforward, low-complexity manipulation of a single request field. No git object crafting, protocol race, or privileged internal access is required beyond the standard ability to issue Gitaly RPCs carrying a `Repository` message (the same threat model as any RPC caller relaying quarantine metadata during normal push/access-check flows).

### Recommendation
Do not let the OR-based `isTransactionQuarantineDir` shortcut bypass ownership verification. Always verify that the resolved `objectDirectoryPath` is scoped to the **repository's own directory** (not merely the storage root) via `storage.ValidateRelativePath(repoPath, objectDirectoryPath)`, and only exempt the ownership-prefix check for the exact, narrowly-matched transaction quarantine subpath (i.e., require both the repository-root containment check to pass AND a match against a repository-specific pattern) rather than short-circuiting all further validation when a loosely-matched `baseDir == "quarantine"` string comparison succeeds.

### Proof of Concept
Not independently executable from static analysis alone; conceptually:
1. Two repositories `repoA` (attacker-accessible) and `repoB` (victim) exist under the same storage.
2. Attacker issues `GetObjectDirectorySize(Repository{StorageName: storage, RelativePath: repoA, GitObjectDirectory: "../repoB.git/objects/quarantine"})` (or an equivalent RPC that calls `ObjectDirectoryPath`).
3. `storage.ValidateRelativePath(storagePath, filepath.Join(repoAPath, objectDirectoryPath))` succeeds because the resolved path is still within the storage root.
4. `filepath.Base(relativeObjectDirectoryPath) == "quarantine"` sets `isTransactionQuarantineDir = true`, skipping the `QuarantineDirectoryPrefix`/`ValidateRelativePath(repoPath, ...)` ownership check.
5. `ObjectDirectoryPath` returns a path inside `repoB`, and the RPC operates on `repoB`'s object directory despite the request being scoped to `repoA`.

I was not able to trace end-to-end which specific production RPC paths pass a fully attacker-controlled (as opposed to Gitaly/Rails-generated) `GitObjectDirectory` value without any additional interceptor-level sanitization, since access-check/interceptor code that might normalize or re-derive this field elsewhere was not fully inspected within the available tool budget; this should be verified further before treating exploitability as fully confirmed for a specific externally reachable RPC.

// ObjectDirectoryPath returns the full path of the object directory. The errors returned are gRPC
// errors with relevant error codes and should be passed back to gRPC without further decoration.
func (repo *Repo) ObjectDirectoryPath(ctx context.Context) (string, error) {
	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", err
	}

	objectDirectoryPath := repo.GetGitObjectDirectory()
	if objectDirectoryPath == "" {
		return "", structerr.NewInvalidArgument("object directory path is not set")
	}

	storagePath, err := repo.locator.GetStorageByName(ctx, repo.GetStorageName())
	if err != nil {
		return "", fmt.Errorf("get storage by name: %w", err)
	}

	// Ensure the path points somewhere in the storage.
	relativeObjectDirectoryPath, err := storage.ValidateRelativePath(storagePath, filepath.Join(repoPath, objectDirectoryPath))
	if err != nil {
		return "", structerr.NewInvalidArgument("validate relative path: %w", err)
	}

	parentDir := filepath.Base(filepath.Dir(relativeObjectDirectoryPath))
	baseDir := filepath.Base(relativeObjectDirectoryPath)
	isTransactionQuarantineDir := (baseDir == "quarantine") || ((parentDir == "quarantine") && strings.HasPrefix(baseDir, "tmp_objdir"))

	// Transactions quarantine a repository by pointing the object directory to a 'quarantine' named
	// directory in the transaction's temporary directory. If the base directory is `quarantine`,
	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.
	if !isTransactionQuarantineDir {
		// We need to check whether the relative object directory as given by the repository is
		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
		// created by git-receive-pack(1). Alternatively, if that is not the case, then it may be a
		// manual object quarantine directory located in the storage's temporary directory. These
		// have a repository-specific prefix which we must check in order to determine whether the
		// quarantine directory does in fact belong to the repo at hand.
		if _, origError := storage.ValidateRelativePath(repoPath, objectDirectoryPath); origError != nil {
			tempDir, err := repo.locator.TempDir(repo.GetStorageName())
			if err != nil {
				return "", structerr.NewInvalidArgument("getting storage's temporary directory: %w", err)
			}

			expectedQuarantinePrefix := filepath.Join(tempDir, storage.QuarantineDirectoryPrefix(repo))
			absoluteObjectDirectoryPath := filepath.Join(repoPath, objectDirectoryPath)

			// The relative path is outside of the repository
			if !strings.HasPrefix(absoluteObjectDirectoryPath, expectedQuarantinePrefix) {
				return "", structerr.NewInvalidArgument("not a valid relative path: %w", origError)
			}
		}
	}

	fullPath := filepath.Join(repoPath, objectDirectoryPath)
	if _, err := os.Stat(fullPath); os.IsNotExist(err) {
		return "", structerr.NewNotFound("object directory does not exist: %q", fullPath)
	}

	return fullPath, nil
}

func (s *server) GetObjectDirectorySize(ctx context.Context, in *gitalypb.GetObjectDirectorySizeRequest) (*gitalypb.GetObjectDirectorySizeResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}
	repo := s.localRepoFactory.Build(repository)

	path, err := repo.ObjectDirectoryPath(ctx)
	if err != nil {
		return nil, err
	}
	// path is the objects directory path, not repo's path
	sizeInBytes, err := dirSizeInBytes(path, snapshot.NewDefaultFilter(ctx))
	if err != nil {
		return nil, fmt.Errorf("calculating directory size: %w", err)
	}

	return &gitalypb.GetObjectDirectorySizeResponse{Size: sizeInBytes / 1024}, nil
}
