Found the analog. `RouteRepositoryMaintenance` in `internal/praefect/router_per_repository.go` routes `OpMaintenance` RPCs (like `OptimizeRepository`) to **every healthy, assigned replica** — including replicas that are inconsistent/behind the primary — without any consistency ("read-only") check, whereas `RouteRepositoryMutator` explicitly enforces `ErrRepositoryReadOnly` when the primary isn't in the consistent-storages set.

### Title
Maintenance RPCs bypass Praefect's read-only/consistency gate and can write on stale replicas - (File: internal/praefect/router_per_repository.go)

### Summary
Praefect's "read-only mode" is the guarded-launch/pause analog for a repository: when a replica's generation lags the primary, `RouteRepositoryMutator` refuses to route write RPCs and returns `ErrRepositoryReadOnly`. However, `OpMaintenance`-scoped RPCs (e.g. `OptimizeRepository`, `PruneUnreachableObjects`) go through a separate routing function, `RouteRepositoryMaintenance`, which has no such consistency check at all.

### Finding Description
`RouteRepositoryMutator` checks `consistentStorages.HasValue(primary)` and returns `ErrRepositoryReadOnly` if the primary is not up to date [1](#0-0) . This is the mechanism that stops writes from being applied while a repository is in a "paused"/inconsistent state, and it's also what `TestStreamDirectorReadOnlyEnforcement` exercises for `RefService/DeleteRefs` [2](#0-1) .

`RouteRepositoryMaintenance`, used for maintenance-scoped RPCs, instead iterates every replica listed in the repository's metadata and routes to any that is healthy and assigned, entirely independent of `consistentStorages`/generation checks: [3](#0-2) . The comment even says "route the maintenance call to all healthy nodes in a best-effort strategy," with no mention of consistency gating.

`OptimizeRepository` is annotated as a maintenance RPC, and Gitaly's own storage manager explicitly documents that it "invokes the housekeeping manager that starts its own write transactions if necessary" — it is forced to look like a read-only op at the *local* Gitaly transaction layer purely so the local snapshot machinery is happy, not because it can't mutate on-disk state: [4](#0-3) . The actual write path (pack-refs, repacking, commit-graph writes, pruning) runs via `RepositoryManager.OptimizeRepository`/`runInTransaction`, which begins its own write transaction against the target replica directly on whichever Gitaly node the RPC was routed to [5](#0-4) .

Because `RouteRepositoryMaintenance` has no `consistentStorages` gate, a client (or Rails/GitLab background jobs) issuing `OptimizeRepository`/`PruneUnreachableObjects` for a repository whose replica set includes an out-of-date secondary will have that maintenance RPC fanned out to the stale replica too, and it will perform real write-transactions (repack, prune, commit-graph rewrite) there — the exact class of bug in the report: state-mutating public/external calls that are not gated by the mechanism ("read-only"/pause) meant to guard all state changes.

### Impact Explanation
This lets maintenance operations perform destructive writes (object pruning, ref/pack rewriting) on a replica Praefect has flagged as inconsistent/read-only, corrupting or diverging that replica further and making later reconciliation/replication (which relies on generation numbers to decide what's authoritative) unreliable. It undermines the read-only invariant that the rest of the system (and operators trying to recover from an inconsistent-replica situation) rely on, matching the report's core complaint that some public state-mutating entry points are not covered by the pause/read-only guard even though most write paths are.

### Likelihood Explanation
`OptimizeRepository`/`PruneUnreachableObjects` are ordinary Gitaly RPCs invoked routinely (GitLab schedules housekeeping, and clients can call them directly through the gRPC API); no privileged access is required, and stale/inconsistent replicas are a normal, expected operational state (that's the entire reason `ErrRepositoryReadOnly` exists). Reaching this path only requires a repository that currently has an inconsistent secondary and issuing a maintenance RPC against it.

### Recommendation
Apply the same `consistentStorages`/generation consistency check used in `RouteRepositoryMutator` to `RouteRepositoryMaintenance` — either skip inconsistent replicas when building the maintenance route, or reuse `ErrRepositoryReadOnly` semantics per-target-node instead of routing maintenance writes to every healthy, assigned replica regardless of consistency state.

### Proof of Concept
1. Create a repository with a primary and at least one secondary; force the secondary's generation to lag (e.g., simulate a failed replication so `GetConsistentStoragesByRepositoryID` excludes it) — this is the same setup `TestStreamDirectorReadOnlyEnforcement` uses to prove `RouteRepositoryMutator` returns `ErrRepositoryReadOnly` [6](#0-5) .
2. Instead of calling `RefService/DeleteRefs` (a mutator), call `RepositoryService/OptimizeRepository` against the virtual repository.
3. Observe that `RouteRepositoryMaintenance` is invoked [7](#0-6) , which has no consistency filter and will include the stale secondary in `nodes` as long as it is `healthy` and `Assigned`.
4. The RPC is dispatched to that stale replica, where `RepositoryManager.OptimizeRepository` begins and commits a real write transaction (pack-refs/repack/prune) against it [8](#0-7) , mutating a replica that the read-only gate was supposed to protect.

Note: I was not able to fully trace how `RouteRepositoryMaintenance`'s result is consumed by the coordinator's stream director (e.g., whether it fans out to all returned nodes concurrently or sequentially) due to remaining tool-call budget; this would be worth confirming in a full session to nail down the exact blast radius per call.

// RouteRepositoryMaintenance will route the maintenance call to all healthy nodes in a best-effort
// strategy. We do not raise an error in case the primary node is unhealthy, but will in case all
// nodes are unhealthy.
func (r *PerRepositoryRouter) RouteRepositoryMaintenance(ctx context.Context, virtualStorage, relativePath string) (RepositoryMaintenanceRoute, error) {
	healthyNodes, err := r.healthyNodes(virtualStorage)
	if err != nil {
		return RepositoryMaintenanceRoute{}, err
	}

	healthyNodesByStorage := map[string]RouterNode{}
	for _, healthyNode := range healthyNodes {
		healthyNodesByStorage[healthyNode.Storage] = healthyNode
	}

	metadata, err := r.rs.GetRepositoryMetadataByPath(ctx, virtualStorage, relativePath)
	if err != nil {
		return RepositoryMaintenanceRoute{}, fmt.Errorf("getting repository metadata: %w", err)
	}

	nodes := make([]RouterNode, 0, len(metadata.Replicas))
	for _, replica := range metadata.Replicas {
		node, ok := healthyNodesByStorage[replica.Storage]
		if !ok {
			continue
		}

		// If the is not assigned to the replica it either hasn't yet been created
		// or it will eventually get deleted. In neither case does it make sense to
		// maintain it, so we skip such nodes.
		if !replica.Assigned {
			continue
		}

		// If the repository doesn't exist on the replica there is no need to perform any
		// maintenance tasks at all.
		if replica.Generation < 0 {
			continue
		}

		nodes = append(nodes, node)
	}

	if len(nodes) == 0 {
		return RepositoryMaintenanceRoute{}, ErrNoHealthyNodes
	}

	return RepositoryMaintenanceRoute{
		RepositoryID: metadata.RepositoryID,
		ReplicaPath:  metadata.ReplicaPath,
		Nodes:        nodes,
	}, nil

// forceReadOnly forces an RPC to treated as a read-only even if it not an accessor.
var forceReadOnly = map[string]bool{
	// OptimizeRepository invokes the housekeeping manager that starts its own write
	// transactions if necessary. The RPC itself doesn't need to be considered a write
	// for that reason.
	gitalypb.RepositoryService_OptimizeRepository_FullMethodName: true,

func isReadOnly(info protoregistry.MethodInfo) bool {
	return info.Operation == protoregistry.OpAccessor || forceReadOnly[info.FullMethodName()]

func (m *RepositoryManager) maybeStartTransaction(ctx context.Context, repo *localrepo.Repo, run func(context.Context, storage.Transaction, *localrepo.Repo) error) error {
	if m.node == nil {
		return run(ctx, nil, repo)
	}

	return m.runInTransaction(ctx, "housekeeping/heuristics", true, repo, run)
}

func (m *RepositoryManager) runInTransaction(ctx context.Context, transactionName string, readOnly bool, repo *localrepo.Repo, run func(context.Context, storage.Transaction, *localrepo.Repo) error) (returnedErr error) {
	originalRepo := &gitalypb.Repository{
		StorageName:  repo.GetStorageName(),
		RelativePath: repo.GetRelativePath(),
	}
	if tx := storage.ExtractTransaction(ctx); tx != nil {
		originalRepo = tx.OriginalRepository(originalRepo)
	}

	storageHandle, err := m.node.GetStorage(repo.GetStorageName())
	if err != nil {
		return fmt.Errorf("get storage: %w", err)
	}

	tx, err := storageHandle.Begin(ctx, storage.TransactionOptions{
		ReadOnly:     readOnly,
		RelativePath: originalRepo.GetRelativePath(),
	})
	if err != nil {
		return fmt.Errorf("begin: %w", err)
	}

	if err := run(
		storage.ContextWithTransaction(ctx, tx),
		tx,
		localrepo.NewFrom(repo, tx.RewriteRepository(originalRepo)),
	); err != nil {
		if rollbackErr := tx.Rollback(ctx); rollbackErr != nil {
			err = errors.Join(err, fmt.Errorf("rollback: %w", rollbackErr))
		}

		return fmt.Errorf("run: %w", err)
	}

	commitLSN, err := tx.Commit(ctx)
	if err != nil {
		return fmt.Errorf("commit: %w", err)
	}

	// No need to log the read-only transaction gathering the heuristics as
	// we're only interested in logging write transactions to identify conflicts.
	if !readOnly {
		storage.LogTransactionCommit(ctx, m.logger, commitLSN, transactionName)
	}

	return nil
}
