### Title
Symlink-based extraction escape in custom-hooks tar handling via `SetCustomHooks`/`RestoreCustomHooks` - (File: internal/gitaly/repoutil/custom_hooks.go)

### Summary
`ExtractHooks` in `internal/gitaly/repoutil/custom_hooks.go` extracts a user-supplied tar stream into the repository's temporary hooks directory by shelling out to the system `tar` binary with no restriction on entry types [1](#0-0) . The code implicitly assumes that the external `tar` implementation will "safely" refuse to create or follow symlinks that escape the target directory, in the same way the ERC777 report's `Escrow.withdraw` assumed that a token exposing an ERC777 interface would necessarily also implement a compatible ERC20 `transfer`. Just as that assumption failed for tokens without a `transfer` function, the assumption that a plain `tar -x` invocation prevents directory-escaping symlinks does not universally hold — the codebase's own test suite proves `custom_hooks` can be represented in a tar as a `tar.TypeSymlink` entry pointing to an arbitrary path [2](#0-1) , yet `ExtractHooks` never checks for or rejects symlink entries before or after invoking `tar`.

### Finding Description
`GetCustomHooks`/`GetCustomHooks` round-trips the `custom_hooks` directory as a tar archive and explicitly preserves symlink type flags (`tar.TypeSymlink`) and link targets when building the archive [2](#0-1) . The corresponding write path, `ExtractHooks`, is reachable from the `SetCustomHooks` and `RestoreCustomHooks` gRPC mutator RPCs, both of which accept a client-supplied tar stream for the target repository [3](#0-2) [4](#0-3) . Internally, `SetCustomHooks` calls `repoutil.SetCustomHooks`, which extracts the archive with `ExtractHooks` into a fresh temp directory before atomically swapping it into the repository's `custom_hooks` path [5](#0-4) .

`ExtractHooks` builds a `tar -xf - -C <path> --strip-components N custom_hooks` invocation and hands the client-controlled stream to it as stdin, with no argument such as `-p`/`--no-same-owner` restriction, no symlink filtering, and no post-extraction validation that extracted paths (including symlink targets) remain within `path` [1](#0-0) . Unlike the archive-extraction code in `internal/gitaly/service/repository/replicate.go`, which was hardened to explicitly reject absolute symlinks and validate that resolved relative symlink targets stay inside the extraction root [6](#0-5) , `ExtractHooks` performs none of these checks and instead defers entirely to whatever behavior the underlying `tar` binary provides — an unverified, environment-dependent assumption, mirroring the ERC777 report's core flaw of relying on an unguaranteed downstream capability.

Because a client can submit a `custom_hooks` tar entry as `tar.TypeSymlink` pointing outside the temp directory (e.g. to another location on the same filesystem writable by the Gitaly process), and because the same code path allows nested regular-file/directory entries inside `custom_hooks/`, an attacker-controlled tar can attempt the classic "tar-slip" pattern: a symlinked `custom_hooks` (or a symlinked subpath under it) redirecting subsequent extracted content outside the intended repository hooks directory.

### Impact Explanation
If exploitable, this allows an ordinary Gitaly client authorized to call `SetCustomHooks`/`RestoreCustomHooks` for a repository to write or overwrite files outside of that repository's `custom_hooks` directory on the Gitaly storage node, i.e. a storage/extraction escape. Because `custom_hooks` content is later executed as Git hooks (`pre-receive`, `update`, etc.) by the Gitaly host, escaping the intended directory could also enable placement of executable content in unexpected locations, compounding the impact beyond simple file corruption.

### Likelihood Explanation
`SetCustomHooks` is a standard mutator RPC exposed to any client with write access to a given repository (used, for example, by GitLab's custom-hooks/import features), so the entry point does not require any privileged or MITM position — it matches an "ordinary user" RPC-crafted-field scenario. The likelihood that the plain `tar` invocation in `ExtractHooks` is actually exploitable depends on the extraction semantics of the system `tar` binary in the deployed environment (GNU tar vs. BSD tar, and their default protections against symlink-based escapes), which I could not fully verify from the indexed source alone.

### Recommendation
Replace the shell-out to the system `tar` binary in `ExtractHooks` with the same explicit, in-process validation already used in `internal/gitaly/service/repository/replicate.go`'s `extractTarToDirectory`: reject absolute symlinks, resolve relative symlink targets against the extraction root and reject any that escape it, and validate every `header.Name`-derived target path stays within the destination directory before creating it [7](#0-6) . Do not rely on the invoked `tar` binary's default behavior as an implicit security boundary.

### Proof of Concept
Not fully verifiable from the indexed source alone: exploitability hinges on the exact flags/behavior of the `tar` binary used at extraction time in `ExtractHooks`, which isn't itself part of the gitaly repo and could not be inspected here. A concrete PoC would involve crafting a tar stream with a `custom_hooks` entry of `Typeflag: tar.TypeSymlink` and `Linkname` pointing outside the temp extraction directory (as constructed by `TestGetCustomHooks_symlink`'s pattern [2](#0-1) ), submitting it via the `SetCustomHooks` streaming RPC, and then verifying whether subsequent tar entries are written through the symlink outside the intended `custom_hooks` directory — this final verification step requires actually running the code with a specific `tar` implementation, which I could not do here.

func ExtractHooks(ctx context.Context, logger log.Logger, reader io.Reader, path string, stripPrefix bool) error {
	// GNU tar does not accept an empty file as a valid tar archive and produces
	// an error. Since an empty hooks tar is symbolic of a repository having no
	// hooks, the reader is peeked to check if there is any data present.
	buf := bufio.NewReader(reader)
	if _, err := buf.Peek(1); errors.Is(err, io.EOF) {
		return nil
	}

	stripComponents := "0"
	if stripPrefix {
		stripComponents = "1"
	}

	cmdArgs := []string{"-xf", "-", "-C", path, "--strip-components", stripComponents, CustomHooksDir}

	var stderrBuilder strings.Builder
	cmd, err := command.New(ctx, logger, append([]string{"tar"}, cmdArgs...),
		command.WithStdin(buf),
		command.WithStderr(&stderrBuilder))
	if err != nil {
		return fmt.Errorf("executing tar command: %w", err)
	}

func TestGetCustomHooks_symlink(t *testing.T) {
	t.Parallel()

	ctx := testhelper.Context(t)
	cfg := testcfg.Build(t)
	_, repoPath := gittest.CreateRepository(t, ctx, cfg, gittest.CreateRepositoryConfig{
		SkipCreationViaService: true,
	})

	linkTarget := "/var/empty"
	require.NoError(t, os.Symlink(linkTarget, filepath.Join(repoPath, "custom_hooks")), "Could not create custom_hooks symlink")

	var hooks bytes.Buffer
	require.NoError(t, GetCustomHooks(ctx, testhelper.NewLogger(t), repoPath, &hooks))

	reader := tar.NewReader(&hooks)
	file, err := reader.Next()
	require.NoError(t, err)

	require.Equal(t, "custom_hooks", file.Name, "tar entry name")
	require.Equal(t, byte(tar.TypeSymlink), file.Typeflag, "tar entry type")
	require.Equal(t, linkTarget, file.Linkname, "link target")

	_, err = reader.Next()
	require.Equal(t, io.EOF, err, "custom_hooks should have been the only entry")
}

// SetCustomHooks sets the git hooks for a repository. The hooks are sent in a
// tar archive containing a `custom_hooks` directory. This directory is
// ultimately extracted to the repository.
func (s *server) SetCustomHooks(stream gitalypb.RepositoryService_SetCustomHooksServer) error {
	ctx := stream.Context()

	firstRequest, err := stream.Recv()
	if err != nil {
		return structerr.NewInternal("getting first request: %w", err)
	}

	repo := firstRequest.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repo); err != nil {
		return structerr.NewInvalidArgument("%w", err)
	}

	reader := streamio.NewReader(func() ([]byte, error) {
		if firstRequest != nil {
			data := firstRequest.GetData()
			firstRequest = nil
			return data, nil
		}

		request, err := stream.Recv()
		return request.GetData(), err
	})

	if err := repoutil.SetCustomHooks(ctx, s.logger, s.locator, s.txManager, reader, repo); err != nil {
		return structerr.NewInternal("setting custom hooks: %w", err)
	}

	return stream.SendAndClose(&gitalypb.SetCustomHooksResponse{})
}
