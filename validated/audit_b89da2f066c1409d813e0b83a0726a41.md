### Title
Credential leak in cleartext logs via `FindRemoteRootRef` (and other remote-URL RPCs missing from `possibleGrpcMethods`) - ([File: internal/log/url_sanitizer.go])

### Summary
The `URLSanitizerHook` only redacts credentials embedded in URLs for the gRPC methods explicitly listed in `AddPossibleGrpcMethod` (`CreateRepositoryFromURL`, `FetchRemote`, `UpdateRemoteMirror`), registered in `internal/cli/gitaly/serve.go:165-169`. `FindRemoteRootRef` (`internal/gitaly/service/remote/find_remote_root_ref.go`) also accepts an attacker-controlled `RemoteUrl`/`ResolvedAddress` and passes it into `git remote show` via `gitcmd.Command`, but is absent from the allow-list, so any spawn/error log entries for that RPC are never passed through `sanitizeSpawnLog`/`sanitizeErrorLog`.

### Finding Description
`FindRemoteRootRef` takes `request.GetRemoteUrl()` directly from the client and uses it to build `git` config (`remote.inmemory.url`, `http.<url>.extraHeader`) and executes `git remote show inmemory` via `repo.Exec(...)` in `findRemoteRootRefCmd` (internal/gitaly/service/remote/find_remote_root_ref.go:17-51). Command execution logging (`internal/command/command.go`) attaches the command's `args` (and `grpc.method`) fields to logrus entries, and any failures propagate as an `error` field. The `URLSanitizerHook.Fire` (internal/log/url_sanitizer.go:33-53) only sanitizes `args`/`error`/`Message` fields when `entry.Data["grpc.method"]` matches one of the three whitelisted method names (internal/cli/gitaly/serve.go:165-169). Since `FindRemoteRootRef` is not in that list, if a credentialed URL (e.g. `https://user:secret@host/repo.git`) is supplied and the URL/config/args end up in a spawn or error log line, the secret is written to the Gitaly server log without redaction.

An unprivileged attacker who can trigger a "connect to remote" style repository action from GitLab Rails (e.g. importing/forking a project from a URL, or any user-facing flow that maps to `FindRemoteRootRef`) controls the `RemoteUrl` field of that RPC and can supply a credentialed URL designed to fail (invalid host, invalid auth, connection refused), causing git's own error output or the constructed remote URL to surface in the Gitaly server logs.

### Impact Explanation
This is an information-disclosure / credential-leak issue: secrets embedded in a remote URL supplied by the requester (or forwarded from GitLab Rails on the user's behalf) may be written verbatim into Gitaly's server-side logs, which are typically accessible to operators/support/log-aggregation systems with broader visibility than the requesting user should have. It matches the "credential disclosure" bounty impact class, though the actual credential value is one the attacker controls/knows in the simplest PoC (their own remote URL); the higher-value exploitation scenario is when GitLab Rails passes a URL containing a token that is not attacker-owned (e.g. a mirror pull URL with a project-level or admin-configured credential) into `FindRemoteRootRef`-adjacent flows, which would leak a secret the attacker does not otherwise know.

### Likelihood Explanation
The attacker needs no privileged Gitaly access — only the ability to trigger a gRPC call to `FindRemoteRootRef` with a URL they control, which is plausible for regular import/fork/remote-preview workflows in GitLab. Reaching an actual credential leak that matters (i.e., a secret the attacker doesn't already control) requires that GitLab Rails constructs the `RemoteUrl` server-side using a credential unknown to the attacker and passes it through this exact RPC and log path; whether such a Rails-side code path exists could not be confirmed from the Gitaly repo alone (Rails is out of scope), so likelihood for a *high-value* leak is uncertain/partial. The gap in the allow-list itself, however, is confirmed and directly reproducible in Gitaly's own log output.

### Recommendation
Add `FindRemoteRootRef` (and audit any other RPC accepting `RemoteUrl`/similar fields, e.g. mirror-related RPCs) to the `possibleGrpcMethods` allow-list in `internal/cli/gitaly/serve.go`, or better, replace the allow-list approach with a mechanism that always sanitizes URLs in `args`/`error`/message fields regardless of gRPC method, since maintaining a manually curated list is fragile and has already drifted from the actual set of RPCs handling remote URLs.

```go
func (hook *URLSanitizerHook) Fire(entry *logrus.Entry) error {
	mth, ok := entry.Data["grpc.method"]
	if !ok {
		return nil
	}

	mthStr, ok := mth.(string)
	if !ok || !hook.possibleGrpcMethods[mthStr] {
		return nil
	}

	if _, ok := entry.Data["args"]; ok {
		sanitizeSpawnLog(entry)
	} else if _, ok := entry.Data["error"]; ok {
		sanitizeErrorLog(entry)
	} else {
		entry.Message = sanitizeString(entry.Message)
	}

	return nil
}
```

```go
func (s *server) findRemoteRootRefCmd(ctx context.Context, request *gitalypb.FindRemoteRootRefRequest) (*command.Command, error) {
	remoteURL := request.GetRemoteUrl()
	var config []gitcmd.ConfigPair

	if resolvedAddress := request.GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if authHeader := request.GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", request.GetRemoteUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	repo := s.localRepoFactory.Build(request.GetRepository())

	return repo.Exec(ctx,
		gitcmd.Command{
			Name:   "remote",
			Action: "show",
			Args:   []string{"inmemory"},
		},
		gitcmd.WithDisabledHooks(),
		gitcmd.WithConfigEnv(config...),
		gitcmd.WithSetupStdout(),
	)
```

```go
func (s *server) FindRemoteRootRef(ctx context.Context, in *gitalypb.FindRemoteRootRefRequest) (*gitalypb.FindRemoteRootRefResponse, error) {
	if in.GetRemoteUrl() == "" {
		return nil, structerr.NewInvalidArgument("missing remote URL")
	}
	if err := s.locator.ValidateRepository(ctx, in.GetRepository()); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	ref, err := s.findRemoteRootRef(ctx, in)
	if err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.FindRemoteRootRefResponse{Ref: ref}, nil
```
