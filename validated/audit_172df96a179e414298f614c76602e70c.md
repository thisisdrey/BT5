## Title
Single-step, irreversible authority transfer in `transfer_to_new_account`/`transfer_to_new_account_pda` permanently bricks user funds on misdirected transfer - (File: `programs/marginfi/src/instructions/marginfi_account/transfer_account.rs`)

### Summary
The `TransferToNewAccount` and `TransferToNewAccountPda` instructions let a `MarginfiAccount` authority migrate all positions to a brand-new account under a `new_authority` in a single atomic, one-way step. The `new_authority` account is explicitly documented as "completely unchecked" and there is no claim/confirmation step by the receiving party, mirroring the `OwnableUpgradeable` single-step transfer bug class: any mistake in the supplied address (typo, wrong keypair, copy-paste error) permanently and irrecoverably migrates the account's entire position set and disables the old account with no way to reverse it.

### Finding Description
`transfer_to_new_account` initializes a new `MarginfiAccount` with `ctx.accounts.new_authority.key()` as its authority, copies over the old account's `lending_account` (all balances/positions), then immediately zeroes and permanently disables the old account: [1](#0-0) 

The old account is marked `ACCOUNT_DISABLED`, its `lending_account` is zeroed, and `migrated_to` is set to the new account key so the migration can never be repeated or undone: [2](#0-1) 

The `new_authority` account is taken as an `UncheckedAccount` with an explicit `WARN` comment stating it is "completely unchecked": [3](#0-2) 

The same unchecked, single-step pattern applies to the PDA variant, where the new account is even derived using the unchecked `new_authority` as a PDA seed: [4](#0-3) 

Only the current account authority can initiate the transfer (`is_signer_authorized` requires `marginfi_account.authority == signer`), so this is fully reachable by any unprivileged user operating their own margin account: [5](#0-4) [6](#0-5) 

This is precisely the bug class described in the external report: no "pending" state, no claim step by `new_authority`, and no revocation path — a single erroneous instruction permanently reassigns control of the funds/positions.

### Impact Explanation
If a user (or any integrator/wallet building this instruction) supplies an incorrect `new_authority` public key — due to a typo, clipboard error, wrong derivation, or a malicious front-end substituting the address — the entire position set (deposits and borrows) held by that `MarginfiAccount` is transferred to a new account controlled by that (possibly unintended or unrecoverable) key, and the old account is permanently disabled (`ACCOUNT_DISABLED`, zeroed `lending_account`, `migrated_to` set). There is no two-step "propose/claim" pattern requiring the `new_authority` to sign an acceptance, so the legitimate owner has no opportunity to catch and correct the mistake before their funds become permanently inaccessible to them. This is a permanent, protocol-level loss/freeze of user funds — the same high-impact category identified in the report ("important protocol functionality can be bricked"), here manifesting as an unrecoverable loss of a user's margin account.

### Likelihood Explanation
Likelihood is low-to-moderate: it requires a user-side (or client/integration) error in specifying `new_authority`, similar to the "requires an error on the admin side" caveat in the original report — but here the erring party is any account holder rather than an admin, and the instruction is directly and permissionlessly reachable through normal account-migration flows (e.g., `p0-cli`'s `marginfi_account_transfer`), which increases exposure relative to an admin-only operation.

### Recommendation
Introduce a two-step transfer/claim pattern for `transfer_to_new_account` and `transfer_to_new_account_pda`: first record a "pending new authority" on the old account (or a pending-transfer record), then require a second instruction where `new_authority` itself signs to "claim" the migrated account before positions are moved and the old account is disabled. This mirrors the `Ownable2Step` recommendation from the report and prevents irreversible fund loss from a single mistyped/incorrect address.

### Proof of Concept
1. User creates `MarginfiAccount` A with authority `U`, deposits collateral and opens borrow positions.
2. User calls `transfer_to_new_account` (or `transfer_to_new_account_pda`) specifying `new_authority = X`, where `X` is a mistyped address or an address the user does not actually control (e.g., pasted from a corrupted clipboard, or a burn/unrecoverable address).
3. The instruction succeeds in one atomic transaction: new account B is initialized with `authority = X` and receives all of A's `lending_account` balances (`initialize_migrated_account`); account A is immediately set `ACCOUNT_DISABLED`, its `lending_account` zeroed, and `migrated_to = B` (`finalize_migrated_old_account`), per `programs/marginfi/src/instructions/marginfi_account/transfer_account.rs` lines 91-105.
4. Because `new_authority` is `UncheckedAccount` with no signature or claim requirement, and `migrated_to` blocks any retry/reversal on account A, the user's entire position is now controlled by key `X` and can never be recovered by the original user through the protocol.

fn initialize_migrated_account(
    new_account: &mut MarginfiAccount,
    old_account: &MarginfiAccount,
    new_authority: Pubkey,
    current_timestamp: u64,
    old_account_key: Pubkey,
) {
    new_account.initialize(old_account.group, new_authority, current_timestamp);
    new_account.lending_account = old_account.lending_account;
    new_account.emissions_destination_account = old_account.emissions_destination_account;
    new_account.account_flags = old_account.account_flags;
    new_account.migrated_from = old_account_key;
    new_account.indexer_flags = old_account.indexer_flags;
    new_account.sync_indexer_flags();
}

fn finalize_migrated_old_account(
    old_account: &mut MarginfiAccount,
    new_account_key: Pubkey,
    current_timestamp: u64,
) {
    old_account.migrated_to = new_account_key;
    old_account.last_update = current_timestamp;
    old_account.lending_account = LendingAccount::zeroed();
    old_account.set_flag(ACCOUNT_DISABLED, true);
    old_account.sync_indexer_flags();
}

pub fn is_signer_authorized(
    marginfi_account: &MarginfiAccount,
    group_admin: Pubkey,
    signer: Pubkey,
    allow_receivership: bool,
    allow_order_execution: bool,
) -> bool {
    if allow_receivership && marginfi_account.get_flag(ACCOUNT_IN_RECEIVERSHIP) {
        return marginfi_account.authority != signer; // forbidden to take receivership of your own account
    }

    if allow_order_execution && marginfi_account.get_flag(ACCOUNT_IN_ORDER_EXECUTION) {
        return true;
    }

    if marginfi_account.get_flag(ACCOUNT_FROZEN) {
        return group_admin == signer;
    }

    marginfi_account.authority == signer
}
