### Title
Unauthenticated HTTP event ingestion in `SignerEventReceiver` allows forged node-event injection - (File: `libsigner/src/events.rs`)

### Summary
The `stacks-signer` binary listens for events pushed by the node's event-observer subsystem via `SignerEventReceiver`. Unlike the node's inbound `/v3/block_proposal` RPC endpoint, which enforces a shared `auth_token`/`Authorization` header check, the signer's own HTTP receiver performs **no authentication whatsoever** on any of its endpoints (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`). Any host that can reach the bound socket can POST arbitrary, attacker-crafted JSON payloads that are parsed and forwarded directly into the signer's run loop, exactly analogous to the AAVE report's core lesson: a security invariant that is *documented/intended* (mutual `auth_token`↔`auth_password` matching) but *not actually enforced* at the code site that matters.

### Finding Description
`SignerEventReceiver::bind` opens a plain HTTP server with no auth wiring: [1](#0-0) 

`next_event` then dispatches based solely on the URL path, with zero credential/header validation before invoking `process_event`: [2](#0-1) 

`process_event` reads the raw body and deserializes it as JSON into one of several event types (`StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, `StacksBlockEvent`), then converts it into a `SignerEvent` and forwards it into the signer's internal channel: [3](#0-2) 

For contrast, the *node side* of this same trust boundary explicitly documents and enforces an `Authorization` check for its own inbound signer-facing endpoint (`/v3/block_proposal`) via `auth_token`: [4](#0-3) 

and the signer client sends that token as an `AUTHORIZATION` header when talking to the node: [5](#0-4) 

However, this authentication is one-directional: it protects the node's endpoint from the signer/attacker, but nothing protects the signer's own listening endpoint (`endpoint` in the signer config, which the shipped sample configs bind to `0.0.0.0:30000`, i.e., all interfaces) from arbitrary senders impersonating the node: [6](#0-5) 

This is the same class of bug as the AAVE report: the code base clearly establishes (via docs, config field names, and the node-side implementation) that requests crossing this node↔signer trust boundary are *supposed* to be authenticated, but the actual receiving code on the signer side never checks any credential — the "equality" between "claimed source = the trusted node" and "actual source = whoever can reach the port" is never enforced.

### Impact Explanation
Any remote/unprivileged party that can reach the signer's event-listener port can submit forged `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` payloads. These are deserialized and pushed, unauthenticated, straight into the signer process's internal event channel/state — i.e., an unauthenticated write into the signer's local state/queue. Because default/sample configuration binds the listener to `0.0.0.0`, this is directly reachable over the network in common deployments, not merely from localhost. This qualifies as "unauthenticated/unauthorized write to state" per the impact taxonomy, independent of what the (out-of-scope) signer decision logic subsequently does with the injected data.

### Likelihood Explanation
High likelihood of reachability: the vulnerable code is the entire ingress path of the signer's HTTP receiver (`next_event`/`process_event`), which is always active whenever a signer is running, requires no special network position, and needs only a single crafted HTTP POST. The shipped sample configuration explicitly binds this listener to all interfaces (`0.0.0.0:30000`), and nothing in `libsigner/src/events.rs` gates access by IP, TLS client cert, or shared secret.

### Recommendation
Add symmetric authentication to `SignerEventReceiver`, mirroring the node-side `auth_token` check used for `/v3/block_proposal`: require and validate an `Authorization` header (matching the signer's configured `auth_password`) on every POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` before calling `process_event`, rejecting unauthenticated requests with `401`. Additionally, document/default the listener bind address to loopback unless explicitly overridden, to reduce blast radius even before the auth fix lands.

### Proof of Concept
1. Deploy a `stacks-signer` using the sample config (`endpoint = "0.0.0.0:30000"`).
2. From any host that can reach port 30000 (no credentials needed), send:
```
POST /new_burn_block HTTP/1.1
Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <n>

{ ... forged BurnBlockEvent JSON ... }
```
3. Observe (as shown by the existing test harness pattern in `libsigner/src/tests/mod.rs`, which uses the identical unauthenticated raw-socket POST technique to simulate "the node") that the request is accepted, parsed, and forwarded into the signer's run loop with no credential check at any point in `next_event`/`process_event`: [7](#0-6) 

This same technique works for `/stackerdb_chunks` and `/proposal_response`, allowing an attacker to feed fabricated StackerDB chunk events or block-validation responses to the signer without ever going through the actual `stacks-node`.

```rust
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
