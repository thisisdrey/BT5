Audit Report

## Title
`ChildBountiesValuePerParent` is never decremented when a child bounty is closed without payout, permanently under-reporting parent bounty payouts - (File: `substrate/frame/multi-asset-bounties/src/lib.rs`)

## Summary
`calculate_payout` derives the parent bounty payout by subtracting `ChildBountiesValuePerParent` from the parent's total value, but `remove_bounty`'s child-removal branch only decrements `ChildBountiesPerParent`, leaving `ChildBountiesValuePerParent` unchanged. Any child bounty closed (not claimed) before payout permanently and silently reserves its value against the parent, causing the parent beneficiary to be underpaid by that amount with no recovery path.

## Finding Description
`calculate_payout` computes the parent's payout as `value.saturating_sub(children_value)` where `children_value = ChildBountiesValuePerParent::<T, I>::get(parent_bounty_id)` [1](#0-0) . `remove_bounty` is the single cleanup function invoked when a child or parent bounty is removed from storage. In the `None` (parent removal) branch it correctly clears `ChildBountiesValuePerParent`; in the `Some(child_bounty_id)` (child removal) branch, it removes the `ChildBounties` entry and decrements `ChildBountiesPerParent`, but never touches `ChildBountiesValuePerParent`: [2](#0-1) .

This means once a child bounty's value is added to `ChildBountiesValuePerParent` at creation, the only way for that reservation to be released is for the entire parent bounty to be torn down — there is no code path that subtracts a single child's `value` from `ChildBountiesValuePerParent` when that child is closed/cancelled without payout via `close_child_bounty`/`impl_close_child_bounty`. The related prdoc confirms the maintainers already touched this exact function pair (`calculate_payout`/`remove_bounty`) for a related bug (destructive `take()` vs. non-destructive `get()`), but that fix only addressed double-read correctness, not the missing decrement-on-close path [3](#0-2) .

The reachable path is: `close_child_bounty` is a public/curator-callable extrinsic (`substrate/frame/child-bounties/src/lib.rs` L798-814 in the referenced companion pallet) that calls `impl_close_child_bounty`, which ultimately triggers `remove_bounty(parent_bounty_id, Some(child_bounty_id), ..)`, silently corrupting the parent's payout accounting.

## Impact Explanation
This causes a permanent, wrong-beneficiary-amount payout: the parent bounty's rightful beneficiary receives `value - children_value`, where `children_value` includes value from children that were cancelled and never paid, rather than only value from children that are still pending or paid. The unaccounted difference has no dispatchable recovery path and remains effectively stuck relative to the intended beneficiary, matching the "wrong beneficiary or amount" and "permanent user-fund lock" impact categories for public payout paths in scope.

## Likelihood Explanation
`close_child_bounty` is routine curator/administrative functionality, not requiring any unusual privilege beyond ordinary bounty curation (curator of the parent bounty, or `RejectOrigin` for forced closure). Every legitimate closure of a child bounty before payout triggers this miscalculation, making the bug highly likely to occur in normal usage of the pallet's documented lifecycle.

## Recommendation
In the `Some(child_bounty_id)` branch of `remove_bounty`, saturating-subtract the child bounty's `value` from `ChildBountiesValuePerParent::<T, I>` when the child bounty is removed without completing a successful payout, mirroring the increment performed at child-bounty creation. Add a regression test that closes (rather than claims) a child bounty and asserts `calculate_payout` on the parent subsequently returns the full parent value.

## Proof of Concept
1. Create parent bounty `P` with value `V`, fund it.
2. Add child bounty `C` with value `v` — `ChildBountiesValuePerParent(P) == v`.
3. Close `C` via `close_child_bounty(P, C)` before it reaches payout — `remove_bounty(P, Some(C), ..)` runs: `ChildBountiesPerParent(P)` decrements, but `ChildBountiesValuePerParent(P)` stays `v`.
4. Award and claim parent `P`: `calculate_payout(P, None, V)` returns `V - v` instead of `V`.
5. Parent beneficiary receives `V - v`; the remaining `v` is unaccounted for in the payout with no call to recover it for the beneficiary.

```rust
	/// Calculates amount the beneficiary receives during child-/bounty payout.
	fn calculate_payout(
		parent_bounty_id: BountyIndex,
		child_bounty_id: Option<BountyIndex>,
		value: T::Balance,
	) -> T::Balance {
		match child_bounty_id {
			None => {
				// Get total child bounties value, and subtract it from the parent
				// value.
				let children_value = ChildBountiesValuePerParent::<T, I>::get(parent_bounty_id);
				debug_assert!(children_value <= value);
				let payout = value.saturating_sub(children_value);
				payout
			},
			Some(_) => value,
		}
	}
```

```rust
	/// Cleanup a child-/bounty from the storage.
	fn remove_bounty(
		parent_bounty_id: BountyIndex,
		child_bounty_id: Option<BountyIndex>,
		metadata: T::Hash,
	) {
		match child_bounty_id {
			None => {
				Bounties::<T, I>::remove(parent_bounty_id);
				ChildBountiesPerParent::<T, I>::remove(parent_bounty_id);
				TotalChildBountiesPerParent::<T, I>::remove(parent_bounty_id);
				ChildBountiesValuePerParent::<T, I>::remove(parent_bounty_id);
			},
			Some(child_bounty_id) => {
				ChildBounties::<T, I>::remove(parent_bounty_id, child_bounty_id);
				ChildBountiesPerParent::<T, I>::mutate(parent_bounty_id, |count| {
					count.saturating_dec()
				});
			},
		}

		T::Preimages::unrequest(&metadata);
	}
```
