### Title
Unauthenticated `RecvError` packet allows any attacker to remotely tear down established tunnels - (File: `outside.go`)

### Summary
Nebula's `RecvError` control message is dispatched and processed before any certificate/AEAD authentication, letting an attacker who knows (or observes) a victim's remote index terminate an established tunnel between two legitimately authenticated peers — mirroring the reported bug class where an entity without ownership of a nonce/session can invalidate it for someone else.

### Finding Description
In `readOutsidePackets`, message dispatch happens strictly from the cleartext header before any cryptographic verification. `header.RecvError` is special-cased and routed straight to `f.handleRecvError` ahead of the `hostinfo`/`ConnectionState` lookup and AEAD decrypt path that gates every other post-handshake message: [1](#0-0) 

`handleRecvError` then looks up the target tunnel purely by the attacker-supplied `h.RemoteIndex` field (which travels in plaintext on every packet header and can be observed by any on/off-path attacker), and, if the source `addr` matches the hostinfo's currently recorded remote endpoint, unconditionally closes the tunnel and deletes the pending handshake state — with no certificate, no PSK, no Noise/AEAD proof of possession of any key: [2](#0-1) 

This is structurally the same bug class as the `ExecutionModule.cancelSignature` finding: a piece of state (a nonce there, an established tunnel/hostinfo here) that should only be invalidated by a cryptographically-authenticated party can instead be invalidated by anyone who satisfies a much weaker check (same `accountId` permission there; a spoofable index+address match here). Header fields (`Version`, `Type`, `Subtype`, `RemoteIndex`, `MessageCounter`) are parsed and validated in `header.H.Parse`/`IsValidSubType` with no signature over them: [3](#0-2) 

The only gate applied is a per-endpoint rate limiter (`f.acceptRecvErrorConfig.ShouldRecvError(addr)`), not an authentication check, and the "spoofing" check only compares the source `netip.AddrPort` against the hostinfo's currently stored remote — a value the attacker can match if they can spoof or are on-path for that UDP 4-tuple: [4](#0-3) 

### Impact Explanation
An attacker with no CA-signed certificate and no participation in any handshake can force termination of an already-established, fully authenticated tunnel between two legitimate peers by sending a single unauthenticated `RecvError` packet whose `RemoteIndex` matches the victim's tunnel and whose source address matches the current remote endpoint. This is a remote state-poisoning / denial-of-service primitive against the mesh: repeated forged `RecvError` packets can persistently disrupt connectivity between arbitrary pairs of otherwise-honest nodes, without ever needing to pass certificate or Noise handshake validation.

### Likelihood Explanation
Exploitation requires (a) knowledge of the victim's `RemoteIndex` for the target tunnel, which is transmitted in cleartext in every packet header of that tunnel and is therefore trivially observable to any on-path or eavesdropping attacker, and (b) the ability to originate a UDP packet appearing to come from the peer's current remote `AddrPort`, which is directly available to any on-path attacker (and to off-path attackers on networks/paths where UDP source-address spoofing is not filtered). This makes the attack realistically reachable for an on-path adversary without any Nebula credentials, and plausible off-path in permissive network environments.

### Recommendation
Do not act on `RecvError` before authenticating the sender. At minimum, require the `RecvError` to be tied to something the peer can only produce if it holds valid connection state (e.g., require it to be authenticated/MAC'd via the tunnel's derived keys, or require multiple corroborating signals such as `RemoteIndex` match plus a recent packet-loss condition already tracked locally) rather than accepting a bare, unauthenticated, spoofable UDP packet as sufficient to tear down a tunnel. Alternatively, treat `RecvError` purely as a hint to retry/re-handshake rather than an immediate authority to delete hostinfo/close the tunnel.

### Proof of Concept
1. Passively observe (or be on-path for) UDP traffic between Node A and Node B after they complete a Nebula handshake; extract the plaintext `RemoteIndex` field from any packet header sent by A to B (or B to A) via `header.H.Parse`.
2. Craft a `RecvError` packet using `header.Encode(buf, header.Version, header.RecvError, 0, capturedRemoteIndex, 0)`, mirroring `sendRecvError`'s construction at: [5](#0-4) 
3. Send this packet to Node A's listening UDP port, spoofing (or, if on-path, naturally using) the source `AddrPort` equal to B's currently recorded remote endpoint on A.
4. On receipt, `readOutsidePackets` routes it directly to `handleRecvError` before any decryption; the `hr != addr` spoofing check passes because the source matches, and A calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, tearing down the legitimate tunnel with B — with no certificate or key material ever presented by the attacker.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```

```go
// Parse is a helper function to parses given bytes into new Header struct
func (h *H) Parse(b []byte) error {
	if len(b) < Len {
		return ErrHeaderTooShort
	}
	// get upper 4 bytes
	h.Version = uint8((b[0] >> 4) & 0x0f)
	// get lower 4 bytes
	h.Type = MessageType(b[0] & 0x0f)
	h.Subtype = MessageSubType(b[1])
	h.Reserved = binary.BigEndian.Uint16(b[2:4])
	h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])
	h.MessageCounter = binary.BigEndian.Uint64(b[8:16])
	return nil
}
```
