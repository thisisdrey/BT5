### Title
Unchecked `u64` multiplication with attacker-controlled `estimated_len` causes panic/overflow in `estimate_tx_fee_from_cost_and_length` - (File: stackslib/src/net/api/postfeerate.rs)

### Summary
The `/v2/fees/transaction` POST endpoint accepts a fully attacker-controlled `estimated_len: Option<u64>` field in the JSON body, which is combined via `std::cmp::max` with the actual payload length and passed unmodified into `estimated_len * MINIMUM_TX_FEE_RATE_PER_BYTE` without any checked/saturating arithmetic. A single unauthenticated remote caller can trigger an integer overflow in this multiplication.

### Finding Description
`try_parse_request` computes `estimated_len = std::cmp::max(body.estimated_len.unwrap_or(0), payload_data.len() as u64)` where `body.estimated_len` comes directly from client-supplied JSON [1](#0-0) . There is no upper bound check on `body.estimated_len` before this computation — only the overall HTTP body length is bounded by `MAX_PAYLOAD_LEN` [2](#0-1) , which limits the *body bytes* size, not the numeric value of the `estimated_len` field the JSON encodes (a `u64` literal like `18000000000000000000` fits trivially within a small JSON payload).

This value is later passed into `estimate_tx_fee_from_cost_and_length`, where the fee floor is computed as:
```rust
let minimum_fee = estimated_len * MINIMUM_TX_FEE_RATE_PER_BYTE;
``` [3](#0-2)  — an unchecked `u64` multiplication. With `MINIMUM_TX_FEE_RATE_PER_BYTE` being a nonzero constant, an attacker choosing `estimated_len` near `u64::MAX / MINIMUM_TX_FEE_RATE_PER_BYTE` causes this multiplication to overflow. In debug builds or any build compiled with `overflow-checks = true`, this panics; in release builds without overflow checks it silently wraps to a bogus (typically very small) `minimum_fee`.

No existing guard intervenes: `try_parse_request` only validates content length, content-type, and successful hex/consensus decoding of the tx payload [4](#0-3) ; it never bounds `body.estimated_len`'s numeric magnitude.

### Impact Explanation
On builds with overflow checks enabled (many CI/test/staging configurations, and any node explicitly built with `overflow-checks = true`), a single unauthenticated POST to `/v2/fees/transaction` panics the request-handling thread, causing denial of service against the RPC endpoint. This matches the "Critical - remote crash/unauthenticated DoS from few messages" category since it requires just one HTTP POST with attacker-chosen `estimated_len` and a valid minimal `transaction_payload`. On standard release builds (default Rust release profile has `overflow-checks = false`), the multiplication silently wraps, producing an economically nonsensical `minimum_fee` in the response — a correctness bug but not a crash.

### Likelihood Explanation
The endpoint is a standard RPC route (`/v2/fees/transaction`, `POST`) reachable by any unprivileged remote client that can connect to the node's RPC port; no secret, signature, or privileged role is required. The attacker only needs to supply a syntactically valid `transaction_payload` hex string that decodes as a `TransactionPayload`, plus an `estimated_len` value chosen to overflow the multiplication. Whether this manifests as a crash depends on the node's build configuration (overflow-checks on/off) — this cannot be fully confirmed without knowing the project's release Cargo profile, but the underlying unchecked-arithmetic fault is unambiguous and present in code regardless.

### Recommendation
Use `estimated_len.checked_mul(MINIMUM_TX_FEE_RATE_PER_BYTE)` (or `saturating_mul`) in `estimate_tx_fee_from_cost_and_length`, returning an `HttpBadRequest` error on overflow instead of panicking or wrapping. Additionally, consider imposing a sane upper bound on `body.estimated_len` during `try_parse_request` (e.g., reject values larger than `MAX_PAYLOAD_LEN` or some reasonable maximum transaction size).

### Proof of Concept
Add a test in `stackslib/src/net/api/tests/postfeerate.rs` that constructs a `FeeRateEstimateRequestBody { estimated_len: Some(u64::MAX / 2), transaction_payload: <valid_hex_for_a_minimal_TransactionPayload> }`, serializes it to JSON, and feeds it through `RPCPostFeeRateRequestHandler::try_parse_request` followed by `estimate_tx_fee_from_cost_and_length` (or the full `try_handle_request` path with a configured fee estimator). Compile/run the test with `RUSTFLAGS="-C overflow-checks=on"` (or in `debug` profile) and assert that the call either panics at `stackslib/src/net/api/postfeerate.rs:112` (`estimated_len * MINIMUM_TX_FEE_RATE_PER_BYTE` attempt to multiply with overflow) or, after the fix, returns a graceful `HttpBadRequest` instead.

    fn try_parse_request(
        &mut self,
        preamble: &HttpRequestPreamble,
        _captures: &Captures,
        query: Option<&str>,
        body: &[u8],
    ) -> Result<HttpRequestContents, Error> {
        let content_len = preamble.get_content_length();
        if !(content_len > 0 && content_len < MAX_PAYLOAD_LEN) {
            return Err(Error::DecodeError(format!(
                "Invalid Http request: invalid body length for FeeRateEstimate ({})",
                content_len
            )));
        }

        if preamble.content_type != Some(HttpContentType::JSON) {
            return Err(Error::DecodeError(
                "Invalid content-type: expected application/json".to_string(),
            ));
        }

        let body: FeeRateEstimateRequestBody = serde_json::from_slice(body)
            .map_err(|e| Error::DecodeError(format!("Failed to parse JSON body: {}", e)))?;

        let payload_hex = if body.transaction_payload.starts_with("0x") {
            &body.transaction_payload[2..]
        } else {
            &body.transaction_payload
        };

        let payload_data = hex_bytes(payload_hex).map_err(|_e| {
            Error::DecodeError("Bad hex string supplied for transaction payload".into())
        })?;

        let tx = TransactionPayload::consensus_deserialize(&mut payload_data.as_slice())?;
        let estimated_len =
            std::cmp::max(body.estimated_len.unwrap_or(0), payload_data.len() as u64);

        self.transaction_payload = Some(tx);
        self.estimated_len = Some(estimated_len);
        Ok(HttpRequestContents::new().query_string(query))
    }
