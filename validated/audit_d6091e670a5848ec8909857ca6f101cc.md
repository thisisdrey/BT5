### Title
Unauthenticated remote shutdown of signer event receiver via forged `/shutdown` HTTP request - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` matches on `request.url() == "/shutdown"` and unconditionally sets `stop_signal` and returns `EventError::Terminated`, with no verification that the request came from the signer's own `SignerStopSignaler` versus any other TCP client. Any party able to open a TCP connection to the bound event-receiver port can send the exact same raw HTTP request `SignerStopSignaler::send` issues and permanently halt the signer's `main_loop`, which then breaks out of its event-ingestion loop.

### Finding Description
The equality being violated is: "authorized shutdown-caller == any TCP sender of `POST /shutdown`". In `next_event`, the branch:
```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
```
at `libsigner/src/events.rs:443-445` performs the store and returns `Terminated` based purely on the URL path matching, with no token, no secret, no peer-address check, and no correlation to the `local_addr` used internally by `SignerStopSignaler::send` (`libsigner/src/events.rs:376-396`). `main_loop` (`libsigner/src/events.rs:284-312`) treats `Err(EventError::Terminated)` as a clean exit signal and `break`s, ending event ingestion permanently since `stop_signal` is never reset. There is no equivalent of a shared secret, HMAC, or loopback-only enforcement guarding this endpoint — `tiny_http::Server` accepts connections on whatever socket address was passed to `bind()` (`libsigner/src/events.rs:404-408`), which is the same interface the node's event dispatcher POSTs to, and is commonly configured to a non-loopback interface when the signer and node run on separate hosts.

### Impact Explanation
Any remote party that can reach the signer's event-receiver TCP port can send:
```
POST /shutdown HTTP/1.1
Host: <addr>
Connection: close
Content-Length: 0

```
and this single message permanently stops the signer's event ingestion (`main_loop` exits and never restarts on its own). This is a repeatable, single-message, unauthenticated denial-of-service against the signer's core event pipeline, meeting the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is TCP reachability to the event-receiver's bound address/port — no secret, no valid StackerDB slot, and no peer registration is needed. The attack cost is a single raw HTTP POST, trivially repeatable to keep the signer permanently down.

### Recommendation
Bind the event receiver's shutdown handling to require a shared secret/token known only to the local `SignerStopSignaler` (e.g., checked via a header or the request body), or restrict acceptance of `/shutdown` to loopback-originated connections only, verified via the peer's socket address on the `tiny_http::Request`.

### Proof of Concept
Rust test plan:
1. Construct a `SignerEventReceiver::<T>::new(false)`, call `bind("127.0.0.1:0")`, capture the returned address.
2. Spawn `main_loop` in a thread (or directly call `next_event` in a loop).
3. From a separate `TcpStream::connect` (not via `SignerStopSignaler`), write the raw bytes:
   `"POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1\r\nConnection: close\r\nContent-Length: 0\r\n\r\n"`.
4. Assert that `next_event()` returns `Err(EventError::Terminated)` and that a subsequent call to `is_stopped()` returns `true`, confirming the shutdown succeeded without ever calling `get_stop_signaler`/`SignerStopSignaler::send`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)
