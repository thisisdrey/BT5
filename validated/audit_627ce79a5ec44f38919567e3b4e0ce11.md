### Title
Out-of-bounds heap read when parsing attacker-controlled Windows reparse-point (symlink/junction) data - ([File: src/os/file_windows.go], [File: src/syscall/syscall_windows.go], [File: src/internal/syscall/windows/reparse_windows.go])

### Summary
On Windows, `os.Readlink`, `filepath.EvalSymlinks`, `os.Lstat`/`os.Open` (via reparse-point handling) and `syscall.Readlink` decode a `REPARSE_DATA_BUFFER` returned by `FSCTL_GET_REPARSE_POINT` and use two attacker-controlled `uint16` fields — `SubstituteNameOffset`/`SubstituteNameLength` (and `PrintNameOffset`/`PrintNameLength`) — to slice a path buffer without validating them against the actual size of the allocated buffer. This mirrors the MFER bug class in the CVE report: a length/offset field taken directly from untrusted input is used to index into a buffer that is smaller than what the field's range permits, leading to an out-of-bounds read.

### Finding Description
Attacker input is the on-disk reparse-point data of a file/directory (e.g. a symlink or junction embedded in an extracted archive, a checked-out repository, or a file on a shared/removable filesystem) that a victim later inspects with `os.Readlink`, `os.Lstat`, `filepath.EvalSymlinks`, or `syscall.Readlink`.

Entry points:
- `os.Readlink` → `readlink` → `readReparseLink` → `readReparseLinkHandle` in [1](#0-0) 
- `os.Root`/`os.Lstat`-family path handling → `readReparseLinkHandle`/`readlinkat` in [2](#0-1) , [3](#0-2) 
- `syscall.Readlink` in [4](#0-3) 

All of these call `syscall.DeviceIoControl(..., FSCTL_GET_REPARSE_POINT, ..., &rdbbuf[0], uint32(len(rdbbuf)), ...)` into a buffer sized `MAXIMUM_REPARSE_DATA_BUFFER_SIZE` (16384 bytes) [5](#0-4) . The returned reparse blob is then cast to `SymbolicLinkReparseBuffer`/`MountPointReparseBuffer`, whose `Path()` method performs:

```go
n1 := rb.SubstituteNameOffset / 2
n2 := (rb.SubstituteNameOffset + rb.SubstituteNameLength) / 2
return syscall.UTF16ToString((*[0xffff]uint16)(unsafe.Pointer(&rb.PathBuffer[0]))[n1:n2:n2])
``` [6](#0-5) [7](#0-6) 

The identical unsafe pattern also exists directly in `syscall.Readlink`:
```go
p := (*[0xffff]uint16)(unsafe.Pointer(&data.PathBuffer[0]))
s = UTF16ToString(p[data.SubstituteNameOffset/2 : (data.SubstituteNameOffset+data.SubstituteNameLength)/2])
``` [8](#0-7) 

The failed check: neither `SubstituteNameOffset`, `SubstituteNameLength`, nor their sum are validated against the actual number of bytes DeviceIoControl returned (`bytesReturned` is read but never checked) or against the real backing array size (16384 bytes = 8192 `uint16` elements). Because the pointer is cast to a fixed `[0xffff]uint16` (65535 elements = 131070 bytes) type, Go's compiler-inserted bounds check only validates against that oversized declared array type — not against the true 16 KiB allocation — so an attacker-chosen offset/length combination up to `0xffff` can cause the resulting slice expression to read far past the real `rdbbuf`/`byteblob` allocation into adjacent heap memory (out-of-bounds read), or, if it exceeds even `0xffff` bytes, cause a slice-bounds-out-of-range runtime panic.

### Impact Explanation
This is an out-of-bounds heap read triggered by fully attacker-controlled, unauthenticated-workflow data (a reparse point placed on disk, e.g. via a malicious archive/tarball extraction or repository checkout that a victim later reads with standard filesystem APis). Concrete impact:
- Information disclosure: adjacent heap bytes get decoded as UTF-16 and returned as the "symlink target" string, potentially leaking sensitive process memory content to the caller/output.
- Denial of service: a sufficiently large offset+length combination can produce a slice-bounds-out-of-range panic, crashing the process that merely calls `os.Readlink`/`os.Lstat`/`filepath.EvalSymlinks` on an attacker-supplied path.

This affects Windows builds of the Go standard library (`os`, `syscall`, `internal/syscall/windows`) and would qualify for Go's security process (PUBLIC/private triage) as a memory-safety bug reachable from ordinary file-metadata operations on untrusted filesystem input, analogous in root cause (untrusted length field indexing an undersized fixed buffer) to the reported MFER `tag==63` stack overflow.

### Likelihood Explanation
The victim workflow is very common: any Go program that extracts or walks an untrusted archive/repository containing symlinks/junctions on Windows and then calls `os.Readlink`, `os.Lstat`, or `filepath.EvalSymlinks` on entries is exposed. Crafting a reparse point with arbitrary `SubstituteNameOffset/Length` bytes requires only the ability to write files with `FSCTL_SET_REPARSE_POINT` (ordinary file write access; no admin/SeCreateSymbolicLinkPrivilege is required to *set arbitrary raw byte content* for the reparse buffer if bypassing the OS-level symlink creation API, e.g. constructing the buffer manually as the repo's own test helpers do in `os_windows_test.go`). No TLS/module/build trust boundary needs to be bypassed; this is squarely "ordinary user data delivered via a normal victim workflow."

### Recommendation
Validate `bytesReturned` from `DeviceIoControl` and bound-check `SubstituteNameOffset`, `SubstituteNameLength`, `PrintNameOffset`, and `PrintNameLength` against the actual returned buffer length before slicing, e.g. reject the reparse point (return `syscall.ENOENT`/an error) if `SubstituteNameOffset+SubstituteNameLength` (or `PrintNameOffset+PrintNameLength`) exceeds `bytesReturned - headerSize`. Replace the oversized `(*[0xffff]uint16)` cast with a properly length-limited slice derived from the real buffer size (e.g. build a `[]uint16` slice of exactly the returned byte count via `unsafe.Slice`) so bounds checks are meaningful.

### Proof of Concept
```go
package windows_test

import (
	"encoding/binary"
	"syscall"
	"testing"
	"unsafe"
)

// Minimal reproduction of the unsafe cast/slice pattern used in
// syscall.Readlink / SymbolicLinkReparseBuffer.Path(), using a buffer sized
// like the real MAXIMUM_REPARSE_DATA_BUFFER_SIZE allocation (16384 bytes),
// but with attacker-controlled SubstituteNameOffset/Length fields that
// exceed that allocation.
func TestReparsePathOOBRead(t *testing.T) {
	const maxReparseBufSize = 16384 // syscall.MAXIMUM_REPARSE_DATA_BUFFER_SIZE

	// Layout mimics SymbolicLinkReparseBuffer: offset(2) len(2) offset(2) len(2) flags(4) pathBuffer...
	buf := make([]byte, maxReparseBufSize)
	binary.LittleEndian.PutUint16(buf[0:2], 0xFFF0)  // SubstituteNameOffset: attacker controlled, near max uint16
	binary.LittleEndian.PutUint16(buf[2:4], 0x0010)  // SubstituteNameLength: pushes end beyond real buffer

	type symbolicLinkReparseBuffer struct {
		SubstituteNameOffset uint16
		SubstituteNameLength uint16
		PrintNameOffset      uint16
		PrintNameLength      uint16
		Flags                uint32
		PathBuffer           [1]uint16
	}

	data := (*symbolicLinkReparseBuffer)(unsafe.Pointer(&buf[0]))

	// This mirrors the vulnerable code in syscall.Readlink / SymbolicLinkReparseBuffer.Path():
	// it casts to a fixed [0xffff]uint16 array (131070 bytes) even though the
	// real backing allocation (buf) is only 16384 bytes.
	p := (*[0xffff]uint16)(unsafe.Pointer(&data.PathBuffer[0]))
	n1 := data.SubstituteNameOffset / 2
	n2 := (data.SubstituteNameOffset + data.SubstituteNameLength) / 2

	// n1:n2 (0x7FF8:0x8000) is well within the declared [0xffff]uint16 array
	// bounds but far past the real 16384-byte `buf` allocation, so this reads
	// out-of-bounds heap memory adjacent to buf instead of panicking or erroring.
	s := syscall.UTF16ToString(p[n1:n2:n2])
	t.Logf("decoded out-of-bounds heap bytes as path: %q", s)
}
```
Expected result: on unpatched code, the slice expression succeeds (no panic) despite `n1:n2` exceeding the real `buf` allocation, proving the read escapes the true 16 KiB reparse buffer into adjacent heap memory rather than being rejected. A corrected implementation should return an error (e.g. `ENOENT` / `SyntaxError`) when `SubstituteNameOffset+SubstituteNameLength` exceeds the actual bytes returned by `DeviceIoControl`.

func readReparseLinkHandle(h syscall.Handle) (string, error) {
	rdbbuf := make([]byte, syscall.MAXIMUM_REPARSE_DATA_BUFFER_SIZE)
	var bytesReturned uint32
	err := syscall.DeviceIoControl(h, syscall.FSCTL_GET_REPARSE_POINT, nil, 0, &rdbbuf[0], uint32(len(rdbbuf)), &bytesReturned, nil)
	if err != nil {
		return "", err
	}

	rdb := (*windows.REPARSE_DATA_BUFFER)(unsafe.Pointer(&rdbbuf[0]))
	switch rdb.ReparseTag {
	case syscall.IO_REPARSE_TAG_SYMLINK:
		rb := (*windows.SymbolicLinkReparseBuffer)(unsafe.Pointer(&rdb.DUMMYUNIONNAME))
		s := rb.Path()
		if rb.Flags&windows.SYMLINK_FLAG_RELATIVE != 0 {
			return s, nil
		}
		return normaliseLinkPath(s)
	case windows.IO_REPARSE_TAG_MOUNT_POINT:
		return normaliseLinkPath((*windows.MountPointReparseBuffer)(unsafe.Pointer(&rdb.DUMMYUNIONNAME)).Path())
	default:
		// the path is not a symlink or junction but another type of reparse
		// point
		return "", syscall.ENOENT
	}
}

		if err != nil {
			return nil, err
		}

		fi, err := statHandle(name, fd)
		if err != nil {
			return nil, err
		}

	})

// Readlink returns the destination of the named symbolic link.
func Readlink(path string, buf []byte) (n int, err error) {
	pathp, err := UTF16PtrFromString(path)
	if err != nil {
		return -1, err
	}
	fd, err := CreateFile(pathp, GENERIC_READ, 0, nil, OPEN_EXISTING,
		FILE_FLAG_OPEN_REPARSE_POINT|FILE_FLAG_BACKUP_SEMANTICS, 0)
	if err != nil {
		return -1, err
	}
	defer CloseHandle(fd)

	rdbbuf := make([]byte, MAXIMUM_REPARSE_DATA_BUFFER_SIZE)
	var bytesReturned uint32
	err = DeviceIoControl(fd, FSCTL_GET_REPARSE_POINT, nil, 0, &rdbbuf[0], uint32(len(rdbbuf)), &bytesReturned, nil)
	if err != nil {
		return -1, err
	}

	rdb := (*reparseDataBuffer)(unsafe.Pointer(&rdbbuf[0]))
	var s string
	switch rdb.ReparseTag {
	case IO_REPARSE_TAG_SYMLINK:
		data := (*symbolicLinkReparseBuffer)(unsafe.Pointer(&rdb.reparseBuffer))
		p := (*[0xffff]uint16)(unsafe.Pointer(&data.PathBuffer[0]))
		s = UTF16ToString(p[data.SubstituteNameOffset/2 : (data.SubstituteNameOffset+data.SubstituteNameLength)/2])
		if data.Flags&_SYMLINK_FLAG_RELATIVE == 0 {
			if len(s) >= 4 && s[:4] == `\??\` {
				s = s[4:]
				switch {
				case len(s) >= 2 && s[1] == ':': // \??\C:\foo\bar
					// do nothing
				case len(s) >= 4 && s[:4] == `UNC\`: // \??\UNC\foo\bar
					s = `\\` + s[4:]
				default:
					// unexpected; do nothing
				}
			} else {
				// unexpected; do nothing
			}
		}
	case _IO_REPARSE_TAG_MOUNT_POINT:
		data := (*mountPointReparseBuffer)(unsafe.Pointer(&rdb.reparseBuffer))
		p := (*[0xffff]uint16)(unsafe.Pointer(&data.PathBuffer[0]))
		s = UTF16ToString(p[data.SubstituteNameOffset/2 : (data.SubstituteNameOffset+data.SubstituteNameLength)/2])
		if len(s) >= 4 && s[:4] == `\??\` { // \??\C:\foo\bar
			s = s[4:]
		} else {
			// unexpected; do nothing
		}
	default:
		// the path is not a symlink or junction but another type of reparse
		// point
		return -1, ENOENT
	}
	n = copy(buf, []byte(s))

	return n, nil
