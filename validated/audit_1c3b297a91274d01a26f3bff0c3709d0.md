### Title
Bad-debt positions with remaining debt below `debtFloorInUsd` can never be fully liquidated, permanently locking residual debt and collateral - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
`Pool.liquidate` enforces two conflicting constraints: it reverts with `RemainingDebtIsLowerThanTheFloor` when a repayment would leave the account's debt below `debtFloorInUsd` but above zero, and it reverts with `AmountIsTooHigh` when the repay amount exceeds what the account's collateral can cover (`quoteLiquidateMax`). For an underwater account whose collateral is worth less than `debtFloorInUsd` of remaining debt, no valid `amountToRepay_` exists: full repayment exceeds the seizable collateral, and any partial repayment leaves dust debt under the floor. The position becomes permanently unliquidatable — bad debt is stuck in the protocol and the victim's residual collateral is locked.

### Finding Description
In `Pool.liquidate` (contracts/Pool.sol), the flow is:

1. Revert if `amountToRepay_` would leave the account's USD debt in `(0, debtFloorInUsd)` → `RemainingDebtIsLowerThanTheFloor` (error declared at line 40).
2. Revert if `amountToRepay_` exceeds the collateral-backed maximum → `AmountIsTooHigh` (line 41), where the cap comes from `quoteLiquidateMax` (line 419), which takes the min of the debt and what the deposit token balance can cover.

The test suite confirms the second revert is reachable on real positions: `test/Pool.test.ts:783` ("should revert if paying more than needed to seize all deposit") shows that when `collateral:debt < 1`, repaying the full debt balance reverts with `AmountIsTooHigh`. The maximum repayable (`quoteLiquidateMax`) therefore always leaves residual debt on underwater accounts. Once price movement pushes that residual debt below `debtFloorInUsd`, every subsequent `liquidate` call hits one of the two reverts:

- repay `<= quoteLiquidateMax` → leaves `0 < remainingDebt < debtFloorInUsd` → `RemainingDebtIsLowerThanTheFloor`
- repay `> quoteLiquidateMax` → `AmountIsTooHigh`

There is no "seize everything and forgive the difference" path (no bad-debt socialization or full-seize liquidation branch), and `DebtToken.repay`/`repayAll` do not rescue the account's collateral because the seized collateral is capped by the deposit balance. This is the Metronome analog of the Nomad bug class: an edge-case input/state combination (incomplete specification handling) causes a hard revert that degrades liveness of a core function (liquidation) instead of being handled gracefully.

### Impact Explanation
- **Protocol insolvency:** bad debt cannot be cleared; the synth supply remains backed by debt that is permanently unrecoverable.
- **Permanent freezing of funds:** the account's remaining collateral stays locked (locked balance covers the unpayable debt; `unlockedBalanceOf` stays 0 as shown in the liquidation tests), and liquidators have no path to seize it.

### Likelihood Explanation
An unprivileged attacker can manufacture this state deterministically: open a position, mint near the collateral factor, then move the collateral value down via an AMM/oracle-manipulable market in the same transaction window (allowed per rules) or simply wait for organic price drift so the position goes underwater with `collateral < debt`. Repay the maximum so the leftover debt falls below `debtFloorInUsd`. From then on all liquidations revert. No privileged role is needed — only public `DebtToken.issue`/`repay` and `Pool.liquidate`. The attacker's own collateral is consumed, but the griefed position can be on any victim account as well, since the residual-debt condition depends only on the victim's balances and oracle prices.

### Recommendation
In `Pool.liquidate`, treat "repay capped by collateral" as a full-close: when `amountToRepay_ == quoteLiquidateMax(...)` seizes the entire deposit balance, skip the `RemainingDebtIsLowerThanTheFloor` check and write off (socialize) the remaining debt, or add an explicit `liquidateBadDebt` path that seizes all collateral of an account whose total collateral USD value is below `debtFloorInUsd`. Alternatively, exempt underwater positions from the floor check entirely — the floor exists to prevent dust positions, which is moot when the account's collateral is exhausted.

### Proof of Concept
Foundry/Hardhat fork sketch (mirrors `test/Pool.test.ts:773-789`):

```solidity
// setup: alice deposits MET, mints msETH near CF limit
msdMET.deposit(depositAmt, alice);
msETHDebtToken.issue(mintAmt, alice);

// attacker/pool condition: drop MET price so position is underwater (debt > collateral)
masterOracle.updatePrice(met, lowPrice); // test uses mock; on fork, move the real oracle's pool

// step 1: liquidate the max allowed — leaves residual debt
uint256 maxRepay = pool.quoteLiquidateMax(msETH, alice, msdMET);
pool.liquidate(msETH, alice, maxRepay, msdMET); // succeeds, dust debt remains

// step 2: residual debt < debtFloorInUsd → every liquidation path reverts
vm.expectRevert(Pool.RemainingDebtIsLowerThanTheFloor.selector);
pool.liquidate(msETH, alice, 1, msdMET);

vm.expectRevert(Pool.AmountIsTooHigh.selector);
pool.liquidate(msETH, alice, msETHDebtToken.balanceOf(alice), msdMET);

// alice's remaining deposit is permanently locked; bad debt unrecoverable
assertGt(msETHDebtToken.balanceOf(alice), 0);
assertEq(msdMET.unlockedBalanceOf(alice), 0);
```
