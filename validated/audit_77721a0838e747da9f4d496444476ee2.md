## Title
Missing authorization control on unauthenticated `RecvError` handler allows any off-mesh attacker to tear down established tunnels - (File: outside.go)

### Summary
`readOutsidePackets` dispatches `header.RecvError` packets straight to `f.handleRecvError` before any decryption, cert verification, or handshake completion — the same structural gap as the reported fallback-function bug: a handler that mutates state (`closeTunnel`, `DeleteHostInfo`) is reachable by any caller with no proof of authorization to act on the referenced session. [2](#0-1) 

### Finding Description
In `readOutsidePackets`, packets are parsed only for header validity (`h.Parse`, version check, `IsValidSubType`) before the type switch routes `header.RecvError` to `handleRecvError(via.UdpAddr, h)` — this happens entirely outside the encrypted/authenticated packet path; no `hostinfo.ConnectionState` or CA-verified certificate is required to reach it. [3](#0-2) 

`handleRecvError` then looks up the victim's `HostInfo` purely by the attacker-supplied `h.RemoteIndex` via `f.hostMap.QueryReverseIndex`, and the only "authorization" check present is that the sender's UDP source address matches the currently known remote address for that tunnel: [4](#0-3) 

That check is not a cryptographic authorization control — it is a plain source-IP/port comparison on an unauthenticated UDP packet, which is trivially spoofable (UDP has no built-in source verification, and the check even happens only "if valid", i.e. `hr.IsValid()`). If it matches (or `hr` is not yet valid, e.g. during roaming/reconnect windows), `handleRecvError` calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` — a real state-mutating, session-terminating action — triggered by a caller who never proved possession of a CA-signed certificate or any cryptographic material tied to the session. This mirrors the reported bug class exactly: the entry point ("fallback function" analog: unauthenticated `RecvError` dispatch) grants access to a sensitive handler with only a superficial, spoofable check instead of a real authorization/binding control (the report's suggested fix was `onlyEntryPointOrSelf`-style verification; here the equivalent would be requiring the encrypted/authenticated tunnel session, i.e. treating `RecvError` like other post-handshake message types). [5](#0-4) 

The `RemoteIndex` values are attacker-guessable/brute-forceable 32-bit integers generated by `generateIndex`, and since UDP is connectionless and the source-address check is spoofable, an attacker with no valid certificate for the mesh CA can forge a `RecvError` packet naming any `RemoteIndex` and (assuming address match or an invalid/roam-window remote) force-terminate a live tunnel between two legitimate mesh peers.

### Impact Explanation
Successful exploitation lets an unauthenticated, off-mesh attacker (no CA-signed certificate) forcibly terminate arbitrary established Nebula tunnels by spoofing a single UDP packet, causing denial of service and forced re-handshakes across the mesh. This is a remote state-poisoning/DoS impact reachable without any privilege, matching the accepted impact categories (remote crash/DoS class, unauthorized state mutation).

### Likelihood Explanation
Likelihood is high for the DoS variant: the attacker needs only to guess/observe a `RemoteIndex` (exposed on the wire in every packet header, so trivially sniffable on-path, or brute-forceable off-path within the 32-bit space) and spoof the correct source UDP address/port, both of which are unauthenticated UDP-layer values. `ShouldRecvError`/`acceptRecvErrorConfig` gate this by configuration (`recv_error` accept lists) but that is a network-policy control, not a cryptographic authorization check, and is not part of the CA/cert trust model. [6](#0-5) 

### Recommendation
Do not act on `RecvError` based solely on a source-address match against an attacker-controlled UDP header. Require the `RecvError` (or an equivalent teardown signal) to be authenticated — e.g., only honor it if it arrives inside an already-authenticated/encrypted tunnel context (as `Control`/`CloseTunnel` messages are), or require a signed/HMAC'd acknowledgment tied to the session's Noise keys before calling `closeTunnel`/`DeleteHostInfo`, analogous to using the existing per-session cryptographic state (the equivalent of `onlyEntryPointOrSelf`) instead of a bare address comparison.

### Proof of Concept
1. Attacker observes or guesses a live tunnel's `RemoteIndex` (visible in plaintext in every packet header exchanged between two mesh peers) and the peers' UDP `AddrPort`s.
2. Attacker (holding no CA-signed certificate) crafts a raw UDP packet with `header.Type = RecvError` and `RemoteIndex` set to the victim's index, spoofing the source address to match the expected peer (or sends during a window where `hr.IsValid()` is false, e.g. shortly after roaming).
3. Packet is sent to the target Nebula node's listening UDP port.
4. `readOutsidePackets` routes it directly to `handleRecvError` with no decryption or cert check.
5. `handleRecvError` finds the `HostInfo` via `QueryReverseIndex`, the spoofable address check passes, and it calls `closeTunnel` + `DeleteHostInfo`, tearing down the legitimate session without either peer's authenticated involvement. [7](#0-6)

func (f *Interface) readOutsidePackets(via ViaSender, out []byte, packet []byte, h *header.H, fwPacket *firewall.Packet, lhf *LightHouseHandler, nb []byte, q int, localCache firewall.ConntrackCache) {
	err := h.Parse(packet)
	if err != nil {
		// Hole punch packets are 0 or 1 byte big, so lets ignore printing those errors
		// TODO: record metrics for rx holepunch/punchy packets?
		if len(packet) > 1 {
			f.messageMetrics.RxInvalid(1)
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				f.l.Debug("Error while parsing inbound packet",
					"from", via,
					"error", err,
					"packet", packet,
				)
			}
		}
		return
	}

	if h.Version != header.Version {
		f.messageMetrics.RxInvalid(1)
		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			f.l.Debug("Unexpected header version received", "from", via)
		}
		return
	}

	// Check before processing to see if this is a expected type/subtype
	if !h.IsValidSubType() {
		f.messageMetrics.RxInvalid(1)
		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			f.l.Debug("Unexpected packet received", "from", via)
		}
		return
	}

	if !via.IsRelayed {
		if f.myVpnNetworksTable.Contains(via.UdpAddr.Addr()) {
			f.messageMetrics.RxInvalid(1)
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				f.l.Debug("Refusing to process double encrypted packet", "from", via)
			}
			return
		}
	}

	// don't keep Rx metrics for message type, since you can see those in the tun metrics
	if h.Type != header.Message {
		f.messageMetrics.Rx(h.Type, h.Subtype, 1)
	}

	// Unencrypted packets
	switch h.Type {
	case header.Handshake:
		f.handshakeManager.HandleIncoming(via, packet, h)
		return

	case header.RecvError:
		f.handleRecvError(via.UdpAddr, h)
		return
	}

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
