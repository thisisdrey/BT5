### Title
Free/underpriced compilation DoS via pre-`GasExceeded` clamp in Wasmtime loading-fee ordering — ([File: runtime/near-vm-runner/src/wasmtime_runner/mod.rs])

### Summary
On mainnet (`fix_contract_loading_cost = false`, PV 86), `WasmtimeVM::with_compiled_and_loaded` performs the full Wasmtime compilation of the contract *before* `GasCounter::after_loading_executable` charges `contract_loading_base`/`contract_loading_bytes`. Because `process_gas_limit` clamps `burnt_gas` to `min(prepaid_gas, max_gas_burnt)` on `GasExceeded` rather than charging the actual (larger) loading fee, an attacker can attach `prepaid_gas` just below the loading-fee threshold, forcing the node to burn real CPU on compiling a large, unique (cache-miss) contract while paying only the small attached amount.

### Finding Description
`WasmtimeVM::with_compiled_and_loaded` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:686-833`) resolves the contract through the two-level cache; on a miss it calls `compile_and_cache`/`compile_uncached` (`:570-624`), which is documented as CPU-expensive (“Caching exists because compilation is expensive” — `protocol-model/spec/contract-vm.md:74`). Only *after* this compilation completes does the code call `gas_counter.before_loading_executable` (`:814`, a no-op when `fix_contract_loading_cost` is false) and then, for a successfully compiled module, `gas_counter.after_loading_executable` (`:821`), which is the sole place that charges `contract_loading_base` + `contract_loading_bytes * code_len` via `add_contract_loading_fee` (`gas_counter.rs:224-227,259-272`).

If the attacker's `prepaid_gas` for the `FunctionCall` is smaller than this loading fee, `add_contract_loading_fee`'s underlying `pay_base`/`pay_per` → `deduct_gas` fails, and `process_gas_limit` (`gas_counter.rs:176-214`) sets `burnt_gas = min(new_burnt_gas, hard_burnt_limit)` where `hard_burnt_limit = min(prepaid_gas, max_gas_burnt)` — i.e. the transaction is charged only the attacker-chosen (small) `prepaid_gas`, not the true loading fee. The expensive compilation has already fully executed on the node's CPU by this point; the gas ledger cannot retroactively reflect that cost beyond what the attacker chose to attach.

By deploying many distinct near-`max_contract_size` WASM modules (each with a unique code hash, guaranteeing a cache miss on `ContractCacheKey::Version5`, `cache.rs:46`) and calling each once with `prepaid_gas` set just above the minimum required for `FunctionCall` action/base costs but below `contract_loading_base + contract_loading_bytes * len`, the attacker forces full-size Wasmtime compilation on every call while paying a fixed, cheap, attacker-chosen gas amount instead of the calibrated size-proportional fee. No existing check (signature, nonce, access-key, action validation, size limits) prevents this, because `max_contract_size` only bounds a single module's size, not the number of distinct modules deployed, and gas-limit enforcement is fundamentally post-hoc for this cost.

This is precisely the defect that `ProtocolFeature::FixContractLoadingCost` (nightly-only, PV 129, `core/primitives-core/src/version.rs:579`) was designed to close by pre-charging the fee in `before_loading_executable` before compilation runs — confirming the flaw is real and currently unpatched on the 2.13.0/PV 86 mainnet configuration analyzed here.

### Impact Explanation
This is a resource-exhaustion/compute-metering-totality violation: the attacker obtains full CPU-heavy WASM compilation work at a cost decoupled from (and settable arbitrarily below) the protocol's own calibrated per-byte compilation price, inflating block/chunk application time relative to gas burnt. This does not, by itself, cause fund theft, double-spend, authorization escalation, or state-root divergence — it is a network-level compute-DoS/gas-metering-totality gap, matching the "block application time blow-up disproportionate to gas burnt" scoped impact described in the question, not one of the fund-loss/consensus-divergence/chain-halt bounty categories.

### Likelihood Explanation
Fully unprivileged and repeatable: requires only a funded account able to (a) deploy multiple distinct near-`max_contract_size` contracts (storage-staking cost scales with size but is a one-time, recoverable stake, not burnt gas) and (b) submit `FunctionCall` transactions with deliberately low `prepaid_gas`. Each call is independent and can be repeated indefinitely with freshly generated unique bytecode (e.g., padding/dead-code variation) to keep forcing compile-cache misses. The mechanism (`process_gas_limit` clamping burnt gas to `prepaid_gas` on `GasExceeded`) is deterministic and requires no timing races.

### Recommendation
Backport the ordering used by `FixContractLoadingCost` to the active mainnet configuration: charge (pre-charge) `contract_loading_base`/`contract_loading_bytes` in `before_loading_executable`, prior to invoking `compile_and_cache`/`Module::deserialize`, so that under-funded calls fail with `GasExceeded` *before* any CPU-expensive compilation occurs, rather than after.

1. On the pre-`FixContractLoadingCost` protocol version (mainnet default), deploy N distinct near-`max_contract_size` WASM contracts (each padded/varied to force a unique `code_hash`).

    pub(crate) fn process_gas_limit(&mut self, new_burnt_gas: Gas, new_used_gas: Gas) -> HostError {
        use std::cmp::min;
        // Never burn more gas than what was paid for.
        let hard_burnt_limit = min(self.prepaid_gas, self.max_gas_burnt);
        self.fast_counter.burnt_gas = min(new_burnt_gas.as_gas(), hard_burnt_limit.as_gas());
        debug_assert!(hard_burnt_limit.as_gas() >= self.fast_counter.burnt_gas);

        // Technically we shall do `self.promises_gas = 0;` or error paths, as in this case
        // no promises will be kept, but that would mean protocol change.
        // See https://github.com/near/nearcore/issues/5148.
        // TODO: consider making this change!
        let used_gas_limit = min(self.prepaid_gas, new_used_gas);
        // [CONTINUATION OF THE PREVIOUS COMMENT]
        //
        // Now, there are two distinct ways an attacker can attempt to exploit this code given
        // their full control of the `new_used_gas` value.
        //
        // 1. `self.prepaid_gas < new_used_gas` This is perfectly fine and would be the happy path,
        //    were the computations performed with arbitrary precision integers all the time.
        // 2. `new_used_gas < new_burnt_gas` means that the `new_used_gas` computation wrapped
        //    and `used_gas_limit` is now set to a lower value than it otherwise should be. In the
        //    past this would have triggered an unconditional assert leading to nodes crashing and
        //    network getting stuck/going down. We don’t actually need to assert, though. By
        //    replacing the wrapping subtraction with a saturating one we make sure that the
        //    resulting value of `self.promises_gas` is well behaved (becomes 0.) All a potential
        //    attacker has achieved in this case is throwing some of their gas away.
        self.promises_gas =
            used_gas_limit.saturating_sub(Gas::from_gas(self.fast_counter.burnt_gas));

        // If we crossed both limits prefer reporting GasLimitExceeded.
        // Alternative would be to prefer reporting limit that is lower (or
        // perhaps even some other heuristic) but old code preferred
        // GasLimitExceeded and we’re keeping compatibility with that.
        if new_burnt_gas > self.max_gas_burnt {
            HostError::GasLimitExceeded
        } else {
            HostError::GasExceeded

    /// Add a cost for loading the contract code in the VM.
    ///
    /// This cost does not consider the structure of the contract code, only the
    /// size. This is currently the only loading fee. A fee that takes the code
    /// structure into consideration could be added. But since that would have
    /// to happen after loading, we cannot pre-charge it. This is the main
    /// motivation to (only) have this simple fee.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn add_contract_loading_fee(&mut self, code_len: u64) -> Result<()> {
        self.pay_per(ExtCosts::contract_loading_bytes, code_len)?;
        self.pay_base(ExtCosts::contract_loading_base)
    }

    /// VM independent setup before loading the executable.
    ///
    /// Does VM independent checks that happen after the instantiation of
    /// VMLogic but before loading the executable. This includes pre-charging gas
    /// costs for loading the executable, which depends on the size of the WASM code.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn before_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        method_name: &str,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if method_name.is_empty() {
            let error = super::errors::FunctionCallError::MethodResolveError(
                super::errors::MethodResolveError::MethodEmptyName,
            );
            return Err(error);
        }
        if config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                let error =
                    super::errors::FunctionCallError::HostError(super::HostError::GasExceeded);
                return Err(error);
            }
        }
        Ok(())
    }

    /// Legacy code to preserve old gas charging behaviour in old protocol versions.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn after_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if !config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                return Err(super::errors::FunctionCallError::HostError(
                    super::HostError::GasExceeded,
                ));
            }
        }
        Ok(())
    }

### 3. Compile + load + loading fee (`with_compiled_and_loaded`)
`WasmtimeVM::with_compiled_and_loaded` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:683`) resolves the compiled artifact through a two-level cache (see §7), then charges the loading fee. Ordering (load-bearing):
1. Look up `ContractCacheKey` in the in-memory `AnyCache`, then the on-disk cache; on a miss, fetch code via `Contract::get_code` and `compile_and_cache` (`:606`); a compile failure is stored/returned as `CompiledContract::CompileModuleError` (`mod.rs:723`).
2. `deserialize` the module, resolve the `memory` export (missing ⇒ `LinkError`), build a `Linker`, `link` host functions (`mod.rs:1127`), and `instantiate_pre`.
3. `before_loading_executable` (`gas_counter.rs:236`): reject empty `method_name` (`MethodResolveError::MethodEmptyName`); if `fix_contract_loading_cost` is set, pre-charge `add_contract_loading_fee` (`contract_loading_base` + `contract_loading_bytes * code_len`, `gas_counter.rs:225`) — on OOG return `HostError::GasExceeded` as an abort.
4. `after_loading_executable` (`gas_counter.rs:260`): if `fix_contract_loading_cost` is **not** set, charge the loading fee *after* loading instead (legacy ordering). On 2.13.0 mainnet `fix_contract_loading_cost` is `false` (the fix is nightly-only, PV 129), so the loading fee is charged post-load.
