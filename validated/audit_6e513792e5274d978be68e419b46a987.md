### Title
Unauthenticated remote shutdown of `SignerEventReceiver` via `/shutdown` POST - ([File: libsigner/src/events.rs])

### Summary
The `/shutdown` branch in `SignerEventReceiver::next_event` sets `stop_signal` to `true` on any POST to `/shutdown` without checking any signature, secret, or peer address. Any TCP client able to reach the signer's event-receiver HTTP listener can terminate the signer's event-processing `main_loop` with a single crafted POST.

### Finding Description
The claimed equality — "the sender of a POST to `/shutdown` == an authorized local operator process" — does not hold in the code. In `next_event`, the request handling dispatches purely on the HTTP method and URL string with no authentication check anywhere in the function: [1](#0-0) 

Specifically:
```rust
if request.method() != &HttpMethod::Post { ... }
...
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
```
There is no comparison against a secret/token, no signature verification, and no `SocketAddr`/peer check against a configured allow-list — contrast this with the `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block` branches, which at least deserialize a typed payload (though those too have no auth check beyond payload parsing). The intended-use path (`SignerStopSignaler::send`) constructs exactly this same unauthenticated request to trigger a local shutdown: [2](#0-1) 

Because the HTTP listener (`HttpServer::http(listener)`, bound in `bind()`) is a plain TCP socket with no TLS/auth layer, any TCP peer that can reach the listening address can send the identical bytes `SignerStopSignaler::send` sends and achieve the same effect: [3](#0-2) 

Once `stop_signal` is set, `next_event` returns `Err(EventError::Terminated)`, which causes `EventReceiver::main_loop` to break out of its loop and exit: [4](#0-3) 

This confirms the fault: there is no gate distinguishing a legitimate local `SignerStopSignaler` caller from an arbitrary remote TCP client — both produce the identical wire bytes and both flip the same shared `AtomicBool`.

### Impact Explanation
A single unauthenticated POST to `/shutdown` permanently halts the signer's event receiver `main_loop`, meaning the signer process stops receiving `stackerdb_chunks`, `proposal_response`, `new_burn_block`, and `new_block` events from the node. This effectively disables that signer's participation in block signing/validation without needing repeated traffic — one message, one node stopped. This matches the "Critical - remote crash/unauthenticated DoS from few messages" category, since it is a control-plane authentication bypass causing termination, not merely bandwidth/connection exhaustion.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs TCP reachability to the signer event-receiver's bound address/port (which is whatever address the signer operator configured, e.g. `event_server` in the signer config) and no credential, secret, signer key, or StackerDB slot ownership is required. The message is a trivial, static, well-known HTTP request (`POST /shutdown HTTP/1.1 ...`), and the attack is fully repeatable/idempotent (each request re-asserts `store(true, ...)`, and once stopped, the receiver stays stopped since nothing resets `stop_signal` to `false`).

### Recommendation
Do not expose an unauthenticated remote-terminable control-plane endpoint on a network-reachable listener. Options: 
1. Only accept `/shutdown` requests originating from `127.0.0.1`/loopback by checking `request.remote_addr()` against the loopback address before honoring the shutdown. 
2. Require a shared secret/token (e.g., a random value generated at startup and passed only to `SignerStopSignaler`, checked via a header or query param) before honoring `/shutdown`. 
3. Replace the HTTP-based stop signal entirely with a genuinely local-only IPC mechanism (e.g., a Unix domain socket, or an in-process channel/condvar) so the shutdown path never touches the network-facing HTTP server at all.

### Proof of Concept
```rust
// libsigner/src/events.rs (or a new integration test)
use std::io::Write;
use std::net::TcpStream;
use std::thread;
use std::time::Duration;

#[test]
fn unauthenticated_remote_shutdown() {
    let mut receiver: SignerEventReceiver<StacksMessage> = SignerEventReceiver::new(false);
    let bound_addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    let handle = thread::spawn(move || {
        // simulate main_loop consuming a couple of events/timeouts
        let _ = receiver.next_event(); // will process the malicious /shutdown POST
        receiver.is_stopped()
    });

    // "attacker" thread: no signature, no secret, arbitrary remote TCP client
    thread::sleep(Duration::from_millis(100));
    let mut stream = TcpStream::connect(bound_addr).unwrap();
    let body = "attacker-controlled";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\nContent-Type: text/plain\r\n\r\n{}",
        bound_addr, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    let was_stopped = handle.join().unwrap();
    assert!(was_stopped, "unauthenticated remote POST /shutdown should not be able to stop the event receiver");
}
```
Expected/observed: the assertion fails to catch the bug — i.e., `is_stopped()` becomes `true` after the unauthenticated remote POST, confirming the DoS at the exact code site `libsigner/src/events.rs:443-445`.
