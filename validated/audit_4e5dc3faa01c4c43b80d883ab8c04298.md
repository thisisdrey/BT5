### Title
Unbounded per-request full VotesStore scan and full witness sort in `getPaginatedNowWitnessList` allow CPU-exhaustion DoS via cheap, repeated, unauthenticated API calls - (File: framework/src/main/java/org/tron/core/Wallet.java)

### Summary
The external report describes an HTTP/2 resource-loop DoS class: a low-cost client action (priority reordering) that forces the server to repeatedly perform disproportionate CPU work on a shared data structure (the priority tree). The closest reachable analog in java-tron is the public `GetPaginatedNowWitnessList` API. Every single call — regardless of the tiny `offset`/`limit` the caller actually requested — forces the full node to iterate the *entire* `VotesStore` and fully sort the *entire* witness list before returning even one row. An anonymous API client can invoke this endpoint (HTTP `/wallet/getpaginatednowwitnesslist` and gRPC) with no authentication, cost, or per-request throttling proportional to the work performed, matching the "cheap client input, disproportionate server churn" bug class of CVE‑2019‑9513.

### Finding Description
`Wallet.getPaginatedNowWitnessList` is reachable directly from `GetPaginatedNowWitnessListServlet`, an unauthenticated HTTP servlet only guarded by `RateLimiterServlet`'s generic rate limiting (not scoped to computational cost). [1](#0-0) 

Inside `getPaginatedNowWitnessList`, before any pagination (`skip`/`limit`) is applied:
1. `chainBaseManager.getWitnessStore().getAllWitnesses()` loads every witness in the store.
2. `countVote(votesStore)` iterates the **entire** `VotesStore` and, for every entry, iterates both its `oldVotes` and `newVotes` lists, building a full vote-delta map.
3. The full witness list is then updated with these deltas and passed to `WitnessStore.sortWitnesses`, which performs a full `O(n log n)` comparator-based sort (with `createReadableString`/string comparisons when `allowWitnessSortOptimization` is off) over *all* witnesses.
4. Only after all of this work is `skip(offset).limit(limit)` applied to trim the result. [2](#0-1) [3](#0-2) [4](#0-3) 

Unlike the `dbIterator` used in `MaintenanceManager.countVote` (which deletes each `VotesStore` entry as it's read, bounding the amortized cost across the block-production cycle), `Wallet.countVote` is a **read-only** scan invoked on every single API call and does not consume/clear entries. [5](#0-4) 

Because `VotesStore` entries accumulate for every `VoteWitnessContract` submitted during the current voting epoch (a cheap, broadcastable transaction any funded account can send repeatedly against many voter accounts), an attacker can grow `VotesStore` and the witness set to a large size at moderate cost, then repeatedly issue free, unauthenticated `getPaginatedNowWitnessList` requests (each requesting e.g. `limit=1`) to force the node to redo the full `O(V + n log n)` scan/sort work on every call — the classic "small client request, disproportionate server compute" pattern from the CVE report, but applied to a HashMap+sort based witness ranking rebuild instead of an HTTP/2 priority tree.

### Impact Explanation
Repeated invocation of this endpoint by anonymous API clients consumes CPU proportional to the full `VotesStore` and witness set sizes on every call, independent of the requested page size. On a busy full node this can starve the HTTP/JSON-RPC/gRPC query-serving threads, degrading or denying that API surface for legitimate wallet/exchange/dApp clients (matches the "an API the node can no longer serve" acceptance criterion) — analogous to the CPU-exhaustion DoS described in the CVE.

### Likelihood Explanation
Likelihood is moderate-to-high: no authentication or special privilege is needed to call `getpaginatednowwitnesslist`, and `VoteWitnessContract` transactions used to inflate `VotesStore` are ordinary, low-cost broadcastable transactions. `RateLimiterServlet` throttles request *count*, not the amount of server-side work per request, so the mismatch between input cost and server cost persists even under normal rate limiting.

### Recommendation
Bound the per-request cost of `getPaginatedNowWitnessList` to the requested page: avoid a full `VotesStore` scan and full witness sort on every call by caching the sorted, vote-adjusted witness ranking (e.g., recomputed once per new `VotesStore` write or with a short TTL) rather than recomputing from scratch on every read, and/or apply computational-cost-aware rate limiting to this endpoint specifically.

### Proof of Concept
1. Submit many `VoteWitnessContract` transactions from distinct funded accounts across an epoch to grow `VotesStore` (each transaction is a normal, cheap broadcastable contract validated/executed by `VoteWitnessActuator.countVoteAccount`). [6](#0-5) 
2. As an anonymous client, repeatedly `POST /wallet/getpaginatednowwitnesslist` (or the gRPC equivalent) with `{"offset":0,"limit":1}`.
3. Observe that each call triggers a full `VotesStore` iteration plus a full witness-list sort in `Wallet.getPaginatedNowWitnessList`/`WitnessStore.sortWitnesses`, regardless of the requested `limit=1`, allowing sustained CPU load with minimal request cost to the attacker.

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;
  }

    return ret;
  }

  public static void sortWitnesses(List<WitnessCapsule> witnesses, boolean isSortOpt) {
    witnesses.sort(Comparator.comparingLong(WitnessCapsule::getVoteCount).reversed()
        .thenComparing(isSortOpt
            ? Comparator.comparing(WitnessCapsule::createReadableString).reversed()
            : Comparator.comparingInt((WitnessCapsule w) -> w.getAddress().hashCode()).reversed()));
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }

  private void countVoteAccount(VoteWitnessContract voteContract) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    VotesStore votesStore = chainBaseManager.getVotesStore();
    MortgageService mortgageService = chainBaseManager.getMortgageService();
    byte[] ownerAddress = voteContract.getOwnerAddress().toByteArray();

    VotesCapsule votesCapsule;

    //
    mortgageService.withdrawReward(ownerAddress);

    AccountCapsule accountCapsule = accountStore.get(ownerAddress);

    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    if (!votesStore.has(ownerAddress)) {
      votesCapsule = new VotesCapsule(voteContract.getOwnerAddress(),
          accountCapsule.getVotesList());
    } else {
      votesCapsule = votesStore.get(ownerAddress);
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    voteContract.getVotesList().forEach(vote -> {
      logger.debug("countVoteAccount, address[{}]",
          ByteArray.toHexString(vote.getVoteAddress().toByteArray()));

      votesCapsule.addNewVotes(vote.getVoteAddress(), vote.getVoteCount());
      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());
    });

    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    votesStore.put(ownerAddress, votesCapsule);
  }
