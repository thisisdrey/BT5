## Title
PSM mint/redeem allows draining a shared multi-asset reserve by minting with a depegged external asset and redeeming a healthy one - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
`pallet-psm` implements a Peg Stability Module where a single internal stablecoin is backed by a pool of multiple approved external assets held in one shared reserve account per instance [1](#0-0) . Exactly like the Rio `reETH` case where deposits of `cbETH`/native ETH share one LRT reserve, PSM's `mint`/`redeem` convert strictly by decimals-adjusted nominal 1:1 value, with no market-price input [2](#0-1) . A user can therefore deposit asset A whose real value has (or is about to) drop below its assumed peg, receive the internal asset at full nominal value, and immediately redeem a different, healthy external asset B from the same shared reserve, extracting real value from the other depositors backing asset B.

### Finding Description
`mint` computes `internal_equivalent` purely from `external_amount` and decimal snapshots, with no reference to the external asset's real market price [3](#0-2) . The caller chooses *which* external asset to deposit and, independently, *which* external asset to redeem — `redeem` only checks aggregated `PsmDebt` for the chosen `external_asset` and the pool's live reserve balance, never requiring symmetry with what the same caller deposited [4](#0-3) . All approved externals share the same reserve account, addressed only by `internal_asset` (`Self::psm_account(&internal_asset)`), so the pool of good and bad collateral is fungible from the contract's perspective [5](#0-4) .

This reproduces the Rio exploit primitive exactly: "deposit asset1 to get LRT, then request to withdraw asset2." Just as Rio's `reETH` treats `cbETH` and native `ETH` as fungible collateral valued only through a lagging price feed, PSM treats every approved external as fungible collateral valued only through a fixed decimal-scaling assumption of a $1 peg — with no oracle, no minimum holding period between mint and redeem, and no restriction that a user may only withdraw the asset type they deposited. The only mitigations present are reactive, admin-triggered circuit breakers (`AllEnabled`/`MintingDisabled`/`AllDisabled`) and static per-asset ceiling weights, both of which require an admin to notice and react — they do not stop an unprivileged user from executing the arbitrage in the same block or before an admin intervenes [6](#0-5) .

### Impact Explanation
If any approved external asset trades below its assumed 1:1 peg (e.g., a depegging stablecoin or a bridged/wrapped asset undergoing a redemption-driven price drop, mirroring the cbETH/wstETH slashing scenario in the source report), an attacker can:
1. Mint internal asset using the depegged asset at full nominal value.
2. Redeem a different, still fully-pegged external asset from the same shared reserve.

This silently transfers real backing value from holders of the healthy external asset to the attacker, without needing any privileged role, leaked key, or malicious validator/node — satisfying "theft or unbacked mint or unlock" / value not conserved for the rightful beneficiaries, which is in-scope per the gate. Because debt/ceiling accounting is per-asset (`PsmDebt`), the pallet has no cross-asset backstop preventing this reserve-draining substitution beyond an admin manually reacting with the circuit breaker.

### Likelihood Explanation
Likelihood is comparable to the original Rio finding: it requires a PSM instance configured with more than one external asset (an intended, documented configuration — `multiple_assets_share_redistributed_ceiling` test confirms multi-external instances are supported and expected) [7](#0-6) , and a predictable/observable price divergence of one external asset from its peg. Depegging events for stablecoins and bridged/wrapped assets are observable in advance (as documented in the source report for cbETH/wstETH), making this a realistic, non-flash-loanable but repeatable attack path for any unprivileged holder of the depegging asset.

### Recommendation
- Require that a user's redeemable external-asset choice be constrained to (or discounted against) what they deposited within a cooldown window, or
- Track and cap per-account or per-block cross-asset "arbitrage" exposure, or
- Integrate a price/peg-deviation check (or automatic circuit-breaker trip) before allowing mint of one external and redemption of a different external in short succession, or
- Segregate reserves per external asset so that redemption of asset B can never be funded by proceeds nominally derived from depositing depegging asset A beyond A's own tracked debt bucket protecting B's backing.

### Proof of Concept
1. Governance creates a PSM instance for `internal_asset` with two approved externals, `USDC_ASSET_ID` (healthy) and `RISKY_ASSET_ID` (about to depeg), each with non-zero ceiling weight, mirroring `multiple_assets_share_redistributed_ceiling` setup [8](#0-7) .
2. Reserve is funded over time with both `USDC` and `RISKY_ASSET` via normal user `mint` calls, per `Psm::mint` [9](#0-8) .
3. Attacker, anticipating `RISKY_ASSET`'s price drop (analogous to cbETH/wstETH slashing), calls `Psm::mint(internal_asset, RISKY_ASSET_ID, large_amount, max_fee)`, receiving `internal_asset` at full nominal (pre-drop) value since `mint` has no market-price check [2](#0-1) .
4. Before/as `RISKY_ASSET`'s real value drops, attacker calls `Psm::redeem(internal_asset, USDC_ASSET_ID, internal_amount, max_fee)`, draining healthy `USDC` from the shared reserve at full nominal value, per `Psm::redeem` [10](#0-9) .
5. Result: attacker holds healthy `USDC` extracted from the pool, while the reserve is left overweight in the now-depegged `RISKY_ASSET`, and remaining internal-asset holders bear the shortfall on their next redemption — the same "delegate your risk to other users" outcome described in the Rio report.

## Overview

The PSM pallet hosts one or more PSM instances, each keyed by its internal
asset id. Each instance:

- **Holds a per-instance reserve account** derived from
  `blake2_256((PalletId::TYPE_ID, PalletId, internal_asset).encode())`.
  External assets deposited by users are held there.
- **Mints and burns its own internal asset**. Users receive the internal asset
  when depositing external assets, and burn the internal asset when
  redeeming.
- **Routes fees to the instance's `fee_destination`**. Mint and redeem fees are
  collected in the internal asset and transferred to the per-instance account
  recorded in `PsmInfo`.
- **Has independent per-external circuit breakers**. Each approved external on
  each instance can be paused without affecting others.

		pub fn mint(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
			external_amount: BalanceOf<T>,
			max_fee: Permill,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;

			let external = ExternalAssets::<T>::get(&internal_asset, &external_asset)
				.ok_or(Error::<T>::UnsupportedAsset)?;
			ensure!(external.status.allows_minting(), Error::<T>::MintingStopped);

			let (ext_decimals, internal_decimals) =
				Self::ensure_decimals_match(&info, &internal_asset, &external_asset, &external)?;

			let internal_equivalent =
				Self::external_to_internal(external_amount, ext_decimals, internal_decimals)?;
			ensure!(!internal_equivalent.is_zero(), Error::<T>::AmountTooSmallAfterConversion);
			ensure!(internal_equivalent >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let effective_external =
				Self::internal_to_external(internal_equivalent, ext_decimals, internal_decimals)?;

			let fee_rate = MintingFee::<T>::get(&internal_asset, &external_asset);
			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
			let fee = fee_rate.mul_ceil(internal_equivalent);
			let internal_to_user = internal_equivalent.saturating_sub(fee);

			let current_total_psm_debt = Self::total_psm_debt(&internal_asset);
			ensure!(
				current_total_psm_debt.saturating_add(internal_equivalent) <= info.max_debt,
				Error::<T>::ExceedsMaxPsmDebt
			);

			let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
			let max_debt = Self::max_asset_debt(&internal_asset, &external_asset, &info);
			let new_debt = current_debt.saturating_add(internal_equivalent);
			ensure!(new_debt <= max_debt, Error::<T>::ExceedsMaxPsmDebt);

			let psm_account = Self::psm_account(&internal_asset);
			T::Fungibles::transfer(
				external_asset.clone(),
				&who,
				&psm_account,
				effective_external,
				Preservation::Expendable,
			)?;
			T::Fungibles::mint_into(internal_asset.clone(), &who, internal_to_user)?;
			if !fee.is_zero() {
				T::Fungibles::mint_into(internal_asset.clone(), &info.fee_destination, fee)?;
			}

			PsmDebt::<T>::insert(&internal_asset, &external_asset, new_debt);

			Self::deposit_event(Event::Minted {
				who,
				internal_asset,
				external_asset,
				external_consumed: effective_external,
				internal_received: internal_to_user,
				internal_fee: fee,
			});
			Ok(())
		}

		pub fn redeem(
			origin: OriginFor<T>,
			internal_asset: T::AssetId,
			external_asset: T::AssetId,
			internal_amount: BalanceOf<T>,
			max_fee: Permill,
		) -> DispatchResult {
			let who = ensure_signed(origin)?;
			let info = Psm::<T>::get(&internal_asset).ok_or(Error::<T>::PsmNotFound)?;

			let external = ExternalAssets::<T>::get(&internal_asset, &external_asset)
				.ok_or(Error::<T>::UnsupportedAsset)?;
			ensure!(external.status.allows_redemption(), Error::<T>::AllSwapsStopped);

			let ext_decimals = external.decimals;
			let internal_decimals = info.internal_decimals;

			ensure!(internal_amount >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let fee_rate = RedemptionFee::<T>::get(&internal_asset, &external_asset);
			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
			let fee = fee_rate.mul_ceil(internal_amount);
			let internal_net = internal_amount.saturating_sub(fee);

			let external_out =
				Self::internal_to_external(internal_net, ext_decimals, internal_decimals)?;
			ensure!(
				internal_net.is_zero() || !external_out.is_zero(),
				Error::<T>::AmountTooSmallAfterConversion
			);
			// `effective_internal_net` is the internal value that round-trips to `external_out`;
			// it is what we actually burn and what the tracked debt decreases by. Any truncation
			// dust stays in the caller's internal balance, symmetric with `mint`, which takes
			// only the round-tripped share of the external amount.
			let effective_internal_net =
				Self::external_to_internal(external_out, ext_decimals, internal_decimals)?;

			let current_debt = PsmDebt::<T>::get(&internal_asset, &external_asset);
			ensure!(current_debt >= effective_internal_net, Error::<T>::InsufficientReserve);

			let reserve = Self::get_reserve(&internal_asset, &external_asset);
			if reserve < external_out {
				defensive!("PSM reserve is less than expected output amount");
				return Err(Error::<T>::Unexpected.into());
			}

			if !fee.is_zero() {
				T::Fungibles::transfer(
					internal_asset.clone(),
					&who,
					&info.fee_destination,
					fee,
					Preservation::Expendable,
				)?;
			}

			if !effective_internal_net.is_zero() {
				T::Fungibles::burn_from(
					internal_asset.clone(),
					&who,
					effective_internal_net,
					Preservation::Expendable,
					Precision::Exact,
					Fortitude::Polite,
				)?;
			}

			let psm_account = Self::psm_account(&internal_asset);
			if !external_out.is_zero() {
				T::Fungibles::transfer(
					external_asset.clone(),
					&psm_account,
					&who,
					external_out,
					Preservation::Expendable,
				)?;
			}
