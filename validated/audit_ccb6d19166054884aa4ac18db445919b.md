### Title
CA blocklisting does not cascade to certificates signed by a blocklisted CA - ([File: cert/ca_pool.go])

### Summary
`CAPool.BlocklistFingerprint`/`IsBlocklisted` only block a certificate whose *own* fingerprint is on the blocklist. The verification path `verify()` (used by both `VerifyCertificate` and `VerifyCachedCertificate`) never checks whether the *signing* CA's fingerprint is blocklisted before trusting it, so revoking a CA does not revoke certificates it already signed.

### Finding Description
`CAPool` stores blocklisted fingerprints in `certBlocklist` and exposes `BlocklistFingerprint`/`IsBlocklisted` for administrators to revoke trust in a specific certificate [1](#0-0) .

The core verification routine `verify()` checks the blocklist only against the leaf certificate's own fingerprint (`certFp`), then looks up the signer via `GetCAForCert` and proceeds to validate curve/expiry/signature/constraints — it never calls `IsBlocklisted` on the signer's fingerprint: [2](#0-1) 

`GetCAForCert` simply returns whichever `CachedCertificate` is stored for the issuer, with no blocklist filtering of the CA itself: [3](#0-2) 

This mirrors the reported bug class of inconsistent/incomplete restriction propagation: in the external report, a "full restriction" was expected to imply all effects of a "soft restriction" but the code paths didn't consistently enforce that composition, and restrictions did not reliably propagate to related entities (e.g., receivers). Here, blocklisting a CA (the strongest form of "restriction" in Nebula's PKI trust model) is expected to revoke everything it signed, but the enforcement only covers the single fingerprint that was explicitly blocklisted — it does not cascade to certificates whose *issuer* is blocklisted.

This is reachable by any already-provisioned peer whose certificate chain includes a CA that an operator later decides to blocklist (e.g. because the CA's private key was compromised, or the CA is being retired). Both handshake-time verification (`VerifyCertificate`) and periodic re-validation of already-established tunnels (`VerifyCachedCertificate`, called from `isInvalidCertificate` in `connection_manager.go`) rely on this same `verify()`/blocklist logic: [4](#0-3) 

### Impact Explanation
An operator who believes they have revoked trust in a CA (by blocklisting its fingerprint) will still accept and maintain tunnels with peers holding certificates signed by that CA, because only an individually-blocklisted leaf fingerprint is rejected. This is a certificate/CA-pool trust bypass: a peer that should be fully de-authenticated (compromised/retired CA) can still complete the Noise handshake and keep an active, trusted tunnel, since neither the handshake path nor the periodic tunnel re-validation path consult the signer's blocklist status.

### Likelihood Explanation
This requires no attacker action beyond already holding a valid certificate issued by the (later blocklisted) CA — a normal, expected use case of certificate revocation/CA rotation. Any operator relying on `BlocklistFingerprint` to revoke an entire CA (rather than enumerating and blocklisting every certificate it ever signed) will unknowingly leave existing peers fully trusted.

### Recommendation
In `verify()`, after resolving `signer` via `GetCAForCert`, also check `ncp.IsBlocklisted(signer.Fingerprint)` (and its alternate P256 fingerprint form) and reject with `ErrBlockListed` if the signer is blocklisted — mirroring how a full restriction is expected to imply/cascade over dependent trust relationships.

### Proof of Concept
1. Provision CA `A` and issue host certificate `H` signed by `A`; add `A` to a `CAPool` via `AddCA`.
2. Peer using `H` completes a handshake successfully (`VerifyCertificate` passes).
3. Operator discovers `A`'s key is compromised and calls `caPool.BlocklistFingerprint(fingerprint_of_A)`.
4. Peer using `H` attempts handshake again (or an existing tunnel is periodically re-validated via `isInvalidCertificate`/`VerifyCachedCertificate`): `verify()` only checks `IsBlocklisted(certFp)` where `certFp` is `H`'s own fingerprint (not blocklisted) — the check on `signer.Fingerprint` (`A`'s fingerprint, which *is* blocklisted) never happens, so `H` is still accepted as trusted [5](#0-4) .

// BlocklistFingerprint adds a cert fingerprint to the blocklist
func (ncp *CAPool) BlocklistFingerprint(f string) {
	ncp.certBlocklist[f] = struct{}{}
}

// ResetCertBlocklist removes all previously blocklisted cert fingerprints
func (ncp *CAPool) ResetCertBlocklist() {
	ncp.certBlocklist = make(map[string]struct{})
}

// IsBlocklisted tests the provided fingerprint against the pools blocklist.
// Returns true if the fingerprint is blocked.
func (ncp *CAPool) IsBlocklisted(fingerprint string) bool {
	if _, ok := ncp.certBlocklist[fingerprint]; ok {
		return true
	}

	return false
}

func (ncp *CAPool) verify(c Certificate, now time.Time, certFp string, signerFp string) (*CachedCertificate, error) {
	if ncp.IsBlocklisted(certFp) {
		return nil, ErrBlockListed
	}

	signer, err := ncp.GetCAForCert(c)
	if err != nil {
		return nil, err
	}

	if signer.Certificate.Curve() != c.Curve() {
		return nil, ErrCurveMismatch
	}

	if signer.Certificate.Expired(now) {
		return nil, ErrRootExpired
	}

	if c.Expired(now) {
		return nil, ErrExpired
	}

	// If we are checking a cached certificate then we can bail early here
	// Either the root is no longer trusted or everything is fine
	if len(signerFp) > 0 {
		if signerFp != signer.Fingerprint {
			return nil, ErrFingerprintMismatch
		}
		return signer, nil
	}
	if !c.CheckSignature(signer.Certificate.PublicKey()) {
		return nil, ErrSignatureMismatch
	}

	err = CheckCAConstraints(signer.Certificate, c)
	if err != nil {
		return nil, err
	}

	return signer, nil
}

// GetCAForCert attempts to return the signing certificate for the provided certificate.
// No signature validation is performed
func (ncp *CAPool) GetCAForCert(c Certificate) (*CachedCertificate, error) {
	issuer := c.Issuer()
	if issuer == "" {
		return nil, fmt.Errorf("no issuer in certificate")
	}

	signer, ok := ncp.CAs[issuer]
	if ok {
		return signer, nil
	}

	return nil, ErrCaNotFound
}

// isInvalidCertificate decides if we should destroy a tunnel.
// returns true if pki.disconnect_invalid is true and the certificate is no longer valid.
// Blocklisted certificates will skip the pki.disconnect_invalid check and return true.
func (cm *connectionManager) isInvalidCertificate(now time.Time, hostinfo *HostInfo) bool {
	remoteCert := hostinfo.GetCert()
	if remoteCert == nil {
		return false //don't tear down tunnels for handshakes in progress
	}

	caPool := cm.intf.pki.GetCAPool()
	err := caPool.VerifyCachedCertificate(now, remoteCert)
	if err == nil {
		return false //cert is still valid! yay!
	} else if err == cert.ErrBlockListed { //avoiding errors.Is for speed
		// Block listed certificates should always be disconnected
		hostinfo.logger(cm.l).Info("Remote certificate is blocked, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else if cm.intf.disconnectInvalid.Load() {
		hostinfo.logger(cm.l).Info("Remote certificate is no longer valid, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else {
		//if we reach here, the cert is no longer valid, but we're configured to keep tunnels from now-invalid certs open
		return false
	}
}
