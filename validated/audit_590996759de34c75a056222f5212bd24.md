### Title
Per-extension patch byte limit override bypasses the enforced maximum patch size, enabling unbounded memory buffering (DoS) - ([File: internal/gitaly/diff/diff.go])

### Summary
`Limits.enforceUpperBound()` clamps every numeric diff limit to a safe upper bound, **except** the per-file-extension override map `MaxPatchBytesForFileExtension`. Because this map's values are used verbatim to gate how much patch data Gitaly buffers per file, a caller can set an arbitrarily large (or unbounded) limit for a given file extension and have it silently take priority over the enforced `MaxPatchBytes` ceiling — mirroring the reported "computed value exceeding the maximum allowed amount" bug class (an unvalidated derived value overriding an intended cap).

### Finding Description
`Limits` carries both a global `MaxPatchBytes` and a per-extension override `MaxPatchBytesForFileExtension map[string]int` [1](#0-0) . When a new parser is created, `enforceUpperBound()` clamps `MaxFiles`, `MaxLines`, `MaxBytes`, `SafeMax*` and `MaxPatchBytes` to their respective hard-coded upper bounds, but it never touches the values stored inside `MaxPatchBytesForFileExtension`: [2](#0-1) 

The per-file size check that is supposed to enforce the ceiling then resolves the limit via `maxPatchBytesForCurrentFile()` → `maxPatchBytesFor()`, which returns the extension-specific value unmodified whenever a match is found, completely bypassing `MaxPatchBytes` (and therefore its enforced upper bound, `maxPatchBytesUpperBound = 512000`): [3](#0-2) 

That result is consumed directly in `Parse()` to decide whether to prune the growing `Patch` buffer: [4](#0-3) 

`MaxPatchBytesForFileExtension` is populated from an RPC-facing field on the diff request (referenced in `internal/gitaly/service/diff/commit_diff.go`), so this map is attacker-controlled input, analogous to the vesting contract's unclamped `allowedToClaim` computation that could exceed the intended vesting cap.

### Impact Explanation
An ordinary client issuing a `CommitDiff`/related diff RPC can set `MaxPatchBytesForFileExtension["someext"]` to a very large integer (e.g. `math.MaxInt`). For any file with that extension, Gitaly will never prune the patch even though the operator/service intended to hard-cap all patches at `maxPatchBytesUpperBound` (500KB) via `enforceUpperBound()`. Combined with `PatchLimitsOnly` (which disables the aggregate `MaxBytes`/`MaxLines` checks), this allows an attacker to force Gitaly to buffer an effectively unbounded single-file patch fully in memory, defeating the resource-limiting safeguard and creating a memory-exhaustion DoS vector on the RPC handler.

### Likelihood Explanation
The request field is directly exposed to any authenticated client able to invoke the diff RPCs (no privileged access required), and exploiting it only requires crafting a request with a controlled extension-to-limit mapping and a file of that extension with a large patch — no race conditions or special server state needed.

### Recommendation
In `enforceUpperBound()`, iterate over `MaxPatchBytesForFileExtension` and clamp every value to `maxPatchBytesUpperBound` (or reject/ignore per-extension limits that exceed it), so the per-extension override can only ever narrow, never widen, the enforced maximum patch size.

### Proof of Concept
1. Issue a `CommitDiff` (or equivalent) RPC request with `EnforceLimits: true`, `MaxPatchBytes: 1000`, and `MaxPatchBytesForFileExtension: {".txt": 2147483647}`.
2. Include a commit whose diff touches a very large `.txt` file (larger than `maxPatchBytesUpperBound`).
3. Observe that `maxPatchBytesForCurrentFile()` returns `2147483647` instead of the clamped `MaxPatchBytes`/`maxPatchBytesUpperBound`, so `parser.prunePatch()` is never invoked for that file and the full patch is buffered and returned, unbounded by the intended 500KB cap. [4](#0-3)

// enforceUpperBound ensures every limit value is within its corresponding upperbound
func (limit *Limits) enforceUpperBound() {
	limit.MaxFiles = min(limit.MaxFiles, maxFilesUpperBound)
	limit.MaxLines = min(limit.MaxLines, maxLinesUpperBound)
	limit.MaxBytes = min(limit.MaxBytes, maxBytesUpperBound)
	limit.SafeMaxFiles = min(limit.SafeMaxFiles, safeMaxFilesUpperBound)
	limit.SafeMaxLines = min(limit.SafeMaxLines, safeMaxLinesUpperBound)
	limit.SafeMaxBytes = min(limit.SafeMaxBytes, safeMaxBytesUpperBound)
	limit.MaxPatchBytes = min(limit.MaxPatchBytes, maxPatchBytesUpperBound)
}

func (parser *Parser) maxPatchBytesForCurrentFile() int {
	return maxPatchBytesFor(parser.limits.MaxPatchBytes, parser.limits.MaxPatchBytesForFileExtension, parser.Diff().ToPath)
}

func maxPatchBytesFor(maxPatchBytes int, maxBytesForExtension map[string]int, toPath []byte) int {
	if len(maxBytesForExtension) > 0 {
		fileName := filepath.Base(string(toPath))
		key := filepath.Ext(fileName)

		if key == "" {
			key = fileName
		}

		if limitForExtension, ok := maxBytesForExtension[key]; ok {
			return limitForExtension
		}
	}

	return maxPatchBytes
}
