### Title
Unauthenticated `RecvError` packet spoofing allows remote attacker to force tunnel teardown (DoS) - (File: outside.go)

### Summary
`Interface.handleRecvError` processes an incoming `header.RecvError` control packet without any cryptographic authentication. It looks up a hostinfo purely by the cleartext `RemoteIndex` field and, if the sender's UDP source address matches the currently-known remote for that hostinfo (or if no remote has been recorded yet), it immediately tears down the tunnel via `f.closeTunnel(hostinfo)` and deletes the pending hostinfo. Because UDP source addresses are trivially spoofable and the check relies solely on address/port equality rather than any handshake-derived secret, an attacker who learns or guesses a victim's `RemoteIndex` (which is sent in cleartext on every packet of that tunnel) can forge a `RecvError` packet appearing to come from the victim's legitimate peer and force a repeated, low-cost denial-of-service against an established tunnel — directly analogous to the reported pattern of a malicious external actor being able to trigger a legitimate protocol path (via an unauthenticated side-channel) to abort/undo useful, intended protocol work at negligible cost and with repeatability.

### Finding Description
`RecvError` is one of the few packet types handled entirely outside the encrypted/authenticated tunnel path: [1](#0-0) 

Inside the handler, the only authentication performed is comparing the incoming UDP source address to the hostinfo's *currently cached* remote address — not any Noise/handshake-derived MAC, sequence number, or session key: [2](#0-1) 

Key problems:
- `h.RemoteIndex` is carried in the cleartext header of ordinary tunnel traffic (`header.Encode`), so it is not a secret protecting this control message; anyone who can observe (or, on shared/broadcast/misconfigured networks, sniff) even a single packet of a target's active tunnel obtains the index needed to spoof a `RecvError` for that tunnel.
- The only anti-spoofing check is `hr.IsValid() && hr != addr` — a plain source-address string/tuple compare. UDP has no built-in source authentication, so an attacker can trivially set the source IP:port of a forged packet to the value they expect the hostmap to have for `hr` (the peer's known/publicly-observable endpoint), defeating this check entirely.
- If `hr` is not yet valid/set (e.g., very early in the tunnel lifetime, or for certain in-progress roaming/relay states), the check is skipped altogether and the spoofed packet is accepted unconditionally.
- Successful delivery immediately calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, destroying an established, legitimate tunnel with a single 1-byte-header UDP packet, at essentially zero cost to the attacker, and the attack can be repeated indefinitely to prevent tunnel re-establishment from ever completing (goal similar to the ETH-report's DoS being repeatable "at no significant cost").

This is reachable by a network attacker who holds **no CA-signed Nebula certificate** and never participates in a handshake — it is a pure packet/header-trust issue in the outside (UDP-facing) receive path, matching the requested analog classes of "packet/header parsing" and "hostmap/lighthouse/relay address trust."

### Impact Explanation
A successful forged `RecvError` causes:
- Immediate teardown of an active, legitimate Nebula tunnel between two authenticated peers.
- Removal of the corresponding pending hostinfo, which can be repeated to prevent re-establishment, producing a sustained denial-of-service against the overlay connection between two victims — the network-level analog of the referenced report's repeatable, cheap DoS against the buy-back path.
- Because the check is address-based rather than cryptographic, this does not require breaking Noise or forging a certificate; it only requires learning a 32-bit index value and being able to spoof (or otherwise present) a matching UDP source address.

### Likelihood Explanation
Likelihood is conditioned on the runtime `recvErrorConfig` (`recvErrorAlways` / `recvErrorPrivate` / `recvErrorNever`, controlled via `acceptRecvErrorConfig`) gating whether `handleRecvError` acts on a packet from a given endpoint at all: [3](#0-2)  — when the accept policy is permissive for the attacker's presented (spoofed) source (e.g., `recvErrorAlways`, or `recvErrorPrivate` combined with a spoofed private-range source when the victim is inside that private range), the path is fully reachable pre-authentication. Discovery of the `RemoteIndex` requires only observing one packet from the target tunnel (it is unencrypted header metadata on every packet), and UDP source spoofing is a standard, low-effort primitive absent egress/ingress filtering (BCP38) on the attacker's or intermediate network. This mirrors the original report's requirement of nothing more than the ability to interact with an already-public, unauthenticated code path (there: `refundETH`/unsolicited ETH transfer to a pool; here: an unauthenticated UDP control packet) to sabotage the legitimate flow repeatedly.

### Recommendation
- Do not allow tunnel teardown to be triggered by an unauthenticated cleartext control message keyed only on address equality. At minimum, require that `RecvError` handling only acts when it is consistent with recent authenticated traffic (e.g., tie it to the current session's replay/counter window and require it be accompanied by, or immediately follow, a verifiable encrypted indicator from the peer) rather than trusting raw UDP source address matching.
- Treat `RemoteIndex` as attacker-observable and non-secret; do not use it as the sole selector for a state-destroying action.
- Consider authenticating `RecvError` (e.g., an authenticated/short-MAC'd error notification derived from the session's established keys) so a third party cannot forge it even when they know the index and can spoof the source address.
- Rate-limit/backoff tunnel teardown-and-rebuild triggered by `RecvError` per peer to blunt repeated forged-teardown DoS even if full authentication isn't added immediately.

### Proof of Concept
1. Attacker passively observes (or otherwise learns) a single packet exchanged between victim `A` and its legitimate peer `B` over an established Nebula tunnel, extracting the cleartext `RemoteIndex` value used by `A`'s hostinfo for that tunnel (present in every packet's header per `header.Encode`/`header.Parse`).
2. Attacker crafts a UDP packet with header `Type = header.RecvError`, `RemoteIndex` = the observed index, and spoofs the UDP source address/port to match `B`'s known endpoint (the value `A`'s hostmap currently has cached as `hr` in `hostinfo.GetRemote()`).
3. Attacker sends this forged packet to `A`'s listening UDP port.
4. `A.readOutsidePackets` dispatches directly to `f.handleRecvError(via.UdpAddr, h)` for `header.RecvError` type packets without any decryption/authentication: [4](#0-3) 
5. `handleRecvError` finds the hostinfo via `QueryReverseIndex(h.RemoteIndex)`, sees the spoofed `addr` matches the cached `hr`, and calls `f.closeTunnel(hostinfo)` plus `DeleteHostInfo`, tearing down `A`'s side of the tunnel with `B`: [5](#0-4) 
6. Attacker repeats this whenever `A` and `B` attempt to re-handshake (learning the new index from any observed packet), sustaining a denial-of-service on the `A`↔`B` tunnel at negligible cost, analogous to the original report's ability to repeatedly and cheaply block the intended protocol operation.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```

```go
type recvErrorConfig uint8

const (
	recvErrorAlways recvErrorConfig = iota
	recvErrorNever
	recvErrorPrivate
)

func (s recvErrorConfig) ShouldRecvError(endpoint netip.AddrPort) bool {
	switch s {
	case recvErrorPrivate:
		return endpoint.Addr().IsPrivate()
	case recvErrorAlways:
		return true
	case recvErrorNever:
		return false
	default:
		panic(fmt.Errorf("invalid recvErrorConfig value: %d", s))
	}
}
```
