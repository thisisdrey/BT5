### Title
Out-of-bounds slice panic in ELF relocation addend parsing during `go build`/link - ([File: src/cmd/link/internal/loadelf/ldelf.go])

### Summary
`cmd/link/internal/loadelf.Load` parses relocation entries from an ELF relocatable object file supplied to the Go linker (for example via a `.syso` file bundled in a package, which `cmd/go` automatically includes in the link without requiring cgo). When computing the addend for a REL-type (non-RELA) relocation, the code indexes the target section's byte slice using the attacker-controlled relocation offset `rOff` with no bounds validation, which can cause the linker to panic on a crafted object.

### Finding Description
Attacker input: a hand-crafted ELF relocatable (`ET_REL`) object file placed as a `.syso` file inside a published Go module (or supplied as a cgo-produced `.o`). `cmd/go`'s `SysoFiles` handling passes such files straight to `cmd/link` at build time [1](#0-0) . The Go entry point is `loadelf.Load` in `src/cmd/link/internal/loadelf/ldelf.go`, which walks each `SHT_REL`/`SHT_RELA` section and, for `SHT_REL` (no explicit addend field), reads the addend from the relocation target section itself: [2](#0-1) 
Specifically, `rOff` is parsed directly from the untrusted relocation entry (`rOff = int32(e.Uint32(p))` or the 64-bit equivalent) with no validation against the size of `sect.base` (the mapped target section, sized to `sect.size` via `elfmap`) [3](#0-2) . The subsequent addend load:
```
if rSize == 4 {
    rAdd = int64(e.Uint32(sect.base[rOff:]))
} else if rSize == 8 {
    rAdd = int64(e.Uint64(sect.base[rOff:]))
}
```
performs no check that `rOff` is within `[0, len(sect.base))`. A crafted relocation with a negative or excessively large `rOff` triggers a Go runtime "index out of range" panic, crashing `cmd/link` (and thus `go build`).

### Impact Explanation
This is a denial-of-service via crash of the build/link tool when processing an untrusted, attacker-supplied object file — the same bug class as the CVE (crafted binary relocation causing out-of-bounds access), translated to Go's safe-memory model as a panic rather than heap corruption. Under Go's PUBLIC track, unhardened parsing of malicious binary object inputs that causes a build-tool panic is a legitimate report category (a "plausible malicious-input parser panic"), distinct from generic resource exhaustion.

### Likelihood Explanation
The victim workflow is completely ordinary: fetching and building/testing a Go module that ships a `.syso` file (a documented, no-cgo-required mechanism for bundling native object code into a package) or building a package with a malicious cgo-produced object. The attacker needs no privileges beyond publishing a module — reaching this code requires no `CGO_ENABLED`-specific configuration beyond the internal linker parsing the object, since `SysoFiles` are linked automatically.

### Recommendation
Add explicit bounds checks on `rOff` (and the read length) against `len(sect.base)` before indexing in the REL addend-loading branch of `loadelf.Load` (and audit the equivalent code paths in `loadmacho`/`loadpe` for the same pattern), returning a `malformed elf file` error instead of allowing an out-of-range slice access.

### Proof of Concept
```go
package loadelf

// Conceptual reproduction: construct a minimal ET_REL ELF64 object with:
// - one PROGBITS section "sect" of size 4 (base length 4)
// - one SHT_REL section referencing "sect" via sh_info,
//   containing a single Elf64_Rel entry with r_offset = 0x7fffffff
//   (or a negative int32 offset) and a relocation type whose relSize == 4.
//
// Feeding this file to loadelf.Load(...) causes:
//   rOff = 0x7fffffff (int32)
//   rAdd = int64(e.Uint32(sect.base[rOff:]))  // sect.base has len 4
// which panics with "runtime error: slice bounds out of range [2147483647:4]"
// instead of returning a graceful "malformed elf file" error.
//
// Expected (fixed) behavior: Load returns a non-nil error such as
// "loadelf: <file>: malformed elf file: relocation offset out of range"
// and cmd/link does not panic.
```

func elfmap(elfobj *ElfObj, sect *ElfSect) (err error) {
	if sect.base != nil {
		return nil
	}

	if sect.off+sect.size > uint64(elfobj.length) {
		err = fmt.Errorf("elf section past end of file")
		return err
	}

	elfobj.f.MustSeek(int64(uint64(elfobj.base)+sect.off), 0)
	sect.base, sect.readOnlyMem, err = elfobj.f.Slice(sect.size)
	if err != nil {
		return fmt.Errorf("short read: %v", err)
	}

	return nil
}
