Audit Report

## Title
Failed inbound XCM processing leaves relayed Ethereum message nonce unmarked, enabling unbounded replay and non-idempotent re-execution - (File: bridges/snowbridge/pallets/inbound-queue-v2/src/lib.rs)

## Summary
`snowbridge-pallet-inbound-queue-v2`'s `process_message` marks a message nonce as received via `Nonce::<T>::set(nonce)` before invoking `T::MessageProcessor::process_message`. Because `submit`/`process_message` is a standard `#[pallet::call]` dispatchable, FRAME wraps it in a storage transaction (`with_storage_layer`), so any `Err` returned by the processor call rolls back the nonce write along with all other state, leaving the message eligible for identical resubmission with no record that execution was ever attempted.

## Finding Description
`process_message` performs `ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce)` then `Nonce::<T>::set(nonce)`, and only afterward calls `T::MessageProcessor::process_message(relayer.clone(), message)`, propagating any error via `.map_err(...)?` [6](#0-5) . The concrete processor wired into BridgeHub, `XcmMessageProcessor`, can fail for reasons unrelated to message validity: `AccountToLocation::try_convert` failing (`SendError::NotApplicable`), `Executor::charge_fees` failing due to an underfunded fee payer (`SendError::Fees`), or `Sender::deliver` failing [5](#0-4) , as well as `Converter::convert` failing with `ConvertMessageError` [7](#0-6) . All of these propagate as `Err` from `process_message`, and thus from `submit`.

FRAME's `#[pallet::call]` macro documents that every generated dispatchable "will be wrapped via `frame_support::storage::with_storage_layer` to make it transactional. Thus if the extrinsic returns with an error any state changes that had already occurred will be rolled back" [1](#0-0) . This is implemented by `with_storage_layer`/`with_transaction`, which calls `sp_io::storage::rollback_transaction()` whenever the closure returns `Err` [2](#0-1) , and is verified generically for nested storage maps/values in `substrate/frame/support/test/tests/storage_transaction.rs` [8](#0-7) . `Nonce::<T>::set` is backed by an ordinary `StorageMap` mutation (`BitMap::mutate`) with no special persistence outside this layer [3](#0-2) , so it is rolled back exactly like any other storage write when `process_message` returns `Err`.

Consequently, after a failed `submit`, `Nonce::<T>::get(nonce)` reverts to `false`, and the `ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce)` guard on the next call for the same nonce passes again, allowing indefinite resubmission of the same proven event log.

## Impact Explanation
This matches the "public underpriced work that degrades block production or stalls bridge processing" impact class: a permissionless caller can craft or select an Ethereum event whose XCM processing deterministically fails (e.g., an unfunded/unregistered fee-payer conversion, or an asset/destination combination that fails `charge_fees`/`validate_send`), and any relayer submitting the correctly-proven event pays the `submit` extrinsic's weight/fee every time while the bridge nonce is never durably marked as attempted. There is no expiry or "processed but failed" marker, so the same message can be replayed arbitrarily far into the future and could unexpectedly succeed later if chain conditions change (e.g., the fee payer becomes funded), producing delayed and non-idempotent execution of a message the emitting/receiving system may have assumed was dead.

## Likelihood Explanation
High. `submit` is a public extrinsic requiring only `ensure_signed` [9](#0-8) . Triggering the failure path requires only a message whose XCM conversion/fee-charging/routing fails at execution time, none of which need privileged access — the underlying light-client proof of the Ethereum event can be entirely legitimate.

## Recommendation
Persist an explicit tri-state (unseen / processed / failed) for the nonce that survives regardless of `MessageProcessor::process_message`'s outcome — e.g., wrap only the processor call in its own inner `with_transaction` scope, catch its error, and unconditionally commit a "failed" nonce marker plus a `MessageProcessingFailed` event in the outer scope while returning `Ok(())`, rather than propagating the error and rolling back the whole extrinsic. Consider adding an expiry/TTL so a once-failed message cannot be silently retried under different future chain conditions.

## Proof of Concept
1. Emit a valid Ethereum Gateway event for nonce `N` whose converted XCM requires fee payment that the relayer's `fee_payer` location/account cannot cover.
2. Call `InboundQueueV2::submit(origin, event)`. `T::Verifier::verify` and `Message::try_from` succeed; `process_message` executes `Nonce::<T>::set(N)`, then `T::MessageProcessor::process_message` fails at `Executor::charge_fees` with `SendError::Fees`, mapped to `Error::<T>::FeesNotMet`, propagated as `Err`.
3. Because `submit` is dispatched inside FRAME's `with_storage_layer`, the whole storage transaction rolls back, restoring `Nonce::<T>::get(N)` to `false` (demonstrated generically for nested `StorageMap`/`StorageValue` rollback in `storage_transaction_rollback_then_commit` at `substrate/frame/support/test/tests/storage_transaction.rs:160-204`).
4. Any relayer resubmits the identical `EventProof` for nonce `N`; `ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce)` passes again, and the failure/cost repeats indefinitely.

/// Execute the supplied function, adding a new storage layer.
///
/// This is the same as `with_transaction`, but assuming that any function returning an `Err` should
/// rollback, and any function returning `Ok` should commit. This provides a cleaner API to the
/// developer who wants this behavior.
pub fn with_storage_layer<T, E, F>(f: F) -> Result<T, E>
where
	E: From<DispatchError>,
	F: FnOnce() -> Result<T, E>,
{
	with_transaction(|| {
		let r = f();
		if r.is_ok() {
			TransactionOutcome::Commit(r)
		} else {
			TransactionOutcome::Rollback(r)
		}
	})
}

	impl<T: Config> Pallet<T> {
		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}
