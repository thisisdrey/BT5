### Title
Missing `discard` flag check in `TransactionViewReceiveAndBuffer::handle_packet_batch_message` allows signature-unverified packets to reach banking/PoH - (File: `core/src/banking_stage/transaction_scheduler/receive_and_buffer.rs`)

### Summary
`core::sigverify::run_transaction_task` only skips forwarding a batch to `banking_stage_sender` when **all** packets in it are discarded (`num_valid_packets == 0`); a batch containing a mix of valid and sigverify-failed packets is forwarded whole, discard flags intact. [1](#0-0)  The consumer of that channel, `TransactionViewReceiveAndBuffer::handle_packet_batch_message`, iterates every packet in the received `BankingPacketBatch` and never checks `packet.meta().discard()` before parsing/sanitizing/queuing it. [2](#0-1) 

### Finding Description
`run_transaction_task` dedups the batch, then runs `sigverify::ed25519_verify_serial`, which sets `discard = true` only on the individual packets that fail signature verification (`perf/src/sigverify.rs::verify_packet`/`ed25519_verify_serial`), leaving other packets in the same `PacketBatch` untouched. [3](#0-2)  The function then computes `num_valid_packets` and only returns early ("do not forward") if the **entire** batch is invalid:
```
if num_valid_packets == 0 { return true; }
```
Otherwise the *whole* `batch` — including any packets still flagged `discard=true` — is wrapped in `BankingPacketBatch::new(batch)` and sent to `banking_stage_sender`. [4](#0-3) 

Downstream, `TransactionViewReceiveAndBuffer::handle_packet_batch_message` is the consumer that turns `BankingPacketBatch` messages into buffered transactions for scheduling/execution. It iterates `packet_batch_message.iter()` and only skips a packet if `packet.data(..)` returns `None`; there is no check of `packet.meta().discard()` anywhere in this function or in `try_handle_packet`/`translate_to_runtime_view`. [2](#0-1) [5](#0-4)  `translate_to_runtime_view` only performs format sanitization (`SanitizedTransactionView::try_new_sanitized`, ALT resolution, account-lock-limit checks, `validate_account_locks`) — none of these re-verify Ed25519 signatures. [6](#0-5)  A grep across `core/src/banking_stage/**` confirms `meta().discard()` is checked nowhere in the banking-stage receive path (only 4 unrelated matches inside `receive_and_buffer.rs` for stats naming), unlike `perf/src/sigverify.rs` and `turbine/src/sigverify_shreds.rs`, which do consistently check `discard()` before further processing.

Exploit flow for an unprivileged attacker (no staked/leader access needed, only a TPU packet send):
1. Craft two distinct (non-duplicate, to avoid the deduper) packets in one `PacketBatch`: packet A with a valid signature (e.g., a trivial self-transfer) and packet B, byte-identical in structure but with a corrupted/forged signature.
2. `dedup_packets_and_count_discards` does not discard either (they hash differently), so `discard_or_dedup_fail != batch_len`.
3. `ed25519_verify_serial` sets `discard=true` only on packet B; `count_valid_packets` returns 1, so the early-return at `num_valid_packets == 0` does not trigger.
4. The batch (A valid, B discarded-but-still-present) is sent whole to `banking_stage_sender`.
5. `TransactionViewReceiveAndBuffer::handle_packet_batch_message` processes both packets without consulting `meta().discard()`, so packet B (invalid signature) is sanitized, account-lock-checked, and inserted into the transaction priority queue exactly like packet A.
6. If it survives cost/age/fee-payer checks (which do not depend on signature correctness), it can be scheduled, locked, executed, and recorded into PoH by `Consumer`/banking execution — producing a block containing a transaction whose signature was never valid, i.e., an executed transaction that never passed "every packet reaching banking has passed sanitization and signature verification."

This directly matches the stated invariant violation: the early-return in `run_transaction_task` is a batch-level ("all discarded") guard, not a per-packet guard, and the consumer relies on that guard alone instead of re-checking the discard flag per packet.

### Impact Explanation
An unstaked remote attacker can get a signature-unverified transaction accepted into the banking pipeline and potentially committed/executed as part of a leader's produced block, violating the core invariant that only sigverify-passed transactions reach PoH recording. This is a verification-bypass / invalid-recorded-block class issue under the scope described (entries not matching actually-verified transactions), matching the "Critical" bounty category referenced in the prompt (invalid block / verification bypass).

### Likelihood Explanation
Trivial to trigger and fully repeatable: it only requires the attacker to place at least one valid-signature packet alongside one (or more) invalid-signature packets in the same UDP/QUIC send batch to the TPU. No staking, gossip presence, or leader status is required — this is a pure ingress-path bug reachable by any unstaked client. The only constraint is that the two packets must not hash-collide as identical bytes in the deduper (trivially avoided by minor payload variation).

### Recommendation
In `TransactionViewReceiveAndBuffer::handle_packet_batch_message` (and any other `BankingPacketBatch` consumer, e.g. `vote_packet_receiver.rs::buffer_packet_batch`), explicitly skip packets where `packet.meta().discard()` is `true`, mirroring the pattern already used in `perf/src/sigverify.rs` and `turbine/src/sigverify_shreds.rs`, before any parsing/sanitization/queuing occurs.

    fn try_handle_packet(
        bytes: Bytes,
        root_bank: &Bank,
        working_bank: &Bank,
        transaction_account_lock_limit: usize,
        sanitize_config: &SanitizeConfig,
        filter_keys: &HashSet<Pubkey>,
    ) -> Result<TransactionViewState, PacketHandlingError> {
        let (view, deactivation_slot) = translate_to_runtime_view(
            bytes,
            root_bank,
            transaction_account_lock_limit,
            sanitize_config,
        )?;

        if !filter_keys.is_empty()
            && view
                .account_keys()
                .iter()
                .any(|key| filter_keys.contains(key))
        {
            return Err(PacketHandlingError::FilterKey);
        }

        let Ok(transaction_configuration) =
            view.transaction_configuration(&working_bank.feature_set)
        else {
            return Err(PacketHandlingError::ComputeBudget);
        };

        let max_age = calculate_max_age(root_bank.epoch(), deactivation_slot, root_bank.slot());
        let (priority, cost) =
            calculate_priority_and_cost(working_bank, &view, &transaction_configuration);

        Ok(TransactionState::new(view, max_age, priority, cost))
    }
}

/// Perform sanitization checks and transition from data to an executable
/// [`RuntimeTransaction`]. This additionally returns the minimum slot for
/// ALT deactivation, if any. If no minimum slot, Slot::MAX is returned.
pub(crate) fn translate_to_runtime_view<D: TransactionData>(
    data: D,
    bank: &Bank,
    transaction_account_lock_limit: usize,
    sanitize_config: &SanitizeConfig,
) -> Result<(RuntimeTransaction<ResolvedTransactionView<D>>, u64), PacketHandlingError> {
    // Parsing and basic sanitization checks
    let Ok(view) = SanitizedTransactionView::try_new_sanitized(data, sanitize_config) else {
        return Err(PacketHandlingError::Sanitization);
    };

    let Ok(view) = RuntimeTransaction::<SanitizedTransactionView<_>>::try_new(
        view,
        MessageHash::Compute,
        None,
    ) else {
        return Err(PacketHandlingError::Sanitization);
    };

    // Discard non-vote packets if in vote-only mode.
    if bank.vote_only_bank() && !view.is_simple_vote_transaction() {
        return Err(PacketHandlingError::Sanitization);
    }

    if usize::from(view.total_num_accounts()) > transaction_account_lock_limit {
        return Err(PacketHandlingError::LockValidation);
    }

    let (loaded_addresses, deactivation_slot) = load_addresses_for_view(&view, bank)?;

    let Ok(view) = RuntimeTransaction::<ResolvedTransactionView<_>>::try_new(
        view,
        loaded_addresses,
        bank.get_reserved_account_keys(),
    ) else {
        return Err(PacketHandlingError::Sanitization);
    };

    // Validate no duplicate accounts (must be after resolution to catch ALT duplicates)
    if validate_account_locks(view.account_keys(), transaction_account_lock_limit).is_err() {
        return Err(PacketHandlingError::LockValidation);
    }

    Ok((view, deactivation_slot))
}

pub fn ed25519_verify_serial(batch: &mut PacketBatch, reject_non_vote: bool, enable_tx_v1: bool) {
    for mut packet in batch.iter_mut() {
        if !packet.meta().discard() && !verify_packet(&mut packet, reject_non_vote, enable_tx_v1) {
            packet.meta_mut().set_discard(true);
        }
    }
