### Title
Unauthenticated remote shutdown of `SignerEventReceiver` via `POST /shutdown` - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` treats any HTTP request whose URL is `/shutdown` as a valid termination command, with no check of the sender's identity, source address, or any shared secret. Any TCP peer that can reach the signer's event-observer HTTP port can permanently halt the signer's event ingestion loop with a single crafted HTTP request.

### Finding Description
The equality claimed to hold — "only the co-located Stacks node that owns this signer may stop its event loop" — is violated because `next_event` dispatches purely on `request.url()` string matching, with no origin/auth check anywhere in the request-handling path: [1](#0-0) 

Specifically:
```
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
```
There is no verification of the peer's IP/socket, no bearer token, and no comparison against the `SignerStopSignaler`'s own address that legitimately triggers this path (the stop signaler itself just connects a `TcpStream` to `self.local_addr` and sends the same unauthenticated `POST /shutdown` request — see `SignerStopSignaler::send`, lines 376-396). The listener is a `tiny_http::Server` bound via `bind()` to whatever socket address is configured for the signer's event observer endpoint; it accepts any TCP connection that can reach that port and interprets any well-formed HTTP POST to `/shutdown` identically, regardless of source.

Once `Err(EventError::Terminated)` propagates out of `next_event`, `EventReceiver::main_loop` (lines 284-312) matches `Err(EventError::Terminated) => break`, permanently exiting the loop. Since `is_stopped()` (backed by the same `AtomicBool`) will now always return `true`, the receiver cannot be restarted without a process restart — there is no code path that resets `stop_signal` to `false`.

### Impact Explanation
A single unauthenticated HTTP POST permanently kills the signer's event-ingestion thread. After this, `out_channels` never receive any further `SignerEvent`s (`StackerDB` chunk events, block proposals, burn block events, block validation responses), silently taking that signer out of the signing protocol until the operator manually restarts the process. This matches the "Critical — remote crash/unauthenticated DoS from few messages" category since it requires just one message and yields a persistent denial of service against a component required for a functioning signer.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's event-observer HTTP endpoint (the same port the co-located Stacks node uses to POST events to the signer). No secret, credential, peer identity, or StackerDB slot ownership is required — the attacker only needs to be able to open a TCP connection and send well-formed HTTP bytes, i.e., an "unprivileged remote attacker" as defined. If the event-observer endpoint is bound to an interface reachable beyond localhost (which is an operator/deployment configuration choice, not enforced in code), this is trivially and repeatably exploitable with a single request per restart cycle.

### Recommendation
Do not accept `/shutdown` (or any control command) from arbitrary remote peers. Options: (1) restrict the stop signal to an in-process/loopback-only mechanism (e.g., a local Unix socket, an internal channel, or verifying `request.remote_addr()` equals `127.0.0.1`/the bound loopback address) instead of an HTTP endpoint reachable by anyone who can hit the listener; (2) require a shared secret/token generated at startup and included by `SignerStopSignaler`, checked via constant-time comparison before honoring `/shutdown`; (3) at minimum, reject `/shutdown` requests whose `request.remote_addr()` does not match the loopback interface used internally by `SignerStopSignaler`.
