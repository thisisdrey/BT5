Audit Report

## Title
Fork/clone replay of ERC20Permit signatures due to static `ChainId` config constant not bound to genesis hash - (File: `substrate/frame/assets/precompiles/src/permit.rs`)

## Summary
The `pallet-assets-precompiles` permit pallet builds its EIP-712 domain separator from `T::ChainId::get()` — a compile-time/runtime `#[pallet::constant] Get<u64>` — plus only the `verifying_contract` address and token `name`, with no chain-unique fingerprint such as the genesis hash mixed in. Two independently deployed chains (e.g., production and a testnet/staging clone) that configure the same numeric `ChainId` and end up with the same deterministic precompile address for an asset will produce byte-identical domain separators and permit digests, making a signature valid on one chain replayable on the other.

## Finding Description
`compute_domain_separator` hashes `DOMAIN_TYPEHASH`, `keccak256(name)`, `keccak256("1")`, `chain_id = T::ChainId::get()`, and `verifying_contract` [1](#0-0) . `T::ChainId` is declared as a plain runtime config constant with no linkage to the chain's genesis hash or any other unique network fingerprint [2](#0-1) . This is confirmed in the mock runtime, where `ChainId` is a hardcoded `parameter_types!` constant (`31337`) [3](#0-2) , i.e., an arbitrary value chosen by the runtime integrator, with no mechanism preventing reuse across separately deployed chains.

`permit_digest` combines this domain separator with the struct hash of `(owner, spender, value, nonce, deadline)` [4](#0-3) , and `do_verify_permit`/`use_permit` recover the signer from this digest and gate approval solely on `recovered == owner`, with the nonce keyed only by `(verifying_contract, owner)` in chain-local storage [5](#0-4) [6](#0-5) . Substrate's native extrinsic replay protection (`CheckGenesis`) explicitly binds to `block_hash(0)` for exactly this reason — to distinguish forked/cloned chains sharing the same spec — but the permit domain separator has no analogous binding [7](#0-6) . The existing test suite only verifies that the separator varies with `verifying_contract` and `name`, never with any chain-identity value [8](#0-7) .

## Impact Explanation
If two chains share the same `ChainId` constant and the same deterministic `verifying_contract` address for an asset (both plausible via config copy-paste between mainnet and testnet/staging/disaster-recovery deployments), a permit signature authorized by an owner on one chain is valid and unconsumed on the other, since nonces are chain-local storage starting at zero independently. This allows an attacker holding a leaked or observed permit signature to replay it and obtain an unauthorized ERC20 allowance on the second chain, which the token owner never intended to grant there — an unauthorized allowance/approval creation matching the "unauthorized execution" / theft-of-value impact class.

## Likelihood Explanation
This requires no privileged access, malicious validator, or compromised infrastructure — only an operational condition (two independently deployed chains reusing the same `ChainId` value and asset index), which is a realistic and common practice since `ChainId` is an arbitrary developer-chosen constant with no uniqueness enforcement in this codebase, unlike Substrate's own genesis-hash-based `CheckGenesis` replay protection.

## Recommendation
Bind the domain separator to a value that is guaranteed unique per deployed chain instance, such as `frame_system::Pallet::<T>::block_hash(BlockNumberFor::<T>::zero())` (genesis hash), in addition to or instead of the static `T::ChainId`, mirroring the design of `CheckGenesis`. Alternatively, document and enforce that `ChainId` must be provably unique per deployment and provide tooling/guardrails (e.g., a startup check comparing configured `ChainId` against a registry) to prevent accidental collisions.

## Proof of Concept
1. Configure runtime A with `type ChainId = ConstU64<31337>` and deploy asset index `N`, yielding precompile address `verifying_contract`.
2. Configure an independently deployed runtime B (e.g., testnet clone) with the identical `type ChainId = ConstU64<31337>` and the same asset index `N`, yielding the same `verifying_contract`.
3. Owner signs `permit_digest(verifying_contract, name, owner, spender, value, nonce=0, deadline)` intending it for chain A.
4. Because `name`, `verifying_contract`, and `chain_id` are identical, and both chains' nonce for `(verifying_contract, owner)` starts at 0, `use_permit` on chain B accepts the same `(v, r, s)` and grants the spender an allowance that the owner never authorized on chain B, as shown by the digest construction in `compute_domain_separator`/`permit_digest` [1](#0-0) .

		pub fn compute_domain_separator(verifying_contract: &H160, name: &[u8]) -> H256 {
			let name_hash = keccak_256(name);
			let version_hash = keccak_256(b"1");
			let chain_id = T::ChainId::get();

			// Encode: typehash || name_hash || version_hash || chainId || verifyingContract
			let mut data = Vec::with_capacity(DOMAIN_SEPARATOR_ENCODED_LEN);
			data.extend_from_slice(&DOMAIN_TYPEHASH);
			data.extend_from_slice(&name_hash);
			data.extend_from_slice(&version_hash);
			// Pad chain_id to 32 bytes (big-endian)
			data.extend_from_slice(&[0u8; 24]);
			data.extend_from_slice(&chain_id.to_be_bytes());
			// Pad address to 32 bytes
			data.extend_from_slice(&[0u8; 12]);
			data.extend_from_slice(verifying_contract.as_bytes());

			H256(keccak_256(&data))
		}

		fn do_verify_permit(
			verifying_contract: &H160,
			name: &[u8],
			owner: &H160,
			spender: &H160,
			value: &[u8; 32],
			deadline: &[u8; 32],
			v: u8,
			r: &[u8; 32],
			s: &[u8; 32],
		) -> Result<(), Error<T>> {
			// EIP-2612: owner and spender cannot be the zero address
			if owner.is_zero() {
				return Err(Error::<T>::InvalidOwner);
			}
			if spender.is_zero() {
				return Err(Error::<T>::InvalidSpender);
			}

			// Validate deadline against current timestamp.
			// EIP-2612 specifies deadlines in UNIX seconds. We use the `UnixTime`
			// trait which returns a `core::time::Duration` — its `as_secs()` method
			// gives us seconds regardless of pallet_timestamp's internal resolution
			// (which stores milliseconds, converted via `Duration::from_millis` in
			// pallet_timestamp's `UnixTime` implementation).
			let now_seconds = <pallet_timestamp::Pallet<T> as UnixTime>::now().as_secs();
			let deadline_u256 = U256::from_big_endian(deadline);
			let now_u256 = U256::from(now_seconds);

			if deadline_u256 < now_u256 {
				return Err(Error::<T>::PermitExpired);
			}

			let nonce = Self::nonce(verifying_contract, owner);
			let digest = Self::permit_digest(
				verifying_contract,
				name,
				owner,
				spender,
				value,
				&nonce,
				deadline,
			);

			let recovered = Self::ecrecover(&digest, v, r, s)?;

			if &recovered != owner {
				return Err(Error::<T>::SignerMismatch);
			}

			Ok(())
		}
