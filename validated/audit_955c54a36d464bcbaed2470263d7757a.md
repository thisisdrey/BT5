### Title
Zero-share deposits are not rejected in `deposit`, allowing depositors to permanently lose their assets - (File: `mainnet/contracts/vault/v0-vault-usdc.clar` and the equivalent `v0-vault-*.clar` vaults)

### Summary
The `deposit` function computes shares via `convert-to-shares-preview` (round-down division) but never asserts that the resulting share amount is non-zero. In contrast, the sibling `redeem` function explicitly guards against a zero output. A depositor who does not (or cannot) rely on `min-out` slippage protection can deposit assets and receive `0` shares while the assets are still pulled into the vault, resulting in a complete, unrecoverable loss of the deposited funds.

### Finding Description
`convert-to-shares-preview` rounds down using `mul-div-down`: [1](#0-0) 

`deposit` uses this value directly as the amount to mint, and only checks that the deposited `amount` itself is non-zero and that `inkind >= min-out` (slippage) — there is no explicit assertion that `inkind > 0`: [2](#0-1) 

Compare this to `redeem`, which performs the mirror-image conversion (`convert-to-assets-preview`) and explicitly guards against a zero output with `ERR-OUTPUT-ZERO`: [3](#0-2) 

Because `total-supply-preview` (via accrued treasury LP) can grow much faster relative to `assets` than the deposited `amount`, once `ts` (shares) is small relative to `ta` (total assets, inflated by accrued interest), `amount * ts / ta` rounds to `0` for any `amount` below `ta / ts`. In that state, `deposit` will:
1. Pass `(asserts! (> amount u0) ERR-AMOUNT-ZERO)` (amount itself is non-zero).
2. Pass `(asserts! (>= inkind min-out) ERR-SLIPPAGE)` whenever `min-out` is `0` (the natural default if a caller does not compute a preview beforehand — e.g. a scripted/contract caller or a UI bug).
3. Pull the underlying asset from the caller via `receive-underlying`.
4. Mint `0` shares via `ft-mint? zft u0 recipient`.

The depositor's assets are transferred into the vault (increasing `assets`) but the depositor receives no vault shares (`zft`) in return, permanently losing their principal to the pool of existing shareholders. This affects every vault contract sharing this pattern (`v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-stx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`), all confirmed to share the identical `deposit`/`convert-to-shares-preview` logic.

### Impact Explanation
This is a direct, permanent loss of a depositor's principal (their own deposited funds), landing squarely in the Critical impact category ("direct theft of user funds at rest or in motion" / "permanent freezing of funds") — the assets are absorbed into the vault's `assets` counter and effectively redistributed to existing shareholders, while the depositor is left with zero shares and no path to recover the lost principal.

### Likelihood Explanation
Likelihood depends on the ratio of `total-assets-preview` to `total-supply-preview` growing large enough (via accrued interest / treasury-LP appreciation) relative to the deposit amount, and on the caller supplying `min-out = 0` (or a `min-out` that still permits `inkind = 0`, which is only possible when `min-out` is `0`). This is realistic for: (a) any integrator/contract caller that does not pre-compute an accurate `min-out` and defaults to `0`, or (b) small "dust" deposits made after the vault has accrued substantial interest, making `ts` small relative to `ta`. It is entirely within an ordinary unprivileged principal's control to trigger (self-inflicted or via a naive integration), and the vault-side code that should prevent it (present in `redeem`) is simply missing in `deposit`.

### Recommendation
Add an explicit assertion in `deposit` mirroring the one already present in `redeem`, e.g. `(asserts! (> inkind u0) ERR-OUTPUT-ZERO)`, before minting, so that a deposit that would produce zero shares always reverts regardless of the `min-out` value supplied by the caller.

### Proof of Concept
1. Vault is live with `total-supply-preview` (ts) small and `total-assets-preview` (ta) large due to accrued interest (e.g., ts = 100_000, ta = 100_000_000 in underlying's smallest unit).
2. Caller (Alice, or an integrating contract) calls `deposit` with `amount = 999`, `min-out = 0`, `recipient = Alice`.
3. `inkind = convert-to-shares-preview(999) = mul-div-down(999, 100_000, 100_000_000) = 0`.
4. Assertions pass: `amount > 0` ✓, `inkind (0) >= min-out (0)` ✓, cap-supply check ✓.
5. `receive-underlying` transfers Alice's 999 units into the vault; `ft-mint? zft 0 Alice` mints zero shares; `assets` is incremented by 999.
6. Alice has permanently lost 999 units of the underlying asset and holds no `zft` shares to redeem them back. [2](#0-1) [3](#0-2) [1](#0-0)

```text
(define-private (convert-to-shares-preview (amount uint))
  (let ((ta (total-assets-preview))
        (ts (total-supply-preview)))
    (if (is-eq ts u0)
        amount
        (if (is-eq ta u0)
            u0
            (mul-div-down amount ts ta)))))
```

```text
(define-public (deposit (amount uint) (min-out uint) (recipient principal))
    (let (
      (states (var-get pause-states))
      (u (try! (accrue)))
      (account contract-caller)
      (CAP-SUPPLY (var-get cap-supply))
      (current-assets (var-get assets))
      (inkind (convert-to-shares-preview amount)))

    (asserts! (not (get deposit states)) ERR-PAUSED)
    (asserts! (var-get initialized) ERR-INIT)
    (asserts! (not (var-get in-flashloan)) ERR-REENTRANCY)
    (asserts! (> amount u0) ERR-AMOUNT-ZERO)
    (asserts! (>= inkind min-out) ERR-SLIPPAGE)
    (asserts! (<= (+ current-assets amount) CAP-SUPPLY) ERR-SUPPLY-CAP-EXCEEDED)

    (try! (receive-underlying amount account))
    (try! (ft-mint? zft inkind recipient))
    (var-set assets (+ current-assets amount))

    (print {
      action: "deposit",
      caller: contract-caller,
      data: {
        depositor: account,
        recipient: recipient,
        amount: amount,
        shares-minted: inkind,
        assets: (+ current-assets amount)
      }
    })

    (ok inkind)))
```

```text
(define-public (redeem (amount uint) (min-out uint) (recipient principal))
  (let (
    (states (var-get pause-states))
    (u (try! (accrue)))
    (account contract-caller)
    (current-assets (var-get assets))
    (balance (get-balance-internal account))
    (balance-check (asserts! (>= balance amount) ERR-INSUFFICIENT-BALANCE))
    (available-assets (get-available-assets))
    (inkind (convert-to-assets-preview amount)))

  (asserts! (>= current-assets inkind) ERR-INSUFFICIENT-ASSETS)
  (asserts! (not (get redeem states)) ERR-PAUSED)
  (asserts! (> amount u0) ERR-AMOUNT-ZERO)
  (asserts! (> inkind u0) ERR-OUTPUT-ZERO)
  (asserts! (>= inkind min-out) ERR-SLIPPAGE)
```
