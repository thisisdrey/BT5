### Title
Arbitrary command execution via `ext::`/`fd::` git remote-helper transport scheme in `CreateRepositoryFromURL` - ([File: internal/gitaly/service/repository/create_repository_from_url.go])

### Summary
`validateCreateRepositoryFromURLRequest` only checks that `Url` is non-empty, and `cloneFromURLCommand` parses the URL with `net/url.Parse` purely to extract/strip userinfo credentials, without ever validating or allow-listing the URL scheme. Since `net/url.Parse` happily accepts opaque schemes such as `ext::` or `fd::`, an attacker-supplied `Url` using these schemes is passed straight into `git clone <urlString> <repositoryFullPath>`, letting git's `ext`/`fd` remote helpers execute an arbitrary local command instead of performing a network fetch.

### Finding Description
`validateCreateRepositoryFromURLRequest` (lines 149-159) only verifies the repository and that `req.GetUrl()` is non-empty — there is no scheme check. `cloneFromURLCommand` (lines 21-85) parses `repoURL` with `url.Parse` solely to pull out `u.User` for building an `Authorization` HTTP header, then reassembles `urlString := u.String()` and passes it unmodified as the clone source argument to `git clone --quiet --bare/--mirror <urlString> <repositoryFullPath>` via `s.gitCmdFactory.NewWithoutRepo`. There is no allow-list of schemes (e.g. restricting to `http`/`https`/`git`/`ssh`), and no `GIT_ALLOW_PROTOCOL` environment restriction is set anywhere in this path (`internal/git/gitcmd/protocol.go` only deals with the git wire protocol version negotiation, not transport allow-listing). Git's own `ext::` transport (`ext::<command>`) and `fd::` transport are valid, well-formed URL strings that `url.Parse` accepts as opaque/scheme URLs without error, so they pass the only check present (non-empty string). When git receives `ext::sh -c "..."` (or similar) as the clone URL, it invokes the given shell command directly instead of performing a network operation, achieving arbitrary command execution in the Gitaly process's context rather than an SSRF.

### Impact Explanation
This is remote code execution on the Gitaly node, executed as the Gitaly service user, triggerable entirely through the `CreateRepositoryFromURLRequest.Url` field that GitLab Rails forwards from user-supplied "import project by URL" input. This is significantly worse than the network-SSRF risk the code comments (`transfer.bundleURI` disabling) already suggest the developers were trying to mitigate, and falls squarely in GitLab's "RCE" bounty impact class.

### Likelihood Explanation
Preconditions require only that the attacker (an unprivileged GitLab user) can trigger repository import/`CreateRepositoryFromURL` with an attacker-controlled `Url`, which is a standard, low-privilege, self-service GitLab feature (importing a project from a URL). No secrets, no privileged role, and no race conditions are needed — a single crafted RPC/import request is sufficient and fully repeatable.

### Recommendation
Enforce a strict scheme allow-list (`http`, `https`, and optionally `git`/`ssh` if intentionally supported) in `validateCreateRepositoryFromURLRequest` or immediately in `cloneFromURLCommand` after `url.Parse`, rejecting any URL whose scheme is not in the allow-list. Additionally, set `GIT_ALLOW_PROTOCOL` (or the equivalent `protocol.*.allow` git config) when invoking `git clone` to defense-in-depth block `ext`, `fd`, `file`, and any other non-network transports.

func (s *server) cloneFromURLCommand(
	ctx context.Context,
	repoURL, resolvedAddress, repositoryFullPath, authorizationToken string, mirror bool,
	opts ...gitcmd.CmdOpt,
) (*command.Command, error) {
	cloneFlags := []gitcmd.Option{
		gitcmd.Flag{Name: "--quiet"},
	}

	if mirror {
		cloneFlags = append(cloneFlags, gitcmd.Flag{Name: "--mirror"})
	} else {
		cloneFlags = append(cloneFlags, gitcmd.Flag{Name: "--bare"})
	}

	u, err := url.Parse(repoURL)
	if err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	var config []gitcmd.ConfigPair
	if u.User != nil {
		password, hasPassword := u.User.Password()

		var creds string
		if hasPassword {
			creds = u.User.Username() + ":" + password
		} else {
			creds = u.User.Username()
		}

		u.User = nil
		authHeader := fmt.Sprintf("Authorization: Basic %s", base64.StdEncoding.EncodeToString([]byte(creds)))
		config = append(config, gitcmd.ConfigPair{Key: "http.extraHeader", Value: authHeader})
	} else if len(authorizationToken) > 0 {
		authHeader := fmt.Sprintf("Authorization: %s", authorizationToken)
		config = append(config, gitcmd.ConfigPair{Key: "http.extraHeader", Value: authHeader})
	}

	urlString := u.String()

	if resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(u.String(), resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		urlString = modifiedURL
		config = append(config, resolveConfig...)
	}

	// Drop support for bundle URI when fetching from a remote repository.
	// Since the URI can point to any server, including localhost, this is to
	// prevent attack vectors that could abuse this mechanism.
	opts = append(opts, gitcmd.WithGlobalOption(gitcmd.ConfigPair{Key: "transfer.bundleURI", Value: "false"}))

	return s.gitCmdFactory.NewWithoutRepo(ctx,
		gitcmd.Command{
			Name:  "clone",
			Flags: cloneFlags,
			Args:  []string{urlString, repositoryFullPath},
		},
		append(opts, gitcmd.WithConfigEnv(config...))...,
	)
}

func validateCreateRepositoryFromURLRequest(ctx context.Context, locator storage.Locator, req *gitalypb.CreateRepositoryFromURLRequest) error {
	if err := locator.ValidateRepository(ctx, req.GetRepository(), storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return err
	}

	if req.GetUrl() == "" {
		return fmt.Errorf("empty Url")
	}

	return nil
}
