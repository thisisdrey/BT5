### Title
Front-runnable `init_global_fee_state` lets any wallet permanently self-assign as the protocol's `global_fee_admin` - ([File: programs/marginfi/src/instructions/marginfi_group/init_global_fee_state.rs])

### Summary
`init_global_fee_state` initializes the single, program-wide `FeeState` PDA and lets the caller pass an arbitrary `admin_key` that becomes `global_fee_admin`, with no check that the caller is the program's deployer/upgrade authority or any other legitimately privileged party. Because the `FeeState` account is a PDA seeded only by a constant (`[FEE_STATE_SEED]`), it can be initialized exactly once, and whoever calls this instruction first permanently becomes the sole admin of protocol-wide fee/pause configuration, with no recovery path for the legitimate team if front-run.

### Finding Description
The `InitFeeState` account struct only requires a generic `payer: Signer<'info>` and does not constrain it to any known authority (e.g., the program's upgrade authority): [1](#0-0) 

The handler takes an arbitrary `admin_key: Pubkey` argument supplied by the caller and stores it directly as `fee_state.global_fee_admin`, with zero validation that this key is tied to the actual protocol owner: [2](#0-1) 

The `FeeState` PDA is derived solely from a fixed seed (`FEE_STATE_SEED`), so its address is fully predictable and identical for every deployment/environment, and the `init` constraint means the account can only be created once — there is no way to re-run this instruction later: [3](#0-2) 

This is functionally identical to the reported bug class: an initialization instruction accepts an arbitrary signer/pubkey as a privileged "admin" role with no cryptographic or on-chain binding to the legitimate owner, and once the one-time-init PDA is created, it can never be re-initialized by the rightful party.

Once set, `global_fee_admin` becomes the only actor who can call `edit_global_fee_state` to modify the admin, fee wallet, all protocol fee rates, and the `pause_delegate_admin`: [4](#0-3) 

The `global_fee_admin` (or the pause delegate it appoints) is also a `pause_authority` capable of pausing the entire protocol: [5](#0-4) 

Every `MarginfiGroup` created afterward pulls its `fee_state_cache` (fee rate, fee wallet) from this single global `FeeState` at group-initialization time: [6](#0-5) 

### Impact Explanation
If an attacker submits `init_global_fee_state` before the legitimate deployer does (e.g., immediately after/during program deployment, since the PDA address is deterministic and publicly derivable from the program ID), they permanently become `global_fee_admin` for the whole marginfi program — not just one group. This grants unauthorized, unrecoverable control to:
- Redirect the `global_fee_wallet` that receives all protocol fees (`program_fee_fixed`/`program_fee_rate`) collected from every group/bank in the protocol — a direct fee-theft vector.
- Set arbitrary `program_fee_rate`/`program_fee_fixed`/liquidation and order fees across the entire protocol.
- Set/replace `pause_delegate_admin` and pause the protocol at will, causing a persistent denial-of-service across every marginfi group.
- Permanently lock the legitimate team out of fee/pause administration, since only the current `global_fee_admin` can call `edit_global_fee_state` to change the admin.

This satisfies the "unauthorized state change" and "theft" impact bars and cannot be reversed by the legitimate protocol owner without a program upgrade.

### Likelihood Explanation
Exploitability depends entirely on transaction ordering at (or shortly after) program deployment: an attacker must observe the deployment and race to call `init_global_fee_state` before the legitimate deployer's initialization transaction lands. This is a realistic but time-window-constrained race (mempool/validator-level front-running), matching the "Medium likelihood" characterization of the analogous report. It requires no privileged access, secrets, or special conditions beyond monitoring new program deployments and reacting quickly.

### Recommendation
Gate `init_global_fee_state` so it can only be called by the program's actual upgrade authority, e.g., by requiring the caller to be validated against the on-chain `ProgramData` account's `upgrade_authority_address`, or by having the instruction executed atomically in the same transaction as/immediately protected by the deploy script, with an explicit on-chain constraint (not just an off-chain convention) that ties `payer`/`admin_key` to a known, verifiable authority — analogous to the recommended fix of constraining the transfer-hook `InitializeExtraAccountMeta` to `mint.mint_authority`.

### Proof of Concept
1. Monitor for deployment of the marginfi program (its program ID is public once deployed).
2. Derive the `FeeState` PDA using the well-known seed `FEE_STATE_SEED` and the deployed program ID — this address is fully predictable.
3. Before the legitimate team submits their own `init_global_fee_state` transaction, submit a competing transaction calling `init_global_fee_state(admin_key = <attacker_pubkey>, fee_wallet = <attacker_wallet>, ...)` as shown in the test harness pattern used legitimately: [7](#0-6) 
4. Because the `fee_state` account uses Anchor's `init` constraint at a fixed PDA, the first successful transaction wins; the legitimate team's later attempt will fail with an "account already in use" error, and the `FeeState.global_fee_admin`/`global_fee_wallet` are now permanently attacker-controlled.
5. The attacker can subsequently call `edit_global_fee_state` to redirect fees, change rates, or pause the protocol, with no way for the legitimate team to reclaim control.

pub fn initialize_fee_state(
    ctx: Context<InitFeeState>,
    admin_key: Pubkey,
    fee_wallet: Pubkey,
    bank_init_flat_sol_fee: u32,
    liquidation_flat_sol_fee: u32,
    order_init_flat_sol_fee: u32,
    program_fee_fixed: WrappedI80F48,
    program_fee_rate: WrappedI80F48,
    liquidation_max_fee: WrappedI80F48,
    order_execution_max_fee: WrappedI80F48,
) -> Result<()> {
    let mut fee_state = ctx.accounts.fee_state.load_init()?;
    fee_state.global_fee_admin = admin_key;
    fee_state.global_fee_wallet = fee_wallet;
    fee_state.key = ctx.accounts.fee_state.key();
    fee_state.bank_init_flat_sol_fee = bank_init_flat_sol_fee;
    fee_state.bump_seed = ctx.bumps.fee_state;
    fee_state.program_fee_fixed = program_fee_fixed;
    fee_state.program_fee_rate = program_fee_rate;
    fee_state.liquidation_max_fee = liquidation_max_fee;
    fee_state.liquidation_flat_sol_fee = liquidation_flat_sol_fee;
    fee_state.order_execution_max_fee = order_execution_max_fee;
    fee_state.order_init_flat_sol_fee = order_init_flat_sol_fee;

    Ok(())
}
