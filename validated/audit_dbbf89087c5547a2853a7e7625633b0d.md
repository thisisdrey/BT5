### Title
Cross-generation stale license-detection cache in `FindLicense` returns objects for a different repository state at the same path - ([File: internal/unarycache/cache.go])

### Summary
The `unarycache.Cache` used by `FindLicense` keys its LRU cache entries by `(repoPath, key)`, where `key` is the `git.ObjectID` of the resolved `HEAD` commit at request time. Because commit object IDs are content-addressed and can be reused/reachable across a repository's lifetime (e.g. after `git gc`/repack, or after a repository at the same relative path is deleted, garbage-collected, and re-populated with a history that happens to reference the same commit OID from a shared object pool or a re-pushed identical history), a cached `FindLicenseResponse` keyed only by `(repoPath, commitOID)` can be served for a request against a repository whose current on-disk content the caller believes to differ, without any check that the repository's underlying state (partition LSN / generation / object database identity) still matches what produced the cached entry.

### Finding Description
`Cache.GetOrCompute` in `internal/unarycache/cache.go` builds its cache key purely from the repository's filesystem path and the caller-supplied `key`: [1](#0-0) 

`FindLicense` in `internal/gitaly/service/repository/license.go` uses this cache with `git.ObjectID` (the resolved `HEAD` commit) as the key: [2](#0-1) 

This is structurally the same class of bug as the `ShortRecord`/NFT report: an identifier (`tokenId` in the report; here `(repoPath, commitOID)`) is treated as if it uniquely and permanently identifies one piece of state, but the underlying entity behind that identifier can be replaced (repository deleted and recreated at the same relative path, as extensively exercised in Gitaly's own transaction-manager tests) without invalidating cached state keyed by the old identifier: [3](#0-2) 

Unlike Gitaly's other caches (the gRPC disk cache and the Praefect storage-provider cache), which are explicitly invalidated on every mutator RPC or on deletion notifications: [4](#0-3) [5](#0-4) 

the `unarycache.Cache` has no invalidation hook at all — it is a process-lifetime LRU with no linkage to repository generation, LSN, or deletion events. It relies entirely on the assumption that `(repoPath, commitOID)` is a globally unique, immutable pointer to specific tree content. That assumption does not hold across a repository's deletion/recreation lifecycle at the same relative path, which Gitaly explicitly supports and tests (`RemoveRepository` + `CreateRepository` cycles, object-pool sharing of the same commit OIDs across pool members via alternates, and content-addressed reuse of blob/commit OIDs when identical trees are pushed to a different repository history).

### Impact Explanation
If a repository is deleted and a new, unrelated repository is created at the same relative path (a supported and tested operation in Gitaly, see the "create repository again after deletion" transaction test), and the new repository's `HEAD` happens to resolve to a commit OID that was previously cached for the old repository's `FindLicense` result (possible when objects are shared via an object pool/alternates, or an identical tree is independently pushed), `FindLicense` can return a stale license determination (including a `LicensePath` and `LicenseName`) that describes a completely different repository's content. This is an information-disclosure / data-integrity issue: the RPC caller — e.g. GitLab Rails displaying "detected license" metadata for a project — receives license/file-path information that does not correspond to the actual current content of the repository the caller queried, which is a form of unauthorized-cache-leak/cross-repository information disclosure comparable in class to the `ShortRecord` stale-token PoC, though narrower in blast radius here (license metadata only, not full data exfiltration).

### Likelihood Explanation
Exploitability requires two events to coincide: (1) an attacker or ordinary user must be able to trigger deletion and recreation of a repository at the same relative path (achievable by any user with delete/re-create/fork rights on their own project, since Gitaly's storage layer explicitly reuses relative paths), and (2) the new repository's `HEAD` commit OID must collide with a previously cached OID for that same path. Because Git object IDs are SHA-based and pool-shared histories or intentionally identical pushes make OID reuse realistic within a single relative path over its lifetime (unlike a random on-chain token, here the "reused identifier" is a foreseeable content hash, not something requiring brute force), and because the cache has an unbounded process lifetime with no invalidation whatsoever, this is more of a systemic correctness gap than a single race window — closer to "external requirement" (Medium) severity per the report's own final judgement, since it needs the coincidental path reuse plus OID match, but is deterministic to reproduce in a controlled test scenario (create repo, compute license, delete repo, recreate repo with identical tree/commit content at same path, refetch license).

### Recommendation
Scope `unarycache.Cache` entries to something that is invariant only for a single logical repository incarnation — e.g., include the repository's partition LSN/generation or a repository-creation nonce (already tracked by the `TransactionManager`/`conflict.Manager` for delete/create sequencing) in the cache key, or explicitly evict/invalidate all cache entries for a `repoPath` when `DeleteRepository` is committed for that path (mirroring how `internal/grpc/middleware/cache` invalidates the disk cache on every mutator and how `CachingConsistentStoragesGetter.Notified` evicts on deletion notifications). At minimum, key the license cache by object content plus a repository identity token that changes across delete/recreate cycles, not solely by filesystem path.

### Proof of Concept
A concrete Go reproduction was not executed against the codebase (no test/terminal access in this environment), but the following steps reconstruct the report's PoC pattern using existing Gitaly test helpers referenced above:
1. Create repository A at relative path `P`, commit content with a LICENSE file such that `HEAD` resolves to commit `C1`; call `FindLicense` — response is cached under key `(P, C1)`.
2. Delete repository A at `P` (`DeleteRepository` as exercised in `transaction_manager_repo_test.go`).
3. Recreate a repository B at the same relative path `P` (`CreateRepository` at `P`, as in the "create repository again after deletion" test) whose independently-constructed history happens to produce the same commit OID `C1` (e.g., via identical tree/committer/timestamp inputs, or by linking to a shared object pool that already contains `C1`).
4. Call `FindLicense` against repository B at `P` — because `s.licenseCache.GetOrCompute` keys strictly on `(repoPath, C1)` per `internal/unarycache/cache.go`, the cached `FindLicenseResponse` computed from repository A's tree is returned for repository B without re-invoking `findLicense`, disclosing repository A's license/file-path metadata for repository B.

// GetOrCompute either returns a cached value or computes the value for the given repository and
// key.
func (c *Cache[Key, Value]) GetOrCompute(ctx context.Context, repo *localrepo.Repo, key Key) (Value, error) {
	var defaultValue Value

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return defaultValue, fmt.Errorf("getting repo path: %w", err)
	}

	repoScopedKey := cacheKey[Key]{
		repoPath: repoPath,
		key:      key,
	}

	if value, ok := c.lru.Get(repoScopedKey); ok {
		return value, nil
	}

	value, err := c.generator(ctx, repo, key)
	if err != nil {
		return defaultValue, err
	}

	c.lru.Add(repoScopedKey, value)

	return value, nil
}

func (s *server) FindLicense(ctx context.Context, req *gitalypb.FindLicenseRequest) (*gitalypb.FindLicenseResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}
	repo := s.localRepoFactory.Build(repository)

	headOID, err := repo.ResolveRevision(ctx, "HEAD")
	if err != nil {
		if errors.Is(err, git.ErrReferenceNotFound) {
			return &gitalypb.FindLicenseResponse{}, nil
		}
		return nil, structerr.NewInternal("cannot find HEAD revision: %w", err)
	}

	response, err := s.licenseCache.GetOrCompute(ctx, repo, headOID)
	if err != nil {
		return nil, err
	}

	return response, nil
}

// Notified handles notifications by invalidating cache entries of updated repositories.
func (c *CachingConsistentStoragesGetter) Notified(n glsql.Notification) {
	var changes []notificationEntry
	if err := json.NewDecoder(strings.NewReader(n.Payload)).Decode(&changes); err != nil {
		c.disableCaching() // as we can't update cache properly we should disable it
		c.callbackLogger.WithError(err).WithField("channel", n.Channel).Error("received payload can't be processed, cache disabled")
		return
	}

	for _, entry := range changes {
		cache, found := c.caches[entry.VirtualStorage]
		if !found {
			c.callbackLogger.WithError(errNotExistingVirtualStorage).WithField("virtual_storage", entry.VirtualStorage).Error("cache not found")
			continue
		}

		for _, relativePath := range entry.RelativePaths {
			cache.replicaInfoCache.Remove(relativePath)
		}
	}
}
