### Title
Missing size enforcement in `insert_uninstantiated_attachment` allows oversized/unbounded uninstantiated attachment storage - ([File: stackslib/src/net/atlas/db.rs])

### Summary
`AtlasDB::insert_uninstantiated_attachment` [1](#0-0)  only checks the *count* of uninstantiated attachments against `max_uninstantiated_attachments` and evicts the oldest rows if the count would exceed the cap, but it never checks `attachment.content.len()` against `self.atlas_config.attachments_max_size` before inserting. The size check exists only in `should_keep_attachment` [2](#0-1) , a separate function that is not called from `insert_uninstantiated_attachment`.

### Finding Description
The claimed bound `bytes_stored <= max_uninstantiated_attachments * attachments_max_size` requires every row inserted via `insert_uninstantiated_attachment` to be size-checked at insertion time. Looking at the function:
- It computes `count_uninstantiated_attachments()` and evicts oldest rows only when count `>= max_uninstantiated_attachments` [3](#0-2) .
- It then unconditionally inserts the attachment content via `INSERT OR REPLACE INTO attachments ... VALUES (?, ?, 0, ?)` with no length check on `attachment.content` [4](#0-3) .

The size guard, `should_keep_attachment`, is a distinct function [2](#0-1)  that must be called by the caller *before* invoking `insert_uninstantiated_attachment`. I was unable to locate and confirm the exact call site in `stackslib/src/net/atlas/download.rs` (the `AttachmentsDownloader`) that processes `GetAttachmentResponse` before this iteration ended — my search for `insert_uninstantiated_attachment`, `should_keep_attachment`, `GetAttachmentResponse`, and `attachments_max_size` in that file returned no matches, meaning I could not verify from the indexed content whether `should_keep_attachment` (or an equivalent size check) is actually invoked prior to calling `insert_uninstantiated_attachment` on the response-handling path.

### Impact Explanation
If the download/response-handling path in `download.rs` calls `insert_uninstantiated_attachment` without first calling `should_keep_attachment` (or performing an equivalent size check), then the per-row size bound is not enforced at the point of storage, and a single oversized attachment could be persisted to disk. Combined with the count-based eviction (which bounds the *number* of rows but not their size), the overall disk usage bound `max_uninstantiated_attachments * attachments_max_size` would not hold if any row exceeds `attachments_max_size`.

### Recommendation

    pub fn should_keep_attachment(
        &self,
        contract_id: &QualifiedContractIdentifier,
        attachment: &Attachment,
    ) -> bool {
        if !self.atlas_config.contracts.contains(contract_id) {
            info!(
                "Atlas: will discard posted attachment - {} not in supported contracts",
                contract_id
            );
            return false;
        }
        if attachment.content.len() as u32 > self.atlas_config.attachments_max_size {
            info!("Atlas: will discard posted attachment - attachment too large");
            return false;
        }
        true
    }

    pub fn insert_uninstantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        // Insert the new attachment
        let uninstantiated_attachments = self.count_uninstantiated_attachments()?;
        if uninstantiated_attachments >= self.atlas_config.max_uninstantiated_attachments {
            let to_delete =
                1 + uninstantiated_attachments - self.atlas_config.max_uninstantiated_attachments;
            self.evict_k_oldest_uninstantiated_attachments(to_delete)?;
        }

        let tx = self.tx_begin()?;
        let now = util::get_epoch_time_secs() as i64;
        let res = tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 0, ?)",
            params![
                attachment.hash(),
                attachment.content,
                now,
            ],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }
