### Title
Unauthenticated PeerDB identity-slot takeover via self-reported handshake address - (File: stackslib/src/net/chat.rs)

### Summary
`ConversationP2P::validate_handshake` only verifies that the `Handshake` message is signed by the key it itself claims (`handshake_data.node_public_key`); it never checks that the self-reported `addrbytes`/`port` match the peer's actual observed socket address unless the connection is outbound **and** already has a bound public key. `Neighbor::load_and_update` then looks up and mutates the on-disk `PeerDB` row keyed purely on this attacker-controlled `(network_id, addrbytes, port)` tuple, merging the attacker's key into an existing neighbor's record.

### Finding Description
In `validate_handshake` (chat.rs 1047-1127), when `self.connection.get_public_key()` is `None`, the only check performed is that the message is signed with the key embedded in the handshake itself: [1](#0-0) 
This proves the attacker owns *some* keypair, but proves nothing about ownership of `handshake_data.addrbytes`/`port`. The only address-binding check is gated behind `self.stats.outbound && Some(_)` (i.e., only for outbound connections that already have a bound key): [2](#0-1) 
For inbound connections, or any connection (inbound/outbound) that has not yet bound a public key, this check is entirely skipped.

Once `validate_handshake` passes, `Neighbor::load_and_update` is invoked, deriving the lookup key straight from the untrusted handshake fields and merging into the corresponding on-disk row: [3](#0-2) 
`PeerDB::get_peer` is queried using `addr.addrbytes`/`addr.port` taken from `NeighborKey::from_handshake(peer_version, network_id, handshake_data)` — fully attacker-controlled — rather than the actual TCP peer address of the inbound socket. If a row already exists for that address (a legitimate, previously-known neighbor), `handshake_update` merges the attacker's freshly-signed public key into that same row: [4](#0-3) 

The result: an attacker who opens an inbound connection and sends a Handshake with `addrbytes`/`port` copied from a legitimate, already-known neighbor's address, signed by an attacker-generated keypair, causes the local node's `PeerDB` entry for that address to be updated so that it associates the attacker's public key with a peer slot the attacker does not control.

### Impact Explanation
This breaks the intended invariant that `(network_id, addrbytes, port) -> public_key` in `PeerDB` reflects proof-of-key-ownership at that address. The write pollutes the local node's persistent peer table under a legitimate neighbor's identity without ever having connected to or controlled that address, constituting an unauthenticated write to node state (`PeerDB`). This affects neighbor-walk/peer-selection logic that trusts this mapping, and is repeatable for any known/discoverable neighbor address, against any node reachable on its P2P port.

### Likelihood Explanation
Precondition is simply that the local node already has a `PeerDB` row for some other neighbor's address (a very common baseline state for any actively peered node), and that the attacker can open an inbound TCP connection to the target's P2P port — no privileged role, secret, or existing relationship with the impersonated peer is required. The attacker cost is a single crafted, self-signed Handshake message.

### Recommendation
Bind `Neighbor::load_and_update`'s lookup/merge to the actually-observed socket address of the connection (or otherwise require proof, e.g., a subsequent round-trip confirming reachability at the claimed address) rather than trusting the self-reported `handshake_data.addrbytes`/`port` verbatim for inbound or not-yet-bound connections, and extend the address-consistency check in `validate_handshake` to cover the inbound/unbound cases as well, not just `self.stats.outbound && Some(_)`.

### Proof of Concept
Rust test in `stackslib::net::chat`:
1. Populate a `PeerDB` with a legitimate neighbor entry `(network_id, addr_A, port_A)` and `pubkey_legit`.
2. Construct `convo_2` as an inbound `ConversationP2P` (`stats.outbound = false`) with no bound public key (`connection.get_public_key() == None`).
3. Build a `Handshake` message whose `handshake_data.addrbytes`/`port` equal `addr_A`/`port_A`, sign it with a freshly generated, unrelated `attacker_privkey`, and call `convo_2.validate_handshake(...)` — assert it returns `Ok(())`.
4. Call `Neighbor::load_and_update(conn, peer_version, network_id, &handshake_data)` and then read back the `PeerDB` row for `(network_id, addr_A, port_A)`; assert its stored public key now equals `attacker_pubkey` instead of `pubkey_legit`, demonstrating the identity-slot takeover.

        conn: &DBConn,
        peer_version: u32,
        network_id: u32,
        handshake_data: &HandshakeData,

        let addr = NeighborKey::from_handshake(peer_version, network_id, handshake_data);
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;

        let peer_opt = PeerDB::get_peer(conn, network_id, &addr.addrbytes, addr.port)
            .map_err(net_error::DBError)?;

        let (mut neighbor, present) = match peer_opt {
            Some(neighbor) => {
                let mut ret = neighbor;
                ret.addr = addr.clone();
                (ret, true)
            }
            None => {

                (ret, false)
            }
