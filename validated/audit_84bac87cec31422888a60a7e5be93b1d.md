Based on my research, I found a strong analog to CVE-2018-16398's bug class (naive path/regex matching leading to a security policy bypass) in java-tron's HTTP API disablement filter.

### Title
Disabled-API policy bypass via naive path-segment matching in `HttpApiAccessFilter.isDisabled()` - (File: `framework/src/main/java/org/tron/core/services/filter/HttpApiAccessFilter.java`)

### Summary
`HttpApiAccessFilter` is the mechanism node operators use to disable specific HTTP wallet API endpoints (e.g. `getaccount`, `getnowblock`) via `disabledApiList`. Its `isDisabled()` method derives the "API name" to check against the blocklist by taking a fixed array index (`[2]`) of the request path after a single `URI.normalize()` call, rather than resolving the actual servlet/API identity. This is the same bug class as the Twistlock AuthZ Broker CVE: a security decision is made from a naive/positional string match on a path instead of the actual resolved action, so a crafted path can desynchronize the two.

### Finding Description
`isDisabled()` implements the block check like this: [1](#0-0) 

It builds `endpoint = contextPath + servletPath`, calls `URI.create(endpoint).normalize()`, and then blindly takes `endpoint.split("/")[2]` as "the API name" to check membership in `disabledApiList`. This assumes the third path segment always corresponds 1:1 with the actual API being invoked. That assumption breaks once extra path segments combined with `..` are present: `URI.normalize()` performs purely lexical `..` collapsing without any knowledge of which segment is "the API name," so inserting benign-looking intermediate segments shifts what ends up at index `[2]` after normalization, desynchronizing the filter's decision from the real target endpoint — exactly analogous to how the Twistlock broker's regex matched `containers/aa/pause?aaa=\/start` as if it were a `start` action.

The project's own regression test proves this desync exists in the helper function itself: [2](#0-1) 

`/wallet/a/b/../getnowblock` normalizes to `/wallet/a/getnowblock`, so `split("/")[2]` becomes `"a"` instead of `"getnowblock"` — the check silently returns `false` (not disabled) even though the request is semantically still directed at `getnowblock`.

### Impact Explanation
`disabledApiList` is the operator-facing control for shutting off specific wallet/JSON-RPC-adjacent HTTP endpoints — used for endpoints considered unsafe, privacy-sensitive, or resource-intensive on a given deployment (shielded-transaction scanning endpoints, market/exchange endpoints, `getaccount`, etc., per `LiteFnQueryHttpFilter`'s much larger analogous list and the `HttpApiAccessFilterTest` usage). An anonymous API client able to construct a path that (a) is dispatched by the servlet container to the intended disabled servlet, while (b) desynchronizes the filter's `endpoint.split("/")[2]` computation, defeats the operator's explicit API-disablement policy and reaches an endpoint the node operator intended to be unreachable. Depending on which API was disabled, this is a "still-reachable" HTTP API that the node believed it "could no longer serve," matching the "API the node can no longer serve" acceptance bar in reverse (the node fails to actually disable it).

### Likelihood Explanation
The flaw is reachable by any unauthenticated HTTP client hitting the fullnode/solidity/PBFT HTTP wallet ports — no signed transaction or special privilege is required, matching the "anonymous API client" reachability bar. The bypass condition is deterministic and already demonstrated by the project's own unit test (`testIsDisabled`), so no guesswork about internal behavior is needed — only confirmation of how the servlet container's own path resolution/dispatch interacts with the crafted path (whether the container's real dispatch also lands on the intended servlet for such inputs), which is an environment-dependent but well-known class of servlet-container path-normalization discrepancy.

### Recommendation
Replace the positional `split("/")[2]` heuristic with a check based on the actual matched servlet/handler identity (e.g., compare against the exact registered path spec used by `context.addServlet(...)`, or resolve the API name from the `HttpServletMapping`/dispatched servlet class rather than from a normalized string). Alternatively, reject any request whose raw (non-normalized) path contains `..` segments before computing `endpoint`, and validate that `endpoint.split("/")` has the exact expected number of segments for the given context before indexing into it.

### Proof of Concept
1. Configure a node with `disabledApiList` containing `getnowblock`.
2. Send `GET /wallet/a/b/../getnowblock` (or any path where inserting `<segment>/..` before the target API name shifts index 2 after `URI.normalize()`).
3. Per `HttpApiAccessFilterTest.testIsDisabled` (`framework/src/test/java/org/tron/core/services/filter/HttpApiAccessFilterTest.java:144-146`), `isDisabled()` returns `false` for this path even though the operator disabled `getnowblock`, demonstrating the check can be defeated by path construction alone.   private boolean isDisabled(String endpoint) {
```java
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
  }
```

```java
  @Test
  public void testIsDisabled() throws Exception {
    List<String> list = new ArrayList<>();
    list.add("getnowblock");
    CommonParameter.getInstance().setDisabledApiList(list);
    Method privateMethod = httpApiAccessFilter.getClass()
            .getDeclaredMethod("isDisabled", String.class);
    privateMethod.setAccessible(true);

    String url = "/wallet/getnowblock";
    boolean f = (boolean) privateMethod.invoke(httpApiAccessFilter,url);
    Assert.assertTrue(f);

    url = "/wallet/a/../b/../getnowblock";
    f = (boolean) privateMethod.invoke(httpApiAccessFilter,url);
    Assert.assertTrue(f);

    url = "/wallet/a/b/../getnowblock";
    f = (boolean) privateMethod.invoke(httpApiAccessFilter,url);
    Assert.assertFalse(f);

    url = "/wallet/getblock";
    f = (boolean) privateMethod.invoke(httpApiAccessFilter,url);
    Assert.assertFalse(f);
  }
```
