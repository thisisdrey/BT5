### Title
Unauthenticated `RecvError` messages let any external attacker tear down established Nebula tunnels — ([File: outside.go])

### Summary
The external report's bug class is: an unauthenticated actor can submit a message type over the network transport that is accepted and processed *without* any peer authentication, and that message mutates security-relevant state (there, a price/timestamp used to gate other updates; here, tunnel/hostmap state), producing a remote DoS/state-poisoning effect. The reachable Nebula analog is `header.RecvError` handling in `readOutsidePackets`/`handleRecvError`.

### Finding Description
Inbound UDP packets are dispatched by type before any Noise handshake/certificate check is performed. In `outside.go`, `RecvError` (like `Handshake`) is handled in the "Unencrypted packets" branch, prior to any cryptographic authentication: [1](#0-0) 

`handleRecvError` looks up the hostinfo purely by the wire-supplied `RemoteIndex` and only performs a source-address comparison against the currently-recorded remote `netip.AddrPort` for that hostinfo — there is no certificate, MAC, or handshake proof tying the sender to the peer: [2](#0-1) 

If the check passes (attacker's packet source `addr` equals the hostinfo's current remote, which for UDP is spoofable and/or simply guessable/observable — e.g., known static/cloud IP:port of a peer), the function unconditionally tears down the tunnel and clears the pending handshake state: [3](#0-2) 

This mirrors the report's root cause pattern exactly: a message type that should only be trusted when it originates from an authenticated party (the actual Noise/CA-verified peer, analogous to the dedicated Oracle thread in the report) is instead accepted from the raw, unauthenticated transport (`outside.go`'s UDP receive path, analogous to the HTTP `action` endpoint), and used to force state changes (session/timestamp state there, hostmap/tunnel state here) that block or reset legitimate operation for the victim.

### Impact Explanation
An attacker who can send a single crafted 8-byte UDP packet (RecvError has no signature, no MAC, no replay-window check — `Bits`/`ConnectionState.Decrypt` machinery is never invoked for this packet type) can force `closeTunnel` and delete the hostinfo/pending handshake for a victim's tunnel to a specific peer, as long as the packet's source `netip.AddrPort` matches (or spoofs) the peer's currently known remote address. This is remote state poisoning / denial of service on an established, otherwise mutually-authenticated tunnel — the victim will have to re-handshake, and a sustained attack (repeated forged `RecvError` packets) can keep tearing down the tunnel, denying connectivity, similar in class to how the Pyth report used unauthenticated messages to block legitimate price updates.

### Likelihood Explanation
Reachability requires only network-level UDP access to the target's listen port — no CA-signed certificate, no completed handshake, and no valid-certificate holder status is needed, satisfying the "no CA-signed certificate" constraint. The primary mitigating factor is the address-match check: the attacker must know (often discoverable/static, e.g. cloud or lighthouse-advertised addresses) or spoof the peer's current UDP remote `AddrPort`. UDP source-address spoofing is feasible on many networks lacking BCP38/ingress filtering, and even without spoofing, an attacker positioned to observe or infer the current remote address (e.g., a lighthouse-registered public IP) can trigger this without spoofing at all. This is also gated by config (`sendRecvErrorConfig`/`acceptRecvErrorConfig`, tied to `listen.send_recv_error`/accept settings per the CHANGELOG's `#670` note), so likelihood depends on whether recv_error acceptance is enabled for the target/source — I was not able to fully confirm the current default value for `acceptRecvErrorConfig` in this codebase version before running out of tool calls, so this should be verified directly in `interface.go`.

### Recommendation
Do not allow an unauthenticated, unsigned `RecvError` packet to unilaterally tear down a tunnel based solely on a UDP source-address match. At minimum:
- Require some proof of session knowledge beyond the plaintext `RemoteIndex` + source-address match (e.g., a MAC covering the index using session/derived keying material, or require the message to be authenticated the same way `CloseTunnel` is protected — note `CloseTunnel` is already decrypted/authenticated because it's dispatched only *after* `ConnectionState.Decrypt` succeeds, per `outside.go:164-166`, whereas `RecvError` is dispatched before any decryption).
- Rate-limit / require corroborating signals (e.g., only honor `RecvError` if a data packet was actually sent to that index recently) before tearing down state.
- Consider making acceptance of unauthenticated `RecvError` opt-in and off by default, and clearly document the residual spoofing risk (this appears partially addressed already via `acceptRecvErrorConfig`, but the underlying trust model still relies on UDP source-address equality, which is not cryptographic proof of identity).

### Proof of Concept
Conceptual PoC (not executed, network access unavailable in this environment):
1. Identify a live Nebula tunnel's peer UDP endpoint (`hostinfo.GetRemote()` — often a stable/static/cloud address, or learned via a compromised/observing lighthouse channel).
2. Craft an 8-byte (header-only) UDP packet with `header.Type = header.RecvError`, `RemoteIndex` set to the victim's local index for that tunnel (indices are also observable/guessable in some flows since they're sent in cleartext handshake payloads), source address spoofed (or genuinely originating) to match the peer's current remote `AddrPort`.
3. Send it to the victim's listen port.
4. Per `handleRecvError` (`outside.go:541-575`), if the address check passes, the victim calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, tearing down the tunnel with no cryptographic proof from the sender. [4](#0-3) [2](#0-1) [5](#0-4)

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
