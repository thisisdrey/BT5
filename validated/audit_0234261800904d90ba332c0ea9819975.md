### Title
Unauthenticated `/shutdown` HTTP request permanently halts `SignerEventReceiver::next_event` - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches on `request.url() == "/shutdown"` with no credential, secret, or peer-identity check, setting `stop_signal` to `true` and returning `Err(EventError::Terminated)`. Any TCP client that can reach the bound event-receiver port can send a bare `POST /shutdown` request and permanently stop the signer's event ingestion loop, since `main_loop` treats `EventError::Terminated` as a clean exit and `is_stopped()` will return `true` forever afterward.

### Finding Description
The intended invariant is that only the node's own event dispatcher (via `SignerStopSignaler::send`, which is only invoked by the signer process itself when it wants to shut down) should be able to halt the receiver. In practice, `next_event` matches on `request.url() == "/shutdown"` [1](#0-0)  with no check that the caller is the node process, holds any secret, or is even the same host—the only requirement is that the HTTP method is `POST` [2](#0-1) . Once matched, it calls `event_receiver.stop_signal.store(true, Ordering::SeqCst)` and returns `Err(EventError::Terminated)` [1](#0-0) . `main_loop` treats `Err(EventError::Terminated)` as a normal, expected exit path and `break`s out of the loop [3](#0-2) . Even if the loop were somehow re-entered, `next_event` immediately re-checks `is_stopped()` at the top and returns `Terminated` again [4](#0-3) , and `is_stopped()` simply loads the now-`true` `AtomicBool` with no reset path [5](#0-4) . There is no comparison of source IP, no bearer token, no shared secret, and no TLS/mTLS check anywhere in this dispatch — the equality "only the node's own dispatcher can stop ingestion" is broken by "any unauthenticated request to `/shutdown` can stop it."

### Impact Explanation
A single unauthenticated `POST /shutdown` request permanently disables the signer's ingestion of `StackerDBChunksEvent`/`BlockValidateResponse`/`BurnBlockEvent`/new-block events, since the atomic stop flag is never reset back to `false` anywhere in this file. This is a Critical unauthenticated DoS from a single message: the signer process keeps running but silently stops observing block proposals, signer messages, and burn blocks, which can degrade or halt the signer's participation in consensus signing without any visible crash. The attack is trivially repeatable and requires no privileged role, secret, or prior compromise — just TCP connectivity to the bound event-receiver address.

### Likelihood Explanation
The only precondition is that the attacker can open a TCP connection to the address the signer's `SignerEventReceiver::bind` is listening on and that the receiver's `main_loop` is running. No peer identity, config value, or canonical-tip state is required. The attacker's cost is a single crafted HTTP POST request; the exploit is deterministic and repeatable against every instance of a signer with a reachable event-receiver socket. The primary caveat, which could not be fully verified in this pass, is the actual network exposure of this receiver (e.g., whether operators are expected to bind it to loopback only, or whether it is commonly bound to a routable interface) — the code itself provides no authentication regardless of bind address, so any deployment that binds this endpoint to a non-loopback interface is directly exploitable.

### Recommendation
Remove the ability for the HTTP `/shutdown` route to control the stop signal from an unauthenticated wire request. `SignerStopSignaler::send` already has direct access to the shared `Arc<AtomicBool>` and does not need to round-trip through HTTP; it can set `stop_signal` directly in-process and only use the TCP connection to unblock the blocking `http_server.recv()` call. If an HTTP-triggered shutdown must remain, gate `/shutdown` behind a check that the request originates from the local loopback interface and/or requires a shared secret/token established between the node and signer at startup, similar to how other privileged control endpoints are protected.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module)
#[test]
fn test_unauthenticated_shutdown_dos() {
    use std::net::TcpStream;
    use std::io::Write;
    use crate::v0::messages::SignerMessage;

    let mut receiver: SignerEventReceiver<SignerMessage> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Attacker: raw TCP connection, no credentials, no prior relationship with the node
    let mut stream = TcpStream::connect(addr).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: x\r\nContent-Length: 0\r\n\r\n";
    stream.write_all(req.as_bytes()).unwrap();

    // First call processes the forged shutdown and terminates
    let res = receiver.next_event();
    assert!(matches!(res, Err(EventError::Terminated)));

    // Receiver is now permanently stopped — every subsequent legitimate event is dropped
    assert!(receiver.is_stopped());
    let res2 = receiver.next_event();
    assert!(matches!(res2, Err(EventError::Terminated)));
}
```
This demonstrates that an attacker with no credentials, using only a raw `TcpStream`, can permanently trip `stop_signal` and make `next_event`/`main_loop` treat the receiver as terminated for the remainder of the process lifetime.
