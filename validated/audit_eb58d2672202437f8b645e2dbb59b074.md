### Title
Linker panics on malformed archive symbol map (`armap`) in `readArmap` - ([File: src/cmd/link/internal/ld/ar.go])

### Summary
`readArmap` in `ar.go` parses the archive symbol table (`armap`) of a host archive (e.g. a `libgcc.a`-style archive linked in during cgo builds) without validating that the declared size field or the embedded name strings are well-formed. A malicious archive can cause `readArmap` to slice a buffer out of bounds or run past the end of the `names` byte slice while scanning for a NUL terminator, producing a runtime panic during linking. This mirrors the Pyth report's root cause: **untrusted external input is consumed and forwarded into a sink without validating the exact/expected bounds first**, only here the sink is a Go slice operation instead of an Ether transfer.

### Finding Description
Attacker-controlled input: a host archive file (`.a`) supplied as part of a Go module or CGO_LDFLAGS-referenced library that a victim links against via `cmd/link`'s `hostArchive` (`src/cmd/link/internal/ld/ar.go:103`). `hostArchive` reads the archive header via `nextar`, then calls `readArmap(name, f, arhdr)` (`ar.go:137`).

Inside `readArmap` (`ar.go:196-247`):
- `contents := make([]byte, atolwhex(arhdr.size))` allocates a buffer sized from the attacker-controlled, string-parsed `size` field of the archive header (`ar.go:203`, `atolwhex` in `ld.go:208-211` silently returns `0` on any parse failure via `strconv.ParseInt`'s ignored error).
- `contents = contents[wordSize:]` (`ar.go:214`) is executed unconditionally — if the declared size is smaller than `wordSize` (4 or 8), this slice expression panics with "slice bounds out of range."
- The subsequent loop `for names[n] != 0 { n++ }` (`ar.go:221-223`) scans for a NUL-terminated symbol name in `names` with no bound check against `len(names)`. A crafted armap that omits the terminating NUL (or has a `c` count larger than the number of embedded names) causes an index-out-of-range panic reading past the slice.

None of these paths validate the declared size against the actual required minimum before performing the slice/arithmetic, exactly analogous to the Solidity code invoking `pyth.updatePriceFeeds{value: msg.value}` without first checking `msg.value` against the fee computed by `pyth.getUpdateFee(updateData)`.

### Impact Explanation
A build/link-time panic caused by a maliciously crafted static archive that a developer links against (e.g., via a dependency's `CGO_LDFLAGS`, embedded `.syso`, or vendored `.a` library) results in a denial of service of the build process. This is a parser panic on attacker-supplied structured binary input reachable through an ordinary `go build`/link workflow, which qualifies as a legitimate parser-panic finding under Go's security policy (PUBLIC track candidate, low severity — it aborts a local build rather than achieving code execution or data corruption).

### Likelihood Explanation
Likelihood is moderate: it requires a victim to link a Go program against an attacker-supplied or attacker-influenced host archive (common in CGO scenarios pulling in third-party static libraries). The attacker does not need any elevated privileges — an ordinarily-untrusted archive file is enough; no malicious server, host, or credential control is required, satisfying the "unprivileged" reachability model of the prompt.

### Recommendation
In `readArmap`, validate `atolwhex(arhdr.size)` is non-negative and at least `wordSize` bytes before slicing (`ar.go:203-214`), and bound the NUL-terminator scan against `len(names)` (`ar.go:220-223`), returning a graceful link error (e.g., via `Exitf`) instead of panicking on malformed/truncated archive symbol tables.

### Proof of Concept

```go
package ld

import "testing"

// TestReadArmapMalformedSize demonstrates that a crafted archive header
// with a size field smaller than wordSize causes readArmap to panic
// via an out-of-bounds slice operation, instead of failing gracefully.
func TestReadArmapMalformedSize(t *testing.T) {
    defer func() {
        if r := recover(); r == nil {
            t.Fatal("expected readArmap to fail gracefully on malformed size, but no panic/error occurred")
        }
    }()

    // Simulate an archive header claiming a symbol-table size (2 bytes)
    // smaller than the required word size (4 bytes for 32-bit armap).
    arhdr := ArHdr{name: "/", size: "2"}

    // In real usage, f is a *bio.Reader positioned over `contents` bytes;
    // here we assert the failure mode: contents[wordSize:] on a
    // 2-byte slice panics with "slice bounds out of range".
    contents := make([]byte, atolwhex(arhdr.size)) // len(contents) == 2
    _ = contents[4:]                                // panics: slice bounds out of range [4:2]
}
```
Expected assertion: `readArmap` (and by extension `atolwhex`/slice logic at `ar.go:203-214`) should reject an archive whose declared symbol-table size is smaller than `wordSize` with a controlled error (e.g. `Exitf("short read from %s", filename)`), rather than allowing the unchecked slice expression to panic.
