### Title
Route-based access-control bypass via decoding mismatch between `http.ServeMux` routing and `http.FileServer` file resolution - ([File: src/net/http/server.go], [File: src/net/http/fs.go])

### Summary
`http.ServeMux` matches requests using `r.URL.EscapedPath()`, splitting on literal `/` bytes and treating an encoded slash (`%2F`) as part of a segment rather than a separator, as explicitly documented at [1](#0-0) . `http.FileServer`'s handler (`fileHandler.ServeHTTP` → `serveFile`), however, resolves files using `r.URL.Path`, the already-decoded path field in which `%2F` has been converted into a literal `/`, per the `url.URL` documentation stating the `Path` field is "stored in decoded form: /%47%6f%2f becomes /Go/" [2](#0-1) . This is the same class of bug as the Hono advisory: one layer (router/middleware) treats `%2F` as non-separator while the sibling layer (static file resolver) treats it as a literal `/`, letting requests that don't match a protecting route pattern still resolve to the protected file on disk.

### Finding Description
Attacker input: `GET /admin%2Fsecret.html`.

1. Entry point: `http.ServeMux.ServeHTTP` → `mux.findHandler(r)` at [3](#0-2) , which uses `escapedPath := r.URL.EscapedPath()` and `cleanPath(path)` (syntactic cleanup only, no decoding) before calling `matchOrRedirect`.
2. Matching: `routingNode.matchPath` / `firstSegment` splits the escaped path only on literal `/` bytes, then unescapes each segment individually [4](#0-3) . Because `%2F` is not a literal `/`, `/admin%2Fsecret.html` is a single segment (unescaping to `admin/secret.html`), so it does not match a two-segment pattern like `/admin/` (or `/admin/{rest...}`) registered to protect that subtree — this is intentional, documented behavior (`server.go:2747`: "%2f" ... "aren't considered separators for request routing").
3. Because the protected pattern doesn't match, the request falls through to whatever handler matches the broader route (e.g. a `http.FileServer(http.Dir(root))` mounted at `/` serving the same root directory that contains `admin/`).
4. Sink: `fileHandler.ServeHTTP` at [5](#0-4)  reads `upath := r.URL.Path` — NOT `EscapedPath()` — and calls `serveFile(w, r, f.root, path.Clean(upath), true)`. Since `r.URL.Path` is the decoded form where `%2F` has already become a literal `/` (per `url.go:268-271`), `path.Clean(upath)` yields `/admin/secret.html`, and `serveFile`/`fs.Open` opens and serves that file directly, bypassing the route-based protection that governs `/admin/`.

The failed check is the implicit assumption that `ServeMux`'s routing decision and `FileServer`'s file-resolution decision operate on the same decoded representation of the path — they don't: one uses `EscapedPath()` (raw/undecoded), the other uses `Path` (decoded, collapsing `%2F` to `/`).

### Impact Explanation
Concrete impact: authentication/authorization bypass for static resources — an unauthenticated attacker can retrieve files intended to be gated behind route-scoped middleware (e.g., `mux.Handle("/admin/", authMiddleware(...))`) by requesting the equivalent path with an encoded slash, as long as a `FileServer`/`ServeFile`-style handler also serves the same directory tree from a less-restricted route (commonly `/`). This matches CWE-177 (Improper Handling of URL Encoding) and mirrors the Hono `serveStatic` advisory's precondition and effect (route-based subpath protection + static serving of the same root). This would be a **PUBLIC** track candidate for Go's security process if it reproduces against a supported release, since it is a documented decoding-inconsistency mismatch between two standard-library components applications commonly combine (`ServeMux` for auth-gated routes + `FileServer` for static assets).

### Likelihood Explanation
Victim workflow: any Go web application that (a) protects a subpath with `ServeMux`-registered middleware/handler and (b) also serves the same filesystem root (or an overlapping root) via `http.FileServer`/`http.FileServerFS`/`http.ServeFile` for unauthenticated static content — a common pattern for apps mixing an admin panel and a public asset directory. The attacker needs only an unauthenticated HTTP client; no special privileges. Likelihood is moderate: it requires the specific combination of "route-level protection" + "sibling static file serving of the same or an overlapping root," which is a real but not universal deployment pattern; whether current Go documentation/tests already flag or prevent this exact combinator was not confirmed within available time and files, so this should be treated as a **candidate requiring live reproduction against a running `net/http` server**, not a confirmed 0-day.

### Recommendation
Make `FileServer`/`serveFile`'s path resolution consistent with `ServeMux`'s routing decoding model: either (a) have `fileHandler.ServeHTTP` reject or 400 requests whose `EscapedPath()` contains `%2F`/`%2f` (similar to how `containsDotDot` rejects `..`), or (b) document explicitly (beyond the existing `ServeMux` doc note) that combining route-scoped protection with a `FileServer` mounted on an overlapping/parent path is unsafe, and provide guidance to use `http.StripPrefix` plus root-scoped `FileServer` instances that don't overlap protected subtrees, or normalize by using `EscapedPath()`-based decisions consistently across both routing and static serving.

```go
package http_test

import (
	"io"
	"net/http"
	"net/http/httptest"
	"os"
	"path/filepath"
	"testing"

// Simulates: ServeMux protects "/admin/" with authMiddleware,
// and FileServer serves the same root "." at "/".
func TestEscapedSlashBypassesRouteProtection(t *testing.T) {
	dir := t.TempDir()
	os.MkdirAll(filepath.Join(dir, "admin"), 0755)
	os.WriteFile(filepath.Join(dir, "admin", "secret.html"), []byte("SECRET"), 0644)

	mux := http.NewServeMux()
	mux.Handle("/admin/", http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		http.Error(w, "unauthorized", http.StatusUnauthorized) // route-based protection
	}))
	mux.Handle("/", http.FileServer(http.Dir(dir))) // same root served statically

	ts := httptest.NewServer(mux)
	defer ts.Close()

	// Direct request is blocked by route protection.
	res, _ := ts.Client().Get(ts.URL + "/admin/secret.html")
	if res.StatusCode != http.StatusUnauthorized {
		t.Fatalf("expected 401 for /admin/secret.html, got %d", res.StatusCode)
	}

	// Encoded-slash request bypasses ServeMux route match but FileServer
	// decodes %2F back to '/' and serves the protected file.
	res2, _ := ts.Client().Get(ts.URL + "/admin%2Fsecret.html")
	body, _ := io.ReadAll(res2.Body)
	if res2.StatusCode == http.StatusOK && string(body) == "SECRET" {
		t.Fatalf("BYPASS: got protected file via %%2F, status=%d body=%q", res2.StatusCode, body)
	}
}
```

```go
	// Get the first segment of path.
	seg, rest := firstSegment(path)
	// First try matching against patterns that have a literal for this position.
	// We know by construction that such patterns are more specific than those
	// with a wildcard at this position (they are either more specific, equivalent,
	// or overlap, and we ruled out the first two when the patterns were registered).
	if n, m := n.findChild(seg).matchPath(rest, matches); n != nil {
		return n, m
	}
	// If matching a literal fails, try again with patterns that have a single
	// wildcard (represented by an empty string in the child mapping).
	// Again, by construction, patterns with a single wildcard must be more specific than
	// those with a multi wildcard.
	// We skip this step if the segment is a trailing slash, because single wildcards
	// don't match trailing slashes.
	if seg != "/" {
		if n, m := n.emptyChild.matchPath(rest, append(matches, seg)); n != nil {
			return n, m
		}
	}
	// Lastly, match the pattern (there can be at most one) that has a multi
	// wildcard in this position to the rest of the path.
	if c := n.multiChild; c != nil {
		// Don't record a match for a nameless wildcard (which arises from a
		// trailing slash in the pattern).
		if c.pattern.lastSegment().s != "" {
			matches = append(matches, pathUnescape(path[1:])) // remove initial slash
		}
		return c, matches
	}
	return nil, nil
```
