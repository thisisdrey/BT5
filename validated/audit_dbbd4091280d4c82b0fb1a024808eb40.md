### Title
`get_add_stake_fee` Omits Transaction-Fee Component When `DISTRIBUTE_TRANSACTION_FEE` Is Enabled, Allowing New Stakers to Steal Existing Delegators' Fee Rewards — (`delegation_pool.move`)

---

### Summary

`delegation_pool::get_add_stake_fee` calculates the dilution-compensation fee charged to new stakers using **only** the base staking-rewards rate from `staking_config::get_reward_rate`. When the `DISTRIBUTE_TRANSACTION_FEE` feature flag (id 97) is active, validators also receive minted transaction-fee APT into their stake pool at epoch end. Because that second reward component is invisible to `get_add_stake_fee`, the fee is systematically underestimated, and every `add_stake` call transfers a measurable amount of APT from existing delegators to the new staker.

---

### Finding Description

**Reward sources at epoch end (`stake::update_stake_pool`):**

1. Staking rewards — `distribute_rewards` mints `stake_amount * rewards_rate / rewards_rate_denominator * perf_ratio` into `stake_pool.active`.
2. Transaction fees — when `is_distribute_transaction_fee_enabled()` is true, `fee_active` APT is additionally minted and merged into `stake_pool.active`. [1](#0-0) 

Both amounts are reflected in the `active` value returned by `stake::get_stake` and consumed by `calculate_stake_pool_drift` → `synchronize_delegation_pool`.

**The broken invariant in `get_add_stake_fee`:**

```move
let (rewards_rate, rewards_rate_denominator) =
    staking_config::get_reward_rate(&staking_config::get());   // ← staking rewards only
// ...
rewards_rate *= (MAX_FEE - operator_commission_percentage(pool_address));
rewards_rate_denominator *= MAX_FEE;
((((amount as u128) * (rewards_rate as u128))
    / ((rewards_rate as u128) + (rewards_rate_denominator as u128))) as u64)
``` [2](#0-1) 

The function never queries `PendingTransactionFee` or any proxy for the expected transaction-fee yield. The fee formula is:

```
fee = amount × r_staking / (1 + r_staking)
```

but the correct formula when transaction fees are distributed is:

```
fee = amount × (r_staking + r_txfee) / (1 + r_staking + r_txfee)
```

**How the `NULL_SHAREHOLDER` mechanism propagates the loss:**

`add_stake` places the underestimated fee into `NULL_SHAREHOLDER`'s shares. At the next `synchronize_delegation_pool` call (when `pending_active == 0`), those shares are redeemed at the **pre-reward price** and the coins are removed from the pool. [3](#0-2) 

After `update_total_coins` is called with the full post-reward `active` value (staking rewards + transaction fees), the new staker's shares appreciate by the full combined rate, while only the staking-rate portion was pre-paid. The shortfall is borne by existing delegators whose per-share value is diluted.

---

### Impact Explanation

For each `add_stake(amount)` call while the validator is active and `DISTRIBUTE_TRANSACTION_FEE` is enabled:

- **Stolen per call ≈** `amount × r_txfee / (1 + r_staking + r_txfee)`

On a busy epoch where transaction fees represent even 0.1 % of active stake, a single 1 000 000 APT `add_stake` call steals roughly 1 000 APT from existing delegators. The effect is additive across all `add_stake` calls within an epoch and across all delegation pools.

This is a direct, unprivileged transfer of APT staking balances from existing delegators to new stakers — matching the "Direct theft… of staking balances" criterion in the Aptos bounty scope.

---

### Likelihood Explanation

- `DISTRIBUTE_TRANSACTION_FEE` (feature 97) and its prerequisite `CALCULATE_TRANSACTION_FEE_FOR_DISTRIBUTION` (feature 96) are fully implemented, tested, and present in the release-builder flag map. [4](#0-3) 

- `add_stake` is a public entry function callable by any unprivileged account.
- No existing guard in `get_add_stake_fee` or `add_stake` compensates for the transaction-fee component.
- The effect is proportional to network activity (higher fees → larger theft per call) and is maximised by calling `add_stake` with a large amount early in an epoch.

---

### Recommendation

`get_add_stake_fee` must incorporate the expected transaction-fee yield when `DISTRIBUTE_TRANSACTION_FEE` is enabled. One approach:

1. Read the accumulated `PendingTransactionFee` for the pool's validator index.
2. Compute `r_txfee = pending_fee_active / stake_pool_active`.
3. Add `r_txfee` to `rewards_rate / rewards_rate_denominator` before applying the formula.

Alternatively, expose a helper from `stake` that returns the combined expected per-epoch appreciation rate (staking + fee) so `delegation_pool` can use a single, always-correct rate.

---

### Proof of Concept

**Setup:** delegation pool with 1 000 000 APT active stake, 0 % operator commission, staking rate = 1 %/epoch, transaction fee for this epoch = 5 000 APT (0.5 % of active stake).

**Step 1 — Attacker calls `add_stake(1_000_000 APT)` mid-epoch:**

```
add_stake_fee = get_add_stake_fee(pool, 1_000_000 APT)
             = 1_000_000 × 0.01 / 1.01
             ≈ 9_901 APT          // only staking rate used
```

Attacker receives `990_099 shares` (at price 1 APT/share). `NULL_SHAREHOLDER` receives `9_901 shares`.

**Step 2 — Epoch ends (`update_stake_pool`):**

- Staking rewards minted into active: `1_000_000 × 1% = 10_000 APT`
- Transaction fees minted into active: `5_000 APT`
- `pending_active` (1 000 000 APT) becomes active
- Total active: `2_015_000 APT`

**Step 3 — `synchronize_delegation_pool`:**

- `NULL_SHAREHOLDER`'s 9 901 shares redeemed at old price (1 APT/share) → 9 901 APT removed
- `update_total_coins(2_015_000)` → price = `2_015_000 / 1_990_099 ≈ 1.01252 APT/share`

**Step 4 — Final balances:**

| Party | Shares | APT |
|---|---|---|
| Existing delegators | 1 000 000 | 1 012 520 |
| Attacker | 990 099 | 1 002 480 |

**Expected (correct fee):**

- Attacker should receive exactly 1 000 000 APT back (no gain from others' rewards)
- Correct fee = `1_000_000 × 0.015 / 1.015 ≈ 14_778 APT`
- Attacker over-gains ≈ **2 480 APT** stolen from existing delegators in a single transaction [2](#0-1) [1](#0-0) [5](#0-4)

    public entry fun add_stake(
        delegator: &signer,
        pool_address: address,
        amount: u64
    ) acquires DelegationPool, GovernanceRecords, BeneficiaryForOperator, NextCommissionPercentage, DelegationPoolAllowlisting {
        // short-circuit if amount to add is 0 so no event is emitted
        if (amount == 0) { return };

        let delegator_address = signer::address_of(delegator);
        assert_delegator_allowlisted(pool_address, delegator_address);

        // synchronize delegation and stake pools before any user operation
        synchronize_delegation_pool(pool_address);

        // fee to be charged for adding `amount` stake on this delegation pool at this epoch
        let add_stake_fee = get_add_stake_fee(pool_address, amount);

        let pool = borrow_global_mut<DelegationPool>(pool_address);

        // stake the entire amount to the stake pool
        aptos_account::transfer(delegator, pool_address, amount);
        stake::add_stake(&retrieve_stake_pool_owner(pool), amount);

        // but buy shares for delegator just for the remaining amount after fee
        buy_in_active_shares(pool, delegator_address, amount - add_stake_fee);
        assert_min_active_balance(pool, delegator_address);

        // grant temporary ownership over `add_stake` fees to a separate shareholder in order to:
        // - not mistake them for rewards to pay the operator from
        // - distribute them together with the `active` rewards when this epoch ends
        // in order to appreciate all shares on the active pool atomically
        buy_in_active_shares(pool, NULL_SHAREHOLDER, add_stake_fee);

        event::emit(
            AddStake {
                pool_address,
                delegator_address,
                amount_added: amount,
                add_stake_fee,
            },
        );
    }
