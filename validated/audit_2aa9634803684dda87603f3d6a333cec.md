### Title
Validator self-stake incentive dilution via legacy weight-sum denominator that includes zero-reward-point validators — (File: `substrate/frame/staking-async/src/pallet/impls.rs`)

### Summary
`pallet-staking-async`'s validator self-stake incentive payout computes each validator's share of the era incentive budget as `validator_weight / total_weight`. For eras still on the legacy (pre-cutoff) formula, `total_weight` is `ErasSumValidatorIncentiveWeight`, which is populated at **election time** for every elected validator with non-zero own-stake, regardless of whether that validator ever earns reward points during the era [1](#0-0) . However, at **payout time**, only validators with non-zero reward points are ever paid: the payout routine returns early for any validator with zero reward points, before the incentive-transfer logic even runs [2](#0-1) . This is structurally identical to the reported Canto `LiquidityMining` bug: the denominator counts "ineligible" participants (validators with zero points) that never claim, so the eligible validators' share is diluted and the incentive pot is never fully paid out.

### Finding Description
The legacy share calculation is:

```rust
let total_weight = ErasSumValidatorIncentiveWeight::<T>::get(era);
...
Perbill::from_rational(validator_weight, total_weight)
``` [3](#0-2) 

`total_weight` is accumulated for *every* elected validator with non-zero own-stake at the time `store_stakers_info` runs (election time, before the era's reward points are known):

```rust
if !own.is_zero() {
    ...
    let incentive_weight = T::StakerRewardCalculator::calculate_validator_incentive_weight(own);
    if !incentive_weight.is_zero() {
        total_incentive_weight_page = total_incentive_weight_page.saturating_add(incentive_weight);
        ErasValidatorIncentiveWeight::<T>::insert(new_planned_era, &stash, incentive_weight);
    }
}
...
Eras::<T>::add_sum_validator_incentive_weight(new_planned_era, total_incentive_weight_page);
``` [4](#0-3) 

But at payout time, `do_payout_stakers_by_page` skips *all* incentive logic — the `calculate_validator_incentive_for_page` call, which triggers `transfer_validator_incentive` — for any validator with zero reward points:

```rust
let validator_reward_points = era_reward_points.individual.get(&stash).copied().unwrap_or_else(Zero::zero);
// Nothing to do if they have no reward points.
if validator_reward_points.is_zero() {
    return Ok(Some(T::WeightInfo::payout_stakers_alive_staked(0)).into());
}
``` [5](#0-4) 

So any validator that is elected (and thus counted in the incentive-weight denominator) but ends up earning zero era points (offline, chilled mid-era, produced no blocks, etc.) contributes weight to the denominator without ever being paid, and without its share being redistributed to the remaining validators. The new weighted-points formula (`ErasSumWeightedPoints`) explicitly fixes this by gating the denominator on points as well as weight — the PR description itself states: "Validators with zero era points or no incentive weight receive nothing, and non-zero weighted performers share the era budget" [6](#0-5)  — but the legacy formula, which is still used for "pending eras" strictly older than `WeightedPointsFormulaStartEra`, retains the flawed all-elected-validators denominator by design ("Pre-upgrade pending eras keep paying out under the legacy stake-only share `w_i / Σ_j w_j`") [7](#0-6) .

This mirrors the audited bug exactly: the denominator (`Σ_j w_j` over all elected validators) is not restricted to the set of validators that actually satisfy the payout condition (non-zero reward points), so the numerator/denominator scope mismatch under-distributes the intended budget whenever ineligible ("no points") entries are present in the pool used for the denominator.

### Impact Explanation
Every era that falls under the legacy formula (any era prior to `WeightedPointsFormulaStartEra`, which is set by a one-shot migration and could include a non-trivial window of eras during/around upgrade) will systematically under-pay the validator self-stake incentive whenever one or more elected validators end the era with zero reward points — a common, non-malicious occurrence (an elected validator simply not producing any blocks in an era). The portion of the era incentive budget corresponding to those validators' weight is never transferred to anyone; it stays in the per-era incentive pot account (`RewardPot::Era(era, RewardKind::ValidatorSelfStake)`) and is later drained without redistribution during era cleanup [8](#0-7) , meaning legitimately-earned incentive value is permanently lost/misallocated rather than paid to the rightful (performing) validators. This is a runtime bug that compromises the intended incentive-distribution behavior and results in under-distribution/misallocation of a payout budget — an in-scope "runtime bug that compromises intended behavior" / value-conservation issue, not an admin or governance failure.

### Likelihood Explanation
High. It requires no attacker action, no privileged actor, and no adversarial relayer/prover — it happens automatically whenever any elected validator with self-stake ends an era with zero reward points (offline, restarted, chilled after election but before era end, etc.), which is a routine occurrence in production validator sets. The bug is deterministic and reproducible purely from normal era-rotation behavior for any era still using the legacy formula.

### Recommendation
For the legacy (pre-cutoff) formula, exclude validators with zero reward points from the incentive-weight denominator, or migrate all pending/legacy eras to the points-gated `ErasSumWeightedPoints` denominator so the sum only ever reflects weight of validators that will actually be paid. Alternatively, redistribute any un-claimed incentive-weight share (from zero-point validators) back into the payable pool before drain, so the era incentive budget is fully and correctly distributed to eligible validators only.

### Proof of Concept
1. Configure `setup_incentive_with_budget` for an era prior to `WeightedPointsFormulaStartEra` (legacy formula in effect), with two validators `alice` and `bob` elected with equal self-stake/incentive weight, so `ErasSumValidatorIncentiveWeight(era) = 2 * w`.
2. During the era, only `bob` earns reward points (`alice` earns zero) — analogous to `zero_reward_points_means_no_payout` test setup [9](#0-8) , but forced onto the legacy path instead of the weighted-points path.
3. Call `make_all_reward_payment(era)`. `alice`'s payout returns early at the zero-reward-points check and never invokes `calculate_validator_incentive_for_page`/`transfer_validator_incentive` [5](#0-4) .
4. For `bob`, `share_part = Perbill::from_rational(bob_weight, total_weight) = Perbill::from_rational(w, 2w) = 1/2` because `total_weight` still includes `alice`'s weight [10](#0-9) .
5. Expected: `bob`, the only validator with reward points, should receive the full incentive budget (as the weighted-points-formula test `zero_reward_points_means_no_payout` demonstrates for the fixed path — `bob` gets the whole budget when `alice` has zero points [11](#0-10) ). Actual (legacy path): `bob` only receives half of the budget; the other half remains stranded in the era's `ValidatorSelfStake` reward pot and is discarded on `cleanup_era`'s drain [8](#0-7) , confirming the dilution/loss described.
