### Title
Cross-repository object disclosure via unrestricted `LinkRepositoryToObjectPool` linking - ([File: internal/gitaly/service/objectpool/link.go])

### Summary
The `LinkRepositoryToObjectPool` RPC accepts two independent, caller-supplied repository identities — `repository` (the target) and `object_pool` (an arbitrary repository designated as a pool) — and links them by writing a Git alternates file, with no check that the two repositories have any prior relationship (e.g. that the pool was actually created from, or is otherwise associated with, the target repository). This mirrors the `OmoRouter.redeem()` flaw: the handler trusts a second, caller-controlled identity (`owner` in the contract, `object_pool` here) to perform a privileged cross-entity operation instead of verifying that the caller's own resource is what's actually being acted upon.

### Finding Description
`LinkRepositoryToObjectPool` only validates that `repository` is a valid Git repository and that `object_pool` resolves to *some* valid pool-shaped repository via `objectpool.FromProto`: [1](#0-0) 

`objectpool.FromProto` verifies only that the path exists, matches the pool naming convention (or is in a temp dir), and `ValidateRepository` succeeds — it never checks that the pool is associated with the `repository` being linked: [2](#0-1) 

`pool.Link()` then unconditionally writes the pool's path into the target repository's `objects/info/alternates` file, once written, Git will resolve missing objects in the target repository by searching the pool's object store, and removes the target's bitmap: [3](#0-2) 

Because any storage-relative path known to the caller can be supplied as either `repository` or `object_pool` (there is no assertion binding them, unlike the SHA1-derived quarantine-directory prefix check used elsewhere in the codebase to bind a quarantine dir to its owning repo, see `QuarantineDirectoryPrefix`): [4](#0-3) 
an attacker who can reach this RPC and knows (or guesses/enumerates) the relative path of a victim's object pool can link their own, unrelated repository to that pool. This immediately grants the attacker's repository read access to every object stored in the victim's pool through the alternates mechanism, exactly analogous to `redeem()` letting an unrelated caller specify a victim `owner` to move that owner's assets.

### Impact Explanation
Once linked, any object present in the target pool (including from other, unrelated forks/members sharing that pool) becomes readable from the attacker-controlled repository via standard Git object resolution (`git cat-file`, `git log`, clone, etc., through Gitaly's Commit/Blob/Diff services). This is a cross-repository object/data disclosure of potentially private commit and blob contents belonging to repositories the attacker has no legitimate relationship with — high impact, comparable to the fund-drain in the original finding since sensitive data ("assets") is exfiltrated by exploiting a caller-supplied identity that isn't verified against the caller's own resource.

### Likelihood Explanation
Likelihood is Medium: exploitation requires the attacker to know the relative path of a repository they are permitted to operate a mutator RPC against (their own repo) and the relative path of the victim's pool. Gitaly itself performs no authorization checks (that's delegated to GitLab Rails in production deployments), so this is squarely a Gitaly-side gap in the storage/RPC layer that a caller with any valid write-capable connection to Gitaly (e.g., a compromised or malicious tenant with legitimate repo access) can trigger directly, without needing to compromise another user's credentials.

### Recommendation
`LinkRepositoryToObjectPool` (and `FetchIntoObjectPool`/`DisconnectGitAlternates` where relevant) should verify an explicit binding between the `repository` and `object_pool` before performing the link — e.g., requiring the pool to have been created via `CreateObjectPool` from that same repository (tracked via stored provenance, analogous to the `QuarantineDirectoryPrefix` binding technique already used for quarantine directories), or requiring a Rails-issued token/hint that proves the caller is authorized for both repositories in the same request. At minimum, reject links where the pool's recorded origin repository does not match the target repository's project/fork lineage.

### Proof of Concept
1. Attacker has legitimate access to `repoA` (their own repository) on a Gitaly node.
2. Attacker learns (or brute-forces, given predictable pool paths) the relative path of `victimPool`, an object pool containing objects from `victimRepo`.
3. Attacker calls:
```
LinkRepositoryToObjectPool(
  Repository:  {StorageName: "default", RelativePath: "repoA.git"},
  ObjectPool:  {Repository: {StorageName: "default", RelativePath: "@pools/ab/cd/victimPool.git"}},
)
```
4. Gitaly validates only that both paths are valid Git repositories (no ownership binding check) and writes `repoA/objects/info/alternates` pointing at `victimPool/objects`.
5. Attacker calls `CommitService`/`BlobService` RPCs against `repoA`, which can now resolve and return objects that physically only exist in `victimPool`, disclosing data from repositories unrelated to `repoA`.

// FromProto returns an object pool object from its Protobuf representation. This function verifies
// that the object pool exists and is a valid pool repository.
func FromProto(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	proto *gitalypb.ObjectPool,
) (*ObjectPool, error) {
	poolPath, err := locator.GetRepoPath(ctx, proto.GetRepository(), storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	if !storage.IsPoolRepository(proto.GetRepository()) {
		// When creating repositories in the ObjectPool service we will first create the
		// repository in a temporary directory. So we need to check whether the path we see
		// here is in such a temporary directory and let it pass.
		tempDir, err := locator.TempDir(proto.GetRepository().GetStorageName())
		if err != nil {
			return nil, fmt.Errorf("getting temporary storage directory: %w", err)
		}

		if !strings.HasPrefix(poolPath, tempDir) {
			return nil, ErrInvalidPoolDir
		}
	}

	pool := &ObjectPool{
		Repo:                localrepo.New(logger, locator, gitCmdFactory, catfileCache, proto.GetRepository()),
		logger:              logger,
		locator:             locator,
		gitCmdFactory:       gitCmdFactory,
		txManager:           txManager,
		housekeepingManager: housekeepingManager,
	}

	if !pool.IsValid(ctx) {
		return nil, ErrInvalidPoolRepository
	}

	return pool, nil
}

// Link will link the given repository to the object pool. This is done by writing the object pool's
// path relative to the repository into the repository's "alternates" file. This does not trigger
// deduplication, which is the responsibility of the caller.
func Link(ctx context.Context, pool, repo *localrepo.Repo, txManager transaction.Manager) (returnedErr error) {
	altPath, err := repo.InfoAlternatesPath(ctx)
	if err != nil {
		return err
	}

	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return err
	}

	linked, err := linkedToRepository(ctx, pool, repo)
	if err != nil {
		return err
	}

	if linked {
		// When the repository is already linked to the repository, cast a vote to ensure the
		// repository is consistent with the other replicas.
		if err := transaction.VoteOnContext(ctx, txManager, voting.VoteFromData([]byte("repository linked")), voting.Synchronized); err != nil {
			return fmt.Errorf("vote on linked repository: %w", err)
		}

		return nil
	}

	alternatesWriter, err := safe.NewLockingFileWriter(altPath)
	if err != nil {
		return fmt.Errorf("creating alternates writer: %w", err)
	}
	defer func() {
		if err := alternatesWriter.Close(); err != nil && returnedErr == nil {
			returnedErr = fmt.Errorf("closing alternates writer: %w", err)
		}
	}()

	if _, err := io.WriteString(alternatesWriter, expectedRelPath); err != nil {
		return fmt.Errorf("writing alternates: %w", err)
	}

	if err := transaction.CommitLockedFile(ctx, txManager, alternatesWriter); err != nil {
		return fmt.Errorf("committing alternates: %w", err)
	}
