## Title
Deferred slash silently dropped when its unbonding-era sub-pool bucket has already been merged - ([File: substrate/frame/nomination-pools/src/lib.rs])

## Summary
`pallet-nomination-pools` distributes a slash proportionally across the specific per-era `with_era` sub-pool buckets identified by `slashed_unlocking`, exactly analogous to the reported Trove pattern of funding liquidations only from the specific collateral "bucket" involved. When the targeted era bucket has already been merged away (via `SubPools::maybe_merge_pools`) before the deferred slash is actually applied, `on_slash` cannot find it, silently no-ops that portion of the slash via a `defensive!()` log only, yet still globally decrements `TotalValueLocked` by the full `total_slashed` amount. This desynchronizes pool bookkeeping from the real, already-reduced staked funds, mirroring the "last trove of a given collateral type" unclaimed-debt scenario from the external report.

## Finding Description
`Pallet::on_slash` is the `OnStakingUpdate` hook that nomination-pools uses to reflect a slash coming from `pallet-staking`'s deferred slashing pipeline: [1](#0-0) 

For each `(era, slashed_balance)` in `slashed_unlocking`, the code does `sub_pools.with_era.get_mut(era).defensive()`. If that specific era bucket is not present, the branch is skipped and nothing is mutated for that era — the code only fires a defensive log (`defensive!("Expected SubPools were not found")` only fires when `slashed_unlocking` is non-empty but `sub_pools` itself is entirely `None`; the per-era `.defensive()` on a missing individual key is likewise a no-op in production builds). Crucially, `TotalValueLocked` is reduced by `total_slashed` unconditionally beforehand, regardless of whether the corresponding sub-pool bucket exists: [2](#0-1) 

The era bucket that `on_slash` expects to still exist can disappear for two independent reasons that are unrelated to whether `pallet-staking`'s underlying ledger still tracks an unlocking chunk for that era (which is what actually drives `slashed_unlocking`):

1. **Lazy merge into `no_era`.** `SubPools::maybe_merge_pools` folds `with_era` buckets older than `effective_post_unbonding_window = MaxUnbondingPools - bonding_duration` into the era-agnostic `no_era` bucket whenever sub-pools are read/written (e.g. on `unbond`/`withdraw_unbonded`): [3](#0-2) 
This merge is driven purely by `MaxUnbondingPools`/`BondingDuration`, not by `SlashDeferDuration`. If a slash is deferred long enough (or the effective window is narrow enough) that pools bookkeeping merges the bucket before the staking pallet actually calls `on_slash` for that era, the exact "bucket no longer exists" condition is hit.
2. **Bucket removal on full withdrawal.** `withdraw_unbonded` removes a `with_era` entry entirely once its points hit zero: [4](#0-3) 

There is a comment acknowledging a closely related class of routing/rounding bugs on this exact path, calling out cases that "should not happen at all": [5](#0-4) 
and a dedicated regression test only demonstrates the case where a widening window correctly *keeps* the bucket around for routing — it does not cover (and the code does not handle) the case where the pools-side bucket is gone by the time the slash lands: [6](#0-5) 

This is the direct structural analog of the Trove report: liquidation/slash proceeds are only ever funded from the specific "bucket" (era sub-pool ≈ collateral type) that was originally targeted, with no fallback to a shared/no-era pool of last resort. When that specific bucket ceases to exist, the slash is neither applied to it nor redirected — yet the global TVL accounting and the real underlying stake (already reduced in `pallet-staking`) proceed as if it had been applied somewhere.

## Impact Explanation
The net effect is a permanent desynchronization between (a) the real, slashed balance actually held by the pool's bonded/unbonding stash in `pallet-staking`, and (b) the pool's internal `SubPools`/`TotalValueLocked` accounting, which continues to believe the unaffected bucket (or the `no_era` bucket it was later merged into) holds its pre-slash value. Members who withdraw against that overstated bucket will be paid based on stale, unslashed point/balance ratios while the pool's real backing funds are short — the shortfall surfaces later as failed/partial withdrawals for the last members to redeem from that bucket (bounded by `transferable_balance` in `withdraw_unbonded`), i.e. permanently unclaimable/stuck value, directly matching the "perpetually unclaimed debt" consequence called out in the external report.

## Likelihood Explanation
This does not require a malicious actor, admin, or governance action — it is a timing/configuration interaction between `T::MaxUnbondingPools`, `bonding_duration()`, and the staking pallet's `SlashDeferDuration`, all of which are ordinary runtime parameters. Any equivocation/offence that triggers a deferred slash landing on an unbonding era whose sub-pool bucket has meanwhile been merged (or fully drained by member withdrawals) reproduces the condition; no privileged access or off-chain assumption is needed.

## Recommendation
In `on_slash`, when the targeted `era` bucket is missing from `with_era`, fall back to applying the proportional reduction to `no_era` (mirroring the same points-weighted reduction logic used for `with_era` buckets) instead of silently dropping the adjustment. Additionally, audit whether `effective_post_unbonding_window` should be derived from (or bounded by) `SlashDeferDuration` rather than solely `MaxUnbondingPools`/`bonding_duration`, so a bucket can never be merged away before all slashes that could still target its era have been finalized.

## Proof of Concept
1. Configure a runtime where the nomination-pools effective post-unbonding window (`MaxUnbondingPools - BondingDuration`) is smaller than `pallet-staking`'s `SlashDeferDuration`.
2. Create a pool, have a member fully unbond in era `E`, creating a `with_era` bucket for era `E`.
3. Advance eras past the effective post-unbonding window so a subsequent pool operation (e.g., another member's `unbond`/`withdraw_unbonded`) triggers `maybe_merge_pools`, folding era `E`'s bucket into `no_era`.
4. Trigger an offence/slash whose deferred application (`SlashDeferDuration` eras later) still targets era `E`'s unlocking chunk in `pallet-staking`'s ledger, producing a non-empty `slashed_unlocking` entry for era `E`.
5. Observe `on_slash` reduce `TotalValueLocked` by `total_slashed` while `sub_pools.with_era.get_mut(&E)` is `None`, so `no_era`'s balance is never reduced — compare `SubPoolsStorage` and members' `total_balance()` against the actual reduced stake reported by `pallet-staking` for the pool's bonded account to confirm the overstatement, then complete a `withdraw_unbonded` for the affected members to observe the shortfall/failed payout.

	/// Merge the oldest `with_era` unbond pools into the `no_era` unbond pool.
	///
	/// This is often used whilst getting the sub-pool from storage, thus it consumes and returns
	/// `Self` for ergonomic purposes.
	fn maybe_merge_pools(mut self, active_era: EraIndex) -> Self {
		// Retain `with_era` pools for ~`MaxUnbondingPools` eras after unlock.
		// E.g., if window is 2 and active era is 10, retain pools 9..=10.
		let effective_post_unbonding_window =
			T::MaxUnbondingPools::get().saturating_sub(T::StakeAdapter::bonding_duration());
		if let Some(newest_era_to_remove) = active_era.checked_sub(effective_post_unbonding_window)
		{
			self.with_era.retain(|k, v| {
				if *k > newest_era_to_remove {
					// keep
					true
				} else {
					// merge into the no-era pool
					self.no_era.points = self.no_era.points.saturating_add(v.points);
					self.no_era.balance = self.no_era.balance.saturating_add(v.balance);
					false
				}
			});
		}

		self
	}

	fn on_slash(
		pool_account: &T::AccountId,
		// Bonded balance is always read directly from staking, therefore we don't need to update
		// anything here.
		slashed_bonded: BalanceOf<T>,
		slashed_unlocking: &BTreeMap<EraIndex, BalanceOf<T>>,
		total_slashed: BalanceOf<T>,
	) {
		let Some(pool_id) = ReversePoolIdLookup::<T>::get(pool_account) else { return };
		// As the slashed account belongs to a `BondedPool` the `TotalValueLocked` decreases and
		// an event is emitted.
		TotalValueLocked::<T>::mutate(|tvl| {
			tvl.defensive_saturating_reduce(total_slashed);
		});

		if let Some(mut sub_pools) = SubPoolsStorage::<T>::get(pool_id) {
			// set the reduced balance for each of the `SubPools`
			slashed_unlocking.iter().for_each(|(era, slashed_balance)| {
				if let Some(pool) = sub_pools.with_era.get_mut(era).defensive() {
					pool.balance = *slashed_balance;
					Self::deposit_event(Event::<T>::UnbondingPoolSlashed {
						era: *era,
						pool_id,
						balance: *slashed_balance,
					});
				}
			});
			SubPoolsStorage::<T>::insert(pool_id, sub_pools);
		} else if !slashed_unlocking.is_empty() {
			defensive!("Expected SubPools were not found");
		}
		Self::deposit_event(Event::<T>::PoolSlashed { pool_id, balance: slashed_bonded });
	}

	// A slash that targets an unbonding era must be applied to that era's own `with_era` bucket.
	// When the effective post-unbonding window widens (e.g. the bonding duration is lowered), eras
	// that a narrower window would have merged into `no_era` are instead retained, so the slash is
	// routed to the correct per-era bucket rather than being dropped or applied to the wrong pool.
	#[test]
	fn slash_lands_in_correct_bucket_after_window_widens() {
		use sp_staking::OnStakingUpdate;

		// We hand-craft `SubPoolsStorage` to exercise the slash-routing logic in isolation, which
		// would otherwise desync the TVL bookkeeping that `do_try_state` validates.
		ExtBuilder::default().with_check(0).build_and_execute(|| {
			assert_eq!(<Runtime as Config>::MaxUnbondingPools::get(), 5);

			// Unbonding sub-pools spanning eras 1..=4, each with a 10/10 points-to-balance ratio.
			let new_pools = || SubPools::<Runtime> {
				no_era: UnbondPool::<Runtime>::default(),
				with_era: unbonding_pools_with_era! {
					1 => UnbondPool::<Runtime> { points: 10, balance: 10 },
					2 => UnbondPool::<Runtime> { points: 10, balance: 10 },
					3 => UnbondPool::<Runtime> { points: 10, balance: 10 },
					4 => UnbondPool::<Runtime> { points: 10, balance: 10 },
				},
			};

			// With bonding duration 3 the effective window is `5 - 3 = 2`: at era 4, eras <= 2 are
			// merged into `no_era`, so era 1 no longer has its own bucket...
			BondingDuration::set(3);
			assert!(new_pools().maybe_merge_pools(4).with_era.get(&1).is_none());

			// ...but lowering the bonding duration to 1 widens the window to `5 - 1 = 4`: at era 4
			// only era <= 0 is merged, so era 1 keeps its own bucket.
			BondingDuration::set(1);
			let widened = new_pools().maybe_merge_pools(4);
			assert_eq!(widened.with_era.keys().copied().collect::<Vec<_>>(), vec![1, 2, 3, 4]);
			SubPoolsStorage::<Runtime>::insert(1, widened);

			let _ = pool_events_since_last_call();

			// A slash that targets era 1 lands in era 1's bucket (reducing 10 -> 4), leaving the
			// other era buckets and `no_era` untouched.
			let slashed_unlocking: BTreeMap<EraIndex, Balance> = [(1, 4)].into_iter().collect();
			Pools::on_slash(&default_bonded_account(), 0, &slashed_unlocking, 6);

			let after = SubPoolsStorage::<Runtime>::get(1).unwrap();
			assert_eq!(after.with_era.get(&1).unwrap().balance, 4);
			assert_eq!(after.with_era.get(&2).unwrap().balance, 10);
			assert_eq!(after.with_era.get(&3).unwrap().balance, 10);
			assert_eq!(after.with_era.get(&4).unwrap().balance, 10);
			assert_eq!(after.no_era.balance, 0);
			assert_eq!(after.no_era.points, 0);

			assert_eq!(
				pool_events_since_last_call(),
				vec![
					Event::UnbondingPoolSlashed { pool_id: 1, era: 1, balance: 4 },
					Event::PoolSlashed { pool_id: 1, balance: 0 },
				]
			);
		});
	}
