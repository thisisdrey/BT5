### Title
Permanent loss of burned tip funds when `add_tip` targets an already-consumed or unknown Snowbridge message nonce - (File: `bridges/snowbridge/pallets/system-frontend/src/lib.rs`, `bridges/snowbridge/pallets/system-v2/src/lib.rs`)

### Summary
The external report's core broken invariant is that a value-bearing action (BTC delegation fee capture) is bound to a mutable, racy identifier without protecting the depositor from losing funds when the race is lost. The Snowbridge tip mechanism has the same class of defect but with a strictly worse outcome: the user's asset is irreversibly burned on the source chain *before* the destination chain confirms the tip can actually be applied to the target message nonce, and if the nonce has already been consumed (or the outbound order can't be found), the burned value is only recorded into a dead-end `LostTips` counter with no way to reclaim it anywhere in the codebase.

### Finding Description
`EthereumSystemFrontend::add_tip` at [1](#0-0)  is a public extrinsic callable by any signed account. It immediately swaps the caller's supplied asset for Ether and **burns it for teleport** via `swap_fee_asset_and_burn` → `burn_for_teleport::<T::AssetTransactor>` at [2](#0-1) , unconditionally destroying the user's funds on the local chain regardless of whether the tip will ever be successfully applied.

Only after the burn does the pallet dispatch an XCM `Transact` to BridgeHub calling `EthereumSystemV2::add_tip` [3](#0-2) , which attempts `InboundQueue::add_tip(nonce, amount)` or `OutboundQueue::add_tip(nonce, amount)`. The inbound implementation explicitly rejects tips for nonces that are already processed: [4](#0-3) . When this (or the outbound "unknown order" equivalent) fails, the burned amount is not refunded — it is merely tallied into `LostTips`: [5](#0-4)  and [6](#0-5) . The doc comment on `LostTips` even states recovery is only aspirational future work, and no code in the repository reads, drains, or refunds this map.

This is exactly the pattern the delegateBtc report describes — value capture bound to a racy, externally-observable identifier (the message nonce, whose "already processed" state is a function of relayer timing that any user can trivially lose) — except here existing guards (`ensure!(!Nonce::<T>::get(nonce), ...)`) correctly prevent double-tip application, but do nothing to prevent the antecedent fund destruction from being wasted. The `swap_and_burn`/`burn_for_teleport` step is irreversible and happens strictly before the destination-chain validity check, so there is no way to make the operation atomic across the XCM hop.

### Impact Explanation
This matches the "permanent user-fund or bridge-state lock" category in the impact gate. Any unprivileged user who calls `add_tip` for a nonce that gets processed (by an honest, non-malicious relayer racing normally, which is expected system behavior, not an attack) before the tip XCM lands on BridgeHub loses their swapped/burned Ether permanently, with only a non-actionable counter incremented. No malicious peer, relayer, validator, or governance action is required — this occurs under entirely honest, expected operation of the bridge due to inherent cross-chain message latency.

### Likelihood Explanation
High. Given normal Snowbridge relaying, inbound nonces are processed continuously by any of many permissionless relayers as soon as a valid proof is available, while the tip's own path involves an extra XCM hop from AssetHub to BridgeHub. Any user who tips a message that gets relayed in the interim — which is common, since relayers are incentivized to act quickly and a tip is often added moments before or after submission — will lose funds. No special conditions or race skill are needed; ordinary latency guarantees this happens periodically.

### Recommendation
Either (a) make the operation atomic by validating the tip target's outstanding/unconsumed status on the origin chain via a light-weight query before burning, (b) defer the burn until after the destination-chain pallet confirms nonce validity (e.g., hold/reserve locally and settle only on success acknowledgment), or (c) implement the promised recovery mechanism for `LostTips`, adding a signed extrinsic that lets the original `sender` reclaim (mint back) their lost tip amount from the same account that receives newly registered rewards, closing the dead-end that currently exists in `bridges/snowbridge/pallets/system-v2/src/lib.rs`.

### Proof of Concept
1. User calls `EthereumSystemFrontend::add_tip(origin, MessageId::Inbound(N), asset)` on AssetHub, where `N` is the nonce of an inbound message that has not yet been marked as relayed on BridgeHub.
2. `swap_fee_asset_and_burn` swaps `asset` for Ether and burns it for teleport — funds leave the user's balance immediately and irrevocably: [2](#0-1) .
3. Before the resulting XCM `Transact` reaches BridgeHub, any relayer submits the proof for nonce `N` via `InboundQueue::submit`, which calls `process_message` and marks the nonce consumed: [7](#0-6) .
4. The deferred `EthereumSystemV2::add_tip` call executes on BridgeHub, calls `InboundQueue::add_tip(N, amount)`, which now returns `Err(AddTipError::NonceConsumed)` per [4](#0-3) .
5. `system-v2::add_tip` catches the error and only writes to `LostTips::<T>::mutate(&sender, ...)`: [6](#0-5) , confirmed by the integration test `tip_to_invalid_nonce_is_added_to_lost_tips` at [8](#0-7) , which explicitly asserts `relayer_lost_tip > 0` and never reclaims it.
6. The user's Ether remains burned with no extrinsic anywhere in the codebase to reclaim the `LostTips` balance — permanent fund loss.

		fn swap_fee_asset_and_burn(
			origin: Location,
			fee_asset: Asset,
		) -> Result<u128, DispatchError> {
			let ether_location = T::EthereumLocation::get();
			let (fee_asset_location, fee_amount) = match fee_asset {
				Asset { id: AssetId(ref loc), fun: Fungible(amount) } => (loc, amount),
				_ => {
					tracing::debug!(target: LOG_TARGET, ?fee_asset, "error matching fee asset");
					return Err(Error::<T>::UnsupportedAsset.into());
				},
			};
			if fee_amount == 0 {
				return Ok(0);
			}

			let ether_gained = if *fee_asset_location != ether_location {
				Self::swap_and_burn(
					origin.clone(),
					fee_asset_location.clone(),
					ether_location,
					fee_amount,
				)
				.inspect_err(|&e| {
					tracing::debug!(target: LOG_TARGET, ?e, "error swapping asset");
				})?
			} else {
				burn_for_teleport::<T::AssetTransactor>(&origin, &fee_asset)
					.map_err(|_| Error::<T>::BurnError)?;
				fee_amount
			};
			Ok(ether_gained)
		}

			origin: OriginFor<T>,
			sender: AccountIdOf<T>,
			message_id: MessageId,
			amount: u128,
		) -> DispatchResult {
			T::FrontendOrigin::ensure_origin(origin)?;

			let result = match message_id {
				Inbound(nonce) => <T as pallet::Config>::InboundQueue::add_tip(nonce, amount),
				Outbound(nonce) => <T as pallet::Config>::OutboundQueue::add_tip(nonce, amount),
			};

			if let Err(ref e) = result {
				tracing::debug!(target: LOG_TARGET, ?e, ?message_id, ?amount, "error adding tip");
				LostTips::<T>::mutate(&sender, |lost_tip| {
					*lost_tip = lost_tip.saturating_add(amount);
				});
			}

			Self::deposit_event(Event::<T>::TipProcessed {
				sender,
				message_id,
				amount,
				success: result.is_ok(),
			});

			Ok(())
		}

	impl<T: Config> Pallet<T> {
		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}
