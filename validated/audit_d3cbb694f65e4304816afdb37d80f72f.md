#No Vulnerability found for this question.

**Rationale:** The premise that an attacker could embed a spoofed `END_FLASHLOAN` discriminator "inside a larger, unrelated instruction's data" to fool `check_flashloan_can_start` while the runtime actually executes something else does not hold on Solana. The `sysvar_ixs` account inspected via `load_instruction_at_checked` reflects the actual, already-serialized instructions of the transaction that the runtime will execute — there is no mechanism for the introspection sysvar to diverge from what is actually dispatched.

`check_flashloan_can_start` requires three things to all hold simultaneously: the 8-byte discriminator at `unchecked_end_fl_ix.data[..8]` must equal `END_FLASHLOAN`, `unchecked_end_fl_ix.program_id` must equal `crate::ID` (the marginfi program itself), and `accounts[0]` must equal the calling `marginfi_account` key [1](#0-0) . Because Anchor's on-chain instruction dispatcher routes strictly by matching the leading 8-byte discriminator against each handler's `Hashable::get_hash()` value, any instruction whose data begins with the `END_FLASHLOAN` bytes `[105, 124, 201, 106, 153, 2, 8, 156]` and is addressed to `crate::ID` (marginfi program) will, when actually invoked, be dispatched to the genuine `lending_account_end_flashloan` handler — not some other "unrelated instruction" — because that is precisely how the discriminator is defined and consumed [2](#0-1) [3](#0-2) . There is no code path where the on-chain runtime executes a different function while the instructions sysvar reports an `END_FLASHLOAN`-prefixed data blob for the same program id — the sysvar content and actual execution are the same serialized data.

Existing regression tests already exercise the adjacent bypass angles (wrong order, wrong target account) and confirm `IllegalFlashloan` is correctly raised: `flashloan_fail_invalid_end_fl_order` and `flashloan_fail_invalid_end_fl_different_m_account` [4](#0-3) . Additionally, `lending_account_end_flashloan` itself unconditionally clears `ACCOUNT_IN_FLASHLOAN` and calls `check_account_init_health` on execution [5](#0-4) , so even if such a "crafted" instruction were somehow accepted by the pre-flight introspection check, its actual invocation (being the real handler) would still perform the health check — there is no divergence between the introspected instruction and the executed one that could be exploited to skip `check_account_init_health`.

pub fn lending_account_end_flashloan<'info>(
    ctx: Context<'info, LendingAccountEndFlashloan<'info>>,
) -> MarginfiResult<()> {
    validate_not_cpi_by_stack_height()?;

    let mut marginfi_account = ctx.accounts.marginfi_account.load_mut()?;

    marginfi_account.unset_flag(ACCOUNT_IN_FLASHLOAN, false);

    check_account_init_health(&marginfi_account, ctx.remaining_accounts, &mut None)?;

    Ok(())
}

#[tokio::test]
async fn flashloan_fail_invalid_end_fl_order() -> anyhow::Result<()> {
    // Setup test executor with non-admin payer
    let test_f = TestFixture::new(Some(TestSettings::all_banks_payer_not_admin())).await;

    let sol_bank = test_f.get_bank(&BankMint::Sol);

    // Fund SOL lender
    let lender_mfi_account_f = test_f.create_marginfi_account().await;
    let lender_token_account_f_sol = test_f
        .sol_mint
        .create_token_account_and_mint_to(1_000)
        .await;
    lender_mfi_account_f
        .try_bank_deposit(lender_token_account_f_sol.key, sol_bank, 1_000, None)
        .await?;

    // Fund SOL borrower
    let borrower_mfi_account_f = test_f.create_marginfi_account().await;

    let borrower_token_account_f_sol = test_f.sol_mint.create_empty_token_account().await;
    // Borrow SOL

    let borrow_ix = borrower_mfi_account_f
        .make_bank_borrow_ix(borrower_token_account_f_sol.key, sol_bank, 1_000)
        .await;

    let mut ixs = vec![borrow_ix];

    let start_ix = borrower_mfi_account_f
        .make_lending_account_start_flashloan_ix(0)
        .await;

    let end_ix = borrower_mfi_account_f
        .make_lending_account_end_flashloan_ix(vec![], vec![])
        .await;

    ixs.insert(0, start_ix);
    ixs.insert(0, end_ix);

    let ctx = test_f.context.borrow_mut();

    let tx = Transaction::new_signed_with_payer(
        &ixs,
        Some(&ctx.payer.pubkey().clone()),
        &[&ctx.payer],
        ctx.banks_client.get_latest_blockhash().await.unwrap(),
    );

    let res = ctx.banks_client.process_transaction(tx).await;

    assert_custom_error!(res.unwrap_err(), MarginfiError::IllegalFlashloan);

    Ok(())
}
