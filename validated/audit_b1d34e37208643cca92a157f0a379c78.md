### Title
Unauthenticated remote DoS via `POST /shutdown` on signer event-listener - (File: libsigner/src/events.rs)

### Summary
The `SignerEventReceiver::next_event` HTTP dispatcher in `libsigner/src/events.rs` handles `/shutdown` by immediately setting the stop flag and returning `EventError::Terminated`, with no secret, token, or peer-identity check of any kind. Any TCP client that can reach the bound listener address can send a single bare `POST /shutdown` request and permanently terminate the signer's event receiver loop.

### Finding Description
In `SignerEventReceiver::next_event` [1](#0-0) , the request dispatch checks `request.url()` against known routes. For `/status`, `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block`, the body is deserialized via `process_event` (JSON parse from the node), but none of these branches, nor `/shutdown`, verify any authentication token, HMAC, or shared secret. The `/shutdown` branch is:
```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
``` [2](#0-1) 
This is the exact same mechanism used internally by `SignerStopSignaler::send`, which crafts a raw HTTP request `POST /shutdown HTTP/1.1 ... Content-Length: ... \r\n\r\n<body>` over a plain `TcpStream` [3](#0-2) . There is no comparison against `auth_password`/`auth_token` anywhere in this dispatch path — that secret is only used for the node's own RPC endpoints (e.g., block-proposal validation), not for this signer-local event listener. `main_loop` treats `EventError::Terminated` as a clean break of the loop [4](#0-3) , permanently ending the signer's ability to receive `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events from its node, effectively taking that signer offline until manually restarted.

### Impact Explanation
Any remote party that can open a TCP connection to the signer's `endpoint` and send one crafted HTTP POST can permanently stop that signer's event-receiver thread, silently removing it from block-validation/signing participation until an operator restarts it. This matches the "Critical - remote crash/unauthenticated DoS from few messages" category since it takes exactly one unauthenticated message to kill the receiver loop, and this is fully repeatable against every restart.

### Likelihood Explanation
Reachability depends entirely on operator configuration of the signer's `endpoint`. The shipped reference configs and docs explicitly show `endpoint = "0.0.0.0:30000"` as a valid/documented value (bind-all) alongside `127.0.0.1:30000` [5](#0-4) , and `docs/signing.md` likewise shows both `127.0.0.1:30000` (node-side observer) and `endpoint = "0.0.0.0:30000"` (signer-side listener) [6](#0-5) . Whenever an operator binds the listener to a non-loopback interface (e.g., to allow a separate host running the node to reach the signer, or a containerized deployment), the port becomes reachable by any remote unprivileged party with network access, requiring zero cost or credentials to exploit.

### Recommendation
Require the signer's `auth_password`/shared-secret to be validated on privileged endpoints (particularly `/shutdown`, and ideally all POST endpoints) before acting on the request, e.g. by checking an `Authorization` header against the configured secret in `next_event` before dispatching to any handler, matching the pattern already used for the node's RPC `auth_token`.

### Proof of Concept
Rust test plan (added under `libsigner/src/events.rs` tests or a new integration test):
1. Construct a `SignerEventReceiver::<T>::new(false)`, `bind()` it to `127.0.0.1:0` to get an ephemeral port, spawn `main_loop()` in a thread with a consumer channel attached via `add_consumer`.
2. From a separate `TcpStream::connect` (simulating an unprivileged remote attacker, no secret), send the raw bytes:
   `POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1:PORT\r\nConnection: close\r\nContent-Length: 4\r\nContent-Type: text/plain\r\n\r\ntest`
3. Assert that `event_receiver.is_stopped()` becomes `true` shortly after, and that the spawned `main_loop` thread joins/exits (proving the loop terminated), with no `auth_password`/token ever sent in the request — reproducing the exact crash/DoS with a single unauthenticated message via the `else if request.url() == "/shutdown"` branch at `libsigner/src/events.rs:443-445`.
