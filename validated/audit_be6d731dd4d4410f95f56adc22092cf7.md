### Title
Dust issuance bypasses issue fees through half-up rounding - (File: contracts/DebtToken.sol)

### Summary
`DebtToken.issue()` prices issuance fees through `quoteIssueOut()`, which calculates `amount_.wadMul(issueFee)`. Because `wadMul()` rounds half-up rather than always rounding in the protocol’s favor, a one-base-unit issuance produces zero fee for any configured issue fee below 50%, including the 25% maximum. An unprivileged user can therefore issue debt in dust increments and receive one synthetic-token unit for each unit of debt while paying no issuance fee.

### Finding Description
`WadRayMath.wadMul()` computes `(a * b + 0.5e18) / 1e18`, so `wadMul(1, 0.25e18)` evaluates to zero. [1](#0-0)  `FeeProvider` permits issue fees up to `MAX_FEE_VALUE = 0.25e18`. [2](#0-1) [3](#0-2) 

`issue()` checks only that `amount_ != 0`, verifies the resulting debt remains collateralized, records `amount_` as debt, and then mints `amount_ - _fee` to the borrower. [4](#0-3) [5](#0-4) [6](#0-5) 

If `debtFloorInUsd` is nonzero, the attacker first opens a floor-compliant position; once total debt is at least the floor, subsequent one-unit mints pass the floor check because `_balanceBefore + amount_` remains above it. [7](#0-6) 

### Impact Explanation
The fee-accrual invariant breaks: `N` separate `issue(1, attacker)` calls create `N` debt units and mint `N` synthetic units to the attacker, while the configured `issueFee` collects nothing. In contrast, a single `issue(N, attacker)` call mints only approximately `N * (1 - issueFee)` to the borrower and mints the remainder to `feeCollector`. This is direct theft of protocol issuance fees; the avoidable value is bounded to less than one-half base unit per call, so materiality is greatest for lower-decimal synthetic assets or when calls are batched.

### Likelihood Explanation
The path is reachable by any externally owned account with sufficient collateral headroom because `issue()` is public and has no privileged caller requirement. Execution is constrained by collateralization, synthetic-token supply caps, the debt floor bootstrap, and transaction-call overhead, but none of those controls restore the skipped fee once dust issuance is used. [8](#0-7) 

### Recommendation
Round every protocol fee in the protocol’s favor. For `quoteIssueOut()`, replace `amount_.wadMul(_issueFee)` with `Math.mulDiv(amount_, _issueFee, 1e18, Math.Rounding.Up)` and reject issuance when the calculated net amount is zero. Audit the paired quote functions and the deposit, withdrawal, repay, liquidation, and swap quote paths so gross-input quotes use ceiling division/multiplication where necessary and net-output quotes never round value toward the caller.

### Proof of Concept
The following Hardhat test demonstrates the accounting difference on a fork with `issueFee = 0.25e18`:

```ts
import { expect } from "chai";

it("bypasses issue fees through one-unit issuance", async () => {
  // Deployed or fixture contracts:
  // pool, depositToken, syntheticToken, debtToken, feeProvider, masterOracle.
  //
  // Preconditions:
  // - attacker has supplied enough collateral for `rounds + bootstrapDebt`;
  // - issueFee > 0, e.g. 0.25e18;
  // - syntheticToken and debtToken are active;
  // - if debtFloorInUsd > 0, attacker first issues a floor-compliant amount.

  const issueFee = await feeProvider.issueFee();
  expect(issueFee).to.be.gt(0);

  const quote = await debtToken.quoteIssueOut(1);
  expect(quote._fee).to.equal(0);
  expect(quote._amountToIssue).to.equal(1);

  const rounds = 1_000;
  const synthBefore = await syntheticToken.balanceOf(attacker.address);
  const feesBefore = await syntheticToken.balanceOf(feeCollector.address);

  for (let i = 0; i < rounds; ++i) {
    await debtToken.connect(attacker).issue(1, attacker.address);
  }

  expect(await debtToken.balanceOf(attacker.address)).to.equal(rounds);
  expect(await syntheticToken.balanceOf(attacker.address)).to.equal(
    synthBefore.add(rounds)
  );
  expect(await syntheticToken.balanceOf(feeCollector.address)).to.equal(
    feesBefore
  );

  // A single gross issuance of `rounds` would instead return approximately:
  // fee     = rounds * issueFee / 1e18
  // issued  = rounds - fee
});
```

For `issueFee = 0.25e18`, `quoteIssueOut(1)` returns `(1, 0)` while `quoteIssueOut(1000)` returns `(750, 250)`, proving that the dust path mints 100% of each gross amount to the borrower and collects none of the configured fee.
