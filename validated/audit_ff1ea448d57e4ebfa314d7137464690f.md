Based on my investigation into the Go standard library's UDP/packet-receiving code paths (the closest analog to curl's `tftp_receive_packet()` heap overflow, which occurs because `recvfrom()` is called with a stale/default buffer length instead of the size actually allocated for a shrunk buffer), I found no matching primitive in this repository.

Key findings:
- `net.UDPConn.readFrom`/`readFromAddrPort` on POSIX always pass the caller-supplied slice `b` directly to `c.fd.readFromInet4`/`readFromInet6`, so the read length is always tied to `len(b)`, not a separately-tracked stale size. [1](#0-0) 
- The fake/plan9 backends similarly use `copy(b, ...)` semantics bounded by `len(b)`, which cannot write past the destination slice regardless of the source packet size. [2](#0-1) [3](#0-2) 
- The DNS resolver's UDP round trip (`dnsPacketRoundTrip`), which is the most similar untrusted-server-response-over-UDP code path in `net/dnsclient_unix.go`, allocates a single fixed `maxDNSPacketSize` buffer per call and reads into it with `c.Read(b)`; there is no code path where a smaller custom buffer is allocated and then a `recvfrom`/`Read` call defaults back to a larger size. [4](#0-3) 

The TFTP CVE's root cause is a state bug where a custom (smaller) `BLKSIZE` is negotiated and the buffer is allocated to that size, but a fallback/default size is used for the actual `recvfrom()` call, causing a write past the allocated buffer. Go's `net` package UDP/DNS read paths don't have an analogous split between "buffer allocation size" and "read syscall size" — the read length is always derived directly from the slice passed in, so there's no reachable heap overflow of this shape in the inspected files.

func (c *UDPConn) readFrom(b []byte, addr *UDPAddr) (int, *UDPAddr, error) {
	buf := make([]byte, udpHeaderSize+len(b))
	m, err := c.fd.Read(buf)
	if err != nil {
		return 0, nil, err
	}
	if m < udpHeaderSize {
		return 0, nil, errors.New("short read reading UDP header")
	}
	buf = buf[:m]

	h, buf := unmarshalUDPHeader(buf)
	n := copy(b, buf)
	*addr = UDPAddr{IP: h.raddr, Port: int(h.rport)}
	return n, addr, nil

func dnsPacketRoundTrip(c Conn, id uint16, query dnsmessage.Question, b []byte) (dnsmessage.Parser, dnsmessage.Header, error) {
	if _, err := c.Write(b); err != nil {
		return dnsmessage.Parser{}, dnsmessage.Header{}, err
	}

	b = make([]byte, maxDNSPacketSize)
	for {
		n, err := c.Read(b)
		if err != nil {
			return dnsmessage.Parser{}, dnsmessage.Header{}, err
		}
		var p dnsmessage.Parser
		// Ignore invalid responses as they may be malicious
		// forgery attempts. Instead continue waiting until
		// timeout. See golang.org/issue/13281.
		h, err := p.Start(b[:n])
		if err != nil {
			continue
		}
		q, err := p.Question()
		if err != nil || !checkResponse(id, query, h, q) {
			continue
		}
		return p, h, nil
	}
