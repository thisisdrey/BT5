### Title
Deactivated DebtToken can still issue synthetic assets via `issue()` - (File: contracts/DebtToken.sol)

### Summary
`DebtToken.issue()` omits the `onlyIfDebtTokenIsActive` modifier that all sibling issuance paths (`mint`, `flashIssue`) enforce. After the governor deactivates a debt token — the protocol's intended kill-switch for a risky or deprecated synth market — any user can keep opening new debt positions and minting the synthetic asset, defeating the purpose of deactivation.

### Finding Description
`DebtToken` exposes an `isActive` flag and a `toggleIsActive`-style admin control (event `DebtTokenActiveUpdated`, contracts/DebtToken.sol:61). Three functions mutate debt state:

- `mint(...)` — guarded by `onlyIfDebtTokenIsActive` via the modifier at contracts/DebtToken.sol:97-99 (see usage at contracts/DebtToken.sol:334-338).
- `flashIssue(...)` — guarded by `onlyIfDebtTokenIsActive` (contracts/DebtToken.sol:287-291).
- `issue(uint256 amount_, address to_)` — the primary user-facing borrow entry point — is guarded only by `whenNotShutdown`, `nonReentrant`, and `onlyIfSyntheticTokenExists` (contracts/DebtToken.sol:235-244). The `onlyIfDebtTokenIsActive` modifier exists in the same file but is simply not applied here.

The `onlyIfSyntheticTokenExists` check only verifies the synth is still registered in the pool's token list (`pool.doesSyntheticTokenExist`), not that this debt token is active. So after governance sets `isActive = false` on the DebtToken — e.g., to wind down a market or respond to an incident — `issue()` continues to:

1. Call `pool.debtPositionOf(msg.sender)` and check collateral sufficiency against the oracle (contracts/DebtToken.sol:254-260).
2. Mint debt principal to the borrower via `_mint` (contracts/DebtToken.sol:262).
3. Mint the issue fee to `feeCollector` and the net synths to `to_` (contracts/DebtToken.sol:264-268).

Deactivation only blocks the SmartFarmingManager paths (`mint`/`flashIssue`), which revert with `DebtTokenInactive`, while the direct borrow path remains fully open.

### Impact Explanation
The deactivation invariant is broken: governance's emergency/wind-down control over a synthetic market does not stop new issuance. An unprivileged borrower can keep creating new debt positions in a market the protocol deliberately shut off — accumulating under-collateralization risk in a deprecated or compromised synth (e.g., after an oracle or collateral issue prompted the deactivation). This converts the intended liveness control into a solvency risk, since supply-cap and collateral checks still permit issuance up to `maxTotalSupply` as long as the position is healthy.

### Likelihood Explanation
Likelihood is conditional on governance deactivating a debt token while its synthetic token remains active and registered — a realistic operational state (deactivating the borrow market without delisting the synth, which would break repayments/liquidations). Once in that state, any EOA with sufficient collateral can call `issue()` permissionlessly; no privileged role, front-running, or oracle manipulation is required. Notably, `_mint` inside `issue` enforces `maxTotalSupply` but not `isActive`.

### Recommendation
Add `onlyIfDebtTokenIsActive` (and, for consistency, `onlyIfSyntheticTokenIsActive`, since `mint` has it) to `DebtToken.issue()` so that every debt-creation path respects the deactivation flag:

```solidity
function issue(
    uint256 amount_,
    address to_
)
    external
    override
    whenNotShutdown
    nonReentrant
    onlyIfSyntheticTokenExists
    onlyIfDebtTokenIsActive
    returns (uint256 _issued, uint256 _fee)
```

### Proof of Concept
Hardhat fork test sketch:

```ts
it("still issues after debt token is deactivated", async () => {
  // setup: user deposits collateral in Pool so debtPositionOf gives issuableInUsd > 0
  await depositToken.connect(alice).deposit(amount);
  await pool.connect(alice).deposit(...);          // per deployed flow

  // governor deactivates the debt token
  await debtToken.connect(governor).toggleIsActive();
  expect(await debtToken.isActive()).to.eq(false);

  // privileged paths now revert
  await expect(
    debtToken.connect(sfm).mint(alice.address, parseEther("1"))
  ).to.be.revertedWithCustomError(debtToken, "DebtTokenInactive");

  // ...but direct issuance still succeeds
  const before = await syntheticToken.balanceOf(alice.address);
  await debtToken.connect(alice).issue(parseEther("100"), alice.address);
  expect(await syntheticToken.balanceOf(alice.address)).to.be.gt(before);
  expect(await debtToken.balanceOf(alice.address)).to.be.gt(0);
});
```

Caveat: the exact call sequence for depositing collateral depends on the deployed `Pool`/`DepositToken` entry points, and `toggleIsActive` naming should be confirmed against the deployed ABI — I was unable to read the remainder of `DebtToken.sol` (lines beyond ~450) or `Pool.sol`'s function-level checks within the available search iterations. The core defect — the missing `onlyIfDebtTokenIsActive` modifier on `issue` while `mint` and `flashIssue` both have it — is directly visible in the source.
