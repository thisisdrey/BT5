Audit Report

## Title
Native value sent to stateless "pure" precompiles is permanently locked with no return path - (File: `substrate/frame/revive/src/exec.rs`)

## Summary
`Stack::call`/`new_frame` in `pallet-revive` unconditionally calls `Self::transfer_from_origin(...)` for every non-delegate call — including calls to "pure" precompiles that have `HAS_CONTRACT_INFO = false` and only implement the stateless `Precompile::call` entry point, which cannot move, forward, or reject `msg.value`. As a result, any native value sent to fixed precompile addresses (e.g., ECRecover, Sha256, Identity, etc.) is transferred into a fallback account derived only from the address bytes, with no mechanism in the codebase to withdraw it back to the sender.

## Finding Description
`Precompile::call` (the entry point used when `HAS_CONTRACT_INFO = false`) receives only `input`/`env: &mut impl Ext` and returns ABI-encoded bytes; per the trait documentation, when `HAS_CONTRACT_INFO` is false "No account or any other state will be created for the address" and "Only `call` should be implemented" [1](#0-0) , giving this entry point no ability to consume, forward, or reject incoming value.

Despite this, in `Stack::new_frame`, the balance transfer is performed unconditionally for any non-delegate call before the code checks whether the callee is a precompile at all: [2](#0-1) 

The subsequent account/consumer bookkeeping block only runs `if precompile.has_contract_info()`, meaning for pure precompiles no account is minted/registered even though the value transfer already succeeded moments earlier: [3](#0-2) 

The destination account for calls to any precompile address (pure or stateful) is resolved via a stateless, address-derived fallback account rather than a normal keyed account: [4](#0-3) 

This fallback account has no owning private key and no contract logic, so nothing in the repository allows withdrawing balance from it back to a caller. This is confirmed by the existing test that intentionally checks this locking behavior as expected: after calling `ECRecover`/`Sha256`/`Identity` with `value = 100`, `Pallet::<Test>::evm_balance(&precompile_addr)` becomes `100` [5](#0-4) .

## Impact Explanation
This matches the "permanent user-fund lock" impact category from the gate. Any unprivileged EOA or contract call — including standard EVM tooling patterns such as `.call{value: x}(...)` targeting a fixed precompile address (1–9, or custom pre-compiles like `System`) — results in native value being irrecoverably locked in a fallback account that no logic can spend, refund, or forward. The exact corrupted/stuck value is the native balance held at `T::AddressMapper::to_fallback_account_id(dest_addr)` for the targeted pure precompile address, which becomes permanently inaccessible once transferred.

## Likelihood Explanation
Likelihood is non-trivial and requires no privileged access, front-running, or malicious peer/relayer assumptions — a single naive or mistaken transaction attaching non-zero `value` to a precompile call (e.g., low-numbered addresses commonly referenced in raw EVM bytecode or naively-generated tooling calls) is sufficient. This is reachable purely through public extrinsics/`eth_call`/`bare_call` paths exposed to any unprivileged caller.

## Recommendation
In `Stack::new_frame`/`Stack::call`, resolve whether the callee is a precompile and, if so, whether `HAS_CONTRACT_INFO` is `false` (a "pure" precompile), prior to calling `transfer_from_origin`. If the callee is a pure precompile and `value` is non-zero, reject the call with an explicit error (e.g. `Error::<T>::TransferToPurePrecompileNotAllowed`) instead of completing the transfer into the unusable fallback account.

## Proof of Concept
1. Deploy a contract or use `bare_call`/`eth_call` targeting a fixed pure precompile address, e.g. `H160::from_low_u64_be(2)` (`Sha256`).
2. Issue a call with `value = 100` and valid `Sha256` input, matching the existing test pattern in `substrate/frame/revive/src/tests/pvm.rs` lines 4751-4774.
3. Observe the call succeeds, returns the expected digest, and `Pallet::<Test>::evm_balance(&precompile_addr)` equals `100`.
4. No dispatchable, precompile function, or governance call exists in the repository to move balance out of this fallback account back to the original sender — the value is permanently stuck.
