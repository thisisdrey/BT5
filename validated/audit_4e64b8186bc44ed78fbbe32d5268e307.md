### No vulnerability found for this question.

**Reasoning:**

The target file, `contracts/wallet/signatures/no-sign/src/contract.rs`, only exposes `Contract::w_init`, a `#[private]` `#[init]` method callable exclusively by the account itself <cite repo="Kohvert/intents--025" path="contracts/wallet/signatures/no-sign/src/contract.rs" start="28="33" end="49" />. There is no nonce-related entrypoint here at all.

Nonce rotation/commit logic lives in `contracts/wallet/src/nonces.rs` (`Nonces::commit` / `Nonces::check_cleanup`) and is reachable only via `WalletImpl::execute_signed` or `WalletImpl::execute_extension` in `contracts/wallet/src/contract.rs` <cite repo="Kohvert/intents--025" path="contracts/wallet/src/contract.rs" start="169="222" />. For the `NoSign` schema:

- `execute_signed` checks `self.0.is_signature_allowed()` **before** touching `nonces.commit()`, and `w_init` permanently sets `s.signature_enabled = false` <cite repo="Kohvert/intents--025" path="contracts/wallet/signatures/no-sign/src/contract.rs" start="43="46" />, so this path errors out (`Error::SignatureDisabled`) before any nonce state is ever mutated <cite repo="Kohvert/intents--025" path="contracts/wallet/src/contract.rs" start="169="172" />. Even if that check were bypassed, `NoSign::verify_request_msg` unconditionally returns `false` <cite repo="Kohvert/intents--025" path="contracts/wallet/signatures/no-sign/src/lib.rs" start="21="28" />, so the whole call reverts and no nonce-rotation state change is persisted.
- `execute_extension` requires the caller (`env::predecessor_account_id()`) to be an enabled extension <cite repo="Kohvert/intents--025" path="contracts/wallet/src/contract.rs" start="208="221" />, and `w_init` sets the extension list to `[env::current_account_id()]` only <cite repo="Kohvert/intents--025" path="contracts/wallet/signatures/no-sign/src/contract.rs" start="39="41" />, i.e. only the wallet itself (self-calls), which the README explicitly states are disallowed for promises. An unprivileged outside attacker cannot become an extension or call this method.

Therefore, no attacker-reachable path in this file can invoke `Nonces::check_cleanup`/`commit` at all.

Separately, even where `check_cleanup` is reachable (other wallet variants), rotation is strictly gated by real elapsed wall-clock time — `self.last_cleaned_at < now - self.timeout` for rotating `current`→`old`, and `self.last_cleaned_at < now - 2*self.timeout` for clearing `old` <cite repo="Kohvert/intents--025" path="contracts/wallet/src/nonces.rs" start="137="153" />. Calling the trigger earlier does not make the underlying time condition true sooner; a nonce can only be evicted from `old` after `2*timeout` has genuinely elapsed, which exceeds any request's maximum validity window of `created_at + min(timeout, msg.timeout) ≤ created_at + timeout` <cite repo="Kohvert/intents--025" path="contracts/wallet/src/contract.rs" start="192="195" />. So the claimed "attacker forces early discard of an in-flight nonce" binding does not hold even in the reachable wallet variants, and is entirely inapplicable to the no-sign `Contract` targeted by this question.
