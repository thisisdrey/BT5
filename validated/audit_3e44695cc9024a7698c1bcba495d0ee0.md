### Title
Frozen CoinStore with Zero Balance Bypasses Freeze Propagation on Migration — (`aptos-move/framework/aptos-framework/sources/coin.move`)

### Summary

`maybe_convert_to_fungible_store` only propagates the `frozen` flag to the primary fungible store inside the branch guarded by `coin.value > 0`. When a frozen CoinStore holds a zero balance, execution falls into the `else` branch, which only calls `destroy_zero(coin)` and returns — the frozen flag is never written to any fungible store. The CoinStore is destroyed, leaving the account with no frozen store at all. Any subsequent deposit creates a fresh, unfrozen primary fungible store, fully bypassing the freeze.

### Finding Description [1](#0-0) 

The outer branch condition at line 676 is `is_coin_initialized<CoinType>() && coin.value > 0`. When `coin.value == 0`, the entire body — including the frozen-flag sync at lines 712–714 — is skipped. The `else` at line 715 only calls `destroy_zero(coin)`. [2](#0-1) 

The frozen-flag propagation: [3](#0-2) 

is unreachable for the zero-balance case. Note also that the inner `if (coin.value == 0)` at line 698 is dead code — it can never be true inside a block already guarded by `coin.value > 0`.

The entry point is fully public and requires only the account's own signer: [4](#0-3) 

There is no frozen-state check on `migrate_to_fungible_store` itself, so a frozen account can call it freely.

The formal spec for `maybe_convert_to_fungible_store` is disabled (`pragma verify = false`), so this invariant violation is not caught by the prover: [5](#0-4) 

### Impact Explanation

A coin issuer (or the Aptos framework for APT) freezes an account to prevent transfers — for compliance, sanctions, or security reasons. After the freeze, if the account's coin balance is zero (either frozen at zero, or burned to zero by the issuer), the account owner can call `migrate_to_fungible_store`. The frozen CoinStore is destroyed without propagating `frozen = true` to any fungible store. The next deposit to the account (from any sender) triggers `ensure_primary_store_exists`, creating a fresh unfrozen primary fungible store. The account can then withdraw and transfer freely, defeating the freeze entirely.

`set_frozen_flag_internal` correctly sets the frozen flag on a fungible store: [6](#0-5) 

But it is never called in the zero-balance migration path.

### Likelihood Explanation

The precondition — a frozen CoinStore with zero balance — is reachable in at least two ways without any attacker privilege:

1. The issuer freezes an account that already has zero balance.
2. The issuer burns the account's balance to zero after freezing (the burn capability permits burning from a frozen store).

Once in that state, the account owner needs only to submit a single `migrate_to_fungible_store` transaction, which is a standard public entry function with no additional guards.

### Recommendation

Move the frozen-flag propagation outside the `coin.value > 0` branch so it executes unconditionally whenever a CoinStore is destroyed. Specifically, `ensure_paired_metadata` and `ensure_primary_store_exists` must be called even for the zero-balance case, and `set_frozen_flag_internal` must be applied if `frozen == true`. The corrected structure should be:

```move
} else {
    // zero-balance path
    destroy_zero(coin);
    // Still propagate frozen flag if coin type is initialized
    if (is_coin_initialized<CoinType>()) {
        let metadata = ensure_paired_metadata<CoinType>();
        let store = primary_fungible_store::ensure_primary_store_exists(account, metadata);
        if (frozen != fungible_asset::is_frozen(store)) {
            fungible_asset::set_frozen_flag_internal(store, frozen);
        }
    }
};
```

fun test_frozen_bypass_via_zero_balance_migration(
    framework: signer, victim: signer
) acquires CoinStore, CoinConversionMap, CoinInfo, PairedCoinType, PairedFungibleAssetRefs {
    // Setup
    account::create_account_for_test(signer::address_of(&framework));
    account::create_account_for_test(signer::address_of(&victim));
    let victim_addr = signer::address_of(&victim);

    let (burn_cap, freeze_cap, mint_cap) =
        initialize_and_register_fake_money(&framework, 6, true);

    // Victim registers and starts with 0 balance
    register<FakeMoney>(&victim);
    assert!(coin_balance<FakeMoney>(victim_addr) == 0, 0);

    // Issuer freezes the victim's CoinStore while balance is 0
    freeze_coin_store<FakeMoney>(victim_addr, &freeze_cap);
    assert!(is_coin_store_frozen<FakeMoney>(victim_addr), 1);

    // Victim migrates — frozen flag is NOT propagated (the bug)
    migrate_to_fungible_store<FakeMoney>(&victim);

    // No CoinStore remains
    assert!(!exists<CoinStore<FakeMoney>>(victim_addr), 2);

    // Primary fungible store now exists (created by migration or next deposit)
    let metadata = ensure_paired_metadata<FakeMoney>();
    // Deposit creates an unfrozen primary store
    let coins = mint<FakeMoney>(100, &mint_cap);
    deposit(victim_addr, coins);

    // Assert: primary fungible store is NOT frozen — freeze was bypassed
    let pfs = primary_fungible_store::primary_store(victim_addr, metadata);
    assert!(!fungible_asset::is_frozen(pfs), 3); // passes — BUG confirmed

    // Victim can now withdraw freely despite having been frozen
    let withdrawn = withdraw<FakeMoney>(&victim, 50);
    burn(withdrawn, &burn_cap);

    move_to(&framework, FakeMoneyCapabilities { burn_cap, freeze_cap, mint_cap });
}
