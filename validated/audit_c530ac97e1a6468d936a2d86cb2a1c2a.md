### Title
Nep245/Imt TokenDiff fee is bypassable by splitting a single delta into unit (-1) deltas - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` waives fees for Nep245 (and Imt) tokens whenever the per-intent `|delta|` is `<= 1`, and the fee is computed independently for each `TokenDiff` intent rather than being aggregated per token across the batch or across transactions. An unprivileged signer can therefore split a negative delta of magnitude `N` into `N` separate `TokenDiff` intents of `delta = -1` and pay zero protocol fee, whereas a single intent with `delta = -N` (N>1) pays `Pips::fee_ceil` on the full amount.

### Finding Description
The binding claimed to hold is:
`fees_collected[T] == Σ over batch of Pips::fee_ceil(protocol_fee_applicable, |delta|)` for every negative delta on token `T`, **independent of how the net delta is split across intents**.

In reality, fee computation happens inside `TokenDiff::execute_intent`, once per `TokenDiff` intent, using only the deltas contained in *that* intent's `diff` map: [1](#0-0) 

The per-token fee rate itself is chosen by `TokenDiff::token_fee`, which explicitly zeroes the fee for `Nep245`/`Imt` tokens when the intent's own `amount <= 1`: [2](#0-1) 

Because the check uses the per-intent `amount = delta.unsigned_abs()` and not any batch- or account-aggregated total, submitting `delta = -2` in a single `TokenDiff` hits the `amount > 1` branch and pays `fee_ceil(2)` (nonzero when `protocol_fee > 0`), while submitting two `TokenDiff` intents each with `delta = -1` on the same `token_id` hits the `amount <= 1` branch twice, each contributing `Pips::ZERO`, for a total fee of `0`.

Nothing downstream re-aggregates or corrects this: `Engine::execute_signed_intent` calls `execute_intent` per intent and per signed payload with no fee reconciliation across the batch, and `TransferMatcher`/`finalize` only matches deposits/withdrawals to produce transfers — it never touches fees: [3](#0-2) [4](#0-3) 

Exploit flow: attacker (or a signer group) holding `>=2` balance of an Nep245 `token_id` submits `execute_intents` with `N` separate `TokenDiff` intents, each `diff = {token_id: -1}` (and matching positive out-deltas to satisfy the invariant), instead of one `TokenDiff` with `delta = -N`. Net balance change on the Verifier is identical, but the fee collected by `fee_collector` is strictly less (zero, in the all-`-1` case) than the single-intent path. No existing guard (`verify`, `has_public_key`, `verify_intent_nonce`, `commit_nonce`, `TransferMatcher::finalize`, `assert_one_yocto`) inspects or restricts the granularity of `TokenDiff` splitting, so this is fully reachable by an ordinary signer.

### Impact Explanation
Protocol fees on Nep245 (multi-token / semi-fungible) token trades can be systematically under-collected or fully avoided by splitting trade deltas into unit (`±1`) increments across multiple `TokenDiff` intents, which is explicitly listed as a Critical impact category ("protocol fees bypassed or over-collected"). This does not move funds out of victims' balances without authorization, but it deprives the `fee_collector` of revenue it is entitled to under the documented fee model, and the divergence is repeatable for any account and any Nep245/Imt token, scaling with the number of intents an attacker can pack into a batch/transaction.

### Likelihood Explanation
Preconditions are minimal: any signer with `>=2` balance of a Nep245 token_id and the ability to sign multiple `TokenDiff` intents (which is standard usage). No special role, relayer key, or DAO access is required — just constructing a batch of unit-delta `TokenDiff` intents instead of one larger-delta intent. This is trivially repeatable and requires no unusual gas/storage beyond normal batch execution costs.

### Recommendation
Aggregate the total negative delta per `token_id` across all `TokenDiff` intents within a signer's batch (or globally within `execute_intents`) before applying the `Nep245`/`Imt` "amount <= 1 waives fee" rule in `TokenDiff::token_fee`, so the fee-exemption threshold cannot be defeated by splitting a single logical trade into multiple unit-delta intents.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
