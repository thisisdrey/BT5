### Title
Missing self-reference check in `LinkRepositoryToObjectPool` allows a repository to be linked as its own object pool alternate - ([File: internal/git/objectpool/link.go])

### Summary
The `Link` function that backs the `LinkRepositoryToObjectPool` RPC never verifies that the target repository and the object pool repository are different. This is directly analogous to the reported `delegatee`/`currentDelegate` equality bug: a value that should never equal another related value is never checked for equality before being used to mutate state.

### Finding Description
`Link` (`internal/git/objectpool/link.go:28`) computes the relative path from the repository to the pool via `getRelativeObjectPath` [1](#0-0)  and writes it into `objects/info/alternates` without ever checking `pool` != `repo`: [2](#0-1) 

If `repository` (`req.GetRepository()`) and the pool's backing repository resolve to the same on-disk repository, `getRelativeObjectPath` computes `filepath.Rel(filepath.Join(repoPath, "objects"), poolPath)`, which for `repoPath == poolPath` yields `..`, producing an alternates entry `../objects` — the repository's own object directory referencing itself. `linkedToRepository` only guards against re-writing an already-correct alternates file; it does not reject a self-referential expected path either [3](#0-2) . `LinkRepositoryToObjectPool` (the gRPC handler) passes the caller-supplied `repository` straight through with no equality check against the pool: [4](#0-3) .

Notably, the codebase already recognizes this exact bug class as dangerous elsewhere: `partition_assigner.go`'s `getAlternatePartitionID` explicitly checks `alternateRelativePath == relativePath` and returns `storage.ErrAlternatePointsToSelf`, with the comment that a self-pointing alternate "would also cause a dead lock as the repository is locked during this call already" [5](#0-4) . That guard, however, lives only in the WAL/transaction partition-assignment code path (`storage.go`'s `ErrAlternatePointsToSelf`) [6](#0-5) , and is exercised only when a repository is first assigned a partition by reading an already-existing alternates file. It is not present in `internal/git/objectpool/link.go`'s `Link`/`getRelativeObjectPath`/`linkedToRepository`, which is the code path actually invoked by the `LinkRepositoryToObjectPool` RPC to write the alternates file in the first place.

### Impact Explanation
A self-referential `objects/info/alternates` entry is recognized by the codebase's own authors as capable of causing deadlocks (per the comment in `partition_assigner.go`) and is an invalid repository state that git tooling (`git-fsck`, `git gc`) does not expect. Depending on how the alternates recursion in `internal/git/dirs.go`'s `altObjectDirs` (which does defend against unbounded depth via `maxAlternatesDepth`) and downstream consumers of the alternates handle a self-loop, this can corrupt object resolution for the repository, produce repeated warnings/errors during git operations, or contribute to a denial-of-service on subsequent operations against that repository (e.g., disconnect/dissociate logic in `internal/git/objectpool/disconnect.go`, which assumes exactly one, distinct, valid alternate directory).

### Likelihood Explanation
`LinkRepositoryToObjectPool` is a Gitaly RPC that operates on caller-supplied `Repository` and `ObjectPool` proto messages; whether an ordinary/unprivileged caller can supply matching repository and pool locations depends on how `poolForRequest` resolves the pool argument (I was unable to fully inspect `internal/gitaly/service/objectpool/util.go`'s `poolForRequest` before running out of iterations, so I cannot confirm with certainty whether pool and target repository validation elsewhere in the request pipeline already rules out this exact collision). This uncertainty is a real gap in verification.

### Recommendation
Add an explicit check in `Link` (`internal/git/objectpool/link.go`) — analogous to `storage.ErrAlternatePointsToSelf` — that rejects the operation when `pool` and `repo` resolve to the same absolute path/relative path, before computing `expectedRelPath` or writing the alternates file, mirroring the guard already present in `getAlternatePartitionID`.

### Proof of Concept
Not fully constructable from static analysis alone: reaching this requires confirming (via `poolForRequest` in `internal/gitaly/service/objectpool/util.go`, which was not fully available in the index) whether an ordinary caller of `LinkRepositoryToObjectPool` can supply a pool repository that resolves to the same relative path as the target `repository`. This is the key open question needed to convert this into a fully proven, reachable exploit; it should be verified with a live Devin session against the full repository.

```go
func getRelativeObjectPath(ctx context.Context, pool, repo *localrepo.Repo) (string, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return "", fmt.Errorf("getting repository path: %w", err)
	}

	relPath, err := filepath.Rel(filepath.Join(repoPath, "objects"), poolPath)
	if err != nil {
		return "", err
	}

	return filepath.Join(relPath, "objects"), nil
```

```go
// linkedToRepository tests if a repository is linked to an object pool
func linkedToRepository(ctx context.Context, pool, repo *localrepo.Repo) (bool, error) {
	poolPath, err := pool.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting object pool path: %w", err)
	}

	repoPath, err := repo.Path(ctx)
	if err != nil {
		return false, fmt.Errorf("getting repo path: %w", err)
	}

	altInfo, err := stats.AlternatesInfoForRepository(repoPath)
	if err != nil {
		return false, fmt.Errorf("getting alternates info: %w", err)
	}

	if !altInfo.Exists || len(altInfo.ObjectDirectories) == 0 {
		return false, nil
	}

	relPath := altInfo.ObjectDirectories[0]
	expectedRelPath, err := getRelativeObjectPath(ctx, pool, repo)
	if err != nil {
		return false, err
	}

	if relPath == expectedRelPath {
		return true, nil
	}

	if filepath.Clean(relPath) != filepath.Join(poolPath, "objects") {
		return false, fmt.Errorf("unexpected alternates content: %q", relPath)
	}

	return false, nil
}
```

```go
func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil
```
