### Title
Protocol fee bypass on `Nep245`/`Imt` token diffs via unit-sized leg splitting - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Finding Description
The binding that must hold is:
`fee_ceil(N) == Σ fee_ceil(a_i)` for any partition `{a_i}` of a token-in amount `N` on the same `TokenId`.

`Pips::fee_ceil` itself (crates/primitives/fees/src/lib.rs:117-121) is a ceiling division and is actually super-additive-safe for ordinary fungible tokens: `ceil(a)+ceil(b) >= ceil(a+b)`, so splitting a `Nep141` amount into many legs can only *increase* the fee collected, never decrease it. The real break is in `TokenDiff::token_fee`, called before `fee_ceil` on every negative delta: [1](#0-0) 

For `TokenIdType::Nep245` (multi-token, which can represent fungible balances, not just NFTs) and `TokenIdType::Imt`, the fee is only applied when the *per-intent* leg amount is `> 1`; if the leg amount is `<= 1`, `token_fee` returns `Pips::ZERO`, and `fee_ceil` on a zero rate is always `0` regardless of `N`: [2](#0-1) 

The exemption is per `TokenDiff::execute_intent` call, i.e. per signed intent leg, using `delta.unsigned_abs()` computed locally within that single intent's diff map: [3](#0-2) 

An unprivileged attacker who wants to move a large `Nep245`/`Imt` balance (e.g. `N = 1000` units) can, instead of submitting one `TokenDiff` intent with `delta = -1000` (which would pay `fee_ceil(1000)` at the configured `protocol_fee`), submit `1000` separate signed `TokenDiff` intents each with `delta = -1` on the same `TokenId`, batched together (or across successive `execute_intents` calls). Each individual call sees `amount = 1`, so `token_fee` matches the `amount <= 1` exemption arm and returns `Pips::ZERO` for every leg, producing total fee `0` instead of `fee_ceil(1000)`. The attacker only needs counterparties/closures that net the batch to zero (which they can construct themselves across their own accounts, or against a real counterparty who is simply matching the requested legs one at a time), so no privileged role or victim key is required. `simulate_intents` would report this same zero-fee outcome, which the attacker (as maker or via a solver) could quote and settle against, exactly matching the "outcome `execute_intents` produces the divergence" pattern described.

Existing guards do not catch this: `Pips::fee_ceil` correctly rounds up whenever it is invoked, but it is invoked with a rate of `Pips::ZERO` due to `token_fee`'s per-leg exemption; there is no aggregation of amounts across intents/legs for the same token and signer, and no minimum/whole-batch check that would detect this splitting.

### Impact Explanation
Protocol fee is under-collected/bypassed entirely for any `Nep245` (multi-token) or `Imt` trade, by simply splitting the trade into unit-sized legs. This is a direct "protocol fees bypassed" case (Critical/High impact category), repeatable by any account, on any `Nep245`/`Imt` token, for unbounded notional, at the cost of extra transaction/gas overhead per unit leg. It does not affect ordinary `Nep141` fungible tokens, where `fee_ceil`'s rounding direction structurally punishes (over-charges) splitting rather than rewarding it.

### Likelihood Explanation
No special privileges are needed — any account can submit multiple signed `TokenDiff` intents in one `MultiPayload`, or across several `execute_intents` calls, each with unit deltas on the same `Nep245`/`Imt` `TokenId`. The only cost is proportional gas/transaction overhead for issuing many small legs, which is trivial relative to the avoided fee at any non-trivial `protocol_fee` and notional. This is fully repeatable and does not depend on races, timing, or third-party cooperation beyond the usual settlement counterparties.

### Recommendation
Do not key the `Nep245`/`Imt` fee exemption on the amount of an individual intent leg. Either: (a) remove the `amount <= 1` exemption for `Nep245`/`Imt` entirely and rely on `fee_ceil`'s rounding (as is already safe for `Nep141`), or (b) track/aggregate the signer's cumulative traded amount per `TokenId` within a settlement batch (and ideally across time) before deciding whether the `<= 1` exemption applies, so the exemption only fires for genuinely NFT-like single-unit transfers and not for fungible-equivalent balances split into unit chunks.

### Proof of Concept
```rust
// crates/primitives/fees/src/lib.rs / contracts/defuse/core/src/intents/token_diff.rs
// cargo test -p defuse-core token_fee_bypass_via_splitting

use defuse_core::{fees::Pips, intents::token_diff::TokenDiff, token_id::{TokenId, nep245::Nep245TokenId}};

#[test]
fn token_fee_bypass_via_splitting() {
    let fee = Pips::ONE_PERCENT; // 1%
    let token_id: TokenId = Nep245TokenId::new("mt.near".parse().unwrap(), "ft1".to_string()).into();

    // one leg, N = 1000
    let fee_one_leg = TokenDiff::token_fee(&token_id, 1000, fee).fee_ceil(1000);
    assert!(fee_one_leg > 0);

    // 1000 legs of amount = 1 each
    let mut fee_split_total = 0u128;
    for _ in 0..1000 {
        fee_split_total += TokenDiff::token_fee(&token_id, 1, fee).fee_ceil(1);
    }

    // Invariant broken: splitting collects strictly less fee than one leg
    assert_eq!(fee_split_total, 0);
    assert!(fee_split_total < fee_one_leg, "fee bypass: {fee_split_total} < {fee_one_leg}");
}
```
This demonstrates that `fee(N) == Σ fee(legs)` is violated for `Nep245`/`Imt` tokens: splitting into unit legs collects `0` total fee versus a strictly positive fee for the same notional executed as a single intent.

        for (token_id, delta) in &self.diff {

                return Err(DefuseError::InvalidIntent);
