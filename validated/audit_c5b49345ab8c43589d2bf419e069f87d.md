Confirms each `MultiPayload` is processed independently via `execute_signed_intent`, so fee decisions in `TokenDiff::token_fee` are evaluated per-intent with no cross-intent aggregation of the same account/token.### Title
Protocol fee bypass via unit-amount `TokenDiff` splitting on Nep245/Imt tokens - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` exempts `Nep245`/`Imt` token deltas from fees whenever `amount <= 1`, and `execute_signed_intents` evaluates each `MultiPayload`'s `TokenDiff` intents independently with no cross-intent or cross-payload aggregation of the transferred amount for the same token. An attacker can therefore move an arbitrarily large aggregate quantity of a single Nep245/Imt `TokenId` by splitting it into many separate signed `TokenDiff` intents, each with `|delta| == 1`, batched in one `execute_intents` call, paying zero protocol fee on the whole transfer.

### Finding Description
The binding that should hold for the batch is:
`fee_collector_balance_delta(T) == Σ over all negative deltas d_i on T in the batch of Pips::fee_ceil(protocol_fee, |d_i|)`.

In `TokenDiff::execute_intent` [1](#0-0) , for each negative delta the fee is computed as `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)`. `token_fee` [2](#0-1)  returns `Pips::ZERO` for `TokenIdType::Nep245`/`Imt` whenever `amount <= 1`, so `fee = Pips::ZERO.fee_ceil(1) = 0` for every such per-intent transfer, regardless of `protocol_fee`.

`Engine::execute_signed_intents` iterates independently over each `MultiPayload` in the batch, calling `execute_signed_intent` → `intents.execute_intent(...)` per payload with no memory of prior payloads' amounts on the same `token_id`/account [3](#0-2) . Thus an attacker who wants to move N units of a Nep245/Imt token can submit N separately-signed `TokenDiff` intents, each `diff = {T: -1}` (matched with a counterparty leg crediting the recipient +1), inside one `execute_intents` batch. Every leg independently satisfies `amount == 1`, so `token_fee` returns `Pips::ZERO` on each, and the aggregate `fees_collected` for `T` sums to `0` no matter how large N is — even though `protocol_fee = Pips::ONE_PERCENT` and total value moved is `N`.

No existing guard prevents this: `MultiPayload::verify`, nonce/salt checks, and `TransferMatcher::finalize` only verify signatures, nonces, and that deltas net correctly among the intents in the batch — none of them re-aggregate historical amounts per token to re-evaluate the `amount > 1` threshold across intents.

### Impact Explanation
This under-collects protocol fee revenue owed to `fee_collector` on Nep245/Imt (multi-token) transfers of any size, as long as the mover is willing to split the transfer into unit-sized legs across multiple signed intents in a single batch. This matches the explicitly listed Critical category "protocol fees bypassed or over-collected." It is fully repeatable: any account, any Nep245/Imt `TokenId`, any batch size, at the cost of only extra signed intents (no NEAR gas limits considered per scope exclusions). It does not require any privileged role, victim key, or state that isn't already reachable by any unprivileged signer submitting their own signed `MultiPayload`s.

### Likelihood Explanation
Preconditions: attacker holds ≥N units of Nep245/Imt token `T`, a counterparty (which can be the attacker's own second account) willing to receive it, and `protocol_fee > 0`. Cost is proportional to the number of split intents (N signatures/payloads), which is straightforward to automate and requires no special privilege — the split is purely a client-side choice of how to structure the `TokenDiff` amounts. This is fully feasible and directly reproducible with a `cargo test` in the core engine crate.

### Recommendation
Change the fee-exemption logic in `TokenDiff::token_fee` so that the "no fee on NFT/MT with |delta| <= 1" exemption is tied to whether the underlying MT token is fungible/semi-fungible (i.e., genuinely NFT-like, single-supply) rather than purely to the per-intent `amount` value, or aggregate amounts per `(signer, token_id)` across all `TokenDiff` intents within a single `execute_intents` batch (and ideally across a time window) before applying the `amount > 1` threshold, so repeated unit transfers cannot evade fee assessment.

### Proof of Concept
In `contracts/defuse/core/src/intents/token_diff.rs` (or an engine-level integration test), construct:
1. A Nep245 `TokenId` `T` and `protocol_fee = Pips::ONE_PERCENT`.
2. N separate `TokenDiff` intents, each `diff = {T: -1}` from signer A (paired with `{T: +1}` to signer B), each wrapped and signed as its own `MultiPayload`.
3. Call `Engine::execute_signed_intents` with all N payloads in one batch.
4. Assert: `fees_collected` total for `T` == 0 (via the `TokenDiffEvent::fees_collected` emitted, or `fee_collector`'s balance delta for `T`) while the aggregate moved amount for `T` == N.
5. Compare against a single `TokenDiff` intent with `diff = {T: -N}`, which correctly yields `fee = Pips::ONE_PERCENT.fee_ceil(N) > 0`, demonstrating the binding `fee_collector_balance_delta(T) == Σ Pips::fee_ceil(protocol_fee, |d_i|)` holds for the single-intent case but is violated (both sides diverge: LHS stays 0, RHS should be `Pips::ONE_PERCENT.fee_ceil(N)`) for the split-intent batch.

    pub fn execute_signed_intents(
        mut self,
        signed: impl IntoIterator<Item = MultiPayload>,
    ) -> Result<Transfers> {
        for signed in signed {
            self.execute_signed_intent(signed)?;
        }
        self.finalize()
    }

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
