The reported issue (GHSA-5pmw-9j92-3c4c) is a heap overflow in the C-based OpenH264 codec, reachable through the Rust `openh264-sys2` crate's unsafe FFI bindings around Cisco's C decoder. This vulnerability class fundamentally depends on unsafe manual memory management in C (buffer writes without bounds checks in the decoder's macroblock/slice processing).

The Go standard library has no analog to this: it does not ship an H.264/video codec, and more importantly, Go's memory model prevents this exact primitive. The comparable Go decoders — [1](#0-0)  for JPEG and [2](#0-1)  for PNG — perform explicit bounds/dimension validation (e.g., rejecting non-positive or overflowing dimensions) before allocating pixel buffers, and any residual out-of-bounds slice access in Go triggers a runtime panic (`index out of range`) rather than a silent heap-corrupting write, which is the core mechanic of the reported CWE-122 vulnerability. I also confirmed the GIF decoder validates frame bounds against the logical screen before allocating ( [3](#0-2) ), and JPEG has dedicated regression tests against malformed/truncated inputs ( [4](#0-3) ).

Since Go's memory-safe slice semantics eliminate the heap-overflow primitive that the report describes, and no equivalent unsafe-pointer arithmetic video/image decoding path exists in this repository, there is no legitimate analog to report here.

```go
func (d *decoder) parseIHDR(length uint32) error {
	if length != 13 {
		return FormatError("bad IHDR length")
	}
	if _, err := io.ReadFull(d.r, d.tmp[:13]); err != nil {
		return err
	}
	d.crc.Write(d.tmp[:13])
	if d.tmp[10] != 0 {
		return UnsupportedError("compression method")
	}
	if d.tmp[11] != 0 {
		return UnsupportedError("filter method")
	}
	if d.tmp[12] != itNone && d.tmp[12] != itAdam7 {
		return FormatError("invalid interlace method")
	}
	d.interlace = int(d.tmp[12])

	w := int32(binary.BigEndian.Uint32(d.tmp[0:4]))
	h := int32(binary.BigEndian.Uint32(d.tmp[4:8]))
	if w <= 0 || h <= 0 {
		return FormatError("non-positive dimension")
	}
	nPixels64 := int64(w) * int64(h)
	nPixels := int(nPixels64)
	if nPixels64 != int64(nPixels) {
		return UnsupportedError("dimension overflow")
	}
	// There can be up to 8 bytes per pixel, for 16 bits per channel RGBA.
	if nPixels != (nPixels*8)/8 {
		return UnsupportedError("dimension overflow")
	}
```
