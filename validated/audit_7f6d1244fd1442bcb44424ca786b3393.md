### Title
Unbounded disk write in CreateRepositoryFromBundle allows storage exhaustion DoS - ([File: internal/gitaly/service/repository/create_repository_from_bundle.go])

### Finding Description
`CreateRepositoryFromBundle` receives an attacker-controlled stream of `CreateRepositoryFromBundleRequest.Data` chunks via a `streamio.NewReader` closure that simply calls `stream.Recv()` in a loop with no cap on the number of messages or cumulative bytes. [1](#0-0) 
This reader is passed straight into `CloneBundle`, which calls `createTempBundle`, and that function performs an unbounded `io.Copy(file, reader)` writing every byte received directly to a file under the storage's temp directory before git ever inspects the bundle. [2](#0-1) 
Note that `CloneBundle`'s `git-clone` invocation explicitly disables hooks (`gitcmd.WithDisabledHooks()`), so none of the pre-receive-hook-based repository/namespace size-quota checks that Rails normally injects into push paths run for this RPC. There is no `grpc.MaxRecvMsgSize` configured to cap per-message size, and there is no application-level maximum bundle size, running total check, or streaming-to-bounded-sink logic anywhere in this path. The only mitigation present is the generic per-RPC concurrency limiter in `internal/grpc/middleware/limithandler`, which limits how many concurrent calls of this RPC can run per repository/lock-key but does not bound the total bytes an individual stream may send.

### Impact Explanation
An attacker with normal push/fork/import capability can open a `CreateRepositoryFromBundle` stream and send an arbitrarily large sequence of `Data` chunks (limited only by client patience and network bandwidth, not by any server-enforced ceiling). Since Gitaly persists these bytes to disk immediately via `io.Copy` before any validation (git-clone/bundle parsing happens only after the entire stream is written), the attacker can fill the shared storage volume, causing write failures and RPC failures for every other repository/tenant hosted on that storage — a storage-wide denial of service, matching GitLab's "denial of service" bounty impact class for resource exhaustion of an RPC handler.

### Likelihood Explanation
The attacker only needs the ability to invoke this RPC with arbitrary payload data — a capability implied by any GitLab feature that surfaces bundle-based repository creation (e.g., project import/fork tooling), and no elevated privileges, secrets, or non-default configuration are required. The attack is fully repeatable and only bound by the attacker's own bandwidth/time, making it a low-effort, highly reliable DoS.

### Recommendation
Enforce a maximum bundle size before or during the streaming copy in `createTempBundle` (e.g., wrap `reader` with an `io.LimitReader` sized to a configurable maximum, or track cumulative bytes read in the `bundleReader` closure and abort the stream once a threshold is exceeded), and additionally consider checking available free space on the target storage before/while writing. This should apply uniformly to all bundle/pack streaming ingestion paths (`CreateRepositoryFromBundle`, `FetchBundle`, etc.), not just this RPC.

### Proof of Concept
```go
func TestCreateRepositoryFromBundle_unboundedDiskWrite(t *testing.T) {
    ctx := testhelper.Context(t)
    cfg, repoClient := setupRepositoryServiceWithoutRepo(t) // existing test helper in create_repository_from_bundle_test.go

    stream, err := repoClient.CreateRepositoryFromBundle(ctx)
    require.NoError(t, err)

    repo := &gitalypb.Repository{StorageName: cfg.Storages[0].Name, RelativePath: gittest.NewRepositoryName(t)}
    require.NoError(t, stream.Send(&gitalypb.CreateRepositoryFromBundleRequest{Repository: repo}))

    // Send N GB of arbitrary chunk data with no valid bundle header.
    chunk := make([]byte, 4<<20) // 4MB per message, near default gRPC max
    const totalGB = 50
    for i := 0; i < totalGB*256; i++ { // 256 * 4MB = 1GB per outer loop
        err := stream.Send(&gitalypb.CreateRepositoryFromBundleRequest{Data: chunk})
        require.NoError(t, err, "server never rejects oversized stream")
    }
    // Expectation for a fixed implementation: server should return a
    // ResourceExhausted/InvalidArgument error once a size threshold is crossed,
    // well before 50GB is written to the temp directory.
}
```
Run this against a storage with a small disk quota to observe the temp bundle file (`repo.bundle` under the storage's `+gitaly/tmp` directory) grow unbounded until disk space is exhausted, causing failures for concurrent operations on other repositories sharing the same storage.

func (repo *Repo) createTempBundle(ctx context.Context, reader io.Reader) (bundlPath string, cleanup func(), returnErr error) {
	tmpDir, cleanup, err := tempdir.New(ctx, repo.GetStorageName(), repo.logger, repo.locator)
	if err != nil {
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}

	bundlePath := filepath.Join(tmpDir.Path(), "repo.bundle")

	file, err := os.Create(bundlePath)
	if err != nil {
		cleanup() // Clean up if we fail after creating the temp directory
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}
	defer func() {
		if err := file.Close(); err != nil && returnErr == nil {
			returnErr = fmt.Errorf("create temp bundle: %w", err)
		}
	}()

	if _, err = io.Copy(file, reader); err != nil {
		cleanup() // Clean up if we fail after creating the temp directory
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}

	return bundlePath, cleanup, nil
}
