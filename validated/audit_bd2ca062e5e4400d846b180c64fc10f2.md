### Title
Positions with debt below `debtFloorInUsd` (or near it) can never be liquidated — permanent bad debt - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
`Pool.liquidate` enforces two mutually exclusive bounds on `amountToRepay_`: the repayment cannot exceed `maxLiquidable` (default `0.5e18` = 50% of the debt balance, set in `initialize`) and, when `debtFloorInUsd > 0`, the *remaining* debt must be either `0` or `>= debtFloorInUsd`. For any account whose debt-token balance `B` satisfies `B_usd < debtFloorInUsd / (1 - maxLiquidable)`, no `amountToRepay_` exists that satisfies both checks: repaying `<= maxLiquidable * B` leaves a remainder `< debtFloorInUsd` (revert `RemainingDebtIsLowerThanTheFloor`), and repaying `B` in full (the only way to leave `0`) gives `amountToRepay_.wadDiv(B) == 1e18 > maxLiquidable` (revert `AmountGreaterThanMaxLiquidable`). Such positions are permanently unliquidatable via the only collateral-seizing path.

### Finding Description
In `Pool.liquidate` (contracts/Pool.sol:537-596):

```solidity
if (amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable) {
    revert AmountGreaterThanMaxLiquidable();          // blocks repay fraction > 50%
}
if (debtFloorInUsd > 0) {
    uint256 _newDebtInUsd = masterOracle().quoteTokenToUsd(
        address(syntheticToken_), _debtTokenBalance - amountToRepay_);
    if (_newDebtInUsd > 0 && _newDebtInUsd < debtFloorInUsd) {
        revert RemainingDebtIsLowerThanTheFloor();    // blocks partial repay to dust
    }
}
```

The two guards only overlap when remaining debt can be `>= debtFloorInUsd`, i.e. when `B_usd * (1 - maxLiquidable) >= debtFloorInUsd`. `debtFloorInUsd` is only enforced inside `liquidate` — `DebtToken.issue`/`flashIssue` have no minimum-debt check — so an unprivileged user can freely mint a debt whose USD value is below the floor (or just above it but below `floor/(1-maxLiquidable)`). If that position ever becomes unhealthy (collateral price decline via an AMM trade against the oracle's source within the same transaction is permitted, or ordinary interest accrual pushing `debt > issuableLimit`), every `liquidate` call against it reverts. `quoteLiquidateMax` (Pool.sol:419-440) confirms the cap is `balanceOf * maxLiquidable`, which is inside the reverting region. `CanNotLiquidateOwnPosition` prevents the attacker from self-cleaning, but they have no incentive to; `DebtToken.repay`/`repayAll` do not seize collateral, so they are not a substitute for liquidation. No modifier (`whenNotShutdown`, `nonReentrant`, SynthContext) prevents reaching this state.

### Impact Explanation
Permanent freezing of the liquidation function for the affected position → protocol insolvency. The collateral backing the bad debt can never be seized (`seize` is `onlyIfCanSeize` → pool-only, DepositToken.sol:343-345), while the debt remains outstanding and keeps accruing interest, worsening the shortfall. Per position the loss is bounded by ~`debtFloorInUsd / (1 - maxLiquidable)`, but the attacker can replicate the position across arbitrarily many accounts and across every registered synthetic token, making aggregate bad debt unbounded. Yield/collateral of honest users is socialized into covering the deficit, and the synthetic token's backing invariant (total collateral value ≥ total debt value) is broken.

### Likelihood Explanation
Medium. Requirements: `debtFloorInUsd > 0` (a governance-set parameter; the feature exists and is documented) and the position becoming unhealthy. An attacker can manufacture unhealthiness cheaply: open a small collateral position, issue debt sized inside the dead zone, then push the collateral's price down via an AMM trade that the oracle reads (same-transaction manipulation is allowed by scope), or simply wait for interest accrual (`DebtToken.accrueInterest` grows the debt continuously until it crosses the collateral factor threshold). Cost per position is only gas plus a dust deposit. Recovery is impossible without governor intervention (raising `maxLiquidable` to 1e18 or zeroing the floor), so even a small number of such positions constitutes permanent bad debt.

### Recommendation
In `Pool.liquidate`, bypass the floor check when the repayment closes the position, and bypass `maxLiquidable` when the entire remaining debt is below the floor, e.g.:

```solidity
uint256 _remaining = _debtTokenBalance - amountToRepay_;
if (_remaining > 0) {
    if (amountToRepay_.wadDiv(_debtTokenBalance) > maxLiquidable) {
        revert AmountGreaterThanMaxLiquidable();
    }
    if (debtFloorInUsd > 0 &&
        masterOracle().quoteTokenToUsd(address(syntheticToken_), _remaining) < debtFloorInUsd) {
        revert RemainingDebtIsLowerThanTheFloor();
    }
}
// additionally: allow full repay when B_usd < debtFloorInUsd regardless of maxLiquidable
```

Equivalently, when `_newDebtInUsd` would be `0` or the whole balance is already below the floor, treat `maxLiquidable` as `1e18` for that position, matching the semantics of `quoteLiquidateMax`.

### Proof of Concept
Hardhat-style sketch against the existing fixtures (`test/Pool.test.ts` pattern):

```ts
it('below-floor position is unliquidatable', async () => {
  await pool.updateDebtFloorInUsd(toUSD('100'))          // governor sets floor (assumed config)

  // alice: deposit $150 collateral (CF 0.5 => limit $75), issue $60 msETH debt (< floor)
  await met.connect(alice).approve(msdMET.address, DEPOSIT)
  await msdMET.connect(alice).deposit(toUSD('150') / metPrice, alice.address)
  await msEthDebtToken.connect(alice).issue(toUSD('60') / ethPrice, alice.address)

  // price moves: collateral drops / interest accrues => position unhealthy
  await masterOracle.updatePrice(met.address, toUSD('0.4'))
  const {_isHealthy} = await pool.debtPositionOf(alice.address)
  expect(_isHealthy).false

  const debt = await msEthDebtToken.balanceOf(alice.address)

  // (1) any partial repay leaves remainder < floor
  await expect(
    pool.connect(liquidator).liquidate(msEth.address, alice.address, debt.div(2), msdMET.address)
  ).revertedWithCustomError(pool, 'RemainingDebtIsLowerThanTheFloor')

  // (2) full repay => 100% > maxLiquidable (0.5e18)
  await expect(
    pool.connect(liquidator).liquidate(msEth.address, alice.address, debt, msdMET.address)
  ).revertedWithCustomError(pool, 'AmountGreaterThanMaxLiquidable')

  // (3) quoteLiquidateMax returns a value inside the reverting region
  const max = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)
  await expect(
    pool.connect(liquidator).liquidate(msEth.address, alice.address, max, msdMET.address)
  ).reverted  // still reverts: either floor or cap

  // => position can never be liquidated; collateral is unreachable, bad debt persists
})
```

Expected: every `liquidate` call reverts; no public entry point can seize the collateral; the position remains on the books indefinitely.
