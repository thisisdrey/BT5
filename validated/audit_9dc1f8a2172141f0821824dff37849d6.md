### Title
Unauthenticated remote `POST /shutdown` permanently terminates the signer's event receiver - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` dispatches on URL path alone; any TCP client that can reach the bound event-receiver port can send `POST /shutdown` with no credentials, setting `stop_signal` and returning `EventError::Terminated`, which causes `EventReceiver::main_loop` to `break` and never process another event.

### Finding Description
The claimed equality — "the shutdown command == one issued by the node operator's local stop signaler" — is broken. In `next_event`, the branch `else if request.url() == "/shutdown" { event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated) }` (`libsigner/src/events.rs:443-445`) performs zero verification of the requester's identity, origin IP, or any shared secret. The only legitimate producer of this request, `SignerStopSignaler::send` (`libsigner/src/events.rs:376-396`), constructs the exact same unauthenticated raw HTTP text (`POST /shutdown HTTP/1.1 ... Yo. Shut this shit down!`) that any TCP client could replicate byte-for-byte. Once `stop_signal` is set, `is_stopped()` returns true on the next `main_loop` iteration and `next_event` itself also short-circuits to `Err(EventError::Terminated)`; `main_loop` (`libsigner/src/events.rs:284-312`) then `break`s permanently, with no code path to reset `stop_signal` or restart the loop.

### Impact Explanation
A single crafted HTTP POST from any TCP client that can reach the event-receiver port permanently halts the signer's event stream — no more `stackerdb_chunks`, `proposal_response`, `new_burn_block`, or `new_block` events are forwarded to the runloop. This is a full, repeatable, unauthenticated remote denial-of-service against a single signer process using one small message, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is TCP reachability to the port bound by `EventReceiver::bind`. No secret, key, peer registration, or StackerDB slot ownership is required — the attacker only needs to open a socket and send a fixed ~140-byte HTTP request. This is trivially repeatable against any exposed instance. The severity in practice depends on deployment: if the signer event-receiver is configured/documented to bind only to `127.0.0.1`, remote exploitation requires an additional misconfiguration exposing that port; I was not able to confirm the default bind address from `stacks-signer/src/config.rs` within the available investigation.

### Recommendation
Require a shared secret or local-only enforcement for the `/shutdown` endpoint (e.g., verify a token embedded by `SignerStopSignaler`, or reject any `/shutdown` request whose peer address is not `127.0.0.1`/`::1`), rather than trusting the URL path alone.

### Proof of Concept
Rust test: bind a `SignerEventReceiver` via `EventReceiver::bind`, spawn `main_loop` in a thread with a consumer attached via `add_consumer`, then from a plain `TcpStream::connect` (not `SignerStopSignaler`) send:
```
POST /shutdown HTTP/1.1\r\nHost: <addr>\r\nConnection: close\r\nContent-Length: 4\r\nContent-Type: text/plain\r\n\r\ntest
```
Then send a legitimate `stackerdb_chunks` event and assert the consumer channel never receives it, confirming `next_event` returned `Err(EventError::Terminated)` and `main_loop` exited via the `break` at `libsigner/src/events.rs:299`.
