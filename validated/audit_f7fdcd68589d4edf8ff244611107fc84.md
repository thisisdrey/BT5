### Title
Attacker-Controlled `codeHash` Field in `CreateSmartContract` Trusted Without Verification by `EXTCODEHASH` (TOCTOU-style Hash Integrity Bypass) - (File: actuator/src/main/java/org/tron/core/vm/program/Program.java)

### Summary
The `SmartContract` protobuf message accepted from a `CreateSmartContract` deploy transaction carries a `codeHash` field that a contract deployer (an unprivileged, unprivileged transaction broadcaster) can set directly. `ContractCapsule` exposes this field as a plain getter/setter with no integrity check against the actual deployed bytecode [1](#0-0) . The TVM's `EXTCODEHASH` implementation (`Program.getCodeHashAt`) treats any non-empty stored `codeHash` as authoritative and only computes `sha3(code)` lazily when the field is empty/zero — it never re-derives or cross-checks the hash against the code that is actually stored at that address [2](#0-1) . This mirrors the Yarn TOCTOU pattern: an integrity value is accepted/cached once and never recomputed/verified on subsequent reads, so the trusted value and the real content can diverge.

### Finding Description
`Program.getCodeHashAt` (used for the `EXTCODEHASH` opcode) reads `ContractCapsule.getCodeHash()`. If that value is present, it is returned as-is; only when empty does it fall back to `Hash.sha3(getCodeAt(address))` and populate the cache [2](#0-1) . Nothing along this read path recomputes `sha3` of the actual code and compares it to the stored `codeHash` — the field is trusted purely because it exists, exactly analogous to Yarn reading from a cache without re-verifying the integrity hash that was computed at write time.

The stored value originates from the `SmartContract` protobuf, which is directly deserialized from the deployer's `CreateSmartContract` transaction contents; `ContractCapsule.setCodeHash`/`getCodeHash` perform no validation of the byte content [1](#0-0) . The codebase itself acknowledges this is a known abusable field: a fork-gated guard, `VMActuator.checkContractHashFields`, is designed to reject non-empty `codeHash`/`trxHash` fields supplied in the deploy transaction once fork `VERSION_4_8_2_2` is activated on the network, while explicitly still *permitting* the attacker-supplied fields to pass through before that fork activates [3](#0-2) [4](#0-3) . This confirms the root cause: prior to (or on any chain/fork configuration where) `VERSION_4_8_2_2` has not activated, an unprivileged deployer can set an arbitrary `codeHash` in their deploy transaction that has no relation to the actual deployed bytecode, and `EXTCODEHASH` will faithfully report that forged value forever, since the lazy-compute branch in `getCodeHashAt` is only reached when the field is empty.

### Impact Explanation
`EXTCODEHASH` is widely relied on by other on-chain contracts (proxy/factory verification such as ERC-1167 minimal-proxy detection, allowlist/denylist code-hash checks, anti-flash-loan/anti-contract guards, and cross-chain bridge or DEX router logic that gates behavior based on a counterparty's bytecode hash). A contract deployer can forge the `codeHash` reported for their own malicious contract to match the hash of a trusted/known-safe contract, defeating any on-chain logic that uses `EXTCODEHASH` for authorization or trust decisions. This can enable unauthorized contract interactions, bypass of code-hash allowlists guarding privileged operations, or spoofing of "verified factory-deployed clone" checks — leading to unauthorized account operations or theft of funds in protocols that gate value transfer based on `EXTCODEHASH`.

### Likelihood Explanation
Exploitation requires only a single, ordinary `CreateSmartContract` transaction from any unprivileged account — no special permissions, no witness/SR collusion, no network condition. The only gating factor is whether fork `VERSION_4_8_2_2` has been activated on the target chain; on any deployment or test network (or a mainnet snapshot) where that fork has not yet activated, the forged-hash path is fully reachable, as proven directly by `ContractHashValidationTest.acceptsHashFieldsBeforeActivation` [3](#0-2) .

### Recommendation
Regardless of fork-activation status, `EXTCODEHASH`/`getCodeHashAt` should never trust a stored `codeHash` value that was not derived by the node itself from the deployed bytecode. Either (1) always recompute `sha3(code)` server-side at contract-creation time and discard/ignore any `codeHash` supplied in the incoming `CreateSmartContract` message unconditionally (not just after a fork block), or (2) verify any supplied `codeHash` against `sha3(code)` at creation time and reject the transaction on mismatch, independent of `ForkController` state.

### Proof of Concept
1. On a network/chain state where fork `VERSION_4_8_2_2` has not activated, submit a `CreateSmartContract` transaction whose embedded `SmartContract` message sets `codeHash` to an arbitrary 32-byte value (e.g., the `sha3` hash of a well-known, trusted contract's bytecode) while deploying attacker-controlled bytecode.
2. Because `VMActuator.checkContractHashFields` only rejects non-empty `codeHash` after fork activation, the forged value passes validation, matching `ContractHashValidationTest.acceptsHashFieldsBeforeActivation` [3](#0-2) .
3. Any subsequent `EXTCODEHASH` query against the attacker's contract address (via `Program.getCodeHashAt`) returns the forged hash without recomputing it from the actual bytecode [2](#0-1) , allowing the attacker's malicious contract to impersonate a trusted contract's code identity to any on-chain consumer of `EXTCODEHASH`.

  public byte[] getCodeHashAt(DataWord address) {
    byte[] tronAddr = address.toTronAddress();
    AccountCapsule account = getContractState().getAccount(tronAddr);
    if (account != null) {
      ContractCapsule contract = getContractState().getContract(tronAddr);
      byte[] codeHash;
      if (contract != null) {
        codeHash = contract.getCodeHash();
        if (ByteUtil.isNullOrZeroArray(codeHash)) {
          byte[] code = getCodeAt(address);
          codeHash = Hash.sha3(code);
          contract.setCodeHash(codeHash);
          getContractState().updateContract(tronAddr, contract);
        }
      } else {
        codeHash = Hash.sha3(new byte[0]);
      }
      return codeHash;
    } else {
      return EMPTY_BYTE_ARRAY;
    }
  }
