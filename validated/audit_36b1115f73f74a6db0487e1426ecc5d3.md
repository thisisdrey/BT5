### Title
Permissionless `lending_pool_emissions_deposit` allows a first-depositor share-price inflation attack against a fresh bank, causing rounding-based fund loss/theft for the next depositor - (File: `programs/marginfi/src/instructions/marginfi_group/configure_bank.rs`)

### Summary
`lending_pool_emissions_deposit` is callable by **any signer** on any bank whose asset-tag is a standard marginfi tag, with only a `total_asset_shares > 0` check [4](#0-3) . It recomputes `bank.asset_share_value` as `(total_assets + amount) / total_asset_shares` [5](#0-4) . This is functionally the same primitive as the reported Perennial `BalancedVault` bug: an attacker who is the sole/first depositor in a bank can mint a minimal number of shares, then call this permissionless instruction to "donate" a large amount of tokens, inflating `asset_share_value` steeply while `total_asset_shares` stays tiny.

### Finding Description
1. Attacker (or a bot racing the very first legitimate depositor of a freshly created bank) deposits the smallest possible amount (e.g. `1` native unit) via the ordinary `lending_account_deposit` path. Since a new bank initializes `asset_share_value = 1` [6](#0-5) , this mints `1` asset share, so `total_asset_shares = 1`.
2. Attacker calls `lending_pool_emissions_deposit` with a large `amount` (their own funds, transferred into the liquidity vault by the `TransferChecked` CPI inside the instruction) [7](#0-6) . Because `total_asset_shares == 1`, `asset_share_value` jumps to roughly `amount + 1`.
3. A victim then deposits normally. `get_asset_shares` divides the deposited value by the now-huge `asset_share_value` and floors to an integer [8](#0-7) , so any deposit smaller than the inflated share value rounds down to `0` shares — the victim's tokens are absorbed into the liquidity vault while receiving no claim on them.
4. The attacker, holding the only non-zero share (`1` share, now worth almost the entire vault balance), can withdraw essentially all funds, including the victim's deposit.

This mirrors the root cause in the Sherlock report precisely: a first depositor mints negligible shares, then inflates the "exchange rate" via a token donation, causing later depositors' shares to round down to zero. The key enabling factor in marginfi is that, unlike the vast majority of the accounting surface (deposits/withdraws/borrows/repays, which use the bank's own tracked `asset_share_value` rather than the live vault balance, making a plain SPL-transfer donation harmless [3](#0-2) ), `lending_pool_emissions_deposit` is a legitimate, permissionless instruction that explicitly recomputes `asset_share_value` from an attacker-supplied `amount` divided by whatever `total_asset_shares` happens to be at call time.

### Impact Explanation
This enables theft of a victim's newly-deposited funds and/or permanent value loss for anyone depositing into a bank shortly after creation while `total_asset_shares` is still small. This satisfies the "concrete theft / unauthorized transfer" bar: the attacker's `1`-share position can later redeem nearly the full vault balance, including funds contributed by the victim's deposit and the attacker's own "emissions" donation.

### Likelihood Explanation
Likelihood is bounded by timing: the attack requires the attacker to be the sole depositor of a bank (i.e., race the very first real deposit), similar to the original Sherlock finding, which was still accepted as a valid Medium despite this same timing constraint. On Solana, a bank creator/attacker can trivially deposit `1` unit and call `lending_pool_emissions_deposit` in the same transaction/bundle right after bank creation and before any other depositor arrives, making the attack cheap and highly feasible against every newly listed bank.

### Recommendation
- Require `total_asset_shares` to exceed a meaningful minimum (not just `> 0`) before `lending_pool_emissions_deposit` is allowed to adjust `asset_share_value`, or cap the per-call increase in `asset_share_value` (e.g., bound `amount` relative to current `total_assets`).
- Alternatively, restrict `lending_pool_emissions_deposit` to admin/emissions-admin signers instead of leaving it fully permissionless, since its only legitimate use case (crediting reward emissions) does not require public callability.
- Consider seeding every new bank with a minimum, un-withdrawable deposit (virtual shares/assets) so `total_asset_shares` can never be attacker-controlled at a value as low as `1`.

/// Permissionlessly deposit same-mint emissions directly into the bank liquidity vault,
/// increasing depositor value through asset share value.
pub fn lending_pool_emissions_deposit(
    ctx: Context<LendingPoolEmissionsDeposit>,
    amount: u64,
) -> MarginfiResult {
    if amount == 0 {
        return Ok(());
    }

    let clock = Clock::get()?;
    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = ctx.accounts.group.load()?;

    utils::validate_bank_state(&bank, utils::InstructionKind::FailsIfPausedOrReduceState)?;

    // Reject mints with non-zero transfer fees or active transfer hooks.
    let mint_ai = ctx.accounts.mint.to_account_info();
    check!(
        !utils::nonzero_fee(mint_ai.clone(), clock.epoch)?,
        MarginfiError::InvalidTransfer
    );
    check!(
        !utils::has_transfer_hook(mint_ai)?,
        MarginfiError::InvalidTransfer
    );

    let total_asset_shares = I80F48::from(bank.total_asset_shares);
    check!(
        total_asset_shares > I80F48::ZERO,
        MarginfiError::EmissionsUpdateError
    );

    bank.accrue_interest(
        clock.unix_timestamp,
        &group,
        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
    )?;

    transfer_checked(
        CpiContext::new(
            ctx.accounts.token_program.key(),
            TransferChecked {
                from: ctx.accounts.emissions_funding_account.to_account_info(),
                to: ctx.accounts.liquidity_vault.to_account_info(),
                authority: ctx.accounts.depositor.to_account_info(),
                mint: ctx.accounts.mint.to_account_info(),
            },
        ),
        amount,
        ctx.accounts.mint.decimals,
    )?;

    let total_assets = bank.get_asset_amount(total_asset_shares)?;
    let updated_total_assets = total_assets
        .checked_add(I80F48::from_num(amount))
        .ok_or_else(math_error!())?;

    bank.asset_share_value = updated_total_assets
        .checked_div(total_asset_shares)
        .ok_or_else(math_error!())?
        .into();

    bank.update_bank_cache(&group)?;

    msg!(
        "Deposited {} same-bank emissions into liquidity vault",
        amount
    );

    Ok(())
}
