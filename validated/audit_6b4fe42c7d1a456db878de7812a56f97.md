### Title
Exact `netip.AddrPort` match in `unlockedIsBad` lets a blocked peer evade the block by rebinding source port - ([File: remote_list.go])

### Finding Description
`RemoteList.BlockRemote` records a rejected remote as `bad.UdpAddr`, a full `netip.AddrPort` (IP **and** port), into `r.badRemotes` [1](#0-0) . Every subsequent decision about whether to keep an address candidate goes through `unlockedIsBad`, which performs an exact-value `slices.Contains(r.badRemotes, remote)` check on the full `AddrPort` [2](#0-1) . `unlockedCollect`, which rebuilds the deduplicated candidate address list used for future handshake attempts, calls `unlockedIsBad` per-candidate the same way for both learned and reported v4/v6 addresses and DNS-derived addresses [3](#0-2) .

Because the comparison is on the tuple `(ip, port)` rather than `ip` alone, any candidate address that was previously blocked at port `P1` is not excluded if it reappears at port `P2` for the same IP. Since `LearnRemote` (invoked from the handshake path on `HostInfo.SetRemote`) re-adds a "learned" address for a given owner vpn IP and marks the list dirty for recollection [4](#0-3) , an attacker who was previously blocked after a wrong-vpn-ip handshake response can simply resend the handshake init from the same source IP with a different source port (natural via NAT rebinding, or trivially forced by the attacker themselves) to have that new `ip:port` pair added back into the reported/learned cache and pass `unlockedIsBad` cleanly, since it isn't byte-for-byte in `r.badRemotes`.

The stated invariant in the code comment — "This is a list of remotes that we have tried to handshake with and have returned from the wrong vpn ip. They should not be tried again during a handshake" [5](#0-4)  — is IP-identity-based in intent but is enforced at IP+port granularity, so the enforcement doesn't actually match the stated invariant for the (very common) case of ephemeral/rebound UDP source ports.

### Impact Explanation
This is a defense-in-depth/anti-abuse bypass, not an authentication or certificate bypass: any resulting handshake with the re-admitted address must still pass Nebula's normal handshake/cert verification, so this alone does not grant tunnel access, decrypt traffic, or forge sessions. The concrete effect is that the "do not retry this remote" invariant is trivially defeated, letting a previously-rejected source re-enter the candidate remote list (`unlockedCollect`/`r.addrs`) and be retried in future handshake rounds and lighthouse address selection, i.e., a limited remote-state poisoning of the `RemoteList` blocklist. It does not by itself demonstrate a crash, wedge, decryption, or firewall bypass.

### Likelihood Explanation
Preconditions: attacker must already have caused a wrong-vpn-ip block once (requires being able to reach the target's UDP handshake endpoint and have it respond that the vpn IP didn't match) and must control/vary the source port of subsequent packets, which is trivial for any UDP sender (source port is entirely attacker-chosen, and NAT rebinding also naturally changes it). No privileged access, cert, or config control is needed, matching the stated attacker model. Repeatability is high — the attacker can vary the port on every packet.

### Recommendation
Key `badRemotes` (and the `unlockedIsBad` comparison) on IP alone (or track blocked IPs in a separate `map[netip.Addr]struct{}` for the wrong-vpn-ip case), rather than the full `netip.AddrPort`, so that any port bearing the previously-rejected IP is excluded from being recollected into `r.addrs`.

### Proof of Concept
Unit test in `remote_list_test.go`:
1. Construct a `RemoteList`, call `r.BlockRemote(ViaSender{UdpAddr: netip.MustParseAddrPort("1.2.3.4:1000")})`.
2. Populate the cache for some owner vpn IP with a reported/learned address `1.2.3.4:1001` (same IP, different port) via `unlockedSetV4`/`LearnRemote`.
3. Call `r.Rebuild(nil)` (which invokes `unlockedCollect`) and assert that `r.addrs` (or `r.CopyAddrs(nil)`) still contains `1.2.3.4:1001`, proving the previously-blocked IP is retried on a new port — `unlockedIsBad(1.2.3.4:1001)` returns `false` even though `1.2.3.4:1000` is blocked.

// LearnRemote locks and sets the learned slot for the owner vpn ip to the provided addr
// Currently this is only needed when HostInfo.SetRemote is called as that should cover both handshaking and roaming.
// It will mark the deduplicated address list as dirty, so do not call it unless new information is available
func (r *RemoteList) LearnRemote(ownerVpnIp netip.Addr, remote netip.AddrPort) {
	r.Lock()
	defer r.Unlock()
	if remote.Addr().Is4() {
		r.unlockedSetLearnedV4(ownerVpnIp, netAddrToProtoV4AddrPort(remote.Addr(), remote.Port()))
	} else {
		r.unlockedSetLearnedV6(ownerVpnIp, netAddrToProtoV6AddrPort(remote.Addr(), remote.Port()))
	}
}

// BlockRemote locks and records the address as bad, it will be excluded from the deduplicated address list
func (r *RemoteList) BlockRemote(bad ViaSender) {
	if bad.IsRelayed {
		return
	}

	r.Lock()
	defer r.Unlock()

	// Check if we already blocked this addr
	if r.unlockedIsBad(bad.UdpAddr) {
		return
	}

	// We copy here because we are taking something else's memory and we can't trust everything
	r.badRemotes = append(r.badRemotes, bad.UdpAddr)

	// Mark the next interaction must recollect/dedupe
	r.shouldRebuild = true
}

					continue
				}

					addrs = append(addrs, u)
				}
			}
