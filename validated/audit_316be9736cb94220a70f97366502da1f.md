### Title
Unprivileged caller can permanently burn reward accrual intervals via truncation in `RewardsDistributor._calculateTokenIndex` - (File: contracts/RewardsDistributor.sol)

### Summary
`RewardsDistributor._calculateTokenIndex` computes the per-interval reward increment as `_ratio = _tokensAccrued.wadDiv(_totalSupply)` and then unconditionally advances `tokenStates[token_].timestamp` whenever `index > 0`, even when `_ratio` rounds to 0. Because `updateBeforeMintOrBurn` is explicitly callable by anyone ("This function also may be called by anyone"), an unprivileged attacker can force index updates at arbitrarily small time deltas, so each interval's accrued rewards round to zero while the timestamp still advances — permanently deleting those rewards from the index for all users of that DepositToken/DebtToken. [1](#0-0) [2](#0-1) 

### Finding Description
In `_calculateTokenIndex`, when `_deltaTimestamps > 0 && _speed > 0`:

```solidity
uint256 _tokensAccrued = _deltaTimestamps * _speed;
uint256 _ratio = _totalSupply > 0 ? _tokensAccrued.wadDiv(_totalSupply) : 0;
_newIndex = (_supplyState.index + _ratio).toUint224();
_newTimestamp = block.timestamp.toUint32();
```

`wadDiv` (contracts/lib/WadRayMath.sol:39-41) computes `(a * WAD + b / 2) / b`, i.e. half-up rounding. `_ratio` becomes `0` whenever `_tokensAccrued * 1e18 < _totalSupply / 2`. When that happens `_newIndex == _supplyState.index` (which is > 0 once the token is registered), so the `_newIndex > 0 && _newTimestamp > 0` branch in `_updateTokenIndex` still stores the new timestamp — the elapsed interval is consumed without crediting any reward. [3](#0-2) [4](#0-3) 

The truncation is reachable from a public, unauthenticated entry point: `updateBeforeMintOrBurn(IERC20 token_, address account_)` has no access control and is documented as callable by anyone. An attacker can call it every block (or many times per block across accounts) to keep `_deltaTimestamps` minimal. The condition for zero accrual is:

```
delta * speed * 1e18 < totalSupply / 2
```

This is easily satisfied when `speed` is small (e.g., a 6-decimal reward token with a low emission rate) or `totalSupply` is large (DepositToken totalSupply is denominated in the underlying's raw units; for an 18-decimal collateral with millions deposited, `totalSupply` is ~1e24–1e30). Example: `totalSupply = 1e27`, `speed = 1e4` (0.01 reward units/s of a 6-decimal token), `delta = 1` s → `1e4 * 1e18 = 1e22 < 5e26` → `_ratio = 0`, and the entire second's emission is discarded.

Unlike the Locke original, which needed a large `totalVirtualBalance`, here the attacker does not even need capital: repeatedly forcing small `_deltaTimestamps` is sufficient. Additionally, an attacker holding a large deposit position (or inflating `totalSupply` via flash-minted deposits timed around calls, since `totalSupply` is read live at line 204) can widen the truncation window.

### Impact Explanation
Rewards emitted during every truncated interval are permanently lost: they never enter `tokenStates[token_].index`, so no user's `tokensAccruedOf` can ever capture them. The reward tokens remain stranded in the distributor (`_transferRewardIfEnoughTokens` only pays out recorded accruals). This is permanent freezing/destruction of unclaimed yield for all suppliers/borrowers of the affected token — matching the "user loses reward in an update round" invariant break of the Locke report.

### Likelihood Explanation
- Trigger cost is ~gas only; `updateBeforeMintOrBurn` is public and unauthenticated.
- On chains with low gas (Optimism/Swell deployments exist), spamming per-block is trivially cheap.
- Also occurs organically on any high-frequency interaction with the token (every mint/burn/transfer of a DepositToken/DebtToken calls `updateBeforeMintOrBurn`/`updateBeforeTransfer`), so even without an attacker, heavily traded tokens with low reward speed or large supply silently leak emission.
- No modifier stops it: `nonReentrant` is absent on `updateBeforeMintOrBurn`, pause flags don't apply, and no minimum-delta guard exists.

### Recommendation
- Do not advance `timestamp` when `_ratio == 0` while `_speed > 0` — carry the un-credited time forward so emissions accumulate until they produce a non-zero index delta (e.g., only update `_newTimestamp` when `_newIndex != _supplyState.index`, or track accrued-but-undistributed remainder).
- Alternatively accrue in a higher-precision accumulator (ray/1e27) or store `lastAccrued` reward-per-token in the token's decimals with an explicit remainder, and consider permissioning or rate-limiting the public `updateBeforeMintOrBurn` path.

### Proof of Concept
Hardhat (fork/test) sketch:

```ts
// Setup: pool registered, distributor added, token speed set by keeper.
await rewardDistributor.updateTokenSpeed(depositToken.address, 1e4) // 0.01 units/s, 6-dec reward token
await depositToken.mint(alice, parseEther('1000000000')) // totalSupply = 1e27 raw units

// Attacker loop (or scripted per-block calls):
for (let i = 0; i < 100; i++) {
  await ethers.provider.send('evm_increaseTime', [1])
  await ethers.provider.send('evm_mine', [])
  // public, unauthenticated
  await rewardDistributor.connect(attacker).updateBeforeMintOrBurn(depositToken.address, alice.address)
}

const { index } = await rewardDistributor.tokenStates(depositToken.address)
// index === INITIAL_INDEX: 100 seconds * 1e4 = 1e6 reward units emitted but index never moved
const accrued = await rewardDistributor.tokensAccruedOf(alice.address)
expect(accrued).to.eq(0) // 1e6 reward units permanently unclaimable
```

Expected: each call computes `1 * 1e4 * 1e18 / 1e27 → 0` (since `1e22 < 1e27/2`), index stays at `INITIAL_INDEX`, timestamp advances, and the emitted rewards are irrecoverable.

```text
    function _calculateTokenIndex(
        TokenState memory _supplyState,
        IERC20 token_
    ) private view returns (uint224 _newIndex, uint32 _newTimestamp) {
        uint256 _speed = tokenSpeeds[token_];
        uint256 _deltaTimestamps = block.timestamp - uint256(_supplyState.timestamp);
        if (_deltaTimestamps > 0 && _speed > 0) {
            uint256 _totalSupply = token_.totalSupply();
            uint256 _tokensAccrued = _deltaTimestamps * _speed;
            uint256 _ratio = _totalSupply > 0 ? _tokensAccrued.wadDiv(_totalSupply) : 0;
            _newIndex = (_supplyState.index + _ratio).toUint224();
            _newTimestamp = block.timestamp.toUint32();
        } else if (_deltaTimestamps > 0 && _supplyState.index > 0) {
            _newTimestamp = block.timestamp.toUint32();
        }
    }
```

```text
    function _updateTokenIndex(IERC20 token_) private {
        TokenState storage _supplyState = tokenStates[token_];
        (uint224 _newIndex, uint32 _newTimestamp) = _calculateTokenIndex(_supplyState, token_);
        if (_newIndex > 0 && _newTimestamp > 0) {
            _supplyState.index = _newIndex;
            _supplyState.timestamp = _newTimestamp;
            emit TokenIndexUpdated(_newIndex, _newTimestamp);
        } else if (_newTimestamp > 0) {
            _supplyState.timestamp = _newTimestamp;
            emit TokenIndexUpdated(_supplyState.index, _newTimestamp);
        }
    }
```
