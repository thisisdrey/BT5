### Title
`TokenDiff::token_fee`'s amount≤1 exemption is applied per-intent, letting a signer split a large Nep245/Imt/Nep171 transfer into unit-size legs to fully bypass the protocol fee - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::execute_intent` computes and collects fees independently for each intent in a signed batch, and `TokenDiff::token_fee` zero-rates any Nep245/Imt (and always Nep171) delta whose absolute amount is `<= 1`. By splitting a single large negative delta of `K` units into `K` separate `TokenDiff` intents of `amount == 1` each (matched in the same batch by a counterparty leg, e.g. a market-maker's fungible-token side), a signer collects `Pips::ZERO` fee on every leg instead of `Pips::fee_ceil(fee, K)` that a single `amount == K` intent would incur.

### Finding Description
The intended binding is: for a given token `T`, `fees_collected(T) == protocol_fee.fee_ceil(sum of |negative deltas of T| across the batch)`.

The actual code computes fee per intent rather than per aggregate batch delta: [1](#0-0) 

and the per-intent fee itself is zero-rated for Nep245/Imt/Nep171 tokens whenever the *individual intent's* `amount <= 1`: [2](#0-1) 

There is no aggregation of deltas for the same token across multiple intents/payloads before the fee is computed - `Engine::execute_signed_intents` simply loops over each `MultiPayload` and each `DefuseIntents` entry, calling `execute_intent` independently for each `TokenDiff`: [3](#0-2) [4](#0-3) 

The only cross-intent invariant enforced afterwards is `TransferMatcher::finalize`, which only checks that all balance deltas across the batch net out to a valid set of transfers (no minting) - it does not recompute or verify fee amounts: [5](#0-4) 

Exploit flow: an unprivileged signer holding `K` units of an Nep245 token signs a single `MultiPayload` containing `K` separate `TokenDiff` intents, each with `diff = {Nep245_token: -1, Nep141_token: +c}`. A matching counterparty (e.g. a solver the attacker also controls, or any willing market maker) supplies the offsetting `{Nep141_token: -K*c, Nep245_token: +K}` in one or more of its own `TokenDiff` intents in the same batch. Each of the attacker's `K` legs independently hits the `amount <= 1` branch in `token_fee`, returning `Pips::ZERO`, so `fees_collected` for the Nep245 token is `0` for the whole batch, whereas a single `TokenDiff` intent moving `-K` units of the same token would have paid `protocol_fee.fee_ceil(K)`. No existing guard (`verify`, nonce checks, `TransferMatcher::finalize`) checks or aggregates fee amounts across intents, so nothing prevents this.

### Impact Explanation
The fee_collector under-receives fees on every batch where an Nep245/Imt/Nep171-type transfer is split into unit legs; this directly matches the listed Critical category "protocol fees bypassed." The blast radius is limited to token types where the `amount<=1` exemption exists (Nep245/Imt and always Nep171) — not Nep141, since Nep141 always applies the fee regardless of amount. Any Nep245 multi-token contract issuing units that carry material per-unit value (rather than being genuinely non-fungible/atomic) is affected, and the technique is fully repeatable across accounts, tokens, and batches at no cost beyond the number of intents that must be signed and gas paid.

### Likelihood Explanation
Preconditions are minimal and match the unprivileged attacker profile: the signer needs an Nep245 balance of `K` units and a willing counterparty (which the attacker can also control) to supply the matching side of the swap in the same batch. No role, DAO permission, or relayer key is required — only the ability to sign a `MultiPayload` with multiple `TokenDiff` intents and call `execute_intents`/`simulate_intents`. The only cost is the marginal per-intent overhead (payload size / gas), which scales linearly with `K` but is entirely within reach of a normal signer.

### Recommendation
Aggregate the `amount<=1` exemption check per `(token_id, signer)` (or per token) across the whole batch rather than per individual `TokenDiff` intent, e.g. by summing all negative deltas for a given `TokenIdType::Nep245`/`Imt` token per signer across the transaction before deciding whether the exemption applies, or by removing the exemption for Nep245/Imt tokens whose supply/decimals indicate fungible-like usage and reserving it strictly for genuinely atomic Nep171 NFTs.

### Proof of Concept
`cargo test` in `contracts/defuse/core` (or `tests/src/tests/defuse/intents/token_diff.rs` in-sandbox):
1. Configure `Env::builder().fee(Pips::ONE_PERCENT)` (nonzero fee).
2. Build a `MultiPayload` for `user1` containing `K` (e.g. 100) `TokenDiff` intents, each `diff = {nep245_token_id: -1, nep141_token_id: +1}` — matched by a single counterparty `TokenDiff` intent (`user2`) with `diff = {nep245_token_id: +K, nep141_token_id: -K}`.
3. Execute via `execute_signed_intents`/`env.defuse_execute_intents` and read `fees_collected` from emitted `TokenDiffEvent`s (or the fee_collector's resulting Nep245 balance) — assert it equals `0`.
4. Build a second scenario: a single `TokenDiff` intent for `user1` with `diff = {nep245_token_id: -K, nep141_token_id: +K}` matched by `user2`'s equivalent single intent, and assert `fees_collected` equals `Pips::ONE_PERCENT.fee_ceil(K)` (`> 0`).
5. Assert the two `fees_collected` values differ, proving the aggregate binding `fees_collected == fee_ceil(sum of negative deltas)` is violated when the same net transfer is split into unit-size legs.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
