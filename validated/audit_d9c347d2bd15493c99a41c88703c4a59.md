Confirmed: Exchange (TRC10 AMM market) actions are NOT reachable from TVM/smart-contract execution — there is no `Exchange*` native-contract processor under `org.tron.core.vm.**`, so `ExchangeCreateContract`, `ExchangeInjectContract`, `ExchangeWithdrawContract`, and `ExchangeTransactionContract` can only be broadcast as top-level, separately-signed transactions, each requiring `ownerAddress` to be a valid, existing account per `DecodeUtil.addressValid` / `accountStore.has(ownerAddress)` checks in their respective actuators [1](#0-0) [2](#0-1) .

### Title
Exchange (TRC10 AMM) liquidity becomes permanently unrecoverable if the creator account is a contract that self-destructs - (File: actuator/src/main/java/org/tron/core/actuator/ExchangeWithdrawActuator.java)

### Summary
`ExchangeCreateActuator` allows any existing account — including a smart-contract account — to become the `creatorAddress` of an Exchange (TRON's on-chain TRC10 AMM pool), depositing `firstTokenBalance`/`secondTokenBalance` into the pool [3](#0-2) . Only that exact `creatorAddress` can later withdraw the pooled liquidity via `ExchangeWithdrawActuator`, which strictly checks `accountCapsule.getAddress().equals(exchangeCapsule.getCreatorAddress())` [4](#0-3) . Because Exchange operations have no corresponding TVM native-contract processor (unlike freeze/unfreeze/delegate, which are all reachable from `Program.java` via `org.tron.core.vm.nativecontract`), a contract can never internally call `exchangeWithdraw`/`exchangeTransaction` on itself; the only path to reclaim funds is a top-level transaction signed by the `creatorAddress` private key. If that creator is a contract account and the contract executes `SUICIDE`, the account is destroyed and its TRX balance is swept to the inheritor via `transferFrozenV2BalanceToInheritor`-style suicide handling in `Program.java`, but the Exchange pool's token balances (`firstTokenBalance`/`secondTokenBalance` inside the `ExchangeCapsule`) are untouched and orphaned, since nothing forces or even permits withdrawal before/at suicide time.

### Finding Description
1. Any account satisfying `accountStore.has(ownerAddress)` and holding sufficient balance can call `ExchangeCreateContract`, including a contract address, since `doValidate()` only checks address validity and balance, not account type [5](#0-4) .
2. The pool's assets are locked to the exact `creatorAddress` for withdrawal (`ExchangeWithdrawActuator.doValidate` at line 181-183) and for injection (`AbstractExchangeActuator`/`ExchangeInjectActuator` similarly ties operations to the creator, per test evidence such as `SameTokenNameCloseSuccessExchangeWithdraw`, `ExchangeInjectActuatorTest`).
3. There is no native-contract/precompile bridge letting a contract's own bytecode invoke `ExchangeWithdrawContract`/`ExchangeTransactionContract` internally (confirmed: no `Exchange` references anywhere under `org.tron.core.vm.**`), unlike freeze/unfreeze/delegate resource actions, which do have `nativecontract` processors reachable from `Program.java` (`withdrawReward()`, `withdrawExpireUnfreeze()`, etc.) [6](#0-5) .
4. Contract accounts in java-tron can be destroyed via the `SUICIDE` opcode handling in `Program.java`, which transfers remaining TRX/frozen balances to an inheritor but has no concept of "close my owned Exchange first" (see the analogous handling for frozen balances in `transferFrozenV2BalanceToInheritor`, which only deals with freeze/delegate/unfreeze state, not Exchange pools) [7](#0-6) .
5. Once the `creatorAddress` account is deleted from `AccountStore`, no transaction can ever again satisfy `accountStore.has(ownerAddress)` for that address as a top-level signer (a destroyed contract has no private key and no code path to re-originate a transaction), so `ExchangeWithdrawContract`/`ExchangeTransactionContract` for that Exchange ID become permanently unexecutable, and the tokens recorded in `ExchangeCapsule.firstTokenBalance`/`secondTokenBalance` are permanently unreachable — a stronger analog of the reported "vault leaves funds in protocol forever" pattern, since here there is no owner-controlled recovery mechanism at all (not even a privileged one), and the loss is unconditional and irreversible.

### Impact Explanation
Funds (TRX and/or TRC10 tokens) deposited into an Exchange pool by a contract account become permanently and irrecoverably locked once that contract self-destructs. This is a permanent freezing-of-funds bug: no account, including the contract owner, an admin, or a committee/witness, has any mechanism to reclaim or redistribute the stranded liquidity. Depending on pool size this can represent an unbounded, permanent loss of user/protocol funds.

### Likelihood Explanation
Reachable by any unprivileged party who deploys a contract, has it create (or become) an Exchange creator, and later self-destructs it (deliberately or as part of normal contract lifecycle/upgrade patterns that use `SUICIDE` for redeployment). No special privilege is required; deployment and triggering are both standard operations for any contract deployer/broadcaster.

### Recommendation
- Require the `SUICIDE`/self-destruct handling in `Program.java` to check whether the destroying address is the `creatorAddress` of any active Exchange in `ExchangeStore`/`ExchangeV2Store`, and either block suicide until the Exchange is closed/withdrawn, or force-withdraw the pool balances to the inheritor address as part of the suicide flow (mirroring how frozen/delegated balances are already transferred to the inheritor).
- Alternatively, disallow `ExchangeCreateContract` when `ownerAddress` corresponds to a contract account, or require exchange creation/withdrawal to be routed only through EOA-controlled addresses.

### Proof of Concept
1. Deploy contract `C`.
2. From `C`, broadcast an `ExchangeCreateContract` with `ownerAddress = C`, depositing TRX/TRC10 tokens into a new pool (`ExchangeCreateActuator.execute`).
3. Have `C` execute a `SUICIDE` opcode, destroying the account and sweeping its TRX balance to an inheritor via `Program.java`'s suicide/inheritance path.
4. Attempt to broadcast `ExchangeWithdrawContract`/`ExchangeTransactionContract` with `ownerAddress = C`: `accountStore.has(ownerAddress)` is now false, so the transaction can never validate; the Exchange pool balances recorded in `ExchangeCapsule` remain in `ExchangeStore`/`ExchangeV2Store` forever, unreachable by any account.

  private long transferFrozenV2BalanceToInheritor(byte[] ownerAddr, byte[] inheritorAddr, Repository repo) {
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddr);
    AccountCapsule inheritorCapsule = repo.getAccount(inheritorAddr);
    long now = repo.getHeadSlot();

    // transfer frozen resource
    ownerCapsule.getFrozenV2List().stream()
        .filter(freezeV2 -> freezeV2.getAmount() > 0)
        .forEach(
            freezeV2 -> {
              switch (freezeV2.getType()) {
                case BANDWIDTH:
                  inheritorCapsule.addFrozenBalanceForBandwidthV2(freezeV2.getAmount());
                  break;
                case ENERGY:
                  inheritorCapsule.addFrozenBalanceForEnergyV2(freezeV2.getAmount());
                  break;
                case TRON_POWER:
                  inheritorCapsule.addFrozenForTronPowerV2(freezeV2.getAmount());
                  break;
              }
            });

    // merge usage
    BandwidthProcessor bandwidthProcessor = new BandwidthProcessor(ChainBaseManager.getInstance());
    bandwidthProcessor.updateUsageForDelegated(ownerCapsule);
    ownerCapsule.setLatestConsumeTime(now);
    if (ownerCapsule.getNetUsage() > 0) {
      bandwidthProcessor.unDelegateIncrease(inheritorCapsule, ownerCapsule,
          ownerCapsule.getNetUsage(), BANDWIDTH, now);
    }

    EnergyProcessor energyProcessor =
        new EnergyProcessor(
            repo.getDynamicPropertiesStore(), ChainBaseManager.getInstance().getAccountStore());
    energyProcessor.updateUsage(ownerCapsule);
    ownerCapsule.setLatestConsumeTimeForEnergy(now);
    if (ownerCapsule.getEnergyUsage() > 0) {
      energyProcessor.unDelegateIncrease(inheritorCapsule, ownerCapsule,
          ownerCapsule.getEnergyUsage(), ENERGY, now);
    }

    // withdraw expire unfrozen balance
    long nowTimestamp = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    long expireUnfrozenBalance =
        ownerCapsule.getUnfrozenV2List().stream()
            .filter(
                unFreezeV2 ->
                    unFreezeV2.getUnfreezeAmount() > 0 && unFreezeV2.getUnfreezeExpireTime() <= nowTimestamp)
            .mapToLong(Protocol.Account.UnFreezeV2::getUnfreezeAmount)
            .sum();
    if (expireUnfrozenBalance > 0) {
      inheritorCapsule.setBalance(inheritorCapsule.getBalance() + expireUnfrozenBalance);
      increaseNonce();
      addInternalTx(null, ownerAddr, inheritorAddr, expireUnfrozenBalance, null,
          "withdrawExpireUnfreezeWhileSuiciding", nonce, null);
    }
    clearOwnerFreezeV2(ownerCapsule);
    repo.updateAccount(ownerCapsule.createDbKey(), ownerCapsule);
    repo.updateAccount(inheritorCapsule.createDbKey(), inheritorCapsule);
    return expireUnfrozenBalance;
  }

  public long withdrawExpireUnfreeze() {
    Repository repository = getContractState().newRepositoryChild();
    byte[] owner = getContextAddress();

    increaseNonce();
    InternalTransaction internalTx = addInternalTx(null, owner, owner, 0, null,
        "withdrawExpireUnfreeze", nonce, null);

    try {
      WithdrawExpireUnfreezeParam param = new WithdrawExpireUnfreezeParam();
      param.setOwnerAddress(owner);

      WithdrawExpireUnfreezeProcessor processor = new WithdrawExpireUnfreezeProcessor();
      processor.validate(param, repository);
      long expireUnfreezeBalance = processor.execute(param, repository);
      repository.commit();
      if (internalTx != null) {
        internalTx.setValue(expireUnfreezeBalance);
      }
      return expireUnfreezeBalance;
    } catch (ContractValidateException e) {
      logger.warn("TVM WithdrawExpireUnfreeze: validate failure. Reason: {}", e.getMessage());
    } catch (ContractExeException e) {
      logger.warn("TVM WithdrawExpireUnfreeze: execute failure. Reason: {}", e.getMessage());
    }
    if (internalTx != null) {
      internalTx.reject();
    }
    return 0;
  }
