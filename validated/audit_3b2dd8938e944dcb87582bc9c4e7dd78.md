### Title
Protocol fee bypass on `Nep245`/`Imt` token swaps via unit-sized `TokenDiff` decomposition - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` exempts `Nep245`/`Imt` token deltas from fees whenever the per-intent amount is `<= 1`. Since fees are computed per-`TokenDiff` intent (not aggregated across the whole batch), an attacker can split a single large NEP-245/IMT swap into many unit-amount `TokenDiff` intents inside one `MultiPayload` batch, paying zero fee on the whole trade instead of the fee owed on the full amount.

### Finding Description
The broken binding: `fees credited to fee_collector` should equal `Σ Pips::fee_ceil(protocol_fee, |delta|)` over the economic amount actually swapped, for every negative delta of every fungible-like token, regardless of how the trade is split into intents.

`Self::token_fee` decides the fee rate per single intent's delta amount: [1](#0-0) 

`TokenDiff::execute_intent` applies each token's delta directly to the signer's balance and computes/collects the fee using only that intent's own `delta`: [2](#0-1) 

Multiple `MultiPayload`s (even from the same or attacker-controlled accounts) are processed independently by `execute_signed_intent`, each with its own nonce/signature, but all their balance deltas are accumulated into a single shared `TransferMatcher` and only checked for net-zero at the very end via `finalize()`: [3](#0-2) [4](#0-3) 

Because the invariant check only requires the aggregate deltas (including any fee credited to `fee_collector`) to net to zero across the whole batch, and because `token_fee` returns `Pips::ZERO` whenever a single intent's `Nep245`/`Imt` delta has `|delta| <= 1`, an attacker with two accounts they control can execute an economically large swap (e.g., 1000 units of a `Nep245TokenId` sub-token) as 1000 separate signed `TokenDiff` intents, each moving exactly `amount = 1`. Every one of those 1000 intents independently hits the `amount <= 1` branch and returns `Pips::ZERO`, so no fee is ever computed or added to `fees_collected`, yet the aggregate transfer (1000 units, matched against the counterparty's 1000 opposite-unit intents) settles exactly as it would for one intent moving `amount = 1000` — except in that single-intent case `token_fee` takes the `TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}` branch and falls through to charge `fee`.

None of the existing guards address this: `MultiPayload::verify`/`has_public_key`/nonce commitment only validate signer authenticity and replay protection per payload, not per-intent amount; `TransferMatcher::finalize` only enforces net-zero delta conservation across the batch, which still holds because the fee itself is zero (no compensating amount is required); there is no per-batch or per-signer aggregation of `TokenDiff` amounts before calling `token_fee`.

### Impact Explanation
The `fee_collector`'s balance under-accumulates fees that would otherwise be owed on `Nep245`/`Imt` token swaps of any size, as long as the trade is decomposed into unit-sized intents. This directly matches "protocol fees bypassed" (Critical). The blast radius is any `Nep245`/`Imt` token registered in the Verifier that represents fungible-like value per unit (e.g., a low-decimal wrapped token minted as a multi-token sub-token) — any pair of cooperating accounts (which the attacker can both control) can swap it fee-free at arbitrary volume, repeatable across accounts, tokens, and batches with no cap other than transaction gas/size limits.

### Likelihood Explanation
No privileged role is required — any two attacker-controlled accounts with valid keys and Verifier balances of the target `Nep245`/`Imt` token can construct the batch of unit-delta `TokenDiff` intents and submit it via `execute_intents`. The cost is only the extra transaction/signing overhead of issuing N intents instead of 1 (out of scope per the rules to reject on gas/size grounds alone, but the exploit is otherwise fully reachable and repeatable with unprivileged capabilities).

### Recommendation
Compute and enforce the fee based on the total absolute amount moved per `(signer, token_id)` (or per token globally) across the entire batch/execution, not per individual `TokenDiff` intent, before deciding whether the `amount <= 1` NFT/MT exemption applies — e.g., aggregate deltas per token across all intents in `Engine::execute_signed_intents` prior to fee calculation, or move fee assessment to `TransferMatcher::finalize` where the true net transferred amount per token is known.

### Proof of Concept
`cargo test` in `contracts/defuse/core/src/intents/token_diff.rs` (or an integration test under `tests/src/tests/defuse/intents/token_diff.rs`, using the existing `Env`/`test_ft_diffs` sandbox harness for signing/executing `MultiPayload`s):

1. Register a `Nep245TokenId` sub-token in the Verifier for two attacker-controlled accounts `A` and `B`, deposit balances such that `A` has `1000` units and `B` has `0`.
2. **Baseline (single intent):** Sign one `TokenDiff` from `A` with `diff = {token: -1000}` and one `TokenDiff` from `B` with `diff = {token: +1000}` (or the closure-adjusted counterpart), submit as one `MultiPayload` batch, execute via `execute_intents`, and assert `fee_collector` balance for `token` equals `protocol_fee.fee_ceil(1000)` (nonzero for `fee != Pips::ZERO`).
3. **Decomposed (1000 unit intents):** Sign 1000 separate `TokenDiff` intents from `A`, each `diff = {token: -1}`, and 1000 separate `TokenDiff` intents from `B`, each `diff = {token: +1}` (each with distinct nonces), bundle all 2000 signed payloads into one `MultiPayload` batch, execute via `execute_intents`.
4. Assert that in step 3 `fee_collector`'s balance for `token` is `0`, while `A`'s and `B`'s balances end up identical to step 2 (i.e., the same net 1000-unit transfer occurred), demonstrating `Self::token_fee` returning `Pips::ZERO` on every intent and the total collected fee being `0 != protocol_fee.fee_ceil(1000)` from step 2 — proving the fee bypass.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
