### Title
Unstaked attacker can starve global QUIC handshake slots via repeated slow-handshake connections, since neither per-IP nor global connection rate limiters gate incomplete handshakes - (File: streamer/src/nonblocking/quic.rs)

### Summary
The pre-handshake admission checks in `run_server` (per-IP `ConnectionRateLimiter::is_allowed` and the global `overall_connection_rate_limiter.current_tokens()` check) only consult token buckets that are populated/consumed *after* a handshake successfully completes, via `register_connection`/`consume_tokens` inside `setup_connection`. An attacker who never lets the handshake complete never triggers those consumption paths, so these rate limiters never actually throttle them. The only remaining backstop is the global `ClientConnectionTracker` cap (`qos.max_concurrent_connections()`) combined with the 2-second `QUIC_CONNECTION_HANDSHAKE_TIMEOUT`, letting one attacker occupy all connection slots indefinitely by cycling stalled handshakes roughly every 2 seconds.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:304-411`), for every accepted `incoming` connection, before a `ClientConnectionTracker` is allocated, the server performs:

1. A global check: `if overall_connection_rate_limiter.current_tokens() == 0 { ... incoming.ignore(); continue; }` [1](#0-0) 
2. A per-IP check: `if !rate_limiter.is_allowed(&incoming.remote_address().ip()) { ... incoming.ignore(); continue; }` [2](#0-1) 

Both of these are non-mutating "peek" checks against `TokenBucket`/`KeyedRateLimiter` state. The tokens are only actually consumed later, inside `setup_connection`, and only on the success branch *after* the handshake completes:
- `rate_limiter.register_connection(&from.ip())` [3](#0-2) 
- `overall_connection_rate_limiter.consume_tokens(1)` [4](#0-3) 

Critically, `ConnectionRateLimiter::is_allowed` explicitly returns `true` when the IP has no prior record: "if we have not seen IP, allow connection request" [5](#0-4) . Since `register_connection` is never invoked for an IP whose handshakes never finish, that IP's bucket is never created/decremented, and `is_allowed` keeps returning `true` forever for repeated attempts from that same IP. Likewise, `overall_connection_rate_limiter.consume_tokens` is only called after success, so incomplete handshakes never draw down the global bucket either.

After passing these no-op checks, the server allocates a `ClientConnectionTracker`, which is the actual global admission gate bounded by `qos.max_concurrent_connections()`: `ClientConnectionTracker::new` increments `stats.open_connections` and fails once `open_connections >= max_concurrent_connections`, causing `refused_connections_too_many_open_connections` to be incremented for the next caller [6](#0-5) [7](#0-6) .

Once a tracker is allocated, `setup_connection` is spawned and waits `timeout(QUIC_CONNECTION_HANDSHAKE_TIMEOUT, connecting)`, where `QUIC_CONNECTION_HANDSHAKE_TIMEOUT = Duration::from_secs(2)` [8](#0-7) [9](#0-8) . If the handshake never completes, the tracker is dropped after 2 seconds (decrementing `open_connections`), and `connection_setup_timeout` is incremented [10](#0-9) .

Because none of the rate limiters that gate admission before tracker allocation are ever charged against an attacker who deliberately stalls the handshake (e.g., sends the QUIC Initial packet but withholds/delays the TLS ClientHello completion or crypto frames), a single unstaked attacker IP can:
- Open a new connection attempt roughly every time a prior stalled tracker frees up (~every 2 s per attempt, but attempts can be pipelined up to `max_concurrent_connections` in parallel),
- Keep all `max_concurrent_connections` global tracker slots continuously occupied by stalled handshakes,
- Never be blocked by `rate_limiter.is_allowed()` or `overall_connection_rate_limiter.current_tokens()`, because those are only decremented on handshake success.

This denies handshake slots to legitimate staked/unstaked senders, whose `incoming` connections get refused via the `ClientConnectionTracker::new` failure path (`refused_connections_too_many_open_connections`), matching the scoped impact in the question.

### Impact Explanation
This is a QoS-bypass / availability denial: an unprivileged, unstaked remote attacker consumes the shared, global handshake-slot budget (`max_concurrent_connections`) indefinitely at negligible cost (never completing a single real handshake), causing legitimate staked and unstaked senders to be refused (`refused_connections_too_many_open_connections`) and their transactions to never reach `packet_batch_sender`/sigverify/scheduling. It falls under the Agave "TPU QoS bypass/starvation" / node availability bounty category, since the invariant that "ingress buffers/connection slots stay bounded regardless of attacker behavior and cannot be starved by incomplete streams" is broken: the design intends per-IP and global rate limiters to bound attempts even before a handshake completes, but the implementation only charges those buckets on success, defeating that intent.

### Likelihood Explanation
Highly feasible and repeatable: it requires only a standard QUIC/UDP client capable of initiating (but stalling) the TLS handshake within the `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` window (2 seconds) — e.g., sending an Initial packet and withholding subsequent crypto handshake frames, or an artificially slow ClientHello. No staking, gossip presence, or leader control is needed; only the ability to reach the leader's public TPU QUIC port, which is the stated attacker capability. The attacker can sustain the DoS indefinitely from a single IP by re-issuing stalled connection attempts as fast as `max_concurrent_connections` slots free up (every ~2 s), since neither of the two pre-tracker rate limiters ever penalizes it.

### Recommendation
Charge rate-limiter tokens (both per-IP and global) at connection-attempt time (when `incoming` is observed / when the `ClientConnectionTracker` is allocated), not only after a successful handshake. Concretely:
- Call `rate_limiter.register_connection(&ip)`/consume tokens as part of the admission check at line 358-369, prior to `ClientConnectionTracker::new`, rather than deferring consumption to `setup_connection`'s success branch.
- Similarly consume from `overall_connection_rate_limiter` at attempt time, not only on success.
- Optionally add a dedicated (address-only, pre-handshake) attempt-rate cap so that spoofed-looking or CIDR-based abuse is bounded even before "control-asserted" ip is proven, without breaking the current commented rationale about not penalizing spoofed IPs before ownership is proven — e.g., separate small buckets for "attempts" vs. "confirmed connections," with the confirmed bucket kept as-is and the attempt bucket capped tightly per IP within `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` windows.

### Proof of Concept
Integration test plan (in `streamer/src/nonblocking/quic.rs` test module, using existing `setup_quic_server` test harness):

```rust
#[tokio::test(flavor = "multi_thread")]
async fn test_slow_handshake_starves_connection_slots() {
    agave_logger::setup();
    let SpawnTestServerResult {
        join_handle, receiver, server_address, stats, cancel,
    } = setup_quic_server(
        None,
        QuicStreamerConfig::default_for_tests(),
        SwQosConfig { max_unstaked_connections: 4, ..SwQosConfig::default_for_tests() },
    );

    // Attacker: repeatedly open raw UDP "Initial" packets toward server_address
    // from the SAME source IP, deliberately never completing the QUIC crypto
    // handshake (e.g. send Initial only, no further frames), cycling every
    // < QUIC_CONNECTION_HANDSHAKE_TIMEOUT so slots are immediately re-taken
    // once freed. Repeat continuously for several seconds.
    let attacker_task = tokio::spawn(async move {
        loop {
            spawn_stalled_quic_handshake(server_address).await; // never completes
            tokio::time::sleep(Duration::from_millis(50)).await;
        }
    });

    // Legitimate fast client attempts a normal handshake concurrently.
    tokio::time::sleep(Duration::from_millis(500)).await;
    let legit_result = timeout(
        Duration::from_secs(1),
        make_client_endpoint(&server_address, None),
    ).await;

    // Assert the legitimate client is refused/delayed while attacker's
    // connections never complete.
    assert!(legit_result.is_err() || stats.refused_connections_too_many_open_connections
        .load(Ordering::Relaxed) > 0);
    assert_eq!(stats.total_new_connections.load(Ordering::Relaxed), 0 /* attacker had none */);

    attacker_task.abort();
    cancel.cancel();
    drop(receiver);
    join_handle.await.unwrap();
}
```

Unit-level PoC for the rate-limiter gap itself (`streamer/src/nonblocking/connection_rate_limiter.rs`):
```rust
#[test]
fn test_is_allowed_never_penalizes_unconfirmed_repeated_attempts() {
    let limiter = ConnectionRateLimiter::new(1, 1, 4);
    let ip = IpAddr::V4(Ipv4Addr::new(10, 0, 0, 1));
    // Simulate 1000 stalled-handshake attempts from the same IP that never
    // call register_connection (i.e., never succeed).
    for _ in 0..1000 {
        assert!(limiter.is_allowed(&ip), "attempt should never be throttled without a completed handshake");
    }
}
```
Expected assertion: `is_allowed` returns `true` for all 1000 iterations, proving the per-IP limiter never engages for an attacker whose handshakes never complete, matching the described DoS window against `ClientConnectionTracker`/`max_concurrent_connections`.

    /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }
