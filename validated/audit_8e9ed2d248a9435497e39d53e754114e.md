### Title
Unauthenticated `/shutdown` and event POSTs on `SignerEventReceiver::next_event` allow state poisoning and permanent DoS - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` dispatches `/status`, `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/shutdown`, and `/new_block` to `process_event`/`forward_event` without verifying that the sender is the configured node, and `/shutdown` unconditionally sets `stop_signal` and returns `EventError::Terminated`, which permanently ends the receiver's `main_loop`. Any TCP client that can reach the bound event port can inject forged `NewBurnBlock`/`NewBlock`/`StackerDBChunksEvent`-wrapped events into the runloop and then kill the receiver so no further (legitimate) event ever corrects the state.

### Finding Description
In `next_event` (`libsigner/src/events.rs:413-459`), the URL match performs no authentication check at all — no shared secret, no TLS client cert, no source-IP allow-list — before calling `process_event::<T,E>(request)` for `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, or before directly flipping `stop_signal` for `/shutdown`: [1](#0-0) 

`process_event` only checks that the JSON body deserializes into the expected type (`E: serde::de::DeserializeOwned`); it performs no signature/identity verification of the request's origin: [2](#0-1) 

Successfully parsed events go straight to `forward_event`, which sends them into the mpsc channel consumed by the signer runloop with no further gating: [3](#0-2) 

The `EventReceiver::main_loop` treats `EventError::Terminated` (returned only from the `/shutdown` branch) as a hard break, permanently ending the receive loop for that thread: [4](#0-3) 

Because `HttpServer` (`tiny_http`) accepts connections from any TCP peer that can reach the socket, and none of the URL branches authenticate the caller, an attacker who can open a TCP connection to the bound port can: (1) POST a forged `/new_burn_block` body that deserializes to `BurnBlockEvent`, which is converted via `TryFrom<BurnBlockEvent> for SignerEvent<T>` (`libsigner/src/events.rs:637-649`) into a `SignerEvent::NewBurnBlock` carrying attacker-chosen `burn_height`/`consensus_hash`/hashes and forwarded to the runloop unchanged; then (2) POST `/shutdown`, which sets `stop_signal` and returns `Err(EventError::Terminated)`, ending `main_loop` for good. The event-receiver thread does not restart itself; `Signer::spawn` (`libsigner/src/runloop.rs:209-256`) spawns the event thread exactly once, so once it exits, the process needs an external supervisor/operator restart to resume receiving legitimate node events — the poisoned state delivered just before `/shutdown` is never corrected by a subsequent legitimate message.

The codebase itself documents this as a known trust-boundary limitation rather than validating it away: `SpawnedSigner::new` logs a warning that "the signer is primarily designed for use with a local or subnet network stacks node" and cautions about exposing it externally without additional security checks: [5](#0-4) 

No existing guard (auth token, TLS, per-connection allow-list) sits in front of `next_event`'s dispatch table, so the equality claimed in the question — "every actuating message the runloop receives should equal one sent by that node" — is broken: it equals whatever any TCP client sends to the port.

### Impact Explanation
An attacker with only TCP reachability to the signer's event-listener port can (a) inject arbitrary forged `SignerEvent::NewBurnBlock`/`NewBlock`/`StackerDBChunksEvent`-derived data into the signer runloop's view of chain state via unauthenticated POSTs, and (b) permanently halt the event receiver via a single unauthenticated `/shutdown` POST, preventing any further correction of that poisoned state until an operator manually restarts the signer process. This is a combined unauthenticated state-injection + permanent-DoS at the signer's transport layer, matching the "remote crash/unauthenticated DoS from few messages" and "unauthenticated/unauthorized write to state" Critical categories. It is fully repeatable against any signer whose event port is reachable.

### Likelihood Explanation
The only precondition is TCP reachability to the bound event-listener port (default `0.0.0.0:30000` per `sample/conf/signer/mainnet-signer-conf.toml:39`, i.e., not restricted to loopback by the sample config) — no secret, no privileged role, no valid StackerDB slot or peer key is required. The attack requires only two crafted HTTP POST requests (crafted JSON body for `/new_burn_block`, then a bare `/shutdown` POST as used by `SignerStopSignaler::send`, `libsigner/src/events.rs:376-396`), making attacker cost minimal and the exploit trivially repeatable.

### Recommendation
Require authentication on every actuating endpoint in `SignerEventReceiver::next_event` before calling `process_event` or acting on `/shutdown` — e.g., a shared-secret header/token (mirroring the node's `auth_token`/signer's `auth_password` pairing already used for the reverse direction), or bind/restrict the listener to loopback/mutually-authenticated channels only, and reject/return 401 for unauthenticated requests instead of processing them. Additionally, consider having `main_loop`/`Signer::spawn` auto-rebind and restart the event thread rather than permanently terminating the process on a single `/shutdown` signal from an unauthenticated source.

### Proof of Concept
1. Start a `SignerEventReceiver::<T>` bound to `127.0.0.1:PORT` via `bind()`, register a consumer channel with `add_consumer`, and run `main_loop()` in a thread (mirroring `libsigner/src/tests/mod.rs`'s `test_simple_signer` setup, `libsigner/src/tests/mod.rs:89-148`).
2. From a plain `TcpStream::connect` unrelated to any configured node, send:
   ```
   POST /new_burn_block HTTP/1.1\r\nHost: 127.0.0.1:PORT\r\nConnection: close\r\nContent-Type: application/json\r\nContent-Length: N\r\n\r\n{<forged BurnBlockEvent JSON with attacker burn_height>}
   ```
3. Assert the consumer channel receives `SignerEvent::NewBurnBlock { burn_height: <forged value>, .. }`.
4. From the same or a new `TcpStream`, send:
   ```
   POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1:PORT\r\nConnection: close\r\nContent-Length: 0\r\n\r\n
   ```
5. Assert that `main_loop` exits (e.g., the spawned thread finishes/joins) and that any subsequent legitimate POST to `/new_burn_block` from a "real" simulated node is never delivered to the channel (`recv_timeout` times out), proving the DoS is permanent for that receiver instance.

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
