### Title
Signer's event-receiver HTTP endpoint accepts unauthenticated pushed events, enabling forged StackerDB/tenure/burn-block data injection - ([File: libsigner/src/events.rs])

### Summary
The signer-side `SignerEventReceiver` (`libsigner/src/events.rs`) runs a plaintext HTTP server that the Stacks node is expected to `POST` events to (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/status`, `/shutdown`). Unlike every comparable node-side RPC endpoint in `stackslib/src/net/api/**` (e.g. `postblock_proposal`, `postblock_v3`, `blockreplay`, `blocksimulate`, `fastcallreadonly`, `txsimulate`), which all validate an `authorization` header against a configured shared secret before processing the request, the signer's event receiver performs **no authentication check whatsoever** on any inbound request.

### Finding Description
`SignerEventReceiver::next_event()` dispatches purely on the HTTP method/URL, with zero credential verification: [1](#0-0) 

Compare this to how every equivalent node-facing HTTP handler in `stackslib` gates access with an `authorization` header check before parsing the body, e.g.: [2](#0-1) [3](#0-2) 

The `SignerEventReceiver::bind()` simply opens a plain `tiny_http`-style HTTP server on the configured socket with no TLS, no token, and no peer-address restriction: [4](#0-3) 

Sample/reference configuration shows this endpoint is explicitly configurable to bind on all interfaces (`endpoint = "0.0.0.0:30000"`), which is documented as needing to match the node's `[[events_observer]] endpoint`, i.e. it is meant to be reachable at least from the node's network path: [5](#0-4) 

Any host that can reach the bound port can `POST` a fabricated `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` JSON payload and have it accepted and forwarded into the signer's `main_loop` / `forward_event` pipeline exactly as if it originated from the paired, trusted stacks-node: [6](#0-5) 

This breaks the equality the design implicitly assumes: "event received on this socket" == "event authentically sent by the configured stacks-node". There is no HMAC/shared-secret/mTLS/IP-allowlist check anywhere in `libsigner/src/http.rs` or `libsigner/src/events.rs` to enforce that equality — a `grep` for `authorization`/`auth_token` in `libsigner/**` returns no results.

### Impact Explanation
This is a remote, unauthenticated write into signer state that can inject forged data feeding directly into downstream signer processing (burn-block view, tenure/block events, StackerDB chunk events). While the actual acceptance/validation of individual chunk signatures happens later (in signer decision logic, which is out of scope), the transport-level gate itself is completely absent — an attacker does not need any key, credential, or role to reach and successfully post to this endpoint if it is bound to a non-loopback address, which the shipped reference configuration explicitly supports. This matches the "unauthenticated/unauthorized write to state" and "forged data" impact classes.

### Likelihood Explanation
High for any deployment where the signer's `endpoint` is bound on a reachable interface (0.0.0.0 or a routable IP), which is explicitly documented/supported in the reference config files. No credentials, keys, or prior access are required — a single unauthenticated HTTP POST suffices.

### Recommendation
Add a shared-secret authentication check (mirroring the `authorization` header pattern already used by `stackslib`'s `postblock_v3`/`postblock_proposal`/`blockreplay` handlers) to `SignerEventReceiver::next_event()` before processing any event, and/or restrict the listener to loopback by default with an explicit opt-in for non-local binding. At minimum, require and verify an `Authorization`/shared-secret header matching the node-side `auth_token` before invoking `process_event`.

### Proof of Concept
Given a signer configured with `endpoint = "0.0.0.0:30000"` (as shown in the shipped reference config), from any remote host reachable to that port:
```
POST /new_burn_block HTTP/1.1
Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <n>

{ ...forged BurnBlockEvent JSON... }
```
This is processed by `next_event()` → `process_event::<T, BurnBlockEvent>(request)` with no credential check, and forwarded into the signer's event pipeline exactly as if it came from the trusted stacks-node, as shown in the existing test harness which itself performs the identical unauthenticated POST flow from a "mock" node: [7](#0-6)

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }
}

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
