### Title
Unvalidated remote Attachment content is unconditionally stored via `AttachmentsDownloader::run` Done-arm - ([File: stackslib/src/net/atlas/download.rs])

### Summary
`AttachmentsBatchStateContext::extend_with_attachments` inserts the `Attachment` from a peer's `GetAttachmentResponse` into `self.attachments` without ever verifying that `attachment.hash()` equals the `content_hash` that was requested (`AttachmentRequest.content_hash`). The Done-arm of `AttachmentsDownloader::run` then unconditionally calls `network.atlasdb.insert_instantiated_attachment(&attachment)` for every drained attachment, regardless of whether `find_all_attachment_instances(&attachment.hash())` returned any rows, so arbitrary attacker-chosen content gets persisted into the `attachments` table with `was_instantiated = 1` with no corresponding on-chain `AttachmentInstance` commitment.

### Finding Description
The claimed equality "attachment stored == attachment referenced by a confirmed `AttachmentInstance.content_hash`" is broken. Trace:

1. `AttachmentsBatchStateContext::get_prioritized_attachments_requests` builds an `AttachmentRequest{ content_hash, sources, .. }` for a hash that is missing locally [1](#0-0) .
2. The request is sent to peers and the response is decoded via `decode_atlas_get_attachment()`; in `extend_with_attachments`, the resulting `response.attachment` is inserted into `self.attachments` (a `HashSet<Attachment>`) with **no comparison** of `attachment.hash()` against `request.content_hash` [2](#0-1) .
3. In `AttachmentsDownloader::run`, the `Done` arm drains `context.attachments` and, for each one, looks up `find_all_attachment_instances(&attachment.hash())` but calls `insert_instantiated_attachment(&attachment)` unconditionally, irrespective of whether that lookup returned any matching instance [3](#0-2) .
4. `AtlasDB::insert_instantiated_attachment` performs an `INSERT OR REPLACE` into the `attachments` table with `was_instantiated = 1` and only opportunistically updates `attachment_instances.is_available` if a matching `content_hash`/`Checked` row exists — the insert into `attachments` itself is unconditional [4](#0-3) .

Because the remote peer serving the `AttachmentRequest` response fully controls the `Attachment` content and the code never checks `attachment.hash() == request.content_hash` before adding it to the batch set, any peer selected as a data source (a node need only be an outbound sync peer reachable over its data URL) can return arbitrary bytes as the "attachment" and have it durably written into the local node's Atlas attachments table, with no confirmed `AttachmentInstance` ever pointing at that hash.

### Impact Explanation
An attacker-controlled peer can cause the victim node to persist arbitrary attacker-chosen blobs into its `attachments` SQLite table via `insert_instantiated_attachment`, repeatable once per distinct fabricated hash/content pair, and bounded only by `max_uninstantiated_attachments`/eviction logic for the uninstantiated path — but here the entry lands directly as `was_instantiated = 1`, bypassing the uninstantiated-attachment eviction cap entirely. This is attachment storage that has no corresponding consensus commitment (no matching `AttachmentInstance.content_hash` row), matching the "attachment/BNS mismatch" High-impact category: storage growth untied to any confirmed on-chain reference, and there is no explicit cap or eviction routine for `was_instantiated = 1` rows analogous to `evict_k_oldest_uninstantiated_attachments`.

### Likelihood Explanation
Preconditions are modest: the attacker's node must be selected as an outbound sync peer with a resolvable data URL so it is asked for attachments (a normal, unprivileged peer role), and it must respond to a legitimate `AttachmentRequest` with fabricated content instead of the real attachment. No secret, no privileged role, and no consensus data are required — the attacker just needs to be a reachable peer that participates in the standard Atlas download protocol. This is fully repeatable per attachment request cycle.

### Recommendation
In `AttachmentsBatchStateContext::extend_with_attachments`, verify `response.attachment.hash() == request.content_hash` before inserting into `self.attachments`; drop/penalize (bump `report.bump_failed_requests()`) responses that fail this check. Additionally, in the `Done` arm of `AttachmentsDownloader::run`, only call `insert_instantiated_attachment` when `find_all_attachment_instances(&attachment.hash())` is non-empty (or when the hash check above already guarantees correctness), so unmatched attachments are not persisted as validated content.

### Proof of Concept
Rust test plan (in `stackslib/src/net/atlas/tests.rs` or a new `download` test module):
1. Construct an `AttachmentsBatchStateContext` and an `AttachmentRequest` with a known `content_hash` `H_expected`.
2. Simulate a peer response containing a `GetAttachmentResponse` whose `attachment.content` is arbitrary bytes such that `attachment.hash() != H_expected` (call this `H_fake`).
3. Call `extend_with_attachments` with this crafted `BatchedRequestsResult` and assert `context.attachments` contains the fabricated attachment (i.e., no rejection occurred).
4. Run the `Done`-arm logic path (or directly replicate it) with `network.atlasdb.find_all_attachment_instances(&H_fake)` returning an empty `Vec` (no `attachment_instances` row for `H_fake` was ever inserted).
5. Call `network.atlasdb.insert_instantiated_attachment(&attachment)` as the Done-arm does, then query `SELECT * FROM attachments WHERE hash = ?` for `H_fake` and assert a row exists with `was_instantiated = 1`, proving storage occurred despite `find_all_attachment_instances` returning empty — confirming the broken equality.

    pub fn get_prioritized_attachments_requests(&self) -> BinaryHeap<AttachmentRequest> {
        let mut queue = BinaryHeap::new();
        let mut enqueued = HashSet::new();
        for ((contract_id, pages, _), peers_responses) in self.inventories.iter() {
            let missing_attachments = match self
                .attachments_batch
                .attachments_instances
                .get(contract_id)
            {
                None => continue,
                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }

    pub fn insert_instantiated_attachment(
        &mut self,
        attachment: &Attachment,
    ) -> Result<(), db_error> {
        let now = util::get_epoch_time_secs() as i64;
        let tx = self.tx_begin()?;
        tx.execute(
            "INSERT OR REPLACE INTO attachments (hash, content, was_instantiated, created_at) VALUES (?, ?, 1, ?)",
            params![attachment.hash(), attachment.content, now],
        )?;
        tx.execute(
            "UPDATE attachment_instances SET is_available = 1 WHERE content_hash = ?1 AND status = ?2",
            params![attachment.hash(), AttachmentInstanceStatus::Checked],
        )?;
        tx.commit()?;
        Ok(())
    }
