This confirms the finding: the sample configs bind `endpoint = "0.0.0.0:30000"` (mainnet-signer-conf.toml, mainnet-signer.toml, testnet-signer.toml), i.e., the signer's event-receiver HTTP server is documented to listen on all interfaces, not just loopback, and the code contains an explicit warning about exposure to external networks (`stacks-signer/src/lib.rs:125-132`). The `next_event` dispatch performs no authentication check on the incoming request before acting on `/shutdown`.

### Title
Unauthenticated remote DoS via `/shutdown` HTTP request to `SignerEventReceiver::next_event` - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` dispatches on `request.url()` string equality with no check of the request's source, credentials, or any shared secret. Any TCP client that can reach the bound HTTP server's address can send `POST /shutdown HTTP/1.1` and cause the receiver's `stop_signal` to be set, terminating the signer's event-receiver `main_loop` and halting event processing.

### Finding Description
The intended invariant is that only the local node process calling `SignerStopSignaler::send` (libsigner/src/events.rs:378-395) can cause `EventReceiver::is_stopped()` to become true. In practice, `next_event` (libsigner/src/events.rs:413-459) matches on `request.url() == "/shutdown"` and unconditionally executes `event_receiver.stop_signal.store(true, Ordering::SeqCst)` (line 444) with no verification of an auth token, source IP, or any credential — unlike the node's block-proposal/RPC path, which uses `auth_password`/`auth_token` (see `sample/conf/signer/mainnet-signer-conf.toml:45-50`). Any TCP client that can open a connection to the bound `HttpServer` (`tiny_http`) and write bytes matching exactly the format `SignerStopSignaler::send` itself uses (`"POST /shutdown HTTP/1.1\r\nHost: ...\r\nConnection: close\r\nContent-Length: ...\r\n\r\n..."`, lines 385-390) triggers the same code path, because the server has no way to distinguish the legitimate local signaler's request from an attacker's. The equality "party allowed to call `SignerStopSignaler::send`" == "party who can trigger `stop_signal==true`" is broken: the set of parties who can reach the listening socket and send this exact HTTP request is any TCP peer with network reachability, not just the co-located node process.

The event-receiver's `endpoint` is explicitly documented and configured to bind on `0.0.0.0` in the shipped reference configs (`sample/conf/signer/mainnet-signer-conf.toml:39` `endpoint = "0.0.0.0:30000"`, `sample/conf/mainnet-signer.toml:27`, `sample/conf/testnet-signer.toml:36`), and the code itself warns at startup that communicating with an external node "could potentially expose sensitive data or functionalities to security risks if additional proper security checks are not integrated" (`stacks-signer/src/lib.rs:125-132`). This confirms the socket is meant to be reachable beyond localhost in typical/documented deployments, making the unauthenticated `/shutdown` path remotely reachable by an unprivileged network attacker with no secret, no signer-slot ownership, and no local access required.

### Impact Explanation
A single crafted `POST /shutdown` HTTP request permanently halts the target signer's `SignerEventReceiver::main_loop` (libsigner/src/events.rs:284-312): the loop calls `next_event`, sees `EventError::Terminated`, and `break`s, after which the receiver never processes `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block` events again. This is an unauthenticated, single-message, remote denial-of-service against a signer node, matching the "Critical - remote crash/unauthenticated DoS from few messages" category. It is trivially repeatable against every signer whose event-receiver port is reachable, and could be used to knock signers offline during critical signing windows.

### Likelihood Explanation
No preconditions beyond network reachability to the signer's `endpoint` port are required — no auth token, no signer key, no StackerDB slot ownership, no peer registration. The attacker cost is a single raw TCP write of a short, publicly-known HTTP request (the exact same format is present in this file at lines 385-390). The reference/sample configs bind this endpoint to `0.0.0.0`, and the codebase's own runtime warning acknowledges the risk of exposing this port to non-local networks.

### Recommendation
Require authentication for `/shutdown` (and ideally all POST endpoints) on `SignerEventReceiver`, e.g., reuse `auth_password`/a shared secret checked via a header, or bind the shutdown mechanism to a loopback-only side channel / Unix socket / in-process signal instead of an HTTP request distinguishable only by its URL. At minimum, verify the request originates from `127.0.0.1`/the local host before honoring `/shutdown`, and reject it otherwise.

fn test_unauthenticated_remote_shutdown() {

        SignerEventReceiver::new(false);

    let bound = receiver.bind(addr).unwrap();

    // Simulate an unprivileged remote TCP client (no auth, no secret)

        bound, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    let handle = thread::spawn(move || receiver.main_loop());
    handle.join().unwrap(); // main_loop terminates from the unauthenticated request

    // Assertion: is_stopped() became true purely from an unauthenticated remote TCP write,
    // with no credential ever presented, proving the broken equality.
}
