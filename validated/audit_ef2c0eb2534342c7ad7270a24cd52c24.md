### Title
No vulnerability found — nonce replay via re-entrant `AuthCall` does not bypass `Nonces::commit` - ([File: contracts/defuse/src/contract/intents/mod.rs])

### Summary
The claimed race does not exist. `Contract` (not `CachedState`) directly implements `State`, so `commit_nonce` writes straight to persistent NEAR contract storage within the original receipt, before that receipt finishes. NEAR's execution model guarantees a receipt's state changes are durably applied before any receipt it spawned (like the detached `do_auth_call` promise's `on_auth` callback) executes, so any later `execute_intents` call — reentrant or not — reads storage that already reflects the nonce as used.

### Finding Description
The binding to validate: `count(successful commit_nonce(signer_id, nonce)) == 1` across all receipts. Trace: `execute_intents` (contracts/defuse/src/contract/intents/mod.rs:27-30) builds `Engine::new(self, ExecuteInspector::default())` with `self: &mut Contract`. `Contract`'s `State::commit_nonce` (contracts/defuse/src/contract/intents/state.rs:123-130) calls straight into `self.accounts.get_or_create(...).commit_nonce(nonce)`, which ultimately calls `Nonces::commit` (contracts/defuse/core/src/nonce/mod.rs:38-45), operating on a `near_sdk` persistent collection (`LookupMap`/bitmap), not an in-memory-only cache. This is fundamentally different from `simulate_intents` (mod.rs:45-47), which uses `self.cached()` → `CachedState`, an in-memory overlay used only for view calls that never persists.

For `AuthCall`, `auth_call()` (contracts/defuse/src/contract/intents/state.rs:303-336) schedules `Self::do_auth_call(...)` as a detached `Promise` (`.detach()` at line 334). Per NEAR's execution model, a scheduled promise only becomes a receipt that executes *after* the current receipt (including all its state writes) has finished and been committed to the block's resulting state root. `do_auth_call` (contracts/defuse/src/contract/intents/auth_call.rs:17-37) itself does not call `execute_intents`; it calls the external callee's `on_auth`. Even in the attacker's constructed scenario where the callee turns around and cross-contract-calls back into `intents.near::execute_intents` with a reused nonce, that call executes as a fresh receipt, reading `Contract`'s persisted state via `CachedState::is_nonce_used`/`commit_nonce` (contracts/defuse/core/src/engine/state/cached.rs:91-96, 172-184), which first checks `self.view.is_nonce_used(...)` — and `self.view` here is the live `Contract` whose storage already has the bit set from the original commit. Thus `commit_nonce` returns `Err(DefuseError::NonceUsed)` immediately, before any further intent processing, matching `Nonces::commit`'s bitmap semantics (`BitMap256::set_bit` returning `true` if already set) at contracts/defuse/core/src/nonce/mod.rs:39-42.

No divergence exists: durable NEAR storage semantics guarantee the nonce bit set in receipt N is visible to any receipt N+k (k≥1) that reads the same contract's storage, regardless of whether that later receipt was triggered synchronously in transaction terms or asynchronously via a detached cross-contract promise chain.

### Impact Explanation
None. No tokens are moved, no signature is bypassed, no double-settlement occurs. The nonce anti-replay mechanism holds exactly as designed across receipt boundaries, which is the fundamental (and correctly implemented) property NEAR persistent storage was designed to guarantee.

    #[private]
    pub fn do_auth_call(signer_id: AccountId, auth_call: AuthCall) -> Promise {
        if !auth_call.attached_deposit.is_zero() {
            require!(
                promise_result_checked_void(0).is_ok(),
                "near_withdraw failed",
            );
        }

        let min_gas = auth_call.min_gas();
        let mut p = Promise::new(auth_call.contract_id);

        if let Some(state_init) = auth_call.state_init {
            p = p.state_init(state_init, NearToken::ZERO);
        }

        ext_auth_callee::ext_on(p)
            .with_attached_deposit(auth_call.attached_deposit)
            .with_static_gas(min_gas)
            .on_auth(signer_id, auth_call.msg)
    }
