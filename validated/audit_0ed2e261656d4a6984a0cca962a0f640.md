Audit Report

## Title
Snowbridge outbound-queue `calculate_fee` can round the remote relayer reward to zero for legitimately-priced messages, allowing underpriced bridge delivery - (File: bridges/snowbridge/pallets/outbound-queue/src/lib.rs)

## Summary
`Pallet::calculate_fee` derives the DOT/KSM-denominated relayer reward by treating a raw wei integer as the inner value of a `FixedU128`, multiplying/dividing by `multiplier`/`exchange_rate`, then dividing again by a decimal-adjustment denominator in `convert_from_ether_decimals`. When the resulting wei-denominated intermediate value is smaller than that denominator, the final integer division silently truncates the relayer reward to zero even though `PricingParameters::validate()` confirms all parameters are non-zero.

## Finding Description
`calculate_fee` computes the remote fee via `calculate_remote_fee` (`fee_per_gas * gas_used_at_most + reward`), wraps it in `FixedU128::from_inner`, applies `saturating_mul(multiplier)` and `checked_div(&exchange_rate)`, then passes the `.into_inner()` result to `convert_from_ether_decimals`, which does `value.checked_div(denom)` where `denom = 10^(18 - Decimals)` (e.g. `1e6` for a 12-decimal chain). [1](#0-0)  Because the wei magnitude is preserved through the multiply/divide by unit-valued `multiplier`/`exchange_rate`, any pre-decimals value below `denom` is floored to zero by the plain integer division. `PricingParameters::validate()` only rejects exact zero for `exchange_rate`, `fee_per_gas`, `rewards.local`, `rewards.remote`, and `multiplier` — it does not guard against the derived fee rounding to zero after the decimal rescale. [2](#0-1) 

This exact defect is reproduced in the pallet's own test suite using fully valid, non-zero pricing parameters (`exchange_rate = 1/1`, `fee_per_gas = 1`, `rewards.remote = 1`, `multiplier = 1/1`, `gas_used = 250000`), yielding `fee.remote == 0`, with an in-code comment acknowledging this "should be avoided." [3](#0-2) 

## Impact Explanation
`Fee.remote` is the reward promised to off-chain relayers for delivering a committed message to Ethereum. If it computes to zero, the local fee is still charged and the message is still committed into the Merkle root and queued for delivery, but relayers have no economic incentive to relay it, causing the message to remain undelivered — matching the "public underpriced work that ... stalls bridge processing" impact bucket, since the message is priced and committed on-chain but the reward guarantee silently fails without any revert or error.

## Likelihood Explanation
Triggering this requires only that `fee_per_gas * gas_used_at_most + reward` (in wei), after multiplier/exchange-rate adjustment, be smaller than `10^(18 - Decimals)` — a function of governance-configured pricing parameters and the message's command-derived gas usage, not any privileged or malicious action by the sender. The condition is deterministically demonstrated by the existing test with entirely valid parameters, confirming feasibility and repeatability without requiring degenerate or adversarial inputs beyond the natural combination of small `fee_per_gas`/`reward` values and modest gas usage.

## Recommendation
Guard the fee computation against zero-rounding: after computing the pre-decimals fixed-point fee, detect truncation to zero in `convert_from_ether_decimals` and either reject the fee calculation or round up (ceil) instead of flooring, so relayers are never promised a zero reward for a fee-bearing message. Alternatively, perform the decimal rescale within the same higher-precision (`U256`/`FixedU128`) domain as the multiplier/exchange-rate math rather than via raw integer division after `.into_inner()`.

## Proof of Concept
Using the pallet's mock config (`Decimals = ConstU8<12>`), the existing test `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` demonstrates the bug: with `exchange_rate = 1/1`, `fee_per_gas = 1`, `rewards.remote = 1`, `multiplier = 1/1`, `gas_used = 250000`, `calculate_fee` returns `fee.remote == 0` despite all pricing parameters passing `validate()`. 		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

		/// Calculate fee in remote currency for dispatching a message on Ethereum
		pub(crate) fn calculate_remote_fee(
			gas_used_at_most: u64,
			fee_per_gas: U256,
			reward: U256,
		) -> U256 {
			fee_per_gas.saturating_mul(gas_used_at_most.into()).saturating_add(reward)
		}

		/// The local component of the message processing fees in native currency
		pub(crate) fn calculate_local_fee() -> T::Balance {
			T::WeightToFee::weight_to_fee(
				&T::WeightInfo::do_process_message().saturating_add(T::WeightInfo::commit_single()),
			)
		}

		// 1 DOT has 10 digits of precision
		// 1 KSM has 12 digits of precision
		// 1 ETH has 18 digits of precision
		pub(crate) fn convert_from_ether_decimals(value: u128) -> T::Balance {
			let decimals = ETHER_DECIMALS.saturating_sub(T::Decimals::get()) as u32;
			let denom = 10u128.saturating_pow(decimals);
			value.checked_div(denom).expect("divisor is non-zero; qed").into()
		}

	pub fn validate(&self) -> Result<(), InvalidPricingParameters> {
		if self.exchange_rate == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.fee_per_gas == U256::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.local.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.remote.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.multiplier == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}

	}

#[test]
fn test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero() {
	new_tester().execute_with(|| {
		let gas_used: u64 = 250000;
		let price_params: PricingParameters<<Test as Config>::Balance> = PricingParameters {
			exchange_rate: FixedU128::from_rational(1, 1),
			fee_per_gas: 1_u32.into(),
			rewards: Rewards { local: 1_u32.into(), remote: 1_u32.into() },
			multiplier: FixedU128::from_rational(1, 1),
		};
		let fee = OutboundQueue::calculate_fee(gas_used, price_params.clone());
		assert_eq!(fee.local, 698000000);
		// Though none zero pricing params the remote fee calculated here is invalid
		// which should be avoided
		assert_eq!(fee.remote, 0);
	});
}
