### Title
Unauthenticated `/wallet/getnodeinfo` HTTP/gRPC endpoint discloses internal node configuration, JVM/OS internals, and live thread stack traces - (File: framework/src/main/java/org/tron/core/services/http/GetNodeInfoServlet.java)

### Summary
The Solr advisory describes a monitoring/metrics endpoint (`/admin/metrics`) that, by default, discloses host environment variables and other operational internals to any user holding only a low-privilege "metrics-read" permission, i.e., over-broad information disclosure through a diagnostics API. java-tron has an analogous unauthenticated diagnostics endpoint, `GetNodeInfoServlet` (mapped to `/wallet/getnodeinfo`, `/walletsolidity/getnodeinfo`, and PBFT/solidity variants), which returns detailed process/host and network configuration to any anonymous API caller.

### Finding Description
`GetNodeInfoServlet.doGet` calls `NodeInfoService.getNodeInfo()` and serializes the result directly to the HTTP response with no authentication or authorization check beyond the generic rate limiter: [1](#0-0) 

`NodeInfoService.getNodeInfo()` aggregates connection info, machine info, config info, and block info: [2](#0-1) 

The `setMachineInfo` method pulls live JVM/host internals via `ManagementFactory` MX beans — CPU/memory sizes, Java version, OS name — and, critically, when the JVM has deadlocked threads, includes **full stack traces and lock-owner thread names** in the response: [3](#0-2) 

`setConfigNodeInfo` exposes operational configuration such as listen port, backup listen port, backup member count/priority, max connection counts, and P2P/discovery settings: [4](#0-3) 

The `NodeInfo` object also carries a full peer list with each peer's host/IP and port, sync state, and disconnect reasons, and a `cheatWitnessInfoMap`: [5](#0-4) 

Access control for HTTP endpoints in java-tron is opt-in via `HttpApiAccessFilter`, which only blocks an endpoint if the operator explicitly adds it to `disabled-api-list` in config; there is no default block list entry for `getnodeinfo`, and the filter/config search in this codebase found no reference to `getnodeinfo` in any shipped `.conf` file: [6](#0-5) 

This mirrors the Solr class of bug: an operational/diagnostics surface (Metrics API vs. NodeInfo API) exposes host- and process-level internals (env vars vs. JVM/OS/thread/peer/config data) to any caller reaching the API, gated only by an optional deny-list rather than a default-secure allow-list or authentication.

### Impact Explanation
An anonymous, unauthenticated caller who can reach the node's HTTP/gRPC/JSON-RPC-adjacent Wallet API can retrieve:
- OS name, Java version, total/free memory, CPU count/rate — fingerprinting information useful for targeting known vulnerabilities on the specific host.
- Full stack traces and lock-owner names of deadlocked threads, which can leak internal class/method names, argument values embedded in thread names, and application logic details (information disclosure, CWE-200).
- Peer IP addresses/ports, backup listen port, and max-connection settings, which aid network reconnaissance and targeted DoS/eclipse-style attacks against the specific SR/node topology.

This does not directly cause fund theft but is a genuine "read access to host environment/internals" disclosure comparable in class to the Solr advisory, and can materially assist a follow-on attack (host fingerprinting, network topology mapping for an eclipse/DoS attack against a witness/backup node).

### Likelihood Explanation
High reachability: `getnodeinfo` is mapped on the default Full Node and Solidity Node HTTP services, is only guarded by a generic `RateLimiterServlet`, and is disabled only if an operator manually adds it to `disabled-api-list`; no evidence was found in this codebase's shipped configs that it is disabled by default. Any anonymous HTTP client can invoke it with a simple GET request. The deadlock stack-trace leak specifically only manifests when the JVM has genuine deadlocks, which is intermittent, lowering — but not eliminating — the practical likelihood of that specific sub-issue while the config/peer/JVM info leak is always present.

### Recommendation
- Require the same authorization tier be attached to `/wallet/getnodeinfo` (and the solidity/PBFT variants) as sensitive operational endpoints, or add it to a secure-by-default disabled/allow-list, consistent with how `HttpApiAccessFilter` gates other sensitive APIs.
- Strip or redact `MachineInfo.deadLockThreadInfoList` stack traces, `ConfigNodeInfo` backup port/priority fields, and full peer host/IP list from the anonymous response; expose them only via an authenticated/local-only management channel (mirroring Solr's approach of hiding sensitive keys by default and moving detailed info off the public metrics path).
- Document and default-populate `disabled-api-list` (or an equivalent allow-list) to exclude `getnodeinfo` from public-facing deployments, matching Apache Solr's remediation of not publishing environment/host details via a broadly reachable metrics API.

### Proof of Concept
```
curl -s http://<node-host>:8090/wallet/getnodeinfo
```
No API key, TRON account, or transaction signature is required. The JSON response (per `GetNodeInfoServlet.doGet` → `NodeInfoService.getNodeInfo()`) includes `machineInfo.osName`, `machineInfo.javaVersion`, `machineInfo.deadLockThreadInfoList[].stackTrace` (when present), `configNodeInfo.listenPort`/`backupListenPort`/`backupMemberSize`, and `peerInfoList[].host`/`port` for every connected peer — all retrievable by any unauthenticated network client that can reach the node's HTTP port.   private void setMachineInfo(NodeInfo nodeInfo) {
    MachineInfo machineInfo = new MachineInfo();
    machineInfo.setThreadCount(threadMXBean.getThreadCount());
    machineInfo.setCpuCount(Runtime.getRuntime().availableProcessors());
    machineInfo.setTotalMemory(operatingSystemMXBean.getTotalPhysicalMemorySize());
    machineInfo.setFreeMemory(operatingSystemMXBean.getFreePhysicalMemorySize());
    machineInfo.setCpuRate(operatingSystemMXBean.getSystemCpuLoad());
    machineInfo.setJavaVersion(runtimeMXBean.getSystemProperties().get("java.version"));
    machineInfo
        .setOsName(operatingSystemMXBean.getName() + " " + operatingSystemMXBean.getVersion());
    machineInfo.setJvmTotalMemory(memoryMXBean.getHeapMemoryUsage().getMax());
    machineInfo.setJvmFreeMemory(
        memoryMXBean.getHeapMemoryUsage().getMax() - memoryMXBean.getHeapMemoryUsage().getUsed());
    machineInfo.setProcessCpuRate(operatingSystemMXBean.getProcessCpuLoad());
    List<MemoryDescInfo> memoryDescInfoList = new ArrayList<>();
    List<MemoryPoolMXBean> pools = ManagementFactory.getMemoryPoolMXBeans();
    if (CollectionUtils.isNotEmpty(pools)) {
      for (MemoryPoolMXBean pool : pools) {
        MemoryDescInfo memoryDescInfo = new MemoryDescInfo();
        memoryDescInfo.setName(pool.getName());
        memoryDescInfo.setInitSize(pool.getUsage().getInit());
        memoryDescInfo.setUseSize(pool.getUsage().getUsed());
        memoryDescInfo.setMaxSize(pool.getUsage().getMax());
        if (pool.getUsage().getMax() > 0) {
          memoryDescInfo.setUseRate((double) pool.getUsage().getUsed() / pool.getUsage().getMax());
        } else {
          memoryDescInfo
              .setUseRate((double) pool.getUsage().getUsed() / pool.getUsage().getCommitted());
        }
        memoryDescInfoList.add(memoryDescInfo);
      }
    }
    machineInfo.setMemoryDescInfoList(memoryDescInfoList);
    //dead lock thread
    long[] deadlockedIds = threadMXBean.findDeadlockedThreads();
    if (ArrayUtils.isNotEmpty(deadlockedIds)) {
      machineInfo.setDeadLockThreadCount(deadlockedIds.length);
      ThreadInfo[] deadlockInfos = threadMXBean.getThreadInfo(deadlockedIds);
      List<DeadLockThreadInfo> deadLockThreadInfoList = new ArrayList<>();
      for (ThreadInfo deadlockInfo : deadlockInfos) {
        DeadLockThreadInfo deadLockThreadInfo = new DeadLockThreadInfo();
        deadLockThreadInfo.setName(deadlockInfo.getThreadName());
        deadLockThreadInfo.setLockName(deadlockInfo.getLockName());
        deadLockThreadInfo.setLockOwner(deadlockInfo.getLockOwnerName());
        deadLockThreadInfo.setBlockTime(deadlockInfo.getBlockedTime());
        deadLockThreadInfo.setWaitTime(deadlockInfo.getWaitedTime());
        deadLockThreadInfo.setState(deadlockInfo.getThreadState().name());
        deadLockThreadInfo.setStackTrace(Arrays.toString(deadlockInfo.getStackTrace()));
        deadLockThreadInfoList.add(deadLockThreadInfo);
      }
      machineInfo.setDeadLockThreadInfoList(deadLockThreadInfoList);
    }

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
  }
