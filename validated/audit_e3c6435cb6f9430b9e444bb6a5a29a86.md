# Analysis Result

### Title
Incorrect acceptable-checksum equality checks in repository consistency verification - (File: internal/git/checksum.go, internal/gitaly/service/repository/calculate_checksum.go)

### Summary
Gitaly's `CalculateChecksum` RPC computes a reference-only "checksum" that Praefect treats as an authoritative proof of two replicas' consistency (analogous to Nomad's "acceptable merkle root" check). The checksum computation silently narrows the set of "acceptable" state that is hashed and collapses distinct repository states (a valid empty repo vs. a corrupted repo, or refs outside a hard-coded allow-list) into the same accepted value. Downstream consumers in `internal/praefect` (`recovery.go`, `replicator_test.go`'s `confirmChecksums` pattern used in production replicator code, and `service/info/repositories.go`) rely on checksum equality alone to decide that a secondary is up to date, and advance the replication generation, exactly the same class of flaw as Nomad's incorrect acceptance of an unproven/default root as valid.

### Finding Description
`Checksum` XORs together SHA1 hashes of only those references matching a fixed allow-list regexp: [1](#0-0) 

Any reference outside `HEAD|refs/(heads|tags|keep-around|merge-requests|environments|notes)/` (e.g. `refs/remotes/`, `refs/replace/`, `refs/pipelines`, arbitrary custom namespaces) is silently dropped from the checksum: [2](#0-1) 

This is confirmed as intentional-but-debatable behaviour in the test suite itself: [3](#0-2) 

In addition, `CalculateChecksum` collapses two semantically different states — a genuinely empty repository and a *corrupted* repository with a broken ref — into the identical `git.ZeroChecksum` sentinel value, provided `git rev-parse --is-bare-repository` still succeeds: [4](#0-3) 

The test explicitly documents this ambiguity as a known weirdness: [5](#0-4) 

This "acceptable/zero value treated as valid" sentinel is the direct analog of Nomad's flaw where an uninitialized/empty proof root was wrongly accepted as a legitimate value in `acceptableRoot`.

Praefect then uses checksum equality as the sole correctness oracle for repository consistency in several code paths that ordinary users can influence via pushes:
- `RecoverPendingTransactions`/`recoverPendingTransaction` marks a secondary as "updated" (and advances its generation, making it eligible to serve reads/writes as authoritative) purely because its checksum equals the primary's: [6](#0-5) 

- The generic replication confirmation helper compares checksums as a boolean "equal" signal: [7](#0-6) 

- `RepositoryReplicas` reports replica health purely from this checksum: [8](#0-7) 

Because the checksum ignores whole classes of refs and collapses corrupt/empty states, two replicas whose *actual* git state genuinely differs (e.g., one has legitimate content in `refs/remotes/*` or `refs/replace/*`, or one is corrupted while the other is empty) can be judged "consistent" by Praefect even though they are not.

### Impact Explanation
This breaks the core safety invariant that Praefect's checksum-based consistency check is supposed to guarantee: "equal checksum ⇒ equal repository state." A secondary that is actually stale, corrupted, or has diverged content in a ref namespace outside the checksum's allow-list can be:
- Marked as "updated" during crash recovery and have its replication generation advanced without ever receiving the missing/corrected data (`internal/praefect/recovery.go`), silently leaving permanent data loss/divergence undetected.
- Reported as a healthy, in-sync replica via `RepositoryReplicas`, misleading operators/tooling that rely on this signal for failover decisions.

This is a data-integrity/consistency-guarantee bypass in the distributed replication logic, not merely a cosmetic issue, since the entire purpose of the checksum comparison is to substitute for an expensive full-content diff.

### Likelihood Explanation
The scenario is reachable through ordinary repository operations: any push, fetch-mirror, or import that creates refs outside the hard-coded allow-list namespace, or that leaves one replica briefly corrupted/incompletely written (a scenario `recovery.go` is explicitly designed to handle, i.e. crash-during-transaction is an expected operational occurrence, not a privileged-actor exploit). No malicious peer/node or privileged access is required — the flaw is in the trust placed on an incomplete/collapsible hash function used for correctness decisions inside standard Gitaly/Praefect operation.

### Recommendation
- Compute the reference checksum over the full ref namespace (or explicitly document/enforce it as a partial-consistency indicator, never used alone to gate generation advancement).
- Distinguish "empty repository" from "corrupted repository" with distinct, non-colliding sentinel values instead of reusing `ZeroChecksum` for both.
- In Praefect, treat checksum equality as a hint requiring a secondary corroborating signal (e.g., full object/pack verification or content diff) before advancing the generation of a repository during crash recovery.

### Proof of Concept
1. Push/write refs into a namespace not covered by `refsAllowed` (e.g. `refs/remotes/origin/foo`) on Node A only.
2. Query `CalculateChecksum` for Node A and Node B (Node B without that ref) — both return the identical checksum since the differing ref is excluded from computation, per `TestCalculateChecksum`'s "unknown references are ignored" case: [9](#0-8) 
3. Trigger `RecoverPendingTransactions` (crash-recovery path) with Node A as primary; Node B is incorrectly marked `updated` and its generation is advanced despite missing content, per: [6](#0-5)

```go
// AddBytes adds a reference to the checksum that is a line in the output format of `git-show-ref`.
func (c *Checksum) AddBytes(line []byte) {
	if !refsAllowed.Match(line) {
		return
	}

	h := sha1.New()
	// hash.Hash will never return an error.
	_, _ = h.Write(line)

	c.update(h.Sum(nil))
}
```

```go
func confirmChecksums(ctx context.Context, logger log.Logger, primaryClient, replicaClient gitalypb.RepositoryServiceClient, primary, replica *gitalypb.Repository) (bool, error) {
	g, gCtx := errgroup.WithContext(ctx)

	var primaryChecksum, replicaChecksum string

	g.Go(getChecksumFunc(gCtx, primaryClient, primary, &primaryChecksum))
	g.Go(getChecksumFunc(gCtx, replicaClient, replica, &replicaChecksum))

	if err := g.Wait(); err != nil {
		return false, err
	}

	logger.WithFields(log.Fields{
		"primary_checksum": primaryChecksum,
		"replica_checksum": replicaChecksum,
	}).Info("checksum comparison completed")

	return primaryChecksum == replicaChecksum, nil
}
```

```go
func (s *Server) getRepositoryDetails(ctx context.Context, virtualStorage, storage, relativePath, replicaPath string) (*gitalypb.RepositoryReplicasResponse_RepositoryDetails, error) {
	conn, ok := s.conns[virtualStorage][storage]
	if !ok {
		return nil, fmt.Errorf("no connection to %q/%q", virtualStorage, storage)
	}

	resp, err := gitalypb.NewRepositoryServiceClient(conn).CalculateChecksum(ctx,
		&gitalypb.CalculateChecksumRequest{
			Repository: &gitalypb.Repository{
				StorageName:  storage,
				RelativePath: replicaPath,
			},
		})
	if err != nil {
		return nil, err
	}

	return &gitalypb.RepositoryReplicasResponse_RepositoryDetails{
		Repository: &gitalypb.Repository{
			StorageName:  storage,
			RelativePath: relativePath,
		},
		Checksum: resp.GetChecksum(),
	}, nil
}
```
