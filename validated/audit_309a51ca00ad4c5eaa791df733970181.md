### Title
`UpdateReferences` RPC bypasses GitLab's authorization hooks that gate all other reference-mutating RPCs - (File: `internal/gitaly/service/ref/update_references.go`)

### Summary
`RefService.UpdateReferences` allows a caller to create, force-update, or delete arbitrary references in a repository, but unlike every other reference-mutating RPC in Gitaly (`UserCreateBranch`, `UserCreateTag`, `UserMergeBranch`, `UserCommitFiles`, etc.), it performs the update directly through the low-level `updateref.Updater` and never invokes the mandatory `pre-receive`/`update` hook chain that performs GitLab's authorization ("access check") and executes admin-installed custom hooks.

### Finding Description
Every ref-mutating RPC that is meant to be reachable as part of ordinary user actions (branch/tag creation, merges, commit-via-API, submodule updates, etc.) routes its reference update through `s.updateReferenceWithHooks`, which ultimately calls `UpdaterWithHooks.UpdateReference`. That code path always runs `hookManager.PreReceiveHook`, which posts the change to Rails' `/internal/allowed` endpoint and, only if authorized, proceeds to run custom `pre-receive`/`update` hooks and migrate quarantined objects, e.g.: [1](#0-0) 

This is exercised consistently, e.g. in `UserCreateBranch`: [2](#0-1) 
and `UserCreateTag`: [3](#0-2) 

By contrast, `RefService.UpdateReferences` builds a bare `updateref.Updater` and commits reference updates directly, with no call into `hook.Manager`, no `NotAllowedError`/access-check handling, and no custom-hook execution at all: [4](#0-3) 

The only validation performed is syntactic (`git.ValidateReference`, object-ID hex validation) — there is no equivalent of the authorization check that gates `Create`-style branch/tag mutation in the sibling RPCs. This is structurally the same defect as the reported bug: a lower-level primitive (`mint`/`UpdateReferences`) exposes the same capability as a higher-level, properly-gated primitive (`create`/`UserCreateBranch`) but omits the authorization check.

### Impact Explanation
Any caller able to invoke `RefService.UpdateReferences` (the same population that can reach any other mutating Gitaly RPC over the shared client connection) can:
- Force-create, force-update, or delete any reference (including protected branches/tags) without GitLab's `/internal/allowed` permission check ever being consulted.
- Bypass administrator-installed custom `pre-receive`/`update` hooks that enforce compliance, push rules, or branch protection.
- Point references at attacker-supplied object IDs without quarantine/hook validation gating the change, which for the reported bug class specifically enables griefing (e.g., pre-creating a reference to block a subsequent expected legitimate update, mirroring the "block issuance by minting first" pattern) or unauthorized history rewriting of protected refs.

### Likelihood Explanation
`UpdateReferences` is a first-class RPC on `RefService`, reachable wherever other repository-mutating RPCs are reachable; it requires only a syntactically valid reference name and object IDs already known/derivable by the caller (e.g., a target branch name and a commit the caller controls). No special privilege beyond ordinary RPC access is required, and the request handling path performs no capability check before committing the ref update.

### Recommendation
Route `UpdateReferences` reference mutations through the same `UpdaterWithHooks`/quarantine gating used by `UserCreateBranch`, `UserCreateTag`, and other user-facing operations RPCs, so that GitLab's access-check endpoint and custom `pre-receive`/`update` hooks are always invoked before a reference is created, force-updated, or deleted — or explicitly document and enforce that this RPC is restricted to trusted internal callers only (e.g., only reachable from backup/restore code paths) and is never exposed on the same access boundary as user-triggered actions.

### Proof of Concept
1. Obtain a valid connection to `RefService` (the same access level required to call any other Gitaly RPC, e.g., as used by `internal/backup/repository.go`'s `sendRefUpdates` helper, which streams `UpdateReferencesRequest` messages: [5](#0-4)  ).
2. Send an `UpdateReferencesRequest` targeting `refs/heads/<protected-branch>` with `old_object_id` empty (force update) and `new_object_id` set to an attacker-chosen commit.
3. Observe that `updater.Commit()` succeeds and the reference is updated with **no** call to `/internal/allowed`, no admin custom hook execution, and no `NotAllowedError` path — unlike calling `UserCreateBranch`/`UserUpdateBranch` with the same target, which would be rejected by GitLab's access check or custom hooks if unauthorized.

func (s *server) UpdateReferences(server gitalypb.RefService_UpdateReferencesServer) error {
	ctx := server.Context()

	request, err := server.Recv()
	if err != nil {
		return fmt.Errorf("receiving initial request: %w", err)
	}

	if err := s.locator.ValidateRepository(ctx, request.GetRepository()); err != nil {
		return err
	}
	repo := s.localRepoFactory.Build(request.GetRepository())

	objectHash, err := repo.ObjectHash(ctx)
	if err != nil {
		return fmt.Errorf("detecting object hash: %w", err)
	}

	// Unset the repository so that we can more easily verify inside of the loop that all incoming requests
	// ain't got a repository set anymore.
	request.Repository = nil

	updater, err := updateref.New(ctx, repo)
	if err != nil {
		return fmt.Errorf("creating updater: %w", err)
	}

	if err := updater.Start(); err != nil {
		return fmt.Errorf("starting updater: %w", err)
	}

	for {
		// Only the first request may have its repository set.
		if request.GetRepository() != nil {
			return structerr.NewInvalidArgument("repository set in subsequent request")
		}

		if len(request.GetUpdates()) == 0 {
			return structerr.NewInvalidArgument("no updates specified")
		}

		for _, update := range request.GetUpdates() {
			reference := string(update.GetReference())
			if err := git.ValidateReference(reference); err != nil {
				return structerr.NewInvalidArgument("validating reference: %w", err).
					WithMetadata("reference", reference).
					WithDetail(&gitalypb.UpdateReferencesError{
						Error: &gitalypb.UpdateReferencesError_InvalidFormat{
							InvalidFormat: &gitalypb.InvalidRefFormatError{
								Refs: [][]byte{[]byte(reference)},
							},
						},
					})
			}

			// The old object ID may be empty, in which case we don't care about the current value of the
			// reference but instead do a force update of it.
			oldObjectID := string(update.GetOldObjectId())
			if len(oldObjectID) > 0 {
				if err := objectHash.ValidateHex(oldObjectID); err != nil {
					return structerr.NewInvalidArgument("validating old object ID: %w", err).WithMetadata("old_object_id", oldObjectID)
				}
			}

			newObjectID := string(update.GetNewObjectId())
			if err := objectHash.ValidateHex(newObjectID); err != nil {
				return structerr.NewInvalidArgument("validating new object ID: %w", err).WithMetadata("new_object_id", newObjectID)
			}

			if err := updater.Update(git.ReferenceName(reference), git.ObjectID(newObjectID), git.ObjectID(oldObjectID)); err != nil {
				return structerr.NewInvalidArgument("queueing update: %w", err)
			}
		}

		if request, err = server.Recv(); err != nil {
			if errors.Is(err, io.EOF) {
				break
			}

			return fmt.Errorf("receiving subsequent request: %w", err)
		}
	}

// sendRefUpdates sends a batch of ref updates to the remote repository.
func (rr *remoteRepository) sendRefUpdates(ctx context.Context, refClient gitalypb.RefServiceClient, updates []*gitalypb.UpdateReferencesRequest_Update) error {
	if len(updates) == 0 {
		return nil
	}

	stream, err := refClient.UpdateReferences(ctx)
	if err != nil {
		return fmt.Errorf("open stream: %w", err)
	}

	// We need to send the first update without the chunker, because the RPC expects the `Repository` field to be
	// empty in subsequent messages. We also need to send the first reference because the RPC expects at least one
	// update.
	if err := stream.Send(&gitalypb.UpdateReferencesRequest{
		Repository: rr.repo,
		Updates: []*gitalypb.UpdateReferencesRequest_Update{
			updates[0],
		},
	}); err != nil {
		return fmt.Errorf("send initial request: %w", err)
	}

	chunker := chunk.New(&updateRefsSender{stream: stream})

	for _, update := range updates[1:] {
		if err := chunker.Send(update); err != nil {
			return fmt.Errorf("send ref update: %w", err)
		}
	}
