### Title
Untrusted archive extraction via system `tar` in `CreateRepositoryFromSnapshot` allows path traversal / storage escape - ([File: internal/gitaly/service/repository/create_repository_from_snapshot.go])

### Summary
The `CreateRepositoryFromSnapshot` RPC handler fetches a tar archive from an attacker-controllable `HttpUrl` and extracts it directly into the newly created repository directory using the system `tar` binary, without validating that the archive entries (paths/symlinks) stay within the target directory. This mirrors the RSCO-5 bug class: a "pointer"/path supplied through a crafted RPC field is not range-checked against the trusted region (the repository directory) before it is used to perform a privileged operation (writing files to disk).

### Finding Description
`CreateRepositoryFromSnapshot` creates a new (attacker-chosen) repository and then calls `s.untar` to populate it: [1](#0-0) 

`untar` performs an HTTP GET to `in.GetHttpUrl()` (with optional `ResolvedAddress` pinning to defeat DNS rebinding, but no control over the response body) and pipes the response directly into the external `tar` command extracting into `path`, the freshly-created bare repository directory: [2](#0-1) 

Unlike the hardened, hand-rolled extractor used elsewhere in the codebase (`extractTarToDirectory` in `internal/gitaly/service/repository/replicate.go`, which explicitly checks `strings.HasPrefix(targetPath, targetDir+...)` for regular files, symlinks, and hard links before writing), this code path delegates extraction entirely to the system `tar` binary with no path-containment check of its own, and no `--strip-components`/allow-list of entry types. There is no equivalent to the `read_mem`/`write_mem` bound check from the analog report — the "address" here is the tar entry name/symlink target, and it is never validated to remain inside the target repository directory before triggering a filesystem write.

The code comment itself flags this as unhardened:
> "NOTE: The received archive is trusted *a lot*. Before pointing this RPC at endpoints not under our control, it should undergo a lot of hardening." [3](#0-2) 

This is a genuine unprivileged-caller analog to the zkvm ecall-parameter bug: a normal RPC caller supplies a URL; the content behind that URL (which the caller fully controls, e.g., by hosting the tar file themselves) is used to write to arbitrary filesystem paths via `..`-traversal entries or symlink entries in the tar stream, without any bounds check tying the write location back to the intended repository directory.

### Impact Explanation
An attacker who can invoke `CreateRepositoryFromSnapshot` (a standard, unprivileged Gitaly RPC surface, analogous to fork/import flows) controls both the request (`HttpUrl`) and the server that responds to it, and therefore fully controls the tar stream contents. Because extraction is delegated to the system `tar` binary without a validated allow-list of relative, non-symlink paths confined to the target directory, a crafted tar archive containing `../../` path components or symlink entries pointing outside the repository directory can write or overwrite arbitrary files on the Gitaly node's filesystem (subject to `tar`'s own default behavior and Gitaly's process privileges), constituting a storage escape and potential cross-repository or host compromise.

### Likelihood Explanation
Likelihood is elevated because: (1) the attacker fully controls the archive content by hosting the HTTP endpoint that `HttpUrl` points to, requiring no privileged access beyond calling a normal creation RPC; (2) no additional validation or sandboxing of the tar contents exists between the network response and the `tar -xvf -` extraction; and (3) the code's own comment acknowledges the archive is implicitly trusted, indicating this was a known but unaddressed gap.

### Recommendation
Replace the system `tar` invocation in `untar` with the same hardened, containment-checked extraction logic already implemented in `internal/gitaly/service/repository/replicate.go`'s `extractTarToDirectory`/`extractFile` (validating that every regular file, directory, symlink target, and hard-link target resolves to a path within the target directory, and rejecting absolute symlinks), or otherwise strictly validate/canonicalize every tar entry name and symlink target against the target directory boundary before writing.

### Proof of Concept
1. Host an HTTP server that serves a tar archive containing an entry such as `../../../../etc/cron.d/malicious` or a symlink entry named `escape` pointing to `../../../../tmp/evil`.
2. Call `CreateRepositoryFromSnapshot` with `HttpUrl` pointing at the attacker-controlled server.
3. `s.untar` downloads the archive and runs `tar -C <repoPath> -xvf -`, extracting the crafted entries; depending on the local `tar` implementation's default handling of `..`/symlink entries, this writes files outside the intended repository directory, demonstrating the storage escape.

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}

func (s *server) CreateRepositoryFromSnapshot(ctx context.Context, in *gitalypb.CreateRepositoryFromSnapshotRequest) (*gitalypb.CreateRepositoryFromSnapshotResponse, error) {
	repository := in.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository, storage.WithSkipRepositoryExistenceCheck()); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	if err := repoutil.Create(ctx, s.logger, s.locator, s.gitCmdFactory, s.catfileCache, s.txManager, s.repositoryCounter, repository, func(repo *gitalypb.Repository) error {
		path, err := s.locator.GetRepoPath(ctx, repo, storage.WithRepositoryVerificationSkipped())
		if err != nil {
			return structerr.NewInternal("getting repo path: %w", err)
		}

		// The archive contains a partial git repository, missing a config file and
		// other important items. Initializing a new bare one and extracting the
		// archive on top of it ensures the created git repository has everything
		// it needs (especially, the config file and hooks directory).
		//
		// NOTE: The received archive is trusted *a lot*. Before pointing this RPC
		// at endpoints not under our control, it should undergo a lot of hardening.
		if err := s.untar(ctx, path, in); err != nil {
			return structerr.NewInternal("extracting snapshot: %w", err)
		}

		return nil
	}); err != nil {
		return nil, structerr.NewInternal("creating repository: %w", err)
	}
