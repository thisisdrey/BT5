### Title
Missing deadline and slippage protection on oracle-priced `Pool.swap` allows stale-price execution and loss of user funds - ([File: contracts/Pool.sol])

### Summary
`Pool.swap(syntheticTokenIn_, syntheticTokenOut_, amountIn_)` accepts no `amountOutMin` and no `deadline` parameter. The amount a user receives is determined entirely by `masterOracle().quote()` at execution time (`quoteSwapOut`, `contracts/Pool.sol:508-525`). A transaction that sits in the mempool and executes after an oracle price update pays/receives at the new price, not the price the user saw at submission — the exact bug class of Asymmetry M-06 (missing deadline on price-sensitive actions).

### Finding Description
- `Pool.swap` has the signature `swap(ISyntheticToken, ISyntheticToken, uint256)` — three arguments, no deadline and no minimum-output bound. [1](#0-0) 
- The conversion rate is oracle-dependent: `quoteSwapOut` calls `masterOracle().quote(tokenIn, tokenOut, amountIn)` then subtracts a fee, so the output is fully determined by the oracle price at the block the transaction is mined. [2](#0-1) 
- A repository-wide search for `deadline` across `contracts/` returns zero matches — no user-facing entry point offers a deadline, and `swap` additionally lacks any slippage bound.
- `SmartFarmingManager.leverage`/`flashRepay` at least carry `depositAmountMin_`/`swapAmountOutMin_` slippage parameters, but still no deadline — a pending `leverage` executed after a price move may pass the stale min-out while the position's real economics have deteriorated, and the only post-check is `PositionIsNotHealthy`, which does not bound slippage. [3](#0-2) 

### Impact Explanation
A user submits `swap(msUSD, msETH, amountIn)` expecting output per the current quote. If the tx is delayed (congestion, low gas, malicious reordering) and the oracle updates the msETH price upward before inclusion, the user receives materially less msETH with no ability to revert. Loss of user funds due to execution at a price worse than the one agreed at signing time; the symmetric case (price moves in user's favor) does not compensate since users cannot opt out.

### Likelihood Explanation
Oracle price updates are routine and user transactions can remain pending. The exposure is permanent: every `swap` caller bears unbounded slippage-by-delay. Severity is Medium — it requires a pending-transaction window plus a price move, and the loss accrues to the caller rather than being directly extractable by a specific attacker.

### Recommendation
Add `amountOutMin_` (and ideally `deadline_`) parameters to `IPool.swap`/`Pool.swap`, reverting with a `SlippageTooHigh`/`Expired` error when `quoteSwapOut(...) < amountOutMin_` or `block.timestamp > deadline_`. Similarly add `deadline_` to `SmartFarmingManager.leverage` and `flashRepay`.

### Proof of Concept
Foundry-style sketch:

```solidity
// fork mainnet, deploy/use Pool with two synths msUSD/msETH priced by MasterOracle
uint256 amountIn = 10_000e18;
(uint256 quotedOut,) = pool.quoteSwapOut(msUSD, msETH, amountIn);

// user signs tx: pool.swap(msUSD, msETH, amountIn) -- no way to bound output
// tx sits pending; oracle pushes new msETH price 10% higher
oracle.updatePrice(msETH, prevPrice * 11 / 10);

vm.prank(user);
pool.swap(msUSD, msETH, amountIn); // succeeds, returns ~quotedOut/1.1
assertLt(msETH.balanceOf(user), quotedOut * 91 / 100); // user lost ~9% with no recourse
```

Note on verification limits: the exact line range of the `Pool.swap` body was not retrieved (only its signature via tests/ABI and its pricing via `quoteSwapOut`), so the citation for the missing parameters rests on the function signature `swap(address,address,uint256)` shown in `deployments/hemi/Pool.json` and the test call sites — sufficient to confirm the absence of `deadline`/`minOut` arguments.

```text
    function quoteSwapOut(
        ISyntheticToken syntheticTokenIn_,
        ISyntheticToken syntheticTokenOut_,
        uint256 amountIn_
    ) public view override returns (uint256 _amountOut, uint256 _fee) {
        _amountOut = _poolRegistry.masterOracle().quote(
            address(syntheticTokenIn_),
            address(syntheticTokenOut_),
            amountIn_
        );

        uint256 _swapFee = feeProvider.swapFees(address(syntheticTokenIn_), address(syntheticTokenOut_));

        if (_swapFee > 0) {
            _fee = _amountOut.wadMul(_swapFee);
            _amountOut -= _fee;
        }
    }
```
