### Title
Single-IP QUIC handshake flood bypasses per-IP rate limiting due to non-mutating `is_allowed()` pre-check and post-handshake-only `register_connection()` - (File: streamer/src/nonblocking/connection_rate_limiter.rs, streamer/src/nonblocking/quic.rs)

### Summary
The per-IP QUIC connection rate limiter only consumes a token in `ConnectionRateLimiter::register_connection` after a handshake completes in `setup_connection`, while the pre-accept check `ConnectionRateLimiter::is_allowed` is explicitly non-mutating. Because there is no cap on the number of concurrently *outstanding* (un-registered) handshake attempts from a single source IP, an attacker can open many parallel QUIC connection attempts from one IP and consume a large share of the server's global `outstanding_incoming_connection_attempts` / `max_concurrent_connections` budget before the `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE` limit is ever enforced.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:331-407`), for every incoming connection the server:
1. Checks `overall_connection_rate_limiter.current_tokens() == 0` — a non-mutating read.
2. Checks `rate_limiter.is_allowed(&incoming.remote_address().ip())` — explicitly documented and implemented as non-mutating: `streamer/src/nonblocking/connection_rate_limiter.rs:34-40` returns `true` whenever the IP has no existing record in the `KeyedRateLimiter` map (`None => true`).
3. Only checks a *global* cap via `ClientConnectionTracker::new(stats.clone(), qos.max_concurrent_connections())` (`streamer/src/nonblocking/quic.rs:371-379`), which is not per-IP.
4. Increments `stats.outstanding_incoming_connection_attempts` and spawns `setup_connection`, which awaits the handshake for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2 seconds) (`streamer/src/nonblocking/quic.rs:472-475`, constant at `streamer/src/nonblocking/quic.rs:80`).

Only if/when the handshake succeeds does `setup_connection` call `rate_limiter.register_connection(&from.ip())` (`streamer/src/nonblocking/quic.rs:483`), which is the only place that actually consumes a token from the per-IP `TokenBucket` (`ConnectionRateLimiter::register_connection`, `streamer/src/nonblocking/connection_rate_limiter.rs:42-50`).

Because `is_allowed()` never mutates state and no record exists for an IP until a connection from it has completed a handshake at least once, an attacker can open many simultaneous connection attempts from the same IP: each one passes `is_allowed()` (no record yet), passes the global `ClientConnectionTracker` check (as long as the global cap is not yet exhausted), and occupies a slot counted in `outstanding_incoming_connection_attempts` for up to 2 seconds before timing out or being explicitly rejected. There is no per-IP limit on the number of concurrently in-flight (pre-registration) attempts — only a global cap (`qos.max_concurrent_connections()`, e.g., `self.config.max_staked_connections * 5 / 4` in `streamer/src/nonblocking/simple_qos.rs:422-425`) applies, and that cap is shared across all IPs, not scoped per source. A single attacker IP can therefore consume the entire global concurrent-connection budget by repeatedly opening (and never completing, or slow-completing) handshakes, for the duration of each 2-second window, indefinitely repeating the attack.

### Impact Explanation
This allows an unstaked, unprivileged remote attacker to monopolize the server's finite `max_concurrent_connections`/`outstanding_incoming_connection_attempts` slots using traffic from a single source IP, well beyond what the `DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE = 8` per-IP budget was intended to permit, since that budget is only enforced after a successful handshake. Legitimate clients attempting to connect will be refused via `refused_connections_too_many_open_connections` once the global cap is exhausted, degrading TPU QUIC ingress availability for all other peers using cheap (no completed handshake, no fee) traffic — this matches the flagged pattern of cheap unprivileged work vastly exceeding intended per-IP budget and degrading the leader below intended cost/availability guarantees.

### Likelihood Explanation
This requires only default configuration (`DEFAULT_MAX_CONNECTIONS_PER_IPADDR_PER_MINUTE = 8`, `QUIC_CONNECTION_HANDSHAKE_TIMEOUT = 2s`) and no staked/privileged access — an attacker only needs to be able to open many parallel QUIC `Initial` handshakes toward the leader's public TPU QUIC port from one IP without necessarily completing them (or completing them slowly), which is fully within reach of an unstaked remote client. The attack is trivially repeatable every ~2 seconds (or continuously, by keeping the pipeline of in-flight attempts full).

### Recommendation
Add a per-IP cap on outstanding (pre-registration) connection attempts, e.g., track in-flight attempt counts per source IP in `ConnectionRateLimiter` (or a companion structure) and reject/`incoming.refuse()` new attempts once the same source IP already has N outstanding, unregistered handshakes in flight, independent of whether `is_allowed()`'s post-handshake token bucket has been touched yet.

### Proof of Concept
Integration test (extending `streamer/src/nonblocking/quic.rs` test module or `tpu-client-next/tests/connection_workers_scheduler_test.rs` style tests) using `setup_quic_server`:
1. Configure a test server with default/realistic `max_connections_per_ipaddr_per_min` and a moderate `max_concurrent_connections`.
2. From a single client IP (bound to one local socket, or multiple sockets sharing `127.0.0.1`), spawn N parallel raw QUIC `Connecting` attempts (e.g., via low-level `quinn::Endpoint::connect` without completing the TLS handshake, or by delaying handshake completion) before any of them completes.
3. Poll `stats.outstanding_incoming_connection_attempts` and assert that it is bounded by a small per-IP constant (e.g., 8-16), rather than growing up to `qos.max_concurrent_connections()` purely from one IP.
4. Additionally assert that legitimate connection attempts from a second, distinct IP are still accepted (not starved) while the first IP's flood is outstanding — expected to fail today since a single IP can consume the entire global `max_concurrent_connections` budget before any per-IP registration occurs.     /// Check if the connection from the said `ip` is allowed.
    /// Here we assume that only IPs with actual confirmed connections are stored in it,
    /// since we should only modify server state once source IP is verified
    pub fn is_allowed(&self, ip: &IpAddr) -> bool {
        // Check if we have records in the rate limiter for the given IP address
        match self.limiter.current_tokens(ip) {
            Some(r) => r > 0, // we have a record, and rate is not exceeded
            None => true,     // if we have not seen IP, allow connection request
        }
    }

    pub fn register_connection(&self, ip: &IpAddr) -> bool {
        if self.limiter.consume_tokens(*ip, 1).is_ok() {
            debug!("Request from IP {ip:?} allowed");
            true // Request allowed
        } else {
            debug!("Request from IP {ip:?} blocked");
            false // Request blocked
        }
    }
