The gob decoder in this repository (`src/encoding/gob/decode.go`) received a partial fix for CVE-2024-34156: a nesting-depth guard was added **only** to the "ignore" decoding path (`dec.decIgnoreOpFor`), which handles fields present in the wire data but absent from the destination struct. The primary decode path used when data actually matches a destination type has no equivalent guard.

### Title
Unbounded recursion in `Decoder.decodeStruct` when decoding real (non-ignored) recursive struct data causes stack-exhaustion panic - (File: src/encoding/gob/decode.go)

### Summary
`encoding/gob`'s `Decoder.Decode` compiles a decode op for each field via `decOpFor`, and for struct-typed fields (including self-referential pointer types like `type RT struct{ Next *RT }`) it installs a closure that calls `dec.decodeStruct` recursively at decode time [1](#0-0)  . Unlike the "ignore" path, which was hardened against CVE-2024-34156 with `maxIgnoreNestingDepth` and a `dec.ignoreDepth` counter [2](#0-1) [3](#0-2) , the real struct-decoding path (`decodeStruct` recursing through `instr.op`) has no depth counter or limit at all [4](#0-3) . An attacker who controls a gob-encoded message consumed by an ordinary `Decoder.Decode(&dst)` call into a recursive struct type can therefore trigger unbounded native-stack recursion and a process-crashing panic.

### Finding Description
Attacker input: a gob stream encoding a deeply-nested chain of a recursive struct (e.g., `type RT struct{ A string; Next *RT }`, as already exercised for correctness — not depth — in `TestNesting` [5](#0-4) ).
Go entry point: `Decoder.Decode` → `decodeStruct(engine, value)` for the top-level struct [6](#0-5) .
Sink: for each field of struct kind, `decOpFor` builds an op that calls `dec.decodeStruct(*enginePtr, value)` again [1](#0-0) , and this op executes once per encoded nesting level inside `decodeStruct`'s per-field loop [7](#0-6) .
Failed check: the fix that Go shipped for GO-2024-3106 added a depth counter (`ignoreDepth`/`maxIgnoreNestingDepth`) but it is wired only into `decIgnoreOpFor`, the compiler for *discarded* fields [8](#0-7) . The real-value decode path (`decOpFor`'s `reflect.Struct` case and the `decodeStruct` runtime loop) performs no analogous depth accounting, so a message that is deeply nested but matches the destination type exactly bypasses the added protection entirely.

### Impact Explanation
A successful attack exhausts the goroutine stack and panics the process (denial of service) when an application decodes attacker-supplied gob data into any recursively-defined struct type — a common RPC/cache-serialization pattern via `net/rpc` or custom gob usage. This is the same "stack exhaustion via `Decoder.Decode`" primitive named in the advisory, just reached through the primary decode path rather than the already-patched ignore path. Under Go's vulnerability triage this would be a PUBLIC-track fix (parser hardening / follow-up to CVE-2022-30635 and CVE-2024-34156), not urgent/high-severity RCE, since the effect is a crash, not memory corruption or code execution.

### Likelihood Explanation
Any ordinary victim workflow that calls `gob.NewDecoder(untrustedReader).Decode(&dst)` on attacker-influenced bytes into a self-referential struct type is affected; no special privileges, TLS/cert control, or malicious peer capability beyond "send bytes to a gob decoder" are required, consistent with an unauthenticated/unprivileged attacker model.

### Recommendation
Add the same nesting-depth accounting used in `decIgnoreOpFor` to the real decode path — e.g., increment/check a `dec.decodeDepth` (or reuse `ignoreDepth`) counter inside `decodeStruct`/`decodeArrayHelper`/`decodeMap` recursion, mirroring `maxIgnoreNestingDepth`, and return a decode error once the limit is exceeded, instead of relying solely on the compile-time `inProgress` cycle-breaker in `decOpFor`.

### Proof of Concept
```go
package gob

import (
	"bytes"
	"testing"
)

type RTChain struct {
	A    string
	Next *RTChain
}

func TestDecodeDeepRecursiveStructStackExhaustion(t *testing.T) {
	// Build a very deep chain (e.g. 10_000_000 levels) directly as Go values,
	// bypassing Encode's own stack usage by constructing iteratively.
	var head *RTChain
	for i := 0; i < 5_000_000; i++ {
		head = &RTChain{A: "x", Next: head}
	}

	b := new(bytes.Buffer)
	if err := NewEncoder(b).Encode(head); err != nil {
		t.Fatalf("encode failed: %v", err)
	}

	var out RTChain
	dec := NewDecoder(b)
	// Expected (fixed) behavior: Decode returns an error like
	// "invalid nesting depth" instead of panicking with a stack overflow.
	err := dec.Decode(&out)
	if err == nil {
		t.Fatalf("expected nesting-depth error, decode succeeded")
	}
}
```
Expected assertion under a fixed implementation: `dec.Decode` returns a bounded "invalid nesting depth" error (as the ignore path already does). Under the current unpatched real-decode path, sufficiently deep input instead exhausts the goroutine stack and panics the process.

// decodeStruct decodes a top-level struct and stores it in value.
// Indir is for the value, not the type. At the time of the call it may
// differ from ut.indir, which was computed when the engine was built.
// This state cannot arise for decodeSingle, which is called directly
// from the user's value, not from the innards of an engine.
func (dec *Decoder) decodeStruct(engine *decEngine, value reflect.Value) {
	state := dec.newDecoderState(&dec.buf)
	defer dec.freeDecoderState(state)
	state.fieldnum = -1
	for state.b.Len() > 0 {
		delta := int(state.decodeUint())
		if delta < 0 {
			errorf("decode: corrupted data: negative delta")
		}
		if delta == 0 { // struct terminator is zero delta fieldnum
			break
		}
		if state.fieldnum >= len(engine.instr)-delta { // subtract to compare without overflow
			error_(errRange)
		}
		fieldnum := state.fieldnum + delta
		instr := &engine.instr[fieldnum]
		var field reflect.Value
		if instr.index != nil {
			// Otherwise the field is unknown to us and instr.op is an ignore op.
			field = value.FieldByIndex(instr.index)
			if field.Kind() == reflect.Pointer {
				field = decAlloc(field)
			}
		}
		instr.op(instr, state, field)
		state.fieldnum = fieldnum
	}
}

var maxIgnoreNestingDepth = 10000

// decIgnoreOpFor returns the decoding op for a field that has no destination.
func (dec *Decoder) decIgnoreOpFor(wireId typeId, inProgress map[typeId]*decOp) *decOp {
	// Track how deep we've recursed trying to skip nested ignored fields.
	dec.ignoreDepth++
	defer func() { dec.ignoreDepth-- }()
	if dec.ignoreDepth > maxIgnoreNestingDepth {
		error_(errors.New("invalid nesting depth"))
	}
	// If this type is already in progress, it's a recursive type (e.g. map[string]*T).
	// Return the pointer to the op we're already building.
	if opPtr := inProgress[wireId]; opPtr != nil {
		return opPtr
	}

func TestNesting(t *testing.T) {
	type RT struct {
		A    string
		Next *RT
	}
	rt := new(RT)
	rt.A = "level1"
	rt.Next = new(RT)
	rt.Next.A = "level2"
	b := new(bytes.Buffer)
	NewEncoder(b).Encode(rt)
	var drt RT
	dec := NewDecoder(b)
	err := dec.Decode(&drt)
	if err != nil {
		t.Fatal("decoder error:", err)
	}
	if drt.A != rt.A {
		t.Errorf("nesting: encode expected %v got %v", *rt, drt)
	}
	if drt.Next == nil {
		t.Errorf("nesting: recursion failed")
	}
	if drt.Next.A != rt.Next.A {
		t.Errorf("nesting: encode expected %v got %v", *rt.Next, *drt.Next)
	}
}
