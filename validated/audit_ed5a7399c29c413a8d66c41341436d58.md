### Title
Cross-StackerDB signature replay due to missing contract-ID binding in chunk authentication - ([File: libstackerdb/src/libstackerdb.rs])

### Summary
`SlotMetadata::auth_digest()` computes the digest that a signer's private key signs to authenticate a StackerDB chunk write, but the digest only commits to `slot_id`, `slot_version`, and `data_hash` — it never includes the target StackerDB's smart-contract identifier. Consequently, a signature that is valid for a chunk in one StackerDB replica is equally valid for the "same" `(slot_id, slot_version, data_hash)` tuple in *any other* StackerDB replica where that signer happens to hold the same slot index, letting an attacker replay a legitimately-signed chunk from one database into a different one it was never authorized for.

### Finding Description
The signing/verification digest is: [1](#0-0) 

`sign()`/`verify()` operate purely on this digest: [2](#0-1) 

The server-side write path, `StackerDBTx::try_replace_chunk`, resolves the expected signer for a slot *scoped to the given `smart_contract`* via `get_slot_validation`, then calls `slot_desc.verify(&slot_validation.signer)`: [3](#0-2) 

Because `verify()`/`auth_digest()` never mix in the `smart_contract` identifier, this check only proves "some signature by signer S over `(slot_id, slot_version, data_hash)`" — it cannot distinguish which StackerDB contract S intended to authorize. The unsolicited-push and inventory paths reach the same `validate_received_chunk` logic, which likewise looks up the signer strictly by `smart_contract_id` but verifies the signature with the contract-agnostic digest: [4](#0-3) 

Any Stacks address that is registered (by the controlling smart contract, e.g. `stackerdb-get-signer-slots`) as the owner of slot `i` in two or more StackerDB replicas (e.g. the same signer's slot index recurring across reward-cycle StackerDB contracts such as `.signers-0-*`/`.signers-1-*`, or across any two independently-deployed StackerDB apps that happen to assign that signer the same slot) can have a chunk it legitimately signed and broadcast for replica A replayed byte-for-byte (same `slot_id`, `slot_version`, `data`, `sig`) into replica B via `POST /v2/stackerdb/.../chunk`, as long as B's current stored version for that slot is lower. `try_replace_chunk`/`validate_received_chunk` will accept it as authentic, and the node will re-gossip it to its peers as valid data for replica B.

### Impact Explanation
This breaks the "authenticated vs. stored" equality the StackerDB protocol relies on: a signature is supposed to authorize a specific write to a specific database, but here it only authorizes a `(slot_id, slot_version, data_hash)` triple that is not bound to any particular contract. The result is unauthenticated cross-database write and subsequent network-wide propagation of data the signer never approved for that destination replica — matching the "Critical" bucket (unauthenticated/unauthorized write to state or StackerDB; network-wide propagation of forged data).

### Likelihood Explanation
StackerDB chunks are public, gossiped p2p data, so capturing a valid signed chunk requires no special access — any observer on the network can record one. Exploitability further depends on the same signer address owning the same slot index in two distinct StackerDB replicas, which is a realistic condition given how reward-cycle StackerDB contracts reuse/rotate largely-overlapping signer sets and deterministic slot assignment. No secret key or privileged role is required by the attacker.

### Recommendation
Include the StackerDB's `QualifiedContractIdentifier` (or an equivalent unique replica identifier) inside `SlotMetadata::auth_digest()` so that a signature is cryptographically bound to the specific StackerDB replica it authorizes, preventing cross-replica replay of otherwise-valid chunk signatures.

### Proof of Concept
1. Deploy/observe two StackerDB-bound contracts, A and B, both of which list signer `S` as the owner of slot `5` (plausible in practice, since the reward-cycle `.signers-*` contracts and various third-party StackerDB apps assign slots deterministically and often reuse the same signer set).
2. Wait for `S` to sign and broadcast a legitimate chunk for slot `5` in replica A: `StackerDBChunkData { slot_id: 5, slot_version: v, sig, data }`.
3. Capture that exact `StackerDBChunkData` from the p2p gossip stream or via a `GetChunk` RPC.
4. Submit the identical struct via `POST /v2/stackerdb/<contract-B>/chunks` (i.e., the `poststackerdbchunk` handler) targeting replica B's slot `5`, where B's current stored version for slot 5 is `< v`.
5. `StackerDBTx::try_replace_chunk` (`stackslib/src/net/stackerdb/db.rs:400-437`) looks up B's slot-5 signer (`S`), calls `slot_desc.verify(&S)`, which succeeds because `auth_digest()` never referenced contract A or B — the write is accepted, stored, and re-broadcast as authentic data for replica B, even though `S` never signed anything for replica B.

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

        // Check per-replica chunk-size cap.
        if (chunk.len() as u64) > self.config.chunk_size {

                slot_desc.slot_id,
            ))?;

        if !slot_desc.verify(&slot_validation.signer)? {
            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
