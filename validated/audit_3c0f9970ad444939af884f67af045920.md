### Title
Signer event receiver HTTP endpoint accepts unauthenticated events, allowing forged event injection - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` (`libsigner/src/events.rs`) implements the HTTP server that a `stacks-signer` process runs to receive pushed events (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown`) from a `stacks-node`. Unlike every comparable node-side RPC handler in `stackslib/src/net/api/*` (`postblock_proposal.rs`, `postblock_v3.rs`, `blockreplay.rs`, `blocksimulate.rs`, `fastcallreadonly.rs`, `txsimulate.rs`), which all gate privileged requests behind an `authorization` header compared against a configured `auth_token`/password, the signer's event receiver performs **no authentication check whatsoever** before dispatching a request to `process_event`.

### Finding Description
On the node side, every privileged HTTP handler enforces:
```
let Some(auth_header) = preamble.headers.get("authorization") else {
    return Err(Error::Http(401, "Unauthorized".into()));
};
if auth_header != password { return Err(Error::Http(401, "Unauthorized".into())); }
``` [1](#0-0) 

This `auth_token` is documented to "secure the communication channel between this node and a connected stacks-signer instance" [2](#0-1) , and is required to match the signer's `auth_password` [3](#0-2) .

However, this token only protects the *node's* inbound endpoints (e.g., `/v3/block_proposal`, `/v2/blocks?broadcast=1`). The **reverse direction** — the node pushing events to the signer's listening `endpoint` (which sample configs bind to `0.0.0.0:30000`, i.e., all interfaces) [4](#0-3)  — is handled entirely by `SignerEventReceiver::next_event`, which dispatches purely on URL path with zero credential check:
```
if request.url() == "/stackerdb_chunks" {
    process_event::<T, StackerDBChunksEvent>(request)
} else if request.url() == "/proposal_response" {
    process_event::<T, BlockValidateResponse>(request)
} else if request.url() == "/new_burn_block" {
    process_event::<T, BurnBlockEvent>(request)
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
} else if request.url() == "/new_block" {
    process_event::<T, StacksBlockEvent>(request)
}
``` [5](#0-4) 

`process_event` simply reads the body and JSON-deserializes it into the target event type, with no signature/HMAC/token verification performed at the transport layer:
```
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
...
    let json_event: E = serde_json::from_slice(body.as_bytes())...
    let signer_event: SignerEvent<T> = json_event.try_into()?;
    Ok(signer_event)
``` [6](#0-5) 

Even the `/shutdown` path is unauthenticated and immediately sets `stop_signal`, terminating the signer's event loop [7](#0-6) .

This is the same *class* of weakness as the MinIO advisory: an authentication gate that should exist for a network-reachable, security-relevant endpoint is either absent or trivially bypassable — here it is absent entirely (fails open unconditionally, not merely rate-limit-free). Events like `NewBurnBlock` and `NewBlock` carry no cryptographic proof of origin (unlike `StackerDBChunkData`, whose slot signature is checked elsewhere) [8](#0-7) , so nothing at the transport layer stops an unauthenticated network peer from injecting a forged `SignerEvent` into the process's channel that feeds the running signer instance [9](#0-8) .

### Impact Explanation
Any network-reachable client that can reach the signer's `endpoint` TCP port can:
- Send a forged `POST /new_burn_block` or `POST /new_block` request with attacker-chosen `BurnBlockEvent`/`StacksBlockEvent` JSON payloads that get deserialized and forwarded, unauthenticated and unverified, into the signer process's internal channel.
- Send `POST /shutdown` to unconditionally terminate the signer's event-receiving loop (denial of service on the signer), with a single unauthenticated request.

This is an unauthenticated write of forged/attacker-controlled data directly into a security-critical component's input stream — matching the "unauthenticated/unauthorized write to state" and "forged-data propagation" impact categories. It is remote and requires no secret, node key, or admin role — only network reachability to the configured `endpoint` (which the sample configs default to binding on `0.0.0.0`).

### Likelihood Explanation
Likelihood depends on whether the signer's `endpoint` is reachable from outside the intended node↔signer link (e.g., misconfigured firewall, or the "communicating with an external node" scenario the code's own warning flags: "Reminder: the signer is primarily designed for use with a local or subnet network stacks node... exercise caution if you are communicating with an external node") [10](#0-9) . Given sample configs bind to `0.0.0.0`, and there is no code-level enforcement of an allow-list or token at this specific listener, exploitation is straightforward for anyone with network access to the port — no brute-forcing or enumeration is even needed, unlike the MinIO case.

### Recommendation
Add authentication to `SignerEventReceiver`'s HTTP endpoint: require a shared secret/token (mirroring the node's `auth_token`/`Authorization` header pattern already used in `stackslib/src/net/api/*`) and reject any `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, and especially `/shutdown` request that lacks a valid, constant-time-compared credential, before calling `process_event`/handling the request in `libsigner/src/events.rs`.

### Proof of Concept
1. Start a `stacks-signer` with `endpoint = "0.0.0.0:30000"` per the sample config.
2. From any host with network access to port 30000, send:
```
POST /new_burn_block HTTP/1.1
Host: <signer-host>:30000
Content-Type: application/json
Content-Length: <len>

{"burn_block_hash":"...","burn_block_height":999999999,"reward_recipients":[],"burn_amount":0,"consensus_hash":"...","burn_block_time":0}
```
No `authorization` header is required or checked; `process_event::<T, BurnBlockEvent>(request)` deserializes and forwards this forged event into the signer's event channel [11](#0-10) , identically to how a legitimate node push would be handled.
3. Alternatively, `POST /shutdown` with any body immediately halts the signer's event loop with no authentication [7](#0-6) .

    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
