### Title
Zero-length/malformed packets bypass the scheduler priority floor and are always forwarded to signature verification - (File: core/src/sigverify.rs)

### Summary
`apply_priority_floor_to_batch` explicitly treats any packet whose `packet.data(..)` returns `None` as `any_kept = true`, regardless of the currently-published `SchedulerPriorityFloor`. An unstaked attacker can send zero-length or otherwise malformed packets over the TPU QUIC path; these never get their `discard` bit set by the floor check and are unconditionally passed on to `ed25519_verify_serial` and, if any valid packet survives that stage, to the banking-stage sender.

### Finding Description
In `core::sigverify::apply_priority_floor_to_batch`: [1](#0-0) 

the loop skips already-discarded packets, then for every remaining packet calls `packet.data(..)`. If that returns `None` (the code comment says "Zero-length or otherwise unreadable"), the packet is marked `any_kept = true` and `continue`d — it is never compared against `floor`, never discarded, and `dropped` is not incremented for it. Only packets that do produce parseable `data` are subject to `calculate_priority_from_bytes` and the `priority <= floor` discard check.

This function is invoked from `run_transaction_task` only when `floor > 0`, i.e. specifically during the congested state the priority floor is designed to protect against: [2](#0-1) 

Because the priority-floor check runs strictly *before* `ed25519_verify_serial`, any packet that "escapes" it via the `None`-data branch still reaches full signature verification: [3](#0-2) 

Dedup happens earlier (`dedup_packets_and_count_discards`), but that only removes exact byte-identical duplicates; an attacker can trivially vary payload bytes/length per packet to avoid the dedup hash while still causing `data(..)` to return `None` (e.g., truncated/zero-length payload, or a length field pointing outside the buffer), so dedup does not close this gap.

### Impact Explanation
This is a QoS/priority-floor evasion: the priority floor exists specifically to cheaply shed low-value/garbage traffic before the more expensive `ed25519_verify_serial` path runs, but malformed packets that can never carry a fee are exempted from that shedding by design ("leave to downstream stages to reject"). Under congestion (elevated `SchedulerPriorityFloor`), a flood of such packets continues to consume the `ed25519_verify_serial` step and increments `total_valid_packets`/queue traffic accounting instead of being dropped up front like other sub-floor traffic, undermining the intended backpressure invariant that "cheap, no-fee packets should not bypass load-shedding." The scoped impact is limited to the priority-floor-bypass channel itself (not full ingress DoS), since malformed packets are still rejected shortly after in `ed25519_verify_serial`/`count_valid_packets` and never reach banking stage as valid work.

### Likelihood Explanation
Fully reachable by an unstaked remote attacker who only needs to open a QUIC stream to the leader's TPU and send arbitrary byte payloads with zero/invalid length — no fee, signature, staking, or special access required. It is trivially repeatable and only becomes meaningfully impactful under the exact congestion condition (`floor > 0`) where the shedding mechanism is supposed to matter.

### Recommendation
Treat packets with unreadable/zero-length `data(..)` as discardable at the priority-floor stage (mark them `discard` and count them in `dropped`) rather than exempting them via `any_kept = true`, since such packets can never satisfy any priority requirement and provide no legitimate signal to keep.

fn priority_floor_does_not_shed_malformed_packets() {

fn apply_priority_floor_to_batch(
    batch: &mut PacketBatch,
    floor: u64,
    bank: &Bank,
) -> (usize, bool) {
    let mut dropped: usize = 0;
    let mut any_kept = false;
    for mut packet in batch.iter_mut() {
        if packet.meta().discard() {
            continue;
        }
        let Some(data) = packet.data(..) else {
            // Zero-length or otherwise unreadable: leave to downstream
            // stages to reject.
            any_kept = true;
            continue;
        };
        // Unparseable packets are kept and left for downstream rejection.
        match calculate_priority_from_bytes(bank, data) {
            Some(priority) if priority <= floor => {
                packet.meta_mut().set_discard(true);
                dropped = dropped.saturating_add(1);
            }
            _ => any_kept = true,
        }
    }
    (dropped, !any_kept)
