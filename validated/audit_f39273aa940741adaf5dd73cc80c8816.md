### Title
Scheduler priority floor is trivially bypassable via self-declared, unverified `compute_unit_price`, defeating pre-sigverify spam filtering - ([File: core/src/sigverify.rs])

### Summary
The scheduler-published priority floor in `apply_priority_floor_to_batch` (`core/src/sigverify.rs:413-440`) is meant to drop low-value packets before the CPU-expensive `ed25519_verify_serial` call during scheduler saturation. However, the priority used for this decision, computed by `calculate_priority_from_bytes` (`core/src/transaction_priority.rs:73-88`), is derived entirely from unverified, attacker-controlled message fields (`compute_unit_price`, signature counts) with no signature or balance check, so an attacker can forge packets with a fake, arbitrarily high priority at negligible cost, bypassing the floor and forcing full ed25519 verification anyway.

### Finding Description
`SigVerifyWorkerPool::run_transaction_task` (`core/src/sigverify.rs:266-324`) calls `apply_priority_floor_to_batch(&mut batch, floor, &working_bank)` (`core/src/sigverify.rs:302-323`) before invoking `sigverify::ed25519_verify_serial` (`core/src/sigverify.rs:327-331`). This is explicitly documented as an optimization: "Sigverify drops at-or-below-floor arrivals... ahead of signature verification" (`banking-stage-ingress-types/src/lib.rs:71-75`).

`apply_priority_floor_to_batch` (`core/src/sigverify.rs:413-440`) calls `calculate_priority_from_bytes(bank, data)` on the raw packet bytes for each packet, and only marks a packet discarded if `priority <= floor`. `calculate_priority_from_bytes` (`core/src/transaction_priority.rs:73-88`) parses the bytes with `SanitizedTransactionView::try_new_sanitized`, which performs structural/format sanitization only — it does not verify ed25519 signatures. The resulting `RuntimeTransaction` is then fed into `calculate_priority_and_cost` (`core/src/transaction_priority.rs:32-66`), which computes `reward` via `solana_fee::calculate_fee_details` (`fee/src/lib.rs:29-39`). That function derives the fee purely from `message.num_transaction_signatures()`/`num_ed25519_signatures()` etc. and the message's self-declared `prioritization_fee` (i.e., the `compute_unit_price` instruction) — no cryptographic signature check and no fee-payer balance check occurs anywhere in this path.

Consequently, an attacker can construct a syntactically well-formed transaction (valid header/instruction layout, arbitrary/garbage signature bytes, any pubkey as fee payer, no real funds) with an extremely high `set_compute_unit_price` value. This yields an artificially high computed `priority` (per the `P = R / (1 + C)` formula in `calculate_priority_and_cost`), exceeding any published floor, so `apply_priority_floor_to_batch` keeps the packet (`any_kept = true` branch, `core/src/transaction_priority.rs`/`core/src/sigverify.rs:436`). The packet therefore proceeds unconditionally to the full `ed25519_verify_serial` call (`core/src/sigverify.rs:327-331`), consuming real CPU, and will subsequently fail signature verification (or later fail during execution for lack of funds) so the leader collects no fee — precisely the disproportion the floor was intended to prevent under saturation.

### Impact Explanation
This falls under CPU-exhaustion / QoS-evasion in the sigverify thread pool: the floor mechanism is the specific defense the scheduler publishes when its buffer is saturated to keep expensive ed25519 verification proportional to actual paid value, and it is defeated by a self-reported, unverified field. During saturation (the exact precondition when this defense is supposed to matter), an unstaked attacker can flood the TPU with garbage-signature, fake-high-priority packets that consume full ed25519 verification cost identically to legitimate high-fee traffic, while providing zero real payment. This degrades sigverify throughput and processing fairness for genuine fee-paying transactions during congestion, matching the "grossly underpriced pre-fee work" / QoS-evasion category referenced in the audit prompt.

### Likelihood Explanation
Feasible and repeatable: it requires only an unstaked TCP/QUIC-connected client on the TPU port, no keys need to be leaked and no valid balance is required, and no privileged component control. The only precondition is a saturated scheduler (achievable via a sustained volume of transactions, including the attacker's own low-cost traffic, driving the buffer to the `SATURATION_BUFFER_PCT` watermark, `core/src/banking_stage/transaction_scheduler/scheduler_controller.rs:44-46,338-352`). Crafting a packet with a high `compute_unit_price` and structurally valid-but-forged signature bytes is inexpensive and can be automated to generate a continuous flood.

### Recommendation
Do not rely purely on self-declared `compute_unit_price`/reward figures for the pre-sigverify floor decision without some cost-bounding or partial validation. Options: perform a cheap partial signature/format sanity check (e.g., signature byte non-triviality, static account resolvability) before trusting the declared priority; rate-limit/deduplicate by fee-payer pubkey independent of claimed priority; or incorporate an inexpensive proof-of-work-like cost (e.g., requiring valid recent blockhash and plausible fee payer with balance lookup) before according a packet floor-bypass privilege. At minimum, cap or discount trust in `compute_unit_price` for floor purposes until signatures are verified, or move a cheap validity pre-check ahead of the floor comparison to prevent unverified inflated priorities from exempting packets from the floor drop.

fn apply_priority_floor_to_batch(
    batch: &mut PacketBatch,
    floor: u64,
    bank: &Bank,
) -> (usize, bool) {
    let mut dropped: usize = 0;
    let mut any_kept = false;
    for mut packet in batch.iter_mut() {
        if packet.meta().discard() {
            continue;
        }
        let Some(data) = packet.data(..) else {
            // Zero-length or otherwise unreadable: leave to downstream
            // stages to reject.
            any_kept = true;
            continue;
        };
        // Unparseable packets are kept and left for downstream rejection.
        match calculate_priority_from_bytes(bank, data) {
            Some(priority) if priority <= floor => {
                packet.meta_mut().set_discard(true);
                dropped = dropped.saturating_add(1);
            }
            _ => any_kept = true,
        }
    }
    (dropped, !any_kept)
}

pub(crate) fn calculate_priority_and_cost<Tx: TransactionMeta + SVMStaticMessage>(
    bank: &Bank,
    transaction: &Tx,
    transaction_configuration: &TransactionConfiguration,
) -> (u64, u64) {
    let cost = CostModel::calculate_cost_for_executed_transaction(
        transaction,
        u64::from(transaction_configuration.compute_unit_limit),
        transaction_configuration.loaded_accounts_data_size_limit,
        &bank.feature_set,
    )
    .sum();
    let fee_details = solana_fee::calculate_fee_details(
        transaction,
        bank.fee_structure().lamports_per_signature,
        transaction_configuration.priority_fee_lamports,
        bank.fee_features(),
    );
    let reward = bank
        .calculate_reward_and_burn_fee_details(&CollectorFeeDetails::from(fee_details))
        .get_deposit();

    // We need a multiplier here to avoid rounding down too aggressively.
    // For many transactions, the cost will be greater than the fees in terms of raw lamports.
    // For the purposes of calculating prioritization, we multiply the fees by a large number so that
    // the cost is a small fraction.
    // An offset of 1 is used in the denominator to explicitly avoid division by zero.
    const MULTIPLIER: u64 = 1_000_000;
    (
        reward
            .saturating_mul(MULTIPLIER)
            .saturating_div(cost.saturating_add(1)),
        cost,
    )
}

/// Priority floor shared from the banking-stage scheduler to sigverify.
///
/// When saturated, the scheduler publishes the queue-min transaction's
/// priority. Sigverify drops at-or-below-floor arrivals.
/// In practice, transactions always have non-zero priorities.

pub struct SchedulerPriorityFloor(AtomicU64);

impl SchedulerPriorityFloor {
    pub fn new() -> Self {

        self.0.store(floor, Ordering::Relaxed);
    }

    pub fn clear(&self) {
        self.set(0);
    }

    pub fn get(&self) -> u64 {
        self.0.load(Ordering::Relaxed)
    }
}
