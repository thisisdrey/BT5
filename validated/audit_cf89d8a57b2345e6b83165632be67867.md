### Title
Remote peer-controlled `data_url` in Handshake enables SSRF-style forced outbound requests to internal/loopback addresses - (File: stackslib/src/util_lib/strings.rs, stackslib/src/net/chat.rs)

### Summary
A remote, unauthenticated (pre-handshake) peer supplies its own `data_url` inside a `Handshake`/`HandshakeAccept` message. This value is only checked by `UrlString::parse_to_block_url()` and `UrlString::has_routable_host()`, neither of which rejects loopback, RFC1918/private, or link-local (e.g. cloud metadata `169.254.169.254`) addresses. The victim node subsequently resolves DNS/IP for this URL and issues real outbound HTTP GET/POST requests (blocks, attachments, tenure data) to it via `send_http_request`/`connect_or_send_http_request`.

### Finding Description
`UrlString::parse_to_block_url` only enforces scheme (`http`/`https`), absence of userinfo, presence of a host, and absence of query/fragment: [1](#0-0) 

`UrlString::has_routable_host` only excludes `0.0.0.0`/`::`/`[::]`, not loopback (`127.0.0.1`), private ranges (`10.0.0.0/8`, `192.168.0.0/16`, `172.16.0.0/12`), or link-local (`169.254.0.0/16`, which hosts the AWS/GCP/Azure instance-metadata service): [2](#0-1) 

This `data_url` originates from an untrusted peer's `HandshakeData` and is copied verbatim into the conversation state on both inbound and outbound handshakes via `update_from_handshake_data`, with no additional filtering: [3](#0-2) 

The node later resolves this URL's host to an IP (accepting whatever DNS/IP the URL specifies) in `ConversationHttp`/neighbor-walk DNS resolution logic: [4](#0-3) 

and initiates a real, blocking HTTP request to that resolved address/port to fetch node data (e.g., attachments, blocks) via `send_http_request`, which performs `TcpStream::connect_timeout` against whatever `SocketAddr` the URL resolves to, with no address-class check performed there either: [5](#0-4) 

Note that `stackslib/src/net/neighbors/walk.rs::handle_handshake_accept` does contain a private-IP override, but it only applies to the *handshake-reported source IP/port* (`addrbytes`/`port`) used for neighbor-DB bookkeeping in the P2P walk — not to the `data_url` string used for HTTP fetches: [6](#0-5) 

Because the HTTP request paths issued (`/v2/blocks/...`, `/v2/attachments/...`, tenure endpoints) are fixed by the protocol and not attacker-controlled, this is not a full arbitrary-request SSRF, but it does let any remote unauthenticated peer force the victim node to make outbound TCP/HTTP connections to arbitrary internal or loopback IP:port combinations of the attacker's choosing, by simply declaring that address as its `data_url`. This breaks the intended equality that a peer's advertised "reachable, routable, external" service endpoint is validated before the node performs outbound requests to it.

### Impact Explanation
This allows a remote unauthenticated peer to direct victim-node outbound HTTP connections at internal-only infrastructure (localhost admin ports, RFC1918 hosts, cloud-provider metadata endpoints) reachable from the node's network position. Depending on deployment, this can be used for internal network/port reconnaissance (success/failure/timing differences reveal what's listening internally) and, if any internal service's response accidentally matches expected Stacks protocol formats, could feed unintended data into node processing logic. This does not qualify as Critical (it doesn't achieve unauthorized state writes, forged data propagation to the network, or memory disclosure by itself), but it fits the High bar of "bounded compute/read-endpoint style state fetch to a non-validated destination," since it's a read/probe capability against arbitrary internal targets triggered by a single unauthenticated handshake message.

### Likelihood Explanation
High likelihood of reachability: any peer, even one that hasn't completed a handshake yet in some flows, can send a `Handshake`/`HandshakeAccept` with a crafted `data_url`; there is no authentication requirement on the URL's host value, and no allow-list/deny-list for private/loopback/link-local address ranges is applied before the node performs outbound HTTP fetches to it.

### Recommendation
Extend `UrlString::has_routable_host()` (or add a dedicated check invoked before any outbound HTTP request is issued to a peer-supplied `data_url`) to reject loopback, RFC1918 private ranges, link-local (169.254.0.0/16) and multicast/reserved ranges, both for literal IP hosts and for the resolved DNS result in `stackslib/src/net/chat.rs`'s DNS-resolution logic. Apply this validation both when parsing incoming handshake data (`update_from_handshake_data`) and at the point resolved IPs are stored (`self.data_ip`), so DNS rebinding to internal addresses is also blocked.

### Proof of Concept
1. Attacker runs a Stacks P2P node/peer and connects to the victim node.
2. Attacker's `Handshake`/`HandshakeAccept` message sets `data_url = "http://169.254.169.254:80/"` (or `http://127.0.0.1:9000/`, targeting a local admin service the attacker suspects is running).
3. Victim's `update_from_handshake_data` stores this URL unfiltered [3](#0-2) .
4. Victim's data-URL DNS/IP resolution logic resolves/accepts the literal IP [4](#0-3) , and only `0.0.0.0`/`::` would have been rejected by `has_routable_host` [2](#0-1) .
5. When the victim later needs to fetch an attachment/block/tenure from this "neighbor," it issues a real outbound HTTP GET to `169.254.169.254:80` or `127.0.0.1:9000` via `send_http_request`'s `TcpStream::connect_timeout` [5](#0-4) , confirming the SSRF-style forced-connection primitive.

    pub fn parse_to_block_url(&self) -> Result<url::Url, codec_error> {
        // even though this code uses from_utf8_unchecked() internally, we've already verified that
        // the bytes in this string are all ASCII.
        let url = url::Url::parse(&self.to_string())
            .map_err(|e| codec_error::DeserializeError(format!("Invalid URL: {:?}", &e)))?;

        if url.scheme() != "http" && url.scheme() != "https" {
            return Err(codec_error::DeserializeError(format!(
                "Invalid URL: invalid scheme '{}'",
                url.scheme()
            )));
        }

        if !url.username().is_empty() || url.password().is_some() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: must not contain a username/password".to_string(),
            ));
        }

        if url.host_str().is_none() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: no host string".to_string(),
            ));
        }

        if url.query().is_some() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: query strings not supported for block URLs".to_string(),
            ));
        }

        if url.fragment().is_some() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: fragments are not supported for block URLs".to_string(),
            ));
        }

        Ok(url)
    }

    /// Is this URL routable?
    /// i.e. is the host _not_ 0.0.0.0 or ::?
    pub fn has_routable_host(&self) -> bool {
        let url = match url::Url::parse(&self.to_string()) {
            Ok(x) => x,
            Err(_) => {
                // should be unreachable
                return false;
            }
        };
        match url.host_str() {
            Some(host_str) => {
                if host_str == "0.0.0.0" || host_str == "[::]" || host_str == "::" {
                    return false;
                } else {
                    return true;
                }
            }
            None => {
                return false;
            }
        }
    }

/// Send an HTTP request to the given host:port.  Returns the decoded response.
/// Internally, this creates a socket, connects it, sends the HTTP request, and decodes the HTTP
/// response.  It is a blocking operation.
///
/// If the request encounters a network error, then return an error.  Don't retry.
/// If the request times out after `timeout`, then return an error.
pub fn send_http_request(
    host: &str,
    port: u16,
    request: StacksHttpRequest,
    timeout: Duration,
) -> Result<StacksHttpResponse, io::Error> {
    // Find the host:port that works.
    // This is sometimes necessary because `localhost` can resolve to both its ipv4 and ipv6
    // addresses, but usually, Stacks services like event observers are only bound to ipv4
    // addresses.  So, be sure to use an address that will lead to a socket connection!
    let mut stream_and_addr = None;
    let mut last_err = None;
    for addr in format!("{host}:{port}").to_socket_addrs()? {
        debug!("send_request: connect to {}", &addr);
        match TcpStream::connect_timeout(&addr, timeout) {
            Ok(sock) => {
                stream_and_addr = Some((sock, addr));
                break;
            }
            Err(e) => {
                last_err = Some(e);
            }
        }
    }

    let Some((mut stream, addr)) = stream_and_addr else {
        return Err(last_err.unwrap_or(io::Error::other("Unable to connect to {host}:{port}")));
    };

    stream.set_read_timeout(Some(timeout))?;
    stream.set_write_timeout(Some(timeout))?;
    stream.set_nodelay(true)?;
