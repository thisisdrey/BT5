## Title
Cross-chain Replay in the `ValidateMultiSign` TVM Precompile — Missing Chain Binding in Signature Hash — (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

## Summary
The `ValidateMultiSign` precompiled contract (address reachable via the `validatemultisign` TVM opcode) authenticates off-chain-signed authorizations for an account's on-chain `Permission` by recovering signer addresses over a hash built solely from `address`, `permissionId`, and caller-supplied `data`. Because this hash never binds to `block.chainid` (or any other chain-unique value), any signature that is valid for a given account/permission/payload triple on one java-tron-based network is equally valid on any other java-tron-based network that shares the same account address and permission configuration (e.g., mainnet vs. a fork/testnet/private chain deployed from the same genesis tooling), letting an unprivileged transaction broadcaster replay the signature cross-chain.

## Finding Description
`ValidateMultiSign.execute()` computes the authentication hash as: [1](#0-0) 

```
byte[] address = words[0].toTronAddress();
int permissionId = words[1].intValueSafe();
byte[] data = words[2].getData();

byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
byte[] hash = Sha256Hash.hash(CommonParameter.getInstance().isECKeyCryptoEngine(), combine);
```

It then recovers each supplied signature against this `hash` and checks accumulated weight against the account's on-chain `Permission` threshold: [2](#0-1) 

Unlike the built-in transaction-signing path — where `TransactionCapsule.getTransactionId()` binds the signature to `ref_block_hash`/`expiration` fields tied to a specific chain's block history [3](#0-2)  — the `combine` payload fed into `ValidateMultiSign` contains no chain-identifying component at all. This is the exact analog of the reported `_borrowHash` bug: a hash used to authorize an action is derived only from application-level parameters (`address`, `permissionId`, `data`), omitting any chain-scoping value (`block.chainid`), so the resulting off-chain signature is portable across any deployment sharing the same account/permission/data triple.

## Impact Explanation
Any TVM smart contract that relies on `ValidateMultiSign` for off-chain-authorized actions (meta-transactions, permit-style approvals, multisig wallets, cross-chain bridge attestations, etc.) inherits this weakness: a user's signature authorizing an action on Chain A (e.g., mainnet) can be captured and replayed verbatim on Chain B (e.g., Nile testnet, a private/forked java-tron network, or a future sidechain) as long as the target account address, `permissionId`, and `data` match — which is trivially true for identical contract bytecode deployed with the same parameters on both networks. This can lead to unauthorized execution of privileged, permission-gated operations and theft/misuse of funds on the second chain without the victim ever having intended to authorize anything there.

## Likelihood Explanation
Exploitation requires no privileged access: an attacker only needs to observe a valid signature emitted/broadcast for use with `ValidateMultiSign` on one network and resubmit the identical `(address, permissionId, data, signatures)` tuple against a contract on another java-tron-based network. Given the growing use of java-tron forks/testnets/private chains sharing tooling and genesis conventions, and that dApps commonly deploy identical bytecode across multiple TRON-compatible networks, this is a realistic and low-effort replay scenario for any contract that uses this precompile as an authorization primitive.

## Recommendation
Include a chain-unique value in the signed payload before hashing, e.g.:

```java
byte[] combine = ByteUtil.merge(
    address,
    ByteArray.fromInt(permissionId),
    ByteArray.fromLong(chainId), // or the equivalent TVM CHAINID value
    data);
byte[] hash = Sha256Hash.hash(CommonParameter.getInstance().isECKeyCryptoEngine(), combine);
```//
Alternatively, document that consuming contracts MUST mix `chainid` (available via the `CHAINID` opcode) into `data` themselves before calling `validatemultisign`, and update reference/example implementations accordingly so downstream contract authors are not silently exposed.

## Proof of Concept
1. Deploy a contract on Chain A that gates a privileged operation (e.g., withdrawal) behind `ValidateMultiSign(ownerAddress, permissionId, data, signatures)`.
2. Owner signs `Sha256Hash.hash(merge(ownerAddress, permissionId, data))` off-chain to authorize the operation on Chain A.
3. Deploy the identical bytecode with the same account/permission configuration on Chain B (a java-tron fork/testnet sharing the same address format).
4. Submit the same `(ownerAddress, permissionId, data, signatures)` tuple to the Chain B contract's `validatemultisign` call.
5. `ValidateMultiSign.execute()` recomputes the identical `hash` (no chain binding), recovers the same signer address, and accepts the signature, authorizing the operation on Chain B without the owner ever signing anything intended for Chain B. [4](#0-3)

    private static final int ENGERYPERSIGN = 1500;
    private static final int MAX_SIZE = 5;
    private static final int ABI_HEADER_WORDS = 5;
    private static final int ABI_ITEM_WORDS = 5;


    @Override
    public long getEnergyForData(byte[] data) {
      long cnt = (data.length / WORD_SIZE - 5) / 5;
      // one sign 1500, half of ecrecover
      return cnt * ENGERYPERSIGN;
    }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] rawData) {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(rawData, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(rawData);
      byte[] address = words[0].toTronAddress();
      int permissionId = words[1].intValueSafe();
      byte[] data = words[2].getData();

      byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
      byte[] hash = Sha256Hash.hash(CommonParameter
          .getInstance().isECKeyCryptoEngine(), combine);

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[3].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }
      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[3].intValueSafe() / WORD_SIZE, rawData) :
          extractBytesArray(words, words[3].intValueSafe() / WORD_SIZE, rawData);

      if (signatures.length == 0 || signatures.length > MAX_SIZE) {
        return Pair.of(true, DATA_FALSE);
      }

      AccountCapsule account = this.getDeposit().getAccount(address);
      if (account != null) {
        try {
          Permission permission = account.getPermissionById(permissionId);
          if (permission != null) {
            //calculate weight
            long totalWeight = 0L;
            List<byte[]> executedSignList = new ArrayList<>();
            for (byte[] sign : signatures) {
              byte[] recoveredAddr = recoverAddrBySign(sign, hash);

              sign = merge(recoveredAddr, sign);
              if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
                if (ByteArray.matrixContains(executedSignList, sign)) {
                  continue;
                }
                MUtil.checkCPUTime();
              }
              long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
              if (weight == 0) {
                //incorrect sign
                return Pair.of(true, DATA_FALSE);
              }
              totalWeight += weight;
              executedSignList.add(sign);
              executedSignList.add(recoveredAddr);
            }

            if (totalWeight >= permission.getThreshold()) {
              return Pair.of(true, dataOne());
            }
          }
        } catch (Throwable t) {
          if (t instanceof OutOfTimeException) {
            throw t;
          }
          logger.info("ValidateMultiSign error:{}", t.getMessage());
        }
      }
      return Pair.of(true, DATA_FALSE);
    }
