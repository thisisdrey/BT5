Audit Report

## Title
Rounding of `unbonding_points` to zero balance in `pallet-nomination-pools::unbond()` permanently strands member funds — ([File: substrate/frame/nomination-pools/src/lib.rs])

## Summary
`Pallet::unbond()` converts a member's `unbonding_points` into an actual balance via `BondedPool::dissolve()` → `Pallet::point_to_balance()`, which performs a round-down division. `point_to_balance` only special-cases the situation where `current_balance`, `current_points`, or the `points` argument itself is zero — it does not guard against a nonzero `points` argument that rounds down to a zero result, and `dissolve` returns this value unchecked. That unguarded zero balance then flows into `T::StakeAdapter::unbond` (a no-op on zero rather than an error) and into the destination sub-pool's `issue()` call, producing `points_unbonded == 0` while the member's `points` and the bonded pool's `points`/`balance` are still debited by the full `unbonding_points`. [1](#0-0) [2](#0-1) [3](#0-2) 

## Finding Description
The claim is largely correct on the mechanics of `point_to_balance`/`dissolve`/`unbond`, but the crucial missing analysis — which the submitter explicitly flagged as unverified — is whether `BondedPool::ok_to_unbond_with` closes this gap. On inspection, it does *not* fully close it: [4](#0-3) 

`ok_to_unbond_with` enforces a minimum-remaining-balance check (`balance_after_unbond >= MinJoinBond::<T>::get()` or `depositor_min_bond()`), but this check is explicitly **skipped when `is_full_unbond` is true**: `is_full_unbond || balance_after_unbond >= ...`. A permissioned member calling `unbond` with `unbonding_points == active_points()` (a full unbond) bypasses the minimum-bond floor entirely, and no check anywhere validates that the *balance* corresponding to those points (via `point_to_balance` at the bonded pool's current, possibly severely slash-degraded, ratio) is nonzero. `ok_to_be_open`/`MaxPointsToBalance` only gates new joins into an `Open` pool — it is not invoked from `unbond`, so a pool that has drifted past that ratio (through legitimate, unprivileged slashing) does not block existing members from unbonding, and `unbond` proceeds using the stale, unguarded `point_to_balance` calculation. This confirms the described exploit path is reachable via a full unbond from a heavily-slashed pool, which is exactly the scenario the claim's PoC describes (albeit the PoC uses a small partial value; the actually-reachable path is the full-unbond exemption). [5](#0-4) 

## Impact Explanation
This is a genuine value-conservation violation matching the "Balances/assets/pools ... must conserve value and settle exactly once to the rightful beneficiary and amount" pivot. A pool member using only the public `unbond` extrinsic can have real bonded value silently reassigned to the remaining pool members while their own points are debited to zero balance in the destination sub-pool, with no revert and no way to recover the value later via `withdraw_unbonded`. [6](#0-5) 

## Likelihood Explanation
The precondition (an extremely degraded points:balance ratio caused by slashing) is a normal, unprivileged, protocol-supported event, not attacker-controlled by itself, but once it exists, any affected member can trigger the loss deterministically and without any privileged capability by issuing a full unbond. This is fully reachable through the public, permissionless `unbond` call path.

## Recommendation
In `BondedPool::dissolve`/`Pallet::unbond`, after computing `unbonding_balance`, reject the operation (or round in the member's favor) whenever `unbonding_balance.is_zero()` while `unbonding_points` is nonzero — regardless of whether the unbond is full or partial — since the current `is_full_unbond` exemption in `ok_to_unbond_with` bypasses the only existing safeguard for exactly this case.

## Proof of Concept
1. Bond several members into a pool at a 1:1 points:balance ratio.
2. Apply a slash large enough that `bonded_pool.balance` becomes vanishingly small relative to `bonded_pool.points` (e.g., balance = 1, points = 10^12), reachable via the pool's existing slash-application flow.
3. A member calls `Pools::unbond(origin, member_account, unbonding_points)` with `unbonding_points == member.active_points()` (a full, permissioned unbond), which bypasses the `MinJoinBond`/`depositor_min_bond` check in `ok_to_unbond_with` via the `is_full_unbond` exemption.
4. `point_to_balance` rounds `unbonding_balance` to `0`; `T::StakeAdapter::unbond` no-ops; the sub-pool's `issue(0)` yields `points_unbonded == 0`; the member's `active_points` are reduced to `0` and `try_unbond` records `unbonding_points: 0` in `unbonding_eras`. The member permanently loses their proportional claim, which is redistributed to remaining pool members through the unchanged bonded balance relative to their points. [7](#0-6)

	fn ok_to_unbond_with(
		&self,
		caller: &T::AccountId,
		target_account: &T::AccountId,
		target_member: &PoolMember<T>,
		unbonding_points: BalanceOf<T>,
	) -> Result<(), DispatchError> {
		let is_permissioned = caller == target_account;
		let is_depositor = *target_account == self.roles.depositor;
		let is_full_unbond = unbonding_points == target_member.active_points();

		let balance_after_unbond = {
			let new_depositor_points =
				target_member.active_points().saturating_sub(unbonding_points);
			let mut target_member_after_unbond = (*target_member).clone();
			target_member_after_unbond.points = new_depositor_points;
			target_member_after_unbond.active_balance()
		};

		// any partial unbonding is only ever allowed if this unbond is permissioned.
		ensure!(
			is_permissioned || is_full_unbond,
			Error::<T>::PartialUnbondNotAllowedPermissionlessly
		);

		// any unbond must comply with the balance condition:
		ensure!(
			is_full_unbond ||
				balance_after_unbond >=
					if is_depositor {
						Pallet::<T>::depositor_min_bond()
					} else {
						MinJoinBond::<T>::get()
					},
			Error::<T>::MinimumBondNotMet
		);

		// additional checks:
		match (is_permissioned, is_depositor) {
			(true, false) => (),
			(true, true) => {
				// permission depositor unbond: if destroying and pool is empty, always allowed,
				// with no additional limits.
				if self.is_destroying_and_only_depositor(target_member.active_points()) {
					// everything good, let them unbond anything.
				} else {
					// depositor cannot fully unbond yet.
					ensure!(!is_full_unbond, Error::<T>::MinimumBondNotMet);
				}
			},
			(false, false) => {
				// If the pool is blocked, then an admin with kicking permissions can remove a
				// member. If the pool is being destroyed, anyone can remove a member
				debug_assert!(is_full_unbond);
				ensure!(
					self.can_kick(caller) || self.is_destroying(),
					Error::<T>::NotKickerOrDestroying
				)
			},
			(false, true) => {
				// Permissionless depositor unbond is only allowed for a full unbond, and only when
				// destroying with the depositor as sole remaining member. `is_full_unbond` is
				// already guaranteed by the outer `ensure!` above.
				debug_assert!(is_full_unbond);
				ensure!(
					self.is_destroying_and_only_depositor(target_member.active_points()),
					Error::<T>::DoesNotHavePermission
				);
			},
		};

		Ok(())
	}

	/// Dissolve some points from the unbonding pool, reducing the balance of the pool
	/// proportionally. This is the opposite of `issue`.
	///
	/// Returns the actual amount of `Balance` that was removed from the pool.
	fn dissolve(&mut self, points: BalanceOf<T>) -> BalanceOf<T> {
		let balance_to_unbond = self.point_to_balance(points);
		self.points = self.points.saturating_sub(points);
		self.balance = self.balance.saturating_sub(balance_to_unbond);

		balance_to_unbond
	}

	/// Calculate the equivalent balance of `points` in a pool with `current_balance` and
	/// `current_points`.
	fn point_to_balance(
		current_balance: BalanceOf<T>,
		current_points: BalanceOf<T>,
		points: BalanceOf<T>,
	) -> BalanceOf<T> {
		let u256 = T::BalanceToU256::convert;
		let balance = T::U256ToBalance::convert;
		if current_balance.is_zero() || current_points.is_zero() || points.is_zero() {
			// There is nothing to unbond
			return Zero::zero();
		}

		// Equivalent of (current_balance / current_points) * points
		balance(
			u256(current_balance)
				.saturating_mul(u256(points))
				// We check for zero above
				.div(u256(current_points)),
		)
