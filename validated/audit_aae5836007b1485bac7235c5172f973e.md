### Title
Missing identity binding in RaptorCast-style relay control messages allows peer impersonation and relay-state poisoning - (File: `relay_manager.go`)

### Summary
Nebula's relay establishment protocol (`NebulaControl_CreateRelayRequest` / `CreateRelayResponse`) carries self-declared identity fields (`RelayFromAddr`, `RelayToAddr`) inside the encrypted control-message payload. The handler that processes these messages, `relayManager.handleCreateRelayRequest`, never checks that the claimed `RelayFromAddr` matches the VPN address of the actual authenticated peer that sent the message (`h.vpnAddrs`). This is the same bug class as the RaptorCast Secondary report: a cryptographically authenticated channel (the Noise-encrypted tunnel to `h`) is used to carry a payload with an internal identity claim, but that claim is never cross-checked against the channel's authenticated identity.

### Finding Description
Control messages arrive already decrypted and are dispatched via `relayManager.HandleControlMsg`, which only null-checks `RelayFromAddr`/`RelayToAddr` before routing to `handleCreateRelayRequest`/`handleCreateRelayResponse`: [1](#0-0) 

`handleCreateRelayRequest` then extracts the caller-supplied `from` address directly from the message body and uses it as the identity of the node the relay is being established "for," with no verification that `from` equals the VPN address of the actual sender `h` of this authenticated tunnel: [2](#0-1) 

The only identity check performed is that `from` is not one of *my own* addresses (self-impersonation guard); there is no check that `from == h.vpnAddrs[0]`: [3](#0-2) 

When the check passes, relay state is created and bound to the real (attacker-controlled) `HostInfo h`, but indexed by the attacker-chosen `from` value: [4](#0-3) [5](#0-4) 

This mirrors the RaptorCast root cause exactly: Stage 1 (cryptographic authentication of the sender via the completed Noise handshake, analogous to RaptorCast's signature verification) is implemented correctly — Nebula's handshake machine does properly bind the recovered static key to the certificate's public key before trusting a peer: [6](#0-5) 
but Stage 2 (checking that identity fields embedded in a post-handshake application payload match the already-authenticated sender) is missing for the relay-request `RelayFromAddr` field, just as it was missing for `validator_id`/`node_id` in the RaptorCast group messages.

### Impact Explanation
Any node that already has a live, authenticated tunnel to a relay-capable node can send a `CreateRelayRequest` claiming an arbitrary `RelayFromAddr` (e.g. a legitimate third-party victim's VPN address it does not control). The relay target will install a `Relay{PeerAddr: <claimed victim>, State: Established}` entry bound to the attacker's real hostinfo, and will send a `CreateRelayResponse` back over the attacker's tunnel. This is remote relay-state poisoning: legitimate relay setup for the real victim can later collide with or be confused by this forged entry (`existingRelay` lookups by IP in `handleCreateRelayRequest`/`handleCreateRelayResponse` key off the claimed address, not off a verified sender), and the relay node may end up believing it can relay data-plane traffic to the impersonated victim through the wrong, attacker-controlled tunnel. This can disrupt or hijack relayed communication paths and cause denial-of-service against legitimate relay establishment for the impersonated node, similar to the RaptorCast "PrepareGroup impersonation" and "ConfirmGroup poisoning" scenarios (peer-discovery/relay-routing state poisoned by an unauthenticated identity claim).

### Likelihood Explanation
High. No special privileges are required beyond having any working (even just-established) Nebula tunnel to a relay-capable node — which any peer holding a CA-signed certificate can obtain by design. Crafting the `RelayFromAddr` field to an arbitrary value requires only modifying a field in the `NebulaControl` protobuf payload before it is encrypted and sent over one's own legitimate tunnel; it costs nothing and needs no further validator/relay-specific privilege.

### Recommendation
In `handleCreateRelayRequest` (and symmetrically in `handleCreateRelayResponse`), require that the claimed `RelayFromAddr` matches one of the sending `HostInfo`'s authenticated `h.vpnAddrs` before trusting it as the relay-from identity, e.g.:
```go
from := protoAddrToNetAddr(m.RelayFromAddr)
if !slices.Contains(h.vpnAddrs, from) {
    logMsg.Error("RelayFromAddr does not match authenticated sender", "claimed", from, "actual", h.vpnAddrs)
    return
}
```
This binds the application-level identity claim to the cryptographically authenticated tunnel identity, closing the gap analogous to the RaptorCast fix (`prep.validator_id.pubkey() != recovered_pubkey`).

### Proof of Concept
1. Attacker establishes a normal, legitimate Nebula tunnel to relay node `R` (attacker's own certificate, own VPN address `A`).
2. Attacker sends `NebulaControl{Type: CreateRelayRequest, RelayFromAddr: <victim V's VPN address>, RelayToAddr: <R's VPN address>, InitiatorRelayIndex: idx}` over its authenticated tunnel to `R`.
3. `HandleControlMsg` → `handleCreateRelayRequest` on `R` sees `target == R` (me), checks only that `from` (= V) isn't `R`'s own address, then calls `AddRelay(rm.l, h, f.hostMap, from=V, &InitiatorRelayIndex, TerminalType, Established)`, where `h` is the attacker's real `HostInfo`.
4. `R` now believes it has an `Established` relay entry for VPN address `V` living on the attacker's tunnel, and sends `CreateRelayResponse` back to the attacker, completing the (forged) relay association — without `V` ever being involved or the message signer's certificate being checked against `V`. 	hm.Lock()

		index, err := generateIndex(l)
		if err != nil {
			return 0, err
		}

		_, inRelays := hm.Relays[index]
		if !inRelays {
			// Avoid standing up a relay that can't be used since only the primary hostinfo

				// The tunnel was torn down after the caller grabbed relayHostInfo. A relay standing
				// on an unlinked hostinfo would never carry traffic, and its Relays entry could
				// never be reclaimed since the delete-time cleanup has already run.
				return 0, errors.New("relay hostinfo is no longer in the hostmap")
			}

			hm.Relays[index] = relayHostInfo
			newRelay := Relay{
				Type:       relayType,
				State:      state,
				LocalIndex: index,
				PeerAddr:   vpnIp,
			}

				newRelay.RemoteIndex = *remoteIdx
			}
			relayHostInfo.relayState.InsertRelay(vpnIp, index, &newRelay)

			return index, nil
		}
	}

	return 0, errors.New("failed to generate unique localIndexId")
}

func (rm *relayManager) HandleControlMsg(h *HostInfo, d []byte, f *Interface) {
	msg := &NebulaControl{}
	err := msg.Unmarshal(d)
	if err != nil {
		h.logger(f.l).Error("Failed to unmarshal control message", "error", err)
		return
	}

	var v cert.Version
	if msg.OldRelayFromAddr > 0 || msg.OldRelayToAddr > 0 {
		v = cert.Version1

		b := [4]byte{}
		binary.BigEndian.PutUint32(b[:], msg.OldRelayFromAddr)
		msg.RelayFromAddr = netAddrToProtoAddr(netip.AddrFrom4(b))

		binary.BigEndian.PutUint32(b[:], msg.OldRelayToAddr)
		msg.RelayToAddr = netAddrToProtoAddr(netip.AddrFrom4(b))
	} else {
		v = cert.Version2
	}

	// validate:
	switch msg.Type {
	case NebulaControl_CreateRelayRequest, NebulaControl_CreateRelayResponse:
		if msg.RelayFromAddr == nil {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("Control message received with nil RelayFromAddr", "type", msg.Type)
			}
			return
		} else if msg.RelayToAddr == nil {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("Control message received with nil RelayToAddr", "type", msg.Type)
			}
			return
		}

func (rm *relayManager) handleCreateRelayRequest(v cert.Version, h *HostInfo, f *Interface, m *NebulaControl) {
	//nil-checks for protoAddrToNetAddr handled by caller
	from := protoAddrToNetAddr(m.RelayFromAddr)
	target := protoAddrToNetAddr(m.RelayToAddr)

	logMsg := rm.l.With(
		"relayFrom", from,
		"relayTo", target,
		"initiatorRelayIndex", m.InitiatorRelayIndex,
		"vpnAddrs", h.vpnAddrs,
	)

	logMsg.Info("handleCreateRelayRequest")
	// Is the source of the relay me? This should never happen, but did happen due to
	// an issue migrating relays over to newly re-handshaked host info objects.
	if f.myVpnAddrsTable.Contains(from) {
		logMsg.Error("Discarding relay request from myself", "myIP", from)
		return
	}

	// Is the target of the relay me?
	if f.myVpnAddrsTable.Contains(target) {
		existingRelay, ok := h.relayState.QueryRelayForByIp(from)
		if ok {
			switch existingRelay.State {
			case Requested:
				ok = h.relayState.CompleteRelayByIP(from, m.InitiatorRelayIndex)
				if !ok {
					logMsg.Error("Relay State not found")
					return
				}
			case Established:
				if existingRelay.RemoteIndex != m.InitiatorRelayIndex {
					// We got a brand new Relay request, because its index is different than what we saw before.
					// This should never happen. The peer should never change an index, once created.
					logMsg.Error("Existing relay mismatch with CreateRelayRequest",
						"existingRemoteIndex", existingRelay.RemoteIndex)
					return
				}
			case Disestablished:
				if existingRelay.RemoteIndex != m.InitiatorRelayIndex {
					// We got a brand new Relay request, because its index is different than what we saw before.
					// This should never happen. The peer should never change an index, once created.
					logMsg.Error("Existing relay mismatch with CreateRelayRequest",
						"existingRemoteIndex", existingRelay.RemoteIndex)
					return
				}
				// Mark the relay as 'Established' because it's safe to use again
				h.relayState.UpdateRelayForByIpState(from, Established)
			case PeerRequested:
				// I should never be in this state, because I am terminal, not forwarding.
				logMsg.Error("Unexpected Relay State found",
					"existingRemoteIndex", existingRelay.RemoteIndex,
					"state", existingRelay.State)
			}
		} else {
			_, err := AddRelay(rm.l, h, f.hostMap, from, &m.InitiatorRelayIndex, TerminalType, Established)
			if err != nil {
				logMsg.Error("Failed to add relay", "error", err)
				return
			}
		}

		relay, ok := h.relayState.QueryRelayForByIp(from)
		if !ok {
			logMsg.Error("Relay State not found", "from", from)
			return
		}

func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}
