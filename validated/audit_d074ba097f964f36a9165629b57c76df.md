### Title
Permissionless `lending_pool_emissions_deposit` enables risk-free sandwich theft of emissions from existing depositors - ([File: programs/marginfi/src/instructions/marginfi_group/configure_bank.rs])

### Summary
`lending_pool_emissions_deposit` is a permissionless instruction that instantly bumps a bank's `asset_share_value` by injecting same-mint tokens into the liquidity vault and dividing the new total by the *current* `total_asset_shares` [1](#0-0) . Because the price bump happens atomically and there is no vesting/lockup period on deposits or withdrawals, any attacker can deposit into the bank immediately before this call and withdraw immediately after (even within the same transaction), capturing a pro-rata slice of the emissions intended for existing long-term depositors — with zero market/time exposure. This is a stronger version of the referenced Citadel finding, which was downgraded to Medium specifically because Citadel's 21-day vesting made the attack marginally profitable at best; marginfi's analog has no such mitigating delay.

### Finding Description
`lending_pool_emissions_deposit` is declared explicitly as permissionless [2](#0-1) . Its accounts require only a valid `bank`/`mint`/`liquidity_vault` triple and a signer `depositor` who funds the transfer [3](#0-2)  — there is no restriction on who calls it or when.

The core logic:
```
let total_asset_shares = I80F48::from(bank.total_asset_shares);
...
transfer_checked(...)                       // moves `amount` into liquidity_vault
let total_assets = bank.get_asset_amount(total_asset_shares)?;
let updated_total_assets = total_assets + amount;
bank.asset_share_value = updated_total_assets / total_asset_shares;
``` [4](#0-3) 

`total_asset_shares` is snapshotted at call time — it includes whatever shares exist at that instant, regardless of how recently they were minted. Deposits (`lending_account_deposit` → `BankAccountWrapper::deposit`) and withdrawals (`lending_account_withdraw` → `BankAccountWrapper::withdraw`/`withdraw_all`) have no minimum holding period, cooldown, or time-weighted vesting logic anywhere in the deposit/withdraw path [5](#0-4) [6](#0-5) . A user can deposit, be minted shares at the pre-emissions `asset_share_value`, then immediately withdraw (even `withdraw_all`) once the emissions bump has occurred, realizing the appreciated value instantly [7](#0-6) .

This directly mirrors the root cause in the referenced Citadel report: a permissionless function increases a share-based accounting value for *all* current holders atomically, and depositing right before / withdrawing right after captures value that should have accrued only to holders present *before* the injection was announced/queued.

### Impact Explanation
Any legitimate emissions funding transaction (e.g., a protocol team or integrator calling `lending_pool_emissions_deposit` to reward existing lenders in a bank) can be sandwiched: an attacker deposits into the same bank just before the emissions deposit lands, and withdraws (or `withdraw_all`s) immediately after — inside the same atomic transaction/bundle if they control ordering, or via the same slot/back-run otherwise. This siphons a portion of every emissions payout away from the genuine long-term depositors the reward was meant for, diluting their yield. Unlike the Citadel case, there's no 21-day vesting cost/exposure, so the attack is risk-free and immediately profitable whenever emissions amounts are non-trivial relative to `total_asset_shares`, satisfying "unauthorized transfer of value" from existing depositors to the attacker.

### Likelihood Explanation
Likelihood is limited primarily by whether an attacker can guarantee transaction ordering around a specific `lending_pool_emissions_deposit` call. Since the instruction itself, `lending_account_deposit`, and `lending_account_withdraw`/`withdraw_all` are all permissionless and can be composed by anyone, an attacker with visibility into a pending emissions-funding transaction (e.g., a scheduled/recurring reward call, or one submitted through a public channel) — or a validator/searcher able to control ordering within a slot — can construct a single atomic transaction bundling deposit → (observe/trigger) emissions deposit → withdraw_all, extracting value with no holding-period risk. This is more practically exploitable than the original Citadel finding because Solana transactions can be atomically composed in one bundle, removing the multi-block exposure window entirely.

### Recommendation
- Require a minimum holding period (or use time-weighted / linear-vesting distribution) before newly deposited shares are eligible to receive `lending_pool_emissions_deposit` value, analogous to fixing the Citadel vesting gap.
- Alternatively, snapshot `total_asset_shares` at a point prior to the emissions call (e.g., using a keeper-set “emissions eligibility” timestamp) rather than the instantaneous total, so shares minted in the same or adjacent transaction don't participate.
- Consider restricting `lending_pool_emissions_deposit` to a privileged/admin caller (with off-chain private submission, e.g., not through predictable public infrastructure) to remove the front-run/back-run window, or require it be executed with `withdraw`/`deposit` disabled for one slot.

### Proof of Concept
1. Bank `B` has depositors with `total_asset_shares = S` and `asset_share_value = V`.
2. Attacker observes (or is the one submitting) a `lending_pool_emissions_deposit(amount)` call funding `B` with `amount` tokens.
3. Attacker submits, in the same atomic transaction or immediately before, `lending_account_deposit(D)` into `B`, minting `D/V` shares and increasing `total_asset_shares` to `S' = S + D/V` [5](#0-4) .
4. The emissions deposit executes: `new_V = (S' * V + amount) / S'`, raising every share's value including the attacker's freshly minted ones [1](#0-0) .
5. Attacker immediately calls `lending_account_withdraw(withdraw_all=true)`, redeeming `D/V * new_V` tokens, i.e. `D + D/S' * amount` — profit of `D/S' * amount` extracted purely from the emissions meant for pre-existing depositors, with zero holding-period exposure [7](#0-6) .
