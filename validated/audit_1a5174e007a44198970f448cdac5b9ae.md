### Title
Vote rewards are permanently locked in `DelegationStore` when a witness's per‑cycle vote total is `REMARK`/`0` at reward‑distribution time - (File: `chainbase/src/main/java/org/tron/core/service/MortgageService.java`)

### Summary
`MortgageService` accumulates block/transaction‑fee rewards for a witness into `DelegationStore` keyed by `(cycle, srAddress)` via `payReward()`/`addReward()`, but the corresponding distribution logic (`computeReward`) silently discards that reward forever whenever the recorded total vote for that exact cycle is the sentinel value `REMARK` (no record) or `0`. This mirrors the reported Wenwin `Staking` bug: value is credited to an accounting bucket keyed by a denominator (`totalSupply` in Wenwin, "total vote for cycle" here) that can legitimately be zero/unset, and the code path that would distribute the reward simply `continue`s instead of holding, forwarding, or refunding it — permanently freezing the funds.

### Finding Description
`MortgageService.payReward()` unconditionally stores rewards for the current cycle regardless of whether a vote total has been recorded for that cycle: [1](#0-0) 

The reward is looked up later by `computeReward(long cycle, List<Pair<byte[], Long>> votes)`, which is used by both `withdrawReward` and `queryReward`: [2](#0-1) 

Here, `totalVote` is read from `DelegationStore.getWitnessVote(cycle, srAddress)`, which returns the sentinel `REMARK = -1L` when no vote record exists for that `(cycle, address)` pair, and `0` when the recorded vote is zero: [3](#0-2) [4](#0-3) 

In both cases `computeReward` executes `continue`, meaning the previously stored `totalReward` for that `(cycle, srAddress)` key is never distributed to any voter — there is no fallback path that forwards it to a later cycle, refunds it, or otherwise reclaims it. The reward key is permanently orphaned in `DelegationStore`, exactly analogous to the Wenwin `Staking.rewardPerTokenStored` value staying stale (returning early) while incoming rewards accumulate on the contract with `totalSupply == 0`.

The `REMARK`/`0` total-vote condition is reachable because `DelegationStore.setWitnessVote` for a given cycle is only populated by `MaintenanceManager.doMaintenance()` when `allowChangeDelegation()` is enabled, iterating `consensusDelegate.getAllWitnesses()`: [5](#0-4) 

`payReward` itself, however, has no equivalent guard tying it to `allowChangeDelegation` or to whether a vote record already exists for the *current* cycle before the first maintenance run populates it — it will happily call `delegationStore.addReward(cycle, witnessAddress, value)` for whatever `cycle = dynamicPropertiesStore.getCurrentCycleNumber()` returns at that moment, even if `setWitnessVote` for that specific cycle/address pair has not yet been written (fresh witness, or the delegation feature has just been toggled on and historical cycles/addresses were never seeded).

### Impact Explanation
Any reward credited under a `(cycle, srAddress)` key whose vote total is unset/zero at the time `queryReward`/`withdrawReward` is evaluated is permanently unrecoverable — no voter, the witness, or any privileged account can ever claim it, and it is not routed to the blackhole or any other burn/park mechanism. This is a silent, permanent freezing-of-funds bug consistent with the Medium-severity classification of the original Wenwin finding (funds locked forever due to a reward accumulator not being updated/consulted correctly when its denominator is zero/unset).

### Likelihood Explanation
This requires no privileged action: it can occur purely from normal block production and voting activity (e.g., a witness becoming active and earning block/fee rewards before a vote record for that specific cycle has been written by `MaintenanceManager`, or vote counts dropping to `0` for a cycle already recorded). This is analogous to the "unlikely but reachable" characterization used by the original report and its judges (downgraded to Medium), since it depends on specific cycle/vote-count timing rather than attacker-controlled input.

### Recommendation
- In `MortgageService.computeReward`, when `totalVote == DelegationStore.REMARK || totalVote == 0` but `totalReward > 0`, do not silently drop the reward: either forward it to the next cycle's reward bucket for the same witness, or route it into a recoverable pool (e.g., allowance to the witness/blackhole) instead of leaving it keyed to an unreachable `(cycle, address)` record.
- Add an explicit precondition in `payReward`/`addReward` to only accumulate rewards for a cycle where `delegationStore.getWitnessVote(cycle, address)` is already set (i.e., not `REMARK`), or lazily backfill the vote record if missing before crediting the reward.

### Proof of Concept
1. A witness first becomes eligible for block/transaction-fee rewards in cycle `N` before `MaintenanceManager.doMaintenance()` has ever called `delegationStore.setWitnessVote(N, witnessAddress, ...)` for that address (e.g., very first cycle right after registration/vote, or right after `allowChangeDelegation` is toggled on for a previously-existing witness whose historical cycle vote was never recorded).
2. Block production triggers `Manager` → `MortgageService.payBlockReward`/`payTransactionFeeReward` → `payReward(witnessAddress, value)`, which calls `delegationStore.addReward(N, witnessAddress, value)`, storing the reward under key `N-<address>-reward`. [1](#0-0) 
3. A voter later calls `withdrawReward`/`queryReward` for this witness's `(cycle, address)` votes. `computeReward` reads `delegationStore.getWitnessVote(N, witnessAddress)`, which returns `REMARK` (or `0`), so the branch `continue`s and the stored reward is never added to `reward`. [2](#0-1) 
4. The value stored at key `N-<address>-reward` in `DelegationStore` is never read successfully again by any code path in `MortgageService`, permanently freezing it.

```java
  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }
```
