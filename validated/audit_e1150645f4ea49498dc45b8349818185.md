Based on my research, I don't find a valid Go analog to this FreeRDP heap-use-after-free.

### Analysis

The FreeRDP CVE describes a classic C memory-safety bug: a capture thread retains and later dereferences a freed channel-callback object (`ecam_channel_write`) after the channel is closed, causing a heap use-after-free. This is a memory-corruption primitive specific to manually-managed memory in C.

Go's garbage collector fundamentally prevents this class of bug in ordinary Go code — an object referenced by a still-running goroutine cannot be freed/reused while that reference is live, so a literal "write through a freed pointer" cannot occur without `unsafe`. The closest conceptual analogs in this repository are goroutine/close races where a background writer goroutine keeps writing to a connection concurrently with `Close()`, e.g.:

- `crypto/tls`'s `Conn.Close` / `closeNotify` interlocking with concurrent `Write` via `activeCall` CAP: [1](#0-0) 
- `net/http/internal/http2`'s `startFrameWrite`/`wroteFrame` async-write goroutine coordinating with stream-closing logic on the serve goroutine: [2](#0-1) 
- The regression test `TestConnCloseBreakingWrite` which specifically exercises a `Write` racing a `Close` to prove the interlock works and doesn't deadlock/misbehave: [3](#0-2) 

These are goroutine/data-race concerns (whether a stale write can escape after logical closure), not memory-corruption use-after-free — Go's memory model prevents the dangling-pointer dereference that is the actual root cause of the FreeRDP CVE. None of these paths exhibit a broken security check, authentication bypass, secret disclosure, or code-execution sink; at most a benign race that Go's own tests already demonstrate is handled correctly (interlocked via `activeCall`/mutexes, not left dangling). Per the scan rules, a plain data race without a concrete security effect (auth bypass, secret disclosure, code execution, or material file write) does not qualify, and I found no code path where a closed/freed callback object is subsequently dereferenced by a background thread in production Go source in this repository.

func (c *Conn) Close() error {
	// Interlock with Conn.Write above.
	var x int32
	for {
		x = c.activeCall.Load()
		if x&1 != 0 {
			return net.ErrClosed
		}
		if c.activeCall.CompareAndSwap(x, x|1) {
			break
		}
	}
	if x != 0 {
		// io.Writer and io.Closer should not be used concurrently.
		// If Close is called while a Write is currently in-flight,
		// interpret that as a sign that this Close is really just
		// being used to break the Write and/or clean up resources and
		// avoid sending the alertCloseNotify, which may block
		// waiting on handshakeMutex or the c.out mutex.

// startFrameWrite starts a goroutine to write wr (in a separate
// goroutine since that might block on the network), and updates the
// serve goroutine's state about the world, updated from info in wr.
func (sc *serverConn) startFrameWrite(wr FrameWriteRequest) {
	sc.serveG.check()
	if sc.writingFrame {
		panic("internal error: can only be writing one frame at a time")
	}

	st := wr.stream
	if st != nil {
		switch st.state {
		case stateHalfClosedLocal:
			switch wr.write.(type) {
			case StreamError, handlerPanicRST, writeWindowUpdate:
				// RFC 7540 Section 5.1 allows sending RST_STREAM, PRIORITY, and WINDOW_UPDATE
				// in this state. (We never send PRIORITY from the server, so that is not checked.)
			default:
				panic(fmt.Sprintf("internal error: attempt to send frame on a half-closed-local stream: %v", wr))
			}
		case stateClosed:
			panic(fmt.Sprintf("internal error: attempt to send frame on a closed stream: %v", wr))
		}
	}
	if wpp, ok := wr.write.(*writePushPromise); ok {
		var err error
		wpp.promisedID, err = wpp.allocatePromisedID()
		if err != nil {
			sc.writingFrameAsync = false
			wr.replyToWriter(err)
			return
		}
	}

	sc.writingFrame = true
	sc.needsFrameFlush = true
	if wr.write.staysWithinBuffer(sc.bw.Available()) {
		sc.writingFrameAsync = false
		err := wr.write.writeFrame(sc)
		sc.wroteFrame(frameWriteResult{wr: wr, err: err})
	} else if wd, ok := wr.write.(*writeData); ok {
		// Encode the frame in the serve goroutine, to ensure we don't have
		// any lingering asynchronous references to data passed to Write.
		// See https://go.dev/issue/58446.
		sc.framer.startWriteDataPadded(wd.streamID, wd.endStream, wd.p, nil)
		sc.writingFrameAsync = true
		go sc.writeFrameAsync(wr, wd)
	} else {
		sc.writingFrameAsync = true
		go sc.writeFrameAsync(wr, nil)
	}
}
