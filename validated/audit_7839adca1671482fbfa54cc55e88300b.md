### Title
Credential exfiltration via userinfo/host confusion in `use_netrc()` - (File: tools/build_defs/repo/utils.bzl)

### Summary
`use_netrc()`, the Starlark helper that maps `.netrc` credentials onto the URLs Bazel is about to download, extracts the "host" for each URL with a naive string split instead of RFC-3986-compliant URL parsing. When a URL contains userinfo with an embedded colon (`scheme://<netrc-host>:<anything>@<attacker-host>/path`), this naive parser picks the string before the first colon as the "host" — which is actually part of the userinfo, not the real destination host. If that fake "host" happens to match a machine entry in the user's/repo's `.netrc`, the corresponding login/password is attached (keyed by the literal URL string) for a request whose real destination, once actually resolved for the TCP connection, is a completely different, attacker-controlled host.

### Finding Description
`tools/build_defs/repo/utils.bzl` implements the "compute auth dict from netrc + urls" logic used by `http_archive`, `http_file`, `http_jar`, and any repo rule using `get_auth(ctx, urls)`: [1](#0-0) 

```
def use_netrc(netrc, urls, patterns):
    auth = {}
    for url in urls:
        schemerest = url.split("://", 1)
        if len(schemerest) < 2:
            continue
        if not (schemerest[0] in ["http", "https"]):
            continue
        host = schemerest[1].split("/")[0].split(":")[0]
        if host in netrc:
            authforhost = netrc[host]
        elif "" in netrc:
            authforhost = netrc[""]
        else:
            continue
        ...
        auth[url] = auth_dict   # keyed by the *entire original URL string*
```

The host is computed as: take everything up to the first `/` (i.e., authority component), then take everything up to the first `:` in that authority. This is correct only when there is no userinfo (`user:pass@host`) portion. If the authority is `good.example.org:secret@attacker.com`, this naive parser returns `good.example.org` — the part before the *first* colon — even though, per RFC 3986 and per how Java's URL/URI/HTTP client actually parses and connects, the userinfo is `good.example.org:secret` and the real host is `attacker.com`.

Consequently, `get_auth()` — used by the built-in `http_archive`/`http_file`/`http_jar` rules and callable by any custom repository rule — will:
1. See a URL such as `https://good.example.org:x@attacker.com/pkg.tar.gz`.
2. Incorrectly resolve "host" to `good.example.org`.
3. Find `good.example.org` in the user's `.netrc` (a real, sensitive credential the user has configured for a trusted host).
4. Store that login/password in `auth[url]`, i.e., tied to the literal URL that will actually be fetched from `attacker.com`.

Downstream, when Bazel's HTTP download machinery performs the actual fetch, it connects using standard URL parsing (host = `attacker.com`), but still attaches the Basic-Auth credential looked up by the *URL string* — sending the `good.example.org` netrc credential to `attacker.com`. This is a genuine host/parser mismatch bug of the same shape as the Curve V2 report: two pieces of logic (Starlark's naive string-splitting "host" determination vs. the real network layer's RFC-3986 host resolution) disagree about what "the pool version"/"the host" is, and the code silently takes the wrong branch, with a security-relevant outcome instead of an availability one.

### Impact Explanation
This is a credential-exfiltration primitive: any URL an unprivileged/hostile origin can inject into a build — a mirror list, a URL emitted by a third-party or malicious `http_archive`/`http_file` invocation, a URL from a `module_mirrors` fallback, or a URL served by a compromised/malicious registry `source.json` that ends up passed through `get_auth`/`use_netrc` — can be crafted to smuggle the victim's real `.netrc` login/password for a legitimate, high-value host to an attacker-controlled server. Given `.netrc` files commonly hold tokens for private artifact hosts (GitHub, GCS, private mirrors), this is a direct credential leak, matching the explicitly accepted impact category "credential exfiltration to an attacker-controlled host."

### Likelihood Explanation
Exploitability requires only that the victim's build ends up requesting attacker-influenced URLs, and that the victim has a `.netrc` entry for the host name embedded as fake userinfo — a realistic setup in CI/CD environments where teams share `.netrc` templates or where the attacker can guess/probe common private hosts (e.g., `github.com`, an internal artifact server) that the victim is likely to have configured. No MITM, no compromised credentials, and no access to the victim machine are required — only the ability to publish a URL that eventually flows into `use_netrc`/`get_auth` (e.g., via a dependency's `http_archive` call, a registry-provided source URL, or `module_mirrors`-style redirection).

### Recommendation
Replace the manual `split("://")/split("/")/split(":")` authority parsing in `use_netrc()` with RFC-3986-correct parsing that explicitly separates userinfo from host (i.e., split on the *last* `@` in the authority component before extracting host/port, discarding anything before it), so that the extracted "host" always matches what the actual HTTP client will connect to. Additionally, consider rejecting or warning on URLs containing userinfo entirely, since Bazel's repository rules do not need userinfo-based authentication and its presence significantly increases parser-confusion risk.

def use_netrc(netrc, urls, patterns):
    """Compute an auth dict from a parsed netrc file and a list of URLs.

    Args:
      netrc: a netrc file already parsed to a dict, e.g., as obtained from
        read_netrc
      urls: a list of URLs.
      patterns: optional dict of url to authorization patterns

    Returns:
      dict suitable as auth argument for ctx.download; more precisely, the dict
      will map all URLs where the netrc file provides login and password to a
      dict containing the corresponding login, password and optional authorization pattern,
      as well as the mapping of "type" to "basic" or "pattern".
    """
    auth = {}
    for url in urls:
        schemerest = url.split("://", 1)
        if len(schemerest) < 2:
            continue
        if not (schemerest[0] in ["http", "https"]):
            # For other protocols, bazel currently does not support
            # authentication. So ignore them.
            continue
        host = schemerest[1].split("/")[0].split(":")[0]
        if host in netrc:
            authforhost = netrc[host]
        elif "" in netrc:
            authforhost = netrc[""]
        else:
            continue
