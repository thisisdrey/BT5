### Title
Unguarded division-by-zero in `calc-treasury-lp-preview` freezes vault interest accrual - (File: mainnet/contracts/vault/v0-vault-stx.clar, and the equivalent per-vault files v0-vault-sbtc.clar, v0-vault-ststx.clar, v0-vault-usdc.clar, v0-vault-usdh.clar, v0-vault-ststxbtc.clar)

### Summary
The Balancer report's root cause is a ratio computation (`r0 = resA / resB`) whose denominator can be driven to zero by ordinary pool state, causing every downstream caller to revert. Zest's vault contracts contain the same class of bug in the treasury-LP-share pricing formula used during interest accrual: `mul-div-down reserve-inc (total-supply) (- ta-preview reserve-inc)` divides by `(ta-preview - reserve-inc)`, a value that is not defensively floored and can reach zero (or underflow, which also aborts in Clarity), permanently reverting `accrue()` and every public entry point that depends on it.

### Finding Description
`calc-treasury-lp-preview` computes the treasury's share of newly accrued interest before minting it: [1](#0-0) 

```
(define-private (calc-treasury-lp-preview)
  (let ((scaled-principal (var-get principal-scaled))
        (idx (var-get index))
        (next (next-index))
        (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
        (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
        (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
        (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
        (ta-preview (total-assets-preview)))
    (if (> reserve-inc u0)
        (mul-div-down reserve-inc (total-supply) (- ta-preview reserve-inc))
        u0)))
```

`ta-preview` is `total-assets-preview`, defined as `current-assets + interest`, where `interest = max(0, debt-preview - total-borrowed)` — i.e., the cumulative unrealized interest not yet reflected in on-hand `assets`: [2](#0-1) 

This exact same construct is called from the public `accrue` function, which is invoked at the top of every deposit, redeem, borrow, and repay path: [3](#0-2) 

```
(define-public (accrue)
  ...
  (let ((next (next-index))
        (nliq (next-liquidity-index))
        (scaled-principal (var-get principal-scaled))
        (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
        (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
        (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
        (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
        (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
    ...
    (if (> treasury-lp u0)
        (try! (ft-mint? zft treasury-lp .dao-treasury))
        false)
    ...))
```

`mul-div-down` is a plain `(/ (* x y) z)` with no zero-check, and Clarity aborts a transaction on both division-by-zero and `uint` subtraction underflow. Whenever `reserve-inc >= (total-assets-preview)`, the subtraction underflows or the division denominator is zero, and the entire `accrue` call — and therefore the calling deposit/redeem/borrow/repay transaction — reverts unconditionally, with no fallback path (unlike `convert-to-shares-preview`/`convert-to-assets-preview` in the same file, which do explicitly guard against zero denominators).

The condition `reserve-inc >= ta-preview` is structurally reachable: `reserve-inc` is `debt-delta * fee-reserve / BPS`, and `ta-preview = current-assets + interest`, where `interest` collapses to essentially `debt-delta` whenever the vault is fully utilized (`current-assets = 0`) and no prior unrealized interest has accumulated (fresh 100%-utilization state, or immediately after a state where the float was previously fully materialized). In that state, `ta-preview ≈ debt-delta`, so `reserve-inc = debt-delta * fee-reserve / BPS` approaches or equals `ta-preview` as `fee-reserve` approaches the `BPS` maximum, causing the subtraction/division to break.

### Impact Explanation
Once triggered, `accrue()` reverts on every call, and since `accrue` is invoked at the start of `deposit`, `redeem`, `system-borrow`, and `system-repay` in every vault (`v0-vault-stx`, `v0-vault-sbtc`, `v0-vault-ststx`, `v0-vault-usdc`, `v0-vault-usdh`, `v0-vault-ststxbtc`), the affected vault becomes permanently unusable: no user can deposit, withdraw, borrow, or repay. This is a permanent freezing of funds (all user collateral/liquidity locked in that vault with no recovery path short of a contract upgrade), matching the in-scope "permanent freezing of funds" impact class.

### Likelihood Explanation
Triggering the exact equality/underflow condition requires the vault to be at (or very near) 100% utilization (`current-assets = 0`, reachable purely by ordinary borrowers draining vault liquidity) combined with the `fee-reserve` parameter being at or extremely close to `BPS` (100%). `fee-reserve` is DAO/governance-configured, not attacker-controlled, so this is not trivially triggerable by an unprivileged principal alone — it requires a specific parameter combination. Likelihood is therefore low-to-moderate: the entry point (`accrue`, called from ordinary deposit/borrow/repay/redeem) is fully unprivileged, but the precondition on `fee-reserve` limits practical reachability to configurations near the reserve-fee ceiling.

### Recommendation
Guard the denominator in both `calc-treasury-lp-preview` and the inline duplicate logic in `accrue()`:
```clarity
(if (and (> reserve-inc u0) (> ta-preview reserve-inc))
    (mul-div-down reserve-inc (total-supply) (- ta-preview reserve-inc))
    u0)
```
Apply this fix consistently across all vault files (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`) since they share identical logic.

### Proof of Concept
1. Deploy/operate a vault (e.g., `v0-vault-usdc`) until `current-assets` (`var-get assets`) reaches `u0` via ordinary `system-borrow` calls draining all available liquidity (100% utilization) — fully achievable by unprivileged borrowers.
2. Ensure no unrealized interest float has accumulated yet (`debt ≈ total-borrowed`, i.e., `interest ≈ u0`), e.g., shortly after the vault first reaches 100% utilization.
3. With `fee-reserve` set (via governance) at or near `BPS` (10000), call any public entry that triggers `accrue()` (e.g., `system-repay`, `deposit`, `redeem`) after enough time has elapsed for `next-index` to produce `debt-delta > 0`.
4. `ta-preview` (`current-assets(0) + interest(≈debt-delta)`) becomes ≈ `reserve-inc` (`debt-delta * fee-reserve/BPS`); `(- ta-preview reserve-inc)` underflows/hits zero in `mul-div-down`, causing the transaction (and all subsequent calls that invoke `accrue()`) to abort — freezing the vault.
