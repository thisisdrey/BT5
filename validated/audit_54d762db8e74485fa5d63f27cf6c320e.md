### Title
Permanent lock of Kamino Farm rewards via balance-delta accounting griefing in `kamino_harvest_reward` - (File: `programs/marginfi/src/instructions/kamino/harvest_reward.rs`)

### Summary
`kamino_harvest_reward` computes the amount of reward tokens to sweep to the global fee wallet by taking a pre/post balance snapshot around the CPI into the Kamino Farms `harvest_reward` instruction, exactly like the Aura/Convex `_claimRewards` pattern in the referenced report. Because Kamino's `harvest_reward` instruction is externally invocable and does not require the destination `user_reward_token_account` owner to sign, an attacker can pre-harvest the reward directly against the Kamino Farms program into the same deterministic ATA before marginfi's instruction runs, making marginfi's delta computation return zero and permanently stranding the already-harvested tokens.

### Finding Description
`kamino_harvest_reward` snapshots `pre_transfer_balance` of `user_reward_ata`, CPIs into Kamino Farms' `harvest_reward`, then computes `received = post_transfer_balance - pre_transfer_balance` and only sweeps that delta to the destination (global fee wallet) ATA: [1](#0-0) 

The `user_reward_ata` is a deterministic Associated Token Account owned by the bank's `liquidity_vault_authority` PDA: [2](#0-1) 

The Kamino Farms `harvest_reward` instruction accepts `payer` merely as a fee-paying signer; it does not require the owner of `user_reward_token_account` to sign, and the transfer authority for moving tokens out of the rewards vault is the farm's own `farm_vaults_authority` PDA, not marginfi's `liquidity_vault_authority`: [3](#0-2) 

This means the instruction is permissionless from Kamino's side with respect to the destination token account — anyone can invoke Kamino Farms' `harvest_reward` directly, supplying marginfi's `liquidity_vault_authority`-owned ATA as `user_reward_token_account`, and have the pending reward tokens deposited there without going through marginfi's accounting hook. When marginfi's own `kamino_harvest_reward` is subsequently called, `pre_transfer_balance` already reflects the attacker-deposited tokens, the CPI harvest yields nothing further (rewards already claimed), so `received = 0`, and `cpi_transfer_obligation_owner_to_destination(0)` sweeps nothing: [4](#0-3) 

Because the sweep function only transfers the computed `received` amount — not the full ATA balance — the pre-existing (attacker-deposited) tokens have no code path to ever be swept out, since every future call will again compute a delta of only the newly-accrued portion (or zero, if fully harvested). The tokens remain permanently locked in the `liquidity_vault_authority`-owned ATA, exactly mirroring the balanceBefore/After griefing in the Aura/Convex report where `getReward` could be called directly by anyone for the target account, leaving `amountsClaimed` at 0 while tokens sat unclaimed in the target contract.

This instruction is documented as intentionally permissionless: `pub fn kamino_harvest_reward(...)` is marked "(permissionless) Harvest the specified reward index...": [5](#0-4) 

### Impact Explanation
Reward tokens intended for the global fee wallet become permanently stuck in the bank's `liquidity_vault_authority`-owned reward ATA. There is no instruction in the reviewed harvest path that sweeps the full ATA balance (only the incremental "received" delta), so any tokens deposited into that account outside of marginfi's own CPI call are frozen indefinitely — a permanent-lock condition consistent with the accepted impact class in this report.

### Likelihood Explanation
Triggering this requires only: (1) knowledge of the public, deterministic PDA addresses (`farm_state`, `user_state`, `rewards_vault`, `farm_vaults_authority`, and the `user_reward_ata` derived from `liquidity_vault_authority`+`reward_mint`) — all discoverable on-chain, and (2) a single permissionless CPI call directly to the Kamino Farms program, which requires no special privilege, no signature from marginfi's PDA, and no marginfi account ownership. Any unprivileged actor can front-run marginfi's harvest call at will, at negligible cost (Solana transaction fee).

### Recommendation
Do not rely on balance-before/after deltas to determine the harvested amount when the underlying claim can be triggered independently by third parties. Instead, sweep the entire current balance of `user_reward_ata` (i.e., `accessor::amount(&user_reward_ata)` after the CPI, not the delta) to the destination account in `cpi_transfer_obligation_owner_to_destination`, so that any externally-deposited tokens are captured rather than stranded. Apply the same review to any other harvest/claim instruction using the same pre/post balance pattern.

### Proof of Concept
1. Attacker observes a Kamino-wrapped bank with pending, unharvested rewards in Kamino Farms.
2. Attacker derives the public PDAs used by `kamino_harvest_reward`: `farm_state`, `user_state` (== `bank.integration_acc_2`), `rewards_vault`, `farm_vaults_authority`, `global_config`, and the reward ATA `user_reward_ata = ATA(liquidity_vault_authority, reward_mint)`.
3. Attacker submits a standalone transaction calling Kamino Farms' `harvest_reward` instruction directly (bypassing marginfi entirely), passing `user_reward_token_account = user_reward_ata` and `payer = attacker`. This is valid because the IDL only requires `payer` to sign, not the ATA owner: [3](#0-2) 
4. The pending rewards for that `user_state`/`reward_index` are transferred from `rewards_vault` into `user_reward_ata`, increasing its balance outside of marginfi's tracked flow.
5. Someone later calls marginfi's `kamino_harvest_reward`. `pre_transfer_balance` already includes the attacker-deposited amount; the CPI harvest returns nothing new (already claimed); `received = post - pre = 0`: [1](#0-0) 
6. `cpi_transfer_obligation_owner_to_destination(0)` sweeps zero tokens; the previously harvested reward tokens remain permanently stuck in the `liquidity_vault_authority`-owned ATA with no subsequent instruction able to reclaim them.

pub fn kamino_harvest_reward(
    ctx: Context<KaminoHarvestReward>,
    reward_index: u64,
) -> MarginfiResult {
    let pre_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    ctx.accounts.cpi_harvest_rewards(reward_index)?;
    let post_transfer_balance = accessor::amount(&ctx.accounts.user_reward_ata.to_account_info())?;
    let received = post_transfer_balance - pre_transfer_balance;
    ctx.accounts
        .cpi_transfer_obligation_owner_to_destination(received)?;
    Ok(())
}

impl<'info> KaminoHarvestReward<'info> {
    pub fn cpi_harvest_rewards(&self, reward_index: u64) -> MarginfiResult {
        let program = self.farms_program.to_account_info();
        let accounts = HarvestReward {
            payer: self.liquidity_vault_authority.to_account_info(),
            user_state: self.user_state.to_account_info(),
            farm_state: self.farm_state.to_account_info(),
            global_config: self.global_config.to_account_info(),
            reward_mint: self.reward_mint.to_account_info(),
            user_reward_token_account: self.user_reward_ata.to_account_info(),
            rewards_vault: self.rewards_vault.to_account_info(),
            rewards_treasury_vault: self.rewards_treasury_vault.to_account_info(),
            farm_vaults_authority: self.farm_vaults_authority.to_account_info(),
            scope_prices: optional_account!(self.scope_prices),
            token_program: self.token_program.to_account_info(),
        };
        let bump = self.bank.load()?.liquidity_vault_authority_bump;
        let signer_seeds: &[&[&[u8]]] =
            bank_signer!(BankVaultType::Liquidity, self.bank.key(), bump);
        let cpi_ctx = CpiContext::new_with_signer(program.key(), accounts, signer_seeds);
        harvest_reward(cpi_ctx, reward_index)?;
        Ok(())
    }
