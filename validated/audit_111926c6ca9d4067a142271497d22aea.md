Rationale: The reported bug is specific to an ERC721 bridge contract calling `safeTransferFrom`, which reverts if the recipient does not implement `ERC721TokenReceiver`. In go-ethereum's in-scope consensus/execution code, ETH transfers (whether via beacon-chain withdrawals or EVM `CALL` value transfers) never require the recipient to implement any receiver interface — balance is credited unconditionally via `StateDB.AddBalance`, e.g. in withdrawal processing [1](#0-0)  and in plain value transfers [2](#0-1) . There is no callback/interface-support requirement gating these unconditional balance credits, so the specific bug class (funds permanently locked because the recipient doesn't implement a receiver interface) has no analog in the in-scope Geth code — it does not map onto any consensus equality (block validity, stateRoot, gas accounting, or persisted head) that Geth could get wrong relative to the EIP spec.

func Transfer(db vm.StateDB, sender, recipient common.Address, amount *uint256.Int, rules *params.Rules) {
	db.SubBalance(sender, amount, tracing.BalanceChangeTransfer)
	db.AddBalance(recipient, amount, tracing.BalanceChangeTransfer)
	if rules.IsAmsterdam && !amount.IsZero() && sender != recipient {
