### Title
Reentrancy-guard filter on `control_inherited_account` is lost across deferred dispatch (Scheduler), letting an inheritor execute forbidden Recovery calls as the recovered account - (File: substrate/frame/recovery/src/lib.rs)

### Summary
`pallet-recovery`'s `control_inherited_account` builds a `Signed(recovered)` origin and attaches an in-memory, closure-based filter via `origin.add_filter(...)` that blocks the recovered account from directly executing any `Recovery` pallet call (a reentrancy guard preventing the inheritor from tampering with recovery state such as `slash_attempt` / `set_friend_groups`). This mirrors the LlamaCore pattern: a narrow, ad-hoc invariant check ("guard slot0 / guard `is_sub_type`") wraps a generically-dangerous delegated-execution primitive (arbitrary nested `RuntimeCall` dispatch), rather than structurally separating privilege domains. The guard only exists for the lifetime of the current call stack's `origin` value; it is never persisted anywhere `RuntimeOrigin` is not itself carried forward untouched.

### Finding Description
`control_inherited_account` in `substrate/frame/recovery/src/lib.rs` (lines 567-601) does:

```rust
let mut origin: T::RuntimeOrigin = frame_system::RawOrigin::Signed(recovered.clone()).into();
// Reentrancy guard
origin.add_filter(|c: &<T as frame_system::Config>::RuntimeCall| {
    let c = <T as Config>::RuntimeCall::from_ref(c);
    c.is_sub_type().is_none()
});
let call_result = call.dispatch(origin).map(|_| ()).map_err(|r| r.error);
``` [1](#0-0) 

This guard correctly stops a directly-nested `RecoveryCall` (even wrapped in `Utility::batch`/`batch_all`, since those pallets call `call.dispatch(origin.clone())`, preserving the attached filter closure), as demonstrated by the pallet's own regression tests: [2](#0-1) [3](#0-2) 

However, the filter is an in-memory `Rc<dyn Fn>` attached to the *live* `OriginFor<T>` value, not to any persisted/encodable representation of the origin. Any pallet that accepts an arbitrary `RuntimeCall` + an *origin identity* and defers execution to a later block — most notably `pallet-scheduler`'s `schedule`/`schedule_named` family, which stores only the origin's `T::PalletsOrigin` (the `RawOrigin::Signed(recovered)` discriminant) and later reconstructs a fresh `OriginFor<T>` from it at dispatch time — cannot carry the ad-hoc filter closure across that persistence boundary. Because `Scheduler::schedule` itself is not a `Recovery` pallet call, `c.is_sub_type().is_none()` is `true` for it, so it passes the reentrancy guard when called synchronously inside `control_inherited_account`. It is accepted, stored, and executed at a future block using `OriginFor::<T>::from(RawOrigin::Signed(recovered))` with none of the caller-attached filters, so any `Recovery` call (`slash_attempt`, `set_friend_groups`, `cancel_attempt`, etc.) scheduled this way runs unguarded as the recovered account.

### Impact Explanation
This lets an inheritor (an unprivileged actor who only has been granted "controller" rights over the recovered account for legitimate purposes, e.g. sweeping funds) defeat the pallet's own reentrancy protection and directly manipulate `Recovery` pallet state as the *recovered* account: slashing a higher-priority friend group's deposit, wiping `set_friend_groups`, or cancelling in-flight recovery attempts from other, higher-priority friend groups — exactly the "malicious controller" scenario the pallet's authors explicitly hardened against with the `add_filter` guard and the two dedicated regression tests. This is fund loss (slashed deposits going to the wrong party / burned) and permanent state corruption of the recovery configuration, matching the "public underpriced work"/"unauthorized execution or origin escalation" and "permanent user-fund lock" impact classes, achievable by a normal signed account with no admin, validator, or governance privilege.

### Likelihood Explanation
Medium-high: it only requires standard, permissionless extrinsics (`Recovery::control_inherited_account` wrapping a `Scheduler::schedule` call) available to any account that has legitimately become an inheritor. No malicious peer/validator/relayer/governance actor is needed. The main uncertainty is runtime-specific: this requires the concrete runtime to include both `pallet-recovery` and `pallet-scheduler` (or another deferred-dispatch pallet with the same store-then-redispatch pattern) in the same `RuntimeCall` enum, and for `pallet-scheduler` to accept `RawOrigin::Signed` origins for later dispatch (which it does by design). I was not able to fully verify, within the remaining tool budget, the exact code path in `substrate/frame/scheduler/src/lib.rs` that reconstructs `OriginFor<T>` from the stored `T::PalletsOrigin` at execution time, nor which shipped runtimes actually configure both pallets together with a signed origin allowed into the scheduler; this should be confirmed by a background agent before treating this as fully proven.

### Recommendation
- Do not rely on transient, closure-based `Origin::add_filter` guards to protect privileged pallet calls when the call/origin pair can be handed to any pallet that defers dispatch (scheduler, preimage+scheduler, multisig timepoint execution, etc.).
- Instead, enforce the "recovered account cannot self-mutate Recovery state" invariant structurally: either (a) reject `call` outright in `control_inherited_account` if it or anything reachable at dispatch-config level could resolve to a `Recovery` call (deep/recursive static check, not just filtering at dispatch time), or (b) block the recovered account from ever using `pallet-scheduler`/`pallet-preimage` to submit `Recovery` calls, e.g. by making the base `BaseCallFilter`/`SignedFilter` recognize and reject `Recovery` calls whenever the signer equals an account with an active `Inheritor` entry, so the restriction is enforced independent of the ephemeral origin filter and survives storage round-tripping through Scheduler.

### Proof of Concept
1. Alice sets up two friend groups: Family (priority 0, higher priority) and Friends (priority 1, inheritor = Ferdie), as in the existing `inheritor_can_slash_higher_priority_attempts_and_remove_friend_groups` test setup. [4](#0-3) 
2. Friends group finishes recovery first; Ferdie becomes inheritor of Alice.
3. Family group (Bob/Charlie) initiates a higher-priority recovery attempt.
4. Instead of directly wrapping `RecoveryCall::slash_attempt` (blocked by the guard, and blocked even through `Utility::batch` per the existing regression test), Ferdie calls:
```rust
Recovery::control_inherited_account(
    signed(FERDIE),
    ALICE,
    Box::new(RuntimeCall::Scheduler(pallet_scheduler::Call::schedule {
        when: current_block + 1,
        maybe_periodic: None,
        priority: 0,
        call: Box::new(RecoveryCall::slash_attempt { friend_group_index: 0 }.into()),
    })),
);
```
   `Scheduler::schedule` is not a `Recovery` call, so `is_sub_type().is_none()` is `true` and the reentrancy filter allows it through under `Signed(recovered)` origin.
5. At block `current_block + 1`, the Scheduler pallet dispatches the stored call using an origin freshly reconstructed from `RawOrigin::Signed(ALICE)` — without the `add_filter` closure attached in step 4 — so `slash_attempt` executes normally, slashing Bob's higher-priority-attempt deposit exactly as the pallet's own tests assert must never happen.

Note: I could not execute this scenario against the actual `pallet-scheduler` implementation within the available tool budget; confirming the exact origin-reconstruction code path in `substrate/frame/scheduler/src/lib.rs` is recommended before treating this as conclusively verified.

/// Regression test to ensure a malicious controller cannot dismiss higher-priority attempts.
#[test]
fn inheritor_can_slash_higher_priority_attempts_and_remove_friend_groups() {
	new_test_ext().execute_with(|| {
		// Alice configures two friend groups:
		//   Group 0 (priority 0, "Family"): BOB, CHARLIE — higher priority
		//   Group 1 (priority 1, "Friends"): DAVE, EVE — lower priority, inheritor = FERDIE
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE, // Family's chosen inheritor
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE, // Friends' chosen inheritor
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// --- Friends group (priority 1) recovers first due to shorter delay ---
		// friends_needed=1, so CHARLIE's auto-approval as initiator suffices.
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// --- Family group (priority 0) initiates a higher-priority attempt ---
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// Attack vector A: FERDIE tries to slash Family's attempt via the proxy.
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(RecoveryCall::slash_attempt { friend_group_index: 0 }.into())
		));

		// BOB's security deposit must NOT have been slashed
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		if bob_balance_after < bob_balance_before {
			panic!(
				"VULNERABILITY: inheritor slashed a higher-priority attempt via proxy! \
				 BOB lost {} from security deposit.",
				bob_balance_before - bob_balance_after
			);
		}
		// The family attempt must still be alive
		assert!(!Recovery::attempts(ALICE).is_empty(), "Family attempt was destroyed");

		// Attack vector B: FERDIE tries to remove all friend groups via the proxy.
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(RecoveryCall::set_friend_groups { friend_groups: vec![] }.into())
		));

		// Friend groups must still be intact
		assert!(
			!Recovery::friend_groups(ALICE).is_empty(),
			"VULNERABILITY: inheritor removed all friend groups via proxy"
		);
	});
}

/// Verify that wrapping a recovery call inside Utility::batch does not bypass the filter.
#[test]
fn inheritor_cannot_bypass_filter_via_utility_batch() {
	new_test_ext().execute_with(|| {
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE,
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE,
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// Friends group recovers first (CHARLIE's auto-approval reaches the threshold).
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// Family initiates higher-priority attempt
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// FERDIE wraps the slash inside a utility::batch call to try to bypass the filter
		let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
		let batch_call: RuntimeCall =
			pallet_utility::Call::batch { calls: vec![slash_call] }.into();
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(batch_call),
		));

		// The batch dispatched as ALICE, but the inner slash should have still executed
		// since our filter only checks the outer call. Check if BOB was slashed:
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		let was_slashed = bob_balance_after < bob_balance_before;

		if was_slashed {
			panic!(
				"BYPASS: recovery call filter was circumvented via utility::batch! \
				 BOB lost {} from security deposit slash.",
				bob_balance_before - bob_balance_after
			);
		}
	});
}
