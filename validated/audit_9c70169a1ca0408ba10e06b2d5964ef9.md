### Title
Protocol fee bypass on NEP-245/IMT tokens via unit-delta `TokenDiff` splitting - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` exempts NEP-245 (and IMT) token deltas from protocol fees whenever the per-intent `|delta| <= 1`, but this exemption is evaluated independently for each `TokenDiff` intent rather than on the aggregate amount transferred on that token within a batch or between two parties. Any signer trading a NEP-245 (multi-token) asset can therefore split what would otherwise be a single fee-liable delta into multiple `delta = ±1` `TokenDiff` intents, each individually falling under the exemption, and pay zero protocol fee regardless of the total traded volume.

### Finding Description
The broken binding: `token_fee(token_id, |Σdeltas_on_token|, fee).fee_ceil(Σ|deltas|)` should equal `Σ (token_fee(token_id, |delta_i|, fee).fee_ceil(|delta_i|))` for any decomposition of a trade into multiple `TokenDiff` intents on the same token — i.e., total fee collected should be invariant to how a trade is split across intents. This does not hold.

In `contracts/defuse/core/src/intents/token_diff.rs`:
```
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
``` [1](#0-0) 

is called inside `ExecutableIntent for TokenDiff::execute_intent` once per `(token_id, delta)` pair of a *single* `TokenDiff` intent, using only that intent's own `amount = delta.unsigned_abs()`:
```
if *delta < 0 {
    let amount = delta.unsigned_abs();
    let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
    fees_collected.add(token_id.clone(), fee)...
}
``` [2](#0-1) 

`DefuseIntents::execute_intent` and `Intent::execute_intent` simply iterate the batch's intent list and dispatch each `TokenDiff` independently, with no aggregation of amounts by signer/token before fee evaluation. [3](#0-2) 

The actual token-balance matching for the whole batch is done separately and later by `TransferMatcher::finalize`, which only checks that net deltas per token sum to zero across all parties — it has no concept of fees and doesn't re-derive them from aggregated amounts. [4](#0-3) 

Exploit: attacker signs two `TokenDiff` intents in one `MultiPayload`/`DefuseIntents` batch, each with `diff = {nep245_token: -1}` (fee-exempt, `amount == 1`), and a counterparty (a solver, or another self-controlled account) supplies matching `+1`/`+1` (or `+2`) deltas on the same token plus the corresponding `token_out` deltas so the batch's `TransferMatcher` nets to zero. Both `-1` legs pay `Pips::ZERO` fee (total fee = 0), whereas submitting a single `TokenDiff` with `diff = {nep245_token: -2}` would pay `fee.fee_ceil(2)` (full, non-zero fee since `amount=2 > 1`). No existing guard (`MultiPayload::verify`, nonce checks, `TransferMatcher::finalize`) checks or reconstructs per-token aggregate trade size before/instead of the per-intent amount used for fee computation, so the divergence is not caught.

### Impact Explanation
The protocol's fee revenue on NEP-245 (and IMT) token trades is under-collected: the `fee_collector` account never receives fees on volumes that are (or can be structured as) sequences of unit deltas, regardless of the underlying trade size, because the exemption threshold is applied per-intent rather than per aggregate trade. This is repeatable indefinitely by any pair of cooperating signers (attacker + any counterparty, self-controlled or not) across any NEP-245/IMT token and any batch, at zero marginal cost beyond additional intents/signatures in the same transaction. This matches the "protocol fees bypassed" Critical impact category, since value (fee revenue) that should move to `fee_collector` never does.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged signer's control: the attacker needs a `MultiPayload` with two (or more) self-signed `TokenDiff` intents on the same NEP-245 token, each with `|delta| == 1`, and a matched counterparty's intents (which can also be self-controlled) to satisfy the batch's net-zero invariant. No privileged role, relayer key, or special balance is required beyond normal token holdings already needed for any trade. The attack scales to arbitrary trade volume by repeating unit-delta intents, so it is highly likely to be used by any economically motivated NEP-245 trader.

### Recommendation
Compute `token_fee`/apply the NEP-245/IMT exemption based on the aggregate `|delta|` accumulated per `(signer, token_id)` (or globally per token) across the whole intents batch, not per individual `TokenDiff` intent, before deciding whether the amount qualifies as an indivisible single-unit transfer exempt from fees. Alternatively, restrict the exemption to `TokenIdType::Nep171` (true NFTs, which are always `amount == 1` by construction) and always charge fees on `Nep245`/`Imt` deltas regardless of amount, since NEP-245 tokens are not inherently indivisible.

### Proof of Concept
Add a `cargo test` in `contracts/defuse/core/src/intents/token_diff.rs` (or a new integration test under `tests/src/tests/defuse/intents/token_diff.rs` using `near-workspaces` sandbox) that:
1. Builds a `Nep245TokenId` and computes `fee_single = TokenDiff::token_fee(&nep245_token, 2, fee).fee_ceil(2)` for a nonzero `fee` (e.g. `Pips::ONE_PERCENT`), asserting `fee_single > 0`.
2. Computes `fee_split = TokenDiff::token_fee(&nep245_token, 1, fee).fee_ceil(1) + TokenDiff::token_fee(&nep245_token, 1, fee).fee_ceil(1)`, asserting `fee_split == 0`.
3. Asserts `fee_split < fee_single`, proving the binding "fee collected is invariant to splitting the same total NEP-245 delta across multiple intents" is violated.
4. Optionally, in the sandbox integration test, execute a full batch: one signer submits two `TokenDiff` intents with `delta = -1` each on the same NEP-245 token (matched against a counterparty's `+1`/`+1` deltas plus corresponding `token_out`), then assert the `fee_collector`'s post-execution `mt_balance_of` on that token is `0`, versus a control batch using a single `delta = -2` `TokenDiff` where the collector balance is `> 0`.

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
