### Title
Lite Fullnode History-Query Restriction Bypassed via JSON-RPC API - (File: `framework/src/main/java/org/tron/core/services/jsonrpc/TronJsonRpcImpl.java`)

### Summary
The `openHistoryQueryWhenLiteFN` restriction, which is meant to prevent a lite fullnode from serving historical block/transaction data it cannot reliably or completely provide, is enforced only for the gRPC and HTTP `/wallet`, `/walletsolidity`, `/walletpbft` endpoints via `LiteFnQueryGrpcInterceptor` and `LiteFnQueryHttpFilter`. The equivalent JSON-RPC endpoints implemented in `TronJsonRpcImpl` are not covered by either filter, so an anonymous JSON-RPC client can still retrieve historical block and transaction data on a lite fullnode even when the operator has explicitly disabled this via configuration — an access-control gap analogous to the GitLab issue where a disabled feature still exposed restricted information through an alternate code path.

### Finding Description
`chainBaseManager.isLiteNode()` combined with `CommonParameter.getInstance().openHistoryQueryWhenLiteFN == false` is the mechanism operators use to signal that a lite fullnode should not serve historical queries (block-by-id, transaction-by-id, etc.), because a lite node prunes/lacks full historical state and serving such queries can return incomplete or inconsistent data.

This check is applied in exactly two places:
- `LiteFnQueryGrpcInterceptor`, which blocks a hardcoded set of `protocol.Wallet/*`, `protocol.WalletSolidity/*`, and `protocol.Database/GetBlockByNum` gRPC methods. [1](#0-0) 
- `LiteFnQueryHttpFilter`, which blocks a hardcoded set of `/wallet/*`, `/walletsolidity/*`, `/walletpbft/*` HTTP paths. [2](#0-1) 

Neither filter's method/path set references any JSON-RPC endpoint, and no equivalent `isLiteNode()`/`openHistoryQueryWhenLiteFN` check exists inside `TronJsonRpcImpl`, which independently implements Ethereum-style historical query methods (e.g., transaction/block/receipt lookups) backed by the same underlying stores. [3](#0-2) 

Because the JSON-RPC service is a separate servlet/handler stack from the `/wallet*` HTTP paths and the gRPC `protocol.Wallet`/`WalletSolidity` services, it is not intercepted by either `LiteFnQueryHttpFilter` or `LiteFnQueryGrpcInterceptor`. This is the same bug class as the GitLab advisory: a security/visibility control that is supposed to gate access to certain information is enforced on some access paths (`gRPC`, classic HTTP wallet API) but omitted on another reachable access path (JSON-RPC), letting an unprivileged client bypass the intended restriction.

### Impact Explanation
An operator who runs a lite fullnode and deliberately sets `openHistoryQueryWhenLiteFN=false` — believing history queries are unavailable node-wide — is not actually enforcing that restriction for JSON-RPC clients. Any unauthenticated remote caller can still pull historical transaction/block/receipt data through JSON-RPC on such a node, exposing data the operator intended to withhold (e.g., to reduce load, avoid serving incomplete/pruned data, or limit exposure of chain history through that node). This is an information-exposure/missing-authorization issue: it does not enable theft of funds or consensus compromise, but it directly violates a documented, operator-configured access restriction and can return incomplete/inconsistent historical data to callers who should have been blocked.

### Likelihood Explanation
Trivial to trigger: any anonymous client with network access to the node's JSON-RPC port can call the affected methods directly with no authentication, no special conditions, and no transaction cost — it is a straightforward, always-reachable query path.

### Recommendation
Add the equivalent `chainBaseManager.isLiteNode() && !CommonParameter.getInstance().openHistoryQueryWhenLiteFN` guard to the historical-data methods in `TronJsonRpcImpl` (or introduce a shared interceptor/filter applied uniformly across HTTP, gRPC, and JSON-RPC transports) so the restriction is enforced consistently across every query surface that exposes the same underlying historical data.

### Proof of Concept
1. Configure and run a lite fullnode with `node.openHistoryQueryWhenLiteFN = false` (or the corresponding default) so that `LiteFnQueryHttpFilter`/`LiteFnQueryGrpcInterceptor` block `/wallet/gettransactionbyid` and `protocol.Wallet/GetTransactionById`.
2. Confirm (as expected) that calling `POST /wallet/gettransactionbyid` returns "this API is closed because this node is a lite fullnode." [4](#0-3) 
3. Call the JSON-RPC endpoint served by `TronJsonRpcImpl` for the equivalent historical transaction lookup on the same node — it succeeds and returns the historical transaction data, because no lite-node check exists on this path. [3](#0-2)

  @Override
  public <ReqT, RespT> ServerCall.Listener<ReqT> interceptCall(ServerCall<ReqT, RespT> call,
      Metadata headers, ServerCallHandler<ReqT, RespT> next) {
    if (chainBaseManager.isLiteNode()
            && !CommonParameter.getInstance().openHistoryQueryWhenLiteFN
            && filterMethods.contains(call.getMethodDescriptor().getFullMethodName())) {
      call.close(Status.UNAVAILABLE
              .withDescription("this API is closed because this node is a lite fullnode"), headers);
      return new ServerCall.Listener<ReqT>() {};
    } else {
      return next.startCall(call, headers);
    }
  }
