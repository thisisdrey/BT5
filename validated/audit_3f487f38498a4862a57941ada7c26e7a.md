[1](#0-0) ### Title
Liquidations can push solvent borrowers into insolvency and create protocol bad debt - (File: contracts/Pool.sol)

### Summary

`Pool.liquidate` repays a borrower’s synthetic-token debt while seizing collateral valued at the repayment plus the liquidator incentive and protocol fee. The current implementation uses a fixed liquidation bonus and only verifies that the position was unhealthy before liquidation; it does not verify that collateral still exceeds debt afterward. With the initialized 10% liquidator incentive and 8% protocol fee, a solvent but unhealthy position can be pushed into insolvency by a single public liquidation. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description

`quoteLiquidateOut` converts `amountToRepay_` into collateral, adds `liquidatorIncentive` to the amount sent to the liquidator, and additionally adds `protocolFee` to the total collateral seized. [1](#0-0) 

`FeeProvider.initialize` sets the liquidator incentive to 10% and protocol liquidation fee to 8%, so each unit of repaid debt can seize approximately `1.18` units of collateral value. [2](#0-1) 

A position is considered healthy when total debt does not exceed collateral value multiplied by each deposit token’s collateral factor. [4](#0-3)  For example, the deployed Hemi WETH deposit token uses an 83% collateral factor. [5](#0-4) 

`Pool.initialize` sets `maxLiquidable` to 50%, allowing an unprivileged caller to repay up to half of a borrower’s debt in one transaction. [6](#0-5) 

`liquidate` checks only the pre-liquidation health flag, the 50% repayment bound, the optional debt floor, and that the borrower has enough deposit-token balance; it does not require `depositUSD > debtUSD` after the liquidation. [7](#0-6) 

For collateral value `C`, debt `D`, repayment `x`, and total liquidation multiplier `m = 1 + incentive + protocolFee`, liquidation produces:

```text
D' = D - x
C' = C - m*x
```

With `m = 1.18` and `x = 0.5 * D`, a liquidation turns the borrower insolvent when:

```text
C - 0.59D < 0.5D
D/C > 1/1.09 ≈ 91.74%
```

Concretely, a borrower with `$1,000` collateral and `$920` debt is unhealthy under an 83% collateral factor but remains solvent. A liquidator can repay `$460` of debt, and `quoteLiquidateOut` seizes `$542.80` of collateral value. The result is approximately `$457.20` collateral backing `$460` debt, converting a solvent borrower into an insolvent one while paying the liquidator an incentive-funded premium. [8](#0-7) [9](#0-8) 

### Impact Explanation

This violates the liquidation-solvency invariant: liquidation is intended to improve a distressed account’s backing, but the implementation can instead remove more collateral value than the debt it extinguishes. An unprivileged liquidator only needs a sufficient synthetic-token balance and can call `liquidate` directly. [10](#0-9) 

The borrower loses collateral at the fixed bonus, while the pool can be left with debt exceeding remaining collateral. If the insolvent borrower does not voluntarily repay, the deficit becomes protocol bad debt that ultimately impairs synthetic-token redeemability.

### Likelihood Explanation

The liquidation path is public and is not restricted to a keeper, governor, or privileged actor. The borrower cannot block it because `DepositToken.seize` is invoked by the pool and bypasses the ordinary unlocked-balance restriction. [11](#0-10) [12](#0-11) 

The attack becomes available whenever a borrower enters the under-collateralized range and approaches `D/C > 91.74%`, which can occur through collateral price depreciation, synthetic appreciation, or accrued interest. Liquidators are economically motivated to execute because they receive collateral worth more than the synthetic assets burned. [1](#0-0) 

The `nonReentrant`, token-existence, shutdown, max-liquidable, balance, and debt-floor checks do not enforce post-liquidation solvency. [13](#0-12) 

### Recommendation

Ensure every liquidation improves account solvency, not merely the collateral-factor health metric.

Possible fixes include:

- Revert if post-liquidation collateral value is less than post-liquidation debt.
- Use a dynamic liquidation incentive that decreases toward zero as `D/C` approaches `1`.
- Cap `amountToRepay_` such that `C - m*x >= D - x`, equivalently `x <= (C - D) / (m - 1)`, unless the liquidation fully closes the debt.
- Treat the point where the liquidation multiplier makes liquidation insolvency-inducing as the effective bad-debt threshold and configure collateral factors and liquidation fees accordingly.

### Proof of Concept

The following Hardhat scenario reproduces the condition using the repository’s oracle fixture solely to establish the distressed market state; the liquidator action uses only the public `Pool.liquidate` entry point.

```ts
it('pushes a solvent undercollateralized borrower into insolvency', async () => {
  // Configure the deployed values exercised by Pool.quoteLiquidateOut:
  // liquidator incentive = 10%, protocol liquidation fee = 8%.
  await feeProvider.updateLiquidatorIncentive(parseEther('0.10'));
  await feeProvider.updateProtocolLiquidationFee(parseEther('0.08'));

  // Deposit token configured with collateralFactor = 0.83.
  // Victim deposits $1,000 and borrows $920 of the synthetic asset.
  await depositUnderlying(victim, parseEther('1000'));
  await depositToken.connect(victim).deposit(parseEther('1000'), victim.address);
  await debtToken.connect(victim).issue(parseEther('920'));

  // Adjust the test oracle so the position is unhealthy:
  // debt = $920, issuable limit = $830, while collateral remains $1,000.
  const before = await pool.debtPositionOf(victim.address);
  expect(before._isHealthy).to.eq(false);
  expect(before._depositInUsd).to.eq(parseEther('1000'));
  expect(before._debtInUsd).to.eq(parseEther('920'));

  // Liquidator acquires enough synthetic debt asset externally or mints it
  // against its own collateral. maxLiquidable is the initialized 50%.
  const repayAmount = parseEther('460');
  await syntheticToken.connect(liquidator).approve(pool.address, repayAmount);

  await pool
    .connect(liquidator)
    .liquidate(
      syntheticToken.address,
      victim.address,
      repayAmount,
      depositToken.address
    );

  // 1.18 * $460 = $542.80 collateral is seized:
  // $506 to liquidator and $36.80 to the fee collector.
  const after = await pool.debtPositionOf(victim.address);

  // Before: C/D = 1000/920 ≈ 1.087.
  // After: C/D = 457.2/460 ≈ 0.993, so the account is insolvent.
  expect(after._depositInUsd).to.be.closeTo(parseEther('457.2'), 1);
  expect(after._debtInUsd).to.eq(parseEther('460'));
  expect(after._depositInUsd).to.be.lt(after._debtInUsd);
});
```

The decisive property is also demonstrated by `quoteLiquidateOut`: repaying `460` returns `_toLiquidator = 506` and `_fee = 36.8`, giving `_totalToSeize = 542.8`; `liquidate` then transfers those deposit-token amounts without checking post-liquidation solvency. [1](#0-0) [14](#0-13)
