### Title
Missing minimum-holding-period on witness-vote reward accrual allows stealing SR reward yield from long-term voters via freeze-vote-withdraw at cycle boundary - (File: chainbase/src/main/java/org/tron/core/service/MortgageService.java, actuator/src/main/java/org/tron/core/vm/utils/VoteRewardUtil.java)

### Summary
TRON's DPoS voting-reward mechanism computes and pays out an entire cycle's Super Representative (SR) reward to any account whose vote is registered before `doMaintenance()` runs for that cycle, with no minimum holding period. Because `FreezeBalanceV2Actuator`/`FreezeBalanceActuator` apply frozen balance (voting power) immediately, and `VoteWitnessActuator`/`VoteRewardUtil.withdrawReward` record the vote's `beginCycle` as the *current* cycle, a user can freeze TRX and vote seconds before a cycle-maintenance boundary, be credited a full cycle's Vi-based reward (identical to a voter who held the position the entire cycle), and immediately call `withdrawReward`/`WithdrawRewardProcessor` to cash out the `allowance` — with zero timelock on the reward itself. This dilutes the reward-per-vote (Vi) for the cycle and siphons yield away from voters who held their stake for the full period, mirroring the Lybra `rigidRedemption` "flash yield capture" pattern, except here even the 0.5%-fee-style disincentive present in Lybra does not exist (freezing/voting is fee-free).

### Finding Description
Reward attribution is tracked per address via `beginCycle`/`endCycle` in `DelegationStore` (native path, `MortgageService.withdrawReward`) and mirrored for TVM callers in `VoteRewardUtil.withdrawReward`: [1](#0-0) 

When an account first votes in the current cycle (`currentCycle == beginCycle` and no snapshot exists yet), the bookkeeping falls through to the `beginCycle < endCycle` branch on the *next* call, ultimately setting `beginCycle = endCycle(=currentCycle)`; the very next cycle transition (`RewardViCalService`/`accumulateWitnessVi`) computes the witness's Vi delta using the witness's `voteCount` at the moment of maintenance — which already includes votes cast moments earlier in the same cycle: [2](#0-1) 

The user's own reward for that cycle is then computed purely from `deltaVi * userVote`, with no check on how long the vote/freeze was actually held during the cycle: [3](#0-2) [4](#0-3) 

Crucially, `FreezeBalanceV2Actuator.execute` applies the frozen balance and voting power instantly with no lock-in period before it counts toward `TotalNetWeight`/`TotalEnergyWeight`/`TronPower`: [5](#0-4) 

and the accrued reward (`allowance`) can be withdrawn immediately, with no delay analogous to `unfreezeDelayDays` — that delay only gates the return of the *frozen principal*, never the yield: [6](#0-5) [7](#0-6) 

This is exactly the pattern flagged in the external Lybra report: value that should accrue proportionally to time-at-risk is instead awarded to anyone present at the reward snapshot, with no timelock analogous to the vault's 3-day soft-lock on `withdraw`, allowing a "hop in, capture the snapshot, hop out" strategy.

### Impact Explanation
Any address can front-run a cycle boundary: freeze the minimum 1 TRX (`frozenBalance >= TRX_PRECISION`), vote for an SR immediately before `doMaintenance()` executes, receive a full cycle's proportional reward via `computeReward`, then call `unfreezeBalanceV2`/withdraw the reward allowance right after. Because the witness's total reward pool for the cycle (`delegationStore.getReward`/`addReward`, funded from block rewards) is divided by total vote count at maintenance time, every such flash-vote directly dilutes and appropriates yield that would otherwise accrue to genuine long-term voters — a transfer of value from honest stakers to the attacker with no compensating cost (freezing carries no fee, unlike Lybra's 0.5% redemption fee).

### Likelihood Explanation
The maintenance cycle boundary time is deterministic and publicly known (`getNextMaintenanceTime` in `DynamicPropertiesStore`), so an attacker can time the freeze+vote transaction to land in the last block before `doMaintenance()` runs, making this reliably and repeatedly exploitable by any unprivileged account holding a small amount of TRX, at essentially zero cost and with the standard `FreezeBalanceV2Contract`/`VoteWitnessContract`/`WithdrawBalanceContract` (or their TVM equivalents) — no special privileges are required.

### Recommendation
Introduce a minimum holding/voting period before a freeze+vote position becomes eligible to accrue reward for a given cycle — e.g., require that the vote/frozen balance existed as of the *start* of the cycle (rather than being registered with `beginCycle = currentCycle`), or prorate reward by the fraction of the cycle actually held, analogous to imposing the softlock used elsewhere in the codebase (`unfreezeDelayDays`) on reward eligibility rather than only on principal withdrawal.

### Proof of Concept
1. Monitor `dynamicPropertiesStore.getNextMaintenanceTime()` to know when the current cycle's `doMaintenance()` will fire.
2. Just before that time, broadcast `FreezeBalanceV2Contract` (1 TRX, `BANDWIDTH` or `TRON_POWER`) via `FreezeBalanceV2Actuator.execute`, immediately followed by `VoteWitnessContract` voting for an SR with high total votes — `VoteWitnessActuator.countVoteAccount` records this vote and, via `mortgageService.withdrawReward`, sets `beginCycle = currentCycle`.
3. When `doMaintenance()` runs, `MaintenanceManager.doMaintenance` calls `delegationStore.accumulateWitnessVi(curCycle, ...)` using the witness's `voteCount`, which already includes the attacker's just-added vote, and `incentiveManager.reward(...)` pays the witness reward for the cycle.
4. In the next cycle, the attacker calls `WithdrawBalanceContract`/`WithdrawRewardContract`; `MortgageService.withdrawReward`/`VoteRewardUtil.withdrawReward` computes `computeReward(beginCycle, endCycle, ...)` = full cycle's Vi delta × the attacker's vote, crediting `allowance` for a position that was only held for a few seconds of that cycle.
5. The attacker withdraws the `allowance` via `WithdrawBalanceActuator`/`WithdrawRewardProcessor` with no delay, and can then `UnfreezeBalanceV2Contract` to reclaim the principal (subject only to `unfreezeDelayDays`, which never gated the reward that was already extracted).

  private long computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    long newAlgorithmCycle = dynamicPropertiesStore.getNewRewardAlgorithmEffectiveCycle();
    List<Pair<byte[], Long>> srAddresses = accountCapsule.getVotesList().stream()
        .map(vote -> new Pair<>(vote.getVoteAddress().toByteArray(), vote.getVoteCount()))
        .collect(Collectors.toList());
    if (beginCycle < newAlgorithmCycle) {
      long oldEndCycle = min(endCycle, newAlgorithmCycle,
          dynamicPropertiesStore.disableJavaLangMath());
      reward = getOldReward(beginCycle, oldEndCycle, srAddresses);
      beginCycle = oldEndCycle;
    }
    if (beginCycle < endCycle) {
      for (Pair<byte[], Long>  vote : srAddresses) {
        byte[] srAddress = vote.getKey();
        BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
        BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
        BigInteger deltaVi = endVi.subtract(beginVi);
        if (deltaVi.signum() <= 0) {
          continue;
        }
        long userVote = vote.getValue();
        reward += deltaVi.multiply(BigInteger.valueOf(userVote))
            .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
      }
    }
    return reward;
  }

  public boolean execute(Object result) throws ContractExeException {

    try {
      freezeBalanceV2Contract = any.unpack(FreezeBalanceV2Contract.class);

      ret.setStatus(fee, code.FAILED);

    }

        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    long frozenBalance = freezeBalanceV2Contract.getFrozenBalance();
    long newBalance = accountCapsule.getBalance() - frozenBalance;

    switch (freezeBalanceV2Contract.getResource()) {
      case BANDWIDTH:
        long oldNetWeight = accountCapsule.getFrozenV2BalanceWithDelegated(BANDWIDTH) / TRX_PRECISION;
        accountCapsule.addFrozenBalanceForBandwidthV2(frozenBalance);
        long newNetWeight = accountCapsule.getFrozenV2BalanceWithDelegated(BANDWIDTH) / TRX_PRECISION;
        dynamicStore.addTotalNetWeight(newNetWeight - oldNetWeight);
        break;
      case ENERGY:
        long oldEnergyWeight = accountCapsule.getFrozenV2BalanceWithDelegated(ENERGY) / TRX_PRECISION;
        accountCapsule.addFrozenBalanceForEnergyV2(frozenBalance);
        long newEnergyWeight = accountCapsule.getFrozenV2BalanceWithDelegated(ENERGY) / TRX_PRECISION;
        dynamicStore.addTotalEnergyWeight(newEnergyWeight - oldEnergyWeight);
        break;
      case TRON_POWER:
        long oldTPWeight = accountCapsule.getTronPowerFrozenV2Balance() / TRX_PRECISION;
        accountCapsule.addFrozenForTronPowerV2(frozenBalance);
        long newTPWeight = accountCapsule.getTronPowerFrozenV2Balance() / TRX_PRECISION;
        dynamicStore.addTotalTronPowerWeight(newTPWeight - oldTPWeight);
        break;

    accountCapsule.setBalance(newBalance);

  public long execute(WithdrawRewardParam param, Repository repo) throws ContractExeException {
    byte[] ownerAddress = param.getOwnerAddress();

    VoteRewardUtil.withdrawReward(ownerAddress, repo);

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    long oldBalance = accountCapsule.getBalance();
    long allowance = accountCapsule.getAllowance();
    long newBalance = 0;

    try {
      newBalance = LongMath.checkedAdd(oldBalance, allowance);
    } catch (ArithmeticException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractExeException(e.getMessage());
    }

    // If no allowance, do nothing and just return zero.
    if (allowance <= 0) {
      return 0;
    }

    accountCapsule.setInstance(accountCapsule.getInstance().toBuilder()
        .setBalance(newBalance)
        .setAllowance(0L)
        .setLatestWithdrawTime(param.getNowInMs())
        .build());

    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
    return allowance;
  }
