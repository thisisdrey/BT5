### Title
Unvalidated ABI offset/length values in `ValidateMultiSign` precompile can throw uncaught array-index exceptions from crafted call data - (File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java)

### Summary
The CVE describes a bug class where an externally supplied index (IIO channel number) is used to write into fixed-size storage without validating that it is in-range/sequential, causing an out-of-bounds access. The closest reachable analog in java-tron is the `ValidateMultiSign` precompiled contract's `execute()` method, which uses attacker-controlled ABI offset/length words to directly index into the `DataWord[] words` array *before* any exception-handling boundary, unlike the sibling `BatchValidateSign` contract which wraps the equivalent logic in a `try { ... } catch (Throwable t)`.

### Finding Description
`ValidateMultiSign.execute()` parses raw call data into `DataWord[] words = DataWord.parseArray(rawData)` and immediately computes an offset from attacker-controlled input: [1](#0-0) 

Note that `words[words[3].intValueSafe() / WORD_SIZE]` and the subsequent call to `extractSigArray`/`extractBytesArray` occur directly in `execute()`, outside of any try/catch. The helper functions themselves index into `words` with an offset/length taken straight from call data without bounds checks against `words.length`: [2](#0-1) 

`extractBytesArray`/`extractSigArray` only guard against `offset > words.length - 1` for the initial length word, but the subsequent loop `words[offset + i + 1]` has no such check, so a crafted `offset`/`len` combination can index past the end of the `words` array. Only `words[3].intValueSafe()/WORD_SIZE` is bounded by a `MAX_SIZE` check for the *size* value once `allowTvmSelfdestructRestriction()` is enabled, but the outer indexing that fetches that size value itself, `words[words[3].intValueSafe() / WORD_SIZE]`, is unguarded and executed unconditionally before the size check: [3](#0-2) 

By contrast, `BatchValidateSign.execute()` wraps the equivalent parsing/extraction logic (`doExecute`) in `try { return doExecute(data); } catch (Throwable t) { ... return Pair.of(true, new byte[WORD_SIZE]); }`, safely absorbing any `ArrayIndexOutOfBoundsException`/`NegativeArraySizeException`: [4](#0-3) 

`ValidateMultiSign` has no such wrapper around its parsing stage, so any out-of-range offset/length in the ABI encoding will throw uncaught from `execute()`.

### Impact Explanation
An unprivileged contract deployer/caller can invoke the `ValidateMultiSign` precompile (reachable from any TVM contract call) with a malformed offset/length so that `words[words[3].intValueSafe() / WORD_SIZE]` or the array-copy loop inside `extractBytesArray`/`extractSigArray` throws `ArrayIndexOutOfBoundsException` or `NegativeArraySizeException`. Whether this results only in transaction failure or propagates further up the execution stack (potentially disrupting block application/consensus if not caught by an outer generic exception handler in `Program`/`Runtime`) could not be fully confirmed within the available investigation — the precompiled-contract call site in `Program.java` was not conclusively verified to wrap all precompile calls in a catch-all `Throwable` handler. This uncertainty should be treated as the key open question for triage.

### Likelihood Explanation
High reachability: any account can deploy a contract or send a transaction that calls the `ValidateMultiSign` precompiled address with attacker-controlled call data, requiring no special privileges.

### Recommendation
Wrap `ValidateMultiSign.execute()`'s parsing/extraction stage in the same defensive `try { ... } catch (Throwable t) { return Pair.of(true, DATA_FALSE); }` pattern already used in `BatchValidateSign`, and add explicit bounds checks (`offset + i + 1 < words.length`) inside `extractBytesArray`, `extractSigArray`, and `extractBytes32Array` before indexing, mirroring the kernel fix that validated channel indices before using them to index fixed storage.

### Proof of Concept
Craft `rawData` for the `ValidateMultiSign` precompile where `words[3]` (the signature-array offset) encodes an offset value that, divided by `WORD_SIZE`, points at or beyond `words.length` (e.g., set the offset word to a very large value like `0xFFFFFFFF`). Calling `words[words[3].intValueSafe() / WORD_SIZE]` at line 1067/1073 then throws `ArrayIndexOutOfBoundsException` before the `MAX_SIZE` guard is ever reached, propagating out of `execute()` uncaught (verification of whether the exception is contained by an outer catch in `Program.java` was not completed).

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();

  }
