### Title
Unauthenticated relay-stats poisoning via forged `RelayData` entries in message preambles - (File: `stackslib/src/net/chat.rs`)

### Summary
`ConversationP2P::process_relayers` blindly trusts the attacker-supplied `relayers: Vec<RelayData>` field carried in every pushed-blocks/microblocks/transaction/StackerDB/Nakamoto-block message, crediting whatever `NeighborAddress` values it contains with bytes/message counts via `self.stats.add_relayer`. The only checks performed — `check_relayer_cycles` and `check_relayers_remote` — verify there are no duplicate hops and that the local node's own key is absent, but never verify that any listed relayer actually participated in forwarding the message. A remote peer can therefore name any third-party `NeighborAddress` in this list and have that peer credited with relay activity it never performed.

### Finding Description
`check_relayers_remote` only rejects a `relayers` list if it contains the local node's own `public_key_hash`, i.e. it prevents self-relay loops, nothing more [1](#0-0) . `process_relayers` runs `check_relayer_cycles` (duplicate detection) and `check_relayers_remote`, and if both pass it iterates every entry and calls `self.stats.add_relayer(&relayer.peer, ...)` unconditionally [2](#0-1) . `add_relayer` simply inserts/updates a `RelayStats` entry keyed by the caller-supplied `NeighborAddress`, with no check that this address corresponds to any connection this conversation, or any conversation at all, has ever seen [3](#0-2) .

These per-conversation stats are later merged into the network-wide `RelayerStats` via `update_relayer_stats`/`merge_relay_stats`, and the merge key even strips the public-key-hash component (`addr.clear_public_key()`), meaning credit is attributed by IP/port alone with no cryptographic binding to the actual sender at all [4](#0-3) [5](#0-4) .

The existing test `convo_process_relayers` demonstrates the mechanics: it builds a `relayers` list of two `RelayData` entries and shows that after `process_relayers` succeeds, `convo.stats.relayed_messages` contains exactly those two entries with `num_messages == 1` and `num_bytes == payload_len - 1` [6](#0-5) . Nothing in this test, or in the production code path, establishes that the `RelayData.peer` values correspond to peers who actually touched the message — they are taken verbatim from the wire-supplied preamble/relayers vector of the message the *local* conversation partner sent, which that partner can populate with arbitrary `NeighborAddress` values, including ones belonging to real, uninvolved third-party neighbors.

So the attacker's exact message is: connect to the target node, send any accepted push message (e.g. `BlocksPush`/`TransactionPush`) with a `relayers` vector containing one legitimate hop (or none) and one forged `RelayData { peer: <victim's NeighborAddress>, seq: ... }` where `victim` never relayed this bytes. `process_relayers` accepts it (no self-reference, no cycle) and credits the victim's address with relay bytes/messages it never sent, breaking the equality "relayer credited in stats == peer that actually forwarded these bytes."

### Impact Explanation
The corrupted `RelayStats`/`RelayerStats` feed directly into `get_inbound_relay_rankings`/`get_outbound_relay_rankings` and `sample_broadcast_peers`, which use relay bandwidth/frequency as a weighting signal for choosing which peers to broadcast future data to. By inflating (or, by omission, deflating relative to others) an innocent third party's recorded relay volume, an attacker can skew broadcast-sampling weight against or in favor of arbitrary neighbors, degrading the innocent peer's effective connectivity/influence in gossip sampling. This is a data-integrity/manipulation issue in peer selection, not a memory-safety or consensus-state issue — no forged block/tx is stored as canonical, no crash occurs, and no unauthorized write to StackerDB/mempool state occurs. It is repeatable on every message the attacker's conversation sends.

### Likelihood Explanation
No preconditions beyond an ordinary, unprivileged P2P connection are required: any remote peer that can complete a handshake and send push-type messages (blocks/microblocks/tx/StackerDB chunk/Nakamoto blocks) can include a forged `RelayData` entry, since `relayers` is validated only for self-reference and cycles, both trivially avoidable. Cost per exploitation attempt is a single crafted message; it is fully repeatable and remotely reachable on the standard P2P port with no privileged role or secret needed.

### Recommendation
Treat the `relayers` field as an unverified hint (as the existing doc comment on `RelayStats` already partially acknowledges: "Used to deduce network choke points") rather than as ground truth for stats that influence peer-selection weighting. Options: (1) only credit relay stats for the immediate sending conversation's own peer (the direct sender of the message), not for entries further back in the `relayers` chain that cannot be verified; (2) require some cryptographic attestation (e.g., a per-hop signature) binding a `RelayData` entry to the actual relaying peer's key before crediting it; (3) at minimum, bound the influence relay-hint stats can have on broadcast-sampling weight, or use lower-weighted/decayed trust for hinted (non-directly-observed) relayers.

### Proof of Concept

1. Build `relayers: Vec<RelayData>` containing a single `RelayData` whose `peer: NeighborAddress` corresponds to a "victim" neighbor address that never connected to `convo` (e.g., a fabricated IP/port/hash not used anywhere else in the test, or reuse of a real neighbor's address that this conversation never handled).
2. Call `convo.process_relayers(&local_peer, &msg.preamble, &relayers)` and assert it returns `true` (i.e., not rejected).
3. Call `convo.stats.take_relayers()` and assert the resulting map contains the forged victim address with `num_messages == 1` and `num_bytes == (msg.preamble.payload_len - 1) as u64`, exactly as the existing test at `stackslib/src/net/chat.rs:6461-6478` already demonstrates for legitimate-looking entries — proving the code path credits arbitrary attacker-chosen addresses with no ownership/participation check.
4. To show downstream effect, feed the resulting `RelayStats` map through `PeerNetwork::update_relayer_stats`/`RelayerStats::merge_relay_stats` (`stackslib/src/net/relay.rs:3334-3339`, `256-298`) and then compare `sample_neighbors`/ranking output before and after injecting the forged entry, showing the victim's sampling weight changes despite never having relayed anything.

    fn process_relayers(
        &mut self,
        local_peer: &LocalPeer,
        preamble: &Preamble,
        relayers: &[RelayData],
    ) -> bool {
        if !ConversationP2P::check_relayer_cycles(relayers) {
            warn!(
                "Invalid relayers -- message from {:?} contains a cycle",
                self.to_neighbor_key()
            );
            return false;
        }

        if !ConversationP2P::check_relayers_remote(local_peer, relayers) {
            warn!(
                "Invalid relayers -- message originates from us ({})",
                local_peer.to_neighbor_addr()
            );
            return false;
        }

        for relayer in relayers.iter() {
            self.stats
                .add_relayer(&relayer.peer, (preamble.payload_len - 1) as u64);
        }

        return true;
    }

    pub fn merge_relay_stats(&mut self, mut stats: HashMap<NeighborAddress, RelayStats>) {
        for (mut addr, new_stats) in stats.drain() {
            addr.clear_public_key();
            let inserted = if let Some(stats) = self.relay_stats.get_mut(&addr) {
                stats.merge(new_stats);
                false
            } else {
                // remove oldest relay memories if we have too many
                if self.relay_stats.len() > MAX_RELAYER_STATS - 1 {
                    let mut to_remove = vec![];
                    for (ts, old_addr) in self.relay_updates.iter() {
                        self.relay_stats.remove(old_addr);
                        if self.relay_stats.len() < MAX_RELAYER_STATS {
                            break;
                        }
                        to_remove.push(*ts);
                    }
                    for ts in to_remove.into_iter() {
                        self.relay_updates.remove(&ts);
                    }
                }
                self.relay_stats.insert(addr.clone(), new_stats);
                true
            };

            if inserted {
                self.relay_updates.insert(self.next_priority, addr);
                self.next_priority += 1;
            }
        }
    }
