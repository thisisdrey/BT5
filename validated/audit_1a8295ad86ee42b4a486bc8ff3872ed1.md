### Title
Unauthenticated `/shutdown` HTTP endpoint permanently halts the signer's event loop - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` handles `POST /shutdown` on the signer's event HTTP server without any authentication or secret check, immediately setting `stop_signal` and returning `EventError::Terminated`. This is the same effect the legitimate `SignerStopSignaler::send()` produces, so any party able to reach the event port can permanently stop the signer's event-processing loop with a single crafted request.

### Finding Description
`SignerEventReceiver::next_event` dispatches based solely on `request.url()` and `request.method()`, with no signature, token, or IP allow-list check anywhere in the function: [1](#0-0) 
matches on `"/shutdown"` and unconditionally does:
```rust
event_receiver.stop_signal.store(true, Ordering::SeqCst);
Err(EventError::Terminated)
```
This is exactly the store performed by the legitimate operator-only path, `SignerStopSignaler::send()`: [2](#0-1) 
which connects to the receiver's own bound address and posts the same `POST /shutdown` request. The receiver's `main_loop` treats `EventError::Terminated` as an unconditional break out of the loop: [3](#0-2) 
There is no equality/authentication check distinguishing a request that came from the trusted `SignerStopSignaler` (created internally via `get_stop_signaler`) from an arbitrary external TCP client — any TCP peer that can complete the HTTP request line and headers to `/shutdown` triggers the identical code path. The `/status` handler is unauthenticated too but has no destructive side effect; `/shutdown` is the only path in this dispatch table that mutates persistent receiver state with no gating.

### Impact Explanation
Any remote party capable of opening a TCP connection to the signer's event-receiver port and sending a single `POST /shutdown` request permanently stops that signer's event processing loop (`main_loop` exits via `EventError::Terminated`), since `stop_signal` is a `SeqCst` `AtomicBool` shared across the process and is never reset. This halts consumption of miner block proposals, StackerDB chunks, and burn-block events by that signer instance — a single-message, repeatable, unauthenticated denial-of-service against a Stacks signer node. This matches the Critical category: "remote crash/unauthenticated DoS from few messages."

### Likelihood Explanation
The event server is bound via `bind()` to `config.endpoint`: [4](#0-3) 
and the code's own warning acknowledges the endpoint may be exposed beyond localhost ("It's important to exercise caution if you are communicating with an external node... expose sensitive data or functionalities to security risks"): [5](#0-4) 
Whether this is remotely reachable depends entirely on the operator's configured `endpoint` bind address (e.g., `0.0.0.0` vs `127.0.0.1`) and any external firewalling — this is deployment/config-dependent and not something enforced by the code itself. No secret, signature, StackerDB slot ownership, or any privileged role is checked in the handler; the attack requires only a single crafted HTTP POST and is trivially repeatable.

### Recommendation
Require a shared secret or mutual-auth token (e.g., a random token generated at startup and passed only to the internal `SignerStopSignaler`, checked via constant-time comparison) before honoring `/shutdown`, or bind the event server to loopback only and reject `/shutdown` requests unless `request.remote_addr()` is loopback. At minimum, do not allow this endpoint to be exposed on a non-loopback interface without an authentication check.

### Proof of Concept

```rust
use std::net::{TcpListener, TcpStream};
use std::io::Write;
use libsigner::{EventReceiver, SignerEventReceiver};
// pseudo-outline, mirrors existing crate test infra:
let mut receiver: SignerEventReceiver<SomeMessageType> = SignerEventReceiver::new(false);
let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

// spawn main_loop in a thread with a dummy consumer channel added via add_consumer
let handle = std::thread::spawn(move || receiver.main_loop());

// Attacker: unrelated socket, no auth
let mut stream = TcpStream::connect(addr).unwrap();
let body = "attacker controlled";
let req = format!(
    "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
    addr, body.len(), body
);
stream.write_all(req.as_bytes()).unwrap();

// Assert the loop terminated due to the unauthenticated request
handle.join().unwrap();
// (equivalently: assert stop_signal / is_stopped() became true without ever calling get_stop_signaler().send())
```
