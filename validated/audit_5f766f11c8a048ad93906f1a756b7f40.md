### Title
Unbounded reftable varint lengths cause out-of-bounds slice panics when parsing attacker-supplied `.ref` table files - (File: internal/git/reftable/reftable.go)

### Summary
`internal/git/reftable/reftable.go` parses Git's reftable binary format the same way `ErrorUtils.getRevertMessage()` parsed revert-reason strings: it trusts a length field embedded in untrusted binary data and uses it directly to slice buffers, without validating the declared length against the actual buffer size. This mirrors the "faked length" bug class from the report, but here the sink is a Go slice expression rather than `abi.decode`, and the reachable path is a WAL-partition transaction / snapshot-based repository creation flow that ingests a reftable produced from data outside of Gitaly's own `git` invocation.

### Finding Description
`getVarInt` decodes a variable-length integer directly from the block buffer, only bounding the *byte-reading loop* against `blockEnd`, and never validating the decoded *value* against anything: [1](#0-0) 

That decoded value is then used immediately, unchecked, as a slice length in `getRefsFromBlock`: [2](#0-1) 

Both `prefix[:prefixLength]` and `src[idx:idx+suffixLength]` use attacker-controllable `prefixLength`/`suffixLength` values decoded straight from the file with no upper bound and no check against `len(prefix)` / `len(src)`. A crafted varint (e.g., a length far larger than the actual `prefix` string or than the remaining bytes in `src`) causes a Go runtime "slice bounds out of range" panic — the direct analog of the faked-length OOM/DoS in the original report, except here it manifests as an immediate panic rather than a gas-exhaustion loop. The same unchecked-length pattern also affects the symref branch (`src[idx : idx+size]` at line 290) and the hash-copy branches (`src[idx : idx+hashSize]`), and `extractBlockLen`/`parseRefBlock` compute buffer offsets (`blockStart+currentBS-2`, `RestartStart`) from attacker-controlled block-length bytes without bounds checks against `len(src)`.

Reftable files are not necessarily always generated purely by a trusted local `git` invocation on the Gitaly node reading them. `internal/gitaly/storage/storagemgr/partition/reftable.go`'s `stageTables`/`reftableRecorder` calls `reftable.ParseTable` on `.ref` files residing in a transaction's *snapshot* directory before staging them into the WAL: [3](#0-2) 

Repository-creation/replication code paths that populate a repository directory from raw byte streams — e.g. `CreateRepositoryFromSnapshot`'s `untar` (extracting an operator-supplied tar over HTTP directly into the new repo's git directory via `tar -xvf -`) and `ReplicateRepository`'s `extractTarToDirectory` (writing tar entries verbatim to disk) — write arbitrary file contents, including files inside a `reftable/` directory, without any git-level validation of their binary structure: [4](#0-3) [5](#0-4) 

If such a repository uses the reftable reference backend, any later attempt to read references from it (`GetReferences()` via `ListRefs`, `FindAllBranches`, `stageTables`, or the WAL replay/reconciliation logic) parses the attacker-influenced table bytes with the unchecked-length code shown above, triggering a panic.

### Impact Explanation
A panic inside `Table.GetReferences()`/`getRefsFromBlock` crashes the goroutine handling the RPC (`ListRefs`, `FindAllBranches`, `stageTables` during transaction commit, or the reftable-consistency helpers used by the storage manager). Depending on whether Gitaly's gRPC panic-recovery middleware catches it per-request or the panic escapes into a background WAL-processing goroutine (as in `stageTables`, which runs during `Begin`/`Commit` of a write transaction, not inside a per-request interceptor), this can cause denial of service ranging from a failed individual RPC to disruption of the write-ahead-log transaction pipeline for the affected partition, which is more severe than a single request failure.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a repository configured to use the reftable backend, and (b) a way to get attacker-influenced bytes into a `.ref`/table file rather than a file produced purely by a local, trusted `git` command. The `CreateRepositoryFromSnapshot` and `ReplicateRepository`/`extractSnapshot` code paths, which write raw tar contents (including files under `reftable/`) straight to disk, are the most plausible vectors, though the snapshot content in practice usually originates from another Gitaly node's `GetSnapshot`, narrowing the population of realistic attackers to compromised/misbehaving peers or externally-fetched HTTP snapshot URLs supplied to `CreateRepositoryFromSnapshot`. Note the RPC's own documentation explicitly warns that "the received archive is trusted *a lot*" and needs hardening before pointing it at endpoints outside Gitaly's control, corroborating that this ingestion path is a recognized weak point.

### Recommendation
Harden `internal/git/reftable/reftable.go` before trusting any length or offset decoded from table bytes:
- In `getVarInt`, additionally bound-check `start < len(src)` before every `src[start]` access.
- After decoding `prefixLength`, `suffixLength`, `size`, and `hashSize`-derived offsets, validate that `idx+length <= len(src)` (and `prefixLength <= len(prefix)`) before slicing; return a parse error instead of panicking when the declared length exceeds the available data.
- Apply the same bounds validation to `extractBlockLen`, `parseRefBlock`'s `RestartStart`/`currentBS` arithmetic, and the block-range/footer offset computations, all of which currently assume well-formed input.
- Wrap `GetReferences()` invocations (or the whole reftable package) with panic recovery at call sites that cannot otherwise guarantee input trust (e.g., post-snapshot-extraction ingestion), converting panics into structured errors.

### Proof of Concept
Not independently executed in this review; the vulnerable code path can be exercised conceptually as follows:
1. Craft a `.ref` reftable file whose header/footer pass `parseHeader`/`parseFooter` (correct magic, version, hash ID, and CRC32) but whose ref block encodes a `prefix_length` varint far larger than the previous `prefix` string, or a `suffix_length` varint whose value plus `idx` exceeds `len(src)`.
2. Place this file (with a matching `tables.list` entry) into a reftable-backend repository's `reftable/` directory, e.g. via a tar snapshot supplied to `CreateRepositoryFromSnapshot` or `ReplicateRepository`'s snapshot-extraction path (both write raw file bytes without validating git object formats).
3. Trigger a reference read against that repository, e.g. `ListRefs`/`FindAllBranches`, or a write transaction whose `Begin` invokes `reftableRecorder`/`stageTables`.
4. Observe a Go runtime panic ("slice bounds out of range") originating from `getRefsFromBlock` (`internal/git/reftable/reftable.go:247`), crashing the handling goroutine.

// getVarInt parses a variable int and increases the index.
func (t *Table) getVarInt(src []byte, start uint, blockEnd uint) (uint, uint, error) {
	var val uint

	val = uint(src[start]) & 0x7f

	for (uint(src[start]) & 0x80) > 0 {
		start++
		if start > blockEnd {
			return 0, 0, fmt.Errorf("exceeded block length")
		}

		val = ((val + 1) << 7) | (uint(src[start]) & 0x7f)
	}

	return start + 1, val, nil
}

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		header, err := tarReader.Next()
		if err == io.EOF {
			break // End of archive
		}
		if err != nil {
			return fmt.Errorf("reading tar header: %w", err)
		}

		targetPath := filepath.Join(targetDir, header.Name)

		if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
			targetPath != targetDir {
			return fmt.Errorf("invalid file path in tar: %s", header.Name)
		}

		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("creating directory %s: %w", targetPath, err)
			}

		case tar.TypeReg:
			if err := s.extractFile(ctx, tarReader, targetPath, header); err != nil {
				return fmt.Errorf("extracting file %s: %w", targetPath, err)
			}

		case tar.TypeSymlink:
			if filepath.IsAbs(header.Linkname) {
				return fmt.Errorf("absolute symlink not allowed: %s -> %s", header.Name, header.Linkname)
			}

			// Resolve the relative symlink target from the symlink's parent directory
			// and verify it stays within the extraction boundary, consistent with the
			// hard link validation below.
			resolvedTarget := filepath.Join(filepath.Dir(targetPath), header.Linkname)
			if !strings.HasPrefix(resolvedTarget, targetDir+string(os.PathSeparator)) &&
				resolvedTarget != targetDir {
				return fmt.Errorf("symlink target escapes extraction directory: %s -> %s", header.Name, header.Linkname)
			}

			// Remove existing file/symlink if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for symlink %s: %w", targetPath, err)
			}

			if err := os.Symlink(header.Linkname, targetPath); err != nil {
				return fmt.Errorf("creating symlink %s -> %s: %w", targetPath, header.Linkname, err)
			}

		case tar.TypeLink:
			linkTarget := filepath.Join(targetDir, header.Linkname)

			if !strings.HasPrefix(linkTarget, targetDir+string(os.PathSeparator)) &&
				linkTarget != targetDir {
				return fmt.Errorf("invalid hard link target: %s", header.Linkname)
			}

			// Remove existing file if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for hard link %s: %w", targetPath, err)
			}

			if err := os.Link(linkTarget, targetPath); err != nil {
				return fmt.Errorf("creating hard link %s -> %s: %w", targetPath, linkTarget, err)
			}

		default:
			// Skip unsupported file types (devices, FIFOs, etc.)
			s.logger.WithField("file", header.Name).WithField("type", header.Typeflag).
				WarnContext(ctx, "skipping unsupported file type in tar archive")
		}

		if header.Typeflag == tar.TypeReg || header.Typeflag == tar.TypeDir {
			if err := os.Chmod(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("setting permissions for %s: %w", targetPath, err)
			}
		}
	}

	return nil
}
