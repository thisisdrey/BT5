### Title
Unstaked QUIC clients can multiply connections to exceed the intended 20% aggregate throughput carve-out - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
`StakedStreamLoadEMA::available_load_capacity_in_throttling_duration` returns a fixed, per-connection stream cap for unstaked peers (`max_unstaked_load_in_throttling_window`, derived from a constant `MAX_UNSTAKED_TPS = 200`), which is enforced only per `ConnectionStreamCounter` in `throttle_stream`. Because this cap is never aggregated across connections, an attacker opening many unstaked connections (up to `max_unstaked_connections`) can multiply the per-connection allowance to consume far more of `max_streams_per_ms` than the `EXPECTED_UNSTAKED_STREAMS_RATIO` (20%) design intends.

### Finding Description
`StakedStreamLoadEMA::new` computes `max_unstaked_load_in_throttling_window = MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000` [1](#0-0)  — a fixed constant independent of `max_streams_per_ms`, `max_unstaked_connections`, or actual global unstaked load. `EXPECTED_UNSTAKED_STREAMS_RATIO` (20%) is used only to shrink the *staked* budget (`max_staked_load_in_ms`) at construction time [2](#0-1) ; it is never used to bound the aggregate unstaked throughput.

`available_load_capacity_in_throttling_duration` simply returns this fixed per-connection value for `ConnectionPeerType::Unstaked`, with no reference to how many unstaked connections exist or how much unstaked load is currently being admitted: [3](#0-2) 

This cap is enforced per-connection via `ConnectionStreamCounter` (one instance per QUIC connection, reset every `STREAM_THROTTLING_INTERVAL`) inside `throttle_stream` [4](#0-3) , and is invoked from `SwQos::on_new_stream`/`max_streams_per_throttling_interval` per connection [5](#0-4) . There is no global counter across all unstaked connections limiting aggregate unstaked streams/sec.

Unstaked connections are admitted up to `max_unstaked_connections` (default 2000) [6](#0-5) , subject only to per-IP connection limits (`max_connections_per_unstaked_peer`, default 8) [7](#0-6)  and pruning of the oldest 10% when the table fills [8](#0-7) . An attacker distributing connections across many source IPs (unprivileged, no stake needed) can occupy close to the full `max_unstaked_connections` capacity, each streaming at its individually allotted 20 streams/100ms (`MAX_UNSTAKED_TPS=200`), for an aggregate potential far above the intended 20% share of `max_streams_per_ms`.

The staked-side throttling (`staked_throttling_enabled`) only reacts to *staked* load exceeding `staked_throttling_on_load_threshold` (95% of the staked EMA budget) [9](#0-8)  — it never observes or reacts to unstaked load (`increment_load` only increments `load_in_recent_interval` for staked peers) [10](#0-9) . Thus unstaked aggregate consumption is structurally decoupled from the EMA-based staked/unstaked split, confirming the reservation is not actually enforced as a cap on unstaked traffic.

### Impact Explanation
With defaults (`DEFAULT_MAX_STREAMS_PER_MS = 500`, `DEFAULT_MAX_UNSTAKED_CONNECTIONS = 2000`), each unstaked connection can sustain ~200 TPS, so the aggregate unstaked ceiling is on the order of `2000 * 200 = 400,000` streams/sec — comparable to the entire `max_streams_per_ms` budget (500,000/sec) and far beyond the 20% (100,000/sec) intended reservation. This lets unstaked/attacker traffic crowd out legitimate staked transaction submission at the QUIC ingress layer of TPU, degrading banking-stage throughput for paying senders — a QoS-evasion / DoS-adjacent condition against the fee-market design, matching an Agave "QoS evasion" bounty category rather than a memory-safety or consensus bug.

### Likelihood Explanation
Feasible for an unprivileged attacker: opening near-`max_unstaked_connections` QUIC connections (distributed across enough source IPs to stay under `max_connections_per_unstaked_peer`) and streaming at the per-connection allotted rate requires no stake, no validator control, and no protocol violation — only standard QUIC/TPU client behavior at scale. It is fully repeatable and does not depend on race conditions.

### Recommendation
Enforce a global aggregate cap on unstaked stream admission (e.g., a shared atomic counter or token bucket checked in `available_load_capacity_in_throttling_duration`/`throttle_stream` for `ConnectionPeerType::Unstaked`) so that total unstaked throughput cannot exceed `EXPECTED_UNSTAKED_STREAMS_RATIO * max_streams_per_ms`, regardless of how many unstaked connections are opened, rather than only bounding each connection independently.

### Proof of Concept
Rust unit/integration test plan (extending `streamer/src/nonblocking/stream_throttle.rs` test module):
1. Construct `StakedStreamLoadEMA::new(stats, DEFAULT_MAX_UNSTAKED_CONNECTIONS, DEFAULT_MAX_STREAMS_PER_MS)`.
2. Simulate `N = DEFAULT_MAX_UNSTAKED_CONNECTIONS` independent `ConnectionStreamCounter`s, each calling `available_load_capacity_in_throttling_duration(ConnectionPeerType::Unstaked, total_stake)` and driving `throttle_stream` up to that per-connection cap within one `STREAM_THROTTLING_INTERVAL`.
3. Assert that `N * max_unstaked_load_in_throttling_window` (aggregate admitted unstaked streams per interval) exceeds `EXPECTED_UNSTAKED_STREAMS_RATIO * max_streams_per_ms * (STREAM_THROTTLING_INTERVAL_MS/1000)`, demonstrating the invariant ("unstaked aggregate bandwidth share is bounded to its reserved fraction") is violated — i.e., `N * 20 > 0.20 * 500 * 0.1 = 10` trivially fails once `N > 0` beyond a handful of connections, and at `N = 2000` the aggregate (`40,000` per 100ms window) vastly exceeds the reserved `10` per window.

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }

pub struct ConnectionStreamCounter {
    pub(crate) stream_count: AtomicU64,
    last_throttling_instant: RwLock<tokio::time::Instant>,
}

impl OpaqueStreamerCounter for ConnectionStreamCounter {}

impl ConnectionStreamCounter {
    pub fn new() -> Self {
        Self {
            stream_count: AtomicU64::default(),
            last_throttling_instant: RwLock::new(tokio::time::Instant::now()),
        }
    }

    /// Reset the counter and last throttling instant and
    /// return last_throttling_instant regardless it is reset or not.
    pub(crate) fn reset_throttling_params_if_needed(&self) -> tokio::time::Instant {
        let last_throttling_instant = *self.last_throttling_instant.read().unwrap();
        if tokio::time::Instant::now().duration_since(last_throttling_instant)
            > STREAM_THROTTLING_INTERVAL
        {
            let mut last_throttling_instant = self.last_throttling_instant.write().unwrap();
            // Recheck as some other thread might have done throttling since this thread tried to acquire the write lock.
            if tokio::time::Instant::now().duration_since(*last_throttling_instant)
                > STREAM_THROTTLING_INTERVAL
            {
                *last_throttling_instant = tokio::time::Instant::now();
                self.stream_count.store(0, Ordering::Relaxed);
            }
            *last_throttling_instant
        } else {
            last_throttling_instant
        }
    }
}

pub(crate) async fn throttle_stream(
    stats: &StreamerStats,
    peer_type: ConnectionPeerType,
    remote_addr: std::net::SocketAddr,
    stream_counter: &Arc<ConnectionStreamCounter>,
    max_streams_per_throttling_interval: u64,
) {
    let throttle_interval_start = stream_counter.reset_throttling_params_if_needed();
    let streams_read_in_throttle_interval = stream_counter.stream_count.load(Ordering::Relaxed);
    if streams_read_in_throttle_interval >= max_streams_per_throttling_interval {
        // The peer is sending faster than we're willing to read. Sleep for what's
        // left of this read interval so the peer backs off.
        let throttle_duration =
            STREAM_THROTTLING_INTERVAL.saturating_sub(throttle_interval_start.elapsed());

        if !throttle_duration.is_zero() {
            debug!(
                "Throttling stream from {remote_addr:?}, peer type: {peer_type:?}, \
                 max_streams_per_interval: {max_streams_per_throttling_interval}, \
                 read_interval_streams: {streams_read_in_throttle_interval} throttle_duration: \
                 {throttle_duration:?}"
            );
            stats.throttled_streams.fetch_add(1, Ordering::Relaxed);
            match peer_type {
                ConnectionPeerType::Unstaked => {
                    stats
                        .throttled_unstaked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
                ConnectionPeerType::Staked(_) => {
                    stats
                        .throttled_staked_streams
                        .fetch_add(1, Ordering::Relaxed);
                }
            }
            sleep(throttle_duration).await;
        }
    }
}

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,

                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }
