### Title
Unauthenticated `RecvError` packet with spoofed source address can force session teardown - (File: outside.go)

### Summary
`Interface.handleRecvError` tears down a live tunnel and its pending handshake state based solely on an unauthenticated UDP packet whose `RemoteIndex` matches an existing hostinfo and whose source `netip.AddrPort` matches `hostinfo.GetRemote()`. There is no cryptographic proof (no MAC/AEAD tag, no handshake nonce) tying the `RecvError` packet to the real peer, so an attacker who can guess/observe the 32-bit `RemoteIndex` and spoof the peer's UDP source address can trigger `closeTunnel` and `handshakeManager.DeleteHostInfo`.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets to `f.handleRecvError(via.UdpAddr, h)` before any encryption/authentication check — `RecvError` is handled in the "Unencrypted packets" switch alongside `Handshake` [1](#0-0) . `handleRecvError` performs only two checks: a config-based rate/policy gate (`acceptRecvErrorConfig.ShouldRecvError(addr)`, which by default is `recvErrorAlways` and accepts any address [2](#0-1) ), then looks up the hostinfo via `f.hostMap.QueryReverseIndex(h.RemoteIndex)` and compares the packet's source address to `hostinfo.GetRemote()` [3](#0-2) . If both match, it unconditionally calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` [4](#0-3) .

None of these checks constitute origin authentication: `RemoteIndex` is a locally-generated 32-bit value exchanged in cleartext during the handshake and observable on the wire (e.g., via passive network position, prior traffic capture, or brute force since it's only 32 bits), and UDP source address is trivially spoofable by an off-path or on-path attacker without possessing the tunnel's symmetric keys. The address-equality check in `handleRecvError` (`hr != addr`) is the same address-oriented reasoning used for roaming and is not a substitute for AEAD-authenticated packet verification — unlike `header.Message`/`header.CloseTunnel` packets, which are dropped before any state-mutating action if `hostinfo.ConnectionState.Decrypt`/`VerifyRelay` fails [5](#0-4) , the `RecvError` path never invokes decryption or MAC verification at all before mutating hostmap/handshake state.

### Impact Explanation
This matches "remote state poisoning" / session-teardown DoS in the Nebula bounty impact categories: an unauthenticated attacker can force deletion of a legitimate tunnel's `HostInfo` from both the main hostmap and the pending handshake manager, disrupting an active, authenticated session and forcing renegotiation, which the attacker can attempt to race or repeatedly abuse to keep a tunnel from ever stabilizing. This does not by itself bypass certificate/CA verification or decrypt traffic, but it is a real remote crash/wedge-adjacent denial-of-service against session state.

### Likelihood Explanation
Feasibility depends on: (1) `listen.accept_recv_error` being at its default `always` (or `private` if attacker can spoof from a private-looking address) — realistic since this is the documented default; (2) the attacker's ability to spoof the legitimate peer's UDP source `netip.AddrPort` — feasible for on-path/off-path attackers on many network paths (UDP spoofing is well known to be blockable by BCP38 but not universally deployed); (3) knowledge/guessing of the target's `RemoteIndex` — this is a 32-bit value observable by anyone who can see any packet on the tunnel (it's sent in cleartext header on every packet, including handshake packets), so it is not secret and requires no brute force if any passive observation of the target's traffic is possible. Given these, the attack is repeatable and does not require any privileged position beyond passive observation and address spoofing capability.

### Recommendation
Do not let unauthenticated `RecvError` packets mutate hostmap/handshake state based on address match alone. Options: require `RecvError` handling to only affect a hostinfo when the local side actually attempted a send that failed (e.g., correlate against a locally tracked "recently sent" nonce/token), or bind `RecvError` responses to a short-lived, per-remote-index token communicated during the handshake and included (and ideally MAC'd with a lightweight key) in the `RecvError` packet, or reduce the action taken to something reversible/rate-limited (e.g., trigger only a fresh handshake attempt rather than deleting existing hostinfo state) unless corroborated by subsequent authenticated handshake traffic.

### Proof of Concept
Unit test in `outside_test.go` style:
1. Set up an `Interface` with `acceptRecvErrorConfig = recvErrorAlways` and a `HostMap` containing a `HostInfo` with a known `RemoteIndex` and `remote` address `A`.
2. Craft a `header.H` with `Type = header.RecvError`, `RemoteIndex` set to the known index, with no valid AEAD/MAC and no association to any real send attempt.
3. Call `f.handleRecvError(A, h)` (or drive it via `readOutsidePackets`) with spoofed source `A`.
4. Assert (current behavior, demonstrating the bug): `closeTunnel` is invoked and the hostinfo is removed from `hostMap` and `handshakeManager` — i.e., `hostMap.QueryReverseIndex(index)` returns `nil` afterward — despite no cryptographic proof of packet origin having been presented.
5. Expected secure behavior (what the fix should enforce): the test should assert that `closeTunnel`/`DeleteHostInfo` are NOT invoked unless some authenticated correlation (e.g., a token bound to an actual outbound packet the attacker could not have observed, or a MAC) is present.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}
```

```go
func (f *Interface) reloadAcceptRecvError(c *config.C) {
	if c.InitialLoad() || c.HasChanged("listen.accept_recv_error") {
		stringValue := c.GetString("listen.accept_recv_error", "always")

		switch stringValue {
		case "always":
			f.acceptRecvErrorConfig = recvErrorAlways
		case "never":
			f.acceptRecvErrorConfig = recvErrorNever
		case "private":
			f.acceptRecvErrorConfig = recvErrorPrivate
		default:
			if c.GetBool("listen.accept_recv_error", true) {
				f.acceptRecvErrorConfig = recvErrorAlways
			} else {
				f.acceptRecvErrorConfig = recvErrorNever
			}
		}

		f.l.Info("Loaded accept_recv_error config", "acceptRecvError", f.acceptRecvErrorConfig.String())
	}
}
```
