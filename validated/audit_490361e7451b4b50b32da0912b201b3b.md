### Title
Unauthenticated `/wallet/getnodeinfo` (and Solidity/PBFT variants) discloses internal peer topology, node identifiers and machine details to any HTTP client - (File: framework/src/main/java/org/tron/core/services/http/GetNodeInfoServlet.java)

### Summary
`GetNodeInfoServlet` exposes the full contents of `NodeInfoService.getNodeInfo()` to any anonymous HTTP request with no signature, token, or permission check, only generic rate limiting.

### Finding Description
`GetNodeInfoServlet.doGet`/`doPost` calls `nodeInfoService.getNodeInfo()` and serializes the result directly to the HTTP response without any authentication or authorization check [1](#0-0) . The servlet only extends `RateLimiterServlet`, whose `service()` method performs QPS/global rate-limit checks and nothing related to caller identity or permissions [2](#0-1) . The only other filters in the request chain, `HttpApiAccessFilter` and `HttpInterceptor`, merely check a static "disabled API" list and record metrics — they do not authenticate callers [3](#0-2) [4](#0-3) .

The response, `NodeInfo`, includes: full peer list with each peer's real IP/host, listening port, node ID, sync state, latency, and local/remote disconnect reasons; node config including listen port, backup port, discovery status, and P2P version; and machine details such as OS name, Java version, CPU/memory usage, and any deadlocked-thread stack traces [5](#0-4) [6](#0-5) . This is registered on multiple unauthenticated paths across FullNode, Solidity, and PBFT HTTP services: `/wallet/getnodeinfo`, `/monitor/getnodeinfo`, `/walletsolidity/getnodeinfo`, and `/getnodeinfo` on the PBFT node [7](#0-6) [8](#0-7) .

This is analogous to the Jenkins CWE-200 case (GHSA-4653-rmch-3g2g), where an unauthenticated widget/page disclosed sensitive CLI/system information to any remote requester — here the java-tron equivalent is an unauthenticated servlet leaking internal peer network topology and node internals to any anonymous HTTP client.

### Impact Explanation
Disclosure of real peer IP addresses, ports, and node IDs lets an attacker map a node's connected peer set (including private/relay peers not otherwise discoverable), enabling targeted network reconnaissance and follow-on network-level attacks (e.g., targeted connection floods against identified peers) against a node that intended those peers to remain non-public. Because the endpoint is reachable by any unauthenticated caller and returns live, unredacted internal state, it meets CWE-200 information-disclosure criteria for the HTTP query surface into `Wallet`/node services.

### Likelihood Explanation
Trivial to exploit: it is a plain unauthenticated `GET`/`POST` to a well-known, always-registered endpoint (`/wallet/getnodeinfo`) with no special preconditions, requiring only network reachability to the node's HTTP API port.

### Recommendation
Require authentication/authorization (e.g., admin-only token, loopback-only binding, or explicit opt-in config) for `GetNodeInfoServlet` and its Solidity/PBFT subclasses, or strip sensitive fields (peer IPs, node IDs, backup ports, thread stack traces) from the default anonymous response, consistent with how `getDisabledApiList` already allows operators to disable sensitive APIs.

### Proof of Concept
```
curl http://<node-host>:<http-port>/wallet/getnodeinfo
```
No credentials required; the JSON response includes `peerList[].host`, `peerList[].port`, `peerList[].nodeId`, `configNodeInfo.listenPort`, `configNodeInfo.backupListenPort`, and `machineInfo` (OS/Java version, CPU/memory) as defined by `NodeInfo`/`Protocol.NodeInfo` [9](#0-8) .
