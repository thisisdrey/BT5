### Title
Unauthenticated `RecvError` Packet Allows Remote Attacker to Force-Close an Established Tunnel (DoS) - (File: outside.go)

### Summary
Nebula's `handleRecvError` accepts an unencrypted, unauthenticated `header.RecvError` control packet and, if the packet's source `netip.AddrPort` matches the tunnel's currently recorded remote address, immediately tears down the tunnel via `f.closeTunnel(hostinfo)` and deletes the pending handshake state. Because UDP source addresses can be spoofed by an off-path or on-path attacker without holding any CA-signed certificate, this control signal can be abused to permanently disrupt legitimate cross-peer communication, mirroring the report's bug class: an unauthenticated/uncontrolled signal ("packet timeout" in IBC, "recv_error" in Nebula) that causes a full, hard teardown of an established communication channel rather than a soft/recoverable failure.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets before any AEAD/key verification is performed: [1](#0-0) 

The handler resolves the target tunnel purely from the plaintext `RemoteIndex` field and compares only the packet's source address against the hostinfo's currently known remote endpoint — no cryptographic authentication of the sender is performed: [2](#0-1) 

If the (spoofable) source `netip.AddrPort` matches, the tunnel is force-closed with `f.closeTunnel(hostinfo)` and the pending-handshake state is deleted, allowing no recovery grace period. This is structurally identical to the IBC finding's root cause: a low-cost, externally-triggerable signal (gas-limit-induced timeout in IBC; spoofed `recv_error` in Nebula) that results in an authoritative, hard-closing state transition of an active channel/tunnel, causing legitimate traffic to be permanently blocked until a new handshake is renegotiated. The IBC report closes an `ORDERED` channel entirely; Nebula's analog fully closes the tunnel object and clears the pending handshake, forcing a full re-handshake and any in-flight application traffic to be dropped.

There is a rate-limiting/config gate, `acceptRecvErrorConfig.ShouldRecvError(addr)` and `sendRecvErrorConfig.ShouldRecvError(endpoint)`, referenced in `interface.go` and `outside.go`, but the index of those definitions could not be located within the available context — their exact throttling semantics (e.g., per-endpoint rate limit vs. full disablement) are unconfirmed from the indexed code, so it's unclear how effective this gate is against a determined spoofing attacker who can vary source ports or send at a rate under the threshold.

### Impact Explanation
An attacker who can spoof UDP packets appearing to originate from a peer's currently active remote address/port can force a legitimate, healthy tunnel to close. This is a remote, unauthenticated denial-of-service against an established Nebula mesh connection — comparable in impact to the IBC report's DoS via forced channel closure, since both allow a party without full protocol trust (no valid signed certificate / no successful counterparty processing) to unilaterally kill an active, correctly functioning communication channel.

### Likelihood Explanation
Exploitability depends on whether the sender's `RemoteAddr:Port` can be reliably spoofed (trivial on non-return-routable/off-path UDP spoofing scenarios, or straightforward for an on-path or NAT-adjacent attacker) and on the strength of the `ShouldRecvError` rate limiting, which could not be fully verified in this pass. If the throttling is weak (e.g., simple per-source-address rate limiting that an attacker can bypass by varying spoofed source ports, since `RemoteIndex`+addr match is address-based, not port-invariant per the check `hr.IsValid() && hr != addr`), the likelihood is moderate-to-high for attackers capable of IP spoofing on the network path between peers.

### Recommendation
- Require `RecvError` to be authenticated (e.g., only accept it if it carries a valid MAC/AEAD tag bound to the session key, or bind it to the current message counter/nonce window) rather than trusting a raw UDP source-address match, since UDP source addresses are not a reliable authentication mechanism.
- Rather than unconditionally hard-closing the tunnel on a single unauthenticated `RecvError`, consider requiring corroborating evidence (e.g., multiple consistent signals, or falling back to a soft state — attempt re-handshake without discarding the existing session) before tearing down an active tunnel.
- Confirm and, if necessary, strengthen `ShouldRecvError` rate-limiting (in `interface.go`) to bound the number of tunnel teardowns achievable per unit time from an unauthenticated signal, closing any gaps such as source-port variation bypassing per-address limits.

### Proof of Concept
1. Establish a legitimate Nebula tunnel between HostA and HostB (both hold valid certs signed by the network's CA).
2. An attacker (with or without a valid Nebula certificate — the `RecvError` packet requires none) spoofs a UDP packet with source address/port equal to HostB's `CurrentRemote` (as seen by HostA) destined to HostA's UDP listener, of type `header.RecvError` and `RemoteIndex` set to HostA's session index for the HostB tunnel (indices used for `RecvError` are often observable/predictable from prior traffic or index-scan since they are not encrypted, see `outside.go:81-84` and `outside.go:541-575`).
3. HostA's `handleRecvError` matches the spoofed address against `hr` and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, tearing down the active tunnel.
4. Repeating this at will forces continuous re-handshakes between HostA and HostB, denying stable connectivity — analogous to the IBC scenario where an adversarial mismatch (there: gas limits; here: spoofable UDP source matching) forces an authoritative channel-closing action that legitimate traffic cannot avoid.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
