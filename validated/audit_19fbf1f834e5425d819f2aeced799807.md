## Title
Unauthenticated peer-controlled SSRF via unrestricted `data_url` in handshake, causing crafted HTTP requests to attacker-chosen internal hosts - ([File: stackslib/src/net/chat.rs])

### Summary
A remote, unauthenticated (any unprivileged) peer that completes a P2P handshake can set its advertised `data_url` to any HTTP(S) host — including loopback, link-local, or RFC1918 addresses — and the victim Stacks node will subsequently connect to that peer-chosen destination to perform mempool sync, tenure/StackerDB chunk downloads, and other RPC calls, without ever validating that the resolved address isn't a private/local address. This mirrors the reported Umbraco CMS SSRF pattern (attacker-controlled `baseUrl` triggers unauthorized server-side requests to arbitrary hosts).

### Finding Description
When a peer handshakes, its self-reported `data_url` is copied verbatim into the conversation state: [1](#0-0) 

The only checks applied to `data_url` are syntactic (`parse_to_block_url`: must be `http`/`https`, no credentials, no query/fragment) in `UrlString::parse_to_block_url`: [2](#0-1) 

There is no check against `PeerAddress::is_in_private_range` / `is_loopback` for this URL, unlike the P2P neighbor-address list, which is explicitly filtered for private ranges via `filter_sensible_neighbors`: [3](#0-2) 

That filter only applies to `NeighborAddress` entries gossiped via `GetNeighbors`/`NeighborsData`, not to the HTTP `data_url` string used to actually connect to a peer's RPC endpoint. Once stored, `data_url` is resolved via DNS/IP parsing and dialed directly for numerous outbound flows that are in-scope of this analysis (non-epoch2x):

- Mempool sync: `mempool_sync_begin_resolve_data_url` resolves the host from `data_url` with no private-range check, then `mempool_sync_send_query` connects and sends a signed HTTP POST to it: [4](#0-3) [5](#0-4) 

- Nakamoto tenure downloads and generic neighbor RPC use `NeighborRPC::get_peer_host`/`send_request`, both keyed off `convo.data_url` with no host-range validation: [6](#0-5) [7](#0-6) 

- The actual dial happens in `PeerNetwork::connect_or_send_http_request`, which just opens a TCP socket to the resolved `SocketAddr` and sends the pre-built `StacksHttpRequest`: [8](#0-7) 

- `PeerHost::try_from_url` (used to build the outgoing request's `Host` header/`PeerHost`) similarly performs no range check, and `PeerNetwork::try_get_url_ip` even special-cases `"localhost"` into `127.0.0.1`: [9](#0-8) [10](#0-9) 

The only place a private data URL is *corrected* rather than rejected is in `handle_handshake_accept`, and only as a convenience fallback when the neighbor's `addrbytes` were private — it does not restrict `data_url` values in general and doesn't run on inbound handshakes where `cur_neighbor` is itself untrusted/first-contact: [11](#0-10) 

This breaks the implicit equality "a peer's advertised RPC endpoint is itself a legitimate external Stacks node" — an attacker can set `data_url` to point at any local service (e.g., an internal admin HTTP endpoint, cloud metadata service, or a colocated but non-Stacks daemon on the operator's LAN) and have the victim node act as an SSRF proxy, issuing HTTP requests (with attacker-influenced timing and page/version parameters) to that destination.

### Impact Explanation
Any remote, unauthenticated peer that can complete (or attempt) a handshake with a victim node can cause that node to originate crafted HTTP requests toward attacker-chosen hosts, including hosts on the node operator's internal network or loopback interface, that are otherwise unreachable from the internet. This is a High-severity SSRF-class bug: it lets an external attacker probe/interact with internal services from the node's network vantage point. It does not directly corrupt chain state, but is a "bounded/targeted network-request forgery" analogous to the Umbraco `baseUrl` SSRF class referenced in the report.

### Likelihood Explanation
Likelihood is high for triggering the request: any peer, inbound or outbound, can set an arbitrary `data_url` during handshake since only URL well-formedness is checked, and the resulting flow (mempool sync, tenure download, StackerDB inventory/chunk requests) run automatically as part of normal node operation without additional authorization.

### Recommendation
Before using a peer's `data_url` to establish outbound HTTP connections, validate the resolved `SocketAddr` (post-DNS-resolution) against private/loopback/link-local/multicast ranges (reusing `PeerAddress::is_in_private_range`/`is_loopback`) and reject or ignore any peer whose reported endpoint resolves to such addresses, unless the node is explicitly configured to allow private peers (mirroring the existing `filter_sensible_neighbors` policy for gossip‑derived neighbor addresses). This check should be applied uniformly wherever `data_url` is resolved and dialed (mempool sync, `NeighborRPC::send_request`, StackerDB chunk fetch, tenure/attachment downloaders).

### Proof of Concept
1. Stand up a malicious peer that completes the Stacks P2P handshake with a victim node, but sets `HandshakeData.data_url` (via `HandshakeData::from_local_peer`-equivalent handcrafted message) to `http://127.0.0.1:<victim-internal-port>/` or an internal LAN/service IP.
2. Wait for the victim to select this peer for mempool sync (`mempool_sync_send_query`) or StackerDB/tenure chunk retrieval.
3. Observe (e.g., via timing side channel, or by running a listener at the target address) that the victim node establishes a TCP connection and sends an HTTP request to the attacker-chosen internal address rather than to the peer's real network location.

    /// Determine that the UrlString parses to something that can be used to fetch blocks via HTTP(S).
    /// A block URL must be an HTTP(S) URL without a query or fragment, and without a login.
    pub fn parse_to_block_url(&self) -> Result<url::Url, codec_error> {
        // even though this code uses from_utf8_unchecked() internally, we've already verified that
        // the bytes in this string are all ASCII.
        let url = url::Url::parse(&self.to_string())
            .map_err(|e| codec_error::DeserializeError(format!("Invalid URL: {:?}", &e)))?;

        if url.scheme() != "http" && url.scheme() != "https" {
            return Err(codec_error::DeserializeError(format!(
                "Invalid URL: invalid scheme '{}'",
                url.scheme()
            )));
        }

        if !url.username().is_empty() || url.password().is_some() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: must not contain a username/password".to_string(),
            ));
        }

        if url.host_str().is_none() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: no host string".to_string(),
            ));
        }

        if url.query().is_some() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: query strings not supported for block URLs".to_string(),
            ));
        }

        if url.fragment().is_some() {
            return Err(codec_error::DeserializeError(
                "Invalid URL: fragments are not supported for block URLs".to_string(),
            ));
        }

        Ok(url)
    }
