### Title
Unsigned integer underflow in reftable block parsing defeats bounds check, leading to out-of-bounds slice panic (DoS) - ([File: internal/git/reftable/reftable.go])

### Summary
Gitaly's Go-native reftable reader computes a block's restart-table offset with unchecked unsigned subtraction. A crafted/degenerate reftable block (reachable via ordinary Git ref operations that produce reftable-backend repositories) can make this subtraction wrap around, defeating the loop bound that is supposed to keep all subsequent slice accesses inside the block. This is the same bug class as the Vyper `slice()` advisory: an arithmetic expression that feeds directly into a bounds check is not validated for overflow/underflow before being trusted.

### Finding Description
`parseRefBlock` computes the start of a block's restart table as: [1](#0-0) 

```go
func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)
	...
	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)
	return t.getRefsFromBlock(src, b)
}
```

`currentBS` (current block size) and `b.RestartCount` are both read directly from the input bytes with `binary.Read`/`extractBlockLen`, without any relationship being validated between them before this subtraction. All the operands are of type `uint` (Go's platform-width unsigned integer), so if `2 + 3*RestartCount` exceeds `blockStart + currentBS`, the subtraction wraps around to a huge positive value instead of erroring or producing a negative number.

`getRefsFromBlock` then uses that potentially-wrapped value as the sole bound for its parsing loop and for all subsequent slice indexing: [2](#0-1) 

```go
idx := b.BlockStart + 4
for idx < b.RestartStart {
    idx, prefixLength, err = t.getVarInt(src, idx, b.RestartStart)
    ...
    idx, suffixLength, err = t.getVarInt(src, idx, b.RestartStart)
    ...
    refname := prefix[:prefixLength] + string(src[idx:idx+suffixLength])
    idx = idx + suffixLength
    ...
```

Because `b.RestartStart` has wrapped to an enormous value, the loop condition `idx < b.RestartStart` remains true far beyond the real block/buffer boundary, and `getVarInt`'s own bound checks (`start > blockEnd`) are likewise checked against the same wrapped `RestartStart`/`FullBlockSize` values, so they do not catch the corruption. The loop keeps calling `src[idx:idx+suffixLength]` with attacker-influenced `suffixLength`/`prefixLength` values, driving `idx` past `len(src)`.

This mirrors the reported Vyper defect precisely: the code has "bounds checks" (`idx < b.RestartStart`, `start > blockEnd`), but the value being checked against was derived from an unchecked arithmetic operation (subtraction/underflow here, addition/overflow in Vyper) that can be manipulated to defeat the very check meant to constrain it.

### Impact Explanation
Go slices panic (index out of range) rather than silently reading adjacent heap memory, so the practical, provable impact is a crash of the goroutine handling the request — a denial-of-service against whatever RPC path triggers reftable parsing for a repository using this Go-native reftable reader. Unlike Go's runtime panic recovery for gRPC handlers (which may convert this into an Internal error per-request), repeated malformed reftables stored for a repository would make every subsequent read of that repository's refs fail, effectively bricking ref-reading operations for that repository (persistent denial of service) rather than a single transient error.

### Likelihood Explanation
Reaching this code requires a reftable file whose header-encoded block length and restart count are inconsistent (`2 + 3*RestartCount > blockStart + currentBS`). Reftable is Gitaly's alternate ref-storage backend; its files are normally produced by Git/Gitaly's own writer, but the values consumed here (`currentBS`, `RestartCount`) come straight from the file bytes with no cross-validation against the actual buffer length before being used to derive `RestartStart`. Any path that allows Gitaly to parse a reftable it did not fully trust/verify (e.g., an imported repository, a replicated/backed-up-and-restored repository, or a corrupted/truncated table) exercises this code without any authentication or privilege being required beyond normal repository operations. I was not able to fully trace every RPC call site that invokes this Go-native reftable parser (versus shelling out to `git`) within the available search budget, so the exact reachability from a single "ordinary user push/fetch" request is not fully confirmed — this should be verified further before treating it as a confirmed remotely-triggerable bug.

### Recommendation
Before performing `b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)`, validate that `2 + 3*RestartCount <= currentBS` (and that `currentBS <= blockEnd-blockStart`) and reject the block with an error otherwise. Additionally, validate `RestartStart` against `len(src)` (not just `blockEnd`/`FullBlockSize`, which are themselves derived from the same untrusted header) before entering the parsing loop in `getRefsFromBlock`, and add explicit bounds checks (`idx+length <= len(src)`) before every `src[idx:idx+...]` slice operation in that function and in `getVarInt`.

### Proof of Concept
Construct a minimal reftable ref block where the trailer declares a `RestartCount` large enough that `2 + 3*RestartCount` exceeds `blockStart + currentBS` (e.g., set the 2-byte restart count field to a large value like `0xFFFF` while keeping the encoded block length small). Feed this block through `Table.GetReferences()` → `parseRefBlock` → `getRefsFromBlock`. The unsigned subtraction for `RestartStart` wraps to a very large `uint`, the `for idx < b.RestartStart` loop no longer bounds `idx` to the block, and the subsequent `src[idx:idx+suffixLength]` slicing panics with "slice bounds out of range" once `idx` exceeds `len(src)`, crashing the handling goroutine.

// parseRefBlock parses a block and if it is a ref block, provides
// all the reference updates.
func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)

	fullBlockSize := t.blockSize
	if fullBlockSize == 0 {
		fullBlockSize = currentBS
	} else if currentBS < fullBlockSize && currentBS < (blockEnd-blockStart) && src[blockStart+currentBS] != 0 {
		fullBlockSize = currentBS
	}

	b := &block{
		BlockStart:    blockStart + headerOffset,
		FullBlockSize: fullBlockSize,
	}

	if err := binary.Read(bytes.NewBuffer(src[blockStart+currentBS-2:]), binary.BigEndian, &b.RestartCount); err != nil {
		return nil, fmt.Errorf("reading restart count: %w", err)
	}

	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)

	return t.getRefsFromBlock(src, b)
