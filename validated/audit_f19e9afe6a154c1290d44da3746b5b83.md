Confirmed: both `transfer_to_new_account` and `transfer_to_new_account_pda` call the shared `initialize_migrated_account` helper, which unconditionally copies `emissions_destination_account` from the old account to the new one, with no reset and no re-validation against the new authority.### Title
Stale `emissions_destination_account` persists across `transfer_to_new_account`(_pda), letting a former owner redirect a sold/transferred account's future emissions to themselves - ([File: programs/marginfi/src/instructions/marginfi_account/transfer_account.rs])

### Summary
`MarginfiAccount.emissions_destination_account` is an unrestricted, authority-settable field [1](#0-0) that off-chain systems use as the payout target for weekly emissions airdrops [2](#0-1) . When an account authority calls `transfer_to_new_account`/`transfer_to_new_account_pda` to hand the account (and all its positions) to a new authority, the shared helper `initialize_migrated_account` copies this field verbatim from the old account into the newly created account instead of resetting it: [3](#0-2) . This is the exact bug class from the report: an address-bound "permission"/redirection setting that was configured by the previous owner stays in effect after ownership changes hands, and the new owner has no visibility into it or reason to check it.

### Finding Description
`emissions_destination_account` can be set to "any valid public key" with no ownership/ATA-derivation check [4](#0-3) , and it is documented purely as an address off-chain distributors pay emissions to [5](#0-4) . A malicious or simply forgetful account owner can:
1. Call `marginfi_account_update_emissions_destination_account` to point `emissions_destination_account` at a wallet they control.
2. Sell/transfer the account (deposits, borrows, and all future yield/points position) to a new owner via `transfer_to_new_account` or `transfer_to_new_account_pda`.
3. The new `MarginfiAccount` is initialized with the old account's `emissions_destination_account` unchanged [3](#0-2) .
4. All future emissions/incentive airdrops earned by the new owner's deposits/borrows continue to be routed to the old owner's chosen destination, indefinitely, until the new owner discovers this and manually calls `marginfi_account_update_emissions_destination_account` to reset it.

The docs acknowledge a *one-week* transitional overlap as expected ("emissions will still airdrop to the old account for that week") [6](#0-5) , but that description assumes the default behavior where emissions go to `account.authority`. It does not account for the case where the field was explicitly set to an address the old owner controls (independent of `authority`) — in that case there is no natural expiration and the redirection persists across all future migrations of the account, since `initialize_migrated_account` is unconditionally invoked on every transfer.

### Impact Explanation
This does not endanger deposited principal or induce insolvency/bad debt directly (the analogous ERC20-approval-theft severity is not fully matched, since only the emissions/incentive stream is diverted, not the underlying collateral). However, it is a genuine, concrete "unauthorized transfer of value": tokens intended for the current position-holder are instead delivered to a former owner's chosen address, without the new owner's knowledge or consent, indefinitely. This is directly analogous to the "stale ERC-20 approvals persist after proxy ownership transfer" bug class - a per-address setting configured by the old owner outlives the ownership change and is used to siphon value away from the rightful new owner.

### Likelihood Explanation
Likelihood is moderate: it requires deliberate or incidental use of `emissions_destination_account` combined with an account transfer/sale, which is a documented, supported flow (`transfer_to_new_account`/`transfer_to_new_account_pda` are unprivileged, user-callable instructions used for account migration and, per the CLI/test code, for third-party-facilitated account transfers). A malicious seller of a marginfi account (e.g. in an over-the-counter account-sale market, or a PDA-based integrator account handed off between users) has direct incentive and capability to exploit this deliberately.

### Recommendation
In `initialize_migrated_account` (`programs/marginfi/src/instructions/marginfi_account/transfer_account.rs`), reset `new_account.emissions_destination_account` to `Pubkey::default()` (or to `new_authority`) instead of copying the old account's value, forcing the new owner to explicitly opt back in via `marginfi_account_update_emissions_destination_account` if they want a custom destination.

### Proof of Concept
1. User A creates a marginfi account and deposits collateral (earns emissions campaign points).
2. User A calls `marginfi_account_update_emissions_destination_account` with `destination_account = walletControlledByA` [7](#0-6) .
3. User A transfers the account to User B via `transfer_to_new_account` (e.g. as part of an account sale) [8](#0-7) .
4. The new account created for User B has `emissions_destination_account == walletControlledByA`, copied unchanged from step 2 [9](#0-8) .
5. Every subsequent week, off-chain emissions/incentive distributions attributable to User B's now-owned deposits/borrows are paid out to `walletControlledByA`, until User B notices and resets the field.

Note: I was unable to fully verify how the off-chain emissions distributor consumes this field (it lives outside this repo's on-chain program), so the precise payout mechanics and any off-chain safeguards are based on the in-repo documentation (`guides/USER/EMISSIONS.md`) rather than direct code inspection of the distributor.

/// (account authority) Set the wallet whose canonical ATA will receive
/// off-chain emissions distributions.
pub fn marginfi_account_update_emissions_destination_account(
    ctx: Context<MarginfiAccountUpdateEmissionsDestinationAccount>,
) -> MarginfiResult {
    let mut marginfi_account = ctx.accounts.marginfi_account.load_mut()?;

    check!(
        !marginfi_account.get_flag(ACCOUNT_FROZEN),
        MarginfiError::AccountFrozen
    );

    marginfi_account.emissions_destination_account = ctx.accounts.destination_account.key();
    Ok(())
}

fn initialize_migrated_account(
    new_account: &mut MarginfiAccount,
    old_account: &MarginfiAccount,
    new_authority: Pubkey,
    current_timestamp: u64,
    old_account_key: Pubkey,
) {
    new_account.initialize(old_account.group, new_authority, current_timestamp);
    new_account.lending_account = old_account.lending_account;
    new_account.emissions_destination_account = old_account.emissions_destination_account;
    new_account.account_flags = old_account.account_flags;
    new_account.migrated_from = old_account_key;
    new_account.indexer_flags = old_account.indexer_flags;
    new_account.sync_indexer_flags();
}

pub fn transfer_to_new_account(ctx: Context<TransferToNewAccount>) -> MarginfiResult {
    // Validate the global fee wallet and claim a nominal fee
    let group = ctx.accounts.group.load()?;
    check_eq!(
        ctx.accounts.global_fee_wallet.key(),
        group.fee_state_cache.global_fee_wallet,
        MarginfiError::InvalidFeeAta
    );
    anchor_lang::system_program::transfer(ctx.accounts.transfer_fee(), ACCOUNT_TRANSFER_FEE)?;

    let mut old_account = ctx.accounts.old_marginfi_account.load_mut()?;

    check!(
        !old_account.get_flag(ACCOUNT_IN_FLASHLOAN),
        MarginfiError::AccountInFlashloan
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_RECEIVERSHIP),
        MarginfiError::ForbiddenIx
    );

    check!(
        !old_account.get_flag(ACCOUNT_IN_ORDER_EXECUTION),
        MarginfiError::ForbiddenIx
    );

    check!(
        old_account.active_orders == 0,
        MarginfiError::IllegalAction,
        "Close all active orders before transfer"
    );

    // Prevent multiple migrations from the same account
    check_eq!(
        old_account.migrated_to,
        Pubkey::default(),
        MarginfiError::AccountAlreadyMigrated
    );

    let mut new_account = ctx.accounts.new_marginfi_account.load_init()?;
    let current_timestamp = Clock::get()?.unix_timestamp as u64;
    initialize_migrated_account(
        &mut new_account,
        &old_account,
        ctx.accounts.new_authority.key(),
        current_timestamp,
        ctx.accounts.old_marginfi_account.key(),
    );

    finalize_migrated_old_account(
        &mut old_account,
        ctx.accounts.new_marginfi_account.key(),
        current_timestamp,
    );

    emit!(MarginfiAccountTransferToNewAccount {
        header: AccountEventHeader {
            signer: Some(ctx.accounts.authority.key()),
            marginfi_account: ctx.accounts.new_marginfi_account.key(),
            marginfi_account_authority: ctx.accounts.new_authority.key(),
            marginfi_group: ctx.accounts.group.key(),
        },
        old_account: ctx.accounts.old_marginfi_account.key(),
        old_account_authority: ctx.accounts.authority.key(),
        new_account_authority: ctx.accounts.new_authority.key(),
    });

    Ok(())
}
