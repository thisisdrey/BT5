### Title
Unbounded per-account market order list iteration causes DoS in `getMarketOrderByAccount` - (File: framework/src/main/java/org/tron/core/Wallet.java)

### Summary
`Wallet.getMarketOrderByAccount` iterates every entry in `MarketAccountOrderCapsule.getOrdersList()` and, for each order id, performs a `MarketOrderStore.get()` lookup and builds a protobuf entry, with **no upper bound / limit** on the number of orders processed. This is directly reachable by any anonymous client via the `GetMarketOrderByAccount` gRPC/HTTP API, analogous to GitLab's CVE-2022-0477 where an unbounded/unchecked bulk operation on stored records caused a Denial of Service.

### Finding Description
`getMarketOrderByAccount` fetches the caller-supplied account's `MarketAccountOrderCapsule` and iterates `orderIdList.forEach(...)` unconditionally, doing a DB lookup for every order id in the list: [1](#0-0) 

This differs from the sibling market query methods `getMarketPriceByPair`, `getMarketOrderListByPair`, and `getMarketPairList`, all of which explicitly cap iteration using `MARKET_COUNT_LIMIT_MAX`: [2](#0-1) 

The endpoint is exposed with no additional pagination/limit parameter through gRPC (`GetMarketOrderByAccount`) and the corresponding HTTP servlet, both callable by unauthenticated/unprivileged API clients: [3](#0-2) [4](#0-3) 

While `MarketSellAssetActuator` caps *active* orders per account at `MAX_ACTIVE_ORDER_NUM = 100`: [5](#0-4) 
the account order list distinguishes `getCount()` (active) from `getTotalCount()` (historical), as observed in test assertions where count and totalCount diverge after cancellation: [6](#0-5) 
I was unable to fully confirm from the available index whether cancelled/filled orders are actually removed from `MarketAccountOrderCapsule`'s backing `getOrdersList()` (which `getMarketOrderByAccount` iterates) or merely marked inactive while remaining in the list — `MarketUtils.updateOrderState` and the exact `MarketAccountOrderCapsule` mutation call sites in the actuator execute path were not retrievable in full from the index within the available iterations. This uncertainty affects whether the list an attacker can grow is bounded by the 100-active-order cap or can grow unbounded via repeated create+cancel/match cycles over time (since `getTotalCount()` keeps increasing across cancels in the test evidence).

### Impact Explanation
If the per-account orders list returned by `getMarketOrderByAccount` is not strictly bounded by the 100-active-order limit (i.e., historical/cancelled/matched orders remain in the list, as suggested by divergent `count`/`totalCount` semantics), a single account can accumulate an arbitrarily large order history via many buy/sell/cancel cycles over time, and any anonymous API caller can then trigger a full-list DB-lookup traversal via `GetMarketOrderByAccount` on that address. Repeated invocation against such accounts consumes disproportionate node CPU/DB read time relative to request cost, potentially degrading or denying the query-serving node's service to other legitimate API clients — the same "unbounded bulk operation -> node resource exhaustion / DoS" class of bug as CVE-2022-0477.

### Likelihood Explanation
Likelihood is moderate: exploitation requires an account with a very large historical order list, which the attacker would need to build themselves (many market transactions consume fees/energy, raising cost), and then repeatedly query it via a public read-only API. No signature/permission checks gate this query endpoint. The severity of impact and the ease of triggering it depend on confirming whether the iterated list is actually unbounded in practice, which I could not fully verify from the available files.

### Recommendation
Apply the same `MARKET_COUNT_LIMIT_MAX`-style bound (or paginate) to `getMarketOrderByAccount`'s traversal of `orderIdList`, consistent with `getMarketPriceByPair` and `getMarketOrderListByPair`, and confirm/enforce that historical (non-active) orders are pruned or capped in `MarketAccountOrderCapsule` so the per-account list cannot grow unbounded over time.

### Proof of Concept
1. From an account, repeatedly submit `MarketSellAssetContract` transactions followed by `MarketCancelOrderContract` (or let orders fully match) to accumulate a large number of entries in that account's `MarketAccountOrderCapsule` order id list over time (bounded only by TRX/fee budget, not by any list-size validation on the historical list).
2. As any unauthenticated client, repeatedly call the `GetMarketOrderByAccount` gRPC/HTTP endpoint (`framework/src/main/java/org/tron/core/services/http/GetMarketOrderByAccountServlet.java`) against that address.
3. Each call causes `Wallet.getMarketOrderByAccount` to perform one `MarketOrderStore.get()` per historical order id with no cap, unlike the bounded sibling market-query methods, consuming excess node resources per request and degrading API availability for other callers.

  public MarketOrderList getMarketOrderByAccount(ByteString accountAddress) {

    if (accountAddress == null || accountAddress.isEmpty()) {
      return null;
    }

    MarketAccountOrderCapsule marketAccountOrderCapsule;
    try {
      marketAccountOrderCapsule = dbManager.getChainBaseManager()
          .getMarketAccountStore().get(accountAddress.toByteArray());
    } catch (ItemNotFoundException e) {
      return null;
    }

    MarketOrderStore marketOrderStore = dbManager.getChainBaseManager().getMarketOrderStore();

    MarketOrderList.Builder marketOrderListBuilder = MarketOrderList.newBuilder();
    List<ByteString> orderIdList = marketAccountOrderCapsule.getOrdersList();

    orderIdList.forEach(
        orderId -> {
          try {
            MarketOrderCapsule orderCapsule = marketOrderStore.get(orderId.toByteArray());
            // set prev and next, hide these messages in the print
            orderCapsule.setPrev(new byte[0]);
            orderCapsule.setNext(new byte[0]);

            marketOrderListBuilder
                .addOrders(orderCapsule.getInstance());
          } catch (ItemNotFoundException e) {
            logger.warn("orderId = {} not found", orderId);
            throw new IllegalStateException("order not found in store");
          }
        }
    );

    return marketOrderListBuilder.build();
  }

  public MarketPriceList getMarketPriceByPair(byte[] sellTokenId, byte[] buyTokenId)
      throws BadItemException {
    MarketUtils.checkPairValid(sellTokenId, buyTokenId);

    MarketPairToPriceStore marketPairToPriceStore = dbManager.getChainBaseManager()
        .getMarketPairToPriceStore();
    MarketPairPriceToOrderStore marketPairPriceToOrderStore = dbManager.getChainBaseManager()
        .getMarketPairPriceToOrderStore();

    MarketPriceList.Builder marketPriceListBuilder = MarketPriceList.newBuilder()
        .setSellTokenId(ByteString.copyFrom(sellTokenId))
        .setBuyTokenId(ByteString.copyFrom(buyTokenId));

    long count = marketPairToPriceStore.getPriceNum(sellTokenId, buyTokenId);
    if (count == 0) {
      return marketPriceListBuilder.build();
    }

    long limit = count < MARKET_COUNT_LIMIT_MAX ? count : MARKET_COUNT_LIMIT_MAX;

    List<byte[]> priceKeysList = marketPairPriceToOrderStore
        .getPriceKeysList(sellTokenId, buyTokenId, limit);

    priceKeysList.forEach(
        priceKey -> {
          MarketPrice marketPrice = MarketUtils.decodeKeyToMarketPrice(priceKey);
          marketPriceListBuilder.addPrices(marketPrice);
        }
    );

    return marketPriceListBuilder.build();
  }

  public MarketOrderPairList getMarketPairList() {
    MarketOrderPairList.Builder builder = MarketOrderPairList.newBuilder();
    MarketPairToPriceStore marketPairToPriceStore = dbManager.getChainBaseManager()
        .getMarketPairToPriceStore();

    Iterator<Entry<byte[], BytesCapsule>> iterator = marketPairToPriceStore
        .iterator();
    long count = 0;
    while (iterator.hasNext()) {
      Entry<byte[], BytesCapsule> next = iterator.next();

      byte[] pairKey = next.getKey();
      builder.addOrderPair(MarketUtils.decodeKeyToMarketPairHuman(pairKey));
      count++;
      if (count > MARKET_COUNT_LIMIT_MAX) {
        break;
      }
    }

    return builder.build();
  }

  public MarketOrderList getMarketOrderListByPair(byte[] sellTokenId, byte[] buyTokenId)
      throws ItemNotFoundException, BadItemException {
    MarketUtils.checkPairValid(sellTokenId, buyTokenId);

    MarketOrderList.Builder builder = MarketOrderList.newBuilder();

    MarketPairToPriceStore marketPairToPriceStore = dbManager.getChainBaseManager()
        .getMarketPairToPriceStore();
    MarketPairPriceToOrderStore marketPairPriceToOrderStore = dbManager.getChainBaseManager()
        .getMarketPairPriceToOrderStore();
    MarketPairPriceToOrderStore pairPriceToOrderStore = dbManager.getChainBaseManager()
        .getMarketPairPriceToOrderStore();
    MarketOrderStore orderStore = dbManager.getChainBaseManager().getMarketOrderStore();

    long countForPrice = marketPairToPriceStore.getPriceNum(sellTokenId, buyTokenId);
    if (countForPrice == 0) {
      return builder.build();
    }
    long limitForPrice =
        countForPrice < MARKET_COUNT_LIMIT_MAX ? countForPrice : MARKET_COUNT_LIMIT_MAX;

    List<byte[]> priceKeysList = marketPairPriceToOrderStore
        .getPriceKeysList(sellTokenId, buyTokenId, limitForPrice);

    long countForOrder = 0;
    for (byte[] pairPriceKey : priceKeysList) {
      MarketOrderIdListCapsule orderIdListCapsule = pairPriceToOrderStore
          .getUnchecked(pairPriceKey);
      if (MARKET_COUNT_LIMIT_MAX - countForOrder <= 0) {
        break;
      }
      if (orderIdListCapsule != null) {
        List<MarketOrderCapsule> orderList = orderIdListCapsule
            .getAllOrder(orderStore, MARKET_COUNT_LIMIT_MAX - countForOrder);

        orderList.forEach(orderCapsule -> {
          // set prev and next, hide these messages in the print
          orderCapsule.setPrev(new byte[0]);
          orderCapsule.setNext(new byte[0]);

          builder.addOrders(orderCapsule.getInstance());
        });
        countForOrder += orderList.size();
      }
    }

    return builder.build();
  }
