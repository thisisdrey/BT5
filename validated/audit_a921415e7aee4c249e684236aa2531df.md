### Title
Unauthenticated HTTP event listener in `SignerEventReceiver` allows any remote party to inject forged events or shut down the signer - (File: libsigner/src/events.rs)

### Summary
The `stacks-signer` process listens on an HTTP socket (bound via `SignerEventReceiver::bind`, typically `0.0.0.0:30000` per the sample configs) to receive events pushed by the trusted `stacks-node`. `SignerEventReceiver::next_event` dispatches incoming requests purely by URL path (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown`, `/status`) with no authentication or origin check of any kind. Anyone who can reach that TCP port can post directly to these endpoints as if they were the node.

### Finding Description
`SignerEventReceiver::next_event` reads an HTTP request from the bound server and routes it to a handler solely based on `request.url()`: [1](#0-0) 

There is no check of an `Authorization` header, shared secret, or peer address anywhere in this file — a grep across `libsigner/**` for `auth_token`, `auth_password`, or `Authorization` returns no matches. The signer-node pairing documentation confirms that `auth_token`/`auth_password` is only used for the *node's* block-proposal RPC endpoint (the direction node→signer verification, i.e. the signer authenticating requests it sends to the node), not for authenticating inbound POSTs to the signer's own event listener: [2](#0-1) 

Notably, the `/shutdown` path directly flips the receiver's stop flag and terminates the main loop with no auth gate at all: [3](#0-2) 

This is the direct analog of the reported bug class: an entry point that is supposed to be reachable only by a specific trusted caller (the `EntryPoint`/node) instead accepts calls from anyone, because the gating check (auth/ownership verification) is missing entirely rather than merely misapplied.

### Impact Explanation
- **Unauthenticated remote DoS (Critical):** Any host that can reach the configured `endpoint` (bound `0.0.0.0` in the shipped sample configs) can send a single unauthenticated `POST /shutdown` HTTP request and terminate the signer's event-receiver main loop, halting the signer's participation in block signing.
- **Forged event injection:** The same lack of gating lets an unauthenticated sender POST arbitrary bodies to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, or `/new_block`, which are parsed and forwarded into the signer's runloop channel as if they originated from the node (`forward_event`): [4](#0-3) 
  Whether this data is further re-validated downstream (e.g., StackerDB chunk signatures, or the node-origin of a `BlockValidateResponse`) is internal signer decision logic, which is out of scope for this analysis, but the transport-layer gap itself is a clear break of the intended caller restriction.

### Likelihood Explanation
High. This requires only network reachability to the signer's listening port and a single crafted HTTP request; no keys, credentials, or privileged roles are needed. The sample configs bind the listener on `0.0.0.0`, and nothing in `libsigner/src/events.rs` restricts the source of connections.

### Recommendation
Require an authenticated channel for the signer's event listener, symmetric to how the node authenticates the signer's block-proposal RPC calls (e.g., checking a shared `auth_token`/`Authorization` header on every request in `SignerEventReceiver::next_event` before dispatching to `process_event`, and specifically before honoring `/shutdown`), and/or restrict the bind address to loopback/firewalled interfaces by default.

### Proof of Concept
Given a running signer listening on `127.0.0.1:30000` (or `0.0.0.0:30000` as in the sample config), an unauthenticated client can terminate it with a raw HTTP request such as:
```
POST /shutdown HTTP/1.1
Host: 127.0.0.1:30000
Content-Length: 0

```
This matches exactly the code path exercised (without any auth header) in `SignerEventReceiver::next_event`: [5](#0-4) 
No prior handshake, key, or `auth_password` is required, since none is checked in this file.

Note: I was not able to fully verify (within the search scope) whether higher layers of `stacks-signer` re-validate `BlockValidateResponse`/`StackerDBChunksEvent` payloads by origin after receipt, since that logic lives in the signer decision code explicitly marked out of scope by the rules; my finding is limited to the transport-level auth gap itself, which is unambiguous.

        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)

                process_event::<T, BurnBlockEvent>(request)

    /// Forward an event
    /// Return true on success; false on error.
    /// Returning false terminates the event receiver.
    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }

### 2. Configure the Signer

Use [`mainnet-signer-conf.toml`](../sample/conf/signer/mainnet-signer-conf.toml) as a starting point.
Key settings:

```toml
stacks_private_key = "<YOUR_SIGNER_PRIVATE_KEY_HEX>"
node_host = "127.0.0.1:20443"
endpoint = "0.0.0.0:30000"
network = "mainnet"
auth_password = "your-secret-token"
db_path = "/var/lib/stacks-signer/signerdb.sqlite"
```

### 3. Verify Coordination

These settings **must** match between the node and signer configs:

| Signer Config   | Node Config                       | Must Match                    |
| --------------- | --------------------------------- | ----------------------------- |
| `auth_password` | `[connection_options] auth_token` | Exact string match            |
| `endpoint`      | `[[events_observer]] endpoint`    | Same host:port                |
| `node_host`     | `[node] rpc_bind`                 | Signer connects to node's RPC |
```
