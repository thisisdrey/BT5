### Title
Unstaked users can classify arbitrary junk transactions as "simple votes" to bypass the scheduler's priority floor - ([File: perf/src/sigverify.rs])

### Summary
The "public-parameter self-selection" bug class from the report (a caller freely choosing a more favorable code path — `referralMint` over `paidMint` — because eligibility is derived only from public, unauthenticated data) has a direct analog in how Agave classifies transactions as "simple vote" transactions on the TPU ingest path. Classification is based solely on structural/public properties of the transaction (single legacy instruction addressed to the well-known vote program ID), not on any proof that the sender is an actual authorized validator voter. Any unstaked, unprivileged client can therefore mint itself a transaction that is treated as a vote and receive the preferential/exempted handling reserved for consensus votes.

### Finding Description
`is_simple_vote_transaction_view` in [1](#0-0)  classifies a packet as a "simple vote" purely from public, self-declared structure: ≤2 signatures, legacy message, exactly one instruction, and that instruction's `program_id` equal to `solana_sdk_ids::vote::id()`. It never checks that the instruction data deserializes into a genuine `VoteInstruction`, nor that any account is an authorized voter — that deeper validation only happens later in `LatestValidatorVote::new_from_view` [2](#0-1)  and `consume_scan_should_process_packet` [3](#0-2) , both of which run *after* the packet has already been given vote-lane treatment by sigverify.

At sigverify time, once `is_simple_vote_tx` is true, `verify_packet` sets `PacketFlags::SIMPLE_VOTE_TX` on the packet [4](#0-3) , provided the packet's own self-consistent Ed25519 signature verifies — which any attacker can trivially satisfy by signing the "vote-shaped" transaction with their own throwaway keypair; no real voting authority is required.

This flag routes the packet into the dedicated `tpu_vote` pipeline (`tpu_vote_sender` / `tpu_vote_deduper` in `SigVerifyStage::new`, [5](#0-4) ), which is configured with `priority_floor: None` ("votes are not dropped for priority-floor", [6](#0-5) ). By contrast, ordinary (non-vote) traffic is subject to `apply_priority_floor_to_batch`, which drops at-or-below-floor packets ahead of verification when the scheduler is saturated [7](#0-6)  and [8](#0-7) .

Because the vote-classification test is satisfiable with entirely public information (the vote program's well-known ID) and a self-issued signature, any unstaked client can manufacture "vote-shaped" junk packets that:
1. Skip the priority-floor congestion-shedding mechanism applied to normal transactions.
2. Consume the separate `tpu_vote` deduper/queue/worker capacity reserved for genuine consensus votes.
3. Cost the attacker nothing in priority fees, since the vote lane's protection model assumes only real, stake-backed votes arrive there.

This mirrors the report's bug class precisely: two public entry points ("paid"/regular vs. "referral"/vote-classified) with different, more favorable treatment for the latter, and the discriminator (program ID equality) is public information that requires no proof of authorization to satisfy.

### Impact Explanation
An unprivileged, unstaked attacker can flood the vote-only ingestion lane with packets that are structurally indistinguishable from votes at the sigverify layer but are semantically garbage. Because this lane is explicitly exempted from the priority-floor drop that protects the scheduler under load, and it uses its own dedicated deduper/queue, this is a QoS-evasion primitive: it lets low-cost, unfee'd traffic contend for resources (queue slots, dedup table entries, sigverify worker time, banking-stage vote-thread cycles) that the system's load-shedding design assumes are reserved for legitimate, indirectly stake-gated (via authorized-voter signature) consensus messages. Under contention this can delay real votes and gives an attacker a way to consume disproportionate validator resources for near-zero cost, undermining the priority-fee/QoS model that other transaction classes must respect.

### Likelihood Explanation
High, from a reachability standpoint: constructing a legacy, single-instruction transaction addressed to the vote program's public ID and self-signing it requires no special access, no stake, and no cluster secrets — every value it needs is public. The only requirement is knowing the fixed vote program address, which is a chain constant.

### Recommendation
Do not treat "single instruction to vote program ID" as sufficient for preferential QoS/priority-floor exemption. Either:
- Require that the classification used to grant priority-floor exemption also verify that the instruction deserializes to a genuine `VoteInstruction::is_single_vote_state_update()` variant (as already done downstream in `LatestValidatorVote::new_from_view` and `vote_parser::is_valid_vote_only_transaction`) before exempting the packet from the priority floor, or
- Apply the priority floor (or an equivalent lightweight cost/rate check) to the vote lane as well, only lifting it once the instruction has been confirmed to be a real, correctly signed authorized-voter vote instruction.

### Proof of Concept
Conceptually (mirrors the existing test `test_is_simple_vote_transaction_paths`/`test_is_simple_vote_transaction` in [9](#0-8) ):
1. Generate a throwaway keypair `attacker`.
2. Build a legacy `Transaction` with a single instruction whose `program_id` is `solana_sdk_ids::vote::id()` and whose accounts/data are arbitrary garbage bytes (not a real `VoteInstruction`).
3. Sign it with `attacker` (self-consistent signature, passes Ed25519 verification).
4. Submit it to the TPU vote ingestion path.
5. Observe `is_simple_vote_transaction_view` returns `true` purely because of the program-ID match [10](#0-9) , the packet is flagged `SIMPLE_VOTE_TX`, and it is routed into the `tpu_vote` pipeline that bypasses `apply_priority_floor_to_batch`, regardless of actual validity as a vote.

fn is_simple_vote_transaction_view<D: TransactionData>(view: &SanitizedTransactionView<D>) -> bool {
    // vote could have 1 or 2 sigs; zero sig has already been excluded by sanitization.
    if view.num_signatures() > 2 {
        return false;
    }

    // simple vote should only be legacy message
    if !matches!(view.version(), TransactionVersion::Legacy) {
        return false;
    }

    // skip if has more than 1 instruction
    if view.num_instructions() != 1 {
        return false;
    }

    let mut instructions = view.instructions_iter();
    let Some(instruction) = instructions.next() else {
        return false;
    };
    if instructions.next().is_some() {
        return false;
    }

    let program_id_index = usize::from(instruction.program_id_index);
    let Some(program_id) = view.static_account_keys().get(program_id_index) else {
        return false;
    };

    *program_id == solana_sdk_ids::vote::id()
}

fn consume_scan_should_process_packet(
    bank: &Bank,
    packet: SanitizedTransactionView<Bytes>,
    error_counters: &mut TransactionErrorMetrics,
) -> Option<RuntimeTransactionView> {
    // Construct the RuntimeTransaction.
    let Ok(view) = RuntimeTransaction::<SanitizedTransactionView<_>>::try_new(
        packet,
        MessageHash::Compute,
        None,
    ) else {
        return None;
    };

    // Filter invalid votes (should never be triggered).
    if !view.is_simple_vote_transaction() {
        return None;
    }

    // Resolve the transaction (votes do not have LUTs).
    debug_assert!(!matches!(view.version(), TransactionVersion::V0));
    let Ok(view) = RuntimeTransactionView::try_new(view, None, bank.get_reserved_account_keys())
    else {
        return None;
    };

    // Check the number of locks and whether there are duplicates
    if validate_account_locks(
        view.account_keys(),
        bank.get_transaction_account_lock_limit(),
    )
    .is_err()
    {
        return None;
    }

    if Consumer::check_fee_payer_unlocked(bank, &view, error_counters).is_err() {
        return None;
    }

    Some(view)
}

fn apply_priority_floor_to_batch(
    batch: &mut PacketBatch,
    floor: u64,
    bank: &Bank,
) -> (usize, bool) {
    let mut dropped: usize = 0;
    let mut any_kept = false;
    for mut packet in batch.iter_mut() {
        if packet.meta().discard() {
            continue;
        }
        let Some(data) = packet.data(..) else {
            // Zero-length or otherwise unreadable: leave to downstream
            // stages to reject.
            any_kept = true;
            continue;
        };
        // Unparseable packets are kept and left for downstream rejection.
        match calculate_priority_from_bytes(bank, data) {
            Some(priority) if priority <= floor => {
                packet.meta_mut().set_discard(true);
                dropped = dropped.saturating_add(1);
            }
            _ => any_kept = true,
        }
    }
    (dropped, !any_kept)
