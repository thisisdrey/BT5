### Title
Missing `transfer.bundleURI=false` Protection in FetchRemote/FindRemoteRootRef/UpdateRemoteMirror Allows SSRF via Malicious Remote Server - ([File: internal/gitaly/service/repository/fetch_remote.go])

### Summary
Gitaly's `CreateRepositoryFromURL` RPC explicitly disables Git's bundle-URI client feature (`transfer.bundleURI=false`) when cloning from a caller-supplied URL, specifically to prevent SSRF, per the fix in [1](#0-0) . However, three sibling RPCs that also invoke Git against attacker/caller-controlled remote URLs — `FetchRemote`, `FindRemoteRootRef`, and `UpdateRemoteMirror` — build their git configuration without ever setting this flag.

### Finding Description
`CreateRepositoryFromURL`'s `cloneFromURLCommand` builds the clone invocation and appends a protective global option: [2](#0-1) 

This comment makes the threat model explicit: bundle URIs advertised by a remote Git server can point "to any server, including localhost."

In contrast, `buildCommandOpts` in `fetch_remote.go` (used by `FetchRemote`, e.g. for pull mirroring) constructs the in-memory remote config — including DNS-rebinding protection via `GetURLAndResolveConfig` — but never disables `transfer.bundleURI`: [3](#0-2) 

The same gap exists in `findRemoteRootRefCmd`, which runs `git remote show inmemory` against a caller-supplied `remote_url`: [4](#0-3) 

And in `updateRemoteMirror`, which fetches remote references from a caller-supplied mirror URL: [5](#0-4) 

All three paths pass an attacker/operator-influenced `url` (or `remote_url`) field to `git`, and none of them append `gitcmd.ConfigPair{Key: "transfer.bundleURI", Value: "false"}` the way `create_repository_from_url.go` does. Since bundle-URI is a Git client feature that follows a URI advertised by whatever server the client connects to during handshake, a malicious/compromised remote endpoint reachable through any of these three RPCs can advertise a `bundle.<name>.uri` pointing at an internal address (e.g. cloud metadata endpoints), and the invoked `git fetch`/`git remote show` process — running with Gitaly's own network access — would fetch that internal resource.

### Impact Explanation
An SSRF here allows Gitaly's git subprocess to make outbound requests to attacker-chosen internal resources (e.g., internal metadata services, internal-only HTTP endpoints) whenever a repository owner configures a pull mirror, remote, or root-ref lookup pointing at a server the attacker controls. This mirrors the reported bug class where a defense (URL/SSRF filtering) is applied at one entry point but is missing from a functionally equivalent subsequent path.

### Likelihood Explanation
`FetchRemote` is exercised by ordinary pull-mirror configuration and repeated scheduled mirror updates; `UpdateRemoteMirror` and `FindRemoteRootRef` are similarly reachable via standard remote/mirror workflows using a `remote_url`/`Remote.url` field that is attacker-controllable when the attacker controls (or can redirect) the target Git server. No special privilege beyond configuring a remote/mirror URL is required.

### Recommendation
Apply the same `transfer.bundleURI=false` global option used in `create_repository_from_url.go`'s `cloneFromURLCommand` to the config/options built in `buildCommandOpts` (fetch_remote.go), `findRemoteRootRefCmd` (find_remote_root_ref.go), and `updateRemoteMirror` (update_remote_mirror.go), so bundle-URI following is consistently disabled across all RPCs that connect to caller/attacker-influenced remote URLs.

### Proof of Concept
1. Configure a pull mirror (or `FetchRemote`/`UpdateRemoteMirror`/`FindRemoteRootRef` RPC call) pointing `remote_url`/`Remote.url` at an attacker-controlled Git server.
2. The attacker's Git server, during the smart-HTTP/SSH handshake, advertises a bundle URI capability with `bundle.<name>.uri=http://169.254.169.254/metadata/v1.json` (or another internal address).
3. Because `transfer.bundleURI` is not disabled in the config built by `buildCommandOpts`/`findRemoteRootRefCmd`/`updateRemoteMirror` (unlike `cloneFromURLCommand`), the Gitaly-invoked `git` client follows the advertised bundle URI and issues an outbound request to the internal address from the Gitaly host's network context.

func buildCommandOpts(ctx context.Context, opts *localrepo.FetchOpts, req *gitalypb.FetchRemoteRequest) error {
	remoteURL := req.GetRemoteParams().GetUrl()
	var config []gitcmd.ConfigPair

	for _, refspec := range getRefspecs(req.GetRemoteParams().GetMirrorRefmaps()) {
		config = append(config, gitcmd.ConfigPair{
			Key: "remote.inmemory.fetch", Value: refspec,
		})
	}

	if resolvedAddress := req.GetRemoteParams().GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return fmt.Errorf("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if featureflag.FetchRemoteProactiveAuth.IsEnabled(ctx) {
		if u, err := url.Parse(remoteURL); err == nil && u.User != nil {
			password, _ := u.User.Password()
			if u.User.Username() != "" && password != "" {
				config = append(config, gitcmd.ConfigPair{
					Key:   "http.proactiveAuth",
					Value: "basic",
				})
			}
		}
	}

	if authHeader := req.GetRemoteParams().GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", req.GetRemoteParams().GetUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	opts.CommandOptions = append(opts.CommandOptions, gitcmd.WithConfigEnv(config...))

	return nil
}

func (s *server) findRemoteRootRefCmd(ctx context.Context, request *gitalypb.FindRemoteRootRefRequest) (*command.Command, error) {
	remoteURL := request.GetRemoteUrl()
	var config []gitcmd.ConfigPair

	if resolvedAddress := request.GetResolvedAddress(); resolvedAddress != "" {
		modifiedURL, resolveConfig, err := gitcmd.GetURLAndResolveConfig(remoteURL, resolvedAddress)
		if err != nil {
			return nil, structerr.NewInvalidArgument("couldn't get curloptResolve config: %w", err)
		}

		remoteURL = modifiedURL
		config = append(config, resolveConfig...)
	}

	config = append(config, gitcmd.ConfigPair{Key: "remote.inmemory.url", Value: remoteURL})

	if authHeader := request.GetHttpAuthorizationHeader(); authHeader != "" {
		config = append(config, gitcmd.ConfigPair{
			Key:   fmt.Sprintf("http.%s.extraHeader", request.GetRemoteUrl()),
			Value: "Authorization: " + authHeader,
		})
	}

	repo := s.localRepoFactory.Build(request.GetRepository())

	return repo.Exec(ctx,
		gitcmd.Command{
			Name:   "remote",
			Action: "show",
			Args:   []string{"inmemory"},
		},
		gitcmd.WithDisabledHooks(),
		gitcmd.WithConfigEnv(config...),
		gitcmd.WithSetupStdout(),
	)
}
