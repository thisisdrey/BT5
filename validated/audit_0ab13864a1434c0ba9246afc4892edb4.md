Based on my analysis, I found a genuine structural analog to the SKALE bug in the QUIC streamer's connection eviction logic.

### Title
Full connection-table scan on every connection eviction causes O(n) CPU cost per incoming QUIC connection - (File: streamer/src/nonblocking/quic.rs)

### Summary
The SKALE report's root cause is that a per-operation cost (selecting a random node) scales linearly with the total number of tracked entities (`nodesInGroup.length` iterations over `possibleNodes`), rather than being O(1)/O(log n), so cost grows unboundedly as the tracked set grows. The equivalent pattern exists in agave's QUIC connection admission path: `ConnectionTable::prune_oldest` performs a full linear scan over the connection table for *every single entry it needs to evict*, and this function is invoked on essentially every new unstaked/staked connection attempt once the table nears capacity.

### Finding Description
`ConnectionTable::prune_oldest` is defined at [1](#0-0) . Its core loop repeatedly calls `self.table.values().enumerate().min_by_key(key)` — a full O(n) scan of every entry currently in the `IndexMap` — once per connection it removes, inside a `while` loop that runs until the table shrinks to `max_size`:

```rust
pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
    let mut num_pruned = 0;
    let key = |(_, connections): &(_, &Vec<_>)| {
        connections.iter().map(ConnectionEntry::last_update).min()
    };
    while self.total_size.saturating_sub(num_pruned) > max_size {
        match self.table.values().enumerate().min_by_key(key) {
            None => break,
            Some((index, connections)) => {
                num_pruned += connections.len();
                self.table.swap_remove_index(index);
            }
        }
    }
    ...
}
```

This is called from `SwQos::prune_unstaked_connection_table`, which every incoming unstaked connection triggers when the table is at/over capacity, pruning down to 90% of `max_unstaked_connections`: [2](#0-1) . The same eviction call path is invoked from `prune_unstaked_connections_and_add_new_connection`, which runs on every new incoming connection once capacity is reached: [3](#0-2) .

Unlike `ConnectionTable::prune_random`, which samples a small constant `PRUNE_RANDOM_SAMPLE_SIZE` of indices for staked-connection eviction (O(1) per call) — see [4](#0-3)  — `prune_oldest` (used for unstaked connections) is unbounded in the sense that its cost is proportional to the full size of the connection table on every invocation, and it may run this scan multiple times per call (once per evicted IP entry) to shrink the table by 10%.

### Impact Explanation
Because `max_unstaked_connections` can be configured to a large value (and this is the exact table an attacker without stake can fill), sustained connection churn from unstaked clients causes each new connection attempt to perform a linear scan across the whole unstaked connection table repeatedly (once per swap-removed IP bucket needed to reach the 90% target). This is CPU work performed on the connection-accept hot path before/around QUIC handshake completion, driven by an unprivileged, unstaked peer — directly analogous to the SKALE issue where a per-operation cost scaled with the total tracked-entity count instead of being O(1). Under high-connection-churn conditions this becomes a CPU amplification/DoS vector on the TPU QUIC ingestion path, degrading a validator's ability to process legitimate traffic.

### Likelihood Explanation
Any unstaked peer can open many short-lived QUIC connections against the TPU/TPU-forward QUIC endpoints (`spawn_stake_weighted_qos_server` in [5](#0-4) ), which is the standard unprivileged transaction-submission path. No stake or special permission is required to reach `SwQos::prune_unstaked_connections_and_add_new_connection`, and the eviction runs automatically once the unstaked table saturates, which is an easily attacker-forced condition.

### Recommendation
Replace the linear `min_by_key` scan in `prune_oldest` with a bounded/sampled selection strategy analogous to `prune_random` (fixed sample size per eviction) or maintain an auxiliary min-heap/ordered structure keyed by `last_update` so that the oldest entry can be located in O(log n) or O(1) amortized time instead of rescanning the entire table on every eviction.

### Proof of Concept
1. Configure/observe a validator's `max_unstaked_connections` (`SwQosConfig::max_unstaked_connections`, wired in [6](#0-5) ).
2. From an unstaked/unprivileged client, open QUIC connections to the TPU port in a tight loop, exceeding `max_unstaked_connections`.
3. Each subsequent connection attempt triggers `prune_unstaked_connection_table` → `ConnectionTable::prune_oldest`, which performs `O(table_size)` scans repeated for each of the ~10% of entries being evicted, on the connection-accept hot path.
4. Measure CPU time spent in `prune_oldest` under sustained connection churn as `max_unstaked_connections` is scaled up, confirming linear growth in per-connection acceptance latency.

    // Randomly selects sample_size many connections, evicts the one with the
    // lowest stake, and returns the number of pruned connections.
    // If the stakes of all the sampled connections are higher than the
    // threshold_stake, rejects the pruning attempt, and returns 0.
    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

    fn prune_unstaked_connection_table(
        &self,
        unstaked_connection_table: &mut ConnectionTable<ConnectionStreamCounter>,
        max_unstaked_connections: usize,
        stats: Arc<StreamerStats>,
    ) {
        if unstaked_connection_table.total_size >= max_unstaked_connections {
            // Prune the connection table down to 90% capacity
            const PRUNE_TABLE_RATIO: f64 = 0.90;
            let max_connections = (PRUNE_TABLE_RATIO * (max_unstaked_connections as f64)) as usize;
            let num_pruned = unstaked_connection_table.prune_oldest(max_connections);
            stats
                .num_evictions_unstaked
                .fetch_add(num_pruned, Ordering::Relaxed);
        }
    }
