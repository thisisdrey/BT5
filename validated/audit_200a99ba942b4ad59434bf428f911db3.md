### Title
Unauthenticated handshake stage-1 packets trigger unbounded, per-packet asymmetric-crypto work with no per-source throttling, enabling a handshake-flood resource-exhaustion DoS - (File: handshake_manager.go)

### Summary
Any untrusted UDP peer (no valid CA-signed certificate required) can send crafted stage-1 handshake packets to a Nebula node and force it to allocate a new Noise handshake `Machine`, perform Diffie-Hellman/asymmetric crypto (`ProcessPacket`/`ReadMessage`), and run certificate/payload validation for every single packet, with no rate limiting, per-IP throttling, or cost-based admission control. This mirrors the in3-server report's core concern: a low-cost client request can force disproportionately expensive server-side cryptographic/compute work, and the codebase has no analog to `checkPerformanceLimits`/DOS-weighting for this path.

### Finding Description
`Interface.readOutsidePackets` routes any packet with `h.Type == header.Handshake` directly to `f.handshakeManager.HandleIncoming` before any per-source authentication has occurred [1](#0-0) .

`HandshakeManager.HandleIncoming` performs only cheap, stateless checks — subtype whitelist, an optional CIDR-based `remote_allow_list` (which defaults to allow-all and is not a rate limiter), and a zero-RemoteIndex check — before calling `beginHandshake` for every stage-1 (`MessageCounter == 1`) packet: [2](#0-1) 

`beginHandshake` then unconditionally constructs a brand-new Noise `Machine` and calls `machine.ProcessPacket`, which performs `noise.ReadMessage` (elliptic-curve Diffie-Hellman / AEAD operations) and certificate/payload validation — all before the peer has proven possession of a CA-signed certificate that the local node trusts: [3](#0-2) [4](#0-3) 

There is no mechanism analogous to `checkPerformanceLimits` in the referenced report — no per-source-IP counter, no weighted cost accounting, no global concurrency cap on pending handshakes, and no cookie/proof-of-work challenge before the expensive crypto path runs. The only gating control (`remote_allow_list`) is a static, admin-configured CIDR allow/deny list, not a dynamic throttle, and is disabled by default (`al == nil` returns `true`, i.e., allow) as shown in `AllowUnknownVpnAddr`: [5](#0-4) 

Because `beginHandshake` allocates a new `HostInfo`/`HandshakeHostInfo` and registers it under a freshly generated index (`generateIndex`) even before the certificate is validated in some paths, and because each invocation pays the full asymmetric-crypto cost regardless of whether the packet ultimately succeeds, a flood of spoofed or real stage-1 packets can consume disproportionate CPU and memory on the receiving node — directly analogous to the audited in3-server issue where "a client requesting another node to interact with a smart contract... will have to wait" while nodes performed heavy, unthrottled work for lightweight attacker input.

### Impact Explanation
An attacker with no valid Nebula certificate, only knowledge of a node's UDP listen address (which is often discoverable via lighthouse queries or simply guessed), can send a stream of stage-1 handshake packets from spoofed source addresses. Each packet forces the target node to perform DH crypto and Machine allocation. Sustained flooding degrades handshake processing for legitimate peers and can exhaust CPU/memory resources on the node, resulting in denial of service against a core mesh-networking function (peer connectivity establishment). This is a remote, unauthenticated resource-exhaustion vector reachable without a CA-signed certificate.

### Likelihood Explanation
Likelihood is high: the endpoint (UDP handshake listener) is intentionally reachable by unauthenticated peers (this is the whole point of the handshake protocol), there is no default rate limiting, and crafting a minimal stage-1 packet (`MessageCounter=1`, `RemoteIndex=0`, arbitrary Noise ciphertext) is straightforward and requires no cryptographic material from the victim. `remote_allow_list` provides no protection unless an operator has proactively restricted allowed CIDRs, which is not a default configuration for public lighthouse/mesh nodes.

### Recommendation
Add a throttling/admission-control layer to `HandshakeManager.HandleIncoming` analogous to the `checkPerformanceLimits`-style mitigation described in the report: (1) track and cap the rate of stage-1 handshake attempts per source IP/UDP address within a sliding time window before invoking `beginHandshake`; (2) cap the total number of concurrently pending (unauthenticated) handshakes tracked in `hm.indexes`/`hm.vpnIps`, dropping or evicting oldest-first once a threshold is reached; (3) consider a lightweight, stateless proof-of-work or cookie/reply-challenge step (as used by WireGuard-style protocols) so a spoofed source cannot cause the receiver to perform costly asymmetric crypto without a round-trip proving reachability; (4) expose these limits via config with sane defaults so unmanaged deployments are protected out of the box.

### Proof of Concept
1. Discover or guess a target Nebula node's public UDP `listen` port.
2. Repeatedly send well-formed stage-1 handshake packets (`header.Handshake`, `header.HandshakeIXPSK0` subtype, `MessageCounter=1`, `RemoteIndex=0`, arbitrary ciphertext body) from many spoofed source `UdpAddr`s, as constructed similarly to the test helper `makeHandshakePacket` used in `e2e/handshake_manager_test.go` [6](#0-5) .
3. Because `HandleIncoming` only checks subtype/RemoteIndex/`remote_allow_list` before calling `beginHandshake` [7](#0-6) , each packet reaches the expensive Noise `ProcessPacket` path regardless of validity, with no per-source throttle to stop the flood.
4. Observe CPU usage from repeated Noise/DH operations and growth of pending handshake state, degrading handling of legitimate peer handshakes — reproducing the resource-exhaustion class described in the referenced in3-server report, applied to Nebula's handshake listener instead of an RPC endpoint.

func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return
	}

func (hm *HandshakeManager) beginHandshake(via ViaSender, packet []byte, h *header.H) {
	f := hm.f
	cs := f.pki.getCertState()

	v := cs.DefaultVersion()
	if cs.GetCredential(v) == nil {
		f.l.Error("Unable to handshake with host because no certificate is available",
			"from", via, "certVersion", v)
		return
	}

	machine, err := handshake.NewMachine(
		v, cs.GetCredential,
		hm.certVerifier(), func() (uint32, error) { return generateIndex(f.l) },
		false, header.HandshakeIXPSK0,
	)
	if err != nil {
		f.l.Error("Failed to create handshake machine", "from", via, "error", err)
		return
	}

	response, result, err := machine.ProcessPacket(nil, packet)
	if err != nil {
		f.l.Error("Failed to process handshake packet", "from", via, "error", err)
		return
	}

	if result == nil {
		// Multi-message pattern: the responder Machine would need to be
		// registered in hm.indexes so a future inbound packet finds it via
		// continueHandshake. The current manager doesn't do that yet, so
		// fail loudly rather than silently dropping the in-flight handshake.
		// TODO: support multi-message responder flows (XX, pqIX, etc.).
		// See also the IX-shaped cipher key assignment in handshake.Machine.
		f.l.Error("multi-message handshake responder is not supported",
			"from", via, "error", handshake.ErrMultiMessageUnsupported)
		return
	}

func (m *Machine) ProcessPacket(out, packet []byte) ([]byte, *Result, error) {
	if m.failed {
		return nil, nil, ErrMachineFailed
	}
	if len(packet) < header.Len {
		return nil, nil, ErrPacketTooShort
	}
	// Reject packets whose subtype doesn't match the one this Machine was
	// built for. A pending handshake that suddenly receives a different
	// subtype on its index is either a stray packet that matched by chance
	// or a peer protocol violation; drop it without failing the Machine so
	// the legitimate retransmit can still complete.
	if header.MessageSubType(packet[1]) != m.subtype {
		return nil, nil, ErrSubtypeMismatch
	}
	if m.result.Initiator && m.hs.MessageIndex() == 0 {
		m.failed = true
		return nil, nil, ErrInitiateNotCalled
	}

	// The (eKey, dKey) ordering here is correct for IX, where the initiator
	// completes the handshake by reading the responder's stage-2 message.
	// noise returns (cs1, cs2) where cs1 is the initiator->responder cipher.
	// For 3-message patterns where a responder finishes by reading the final
	// message, this ordering would be wrong; revisit when XX/pqIX lands.
	msg, eKey, dKey, err := m.hs.ReadMessage(nil, packet[header.Len:])
	if err != nil {
		// Noise ReadMessage failed. The noise library checkpoints and rolls back
		// on failure, so the Machine is still alive. The caller can retry with
		// a different packet.
		return nil, nil, fmt.Errorf("noise ReadMessage: %w", err)
	}

	// From here on, noise state has advanced. Any error is fatal.
	flags := m.peerMsgFlags()

	if err := m.processPayload(msg, flags); err != nil {
		return nil, nil, err
	}
