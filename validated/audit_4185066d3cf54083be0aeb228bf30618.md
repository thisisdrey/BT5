### Title
Unhardened, unauthenticated-by-design tar extraction in `CreateRepositoryFromSnapshot` allows storage escape / arbitrary file write - (File: internal/gitaly/service/repository/create_repository_from_snapshot.go)

### Summary
The external report's bug class is "a privileged entry point performs a trusted, state-changing action (minting) based entirely on attacker-suppliable input, because the code that consumes it assumes it is only ever invoked through a trusted intermediary, and never validates that assumption." The closest concrete, currently-reachable analog in this Gitaly codebase is `CreateRepositoryFromSnapshot`, whose `untar` helper extracts an attacker/import-controlled tar stream straight onto disk with no validation of entry names, no confinement of the extraction, and an explicit code comment acknowledging that the input is "trusted *a lot*."

### Finding Description
`CreateRepositoryFromSnapshot` fetches an HTTP body (`in.GetHttpUrl()`, optionally with `in.GetHttpAuth()` and an operator-supplied `ResolvedAddress`) and pipes it directly into `tar -C path -xvf -`: [1](#0-0) 

There is no inspection of the archive: no rejection of `../` path segments, absolute paths, symlinks, or hardlinks in the tar stream before or during extraction. The call site even documents this as a known, unaddressed trust gap: [2](#0-1) 

This is the same root-cause shape as the CDP report: a handler (`mint_stable_coin` / here, the snapshot-extraction routine) performs a sensitive, irreversible action (minting coins / writing arbitrary files into the Gitaly storage tree) purely on the basis of caller-supplied data (a fake CW20 token / a crafted tar stream), without validating that the data actually originates from — or is constrained to the bounds established by — the trusted source it was designed for (the "target collateral" contract / a legitimate, self-contained repository snapshot).

Unlike the object-quarantine / alternates code paths in this same repo, which explicitly validate that supplied `GitObjectDirectory`/`GitAlternateObjectDirectories` values stay within the repository's storage root and quarantine prefix (see `ObjectDirectoryPath`), the snapshot-extraction path performs no equivalent confinement check on the archive contents: [3](#0-2) 

### Impact Explanation
A caller able to invoke `CreateRepositoryFromSnapshot` (used for repository import/migration flows) controls both `HttpUrl`/`ResolvedAddress` (SSRF-adjacent: the request target and TLS verification behavior are attacker-influenced) and, more critically, the entire content of the tar stream returned by that URL. Because extraction is unconstrained, a crafted archive containing `../../` path components or symlinked entries can write or overwrite files outside the newly created repository directory — a storage escape / arbitrary file write on the Gitaly storage volume, potentially clobbering configuration, hooks of other repositories, or files outside the storages root entirely, depending on Gitaly's process permissions.

### Likelihood Explanation
The functionality is reachable through the normal `RepositoryService` used for repository import/snapshot restoration, i.e., part of ordinary "import" tooling rather than an internal-only debug RPC, and is routed through Praefect like any other repository-creating RPC: [4](#0-3) 
No test in the corresponding test file exercises path-traversal or symlink protection, and the code's own comment states the archive is trusted "a lot" and needs hardening before being pointed at endpoints "not under our control" — indicating the protection was never implemented.

### Recommendation
Before or during extraction, validate every tar entry: reject absolute paths, `..` path segments (after `filepath.Clean`), and symlink/hardlink entries whose targets resolve outside the destination `path`. Alternatively, extract into a scratch directory first and use a hardened Go tar-extraction routine that enforces containment, only moving the fully-validated repository directory into place afterward, mirroring the confinement checks already used for quarantine/alternate object directories.

### Proof of Concept
An attacker (or compromised import source) controlling the HTTP endpoint referenced by `HttpUrl` in a `CreateRepositoryFromSnapshotRequest` returns a tar stream containing an entry such as `../../../../etc/cron.d/evil` (or a symlink entry pointing outside `path`). Because `untar` runs `tar -C path -xvf -` with no entry filtering, the file is written outside the intended repository directory as soon as the RPC is invoked, without any additional privilege beyond the ability to call the RPC and supply a URL Gitaly will fetch.

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}
