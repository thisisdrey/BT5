### Title
Replay-window check-then-commit race lets duplicate/replayed packets be decrypted and delivered twice - ([File: connection_state.go])

### Summary
`ConnectionState.Decrypt` reads the anti-replay window state (`window.Check`), releases the lock, performs the (comparatively expensive) AEAD decrypt, and only *afterwards* re-acquires the lock to commit the counter into the window via `window.Update`. Because the "is this counter already seen" check and the "mark this counter as seen" commit are two separate, unlocked-in-between operations, two packets carrying the same message counter that are processed concurrently (e.g., on the multi-queue UDP reader routines) can both pass `Check` before either has called `Update`, letting both be decrypted and delivered. [1](#0-0) 

### Finding Description
`ConnectionState.Decrypt` is the data-plane authentication/anti-replay gate for every message packet coming off the wire: [1](#0-0) 

The sequence is: lock → `window.Check(messageCounter)` → unlock → `dKey.DecryptDanger(...)` (no lock held) → lock → `window.Update(messageCounter)` → unlock. `Bits.Check` is a pure read that returns `true` as long as the counter hasn't been marked yet; `Bits.Update` is the operation that actually flips the bit for that counter. [2](#0-1) [3](#0-2) 

Because the lock is released between `Check` and the eventual `Update`, the "has this counter been seen" state is exactly analogous to the oracle price in the DYAD report: an attacker who can present the same already-observed ciphertext to the node from two different execution paths at (nearly) the same instant can get both to observe the "not yet seen" state before either commits it. Nebula's underlay reader is explicitly designed to run multiple concurrent queues that each independently invoke `readOutsidePackets` → `ConnectionState.Decrypt` for packets destined to the same `HostInfo`: [4](#0-3) [5](#0-4) 

`outside.go` routes any inbound `header.Message` packet straight into `hostinfo.ConnectionState.Decrypt` using the message counter taken directly from the (unauthenticated at that point) header: [6](#0-5) 

An attacker who has captured one legitimate ciphertext (e.g., an on-path or MITM observer, no CA-signed certificate needed) can inject that exact ciphertext twice, timed to land on two different reader queues (`listen.batch`/`routines > 1` is the documented multi-queue configuration) so that both invocations of `Decrypt` execute `Check` before either executes `Update`. Both copies pass the replay check, both successfully AEAD-decrypt (it's valid, previously-seen ciphertext), and both are handed to `handleOutsideMessagePacket` for delivery to the local tun device — defeating the purpose of the 1024-entry replay window (`ReplayWindow = 1024`). [7](#0-6) 

This is the same root-cause class as the DYAD H-03 report: a value that gates a state-changing decision (there: oracle price; here: "already processed" bit) is read and acted upon, with the actual commit of that value deferred to a later, separately-locked step, creating a window an attacker can race.

### Impact Explanation
Successful exploitation causes duplicate delivery of an already-observed, replayed packet to the tun device — a concrete replay-protection bypass in the "nonce/replay handling" logic that the protocol explicitly relies on to prevent packet replay attacks (e.g., replaying UDP-encapsulated application traffic, resulting in duplicate application-level effects on the receiving host). It undermines a security property (`ConnectionState.Decrypt`/`Bits` are the sole replay defense) without requiring the attacker to hold a valid certificate or be an authenticated peer — only the ability to capture and re-inject a ciphertext already seen in transit.

### Likelihood Explanation
Exploitation requires: (1) multi-queue mode, which is a normal, documented production configuration (`routines`/`listen.batch` > 1) rather than an edge case, and (2) the ability to send the same UDP payload to the target twice in a narrow window so it lands on two different reader goroutines before the first `Update` commits. This is a realistic on-path/MITM capability and does not require compromising any cryptographic material, making the race practically triggerable, though its window is narrow (bounded by one AEAD decrypt's duration).

### Recommendation
Close the TOCTOU gap: hold the replay-window lock (or otherwise atomically reserve the counter) across the entire check-decrypt-commit sequence, or perform a single atomic "check-and-reserve" operation on `Bits` before starting the AEAD decrypt, only finalizing/rolling back the reservation based on decrypt success. This removes the window during which two concurrent identical counters can both be treated as unseen.

### Proof of Concept
1. Establish a tunnel between two Nebula nodes with `routines`/`listen.batch` configured for multiple queues (multi-queue UDP reader).
2. Capture one legitimate `header.Message` ciphertext frame sent by node A to node B (e.g., via network tap/MITM).
3. Simultaneously inject two copies of the identical captured frame into node B's UDP socket, timed so the OS/kernel batch-delivery (`recvmmsg`/multiple listener queues) dispatches them to two different `listenOut` goroutines.
4. Both goroutines call `readOutsidePackets` → `ConnectionState.Decrypt` concurrently; both execute `window.Check(messageCounter)` under the lock before either executes `window.Update(messageCounter)`, per the sequence in [1](#0-0) .
5. Both invocations return `true` from `Check`, both successfully decrypt (same valid ciphertext), and both packets proceed to `handleOutsideMessagePacket`, resulting in the replayed frame being delivered twice to the tun device — confirming the anti-replay guarantee is bypassed.

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}
	return out, nil
}

// Check returns true if i is within (or way out in front of) the window, and not a replay
func (b *Bits) Check(l *slog.Logger, i uint64) bool {
	// If i is the next number, return true.
	if i > b.current {
		return true
	}

	if b.strictlyWithinWindow(i) {
		return !b.get(i)
	}

	// Not within the window
	if l.Enabled(context.Background(), slog.LevelDebug) {
		l.Debug("rejected a packet (top)", "current", b.current, "incoming", i)
	}
	return false
}

func (b *Bits) Update(l *slog.Logger, i uint64) bool {
	// Fast path: i is the next expected counter. Split out so the function
	// stays small and avoids paying for the slow paths' slog argument-build
	// stack frame on every call. The bit read/test/write is inlined to
	// touch the backing word once.
	if i == b.current+1 {
		pos := i & b.lengthMask
		word := pos >> 6
		mask := uint64(1) << (pos & 63)
		w := b.bits[word]
		if i > b.length && w&mask == 0 {
			b.lostCounter.Inc(1)
		}
		b.bits[word] = w | mask
		b.current = i
		return true
	}
	return b.updateSlow(l, i)
}

func (f *Interface) listenOut(i int) {
	var li udp.Conn
	if i > 0 {
		li = f.writers[i]
	} else {
		li = f.outside
	}

	ctCache := firewall.NewConntrackCacheTicker(f.ctx, f.l, f.conntrackCacheTimeout)
	lhh := f.lightHouse.NewRequestHandler()
	plaintext := make([]byte, udp.MTU)
	h := &header.H{}
	fwPacket := &firewall.Packet{}
	nb := make([]byte, 12, 12)

	err := li.ListenOut(func(fromUdpAddr netip.AddrPort, payload []byte) {
		f.readOutsidePackets(ViaSender{UdpAddr: fromUdpAddr}, plaintext[:0], payload, h, fwPacket, lhh, nb, i, ctCache.Get())
	})

	// An error after teardown began is shutdown noise, the closed flag covers resources
	// Close releases itself and the cancelled ctx covers ones torn down by their owners
	// reacting to it, like the user device pipes
	if err != nil && !f.closed.Load() && f.ctx.Err() == nil {
		f.l.Error("Error while reading inbound packet, closing", "error", err)
		f.onFatal(err)
	}

	f.l.Debug("underlay reader is done", "reader", i)
}
