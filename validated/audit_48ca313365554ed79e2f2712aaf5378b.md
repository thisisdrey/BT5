Based on my research, I found a concrete structural analog to the reported bug class in Wise-Lending: **two code paths compute the same security-relevant value, but only one of them performs the escape/validation check that the other has.**

### Title
Custom hook environment construction bypasses object-directory path validation performed elsewhere - (File: internal/gitaly/hook/custom.go)

### Summary
Gitaly has two separate code paths that resolve a repository's Git object directory and alternate object directories into on-disk paths. `Repo.ObjectDirectoryPath` in `internal/git/localrepo/paths.go` validates that the relative `GitObjectDirectory`/`GitAlternateObjectDirectories` fields cannot escape the storage root and, if outside the repo, must match the expected quarantine-directory prefix for that repository [1](#0-0) . However, the twin function `customHooksEnv`, which builds the environment passed to custom pre-receive/update/post-receive hook scripts, independently re-derives `GIT_OBJECT_DIRECTORY` and `GIT_ALTERNATE_OBJECT_DIRECTORIES` by simply joining `repoPath` with the same repository-proto fields — without ever calling `ObjectDirectoryPath` or `ValidateRelativePath` [2](#0-1) .

### Finding Description
`ObjectDirectoryPath` treats `GitObjectDirectory`/`GitAlternateObjectDirectories` as untrusted, attacker-influenceable input and enforces that the resolved path either (a) stays within the repository/storage root, or (b) matches the repo-specific quarantine prefix generated by `storage.QuarantineDirectoryPrefix` [3](#0-2) . This mirrors the "weighted" collateral check (`_checkPoolCondition`) in the report that validates a condition before trusting a value.

`customHooksEnv`, used when Gitaly spawns admin-installed custom hooks (the "Bare" analog), takes the very same proto fields (`payload.Repo.GetGitObjectDirectory()`, `payload.Repo.GetGitAlternateObjectDirectories()`) but resolves them with a bare `filepath.Join(repoPath, ...)` and injects the result straight into `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` [4](#0-3) . There is no call to `ValidateRelativePath`, no root-escape check, and no quarantine-prefix check on this path — the same class of omission as `overallETHCollateralsBare` skipping `_checkPoolCondition` while `overallETHCollateralsWeighted` performs it.

Because custom hooks (and any Git subprocess they spawn) inherit these environment variables, a value that reaches this code path unfiltered would let a spawned `git` process search for objects outside the intended repository/quarantine directory — exactly the kind of alternates/quarantine isolation escape called out as in-scope.

### Impact Explanation
If a caller-supplied `GitObjectDirectory`/`GitAlternateObjectDirectories` value (relative path with `../` components) reaches `customHooksEnv` without having first passed through `ObjectDirectoryPath`'s validation, the resulting `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables can point custom hook subprocesses at directories outside the repository's own object store or its legitimate quarantine directory — a cross-repository/storage object-directory escape, matching the "concrete storage escape" / "cross-repository object access" acceptance criteria.

### Likelihood Explanation
Exploitability depends on whether `payload.Repo` reaching `customHooksEnv` can carry a `GitObjectDirectory`/`GitAlternateObjectDirectories` value that was not already sanitized upstream (e.g. by `quarantine.Apply`, which always builds these fields internally as safe relative paths) [5](#0-4) . In the normal receive-pack/quarantine flow these fields are Gitaly-generated and safe, which lowers likelihood; however, the lack of a defense-in-depth check at this call site — unlike the equivalent `ObjectDirectoryPath` accessor used elsewhere — means any future or alternate caller that plumbs a repository proto with attacker-influenced object-directory fields into the hook payload would bypass the validation Gitaly relies on elsewhere.

### Recommendation
Route `customHooksEnv`'s object-directory and alternate-object-directory resolution through `Repo.ObjectDirectoryPath`/`ValidateRelativePath` (or an equivalent shared validator) instead of a bare `filepath.Join`, so that the same escape/quarantine-prefix checks enforced in `internal/git/localrepo/paths.go` are guaranteed to apply consistently to every code path that turns these repository-proto fields into filesystem paths or environment variables.

### Proof of Concept
Not independently confirmed against a live attacker-controlled `GitObjectDirectory` value reaching `customHooksEnv`; this is a code-path/consistency analysis based on comparing `internal/git/localrepo/paths.go` (`ObjectDirectoryPath`, lines 19-83) against `internal/gitaly/hook/custom.go` (`customHooksEnv`, lines 164-221). A full PoC would require tracing whether any RPC allows a `Repository` message with a crafted relative `GitObjectDirectory`/`GitAlternateObjectDirectories` to flow into `GitLabHookManager.customHooksEnv` without first passing through `quarantine.Apply` or `ObjectDirectoryPath`.

func (m *GitLabHookManager) customHooksEnv(ctx context.Context, payload gitcmd.HooksPayload, pushOptions []string, envs []string) ([]string, error) {
	repoPath, err := m.locator.GetRepoPath(ctx, payload.Repo, storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	customEnvs := append(command.AllowedEnvironment(envs), pushOptionsEnv(pushOptions)...)

	objectDirectory := env.ExtractValue(envs, "GIT_OBJECT_DIRECTORY")
	if objectDirectory == "" && payload.Repo.GetGitObjectDirectory() != "" {
		objectDirectory = filepath.Join(repoPath, payload.Repo.GetGitObjectDirectory())
	}
	if objectDirectory != "" {
		customEnvs = append(customEnvs, "GIT_OBJECT_DIRECTORY="+objectDirectory)
	}

	alternateObjectDirectories := env.ExtractValue(envs, "GIT_ALTERNATE_OBJECT_DIRECTORIES")
	if alternateObjectDirectories == "" && len(payload.Repo.GetGitAlternateObjectDirectories()) != 0 {
		var absolutePaths []string
		for _, alternateObjectDirectory := range payload.Repo.GetGitAlternateObjectDirectories() {
			absolutePaths = append(absolutePaths, filepath.Join(repoPath, alternateObjectDirectory))
		}
		alternateObjectDirectories = strings.Join(absolutePaths, ":")
	}
	if alternateObjectDirectories != "" {
		customEnvs = append(customEnvs, "GIT_ALTERNATE_OBJECT_DIRECTORIES="+alternateObjectDirectories)

// Apply applies the quarantine on the repository. This is done by setting the quarantineDirectory
// as the repository's object directory, and configuring the repository's object directory as an alternate.
func Apply(repoPath string, repo *gitalypb.Repository, quarantineDir string) (*gitalypb.Repository, error) {
	relativePath, err := filepath.Rel(repoPath, quarantineDir)
	if err != nil {
		return nil, fmt.Errorf("creating quarantine: %w", err)
	}

	// All paths are relative to the repository root.
	objectDir := repo.GetGitObjectDirectory()
	if objectDir == "" {
		// Set the default object directory as an alternate if the repository didn't
		// have the object directory overwritten yet.
		objectDir = "objects"
	}

	alternateObjectDirs := make([]string, 0, len(repo.GetGitAlternateObjectDirectories())+1)
	alternateObjectDirs = append(alternateObjectDirs, objectDir)
	alternateObjectDirs = append(alternateObjectDirs, repo.GetGitAlternateObjectDirectories()...)

	quarantinedRepo := proto.Clone(repo).(*gitalypb.Repository)
	quarantinedRepo.GitObjectDirectory = relativePath
	quarantinedRepo.GitAlternateObjectDirectories = alternateObjectDirs

	return quarantinedRepo, nil
}
