### Title
Handshake-supplied `data_url` is not private-range filtered before the node initiates outbound StackerDB HTTP connections (SSRF-analog) - ([File: stackslib/src/net/neighbors/rpc.rs])

### Summary
Any remote, unauthenticated peer that performs a handshake can set an arbitrary `data_url` (host/port) via `HandshakeData`, and the node stores this value with no address-plausibility validation. `StackerDBSync`/`NeighborRPC::send_request` later uses this attacker-chosen URL to open outbound HTTP connections. This is a missing-permission/missing-validation analog to the Jenkins CVE: a low-privilege actor (any peer that can complete a handshake — no elevated network role required) causes the node to originate a connection to a server address of the attacker's choosing.

### Finding Description
`HandshakeData.data_url` is decoded straight from the wire in `HandshakeData::consensus_deserialize` with only a port-nonzero check [1](#0-0) , and is copied verbatim into the conversation state by `update_from_handshake_data` (`self.data_url = handshake_data.data_url.clone();`) with no restriction on scheme, host, or address range [2](#0-1) . This happens for both authenticated and unauthenticated inbound handshakes handled by `handle_handshake` [3](#0-2) ; the `validate_handshake` routine checks only the signature, key staleness, and self-handshake, never the plausibility of `data_url` [4](#0-3) .

Once stored, `convo.data_url` is used directly to build an HTTP connection target for StackerDB replication via `NeighborRPC::get_peer_host`/`send_request`, which calls `PeerHost::try_from_url(&convo.data_url)` and `http.connect_http(...)` with the resolved address — with no private-range or denylist check at this call site [5](#0-4) .

This contrasts with the parallel, better-guarded path: `StackerDBConfig::eval_hint_replicas` (contract-sourced hint replicas) explicitly filters out private-range peer addresses before adding them to `hint_replicas` [6](#0-5) , and the mempool-sync path (`do_mempool_sync`/`SendQuery` state) explicitly re-checks `PeerAddress::from_socketaddr(addr).is_in_private_range()` immediately before issuing the HTTP request [7](#0-6) . The StackerDB neighbor-RPC path (`neighbors/rpc.rs`) has no equivalent gate — it is missing the same permission/validation check that other outbound-URL consumers in this same module tree apply.

### Impact Explanation
An attacker who can simply establish a p2p handshake (an unprivileged, remote action — no admin role, no node secret, no signer key needed) can steer the victim node's outbound StackerDB HTTP traffic toward an attacker-chosen host:port, including internal/private addresses reachable from the node (if `private_neighbors` is enabled, or via non-RFC1918 but still attacker-controlled hosts otherwise). This can be used to probe internal services or direct outbound bandwidth/requests at a third party, matching the CVE's core impact: "initiate a connection to an attacker-specified server" from a low-privilege interaction.

### Likelihood Explanation
Likelihood is bounded by the fact that `send_request` in `neighbors/rpc.rs` is only reached for peers that already have an "authenticated" neighbor conversation and (for the private-range subset) `private_neighbors` must be enabled for private addresses to be dialed at all elsewhere in the stack; the mempool sync path already re-validates against private ranges, suggesting the omission in `neighbors/rpc.rs` is likely an inconsistency rather than an intentionally-open path. Still, no additional privilege beyond completing a handshake is required to set `data_url`, and the missing check is concrete and locatable.

### Recommendation
Add the same private-range/address-plausibility check used in `do_mempool_sync`'s `SendQuery` state (and the `eval_hint_replicas` filter) to `NeighborRPC::get_peer_host`/`send_request` before calling `connect_http`, rejecting or gating (per `connection_opts.private_neighbors`) any resolved `data_ip` that falls in a private/loopback/link-local range.

### Proof of Concept
1. Attacker node completes a p2p handshake with the victim, sending `HandshakeData` with `data_url = "http://169.254.169.254:80/"` (or an internal service address) and a valid signature over its own key (self-signed handshake is permitted per `validate_handshake`).
2. Victim's `update_from_handshake_data` stores this `data_url` on the conversation unchanged.
3. When the victim's `StackerDBSync` needs to fetch/push a chunk from that peer, `NeighborRPC::send_request` resolves `data_url` and calls `connect_http` — with no private-range check — causing the victim to originate an HTTP connection to the attacker-specified address.

    fn validate_handshake(
        &mut self,
        local_peer: &LocalPeer,
        chain_view: &BurnchainView,
        message: &mut StacksMessage,
    ) -> Result<(), net_error> {
        let handshake_data = match message.payload {
            StacksMessageType::Handshake(ref mut data) => data.clone(),
            _ => panic!("Message is not a handshake"),
        };

        match self.connection.get_public_key() {
            None => {
                // if we don't yet have a public key for this node, verify the message.
                // if it's improperly signed, it's probably a poorly-timed re-key request (but either way the message should be rejected)
                message
                    .verify_secp256k1(&handshake_data.node_public_key)
                    .map_err(|_e| {
                        debug!(
                            "{:?}: invalid handshake: not signed with given public key",
                            &self
                        );
                        net_error::InvalidMessage
                    })?;
            }
            Some(_) => {
                // for outbound connections, the self-reported address must match socket address if we already have a public key.
                // (not the case for inbound connections, since the peer socket address we see may
                // not be the same as the address the remote peer thinks it has).
                // The only exception to this is if the remote peer does not yet know its own
                // public IP address, in which case, its handshake addrbytes will be the
                // any-network bind address (0.0.0.0 or ::)
                if self.stats.outbound
                    && (!handshake_data.addrbytes.is_anynet()
                        && (self.peer_addrbytes != handshake_data.addrbytes
                            || self.peer_port != handshake_data.port))
                {
                    // wrong peer address
                    debug!(
                        "{:?}: invalid handshake -- wrong addr/port ({:?}:{:?})",
                        &self, &handshake_data.addrbytes, handshake_data.port
                    );
                    return Err(net_error::InvalidHandshake);
                }
            }
        };

        let their_public_key_res = handshake_data.node_public_key.to_public_key();
        match their_public_key_res {
            Ok(_) => {}
            Err(_e) => {
                // bad public key
                debug!("{:?}: invalid handshake -- invalid public key", &self);
                return Err(net_error::InvalidMessage);
            }
        };

        if handshake_data.expire_block_height <= chain_view.burn_block_height {
            // already stale
            debug!(
                "{:?}: invalid handshake -- stale public key (expired at {})",
                &self, handshake_data.expire_block_height
            );
            return Err(net_error::InvalidHandshake);
        }

        // the handshake cannot come from us
        if handshake_data.node_public_key
            == StacksPublicKeyBuffer::from_public_key(&Secp256k1PublicKey::from_private(
                &local_peer.private_key,
            ))
        {
            debug!(
                "{:?}: invalid handshake -- got a handshake from myself",
                &self
            );
            return Err(net_error::InvalidHandshake);
        }

        Ok(())
    }

    /// Find the PeerHost to use when creating a Stacks HTTP request.
    /// Returns Some(host) if we're connected and authenticated to this peer
    /// Returns None otherwise.
    pub fn get_peer_host(network: &PeerNetwork, addr: &NeighborAddress) -> Option<PeerHost> {
        let nk = addr.to_neighbor_key(network);
        let convo = network.get_neighbor_convo(&nk)?;
        PeerHost::try_from_url(&convo.data_url)
    }

    /// Send an HTTP request to the given neighbor's HTTP endpoint.
    /// The peer must already be connected and authenticated via the p2p network.
    /// Returns Ok(()) if we successfully queue the request.
    /// Returns Err(..) if we fail to connect to the remote peer for some reason.
    pub fn send_request(
        &mut self,
        network: &mut PeerNetwork,
        naddr: NeighborAddress,
        request: StacksHttpRequest,
    ) -> Result<(), NetError> {
        let nk = naddr.to_neighbor_key(network);
        let convo = network
            .get_neighbor_convo(&nk)
            .ok_or(NetError::PeerNotConnected(format!(
                "No authenticated conversation open to {nk} -- cannot perform HTTP request",
            )))?;
        let data_url = convo.data_url.clone();
        let data_addr = if let Some(ip) = convo.data_ip {
            ip
        } else if convo.waiting_for_dns() {
            debug!(
                "{}: have not resolved {} data URL {} yet: waiting for DNS",
                network.get_local_peer(),
                &convo,
                &data_url
            );
            return Err(NetError::WaitingForDNS);
        } else {
            debug!(
                "{}: have not resolved {} data URL {} yet, and not waiting for DNS",
                network.get_local_peer(),
                &convo,
                &data_url
            );
            return Err(NetError::PeerNotConnected(format!(
                "Have not resolved {nk} data URL {data_url} yet, and not waiting for DNS",
            )));
        };

        let event_id =
            PeerNetwork::with_network_state(network, |ref mut network, ref mut network_state| {
                PeerNetwork::with_http(network, |ref mut network, ref mut http| {
                    match http.connect_http(network_state, network, data_url, data_addr, None) {
                        Ok(event_id) => Ok(event_id),
                        Err(NetError::AlreadyConnected(event_id, _)) => Ok(event_id),
                        Err(e) => {
                            return Err(e);
                        }
                    }
                })
            })?;
