### Title
New accounts are credited `balance × INITIAL_INDEX` of rewards when token index still equals `INITIAL_INDEX`, draining the distributor - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
`RewardsDistributor._calculateTokenDelta` only normalizes a missing `accountIndexOf` entry when the global token index is strictly greater than `INITIAL_INDEX` (1e18). While the index is still exactly `INITIAL_INDEX` — i.e. the same block in which the first non-zero `tokenSpeeds` is set — any account that has never been indexed has `accountIndex == 0`, so `_deltaIndex = INITIAL_INDEX - 0 = 1e18` and `tokensDelta = balance.wadMul(1e18) = balance`. A permissionless call to `updateBeforeMintOrBurn` therefore credits the caller's entire deposit-token balance as accrued rewards, and `claimRewards` pays it out from the distributor's `rewardToken` balance. This is the same class as the `setScale` finding: a stored baseline/scale value (`INITIAL_INDEX`) is inconsistent with the per-account baseline of `0`, producing a miscalculated payout.

### Finding Description
In `_updateTokenSpeed`, when a token receives its first non-zero speed, its state is initialized to `TokenState({index: INITIAL_INDEX, timestamp: block.timestamp})` [1](#0-0) .

In `_calculateTokenDelta`, the fallback that maps "never-seen account" to `INITIAL_INDEX` only applies when `_tokenIndex > INITIAL_INDEX`:

```solidity
if (_accountIndex == 0 && _tokenIndex > INITIAL_INDEX) {
    _accountIndex = INITIAL_INDEX;
}
uint256 _deltaIndex = _tokenIndex - _accountIndex;
_tokensDelta = token_.balanceOf(account_).wadMul(_deltaIndex);
``` [2](#0-1) 

While `index == INITIAL_INDEX` exactly (delta timestamps still 0, i.e. the block where speed was set), the fallback is skipped, `_deltaIndex = 1e18`, and the account is credited `balanceOf(account)` reward tokens. `updateBeforeMintOrBurn` is explicitly callable by anyone [3](#0-2) , and `claimRewards` pays `tokensAccruedOf[account_]` whenever the distributor holds enough `rewardToken` [4](#0-3) .

### Impact Explanation
An unprivileged attacker deposits underlying to mint a large `DepositToken` balance, then — in the same block the governor first calls `updateTokenSpeed`/`updateTokenSpeeds` for that token (observable via mempool, bundle-able) — calls `updateBeforeMintOrBurn(depositToken, attacker)` and `claimRewards(attacker)`. The attacker is credited and paid reward tokens equal to their deposit balance, draining the distributor's reward inventory that belongs to other users' accrued yield. This is theft of unclaimed yield. Each fresh account can be exploited once, so the attack scales with the deposit balance the attacker can marshal (real underlying is required, but it can be withdrawn afterwards subject to `minDepositTime`).

### Likelihood Explanation
The trigger window is narrow: it exists only while `tokenStates[token].index == INITIAL_INDEX`, i.e. between speed initialization and the first index update with `deltaTimestamps > 0` — practically the same block as the governor's first `updateTokenSpeed` call. However, it requires no privileges, is repeatable per newly added reward token (each `TokenState` starts at `INITIAL_INDEX`), and mempool monitoring makes the timing achievable. No modifier, pause flag, or `SynthContext` check blocks the path: `updateBeforeMintOrBurn` and `claimRewards` are permissionless.

### Recommendation
Treat `accountIndexOf == 0` as "never synced" consistently: change the fallback condition to `if (_accountIndex == 0 && _tokenIndex >= INITIAL_INDEX)` (or initialize `accountIndexOf` to `INITIAL_INDEX` on first accrual regardless of index value), so a zero account index never produces a non-zero `_deltaIndex` larger than genuinely accrued rewards.

### Proof of Concept
```typescript
// Hardhat test sketch (test/RewardDistributor.test.ts style)
it('steals rewards while index == INITIAL_INDEX', async function () {
  // fund distributor with reward token
  await vsp.mint(rewardDistributor.address, parseEther('1000'))

  // attacker holds deposit-token balance before speed is set
  msdTOKEN1.totalSupply.returns(parseEther('100'))
  msdTOKEN1.balanceOf.whenCalledWith(attacker.address).returns(parseEther('100'))

  // governor sets first speed for token; index initialized to INITIAL_INDEX = 1e18
  await rewardDistributor.updateTokenSpeed(msdTOKEN1.address, parseEther('1'))
  // NOTE: same block -> tokenStates[msdTOKEN1].index === INITIAL_INDEX (deltaTimestamps == 0)

  // permissionless call: accountIndex == 0, index == INITIAL_INDEX (not >)
  // => deltaIndex = 1e18 => tokensDelta = 100e18 * 1e18 / 1e18 = 100e18
  await rewardDistributor.connect(attacker).updateBeforeMintOrBurn(msdTOKEN1.address, attacker.address)
  expect(await rewardDistributor.tokensAccruedOf(attacker.address)).to.eq(parseEther('100'))

  // drain reward tokens equal to deposit balance despite zero time elapsed
  const before = await vsp.balanceOf(attacker.address)
  await rewardDistributor.connect(attacker)['claimRewards(address)'](attacker.address)
  expect((await vsp.balanceOf(attacker.address)).sub(before)).to.eq(parseEther('100'))
})
```
