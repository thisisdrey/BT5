### Title
Unauthenticated RecvError packets can tear down established tunnels without a spoofing check on the initial state - (File: outside.go)

### Summary
`handleRecvError` is invoked directly from `readOutsidePackets` for any packet with `header.RecvError` type, before any decryption, cert verification, or CA-signed identity check occurs. It looks up a hostinfo purely from an attacker-controlled `RemoteIndex` and, if `hostinfo.GetRemote()` is not yet set/valid, closes the tunnel and deletes the pending handshake state — mirroring the reported bug class where an unrestricted "setup"/"reset" style function can be called by anyone to force unexpected state transitions.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets straight to `f.handleRecvError(via.UdpAddr, h)` with no authentication of the sender: [1](#0-0) 

Inside `handleRecvError`, the only gates are a local config check (`acceptRecvErrorConfig.ShouldRecvError`) and a comparison against the hostinfo's currently known remote address: [2](#0-1) 

The spoofing guard (`hr.IsValid() && hr != addr`) only protects a hostinfo that *already has* a confirmed remote address. Any pending/newly-created hostinfo (or one whose remote address is not yet set — e.g., before the first tunnel roam, or in states where `GetRemote()` returns an invalid `AddrPort`) has no protection: an attacker who merely knows or guesses a valid `RemoteIndex` (a 32-bit index, sent in cleartext handshake responses, or obtainable by observing traffic) can send a bare `RecvError` packet from any spoofed or arbitrary UDP source and unconditionally trigger `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)` — destroying tunnel/handshake state with no certificate or cryptographic proof of identity, exactly analogous to an unauthenticated caller invoking a privileged state-mutating function.

### Impact Explanation
This allows any network-adjacent attacker without a CA-signed certificate to forcibly tear down victim tunnels or in-progress handshakes (denial of service), forcing repeated re-handshakes and enabling amplification of subsequent handshake-hijack races (as covered by the `TestWrongResponderHandshake` family of tests) since the attacker controls the timing of tunnel destruction.

### Likelihood Explanation
Requires only knowledge of a `RemoteIndex` (a 32-bit value transmitted on the wire during handshake) and the ability to send a spoofed/arbitrary-source UDP packet to the target's listen port — no cryptographic handshake or CA-issued identity is required. Likelihood is moderate-to-high on networks where UDP source spoofing is feasible or where the index can be observed.

### Recommendation
Do not act on `RecvError` for hostinfos whose remote address is not yet confirmed/valid, and require some minimal state confirmation (e.g., an active tunnel with the same recently-observed remote) before tearing anything down. Consider rate-limiting and requiring the `RecvError` sender address to already match a hostinfo whose handshake has completed (`ConnectionState != nil`) rather than allowing any hostinfo with an as-yet-unset remote to be closed unconditionally.

### Proof of Concept
1. Observe or guess a victim's `localIndexId` for a tunnel in-progress or one whose `remote` hasn't been set yet (e.g., statically configured host before first packet exchange).
2. Craft a `header.RecvError` packet (`header.Encode(..., header.RecvError, 0, index, 0)`) with the guessed `RemoteIndex` and send it from an arbitrary/spoofed UDP source to the target's listen port.
3. Since `hostinfo.GetRemote()` returns an invalid `AddrPort` for that hostinfo, the `hr.IsValid() && hr != addr` check is skipped, and `handleRecvError` unconditionally calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, destroying the tunnel/handshake state without any certificate check.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
