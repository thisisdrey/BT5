### Title
tar-based snapshot extraction path traversal leaves attacker-controlled files outside repository on rollback - ([File: internal/gitaly/service/repository/create_repository_from_snapshot.go])

### Summary
`CreateRepositoryFromSnapshot`'s `untar` helper pipes an attacker-controlled HTTP response body directly into `tar -C path -xvf -` with no entry-name validation, and `repoutil.Create`'s failure-path cleanup only `os.RemoveAll`s the temporary repository directory itself, not the parent temp-storage directory where a `../`-prefixed tar entry would land.

### Finding Description
`untar` (`internal/gitaly/service/repository/create_repository_from_snapshot.go:87-121`) streams `rsp.Body` from `in.GetHttpUrl()` straight into an external `tar -C path -xvf -` process, with the code comment explicitly acknowledging "the received archive is trusted a lot" and needs hardening (`internal/gitaly/service/repository/create_repository_from_snapshot.go:140-141`). `path` is the temporary repository directory created by `repoutil.Create` (`internal/gitaly/repoutil/create.go:106-110`, via `tempdir.NewRepository`).

Standard GNU `tar` does not sanitize `../` path components in archive member names by default; a first entry named `../leftover-file` will be written to the parent of `path`, i.e. the storage's shared temp root (`+gitaly/tmp/...`), before `tar` ever encounters the second, corrupt entry that eventually makes it exit non-zero.

When `tar` fails, `cmd.Wait()` returns an error, `untar` returns it via `structerr.NewInternal`, and the `seedRepository` callback in `repoutil.Create` returns that error at line 144. `Create` then returns early (line 147) without moving the temp directory into place. The only cleanup that fires is the `defer cleanup()` registered at line 110, which resolves to `tempdir.NewWithPrefix`'s cleanup closure (`internal/tempdir/tempdir.go:42-46`): `os.RemoveAll(dir.path)` — i.e. it removes only the temp repo directory (`newRepoDir.Path()`), not its parent. Any file written via a `../` traversal escapes `newRepoDir.Path()` and is never touched by this cleanup, so it survives the failed/rolled-back RPC.

No other check intervenes: `repoutil.Create` never inspects or restricts what `seedRepository` writes to disk, and there is no tar-entry-name validation (no `filepath.Clean`/prefix check) anywhere in the untar path.

### Impact Explanation
An unprivileged user who can control `HttpUrl` (or a service configured to fetch from) can leave attacker-controlled files inside Gitaly's shared per-storage temp directory (`+gitaly/tmp/...`) even though the RPC ultimately fails and reports an error. This matches the GitLab bounty "arbitrary file write" / storage-path-escape impact class, though scoped only to the temp directory tree under the storage root rather than an arbitrary filesystem location, since `tar -C path` bounds the traversal to ancestors of `path` reachable via relative `../` segments in the tar stream, and `path` itself is confined by `locator.TempDir`/`GetRepoPath`. Concretely, this results in residual orphaned files (potential disk exhaustion, name-squatting for subsequent temp directories, or confusing/poisoning artifacts other RPCs may later read from the shared temp root) that persist despite the RPC reporting failure.

### Likelihood Explanation
Fully attacker-controlled and reproducible: the attacker only needs to control the content served at `HttpUrl` (already an explicit trust boundary acknowledged in the code) and does not need any elevated privilege beyond invoking `CreateRepositoryFromSnapshot` with a URL they control. Making the second tar entry corrupt/truncated to force a non-zero `tar` exit is trivial and deterministic.

### Recommendation
Sanitize tar entries before/while extracting: reject archives containing entries whose cleaned path escapes the destination directory (e.g., extract using a Go tar reader that validates each header's `Name` via `filepath.IsLocal`/prefix-checking against `path` before writing, instead of shelling out to `tar` unsanitized), and/or pass `tar` additional hardening flags (e.g. `--no-absolute-names`) and reject `..` components before invocation. Additionally, make cleanup on `repoutil.Create` failure defensive against escapes, or run the extraction inside a securely-created, uniquely-namespaced sandbox directory that is fully removed regardless of relative escapes (e.g., verify no new top-level entries appeared outside the temp dir, or extract into a chroot/mount namespace).

### Proof of Concept
```go
// internal/gitaly/service/repository/create_repository_from_snapshot_test.go (illustrative addition)
func TestCreateRepositoryFromSnapshot_tarTraversalLeavesResidueOnFailure(t *testing.T) {
    // Serve a tar stream:
    //   1) valid-looking entry "../leftover-file" (escapes the extraction dir)
    //   2) truncated/corrupt second header, causing `tar` to exit non-zero
    srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        tw := tar.NewWriter(w)
        hdr := &tar.Header{Name: "../leftover-file", Mode: 0o600, Size: int64(len("pwned"))}
        require.NoError(t, tw.WriteHeader(hdr))
        _, _ = tw.Write([]byte("pwned"))
        // Do not close tw / write a valid second header — flush truncated bytes to break tar mid-stream.
        _, _ = w.Write([]byte{0x1f, 0x00, 0x00}) // garbage causing tar to fail
    }))
    defer srv.Close()

    // ... invoke CreateRepositoryFromSnapshot with HttpUrl: srv.URL ...
    _, err := client.CreateRepositoryFromSnapshot(ctx, &gitalypb.CreateRepositoryFromSnapshotRequest{
        Repository: repo,
        HttpUrl:    srv.URL,
    })
    require.Error(t, err) // RPC fails as expected

    // Assertion: walk the storage's temp root and confirm no "leftover-file" survived.
    tempRoot := filepath.Join(cfg.Storages[0].Path, "+gitaly/tmp")
    found := false
    _ = filepath.WalkDir(tempRoot, func(path string, d fs.DirEntry, err error) error {
        if d != nil && d.Name() == "leftover-file" {
            found = true
        }
        return nil
    })
    require.False(t, found, "attacker-controlled file survived failed CreateRepositoryFromSnapshot rollback")
}
```
Expected (vulnerable) result: `found == true` — the `leftover-file` persists under the storage's temp root despite the RPC returning an error, demonstrating that `repoutil.Create`'s rollback (`os.RemoveAll(newRepoDir.Path())`) does not remove files written outside the temporary repository directory via tar path traversal. ```go
func NewWithPrefix(ctx context.Context, storageName, prefix string, logger log.Logger, locator storage.Locator) (Dir, func(), error) {
	dir, err := newDirectory(ctx, storageName, prefix, logger, locator)
	if err != nil {
		return Dir{}, nil, err
	}

	cleanup := func() {
		if err := os.RemoveAll(dir.path); err != nil {
			logger.WithError(err).WithField("temporary_directory", dir.path).ErrorContext(ctx, "failed to cleanup temp dir")
		}
	}

	return dir, cleanup, nil
}
