### Title
Fee bypass on Nep245/Imt tokens by splitting a bulk transfer into unit-amount `TokenDiff` legs - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` exempts Nep245 (multi-token) and Imt token deltas from protocol fees only when the per-intent `amount <= 1`, and `TokenDiff::execute_intent` computes and collects this fee independently for every executed `TokenDiff` intent rather than for the aggregate delta a signer moves across a batch. An attacker can split a bulk transfer of `K` units of the same Nep245/Imt token id into `K` separate `TokenDiff` intents each with `delta = -1`, so every leg hits the `amount <= 1` exemption and the batch collects zero fee instead of `Pips::fee_ceil(K)`.

### Finding Description
The broken binding: for a signer moving total negative delta `-K` on token `T` in a batch, the intended invariant is
`sum(fees_collected for T across the batch) == protocol_fee.fee_ceil(K)`.
Instead, when the `-K` is expressed as `K` separate `TokenDiff` intents each with `delta = -1`, the actual result is `sum(fees_collected for T) == 0`.

Code path: `TokenDiff::execute_intent` [1](#0-0)  iterates over `self.diff` (a `BTreeMap<TokenId, i128>` local to one `TokenDiff` intent) and for each negative delta computes `Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` using only that intent's own `amount`. `token_fee` explicitly zeroes the fee for `Nep245`/`Imt` when `amount <= 1`: [2](#0-1) 

Each `TokenDiff` is executed independently inside `Engine::execute_signed_intent`, which loops over all intents in a `MultiPayload` (or across multiple `MultiPayload`s in one `execute_intents`/`simulate_intents` call) via `intents.execute_intent(&signer_id, self, hash)` [3](#0-2) . There is no aggregation of per-token deltas across intents before computing `token_fee`; the only cross-intent invariant enforced is `TransferMatcher::finalize`, which only checks that total deposits/withdrawals per token net to zero across the whole batch (including the fee-collector's deposit) — it does not check that the correct *amount* of fee was deposited [4](#0-3) .

Attacker's payload: a single (or a small set of) `MultiPayload`(s) whose `DefuseIntents.message` contains `K` `TokenDiff` intents, each with `diff = {T: -1}`, matched by a counterparty (or the attacker's own other account/leg in the same batch) supplying the corresponding `+1` deposits per leg so the batch invariant nets to zero, exactly as in the existing `swap_p2p`/`solver_user_closure` test patterns [5](#0-4) . Because each leg's `amount` is exactly `1`, `token_fee` returns `Pips::ZERO` for every leg, so `fees_collected` stays empty and `internal_add_balance` to the fee collector is never invoked, versus a single `TokenDiff{diff: {T: -K}}` which would charge `protocol_fee.fee_ceil(K)`.

None of the existing guards prevent this: `MultiPayload::verify`/nonce checks only bind signature and replay, not fee aggregation; `TransferMatcher::finalize` only checks the sum of deposits/withdrawals nets to zero, which is satisfied identically whether or not the fee was collected (the counterparty simply needs to supply `K` instead of `K - fee`).

### Impact Explanation
Fee under-collection scales linearly with the number of 1-unit legs an attacker uses to represent a bulk Nep245/Imt token transfer, directly harming `fee_collector`, matching the "protocol fees bypassed" Critical category. Any signer able to construct a `TokenDiff`-based swap (self-swap, matched with a cooperating counterparty, or any repeatable trading flow) can repeat this per-token per-batch, with no requirement for elevated privileges — only a normal signer with a positive Nep245/Imt balance. The blast radius covers any deployment where `fee() > 0` and Nep245/Imt tokens are traded through `TokenDiff` in meaningful bulk quantities.

### Likelihood Explanation
Preconditions are minimal: a signer holding `K` units of a Nep245/Imt token, a `fee_collector` configured with `protocol_fee > 0`, and any counterparty (even the attacker's own second account) able to complete the batch's zero-sum requirement. The attack costs only the gas for signing/executing `K` intents in one or a few `execute_intents` calls, which is fully within an unprivileged user's capability, and is repeatable for every batch and every Nep245/Imt token traded.

### Recommendation
Compute `token_fee` based on the aggregate per-token, per-signer negative delta across the whole batch (or at minimum across all `TokenDiff` intents signed by the same `signer_id` within one call to `execute_intents`), rather than per individual `TokenDiff` intent's own `amount`. Alternatively, remove or tighten the `amount <= 1` exemption for `Nep245`/`Imt` so that it is determined by the underlying token's semantics (e.g., only apply the exemption when the specific `token_id` is known to be non-fungible/one-of-a-kind), not simply by the per-intent transferred quantity.

### Proof of Concept
`near-workspaces`/sandbox test (extends `tests/src/tests/defuse/intents/token_diff.rs` style):
1. Deploy a Nep245 (multi-token) contract, deposit `K = 1000` units of token id `T` to `user1`, configure `env` with `fee = Pips::ONE_PERCENT` and a `fee_collector`.
2. Case A: `user1` and `user2` sign a single `TokenDiff{diff: {T: -1000, ...matching credit...}}` swap so the batch nets to zero; execute via `env.defuse_execute_intents`; assert `fee_collector`'s balance of `T` increases by `Pips::ONE_PERCENT.fee_ceil(1000)`.
3. Case B: `user1` and `user2` sign `1000` separate `TokenDiff` intents (or one payload with 1000 `TokenDiff` entries), each `{T: -1}` matched by corresponding `+1` legs from `user2`, netting the batch to zero; execute; assert `fee_collector`'s balance of `T` increases by `0`.
4. Assert Case B's fee-collector credit is strictly less than Case A's (`0 < Pips::ONE_PERCENT.fee_ceil(1000)`), proving the fee-under-collection binding is broken.

    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }

    }
