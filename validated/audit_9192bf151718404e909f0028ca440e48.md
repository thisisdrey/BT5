### Title
Cheap, self-refreshing streams let an unstaked peer evade `prune_oldest` eviction, prolonging QoS-favored connection slot occupancy - ([File: streamer/src/nonblocking/quic.rs])

### Summary
The reported bug is a "prolong distribution via cheap repeated calls" pattern: an unprivileged actor keeps resetting a time-based state variable with a minimal-cost action, defeating the intended fairness of a time-ordered mechanism. The Agave QUIC streamer has an analogous mechanism: unstaked connection slots are reclaimed by evicting the connection with the oldest `last_update` timestamp, but any peer can refresh that timestamp arbitrarily cheaply by finishing a trivial stream, letting it dodge eviction indefinitely.

### Finding Description
`ConnectionTable::prune_oldest` selects the connection(s) with the minimum `last_update` across the table and evicts them when the table exceeds capacity: [1](#0-0) 

`last_update` (an `Arc<AtomicU64>` timestamp stored per `ConnectionEntry`) is refreshed every time a stream on that connection finishes, via the `on_stream_finished` QoS callback: [2](#0-1) 
(equivalently in `SimpleQos`) [3](#0-2) 

For unstaked (unprivileged) connections, `prune_oldest` is invoked from `prune_unstaked_connections_and_add_new_connection` whenever a new connection needs to be admitted and the unstaked table is at capacity, in order to make room by removing the "stalest" existing connection: `SwQos::try_add_connection` routes both staked-overflow and unstaked peers through this path. [4](#0-3) 

Because `last_update` is refreshed on every finished stream regardless of stream size/cost, an unstaked attacker holding a connection can periodically open and close a trivially small stream (a single tiny write, well within the unstaked per-connection stream allowance under `throttle_stream`) purely to bump its `last_update` value. This is directly analogous to the reported bug's `distribute(1)` call: a negligible-cost action resets the timer that governs a fairness/eviction mechanism, letting the actor indefinitely postpone the "distribution"/eviction event that should otherwise occur based on elapsed idle time.

### Impact Explanation
This lets one or more unstaked, low-value connections perpetually occupy slots in the unstaked connection table by staying "fresh," causing genuinely new/legitimate unstaked connection attempts to be rejected (`try_add_connection` returns `None`, `connection_add_failed_unstaked_node` increments) or forcing staked-peer overflow connections that fall back to the unstaked table to be evicted instead, since `prune_oldest` will always pick some *other* stale entry, biasing which peers keep access. This is a QoS-evasion effect: capacity meant to rotate fairly among unstaked peers can be monopolized cheaply, degrading availability for other unstaked clients attempting to reach the validator's QUIC ingest path. It does not cause a panic or memory blowup and the table sizes remain bounded, so the impact is limited to fairness/availability degradation for unstaked peers rather than validator compromise.

### Likelihood Explanation
Any unprivileged peer can open a QUIC connection classified as unstaked and is only required to send trivial streams periodically (bounded by `STREAM_THROTTLING_INTERVAL`/`max_streams_per_throttling_interval` for unstaked peers) to keep `last_update` current. No special stake or permission is needed, and the cost per refresh is minimal (one tiny stream), mirroring the "few wei" cost of the original report.

### Recommendation
Consider bounding how much a single connection's `last_update` can be "refreshed" relative to real elapsed connection age, e.g., track connection creation time separately and factor it into the pruning key (age-since-creation and/or total bytes/streams served) instead of relying solely on most-recent-activity, or apply a minimum idle-refresh cost (e.g., only count refreshes tied to meaningful stream volume) similar to the original recommendation of requiring a minimum distribution amount.

### Proof of Concept
1. Establish an unstaked QUIC connection to the validator's TPU QUIC endpoint.
2. Open and immediately close a minimal single-byte unidirectional stream at an interval just under the point where the connection would otherwise be considered "oldest" (each closure triggers `on_stream_finished`, updating `last_update` via `timing::timestamp()`).
3. When `SwQos::try_add_connection`/`prune_unstaked_connections_and_add_new_connection` runs `prune_oldest` to admit new unstaked connections, this refreshed connection is skipped for eviction because its `last_update` is never the minimum, while genuinely idle/newer connections attempting to join get rejected or other entries get evicted instead.     pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }
