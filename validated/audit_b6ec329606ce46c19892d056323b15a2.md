## Analog Found: Symlink-following file overwrite in VM trace file writer

### Title
Unvalidated symlink-following write in VM program trace file handler - (File: actuator/src/main/java/org/tron/core/vm/VMUtils.java)

### Summary
`VMUtils.createProgramTraceFile()` and `VMUtils.saveProgramTraceFile()` build a trace-file path from an attacker-known, attacker-derived transaction hash and write to it using the plain `File`/`FileOutputStream` APIs, which transparently follow symbolic links, without ever checking whether the target path is a symbolic link.

### Finding Description
When `vm.vmTrace` is enabled, every smart-contract execution routed through `VMActuator` computes the transaction hash and calls `VMUtils.saveProgramTraceFile(txHash, traceContent)`: [1](#0-0) 

`createProgramTraceFile()` resolves the target as `./vm_trace/{txHash}.json`. If the file already `exists()`, and `isFile()`/`canWrite()` return true, it is reused as-is — with no `isSymbolicLink()`/`NOFOLLOW_LINKS` check anywhere in this path: [2](#0-1) 

`writeStringToFile()` then opens a plain `FileOutputStream(file)`, which follows the symlink at the OS level and writes the serialized VM trace JSON through it to whatever target the link points to: [3](#0-2) 

The transaction hash used as the filename is fully deterministic from the transaction's raw data before it is ever broadcast, so an attacker can compute it offline. If the attacker has (or obtains, e.g. via any other local/shared-write primitive on the node's working directory) the ability to plant a single file at `./vm_trace/{predicted_txHash}.json` as a symbolic link pointing at a sensitive file the node process can write (config file, another database file, a keystore, etc.), then simply broadcasting the ordinary contract-triggering transaction whose hash matches that filename causes the node to write attacker-influenced VM-trace content through the symlink into the target file — the same bug class as the pwnlift upload-handler symlink-following CVE (predictable/attacker-controlled path + no symlink check + blind write).

Note that this codebase elsewhere (e.g. `KeystoreCliUtils.readKeystoreFile`, `WalletUtils.warnIfSymbolicLink`) explicitly hardens against exactly this class of bug for keystore file I/O, but the VM trace writer in the hot transaction-execution path was not hardened the same way.

### Impact Explanation
An attacker who can plant a single symlink under the node's `vm_trace` output directory and subsequently broadcast one ordinary transaction can force the node to overwrite an arbitrary file it has write access to, with content it fully or partially controls (the trace JSON reflects the executed opcodes/results of the attacker's own contract call). Depending on the symlink target this can corrupt operational database files, config, or other node state, causing crashes, halted operation, or data corruption on the node — satisfying "node crash or halt" impact criteria.

### Likelihood Explanation
Requires: (1) `vm.vmTrace = true`, which is off by default (`vmTrace = false` in `reference.conf`) — matching the "privileged deployment" precondition of the original CVE; and (2) some pre-existing local write access to the node's working directory to plant the symlink. Given those preconditions, triggering the overwrite itself requires only a single ordinary, unprivileged transaction broadcast with a precomputed hash — no special permissions on-chain are needed for the triggering step.

### Recommendation
In `VMUtils.createProgramTraceFile`, resolve the target file with `Files.readAttributes(path, BasicFileAttributes.class, LinkOption.NOFOLLOW_LINKS)` and refuse to use/write the file if `attrs.isSymbolicLink()` (or if it's not a regular file), mirroring the pattern already used in `KeystoreCliUtils.readKeystoreFile`. Write via `Files.newByteChannel(path, EnumSet.of(StandardOpenOption.WRITE, StandardOpenOption.CREATE), ...)` combined with `LinkOption.NOFOLLOW_LINKS`-based pre-checks instead of the symlink-following `FileOutputStream`.

### Proof of Concept
1. Ensure `vm.vmTrace = true` on the target node (operator/deployment configuration).
2. Attacker (with some local write access to the node's working directory, e.g. a co-located low-privilege process) precomputes the hash `H` of a transaction they intend to broadcast (transaction hash is deterministic from raw transaction bytes and is known before submission).
3. Attacker creates `./vm_trace/H.json` as a symbolic link pointing to a sensitive file the tron node process can write (e.g. another database/config file inside the node's data directory).
4. Attacker broadcasts the transaction (any contract call/deployment) so its hash equals `H`.
5. During execution, `VMActuator` invokes `VMUtils.saveProgramTraceFile(H, traceContent)`, which finds the existing "file" at `./vm_trace/H.json`, confirms it is `isFile()`/`canWrite()` (true through the symlink), and writes the trace JSON through the symlink into the sensitive target file, overwriting its contents.

```java
  private static File createProgramTraceFile(String txHash) {
    File result = null;

    if (VMConfig.vmTrace()) {

      File file = new File(new File("./", "vm_trace"), txHash + ".json");

      if (file.exists()) {
        if (file.isFile() && file.canWrite()) {
          result = file;
        }
      } else {
        try {
          file.getParentFile().mkdirs();
          if (!file.createNewFile()) {
            logger.error("failed to create file {}", file.getPath());
          }
          result = file;
        } catch (IOException e) {
          // ignored
        }
      }
    }

    return result;
  }
```

```java
  private static void writeStringToFile(File file, String data) {
    OutputStream out = null;
    try {
      out = new FileOutputStream(file);
      if (data != null) {
        out.write(data.getBytes("UTF-8"));
      }
    } catch (Exception e) {
      logger.error(format("Cannot write to file '%s': ", file.getAbsolutePath()), e);
    } finally {
      closeQuietly(out);
    }
  }

  public static void saveProgramTraceFile(String txHash, String content) {
    File file = createProgramTraceFile(txHash);
    if (file != null) {
      writeStringToFile(file, content);
    }
  }
```
