### Title
`TokenDiff::token_fee` returns `Pips::ZERO` for `TokenId::Imt` legs with `amount <= 1`, letting a signer split any large IMT balance into unit-amount `TokenDiff` intents to bypass protocol fees entirely - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` charges the configured `Pips` fee on an `Imt` (and `Nep245`) leg only `if amount > 1`; for `amount == 1` it unconditionally returns `Pips::ZERO`. Because fee is computed per signed `TokenDiff` intent on that intent's own `delta.unsigned_abs()`, and `execute_intents` never nets deltas across multiple signed intents in a batch before charging fees, an unprivileged signer can convert one large negative delta `-N` on an `Imt` token id into `N` separate signed `TokenDiff` intents each with delta `-1`, causing every leg to hit the `amount <= 1` zero-fee branch and paying zero fee on the full notional `N`.

### Finding Description
The binding that should hold is: `fees_collected(imt_token_id) == Pips::fee_ceil(protocol_fee, total_negative_delta(imt_token_id))` for the aggregate exposure a signer settles against `imt_token_id` within one `execute_intents` call.

In `TokenDiff::execute_intent` (`contracts/defuse/core/src/intents/token_diff.rs:59-78`), for each `(token_id, delta)` pair in a single `TokenDiff.diff` map, if `delta < 0` the fee is computed as:
```
let amount = delta.unsigned_abs();
let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
``` [1](#0-0) 

`token_fee` is:
```rust
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
``` [2](#0-1) 

`TokenId::Imt` supports arbitrary `u128` balances (`ImtTokens = Amounts<BTreeMap<..., u128>>`, minted via `ImtMint::execute_intent` → `engine.state.imt_mint`), so it is used to represent fungible-style balances, not just unique NFT-like items. [3](#0-2) [4](#0-3) 

Fee computation happens per-intent, per-leg, based only on that leg's own `delta`. There is no cross-intent aggregation of deltas on the same `token_id` within one `execute_intents` batch before the `if *delta < 0` fee branch runs, so a batch of N signed `TokenDiff` intents each carrying `{imt_token_id: -1}` (paired with whatever positive out-leg the attacker wants) causes `token_fee` to hit the `amount <= 1 → Pips::ZERO` branch N times, for a total collected fee of `0`, versus `Pips::fee_ceil(fee, N)` if the same `-N` had been expressed as a single `TokenDiff` leg.

None of the existing guards (`MultiPayload::verify`, nonce/`VersionedNonce` checks, `SaltRegistry`, `Lock`, `TransferMatcher::finalize`) prevent this: each of the N intents has its own distinct nonce and valid signature, so all N can be included and executed in one `execute_intents` call.

### Impact Explanation
The `fee_collector` account is credited `Pips::ZERO` instead of `Pips::fee_ceil(protocol_fee, N)` for the aggregate `-N` exposure the signer actually settles on the `Imt` token id, for any `N` the attacker chooses (bounded only by their IMT balance). This is a systematic protocol-fee bypass on Imt (and equally Nep245) token diffs, repeatable by any signer with an `Imt` balance, across any number of tokens and batches, matching the "protocol fees bypassed or over-collected" Critical category.

### Likelihood Explanation
Preconditions are trivial for any unprivileged account: mint or otherwise acquire a large `TokenId::Imt` balance under one `imt:<minter_id>:<token_id>` (self-mintable via `ImtMint`), then sign N `TokenDiff` intents each moving `-1` unit of that token id (matched by some counter-intent or self-consistent closure) inside one `execute_intents` call. Cost is only the extra transaction/gas overhead of N small intents instead of one; there is no capital cost or role requirement. Fully repeatable per account/token/batch.

### Recommendation
Compute the fee-eligible `amount` from the aggregate negative delta across the whole batch for a given `token_id` (or track total per-signer supply movement per token id across the entire `execute_intents` call) rather than per single `TokenDiff` intent leg, before applying the `amount <= 1` zero-fee exemption for `Nep245`/`Imt`.

### Proof of Concept
`cargo test` (unit test in `defuse-core`, or `near-workspaces`/sandbox test in `tests/src/tests/defuse`):
1. Mint an `Imt` balance of `N` (e.g. `N = 100`) to a signer via `ImtMint`.
2. Set a nonzero protocol `fee` (e.g. `Pips::ONE_PERCENT`).
3. Path A: sign and execute a single `TokenDiff { imt_token_id: -N, other_token: +M }`; record `fee_collector` balance of `imt_token_id` afterward — assert it equals `fee.fee_ceil(N)`.
4. Path B (fresh state, same starting balances): sign and execute N separate `TokenDiff { imt_token_id: -1, other_token: +m }` intents (with distinct nonces) inside one `execute_intents` call; record `fee_collector` balance of `imt_token_id` afterward.
5. Assert `fee_collector` balance from Path B `== 0` while Path A `> 0`, proving `fees_collected != Pips::fee_ceil(fee, N)` for the same aggregate notional, violating the binding.
