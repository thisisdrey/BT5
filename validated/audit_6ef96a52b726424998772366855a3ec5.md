### Title
Protocol fee bypass on Nep245/Imt tokens by splitting a large diff into many amount=1 `TokenDiff` intents - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` exempts `Nep245`/`Imt` token deltas from any fee whenever `amount <= 1`, and this check is evaluated per `TokenDiff::execute_intent` call on that intent's own `delta`, with no aggregation across intents in the same or different batches. A signer moving `N` units of the same `Nep245`/`Imt` token can therefore submit `N` separate `TokenDiff` intents each with `|delta| == 1` instead of one intent with `|delta| == N`, causing the cumulative fee collected to be `0` instead of `fee.fee_ceil(N)`.

### Finding Description
Broken binding: `fee_collected(1 intent, delta = -N) == Σ fee_collected(N intents, each delta = -1)` for the same `Nep245`/`Imt` `token_id`, where `protocol_fee = engine.state.fee() > 0`.

In `execute_intent` [1](#0-0) , for each negative delta in the diff the fee is computed as:
```
let amount = delta.unsigned_abs();
let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
```
`token_fee` is:
```rust
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
``` [2](#0-1) 

The `amount` argument is scoped strictly to the single intent being executed — it is `delta.unsigned_abs()` for that one `TokenDiff`'s entry, not a running total across the signer's nonces or across the batch. `execute_intent` is invoked once per `TokenDiff` intent inside a `MultiPayload` (see loop over intents in the batch, `contracts/defuse/src/contract/intents/mod.rs` / `contracts/defuse/src/intents.rs`), and each invocation independently recomputes `protocol_fee` and independently decides whether to charge it. The `TransferMatcher`/`Deltas` machinery [3](#0-2)  only nets balances into actual transfers for settlement — it runs after fees are already computed and collected per-intent, and it does not net "amount" for fee-eligibility purposes.

Exploit: an attacker (or two colluding accounts, including the same person's two accounts) holding `N` units of a `Nep245`/`Imt` sub-token signs `N` separate `TokenDiff` intents, each `diff = {token_id: -1}` (paired with an offsetting `+1` on the same or another leg to satisfy the batch's zero-sum `TransferMatcher::finalize` invariant), instead of one `TokenDiff` with `diff = {token_id: -N}`. Each of the `N` calls computes `Self::token_fee(token_id, 1, protocol_fee) == Pips::ZERO` because `amount > 1` is false, so `fee_ceil(1) == 0` every time. The one-intent equivalent would compute `Self::token_fee(token_id, N, protocol_fee) == protocol_fee` (nonzero) and `fee_ceil(N) > 0`. No existing guard (`MultiPayload::verify`, nonce checks, `TransferMatcher::finalize`, `assert_one_yocto`) inspects or aggregates the `amount` used for the fee-exemption threshold across intents, so the divergence is not caught anywhere in the call path.

### Impact Explanation
The fee collector (`engine.state.fee_collector()`) receives strictly less than it is owed on the aggregate volume moved, whenever `protocol_fee > 0` and the split uses `N > 1` unit-sized `TokenDiff` intents on a `Nep245`/`Imt` token instead of one intent with `amount = N`. This is a protocol-fee-bypass finding (explicitly listed Critical category). It is fully repeatable: any account holding a `Nep245`/`Imt` balance can apply this to any amount and any token by simply issuing more, smaller signed intents; the fee due asymptotically approaches zero relative to volume as the split factor increases, with total bypassed fee up to `fee.fee_ceil(N)` per exploited swap. No other party's funds are stolen directly — the effect is under-collection of protocol revenue that would otherwise be credited to the fee collector, at signer/attacker's exclusive benefit (they still get to complete the same net token movement).

### Likelihood Explanation
Preconditions: a nonzero `protocol_fee` configured on the Verifier, and a signer (or a signer plus counterparty they control) with a `Nep245`/`Imt` balance large enough that a normal single intent would cross the `amount > 1` threshold. No privileged role is needed — only the ability to sign `DefusePayload`s and call `execute_intents`/`simulate_intents`, both available to any unprivileged NEAR account. The only cost is more transactions (higher NEAR gas), which is bounded and does not require any circumvented rate limiting. This is trivially and cheaply repeatable across tokens, accounts and amounts.

### Recommendation
Compute the `Nep245`/`Imt` fee-exemption threshold on the aggregated per-token, per-signer volume across the whole batch (or remove the `amount <= 1` fee-exemption special case entirely and always apply `fee.fee_ceil(amount)` for these token types, letting genuinely single-unit NFT-like transfers pay a negligible/rounded fee via `fee_ceil` rounding rather than an unconditional `Pips::ZERO`). At minimum, aggregate deltas per `(signer_id, token_id)` across all intents in a `MultiPayload` before evaluating `token_fee`'s `amount` threshold, rather than evaluating it per individual `TokenDiff` intent.

### Proof of Concept
```rust
// contracts/defuse/core/src/intents/token_diff.rs (or a new integration test)
#[test]
fn split_bypasses_nep245_fee() {
    let token_id = TokenId::from(Nep245TokenId::new(
        "mt.near".parse().unwrap(), "ft1".to_string(),
    ));
    let fee = Pips::ONE_PERCENT; // nonzero protocol fee

    // Single intent equivalent: amount = 100
    let single_fee = TokenDiff::token_fee(&token_id, 100, fee).fee_ceil(100);
    assert!(single_fee > 0);

    // Split into 100 intents, each amount = 1
    let split_total_fee: u128 = (0..100)
        .map(|_| TokenDiff::token_fee(&token_id, 1, fee).fee_ceil(1))
        .sum();
    assert_eq!(split_total_fee, 0);

    // Binding violated: split fee strictly less than single-intent fee
    assert!(split_total_fee < single_fee);
}
```
An end-to-end `near-workspaces` sandbox test can additionally drive `execute_intents` with 100 signed `TokenDiff` intents (each `{token_id: -1}` matched by an offsetting `+1` leg to satisfy `TransferMatcher::finalize`) versus one signed `TokenDiff` intent with `{token_id: -100}`, and assert the fee collector's post-execution `Nep245` balance differs between the two scenarios despite identical net token movement.
