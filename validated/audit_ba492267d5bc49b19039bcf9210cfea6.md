### Title
Unsanitized attacker-controlled length used for array allocation and data extraction in precompiled contract ABI decoding - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
`PrecompiledContracts.extractBytes32Array`, `extractBytesArray`, and `extractSigArray` read a "length" word directly out of the caller-supplied calldata (`words[offset].intValueSafe()`) and immediately use it to allocate a `byte[len][]` and to compute subsequent offsets into the raw `data` buffer, mirroring the CVE-2018-7225 pattern of trusting an unsanitized length field from an untrusted message before using it to size/access memory.

### Finding Description
`extractBytes32Array` takes `len` straight from `words[offset].intValueSafe()` with no upper bound and no check that `offset + len` stays within the `words` array: [1](#0-0) 

`extractBytesArray` and `extractSigArray` only guard the initial `offset`, not the loop bound derived from the attacker-controlled `len`, and then feed further attacker-controlled `bytesOffset`/`bytesLen` values into `extractBytes`, which does an unchecked `Arrays.copyOfRange`: [2](#0-1) 

Because `intValueSafe()` merely clamps a 256-bit word into the `int` range (it does not bound it to the actual size of `words`/`data`), a caller can set the length word to an arbitrarily large value (up to `Integer.MAX_VALUE`). This is used to:
- Allocate `new byte[len][]`, which for a large `len` attempts to allocate on the order of gigabytes of reference storage before any data has even been validated.
- Index `words[offset + i + 1]` past the actual `words.length`, throwing `ArrayIndexOutOfBoundsException`.
- Compute negative or absurd offsets/lengths passed to `Arrays.copyOfRange(data, offset, offset + len)`, which throws unchecked exceptions (`ArrayIndexOutOfBoundsException`, `NegativeArraySizeException`) on malformed input.

This is structurally the same bug class as CVE-2018-7225: a length field taken from an untrusted message is used to size/access a buffer without first validating it against the bounds of the actual payload.

### Impact Explanation
These helpers back the `ValidateMultiSign` and `BatchValidateSign` precompiled contracts, which are reachable by any unprivileged smart contract call (any account can invoke a precompile address from a deployed/triggered contract). A crafted call with an oversized length word can trigger an attempted multi-gigabyte allocation (`OutOfMemoryError`) or an unchecked runtime exception deep inside precompile execution. If such an `Error`/uncaught exception is not fully absorbed by the general precompiled-contract exception handling in the VM's `callToPrecompiledAddress` path, it can propagate out of transaction execution, causing that transaction's execution thread to abort abnormally rather than cleanly reverting — a node stability/availability risk (DoS) triggerable by any account, at the cost of the energy paid for the call. This is a resource/robustness issue in code reachable from any signed transaction that calls the precompile, not merely a local revert.

### Likelihood Explanation
High: the input is directly controlled by calldata supplied in the transaction (`TriggerSmartContract`) targeting the fixed precompile addresses for `ValidateMultiSign`/`BatchValidateSign`. No special privileges, keys, or SR/witness status are required — only the ability to broadcast a transaction that calls the precompile with crafted ABI-encoded arguments.

### Recommendation
Bound every length read from `words`/`data` against the true remaining size of `words` and `data` before allocating arrays or computing derived offsets in `extractBytes32Array`, `extractBytesArray`, and `extractSigArray` (similar to the bounds checks already present in `RLP.verifyLength` and `ContractEventParser.subBytes`), and wrap/validate so malformed lengths cause a controlled `Pair.of(false, ...)` failure rather than an uncaught allocation failure or array exception.

### Proof of Concept
1. Deploy any contract and call the `ValidateMultiSign` (or `BatchValidateSign`) precompiled contract address directly via `TriggerSmartContract` (any unprivileged account can do this).
2. Craft the ABI-encoded input so that the word at the expected array-length offset is set to a very large value (e.g., `0x7FFFFFFF`), while the actual calldata is short.
3. `extractBytesArray`/`extractSigArray` will read this length via `intValueSafe()` and attempt `new byte[len][]`, or index `words[offset + i + 1]` beyond the real array, immediately raising `OutOfMemoryError`/`ArrayIndexOutOfBoundsException` during precompile execution for that single transaction.

Note: I could not fully trace, within the available indexed context, whether the outer VM invocation wrapper (`Program.callToPrecompiledAddress`) catches `Throwable`/`Error` broadly enough to always contain an `OutOfMemoryError` from this path; this should be verified directly against `actuator/src/main/java/org/tron/core/vm/program/Program.java` in a full session, as it determines whether the impact is limited to a single transaction revert versus a broader node-level disruption.

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }

  private static byte[][] extractSigArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          SIG_LENGTH);
    }
    return bytesArray;
  }

  private static byte[] extractBytes(byte[] data, int offset, int len) {
    return Arrays.copyOfRange(data, offset, offset + len);
  }
