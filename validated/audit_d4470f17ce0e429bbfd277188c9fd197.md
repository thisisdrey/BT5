### Title
Unsigned integer underflow in reftable block-length parsing causes out-of-bounds panic (DoS) - (File: internal/git/reftable/reftable.go)

### Summary
`Table.parseRefBlock` and `Table.getBlockRange` in Gitaly's reftable reader compute buffer offsets by subtracting attacker/remote-influenced length fields from other size values using unsigned (`uint`) arithmetic. If the subtrahend exceeds the minuend — which can happen when a reftable block is truncated, corrupted, or crafted with an inconsistent `RestartCount`/block-length — the subtraction wraps around to a huge value instead of erroring out, exactly analogous to the reported `_calculateMaxBorrowCollateral` bug where a limit is naively reduced by a percentage without checking for underflow. In Go this wraparound does not "revert" — it silently produces a huge offset that is then used to slice a byte buffer, causing an out-of-bounds panic.

### Finding Description
`getBlockRange` computes the end of a block as `t.footerOffset - offset` [1](#0-0) . More critically, `parseRefBlock` computes the restart-table start as:

```go
b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)
``` [2](#0-1) 

`currentBS` is read directly from file bytes via `extractBlockLen` (a 3-byte big-endian value taken from the block header) [3](#0-2) , and `b.RestartCount` is likewise read directly from file bytes near the end of the block [4](#0-3) . Neither value is validated against the other before the subtraction. If `currentBS < 2 + 3*RestartCount` (e.g. due to a truncated/corrupted/malformed reftable, which can be produced by fetching from an untrusted remote or importing a repository), the expression underflows because `uint` arithmetic wraps instead of going negative. The resulting `RestartStart` becomes an enormous value, which is then used as a loop bound and slice index in `getRefsFromBlock` (e.g. `idx < b.RestartStart`, `src[idx:idx+suffixLength]`) [5](#0-4) , producing an out-of-bounds slice access and a Go runtime panic.

This is the direct analog of the reported bug class: a limit/threshold is derived by subtracting a variable amount from another variable amount without an underflow guard, and because the subtraction happens in an unsigned/fixed-width type, the result silently becomes an enormous (wrapped) value rather than failing safely — in Solidity this reverts the transaction, in Go this causes a panic/crash of the handling goroutine.

### Impact Explanation
`Table.GetReferences()` (which triggers `parseRefBlock`) is exercised by production code paths that read reftable-backend repositories, including the WAL/transaction machinery (`internal/gitaly/storage/storagemgr/partition/reftable.go`, which calls `reftable.ParseTable`/`ReadTablesList` during reference-transaction staging) [6](#0-5) . Reftable files can enter a repository via fetches/imports from remote URLs (e.g., `FetchRemote`, which stages fetched data through a quarantine directory before migrating it into the target repo) [7](#0-6) . A corrupted or malformed reftable delivered this way — whether due to network truncation, a buggy/malicious upstream Git server, or an unusual reftable layout not covered by the parser's assumptions — can trigger the panic described above when Gitaly subsequently reads references from it, denying service to the RPC handler (and, if the panic occurs on a background/goroutine path without gRPC panic-recovery middleware, potentially crashing the Gitaly process).

### Likelihood Explanation
Likelihood is moderate-to-low: the reftable format is normally written by Git itself and is expected to be well-formed. However, unlike in the original DeFi report where the underflow required only a benign external state change, here the underflow requires a malformed/corrupted table (e.g. truncated download, disk write failure, or the process being interrupted mid-write). Since Gitaly reads reftables coming from remote/imported repositories without doing origin-independent structural validation of `currentBS` vs. `RestartCount` before performing the subtraction, any such corruption converts a normal parsing error into an unrecovered arithmetic underflow and a hard crash rather than a graceful error return.

### Recommendation
Before computing `b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)`, validate that `currentBS >= 2 + 3*uint(b.RestartCount)` (and similarly validate `offset + size` vs `footerOffset` in `getBlockRange`, and all other offset arithmetic in the reftable parser) and return a descriptive parse error instead of allowing the unsigned subtraction to wrap. Apply the same underflow-guard pattern used correctly elsewhere in the codebase (e.g., bounds checks already present in `getVarInt`) throughout `reftable.go`.

### Proof of Concept
Not verifiable without a live environment: constructing a byte-exact malformed `.ref` reftable file that passes header/footer CRC32 validation (`parseFooter`, `crc32.ChecksumIEEE`) [8](#0-7)  yet has an inconsistent `currentBS`/`RestartCount` pair in a ref block would confirm the panic. This would require binary crafting and running `Table.GetReferences()` against it, which is outside the scope of static analysis here.

func parseFooter(reader io.Reader, f *footer) error {
	footerBytes, err := io.ReadAll(reader)
	if err != nil {
		return fmt.Errorf("read all: %w", err)
	}

	footerReader := bytes.NewReader(footerBytes)
	if err := parseHeader(footerReader, &f.header); err != nil {
		return fmt.Errorf("parse header: %w", err)
	}

	if err := binary.Read(footerReader, binary.BigEndian, &f.footerEnd); err != nil {
		return fmt.Errorf("parse remainder: %w", err)
	}

	if crc32.ChecksumIEEE(footerBytes[:len(footerBytes)-binary.Size(f.CRC32)]) != f.CRC32 {
		return errors.New("checksum mismatch")
	}

	return nil
}

func (t *Table) getBlockRange(offset, size uint) (uint, uint) {
	if offset >= t.footerOffset {
		return 0, 0
	}

	if offset+size > t.footerOffset {
		size = t.footerOffset - offset
	}

	return offset, offset + size
}

// parseRefBlock parses a block and if it is a ref block, provides
// all the reference updates.
func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)

	fullBlockSize := t.blockSize
	if fullBlockSize == 0 {
		fullBlockSize = currentBS
	} else if currentBS < fullBlockSize && currentBS < (blockEnd-blockStart) && src[blockStart+currentBS] != 0 {
		fullBlockSize = currentBS
	}

	b := &block{
		BlockStart:    blockStart + headerOffset,
		FullBlockSize: fullBlockSize,
	}

	if err := binary.Read(bytes.NewBuffer(src[blockStart+currentBS-2:]), binary.BigEndian, &b.RestartCount); err != nil {
		return nil, fmt.Errorf("reading restart count: %w", err)
	}

	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)

	return t.getRefsFromBlock(src, b)
}
