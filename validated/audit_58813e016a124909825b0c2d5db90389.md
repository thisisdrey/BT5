### Title
Unauthenticated POST to `/v3/blocks/upload/` triggers unconditional P2P relay, bypassing the broadcast=1 auth gate - ([File: stackslib/src/net/api/postblock_v3.rs])

### Summary
`RPCPostBlockRequestHandler::try_parse_request` only requires the configured secret when the caller explicitly sets `broadcast=1`, silently allowing unauthenticated uploads with `self.broadcast=Some(false)`. However, `try_handle_request` ignores `self.broadcast` entirely when deciding whether to queue the block for P2P relay, so any accepted block — authenticated or not — is unconditionally handed to `node.set_relay_message`.

### Finding Description
The intended invariant expressed by the code in `try_parse_request` is: broadcasting to the network requires authentication. [1](#0-0) 

That invariant is enforced only at parse time (rejecting `broadcast=1` without auth), and `self.broadcast` is stored purely as a bookkeeping flag passed down to `Relayer::process_new_nakamoto_block_ext` as an `announce`-style parameter: [2](#0-1) 

Critically, the code that actually forwards the block to the node's outbound relay queue does not consult `self.broadcast` at all — it fires solely off `data_resp.accepted`: [3](#0-2) 

So the exploit path is: attacker POSTs `/v3/blocks/upload/` with no `authorization` header and no `broadcast=1` query arg (satisfying the parse-time auth gate trivially, since neither is required in that case), body is a syntactically valid, consensus-acceptable `NakamotoBlock`. `try_parse_request` sets `self.block = Some(block)`, `self.broadcast = Some(false)`. `try_handle_request` calls `Relayer::process_new_nakamoto_block_ext(..., false)`; if the chainstate/consensus layer accepts the block (i.e. `data_resp.accepted == true`), the `if data_resp.accepted` branch unconditionally queues `StacksMessageType::NakamotoBlocks` via `node.set_relay_message`, regardless of the `broadcast` value that was just computed to gate exactly this behavior. The equality the endpoint's own auth logic implies — "block reaches P2P peers only if the request carried the secret with `broadcast=1`" — is broken because the relay trigger only checks acceptance, not the broadcast/authentication flag.

### Impact Explanation
Any remote, unauthenticated party who can reach the node's RPC port can cause the node to unconditionally relay a block over P2P to all its peers, without ever supplying the configured RPC secret. This turns an endpoint whose access-control was clearly designed to gate network propagation behind authentication into a no-auth trigger for that same propagation, matching "network-wide propagation ... triggered by a fully unauthenticated request." It does not allow injecting a block that fails chain-validation (the block must still pass `Relayer::process_new_nakamoto_block_ext`'s acceptance checks), but it does let unauthenticated callers force the node to act as an involuntary relay/amplifier for any block they can get accepted, defeating the intended broadcast authorization control.

### Likelihood Explanation
- Precondition: node has `RPCPostBlockRequestHandler::auth` configured (i.e., operator believes unauthenticated relay is blocked).
- Attacker needs only network reachability to the RPC port — no secret, no peer/StackerDB privilege.
- Repeatable per accepted block; cost is producing/obtaining one consensus-valid `NakamotoBlock` body.
- The bug is deterministic and code-visible (no race or timing dependency): the `if data_resp.accepted` block simply never reads `self.broadcast`/`data_resp` broadcast intent.

### Recommendation
Gate the relay in `try_handle_request` on `self.broadcast` as well as `data_resp.accepted`, e.g.:
```rust
if data_resp.accepted && self.broadcast.unwrap_or(false) {
    node.set_relay_message(...);
}
```
This restores the intended equality that P2P relay only happens for authenticated `broadcast=1` requests.

### Proof of Concept
In `stackslib::net::api::tests::postblock_v3`, construct a `TestRPC`/`StacksNodeState` harness with `RPCPostBlockRequestHandler::new(Some("secret".into()))`. Send a `try_parse_request` call with:
- no `authorization` header,
- `query = None` (no `broadcast=1`),
- body = a valid serialized `NakamotoBlock` that will be accepted by the test chainstate fixture.

Assert `handler.broadcast == Some(false)`. Then call `try_handle_request` against a mocked `StacksNodeState`/relayer where `process_new_nakamoto_block_ext` returns an "accepted" result, and assert that `node.pop_relayer_event()` (or equivalent inspection of the relay-message queue) contains a `StacksMessageType::NakamotoBlocks` — demonstrating relay occurred despite `broadcast == Some(false)` and no auth header being present.
