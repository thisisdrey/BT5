Audit Report

## Title
`SwapFirstAssetTrader::refund_weight` executes an unbounded-slippage swap with `amount_out_min = None`, allowing fee refunds to be drained via pool-price manipulation - (File: `cumulus/primitives/utility/src/lib.rs`)

## Summary
`SwapFirstAssetTrader` is a live `WeightTrader` wired into the `Trader` tuple of `AssetHubRococo`, `AssetHubWestend`, `Penpal`, and `staking-async` parachain runtimes to let users pay XCM execution fees in a non-`Target` asset via `pallet_asset_conversion`. Its `refund_weight` function converts the unused portion of `total_fee` back into the user's original asset by calling `SwapCredit::swap_exact_tokens_for_tokens(..., None)`, omitting any minimum-output/slippage bound, unlike `buy_weight` and `quote_weight`, which both compute or enforce an expected exchange amount.

## Finding Description
`refund_weight` extracts the unused `Target`-asset credit and swaps it into the asset used in the last `buy_weight` call: [1](#0-0) 

Passing `None` as `amount_out_min` reaches `pallet_asset_conversion::do_swap_exact_credit_tokens_for_tokens`, where both output-sufficiency checks are gated behind `amount_out_min.map_or(true, ...)`. When `amount_out_min` is `None`, both `ensure!` checks trivially evaluate to `true`, so the `ProvidedMinimumNotSufficientForSwap` guard is entirely skipped and the swap succeeds regardless of how little output the pool returns: [2](#0-1) 

By contrast, `buy_weight` uses `swap_tokens_for_exact_tokens` to obtain a specific fee amount, and the `SingleAssetExchangeAdapter` used by XCM's `ExchangeAsset` instruction always supplies `Some(want_amount)` as an explicit floor when doing a "swap exact tokens for tokens", confirming that omitting the minimum in `refund_weight` is an outlier deviation from the established pattern elsewhere in the codebase, rather than an intentional design choice.

`SwapFirstAssetTrader` is confirmed to be referenced/configured in `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/xcm_config.rs`, `cumulus/parachains/runtimes/assets/asset-hub-westend/src/xcm_config.rs`, `cumulus/parachains/runtimes/testing/penpal/src/xcm_config.rs`, and `substrate/frame/staking-async/runtimes/parachain/src/xcm_config.rs`, matching the live-configuration claim.

## Impact Explanation
This affects the "assets ... must conserve value and settle exactly once to the rightful beneficiary and amount" invariant on a code path reachable by any XCM message that overestimates its `BuyExecution` weight limit and pays fees in a non-`Target` asset through `SwapFirstAssetTrader`. Because the refund swap has no minimum-output enforcement, a pool-price manipulation immediately before the refund executes can cause the sender to receive an arbitrarily small refund instead of the fair-rate amount, with the difference captured as arbitrage by whoever moved the pool. This is a systemic pricing-integrity flaw in a fee-refund primitive deployed on multiple live parachain runtimes, not a test-only or mock-only issue.

## Likelihood Explanation
Exploitation requires only ordinary permissionless actions: submitting a large swap against the same `pallet_asset_conversion` pool in the same block as the refund-triggering XCM message, which any unprivileged user with the assets to move the pool can do. Every overestimated-weight XCM message that pays fees in a non-`Target` asset via `SwapFirstAssetTrader` is a candidate for this attack, making the vulnerability repeatable and not dependent on validator, collator, or governance privilege.

## Recommendation
Compute an expected minimum acceptable refund via `QuotePrice::quote_price_exact_tokens_for_tokens` (mirroring how `quote_weight` already calls `QuotePrice::quote_price_tokens_for_exact_tokens`) and pass `Some(min_acceptable_amount)` into `swap_exact_tokens_for_tokens` inside `refund_weight`. If the quote cannot guarantee an acceptable minimum, the refund swap should be skipped and the `Target` asset credit retained/returned instead of accepting an unbounded-slippage swap.

## Proof of Concept
1. Configure a runtime with `SwapFirstAssetTrader<Target=DOT, ...>` (as in `AssetHubRococo`/`AssetHubWestend`) with a `DOT`/`USDT` pool in `pallet_asset_conversion`.
2. Submit an XCM message with an inflated `BuyExecution` weight limit, paying in `USDT`; `buy_weight` swaps `USDT → DOT` to cover the estimated fee, leaving a large unused `total_fee` in `DOT` for refund.
3. In the same block, execute a large `USDT → DOT` swap against the same pool immediately before the refund is processed, depressing the `DOT → USDT` rate.
4. `refund_weight` calls `swap_exact_tokens_for_tokens(vec![DOT, USDT], refund, None)` at `cumulus/primitives/utility/src/lib.rs:540-544`; since `amount_out_min` is `None`, `do_swap_exact_credit_tokens_for_tokens` at `substrate/frame/asset-conversion/src/lib.rs:1075-1109` skips the `ProvidedMinimumNotSufficientForSwap` check and the swap succeeds despite returning far less `USDT` than fair value.
5. The original sender receives a diminished refund while the pool-manipulating party recoups the difference by reversing their trade after the refund executes, extracting value with no error or revert.

		pub(crate) fn do_swap_exact_credit_tokens_for_tokens(
			path: Vec<T::AssetKind>,
			credit_in: CreditOf<T>,
			amount_out_min: Option<T::Balance>,
		) -> Result<CreditOf<T>, (CreditOf<T>, DispatchError)> {
			let amount_in = credit_in.peek();
			let inspect_path = |credit_asset| {
				ensure!(
					path.first().map_or(false, |a| *a == credit_asset),
					Error::<T>::InvalidPath
				);
				ensure!(!amount_in.is_zero(), Error::<T>::ZeroAmount);
				ensure!(amount_out_min.map_or(true, |a| !a.is_zero()), Error::<T>::ZeroAmount);

				Self::validate_swap_path(&path)?;
				let path = Self::balance_path_from_amount_in(amount_in, path)?;

				let amount_out = path.last().map(|(_, a)| *a).ok_or(Error::<T>::InvalidPath)?;
				ensure!(
					amount_out_min.map_or(true, |a| amount_out >= a),
					Error::<T>::ProvidedMinimumNotSufficientForSwap
				);
				Ok((path, amount_out))
			};
			let (path, amount_out) = match inspect_path(credit_in.asset()) {
				Ok((p, a)) => (p, a),
				Err(e) => return Err((credit_in, e)),
			};

			let credit_out = Self::credit_swap(credit_in, &path)?;

			Self::deposit_event(Event::SwapCreditExecuted { amount_in, amount_out, path });

			Ok(credit_out)
		}
