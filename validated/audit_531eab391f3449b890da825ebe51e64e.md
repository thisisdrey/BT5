### Title
`DebtToken.issue` bypasses the `isActive` deactivation gate enforced on all other issuance paths - ([File: contracts/DebtToken.sol](contracts/DebtToken.sol))

### Summary
Analogous to the Parse Server advisory (a parallel endpoint that skips the authorization gate its siblings enforce), `DebtToken.issue` omits the `onlyIfDebtTokenIsActive` / `onlyIfSyntheticTokenIsActive` modifiers that guard the other two debt-issuance entry points (`mint` and `flashIssue`). When governance deactivates a debt token to halt new borrowing against a market, an unprivileged user can keep issuing synthetic debt through `issue`.

### Finding Description
The debt-issuance surface has three entry points:

- `issue(amount_, to_)` — permissionless, collateral-checked issuance. Modifiers: `whenNotShutdown nonReentrant onlyIfSyntheticTokenExists` (contracts/DebtToken.sol:235-244). **No `onlyIfDebtTokenIsActive` check.**
- `flashIssue(to_, amount_)` — gated by `onlyIfSmartFarmingManager` **and** `onlyIfDebtTokenIsActive` (contracts/DebtToken.sol:281-292).
- `mint(to_, amount_)` — gated by `onlyIfSmartFarmingManager` **and** `onlyIfSyntheticTokenIsActive` (contracts/DebtToken.sol:328-339).

`DebtToken` exposes `toggleIsActive` (governor-only) and an `onlyIfDebtTokenIsActive` modifier precisely so issuance can be halted per-market — the same role `beforeFind`/`afterFind` play as an access gate in the advisory. `issue` skips that gate entirely. Additionally, `issue` does not check `syntheticToken.isActive()` up front; it is only caught indirectly inside `SyntheticToken._mint`, whereas the sibling paths check it explicitly.

The lock/health checks do not close the gap: `issue` still enforces `debtPositionOf` collateral sufficiency and `whenNotShutdown`, so the bypass only manifests when the debt token (not the whole pool, not the synthetic token) is deactivated.

### Impact Explanation
`toggleIsActive` on `DebtToken` is the per-market kill switch for new debt. If governance deactivates a debt token — e.g., to stop issuance of a synth whose collateral/oracle profile turned toxic, or to deprecate a market — any unprivileged EOA can continue issuing new debt via `issue`, `Operator.execute`-batched `issue` calls, or gateway flows. This defeats the intended freeze and can grow protocol debt exposure that governance explicitly tried to halt, a path toward protocol insolvency if deactivation was risk-motivated. It is not direct theft: issuance remains collateralized by `debtPositionOf`.

### Likelihood Explanation
Requires a state where `isActive == false` on a debt token while the pool is not shut down — a deliberate governance action, but one with a well-defined purpose (halting issuance). Once in that state, exploitation is trivially repeatable by any EOA calling `issue`. The gap is reachable purely through public entry points.

### Recommendation
Add `onlyIfDebtTokenIsActive` (and `onlyIfSyntheticTokenIsActive` for consistency) to `issue`, matching the modifier set on `flashIssue` and `mint`, so deactivating a debt token reliably blocks all issuance paths.

### Proof of Concept
Hardhat sketch against deployed fixtures:

```ts
// Setup: pool with depositToken + debtToken, alice deposits collateral
await debtToken.connect(governor).toggleIsActive(); // isActive = false

// Sanity: privileged paths are blocked
await expect(debtToken.connect(sfm).flashIssue(alice.address, 1)).to.be.revertedWith("DebtTokenInactive");

// Bypass: permissionless issuance still succeeds
await depositToken.connect(alice).deposit(collateralAmount, alice.address);
await debtToken.connect(alice).issue(synthAmount, alice.address); // succeeds despite isActive == false

assert((await syntheticToken.balanceOf(alice.address)).gt(0));
```

If the intended severity bar is direct theft/insolvency only and continued collateralized issuance is deemed acceptable behavior, this reduces to an inconsistency; otherwise it is a live gate bypass reachable by any unprivileged caller.
