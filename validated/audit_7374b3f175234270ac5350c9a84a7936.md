## Title
Unauthenticated unbounded HTTP body read in the signer's event-receiver causes unbounded memory allocation (DoS) - (File: `libsigner/src/events.rs`)

### Summary
The `stacks-signer` binary runs an HTTP server (`SignerEventReceiver`) that listens for event POSTs normally sent by a trusted `stacks-node` event dispatcher. This server performs no authentication and no request-body size cap: `process_event` reads the entire POST body into memory with `read_to_string` before any length check or JSON validation, and is bound on a socket address that operator-facing reference configuration explicitly sets to a non-loopback interface (`0.0.0.0:30000`). This is the same bug class as the reported MCP Ruby SDK issue: unbounded `request.body.read` + `JSON.parse` with no size limit before authentication/session validation.

### Finding Description
`SignerEventReceiver::bind` starts a `tiny_http::Server` on the configured `endpoint` [1](#0-0) . `next_event` dispatches incoming requests purely by URL path (`/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, `/new_block`, `/shutdown`, `/status`) with **no authentication check of any kind** — unlike the node-side RPC endpoints (e.g. `RPCPostStackerDBChunkRequestHandler`, `RPCBlockProposalRequestHandler`) which require a password/auth header [2](#0-1) .

For every recognized POST path, `process_event` is called, which reads the full request body into a `String` with no size limit before doing anything else:
```
let mut body = String::new();
if let Err(e) = request.as_reader().read_to_string(&mut body) { ... }
``` [3](#0-2) 

There is no `Content-Length` pre-check and no bound passed to the reader — the entire attacker-controlled body is materialized in memory before `serde_json::from_slice` is even attempted. This mirrors exactly the root cause in the external report (`body_string = request.body.read` with no cap, followed by unbounded `JSON.parse`).

Compare this to the node's own inbound HTTP/JSON-RPC surface, `stackslib/src/net/httpcore.rs`, `poststackerdbchunk.rs`, `postblock_proposal.rs`, `postfeerate.rs`, and `fastcallreadonly.rs`, all of which check `preamble.get_content_length()` against `MAX_PAYLOAD_LEN`/`MAX_MESSAGE_LEN`/`maximum_call_argument_size` *before* touching the body [4](#0-3) [5](#0-4) . The signer's event listener has no equivalent guard.

Reference configuration shipped in the repo directs operators to bind this listener to `0.0.0.0`, i.e., a publicly/remotely reachable address, rather than `127.0.0.1`:
```
endpoint = "0.0.0.0:30000"
``` [6](#0-5) 

### Impact Explanation
Any remote, unauthenticated party that can reach the signer's event port (which the shipped reference config explicitly exposes on all interfaces) can send a single oversized `POST /stackerdb_chunks` (or any of the other recognized paths) and force the signer process to allocate memory proportional to the request body size, with no upper bound. This can exhaust the process's memory and crash or hang the `stacks-signer` process — a signer availability/DoS impact, achievable with a handful of unauthenticated requests, matching the "Critical - remote crash/unauthenticated DoS from few messages" bucket.

### Likelihood Explanation
No authentication, no size limit, and a single HTTP request suffices — the only precondition is TCP reachability to the configured `endpoint`, which the project's own reference configuration sets to `0.0.0.0`. This makes exploitation straightforward for any attacker who can reach the port.

### Recommendation
Enforce a maximum request-body size before calling `read_to_string`/`read_to_end` in `process_event` (e.g., check `request.body_length()` against a constant such as `BLOCK_RESPONSE_DATA_MAX_SIZE` or a new dedicated cap, and use a bounded reader such as `Read::take(limit)`), and reject/drain-and-close oversized requests early. Consider also requiring a shared-secret/auth check on this listener, consistent with the node-side RPC handlers, since it currently trusts any peer that can connect.

### Proof of Concept
1. Configure a `stacks-signer` with `endpoint = "0.0.0.0:30000"` (as in the shipped `sample/conf/signer/mainnet-signer-conf.toml`).
2. From a remote host, open a TCP connection to port 30000 and send:
   ```
   POST /stackerdb_chunks HTTP/1.1
   Host: <signer-ip>:30000
   Content-Type: application/json
   Content-Length: <N, e.g. 500000000>
   Connection: close

   <N bytes of arbitrary/junk data>
   ```
3. `process_event` will call `read_to_string` on the entire body before any parsing occurs, allocating ~N bytes of process memory regardless of whether the JSON is valid, with no rejection based on size. Repeating this (or sending one very large body) drives the signer's memory usage up, potentially crashing the process — with no credentials or prior interaction required.

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;
