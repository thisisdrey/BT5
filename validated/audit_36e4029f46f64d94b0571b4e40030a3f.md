### Title
Unchecked chunk size causes slice-bounds panic in `suffixarray.Index.Read` when parsing untrusted serialized index data - ([File: src/index/suffixarray/suffixarray.go])

### Summary
`index/suffixarray`'s `Index.Read` deserializes a previously-written suffix array index from an `io.Reader`. The internal helper `readSlice` reads an attacker-controlled `size` value and uses it directly as a slice upper bound (`buf[binary.MaxVarintLen64:size]`) without checking that `size >= binary.MaxVarintLen64`, so a crafted/corrupted input with a small `size` value triggers a runtime "slice bounds out of range" panic instead of returning the intended `errCorrupted` error.

### Finding Description
The public entry point is `(*Index).Read(r io.Reader) error` [1](#0-0) , which any caller can invoke on data it did not itself produce (e.g. loading a previously persisted/serialized suffix-array index from disk or from a network peer). `Read` calls `readSlice(r, buf, sa, uint64(n))` in a loop [2](#0-1) .

Inside `readSlice`, the buffer-size field is read via `readInt` and only validated for being non-negative and fitting in an `int`:
```
size64, err = readInt(r, buf)
if int64(int(size64)) != size64 || int(size64) < 0 {
    return 0, errCorrupted
}
size := int(size64)
if _, err = io.ReadFull(r, buf[binary.MaxVarintLen64:size]); err != nil {
``` [3](#0-2) 

There is no check that `size >= binary.MaxVarintLen64` (10). If the attacker supplies a `size` in the range `0..9`, the expression `buf[binary.MaxVarintLen64:size]` becomes `buf[10:size]` with `size < 10`, i.e. a slice expression whose low bound exceeds its high bound. This is a Go runtime invariant violation and panics with "slice bounds out of range" rather than being handled as the intended corrupted-data error path (the same class of "failed to validate before using value as bound" bug as the reported Solidity `withdraw` underflow, just manifesting as a Go slice-bounds panic instead of an arithmetic underflow revert).

### Impact Explanation
Any process that calls `Index.Read` on data it received from an external/untrusted source (a normal expected usage of this serialization API — the package explicitly supports `Write`/`Read` round-tripping of a persisted index) can be crashed by a single crafted byte sequence, causing a denial of service (unrecovered panic) in that process. This falls under Go's PUBLIC track as a parser panic on malicious input, consistent with Go's security policy allowing "a real server panic or plausible malicious-input parser panic" to qualify.

### Likelihood Explanation
The victim workflow is simply calling the documented `Index.Read` method to load a suffix-array index (e.g., restoring a previously saved search index) — a normal, unprivileged consumption of externally-sourced data, no special privileges or trusted-code assumptions required. The attacker only needs to supply/replace the bytes that are fed into `Read`.

### Recommendation
In `readSlice`, validate that `size >= binary.MaxVarintLen64` (in addition to the existing bounds/negativity checks) before slicing `buf[binary.MaxVarintLen64:size]`, returning `errCorrupted` when the check fails.

### Proof of Concept
```go
package suffixarray

import (
	"bytes"
	"encoding/binary"
	"testing"
)

// TestReadSliceSmallSizePanics demonstrates that readSlice panics on a
// crafted "size" field smaller than binary.MaxVarintLen64, instead of
// returning errCorrupted.
func TestReadSliceSmallSizePanics(t *testing.T) {
	buf := make([]byte, bufSize)

	// Encode a "size" value of 1 (less than binary.MaxVarintLen64==10).
	var sizeBuf [binary.MaxVarintLen64]byte
	binary.PutVarint(sizeBuf[:], 1)

	r := bytes.NewReader(sizeBuf[:])

	defer func() {
		if r := recover(); r == nil {
			t.Fatalf("expected panic due to invalid slice bounds, got none")
		}
	}()

	// data with len()==0 to keep the call simple; maxIndex arbitrary.
	_, _ = readSlice(r, buf, int32s(nil), 0)
}
```
Expected result today: the call panics with `runtime error: slice bounds out of range [10:1]` inside `readSlice`, rather than returning `(0, errCorrupted)`.

// Read reads the index from r into x; x must not be nil.
func (x *Index) Read(r io.Reader) error {
	// buffer for all reads
	buf := make([]byte, bufSize)

	// read length
	n64, err := readInt(r, buf)
	if err != nil {
		return err
	}
	if int64(int(n64)) != n64 || int(n64) < 0 {
		return errCorrupted
	}
	n := int(n64)

	// allocate space
	if 2*n < cap(x.data) || cap(x.data) < n || x.sa.int32 != nil && n > maxData32 || x.sa.int64 != nil && n <= maxData32 {
		// new data is significantly smaller or larger than
		// existing buffers - allocate new ones
		x.data = make([]byte, n)
		x.sa.int32 = nil
		x.sa.int64 = nil
		if n <= maxData32 {
			x.sa.int32 = make([]int32, n)
		} else {
			x.sa.int64 = make([]int64, n)
		}
	} else {
		// re-use existing buffers
		x.data = x.data[0:n]
		x.sa = x.sa.slice(0, n)
	}

	// read data
	if _, err := io.ReadFull(r, x.data); err != nil {
		return err
	}

	// read index
	sa := x.sa
	for sa.len() > 0 {
		n, err := readSlice(r, buf, sa, uint64(n))
		if err != nil {
			return err
		}
		sa = sa.slice(n, sa.len())
	}
	return nil
