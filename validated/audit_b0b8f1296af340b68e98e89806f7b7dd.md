### Title
Admin interest-rate config changes are applied retroactively to already-elapsed accrual periods - ([File: programs/marginfi/src/instructions/marginfi_group/configure_bank.rs])

### Summary
`lending_pool_configure_bank` and `lending_pool_configure_bank_interest_only` update a bank's `interest_rate_config` without first calling `accrue_interest`. Because `accrue_interest` computes interest for the *entire* elapsed `time_delta` since `bank.last_update` using whatever `interest_rate_config` is active at the time it is called, any config update made between two accrual calls is applied retroactively to time that already elapsed under the old configuration — the exact bug class described in the external report for Zaros funding rates.

### Finding Description
`Bank::accrue_interest` in `programs/marginfi/src/state/bank.rs` computes `time_delta = current_timestamp - self.last_update` and then derives the lending/borrowing/fee rates from `self.config.interest_rate_config` (via `create_interest_rate_calculator`) and applies them uniformly over the whole `time_delta`: [1](#0-0) 

`interest_rate_config` is not versioned or checkpointed by time — it is a single mutable struct on the bank. The admin-only instruction `lending_pool_configure_bank` calls `bank.configure(&bank_config)`, which mutates `self.config.interest_rate_config` directly, with **no prior call to `accrue_interest`**: [2](#0-1) 

The same is true for the scoped `lending_pool_configure_bank_interest_only` instruction (used by the `delegate_curve_admin` role), which updates the interest curve/fee parameters directly without accruing first: [3](#0-2) 

Because `bank.last_update` is untouched by the configure instructions, the next time any user interaction (deposit/withdraw/borrow/repay/liquidate) or the permissionless `lending_pool_accrue_bank_interest` triggers `accrue_interest`, the full elapsed period since the last accrual — including time that passed *before* the admin's config change — is charged/credited at the **new** rate parameters, not the rate that was actually in effect during that historical period. This mirrors the reported Zaros issue: fees/funding that "accrue" and settle lazily on next interaction are computed with whatever configuration is live at settlement time rather than the configuration that applied during each sub-interval.

### Impact Explanation
Any change to `interest_rate_config` (curve `points`, `zero_util_rate`, `hundred_util_rate`, `protocol_ir_fee`, `insurance_ir_fee`, fixed APR fees, etc.) via `lending_pool_configure_bank` or `lending_pool_configure_bank_interest_only` retroactively re-prices the entire un-accrued interest window for every depositor and borrower in that bank:
- Borrowers who have not interacted with their position recently can be retroactively charged a higher borrow rate than was ever actually posted during most of the elapsed period, potentially pushing accounts into unexpected liquidation or bad debt.
- Depositors can be retroactively shorted interest they believed was accruing at the previously configured rate.
- This is an unauthorized state change to user balances (via share value math) driven by a config update, producing outcomes users did not consent to and could not react to — a core-accounting fairness/integrity issue in the bank's interest engine, not merely a UX inconvenience.

Given marginfi's continuous per-second compounding model (unlike Zaros' periodic funding accrual), the retroactive misapplication window can span the entire time since the last user/permissionless accrual on that bank, which is unbounded if no one interacts with the bank or calls `lending_pool_accrue_bank_interest`.

### Likelihood Explanation
This does not require any attacker interaction — it is triggered any time an admin (group admin or `delegate_curve_admin`) legitimately updates interest-rate parameters on an active bank, which is an expected/normal operational action (rate curve tuning, fee adjustments). The affected code path (`configure` / `configure_bank_lite.rs`) is reachable on every production bank and is not gated by any "accrue first" check. Because the flaw is baked into ordinary parameter-update tooling rather than requiring an exploit, it is highly likely to manifest whenever rates are adjusted while positions are outstanding and un-accrued.

### Recommendation
Force an `accrue_interest` call (settling all pending interest at the currently-active rate config and refreshing `last_update`) as the first step of both `lending_pool_configure_bank` and `lending_pool_configure_bank_interest_only`, before applying any changes to `interest_rate_config`. This ensures any new curve/fee parameters only apply prospectively from the moment of the config change, consistent with how `lending_pool_emissions_deposit` already accrues before mutating share values.

### Proof of Concept
1. Bank has outstanding deposits/liabilities; `last_update = T0`.
2. No user interaction and no call to `lending_pool_accrue_bank_interest` for a long window (e.g., 30 days).
3. At `T0 + 15 days`, group admin (or `delegate_curve_admin`) calls `lending_pool_configure_bank` / `lending_pool_configure_bank_interest_only` to raise `hundred_util_rate`/curve `points` (increasing the borrow APR). This mutates `bank.config.interest_rate_config` directly per: [4](#0-3) 
   without updating `last_update`.
4. At `T0 + 30 days`, any user action (e.g. a borrower repaying, or a permissionless caller invoking `lending_pool_accrue_bank_interest`) triggers `accrue_interest`, which computes `time_delta = 30 days` and applies the **new (post-day-15) interest rate** to the full 30-day period, per: [5](#0-4) 
5. Borrowers are thus charged the higher rate for the first 15 days too, even though the old (lower) rate was in effect and displayed to them during that time — directly analogous to the PoC in the external report where a mid-period config change changed the amount ultimately paid for a period that had already partially elapsed under different parameters.

    fn accrue_interest(
        &mut self,
        current_timestamp: i64,
        group: &MarginfiGroup,
        #[cfg(not(feature = "client"))] bank: Pubkey,
    ) -> MarginfiResult<()> {
        #[cfg(all(not(feature = "client"), feature = "debug"))]
        sol_log_compute_units();

        let time_delta: u64 = (current_timestamp - self.last_update).try_into().unwrap();
        if time_delta == 0 {
            return Ok(());
        }

        let total_assets = self.get_asset_amount(self.total_asset_shares.into())?;
        let total_liabilities = self.get_liability_amount(self.total_liability_shares.into())?;

        self.last_update = current_timestamp;

        if (total_assets == I80F48::ZERO) || (total_liabilities == I80F48::ZERO) {
            #[cfg(not(feature = "client"))]
            emit!(LendingPoolBankAccrueInterestEvent {
                header: GroupEventHeader {
                    marginfi_group: self.group,
                    signer: None
                },
                bank,
                mint: self.mint,
                delta: time_delta,
                fees_collected: 0.,
                insurance_collected: 0.,
            });

            return Ok(());
        }
        let ir_calc = self
            .config
            .interest_rate_config
            .create_interest_rate_calculator(group);

        let InterestRateStateChanges {
            new_asset_share_value: asset_share_value,
            new_liability_share_value: liability_share_value,
            insurance_fees_collected,
            group_fees_collected,
            protocol_fees_collected,
        } = calc_interest_rate_accrual_state_changes(
            time_delta,
            total_assets,
            total_liabilities,
            &ir_calc,
            self.asset_share_value.into(),
            self.liability_share_value.into(),
        )?;

pub fn lending_pool_configure_bank_interest_only(
    ctx: Context<LendingPoolConfigureBankInterestOnly>,
    interest_rate_config: InterestRateConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;
    msg!(
        "Configuring bank: {:?} mint: {:?}",
        ctx.accounts.bank.key(),
        bank.mint
    );

    // If settings are frozen, interest rates can't update.
    if bank.get_flag(FREEZE_SETTINGS) {
        msg!("WARN: Bank settings frozen, did nothing.");
    } else {
        bank.config
            .interest_rate_config
            .update(&interest_rate_config);
        bank.config.interest_rate_config.validate()?;
        msg!("Bank configured!");
    }

    Ok(())
}

pub fn calc_interest_rate_accrual_state_changes(
    time_delta: u64,
    total_assets_amount: I80F48,
    total_liabilities_amount: I80F48,
    interest_rate_calc: &InterestRateCalc,
    asset_share_value: I80F48,
    liability_share_value: I80F48,
) -> MarginfiResult<InterestRateStateChanges> {
    // If the cache is empty, we need to calculate the interest rates
    let utilization_rate: I80F48 = total_liabilities_amount
        .checked_div(total_assets_amount)
        .ok_or_else(math_error!())?;
    debug!(
        "Utilization rate: {}, time delta {}s",
        utilization_rate, time_delta
    );
    let interest_rates = interest_rate_calc.calc_interest_rate(utilization_rate)?;

    debug!("{:#?}", interest_rates);

    let ComputedInterestRates {
        lending_rate_apr,
        borrowing_rate_apr,
        group_fee_apr,
        insurance_fee_apr,
        protocol_fee_apr,
        ..
    } = interest_rates;

    Ok(InterestRateStateChanges {
        new_asset_share_value: calc_accrued_interest_payment_per_period(
            lending_rate_apr,
            time_delta,
            asset_share_value,
        )
        .ok_or_else(math_error!())?,
        new_liability_share_value: calc_accrued_interest_payment_per_period(
            borrowing_rate_apr,
            time_delta,
            liability_share_value,
        )
        .ok_or_else(math_error!())?,
        insurance_fees_collected: calc_interest_payment_for_period(
            insurance_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
        group_fees_collected: calc_interest_payment_for_period(
            group_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
        protocol_fees_collected: calc_interest_payment_for_period(
            protocol_fee_apr,
            time_delta,
            total_liabilities_amount,
        )
        .ok_or_else(math_error!())?,
    })
}
