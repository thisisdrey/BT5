### Title
Integer overflow in `FreezeBalanceProcessor.execute()` expire-time calculation due to missing `frozenDuration` bounds check - (File: `actuator/src/main/java/org/tron/core/vm/nativecontract/FreezeBalanceProcessor.java`)

### Summary
The TVM native "freeze balance" contract entry point (`FreezeBalanceProcessor`), which any deployed contract can invoke via the native staking precompile path, computes `expireTime = nowInMs + param.getFrozenDuration() * FROZEN_PERIOD` without any bound or overflow check on `frozenDuration`. Unlike the account-level `FreezeBalanceActuator`, which validates `frozenDuration` against `minFrozenTime`/`maxFrozenTime`, `FreezeBalanceProcessor.validate()` performs no such check, mirroring the root cause of the referenced Hyperlane bug where an unclamped duration value fed into a time addition caused an overflow. [1](#0-0) 

### Finding Description
`FreezeBalanceProcessor.validate()` checks `frozenBalance` bounds, `frozenCount`, resource type, and delegation rules, but never validates `param.getFrozenDuration()`: [2](#0-1) 

`execute()` then computes the expire timestamp with an unchecked multiplication and addition:
```
long expireTime = nowInMs + param.getFrozenDuration() * FROZEN_PERIOD;
``` [3](#0-2) 

By contrast, the account-level `FreezeBalanceActuator.validate()` bounds `frozenDuration` between `minFrozenTime` and `maxFrozenTime` (subject to a `needCheckFrozeTime` config flag used mainly for tests), and `AssetIssueActuator` was hardened post-hoc with an explicit `StrictMathWrapper.addExact` overflow guard for its own expire-time computation after VERSION_4_8_1: [4](#0-3) [5](#0-4) 

`FreezeBalanceProcessor`, however, received no equivalent hardening, leaving the native-contract (TVM) freeze path with an attacker-controlled multiplicand (`frozenDuration`) that is fed directly into the addition used to derive `expireTime` for both self-freeze (`setFrozenForBandwidth`/`setFrozenForEnergy`) and delegated freeze (`delegateResource` → `DelegatedResourceCapsule.addFrozenBalanceForBandwidth/Energy`).

### Impact Explanation
If `frozenDuration` is large enough that `frozenDuration * FROZEN_PERIOD` overflows a `long`, or the subsequent addition of `nowInMs` overflows, `expireTime` can wrap to a small or negative value. Because unfreeze logic elsewhere in the codebase compares `expireTime <= now` to determine unlock eligibility (e.g., `UnfreezeBalanceV2Processor.unfreezeExpire` and analogous BandwidthProcessor/EnergyProcessor logic), a wrapped, already-past `expireTime` would make funds that are supposed to be locked for the specified duration immediately eligible for unfreeze, letting a caller effectively bypass the freeze lock period. This falls under unauthorized/premature release of otherwise-locked TRX (a funds-freezing/economic-invariant violation) reachable purely through contract execution — no privileged role required.

### Likelihood Explanation
Reachability requires only a contract that invokes the native freeze-balance functionality with an attacker-chosen `frozenDuration` argument — the same call path any TVM contract can use to freeze/delegate resources. Since `frozenDuration` is entirely attacker-supplied and unconstrained in `FreezeBalanceProcessor.validate()`, triggering the overflow requires no special permissions, only a malformed/oversized duration argument in an ordinary transaction.

### Recommendation
Add explicit bounds checking on `frozenDuration` in `FreezeBalanceProcessor.validate()` mirroring `FreezeBalanceActuator` (`minFrozenTime`/`maxFrozenTime`), and additionally guard the multiplication/addition in `execute()` with overflow-safe arithmetic (e.g., `Math.multiplyExact`/`Math.addExact` or the existing `StrictMathWrapper`), throwing `ContractValidateException` on overflow, consistent with the fix already applied in `AssetIssueActuator`.

### Proof of Concept
A contract invokes the native freeze-balance functionality with `frozenDuration` set to a value close to `Long.MAX_VALUE / FROZEN_PERIOD` (or larger, since no upper bound is enforced), causing:
```
expireTime = nowInMs + frozenDuration * FROZEN_PERIOD
```
to overflow into a negative or small positive value in `FreezeBalanceProcessor.execute()` (`actuator/src/main/java/org/tron/core/vm/nativecontract/FreezeBalanceProcessor.java:76-77`). The resulting `expireTime` stored via `setFrozenForBandwidth`/`setFrozenForEnergy` or `DelegatedResourceCapsule.addFrozenBalanceForBandwidth/Energy` is then already "expired" relative to `now`, allowing subsequent unfreeze calls to release the balance immediately instead of after the intended lock duration.

  public void validate(FreezeBalanceParam param, Repository repo) throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    // validate arg @frozenBalance
    byte[] ownerAddress = param.getOwnerAddress();
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddress);
    long frozenBalance = param.getFrozenBalance();
    if (frozenBalance <= 0) {
      throw new ContractValidateException("FrozenBalance must be positive");
    } else if (frozenBalance < TRX_PRECISION) {
      throw new ContractValidateException("FrozenBalance must be greater than or equal to 1 TRX");
    } else if (frozenBalance > ownerCapsule.getBalance()) {
      throw new ContractValidateException("FrozenBalance must be less than or equal to accountBalance");
    }

    // validate frozen count of owner account
    int frozenCount = ownerCapsule.getFrozenCount();
    if (frozenCount != 0 && frozenCount != 1) {
      throw new ContractValidateException("FrozenCount must be 0 or 1");
    }

    // validate arg @resourceType
    switch (param.getResourceType()) {
      case BANDWIDTH:
      case ENERGY:
        break;
      default:
        throw new ContractValidateException(
            "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
    }

    // validate for delegating resource
    byte[] receiverAddress = param.getReceiverAddress();
    if (!FastByteComparisons.isEqual(ownerAddress, receiverAddress)) {
      param.setDelegating(true);

      // check if receiver account exists. if not, then create a new account
      AccountCapsule receiverCapsule = repo.getAccount(receiverAddress);
      if (receiverCapsule == null) {
        receiverCapsule = repo.createNormalAccount(receiverAddress);
      }

      // forbid delegating resource to contract account
      if (receiverCapsule.getType() == Protocol.AccountType.Contract) {
        throw new ContractValidateException(
            "Do not allow delegate resources to contract addresses");
      }
    }
  }
