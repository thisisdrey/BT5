### Title
Non-transitive comparator in `ExchangeStore.getAllExchanges()` can crash the node on `ListExchanges` API calls - (File: chainbase/src/main/java/org/tron/core/store/ExchangeStore.java)

### Summary
`ExchangeStore.getAllExchanges()` sorts all TRX-token exchange pairs with a comparator that violates the general `Comparator` contract (transitivity/consistency), which is exactly the class of bug the CVE describes: a query-path routine ("optimizer"/sort logic) that can throw an unhandled exception and hang/crash the server when processing legitimate, unprivileged requests.

### Finding Description
The comparator used in `getAllExchanges()` is:
```java
.sorted((ExchangeCapsule a, ExchangeCapsule b) -> a.getCreateTime() <= b.getCreateTime() ? 1 : -1)
``` [1](#0-0) 

This comparator never returns `0` for equal elements and is not antisymmetric/transitive in the way `Collections.sort`/`Stream.sorted` (backed by TimSort) require: for two capsules `a` and `b` with equal `createTime`, `compare(a,b)` returns `1` and `compare(b,a)` also returns `1`, breaking the antisymmetry contract that `compare(a,b) == -compare(b,a)`. When TimSort detects such contract violations during merge operations on sufficiently large arrays (Java's TimSort triggers this check once the array size exceeds 32 elements), it throws `java.lang.IllegalArgumentException: Comparison method violates its general contract!`. This is a well-known JDK failure mode for malformed comparators, directly analogous to the MySQL optimizer bug causing a crash/hang from processing normal queries.

This method is invoked from `Wallet` to serve the `ListExchanges` HTTP/gRPC/JSON-RPC API used by any anonymous API client — reachable without any special privilege via `ListExchangesServlet`, `ListExchangesOnSolidityServlet`, `ListExchangesOnPBFTServlet`, and the corresponding gRPC service in `RpcApiService` [2](#0-1) . `Wallet.java` references `ExchangeStore.getAllExchanges()` as the data source for this API surface, meaning any external, unauthenticated caller triggers the vulnerable sort whenever more than 32 exchange pairs exist on-chain — a condition trivially reachable since Bandwidth/creation of exchange pairs is a normal, low-privilege transaction type in java-tron.

### Impact Explanation
If `getAllExchanges()` throws `IllegalArgumentException`, the exception propagates up through `Wallet.getExchangeList()` into the servlet layer. In the HTTP servlets this is likely caught generically by `Util.processError(e, response)` and would only fail that single request; however, if the same store/comparator pattern is used anywhere in gRPC service handling or in block-application-adjacent code paths that do not have equivalent exception handling, an uncaught `IllegalArgumentException` in a thread not protected by servlet-level try/catch could propagate further, causing a full-node service disruption for that request thread, matching the CVE's "hang or frequently repeatable crash" pattern for a query subsystem. Even scoped only to the query API, this constitutes a repeatable denial-of-service against a node's `ListExchanges` API — an availability impact reachable by any anonymous client, consistent with the CVSS vector's Availability-only impact in the reference CVE.

### Likelihood Explanation
Once the exchange store accumulates more than ~32 entries with any two exchanges sharing the same `createTime` (a very plausible collision at ms-scale on a fast-producing chain, or two exchanges created in the same block), TimSort's contract check will reliably trigger the exception on every subsequent call to `getAllExchanges()`/`ListExchanges`, making this deterministically and repeatedly triggerable by simply calling the API — no special conditions or privileges are required beyond the exchange count threshold, which is realistic for a live TRON network.

### Recommendation
Fix the comparator to be contract-compliant, e.g. use `Comparator.comparingLong(ExchangeCapsule::getCreateTime).reversed()` or an explicit `Long.compare(b.getCreateTime(), a.getCreateTime())`, which correctly handles equal keys and satisfies transitivity/antisymmetry required by `Collections.sort`/TimSort.

### Proof of Concept
1. Issue (or simulate) more than 32 `ExchangeCreateContract` transactions such that at least two exchanges share the same `createTime` (block timestamp), which is common when multiple exchanges are created in the same block.
2. Call the `ListExchanges` HTTP API (`POST /wallet/listexchanges`) or the equivalent gRPC/JSON-RPC call.
3. `Wallet.getExchangeList()` invokes `ExchangeStore.getAllExchanges()`, which calls `Streams.stream(iterator()).sorted(...)` with the non-contract-compliant comparator.
4. TimSort detects the contract violation once the collection size exceeds the merge-sort threshold and throws `IllegalArgumentException: Comparison method violates its general contract!`, causing the request to fail; if this code path or a similarly-implemented comparator is exercised in a context without top-level exception handling, it results in a repeatable service disruption. @Component
public class ExchangeStore extends TronStoreWithRevoking<ExchangeCapsule> {

  @Autowired
  protected ExchangeStore(@Value("exchange") String dbName) {
    super(dbName);
  }

  @Override
  public ExchangeCapsule get(byte[] key) throws ItemNotFoundException {
    byte[] value = revokingDB.get(key);
    return new ExchangeCapsule(value);
  }

  /**
   * get all exchanges.
   */
  public List<ExchangeCapsule> getAllExchanges() {
    return Streams.stream(iterator())
        .map(Map.Entry::getValue)
        .sorted(
            (ExchangeCapsule a, ExchangeCapsule b) -> a.getCreateTime() <= b.getCreateTime() ? 1
                : -1)
        .collect(Collectors.toList());
  }
```

package org.tron.core.services.http;

import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;
import org.tron.core.Wallet;


@Component
@Slf4j(topic = "API")
public class ListExchangesServlet extends RateLimiterServlet {

  @Autowired
  private Wallet wallet;

  protected void doPost(HttpServletRequest request, HttpServletResponse response) {
    try {
      boolean visible = Util.getVisible(request);
      response.getWriter().println(JsonFormat.printToString(wallet.getExchangeList(), visible));
    } catch (Exception e) {
      Util.processError(e, response);
    }
  }

  protected void doGet(HttpServletRequest request, HttpServletResponse response) {
    doPost(request, response);
  }
}
