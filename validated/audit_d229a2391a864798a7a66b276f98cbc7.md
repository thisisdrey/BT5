### Title
`pallet-oracle`'s `DefaultCombineData` and `DataProvider::get` return an indefinitely stale aggregated value as if it were fresh, once oracle operators stop feeding — (File: `substrate/frame/honzon/oracle/src/default_combine_data.rs`)

### Summary
`pallet-oracle` (introduced for the Polkadot Stablecoin on AssetHub work, see `prdoc/stable2512/pr_9815.prdoc`) filters individual raw feeder submissions by an expiry window, but the *aggregated* value stored in `Values` is never re-validated for freshness once it is written. When feeders stop submitting (or all fresh submissions expire), `combine_data` silently falls back to the previously cached aggregate and keeps returning it forever, and `DataProvider::get` (the interface most consumer pallets are expected to use) does not even expose the timestamp for a consumer to check. This is functionally the same defect as the reported `staleCheckLatestRoundData()` issue: the price/data consumer has no way to detect that the underlying feed has gone dark, so old data keeps being trusted as current.

### Finding Description
`DefaultCombineData::combine_data` only prunes stale entries from the *newly submitted* raw values, then falls back to whatever was previously aggregated if not enough fresh values remain: [1](#0-0) 

Note that `prev_value` (the last aggregated `TimestampedValue`) is returned unconditionally on the "not enough fresh values" path — there is no expiry check applied to `prev_value` itself before re-emitting it as the new aggregate.

`Pallet::get` (the primary read API) simply returns whatever is currently stored, without any additional freshness check: [2](#0-1) 

The `DataProvider` trait — the interface pallets are documented to consume (`## Usage ... other pallets can use the DataProvider trait to read the aggregated data`, see `substrate/frame/honzon/oracle/README.md:37-41`) — strips the timestamp entirely and returns only the raw value: [3](#0-2) [4](#0-3) 

So a consumer using `DataProvider::get()` — the pallet's recommended integration path — has zero information to detect staleness even in principle; it receives a bare price with no timestamp, no "feed active" flag, and no on-chain revert if the underlying feed has gone stale for an arbitrarily long time.

This is confirmed by the pallet's own test suite, which explicitly demonstrates that advancing chain time does **not** invalidate a previously combined value: [5](#0-4) 

The test feeds three values, gets a combined result, then jumps chain time forward by roughly 10x the `ExpiresIn` window (`ExpiresIn` = `ConstU32<600>` per `mock.rs`, and the test advances from `12345` to `23456`), and asserts `ModuleOracle::get(&key)` is unchanged — i.e., the pallet keeps serving the same old value as if it were still current, exactly analogous to the Chainlink oracle continuing to serve a stale round because no liveness/staleness check exists at the boundary where the consumer trusts the data.

### Impact Explanation
Any downstream pallet that consumes `pallet-oracle` prices through the documented `DataProvider` interface (e.g. a stablecoin/CDP-style pallet computing collateral ratios, liquidations, or mint/redeem pricing, which is the explicit intended use case per `pr_9815.prdoc`) inherits this defect: if oracle operators go offline, get censored, or simply stop submitting, the chain continues to use the last known price indefinitely with no built-in signal that the feed is dead. This can allow undercollateralized positions to avoid liquidation, or liquidations/mints to execute at incorrect prices, directly threatening solvency/accounting invariants of any consuming financial pallet — the same "outdated data used in operations" impact described in the source report.

### Likelihood Explanation
No privileged action or malicious actor is required — this triggers purely from oracle operators going quiet (network partition, censorship, planned/unplanned downtime, or simply falling below `MinimumCount`), which is an expected operational condition, not an attack. Because `DataProvider::get` discards the timestamp, even a careful consumer author integrating the pallet as documented cannot add a mitigating check without going out-of-band to `DataProviderExtended`/`get_all_values` and manually inspecting timestamps themselves — something the primary, documented interface does not encourage or require.

### Recommendation
- Have `CombineData` (or the pallet's `get`/`DataProvider` implementations) enforce a maximum staleness on the *returned* aggregate, not just on the raw values considered for re-aggregation — i.e., check `prev_value.timestamp` against `now` before returning it, and return `None` if it has expired.
- Expose the timestamp through the `DataProvider` trait (or provide a `DataProviderExtended`-based default that consumers are steered toward) so pallets integrating oracle data are forced to reason about freshness, mirroring the Chainlink recommendation to explicitly gate on liveness before trusting a value.

### Proof of Concept
Using the pallet's own mock (`ExpiresIn = ConstU32<600>`, `MinimumCount = ConstU32<3>`):
1. Three operators feed the same key: `feed_values` from accounts 1, 2, 3 at timestamp `12345`.
2. `combine_data` produces `Some(TimestampedValue { value, timestamp: 12345 })`, stored in `Values`.
3. Advance chain time far beyond `ExpiresIn` (e.g. to `23456`, or arbitrarily further) with `Timestamp::set_timestamp`.
4. No further `feed_values` calls occur (operators offline/censored).
5. Call `ModuleOracle::get(&key)` — it still returns `TimestampedValue { value, timestamp: 12345 }` unchanged, exactly as shown in `should_combined_data` (`substrate/frame/honzon/oracle/src/tests.rs:145-171`), and any consumer using `DataProvider::get()` receives the raw stale `value` with no timestamp or staleness indicator at all.

	fn combine_data(
		_key: &<T as Config<I>>::OracleKey,
		mut values: Vec<TimestampedValueOf<T, I>>,
		prev_value: Option<TimestampedValueOf<T, I>>,
	) -> Option<TimestampedValueOf<T, I>> {
		let expires_in = ExpiresIn::get();
		let now = T::Time::now();

		values.retain(|x| x.timestamp.saturating_add(expires_in) > now);

		let count = values.len() as u32;
		let minimum_count = MinimumCount::get();
		if count < minimum_count || count == 0 {
			return prev_value;
		}

		let mid_index = count / 2;
		// Won't panic as `values` ensured not empty.
		let (_, value, _) =
			values.select_nth_unstable_by(mid_index as usize, |a, b| a.value.cmp(&b.value));
		Some(value.clone())
	}

#[test]
fn should_combined_data() {
	new_test_ext().execute_with(|| {
		let key: u32 = 50;

		assert_ok!(ModuleOracle::feed_values(
			RuntimeOrigin::signed(1),
			vec![(key, 1300)].try_into().unwrap()
		));
		assert_ok!(ModuleOracle::feed_values(
			RuntimeOrigin::signed(2),
			vec![(key, 1000)].try_into().unwrap()
		));
		assert_ok!(ModuleOracle::feed_values(
			RuntimeOrigin::signed(3),
			vec![(key, 1200)].try_into().unwrap()
		));

		let expected = Some(TimestampedValue { value: 1200, timestamp: 12345 });

		assert_eq!(ModuleOracle::get(&key), expected);

		Timestamp::set_timestamp(23456);

		assert_eq!(ModuleOracle::get(&key), expected);
	});
}
