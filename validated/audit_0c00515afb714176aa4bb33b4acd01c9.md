### Title
IPv6 extension-header length overflow could make the firewall parse the wrong protocol/port (historical bug, now fixed) - (File: outside.go)

### Summary
Nebula's `parseV6` function walks the chain of IPv6 extension headers to find the real transport-layer header (TCP/UDP/ICMPv6) so the firewall can extract protocol and port for rule matching. The header length field for options like Hop-by-Hop, Routing, and Destination is expressed in units of 8-byte words (`HdrExtLen`), analogous to the DeFi report's `USDe`↔`sUSDe` conversion where a quantity in one unit was mistakenly treated as if it were already in the target unit. Historically, this conversion (`(int(data[offset+1]) + 1) << 3`) was computed with an undersized integer type that could overflow/wrap for a maliciously crafted `HdrExtLen` (255), producing an offset far smaller than the real header length. This caused the firewall to derive protocol/port fields from attacker-controlled option bytes at a "forged" offset while the host OS parsed the real, correctly-computed offset, letting a remote peer smuggle traffic past intended port/protocol firewall rules.

### Finding Description
`parseV6` in [1](#0-0)  loops over IPv6 extension headers using `next = (int(data[offset+1]) + 1) << 3` (or `<< 2` for AH) to advance `offset` toward the real transport header, exactly mirroring the "amount to shares" unit-conversion step in the reported DeFi bug. The regression test `Test_newPacket_v6ExtHeaderOverflow` at [2](#0-1)  documents the exact failure mode: with `HdrExtLen=255` the true extension size is `(255+1)*8 = 2048` bytes, so the real transport header sits at offset 2088; prior to the fix, the advance was computed in `uint8` and wrapped to 0 (clamped to 8), so the firewall read the transport header ~2KB too early — from attacker-controlled option bytes — while the host kernel used the correct 2088 offset. This is confirmed as fixed by the CHANGELOG entry: "Fix an IPv6 extension-header length overflow that could make the firewall parse the wrong protocol and ports." [3](#0-2) 

The parallel to the reported bug is exact at the structural level:
- Reported bug: a quantity in `USDe` units was passed directly as if it were already `sUSDe` shares, skipping the required unit conversion (`previewWithdraw`), causing the wrong (too-large) amount of the underlying asset to be transferred.
- Nebula analog: a length quantity expressed in 8-byte-word units was converted to a byte offset using arithmetic that could overflow in an undersized type, causing the wrong (too-small) byte offset to be used, causing a security-relevant component (the firewall) to read the wrong data — i.e., trusting an incorrectly "converted" value instead of the real one.

### Impact Explanation
If this bug were still present, a remote unauthenticated peer able to send raw IP packets through an established tunnel could construct a crafted IPv6 packet with a maximal `HdrExtLen` extension header such that the wrapped offset lands on attacker-chosen bytes. The firewall would then classify the packet's protocol/port based on forged data rather than the packet's real transport header, allowing a firewall bypass (traffic classified as an allowed protocol/port while the host's real handling differs), i.e., remote firewall enforcement bypass.

### Likelihood Explanation
This requires no CA-signed certificate and no privileged position — any peer capable of sending IP packets over an existing (or even fragmentary) tunnel path that reaches `parseV6` could trigger it, since the trigger is purely a matter of the extension header's `HdrExtLen` byte. It fits squarely in the allowed category "packet/header parsing" / "firewall enforcement" reachable by an attacker without a CA-signed certificate.

### Recommendation
This is already fixed in the current codebase: `parseV6` now computes `next` using `int` arithmetic instead of an undersized type, so the offset walk cannot overflow before reaching the real transport header, verified by the `Test_newPacket_v6ExtHeaderOverflow` regression test. No further action is required beyond continuing to run this regression test on future refactors of `parseV6`.

### Proof of Concept
The exact reproduction is captured in the existing regression test: [4](#0-3) 
- Build an IPv6 packet with `NextHeader = IPv6Destination`, and Destination-Options `NextHeader = TCP`, `HdrExtLen = 255`.
- Place a forged TCP header at the pre-fix (wrong) offset 48 with destination port 443, and the real TCP header at offset 2088 with destination port 22.
- Before the fix: `newPacket` would report `LocalPort = 443` (the forged value) due to the overflow; after the fix, it correctly reports `LocalPort = 22`, matching what the host OS delivers.

func parseV6(data []byte, incoming bool, fp *firewall.Packet) error {
	dataLen := len(data)
	if dataLen < ipv6.HeaderLen {
		return ErrIPv6PacketTooShort
	}

	if incoming {
		fp.RemoteAddr, _ = netip.AddrFromSlice(data[8:24])
		fp.LocalAddr, _ = netip.AddrFromSlice(data[24:40])
	} else {
		fp.LocalAddr, _ = netip.AddrFromSlice(data[8:24])
		fp.RemoteAddr, _ = netip.AddrFromSlice(data[24:40])
	}

	protoAt := 6             // NextHeader is at 6 bytes into the ipv6 header
	offset := ipv6.HeaderLen // Start at the end of the ipv6 header
	next := 0
	for {
		if protoAt >= dataLen {
			break
		}
		proto := layers.IPProtocol(data[protoAt])

		switch proto {
		case layers.IPProtocolESP, layers.IPProtocolNoNextHeader:
			fp.Protocol = uint8(proto)
			fp.RemotePort = 0
			fp.LocalPort = 0
			fp.Fragment = false
			return nil

		case layers.IPProtocolICMPv6:
			if dataLen < offset+6 {
				return ErrIPv6PacketTooShort
			}
			fp.Protocol = uint8(proto)
			fp.LocalPort = 0 //incoming vs outgoing doesn't matter for icmpv6
			icmptype := data[offset+1]
			switch icmptype {
			case layers.ICMPv6TypeEchoRequest, layers.ICMPv6TypeEchoReply:
				fp.RemotePort = binary.BigEndian.Uint16(data[offset+4 : offset+6]) //identifier
			default:
				fp.RemotePort = 0
			}
			fp.Fragment = false
			return nil

		case layers.IPProtocolTCP, layers.IPProtocolUDP:
			if dataLen < offset+4 {
				return ErrIPv6PacketTooShort
			}

			fp.Protocol = uint8(proto)
			if incoming {
				fp.RemotePort = binary.BigEndian.Uint16(data[offset : offset+2])
				fp.LocalPort = binary.BigEndian.Uint16(data[offset+2 : offset+4])
			} else {
				fp.LocalPort = binary.BigEndian.Uint16(data[offset : offset+2])
				fp.RemotePort = binary.BigEndian.Uint16(data[offset+2 : offset+4])
			}

			fp.Fragment = false
			return nil

		case layers.IPProtocolIPv6Fragment:
			// Fragment header is 8 bytes, need at least offset+4 to read the offset field
			if dataLen < offset+8 {
				return ErrIPv6PacketTooShort
			}

			// Check if this is the first fragment
			fragmentOffset := binary.BigEndian.Uint16(data[offset+2:offset+4]) &^ uint16(0x7) // Remove the reserved and M flag bits
			if fragmentOffset != 0 {
				// Non-first fragment, use what we have now and stop processing
				fp.Protocol = data[offset]
				fp.Fragment = true
				fp.RemotePort = 0
				fp.LocalPort = 0
				return nil
			}

			// The next loop should be the transport layer since we are the first fragment
			next = 8 // Fragment headers are always 8 bytes

		case layers.IPProtocolAH:
			// Auth headers, used by IPSec, have a different meaning for header length
			if dataLen <= offset+1 {
				break
			}
			next = (int(data[offset+1]) + 2) << 2

		default:
			// Normal ipv6 header length processing
			if dataLen <= offset+1 {
				break
			}
			next = (int(data[offset+1]) + 1) << 3
		}

		if next <= 0 {
			// Safety check, each ipv6 header has to be at least 8 bytes
			next = 8
		}

		protoAt = offset
		offset = offset + next
	}

	return ErrIPv6CouldNotFindPayload
}

// Test_newPacket_v6ExtHeaderOverflow is a regression test for the IPv6 extension-header
// length uint8 overflow in parseV6. A Destination-Options header with HdrExtLen=255 spans
// (255+1)*8 = 2048 bytes, so the real transport header sits at offset 2088. Before the fix
// the advance was computed in uint8 and wrapped to 0 (then clamped to 8), so the firewall
// read the transport header ~2KB too early from attacker-controlled option bytes while the
// host OS parses the real header, a firewall port/proto bypass. The fix makes parseV6 land
// on the same offset the host does.
func Test_newPacket_v6ExtHeaderOverflow(t *testing.T) {
	p := &firewall.Packet{}

	const (
		hdrLen      = 40              // IPv6 header
		extLen      = 2048            // (255+1)*8, the true Destination-Options header size
		realTCPAt   = hdrLen + extLen // 2088, where the host reads the transport header
		forgedTCPAt = hdrLen + 8      // 48, where the pre-fix wrapped+clamped walk landed
	)

	pkt := make([]byte, realTCPAt+4)
	pkt[0] = 0x60                                   // version 6
	pkt[6] = byte(layers.IPProtocolIPv6Destination) // NextHeader -> Destination Options
	pkt[40] = byte(firewall.ProtoTCP)               // Dest-Options NextHeader -> TCP
	pkt[41] = 255                                   // HdrExtLen = 255

	// Forged transport header at the pre-fix (wrong) offset: dst port 443.
	binary.BigEndian.PutUint16(pkt[forgedTCPAt+2:forgedTCPAt+4], 443)
	// Real transport header at the offset the host actually uses: dst port 22.
	binary.BigEndian.PutUint16(pkt[realTCPAt+2:realTCPAt+4], 22)

	require.NoError(t, newPacket(pkt, true, p))
	assert.Equal(t, uint8(firewall.ProtoTCP), p.Protocol)
	// LocalPort is the destination port for incoming traffic. It must be the real port (22)
	// the host delivers to, not the forged 443 at the overflowed offset.
	assert.Equal(t, uint16(22), p.LocalPort, "firewall must parse the real transport header, not the overflowed offset")
}
