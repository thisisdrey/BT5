## Title
Heap buffer over-read in ijar's ZIP central-directory parser due to missing bounds checks — (`File: third_party/ijar/zip.cc`)

### Summary
`InputZipFile::ProcessCentralDirEntry` in `third_party/ijar/zip.cc` parses each Central Directory Header (CDH) of a ZIP/JAR file without ever calling `EnsureRemaining()`, the very check that its sibling routine `ProcessLocalFileEntry` uses on every field it reads [1](#0-0) . A crafted CDH with inflated `file_name_length`, `extra_field_length`/`file_comment_length`, or a malformed ZIP64 extra-field `data_size` can walk the cursor `p`/`extra_p` past the end of the memory-mapped input file, causing out-of-bounds heap reads that are then copied into the tool's internal buffers and ultimately into interface-jar output.

### Finding Description
`ProcessCentralDirEntry` reads the fixed CDH fields and then the variable-length filename, extra field, and comment directly off the mmap'd buffer, with no check that these lengths stay inside the mapped region: [2](#0-1) 

The extra-field walk is especially unsafe — it advances `extra_p` by an attacker-controlled `data_size` and only stops when `extra_p == p`, so a `data_size` that overshoots `p` causes the loop to keep dereferencing memory far outside the mapped file (potentially unmapped pages, causing SIGSEGV, or adjacent heap allocations, causing an over-read): [3](#0-2) 

By contrast, `ProcessLocalFileEntry`, which parses the same conceptual fields (`file_name_length`, `extra_field_length`) from the *local* file header, explicitly calls `EnsureRemaining()` before touching memory: [4](#0-3) 

`EnsureRemaining` itself exists specifically to prevent reading past `input_file_->Length()`: [5](#0-4) 

The filename bytes read from the (potentially out-of-bounds) `p` are then memcpy'd into a fixed `filename[PATH_MAX]` buffer and used to decide whether/what to extract or copy into the ijar output: [6](#0-5) [7](#0-6) 

ijar processes JAR files that are ordinary, attacker-influenced build inputs — e.g., `java_import`/`http_jar`/`http_archive`-fetched prebuilt jars used to generate interface jars during the build. An attacker who controls the bytes of such a jar (a hostile mirror, registry entry, or dependency archive whose pinned `sha256`/`integrity` is computed over the attacker's own malicious file) can trigger this parser on fully-attacker-controlled bytes; the checksum only proves the bytes are exactly what the attacker produced; it does nothing to validate internal ZIP structural invariants.

### Impact Explanation
An out-of-bounds heap read in `ProcessCentralDirEntry` can copy adjacent heap memory into the `filename` buffer and, transitively, into the generated interface jar (an output artifact of the build), or crash the ijar process. Because the whole point of `sha256`/`integrity` verification is to bind the *bytes* the developer expects, not to validate the ZIP container's internal structural consistency, this parser bug lets a hostile origin (mirror, registry, or archive host) whose file matches a legitimately pinned checksum (because the attacker crafted both the file and, at pinning time, its hash) still corrupt/crash the local ijar invocation or leak adjacent process heap bytes into a build output that is subsequently cached/consumed by other targets.

### Likelihood Explanation
`java_import`, prebuilt jar rules, and other rules invoking ijar on externally-fetched, non-source-controlled jars are common in real Bazel builds (e.g., via `http_jar`, `http_archive` with `type = "jar"`, or Maven-style external dependencies). Any project that consumes a jar from a third-party/mirror source is exposed the moment that jar is run through ijar to build an interface jar, which happens automatically for `java_library`'s exported jars.

### Recommendation
Add `EnsureRemaining()` checks (or equivalent bounds validation against `input_file_->Length()`/the mapped region) before reading `file_name_length`, `extra_field_length`, `file_comment_length`, and before iterating the extra-field records in `InputZipFile::ProcessCentralDirEntry`, mirroring the protections already present in `ProcessLocalFileEntry`. Additionally bound the extra-field loop so that `data_size` cannot advance `extra_p` past the declared `extra_field_length` boundary.

### Proof of Concept
Construct a minimal ZIP/JAR whose End-of-Central-Directory declares one entry, and whose single Central Directory Header sets `file_name_length`/`extra_field_length`/`file_comment_length` (or a ZIP64 extra-field `data_size`) large enough to push the cursor past the actual mapped file length, then invoke:
```
ijar <malicious.jar> <out.jar>
```
Similar to the existing `CreateZipWithMalformedExtraField` helper used for the (separate) singlejar CDH parser test [8](#0-7) , a JUnit/`cc_test` fixture constructing such a jar and calling `InputZipFile::Open()`/`ProcessNext()` under AddressSanitizer would demonstrate the heap-buffer-overflow/read directly, without requiring any local machine access beyond running `ijar` on attacker-supplied bytes.

  // Check that at least n bytes remain in the input file, otherwise
  // abort with an error message.  "state" is the name of the field
  // we're about to read, for diagnostics.
  int EnsureRemaining(size_t n, const char *state) {
    size_t in_offset = p - zipdata_in_;
    size_t remaining = input_file_->Length() - in_offset;
    if (n > remaining) {
      return error("Premature end of file (at offset %zd, state=%s); "
                   "expected %zd more bytes but found %zd.\n",
                   in_offset, state, n, remaining);
    }
    return 0;
  }

bool InputZipFile::ProcessNext() {
  // Process the next entry in the central directory. Also make sure that the
  // content pointer is in sync.
  u8 compressed, uncompressed;
  u8 offset;
  if (!ProcessCentralDirEntry(central_dir_current_, &compressed, &uncompressed,
                              filename, PATH_MAX, &attr, &offset)) {
    return false;
  }

  // There might be an offset specified in the central directory that does
  // not match the file offset, so always update our pointer.
  p = zipdata_in_ + in_offset_ + offset;

  if (EnsureRemaining(4, "signature") < 0) {
    return false;
  }
  u4 signature = get_u4le(p);
  if (signature == LOCAL_FILE_HEADER_SIGNATURE) {
    if (ProcessLocalFileEntry(compressed, uncompressed) < 0) {
      return false;
    }
  } else {
    error("local file header signature for file %s not found\n", filename);
    return false;
  }

  return true;
}

bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }

std::string CreateZipWithMalformedExtraField() {
  std::string zip_data;
  const std::string filename = "evil.bin";

  // 1. Local File Header (LFH)
  size_t lh_offset = zip_data.size();
  size_t lh_size = sizeof(LH) + filename.size();
  zip_data.resize(lh_offset + lh_size, 0);
  auto* lh = reinterpret_cast<LH*>(&zip_data[lh_offset]);
  lh->signature();
  lh->version(10);
  lh->file_name(filename.data(), filename.size());

  // 2. Extra field payload containing an oversized payload_size
  uint8_t ef_buffer[8] = {0};
  auto* ef1 = reinterpret_cast<ExtraField*>(ef_buffer);
  ef1->signature(0x000d);
  ef1->payload_size(0);

  auto* ef2 = reinterpret_cast<ExtraField*>(ef_buffer + ef1->size());
  ef2->signature(0xdead);
  ef2->payload_size(0xf000);  // Malformed size exceeding extra field buffer

  // 3. Central Directory Header (CDH)
  size_t cdh_offset = zip_data.size();
  size_t cdh_size = sizeof(CDH) + filename.size() + sizeof(ef_buffer);
  zip_data.resize(cdh_offset + cdh_size, 0);
  auto* cdh = reinterpret_cast<CDH*>(&zip_data[cdh_offset]);
  cdh->signature();
  cdh->version(20);
  cdh->version_to_extract(10);
  cdh->local_header_offset32(lh_offset);
  cdh->file_name(filename.data(), filename.size());
  cdh->extra_fields(ef_buffer, sizeof(ef_buffer));

  // 4. End of Central Directory (EOCD)
  size_t ecd_offset = zip_data.size();
  zip_data.resize(ecd_offset + sizeof(ECD), 0);
  auto* ecd = reinterpret_cast<ECD*>(&zip_data[ecd_offset]);
  ecd->signature();
  ecd->this_disk_entries16(1);
  ecd->total_entries16(1);
  ecd->cen_size32(cdh_size);
  ecd->cen_offset32(cdh_offset);

  return zip_data;
}
