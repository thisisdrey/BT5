### Title
Unauthenticated block-upload triggers unconditional network-wide relay, bypassing the `broadcast` auth gate - (File: stackslib/src/net/api/postblock_v3.rs)

### Summary
`RPCPostBlockRequestHandler::try_parse_request` only requires authentication when the caller explicitly sets `broadcast=1`; an unauthenticated POST with `broadcast` omitted is accepted for local processing. However, `try_handle_request` relays the block to the P2P network based solely on `data_resp.accepted`, with no check of `self.broadcast`/authentication state, so an unauthenticated submitter can still cause network-wide relay of the block.

### Finding Description
In `try_parse_request` [1](#0-0) , `authenticated` is only enforced when `broadcast && !authenticated` — i.e. the auth check is skipped entirely as long as the query string does not contain `broadcast=1`. In that case `self.broadcast` is set to `Some(false)` and the request proceeds without any `authorization` header.

In `try_handle_request`, the block is passed to `Relayer::process_new_nakamoto_block_ext` along with `self.broadcast.unwrap_or(false)` [2](#0-1) . Regardless of what that broadcast flag was, once chainstate validation independently returns "accepted", the handler unconditionally relays the block to the peer network:

```rust
// should set to relay...
if data_resp.accepted {
    node.set_relay_message(StacksMessageType::NakamotoBlocks(NakamotoBlocksData {
        blocks: vec![block],
    }));
}
``` [3](#0-2) 

This gate checks only `data_resp.accepted` — it does not check `self.broadcast` or any authentication flag. Thus the equality the question describes (`set_relay_message` invocations == requests with `self.broadcast == Some(true)`) is broken: any accepted block, whether submitted authenticated+`broadcast=1` or completely unauthenticated with `broadcast` omitted, is relayed identically.

### Impact Explanation
Any unprivileged remote party who can reach the node's RPC port can POST a well-formed, chainstate-valid `NakamotoBlock` (e.g., one they observed elsewhere, or one they are otherwise permitted to construct/have) without any `authorization` header and without `broadcast=1`, and the node will still push it into `node.set_relay_message`, causing the node to disseminate it to its P2P peers. This defeats the purpose of the `broadcast`/authentication gate entirely — the RPC operator's intent (only trusted/authenticated parties can trigger this node to act as a relay origin for a block) is bypassed. This is an auth-bypass finding: unauthenticated callers achieve the privileged "trigger network relay" action that the code explicitly tries to restrict to authenticated + `broadcast=1` requests.

### Likelihood Explanation
The `/v3/blocks/upload/` endpoint is reachable by any peer able to connect to the node's RPC port, no privileged role or secret required for the unauthenticated path. The only precondition is that the submitted block passes chainstate acceptance criteria (i.e., is a legitimately valid, signed Nakamoto block) — this is the same acceptance check any legitimate node performs, so it is not a difficult bar for a block the attacker has obtained but is not authorized to trigger relay for. The behavior is deterministic and repeatable for every accepted block submission.

### Recommendation
Gate the relay call on both acceptance and authorization/broadcast intent, e.g.:
```rust
if data_resp.accepted && self.broadcast.unwrap_or(false) {
    node.set_relay_message(...);
}
```
so that only authenticated requests with explicit `broadcast=1` cause the node to relay the block to its peers.

### Proof of Concept
In `stackslib/src/net/api/tests/postblock_v3.rs`, add a test that:
1. Constructs an `RPCPostBlockRequestHandler` with `auth = Some(password)`.
2. Builds an HTTP request via `try_parse_request` with no `authorization` header and no `broadcast` query parameter (so `authenticated = false`, `broadcast = false`).
3. Feeds a valid, chainstate-acceptable `NakamotoBlock` as the body.
4. Calls `try_handle_request` against a `StacksNodeState` whose chainstate/sortdb accept the block.
5. Assert that `node.relay_message` (the field set by `set_relay_message`) is `Some(StacksMessageType::NakamotoBlocks(...))` even though the request was unauthenticated and `broadcast` was never set — confirming relay occurs purely from `data_resp.accepted`, independent of `self.broadcast`.
