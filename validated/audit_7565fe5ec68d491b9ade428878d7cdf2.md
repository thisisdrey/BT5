## Title
Front-runnable deterministic PDA squatting via unchecked `new_authority` in `transfer_to_new_account_pda` permanently blocks victims' account creation - (File: `programs/marginfi/src/instructions/marginfi_account/transfer_account.rs`)

### Summary
The `TransferToNewAccountPda` instruction derives the destination account address deterministically from public inputs (`group`, `new_authority`, `account_index`, `third_party_id`), exactly like the Gnosis Safe `create2` salt scheme in the referenced report. Unlike the account-creation instruction `MarginfiAccountInitializePda` (which requires `authority` to be a real `Signer` matching the seed), `TransferToNewAccountPda` treats `new_authority` as a fully unchecked, non-signing account. Any unprivileged user who owns a throwaway `MarginfiAccount` can therefore pre-create ("squat") the deterministic PDA for an arbitrary victim pubkey/`account_index`/`third_party_id` combination without ever holding the victim's private key, permanently blocking that specific slot for the legitimate user — the same "deterministic-address front-running/DoS" bug class described in the report.

### Finding Description
`MarginfiAccountInitializePda` requires the `authority` account whose pubkey is used in the seed to also be the transaction `Signer`, so nobody can create a PDA for someone else's pubkey: [1](#0-0) 

However, `TransferToNewAccountPda` derives the exact same `MARGINFI_ACCOUNT_SEED` PDA using `new_authority.key()`, and `new_authority` is only an `UncheckedAccount` — it is never required to sign: [2](#0-1) 

The only signer requirement is on `authority` and `fee_payer`, which correspond to the *caller's own* `old_marginfi_account` (any pre-existing account they control, validated only via `is_signer_authorized`/`account_not_frozen_for_authority`): [3](#0-2) 

The handler then initializes the PDA account with `authority = new_authority` (attacker-supplied, unchecked), copying migrated data from the attacker's own throwaway old account: [4](#0-3) [5](#0-4) 

Because `init` constraints in Anchor fail if the target PDA already exists, once an attacker has created this PDA for `(group, victim_pubkey, account_index, third_party_id)`, the victim's own future call to `MarginfiAccountInitializePda` or `TransferToNewAccountPda` targeting the same tuple will permanently fail (`init` errors on an already-initialized account), exactly mirroring the report's Gnosis Safe salt-collision scenario where "using the same salt as an already-deployed Safe will cause the action to revert." The duplicate-creation-fails behavior is confirmed by the project's own tests: [6](#0-5) 

### Impact Explanation
This results in a permanent lock/DoS of a specific deterministic PDA slot for any victim address: an attacker can pre-emptively squat commonly used `account_index` values (e.g. `0`, `1`, `2`, which off-chain integrations/indexers conventionally rely on as canonical/default slots) for arbitrary or even not-yet-used wallet addresses, at negligible cost (one throwaway account + the flat `ACCOUNT_TRANSFER_FEE`). This blocks legitimate users or third-party integrations from ever using the canonical PDA-derived account for that `account_index`, forcing them to migrate to non-standard indices or abandon the intended deterministic addressing scheme — matching the report's "permanent lock/freeze" impact class for unprivileged users, not admins.

### Likelihood Explanation
The attack requires no special privileges: only ownership of a single throwaway `MarginfiAccount` and knowledge of the target's public wallet address (which is by definition public). Because `account_index`/`third_party_id` inputs are small, low-entropy `u16` values and PDA derivation is fully deterministic from public data, mass-squatting popular addresses/indices is cheap and straightforward to script, making this readily exploitable in production once a target address is known (e.g., announced ahead of a planned migration or well-known protocol/treasury address).

### Recommendation
Require `new_authority` to be a `Signer` in `TransferToNewAccountPda` (as is already enforced for `authority` in `MarginfiAccountInitializePda`), or otherwise validate that the caller is authorized to claim that specific destination PDA before allowing `init`. If self-service migration to arbitrary addresses must remain unchecked for UX reasons, consider requiring victim co-signature, or emit/allow the intended owner to reclaim/close the account, or restrict this pattern to `account_index`/`third_party_id` reservations that are provably owned by the recipient beforehand.

### Proof of Concept
1. Attacker creates a normal `MarginfiAccount` for themselves (`old_marginfi_account`), satisfying `is_signer_authorized`/`account_not_frozen_for_authority`.
2. Attacker calls `transfer_to_new_account_pda(account_index=0, third_party_id=None)` with `authority` = attacker's own signer, `new_authority` = victim's known public key (unchecked, no signature needed) — see accounts struct at [7](#0-6) .
3. This creates and initializes the PDA at seeds `[MARGINFI_ACCOUNT_SEED, group, victim_pubkey, 0u16, 0u16]` with `authority = victim_pubkey`, consuming the attacker's old account in the process.
4. Victim later attempts `marginfi_account_create_pda`/`initialize_account_pda` with the same `account_index=0`, `third_party_id=None` for the same group — the `init` constraint fails because the PDA already exists, permanently denying the victim that canonical slot — see [8](#0-7)  and the confirming duplicate-creation test at [6](#0-5) .

#[derive(Accounts)]
#[instruction(account_index: u16, third_party_id: Option<u16>)]
pub struct TransferToNewAccountPda<'info> {
    #[account(
        constraint = (
            !group.load()?.is_protocol_paused()
        ) @ MarginfiError::ProtocolPaused
    )]
    pub group: AccountLoader<'info, MarginfiGroup>,

    #[account(
        mut,
        has_one = group @ MarginfiError::InvalidGroup,
        constraint = {
            let a = old_marginfi_account.load()?;
            account_not_frozen_for_authority(&a, authority.key())
        } @ MarginfiError::AccountFrozen,
        constraint = {
            let a = old_marginfi_account.load()?;
            let g = group.load()?;
            is_signer_authorized(&a, g.admin, authority.key(), false, false)
        } @ MarginfiError::Unauthorized
    )]
    pub old_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    #[account(
        init,
        payer = fee_payer,
        space = 8 + std::mem::size_of::<MarginfiAccount>(),
        seeds = [
            MARGINFI_ACCOUNT_SEED.as_bytes(),
            group.key().as_ref(),
            new_authority.key().as_ref(),
            &account_index.to_le_bytes(),
            &third_party_id.unwrap_or(0).to_le_bytes(),
        ],
        bump
    )]
    pub new_marginfi_account: AccountLoader<'info, MarginfiAccount>,

    pub authority: Signer<'info>,

    #[account(mut)]
    pub fee_payer: Signer<'info>,

    /// CHECK: WARN: New authority is completely unchecked
    pub new_authority: UncheckedAccount<'info>,

    /// CHECK: Validated against group fee state cache
    #[account(mut)]
    pub global_fee_wallet: UncheckedAccount<'info>,

    /// Instructions sysvar for CPI validation
    /// CHECK: Standard sysvar account
    #[account(address = solana_instructions_sysvar::id())]
    pub instructions_sysvar: UncheckedAccount<'info>,

    pub system_program: Program<'info, System>,

#[tokio::test]
async fn marginfi_account_create_pda_duplicate_fails() -> anyhow::Result<()> {
    let test_f = TestFixture::new(None).await;

    let authority = test_f.payer();
    let account_index = 0;
    let third_party_id = None;

    // Derive PDA for the marginfi account
    let (marginfi_account_pda, _bump) = MarginfiAccount::derive_pda(
        &test_f.marginfi_group.key,
        &authority,
        account_index,
        third_party_id,
        &marginfi::ID,
    );

    let accounts = marginfi::accounts::MarginfiAccountInitializePda {
        marginfi_group: test_f.marginfi_group.key,
        marginfi_account: marginfi_account_pda,
        authority: authority,
        fee_payer: authority,
        instructions_sysvar: solana_instructions_sysvar::id(),
        system_program: system_program::id(),
    };

    let init_marginfi_account_pda_ix = Instruction {
        program_id: marginfi::ID,
        accounts: accounts.to_account_metas(Some(true)),
        data: marginfi::instruction::MarginfiAccountInitializePda {
            account_index,
            third_party_id,
        }
        .data(),
    };

    // First transaction should succeed
    let tx1 = Transaction::new_signed_with_payer(
        &[init_marginfi_account_pda_ix.clone()],
        Some(&test_f.payer()),
        &[&test_f.payer_keypair()],
        test_f.get_latest_blockhash().await,
    );

    let res1 = test_f
        .context
        .borrow_mut()
        .banks_client
        .process_transaction(tx1)
        .await;

    assert!(res1.is_ok());

    // Second transaction with same parameters should fail
    let tx2 = Transaction::new_signed_with_payer(
        &[init_marginfi_account_pda_ix],
        Some(&test_f.payer()),
        &[&test_f.payer_keypair()],
        test_f.get_latest_blockhash().await,
    );

    let res2 = test_f
        .context
        .borrow_mut()
        .banks_client
        .process_transaction(tx2)
        .await;

    assert!(res2.is_err(), "Duplicate account creation should fail");

    Ok(())
