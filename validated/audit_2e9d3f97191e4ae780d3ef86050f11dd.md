Audit Report

## Title
`relayer_fee` in Snowbridge inbound queue v2 messages is an unbounded, attacker-chosen value minted as relayer reward with no check against actual bridged value - ([File: bridges/snowbridge/pallets/inbound-queue-v2/src/lib.rs])

## Summary
`InboundQueue::process_message` in `bridges/snowbridge/pallets/inbound-queue-v2/src/lib.rs` credits the `relayer_fee` field of a decoded Ethereum `Message` directly into `pallet-bridge-relayers`' `RelayerRewards` storage via `T::RewardPayment::register_reward`, with no bound relative to `message.value`, `execution_fee`, or any protocol fee schedule [1](#0-0) . The `relayer_fee` originates from the unprivileged `IGatewayV2.Payload.relayerFee` field emitted by any Ethereum-side caller of the Gateway contract and is decoded verbatim in `Message::try_from(&Log)` [2](#0-1) . When the relayer claims the reward for Snowbridge on Bridge Hub Westend, `BridgeRewardPayer::pay_reward` routes it through `PayAccountOnLocation`, which builds an XCM containing a `ReserveAssetDeposited` instruction for the full reward amount and `DepositAsset`s it to the beneficiary on AssetHub — i.e., it mints/reserve-deposits the claimed WETH amount rather than debiting a pool backed by actually-bridged Ether [3](#0-2) [4](#0-3) .

## Finding Description
`submit` is a public, `ensure_signed` extrinsic that verifies only proof-of-existence of the Ethereum event log (`T::Verifier::verify`) and decodes it into a `Message`, then calls `process_message` [5](#0-4) . Inside `process_message`, the only checks performed are that `message.gateway` matches the configured `GatewayAddress` (`Error::InvalidGateway`) and that the `nonce` has not been used (`Error::InvalidNonce`) — both are checks on the message *envelope*, not its *content* [6](#0-5) . The reward computation `total_tip = relayer_fee.saturating_add(tip)` and the subsequent `register_reward` call have no bound against `message.value`, `message.execution_fee`, or any `Config::MaxRelayerFee`-style constant [7](#0-6) .

`Message::try_from(&Log)` copies `relayerFee` from the raw Solidity `Payload` struct verbatim into the Substrate-side `relayer_fee: u128` field, with no cross-check against `value` [2](#0-1) , and `Payload.relayerFee` in the Solidity event schema is a free-form field set by whoever emits the `OutboundMessageAccepted` event on Ethereum [8](#0-7) , i.e. an unprivileged end user calling the Gateway's send/register functions, not governance or a trusted relayer.

Downstream, `register_relayer_reward` in `pallet-bridge-relayers` simply `saturating_add`s whatever value it is given into `RelayerRewards` storage with no cap [9](#0-8) . When claimed for Snowbridge rewards specifically, `BridgeRewardPayer::pay_reward` dispatches to `PayAccountOnLocation::pay_reward`, which constructs an XCM with `ReserveAssetDeposited(assets)` for the full reward amount followed by `DepositAsset` to the beneficiary on AssetHub [3](#0-2) . `ReserveAssetDeposited` causes AssetHub's XCM executor to credit the beneficiary with that much foreign WETH asset as if it were reserve-backed by Ethereum, without verifying that Ether corresponding to that amount was actually locked on Ethereum for this message. This is functionally equivalent to an unbacked mint of the reward asset, gated only by the attacker-controlled `relayer_fee` field.

## Impact Explanation
An attacker who controls the Ethereum-side call that emits the `OutboundMessageAccepted` event (any unprivileged user of the Gateway contract) can set `relayerFee` to an arbitrarily large `u128` unrelated to `value`. After relaying the event (which the attacker can do themselves, since `submit` is callable by any signed account), the full inflated `relayer_fee` is registered as a claimable reward and, on claim, minted via `ReserveAssetDeposited`/`DepositAsset` XCM to an attacker-chosen AssetHub beneficiary. This matches the "theft or unbacked mint or unlock" impact category for Snowbridge BridgeHub code, since value is created/paid out without being backed by real bridged Ether.

## Likelihood Explanation
High. No collusion, governance action, or key compromise is required. `submit` is open to `ensure_signed(origin)`, the attacker fully controls `Payload.relayerFee` on the Ethereum side before generating the proof, and can act as their own relayer to submit and later claim the reward via `claim_rewards`/`claim_rewards_to`.

## Recommendation
Bound `relayer_fee` in `InboundQueue::process_message` before calling `register_reward` — e.g., add a `Config::MaxRelayerFee` constant, or require `relayer_fee` be capped as a fraction of `message.value`/`execution_fee`, rejecting or saturating excess with a new `Error` variant instead of trusting the raw Ethereum event field verbatim.

## Proof of Concept
1. On Ethereum, invoke the Gateway's outbound message function with `Payload.value = 0` and `Payload.relayerFee = u128::MAX` (or any amount far exceeding real backing).
2. Obtain the event log and a valid verifier proof (this only proves event existence, not value sanity).
3. Call `EthereumInboundQueueV2::submit(origin, event_proof)` as the attacker's own account.
4. `process_message` (`bridges/snowbridge/pallets/inbound-queue-v2/src/lib.rs:219-239`) computes `total_tip = relayer_fee.saturating_add(tip)` and calls `register_reward`, crediting `RelayerRewards` for the full inflated amount despite near-zero real `value`.
5. Call `claim_rewards_to` on `pallet-bridge-relayers`; `BridgeRewardPayer::pay_reward` → `PayAccountOnLocation::pay_reward` issues `ReserveAssetDeposited`/`DepositAsset` on AssetHub for the inflated amount, minting WETH to the attacker's chosen beneficiary, unbacked by any real bridged value.

		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}
