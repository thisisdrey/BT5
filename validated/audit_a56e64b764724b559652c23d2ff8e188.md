### Title
`StackerDBSession::get_chunks` accepts oversized chunk bodies with no size-limit check, unlike `get_latest_chunks` - ([File: libsigner/src/session.rs])

### Summary
`StackerDBSession::get_chunks` (`libsigner/src/session.rs`) pushes the raw HTTP response body returned for `GET {stackerdb_get_chunk_path}` directly into the result vector without ever comparing `body_bytes.len()` to `STACKERDB_MAX_CHUNK_SIZE`/`SIGNERS_STACKERDB_CHUNK_SIZE`, whereas the sibling function `get_latest_chunks` explicitly enforces this bound. A malicious RPC responder can therefore return an arbitrarily large HTTP 200 body for a chunk fetch, and that oversized buffer will be handed unbounded to the caller (and ultimately to `T::consensus_deserialize` via `get_latest`/`get_chunk` callers).

### Finding Description
The claimed equality is broken: in `get_chunks` [1](#0-0) 
the response `body_bytes` from `self.rpc_request("GET", &path, None, &[])` is wrapped in `Some(body_bytes)` and pushed into `payloads` with no size check at all. Compare with `get_latest_chunks`, which computes a `limit` (`SIGNERS_STACKERDB_CHUNK_SIZE` or `STACKERDB_MAX_CHUNK_SIZE`) and rejects (`None`) any body exceeding it: [2](#0-1) 

The underlying transport, `run_http_request`, reads the entire socket via `sock.read_to_end(&mut buf)` with no cap, and for non-chunked bodies simply does `buf.to_vec()` with no length enforcement at all (the `MAX_MESSAGE_LEN` bound is only applied to the chunked-transfer-encoding decode path, `HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into())`): [3](#0-2) [4](#0-3) 

So a plain (non-chunked) HTTP/1.1 response with `Content-Length` unset or arbitrarily large, or simply a connection that keeps streaming bytes until close, will be fully buffered by `read_to_end` and returned by `get_chunks` uncapped. This bypasses the size discipline that `get_latest_chunks` enforces, and the oversized buffer then flows into `get_chunk` → `get_latest`/`consensus_deserialize` call sites without any prior bound.

### Impact Explanation
A rogue node acting as the RPC server that a signer's `StackerDBSession` connects to (e.g., the signer's configured node, or any node it queries for `get_chunk`/`get_chunks`) can force the signer client to allocate and hold an arbitrarily large buffer in memory per request, since no bound analogous to `get_latest_chunks`'s check exists in `get_chunks`. This is a single-message, repeatable resource-exhaustion vector against the signer process. It does not itself forge accepted StackerDB state (the data would still normally need to pass slot-signature/version checks upstream) but it is an unbounded-memory-allocation bug reachable purely from an unprivileged RPC responder's HTTP response, matching a Critical-severity single-message DoS characteristic.

### Likelihood Explanation
Precondition: the attacker must be the node (or in control of the traffic) that a `StackerDBSession` connects to via `get_chunk`/`get_chunks` — this is the RPC server role for that call, not requiring any secret, key ownership, or admin privilege; the signer simply needs to have configured/queried this node. The attacker cost is a single crafted HTTP response, freely repeatable on every `get_chunk` call the signer makes to that endpoint.

### Recommendation
Add the same length check present in `get_latest_chunks` to `get_chunks`: compute the appropriate `limit` (`SIGNERS_STACKERDB_CHUNK_SIZE` vs `STACKERDB_MAX_CHUNK_SIZE` based on contract name) and reject/treat as `None` any `body_bytes.len() > limit` before pushing into `payloads`. Additionally, consider enforcing a hard cap inside `run_http_request`/`decode_http_body` for non-chunked bodies (e.g., checking `Content-Length` against a maximum before reading, and bounding `read_to_end`), so the transport layer itself cannot be made to buffer unbounded attacker-controlled data.

### Proof of Concept
Rust test plan (net test) mirroring the existing `socket_timeout_works_as_expected` test in `libsigner/src/session.rs`:
1. Spin up a `TcpListener` on `127.0.0.1:0`.
2. In the accepted connection, write back `"HTTP/1.1 200 OK\r\nConnection: close\r\n\r\n"` followed by `STACKERDB_MAX_CHUNK_SIZE * 10` bytes of arbitrary payload (no `Content-Length` header, so `run_http_request`'s `read_to_end` just buffers all sent bytes until close).
3. Construct a `StackerDBSession` pointed at that listener address and call `get_chunks(&[(0, 0)])`.
4. Assert `Ok(vec![Some(bytes)])` is returned and `bytes.len() == STACKERDB_MAX_CHUNK_SIZE * 10`, i.e., no rejection occurs — contrasted with an equivalent call to `get_latest_chunks(&[0])` against the same oversized response, which returns `Ok(vec![None])` due to the `body_bytes.len() > limit` check at `libsigner/src/session.rs:243`.

/// Decode an HTTP body, given the headers.
pub fn decode_http_body(headers: &HashMap<String, String>, mut buf: &[u8]) -> io::Result<Vec<u8>> {
    let chunked = if let Some(val) = headers.get("transfer-encoding") {
        val == "chunked"
    } else {
        false
    };

    let body = if chunked {
        // chunked encoding
        let ptr = &mut buf;
        let mut fd = HttpChunkedTransferReader::from_reader(ptr, MAX_MESSAGE_LEN.into());
        let mut decoded_body = vec![];
        fd.read_to_end(&mut decoded_body)?;
        decoded_body
    } else {
        // body is just as-is
        buf.to_vec()
    };

    Ok(body)
}

/// Run an HTTP request, synchronously, through the given read/write handle
/// Return the HTTP reply, decoded if it was chunked
pub fn run_http_request<S: Read + Write>(
    sock: &mut S,
    host: &str,
    verb: &str,
    path: &str,
    content_type: Option<&str>,
    payload: &[u8],
) -> Result<Vec<u8>, RPCError> {
    let content_length_hdr = if !payload.is_empty() {
        format!("Content-Length: {}\r\n", payload.len())
    } else {
        "".to_string()
    };

    let req_txt = if let Some(content_type) = content_type {
        format!(
            "{verb} {path} HTTP/1.1\r\nHost: {host}\r\nConnection: close\r\nContent-Type: {content_type}\r\n{content_length_hdr}User-Agent: libsigner/0.1\r\nAccept: */*\r\n\r\n"
        )
    } else {
        format!(
            "{verb} {path} HTTP/1.1\r\nHost: {host}\r\nConnection: close\r\n{content_length_hdr}User-Agent: libsigner/0.1\r\nAccept: */*\r\n\r\n"
        )
    };
    debug!("HTTP request\n{}", &req_txt);

    sock.write_all(req_txt.as_bytes())?;
    sock.write_all(payload)?;

    let mut buf = vec![];

    sock.read_to_end(&mut buf)?;

    let (headers, body_offset) = decode_http_response(&buf)?;
    if body_offset >= buf.len() {
        // no body
        debug!("No HTTP body");
        debug!("Headers: {:?}", &headers);
        return Ok(vec![]);
    }

    decode_http_body(&headers, &buf[body_offset..]).map_err(|e| e.into())
