### Title
Unstaked QUIC stream throttle is enforced per source-IP key, not globally across the unstaked class, allowing Sybil-distributed ingress to vastly exceed the reserved unstaked TPS budget - ([File: streamer/src/nonblocking/stream_throttle.rs])

### Summary
`StakedStreamLoadEMA::available_load_capacity_in_throttling_duration` grants every unstaked `ConnectionTableKey` (effectively every distinct source IP, since unstaked peers have no pubkey) the same fixed budget of `max_unstaked_load_in_throttling_window` streams per 100ms window, with no cross-key/global accounting for the aggregate unstaked class. An unprivileged attacker who spreads connections across many source IPs (Sybil) can multiply this per-key budget by the number of distinct IPs used, producing aggregate unstaked ingress into `fetch_stage`/sigverify far beyond the ~20% (`EXPECTED_UNSTAKED_STREAMS_RATIO`) of `max_streams_per_ms` that the throttling design assumes is reserved for the whole unstaked class.

### Finding Description
`streamer/src/nonblocking/stream_throttle.rs` defines `MAX_UNSTAKED_TPS: u64 = 200` and derives `max_unstaked_load_in_throttling_window = MAX_UNSTAKED_TPS * STREAM_THROTTLING_INTERVAL_MS / 1000` (20 streams/100ms by default), independent of stake, connection count, or number of unstaked source addresses: [1](#0-0) 

This value is looked up per-`SwQosConnectionContext` and enforced via `throttle_stream` against a `ConnectionStreamCounter` associated with a `ConnectionTableKey`: [2](#0-1) 

For unstaked peers (no pubkey), the key collapses to `ConnectionTableKey::IP(ip)`: [3](#0-2) 

`ConnectionTable::try_add_connection` reuses a single shared `stream_counter` for all connections under the same key (`connection_entry.first().map(|entry| entry.stream_counter.clone())`), so multiple connections opened from the *same* IP correctly share one throttle budget and cannot evade via connection churn from a single address: [4](#0-3) 

However, each *distinct* key (i.e., distinct source IP for unstaked traffic) gets its own independent `ConnectionStreamCounter` and its own full `max_unstaked_load_in_throttling_window` allowance. Nowhere in `SwQos`/`StakedStreamLoadEMA` is there a global counter that sums stream admission across all unstaked keys before packets are handed to `sender`/`fetch_stage`/sigverify - `increment_load` only tracks staked load for the EMA used to gate staked throttling, and unstaked load is never accumulated globally: [5](#0-4) 

The only aggregate control on the unstaked class is `max_unstaked_connections` (default 2000), which caps the *count* of admitted connections/keys in the table, not the aggregate stream throughput: [6](#0-5) 

Since `MAX_UNSTAKED_TPS`/`EXPECTED_UNSTAKED_STREAMS_RATIO` are described as the *fraction of max TPS expected to be consumed by unstaked connections* as a class, but the enforcement mechanism only grants that fixed per-key rate, an attacker distributing connections over many source IPs multiplies the effective unstaked admission rate: `total_admitted_streams_per_100ms ≈ num_distinct_unstaked_ips * max_unstaked_load_in_throttling_window`, up to the `max_unstaked_connections` cap (2000 keys), i.e. up to 2000 × 20 = 40,000 streams/100ms (400k/sec) versus the intended ~20% of `max_streams_per_ms` (100k/sec at defaults) reserved bandwidth for the whole unstaked class.

### Impact Explanation
This lets a purely unstaked (fee-free) attacker force sigverify/dedup/buffering work in `fetch_stage` that is a multiple of the documented unstaked TPS budget, simply by using more source IPs, degrading leader throughput/CPU below the cost the fee-less traffic should be permitted to impose - matching the "grossly underpriced pre-fee work" / QoS evasion bounty category referenced in the question (`bank_forks.rs` scope: work vastly exceeding fees collected).

### Likelihood Explanation
Fully reachable by an unprivileged remote attacker: no stake, gossip membership, or validator control is required, only the ability to open QUIC connections from many source IPs (a classic Sybil/cloud-IP-rotation technique) up to the `DEFAULT_MAX_UNSTAKED_CONNECTIONS` (2000) admission ceiling. Each connection needs only to stay within its own per-key throttle to avoid `throttle_stream` backoff, which is trivial to script.

### Recommendation
Add a global unstaked-load accounting mechanism analogous to `staked_throttling_enabled`/`current_load_ema` (e.g., a shared `AtomicU64` load counter incremented on every unstaked stream and decayed via an EMA), and make `available_load_capacity_in_throttling_duration(Unstaked, ..)` return a per-key share that shrinks as aggregate unstaked load across all keys approaches `EXPECTED_UNSTAKED_STREAMS_RATIO * max_streams_per_ms`, mirroring how staked capacity is already divided by `stake / total_stake`.

### Proof of Concept
Add an integration test to `streamer/src/nonblocking/stream_throttle.rs` / `swqos.rs` that:
1. Constructs a `SwQos`/`StakedStreamLoadEMA` with default config.
2. Simulates `N` distinct unstaked `SwQosConnectionContext`s with distinct `remote_address` IPs (via `ConnectionTableKey::IP`), each admitted under `max_unstaked_connections`.
3. For each of the `N` contexts, calls `available_load_capacity_in_throttling_duration(Unstaked, total_stake)` and `throttle_stream` up to that per-key cap.
4. Assert: `N * max_unstaked_load_in_throttling_window` (summed accepted streams across all keys within one `STREAM_THROTTLING_INTERVAL`) exceeds `EXPECTED_UNSTAKED_STREAMS_RATIO * max_streams_per_ms * (STREAM_THROTTLING_INTERVAL_MS/1000)` once `N` exceeds a small threshold (e.g., N=6 with default `max_streams_per_ms=500` already exceeds the 20% reserved unstaked share), demonstrating there is no code path that caps this aggregate.

    pub(crate) fn available_load_capacity_in_throttling_duration(
        &self,
        peer_type: ConnectionPeerType,
        total_stake: u64,
    ) -> u64 {
        match peer_type {
            ConnectionPeerType::Unstaked => self.max_unstaked_load_in_throttling_window,
            ConnectionPeerType::Staked(stake) => {
                if self.staked_throttling_enabled.load(Ordering::Relaxed) {
                    // 1 is added to `max_unstaked_load_in_throttling_window` to guarantee that staked
                    // clients get at least 1 more number of streams than unstaked connections.
                    self.max_staked_load_in_throttling_window
                        .saturating_mul(stake)
                        .checked_div(total_stake)
                        .unwrap_or(self.max_unstaked_load_in_throttling_window + 1)
                        .max(self.max_unstaked_load_in_throttling_window + 1)
                } else {
                    self.max_staked_load_in_throttling_window
                }
            }
        }
    }
