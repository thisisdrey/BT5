### Title
Unbounded per-packet cryptographic cost in unauthenticated handshake processing enables remote CPU-exhaustion DoS - (File: `handshake_manager.go`, `handshake/machine.go`)

### Summary
The External Report's core issue is that `RFTLib` invokes an untrusted external callback (`tokenRequestCB()`) with no gas cap, letting a malicious counterparty force the caller to burn unbounded computation/gas. The reachable analog in Nebula is `HandshakeManager.HandleIncoming` → `beginHandshake`, which runs full Noise handshake crypto, certificate recombination, and CA-signature verification for every inbound stage-1 packet from a completely unauthenticated remote address — before any certificate has been validated and with no per-source cost cap or rate limiting.

### Finding Description
`HandshakeManager.HandleIncoming` dispatches any packet with `MessageCounter == 1` straight to `beginHandshake`, gated only by a remote-allow-list check, not by CA validity [1](#0-0) . `beginHandshake` then constructs a new `handshake.Machine` and calls `machine.ProcessPacket`, which performs a Noise `ReadMessage` (elliptic-curve DH) and, when the peer message carries payload data, calls `processPayload`/`validateCert` [2](#0-1) .

`validateCert` performs `cert.Recombine` on attacker-supplied `payload.Cert` bytes and then calls `m.verifier(rc)`, which runs full CA-pool signature verification (`CAPool.verify`/`VerifyCertificate`, including elliptic-curve signature checks) [3](#0-2) . This verifier work executes purely on attacker-controlled input and completes (or fails) only after the expensive DH + signature-verification path has run — the same "untrusted callee decides how much work the caller does" pattern as the reported `tokenRequestCB()` gas-griefing issue, except the "gas" here is CPU time on a Noise DH + ECDSA/EdDSA verification per packet.

No rate limiting, per-source cookie, or work-cap mechanism exists anywhere in the codebase to bound how many such stage-1 packets an unauthenticated remote address can force the node to process: a repository-wide search for rate limiting, cookie-based mitigation, or handshake DoS protection returns no matches. `HandleIncoming`'s only other decision points before `beginHandshake` are cheap comparisons (`h.Subtype`, `h.RemoteIndex == 0`, remote-allow-list) that do not throttle repeated attempts from the same or spoofed source addresses [1](#0-0) .

### Impact Explanation
An attacker with no valid CA-signed certificate can send a flood of spoofed or unspoofed UDP stage-1 handshake packets. Each one forces the victim node to perform a Noise Diffie-Hellman computation and, if a cert payload is attached, a full certificate recombination plus CA signature verification, all before the packet is ever authenticated. Because this cost is paid unconditionally and there is no cap, an attacker can drive sustained CPU exhaustion on the node, degrading or denying legitimate handshake processing — a remote availability/DoS impact reachable without any credentials.

### Likelihood Explanation
Likelihood is high: `beginHandshake` is reachable by any host that can send a single UDP packet to the listening port, gated only by the (often permissive/default-allow) remote-allow-list check, and the expensive verification path is entered any time the attacker includes a certificate payload in a spoofed stage-1 message. No cost cap, cookie challenge, or rate limiter currently exists to blunt repeated attempts.

### Recommendation
Introduce a bounded work/rate cap on unauthenticated stage-1 handshake processing before doing DH and CA-signature verification — e.g., per-source-address rate limiting or a stateless cookie/proof-of-work challenge (similar to WireGuard's cookie reply mechanism) so that expensive Noise DH and `CAPool.verify` calls are only performed after a cheap validity check, and cap the number of concurrent/pending handshake Machines allocated per remote address in `HandshakeManager`.

### Proof of Concept
1. Attacker sends a UDP packet with `header.H.MessageCounter == 1`, `RemoteIndex == 0`, valid `HandshakeIXPSK0` subtype, and an embedded oversized/garbage `payload.Cert`, to the victim's listening port, spoofing or varying the source address.
2. `HandleIncoming` routes it to `beginHandshake` [4](#0-3) , which creates a new `handshake.Machine` and calls `ProcessPacket`, performing a Noise DH operation and then `validateCert`, which recombines the certificate and calls the CA-pool verifier (ECC signature check) [5](#0-4) .
3. Repeating this at high rate from many source addresses (no rate limit exists) forces the victim to continuously perform DH + certificate + signature verification work, exhausting CPU with no cost cap on the attacker's side — the handshake-analog of unbounded gas consumption from an untrusted external call.

func (hm *HandshakeManager) HandleIncoming(via ViaSender, packet []byte, h *header.H) {
	// Gate on known handshake subtypes. Unknown subtypes (or future ones we
	// don't yet support) are dropped here rather than silently routed through
	// the IX path. Add a case when introducing a new pattern.
	switch h.Subtype {
	case header.HandshakeIXPSK0:
		// supported
	default:
		hm.l.Debug("dropping handshake with unsupported subtype",
			"from", via, "subtype", h.Subtype)
		return
	}

	// First remote allow list check before we know the vpnIp
	if !via.IsRelayed {
		if !hm.lightHouse.GetRemoteAllowList().AllowUnknownVpnAddr(via.UdpAddr.Addr()) {
			hm.l.Debug("lighthouse.remote_allow_list denied incoming handshake", "from", via)
			return
		}
	}

	// First message of a new handshake. The wire format requires RemoteIndex
	// to be zero here (the initiator has no responder index to fill in yet),
	// and generateIndex never allocates 0, so any non-zero RemoteIndex on a
	// stage-1 packet is malformed or someone probing for an index collision.
	// Drop without paying the cost of running noise on a pending Machine.
	if h.MessageCounter == 1 {
		if h.RemoteIndex != 0 {
			hm.l.Debug("dropping stage-1 handshake with non-zero RemoteIndex",
				"from", via, "remoteIndex", h.RemoteIndex)
			return
		}
		hm.beginHandshake(via, packet, h)
		return

func (m *Machine) ProcessPacket(out, packet []byte) ([]byte, *Result, error) {
	if m.failed {
		return nil, nil, ErrMachineFailed
	}
	if len(packet) < header.Len {
		return nil, nil, ErrPacketTooShort
	}
	// Reject packets whose subtype doesn't match the one this Machine was
	// built for. A pending handshake that suddenly receives a different
	// subtype on its index is either a stray packet that matched by chance
	// or a peer protocol violation; drop it without failing the Machine so
	// the legitimate retransmit can still complete.
	if header.MessageSubType(packet[1]) != m.subtype {
		return nil, nil, ErrSubtypeMismatch
	}
	if m.result.Initiator && m.hs.MessageIndex() == 0 {
		m.failed = true
		return nil, nil, ErrInitiateNotCalled
	}

	// The (eKey, dKey) ordering here is correct for IX, where the initiator
	// completes the handshake by reading the responder's stage-2 message.
	// noise returns (cs1, cs2) where cs1 is the initiator->responder cipher.
	// For 3-message patterns where a responder finishes by reading the final
	// message, this ordering would be wrong; revisit when XX/pqIX lands.
	msg, eKey, dKey, err := m.hs.ReadMessage(nil, packet[header.Len:])
	if err != nil {
		// Noise ReadMessage failed. The noise library checkpoints and rolls back
		// on failure, so the Machine is still alive. The caller can retry with
		// a different packet.
		return nil, nil, fmt.Errorf("noise ReadMessage: %w", err)
	}

	// From here on, noise state has advanced. Any error is fatal.
	flags := m.peerMsgFlags()

	if err := m.processPayload(msg, flags); err != nil {
		return nil, nil, err
	}

func (m *Machine) validateCert(payload Payload) error {
	cred := m.getCred(m.myVersion)
	if cred == nil {
		m.failed = true
		return fmt.Errorf("%w: %v", ErrNoCredential, m.myVersion)
	}
	rc, err := cert.Recombine(
		cert.Version(payload.CertVersion),
		payload.Cert,
		m.hs.PeerStatic(),
		cred.Cert.Curve(),
	)
	if err != nil {
		m.failed = true
		return fmt.Errorf("recombine cert: %w", err)
	}

	if !bytes.Equal(rc.PublicKey(), m.hs.PeerStatic()) {
		m.failed = true
		return ErrPublicKeyMismatch
	}

	// Version negotiation, if the peer sent a different version and we have it, switch
	if rc.Version() != m.myVersion {
		if m.getCred(rc.Version()) != nil {
			m.myVersion = rc.Version()
		}
	}

	verified, err := m.verifier(rc)
	if err != nil {
		m.failed = true
		return fmt.Errorf("verify cert: %w", err)
	}

	m.result.RemoteCert = verified
	m.remoteCertSet = true
	return nil
}
