## Analysis

The Compound `_setCreditLimit` bug is a "protocol pause fails to block a privileged state-mutating admin function that the pause is explicitly designed to block" bug class. The strongest reachable analog in marginfi is the group's `panic_pause` mechanism failing to guard `lending_pool_configure_bank`.

### Title
Panic-pause does not block bank configuration changes via `LendingPoolConfigureBank`, contradicting documented pause guarantees - (File: `programs/marginfi/src/instructions/marginfi_group/configure_bank.rs`)

### Summary
When the protocol is panic-paused via `panic_pause`, marginfi's documentation states that "Admin bank configuration changes that route through `LendingPoolConfigureBank`" are blocked. In the actual code, the `LendingPoolConfigureBank` account validation struct performs no pause check whatsoever, so `lending_pool_configure_bank` (and its scoped variants `LendingPoolConfigureBankInterestOnly`, `LendingPoolConfigureBankLimitsOnly`, `LendingPoolConfigureBankEmode`, `LendingPoolConfigureBankOracle`) remain fully callable while `panic_state.is_paused()` is true.

### Finding Description
`panic_pause` is meant to act as an emergency circuit breaker that halts protocol state changes — including admin bank configuration — while an incident is investigated [1](#0-0) . The instruction responsible for the vast majority of bank config mutations — weights, limits, operational state, risk tier, oracle confidence/age, flags — is `lending_pool_configure_bank`, and its `Accounts` struct only validates `has_one = admin` and `has_one = group`, with no constraint referencing `is_protocol_paused()`: [2](#0-1) 

Contrast this with `LendingPoolEmissionsDeposit` in the very same file, which explicitly enforces the pause via an account constraint: [3](#0-2) 

The same gap exists in the delegate-scoped configuration paths, none of which check pause state: [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) 

Notably, the test suite itself flags this as an unverified gap with an explicit TODO right after the pause-mode spec file's tests: [8](#0-7) 

This is the direct analog to the reported Compound issue: a documented/expected pause invariant ("no configuration changes while paused") is not enforced in the actual gated instruction, so the pause fails to act as the circuit breaker it's advertised to be.

### Impact Explanation
During a panic-pause — which is triggered specifically because something is wrong (compromised key, oracle manipulation, or other active incident) — bank risk parameters (asset/liability weights, operational state, risk tier, oracle max confidence/age, deposit/borrow limits, freeze/tokenless-repayment flags) can still be silently changed. If the pause was triggered because of a compromised `admin` key or a `pause_delegate_admin`-only response to a discovered issue, this gap means the party that triggered the pause has no guarantee that bank configuration is frozen during the incident window, undermining the entire purpose of the pause as an emergency stop and potentially enabling further unauthorized state changes (e.g., manipulating weights/oracle config) precisely when the protocol is supposed to be locked down.

### Likelihood Explanation
Reaching this state requires no special privilege beyond what `admin`/delegate admins already hold, and no additional preconditions — the pause simply has no effect on this instruction. Given the instruction is documented as pause-gated and other similar instructions (`LendingPoolEmissionsDeposit`) do implement the pause check correctly, this is a straightforward oversight rather than a deep architectural issue, and would be exercised any time configuration changes are attempted during an active pause window (whether accidental, by a compromised key, or as part of a coordinated attack that also compromises the pause response).

### Recommendation
Add a pause constraint to `LendingPoolConfigureBank` (and the delegate-scoped variants `LendingPoolConfigureBankInterestOnly`, `LendingPoolConfigureBankLimitsOnly`, `LendingPoolConfigureBankEmode`, `LendingPoolConfigureBankOracle`), mirroring the pattern already used in `LendingPoolEmissionsDeposit`:
```rust
constraint = !group.load()?.is_protocol_paused() @ MarginfiError::ProtocolPaused
```
on the `group` account in each corresponding `Accounts` struct, consistent with the documented behavior in `PERMISSIONS_AND_ROLES.md`.

### Proof of Concept
1. `global_fee_admin` or `pause_delegate_admin` calls `panic_pause`, setting `fee_state.panic_state` to paused [9](#0-8) .
2. While paused, the group `admin` calls `lending_pool_configure_bank` with a `BankConfigOpt` changing e.g. `asset_weight_init`, `liability_weight_maint`, `operational_state`, or `oracle_max_confidence`.
3. The instruction proceeds and mutates `Bank.config` because `LendingPoolConfigureBank`'s `Accounts` validation contains no pause constraint [10](#0-9) , unlike the sibling `LendingPoolEmissionsDeposit` instruction in the same file which does enforce `!is_protocol_paused()`.
4. Confirmed as an untested/open gap by the repo's own test TODO in `e05_panicMode.spec.ts` [11](#0-10) .

## Protocol Panic-Pause

When the `global_fee_admin` or `pause_delegate_admin` invokes `panic_pause`, the protocol enters a
group-wide paused state. The pause auto-expires (see `PanicState::PAUSE_DURATION_SECONDS`) and is
rate-limited (max consecutive pauses per window, max per day) so it cannot be held indefinitely.

### Blocked while paused

All normal user flows are disabled:

- Deposit, Borrow, Withdraw, Repay (both native banks and integration banks — Kamino, Drift,
  Juplend, Solend)
- Order placement / order flows
- Account transfer
- Classic liquidation (`LendingAccountLiquidate`)
- Permissionless bank-fee collection
- Permissionless bad-debt settlement (`HandleBankruptcy` when called by a non-admin, even on banks
  with the `PERMISSIONLESS_BAD_DEBT_SETTLEMENT` flag)
- Admin bank configuration changes that route through `LendingPoolConfigureBank`

pub fn lending_pool_configure_bank(
    ctx: Context<LendingPoolConfigureBank>,
    bank_config: BankConfigOpt,
) -> MarginfiResult {
    let mut bank = ctx.accounts.bank.load_mut()?;

    // If settings are frozen, you can only update the deposit and borrow limits, everything else is ignored.
    if bank.get_flag(FREEZE_SETTINGS) {
        bank.configure_unfrozen_fields_only(&bank_config)?;

        msg!("WARN: Only deposit+borrow limits updated. Other settings IGNORED for frozen banks!");

        emit!(LendingPoolBankConfigureFrozenEvent {
            header: GroupEventHeader {
                marginfi_group: ctx.accounts.group.key(),
                signer: Some(*ctx.accounts.admin.key)
            },
            bank: ctx.accounts.bank.key(),
            mint: bank.mint,
            deposit_limit: bank.config.deposit_limit,
            borrow_limit: bank.config.borrow_limit,
        });
    } else {
        // Settings are not frozen, everything updates
        bank.configure(&bank_config)?;
        msg!("Bank configured!");

        let group = ctx.accounts.group.load()?;
        bank.emode.validate_entries_with_liability_weights(
            &bank.config,
            group.emode_max_init_leverage,
            group.emode_max_maint_leverage,
        )?;

        emit!(LendingPoolBankConfigureEvent {
            header: GroupEventHeader {
                marginfi_group: ctx.accounts.group.key(),
                signer: Some(*ctx.accounts.admin.key)
            },
            bank: ctx.accounts.bank.key(),
            mint: bank.mint,
            config: bank_config,
        });
    }

    Ok(())
}

```rust
pub fn panic_pause(ctx: Context<PanicPause>) -> Result<()> {
    let mut fee_state = ctx.accounts.fee_state.load_mut()?;
    let current_timestamp = Clock::get()?.unix_timestamp;

    // Update panic state if the current pause has expired
    fee_state.panic_state.unpause_if_expired(current_timestamp);

    fee_state.panic_state.pause(current_timestamp)?;

    msg!("Protocol paused at timestamp: {}", current_timestamp);
```
