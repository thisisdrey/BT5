### Title
Unauthenticated remote shutdown of signer event receiver via `POST /shutdown` - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::bind` opens a plain `tiny_http` server with no peer allowlist, TLS, or shared-secret check, and `SignerEventReceiver::next_event` treats any request to `/shutdown` as a valid termination command. Any remote party able to open a TCP connection to the bound event-receiver socket can send `POST /shutdown` and permanently stop the signer's event pipeline.

### Finding Description
`EventReceiver::bind` for `SignerEventReceiver` just does `HttpServer::http(listener)` with no authentication mechanism at all [1](#0-0) . In `next_event`, the dispatch logic checks `request.url()` and, for `/shutdown`, unconditionally sets `stop_signal` to true and returns `EventError::Terminated`, regardless of who sent the request: [2](#0-1) . This is the exact same code path used internally by `SignerStopSignaler::send`, which crafts the literal bytes `POST /shutdown HTTP/1.1\r\n...` to signal its own event receiver to stop [3](#0-2) . There is no check that the request came from the local node's event dispatcher (e.g. no shared secret, no loopback-only enforcement visible in this code, no signature). `EventReceiver::main_loop` treats `Err(EventError::Terminated)` from `next_event` as a clean exit signal and `break`s out of the loop permanently [4](#0-3) . Once broken, the loop is gone — there is no retry/restart logic in `main_loop`, so the signer stops receiving new blocks, block-validation responses, burn-block events, and StackerDB chunks until manually restarted.

I was not able to fully confirm from the index whether the production deployment binds the event-receiver socket to `0.0.0.0` (remotely reachable) or to `127.0.0.1` (loopback-only) — this depends on the `endpoint` configuration value in `stacks-signer/src/config.rs`, which I could not fully inspect before running out of tool iterations. If the configured `event_recv` bind address is anything other than loopback-only (which is the common signer deployment pattern to allow the node's event-observer to reach the signer, potentially across hosts), this is a valid, complete, and unauthenticated remote DoS.

### Impact Explanation
A successful `POST /shutdown` permanently halts `main_loop`, meaning the signer process stops consuming events from its own node (block proposals, StackerDB chunks, burn blocks). This is a single-message, unauthenticated DoS against the signer's event-processing pipeline, matching the "Critical - remote crash/unauthenticated DoS from few messages" category, assuming the port is remotely reachable.

### Likelihood Explanation
The attacker only needs TCP connectivity to the bound event-receiver socket and no credentials, secret, or privileged role — sending the exact bytes that `SignerStopSignaler::send` itself sends is sufficient. Attack cost is a single TCP connection and message; it is trivially repeatable. The severity is entirely gated on whether that socket is reachable from an untrusted network (which I could not conclusively verify from the indexed code, since the bind address is operator/config-controlled via `stacks-signer/src/config.rs`, whose relevant `endpoint`/bind-address logic I was unable to finish reviewing).

### Recommendation
Add an authentication check to the `/shutdown` branch in `SignerEventReceiver::next_event` (and ideally to all POST handlers) — e.g., require a shared secret/token configured out-of-band between the node's event dispatcher and the signer, or bind the event-receiver socket to loopback only and document/enforce that it must not be exposed to untrusted networks. At minimum, `/shutdown` should not be a bare unauthenticated HTTP path indistinguishable from any other remote sender.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module)
use std::net::{TcpStream, SocketAddr};
use std::io::Write;
use std::thread;

#[test]
fn test_unauthenticated_shutdown() {
    let mut receiver: SignerEventReceiver<crate::v0::messages::SignerMessage> =
        SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();

    // Attacker: raw TCP connection, no secret, no prior get_stop_signaler() call
    let mut stream = TcpStream::connect(bound).unwrap();
    let body = "attack";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{}",
        bound, body.len(), body
    );
    stream.write_all(req.as_bytes()).unwrap();

    let err = receiver.next_event().unwrap_err();
    assert!(matches!(err, EventError::Terminated));
    assert!(receiver.is_stopped());
}
```
This demonstrates that an unprivileged remote TCP sender — without ever calling `get_stop_signaler()` — can force `next_event()` to return `EventError::Terminated`, which in `main_loop` triggers a permanent `break`.
