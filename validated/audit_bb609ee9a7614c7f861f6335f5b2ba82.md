### Title
Stale `PromiseYieldReceipt`/`PromiseYieldTimeout` entries survive account deletion, letting a timed-out `PromiseResume` execute a deleted account's queued self-call actions against a recreated account - (File: core/store/src/utils/mod.rs, runtime/runtime/src/lib.rs)

### Summary
`remove_account` (core/store/src/utils/mod.rs:504-575), called by `action_delete_account` (runtime/runtime/src/actions.rs:314-390), removes `TrieKey::Account`, `ContractCode`, `AccessKey`/`GasKeyNonce`, and `ContractData`, but never touches `TrieKey::PromiseYieldReceipt`, `TrieKey::PromiseYieldStatus`, or the global `TrieKey::PromiseYieldTimeout` FIFO queue entries created by `create_promise_yield_receipt`/`enqueue_promise_yield_timeout`. If an account creates a self-directed `PromiseYield` (via `promise_yield_create`) and is then deleted before the yield times out, the queued timeout entry and the parked `PromiseYieldReceipt` remain in state under the same account_id, keyed independently of the account's liveness.

### Finding Description
`create_promise_yield_receipt` (runtime/runtime/src/ext.rs:353-369) always creates a `PromiseYield` receipt with `receiver_id == self.context.current_account_id` [1](#0-0) , and `function_call.rs` enqueues a `PromiseYieldTimeout { account_id, data_id, expires_at }` entry into the shard's global FIFO queue at the same time the `PromiseYield` receipt is emitted [2](#0-1) . When the `PromiseYield` receipt is processed it is persisted under `TrieKey::PromiseYieldReceipt { receiver_id, data_id }` via `set_promise_yield_receipt` [3](#0-2) .

`remove_account` (core/store/src/utils/mod.rs:504-575) deletes `TrieKey::Account`, `ContractCode`, access/gas keys, and `ContractData` for the account, but has no logic that scans for or removes `TrieKey::PromiseYieldReceipt`, `TrieKey::PromiseYieldStatus`, `TrieKey::YieldIdToDataId`/`DataIdToYieldId`, or the corresponding entry in the `TrieKey::PromiseYieldTimeout` queue [4](#0-3) . `action_delete_account` calls `remove_account` unconditionally as long as storage-usage and gas-key-balance caps are satisfied, with no check for pending yields [5](#0-4) .

`resolve_promise_yield_timeouts` (runtime/runtime/src/lib.rs:3009-3105) runs unconditionally at the end of every chunk's receipt processing, independent of any resume call. For each expired queue entry it only checks whether `TrieKey::PromiseYieldReceipt { receiver_id: queue_entry.account_id, data_id }` still exists in the trie [6](#0-5) ; since `remove_account` never deleted that key, the check passes and a `PromiseResume { data: None }` is synthesized and forwarded to the same account [7](#0-6) . When that resume is later processed, `apply_action_receipt` is called on the still-present stale yield receipt (`lib.rs:1514-1562`) whose `receiver_id == predecessor_id == account_id` [8](#0-7) , executing the original (now stale) actions as a self-call against whatever account/contract currently occupies that `account_id` — with no re-validation that the account is the same entity that created the yield.

### Impact Explanation
This is an authorization-escalation / liveness bug: a self-call ("predecessor == receiver == self") guard is a common trust boundary many contracts use to gate privileged internal-only logic (e.g., callback finalization after a cross-contract call). Because none of the `PromiseYield*` trie state is cleaned up on account deletion, a stale self-call queued by the account before deletion will still fire — purely from block-height elapsing, with no attacker action required after the initial setup — against whatever account/contract subsequently occupies that same `account_id`, forging the "self" trust check for code that never authorized it.

### Likelihood Explanation
Preconditions: the attacker must control account A, invoke `promise_yield_create` with `yield_timeout_length_in_blocks` scheduled in the future, then delete A via `DeleteAccountAction` (allowed as long as storage/gas-key caps are satisfied — checked in `action_delete_account`), and account A's name must subsequently become available and be recreated with new state/contract before the timeout height is reached. The mechanics (delete + recreate + advance blocks) are fully reachable by an ordinary unprivileged client using only standard transactions (`FunctionCall`, `DeleteAccount`, `CreateAccount`/subaccount creation) — no validator, node-operator, or privileged access is needed. The main constraint on real-world impact is that the "new occupant" of the exact same `account_id` must independently exist and deploy self-trusting logic before the timeout fires, which narrows (but does not eliminate) practical exploitation scenarios (e.g., re-registering an abandoned subaccount name, contract migration/redeploy flows that delete-then-recreate the same account).

### Recommendation
On account deletion, also purge any pending `PromiseYield` state for that account: iterate/remove `TrieKey::PromiseYieldReceipt`, `TrieKey::PromiseYieldStatus`, and `YieldIdToDataId`/`DataIdToYieldId` entries for `account_id` in `remove_account`, and either (a) disallow `DeleteAccountAction` while the account has pending yields, or (b) have `resolve_promise_yield_timeouts` cross-check that the parked yield receipt's stored predecessor/creation context still corresponds to a live account epoch (e.g., an account "generation" counter) before synthesizing/executing the `PromiseResume`.

### Proof of Concept
Runtime integration test (extending `runtime/runtime/src/tests/apply.rs` or `test-loop-tests/src/tests/yield_timeouts.rs` patterns):
1. Deploy a test contract to account A exposing a method that creates a `PromiseYield` self-callback (`call_yield_create_return_promise`) with a short `yield_timeout_length_in_blocks`.
2. Submit the yield-creating call; confirm state contains `TrieKey::PromiseYieldReceipt{A, data_id}` and a `TrieKey::PromiseYieldTimeout` entry.
3. Submit `DeleteAccountAction` for A (with a beneficiary), confirm `TrieKey::Account{A}` is gone from state but assert `TrieKey::PromiseYieldReceipt{A, data_id}` still exists (proving the cleanup gap).
4. Recreate account A (e.g., `CreateAccountAction` + `DeployContractAction` deploying a different contract with a self-call-gated privileged method).
5. Advance blocks to `yield_timeout_height`; assert `resolve_promise_yield_timeouts` produces a `PromiseResume` receipt (per `find_promise_resume_receipt_ids_from_latest_block`-style helper).
6. Advance one more block and assert the stale yield's original actions executed against the *new* account A's contract/state (e.g., its self-gated method ran), proving stale-action execution occurred purely from block elapsing with no additional attacker transaction after setup.

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}
