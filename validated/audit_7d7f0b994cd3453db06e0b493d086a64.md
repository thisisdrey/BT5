### Title
Missing Validation on `CreateRepositoryFromSnapshotRequest` Fields Enables Path-Traversal Tar Extraction and SSRF - ([File: internal/gitaly/service/repository/create_repository_from_snapshot.go])

### Summary
`CreateRepositoryFromSnapshot` mirrors the `Gateway.query()` bug class: several request fields that flow directly into a privileged filesystem/network operation are never validated for shape, scheme, or contents, and the archive extraction that follows offers no protection against path/symlink escape, unlike the hardened tar-extraction logic that exists elsewhere in the same codebase.

### Finding Description
`validateCreateRepositoryFromSnapshotRequest`-equivalent logic in `CreateRepositoryFromSnapshot` only validates the target `Repository` field; it performs no validation on `in.GetHttpUrl()`, `in.GetHttpAuth()`, or the eventual archive content: [1](#0-0) 

The `untar` helper builds an HTTP request straight from `in.GetHttpUrl()` with no scheme/host allow-listing, then pipes the raw HTTP response body into an unrestricted GNU `tar -C path -xvf -` invocation: [2](#0-1) 

The `NOTE` comment directly in the code acknowledges the gap: *"The received archive is trusted a lot. Before pointing this RPC at endpoints not under our control, it should undergo a lot of hardening."* [3](#0-2) 

This is the same bug class as the `Gateway.query()` finding: request-controlled fields (`HttpUrl`, and implicitly the archive it returns) are accepted and used to drive privileged behavior (an outbound HTTP fetch plus unrestricted `tar` extraction into a repository directory) without checking that they are sane/expected values. Contrast this with the equivalent snapshot-extraction code path added later in `replicate.go`, which explicitly guards against absolute symlinks, symlink-target escape, and hard-link escape before writing any file: [4](#0-3) 

No such checks exist for the archive fetched by `untar` — it is handed to an external `tar` binary whose extraction behavior (handling of symlinks, hardlinks, and `..` segments) is not validated by Gitaly at all, and `HttpUrl` itself is not restricted to any particular host/scheme, so if the caller does not also always supply `ResolvedAddress` (which is only conditionally used), the RPC will fetch and extract an archive from an arbitrary attacker-supplied URL.

### Impact Explanation
If the archive returned by the unvalidated `HttpUrl` is attacker-influenced (e.g., an internal service reachable from Gitaly, or a compromised/malicious HTTP endpoint), the raw `tar` extraction can place symlinks/hardlinks or `../`-style entries that escape the intended target repository directory, corrupting or overwriting arbitrary files on the storage volume that the Gitaly process can write to. Additionally, the unvalidated `HttpUrl` allows the RPC to be used as an SSRF primitive against internal network endpoints when `ResolvedAddress` is not enforced by the caller. Both outcomes go beyond the repository being created and can affect the broader Gitaly node.

### Likelihood Explanation
`CreateRepositoryFromSnapshot` is a first-class Gitaly RPC (`CreateRepositoryFromSnapshotRequest`) reachable through the standard `RepositoryService`. Any caller with access to invoke this RPC (e.g., through GitLab Rails/Workhorse proxying a user-triggered import/snapshot action) controls `HttpUrl`/`HttpAuth` end-to-end. Since Gitaly itself performs no scheme/host validation and no post-extraction path checks, exploitation only requires control over, or ability to redirect, the HTTP endpoint content — a realistic scenario for import/fork/snapshot-style flows.

### Recommendation
- Validate `in.GetHttpUrl()`: enforce an allow-listed scheme (`http`/`https`), and require `ResolvedAddress` to be present and consistent with existing DNS-rebinding protections (as already done for `CreateRepositoryFromURL`).
- Replace the raw external `tar -xvf` invocation in `untar` with the same manually-implemented, security-checked extraction routine used by `extractTarToDirectory`/`extractFile` in `replicate.go` (absolute-symlink rejection, symlink/hardlink target containment checks, and `..`-safe path joins) rather than delegating to an unrestricted external `tar` process.
- Add explicit request validation analogous to other RPCs (compare `validateCreateRepositoryFromURLRequest`, which rejects an empty `Url`): [5](#0-4) 

### Proof of Concept
1. An attacker controls (or can redirect, e.g., via an open redirect or compromised internal service) the HTTP endpoint referenced by `CreateRepositoryFromSnapshotRequest.HttpUrl`.
2. The attacker's server responds with a crafted tar archive containing, e.g., a symlink entry `evil -> ../../../../etc` followed by a regular file entry `evil/passwd` with attacker-controlled contents.
3. `CreateRepositoryFromSnapshot` calls `s.untar`, which fetches the archive and extracts it with `tar -C <repoPath> -xvf -` with no post-processing validation, allowing GNU tar's own symlink-following semantics to write `evil/passwd` outside `repoPath` (exact behavior depends on the `tar` implementation/flags, which Gitaly does not constrain).
4. Because `HttpUrl` is never restricted to expected hosts/schemes and `ResolvedAddress` is optional, the same code path can also be pointed at internal-only HTTP services for SSRF purposes.

Note: I was unable to directly execute `tar`'s runtime symlink-following behavior in this environment to confirm the exact escape primitive (this depends on the specific GNU/BSD tar version bundled with Gitaly), but the code-level absence of any validation on `HttpUrl` and any post-extraction containment checks (in contrast to the hardened logic that exists in `replicate.go`) is confirmed directly from the source.

func (s *server) untar(ctx context.Context, path string, in *gitalypb.CreateRepositoryFromSnapshotRequest) error {
	req, err := http.NewRequestWithContext(ctx, "GET", in.GetHttpUrl(), nil)
	if err != nil {
		return structerr.NewInvalidArgument("Bad HTTP URL: %w", err)
	}

	client := httpClient
	if resolvedAddress := in.GetResolvedAddress(); resolvedAddress != "" {
		client, err = newResolvedHTTPClient(in.GetHttpUrl(), resolvedAddress)
		if err != nil {
			return structerr.NewInvalidArgument("creating resolved HTTP client: %w", err)
		}
	}

	if in.GetHttpAuth() != "" {
		req.Header.Set("Authorization", in.GetHttpAuth())
	}

	rsp, err := client.Do(req)
	if err != nil {
		return structerr.NewInternal("HTTP request failed: %w", err)
	}
	defer rsp.Body.Close()

	if rsp.StatusCode < http.StatusOK || rsp.StatusCode >= http.StatusMultipleChoices {
		return structerr.NewInternal("HTTP server: %s", rsp.Status)
	}

	cmd, err := command.New(ctx, s.logger, []string{"tar", "-C", path, "-xvf", "-"}, command.WithStdin(rsp.Body))
	if err != nil {
		return err
	}

	return cmd.Wait()
}

// extractTarToDirectory extracts a tar archive to the specified directory using Go's tar package
func (s *server) extractTarToDirectory(ctx context.Context, reader io.Reader, targetDir string) error {
	targetDir = filepath.Clean(targetDir)
	tarReader := tar.NewReader(reader)

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()
		default:
		}

		header, err := tarReader.Next()
		if err == io.EOF {
			break // End of archive
		}
		if err != nil {
			return fmt.Errorf("reading tar header: %w", err)
		}

		targetPath := filepath.Join(targetDir, header.Name)

		if !strings.HasPrefix(targetPath, targetDir+string(os.PathSeparator)) &&
			targetPath != targetDir {
			return fmt.Errorf("invalid file path in tar: %s", header.Name)
		}

		switch header.Typeflag {
		case tar.TypeDir:
			if err := os.MkdirAll(targetPath, os.FileMode(header.Mode)); err != nil {
				return fmt.Errorf("creating directory %s: %w", targetPath, err)
			}

		case tar.TypeReg:
			if err := s.extractFile(ctx, tarReader, targetPath, header); err != nil {
				return fmt.Errorf("extracting file %s: %w", targetPath, err)
			}

		case tar.TypeSymlink:
			if filepath.IsAbs(header.Linkname) {
				return fmt.Errorf("absolute symlink not allowed: %s -> %s", header.Name, header.Linkname)
			}

			// Resolve the relative symlink target from the symlink's parent directory
			// and verify it stays within the extraction boundary, consistent with the
			// hard link validation below.
			resolvedTarget := filepath.Join(filepath.Dir(targetPath), header.Linkname)
			if !strings.HasPrefix(resolvedTarget, targetDir+string(os.PathSeparator)) &&
				resolvedTarget != targetDir {
				return fmt.Errorf("symlink target escapes extraction directory: %s -> %s", header.Name, header.Linkname)
			}

			// Remove existing file/symlink if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for symlink %s: %w", targetPath, err)
			}

			if err := os.Symlink(header.Linkname, targetPath); err != nil {
				return fmt.Errorf("creating symlink %s -> %s: %w", targetPath, header.Linkname, err)
			}

		case tar.TypeLink:
			linkTarget := filepath.Join(targetDir, header.Linkname)

			if !strings.HasPrefix(linkTarget, targetDir+string(os.PathSeparator)) &&
				linkTarget != targetDir {
				return fmt.Errorf("invalid hard link target: %s", header.Linkname)
			}

			// Remove existing file if it exists
			if err := os.Remove(targetPath); err != nil && !os.IsNotExist(err) {
				return fmt.Errorf("removing existing file for hard link %s: %w", targetPath, err)
			}

			if err := os.Link(linkTarget, targetPath); err != nil {
				return fmt.Errorf("creating hard link %s -> %s: %w", targetPath, linkTarget, err)
			}
