### Title
FreezeBalanceV2Processor (TVM native contract) omits the `supportUnfreezeDelay()` migration-gate check present in the normal FreezeBalanceV2Actuator path - (File: actuator/src/main/java/org/tron/core/vm/nativecontract/FreezeBalanceV2Processor.java)

### Summary
`FreezeBalanceV2Actuator`, the actuator used for ordinary `FreezeBalanceV2Contract` transactions, refuses to run unless the committee has enabled the "Freeze v2" staking model via the dynamic property flag checked by `dynamicStore.supportUnfreezeDelay()` [1](#0-0) . The equivalent TVM-reachable code path, `FreezeBalanceV2Processor.validate()`, which backs the `freezeBalanceV2` native/precompiled operation invocable from any smart contract, never performs this check [2](#0-1) . This mirrors the reported `vest()`-during-`migrationMode` bug: a state-mutating operation is missing the same "is the new mechanism actually enabled/migrated" gate that its sibling entry point enforces.

### Finding Description
The freeze/unfreeze v1→v2 staking migration in java-tron is controlled by the dynamic property `ALLOW_UNFREEZE_DELAY`, exposed as `supportUnfreezeDelay()` on `DynamicPropertiesStore` [3](#0-2) . Both `FreezeBalanceActuator` (old freeze) and `FreezeBalanceV2Actuator` (new freeze) explicitly consult this flag to ensure the two mechanisms are mutually exclusive during the migration window: the old actuator rejects freezing once v2 is opened [4](#0-3) , and the new actuator rejects freezing until v2 has been explicitly opened by committee proposal [1](#0-0) .

`FreezeBalanceV2Processor`, which implements the identical freeze-v2 state mutation (`addFrozenBalanceForBandwidthV2`, `addFrozenForTronPowerV2`, weight accounting, etc.) but is invoked from TVM contract execution via `Program.java`, contains none of this migration-state validation — its `validate()` only checks address validity, account existence, balance sufficiency, and resource-type validity, and its `execute()` directly mutates `FrozenV2`-related account state and total weights unconditionally [5](#0-4) . The only gate on TVM freeze operations at all is `VMConfig.allowTvmFreeze()`/`ALLOW_TVM_FREEZE`, which governs whether TVM-level freeze/delegate opcodes exist, not whether the underlying Freeze v2 accounting model (`ALLOW_UNFREEZE_DELAY`) has actually been migrated to. These are two independent committee proposals (`ALLOW_TVM_FREEZE` and `ALLOW_UNFREEZE_DELAY`), and nothing in the reviewed processor code ties the TVM path's execution to the latter.

### Impact Explanation
If `ALLOW_TVM_FREEZE` is enabled by committee but `ALLOW_UNFREEZE_DELAY` (freeze v2 migration) has not yet been enabled (or is toggled independently), a smart contract could invoke the freeze-v2 native operation and mutate `FrozenV2` balances and global resource weight totals while the network is still officially operating under the old (v1) freeze accounting model that other subsystems (`BandwidthProcessor`, `EnergyProcessor`, `UnfreezeBalanceActuator`, `WithdrawExpireUnfreezeActuator`) assume is exclusive during this period. This can desynchronize total resource weight accounting (`addTotalNetWeight`/`addTotalEnergyWeight`/`addTotalTronPowerWeight`) between the two freeze models, corrupting bandwidth/energy allocation for all accounts and potentially permitting resource-weight or balance accounting inconsistencies chain-wide — a state-consistency violation reachable purely through a normal contract call.

### Likelihood Explanation
Reachable by any unprivileged account by deploying/calling a contract that triggers the `freezeBalanceV2` TVM operation, requiring only that `ALLOW_TVM_FREEZE` is on (a real mainnet/testnet configuration state) regardless of the separate `ALLOW_UNFREEZE_DELAY` proposal status — no special privilege beyond normal contract invocation is needed.

### Recommendation
Add an explicit `if (!repo.getDynamicPropertiesStore().supportUnfreezeDelay()) { throw new ContractValidateException(...); }` check to `FreezeBalanceV2Processor.validate()` (and audit `UnfreezeBalanceV2Processor.validate()` for the same missing check), mirroring the guard already present in `FreezeBalanceV2Actuator.validate()`, so the TVM-triggered path cannot execute Freeze v2 state changes before the migration to the new staking model has been formally enabled by committee.

### Proof of Concept
Not independently executed; this is based on static comparison of `FreezeBalanceV2Actuator.validate()` (which enforces `supportUnfreezeDelay()`) against `FreezeBalanceV2Processor.validate()` (which does not), both implementing the same `FreezeBalanceV2` state mutation, reachable respectively via a normal transaction and via a TVM contract call. I was not able to fully trace, within available iterations, the exact opcode dispatch conditions in `Program.java`/`OperationRegistry.java` that gate calls into `FreezeBalanceV2Processor` (e.g., whether `ALLOW_TVM_FREEZE` alone suffices to reach it independent of `ALLOW_UNFREEZE_DELAY`), so confirmation of the precise on-chain preconditions would require further review of `actuator/src/main/java/org/tron/core/vm/program/Program.java` and `OperationRegistry.java`.

  public void validate(FreezeBalanceV2Param param, Repository repo) throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    byte[] ownerAddress = param.getOwnerAddress();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid address");
    }
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddress);
    if (ownerCapsule == null) {
      String readableOwnerAddress = StringUtil.createReadableString(ownerAddress);
      throw new ContractValidateException(
          ACCOUNT_EXCEPTION_STR + readableOwnerAddress + "] does not exist");
    }
    long frozenBalance = param.getFrozenBalance();
    if (frozenBalance <= 0) {
      throw new ContractValidateException("FrozenBalance must be positive");
    } else if (frozenBalance < TRX_PRECISION) {
      throw new ContractValidateException("FrozenBalance must be greater than or equal to 1 TRX");
    } else if (frozenBalance > ownerCapsule.getBalance()) {
      throw new ContractValidateException(
          "FrozenBalance must be less than or equal to accountBalance");
    }

    // validate arg @resourceType
    switch (param.getResourceType()) {
      case BANDWIDTH:
      case ENERGY:
        break;
      case TRON_POWER:
        if (!repo.getDynamicPropertiesStore().supportAllowNewResourceModel()) {
          throw new ContractValidateException(
              "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
        break;
      default:
        if (repo.getDynamicPropertiesStore().supportAllowNewResourceModel()) {
          throw new ContractValidateException(
              "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY、TRON_POWER]");
        } else {
          throw new ContractValidateException(
              "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
    }

    if (repo.isSelfDestructed(ownerAddress)) {
      MUtil.checkCPUTimeForFreezeV2AfterSelfDestruct();
    }
  }

  public void execute(FreezeBalanceV2Param param, Repository repo) {
    DynamicPropertiesStore dynamicStore = repo.getDynamicPropertiesStore();

    byte[] ownerAddress = param.getOwnerAddress();
    long frozenBalance = param.getFrozenBalance();
    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }
    switch (param.getResourceType()) {
      case BANDWIDTH:
        long oldNetWeight = accountCapsule.getFrozenV2BalanceWithDelegated(BANDWIDTH) / TRX_PRECISION;
        accountCapsule.addFrozenBalanceForBandwidthV2(frozenBalance);
        long newNetWeight = accountCapsule.getFrozenV2BalanceWithDelegated(BANDWIDTH) / TRX_PRECISION;
        repo.addTotalNetWeight(newNetWeight - oldNetWeight);
        break;
      case ENERGY:
        long oldEnergyWeight = accountCapsule.getFrozenV2BalanceWithDelegated(ENERGY) / TRX_PRECISION;
        accountCapsule.addFrozenBalanceForEnergyV2(frozenBalance);
        long newEnergyWeight = accountCapsule.getFrozenV2BalanceWithDelegated(ENERGY) / TRX_PRECISION;
        repo.addTotalEnergyWeight(newEnergyWeight - oldEnergyWeight);
        break;
      case TRON_POWER:
        long oldTPWeight = accountCapsule.getTronPowerFrozenV2Balance() / TRX_PRECISION;
        accountCapsule.addFrozenForTronPowerV2(frozenBalance);
        long newTPWeight = accountCapsule.getTronPowerFrozenV2Balance() / TRX_PRECISION;
        repo.addTotalTronPowerWeight(newTPWeight - oldTPWeight);
        break;
      default:
        logger.debug("Resource Code Error.");
    }

    // deduce balance of owner account
    long newBalance = accountCapsule.getBalance() - frozenBalance;
    accountCapsule.setBalance(newBalance);
    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
  }
