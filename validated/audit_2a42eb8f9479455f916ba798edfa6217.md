### Title
Unbounded pending-handshake state growth allows unauthenticated remote memory-exhaustion DoS - (File: `handshake_manager.go`)

### Summary
`HandshakeManager.HandleIncoming` accepts any well-formed stage-1 handshake packet from an unauthenticated remote and unconditionally calls `beginHandshake`, which allocates a new `HandshakeHostInfo` and registers it in the `hm.vpnIps` and `hm.indexes` maps via `allocateIndex`. There is no counter or cap limiting how many such pending entries can exist at once, mirroring the reported bug class: state that grows without any accounting or a `maxSupply`-style enforcement check.

### Finding Description
On receipt of a stage-1 handshake packet (`h.MessageCounter == 1`), the only gates applied are a remote-allow-list check and a `RemoteIndex == 0` sanity check, both performed before any certificate/authentication material is validated: [1](#0-0) 

Once past these lightweight checks, `beginHandshake` proceeds to allocate a `HandshakeHostInfo` and call `allocateIndex`, which inserts an entry into `hm.indexes` (and `StartHandshake`/`beginHandshake` insert into `hm.vpnIps`) with no bound on the number of concurrent pending entries: [2](#0-1) [3](#0-2) 

The only size limit present in the pending-handshake machinery is `maxCachedPackets`, which bounds the number of *buffered outbound packets per handshake*, not the total number of pending handshakes/index entries tracked by the manager: [4](#0-3) 

The `HandshakeManager` struct itself only exposes gauges (`hostmap.pending.hosts`, `hostmap.pending.indexes`) for observability, with no enforcement logic tied to them: [5](#0-4) 

This is directly analogous to the reported issue: the external report's `GigaNameNFT`/`GameNFT` bug is that mint operations occur without checking an accurate running total against a supply cap. Here, pending-handshake creation occurs without checking any running total against a cap, so an attacker who has never presented a CA-signed certificate can drive unbounded growth of in-memory state.

### Impact Explanation
An attacker with no valid certificate can repeatedly send spoofed stage-1 handshake-initiation packets (varying source `netip.Addr`/spoofed `via.UdpAddr`) to force the node to allocate and retain `HandshakeHostInfo` entries (plus associated `HostInfo`, `HandshakePacket` maps, and index-map entries) indefinitely, growing `hm.vpnIps` and `hm.indexes` without bound until the process exhausts memory or becomes severely degraded — a remote, pre-authentication denial-of-service against the node.

### Likelihood Explanation
Likelihood is Medium-to-High: the code path is reachable by any unauthenticated attacker who can source UDP packets to the listener; the only precondition is passing the remote allow-list (default-open unless configured) and forming a syntactically valid stage-1 packet with `RemoteIndex == 0`, which requires no cryptographic material and no CA-signed certificate.

### Recommendation
Introduce and enforce an explicit maximum count of pending (unauthenticated) handshake entries tracked in `HandshakeManager` (e.g., cap `len(hm.vpnIps)`/`len(hm.indexes)`), rejecting or evicting-oldest-first once the cap is reached, mirroring the report's recommendation to introduce an accurate running counter (`totalSupply`) checked against a limit (`maxSupply`) before allowing new entries to be created — here, before allowing a new pending-handshake entry to be admitted.

### Proof of Concept
1. From an address with no CA-signed certificate, craft a UDP packet with `header.HandshakeIXPSK0` subtype, `MessageCounter == 1`, and `RemoteIndex == 0`, so it passes the checks in `HandleIncoming` at `handshake_manager.go:163-185`.
2. Send a large volume of such packets from many spoofed/varying source addresses (each treated as a distinct `vpnIp`/pending handshake).
3. Each packet drives `beginHandshake` → `allocateIndex`, inserting a new entry into `hm.vpnIps` and `hm.indexes` (`handshake_manager.go:502-528`), with no cap enforced anywhere in the manager.
4. Repeat until the node's memory usage grows unbounded, degrading or crashing the process — achieved entirely without ever presenting a valid CA-signed certificate.

// StartHandshake will ensure a handshake is currently being attempted for the provided vpn ip
func (hm *HandshakeManager) StartHandshake(vpnAddr netip.Addr, cacheCb func(*HandshakeHostInfo)) *HostInfo {
	hm.Lock()

	if hh, ok := hm.vpnIps[vpnAddr]; ok {
		// We are already trying to handshake with this vpn ip
		if cacheCb != nil {
			cacheCb(hh)
		}
		hm.Unlock()
		return hh.hostinfo
	}

	hostinfo := &HostInfo{
		vpnAddrs:        []netip.Addr{vpnAddr},
		HandshakePacket: make(map[uint8][]byte, 0),
		relayState: RelayState{
			relays:         nil,
			relayForByAddr: map[netip.Addr]*Relay{},
			relayForByIdx:  map[uint32]*Relay{},
		},
	}

	hh := &HandshakeHostInfo{
		hostinfo:  hostinfo,
		startTime: time.Now(),
	}
	hm.vpnIps[vpnAddr] = hh
	hm.metricInitiated.Inc(1)
	hm.OutboundHandshakeTimer.Add(vpnAddr, hm.config.tryInterval)

	if cacheCb != nil {
		cacheCb(hh)
	}

	// If this is a static host, we don't need to wait for the HostQueryReply
	// We can trigger the handshake right now
	_, doTrigger := hm.lightHouse.GetStaticHostList()[vpnAddr]
	if !doTrigger {
		// Add any calculated remotes, and trigger early handshake if one found
		doTrigger = hm.lightHouse.addCalculatedRemotes(vpnAddr)
	}

	if doTrigger {
		select {
		case hm.trigger <- vpnAddr:
		default:
		}
	}

	hm.Unlock()
	hm.lightHouse.QueryServer(vpnAddr)
	return hostinfo
}

// allocateIndex generates a unique localIndexId for this HostInfo
// and adds it to the pendingHostMap. Will error if we are unable to generate
// a unique localIndexId
func (hm *HandshakeManager) allocateIndex(hh *HandshakeHostInfo) (uint32, error) {
	hm.mainHostMap.RLock()
	defer hm.mainHostMap.RUnlock()
	hm.Lock()
	defer hm.Unlock()

	for range 32 {
		index, err := generateIndex(hm.l)
		if err != nil {
			return 0, err
		}

		_, inPending := hm.indexes[index]
		_, inMain := hm.mainHostMap.Indexes[index]

		if !inMain && !inPending {
			hh.hostinfo.localIndexId = index
			hm.indexes[index] = hh
			return index, nil
		}
	}

	return 0, errors.New("failed to generate unique localIndexId")
}
