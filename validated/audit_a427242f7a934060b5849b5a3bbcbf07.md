Based on my analysis, there's a concrete analog in `outside.go`'s `handleHostRoaming` function that mirrors the ETWAP bug's asymmetric update pattern (unconstrained immediate update in the attacker-favorable direction, but constrained/suppressed correction in the recovery direction).

### Title
Asymmetric roam-suppression logic lets a spoofed-source packet grief a live tunnel's remote-address routing - (File: outside.go)

### Summary
`handleHostRoaming` updates a `HostInfo`'s trusted remote UDP address immediately whenever an authenticated packet arrives from a different socket source address, but only suppresses a roam back to the *specific* previous remote for `RoamingSuppressSeconds`. Because the suppression check is keyed on an exact-address match rather than being symmetric, a single decrypted packet reflected with a forged source address can redirect the tunnel to an attacker-chosen address, and the subsequent legitimate traffic (arriving from the real, previous address) is then suppressed from correcting the roam for `RoamingSuppressSeconds`, exactly mirroring the eTWAP report's "immediate update one way / smoothed-only recovery the other way" flaw that enables griefing.

### Finding Description
The remote-address roaming state machine lives in `handleHostRoaming`: [1](#0-0) 

The `via.UdpAddr` value driving this logic comes directly from the UDP socket's `fromUdpAddr`, which is unauthenticated network-layer metadata, not part of the AEAD-protected payload: [2](#0-1) 

`readOutsidePackets` calls `handleHostRoaming` immediately after AEAD decryption succeeds, but decryption only proves the *payload* came from the correct session key holder — it says nothing about which socket address actually sent the packet, since `via.UdpAddr` is set before decryption and never re-verified against the decrypted content: [3](#0-2) 

The roam logic itself is asymmetric exactly like the ETWAP bug:
- Any new address that passes `remote_allow_list` is accepted immediately (`hostinfo.SetRemote(via.UdpAddr)`), with no cap on how often or how far the address can change.
- The only defense — `RoamingSuppressSeconds` — suppresses roaming *back* to the one specific prior address (`via.UdpAddr == hostinfo.lastRoamRemote`), not roaming *away* from the legitimate address to a new one. [4](#0-3) 

Because `lastRoamRemote` is set to whatever the current (legitimate) remote was at the moment of the forced roam, the very next packet that legitimately arrives from the real peer address will match `lastRoamRemote` and be suppressed for `RoamingSuppressSeconds`: [5](#0-4) 

This is the same bug class as the ETWAP report: a state used to gate/redirect traffic can be pushed instantly in one direction by an attacker-controlled event, while the corrective path back to the legitimate value is throttled — producing a window where legitimate operations (here, correct packet routing) are denied.

### Impact Explanation
An attacker who can capture or observe one valid, not-yet-consumed ciphertext packet between two peers (e.g., on the same network segment, or any position that lets them inject a UDP datagram with a forged source `AddrPort` carrying that ciphertext) can force the receiver to redirect its "trusted remote" for that tunnel to an arbitrary bogus address. Traffic that the victim intends to send to its real peer is instead sent to the bogus address for up to `RoamingSuppressSeconds`, and the legitimate peer's real packets are prevented from correcting the roam for the same window because they match `lastRoamRemote`. This is a remote state-poisoning / traffic-misdirection and availability (DoS) impact on the affected tunnel, reachable without holding a CA-signed certificate.

### Likelihood Explanation
Exploitation requires only the ability to inject a single UDP datagram with a spoofed source `AddrPort` reusing bytes of one legitimate, unexpired ciphertext (bounded by the anti-replay window in `bits.go`/`connection_state.go`). No cryptographic material, handshake participation, or valid certificate is needed — the vulnerable check operates purely on socket-layer source metadata. On networks where source-address spoofing or packet capture is feasible (shared L2 segments, certain NAT/ISP paths), this is straightforward and repeatable, since each spoof can target a new address and thus is never blocked by the previous-address-only suppression.

### Recommendation
Apply the suppression symmetrically: rate-limit/require corroboration for *any* roam event within `RoamingSuppressSeconds` of the last roam (not just a roam back to the exact previous address), and/or require additional confirmation (e.g., a successful `Test`/handshake round-trip) before trusting an unauthenticated socket-source change to redirect the tunnel's remote endpoint, mirroring the report's recommendation to apply the same update logic in both directions.

### Proof of Concept
1. Establish two legitimate Nebula peers `A` and `B` with an active tunnel; `A`'s `HostInfo` for `B` has `remote = B_addr`.
2. Attacker `M` (holding no CA-signed cert) observes/captures one in-flight ciphertext packet `P` that `B` sent to `A` (valid AEAD tag, unused counter).
3. `M` re-transmits `P` to `A`'s listening socket with a spoofed UDP source address `Evil_addr` (not `B_addr`).
4. `A`'s `Decrypt` succeeds (valid tag, unused counter), so `readOutsidePackets` calls `handleHostRoaming(hostinfo, via{UdpAddr: Evil_addr})` — see `outside.go:264-294`. `remote_allow_list` defaults to allow, so `A` immediately sets `remote = Evil_addr` and records `lastRoamRemote = B_addr`.
5. `A`'s subsequent outbound traffic for this tunnel is sent to `Evil_addr` instead of `B_addr`.
6. When `B`'s genuine next packet arrives at `A` with source `B_addr`, the check `via.UdpAddr == hostinfo.lastRoamRemote` (`B_addr == B_addr`) is true and the roam-back is suppressed for `RoamingSuppressSeconds`, so `A` continues misdirecting traffic to `Evil_addr` for that whole window — reproducing the ETWAP-style "instant attacker-favorable update, throttled legitimate correction" DoS pattern.

func (f *Interface) handleHostRoaming(hostinfo *HostInfo, via ViaSender) {
	curRemote := hostinfo.GetRemote()
	if !via.IsRelayed && curRemote != via.UdpAddr {
		if !f.lightHouse.GetRemoteAllowList().AllowAll(hostinfo.vpnAddrs, via.UdpAddr.Addr()) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("lighthouse.remote_allow_list denied roaming", "newAddr", via.UdpAddr)
			}
			return
		}

		if !hostinfo.lastRoam.IsZero() && via.UdpAddr == hostinfo.lastRoamRemote && time.Since(hostinfo.lastRoam) < RoamingSuppressSeconds*time.Second {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				hostinfo.logger(f.l).Debug("Suppressing roam back to previous remote",
					"suppressSeconds", RoamingSuppressSeconds,
					"udpAddr", curRemote,
					"newAddr", via.UdpAddr,
				)
			}
			return
		}

		hostinfo.logger(f.l).Info("Host roamed to new udp ip/port.",
			"udpAddr", curRemote,
			"newAddr", via.UdpAddr,
		)
		hostinfo.lastRoam = time.Now()
		hostinfo.lastRoamRemote = curRemote
		hostinfo.SetRemote(via.UdpAddr)
	}

}
