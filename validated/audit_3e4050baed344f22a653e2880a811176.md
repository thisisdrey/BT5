### Title
Non-atomic replay-window check-then-update in `ConnectionState.Decrypt`/`VerifyRelay` allows packet replay across concurrent reader routines - ([File: connection_state.go])

### Summary
`ConnectionState.Decrypt` and `ConnectionState.VerifyRelay` split anti-replay enforcement into two separate critical sections: `window.Check()` under `decryptLock`, then AEAD decryption *outside* the lock, then `window.Update()` under a freshly-reacquired `decryptLock`. Because the check and the "consume" (mark-as-seen) operation are not performed atomically with the decrypt itself, two copies of the same captured ciphertext packet delivered to two different reader goroutines (nebula supports multiple UDP reader `routines`) can both pass `Check` before either calls `Update`, letting the same message counter be decrypted and accepted twice — the anti-replay window is bypassed by a race, analogous to the reported bug class of "nonce/signature validity window vs. actual consumption is not atomic, enabling replay."

### Finding Description
`Decrypt` performs three separate steps, each independently locked: [4](#0-3) 

1. `cs.window.Check(l, messageCounter)` is called under `decryptLock`, then the lock is released.
2. `cs.dKey.DecryptDanger(...)` runs the AEAD decryption *without holding the lock*.
3. `cs.window.Update(l, messageCounter)` re-acquires the lock and marks the counter as consumed.

`Bits.Check` only inspects whether the bit for `i` is already set — it does not itself mark the bit: [5](#0-4) 

`Bits.Update` is the only method that actually records `i` as seen (via `b.set`/`b.bits[word] |= mask`): [6](#0-5) 

Because `Check` and `Update` are not one atomic operation covering the decrypt, if a network attacker captures a legitimate encrypted data-plane or relay packet and delivers two copies of it to the victim such that they land in two different reader goroutines (`f.listenOut(i)` for `i` in `0..routines`, each independently calling `f.readOutsidePackets` → `hostinfo.ConnectionState.Decrypt`), both goroutines can execute `Check` before either executes `Update`. Both `Check` calls observe the counter as unseen and return `true`, so both proceed to decrypt the same ciphertext with `DecryptDanger` and both later call `Update`, both succeeding. The same holds for `VerifyRelay`, which follows the identical check-decrypt-update pattern for relay frames: [7](#0-6) 

This is directly analogous to the reported Sequence wallet issue where nonce/signature "validity" was checked separately from the point where it is durably consumed, letting an attacker exploit the gap between validation and consumption to replay data that should have been rejected as already-seen.

### Impact Explanation
An off-path network attacker who can capture and duplicate a single legitimate ciphertext UDP packet (no valid certificate or trusted peer status required — this is pure traffic capture/replay, reachable on any network path that can see and duplicate packets to the victim, e.g., via a compromised switch/router, ARP spoofing, or general on-path/near-path positioning) can, on a system configured with `routines > 1` (multiple UDP reader queues), cause the replay window to accept and decrypt the same ciphertext twice. This defeats the anti-replay guarantee the sliding window (`ReplayWindow`) is specifically designed to provide, and for `handleOutsideMessagePacket`/tun-injected traffic this can result in duplicate delivery of application data into the tunnel, i.e., traffic replay/state poisoning at the data plane.

### Likelihood Explanation
Exploitability depends on the two duplicate packets being processed on two different reader goroutines concurrently and landing between the paired `Check`/`Update` window — a race that is timing-dependent but has a wide window since `DecryptDanger` (an AEAD open) is not instantaneous, and an attacker fully controls both the packet content (a straight capture) and the timing of resubmission (send both copies back-to-back). It is only exploitable when the deployment sets `routines > 1`, which is a supported and documented configuration, not merely a test-only mode.

### Recommendation
Hold `decryptLock` for the entire `Check` → `DecryptDanger` → `Update` sequence in both `Decrypt` and `VerifyRelay` (or otherwise make the check-and-mark atomic, e.g., a single `CheckAndUpdate` reserving the slot before decrypting and rolling back on decrypt failure) so that no other goroutine can observe an unconsumed counter as "available" while a decrypt for that same counter is in flight.

### Proof of Concept
1. Configure two nebula nodes with `routines: 2` (or more) so `Interface.routines > 1` and multiple `listenOut` goroutines are started (`interface.go`, `run()`/`activate()`).
2. Establish a tunnel and capture one legitimate data-plane UDP packet `P` (a normal `header.Message` packet) sent by the peer.
3. From an attacker position that can inject UDP packets to the victim (e.g., spoofing the peer's source `AddrPort`, or a genuine MITM), send two copies of `P` to the victim's listening port in immediate succession, timed so they are picked up by two different reader routines (`listenOut(0)` and `listenOut(1)`), e.g., by using two sockets/threads sending simultaneously.
4. Instrument or race-detect `ConnectionState.Decrypt`: under high concurrency/duplication, observe that `window.Check` returns `true` for the same `messageCounter` on both goroutines before either has called `window.Update`, causing `DecryptDanger` to succeed twice and the duplicate payload to be delivered to `handleOutsideMessagePacket` twice, instead of the second copy being rejected with `ErrAlreadySeen`.

func (f *Interface) listenOut(i int) {
	var li udp.Conn
	if i > 0 {
		li = f.writers[i]
	} else {
		li = f.outside
	}

	ctCache := firewall.NewConntrackCacheTicker(f.ctx, f.l, f.conntrackCacheTimeout)
	lhh := f.lightHouse.NewRequestHandler()
	plaintext := make([]byte, udp.MTU)
	h := &header.H{}
	fwPacket := &firewall.Packet{}
	nb := make([]byte, 12, 12)

	err := li.ListenOut(func(fromUdpAddr netip.AddrPort, payload []byte) {
		f.readOutsidePackets(ViaSender{UdpAddr: fromUdpAddr}, plaintext[:0], payload, h, fwPacket, lhh, nb, i, ctCache.Get())
	})

	// An error after teardown began is shutdown noise, the closed flag covers resources
	// Close releases itself and the cancelled ctx covers ones torn down by their owners
	// reacting to it, like the user device pipes
	if err != nil && !f.closed.Load() && f.ctx.Err() == nil {
		f.l.Error("Error while reading inbound packet, closing", "error", err)
		f.onFatal(err)
	}

	f.l.Debug("underlay reader is done", "reader", i)
}

func (cs *ConnectionState) Decrypt(l *slog.Logger, messageCounter uint64, out []byte, packet []byte, nb []byte) ([]byte, error) {
	var err error
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}

	out, err = cs.dKey.DecryptDanger(out, packet[:header.Len], packet[header.Len:], messageCounter, nb)
	if err != nil {
		return nil, err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return nil, ErrAlreadySeen
	}
	return out, nil
}

// VerifyRelay verifies AEAD protected (but not encrypted) relay frames. packet must be length-checked by the caller.
func (cs *ConnectionState) VerifyRelay(l *slog.Logger, messageCounter uint64, packet []byte, nb []byte) error {
	cs.decryptLock.Lock()
	result := cs.window.Check(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	signedPayload := packet[:len(packet)-cs.dKey.Overhead()]
	signatureValue := packet[len(packet)-cs.dKey.Overhead():]
	_, err := cs.dKey.DecryptDanger(nil, signedPayload, signatureValue, messageCounter, nb)
	if err != nil {
		return err
	}

	cs.decryptLock.Lock()
	result = cs.window.Update(l, messageCounter)
	cs.decryptLock.Unlock()
	if !result {
		return ErrAlreadySeen
	}

	return nil

// Check returns true if i is within (or way out in front of) the window, and not a replay
func (b *Bits) Check(l *slog.Logger, i uint64) bool {
	// If i is the next number, return true.
	if i > b.current {
		return true
	}

	if b.strictlyWithinWindow(i) {
		return !b.get(i)
	}

	// Not within the window
	if l.Enabled(context.Background(), slog.LevelDebug) {
		l.Debug("rejected a packet (top)", "current", b.current, "incoming", i)
	}
	return false
}

func (b *Bits) Update(l *slog.Logger, i uint64) bool {
	// Fast path: i is the next expected counter. Split out so the function
	// stays small and avoids paying for the slow paths' slog argument-build
	// stack frame on every call. The bit read/test/write is inlined to
	// touch the backing word once.
	if i == b.current+1 {
		pos := i & b.lengthMask
		word := pos >> 6
		mask := uint64(1) << (pos & 63)
		w := b.bits[word]
		if i > b.length && w&mask == 0 {
			b.lostCounter.Inc(1)
		}
		b.bits[word] = w | mask
		b.current = i
		return true
	}
	return b.updateSlow(l, i)
}
