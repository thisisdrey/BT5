## Title
Panic-based DoS via unchecked slice indexing when parsing untrusted reftable data ingested through `CreateRepositoryFromSnapshot` - (File: internal/git/reftable/reftable.go)

### Summary
`CreateRepositoryFromSnapshot` extracts a fully attacker-controlled tar archive directly on top of a freshly created bare repository via `tar -C <path> -xvf -`, and the code comment explicitly documents that "the received archive is trusted *a lot*" and needs hardening before being exposed to untrusted sources. [1](#0-0)  A malicious archive can therefore place an attacker-crafted reftable file (`.git/reftable/*.ref`) into the repository. When such a repository is subsequently read (e.g. via `Table.GetReferences`), the reftable parser performs multiple unchecked slice index computations derived directly from untrusted byte offsets/lengths in the file, mirroring the reported bug class: values pulled from untrusted structured input are used to index/slice data without validating that the resulting offsets are in range, so the parser can panic instead of returning an error.

### Finding Description
`Table.extractBlockLen` slices the input buffer using an offset computed purely from file content with no bounds check: `src[blockStart+1 : blockStart+4]`. [2](#0-1)  `Table.parseRefBlock` then uses this attacker-influenced `currentBS` to slice further (`src[blockStart+currentBS-2:]`) and to compute `RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)`, which can underflow (since these are unsigned `uint` values) if `currentBS` is small or `RestartCount` is large, producing a huge `RestartStart` used later as a slice index. [3](#0-2)  `getRefsFromBlock` and its variable-int/refname/hash parsing (`refname := prefix[:prefixLength] + string(src[idx:idx+suffixLength])`, `src[idx : idx+uint(hashSize)]`, etc.) further slice `src` using lengths derived from the file with only partial bounds validation against `blockEnd`/`FullBlockSize`, not against `len(src)`. [4](#0-3)  `GetReferences` itself also indexes `src[blockStart+headerOffset]` without checking that this index is within `len(src)`. [5](#0-4)  Any of these can trigger an out-of-range slice/index panic in Go, exactly analogous to the reported pattern of using unchecked data (`expect`/direct indexing on attacker-influenced structure) instead of returning a recoverable error.

The entry point that lets an ordinary/external actor supply the raw bytes that end up parsed this way is `CreateRepositoryFromSnapshot`, which downloads and extracts an arbitrary tar stream directly into the new repository's git directory before any git-native validation of its contents occurs. [6](#0-5) 

### Impact Explanation
A crafted reftable placed via the snapshot RPC can cause a subsequent RPC that reads references from that repository (any operation that ends up calling into the reftable reader) to panic. While Gitaly wraps unary/stream RPC handlers with `panichandler.UnaryPanicHandler`/`StreamPanicHandler`, which recover top-level panics and convert them to `Internal` errors rather than crashing the whole process, [7](#0-6)  repeated triggering still results in per-request denial of service (every read of the affected repository's refs fails/panics), and if the panic occurs on a code path not fully covered by the interceptor chain (e.g., background goroutines, housekeeping, or replication paths that call into `reftable` outside of a direct RPC handler goroutine) it can crash the whole `gitaly` process, consistent with the "denial-of-service against a handler" impact category.

### Likelihood Explanation
`CreateRepositoryFromSnapshot`'s own source comments explicitly acknowledge the trust and hardening gap, which corroborates that arbitrary file content can be injected into the resulting repository's `.git` directory, including a `.git/reftable/` directory whose files this parser subsequently reads without independently verifying internal offsets against slice bounds. This is a straightforward "ordinary user-controlled RPC field" (`HttpUrl`/tar stream) driving into an unhardened binary parser, directly analogous to the reported bug class of untrusted structured data reaching panic-prone code.

### Recommendation
- **Short term:** Add explicit bounds checks before every slice/index operation in `internal/git/reftable/reftable.go` (`extractBlockLen`, `parseRefBlock`, `getRefsFromBlock`, `GetReferences`), returning a descriptive error (e.g. via `fmt.Errorf`) instead of allowing Go's runtime to panic on out-of-range access. In particular, validate `blockStart+4 <= len(src)`, `currentBS >= 2` before subtracting, `RestartStart` computation against underflow, and `idx+suffixLength <= blockEnd`/`len(src)` before slicing.
- **Long term:** Treat archives/snapshots ingested via `CreateRepositoryFromSnapshot` as untrusted input requiring validation/sanitization before use (as already flagged in the code's own comment), and add fuzz tests for the reftable parser given it operates on binary, offset-driven, externally-influenced data.

### Proof of Concept
1. Call `CreateRepositoryFromSnapshot` with `HttpUrl` pointing to a server serving a tar archive containing a `.git` layout with a crafted `reftable/tables.list` and a malformed `.ref` file whose header advertises an inconsistent/undersized block length (`currentBS`) or an oversized `RestartCount`, such that `RestartStart` underflows or block offsets exceed the file's actual length.
2. Trigger any Gitaly RPC that reads references from the resulting repository (causing `Table.GetReferences`/`parseRefBlock`/`getRefsFromBlock` to run against the crafted file).
3. Observe a Go runtime panic (`slice bounds out of range`) originating from `internal/git/reftable/reftable.go`, recovered by the panic handler as an `Internal` gRPC error at best, or crashing background/non-interceptor-guarded code paths at worst — denying availability for that repository's ref-reading operations.

*Note: I was unable to fully trace every runtime code path that ultimately invokes `Table.GetReferences`/`Table.parseRefBlock` (e.g., which specific reference-backend selection logic triggers reftable parsing on an MVCC/reftable-backend repository created via `CreateRepositoryFromSnapshot`), due to index size limits on file coverage. Confirming this exact call chain end-to-end would benefit from a full Devin session with complete repository access.*

// parseRefBlock parses a block and if it is a ref block, provides
// all the reference updates.
func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)

	fullBlockSize := t.blockSize
	if fullBlockSize == 0 {
		fullBlockSize = currentBS
	} else if currentBS < fullBlockSize && currentBS < (blockEnd-blockStart) && src[blockStart+currentBS] != 0 {
		fullBlockSize = currentBS
	}

	b := &block{
		BlockStart:    blockStart + headerOffset,
		FullBlockSize: fullBlockSize,
	}

	if err := binary.Read(bytes.NewBuffer(src[blockStart+currentBS-2:]), binary.BigEndian, &b.RestartCount); err != nil {
		return nil, fmt.Errorf("reading restart count: %w", err)
	}

	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)

	return t.getRefsFromBlock(src, b)
}

// GetReferences returns all references from the table.
func (t *Table) GetReferences() ([]git.Reference, error) {
	headerOffset := uint(t.footer.Version.HeaderSize())
	offset := uint(0)
	var allRefs []git.Reference

	if _, err := t.src.Seek(0, io.SeekStart); err != nil {
		return nil, fmt.Errorf("seek start: %w", err)
	}

	src, err := io.ReadAll(t.src)
	if err != nil {
		return nil, fmt.Errorf("read all: %w", err)
	}

	for offset < t.footerOffset {
		blockStart, blockEnd := t.getBlockRange(offset, t.blockSize)
		if blockStart == 0 && blockEnd == 0 {
			break
		}

		// If we run out of ref blocks, we can stop the iteration.
		if src[blockStart+headerOffset] != 'r' {
			return allRefs, nil
		}

		references, err := t.parseRefBlock(src, headerOffset, blockStart, blockEnd)
		if err != nil {
			return nil, fmt.Errorf("parsing block: %w", err)
		}

		if len(references) == 0 {
			break
		}

		allRefs = append(allRefs, references...)

		offset = blockEnd
	}

// UnaryPanicHandler creates a new unary server interceptor that handles panics.
func UnaryPanicHandler(logger log.Logger) grpc.UnaryServerInterceptor {
	return func(ctx context.Context, req interface{}, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (resp interface{}, err error) {
		defer handleCrash(logger, info.FullMethod, func(grpcMethodName string, r interface{}) {
			err = toPanicError(grpcMethodName, r)
		})

		return handler(ctx, req)
	}
}

// StreamPanicHandler creates a new stream server interceptor that handles panics.
func StreamPanicHandler(logger log.Logger) grpc.StreamServerInterceptor {
	return func(srv interface{}, stream grpc.ServerStream, info *grpc.StreamServerInfo, handler grpc.StreamHandler) (err error) {
		defer handleCrash(logger, info.FullMethod, func(grpcMethodName string, r interface{}) {
			err = toPanicError(grpcMethodName, r)
		})

		return handler(srv, stream)
	}
}
