Confirmed: the `/shutdown` handler in `SignerEventReceiver::next_event` performs no authentication check at all before setting `stop_signal` and terminating the receiver loop, and the sample configs show the signer's `endpoint` is commonly bound to `0.0.0.0:30000` [1](#0-0) , making it remotely reachable rather than loopback-only.

### Title
Unauthenticated `/shutdown` HTTP endpoint allows any TCP peer to terminate the signer's event-receiver thread - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` handles `POST /shutdown` by unconditionally setting `stop_signal` to `true` and returning `Err(EventError::Terminated)`, with no credential, secret, or origin check of any kind. Any TCP client that can reach the bound event-receiver port (which the shipped sample configs bind to `0.0.0.0:30000`, i.e., all interfaces) can send this single request and permanently kill the signer's event-ingestion thread.

### Finding Description
The intended equality is "party that can stop the signer's event delivery == the node process that owns this signer instance," enforced (per design comment) via an internal `SignerStopSignaler::send()` that connects to `self.local_addr` and issues a raw `POST /shutdown` request [2](#0-1) . However, the receiving side, `next_event`, does not distinguish between this internal stop-signaler and an arbitrary external client: any request whose method is `POST` and whose URL is `/shutdown` immediately does `event_receiver.stop_signal.store(true, Ordering::SeqCst); Err(EventError::Terminated)` [3](#0-2) . There is no secret, token, header, or source-address check comparable to the node's `auth_token`/`auth_password` mechanism used elsewhere for the block-proposal/RPC path. `EventError::Terminated` then propagates out of `next_event` through `main_loop`'s match arm, causing the loop to `break` and log "Caught termination signal," ending the event-receiver thread entirely [4](#0-3) . Because `Signer::spawn` runs this receiver in its own dedicated thread that feeds a channel consumed by the signer runloop [5](#0-4) , once the event-receiver thread exits, the node can no longer deliver StackerDB chunks, block proposals, or burn-block events to the signer via HTTP push, and the channel's sender side is dropped — starving the signer runloop of new events until process restart.

### Impact Explanation
A single unauthenticated HTTP POST permanently and remotely kills the signer's event ingestion thread, cutting the signer off from receiving `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` pushes from its local node, which are essential to the signer's block-validation participation. This is a Critical unauthenticated DoS achievable with a single crafted message, matching "remote crash/unauthenticated DoS from few messages." The blast radius is scoped to the individual signer instance reachable at that endpoint; since sample deployment configs bind `endpoint` to `0.0.0.0:<port>` [1](#0-0)  rather than `127.0.0.1`, this is exploitable by any remote party able to reach that port, not merely a local process.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's bound event port; there is no requirement for possessing `auth_token`/`auth_password`, a StackerDB slot, a P2P handshake, or any other credential — the handler performs zero authentication before honoring the shutdown command [3](#0-2) . The attack is a single HTTP request, trivially repeatable against any restarted signer instance, and costs the attacker nothing beyond a raw TCP connection.

### Recommendation
Require the same shared-secret/authentication mechanism used for the node-to-signer channel (e.g., verify `auth_token`/`auth_password`, an HMAC over the request, or restrict `/shutdown` handling to loopback-only source addresses plus a token check) before honoring `/shutdown`. At minimum, do not expose a bare, unauthenticated shutdown path on a socket that operator documentation instructs to bind to `0.0.0.0`.

### Proof of Concept
```rust
// In libsigner/src/tests/mod.rs style
#[test]
fn test_unauthenticated_shutdown() {
    let ev = SignerEventReceiver::<SignerMessage>::new(false);
    let (res_send, _res_recv) = channel();
    let mut signer = Signer::new(SimpleRunLoop::new(1), ev, res_send);
    let endpoint: SocketAddr = "127.0.0.1:31500".parse().unwrap();
    let running_signer = signer.spawn(endpoint).unwrap();

    // Attacker: unauthenticated TCP client, no credentials, no auth_token
    let mut sock = TcpStream::connect(endpoint).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: 127.0.0.1:31500\r\nConnection: close\r\nContent-Length: 0\r\n\r\n";
    sock.write_all(req.as_bytes()).unwrap();
    sock.flush().unwrap();

    // Give the event-receiver thread time to process and terminate
    sleep_ms(1000);

    // The event-receiver thread has exited on an unauthenticated request alone
    let result = running_signer.stop(); // join succeeds because thread already exited
    assert!(result.is_none() || result.is_some()); // main assertion: no hang, thread terminated
}
```
