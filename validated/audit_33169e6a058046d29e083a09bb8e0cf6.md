### Title
Unbounded per-RPC CPU/memory via unvalidated `paths`/`attributes` counts in `GetFileAttributes` - (File: internal/gitaly/service/repository/file_attributes.go)

### Summary
`GetFileAttributes` iterates over every entry in `in.GetPaths()` and, for each, blocks on a synchronous NUL-delimited request/response round-trip with a long-lived `git check-attr --stdin -z` subprocess for every attribute in `in.GetAttributes()`. Neither the number of paths nor the number of attributes is bounded, so a single RPC can force O(paths × attributes) synchronous stdin writes/flushes and stdout reads, consuming CPU and holding open a subprocess and its buffers for the full request duration.

### Finding Description
`validateGetFileAttributesRequest` only checks that `Repository`, `Revision`, `Paths`, and `Attributes` are non-empty; it enforces no upper bound on `len(in.GetPaths())` or `len(in.GetAttributes())`. [1](#0-0) 

`GetFileAttributes` then loops over every path and calls `checkAttrCmd.Check(path)` sequentially. [2](#0-1) 

`CheckAttrCmd.Check` writes the path plus a NUL terminator to the subprocess's `bufio.Writer` stdin, flushes, and then performs `c.count` (`= len(attributes)`) blocking `ReadBytes('\000')` calls against the subprocess's `bufio.Reader` stdout for each path, since `git check-attr --stdin -z` emits `<path> NUL <attribute> NUL <value> NUL` triplets per attribute. [3](#0-2) 

The `check-attr` process is spun up once per RPC with all requested attribute names passed as CLI args and lives for the whole request via `defer finishAttr()`. [4](#0-3) 

An attacker with ordinary push access can craft the commit/tree referenced by `revision` (paths need not even exist in the tree — `check-attr` will just return unspecified attributes) and simply send a `GetFileAttributesRequest` with very large `paths` and `attributes` repeated fields. There is no cap on either list's length, so the total work is proportional to `len(paths) * len(attributes)`, entirely attacker-controlled, and executed synchronously within a single RPC handler goroutine holding a live `check-attr` subprocess and its buffered pipes for the duration.

### Impact Explanation
This causes CPU and (bounded, but still significant) memory consumption in a single Gitaly RPC handler proportional to attacker-supplied `paths × attributes` counts, keeping a `git check-attr` subprocess alive and its `bufio.Reader`/`bufio.Writer` allocated for the whole request. Because each RPC runs in its own goroutine, this does not directly freeze the entire server, but it does consume CPU/memory resources on the shared gitaly-server process and can degrade concurrent RPCs if many such requests are issued or issued repeatedly, matching a resource-exhaustion / DoS impact class. The practical size of a single request is bounded by gRPC's default max receive message size (commonly 4MB unless reconfigured), which still permits tens of thousands of short paths/attributes per request, and the RPC can be repeated without additional privilege.

### Likelihood Explanation
The precondition is only ordinary push/fetch access plus the ability to call the gRPC endpoint directly (e.g., via a crafted client bypassing GitLab Rails, or if Rails ever exposes uncapped pass-through of these fields), which the threat model treats as attacker-controlled. No admin/operator access, secret, or Gitaly bug beyond the missing bound is required. The attack is trivially repeatable and scriptable.

### Recommendation
Enforce explicit upper bounds in `validateGetFileAttributesRequest` on `len(in.GetPaths())` and `len(in.GetAttributes())` (e.g., a small constant limit consistent with other Gitaly RPCs that cap repeated fields), returning `InvalidArgument` when exceeded. Consider also bounding total combined size of paths/attributes strings, and evaluate applying a request-level timeout/context cancellation check inside the `Check` loop so long-running requests can be aborted.

func TestGetFileAttributes_DoS(t *testing.T) {

    cfg, client := setupRepositoryService(t)
    repoProto, repoPath := gittest.CreateRepository(t, ctx, cfg)

        ))

    const numPaths = 200000
    const numAttrs = 50
    paths := make([]string, numPaths)
    for i := range paths {
        paths[i] = fmt.Sprintf("example.go") // repeat same existing path many times
    }
    attrs := make([]string, numAttrs)
    for i := range attrs {
        attrs[i] = fmt.Sprintf("attr%d", i)
    }

    start := time.Now()
    _, err := client.GetFileAttributes(ctx, &gitalypb.GetFileAttributesRequest{
        Repository: repoProto,
        Revision:   []byte("main"),
        Attributes: attrs,
        Paths:      paths,
    })
    require.NoError(t, err)
    t.Logf("elapsed: %s", time.Since(start)) // demonstrates growth ~ O(numPaths*numAttrs)
}

func validateGetFileAttributesRequest(ctx context.Context, locator storage.Locator, in *gitalypb.GetFileAttributesRequest) error {

		return errors.New("file paths are required")

	return nil

func CheckAttr(ctx context.Context, repo gitcmd.RepositoryExecutor, revision git.Revision, names []string) (*CheckAttrCmd, func(), error) {
	if len(names) == 0 {
		return nil, nil, structerr.NewInvalidArgument("empty list of attribute names")
	}

	cmd, err := repo.Exec(ctx, gitcmd.Command{
		Name: "check-attr",
		Flags: []gitcmd.Option{
			gitcmd.Flag{Name: "--stdin"},
			gitcmd.Flag{Name: "-z"},
			gitcmd.ValueFlag{Name: "--source", Value: revision.String()},
		},
		Args: names,
	},
		gitcmd.WithSetupStdin(),
		gitcmd.WithSetupStdout(),
	)
	if err != nil {
		return nil, nil, fmt.Errorf("start check-attr command: %w", err)
	}

	checker := CheckAttrCmd{
		cmd:    cmd,
		stdout: bufio.NewReader(cmd),
		stdin:  bufio.NewWriter(cmd),
		count:  len(names),
		m:      &sync.Mutex{},
	}

	return &checker, func() { _ = cmd.Wait() }, nil
}

// Check the attributes for the file at the given path.
func (c CheckAttrCmd) Check(path string) (Attributes, error) {
	if strings.Contains(path, "\000") {
		return nil, fmt.Errorf("path with NUL byte not allowed")
	}

	c.m.Lock()
	defer c.m.Unlock()

	if _, err := c.stdin.WriteString(path + "\000"); err != nil {
		return nil, fmt.Errorf("write path: %w", err)
	}
	if err := c.stdin.Flush(); err != nil {
		return nil, fmt.Errorf("flush: %w", err)
	}

	attrs := Attributes{}
	buf := make([]string, 0, 3)

	// Using git-check-attr(1) with -z will return data in the format:
	// <path> NUL <attribute> NUL <info> NUL ...
	for i := 0; i < c.count; {
		word, err := c.stdout.ReadBytes('\000')
		if err != nil {
			return nil, fmt.Errorf("read line: %w", err)
		}

		buf = append(buf, string(bytes.TrimSuffix(word, []byte{0})))

		if len(buf) < 3 {
			continue // Keep going until we have 3 words
		}

		if buf[0] != path {
			return nil, fmt.Errorf("wrong path name detected, expected %q, got %q", path, buf[0])
		}
		if buf[2] != Unspecified {
			attrs = append(attrs, Attribute{Name: buf[1], State: buf[2]})
		}

		i++
		buf = buf[:0]
	}

	return attrs, nil
