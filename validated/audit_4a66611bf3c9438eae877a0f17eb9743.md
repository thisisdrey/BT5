### Title
DoS via unbounded pathological PCRE regex in `SearchFilesByContent` `Query` field passed to `git grep --perl-regexp` - ([File: internal/gitaly/service/repository/search_files.go])

### Finding Description
`SearchFilesByContent` takes `req.GetQuery()` and passes it, completely unmodified and length-unchecked, into `gitcmd.ValueFlag{Name: "-e", Value: req.GetQuery()}` alongside `gitcmd.Flag{Name: "--perl-regexp"}` when invoking `git grep` [1](#0-0) . `validateSearchFilesRequest` only checks that the query is non-empty and that the ref does not start with `-`; it applies no length or complexity restriction to `Query` [2](#0-1) . This is inconsistent with the sibling `SearchFilesByName` RPC, which explicitly caps its `Filter` regex at `searchFilesFilterMaxLength = 1000` bytes before compiling it with Go's `regexp` package [3](#0-2) [4](#0-3) . Because `--perl-regexp` engages git's PCRE backend (a backtracking regex engine, unlike RE2), a pathological pattern such as `(a+)+$` or `(a|aa)+$` matched against attacker-controlled repository content of moderate size can trigger catastrophic backtracking, causing the spawned `git grep` subprocess to consume CPU for a very long time or effectively hang.

### Impact Explanation
An unprivileged user who can push content to a repository they own (or fork/import one) fully controls both the `Query` regex and the searched blob content, and can invoke `SearchFilesByContent` directly via RPC. A crafted pattern plus a matching-but-non-matching content blob can drive the `git grep` process into near-exponential-time backtracking, tying up a Gitaly worker/subprocess and repository resources for as long as the RPC context allows, which matches the "resource exhaustion of an RPC handler" / DoS impact class.

### Likelihood Explanation
This requires no special privileges beyond the baseline "push to own repo" capability assumed for the attacker, no secrets, and no race conditions — a single crafted `SearchFilesByContentRequest` is sufficient and fully repeatable.

### Recommendation
Apply the same defensive length cap used for `SearchFilesByName`'s `Filter` (or a dedicated limit) to `SearchFilesByContent`'s `Query`, and/or disallow or sanitize constructs known to cause catastrophic backtracking, or bound `git grep` execution with an enforced CPU/wall-clock timeout independent of the general RPC context deadline.

func validateSearchFilesRequest(ctx context.Context, locator storage.Locator, req searchFilesRequest) error {
	if err := locator.ValidateRepository(ctx, req.GetRepository()); err != nil {
		return err
	}

	if len(req.GetQuery()) == 0 {
		return errors.New("no query given")
	}

	if len(req.GetRef()) == 0 {
		return errors.New("no ref given")
	}

	if bytes.HasPrefix(req.GetRef(), []byte("-")) {
		return errors.New("invalid ref argument")
	}

	return nil
}
