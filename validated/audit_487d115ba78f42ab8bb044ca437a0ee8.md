Based on my research, I found a concrete analog in the TVM precompiled contracts helper functions used to parse dynamic arrays out of raw calldata.

### Title
Unbounded array-length allocation in TVM precompiled-contract calldata parsing causes OutOfMemoryError / node crash - ([File: actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java])

### Summary
`PrecompiledContracts.extractBytes32Array`, `extractBytesArray`, and `extractSigArray` read an array-length field directly out of attacker-supplied calldata and immediately use it to size a Java array (`new byte[len][]`), with no check that `len` is sane relative to the actual size of the input. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`extractBytes32Array(DataWord[] words, int offset)` computes `len = words[offset].intValueSafe()` and allocates `byte[len][]` without ever validating `len` against `words.length`. If `len` is large (e.g., near `Integer.MAX_VALUE`), the subsequent loop `for (int i = 0; i < len; i++) { bytes32Array[i] = words[offset + i + 1].getData(); }` will also throw `ArrayIndexOutOfBoundsException` on `words[offset + i + 1]`, but the allocation itself (`new byte[len][]`) happens first and can already exhaust heap or throw `OutOfMemoryError` before that bounds check is ever reached. [1](#0-0) 

`extractBytesArray` does check `offset > words.length - 1` before reading the length word, but after that it derives `len` from the same unchecked `intValueSafe()` call and allocates `byte[len][]` with no upper bound tied to `data.length` or `words.length`, before it ever touches per-element offsets that would fail. [2](#0-1) 

`extractSigArray` has the identical pattern. [3](#0-2) 

This is directly analogous to CVE-2017-13147: a length value taken from untrusted input (there, an MNG chunk length; here, an ABI-encoded array-length word in calldata to a precompiled contract) is used to drive a memory allocation without first validating it against the bounds of the actual available data, leading to an allocation-failure/DoS condition.

### Impact Explanation
Any transaction or contract call that reaches one of the TVM precompiled contracts using these array-extraction helpers (multi-signature/batch-verification style precompiles that accept `bytes32[]`/`bytes[]`/signature-array parameters) can supply a huge length word. The resulting attempted allocation of an oversized `byte[len][]` can throw `OutOfMemoryError`, which — depending on where it is caught relative to Java-tron's VM exception handling — can disrupt execution of the node process handling that transaction/block, i.e., a resource-exhaustion/availability impact on the node processing the malicious call.

### Likelihood Explanation
I could not fully confirm, within the available iterations, exactly which precompiled contract(s) currently invoke `extractBytesArray`/`extractBytes32Array`/`extractSigArray` (my last searches for `batchValidateSign`/`validateMultiSign` callers timed out before I could inspect the call sites), so I cannot state with certainty that a specific reachable precompiled-contract address is wired to these helpers in the current codebase, nor whether `DataWord.intValueSafe()` clamps values in a way that limits the practical maximum of `len`. This uncertainty is significant: if `intValueSafe()` clamps to a small bound, or if these helper methods are dead/test-only code not reachable from any live precompiled contract dispatch, the analog would not be exploitable.

### Recommendation
Given the above uncertainty, I recommend validating this finding with full repository access (a Devin session) rather than treating it as confirmed: confirm (1) which precompiled contract addresses call `extractBytesArray`/`extractBytes32Array`/`extractSigArray`, (2) whether those addresses are reachable via a normal `CALL`/`STATICCALL` from user-deployed contract bytecode, and (3) the exact behavior of `DataWord.intValueSafe()`. If reachable, add an explicit bound check (`len` must be ≤ a small sane maximum and consistent with `words.length`/`data.length`) before allocating the array in all three helper methods.

  private static byte[][] extractBytesArray(DataWord[] words, int offset, byte[] data) {
    if (offset > words.length - 1) {
      return new byte[0][];
    }
    int len = words[offset].intValueSafe();
    byte[][] bytesArray = new byte[len][];
    for (int i = 0; i < len; i++) {
      int bytesOffset = words[offset + i + 1].intValueSafe() / WORD_SIZE;
      int bytesLen = words[offset + bytesOffset + 1].intValueSafe();
      bytesArray[i] = extractBytes(data, (bytesOffset + offset + 2) * WORD_SIZE,
          bytesLen);
    }
    return bytesArray;
  }
