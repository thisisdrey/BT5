## Analysis

Confirmed. `matrixContains` does exact `byte[]` equality (`Arrays.equals`), and `executedSignList` in `ValidateMultiSign.execute` stores both the raw `recoveredAddr` and the `merge(recoveredAddr, sign)` blob. The dedup check only skips weight accumulation when the *exact same signature bytes* have already been counted for that address; a second, distinct-but-valid ECDSA signature (different `(r,s)` or different `sign` byte layout) that recovers to the *same* `recoveredAddr` is **not** treated as a duplicate signer and its weight is added a second time.

### Title
Duplicate-signature weight double-counting bypasses multisig threshold in `ValidateMultiSign` precompile - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
The `ValidateMultiSign` TVM precompile computes a smart-contract account's weighted-multisig threshold by summing key weights of the addresses recovered from a caller-supplied signature array. Its duplicate-signer detection only compares the raw signature bytes, not the recovered signer address as the sole dedup key. Because ECDSA signatures over the same hash are non-unique per signer (different nonces / malleated `s` produce distinct valid signature bytes for the same key), a single private key holder can submit multiple *distinct* signatures that all recover to their own address, and each one adds that key's weight again, letting one signer satisfy a threshold meant to require multiple distinct signers.

### Finding Description
In `PrecompiledContracts.ValidateMultiSign.execute` [1](#0-0) :

```java
long totalWeight = 0L;
List<byte[]> executedSignList = new ArrayList<>();
for (byte[] sign : signatures) {
  byte[] recoveredAddr = recoverAddrBySign(sign, hash);
  sign = merge(recoveredAddr, sign);
  if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
    if (ByteArray.matrixContains(executedSignList, sign)) {
      continue;
    }
    MUtil.checkCPUTime();
  }
  long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
  ...
  totalWeight += weight;
  executedSignList.add(sign);
  executedSignList.add(recoveredAddr);
}
```

`ByteArray.matrixContains` performs exact byte-array equality (`Arrays.equals`) [2](#0-1) . The code only `continue`s (skips adding weight) when both the address **and** the exact `merge(recoveredAddr, sign)` blob were already seen. If the address was already seen but the current `sign` bytes differ (any new valid signature over the same hash by the same key — e.g., a different nonce `k`, or the `(r, n-s)` malleated form), the `continue` is *not* taken, `MUtil.checkCPUTime()` is invoked, and execution falls through to `totalWeight += weight`, counting that signer's weight again.

This is the direct analog of the reported bug class: an aggregate limit (`permission.getThreshold()`) is checked against a caller-supplied array (`signatures`) without deduplicating by the entity that actually matters (the recovered signer address), only by an incidental proxy (raw bytes) that an attacker fully controls and can vary at will.

This precompile is reachable from any TVM contract exposing this functionality to a `TriggerSmartContract`/`TriggerConstantContract` call, i.e., from any unprivileged transaction broadcaster who can call a contract that invokes `validatemultisign(...)`.

### Impact Explanation
Smart contracts that rely on `validatemultisign` for on-chain weighted M-of-N authorization (e.g., custody/vault contracts, escrow, DAO multisig-gated withdrawals) assume the check enforces that the summed weight came from genuinely distinct approving keys per `Permission`. With this flaw, a single compromised or malicious key holder among the permission's `keys` can locally generate several distinct valid signatures over the same hash (trivial — sign multiple times, or malleate `s`), submit them all in one call, and have their single key's weight counted multiple times, reaching or exceeding `permission.getThreshold()` alone. This defeats the intended threshold-signature security guarantee and enables a single-key holder to authorize state changes/fund transfers that were meant to require independent co-signers — an unauthorized account operation / theft-of-funds primitive for any contract that gates value transfer or privileged actions behind this multisig check.

### Likelihood Explanation
Exploitation requires only: (1) a `Permission` whose `keysCount() > 1` and `threshold` intended to require multiple distinct keys, but where one key's weight alone (or combined with attacker-known keys) is less than the threshold; (2) the attacker controls at least one key in that permission; (3) the attacker crafts ≥2 distinct signatures from that one key over the identical `hash` (trivial, deterministic ECDSA nonce reuse is not even required — signature malleability alone via `(r, n-s)` suffices, and can be done fully offline). No special privilege, node cooperation, or race condition is needed — this is reachable from a single crafted `TriggerSmartContract` call.

### Recommendation
Deduplicate strictly by `recoveredAddr`, not by the combined `(recoveredAddr, sign)` tuple: once an address has contributed weight, any further signature recovering to that same address must be skipped entirely, regardless of whether the raw signature bytes differ. E.g.:

```java
if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
    continue;
}
...
executedSignList.add(recoveredAddr);
```

removing the byte-level `sign` comparison and the fallthrough path that allows re-counting weight for an address already credited.

### Proof of Concept
1. Create an account with an Active `Permission` containing two keys `A` (weight 1) and `B` (weight 1), `threshold = 2`.
2. Attacker controls only key `A`.
3. Attacker computes `hash` per `ValidateMultiSign.execute` (`Sha256Hash` of `merge(address, permissionId, data)`).
4. Attacker signs `hash` with key `A` twice using two different nonces `k1 != k2` (or takes one signature and computes its `(r, n-s)` malleated counterpart), producing `sig1 != sig2`, both recovering to address `A`.
5. Call the precompile (via a contract invoking `validatemultisign(address, permissionId, data, [sig1, sig2])`, mapped to `PrecompiledContracts.ValidateMultiSign.execute`).
6. Trace through `execute`: first iteration adds weight 1 for `A` (`executedSignList` now has `merge(A,sig1)` and `A`). Second iteration: `matrixContains(executedSignList, A)` is `true`, but `matrixContains(executedSignList, merge(A,sig2))` is `false` (different sign bytes) — so it does **not** `continue`, and `totalWeight += weight` runs again, giving `totalWeight = 2 >= threshold(2)`, returning `Pair.of(true, dataOne())` (success) despite only key `A` ever having signed.

Note: I was unable to find a test in this snapshot that exercises this specific two-distinct-signatures-same-address scenario for `ValidateMultiSign` (existing tests such as `ValidateMultiSignContractTest.testDifferentCase` only test byte-identical repeated signatures, which are correctly deduplicated) — a Devin session with full repo/test access could add and run such a PoC test to confirm the double-count in practice.   public static class ValidateMultiSign extends PrecompiledContract {

    private static final int ENGERYPERSIGN = 1500;
    private static final int MAX_SIZE = 5;
    private static final int ABI_HEADER_WORDS = 5;
    private static final int ABI_ITEM_WORDS = 5;


    @Override
    public long getEnergyForData(byte[] data) {
      long cnt = (data.length / WORD_SIZE - 5) / 5;
      // one sign 1500, half of ecrecover
      return cnt * ENGERYPERSIGN;
    }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] rawData) {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(rawData, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(rawData);
      byte[] address = words[0].toTronAddress();
      int permissionId = words[1].intValueSafe();
      byte[] data = words[2].getData();

      byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
      byte[] hash = Sha256Hash.hash(CommonParameter
          .getInstance().isECKeyCryptoEngine(), combine);

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[3].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }
      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[3].intValueSafe() / WORD_SIZE, rawData) :
          extractBytesArray(words, words[3].intValueSafe() / WORD_SIZE, rawData);

      if (signatures.length == 0 || signatures.length > MAX_SIZE) {
        return Pair.of(true, DATA_FALSE);
      }

      AccountCapsule account = this.getDeposit().getAccount(address);
      if (account != null) {
        try {
          Permission permission = account.getPermissionById(permissionId);
          if (permission != null) {
            //calculate weight
            long totalWeight = 0L;
            List<byte[]> executedSignList = new ArrayList<>();
            for (byte[] sign : signatures) {
              byte[] recoveredAddr = recoverAddrBySign(sign, hash);

              sign = merge(recoveredAddr, sign);
              if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
                if (ByteArray.matrixContains(executedSignList, sign)) {
                  continue;
                }
                MUtil.checkCPUTime();
              }
              long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
              if (weight == 0) {
                //incorrect sign
                return Pair.of(true, DATA_FALSE);
              }
              totalWeight += weight;
              executedSignList.add(sign);
              executedSignList.add(recoveredAddr);
            }

            if (totalWeight >= permission.getThreshold()) {
              return Pair.of(true, dataOne());
            }
          }
        } catch (Throwable t) {
          if (t instanceof OutOfTimeException) {
            throw t;
          }
          logger.info("ValidateMultiSign error:{}", t.getMessage());
        }
      }
      return Pair.of(true, DATA_FALSE);
    }
  }

  public static boolean matrixContains(List<byte[]> source, byte[] obj) {
    for (byte[] sobj : source) {
      if (Arrays.equals(sobj, obj)) {
        return true;
      }
    }
    return false;
  }
