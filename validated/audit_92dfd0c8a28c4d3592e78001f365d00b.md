### Title
Priority-floor sigverify bypass via structurally-valid transactions with invalid ComputeBudget instructions forces full ed25519 verification regardless of saturation - ([File: core/src/sigverify.rs], [File: core/src/transaction_priority.rs])

### Summary
`apply_priority_floor_to_batch` relies on `calculate_priority_from_bytes` to decide whether a packet can be cheaply dropped under scheduler saturation, but that function performs a strictly stronger validation (including `ComputeBudgetInstructionDetails::try_from`) than the minimal parse `verify_packet` uses to gate expensive signature verification. A packet that is a structurally valid `SanitizedTransactionView` but has an invalid/duplicate ComputeBudget instruction makes `calculate_priority_from_bytes` return `None` (so it is never dropped by the floor, `any_kept = true`), yet `verify_packet` will still successfully parse it and proceed to perform full ed25519 signature verification.

### Finding Description
`apply_priority_floor_to_batch` in `core/src/sigverify.rs` calls `calculate_priority_from_bytes(bank, data)` for every non-discarded packet, and any packet for which this returns `None` is kept (`any_kept = true`) and left for downstream rejection instead of being cheaply dropped: [1](#0-0) 

`calculate_priority_from_bytes` in `core/src/transaction_priority.rs` chains: `SanitizedTransactionView::try_new_sanitized` → `RuntimeTransaction::<SanitizedTransactionView<_>>::try_new` → `transaction_configuration(&bank.feature_set)` → `calculate_priority_and_cost`, propagating any failure to `None` via `.ok()?`: [2](#0-1) 

The downstream expensive path, `verify_packet` in `perf/src/sigverify.rs`, only requires `SanitizedTransactionView::try_new_sanitized` to succeed before it proceeds to iterate every signature and call `signature.verify(pubkey, message)` — real ed25519 cryptographic verification work: [3](#0-2) 

The gap is that `RuntimeTransaction::<SanitizedTransactionView<_>>::try_new` performs additional checks beyond the bare structural parse — specifically it builds `ComputeBudgetInstructionDetails` via `ComputeBudgetInstructionDetails::try_from`, which returns `Err` on a duplicate ComputeBudget instruction or on invalid instruction data addressed to the ComputeBudget program id: [4](#0-3) [5](#0-4) 

Because `verify_packet` never calls `RuntimeTransaction::try_new` or `ComputeBudgetInstructionDetails::try_from`, a packet whose message contains e.g. two `SetComputeUnitLimit` instructions (a one-line malformation) will:
1. Successfully parse under `SanitizedTransactionView::try_new_sanitized` (used by both paths), so `verify_packet` proceeds to perform full signature verification and only discards the packet afterward if signatures don't verify.
2. Fail `RuntimeTransaction::try_new` (`DuplicateInstruction` error) inside `calculate_priority_from_bytes`, causing `calculate_priority_from_bytes` to return `None`, so `apply_priority_floor_to_batch` treats it as `any_kept = true` and never drops it — regardless of how high the published `floor` is.

This defeats the specific purpose of `SchedulerPriorityFloor`/`apply_priority_floor_to_batch`, which exists to shed cheap, low-value load ahead of the costly `ed25519_verify_serial` call when the scheduler is saturated (per the comments in `run_transaction_task`): [6](#0-5) 

### Impact Explanation
An unstaked attacker can flood the TPU with transactions that are guaranteed to never execute (duplicate/invalid ComputeBudget instructions) but are still fully signature-verified on every packet, even while the scheduler is saturated and actively trying to shed exactly this kind of worthless load via the priority floor. This is a QoS-evasion / underpriced pre-fee work issue: the priority-floor defense added specifically to bound sigverify CPU spent on cheap packets under load can be unconditionally bypassed for a whole class of packets, at no cost to the attacker (no valid fee, no valid signature required — only a well-formed message with a trivial ComputeBudget malformation).

### Likelihood Explanation
Requires only the stated precondition (scheduler saturated so `priority_floor > 0`), which is attacker-triggerable simply by flooding transactions to fill the scheduler's buffer to the `SATURATION_BUFFER_PCT` watermark. Constructing the malformed-but-structurally-valid packets is trivial (duplicate a `ComputeBudgetInstruction::set_compute_unit_limit` in the message) and requires no special access — fully within the unstaked/remote-attacker threat model. Repeatable indefinitely as long as packets are sent to the TPU port.

### Recommendation
Make `apply_priority_floor_to_batch`'s cheap-rejection path use exactly the same parse depth as `verify_packet` (i.e., only require `SanitizedTransactionView::try_new_sanitized` to succeed) rather than the stronger `calculate_priority_from_bytes`/`RuntimeTransaction::try_new` validation, or conversely, have `verify_packet` short-circuit on the same additional checks that `calculate_priority_from_bytes` performs before doing signature verification, so both code paths agree on which packets are "unparseable" and neither can outrun the other's rejection.

### Proof of Concept
```rust
// core/src/sigverify.rs (or transaction_priority.rs) test module
#[test]
fn priority_floor_bypassed_by_duplicate_compute_budget_ix() {
    use solana_compute_budget_interface::ComputeBudgetInstruction;
    use solana_message::Message;
    use solana_transaction::{Transaction, versioned::VersionedTransaction};

    let (bank, mint) = test_bank_with_lamports_per_signature(5_000);

    // Structurally valid message, but with a DUPLICATE ComputeBudget
    // instruction, which RuntimeTransaction::try_new rejects.
    let to = Pubkey::new_unique();
    let transfer = system_instruction::transfer(&mint.pubkey(), &to, 1);
    let cu_limit_a = ComputeBudgetInstruction::set_compute_unit_limit(100_000);
    let cu_limit_b = ComputeBudgetInstruction::set_compute_unit_limit(200_000); // duplicate
    let message = Message::new(&[transfer, cu_limit_a, cu_limit_b], Some(&mint.pubkey()));
    let tx = Transaction::new(&[&mint], message, bank.last_blockhash());
    let bytes = bincode::serialize(&VersionedTransaction::from(tx)).unwrap();

    // 1. calculate_priority_from_bytes returns None: this packet can NEVER
    //    be dropped by apply_priority_floor_to_batch, no matter the floor.
    assert!(calculate_priority_from_bytes(&bank, &bytes).is_none());

    // 2. But the bare SanitizedTransactionView parse (used by verify_packet)
    //    succeeds, so ed25519_verify_serial will still do full signature
    //    verification work on it.
    let view = SanitizedTransactionView::try_new_sanitized(&bytes[..], &sanitize_config());
    assert!(view.is_ok(), "verify_packet's cheap parse succeeds for this packet");
}
```
Extended integration-level assertion: build a `PacketBatch` containing many copies of this duplicate-ComputeBudget-instruction transaction, set a high `SchedulerPriorityFloor` value, call `apply_priority_floor_to_batch`, and assert `dropped == 0` / `all_below == false` for the whole batch, then measure that `ed25519_verify_serial` still performs full per-signature `verify()` calls on every packet — demonstrating that an attacker-chosen, zero-value transaction pattern is immune to the priority-floor shedding mechanism regardless of the floor's value.

fn verify_packet(packet: &mut PacketRefMut, reject_non_vote: bool, enable_tx_v1: bool) -> bool {
    // If this packet was already marked as discard, drop it
    if packet.meta().discard() {
        return false;
    }

    let Some(data) = packet.data(..) else {
        return false;
    };

    let (is_simple_vote_tx, verified) = {
        let Ok(view) = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()) else {
            return false;
        };

        if !enable_tx_v1 && matches!(view.version(), TransactionVersion::V1) {
            return false;
        }

        let is_simple_vote_tx = is_simple_vote_transaction_view(&view);
        if reject_non_vote && !is_simple_vote_tx {
            (is_simple_vote_tx, false)
        } else {
            let signatures = view.signatures();
            if signatures.is_empty() {
                (is_simple_vote_tx, false)
            } else {
                let message = view.message_data();
                let static_account_keys = view.static_account_keys();
                let verified = signatures
                    .iter()
                    .zip(static_account_keys.iter())
                    .all(|(signature, pubkey)| signature.verify(pubkey.as_ref(), message));
                (is_simple_vote_tx, verified)
            }
        }
    };

    fn process_instruction(&mut self, index: u8, instruction: &SVMInstruction) -> Result<()> {
        let invalid_instruction_data_error =
            TransactionError::InstructionError(index, InstructionError::InvalidInstructionData);
        let duplicate_instruction_error = TransactionError::DuplicateInstruction(index);

        match try_from_slice_unchecked(instruction.data) {
            Ok(ComputeBudgetInstruction::RequestHeapFrame(bytes)) => {
                if self.requested_heap_size.is_some() {
                    return Err(duplicate_instruction_error);
                }
                self.requested_heap_size = Some((index, bytes));
            }
            Ok(ComputeBudgetInstruction::SetComputeUnitLimit(compute_unit_limit)) => {
                if self.requested_compute_unit_limit.is_some() {
                    return Err(duplicate_instruction_error);
                }
                self.requested_compute_unit_limit = Some((index, compute_unit_limit));
            }
            Ok(ComputeBudgetInstruction::SetComputeUnitPrice(micro_lamports)) => {
                if self.requested_compute_unit_price.is_some() {
                    return Err(duplicate_instruction_error);
                }
                self.requested_compute_unit_price = Some((index, micro_lamports));
            }
            Ok(ComputeBudgetInstruction::SetLoadedAccountsDataSizeLimit(bytes)) => {
                if self.requested_loaded_accounts_data_size_limit.is_some() {
                    return Err(duplicate_instruction_error);
                }
                self.requested_loaded_accounts_data_size_limit = Some((index, bytes));
            }
            _ => return Err(invalid_instruction_data_error),
        }

        Ok(())
    }
