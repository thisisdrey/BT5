Audit Report

## Title
Missing `PrecompileDelegateDenied` guard on the built-in `System` precompile allows caller-context spoofing during delegatecall - (File: `substrate/frame/revive/src/precompiles/builtin/system.rs`)

## Summary
The `System::call` implementation in `substrate/frame/revive/src/precompiles/builtin/system.rs` resolves caller identity via `env.caller()`, `env.caller_is_origin()`, and `env.caller_is_root()` without ever checking `env.is_delegate_call()`, unlike the sibling precompiles patched by PR `pr_11715` (`substrate/frame/assets/precompiles/src/lib.rs`, `substrate/frame/asset-conversion/precompiles/src/lib.rs`, `polkadot/xcm/pallet-xcm/precompiles/src/lib.rs`) and `substrate/frame/vesting/precompiles/src/lib.rs`, which all explicitly reject delegatecall with `PrecompileDelegateDenied`. This lets a delegatecalled contract obtain the true caller/origin/root identity of the delegatecalling contract's frame and use it to pass authorization checks it should not be able to satisfy.

## Finding Description
`System::call` in `substrate/frame/revive/src/precompiles/builtin/system.rs` handles `callerIsOrigin`, `callerIsRoot`, `ownCodeHash`, and `terminate` branches purely based on `env.caller()`/`env.caller_is_origin()`/`env.caller_is_root()` with no `is_delegate_call()` check anywhere in the function body: [1](#0-0) 

By contrast, the four sibling precompiles that were fixed by PR 11715 explicitly guard against delegatecall before deriving caller identity, e.g.: [2](#0-1) [3](#0-2) 

and the PR description itself explains the exact root cause this finding relies on — that `env.caller()` "during delegatecall returns the original caller" — and lists the precompiles patched, which does not include the built-in `System` precompile: [4](#0-3) 

The `PrecompileDelegateDenied` error variant exists in `pallet-revive` core (`substrate/frame/revive/src/lib.rs`, `substrate/frame/revive/src/exec.rs`, `substrate/frame/revive/src/precompiles.rs`) and is already available for use by `System::call`, but is not invoked there.

## Impact Explanation
This satisfies the "unauthorized execution or origin escalation" impact category from the Polkadot SDK Pivots ("Public wrappers such as ... `contracts`, and `revive` must not widen origin"). A contract delegatecalled into by a privileged/root-controlled contract can call `System.callerIsRoot()`, `System.callerIsOrigin()`, or `System.ownCodeHash()` and receive answers describing the delegatecalling frame's true caller/origin, not itself. Any downstream logic in the victim contract that trusts these System precompile answers to gate privileged behavior can be tricked into executing privileged code paths on behalf of an unprivileged delegatecallee, i.e., the effective authorization "origin" seen by the contract's own logic is the wrong value (the delegatecalling contract's original caller instead of the delegatecallee).

## Likelihood Explanation
No privileged actor, governance action, or off-chain compromise is required — only an unprivileged attacker who can get a target contract to `delegatecall` into attacker-supplied or attacker-influenced code, which is a common integration pattern (library/plugin/logic upgrade contracts) on `pallet-revive`. The same bug class was independently identified and fixed for four other precompiles in the same codebase (PR 11715), demonstrating the exploit path is real and was intentionally patched elsewhere, but the fix was incomplete because it did not cover the always-present built-in `System` precompile at address `0x900`.

## Recommendation
Add the same guard used in `pallet-xcm`, `pallet-assets`, `pallet-asset-conversion`, and `pallet-vesting` precompiles to `System::call` in `substrate/frame/revive/src/precompiles/builtin/system.rs`, at minimum for the caller-identity-dependent branches (`callerIsOrigin`, `callerIsRoot`, `ownCodeHash`, and `terminate`):
```rust
frame_support::ensure!(
    !env.is_delegate_call(),
    crate::Error::<T>::PrecompileDelegateDenied,
);
```

## Proof of Concept
1. Deploy victim contract `V` with a privileged function that checks `System.callerIsRoot()` (or `callerIsOrigin()`/`ownCodeHash()`) before executing sensitive logic, and which exposes a delegatecall-based plugin mechanism, e.g. `execute(address lib, bytes calldata data) external { lib.delegatecall(data); }`.
2. An unprivileged attacker deploys malicious library `L` whose code calls the `0x900` System precompile's `callerIsRoot()`/`ownCodeHash()` and then triggers `V`'s privileged internal logic.
3. A privileged/root account (or automated flow) calls `V.execute(L, data)`, causing `V` to delegatecall `L`.
4. Inside `L`'s delegatecall frame, `env.caller()` still resolves to the root/privileged account (delegatecall does not change caller in `pallet-revive`'s `Ext`), so `System.callerIsRoot()` returns `true` even though `L`, not the privileged account, is actually driving execution.
5. `L` uses this false-positive authorization signal to execute privileged logic within `V`'s frame that it was never authorized to trigger directly, confirmable by adding a unit test analogous to `delegatecall_is_rejected` (see `polkadot/xcm/pallet-xcm/precompiles/src/tests.rs`) targeting `System<Test>::call` and observing it currently succeeds instead of returning `PrecompileDelegateDenied`.
