### Title
`pallet-psm::redeem` skips the live-decimals guard that `mint` enforces, letting a decimals-metadata change drain the PSM reserve - (File: `substrate/frame/psm/src/lib.rs`)

### Summary
`pallet-psm` is a Peg-Stability-Module analog to the reported `Minter` contract: it swaps between an `internal_asset` and a list of governance-approved `external_asset`s, converting amounts via a decimals-scaling factor computed from `ExternalAssetInfo::decimals` and `PsmInfo::internal_decimals`. `mint()` explicitly re-checks the *live* decimals of both assets against the registration snapshot before doing the conversion via `Self::ensure_decimals_match(...)` [1](#0-0) , and halts with `DecimalsMismatch` if metadata has drifted [2](#0-1) . `redeem()`, however, uses the **snapshotted** `external.decimals` and `info.internal_decimals` directly, without ever calling `ensure_decimals_match`, before computing `internal_to_external` [3](#0-2) . This is the same “decimal precision mismatch not accounted for” bug class as the `Minter` report: a conversion routine assumes a fixed decimal relationship between two assets, but that relationship is externally mutable, and only one of the two mirrored entry points checks for drift.

### Finding Description
`external_to_internal`/`internal_to_external` purely scale raw balances by `10^|ext_decimals - internal_decimals|` [4](#0-3) [5](#0-4) . The correctness of this scaling depends entirely on `ext_decimals` (taken from the `ExternalAssetInfo` snapshot recorded at `add_external_asset` time) still matching the live decimals reported by `T::Fungibles::decimals(external_asset)`.

`mint()` protects against drift by calling `ensure_decimals_match`, which compares the live decimals of both the internal and external asset against the stored snapshots and returns `Error::DecimalsMismatch` if they diverge [6](#0-5) , and this is confirmed by the test `mint_halts_when_asset_decimals_drift` [7](#0-6) .

`redeem()` reads `ext_decimals = external.decimals` and `internal_decimals = info.internal_decimals` straight from storage and feeds them into `internal_to_external` without any live-metadata check [8](#0-7) . The code comment even states this is intentional (“Redemptions use the decimals snapshotted when the PSM/external pair was registered, allowing existing positions to unwind even if live metadata later changes”) [9](#0-8) .

The problem is that `pallet-assets` decimals metadata is not immutable — it can be changed by the asset's own admin/owner via `set_metadata`, independent of the PSM instance's governance (`full_admin`/`emergency_admin` only control the PSM side, not the external asset's own metadata role). The PSM instance's governance approves an `external_asset` once, at a point-in-time decimals value; nothing in the code re-verifies that the raw units transferred out of the reserve during `redeem` still correspond to the same real value that was deposited during `mint`. This is functionally identical to the report's exploited invariant: an asset's real per-unit value (there, price/exchange-rate; here, decimal scale) is assumed fixed but is externally mutable, and one of the two conversion paths (there, `mint`; here, `redeem`) fails to re-validate it, corrupting the exchange between `internal_asset` and `external_asset` and letting more (or less) value than deposited flow out of the shared PSM reserve (`Self::psm_account`).

### Impact Explanation
Because `redeem()` never checks decimals drift, once an external asset's decimals metadata changes after debt has accrued, `internal_to_external` computes a scaling factor that no longer reflects the real value of the token being transferred. A redeemer can receive external-asset raw units that are worth far more (or the protocol can pay out far more) than the internal-asset amount actually burned represents, draining `T::Fungibles::balance(external_asset, psm_account)` — the shared reserve backing potentially multiple external assets under the same `internal_asset`. This is a direct "total loss" style drain of protocol reserves / cross-subsidizing of other depositors' collateral, matching the required impact of theft/unbacked settlement and permanent fund loss for the PSM instance.

### Likelihood Explanation
Exploitability depends on the specific `external_asset`'s decimals metadata actually being mutable by an entity outside the PSM's own governance (i.e., that asset's `pallet-assets` owner/issuer role) and that mutation occurring after debt exists. `mint()` is guarded, so an attacker cannot simply flip decimals and immediately mint against a wrong rate — but they can mint at the correct rate first (accruing legitimate debt), then change decimals, then call `redeem()`, which has no equivalent guard, to unwind at an incorrect rate. This requires no chain-level privilege, validator, relayer, or governance action — only the PSM-external asset's own metadata-admin role, which for permissionlessly created `pallet-assets` instances is typically held by an ordinary account, not the PSM's `full_admin`.

### Recommendation
Call `Self::ensure_decimals_match(&info, &internal_asset, &external_asset, &external)?` (or an equivalent live-decimals check) inside `redeem()` exactly as `mint()` does, before computing `internal_to_external`/`external_to_internal`. If a mismatch is detected, `redeem` should also halt with `Error::DecimalsMismatch` (or route through an explicit, permissionless "unwind at snapshot rate" path that is only reachable after the pair has been frozen for new debt and is bounded to at most the debt that existed *before* drift was detected), rather than unconditionally trusting the stale snapshot for arbitrary future redemptions.

### Proof of Concept
1. PSM governance (`full_admin`) creates a PSM for `internal_asset = hUSD` (6 decimals) and approves `external_asset = FOO`, a `pallet-assets` asset with live decimals = 6, via the registration path that snapshots `ExternalAssetInfo::decimals = 6`.
2. Alice calls `Psm::mint(internal_asset=hUSD, external_asset=FOO, external_amount=1_000_000, ..)`; `ensure_decimals_match` passes (6 == 6), she deposits 1,000,000 raw FOO and is credited ~1,000,000 raw hUSD; `PsmDebt` for `(hUSD, FOO)` increases accordingly, and 1,000,000 raw FOO now sits in `psm_account`.
3. FOO's own metadata admin (an ordinary, PSM-unrelated account, not `full_admin`) calls `pallet_assets::set_metadata` to change FOO's decimals from 6 to 0 (a 10^6 scale change), which is unrelated to and unblocked by the PSM's governance.
4. Alice calls `Psm::redeem(internal_asset=hUSD, external_asset=FOO, internal_amount=1_000_000, ..)`. `redeem()` does **not** call `ensure_decimals_match`, so it still uses the stale snapshot `ext_decimals = 6`, `internal_decimals = 6`, computing `external_out ≈ 1_000_000` raw FOO units — but FOO's real decimals are now 0, meaning those 1,000,000 raw units represent roughly 10^6× the real value they represented at deposit time.
5. `T::Fungibles::transfer` pays out the reserve at the stale (now catastrophically wrong) rate, draining `psm_account`'s FOO balance and, by extension, any other depositors' backing collateral held in the same shared reserve, while `PsmDebt` bookkeeping is decremented as if a normal, value-preserving redemption occurred.

				.ok_or(Error::<T>::UnsupportedAsset)?;
			ensure!(external.status.allows_redemption(), Error::<T>::AllSwapsStopped);

			let ext_decimals = external.decimals;
			let internal_decimals = info.internal_decimals;

			ensure!(internal_amount >= info.min_swap_amount, Error::<T>::BelowMinimumSwap);

			let fee_rate = RedemptionFee::<T>::get(&internal_asset, &external_asset);
			ensure!(fee_rate <= max_fee, Error::<T>::FeeTooHigh);
			let fee = fee_rate.mul_ceil(internal_amount);
			let internal_net = internal_amount.saturating_sub(fee);

			let external_out =
				Self::internal_to_external(internal_net, ext_decimals, internal_decimals)?;
			ensure!(
				internal_net.is_zero() || !external_out.is_zero(),
				Error::<T>::AmountTooSmallAfterConversion

			// only the round-tripped share of the external amount.

		pub(crate) fn external_to_internal(
			amount: BalanceOf<T>,
			ext_decimals: u8,
			internal_decimals: u8,
		) -> Result<BalanceOf<T>, Error<T>> {
			use core::cmp::Ordering::*;
			match ext_decimals.cmp(&internal_decimals) {
				Equal => Ok(amount),
				Less => {
					let diff = (internal_decimals - ext_decimals) as u32;
					let factor = Self::pow10(diff)?;
					amount.checked_mul(&factor).ok_or(Error::<T>::ConversionOverflow)
				},
				Greater => {
					let diff = (ext_decimals - internal_decimals) as u32;
					let factor = Self::pow10(diff)?;
					Ok(amount.checked_div(&factor).unwrap_or_else(BalanceOf::<T>::zero))
				},
			}
		}

		/// Verify the live decimals for an external still match the snapshot taken at
		/// registration on this PSM, and that the internal asset's live decimals still
		/// match the snapshot stored in [`PsmInfo`].
		pub(crate) fn ensure_decimals_match(
			info: &PsmInfo<T>,
			internal_asset: &T::AssetId,
			external_asset: &T::AssetId,
			external: &ExternalAssetInfo,
		) -> Result<(u8, u8), DispatchError> {
			ensure!(
				T::Fungibles::decimals(external_asset.clone()) == external.decimals,
				Error::<T>::DecimalsMismatch
			);
			ensure!(
				T::Fungibles::decimals(internal_asset.clone()) == info.internal_decimals,
				Error::<T>::DecimalsMismatch
			);
			Ok((external.decimals, info.internal_decimals))
		}
