### Title
Unbounded `GetFileAttributesRequest.Paths` causes serialized per-path `check-attr` round-trips leading to CPU/wall-clock exhaustion - ([File: internal/gitaly/service/repository/file_attributes.go])

### Summary
`GetFileAttributes` iterates `in.GetPaths()` and calls `checkAttrCmd.Check(path)` once per path, with each call taking `c.m.Lock()`, writing to the subprocess stdin, and blocking on `c.stdout.ReadBytes('\000')` synchronously. `validateGetFileAttributesRequest` only checks that `Paths` is non-empty, with no upper bound on the number of entries, so an attacker-controlled request with a very large `Paths` list forces thousands of sequential, blocking round-trips to a single `git check-attr --stdin` process within one RPC call.

### Finding Description
`GetFileAttributes` (internal/gitaly/service/repository/file_attributes.go:14-42) validates the request via `validateGetFileAttributesRequest`, which only requires `Paths` and `Attributes` be non-empty and does not cap their length [1](#0-0) . It then loops over every path in `in.GetPaths()` calling `checkAttrCmd.Check(path)` synchronously [2](#0-1) .

`CheckAttrCmd.Check` (internal/git/gitattributes/check_attr.go:63-107) locks a mutex, writes the path to the long-lived `check-attr` subprocess's stdin, flushes, and then blocks reading NUL-delimited output from the subprocess's stdout until it has collected `3 * len(names)` tokens [3](#0-2) . Because each call is a full synchronous write+read round trip to an external process and the calls are made in a plain `for` loop with no concurrency or size limiting, the total RPC processing time scales linearly with `len(in.GetPaths())`, with no server-side cap on that count. There is no per-request message-size-based cap in this validation path, and no per-item timeout is applied inside the loop (the outer RPC context deadline is the only bound, and if it's not set aggressively, the call can run for a long time). This matches the described DoS-of-RPC-handler pattern: unbounded per-request resource cost tied directly to a repeated field an unprivileged caller fully controls.

### Impact Explanation
An attacker who owns/forks a repository and can invoke `GetFileAttributesRequest` directly can supply an extremely large `Paths` array (bounded only by gRPC's default max message size, ~4MB, but that alone permits tens of thousands of short path strings). Each entry costs at least one synchronous subprocess round-trip under a mutex, so the RPC handler's wall-clock time and CPU usage grow roughly linearly with the number of paths. This ties up a Gitaly worker/goroutine and the `git check-attr` subprocess for an extended period, degrading availability for other RPCs multiplexed on the same Gitaly process/repository, consistent with a DoS-of-RPC-handler impact (availability degradation, not data compromise).

### Likelihood Explanation
Preconditions are minimal: the attacker only needs the ability to call `GetFileAttributes` against a repository they control (own or forked), which is available to any unprivileged authenticated user with repository access. No special role, secret, or non-default configuration is required. The request is trivial to construct and repeat, and the cost multiplier (thousands of synchronous round trips per single RPC) makes this a repeatable, low-cost amplification for the caller versus the server.

### Recommendation
Enforce a reasonable upper bound on `len(in.GetPaths())` (and `len(in.GetAttributes())`) in `validateGetFileAttributesRequest`, returning `InvalidArgument` when exceeded. Additionally consider batching multiple paths into a single `check-attr --stdin -z` invocation with pipelined writes/reads (rather than one write+blocking-read per path) and/or applying a per-request timeout/limiter independent of the overall RPC deadline.

### Proof of Concept
```go
func BenchmarkGetFileAttributesLargePaths(b *testing.B) {
    ctx := testhelper.Context(b)
    cfg, client := setupRepositoryService(b)
    repoProto, repoPath := gittest.CreateRepository(b, ctx, cfg)

    gittest.WriteCommit(b, cfg, repoPath,
        gittest.WithBranch("main"),
        gittest.WithTreeEntries(
            gittest.TreeEntry{Path: ".gitattributes", Mode: "100644", Content: "*.go diff=go text\n"},
            gittest.TreeEntry{Path: "example.go", Mode: "100644", Content: "x"},
        ))

    for _, n := range []int{100, 1000, 10000} {
        paths := make([]string, n)
        for i := range paths {
            paths[i] = "example.go"
        }
        req := &gitalypb.GetFileAttributesRequest{
            Repository: repoProto,
            Revision:   []byte("main"),
            Attributes: []string{"diff"},
            Paths:      paths,
        }
        start := time.Now()
        _, err := client.GetFileAttributes(ctx, req)
        require.NoError(b, err)
        b.Logf("n=%d elapsed=%s", n, time.Since(start))
    }
}
```
Expected: wall-clock time grows roughly linearly with `n`, with no request-side cap preventing arbitrarily large `n` (limited only by gRPC's default max message size), demonstrating unbounded per-request cost.

	if strings.Contains(path, "\000") {
		return nil, fmt.Errorf("path with NUL byte not allowed")
	}

	c.m.Lock()
	defer c.m.Unlock()
