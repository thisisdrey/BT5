### Title
Nonce dedup pre-filter in `handle_packet_batch_message` never engages for never-validating nonce-like packets, forcing an accounts-db lookup per attacker packet - ([File: core/src/banking_stage/transaction_scheduler/receive_and_buffer.rs])

### Summary
The nonce dedup check in `TransactionViewReceiveAndBuffer::handle_packet_batch_message` only short-circuits `working_bank.check_transaction_without_status_cache` for a given `nonce_pubkey` once a transaction for that address has *successfully* validated and been recorded via `container.set_nonce_transaction_priority_id`. An attacker can craft signed, self-funded, cheap transactions that always parse/sanitize successfully but always fail nonce validation, so the nonce address is never recorded, and every single packet reaches `check_transaction_without_status_cache` → `check_nonce_transaction_validity` → `load_message_nonce_data` → `get_account_with_fixed_root`, an accounts-db lookup, defeating the stated purpose of the pre-filter ("prefilter without loading from accounts-db").

### Finding Description
In `handle_packet_batch_message` [1](#0-0) , the drop check is:
```
let drop_incoming_nonce_tx = raw_nonce_address
    .and_then(|address| container.get_nonce_transaction_priority_id(&address))
    .is_some_and(|existing| existing.priority >= priority || !container.is_queued(existing));
```
This returns `false` (i.e. does NOT drop, and falls through to the expensive check) whenever `container.get_nonce_transaction_priority_id(&address)` is `None` — which is the case for any nonce address that has never previously produced a *successfully validated* nonce transaction in the container.

The expensive path is `working_bank.check_transaction_without_status_cache` [2](#0-1) , which calls `check_transaction_age` [3](#0-2) . If the transaction's `recent_blockhash` is not in the blockhash queue (trivial to arrange by using a random hash), `check_nonce_transaction_validity` is invoked, which calls `load_message_nonce_data` [4](#0-3) :
```
let nonce_account = self.get_account_with_fixed_root(nonce_address)?;
```
This is a real accounts-db read (existing or not), performed unconditionally for every incoming "nonce-like" packet whose `nonce_pubkey` has not yet been admitted into the container.

If the crafted transaction never actually validates (e.g., attacker references an arbitrary/nonexistent pubkey as the nonce account, or a real nonce account they don't control with a mismatched stored hash or wrong authority), `check_nonce_transaction_validity`/`verify_nonce_account` will always return `None`, `check_transaction_age` returns `Err(BlockhashNotFound)`, the packet is discarded before `container.insert_map_only`/`set_nonce_transaction_priority_id` is ever reached. Consequently `get_nonce_transaction_priority_id(&address)` remains `None` forever for that address, and the dedup short-circuit at line 301-305 never engages — every subsequent packet with the same (or a fresh) `nonce_pubkey` again falls through to `get_account_with_fixed_root`.

The comment at lines 295-300 explicitly states the intended invariant: "this means we discard blockhash transactions structured like nonce transactions... it allows us to prefilter without loading from accounts-db." That invariant only holds for the specific scenario tested in `test_receive_and_buffer_pseudo_nonce_never_evicts`/`test_receive_and_buffer_nonce_dedup_drop_evict` (i.e., after a real nonce transaction has already been admitted). It does not hold for the "always-failing nonce candidate" case, which the existing test suite (`test_receive_and_buffer_nonce_dedup_validation_failure`) only exercises with a single low-count sequence, not with sustained fan-out of many always-failing addresses/packets.

To reach this path, only cheap sanitization needs to pass: the attacker signs the transaction themselves (self-funded fee payer, self-signed authority), constructs a first instruction that looks like `AdvanceNonceAccount` with an arbitrary target pubkey, and sets `recent_blockhash` to a value that both isn't in the blockhash queue and isn't the current durable nonce. Signature verification cost for a single-signer transaction is bounded and constant, but the resulting accounts-db lookup (`get_account_with_fixed_root`) is a real index/store access whose cost is not amortized by any per-address or per-connection rate limit beyond banking-stage's generic ingress throughput handling.

### Impact Explanation
This amplifies bank/accounts-db lookup CPU work per byte of attacker-controlled packet data on the banking stage's ingress path, which runs on the leader's hot path for every slot it is leader. Because the dedup mechanism is explicitly designed to bound this cost and fails to do so for the always-failing case, this falls under "grossly underpriced pre-fee work" / QoS evasion in the ingress pipeline: an unstaked attacker pays only the constant cost of constructing and signing throwaway transactions, but forces the leader to perform an accounts-db account lookup per packet, unbounded by any successful-transaction cost or fee payment (the transaction never lands, so no fee is ever charged for the induced work).

### Likelihood Explanation
Fully attacker-controlled and reproducible with zero staked/validator/gossip access: it only requires opening a TPU/QUIC connection and sending arbitrary, self-signed packets, satisfying the stated threat model of an unstaked remote client. The construction (self-signed nonce-shaped transaction with a bogus/foreign nonce address and non-matching recent_blockhash) is trivial and deterministic, and the number of times the expensive lookup fires scales linearly with the number of distinct packets sent, since the container's nonce map is never populated for failing candidates. This is straightforward to demonstrate with existing test scaffolding (`send_transactions`/`receive` helpers already present in the file's test module).

### Recommendation
Add a bounded negative-cache (e.g., a small LRU or bloom-filter-like structure of recently-seen-but-invalid nonce addresses/recent_blockhash pairs) so that repeated attempts referencing the same failing nonce address within a short window are dropped before reaching `check_transaction_without_status_cache`. Alternatively, cheaply pre-validate that `get_durable_nonce()`'s referenced instruction is a well-formed `AdvanceNonceAccount` call signed by the fee payer/authority and rate-limit per-source-IP/connection before allowing repeated accounts-db lookups for unresolved nonce addresses.

### Proof of Concept
Extend the existing test module in `receive_and_buffer.rs` (which already has `create_nonce_transaction`, `send_transactions`, `receive`, and `ReceivingStats` counters) with a fuzz-style test:
```rust
#[test]
fn test_nonce_dedup_prefilter_bypassed_by_always_failing_nonce() {
    let (sender, receiver) = bounded(4096);
    let (bank_forks, mint_keypair) = test_bank_forks_with_fee();
    let (mut receive_and_buffer, mut container) =
        setup_transaction_view_receive_and_buffer(receiver, bank_forks.clone());

    // Reference a nonce account that never exists / never validates.
    let bogus_nonce_pubkey = Pubkey::new_unique();
    let bad_hash = Hash::new_unique(); // not in blockhash queue, not current durable nonce

    let mut txs = Vec::new();
    for _ in 0..2000 {
        txs.push(create_nonce_transaction(
            &mint_keypair,
            &bogus_nonce_pubkey,
            LOW_FEE,
            bad_hash,
        ));
    }
    send_transactions(&sender, &txs);

    let stats = receive(&mut receive_and_buffer, &mut container);

    // Expect: none ever buffered/deduped (they all fail validation every time)
    assert_eq!(stats.num_buffered, 0);
    assert_eq!(stats.num_dropped_on_nonce_dedup, 0); // <-- dedup never engages
    assert_eq!(stats.num_dropped_on_age, 2000);       // every packet hits check_transaction_without_status_cache

    // Instrument/measure (e.g., via a counting wrapper around
    // Bank::get_account_with_fixed_root or check_transaction_without_status_cache)
    // that the accounts-db lookup was invoked ~2000 times, i.e. once per packet,
    // instead of being bounded by the dedup pre-filter.
}
```
Expected result: `num_dropped_on_nonce_dedup == 0` and the number of `check_transaction_without_status_cache` (and underlying `get_account_with_fixed_root`) invocations equals the number of packets sent, confirming the pre-filter provides no protection against repeated always-failing nonce-shaped packets sharing (or varying) `nonce_pubkey`.

        error_counters: &mut TransactionErrorMetrics,

            next_durable_nonce,

        ) {

        }
    }

        let nonce_address = message.get_durable_nonce()?;
