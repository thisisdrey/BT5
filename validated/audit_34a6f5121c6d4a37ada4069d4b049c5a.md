**Reasoning:**

`update_interest_rates` in `programs/marginfi/src/state/bank_cache.rs` is a pure, stateless function that writes exactly three `u32` display/metadata fields (`base_rate`, `lending_rate`, `borrowing_rate`) onto the `BankCache` struct passed by reference. [1](#0-0) 

It takes no account references, pubkeys, or destinations — it cannot "redirect value" or touch any economic object other than the exact `BankCache` handed to it by its only caller, `update_bank_cache` on the loaded `Bank` account itself. [2](#0-1) 

The entrypoint `lending_pool_accrue_bank_interest` loads a single `bank` `AccountLoader` that is Anchor-constrained with `has_one = group`, so there is no way for an unprivileged caller to bind or redirect the operation onto a different bank/group than the one explicitly passed and validated in the accounts struct. [3](#0-2) 

Given unchanged bank state (same `total_asset_shares`/`total_liability_shares`, same `asset_share_value`/`liability_share_value`, same `last_update` timestamp), `update_bank_cache` recomputes the same `utilization_rate` and the same `ComputedInterestRates`, so repeated calls with `update_interest_rates` write the identical `u32` values — the operation is idempotent under unchanged state. [4](#0-3) 

Separately, `accrue_interest` — which actually mutates share values and fee accumulators — explicitly no-ops when `time_delta == 0`, preventing any double-accrual/replay from repeated permissionless calls within the same timestamp. [5](#0-4) 

The premise that a utilization boundary "flip" from a tiny balance change causes `update_interest_rates` to act on "the wrong economic object" doesn't hold: a utilization change only alters *which interest-rate curve point* is used for the *same* bank's *own* cache — it does not redirect the write to any other bank, account, or destination, and does not move or misattribute any funds, shares, or fees. This is expected rate-curve behavior (as documented in `README.md`), not a state-binding or replay bug. [6](#0-5) 

No code path exists by which this permissionless crank can pay out, transfer, or credit value to an unvalidated destination, nor can repeated invocation against unchanged state cause drift in cache, bank totals, or destinations.

    fn update_bank_cache(&mut self, group: &MarginfiGroup) -> MarginfiResult<()> {
        if self.cache.is_liquidation_price_cache_locked() {
            return Ok(());
        }
        let total_assets_amount: I80F48 = self.get_asset_amount(self.total_asset_shares.into())?;
        let total_liabilities_amount: I80F48 =
            self.get_liability_amount(self.total_liability_shares.into())?;

        if (total_assets_amount == I80F48::ZERO) || (total_liabilities_amount == I80F48::ZERO) {
            self.cache.reset_preserving_oracle_price();
            return Ok(());
        }

        let ir_calc = self
            .config
            .interest_rate_config
            .create_interest_rate_calculator(group);

        let utilization_rate: I80F48 = total_liabilities_amount
            .checked_div(total_assets_amount)
            .ok_or_else(math_error!())?;
        let interest_rates = ir_calc.calc_interest_rate(utilization_rate)?;

        update_interest_rates(&mut self.cache, &interest_rates);

        // Update banks last update timestamp
        self.last_update = Clock::get()?.unix_timestamp;
        Ok(())
    }

pub fn lending_pool_accrue_bank_interest(
    ctx: Context<LendingPoolAccrueBankInterest>,
) -> MarginfiResult {
    let clock = Clock::get()?;
    let mut bank = ctx.accounts.bank.load_mut()?;
    let group = &ctx.accounts.group.load()?;

    bank.accrue_interest(
        clock.unix_timestamp,
        group,
        #[cfg(not(feature = "client"))]
        ctx.accounts.bank.key(),
    )?;

    // TODO see if we can recycle some things like the InterestRateCalc from accrue to save some CU
    bank.update_bank_cache(group)?;

    Ok(())
}

### Interest Rates, Curves, and Compounding

In general, Banks are configured to charge progressively higher interest as the "utilization rate"
(UR) increases. The UR for a Bank is simply borrows/deposits. Interest typically climbs slowly until
the "optimal utilization rate", which for most assets is around 80-90%. Beyond that level, interest
grows rapidly. At 100% UR, lenders cannot withdraw, because all funds have been borrowed out! High
interest rates at 90%+ UR drive market conditions to force borrowers to repay their debts.

For more details about the interest configuration for a particular Bank, see the `zero_util_rate`
(interest at 0% UR), `hundred_util_rate` (interest at 100% UR), and `points` (interest at all levels
in between). Note that we support up to seven points in our interest rate curves (0 UR, 100 UR, and
5 in between), but the majority of banks use only 2 (0 at 0 UR, one in between, and a value at 100
UR).
