### Title
Predictable-path symlink file overwrite in TVM trace writer - (File: actuator/src/main/java/org/tron/core/vm/VMUtils.java)

### Summary
`VMUtils.createProgramTraceFile()`/`writeStringToFile()`, invoked from `VMActuator.finalization()` whenever `vm.vmTrace = true`, writes the TVM execution trace to a filename fully determined by the broadcasted transaction's own hash, with no symlink check and a truncating `FileOutputStream` open — mirroring the FastNetMon `print_screen_contents_into_file()` symlink weakness.

### Finding Description
`createProgramTraceFile(txHash)` builds `File file = new File(new File("./", "vm_trace"), txHash + ".json")` [4](#0-3) . It then does a classic check-then-act: if `file.exists()` it merely checks `isFile()`/`canWrite()` and returns it for writing; if not, it `createNewFile()`s it [5](#0-4) . Neither branch verifies the path component is not a symbolic link (no `Files.readAttributes(..., NOFOLLOW_LINKS)`, no `O_NOFOLLOW`). `writeStringToFile()` then opens the file with a plain `new FileOutputStream(file)`, which truncates and follows any symlink transparently [6](#0-5) .

Because `txHash` is `Hex.toHexString(rootInternalTx.getHash())` — the hash of the very transaction the caller constructed and can compute before ever sending it to the node [3](#0-2)  — the resulting filename `./vm_trace/<hash>.json` is fully attacker-predictable ahead of time, exactly as the CVE's `/tmp/fastnetmon.dat` is a fixed, predictable path. A local attacker who can write into the node's working directory (e.g., a co-tenant/service account on a shared host) can pre-create a symlink at that exact path pointing to any file writable by the node process (e.g. `~/.ssh/authorized_keys`, a cron file, or node config), then broadcast the crafted transaction to trigger the trace write, which follows the symlink and truncates/overwrites the target with attacker-influenced trace JSON content (containing hex-encoded op-trace/return data the attacker can partially shape via the transaction/contract).

### Impact Explanation
If exploited on a node with `vm.vmTrace` enabled (a supported, documented debug configuration, not a niche/mocked path), this allows a local attacker to overwrite arbitrary files writable by the java-tron process user — a config-tampering / persistence / potential RCE primitive (e.g., overwriting startup scripts, keystores paths, or authorized_keys), matching the CVE's "local attacker overwrite arbitrary files as the process user" impact class. This lands as CWE-59 (symlink following) / CWE-367 (TOCTOU), Medium severity, consistent with the CVSS 5.5 local-attack profile of the source advisory.

### Likelihood Explanation
Requires two preconditions: (1) `vm.vmTrace = true` on the node (off by default, opt-in for debugging [7](#0-6) ), and (2) local filesystem access to the node's working directory to plant the symlink before broadcasting. Given both, exploitation is fully deterministic — no race or guessing needed, since the attacker controls the transaction bytes and thus the exact target filename.

### Recommendation
In `VMUtils.createProgramTraceFile()`, resolve and validate that `vm_trace/<hash>.json` is not a symbolic link using `Files.readAttributes(path, BasicFileAttributes.class, LinkOption.NOFOLLOW_LINKS)` before touching it, and open the file for writing via `Files.newByteChannel(path, EnumSet.of(CREATE, WRITE, TRUNCATE_EXISTING), LinkOption.NOFOLLOW_LINKS)` (or equivalent `O_NOFOLLOW`-safe API) instead of `File.createNewFile()` + `new FileOutputStream(file)`, refusing to write if the path is or becomes a symlink.

### Proof of Concept
1. On a java-tron node started with `vm.vmTrace = true`, as a local user sharing the node's working directory, build (offline) a `TriggerSmartContract`/`CreateSmartContract` transaction and compute its hash locally to get `H`.
2. Create `./vm_trace/H.json` as a symlink to a file writable by the node process, e.g. `ln -s /home/tron/.ssh/authorized_keys ./vm_trace/H.json`.
3. Broadcast the transaction to the node so it executes and reaches `VMActuator.finalization()` → `VMUtils.saveProgramTraceFile(H, traceContent)`.
4. The node opens `./vm_trace/H.json` via `new FileOutputStream`, follows the symlink, and truncates/overwrites `authorized_keys` with trace JSON content, corrupting/hijacking it.

  private static File createProgramTraceFile(String txHash) {
    File result = null;

    if (VMConfig.vmTrace()) {

      File file = new File(new File("./", "vm_trace"), txHash + ".json");

      if (file.exists()) {
        if (file.isFile() && file.canWrite()) {
          result = file;
        }
      } else {
        try {
          file.getParentFile().mkdirs();
          if (!file.createNewFile()) {
            logger.error("failed to create file {}", file.getPath());
          }
          result = file;
        } catch (IOException e) {
          // ignored
        }
      }
    }

    return result;
  }

  private static void writeStringToFile(File file, String data) {
    OutputStream out = null;
    try {
      out = new FileOutputStream(file);
      if (data != null) {
        out.write(data.getBytes("UTF-8"));
      }
    } catch (Exception e) {
      logger.error(format("Cannot write to file '%s': ", file.getAbsolutePath()), e);
    } finally {
      closeQuietly(out);
    }
  }

  public static void saveProgramTraceFile(String txHash, String content) {
    File file = createProgramTraceFile(txHash);
    if (file != null) {
      writeStringToFile(file, content);
    }
  }
