### Title
Unauthenticated global handshake-slot exhaustion via never-completing QUIC connections bypasses per-IP throttling - ([File: streamer/src/nonblocking/quic.rs])

### Summary
`ConnectionRateLimiter::is_allowed`/`register_connection` only track a source IP once its QUIC handshake has *succeeded* (inside `setup_connection`, after `connecting.await` resolves `Ok`). Before that point, the only gate on new connection attempts is a single **global**, non-per-IP concurrency budget (`qos.max_concurrent_connections()` via `ClientConnectionTracker::new`). A single unprivileged IP can therefore open enough never-completing (or slow) handshakes to fully occupy this shared budget for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT` (2s) at a time, indefinitely, denying handshake slots to all other unstaked and staked peers.

### Finding Description
In `run_server` (`streamer/src/nonblocking/quic.rs:331-407`), each incoming connection is checked in this order:
1. `overall_connection_rate_limiter.current_tokens() == 0` [1](#0-0) 
2. `rate_limiter.is_allowed(&ip)` (per-IP) [2](#0-1) 
3. `ClientConnectionTracker::new(stats, qos.max_concurrent_connections())` — a **global**, not per-IP, cap on concurrently-open connection slots (staked+unstaked combined) [3](#0-2) 

Only after `incoming.accept()` succeeds does `setup_connection` await the actual handshake with a 2-second timeout, and only on `Ok(new_connection)` (i.e., handshake success) is `rate_limiter.register_connection(&from.ip())` called and `overall_connection_rate_limiter.consume_tokens(1)` invoked [4](#0-3) .

`ConnectionRateLimiter::is_allowed` explicitly treats any never-before-seen IP as allowed (`None => true`) [5](#0-4) , and since `register_connection` is only reached on handshake success, an attacker who never completes the handshake is **never recorded** by the per-IP limiter, no matter how many concurrent half-open attempts they issue from that IP. Similarly, `overall_connection_rate_limiter` tokens are only consumed post-handshake (line 495), so a flood of non-completing handshakes never drains it either — the pre-accept `current_tokens() == 0` check at line 347 stays permissive throughout the attack.

The only real bottleneck the attacker faces is the shared `open_connections` counter gated by `qos.max_concurrent_connections()`, computed in `SwQos::max_concurrent_connections` as `(max_staked_connections + max_unstaked_connections) * 5 / 4` [6](#0-5) , using defaults `DEFAULT_MAX_STAKED_CONNECTIONS = 2000` and `DEFAULT_MAX_UNSTAKED_CONNECTIONS = 2000` [7](#0-6)  — i.e. a default budget of 5000 slots, shared by all peers regardless of stake, and consumed *before* the peer's stake/identity is even known (identity/stake is only resolved after handshake via `get_connection_stake`) [8](#0-7) .

Because this slot is held for up to `QUIC_CONNECTION_HANDSHAKE_TIMEOUT = 2s` per pending attempt [9](#0-8) , one IP sustaining ≥2500 fresh handshake attempts/sec (using distinct QUIC connection IDs / source ports so each is treated as a new `Incoming`) can keep the entire global slot pool saturated continuously, causing `ClientConnectionTracker::new` to fail for all subsequent connections (`refused_connections_too_many_open_connections`) regardless of whether those subsequent connectors are staked or unstaked, since stake cannot be evaluated until after a slot is granted and the handshake completes.

The developers' own comment at lines 332-340 acknowledges that per-IP throttling cannot be applied pre-handshake due to IP-spoofing concerns, but this tradeoff only protects against *spoofed*-IP amplification; it does not protect the shared concurrency budget from being monopolized by a single real, routable attacker IP that completes TCP-like ownership assertion (a valid UDP 4-tuple) without ever finishing TLS.

### Impact Explanation
This allows an unprivileged, unstaked remote attacker with a single IP to exhaust the leader's entire QUIC/TPU connection-acceptance capacity, denying legitimate staked and unstaked senders the ability to establish new TPU connections during the attack window. Since this budget gates a leader's TPU ingress path, this constitutes a QoS/DoS bypass of the intended unstaked/staked connection-limit invariant, matching Agave's "TPU/QoS starvation / resource exhaustion" bounty category — not a consensus-safety bug, but a real availability degradation reachable by a single unprivileged network client.

### Likelihood Explanation
Feasible with only: one routable IP, ability to send valid QUIC Initial packets (to pass `incoming.accept()`) without completing the handshake, and sustained throughput to keep the ~5000-slot global pool saturated. No special protocol knowledge, staking, or spoofing is required, and the attack is repeatable indefinitely by simply re-issuing connection attempts every ~2 seconds (the handshake timeout).

### Recommendation
Apply a coarse per-IP admission gate (e.g., using an IP-based token bucket keyed on `remote_address().ip()`, updated *before* granting a global `ClientConnectionTracker` slot rather than only after successful handshake) to cap the number of concurrently *pending* (not-yet-handshaken) connections a single IP may hold, independent of whether it completes the handshake. This preserves the anti-spoofing rationale (still don't apply the persistent per-IP `ConnectionRateLimiter` state until handshake success) while preventing one address from monopolizing the shared pre-handshake concurrency budget.

### Proof of Concept
Integration test plan (extending `streamer/src/nonblocking/quic.rs` test harness / `tpu-client-next` test utilities):
```rust
#[tokio::test(flavor = "multi_thread")]
async fn test_single_ip_handshake_flood_starves_legit_clients() {
    // Spawn run_server with default SwQosConfig (max_staked=2000, max_unstaked=2000)
    // -> max_concurrent_connections ~= 5000
    let SpawnTestServerResult { stats, server_address, cancel, .. } =
        setup_quic_server(None, QuicStreamerConfig::default_for_tests(), SwQosConfig::default());

    // From a single source IP (localhost), open >5000 concurrent QUIC connection
    // attempts that never complete the TLS handshake (e.g. send Initial packet
    // then stall, or connect to a stub UDP endpoint that never replies with
    // Handshake packets), each held open near QUIC_CONNECTION_HANDSHAKE_TIMEOUT.
    for _ in 0..6000 {
        tokio::spawn(open_stalling_quic_handshake(server_address));
    }

    // Give attacker attempts time to occupy all global slots.
    tokio::time::sleep(Duration::from_millis(500)).await;

    // A legitimate client (fresh IP-independent client, could even be same IP
    // to demonstrate no protection) attempts to connect and should be refused
    // due to exhausted global concurrent-connection budget.
    let legit_result = make_client_endpoint(&server_address, None).await;
    assert!(legit_result.is_err_or_times_out());
    assert!(stats.refused_connections_too_many_open_connections.load(Ordering::Relaxed) > 0);

    cancel.cancel();
}
```
Expected assertion: `refused_connections_too_many_open_connections` increments and a legitimate client cannot establish a TPU connection within one leader slot duration, while `connection_rate_limited_per_ipaddr` for the attacker's IP remains 0 throughout (proving per-IP throttling never engaged).

impl ClientConnectionTracker {
    /// Check the max_concurrent_connections limit and if it is within the limit
    /// create ClientConnectionTracker and increment open connection count. Otherwise returns Err
    fn new(stats: Arc<StreamerStats>, max_concurrent_connections: usize) -> Result<Self, ()> {
        let open_connections = stats.open_connections.fetch_add(1, Ordering::Relaxed);
        if open_connections >= max_concurrent_connections {
            stats.open_connections.fetch_sub(1, Ordering::Relaxed);
            debug!(
                "There are too many concurrent connections opened already: open: \
                 {open_connections}, max: {max_concurrent_connections}"
            );
            return Err(());
        }

        Ok(Self { stats })
    }
}
