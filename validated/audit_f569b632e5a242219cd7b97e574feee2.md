### Title
`terminate_vesting_contract` Can Be Permanently Blocked by a Shareholder Opting Out of Direct Coin Transfers — (`File: aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`terminate_vesting_contract` unconditionally calls `distribute()` before performing the critical state change (`state = VESTING_POOL_TERMINATED`). `distribute()` calls `aptos_account::deposit_coins` for every shareholder/beneficiary. If any recipient has opted out of direct coin transfers (`set_allow_direct_coin_transfers(false)`) and does not have a legacy `CoinStore<AptosCoin>`, the deposit aborts, the entire transaction reverts, and the vesting contract can never be terminated. The admin's staking funds are permanently frozen.

---

### Finding Description

`terminate_vesting_contract` is the admin's only path to recover funds from a vesting contract. Its implementation is:

```move
public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
    assert_active_vesting_contract(contract_address);

    // Distribute all withdrawable coins ...
    distribute(contract_address);   // ← can abort

    let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
    verify_admin(admin, vesting_contract);
    ...
    vesting_contract.state = VESTING_POOL_TERMINATED;   // ← never reached if distribute aborts
    vesting_contract.remaining_grant = 0;
    unlock_stake(vesting_contract, active_stake);
}
``` [1](#0-0) 

`distribute()` iterates over all shareholders and calls `aptos_account::deposit_coins(recipient_address, share_of_coins)` for each one:

```move
shareholders.for_each_ref(|shareholder| {
    ...
    let recipient_address = get_beneficiary(vesting_contract, shareholder);
    aptos_account::deposit_coins(recipient_address, share_of_coins);
});
``` [2](#0-1) 

`aptos_account::deposit_coins` contains the following abort path:

```move
if (!coin::is_account_registered<CoinType>(to)) {
    assert!(
        can_receive_direct_coin_transfers(to),
        error::permission_denied(EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS)
    );
    coin::register<CoinType>(&create_signer(to));
};
``` [3](#0-2) 

`can_receive_direct_coin_transfers` returns `false` when the account has explicitly called `set_allow_direct_coin_transfers(false)`:

```move
public fun can_receive_direct_coin_transfers(account: address): bool acquires DirectTransferConfig {
    !exists<DirectTransferConfig>(account)
        || borrow_global<DirectTransferConfig>(account).allow_arbitrary_coin_transfers
}
``` [4](#0-3) 

With the FA migration, accounts that use only a primary fungible store (no legacy `CoinStore<AptosCoin>`) will have `coin::is_account_registered<AptosCoin>` return `false`. Any such shareholder who has called `set_allow_direct_coin_transfers(false)` will cause `deposit_coins` to abort with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.

The codebase itself acknowledges this class of problem in the comment on `set_beneficiary`:

```move
// Verify that the beneficiary account is set up to receive APT. This is a requirement so distribute() wouldn't
// fail and block all other accounts from receiving APT if one beneficiary is not registered.
assert_account_is_registered_for_apt(new_beneficiary);
``` [5](#0-4) 

However, this guard only applies at `set_beneficiary` time and only checks registration, not `allow_arbitrary_coin_transfers`. It does not protect against a shareholder (whose address is set at contract creation, not via `set_beneficiary`) calling `set_allow_direct_coin_transfers(false)` at any later time.

---

### Impact Explanation

- The admin can never set `state = VESTING_POOL_TERMINATED`, so `admin_withdraw` (which requires `state == VESTING_POOL_TERMINATED`) is also permanently blocked.
- All staking funds in the vesting contract's pool are permanently frozen — the admin cannot recover them.
- This constitutes **permanent freezing of user-controlled on-chain APT staking balances**.

---

### Likelihood Explanation

Any shareholder in a vesting contract can trigger this by calling the public entry function `set_allow_direct_coin_transfers(false)` on their own account. This is a zero-cost, unprivileged, single-transaction action. On mainnet, accounts created after the FA migration or accounts that have voluntarily migrated (`migrate_to_fungible_store`) will not have a `CoinStore<AptosCoin>`, satisfying the precondition. A malicious or uncooperative shareholder can deliberately block termination to prevent the admin from recovering funds.

---

### Recommendation

Decouple the distribution from the termination. The state change (`VESTING_POOL_TERMINATED`) and stake unlock should not be gated on a successful distribution. Two options:

1. **Separate the calls**: Remove `distribute(contract_address)` from `terminate_vesting_contract`. Let the admin call `distribute` independently before or after termination.
2. **Skip-on-failure**: Wrap the per-shareholder `deposit_coins` call in a try/catch pattern (or check preconditions before attempting), so that a single recipient's inability to receive funds does not abort the entire termination.

---

### Proof of Concept

1. Admin creates a vesting contract with shareholder `S`.
2. `S` calls `set_allow_direct_coin_transfers(false)` on their account.
3. `S` migrates to FA (or is a new account with no `CoinStore<AptosCoin>`), so `coin::is_account_registered<AptosCoin>(S)` returns `false`.
4. Rewards accumulate; `vest()` is called; some coins become withdrawable in the staking pool.
5. Admin calls `terminate_vesting_contract(admin, contract_address)`.
6. Internally, `distribute(contract_address)` is called.
7. `withdraw_stake` returns non-zero coins.
8. `aptos_account::deposit_coins(S, share)` is called.
9. `coin::is_account_registered<AptosCoin>(S)` → `false`.
10. `can_receive_direct_coin_transfers(S)` → `false` (opted out).
11. Transaction aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
12. `vesting_contract.state` remains `VESTING_POOL_ACTIVE`; `admin_withdraw` is permanently blocked.

    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }
