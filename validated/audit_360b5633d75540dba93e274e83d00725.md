Audit Report

## Title
Coretime renewals corrupt `sellout_price`/`cores_sold` fed into `AdaptPrice`, letting a caller manipulate the next sale's start/target price - (File: `substrate/frame/broker/src/utility_impls.rs`)

## Summary
`pallet-broker`'s `purchase_core` function is shared by both `do_purchase` (market-priced) and `do_renew` (non-market, capped-bump-priced) code paths, and unconditionally overwrites `sale.sellout_price` with whatever `price` it is given as long as `sale.cores_sold <= sale.ideal_cores_sold`. Since renewals carry a stale, non-market price (`record.price`, capped via `price_cap`) rather than a genuine sale-derived price, an account holding renewable cores can call `do_renew` before any organic market purchase happens in a sale period, saturating `cores_sold` up to `ideal_cores_sold` and locking a stale `sellout_price` into the record. That corrupted `sellout_price` is later consumed unmodified by `rotate_sale` → `SalePerformance::from_sale` → `T::PriceAdapter::adapt_price` (`CenterTargetPrice`/`MinimumPrice`) to set the *next* sale's `end_price`/`target_price` for all other buyers.

## Finding Description
`purchase_core` at `substrate/frame/broker/src/utility_impls.rs:78-91` is the single choke point that records `sellout_price`:
```rust
pub(crate) fn purchase_core(...) -> Result<CoreIndex, DispatchError> {
    Self::charge(who, price)?;
    let core = sale.first_core.saturating_add(sale.cores_sold);
    sale.cores_sold.saturating_inc();
    if sale.cores_sold <= sale.ideal_cores_sold || sale.sellout_price.is_none() {
        sale.sellout_price = Some(price);
    }
    Ok(core)
}
``` [1](#0-0) 

`do_purchase` feeds it the true leadin-decayed market price via `Self::sale_price(&sale, now)`: [2](#0-1) 

`do_renew`, by contrast, feeds it `record.price` — a stale, previously-computed capped renewal price that has no relationship to current market conditions — and separately computes/stores a new capped price for the following renewal cycle: [3](#0-2) 

Because `do_renew` has no ordering constraint relative to `do_purchase` (unlike `do_purchase`, it does not even check `now > sale.sale_start`), and only gates on `ensure_cores_for_sale`, a holder of renewable cores can call `renew` for enough cores to push `cores_sold` past `ideal_cores_sold` before any market purchase occurs. Once `cores_sold > ideal_cores_sold`, subsequent genuine `do_purchase` calls no longer update `sellout_price` (the `<=` gate is closed), so the corrupted renewal price persists to the end of the sale.

`rotate_sale` then passes this contaminated data straight into the price adapter:
```rust
let new_prices = T::PriceAdapter::adapt_price(SalePerformance::from_sale(&old_sale));
``` [4](#0-3) 

`SalePerformance::from_sale` copies `sellout_price`/`cores_sold`/`ideal_cores_sold` verbatim from the (now polluted) `SaleInfoRecord`: [5](#0-4) 

`CenterTargetPrice::adapt_price` (wrapped by `MinimumPrice`) derives both `end_price` and `target_price` for the next sale purely from `performance.sellout_price`: [6](#0-5) 

This is the same class of defect that `PR 4521` ("AdaptPrice trait is now price controlled") aimed to address by moving from raw `cores_sold` counts to `sellout_price`-based adaptation, explicitly citing a discovered Kusama-launch price-manipulation issue — but that change did not separate renewal-sourced prices from market-purchase-sourced prices at the `purchase_core` write site, so the contamination channel described here remains open: [7](#0-6) 

## Impact Explanation
This is a runtime bug that compromises the intended behavior of `pallet-broker`'s price-discovery mechanism: the value used to set the *next* Coretime sale's `end_price`/`target_price` — an invariant meant to reflect genuine market demand — can be set to an attacker-influenced, non-market value (`record.price` from renewals) instead of the true sellout price. An unprivileged holder of a renewable core (ordinary permissionless capability, requiring no governance/validator/admin privilege) can drive `sellout_price` artificially low, allowing under-priced acquisition of coretime in the following sale, or artificially high, unfairly inflating the price paid by unrelated ordinary buyers in the next sale. This matches the "public underpriced work" impact category tied to Coretime pricing correctness.

## Likelihood Explanation
`Call::renew` is a normal, permissionless public extrinsic; nothing in `do_renew` or `purchase_core` distinguishes renewal-sourced prices from market-purchase-sourced prices, nor enforces any ordering requiring market purchases to occur first. Because `ideal_cores_sold` is typically a small fraction of `cores_offered`, only a small number of renewals submitted early in a sale period are needed to saturate the `cores_sold <= ideal_cores_sold` gate and lock in the stale price, making the attack cheap and repeatable every sale period.

## Recommendation
Track renewal-driven contributions to `sellout_price`/`cores_sold` separately from market-purchase-driven contributions in `SaleInfoRecord` — e.g., have `do_renew` bypass the `sellout_price` write in `purchase_core` entirely (only `do_purchase` should be allowed to set/refresh `sellout_price`), or add a dedicated counter for renewal cores that is excluded from what `SalePerformance::from_sale` passes to `T::PriceAdapter::adapt_price`.

## Proof of Concept
1. Configure a sale where `ideal_cores_sold` is small (e.g., 2) relative to `cores_offered` (e.g., 50), via `ideal_bulk_proportion`.
2. Ensure two cores have `PotentialRenewals` entries with a stale/low `record.price` from a prior low-demand period.
3. As soon as the new sale opens, submit `Call::renew` for both cores before any `Call::purchase` lands. Each call routes through `do_renew` → `purchase_core`, incrementing `cores_sold` to 1 then 2 and setting `sale.sellout_price = Some(record.price)` both times since `cores_sold <= ideal_cores_sold`.
4. Submit a genuine `Call::purchase` at the true market leadin price; since `cores_sold` (3) now exceeds `ideal_cores_sold` (2), `sellout_price` is not updated and remains the stale renewal price.
5. At `rotate_sale`, `SalePerformance::from_sale(&old_sale).sellout_price` equals the stale renewal price rather than the true market-clearing price, and `T::PriceAdapter::adapt_price` computes the next sale's `end_price`/`target_price` from this corrupted value, verifiable via a unit test asserting `adapt_price` output differs materially from what it would be using the actual market-purchase price.

	fn adapt_price(performance: SalePerformance<Balance>) -> AdaptedPrices<Balance> {
		let Some(sellout_price) = performance.sellout_price else {
			return AdaptedPrices {
				end_price: performance.end_price,
				target_price: FixedU64::from(10).saturating_mul_int(performance.end_price),
			};
		};

		let price = FixedU64::from_rational(1, 10).saturating_mul_int(sellout_price);
		let price = if price == Balance::zero() {
			// We could not recover from a price equal 0 ever.
			sellout_price
		} else {
			price
		};

		AdaptedPrices { end_price: price, target_price: sellout_price }
	}
