### Title
`Pool.liquidate` permanently reverts for underwater positions whose remaining debt would fall below `debtFloorInUsd`, making residual bad debt unliquidatable - ([File: contracts/Pool.sol](contracts/Pool.sol))

### Summary
Analogous to the Astaria H-19 bug (partial repayment of an expired lien reverts because `lien.last` is pushed past `lien.end`, breaking `end - lien.last`), Metronome's `Pool.liquidate` contains a state-boundary revert that DoS's the "last mile" of a liquidation. When `debtFloorInUsd > 0`, any `amountToRepay_` that leaves the account with debt in `(0, debtFloorInUsd)` reverts with `RemainingDebtIsLowerThanTheFloor`, while repaying the full debt reverts with `AmountIsTooHigh` whenever the seized collateral would exceed the account's `DepositToken` balance (i.e., underwater positions). The result is a permanently unliquidatable residual bad debt, symmetric to Astaria's permanently unpayable partial lien.

### Finding Description
In `Pool.liquidate` (`contracts/Pool.sol:537-596`):

1. The liquidator must repay at most `maxLiquidable` fraction of the debt (`Pool.sol:567`), so full repayment may already be disallowed.
2. If `debtFloorInUsd > 0`, the post-repayment debt `_debtTokenBalance - amountToRepay_` must be either `0` or `>= debtFloorInUsd` (`Pool.sol:571-579`), otherwise it reverts.
3. `_totalSeized` must not exceed `depositToken_.balanceOf(account_)` (`Pool.sol:583-585`), otherwise it reverts with `AmountIsTooHigh`.

For an underwater position (collateral USD value < debt USD value, confirmed possible by the test suite at `test/Pool.test.ts:773-789`), the maximum repayable amount `quoteLiquidateMax` (`Pool.sol:419-440`) is capped by what the collateral can cover, which is strictly less than the full debt. Any repayment in the allowed range therefore leaves `0 < remainingDebt`, and once successive partial liquidations push the remaining debt below `debtFloorInUsd`, every subsequent `liquidate` call reverts:

- Any `amountToRepay_ < debtBalance` → `RemainingDebtIsLowerThanTheFloor`
- `amountToRepay_ == debtBalance` → `quoteLiquidateOut` produces `_totalSeized > balanceOf(account_)` → `AmountIsTooHigh`

There is no alternative path to clear the debt: `DebtToken.repay`/`repayAll` require burning the payer's own synthetic tokens voluntarily (no incentive to socialize a stranger's bad debt), and `liquidate` is the only incentivized clearing mechanism.

### Impact Explanation
Permanent freezing of protocol funds / protocol insolvency: the residual bad debt can never be liquidated, so the corresponding synthetic token supply remains backed by insufficient collateral. This is the same economic DoS as H-19 — partial repayment paths revert — but in Metronome it permanently bricks the final stage of liquidation rather than just individual auction bids.

### Likelihood Explanation
Requires `debtFloorInUsd > 0` (a supported, tested configuration — `updateDebtFloor` is exercised in `test/Pool.test.ts:408-437`) and a position to become underwater, which occurs whenever collateral falls faster than liquidators act or during sharp price moves. No privileged role, oracle manipulation, or attacker action is needed to reach the stuck state; any unprivileged liquidator can demonstrate the revert.

### Recommendation
Allow the boundary case explicitly: when a repayment would leave debt in `(0, debtFloorInUsd)` but is the maximum repayable given the account's collateral (i.e., `amountToRepay_ >= quoteLiquidateMax`), either (a) permit the full debt to be repaid/seized regardless of the floor, or (b) permit partial repayment that leaves sub-floor debt when no full-repayment path exists. Alternatively, write off the dust debt (burn it without seize) when the account's entire collateral has been seized.

### Proof of Concept
Foundry/Hardhat fork sketch against deployed `Pool`:

```solidity
// Setup: debtFloorInUsd = $3,000 (governance setter updateDebtFloor, as in tests)
// alice deposits MET, mints msETH debt = 1 msETH ($4,000)
// MET price drops 50% -> position underwater (collateral < debt)
masterOracle.updatePrice(met, 0.5e18);

uint256 debt = msEthDebtToken.balanceOf(alice);      // e.g. ~1 msETH, > $3,000 floor
uint256 maxRepay = pool.quoteLiquidateMax(msETH, alice, msdMET); // capped by collateral
assert(maxRepay < debt);                             // cannot fully repay

// 1) Max partial repayment leaves dust debt < floor
vm.prank(liquidator);
vm.expectRevert(Pool.RemainingDebtIsLowerThanTheFloor.selector);
pool.liquidate(msETH, alice, maxRepay, msdMET);      // debt - maxRepay in (0, floor)

// 2) Full repayment seizes more than balance
vm.prank(liquidator);
vm.expectRevert(Pool.AmountIsTooHigh.selector);
pool.liquidate(msETH, alice, debt, msdMET);

// Debt is permanently unliquidatable -> bad debt accrues interest forever
```

The existing tests already demonstrate both reverts independently (`test/Pool.test.ts:409-421` floor revert, `:783-789` `AmountIsTooHigh` under water); combining them on one underwater position shows the dead-end state.
