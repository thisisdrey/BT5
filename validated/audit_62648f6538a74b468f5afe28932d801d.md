### Title
Unauthenticated event-receiver HTTP endpoint allows forging `SignerEvent`s (incl. unsigned miner messages) into the signer's runloop - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` accepts any raw HTTP POST to `/stackerdb_chunks` (or `/proposal_response`, `/new_burn_block`, `/new_block`) on its bound socket and hands the body straight to `process_event::<T, StackerDBChunksEvent>`, with no check that the caller is the local stacks-node's event dispatcher. For the `.miners` boot contract branch, the resulting `StackerDBChunksEvent` chunks are deserialized into `SignerEvent::MinerMessages` with zero signature verification, so an attacker who can reach the bound port can inject fully attacker-controlled miner messages into the signer's internal event stream.

### Finding Description
The identity assumed by the signer runloop is "every `SignerEvent` came from a StackerDB chunk written by an authorized slot owner." That equality is broken at the transport layer: `SignerEventReceiver::bind` opens a plain `tiny_http::HttpServer` [1](#0-0) , and `next_event`/`process_event` perform no authentication of the HTTP client — no secret header, no cookie, no peer-IP allowlist — before routing the body into `serde_json::from_slice::<StackerDBChunksEvent>` and `TryInto<SignerEvent<T>>` [2](#0-1) [3](#0-2) .

For the `MINERS_NAME` contract branch of `TryFrom<StackerDBChunksEvent> for SignerEvent<T>`, each `chunk.data` is passed directly to `T::consensus_deserialize` with **no call to `chunk.recover_pk()` or `chunk.verify()`** — unlike the sibling `SIGNERS_NAME` branch, which at least recovers a public key from `chunk.sig` before accepting the message: [4](#0-3) 

So for `.miners` chunks, any bytes an attacker places in the JSON `modified_slots[].data` field (base/hex-encoded per `StackerDBChunkData`'s serde impl) that deserialize as a valid `T` (e.g., `SignerMessage`) become a `SignerEvent::MinerMessages(...)` forwarded verbatim to the runloop channel via `forward_event` [5](#0-4) . The `sig`/`slot_id`/`slot_version` fields of `StackerDBChunkData` are attacker-supplied and never checked against any real StackerDB state or slot ownership at this layer.

Even for the `SIGNERS_NAME` branch, `chunk.recover_pk()` only *recovers whatever public key algebraically satisfies the ECDSA-recoverable signature over attacker-chosen data* [6](#0-5)  — it does not verify that the recovered key belongs to a signer who legitimately owns that slot in the real StackerDB replica set. An attacker can trivially generate their own keypair, sign their own fabricated chunk, and have `recover_pk` "succeed," producing a `SignerEvent::SignerMessages` entry with an attacker-chosen `StacksPublicKey`. Any downstream code that trusts the `(slot_id, StacksPublicKey, T)` tuple without independently re-deriving/checking real StackerDB slot ownership (out of scope here per the "signer decision logic" exclusion, but relevant context) would be consuming forged data.

The root cause is architectural: this HTTP listener is designed to only ever be called by the co-located stacks-node process's event-dispatcher over loopback, but the code enforces that assumption nowhere — no bearer token, no Unix-socket restriction, no mTLS, no request-origin check. If the configured bind address is reachable beyond loopback (e.g., `0.0.0.0`), any remote unprivileged party can open a TCP connection and issue the raw HTTP request described in the prompt.

### Impact Explanation
An attacker who can reach the bound event-receiver socket can inject arbitrary `SignerEvent::MinerMessages` (unsigned, for the `.miners` lane) and attacker-signed `SignerEvent::SignerMessages` (self-signed, not validated against real slot ownership at this layer) directly into the signer's internal processing pipeline, bypassing StackerDB's own chunk-write authorization entirely. This is an unauthenticated write into the signer's internal event stream — the exact "Critical: unauthenticated write to state" category in scope. It is trivially repeatable per TCP connection/POST.

### Likelihood Explanation
Precondition per the prompt: the event-receiver bind address is reachable beyond loopback (e.g. bound to `0.0.0.0` in config). Given that precondition, the attack requires no secret, no valid slot ownership, no privileged role — just the ability to open a TCP connection and send a well-formed HTTP POST with a JSON body deserializable as `StackerDBChunksEvent`. Attacker cost is minimal (single HTTP request), and it is fully repeatable.

### Recommendation
Add an authentication gate to `SignerEventReceiver`/`next_event` that verifies the caller is the local, trusted stacks-node event dispatcher before processing any body — e.g., a shared bearer secret/HMAC configured out-of-band and checked in `process_event`, and/or bind the listener to a Unix domain socket or loopback-only address enforced in code (not just operator configuration). Additionally, for the `.miners` branch of `TryFrom<StackerDBChunksEvent>`, require and check `chunk.recover_pk()`/`chunk.verify()` against the actual known miner key for defense in depth, matching the `SIGNERS_NAME` branch's existing (partial) check.

### Proof of Concept
Rust integration test in `libsigner`:
1. Construct a `SignerEventReceiver::<SignerMessage>::new(false)`, call `bind("127.0.0.1:0")`, spawn `main_loop` in a thread, and `add_consumer` with an `mpsc::channel`.
2. From the test (acting as "attacker"), open a raw `TcpStream::connect` to the bound address.
3. Build a JSON body for `StackerDBChunksEvent { contract_id: boot_code_id("miners", false), modified_slots: vec![StackerDBChunkData::new(0, 1, consensus_serialize(some SignerMessage))] }` (no valid signature required for the `.miners` branch since `recover_pk` is never called for it) and send:
   `POST /stackerdb_chunks HTTP/1.1\r\nHost: ...\r\nContent-Length: N\r\nContent-Type: application/json\r\n\r\n<json>`
4. Assert the consumer channel receives `SignerEvent::MinerMessages(vec![msg])` matching the attacker-supplied message, proving unauthenticated injection into the signer's event stream with no verification that the HTTP caller was the local stacks-node. [7](#0-6) [8](#0-7)

    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }

    fn forward_event(&mut self, ev: SignerEvent<T>) -> bool {
        if self.out_channels.is_empty() {
            // nothing to do
            error!("No channels connected to event receiver");
            false
        } else if self.out_channels.len() == 1 {
            // avoid a clone
            if let Err(e) = self.out_channels[0].send(ev) {
                error!("Failed to send to signer runloop: {:?}", &e);
                return false;
            }
            true
        } else {
            for (i, out_channel) in self.out_channels.iter().enumerate() {
                if let Err(e) = out_channel.send(ev.clone()) {
                    error!("Failed to send to signer runloop #{}: {:?}", i, &e);
                    return false;
                }
            }
            true
        }
    }

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
