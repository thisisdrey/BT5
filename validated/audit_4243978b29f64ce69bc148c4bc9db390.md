This confirms the finding: `action_add_key` at `runtime/runtime/src/access_keys.rs:230-241` **ignores** the `nonce` field passed in the `AddKeyAction` entirely — it explicitly overwrites it with `initial_nonce_value(block_height)` regardless of what value a contract sends via `promise_batch_action_add_key_with_full_access`/`_with_function_call`. The nonce carried through `Memory::set` → `append_action_add_key_with_full_access`/`append_action_add_key_with_function_call` (in `runtime/near-vm-runner/src/logic/logic.rs:3452-3469`, `3492-3538`, and `runtime/runtime/src/receipt_manager.rs:566-606`) is discarded on execution for regular keys, and forced to `0` for gas keys (`add_gas_key`, `access_keys.rs:206`). Nonce monotonicity for *existing* keys is separately enforced at transaction-verification time by `verify_nonce` in `runtime/runtime/src/verifier.rs:210-237`, which compares `tx_nonce` against the persisted `AccessKey::nonce` (`Monotonic`/`Strict` modes) and is never bypassed by an `AddKey` action.

Given this, the attacker's premise doesn't hold: writing arbitrary nonce bytes into an `AddKeyAction` via guest memory has no effect on the eventual on-chain nonce because the runtime overwrites/forces it deterministically based on block height, and subsequent nonce checks operate on this authoritative on-chain value, not anything attacker-controlled. There is no code path where `Memory::set`'s lack of "semantic validation" translates into a replay-capable nonce reuse — the semantic validation exists precisely in `add_regular_key`/`add_gas_key` (overwrite) and `verify_nonce` (comparison against stored state), both of which are unconditionally applied and unrelated to raw guest-memory contents. /// Verify that the transaction nonce is valid.
fn verify_nonce(
    tx_nonce: Nonce,
    current_nonce: Nonce,
    block_height: Option<BlockHeight>,
    nonce_mode: NonceMode,
) -> Result<(), InvalidTxError> {
    match nonce_mode {
        NonceMode::Monotonic => {
            if tx_nonce <= current_nonce {
                return Err(InvalidTxError::InvalidNonce { tx_nonce, ak_nonce: current_nonce });
            }
        }
        NonceMode::Strict => {
            if !current_nonce.checked_add(1).is_some_and(|expected| tx_nonce == expected) {
                return Err(InvalidTxError::InvalidNonce { tx_nonce, ak_nonce: current_nonce });
            }
        }
    }
    if let Some(height) = block_height {
        let upper_bound = height
            .saturating_mul(near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER);
        if tx_nonce >= upper_bound {
            return Err(InvalidTxError::NonceTooLarge { tx_nonce, upper_bound });
        }
    }
    Ok(())
}
