### Title
Unvalidated attacker-supplied attachment content is unconditionally persisted to AtlasDB regardless of the requested `content_hash` - (File: `stackslib/src/net/atlas/download.rs`)

### Summary
In `AttachmentsDownloader::run`, when the `AttachmentsBatchStateMachine` reaches `Done`, every attachment collected in `context.attachments` is inserted into `AtlasDB` via `insert_instantiated_attachment` unconditionally, before checking whether it corresponds to any tracked `AttachmentInstance`. Because the lookup key used (`attachment.hash()`) is derived from the attacker-served bytes themselves rather than being checked against the `content_hash` that was actually requested from the peer, a malicious peer can respond to an `AttachmentRequest` with arbitrary content that gets stored in AtlasDB even though it matches no on-chain-confirmed `AttachmentInstance`.

### Finding Description
The download pipeline works as follows:
- `AttachmentsBatchStateContext::get_prioritized_attachments_requests` builds `AttachmentRequest`s keyed by a specific `content_hash` taken from `attachments_batch.attachments_instances` (instances that were tracked from real, on-chain name operations) [1](#0-0) .
- `AttachmentsBatchStateContext::extend_with_attachments` receives the HTTP response for that request and inserts `response.attachment` into `context.attachments` (a `HashSet<Attachment>`) with **no comparison** between the decoded `response.attachment.hash()` and the `request.content_hash` that was actually asked for [2](#0-1) .
- When the state machine transitions to `Done`, `AttachmentsDownloader::run` drains `context.attachments` and, for each attachment, looks up matching instances by `attachment.hash()` (the hash of the attacker-served bytes, not the originally-requested `content_hash`), then calls `network.atlasdb.insert_instantiated_attachment(&attachment)` **unconditionally**, regardless of whether `attachments_instances` (the lookup result) is empty [3](#0-2) .

The broken equality is: the code assumes `attachment.hash() == content_hash` of some tracked `AttachmentInstance` that triggered the request, but this is never enforced. A malicious peer that is legitimately selected as an outbound sync source (`network.get_outbound_sync_peers()` / `context.peers`, no special privilege required) and whose inventory response claims to have the attachment can, when the actual `AttachmentRequest` for content hash `X` arrives, return arbitrary bytes `Y` instead of the real content. `decode_atlas_get_attachment` only parses the HTTP body into an `Attachment`; it performs no hash-equality check against the request's `content_hash`. The client then computes `hash(Y)` and stores `Y` under that self-derived hash in AtlasDB via `insert_instantiated_attachment`, even though no `AttachmentInstance` (i.e., no committed name operation) ever referenced `hash(Y)`. `context.attachments_batch.resolve_attachment(&attachment.hash())` also uses this wrong key, so it's a no-op against the real, still-unresolved entry for `X` — meaning the legitimate instance for `X` is never resolved by this malicious peer's answer (it will eventually be retried/dropped), while the bogus content for `Y` is stored regardless.

### Impact Explanation
Any malicious peer selected as an outbound Atlas sync source can, for each attachment request it is asked to serve, respond with arbitrary content instead of the requested data. That content is persisted to the node's AtlasDB (`insert_instantiated_attachment`) even though it is tied to zero committed name operations, matching the "attachment/BNS mismatch" High-severity category: the node ends up storing/serving attachment blobs that no canonical on-chain commitment ever referenced. This is repeatable per legitimate attachment request the victim node issues (bounded by the number of real `AttachmentInstance`s the node is trying to resolve and its `max_attachment_retry_count`), enabling low-cost pollution of AtlasDB with junk data attributable to a peer under attacker control.

### Likelihood Explanation
Preconditions are modest and within the unprivileged-attacker model: the attacker must run a peer that the victim selects as an outbound sync peer (`network.get_outbound_sync_peers()`), advertise (via a legitimate-looking `GetAttachmentsInvResponse`) that it holds the attachment for a real, in-flight `AttachmentInstance`'s `content_hash`, and then respond to the resulting `AttachmentRequest` with arbitrary bytes instead of the correct content. No secret, admin role, or privileged slot ownership is required — only normal P2P connectivity and participation as a data-serving peer, which is explicitly in-scope. The attack is repeatable across every attachment request the attacker's peer is chosen to serve.

### Recommendation
In `AttachmentsBatchStateContext::extend_with_attachments`, verify `response.attachment.hash() == request.content_hash` before adding the attachment to `context.attachments`; reject and penalize (bump failed requests / mark faulty) responses that don't match. Additionally, in `AttachmentsDownloader::run`, only call `network.atlasdb.insert_instantiated_attachment(&attachment)` when `find_all_attachment_instances(&attachment.hash())` returns a non-empty result (i.e., only persist content that is actually referenced by a tracked, on-chain-confirmed `AttachmentInstance`).

### Proof of Concept
1. Construct an `AttachmentsBatchStateContext` with one tracked `AttachmentInstance` whose `content_hash = X` (simulating a real on-chain name-operation reference).
2. Simulate `BatchedRequestsState::Done` for the `DownloadingAttachment` state with `results.succeeded` containing an `AttachmentRequest{ content_hash: X, .. }` paired with a decoded response whose `Attachment` has `content = b"attacker-garbage"` (so `hash(content) = Y != X`).
3. Call `AttachmentsBatchStateContext::extend_with_attachments` (or, at a higher level, drive `AttachmentsDownloader::run` through to `Done`) and assert:
   - `context.attachments` now contains the attachment with hash `Y`.
   - After `run` completes, `network.atlasdb.find_attachment(&Y)` (or equivalent AtlasDB read for hash `Y`) returns `Some(attacker-garbage)`.
   - `network.atlasdb.find_all_attachment_instances(&X)` still has no resolved attachment (the real instance for `X` was never satisfied), proving stored content `Y` is orphaned — persisted with no corresponding on-chain-confirmed `AttachmentInstance`.

    pub fn get_prioritized_attachments_requests(&self) -> BinaryHeap<AttachmentRequest> {
        let mut queue = BinaryHeap::new();
        let mut enqueued = HashSet::new();
        for ((contract_id, pages, _), peers_responses) in self.inventories.iter() {
            let missing_attachments = match self
                .attachments_batch
                .attachments_instances
                .get(contract_id)
            {
                None => continue,
                Some(missing_attachments) => missing_attachments,
            };
            // Note: we're getting missing_attachments (attachment_id: content_hash)
            for (attachment_index, content_hash) in missing_attachments.iter() {
                let page_index = attachment_index / AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;
                // Since there's a limit in the number of pages that a node can request,
                // we can potentially have multiple inventory request at once.
                if !pages.contains(&page_index) {
                    continue;
                }

                if enqueued.contains(content_hash) {
                    debug!("Atlas: {} already enqueued", content_hash);
                    continue;
                }

                let mut sources = HashMap::new();
                let position_in_page =
                    attachment_index % AttachmentInstance::ATTACHMENTS_INV_PAGE_SIZE;

                for (peer_url, response) in peers_responses.iter() {
                    // Considering the response, look for the page with the index
                    // we're looking for.
                    let search_page = response.pages.iter().find(|page| page.index == page_index);

                    let has_attachment = search_page
                        .and_then(|search_page| {
                            search_page.inventory.get(position_in_page as usize)
                        })
                        .map(|result| *result == 1)
                        .unwrap_or(false);

                    if !has_attachment {
                        debug!(
                            "Atlas: peer does not have attachment ({}, {}) in its inventory {:?}",
                            page_index, position_in_page, response.pages
                        );
                        continue;
                    }

                    let report = self
                        .peers
                        .get(peer_url)
                        .expect("Atlas: unable to retrieve reliability report for peer");
                    sources.insert(peer_url.clone(), report.clone());
                }

                if sources.is_empty() {
                    warn!("Atlas: could not find a peer including attachment in its inventory");
                    continue;
                }

                // Success, we found at least one inventory including the attachment we're looking for.
                let request = AttachmentRequest {
                    sources,
                    content_hash: content_hash.clone(),
                    stacks_block_height: self.attachments_batch.stacks_block_height,
                    canonical_stacks_tip_height: self.attachments_batch.canonical_stacks_tip_height,
                };
                enqueued.insert(content_hash);
                queue.push(request);

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }
