### Title
Unauthenticated `recv_error` forgery allows remote attackers to force-close tunnels without holding a valid certificate - (File: outside.go)

### Summary
The Morpho Blue report flags a class of bug where a security-relevant state transition (market creation) proceeds without verifying that the transition hasn't already been claimed/observed by someone else, letting an attacker who can predict/observe the relevant parameters race ahead and manipulate state to the victim's detriment. The reachable analog in nebula is `Interface.handleRecvError` in `outside.go`, which tears down an existing, fully-authenticated tunnel on receipt of a bare, unauthenticated `header.RecvError` control message, relying only on a UDP source-address comparison rather than any cryptographic proof of authorization.

### Finding Description
`RecvError` packets are handled before any certificate/AEAD verification occurs. In `readOutsidePackets`, the type switch dispatches `header.RecvError` straight to `f.handleRecvError(via.UdpAddr, h)` prior to any hostinfo/connection-state lookup or decryption: [1](#0-0) 

`handleRecvError` then locates the target tunnel purely from the attacker-supplied `h.RemoteIndex` (a 32-bit value carried in cleartext in every header, including the initial handshake and every subsequent data packet) and only guards against forgery by comparing the packet's *source UDP address* to the hostinfo's last known remote: [2](#0-1) 

Both values needed to forge this message — the `RemoteIndex` and the victim's current UDP `remote` — are visible to any on-path observer (they are sent unencrypted in the header) or can often be inferred/guessed by an off-path attacker (lighthouse queries reveal a node's advertised UDP endpoint; UDP source addresses are trivially spoofable and are not cryptographically bound to the sender). No CA-signed certificate, valid Noise handshake, or possession of the AEAD keys is required to send this control message — this mirrors the missing "already exists / already claimed" check in the Morpho report: the tunnel's teardown-eligibility is decided from unauthenticated, externally-observable/guessable parameters instead of a proof tied to the legitimate participants.

Once `handleRecvError` accepts the forged packet, it unconditionally calls: [3](#0-2) 
which deletes the hostinfo from both the main hostmap and the pending handshake manager, immediately destroying the live, authenticated tunnel.

### Impact Explanation
An attacker with no valid certificate can force repeated teardown of legitimate tunnels between two Nebula nodes purely by replaying/spoofing an unauthenticated `RecvError` header with a matching `RemoteIndex` and spoofed source address matching the target's known remote endpoint. This is a remote denial-of-service against the overlay network: sustained forged `RecvError` traffic can prevent stable tunnels from ever completing (a "whack-a-mole" of forced rehandshakes), degrading or denying connectivity between victims. This matches the report's "Medium/Medium" DoS classification — no traffic decryption or forgery of application data occurs, but availability of the tunnel is directly and remotely compromised without authentication.

### Likelihood Explanation
Likelihood is Medium: exploitation does not require compromising cryptographic material, only observing or guessing two values (`RemoteIndex` and the current remote `UdpAddr`) that are inherently sent in cleartext over the wire on every packet. An on-path attacker (e.g., shared network segment, ISP-level observer) trivially obtains both; an off-path attacker must guess a 32-bit index and spoof a UDP source address, which is feasible over sustained UDP flooding since there is no rate limiting tied to authentication for this message type. The codebase does provide a configuration knob (`accept_recv_error`/`send_recv_error` via `acceptRecvErrorConfig.ShouldRecvError`) that can restrict acceptance by peer address, indicating the maintainers are aware this path is sensitive, but by default (or when broadly configured) it remains reachable by unauthenticated actors.

### Recommendation
Do not act on `RecvError` (or similarly-privileged control messages) using cleartext, unauthenticated data alone. Options:
1. Require `RecvError` messages to be authenticated (e.g., signed/MACed with the tunnel's existing AEAD key) before honoring them, similar to how `CloseTunnel` is processed only after decryption succeeds inside an authenticated session.
2. At minimum, tighten the existing address check to require a stronger correlation than a single spoofable comparison, and consider rate-limiting/backoff before actually tearing down a tunnel on a single unauthenticated signal, e.g., requiring several corroborating recv_error observations or falling back to letting the normal replay/handshake-timeout logic reclaim stale tunnels instead of an immediate unauthenticated teardown.

### Proof of Concept
1. Establish a normal tunnel between node A and node B; observe (via passive sniffing on a shared segment, or by querying the lighthouse for B's advertised UDP endpoint) B's `UdpAddr` and any header's `RemoteIndex` value for the A→B direction (visible in cleartext in every packet header per `header.H`, see [4](#0-3) ).
2. Craft a raw UDP packet using `header.Encode(..., header.RecvError, 0, capturedRemoteIndex, 0)` with a spoofed source address equal to B's known `UdpAddr`, and send it to A.
3. A's `readOutsidePackets` routes it directly to `handleRecvError` without any decryption or cert check; since the spoofed source matches the hostinfo's recorded remote, the `hr != addr` check passes and `f.closeTunnel(hostinfo)` executes, killing the legitimate tunnel — repeatable indefinitely to deny service.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
```
