Audit Report

## Title
`ProxyType::NonTransfer` in Asset Hub runtimes does not block `PolkadotXcm` calls, letting a "non-transfer" proxy move the delegator's funds - ([File: cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs])

## Summary
`ProxyType::NonTransfer::filter` in `asset-hub-westend` (and sibling Asset Hub / parachain runtimes) is implemented as a blocklist that returns `true` (call allowed) for every `RuntimeCall` variant not explicitly listed, and `RuntimeCall::PolkadotXcm(..)` is absent from that list. Since `pallet_xcm` dispatchables such as `transfer_assets`, `limited_teleport_assets`, and `limited_reserve_transfer_assets` move the caller's own `Balances`/`Assets`/NFT holdings off-chain, a delegate holding only a `NonTransfer` proxy can use `Proxy::proxy` to invoke these calls under the delegator's origin and move the delegator's funds to an attacker-controlled destination.

## Finding Description
The filter implementation confirmed in the current repository state is: [1](#0-0) 

This is a blocklist (`!matches!(...)`): the call is permitted for a `NonTransfer` proxy unless it matches one of the enumerated variants (`Balances`, `Assets`, `NftFractionalization`, `Nfts`, `Uniques`, `Scheduler`, `Treasury`, `Vesting::vested_transfer`, `ConvictionVoting`, `Referenda`, `Whitelist`). `RuntimeCall::PolkadotXcm(..)` is not in this list, so it is treated as a non-transfer-safe call by default.

By contrast, the relay-chain runtimes implement `NonTransfer` as an allowlist (`matches!(...)`) and explicitly document that the entire XCM Pallet is intentionally omitted from the allowed set, showing the design intent that XCM calls must not be reachable from a `NonTransfer` proxy: [2](#0-1) 

`pallet_proxy`'s public `proxy`/`proxy_announced` extrinsics dispatch the wrapped call using the real (delegator's) origin once `ProxyType::filter` returns `true`; there is no independent global call filter in the asset-hub-westend runtime file that separately excludes `PolkadotXcm` calls from proxy dispatch. Since `pallet_xcm`'s asset-moving extrinsics execute using the dispatch origin's own account for withdrawal (not requiring any transfer-type proxy), the missing filter entry directly breaks the "non-transfer" invariant that governance/voting-only proxy delegations are supposed to provide.

## Impact Explanation
This allows a delegate holding a `NonTransfer` proxy — a delegation type intended to preclude any asset movement — to invoke `PolkadotXcm::transfer_assets`, `limited_teleport_assets`, `limited_reserve_transfer_assets`, or `execute` via `Proxy::proxy`, moving the delegator's `Balances`/`Assets`/NFT holdings to any destination the delegate chooses. This is unauthorized execution / origin-scope escalation through a public wrapper (`pallet-proxy`) that results in theft of the proxied account's funds, matching the "unauthorized execution or origin escalation" / "theft ... or unlock" impact classes in the Polkadot SDK impact gate.

## Likelihood Explanation
No privileged access is required beyond a routine, expected configuration: any account owner who grants a `NonTransfer` proxy to another account (e.g., for governance/voting delegation) is exposed. The attacker is simply the proxy delegate calling the public `Proxy::proxy` extrinsic with a `PolkadotXcm` call — no additional preconditions, compromised keys, or privileged roles are needed, making this fully reachable by an unprivileged external actor once a `NonTransfer` delegation exists.

## Recommendation
Add `RuntimeCall::PolkadotXcm(..)` (and any other pallet capable of moving the caller's assets, e.g., `AssetConversion` swaps chained with XCM) to the `NonTransfer` exclusion list in `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs`, `asset-hub-rococo/src/lib.rs`, and other Asset Hub / parachain runtimes using the blocklist-style filter. Alternatively, convert these runtimes' `NonTransfer` filter to the relay chain's allowlist style so pallets are excluded by default rather than included by default.

## Proof of Concept
1. Account `A` calls `Proxy::add_proxy(B, ProxyType::NonTransfer, delay)` on Asset Hub Westend, granting `B` a non-transfer proxy.
2. `B` submits `Proxy::proxy(RuntimeOrigin::signed(B), A, Some(ProxyType::NonTransfer), Box::new(RuntimeCall::PolkadotXcm(pallet_xcm::Call::limited_teleport_assets { dest, beneficiary: B, assets: A's full balance, fee_asset_item: 0, weight_limit: Unlimited })))`.
3. `ProxyType::NonTransfer::filter` evaluates `!matches!(c, Balances{..} | Assets{..} | ... )`; since `RuntimeCall::PolkadotXcm(..)` matches none of the listed patterns, the filter returns `true`.
4. The call dispatches with `A`'s origin, teleporting `A`'s assets under `B`'s chosen beneficiary, despite `B` never being granted transfer rights — demonstrating the broken invariant.
