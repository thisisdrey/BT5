### Title
Unauthenticated `RecvError` packet lets a spoofing attacker tear down another peer's established tunnel - (File: `outside.go`)

### Summary
`ArbitrumDepositProcessorL1` granted the `cancel()` permission to an address the attacker fully controls, letting them destroy an already-committed cross-chain message. Nebula's analog is the `RecvError` packet path: it is accepted and acted upon (`f.closeTunnel(hostinfo)`) purely on the basis of a cleartext, unauthenticated header field plus a UDP source-address match — no cryptographic proof that the sender possesses the tunnel's Noise keys is required, so anyone who can observe or spoof the right values can tear down a legitimately-established tunnel between two other, honest peers.

### Finding Description
`RecvError` is dispatched before any decryption or certificate check, directly from `readOutsidePackets`: [1](#0-0) 

`handleRecvError` then looks the tunnel up purely by the cleartext `RemoteIndex` field and closes it if the packet's source address happens to match the hostinfo's currently known remote: [2](#0-1) 

The only "authentication" performed is `hr.IsValid() && hr != addr` — a comparison against the UDP source `netip.AddrPort` of the incoming packet, not a cryptographic signature or MAC. `RemoteIndex` and `MessageCounter` are transmitted unauthenticated in every packet's plaintext header: [3](#0-2) 

Because `RemoteIndex` is visible in the clear on every packet exchanged between the victim and its peer (handshake and data packets alike), any attacker positioned to observe traffic (or otherwise learn/guess the 32-bit index) and able to spoof a UDP packet with the victim's peer's source `ip:port` can forge a `RecvError` packet that causes `closeTunnel` to run on the receiving node, exactly mirroring the "attacker holds a role-confused cancellation permission over already-finalized state" pattern from the source report: a party that never proved cryptographic possession of the session is nonetheless given the authority to invalidate it.

This is the same root cause pattern as the Arbitrum bug: an address-only (not identity/authorization) check is used to grant destructive control over state that was already legitimately established between two other parties.

### Impact Explanation
An attacker can force repeated, unauthenticated teardown of live tunnels between arbitrary pairs of legitimate nebula nodes, forcing wasted re-handshakes, connection churn, and denial-of-service against the mesh, without ever presenting a valid certificate or completing a handshake. This is comparable in severity to the referenced finding: it does not need to break the crypto handshake itself, but it lets an outsider grief already-established, "claimed"/completed state (an active tunnel) into an unusable state, needing the victims to re-handshake instead of governance intervention — a lower-friction, self-service DoS/griefing primitive reachable by anyone who can spoof UDP source addressing and observe or guess the target's index and current remote endpoint.

### Likelihood Explanation
The `RecvError` path is enabled by default (`send_recv_error`/`accept_recv_error` default to `always`), as the project's own CHANGELOG entries for `#670` and `#1569` acknowledge — this feature has historically been treated as a security-sensitive knob because it "can expose the fact that Nebula is running" and now also because it can be triggered by network-layer spoofing. Any attacker with the ability to spoof UDP source IP:port (common on networks lacking egress/ingress filtering, or an on-path attacker) and knowledge of the 32-bit `RemoteIndex` (learnable by passively observing the victim's traffic, since it's carried unauthenticated in every packet) can trigger this without any CA-issued certificate.

### Recommendation
Do not act on `RecvError` (or any tunnel-teardown-triggering packet) based solely on source-address matching. Require it to be authenticated the same way data-plane traffic is (e.g., only accept it once decrypted/verified inside an already-authenticated channel, or require a signed/keyed proof tied to the current session), or at minimum rate-limit and treat `RecvError`-triggered teardown as advisory rather than authoritative, requiring corroboration (e.g. dead-tunnel/keepalive failure) before calling `closeTunnel`.

### Proof of Concept
1. Attacker passively observes UDP traffic between victim `A` and peer `B` (or otherwise learns `A`'s `localIndexId`/`RemoteIndex` used with `B`), and knows `B`'s current UDP `ip:port` as seen by `A` (`hostinfo.GetRemote()`).
2. Attacker crafts a `RecvError` packet: `header.Encode(buf, header.Version, header.RecvError, 0, remoteIndexOfAtB, 0)` and sends it to `A`, spoofing the UDP source address to equal `B`'s current remote endpoint.
3. `A.handleRecvError` (`outside.go:541`) finds the hostinfo via `QueryReverseIndex`, sees `addr == hr`, and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, tearing down the legitimate tunnel between `A` and `B` without either party's cryptographic involvement.
4. Repeat at will against any tunnel whose index/remote can be observed, causing persistent griefing/DoS.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}

type H struct {
	Version        uint8
	Type           MessageType
	Subtype        MessageSubType
	Reserved       uint16
	RemoteIndex    uint32
	MessageCounter uint64
}

// Encode uses the provided byte array to encode the provided header values into.
// Byte array must be capped higher than HeaderLen or this will panic
func Encode(b []byte, v uint8, t MessageType, st MessageSubType, ri uint32, c uint64) []byte {
	b = b[:Len]
	b[0] = v<<4 | byte(t&0x0f)
	b[1] = byte(st)
	binary.BigEndian.PutUint16(b[2:4], 0)
	binary.BigEndian.PutUint32(b[4:8], ri)
	binary.BigEndian.PutUint64(b[8:16], c)
	return b
}

// String creates a readable string representation of a header
func (h *H) String() string {
	if h == nil {
		return "<nil>"
	}
	return fmt.Sprintf("ver=%d type=%s subtype=%s reserved=%#x remoteindex=%v messagecounter=%v",
		h.Version, h.TypeName(), h.SubTypeName(), h.Reserved, h.RemoteIndex, h.MessageCounter)
}

// MarshalJSON creates a json string representation of a header
func (h *H) MarshalJSON() ([]byte, error) {
	return json.Marshal(m{
		"version":        h.Version,
		"type":           h.TypeName(),
		"subType":        h.SubTypeName(),
		"reserved":       h.Reserved,
		"remoteIndex":    h.RemoteIndex,
		"messageCounter": h.MessageCounter,
	})
}

// Encode turns header into bytes
func (h *H) Encode(b []byte) ([]byte, error) {
	if h == nil {
		return nil, errors.New("nil header")
	}

	return Encode(b, h.Version, h.Type, h.Subtype, h.RemoteIndex, h.MessageCounter), nil
}

// Parse is a helper function to parses given bytes into new Header struct
func (h *H) Parse(b []byte) error {
	if len(b) < Len {
		return ErrHeaderTooShort
	}
	// get upper 4 bytes
	h.Version = uint8((b[0] >> 4) & 0x0f)
	// get lower 4 bytes
	h.Type = MessageType(b[0] & 0x0f)
	h.Subtype = MessageSubType(b[1])
	h.Reserved = binary.BigEndian.Uint16(b[2:4])
	h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])
	h.MessageCounter = binary.BigEndian.Uint64(b[8:16])
	return nil
}
