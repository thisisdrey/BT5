Audit Report

## Title
Reward payout marks era/page as claimed before the transfer succeeds, permanently losing staker rewards on transfer failure - (File: substrate/frame/staking-async/src/pallet/impls.rs)

## Summary
`do_payout_stakers_by_page` calls `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` before performing the actual reward transfer via `payout_from_provider` → `make_payout_from_provider`. If the underlying `T::Currency::transfer` fails, `make_payout_from_provider` catches the error, logs it, and returns `None` rather than propagating a `DispatchError`, so the extrinsic still returns `Ok`. Because no error is raised, FRAME's transactional dispatch does not roll back the earlier `set_rewards_as_claimed` write, permanently marking that era/page reward as paid even though the transfer never happened.

## Finding Description
`do_payout_stakers_by_page` checks `Eras::<T>::is_rewards_claimed` and then immediately commits `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` at [1](#0-0) , with the comment "Input data seems good, no errors allowed after this point" confirming this is treated as an irrevocable checkpoint.

When `use_dap_payout` is active, `payout_from_provider` is invoked, which calls `make_payout_from_provider` for the validator and each nominator: [2](#0-1) . Inside `make_payout_from_provider`, if `T::Currency::transfer(&staker_rewards_pot, &payout_account, amount, Preservation::Expendable)` fails, the error is only logged and `None` is returned, without propagating a `DispatchError`: [3](#0-2) . The caller `payout_from_provider` simply skips emitting a `Rewarded` event for that beneficiary and continues, and `do_payout_stakers_by_page` still returns `Ok(...)` at the end of the function.

Because the dispatchable returns `Ok`, none of the storage writes made earlier — including `set_rewards_as_claimed` — are rolled back. The validator's own incentive payout path (`transfer_validator_incentive`) exhibits the identical swallow-and-log pattern on transfer failure, confirmed in the codebase.

## Impact Explanation
Once `Eras::<T>::set_rewards_as_claimed` is set for `(era, stash, page)`, subsequent calls to `payout_stakers`/`do_payout_stakers_by_page` for that page are rejected via the `AlreadyClaimed` check at [4](#0-3) . If any individual transfer to a nominator or validator fails for a legitimate on-chain reason (e.g. `Preservation::Expendable` failing below existential deposit, or a hold/freeze conflict on the destination), that specific staker's reward for that era/page is permanently and irrecoverably lost, since the claimed flag can never be cleared. This matches the "permanent user-fund lock" impact category via duplicate/skipped settlement bookkeeping — the exact corrupted value being the `ClaimedRewards`/`is_rewards_claimed` marker for `(era, stash, page)`, which is set to "claimed" without the corresponding transfer having settled.

## Likelihood Explanation
`payout_stakers` / `do_payout_stakers_by_page` is a permissionless, unprivileged dispatchable callable by any signed account for any validator/era/page — no malicious peer, governance action, or leaked key is required. The failure condition (a reward transfer to a specific beneficiary account failing due to ED/hold/freeze interactions under `Preservation::Expendable`) is a realistic on-chain condition that the code itself explicitly anticipates and handles defensively (via `log!(error, ...)`), rather than a contrived edge case.

## Recommendation
Move `Eras::<T>::set_rewards_as_claimed(era, &stash, page)` to occur only after all payout transfers for that page have been attempted and confirmed successful, or have `make_payout_from_provider`/`transfer_validator_incentive` propagate transfer failures as a hard `Err` from `do_payout_stakers_by_page`, causing the whole extrinsic — including the "claimed" marker — to roll back atomically. Alternatively, introduce a per-beneficiary retry/pending-payout mechanism instead of unconditionally marking the entire page as claimed regardless of individual transfer outcomes.

## Proof of Concept
1. Configure a nominator's `RewardDestination::Account(x)` such that a `Preservation::Expendable` transfer of the exact reward amount from `staker_rewards_pot` to account `x` fails (e.g., account `x` holds a `Hold`/`Freeze` interacting with the transfer, or the pot lacks the exact liquidity for that beneficiary due to rounding across many beneficiaries).
2. Call `payout_stakers(era, validator_stash, page)` (or the paged variant) as any signed account.
3. Observe that `set_rewards_as_claimed(era, &stash, page)` is committed at line 386 before any transfer is attempted; the transfer for the affected nominator fails inside `make_payout_from_provider`, is logged, and `None` is returned — no `Rewarded` event is emitted for that beneficiary, and no error is propagated.
4. The extrinsic completes with `Ok(...)`; the nominator's era/page reward is now permanently marked as claimed with no retry path, and the funds were never delivered — a silent, unrecoverable loss for that nominator.
