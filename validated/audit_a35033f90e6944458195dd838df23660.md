### Title
Unbounded temp-file write of attacker-controlled blob in `RawBlame`'s `createTemporaryIgnoreRevsFile` causes disk exhaustion DoS - (File: internal/gitaly/service/commit/raw_blame.go)

### Summary
`RawBlame` resolves the client-supplied `IgnoreRevisionsBlob` revision via `catfile` and copies the entire blob object to a temporary file with no size limit and no use of Gitaly's storage-scoped temp-directory mechanism. An unprivileged user who owns/controls a repository can commit an arbitrarily large blob and repeatedly reference it in `RawBlame` requests to force the Gitaly node to write large amounts of data to the shared OS temp directory, exhausting local disk space.

### Finding Description
In `createTemporaryIgnoreRevsFile`, the server resolves `in.GetIgnoreRevisionsBlob()` to a git object via `objectReader.Object(ctx, git.Revision(revision))` [1](#0-0) , verifies it `IsBlob()` [2](#0-1) , then creates a temp file with `os.CreateTemp("", "ignore-revs-file-*")` and copies the full blob into it with `blobObj.WriteTo(tmpFile)` [3](#0-2) .

There is no size check on the blob before or during the copy — unlike other blob-serving RPCs in the codebase (e.g. `ListBlobs`/`GetBlobs`) which enforce an explicit `bytesLimit`/`readLimit` via `io.CopyN` [4](#0-3)  and `sendBlobTreeEntry` [5](#0-4) , or `GetLFSPointers` which filters by `lfsPointerMaxSize` [6](#0-5) . Additionally, `os.CreateTemp("", ...)` places the file in the process default OS temp directory rather than using Gitaly's storage-scoped `tempdir.New` helper (used elsewhere, e.g. `internal/git/localrepo/bundle.go`'s `createTempBundle` [7](#0-6) ), which ties temporary storage to a specific storage location. This means the write bypasses any storage/quota accounting tied to the repository's storage and lands on a filesystem that may be shared across all repositories/tenants on the Gitaly node.

An attacker who owns a repository can push or commit a blob of significant size (bounded only by whatever push/commit size limits GitLab Rails enforces, which can still be gigabytes), then issue `RawBlame` requests with `IgnoreRevisionsBlob` set to that blob's OID. Each such request causes Gitaly to fully materialize the blob to local disk in `/tmp` (or equivalent), and this can be repeated to exhaust disk space on the node, affecting availability for all users of that storage/node.

### Impact Explanation
This is a resource-exhaustion / denial-of-service vector on a Gitaly node: repeated `RawBlame` calls referencing a large blob write large amounts of data to local disk outside of repository-scoped storage tracking, potentially exhausting the OS temp partition and impacting other repositories/tenants hosted on the same node. This maps to GitLab's "Denial of Service" bounty impact class for Gitaly RPC handlers.

### Likelihood Explanation
The attacker only needs standard, unprivileged repository push/commit access to their own repository (to create the oversized blob) and the ability to call `RawBlame` (a standard read RPC) referencing that blob as `IgnoreRevisionsBlob`. No special role, config, or secret is required, and the request can be repeated to amplify the effect, making this straightforward and reproducible for any authenticated user with a repository.

### Recommendation
Enforce a maximum size limit on the ignore-revs blob before copying (check `blobObj` size/`ObjectInfo` against a small configurable cap, e.g. via `ObjectInfoReader` before invoking `ObjectReader`, similar to `lfsPointerMaxSize`), reject oversized blobs with `InvalidArgument`, and use `io.CopyN` with that bound instead of unlimited `WriteTo`. Additionally, use the storage-scoped `tempdir.New` (as done in `bundle.go`) instead of raw `os.CreateTemp("", ...)` so temp usage is accounted for within the repository's storage rather than a globally shared OS temp directory.

### Proof of Concept
```go
// Go test sketch, place in internal/gitaly/service/commit package test file.
func TestRawBlame_OversizedIgnoreRevsBlob_DoS(t *testing.T) {
    ctx := testhelper.Context(t)
    cfg, client := setup(t, ctx)
    repo, repoPath := gittest.CreateRepository(t, ctx, cfg)

    // Simulate attacker committing a large blob (e.g. 2GB of data).
    largeBlobOID := gittest.WriteBlob(t, cfg, repoPath, bytes.Repeat([]byte{'a'}, 2<<30))

    commitID := gittest.WriteCommit(t, cfg, repoPath,
        gittest.WithTreeEntries(gittest.TreeEntry{Path: "file.txt", Mode: "100644", Content: "line1\n"}),
        gittest.WithBranch("master"),
    )

    stream, err := client.RawBlame(ctx, &gitalypb.RawBlameRequest{
        Repository:          repo,
        Revision:             []byte(commitID),
        Path:                 []byte("file.txt"),
        IgnoreRevisionsBlob:  []byte(largeBlobOID),
    })
    require.NoError(t, err)

    // Observe that Gitaly writes the full 2GB blob to a temp file (visible via
    // disk usage of /tmp during the RPC) before git-blame even runs. Repeating
    // this call concurrently amplifies disk consumption.
    for {
        _, err := stream.Recv()
        if err != nil {
            break
        }
    }
}
```
Monitoring `/tmp` disk usage during this test (or `lsof`/`du` on the Gitaly host) shows a multi-gigabyte temporary file created per request with no size cap, confirming the unbounded write.
