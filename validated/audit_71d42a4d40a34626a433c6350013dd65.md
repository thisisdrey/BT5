### Title
Unvalidated interest-rate fee parameters can `assert!`-panic `calc_interest_rate`, permanently DoS-ing a bank's interest accrual - ([File: programs/marginfi/src/state/interest_rate.rs])

### Summary
The `updatePerformanceFee()`/`lendingAPR()` bug class (admin-settable fee parameter with no upper/sign bound causing an unconditional revert in a core rate-calculation function) is reproducible in marginfi-v2. `InterestRateConfig::validate_seven_point()` never validates the fee fields (`insurance_fee_fixed_apr`, `insurance_ir_fee`, `protocol_fixed_fee_apr`, `protocol_ir_fee`), and `edit_fee_state()` never validates `program_fee_rate`/`program_fee_fixed`. If any of these fee fields is set to a value that makes a derived rate negative, `calc_interest_rate()` panics via `assert!`, which aborts every subsequent transaction that touches the bank's interest accrual — a full DoS.

### Finding Description
`InterestRateConfigImpl::validate()` dispatches to `validate_seven_point()`: [1](#0-0) 
This function only checks the curve shape (`zero_util_rate`, `hundred_util_rate`, `points` ordering) — it never checks `insurance_fee_fixed_apr`, `insurance_ir_fee`, `protocol_fixed_fee_apr`, or `protocol_ir_fee`, which are set unconditionally by `update()`: [2](#0-1) 

These fee fields are stored as `WrappedI80F48`, a raw signed fixed-point wrapper with no range restriction whatsoever (any bit pattern round-trips through `I80F48::from_le_bytes`): [3](#0-2) 

Similarly, the global `program_fee_rate` / `program_fee_fixed` used by every group's interest calculation are set by the global fee admin with **zero validation**: [4](#0-3) 

These fee values flow directly into `calc_interest_rate()`, which computes `lending_rate_apr`, `borrowing_rate_apr`, `group_fee_apr`, `insurance_fee_apr`, and `protocol_fee_apr` and then enforces non-negativity with Rust `assert!` — a hard panic, not a checked/graceful `MarginfiError`: [5](#0-4) 

Because `calc_fee_rate()` computes `base_rate * rate_fee + fixed_fee` with no floor at zero, any admin-set fee field with a sufficiently negative fixed component (or a rate/fixed combination that outweighs `base_rate_apr`) produces a negative `group_fee_apr`/`insurance_fee_apr`/`protocol_fee_apr`, tripping the `assert!` and panicking: [6](#0-5) 

`calc_interest_rate()` is invoked from `accrue_interest()`, which runs on essentially every state-changing bank interaction (deposit, borrow, repay, withdraw, liquidate): [7](#0-6) 

This is the direct analog of the reported bug: an admin-controlled fee/rate parameter with no bound check feeds a formula in a core accounting function that is defended with a panic/underflow instead of a graceful, checked error — every unprivileged user's read/write interaction with the affected bank then reverts.

### Impact Explanation
Once such a fee is set (via `ConfigureBankLiteCurve`/`edit_staked_settings`-style bank config paths that call `InterestRateConfigImpl::update()`, or via `edit_global_fee_state`), every unprivileged user's deposit, borrow, repay, withdraw, and liquidation against that bank (or, in the `program_fee_rate`/`program_fee_fixed` case, against **every bank in every group with program fees enabled**) will panic inside `accrue_interest` → `calc_interest_rate`, denying service to all depositors/borrowers/liquidators. This is a permanent freeze of bank operations until the value is corrected by another privileged transaction, potentially trapping user funds (unable to withdraw or repay) and blocking liquidations of unhealthy positions in the interim — a core-accounting-path DoS with insolvency/bad-debt risk if liquidations are blocked while positions decay.

### Likelihood Explanation
Triggering this requires an admin-side action (fee/curve admin or global fee admin setting a bad value), which could occur by misconfiguration, a compromised delegate-curve-admin key, or a compromised `global_fee_admin`/its multisig. Given the total absence of bounds validation on these specific fee fields (unlike the curve-shape checks that do exist), any such action — accidental or malicious — immediately and unconditionally halts the affected bank(s), with no on-chain fee/value bound acting as a safety net.

### Recommendation
Add explicit bounds validation for all fee fields before they are persisted:
- In `InterestRateConfigImpl::validate()`/`validate_seven_point()`, reject `insurance_fee_fixed_apr`, `insurance_ir_fee`, `protocol_fixed_fee_apr`, and `protocol_ir_fee` values that are negative or that could drive `borrowing_rate_apr`/`group_fee_apr`/`insurance_fee_apr`/`protocol_fee_apr` negative across the full utilization range.
- In `edit_fee_state()` (and `initialize_fee_state`), validate `program_fee_rate`/`program_fee_fixed` are within a sane, non-negative bound before writing to `FeeState`.
- Replace the `assert!` checks in `calc_interest_rate()` with `check!`/`ok_or_else(math_error!())`-style checked errors that return a `MarginfiError` instead of panicking, so a bad configuration produces a recoverable instruction failure rather than an unrecoverable panic baked into every future accrual call.

### Proof of Concept
Conceptual PoC mirroring the report's structure (cannot be executed in this read-only session, but the code path is concrete):
1. As the delegate curve admin (or group admin), call `ConfigureBankLiteCurve` with `insurance_fee_fixed_apr` set to a large negative `WrappedI80F48` (e.g., `-10.0`), which passes `validate_seven_point()` unchanged since it never inspects fee fields — see `InterestRateConfig::update`/`validate_seven_point` at [8](#0-7) .
2. Any user calls `lending_pool_pulse_bank_price_cache`, `deposit`, `borrow`, `repay`, or `withdraw` against that bank, invoking `accrue_interest` → `calc_interest_rate` — see [7](#0-6)  and [9](#0-8) .
3. `insurance_fee_apr` (or another fee apr) computed via `calc_fee_rate` becomes negative, tripping `assert!(insurance_fee_apr >= I80F48::ZERO)`, panicking the transaction and reverting it for every caller thereafter — a persistent DoS on the bank until an admin corrects the configuration.

    fn validate_seven_point(&self) -> MarginfiResult {
        let zero = self.zero_util_rate;
        let hundred = self.hundred_util_rate;

        // Collect used points (util > 0), enforce trailing padding
        let mut used: Vec<RatePoint> = Vec::with_capacity(self.points.len());
        let mut seen_padding = false;
        for (i, p) in self.points.iter().enumerate() {
            if p.util == 0 {
                // Padding: must be (0,0); once seen, all following must be padding as well.
                if p.rate != 0 {
                    msg!("Expected padding (zero rate) at {:?}", i);
                    return err!(MarginfiError::InvalidConfig);
                }
                seen_padding = true;
            } else {
                // No "holes": non-zero util after padding is not allowed.
                if seen_padding {
                    msg!("Expected padding at {:?} (no holes permitted)", i);
                    return err!(MarginfiError::InvalidConfig);
                }

                used.push(*p);
            }
        }

        // Points must be strictly increasing in util, and non-decreasing in rate
        for i in 1..used.len() {
            let prev = &used[i - 1];
            let curr = &used[i];

            if prev.util >= curr.util {
                msg!("util not ascending between {:?} {:?}", i - 1, i);
                msg!("utils: {:?} {:?}", prev.util, curr.util);
                return err!(MarginfiError::InvalidConfig);
            }
            if prev.rate > curr.rate {
                msg!("rate is decreasing between {:?} {:?}", i - 1, i);
                msg!("rates: {:?} {:?}", prev.rate, curr.rate);
                return err!(MarginfiError::InvalidConfig);
            }
        }

        // rate at zero < rate at 100%, and for each point p, 0_rate <= p <= 100%_rate
        let zero_lte_hundred = zero <= hundred;
        if !zero_lte_hundred {
            msg!("The zero rate is higher than the hundred rate");
            return err!(MarginfiError::InvalidConfig);
        }
        let p_between_zero_hundred = used.iter().all(|p| zero <= p.rate && p.rate <= hundred);
        if !p_between_zero_hundred {
            msg!("A point is not between 0 and 100 rates");
            return err!(MarginfiError::InvalidConfig);
        }

        Ok(())
    }

/// Calculates the fee rate for a given base rate and fees specified.
/// The returned rate is only the fee rate without the base rate.
///
/// Used for calculating the fees charged to the borrowers.
fn calc_fee_rate(base_rate: I80F48, rate_fees: I80F48, fixed_fees: I80F48) -> Option<I80F48> {
    if rate_fees.is_zero() {
        return Some(fixed_fees);
    }

    base_rate.checked_mul(rate_fees)?.checked_add(fixed_fees)
}
