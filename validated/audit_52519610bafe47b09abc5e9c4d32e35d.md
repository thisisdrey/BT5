### Title
Protocol fee bypass on Nep245/Imt token diffs by splitting an amount into unit (`|delta|<=1`) legs - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::token_fee` charges `Pips::ZERO` for any `Nep245`/`Imt` leg whose absolute delta is `<= 1`, while a single leg with `amount > 1` is charged the full `protocol_fee` rounded up via `fee_ceil`. Because a signer can freely decompose a negative delta of size `N` into `N` separate `TokenDiff` intents of `amount = 1` inside the very same signed `DefuseIntents` payload, they can reduce the total protocol fee for an identical net token outflow from `fee_ceil(N * fee)` down to exactly `0`.

### Finding Description
The binding that should hold is:
`fees_collected(TokenDiff{token: -N}) == fees_collected(N × TokenDiff{token: -1})` for the same multi-token and the same net outflow `N`.

For `TokenIdType::Nep245`/`Imt`, the fee rate is `Pips::ZERO` whenever `amount <= 1`, and only equals the full `protocol_fee` when `amount > 1`. `Engine::execute_signed_intent` (`contracts/defuse/core/src/engine/mod.rs:79`) executes an entire `DefuseIntents` message — which can contain an arbitrary list of `TokenDiff` intents — under a single verified signature and a single committed `Nonce`. Each `TokenDiff` in that list is processed independently by the loop in `TokenDiff::execute_intent`, and `protocol_fee`/`fee` are computed per-intent, not on the cumulative amount moved for the token across the whole payload.

Attacker's exact payload: instead of signing one `DefuseIntents{ intents: [TokenDiff{ diff: {mt_token: -2, ...} }] }` (which charges `fee_ceil(2) >= 1` fee-unit), the attacker signs `DefuseIntents{ intents: [TokenDiff{ diff: {mt_token: -1} }, TokenDiff{ diff: {mt_token: -1} }] }` in one payload with the matching counter-legs needed to satisfy the batch's zero-sum invariant in `finalize`. Both unit legs hit the `amount <= 1` branch and return `Pips::ZERO`, so `fees_collected` for the whole payload is `0`, versus a strictly positive amount for the single `-2` leg.

None of the existing guards intercept this: `MultiPayload::verify`/`has_public_key`/`verify_intent_nonce`/`commit_nonce` only check signature and replay validity of the whole payload, not per-token cumulative amounts; `TransferMatcher::finalize` only enforces that the batch's deltas net to zero, which is unaffected by how the fee is internally split; there is no aggregation of `amount` per `TokenId` across intents before calling `token_fee`.

### Impact Explanation
The fee collector under-collects protocol fees on every Nep245/Imt (multi-token) swap that could otherwise be executed as one bigger `TokenDiff` leg, by having the signer decompose it into `amount = 1` legs. This is a systematic protocol fee bypass, not merely a one-off rounding quirk at the boundary `amount == 2`: any `Nep245`/`Imt` amount `N` can be fully de-feed by splitting into `N` unit legs in a single signed payload. This falls into the Critical category "protocol fees bypassed ... over-collected" because value that should flow to `fee_collector` never does, at no extra signing/transaction cost to the attacker (one payload, one nonce, one signature covers the whole decomposed batch).

### Likelihood Explanation
Preconditions: attacker only needs to hold balance `N` of a Nep245/Imt token they want to swap/move and construct their own `DefuseIntents` list with `N` unit legs (each `amount = 1`) instead of one leg of `amount = N`, matched with whatever counter-legs are needed to satisfy the batch's zero-sum invariant (which the attacker fully controls if they are trading with themselves or with any willing counterparty, and can always do for self-transfers/withdrawal-style diffs). This requires no privileged role, no relayer key, and no additional signatures. It is trivially repeatable for every Nep245/Imt swap and every account, and the fee reduction is deterministic (from `fee_ceil(N*rate)` down to `0`).

### Recommendation
Compute the fee based on the total moved amount per `TokenId` across all `TokenDiff` intents within the same signed `DefuseIntents` (or the whole batch) rather than per intent/leg, e.g. aggregate `amount` per `(token_id)` before evaluating `token_fee`'s `amount > 1` condition, or remove the `amount <= 1` fee exemption for Nep245/Imt tokens entirely and rely solely on `fee_ceil` rounding semantics.

### Proof of Concept
```rust
// contracts/defuse/core/src/intents/token_diff.rs (new test)
#[test]
fn split_mt_diff_bypasses_fee() {
    let fee = Pips::ONE_PERCENT; // any non-zero fee
    let mt_token: TokenId = Nep245TokenId::new("mt.near".parse().unwrap(), "unit1".to_string()).into();

    // single leg of amount 2
    let fee_single = TokenDiff::token_fee(mt_token.clone(), 2, fee).fee_ceil(2);
    assert!(fee_single > 0);

    // two legs of amount 1 each
    let fee_leg1 = TokenDiff::token_fee(mt_token.clone(), 1, fee).fee_ceil(1);
    let fee_leg2 = TokenDiff::token_fee(mt_token.clone(), 1, fee).fee_ceil(1);
    let fee_split_total = fee_leg1 + fee_leg2;

    // binding fees_collected(-2) == 2 * fees_collected(-1) is violated:
    assert_eq!(fee_split_total, 0);
    assert_ne!(fee_single, fee_split_total);
}
```
This can be extended to a `near-workspaces`/engine-level integration test executing one `DefuseIntents` payload containing `TokenDiff{token: -2}` versus another payload containing two `TokenDiff{token: -1}` legs (with matching counter-legs to satisfy `finalize`), asserting the `fee_collector`'s credited balance differs (`> 0` vs `== 0`) for the identical net token outflow.
