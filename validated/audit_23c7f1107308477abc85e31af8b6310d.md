### Title
Missing pubkey/address cross-check in `handle_neighbor_handshake_accept` allows forged `(addr, pubkey)` writes to PeerDB frontier - ([File: stackslib/src/net/neighbors/walk.rs])

### Summary
`neighbor_handshakes_try_finish` collects `HandshakeAccept`/`StackerDBHandshakeAccept` replies from neighbors-of-neighbors and passes them straight to `add_or_schedule_replace_neighbor` via `handle_neighbor_handshake_accept`, without ever validating that the self-reported `HandshakeData.addrbytes/.port/.node_public_key` match the `NeighborAddress` (`naddr`) that was actually solicited. This is inconsistent with the sibling `pingback_handshakes_try_finish` path, which explicitly calls `check_handshake_pubkey_hash` before the same DB-writing call, showing the check is a known but here-omitted mitigation.

### Finding Description
The equality that should hold — the `(addr, pubkey)` pair written into `PeerDB` must equal the pair the walker actually solicited via `naddr` — is broken on this path.

Trace:
- `neighbor_handshakes_begin` (walk.rs:979-1089) opens sessions to `NeighborAddress` values `na` obtained from a `GetNeighbors` reply of `cur_neighbor`, via `self.comms.neighbor_session_begin(network, &na)` [1](#0-0) .
- `neighbor_handshakes_try_finish` collects replies as `(naddr, message)` pairs and, for `HandshakeAccept`/`StackerDBHandshakeAccept`, calls `handle_neighbor_handshake_accept(network, naddr, &message.preamble, data, db_data)` with **no** call to any pubkey-hash/address check against `naddr` [2](#0-1) .
- `handle_neighbor_handshake_accept` forwards the raw `data.handshake` (fully attacker-controlled fields) directly into `add_or_schedule_replace_neighbor` [3](#0-2) .
- `add_or_schedule_replace_neighbor` calls `Neighbor::load_and_update(&tx, preamble.peer_version, preamble.network_id, handshake)`, then `save`/`save_update`, committing the record to the persistent `PeerDB` frontier [4](#0-3) .
- `Neighbor::load_and_update` derives the stored key purely from self-reported fields: `let addr = NeighborKey::from_handshake(peer_version, network_id, handshake_data);` and `let pubk = handshake_data.node_public_key...` [5](#0-4) . Neither field is compared to `naddr`'s actual address or `naddr.public_key_hash`.

By contrast, the sibling code path for pingback handshakes performs exactly this check before the identical DB write: `check_handshake_pubkey_hash(&peer_nk, data, &naddr)` [6](#0-5)  then `add_or_schedule_replace_neighbor(...)` only if it passes [7](#0-6) . Likewise, the direct-neighbor handshake path (`handle_handshake_accept`) rejects a reply whose reported `addr` doesn't match `cur_neighbor.addr` for outbound walks [8](#0-7) . Both of these confirm the check is understood to be necessary elsewhere in this exact file, yet it is missing for `handle_neighbor_handshake_accept`.

The message signature (`verify_secp256k1`) only proves self-consistency — that the payload was signed by the private key matching the embedded `node_public_key` — it never proves that key or the embedded `addrbytes/port` correspond to the socket/identity the walker actually solicited (`naddr`).

Attacker's exact message: any peer that is listed as a "neighbor-of-neighbor" (either because it genuinely runs the socket at `naddr.addrbytes:naddr.port`, or because a colluding/malicious `cur_neighbor` reports an attacker-chosen `naddr` that the attacker's own node answers for) replies to the walker's unsolicited `Handshake` with a `HandshakeAccept`/`StackerDBHandshakeAccept` whose `HandshakeData.addrbytes/.port/.node_public_key` are set to an arbitrary, self-consistent (self-signed) value unrelated to `naddr`.

### Impact Explanation
The victim node's `PeerDB` frontier gets an unauthenticated write of an attacker-chosen `(addr, pubkey)` pair (via `PeerDB::try_insert_peer` / `PeerDB::update_peer`), potentially overwriting or displacing legitimate entries and even causing the local node to later `GetNeighbors`-gossip this forged entry to further peers, propagating the poisoned entry network-wide. This corrupts neighbor discovery for the victim node and any node that subsequently walks through it — matching the Critical category "unauthenticated write to state ... network-wide propagation of forged data." Repeatable on every walk cycle that reaches `GetHandshakesFinish` against the attacker's node.

### Likelihood Explanation
The attacker needs only to run an ordinary P2P-reachable node (no secret/privileged role) and be reachable as a `naddr` value fed into `neighbor_handshakes_begin` — either by naturally being a real neighbor-of-neighbor of some legitimate peer, or by a colluding peer reporting the attacker's address in its `GetNeighbors` reply. No signature bypass or crypto break is required; the attacker signs its own forged payload with its own key, which is exactly what `verify_secp256k1` expects. This is a low-cost, remotely-triggerable, repeatable condition during normal neighbor-walk operation (`NeighborWalkState::GetHandshakesFinish`).

### Recommendation
In `neighbor_handshakes_try_finish`/`handle_neighbor_handshake_accept`, before calling `add_or_schedule_replace_neighbor`, validate the reply the same way `pingback_handshakes_try_finish` does: call `check_handshake_pubkey_hash(&nkey, data, &naddr)` (or an equivalent check comparing `data.handshake.addrbytes/.port` and the hash of `data.handshake.node_public_key` against `naddr`), and drop/mark-broken any reply that fails, mirroring the existing address check already present in `handle_handshake_accept` for the direct cur_neighbor path.

### Proof of Concept
Rust test plan (in `stackslib::net::neighbors::db` or `walk.rs` test module):
1. Build a `PeerNetwork`/`NeighborWalk` test harness (reuse helpers in `stackslib/src/net/tests/neighbors.rs`) with `state = GetHandshakesFinish` and a `pending_neighbor_addrs`/`naddr` entry `naddr_X` = `(addrbytes_X, port_X, pubkey_hash_X)` for victim identity X.
2. Craft a `Preamble` + `HandshakeAcceptData` where `data.handshake.addrbytes/.port` = `addrbytes_Y/port_Y` (different from `naddr_X`) and `data.handshake.node_public_key` = attacker's own key (self-signed correctly so `verify_secp256k1` passes).
3. Call `walk.handle_neighbor_handshake_accept(&mut network, naddr_X.clone(), &preamble, &data, None)` (or feed through `neighbor_handshakes_try_finish` with a mocked reply keyed by `naddr_X`).
4. Assert failure is expected (rejection) — currently it will instead succeed and call `PeerDB::get_peer(conn, network_id, &addrbytes_Y, port_Y)` to find a mismatched entry, i.e. `assert!(PeerDB::get_peer(peerdb_conn(), network_id, &addrbytes_Y, port_Y).unwrap().is_some())` with `public_key == attacker_pubkey`, proving an unauthenticated write of an address/key pair unrelated to the solicited `naddr_X`. A fixed implementation should return an error/skip the entry instead, causing this assertion to fail (no such PeerDB row created).

    /// Does a given handshakedata represent an expected public key hash?
    fn check_handshake_pubkey_hash(
        nk: &NeighborKey,
        data: &HandshakeAcceptData,
        naddr: &NeighborAddress,
    ) -> bool {
        let neighbor_pubkey_hash =
            Hash160::from_node_public_key_buffer(&data.handshake.node_public_key);
        if neighbor_pubkey_hash != naddr.public_key_hash {
            debug!(
                "Neighbor {:?} had an unexpected pubkey hash: expected {:?} != {:?}",
                nk, &naddr.public_key_hash, &neighbor_pubkey_hash
            );
            return false;
        }

        true
    }

    fn add_or_schedule_replace_neighbor(
        &self,
        network: &mut PeerNetwork,
        preamble: &Preamble,
        handshake: &HandshakeData,
        db_data: Option<&StackerDBHandshakeData>,
        replacements: &mut NeighborReplacements,
    ) -> Result<(bool, Neighbor), net_error> {
        let local_peer_str = format!("{:?}", network.get_local_peer());
        let tx = network.peerdb_tx_begin()?;
        let (mut neighbor_from_handshake, was_present) =
            Neighbor::load_and_update(&tx, preamble.peer_version, preamble.network_id, handshake)?;

        if was_present {
            test_debug!(
                "{}: already know about neighbor {:?}",
                &local_peer_str,
                &neighbor_from_handshake.addr
            );
            neighbor_from_handshake
                .save_update(&tx, db_data.map(|x| x.smart_contracts.as_slice()))?;
            tx.commit()?;

            // seen this neighbor before
            return Ok((false, neighbor_from_handshake));
        }

        debug!(
            "{}: new neighbor {:?}",
            &local_peer_str, &neighbor_from_handshake.addr
        );

        // didn't know about this neighbor yet. Try to add it.
        let added =
            neighbor_from_handshake.save(&tx, db_data.map(|x| x.smart_contracts.as_slice()))?;

        if added {
            // neighbor was new, and we had space to add it.
            tx.commit()?;
            return Ok((true, neighbor_from_handshake));
        }

        // neighbor was new, but we don't have space to insert it.
        // find and record a neighbor it would replace.
        let replaced_neighbor_slot_opt =
            Self::find_replaced_neighbor_slot(&tx, &neighbor_from_handshake.addr)?;
        if let Some(slot) = replaced_neighbor_slot_opt {
            replacements.add_neighbor(
                NeighborAddress::from_neighbor(&neighbor_from_handshake),
                neighbor_from_handshake.clone(),
                slot,
            );
        }

        tx.commit()?;

        // neighbor was new
        Ok((true, neighbor_from_handshake))
    }
