### Title
Unauthenticated `/shutdown` HTTP request permanently terminates the signer's event receiver - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` treats any HTTP POST to `/shutdown` as authoritative and unconditionally sets `stop_signal` and returns `EventError::Terminated`, with no check that the request actually originated from the signer's own `SignerStopSignaler`. Any TCP client that can reach the signer's bound event-receiver address can send this single crafted request to permanently kill the signer's event loop.

### Finding Description
The intended shutdown mechanism is `SignerStopSignaler::send` (`libsigner/src/events.rs:376-396`), which connects to the receiver's own `local_addr` and issues `POST /shutdown HTTP/1.1 ...` purely to wake up the blocking `tiny_http` server so the already-set `AtomicBool` stop flag can be observed. However, the actual termination logic lives in `next_event` at `libsigner/src/events.rs:443-445`:

```rust
} else if request.url() == "/shutdown" {
    event_receiver.stop_signal.store(true, Ordering::SeqCst);
    Err(EventError::Terminated)
}
```

This branch matches on URL alone — there is no shared secret, no peer-address/loopback check, no correlation with the `stop_signal` having already been set by the internal signaler, and no authentication of any kind (unlike node-originated event routes, which at least require `Method::Post` but are otherwise similarly unauthenticated, this route directly flips global receiver state). Any peer that opens a TCP connection to the receiver's bound port and sends `POST /shutdown HTTP/1.1\r\nHost: x\r\nContent-Length: 0\r\n\r\n` triggers the exact same store+return path, causing `main_loop` (`libsigner/src/events.rs:296-300`) to break out of its loop and stop processing events. The sample/reference signer configs bind this endpoint to `0.0.0.0` (`sample/conf/signer/mainnet-signer-conf.toml:39`, `endpoint = "0.0.0.0:30000"`), and the code itself warns operators about exposing the signer to external networks (`stacks-signer/src/lib.rs:125-132`), confirming this port is intended/expected to potentially be reachable beyond localhost in real deployments.

### Impact Explanation
A successful `/shutdown` POST permanently halts the signer's `SignerEventReceiver::main_loop`, meaning the signer stops receiving all subsequent StackerDB chunk events, burn-block events, and block-validation responses from its node. This blinds the signer to new information and would need a full process restart to recover — a single crafted HTTP message from an unauthenticated remote peer causes an irrecoverable denial of service against a signer's event ingestion path, matching the "Critical - remote crash/unauthenticated DoS from few messages" category.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's bound event-receiver address; no secret, key, or privileged role is required. This is not bandwidth/volumetric DoS — a single, cheaply crafted HTTP request suffices. Deployments that bind the endpoint to non-loopback addresses (as the shipped `0.0.0.0` sample config does) are directly and repeatably exploitable by any remote party who can reach that port.

### Recommendation
Do not use a network-reachable URL path as the shutdown trigger. Options: (1) restrict `/shutdown` handling to connections originating from the receiver's own bound loopback address (verify peer socket address equals `local_addr`'s IP/loopback), (2) require a per-process random shared secret known only to the `SignerStopSignaler` and included in the request, validated before honoring the shutdown, or (3) replace the HTTP-based wakeup mechanism entirely with an internal-only signaling primitive (e.g., a self-pipe/local socketpair, or a periodic poll of the `AtomicBool` with a short timeout on `recv`) so no externally reachable endpoint can influence `stop_signal`.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module) or a new integration test
use std::net::{TcpListener, TcpStream};
use std::io::Write;

#[test]
fn unauthenticated_shutdown_terminates_receiver() {
    let mut receiver: SignerEventReceiver<SomeSignerMessageType> = SignerEventReceiver::new(false);
    let addr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();

    // Attacker: plain TCP client, no auth, no relation to SignerStopSignaler
    let mut stream = TcpStream::connect(bound).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: x\r\nContent-Length: 0\r\n\r\n";
    stream.write_all(req.as_bytes()).unwrap();

    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
This demonstrates that any TCP peer, without holding the signer's identity or any secret, can flip `stop_signal` and terminate `next_event`/`main_loop` exactly as the internal `SignerStopSignaler` would, confirming the missing caller-identity check at `libsigner/src/events.rs:443-445`.                 }

                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));

                process_event::<T, StackerDBChunksEvent>(request)
