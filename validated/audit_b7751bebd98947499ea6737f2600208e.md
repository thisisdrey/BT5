### Title
Stale stake snapshot cached per-QUIC-connection causes QoS evasion after a peer's stake decreases - (File: `streamer/src/nonblocking/swqos.rs`)

### Summary
`SwQos::build_connection_context` computes a connection's `peer_type` (staked/unstaked) and `total_stake` once, at connection-establishment time, from the shared `staked_nodes` map, and stores them in `SwQosConnectionContext`. This context is never refreshed for the remainder of the QUIC connection's life, even though `staked_nodes` is refreshed cluster-wide every 5 seconds (and stakes actually change every epoch). This mirrors the reported bug class: a value that should track a live, mutable resource (liquidity / stake) is captured once and reused stale, letting a party keep favorable treatment (or receive less than deserved) long after the underlying resource changed.

### Finding Description
`build_connection_context` snapshots the peer's stake and total network stake exactly once when a connection is accepted: [1](#0-0) 

This `SwQosConnectionContext` (containing `peer_type` and `total_stake`) is stored for the lifetime of the connection via `try_add_connection`/`cache_new_connection` and is reused on every subsequent stream without ever being recomputed: [2](#0-1) [3](#0-2) 

Meanwhile, the authoritative stake data (`staked_nodes`) that `build_connection_context` reads from is updated independently and continuously by `StakedNodesUpdaterService`, on a 5-second cycle, tracking the bank's current epoch stake: [4](#0-3) 

Because `SwQos` has no mechanism to re-derive `peer_type`/`total_stake` for an already-established connection, a validator that had high stake at connection time but subsequently loses stake (deactivates/redelegates, or is simply overtaken in relative share as `total_stake` shifts) continues to be treated as high-stake for QoS purposes: `available_load_capacity_in_throttling_duration` and `compute_max_allowed_uni_streams_with_rtt` both key off the stale `peer_type`/`total_stake` fields for the entire connection lifetime: [5](#0-4) [6](#0-5) 

This is the direct analog of the reported bug: a resource-weight value (`liquidity` in the report, `stake` here) is cached at the start of a session and used to compute an ongoing entitlement (`rewards` in the report, `stream/connection throughput budget` here), without ever being refreshed against the live, mutable underlying state.

### Impact Explanation
An unstaked or lower-staked peer that opens a long-lived QUIC connection while briefly staked (or during a period of high relative stake) keeps disproportionately high stream-throughput and stream-concurrency allowances (`max_uni_streams`, `max_streams_per_throttling_interval`) for the entire duration of that connection, even after its stake is reduced or withdrawn. Since QUIC connections can remain open for extended periods, this allows an actor to sustain a QoS class more favorable than currently warranted, effectively evading the stake-weighted QoS (SWQoS) throttling that is meant to prioritize genuinely staked validators and rate-limit everyone else — a form of QoS evasion in the unprivileged-user-facing streamer path.

### Likelihood Explanation
Likelihood is moderate: the connection context is guaranteed to be stale relative to the periodic 5-second `staked_nodes` refresh and to epoch boundaries, since there is no re-evaluation path at all for open connections — only new connections get a fresh snapshot. Any peer whose stake decreases after connecting will automatically continue to benefit from the higher allotment until the connection is closed and re-established, requiring no special timing or race to trigger.

### Recommendation
Re-derive (or periodically refresh) `peer_type`/`total_stake` for the lifetime of a connection instead of caching it once at connection acceptance — e.g., re-check `get_connection_stake` against the current `staked_nodes` snapshot in `on_new_stream`/`max_streams_per_throttling_interval` (as is effectively already done for the global `total_stake` normalization via `staked_stream_load_ema`), so that QoS decisions reflect current stake rather than a value frozen at connection-establishment time.

### Proof of Concept
1. Validator/staker A obtains sufficient active stake and opens a QUIC connection to a target node; `build_connection_context` classifies it as `ConnectionPeerType::Staked(stake)` with a given `total_stake`, and this context is cached in the connection table via `cache_new_connection`.
2. A immediately deactivates/withdraws its stake (or stake naturally rolls off at the epoch boundary), so a fresh connection from A would now be classified `Unstaked` or with far lower `stake`.
3. `StakedNodesUpdaterService` updates the shared `staked_nodes` map within 5 seconds, but A's already-open connection's `SwQosConnectionContext` is never touched.
4. A keeps sending streams on the same open connection; `on_new_stream` → `max_streams_per_throttling_interval` → `available_load_capacity_in_throttling_duration` uses the stale, higher `stake`/`total_stake` captured in step 1, granting A a throughput budget consistent with its old (now-invalid) stake for as long as the connection stays open.

fn compute_max_allowed_uni_streams_with_rtt(
    rtt_millis: u32,
    peer_type: ConnectionPeerType,
    total_stake: u64,
) -> u32 {
    let streams = match peer_type {
        ConnectionPeerType::Staked(peer_stake) => {
            // No checked math for f64 type. So let's explicitly check for 0 here
            if total_stake == 0 || peer_stake > total_stake {
                warn!(
                    "Invalid stake values: peer_stake: {peer_stake:?}, total_stake: \
                     {total_stake:?}"
                );

                QUIC_MIN_STAKED_CONCURRENT_STREAMS
            } else {
                let delta = (QUIC_TOTAL_STAKED_CONCURRENT_STREAMS
                    - QUIC_MIN_STAKED_CONCURRENT_STREAMS) as f64;

                (((peer_stake as f64 / total_stake as f64) * delta) as u32
                    + QUIC_MIN_STAKED_CONCURRENT_STREAMS)
                    .clamp(
                        QUIC_MIN_STAKED_CONCURRENT_STREAMS,
                        QUIC_MAX_STAKED_CONCURRENT_STREAMS,
                    )
            }
        }
        ConnectionPeerType::Unstaked => QUIC_MAX_UNSTAKED_CONCURRENT_STREAMS,
    };
    // scale amount of streams based on RTT if RTT is larger than REFERENCE_RTT_MS
    // multiply first then divide to avoid rounding errors.
    (streams.saturating_mul(rtt_millis.clamp(REFERENCE_RTT_MS, MAX_RTT_MS))) / REFERENCE_RTT_MS
}

impl QosController<SwQosConnectionContext> for SwQos {
    fn build_connection_context(&self, connection: &Connection) -> SwQosConnectionContext {
        let remote_address = connection.remote_address();
        get_connection_stake(connection, &self.staked_nodes).map_or(
            SwQosConnectionContext {
                peer_type: ConnectionPeerType::Unstaked,
                total_stake: 0,
                remote_pubkey: None,
                in_staked_table: false,
                remote_address,
                stream_counter: None,
                last_update: Arc::new(AtomicU64::new(timing::timestamp())),
            },
            |(pubkey, stake, total_stake)| {
                // The heuristic is that the stake should be large enough to have 1 stream pass through within one throttle
                // interval during which we allow max (MAX_STREAMS_PER_MS * STREAM_THROTTLING_INTERVAL_MS) streams.

                let peer_type = {
                    let max_streams_per_ms = self.staked_stream_load_ema.max_streams_per_ms();
                    let min_stake_ratio =
                        1_f64 / (max_streams_per_ms * STREAM_THROTTLING_INTERVAL_MS) as f64;
                    let stake_ratio = stake as f64 / total_stake as f64;
                    if stake_ratio < min_stake_ratio {
                        // If it is a staked connection with ultra low stake ratio, treat it as unstaked.
                        ConnectionPeerType::Unstaked
                    } else {
                        ConnectionPeerType::Staked(stake)
                    }
                };

                SwQosConnectionContext {
                    peer_type,
                    total_stake,
                    remote_pubkey: Some(pubkey),
                    in_staked_table: false,
                    remote_address,
                    last_update: Arc::new(AtomicU64::new(timing::timestamp())),
                    stream_counter: None,
                }
            },
        )
    }

const STAKE_REFRESH_CYCLE: Duration = Duration::from_secs(5);

pub struct StakedNodesUpdaterService {
    thread_hdl: JoinHandle<()>,
}

impl StakedNodesUpdaterService {
    pub fn new(
        exit: Arc<AtomicBool>,
        bank_forks: Arc<RwLock<BankForks>>,
        staked_nodes: Arc<RwLock<StakedNodes>>,
        staked_nodes_overrides: Arc<RwLock<HashMap<Pubkey, u64>>>,
    ) -> Self {
        let thread_hdl = Builder::new()
            .name("solStakedNodeUd".to_string())
            .spawn(move || {
                while !exit.load(Ordering::Relaxed) {
                    let stakes = {
                        let root_bank = bank_forks.read().unwrap().root_bank();
                        root_bank.current_epoch_staked_nodes()
                    };
                    let overrides = staked_nodes_overrides.read().unwrap().clone();
                    *staked_nodes.write().unwrap() = StakedNodes::new(stakes, overrides);
                    std::thread::sleep(STAKE_REFRESH_CYCLE);
                }
            })
            .unwrap();

        Self { thread_hdl }
    }
