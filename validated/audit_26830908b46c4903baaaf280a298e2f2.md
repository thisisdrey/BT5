### Title
Unauthenticated `POST /shutdown` on the signer's event-listener port permits any reachable peer to kill the signer's event-receiver thread - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` handles the `/shutdown` URL path with no authentication check whatsoever, immediately setting `stop_signal` and returning `EventError::Terminated`. Since `EventReceiver::main_loop` treats `EventError::Terminated` as a normal exit condition, a single unauthenticated HTTP request from any TCP peer that can reach the signer's listening endpoint permanently terminates the signer's event-receiver thread.

### Finding Description
In `next_event`, the request-routing logic checks the URL and, for `/shutdown`, unconditionally executes: [1](#0-0) 
There is no verification of request origin, no auth token/password check, and no restriction tying this route to the node that the signer is configured to trust. Compare this to the rest of the signer/node protocol, which requires `auth_password`/`auth_token` matching for node↔signer RPC interactions, as documented in `docs/signing.md` and the sample configs — but the event-listener HTTP server (`tiny_http`-based `HttpServer`) that `SignerEventReceiver::bind` stands up has no such gate at all: [2](#0-1) 

The intended use is that the node itself calls this route internally via `SignerStopSignaler::send`, which crafts a raw `POST /shutdown` request and writes it directly to a `TcpStream` connected to `self.local_addr`: [3](#0-2) 
This mechanism relies entirely on network-layer trust (only the node can reach the port) rather than any application-layer authentication, and the same reference deployment configuration explicitly documents binding this endpoint to `0.0.0.0:30000` (all interfaces), not `127.0.0.1`: [4](#0-3) 

Once the request is received, `EventError::Terminated` propagates out of `with_server` in `next_event`, and `main_loop` treats it as a clean shutdown signal, breaking out of its loop entirely: [5](#0-4) 
This thread is spawned once in `Signer::spawn` and is not restarted on exit: [6](#0-5) 
so a single successful `/shutdown` POST permanently disables the signer's ability to process any subsequent StackerDB/block/burn-block events for the lifetime of the process.

### Impact Explanation
Any remote party that can open a TCP connection to the signer's event-listener port (bound, per the reference config, to `0.0.0.0`) can send one unauthenticated `POST /shutdown HTTP/1.1` request and permanently kill the event-receiver thread, silently blinding the signer to all further node-forwarded events (stacker-DB chunks, block proposals, burn blocks). This is a Critical, unauthenticated single-message DoS against a component central to Nakamoto consensus signing.

### Likelihood Explanation
No privileged role, secret, or prior state is required — the attacker only needs network reachability to the signer's configured `endpoint` port. Given the shipped reference config binds this to `0.0.0.0:30000`, any deployment following that guidance without an external firewall is directly exposed. The attack is a single crafted HTTP request, trivially repeatable, and requires no valid signer key, no StackerDB slot ownership, and no interaction with the node's authenticated RPC surface.

### Recommendation
Remove or gate the `/shutdown` HTTP route from being triggerable by arbitrary remote clients. Options: (1) restrict the listener to loopback only and document/enforce that `endpoint` must bind to `127.0.0.1`; (2) require the same auth token/password used elsewhere in the node–signer protocol to be present on the `/shutdown` request before honoring it; (3) replace the internal stop mechanism with a non-network-exposed side channel (e.g., a dedicated local Unix socket, or an in-process shutdown flag reachable only from the same process that calls `SignerStopSignaler::send`).

### Proof of Concept
```rust
// libsigner/src/events.rs (test module) — demonstrates unauthenticated shutdown
#[test]
fn test_unauthenticated_shutdown_dos() {
    let mut receiver: SignerEventReceiver<crate::v0::messages::SignerMessage> =
        SignerEventReceiver::new(false);
    let addr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();

    // Simulate an arbitrary remote attacker: NOT the node's event-observer thread,
    // just a bare TcpStream.
    let mut stream = std::net::TcpStream::connect(bound).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: x\r\nConnection: close\r\nContent-Length: 0\r\n\r\n";
    stream.write_all(req.as_bytes()).unwrap();

    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
This confirms that a bare, unauthenticated TCP client—not the node's own event-observer thread—can single-handedly terminate the signer's event-receiver loop via `EventError::Terminated`, matching the guard failure at `libsigner/src/events.rs:443-445`.
