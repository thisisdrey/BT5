## Title
Ordinary RPC caller can bypass Gitaly's transaction/quarantine gating for Accessor RPCs by setting only `GitAlternateObjectDirectories` - ([File: internal/gitaly/storage/storagemgr/middleware.go])

### Summary
`beginTransactionForRepository` decides whether a request is a Rails "quarantine loop-back" (and thus should skip starting a fresh transaction) using an **OR** condition on two independent fields, mirroring the reported bug class where a disjunctive check on two values is used where the intended semantics require both/neither to hold together. This lets a caller who sets only one of the two object-directory fields on an Accessor RPC take the "already quarantined, skip transaction" branch even though no legitimate quarantine was established for this request.

### Finding Description
The condition that gates whether a fresh repository-scoped transaction is started is: [1](#0-0) 

```go
if targetRepo.GetGitObjectDirectory() != "" || len(targetRepo.GetGitAlternateObjectDirectories()) > 0 {
    ...
    if methodInfo.Operation == protoregistry.OpMutator {
        return transactionalizedRequest{}, ErrQuarantineConfiguredOnMutator
    }
    rewrittenReq, err := restoreSnapshotRelativePath(ctx, methodInfo, req)
    ...
    return nonTransactionalRequest(ctx, rewrittenReq), nil
}
```

The comment directly above the check acknowledges the analog to the reported bug class: [2](#0-1)  states that "this property is violated ... configuring the object directory or the alternate object directory ... allows for circumventing the transaction management by configuring either of the object directories," and that the authors "leave this unaddressed for now."

Just as the Uniswap report's `deposit` used `baseLower == 0 || baseUpper == 0` to decide "bounds undefined" when the correct predicate required both to be zero, this code uses `GitObjectDirectory != "" || len(GitAlternateObjectDirectories) > 0` to decide "quarantine already configured by Rails' loop-back," when a genuine quarantine loop-back always sets **both** fields together (per `quarantine.Apply`, which always sets `GitObjectDirectory` to the quarantine path and appends the original object dir into `GitAlternateObjectDirectories`, see [3](#0-2) ). Because the check is a disjunction rather than requiring the well-formed pairing, an ordinary caller can trigger the "already quarantined" branch by setting **only** `GitAlternateObjectDirectories` (leaving `GitObjectDirectory` empty), for an Accessor RPC. This takes the request down the `nonTransactionalRequest` path — skipping `partition.Begin`/snapshot creation and the `locator.ValidateRepository` call that would otherwise occur at [4](#0-3)  — and instead calls `restoreSnapshotRelativePath`, executing the handler directly against the repository as addressed by the raw, attacker-influenced relative path/alternate directories rather than through the transaction manager's snapshot machinery.

### Impact Explanation
This is a legitimate variant of the reported bug class (disjunctive short-circuit check standing in for a conjunctive/paired-state check), located in RPC-handler gating logic that governs whether a request is transactionalized and its access-checked/quarantined. Bypassing this gate means an Accessor RPC can be routed around Gitaly's transaction manager and repository validation, potentially reading/serving objects from an attacker-supplied alternate object directory path outside the normal quarantine lifecycle. However, exploitability depends on downstream validation of the `GitAlternateObjectDirectories` value and whether callers other than Rails/Praefect's loop-back are able to set this proto field on arbitrary Accessor RPC requests; the code and comment already flag this as a known, currently-accepted limitation ("we'll leave this unaddressed for now"), and I could not fully trace whether other layers (e.g. `ObjectDirectoryPath` path validation in `internal/git/localrepo/paths.go`) fully neutralize the downstream risk. Given the explicit self-acknowledged nature of this design gap and the uncertainty about full exploitability, I assess Medium confidence but note this should be treated as a hardening item rather than a confirmed, fully-chained RCE/data-exfiltration.

### Likelihood Explanation
Likelihood is Medium: reaching `beginTransactionForRepository` only requires an ordinary gRPC caller with any Accessor RPC scoped to a repository (`protoregistry.ScopeRepository`) and control over the `GitAlternateObjectDirectories` repeated field of the `Repository` message, which is a standard, client-settable proto field on requests. No privileged access, leaked token, or malicious peer is needed — this is reachable from a normal RPC caller's crafted request field, consistent with the "crafted RPC field" validation criterion.

### Recommendation
Replace the disjunctive check with the same paired condition that `quarantine.Apply` produces: require **both** `GitObjectDirectory != ""` **and** `len(GitAlternateObjectDirectories) > 0` (or equivalently only trust the fields when accompanied by the `MetadataKeySnapshotRelativePath` metadata that Rails' loop-back sets, as validated in `restoreSnapshotRelativePath`). At minimum, reject requests where only one of the two fields is populated, and validate that the supplied `GitAlternateObjectDirectories` value corresponds to an actual sanctioned quarantine directory for the target repository before skipping transaction creation.

### Proof of Concept
Conceptual reproduction (exact request construction not verified end-to-end due to index limits on the RPC dispatch layer):
1. Issue any repository-scoped Accessor RPC (e.g. `FindCommits`) directly to Gitaly.
2. In the `Repository` message, leave `git_object_directory` unset but set `git_alternate_object_directories` to an arbitrary non-empty value.
3. `beginTransactionForRepository` evaluates `targetRepo.GetGitObjectDirectory() != "" || len(targetRepo.GetGitAlternateObjectDirectories()) > 0` as `true` purely because of the alternate-directories field, causing the request to skip `partition.Begin`/`locator.ValidateRepository` and instead flow through `restoreSnapshotRelativePath` and `nonTransactionalRequest`, even though no genuine Rails quarantine loop-back occurred. // Apply applies the quarantine on the repository. This is done by setting the quarantineDirectory
// as the repository's object directory, and configuring the repository's object directory as an alternate.
func Apply(repoPath string, repo *gitalypb.Repository, quarantineDir string) (*gitalypb.Repository, error) {
	relativePath, err := filepath.Rel(repoPath, quarantineDir)
	if err != nil {
		return nil, fmt.Errorf("creating quarantine: %w", err)
	}

	// All paths are relative to the repository root.
	objectDir := repo.GetGitObjectDirectory()
	if objectDir == "" {
		// Set the default object directory as an alternate if the repository didn't
		// have the object directory overwritten yet.
		objectDir = "objects"
	}

	alternateObjectDirs := make([]string, 0, len(repo.GetGitAlternateObjectDirectories())+1)
	alternateObjectDirs = append(alternateObjectDirs, objectDir)
	alternateObjectDirs = append(alternateObjectDirs, repo.GetGitAlternateObjectDirectories()...)

	quarantinedRepo := proto.Clone(repo).(*gitalypb.Repository)
	quarantinedRepo.GitObjectDirectory = relativePath
	quarantinedRepo.GitAlternateObjectDirectories = alternateObjectDirs

	return quarantinedRepo, nil
}
