### Title
Unauthenticated handshake header fields (`RemoteIndex`, `MessageCounter`, `Type`, `Subtype`) allow attacker tampering without invalidating the Noise AEAD tag - ([File: handshake/machine.go])

### Summary
Nebula's Noise handshake authenticates the *payload* (certificate, indexes, time, cert version) via the Noise AEAD, but the plaintext wire `header.H` (Version/Type/Subtype/RemoteIndex/MessageCounter) that precedes it is never included as associated data when the handshake ciphertext is processed. This mirrors the Crestal `M-2` bug class: a subset of protocol-critical fields sits outside the cryptographic authentication boundary and can be swapped by an attacker who merely observes/relays a legitimate packet on the wire, since UDP has no channel confidentiality/integrity of its own.

### Finding Description
In `Machine.ProcessPacket`, the handshake ciphertext is decrypted with: [1](#0-0) 
Only `packet[header.Len:]` is passed to `m.hs.ReadMessage`; the 16-byte header (`Version`, `Type`, `Subtype`, `RemoteIndex`, `MessageCounter`) is not supplied as associated data, so it is not covered by the Noise AEAD tag. Contrast this with the data-plane path, where the header is explicitly bound into the AEAD as associated data: [2](#0-1) 

On the outgoing side, the header is likewise assembled independently of the encrypted payload and simply prepended: [3](#0-2) 

`header.H` fields (`RemoteIndex`, `MessageCounter`) are defined and parsed straight off the wire with no integrity check: [4](#0-3) 

Dispatch of incoming handshake packets keys entirely off these unauthenticated header fields — `h.MessageCounter` decides new-vs-continuation handling, and `h.RemoteIndex` is used to look up the pending handshake state: [5](#0-4) 

Because the header is outside the AEAD boundary, an attacker who captures a legitimate in-flight handshake packet (trivial on UDP without needing to break Noise) can rewrite `RemoteIndex`/`MessageCounter`/`Subtype` while leaving the ciphertext payload untouched, and Noise's `ReadMessage` will still accept it as long as the ciphertext itself is unmodified — the modified header is never checked against anything cryptographic. This is the same root cause as the Crestal report: some fields that determine how a signed/authenticated blob is applied are not part of the authenticated data, so an attacker downstream of the signer/sender can graft a valid authenticated payload onto forged surrounding metadata.

### Impact Explanation
Rewriting `RemoteIndex` on a stage-2/continuation packet can misroute it to a different `HandshakeHostInfo` entry (index-collision/misdelivery), and code explicitly acknowledges the packet-vs-machine subtype/index binding is the *only* gate (`ErrSubtypeMismatch`, index lookups) rather than a cryptographic one: [6](#0-5) 
This enables remote-state poisoning of the handshake manager's index tables (spurious `ErrLocalIndexCollision`/mismatched routing, denial of service against a specific pending handshake) using only packet capture/replay-with-header-rewrite, without needing to forge a certificate or break the Noise handshake cryptography itself.

### Likelihood Explanation
Requires only network-path access to observe/relay one legitimate handshake UDP packet — no valid certificate, no CA trust, and no participation as a peer/lighthouse is needed, satisfying the "attacker with no CA-signed certificate" constraint. This is a lower bar than the original Crestal bug (which required becoming an ERC-4337 bundler); here it just requires being on-path for UDP traffic, which is a standard network-attacker capability this class of vulnerability assumes.

### Recommendation
Bind the wire header into the Noise handshake authentication, e.g. by passing `packet[:header.Len]` as associated data into `ReadMessage`/`WriteMessage` (or by hashing the header into the Noise transcript before payload processing), so any tampering with `RemoteIndex`, `MessageCounter`, `Type`, or `Subtype` invalidates the AEAD tag exactly like it already does for post-handshake data packets in `ConnectionState.Decrypt`.

### Proof of Concept
1. Capture a legitimate stage-2 (or later) handshake UDP packet between two Nebula peers on a network path the attacker controls (e.g., shared L2, malicious router, ARP spoofing) — no cryptographic material is needed.
2. Rewrite the plaintext header bytes `packet[4:8]` (`RemoteIndex`) and/or `packet[8:16]` (`MessageCounter`) to arbitrary attacker-chosen values while leaving `packet[header.Len:]` (the Noise ciphertext) untouched.
3. Forward the modified packet to the target. `Machine.ProcessPacket` still successfully calls `m.hs.ReadMessage(nil, packet[header.Len:])` because the ciphertext/AEAD tag is unmodified, but `HandshakeManager.HandleIncoming` and `continueHandshake`/`queryIndex` now act on the attacker-controlled `RemoteIndex`/`MessageCounter`, misrouting or disrupting the victim's pending-handshake bookkeeping.

Note: I was not able to fully trace every downstream consequence of a forged `RemoteIndex` collision inside `HandshakeManager` (e.g., exact behavior of `queryIndex`/`indexes` map mutation under attacker-forged values) within the remaining investigation budget; a Devin session with full repo access would be needed to enumerate the complete blast radius of index-table poisoning.

type H struct {
	Version        uint8
	Type           MessageType
	Subtype        MessageSubType
	Reserved       uint16
	RemoteIndex    uint32
	MessageCounter uint64
}

// Encode uses the provided byte array to encode the provided header values into.
// Byte array must be capped higher than HeaderLen or this will panic
func Encode(b []byte, v uint8, t MessageType, st MessageSubType, ri uint32, c uint64) []byte {
	b = b[:Len]
	b[0] = v<<4 | byte(t&0x0f)
	b[1] = byte(st)
	binary.BigEndian.PutUint16(b[2:4], 0)
	binary.BigEndian.PutUint32(b[4:8], ri)
	binary.BigEndian.PutUint64(b[8:16], c)
	return b
}

// String creates a readable string representation of a header
func (h *H) String() string {
	if h == nil {
		return "<nil>"
	}
	return fmt.Sprintf("ver=%d type=%s subtype=%s reserved=%#x remoteindex=%v messagecounter=%v",
		h.Version, h.TypeName(), h.SubTypeName(), h.Reserved, h.RemoteIndex, h.MessageCounter)
}

// MarshalJSON creates a json string representation of a header
func (h *H) MarshalJSON() ([]byte, error) {
	return json.Marshal(m{
		"version":        h.Version,
		"type":           h.TypeName(),
		"subType":        h.SubTypeName(),
		"reserved":       h.Reserved,
		"remoteIndex":    h.RemoteIndex,
		"messageCounter": h.MessageCounter,
	})
}

// Encode turns header into bytes
func (h *H) Encode(b []byte) ([]byte, error) {
	if h == nil {
		return nil, errors.New("nil header")
	}

	return Encode(b, h.Version, h.Type, h.Subtype, h.RemoteIndex, h.MessageCounter), nil
}

// Parse is a helper function to parses given bytes into new Header struct
func (h *H) Parse(b []byte) error {
	if len(b) < Len {
		return ErrHeaderTooShort
	}
	// get upper 4 bytes
	h.Version = uint8((b[0] >> 4) & 0x0f)
	// get lower 4 bytes
	h.Type = MessageType(b[0] & 0x0f)
	h.Subtype = MessageSubType(b[1])
	h.Reserved = binary.BigEndian.Uint16(b[2:4])
	h.RemoteIndex = binary.BigEndian.Uint32(b[4:8])
	h.MessageCounter = binary.BigEndian.Uint64(b[8:16])
	return nil
}
