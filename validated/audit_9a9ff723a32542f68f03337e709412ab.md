## Analysis

**Core broken invariant from the report:** the Solidity `AuctionHouse::_settleAuction` decides whether "a valid bid ≥ reservePrice" happened by comparing `address(this).balance` (a value any external actor can inflate via `selfdestruct`) instead of the internally tracked `_auction.amount`. Any code path that gates a financial-settlement decision on the *raw balance of an account* instead of an internally tracked accounting value is vulnerable to the same class of attack, because plain-balance transfers into a known account are always permissionless.

**Local analog found:** `Pallet::ensure_crowdloan_ended` in the `pallet-crowdloan` module gates `withdraw`/`refund` on exactly this kind of raw-balance check. [1](#0-0)

### Title
Crowdloan `withdraw`/`refund` uses manipulable raw account balance instead of tracked bid/lease state to gate fund release - (`polkadot/runtime/common/src/crowdloan/mod.rs`)

### Summary
`ensure_crowdloan_ended` decides whether a crowdloan's raised funds are safe to release back to contributors by comparing the fund account's `free_balance` to `fund.raised`. When a crowdloan wins a slot auction, `pallet-auctions`/`pallet-slots` reserve part of the fund account's balance as the winning bid deposit, which lowers `free_balance` below `fund.raised` — this is exactly how `BidOrLeaseActive` is meant to be detected. Because the fund account is a plain, deterministic `PalletId`-derived `AccountId` and not a contract, anyone can top it up with an ordinary `Balances::transfer_allow_death`/`transfer_keep_alive` call, directly inflating `free_balance`. This is the on-chain equivalent of the Solidity report's `selfdestruct` donation to `address(this).balance` — no privileged actor, relayer, or governance action is needed.

### Finding Description
The check is meant to be a proxy for "is a bid/lease currently active for this para" but instead reads a value (`free_balance`) that is freely and publicly writable by anyone via a normal transfer: [2](#0-1) 

The existing tests already demonstrate that an ordinary transfer to the fund account changes accounting outcomes (`withdraw_cannot_be_griefed`), confirming the fund account accepts arbitrary incoming transfers with no guard: [5](#0-4) 

While that specific test only shows harmless "overfunding" being burned on `dissolve`, the same primitive (public transfer into the fund account) can be used *while the auction bid deposit for the para is still reserved* to push `free_balance` back up to/above `fund.raised`, satisfying `ensure_crowdloan_ended` even though `BidOrLeaseActive` should be true. `withdraw`/`refund` then proceed to pay contributors and permanently delete their contribution records (`contribution_kill`) and zero out `fund.raised`: [6](#0-5) 

Nothing else in the pallet checks the actual reserved/bid state of the fund account before paying out — the `free_balance >= raised` comparison is the *only* guard. Existing guards (`now >= fund.end`, `has_won_an_auction` check in `do_contribute`, cap checks) do not stop this path because they are evaluated only at contribution time, not at withdraw/refund time.

### Impact Explanation
This breaks the invariant that a crowdloan's raised value settles exactly once to the rightful beneficiary. If a para's crowdloan deposit is still reserved (bid active/lease live) and an attacker donates enough tokens to the fund account to defeat `ensure_crowdloan_ended`, contributors can be refunded while the underlying deposit remains locked/committed to the slot auction. When that deposit is eventually unreserved back to the fund account (auction loss or lease expiry), there are no contribution records left to attribute it to (`contribution_kill` already ran), so those funds become stranded and are ultimately burned via `dissolve`'s `make_free_balance_be(&pot, Zero::zero())`. This is a duplicate-settlement / fund-loss scenario: contributors effectively receive value twice (early refund plus a slot the para still holds using their locked deposit) while any leftover deposit is permanently destroyed rather than returned to its rightful owners — directly matching the "duplicate settlement or payout" / "permanent user-fund lock" impact classes.

### Likelihood Explanation
The attack requires only a public, unprivileged `Balances::transfer_allow_death`/`transfer_keep_alive` call to a deterministically-computable account id (`Crowdloan::fund_account_id(fund_index)`), which is derivable by anyone from public storage (`Funds`). No malicious validator, collator, relayer, or governance action is required, and the fund account being a normal `AccountId` (unlike the Solidity contract case that needed `selfdestruct`) makes the donation trivially easy — a single ordinary transfer extrinsic suffices.

### Recommendation
Do not rely on `free_balance(&fund_account)` to infer whether a bid/lease is active. Track the fact explicitly, e.g. by querying `T::Auctioneer::has_won_an_auction`/an explicit "amount reserved for this para" accessor, or by tracking the fund's bid-reserved amount directly in `FundInfo` and comparing against that tracked value instead of the raw account balance.

### Proof of Concept
1. Contributors fund a crowdloan for `para`; `fund.raised = R`.
2. The crowdloan wins the slot auction; `pallet-slots`/`pallet-auctions` reserve `R` (or some amount) out of the fund account's free balance as the lease deposit, so `free_balance(fund_account) < fund.raised`, correctly tripping `BidOrLeaseActive` if `withdraw`/`refund` were called now.
3. Attacker (or anyone, including a contributor) calls `Balances::transfer_allow_death(attacker, fund_account, R)` to top up the fund account's free balance until `free_balance(fund_account) >= fund.raised` again.
4. Attacker calls `Crowdloan::withdraw`/`Crowdloan::refund`; `ensure_crowdloan_ended` now passes because it only compares `free_balance` vs `fund.raised`, even though the lease deposit is still reserved and the para still holds the slot.
5. Contribution records are deleted and `fund.raised` is zeroed while the para's lease deposit remains locked; once later released it has no contribution record to return to, and is ultimately burned via `dissolve`, permanently destroying value that should have gone back to contributors — while contributors already received their funds early.

			origin: OriginFor<T>,
			#[pallet::compact] index: ParaId,
		) -> DispatchResultWithPostInfo {
			ensure_signed(origin)?;

			let mut fund = Funds::<T>::get(index).ok_or(Error::<T>::InvalidParaId)?;
			let now = frame_system::Pallet::<T>::block_number();
			let fund_account = Self::fund_account_id(fund.fund_index);
			Self::ensure_crowdloan_ended(now, &fund_account, &fund)?;

			let mut refund_count = 0u32;
			// Try killing the crowdloan child trie
			let contributions = Self::contribution_iterator(fund.fund_index);
			// Assume everyone will be refunded.
			let mut all_refunded = true;
			for (who, (balance, _)) in contributions {
				if refund_count >= T::RemoveKeysLimit::get() {
					// Not everyone was able to be refunded this time around.
					all_refunded = false;
					break;
				}
				CurrencyOf::<T>::transfer(&fund_account, &who, balance, AllowDeath)?;
				CurrencyOf::<T>::reactivate(balance);
				Self::contribution_kill(fund.fund_index, &who);
				fund.raised = fund.raised.saturating_sub(balance);
				refund_count += 1;
			}

			// Save the changes.
			Funds::<T>::insert(index, &fund);

			if all_refunded {
				Self::deposit_event(Event::<T>::AllRefunded { para_id: index });
				// Refund for unused refund count.
				Ok(Some(T::WeightInfo::refund(refund_count)).into())
			} else {
				Self::deposit_event(Event::<T>::PartiallyRefunded { para_id: index });
				// No weight to refund since we did not finish the loop.
				Ok(().into())
			}
		}

	/// This function checks all conditions which would qualify a crowdloan has ended.
	/// * If we have reached the `fund.end` block OR the first lease period the fund is trying to
	///   bid for has started already.
	/// * And, if the fund has enough free funds to refund full raised amount.
	fn ensure_crowdloan_ended(
		now: BlockNumberFor<T>,
		fund_account: &T::AccountId,
		fund: &FundInfo<T::AccountId, BalanceOf<T>, BlockNumberFor<T>, LeasePeriodOf<T>>,
	) -> sp_runtime::DispatchResult {
		// `fund.end` can represent the end of a failed crowdloan or the beginning of retirement
		// If the current lease period is past the first period they are trying to bid for, then
		// it is already too late to win the bid.
		let (current_lease_period, _) =
			T::Auctioneer::lease_period_index(now).ok_or(Error::<T>::NoLeasePeriod)?;
		ensure!(
			now >= fund.end || current_lease_period > fund.first_period,
			Error::<T>::FundNotEnded
		);
		// free balance must greater than or equal amount raised, otherwise funds are being used
		// and a bid or lease must be active.
		ensure!(
			CurrencyOf::<T>::free_balance(&fund_account) >= fund.raised,
			Error::<T>::BidOrLeaseActive
		);

		Ok(())
	}
