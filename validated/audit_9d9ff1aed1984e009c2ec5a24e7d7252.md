#No Vulnerability found for this question.

**Analysis supporting this conclusion:**

`result.MessageIndex` is set in `handshake.Machine.completed()` from `m.hs.MessageIndex()` — the underlying noise library's own internal message counter, which only advances on a **successful** `ReadMessage`/`WriteMessage` call within a single `Machine` instance [1](#0-0) . For the only currently-supported pattern, `HandshakeIXPSK0`, this value is deterministically `2` at completion regardless of retries, since IX is a fixed 2-message pattern [2](#0-1) .

Retransmitted/duplicate stage-0 packets don't reach an existing pending `Machine` at all — `HandleIncoming` always routes `MessageCounter == 1` packets to `beginHandshake`, which allocates a *brand-new* `Machine` and produces a fresh, independent `Result` each time [3](#0-2) . Duplicate completions are filtered by exact byte-comparison in `CheckAndComplete` (`ErrAlreadySeen`), before `newConnectionStateFromResult` output is ever installed twice [4](#0-3) .

For continuation packets (stage-2 duplicates), `continueHandshake` re-validates that the pending index entry is still tracked under `hh.Lock()` immediately before calling into the `Machine` [5](#0-4) . Once a handshake completes, `hm.Complete` removes the pending index entry (`hm.unlockedDeleteHostInfo`) before any cached/queued packets are processed, and this happens under the same `hh.Lock` that serializes any concurrent duplicate delivery [6](#0-5) . A duplicate stage-2 packet arriving after completion therefore fails the `cur != hh` / `!ok` check and is dropped without ever reaching the `Machine` a second time, so `MessageIndex` cannot be double-incremented or under/over-counted by replay.

Existing e2e tests (`TestHandshakeRetransmitDuplicate`) confirm the intended behavior: duplicate stage-0 packets are absorbed via `ErrAlreadySeen` and only the cached original response is resent, with the hostmap ending up with exactly one tunnel [7](#0-6) , and `connection_state_test.go` confirms the counter/window seeding matches `MessageIndex` exactly for a normal (non-replayed) run [8](#0-7) .

Since `MessageIndex` is not attacker-influenced wire data but a fixed, pattern-determined count of successful local Noise state transitions, and duplicate/replayed handshake packets are filtered out before they can affect a completing `Machine`, the premised desync between `result.MessageIndex` and actual wire counters is not reachable.

func (hm *HandshakeManager) Complete(hostinfo *HostInfo, f *Interface) {
	hm.mainHostMap.Lock()
	defer hm.mainHostMap.Unlock()
	hm.Lock()
	defer hm.Unlock()

	existingRemoteIndex, found := hm.mainHostMap.RemoteIndexes[hostinfo.remoteIndexId]

		// We have a collision, but this can happen since we can't control
		// the remote ID. Just log about the situation as a note.

			"collision", existingRemoteIndex.vpnAddrs,

	// We need to remove from the pending hostmap first to avoid undoing work when after to the main hostmap.
	hm.unlockedDeleteHostInfo(hostinfo)
	hm.mainHostMap.unlockedAddHostInfo(hostinfo, f)

func TestHandshakeRetransmitDuplicate(t *testing.T) {
	t.Parallel()
	// Verify the responder correctly handles receiving the same msg1 multiple times
	// (retransmission). The duplicate goes through CheckAndComplete -> ErrAlreadySeen
	// and the cached response is resent.

	ca, _, caKey, _ := cert_test.NewTestCaCert(cert.Version1, cert.Curve_CURVE25519, time.Now(), time.Now().Add(10*time.Minute), nil, nil, []string{})
	myControl, myVpnIpNet, myUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "me", "10.128.0.1/24", nil)
	theirControl, theirVpnIpNet, theirUdpAddr, _ := newSimpleServer(cert.Version1, ca, caKey, "them", "10.128.0.2/24", nil)

	myControl.InjectLightHouseAddr(theirVpnIpNet[0].Addr(), theirUdpAddr)
	theirControl.InjectLightHouseAddr(myVpnIpNet[0].Addr(), myUdpAddr)

	myControl.Start()
	theirControl.Start()

	r := router.NewR(t, myControl, theirControl)
	defer r.RenderFlow()

	msg1 := myControl.GetFromUDP(true)

	t.Log("Inject msg1 into them, first time")

	_ = theirControl.GetFromUDP(true)

	t.Log("Verify only one tunnel exists on each side")
	assert.Len(t, myControl.ListHostmapHosts(false), 1)
	assert.Len(t, theirControl.ListHostmapHosts(false), 1)

	myControl.Stop()
	theirControl.Stop()
