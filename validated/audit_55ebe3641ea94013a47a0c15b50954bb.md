### Title
Depositors can front-run bad-debt socialization by redeeming vault shares before the exchange-rate write-down - (File: `mainnet/contracts/vault/v0-vault-usdc.clar`, `mainnet/contracts/market/v0-4-market.clar`)

### Summary
Zest's tokenized lending vaults (`v0-vault-usdc.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdh.clar`, etc.) price `redeem()` using the current `lindex`/`assets` exchange rate, while bad-debt write-downs to that same exchange rate are only applied later, inside `liquidate()`, via `socialize-debt-asset` → `vault-socialize-debt` → `socialize-debt`. Because these are two independent, permissionless transactions, any depositor who observes an under-collateralized position that will produce bad debt can redeem their zTokens at the stale, pre-write-down price before the liquidation transaction lands, shifting the entire loss onto depositors who do not react in time.

### Finding Description
`redeem()` computes the payout with `convert-to-assets-preview`, based on the vault's current share price (`assets`/`lindex` state): [1](#0-0) 

The share price is only marked down when bad debt is socialized. This happens exclusively inside `liquidate()` in the market contract, when a position has no collateral left to seize: [2](#0-1) 

which calls `socialize-debt-asset`: [3](#0-2) 

which in turn calls the vault's `socialize-debt`, the function that actually writes down `lindex` (and therefore every depositor's exchange rate) proportionally to the loss: [4](#0-3) 

The comment on `liquidate-multi` even acknowledges the front-running risk is a known concern for liquidators competing over collateral ("Prevents front-running attacks that prevent bad debt socialization"), but nothing in the vault or market layer prevents a *depositor* (not a liquidator) from redeeming out of the vault before the socialization write-down that this same liquidation will cause: [5](#0-4) 

This is the exact structural analog of the Rio report: in Rio, `RioLRTCoordinator::requestWithdrawal` locks in an exchange rate before an EigenLayer penalty/slashing update (`verifyBalanceUpdates`/`verifyAndProcessWithdrawals`) drops the TVL, letting the withdrawer dodge the loss and pushing it onto remaining LRT holders. Here, `redeem()` locks in the pre-write-down exchange rate before `liquidate()`'s `socialize-debt` marks down `lindex`, letting the redeemer dodge the bad-debt loss and pushing an out-sized (potentially total) share of it onto remaining zToken holders — mirroring the escalation argument in the Rio judging thread (0xmonrel) that the loss is not merely diluted but concentrated among those who fail to front-run.

### Impact Explanation
Any position heading toward zero-collateral liquidation (visible on-chain once oracle price data makes it undercollateralized) signals imminent bad-debt socialization. A depositor (or a bot) watching the mempool/chain state can `redeem()` before the liquidation confirms and receive full underlying value at the stale exchange rate. Because `socialize-debt` reduces `lindex` proportionally to `(debt-reduction / old-total-assets)` across the *remaining* supply of shares only, the loss that should have been spread across all depositors at the time of insolvency is instead concentrated on whoever remains after the front-runner exits — potentially causing remaining depositors to lose a disproportionate, and in extreme cases nearly total, amount of their principal for a comparatively small bad debt amount. This directly reduces the funds at rest of non-front-running depositors — theft of user principal from the perspective of the remaining LPs, since value is transferred from them to the front-runner beyond their fair proportional share.

### Likelihood Explanation
Likelihood is comparable to the original Rio finding: bad debt/insolvent positions are rare edge cases (similar to slashing being rare for validators), but detection is trivial (position health/collateral state and oracle prices are public), and exploiting it requires only a standard `redeem()` call with no special privileges — no flashloan, no DAO/oracle compromise, just an ordinary transaction raced ahead of a pending `liquidate()` call. Any user monitoring undercollateralized positions across the vault's supported assets (`v0-vault-usdc.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdh.clar`, `v0-vault-stx.clar`) can repeat this whenever bad debt is about to be socialized.

### Recommendation
When a liquidation is determined to require bad-debt socialization, account for the write-down retroactively against all shares redeemed during the window between when the position became insolvent (or within the same block/epoch as the triggering liquidation) and when `socialize-debt` executes — e.g., by tracking a pending-loss accrual that is applied atomically before allowing `redeem()` to price out at a rate that has not yet reflected known insolvency, or by requiring `liquidate()` to be able to be triggered in the same atomic step that blocks intervening redemptions once a position is flagged as having zero remaining collateral.

### Proof of Concept
1. A borrower's position becomes undercollateralized such that, upon liquidation, `no-collateral-left` will be true, triggering `bad-debt-socialized` in `v0-4-market.clar` liquidate() (lines 1534-1560).
2. Depositor D (or a bot) observes this on-chain and, before any liquidator's transaction lands, calls the vault's `redeem()` (e.g. `v0-vault-usdc.clar` lines 795-819), receiving `inkind` underlying computed via `convert-to-assets-preview` at the current, not-yet-written-down `lindex`.
3. A liquidator (or another party) then calls `market::liquidate()`, which finds no collateral left, and calls `socialize-debt-asset` → vault `socialize-debt` (lines 946-968), reducing `lindex` proportionally to the bad debt divided by `total-assets` **at that later point**, which excludes D's already-withdrawn assets from the base.
4. Because D exited before the write-down, the remaining depositors absorb a larger proportional loss than they would have if D's shares were still part of `total-assets` when the loss was distributed.

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

            ;; Socialize in vault - pass scaled directly to avoid rounding
            (unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)
            ;; Refresh cache with new indexes post-write-down (lindex decreased)
            (map-set index-cache
                     { timestamp: stacks-block-time, aid: asset-id }
                     (unwrap! (vault-accrue asset-id) failed-status))
            ;; Remove from obligation
            (unwrap! (contract-call? .v0-market-vault
                                      debt-remove-scaled
                                      borrower
                                      scaled-debt
                                      asset-id) failed-status)
          acc)
        ))
