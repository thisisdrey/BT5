### Title
Stale Oracle Price Silently Reused Across Downtime with No Freshness Enforcement on Consumed Value - (File: `substrate/frame/honzon/oracle/src/default_combine_data.rs`, `substrate/frame/honzon/oracle/src/traits.rs`, `substrate/frame/honzon/oracle/src/lib.rs`)

### Summary
`pallet-oracle`'s aggregation logic (`DefaultCombineData`) only filters *incoming raw feed* entries by an `ExpiresIn` window before aggregating them, but if the number of still-fresh raw values falls below `MinimumCount`, it falls back to returning the arbitrarily old `prev_value` unchecked. Worse, the primary consumer-facing interface, `DataProvider::get`, strips the timestamp entirely and returns only the raw value, so any downstream pallet consuming prices through this trait has no way whatsoever to detect that the value it just used is stale. This mirrors the Canto TWAP report's exact broken invariant: a price/data source with no enforced bound on "how much time has passed since the last observation," silently returning outdated data during periods of feeder downtime, DOS, or gas spikes.

### Finding Description
`DefaultCombineData::combine_data` filters the currently submitted raw values by freshness, but explicitly falls back to the previous aggregated value with no freshness check on it: [1](#0-0) 

Note line 46 only retains raw values that are still within `expires_in` of `now`; but line 50-52 returns `prev_value` as-is whenever fewer than `minimum_count` values survive — with no check on how old `prev_value.timestamp` itself is. If oracle operators go offline (network downtime, DOS, extreme gas prices preventing `feed_values` from landing, as described in the external report's attack scenarios), `Values<T,I>` simply keeps returning the last combined value indefinitely, no matter how many blocks or how much wall-clock time has elapsed.

Compounding this, the simple `DataProvider` trait — the interface most likely to be used by price-consuming pallets — discards the timestamp entirely: [2](#0-1) 

and the pallet's own implementation of it: [3](#0-2) 

only `DataProviderExtended::get_all_values` exposes the `TimestampedValue`, but nothing in the pallet enforces that a consumer must check it, and `Pallet::get()` itself performs no staleness gate before returning the stored value: [4](#0-3) 

There is no equivalent of Canto's precedent-setting refusal (e.g., returning `None`/an error when the aggregated value's own age exceeds a bound) applied to the *stored, previously combined* value — only to the incoming raw feed set.

### Impact Explanation
Any downstream consumer configured to read prices via `DataProvider::get` (the documented integration path per the pallet's own README: "other pallets can use the `DataProvider` trait to read the aggregated data") receives a bare value with zero indication of freshness. During a period where oracle operators cannot submit fresh feeds — due to network downtime, an extreme gas spike, or any DOS-style disruption of the kind explicitly described in the external report — `Values<T,I>` continues to serve the last known price unconditionally and forever, with no expiry, no warning flag, and no way for the consuming logic to distinguish a one-block-old price from a price that is thousands of blocks stale. Any lending, collateral-valuation, or liquidation logic built against this `DataProvider` interface inherits the exact TWAP-staleness risk from the source report: an attacker who can anticipate resumed block production after downtime (or simply wait for a large price swing during an outage) can execute against a stale valuation before feeders catch up.

### Likelihood Explanation
This requires no privileged actor, malicious validator, or governance action — it is a direct consequence of normal, unprivileged use of the pallet's public `DataProvider` and `Pallet::get` read paths under a foreseeable operational condition (feeder downtime/network disruption), which the external report itself frames as realistic and already observed in production networks.

### Recommendation
- Store the last-updated timestamp alongside (or embedded in) the value returned by `DataProvider::get`, or change the trait/impl so plain `DataProvider::get` cannot be used for price-sensitive logic without freshness data.
- In `Pallet::get()` / `combined()`, apply the same `ExpiresIn` staleness check to the returned `prev_value` fallback that is already applied to incoming raw values — return `None` (or a distinguishable stale marker) once the last aggregated value exceeds the expiry window, consistent with the existing precedent of refusing unreliable data rather than serving it silently.
- Document and enforce (e.g., via a wrapper adapter) that any pallet consuming oracle data for financial decisions (collateral pricing, liquidations, swaps) must check `TimestampedValue.timestamp` against current `T::Time::now()` before trusting the value.

### Proof of Concept
1. Configure `pallet-oracle` with `MinimumCount = N`, `ExpiresIn = D`.
2. Feed values from `N` operators so `Values::<T>::get(key)` is populated with `TimestampedValue { value: P, timestamp: t0 }`.
3. Simulate operator downtime (network DOS / gas spike / operators stop calling `feed_values`) for a duration `>> D`.
4. Call `Pallet::get(&key)` or `DataProvider::get(&key)` at `now = t0 + 100*D`: the pallet still returns `Some(P)` (or `Some(value=P)` with no timestamp via `DataProvider`), identical to the pre-downtime price, with no error, no `None`, and no staleness signal — exactly the "reserves()/quote() with no awareness of block.timestamp" flaw described in the source report, reproduced here via `combine_data`'s unconditional `prev_value` fallback (`substrate/frame/honzon/oracle/src/default_combine_data.rs:50-52`) and the timestamp-stripping `DataProvider::get` impl (`substrate/frame/honzon/oracle/src/lib.rs:449-452`).

```rust
	fn combine_data(
		_key: &<T as Config<I>>::OracleKey,
		mut values: Vec<TimestampedValueOf<T, I>>,
		prev_value: Option<TimestampedValueOf<T, I>>,
	) -> Option<TimestampedValueOf<T, I>> {
		let expires_in = ExpiresIn::get();
		let now = T::Time::now();

		values.retain(|x| x.timestamp.saturating_add(expires_in) > now);

		let count = values.len() as u32;
		let minimum_count = MinimumCount::get();
		if count < minimum_count || count == 0 {
			return prev_value;
		}

		let mid_index = count / 2;
		// Won't panic as `values` ensured not empty.
		let (_, value, _) =
			values.select_nth_unstable_by(mid_index as usize, |a, b| a.value.cmp(&b.value));
		Some(value.clone())
	}
```
