The reported issue in n8n is an application-level authorization flaw: a multi-tenant workflow platform allows a privileged-but-scoped user to name an arbitrary credential ID belonging to another user/project and have the server decrypt and exfiltrate it, because the destination-credentials-access.ts logic in `packages/cli/src/modules/log-streaming.ee/destinations/destination-credentials-access.ts` never checks that the requesting user owns/has access to the referenced credential before decrypting it.

This bug class requires a multi-tenant credential store with per-user/per-project ownership boundaries and a caller-supplied credential ID that bypasses the ownership check. The Go standard library repository (`Kohvert/go--021`) has no such concept — there is no server-side, multi-tenant credential store analogous to n8n's credential vault.

The closest thing in this repo is the `GOAUTH` credential mechanism in [1](#0-0)  and [2](#0-1) , which populates HTTP request headers with credentials for a given URL. However this is fundamentally different in nature:

- It runs locally under the invoking user's own `go` command process, on the user's own machine, using the user's own `GOAUTH` configuration — there is no separate "owner" whose credential another party could impersonate or steal.
- `loadCredential` matches credentials strictly by URL host+path prefix walking up the hierarchy [3](#0-2) , and `runGitAuth` explicitly validates that the prefix returned by `git credential fill` is a prefix of the requested URL before using it [4](#0-3) , which is exactly the kind of scoping/ownership check that was missing in the n8n case.
- There's no "attacker names credential ID belonging to another user" primitive possible here — credentials are keyed by URL prefix within a single local process's own credential store, not by an ID an unprivileged remote party can reference to reach another tenant's secret.

No unprivileged-attacker-reachable, unfixed analog of "decrypt/disclose another party's stored secret without an ownership check" exists in this repository.

func loadCredential(req *http.Request, rawURL string) bool {
	u, err := url.Parse(rawURL)
	if err != nil {
		return false
	}
	// Match credentials by host and path, excluding userinfo, query, and fragment.
	currentPrefix := u.Host + u.EscapedPath()
	currentPrefix = strings.TrimSuffix(currentPrefix, "/")

	// Iteratively try prefixes, moving up the path hierarchy.
	// E.g. example.com/foo/bar, example.com/foo, example.com
	for {
		headers, ok := credentialCache.Load(currentPrefix)
		if !ok {
			lastSlash := strings.LastIndexByte(currentPrefix, '/')
			if lastSlash == -1 {
				return false
			}
			currentPrefix = currentPrefix[:lastSlash]
			continue
		}
		for key, values := range headers.(http.Header) {
			for _, value := range values {
				req.Header.Add(key, value)
			}
		}
		return true
	}

// 'git credential fill', validates them with a HEAD request
// (using the provided client) and updates the credential helper's cache.
// It returns the matching credential prefix, the http.Header with the
// Basic Authentication header set, or an error.
// The caller must not mutate the header.
func runGitAuth(client *http.Client, dir, url string) (string, http.Header, error) {
	if url == "" {
		// No explicit url was passed, but 'git credential'
		// provides no way to enumerate existing credentials.
		// Wait for a request for a specific url.
		return "", nil, fmt.Errorf("no explicit url was passed")
	}
	if dir == "" {
		// Prevent config-injection attacks by requiring an explicit working directory.
		// See https://golang.org/issue/29230 for details.
		panic("'git' invoked in an arbitrary directory") // this should be caught earlier.
	}
	cmd := exec.Command("git", "credential", "fill")
	cmd.Dir = dir
	cmd.Stdin = strings.NewReader(fmt.Sprintf("url=%s\n", url))
	out, err := cmd.CombinedOutput()
	if err != nil {
		return "", nil, fmt.Errorf("'git credential fill' failed (url=%s): %w\n%s", url, err, out)

	if !strings.HasPrefix(url, parsedPrefix) {
		return "", nil, fmt.Errorf("requested a credential for %s, but 'git credential fill' provided one for %s\n", url, parsedPrefix)
