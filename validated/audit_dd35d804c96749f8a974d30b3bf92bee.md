### Title
Unvalidated `git_object_directory` / `git_alternate_object_directories` fields allow object-directory path escape - ([File: internal/git/alternates/alternates.go])

### Summary
The external report describes `Burve::uniswapV3MintCallback` trusting a caller-supplied address embedded in `data` and using it to move funds without verifying the caller is the legitimate pool. The reachable Gitaly analog is `alternates.Env`, which trusts caller-supplied path fields on the `Repository` protobuf message (`git_object_directory`, `git_alternate_object_directories`) and joins them onto the repository path for *every* Git subprocess Gitaly spawns, without performing the same boundary validation that the equivalent accessor (`localrepo.Repo.ObjectDirectoryPath`) enforces.

### Finding Description
`alternates.Env` builds the `GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variables by blindly joining the repository's on-disk path with the caller-controlled `objectDirectory`/`alternateObjectDirectories` values: [1](#0-0) 

This function is invoked unconditionally for any repository-scoped Git command: [2](#0-1) 

The two fields it consumes are ordinary, client-settable fields on the `Repository` message that is embedded in virtually every RPC request: [3](#0-2) 

By contrast, the codebase already has a "correct" implementation for the same concept — `Repo.ObjectDirectoryPath` — which explicitly calls `storage.ValidateRelativePath` to keep the path inside the storage root, and additionally checks that any path escaping the repo directory matches the expected transaction-quarantine prefix before it is trusted: [4](#0-3) 

`alternates.Env` performs none of these checks — it is the unrestricted counterpart to `ObjectDirectoryPath`, analogous to `uniswapV3MintCallback` trusting a decoded `data` value instead of verifying the caller.

The transaction middleware does add a partial guard, but only for **mutator** RPCs: if `git_object_directory`/`git_alternate_object_directories` are set on a mutator request, it is rejected outright. For **accessor** RPCs, the same fields are allowed through (via `restoreSnapshotRelativePath`) and the request proceeds non-transactionally: [5](#0-4) 

This asymmetry means an ordinary, authenticated gRPC client issuing any accessor RPC can populate `git_object_directory`/`git_alternate_object_directories` with a relative path containing `..` segments. Because `alternates.Env` uses plain `filepath.Join` with no post-join containment check, the resulting `GIT_OBJECT_DIRECTORY` can point outside of the repository — and potentially outside the configured storage — for every Git subprocess spawned to serve that accessor request.

### Impact Explanation
If reachable on an accessor RPC that does not otherwise sanitize these fields, this allows Git subprocesses to read (and in commands that write loose objects, potentially write) objects from/into an attacker-chosen directory outside the intended repository/storage boundary. This is a concrete storage-escape primitive: it can be used to disclose the contents of arbitrary Git object stores on the host filesystem that the Gitaly process can read (e.g., other tenants' repositories or system directories reachable via relative traversal), which is a high-impact information-disclosure/cross-repository-object-access issue in a multi-tenant GitLab/Gitaly deployment.

### Likelihood Explanation
Likelihood is only moderate-to-uncertain because:
- I confirmed the missing validation in `alternates.Env` and its unconditional use in `newCommand`, and confirmed the client-settable nature of the two proto fields.
- I could not, within the available search budget, positively confirm the concrete implementation of `locator.ValidateRepository` (referenced in `middleware.go`) to rule out that it independently sanitizes these fields for accessor RPCs before they reach `alternates.Env`, nor could I enumerate which specific accessor RPC handlers skip any additional field-level sanitization. Absent that confirmation, this should be treated as a probable but not fully proven end-to-end reachable path.

### Recommendation
Route `git_object_directory` / `git_alternate_object_directories` through the same validated path-resolution logic used by `Repo.ObjectDirectoryPath` (i.e., call `storage.ValidateRelativePath` and the quarantine-prefix check) before they are used in `alternates.Env`, for both mutator and accessor RPCs, rather than relying solely on the mutator-only rejection in the transaction middleware.

### Proof of Concept
Conceptual (not verified end-to-end due to tool/time limits): send an accessor RPC (one not rejected by `beginTransactionForRepository`'s mutator check) with a `Repository` message whose `git_alternate_object_directories` is set to a relative path such as `"../../../other-storage/other-repo/objects"`. Trace through `ExecCommandFactory.newCommand` → `alternates.Env` to confirm the resulting `GIT_ALTERNATE_OBJECT_DIRECTORIES` environment variable resolves outside the intended repository, and that a subsequent Git operation (e.g., object lookup) against that repository can read objects from the escaped path.

// Env returns the alternate object directory environment variables.
func Env(repoPath, objectDirectory string, alternateObjectDirectories []string) []string {
	var env []string
	if objectDirectory != "" {
		env = append(env, fmt.Sprintf("GIT_OBJECT_DIRECTORY=%s", filepath.Join(repoPath, objectDirectory)))
	}

	if len(alternateObjectDirectories) > 0 {
		var dirsList []string

		for _, dir := range alternateObjectDirectories {
			dirsList = append(dirsList, filepath.Join(repoPath, dir))
		}

		env = append(env, fmt.Sprintf("GIT_ALTERNATE_OBJECT_DIRECTORIES=%s", strings.Join(dirsList, ":")))
	}

	return env
}

	// Git push may apply an additional layer of quarantine such as `/quarantine/tmp_objdir-incoming-Gbc29N`
	// so we don't assert the `/quarantine` being the last element of the path. We thus also check for
	// whether the parent directory is in `quarantine` and whether the base directory has the expected
	// `tmp_objdir` suffix.

		// a valid path. This may either be a path in the Git repository itself, where it may either
		// point to the main object directory storage or to an object quarantine directory as
