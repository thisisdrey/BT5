Audit Report

## Title
Permanent stake and reward lock in `pallet-asset-rewards` from unbounded `last_update_block` after pool expiry - (File: `substrate/frame/asset-rewards/src/lib.rs`)

## Summary
`update_pool_rewards` unconditionally sets `last_update_block` to the raw current block number instead of clamping it to `expiry_block`, while `reward_per_token` computes `last_block_reward_applicable(pool_info.expiry_block).ensure_sub(pool_info.last_update_block)`. Once any account interacts with an already-expired pool, `last_update_block` becomes greater than `expiry_block`, and every subsequent call to `reward_per_token` underflows via `ensure_sub`, permanently reverting `stake`, `unstake`, `harvest_rewards`, `set_pool_reward_rate_per_block`, and `set_pool_expiry_block` for that pool.

## Finding Description
`update_pool_rewards` sets `new_pool_info.last_update_block = T::BlockNumberProvider::current_block_number();` without capping it against `pool_info.expiry_block`: [1](#0-0) 

`reward_per_token` then computes the elapsed blocks as `last_block_reward_applicable(pool_info.expiry_block).ensure_sub(pool_info.last_update_block)`, where `last_block_reward_applicable` caps at `expiry_block`: [2](#0-1) [3](#0-2) 

Once any account triggers an update after `now > expiry_block`, `last_update_block` is stored as `now`, which is strictly greater than `expiry_block`. On the next call, `last_block_reward_applicable(expiry_block)` returns `expiry_block` (since `now >= expiry_block`), and `expiry_block.ensure_sub(last_update_block)` underflows because `last_update_block > expiry_block`, causing `ensure_sub` to return `Err`, which propagates up via `?` and aborts the extrinsic.

`set_pool_reward_rate_per_block` and `set_pool_expiry_block` both call `Self::reward_per_token(&pool_info)?` using the pool's stored (already-passed) `expiry_block` before applying any new value, so they also fail once the pool is in this state: [4](#0-3) [5](#0-4) 

This confirms there is no privileged or unprivileged code path capable of resetting `last_update_block` back at or below `expiry_block` once it has been advanced past it — `set_pool_expiry_block`, the only function that mutates `expiry_block`, itself calls the failing `reward_per_token` first.

## Impact Explanation
This matches the "permanent user-fund or bridge-state lock" impact category in the Polkadot SDK gate: staked tokens (frozen via `T::AssetsFreezer`) and unharvested reward-asset balances held in the pool's account become permanently unreachable through the pallet's entire mutating call surface (`stake`, `unstake`, `harvest_rewards`, `set_pool_reward_rate_per_block`, `set_pool_expiry_block`) once triggered, with no recovery extrinsic, since `cleanup_pool` requires an empty pool that can never be reached.

## Likelihood Explanation
High and fully unprivileged. The bug is triggered by the ordinary lifecycle event of a pool reaching `expiry_block` combined with a single subsequent interaction. `unstake` and `harvest_rewards` are explicitly permissioned to allow any caller (not just the staker) once `now > pool_info.expiry_block`: [6](#0-5) 
This means any external, unprivileged account can be the one who triggers the state corruption for any staker's position with no special role required, and it requires no timing precision beyond simply waiting past expiry.

## Recommendation
In `update_pool_rewards`, clamp `last_update_block` to `Self::last_block_reward_applicable(pool_info.expiry_block)` (the same capped value used in `reward_per_token`) rather than the raw current block number, ensuring `last_update_block` never exceeds `expiry_block` until it is legitimately extended via `set_pool_expiry_block`.

## Proof of Concept
1. `create_pool` with `expiry_block = E` and `reward_rate_per_block > 0`; staker calls `stake` before `E`.
2. Advance the chain past `E` to `E + k` with no interactions in between.
3. Any account calls `unstake` or `harvest_rewards` for the staker (permitted post-expiry for any caller per the `ensure!(now > pool_info.expiry_block || caller == staker, BadOrigin)` check) — this succeeds and sets stored `last_update_block = E + k`.
4. Any subsequent call to `stake`, `unstake`, `harvest_rewards`, `set_pool_reward_rate_per_block`, or `set_pool_expiry_block` on this pool calls `reward_per_token`, which computes `last_block_reward_applicable(E).ensure_sub(E + k)` = `E.ensure_sub(E + k)`, underflows, and returns `Err`, aborting the extrinsic — including `set_pool_expiry_block`, the only function that could otherwise "fix" the expiry.
5. All staked tokens and unharvested rewards for the pool remain permanently locked with no available recovery path.

	fn set_pool_reward_rate_per_block(
		admin: &T::AccountId,
		pool_id: PoolId,
		new_reward_rate_per_block: T::Balance,
	) -> DispatchResult {
		let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
		ensure!(pool_info.admin == *admin, BadOrigin);
		ensure!(
			new_reward_rate_per_block > pool_info.reward_rate_per_block,
			Error::<T>::RewardRateCut
		);

		// Always start by updating the pool rewards.
		let rewards_per_token = Self::reward_per_token(&pool_info)?;
		let mut pool_info = Self::update_pool_rewards(&pool_info, rewards_per_token)?;

		pool_info.reward_rate_per_block = new_reward_rate_per_block;
		Pools::<T>::insert(pool_id, pool_info);

		Self::deposit_event(Event::PoolRewardRateModified { pool_id, new_reward_rate_per_block });

		Ok(())
	}

	fn set_pool_expiry_block(
		admin: &T::AccountId,
		pool_id: PoolId,
		new_expiry: DispatchTime<BlockNumberFor<T>>,
	) -> DispatchResult {
		let now = T::BlockNumberProvider::current_block_number();
		let new_expiry_block = new_expiry.evaluate(now);
		ensure!(new_expiry_block > now, Error::<T>::ExpiryBlockMustBeInTheFuture);

		let pool_info = Pools::<T>::get(pool_id).ok_or(Error::<T>::NonExistentPool)?;
		ensure!(pool_info.admin == *admin, BadOrigin);
		ensure!(new_expiry_block > pool_info.expiry_block, Error::<T>::ExpiryCut);

		// Always start by updating the pool rewards.
		let reward_per_token = Self::reward_per_token(&pool_info)?;
		let mut pool_info = Self::update_pool_rewards(&pool_info, reward_per_token)?;

		pool_info.expiry_block = new_expiry_block;
		Pools::<T>::insert(pool_id, pool_info);

		Self::deposit_event(Event::PoolExpiryBlockModified { pool_id, new_expiry_block });

		Ok(())
	}
