This is exactly the analogous bug class in Nebula. `pki.disconnect_invalid` is documented as defaulting to `false` when introduced, and even after being flipped to default `true` in a later release, it remains an *optional, disableable* enforcement mechanism — precisely mirroring the "presence of delegate not enforced" pattern: a security-relevant recovery/enforcement check exists but is not mandatory, and its absence (or being turned off) leaves peers trusting expired/invalid credentials indefinitely.

### Title
Tunnels to peers with expired/invalid certificates are kept alive when `pki.disconnect_invalid` is not enabled - (File: connection_manager.go)

### Summary
Nebula's `isInvalidCertificate` check, which is the only mechanism that tears down an established tunnel once the peer's certificate becomes invalid (e.g. expired), is gated entirely behind the optional, user-configurable flag `pki.disconnect_invalid`. If this flag is not set (or explicitly disabled), a tunnel is never disconnected on certificate expiry — only certificate blocklisting forces a teardown. [1](#0-0) 

### Finding Description
`isInvalidCertificate` calls `caPool.VerifyCachedCertificate` and, unless the error is specifically `ErrBlockListed`, only tears down the tunnel `else if cm.intf.disconnectInvalid.Load()`. When that flag is false, the function returns `false` even though the peer certificate is expired or its issuing CA has been removed from the trust pool, and the comment explicitly documents this: "if we reach here, the cert is no longer valid, but we're configured to keep tunnels from now-invalid certs open." [2](#0-1) 

This is directly analogous to the BridgeFacet report: a corrective/enforcement control (there, the delegate; here, `disconnect_invalid`) exists specifically to resolve an unfavorable state (stuck slippage / an expired-but-still-trusted peer credential), but its use is optional and unenforced by the rest of the authentication path. The changelog confirms this was a known, accepted design tradeoff from the moment the feature was introduced: `pki.disconnect_invalid` "will tear down tunnels when they become invalid (through expiry or removal of root trust). Default is `false`." [3](#0-2) 

Even after the default was flipped to `true` in a later release, the release notes flag an operational trap: "If you use SIGHUP to reload certificates without restarting Nebula, you should ensure all of your clients are on 1.7.0 or newer before you enable this feature," implying operators may deliberately turn it back off, re-introducing the exposure. [4](#0-3) 

Importantly, this only guards *already-established* tunnels. The initial handshake path does correctly enforce expiry (`VerifyCertificate`/`VerifyCachedCertificate` failing on `ErrExpired` blocks new handshakes) [5](#0-4) , but once a session exists, an expired certificate keeps working indefinitely if the flag is off.

### Impact Explanation
An attacker who has compromised or extracted a peer's private key/certificate before it expired (or a peer whose certificate is later invalidated because its CA is removed from `pki.ca`/rotated) continues to enjoy a fully trusted, encrypted, and firewalled-per-cert tunnel for as long as the tunnel remains "active" (subject only to `dropInactive`/rehandshake timers), since the only forced-teardown path (blocklisting) requires the operator to know the specific fingerprint to block. This is a medium-risk trust/authorization staleness issue: it doesn't bypass cryptographic authentication of the handshake itself, but it defeats the intended lifecycle/revocation model (expiry-based revocation) for the lifetime of the tunnel when the operator has not opted in to `disconnect_invalid`.

### Likelihood Explanation
This requires no attacker action beyond already possessing a valid (but now-expired, or CA-revoked) certificate and an existing tunnel — exactly the scenario cert expiry/CA rotation is meant to close off. Because the flag defaults differently across versions and is explicitly optional/reloadable, the vulnerable configuration is easy to reach in real deployments (default-off in older versions, or explicitly disabled by an operator in newer ones).

### Recommendation
Make expiry-based teardown of active tunnels unconditional (as blocklisting already is), or at minimum make `pki.disconnect_invalid` non-optional by default with no way to silently disable it, and document prominently that leaving it disabled preserves trust in expired/revoked peer certificates for the life of the tunnel.

### Proof of Concept
1. Configure two Nebula nodes with `pki.disconnect_invalid` unset/false (or a version defaulting to false).
2. Issue peer B a short-lived certificate and establish a tunnel between A and B before it expires.
3. Let B's certificate expire (or remove/rotate B's issuing CA from A's `pki.ca` so `VerifyCachedCertificate` returns a non-blocklist error).
4. Observe via `connection_manager_test.go`'s `Test_NewConnectionManagerTest_DisconnectInvalid` logic that `isInvalidCertificate` returns `false` when `disconnectInvalid` is not set to `true`, and the tunnel between A and B continues carrying traffic indefinitely. [6](#0-5)

// isInvalidCertificate decides if we should destroy a tunnel.
// returns true if pki.disconnect_invalid is true and the certificate is no longer valid.
// Blocklisted certificates will skip the pki.disconnect_invalid check and return true.
func (cm *connectionManager) isInvalidCertificate(now time.Time, hostinfo *HostInfo) bool {
	remoteCert := hostinfo.GetCert()
	if remoteCert == nil {
		return false //don't tear down tunnels for handshakes in progress
	}

	caPool := cm.intf.pki.GetCAPool()
	err := caPool.VerifyCachedCertificate(now, remoteCert)
	if err == nil {
		return false //cert is still valid! yay!
	} else if err == cert.ErrBlockListed { //avoiding errors.Is for speed
		// Block listed certificates should always be disconnected
		hostinfo.logger(cm.l).Info("Remote certificate is blocked, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else if cm.intf.disconnectInvalid.Load() {
		hostinfo.logger(cm.l).Info("Remote certificate is no longer valid, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else {
		//if we reach here, the cert is no longer valid, but we're configured to keep tunnels from now-invalid certs open
		return false
	}
}
