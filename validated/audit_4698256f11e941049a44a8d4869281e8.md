Audit Report

## Title
`control_inherited_account`'s reentrancy filter only blocks direct recovery calls, allowing an inheritor to bypass it by wrapping a `slash_attempt`/config-mutating call inside `pallet_utility::batch` and act with the `recovered` account's signed origin against higher-priority friend groups - (File: `substrate/frame/recovery/src/lib.rs`)

## Summary
`pallet_recovery::control_inherited_account` installs a reentrancy filter on the derived `recovered`-account origin that only inspects whether the *outer* call is a recovery sub-call, via `origin.add_filter(|c| c.is_sub_type().is_none())` [1](#0-0) . Because `Dispatchable::dispatch` on `RuntimeCall` only calls `filter_call` on the top-level call before delegating to `UnfilteredDispatchable::dispatch_bypass_filter` [2](#0-1) , wrapping a `RecoveryCall::slash_attempt` inside `pallet_utility::Call::batch` lets the inner call dispatch under the filtered origin without being re-checked against the guard.

## Finding Description
`control_inherited_account` derives a `Signed(recovered)` origin, attaches a filter intended to block the `inheritor` from re-entering the recovery pallet ("The controller is not allowed to dispatch calls of the recovery pallet...") [3](#0-2) , then calls `call.dispatch(origin)` [4](#0-3) . The generated `Dispatchable::dispatch` implementation for `RuntimeCall` checks `filter_call` only against the top-level `self`, then calls `dispatch_bypass_filter`, which for `pallet_utility::Call::batch` iterates inner calls and dispatches them via `dispatch_bypass_filter` — skipping the filter entirely for nested calls [2](#0-1) . This means an inner `slash_attempt` call nested inside a `Utility::batch` outer call bypasses the guard and executes as the `recovered` account, contradicting the pallet's own stated intent.

## Impact Explanation
This matches the "unauthorized execution or origin escalation" impact category: a security filter meant to prevent the inheritor from mutating recovery state (slashing/cancelling higher-priority friend groups' attempts) is bypassed via a standard, always-available public wrapper (`pallet_utility::batch`). The concrete corrupted state is the higher-priority friend group's pending `ActiveRecoveries`/attempt entry and the initiator's `SecurityDeposit` balance, which get slashed/removed even though the guard was specifically designed to prevent this via `is_sub_type()` filtering.

## Likelihood Explanation
High. No privileged actor is required — only an account that has become `inheritor` for a lower-priority friend group while a higher-priority group's attempt is pending. `pallet_utility` is a standard pallet included in virtually all polkadot-sdk runtimes, and `batch`/`batch_all`/`force_batch` are public, unprivileged extrinsics [5](#0-4) . The repository already contains a dedicated regression test (`inheritor_cannot_bypass_filter_via_utility_batch`) built to `panic!` specifically on this bypass, confirming this is a recognized, real, and exploitable behavior rather than theoretical [6](#0-5) .

## Recommendation
Make the reentrancy guard robust against nested/wrapped dispatch rather than relying solely on top-level `filter_call`:
- Recursively unwrap known wrapper calls (`Utility::batch`/`batch_all`/`force_batch`, `Proxy`, `Multisig`) and apply the same `is_sub_type` check to each nested call before allowing dispatch.
- Alternatively, ensure nested dispatch paths (e.g. `Utility::batch`) re-consult the origin's active call filter for each inner call instead of using `dispatch_bypass_filter`, or explicitly reject `Utility`/`Multisig`/`Proxy` pallet calls in the reentrancy filter in addition to recovery sub-calls.

## Proof of Concept
The existing test in the repository fully reproduces this: ALICE configures two friend groups (`family`, priority 0, inheritor DAVE; `friends_group`, priority 1, inheritor FERDIE). `friends_group` completes recovery first, making FERDIE the inheritor. `family` (BOB) then initiates its higher-priority attempt. FERDIE calls `control_inherited_account` with a `Utility::batch` outer call wrapping an inner `RecoveryCall::slash_attempt { friend_group_index: 0 }`. The outer call passes `filter_call` (it's `Utility::batch`, not a recovery sub-call), and the inner `slash_attempt` executes via `dispatch_bypass_filter`, slashing BOB's `SecurityDeposit` and destroying the higher-priority pending attempt [6](#0-5) .

/// Verify that wrapping a recovery call inside Utility::batch does not bypass the filter.
#[test]
fn inheritor_cannot_bypass_filter_via_utility_batch() {
	new_test_ext().execute_with(|| {
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE,
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE,
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// Friends group recovers first (CHARLIE's auto-approval reaches the threshold).
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// Family initiates higher-priority attempt
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// FERDIE wraps the slash inside a utility::batch call to try to bypass the filter
		let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
		let batch_call: RuntimeCall =
			pallet_utility::Call::batch { calls: vec![slash_call] }.into();
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(batch_call),
		));

		// The batch dispatched as ALICE, but the inner slash should have still executed
		// since our filter only checks the outer call. Check if BOB was slashed:
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		let was_slashed = bob_balance_after < bob_balance_before;

		if was_slashed {
			panic!(
				"BYPASS: recovery call filter was circumvented via utility::batch! \
				 BOB lost {} from security deposit slash.",
				bob_balance_before - bob_balance_after
			);
		}
	});
}
