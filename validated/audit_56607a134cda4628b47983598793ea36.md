Audit Report

## Title
Unbacked relayer reward: `relayer_fee` is a self-declared field trusted without any cross-check against transferred value - (File: bridges/snowbridge/pallets/inbound-queue-v2/src/lib.rs)

## Summary
`Pallet::process_message` credits `message.relayer_fee` verbatim to the submitting relayer via `T::RewardPayment::register_reward`, and this field is decoded straight out of the untrusted `OutboundMessageAccepted` Ethereum event payload with no comparison to `message.value`, the actual reserved/bridged assets, or any other economically-bound quantity in the same message. [1](#0-0)  The registered reward is later paid out as real, backed value from the bridge's rewards/sovereign account on the destination chain (as shown by `PayRewardFromAccount::pay_reward` performing an actual balance transfer, and the integration test `claim_rewards_works` showing a real `pallet_assets::Deposited` payout on AssetHub), meaning an inflated `relayer_fee` translates into an unbacked drain of real bridge funds rather than a purely cosmetic number. [2](#0-1) 

## Finding Description
`Message::try_from` decodes `relayer_fee` directly from the Solidity event payload (`event_payload.relayerFee`), a field that is entirely attacker-controlled by whoever calls the Gateway's `v2_sendMessage`/`v2_registerToken` on Ethereum. [3](#0-2) 

`process_message` verifies the gateway address and nonce (replay protection), dispatches the message via `MessageProcessor`, and then unconditionally pays `relayer_fee.saturating_add(tip)` to the relayer through `T::RewardPayment::register_reward` — there is no check relating `relayer_fee` to `message.value`, to the assets actually reserved/withdrawn for the message, or to any escrowed amount. [4](#0-3) 

The XCM conversion path only turns `message.value` and `message.execution_fee` into real reserve/pay-fees instructions — `relayer_fee` never participates in the asset-moving side of the bridge at all, confirming it is a free-standing, unvalidated number. [5](#0-4) 

The registered reward is not inert bookkeping: `register_relayer_reward` stores it in `RelayerRewards`, and `do_claim_rewards` → `T::PaymentProcedure::pay_reward` executes a real `fungible::Mutate::transfer` from a bridge-controlled rewards account to the relayer/beneficiary. [6](#0-5) [7](#0-6)  The Snowbridge integration test confirms this results in an actual `ForeignAssets::Deposited` payout of `eth_location()` tokens on AssetHub when claimed. [8](#0-7) 

The unit test `relayer_fee_paid_out_when_no_tip_exists` explicitly demonstrates that `relayer_fee` is paid out exactly as supplied in the `Message` struct regardless of `value`, with no cross-check performed anywhere in the pallet. [9](#0-8) 

The only authenticity check performed is `T::Verifier::verify`, which proves the log is a genuine Ethereum event, but says nothing about whether the *contents* of that log (specifically `relayerFee`) are economically consistent with `value`. Whether the off-repo Solidity `Gateway` contract itself enforces `msg.value >= relayerFee + executionFee + Σassets` before it ever emits the event cannot be verified from this repository — no Solidity Gateway contract source exists in this indexed codebase to confirm or refute that invariant is enforced upstream.

## Impact Explanation
If the Ethereum-side Gateway contract does not itself bound `relayerFee` by the value actually locked in the same call (a fact not verifiable in-repo), an unprivileged Ethereum account could set an arbitrarily large `relayerFee` while transferring minimal real value, and any relayer submitting the resulting proof would receive a real, bridge-funded payout via `pallet_bridge_relayers`, draining the bridge's rewards/sovereign account. This matches the "theft or unbacked mint or unlock" impact class in principle, since the corrupted value is `message.relayer_fee` credited via `register_reward`/`RelayerRewards` without being bound to `message.value`.

## Likelihood Explanation
Likelihood is **unknown from this repository** because the critical control point — whether the Solidity `Gateway` contract enforces `msg.value >= relayerFee + executionFee + Σassets` at the time the event is emitted — lives in the Snowbridge Ethereum contracts, which are not present in this indexed codebase (no `*.sol` Gateway source was found). The Substrate-side code performs no defense-in-depth check, but per the review rules, this claim's exploitability hinges entirely on off-repo contract behavior that cannot be confirmed or refuted here. If the invariant is enforced at message-creation time on Ethereum (which is the documented intent — "This wrapped Ether is derived from Ether that the message origin has locked up on Ethereum" per the pallet's own doc comment), then by the time the event is authenticated via beacon/receipt proof, `relayer_fee` is already backed, and there is no exploit path purely within this repository's Rust code.

## Recommendation
Since the enforcement point is off-repo and unverifiable, this cannot be confirmed as an exploitable defect within the scoped polkadot-sdk/Snowbridge Substrate code; it is a design assumption tied to Ethereum-side contract logic outside the audited repository.

## Proof of Concept
Not reproducible within this repository: the described attack path (calling `v2_sendMessage`/`v2_registerToken` with an inflated `relayerFee` disproportionate to `value`) depends on the behavior of the off-repo Solidity `Gateway` contract, which is not present in this codebase to test or confirm. The cited unit test `relayer_fee_paid_out_when_no_tip_exists` only demonstrates the pallet's internal, expected behavior given an already-validated `Message` — it does not demonstrate that an attacker can produce such a message through the real Ethereum Gateway without matching `value`.

		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

		fn do_claim_rewards(
			relayer: T::AccountId,
			reward_kind: T::Reward,
			beneficiary: BeneficiaryOf<T, I>,
		) -> DispatchResult {
			RelayerRewards::<T, I>::try_mutate_exists(
				&relayer,
				reward_kind,
				|maybe_reward| -> DispatchResult {
					let reward_balance =
						maybe_reward.take().ok_or(Error::<T, I>::NoRewardForRelayer)?;
					T::PaymentProcedure::pay_reward(
						&relayer,
						reward_kind,
						reward_balance,
						beneficiary.clone(),
					)
					.map_err(|e| {
						tracing::error!(
							target: LOG_TARGET,
							error=?e,
							?relayer,
							?reward_kind,
							?reward_balance,
							?beneficiary,
							"Failed to pay rewards"
						);
						Error::<T, I>::FailedToPayReward
					})?;

					Self::deposit_event(Event::<T, I>::RewardPaid {
						relayer: relayer.clone(),
						reward_kind,
						reward_balance,
						beneficiary,
					});
					Ok(())
				},
			)

#[test]
fn claim_rewards_works() {
	let assethub_location = BridgeHubWestend::sibling_location_of(AssetHubWestend::para_id());
	let assethub_sovereign = BridgeHubWestend::sovereign_account_id_of(assethub_location);

	let relayer_account = BridgeHubWestendSender::get();
	let reward_address = AssetHubWestendReceiver::get();

	BridgeHubWestend::fund_accounts(vec![
		(assethub_sovereign.clone(), INITIAL_FUND),
		(relayer_account.clone(), INITIAL_FUND),
	]);
	set_up_eth_and_dot_pool();

	BridgeHubWestend::execute_with(|| {
		type RuntimeEvent = <BridgeHubWestend as Chain>::RuntimeEvent;
		type RuntimeOrigin = <BridgeHubWestend as Chain>::RuntimeOrigin;
		let reward_amount = ETHER_MIN_BALANCE * 2; // Reward should be more than Ether min balance

		type BridgeRelayers = <BridgeHubWestend as BridgeHubWestendPallet>::BridgeRelayers;
		BridgeRelayers::register_reward(
			(&relayer_account.clone()).into(),
			BridgeReward::Snowbridge,
			reward_amount,
		);

		// Check that the reward was registered.
		assert_expected_events!(
			BridgeHubWestend,
			vec![
				RuntimeEvent::BridgeRelayers(pallet_bridge_relayers::Event::RewardRegistered { relayer, reward_kind, reward_balance }) => {
					relayer: *relayer == relayer_account,
					reward_kind: *reward_kind == BridgeReward::Snowbridge,
					reward_balance: *reward_balance == reward_amount,
				},
			]
		);

		let relayer_location = Location::new(
			0,
			[Junction::AccountId32 { id: reward_address.clone().into(), network: None }],
		);
		let reward_beneficiary =
			BridgeRewardBeneficiaries::AssetHubLocation(VersionedLocation::V5(relayer_location));
		let result = BridgeRelayers::claim_rewards_to(
			RuntimeOrigin::signed(relayer_account.clone()),
			BridgeReward::Snowbridge,
			reward_beneficiary.clone(),
		);
		assert_ok!(result);

		assert_expected_events!(
			BridgeHubWestend,
			vec![
				// Check that the pay reward event was emitted on BH
				RuntimeEvent::BridgeRelayers(pallet_bridge_relayers::Event::RewardPaid { relayer, reward_kind, reward_balance, beneficiary }) => {
					relayer: *relayer == relayer_account,
					reward_kind: *reward_kind == BridgeReward::Snowbridge,
					reward_balance: *reward_balance == reward_amount,
					beneficiary: *beneficiary == reward_beneficiary,
				},
			]
		);
	});

					asset_id: *asset_id == eth_location(),
					owner: *owner == reward_address.clone().into(),
				},
			]
		);
	})

#[test]
fn relayer_fee_paid_out_when_no_tip_exists() {
	new_tester().execute_with(|| {
		let nonce: u64 = 88;
		let relayer_fee: u128 = 5_000;

		// Ensure no tip exists for this nonce
		assert_eq!(Tips::<Test>::get(nonce), None);

		// Process inbound message with relayer_fee but no tip
		let relayer: AccountId = Keyring::Bob.into();
		assert_ok!(InboundQueue::process_message(
			relayer,
			Message {
				nonce,
				assets: vec![],
				payload: Payload::Raw(vec![]),
				claimer: None,
				execution_fee: 1_000_000_000,
				relayer_fee,
				gateway: mock::GatewayAddress::get(),
				origin: H160::random(),
				value: 3_000_000_000,
			},
		));

		// Relayer fee should be paid out even without tip
		assert_eq!(
			RegisteredRewardsCount::get(),
			1,
			"Relayer fee should be paid out even when no tip exists"
		);

		// Check the actual reward amount paid out
		assert_eq!(
			RegisteredRewardAmount::get(),
			relayer_fee,
			"Reward amount should equal relayer_fee when no tip exists"
		);
