Audit Report

## Title
Outbound Queue V2 accepts zero/near-zero relayer fee messages, enabling underpriced spam of the Snowbridge outbound pipeline - (File: `bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs`)

## Summary
The V2 Snowbridge outbound pipeline accepts and processes messages with an arbitrary (including zero) `fee` value, unlike V1 which enforces `PricingParameters::validate()` requiring non-zero rewards. This allows unprivileged callers to fill `PendingOrders`, `MessageLeaves`, and `Messages` storage with permanently undeliverable, zero-cost entries, consuming Bridge Hub block resources every block.

## Finding Description
The V2 `Message` fee originates from the XCM `PayFees` instruction and is extracted by `XcmConverter::extract_remote_fee` in `bridges/snowbridge/primitives/outbound-queue/src/v2/converter/convert.rs` (L95-117). That function only checks that the fee asset ID is Ether/Here (`ensure!(fee_asset_id.0 == Here.into(), InvalidFeeAsset)`, L113) and that `reserved_fee_amount >= fee_amount` (L115) — it never checks `fee_amount > 0` or against any floor, unlike sibling code such as `extract_ethereum_native_assets`/`extract_polkadot_native_assets` which do enforce `ensure!(amount > 0, ZeroAssetTransfer)` (L149, L176) for transferred asset amounts.

`SendMessage::validate` in `bridges/snowbridge/pallets/outbound-queue-v2/src/send_message_impl.rs` (L23-32) only checks payload size, not fee magnitude.

`Pallet::do_process_message` in `bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs` (L343-443) decodes the `Message` including `fee`, unconditionally appends the message hash to `MessageLeaves` (committed into the header digest via `commit()`, L322-339) and creates a `PendingOrder { nonce, fee, block_number }` (L431-436) with no check that `fee` is non-zero or economically meaningful. The reward is only ever paid in `process_delivery_receipt` (L446-480), where `if order.fee > 0` gates payment — confirming the pallet's own logic anticipates `fee == 0` as a valid, reachable state rather than rejecting it.

The design document `bridges/snowbridge/docs/v2.md` (L99-102) explicitly states a minimum relayer reward (equal to the existential deposit) should be imposed "to stop spamming messages with 0 rewards" — an acknowledged requirement that is not implemented anywhere in the reviewed V2 code path (`convert.rs`, `send_message_impl.rs`, or `do_process_message`).

## Impact Explanation
An attacker with any XCM-send capability reaching Bridge Hub's `ExportMessage` (e.g., via Asset Hub) can attach `PayFees(WETH, 0)` (or 1 wei) and have the message accepted, hashed into the per-block committed merkle root, and stored as a `PendingOrder` that no rational relayer will ever claim via `submit_delivery_receipt`. Repeating this up to `MaxMessagesPerBlock` consumes real chain resources (weight, `MessageLeaves`/`Messages` storage, `commit()` merkle computation) each block for negligible/zero cost, crowds out legitimately-priced messages competing for the same fixed per-block budget, and leaves `PendingOrders` permanently populated with unclaimable entries. This matches the allowed impact category "public underpriced work that degrades block production or stalls bridge processing."

## Likelihood Explanation
No privileged access is required — any account capable of routing an XCM through the standard V2 message pattern (`WithdrawAsset(ETH)`, `PayFees(ETH, epsilon)`, asset transfer, `AliasOrigin`, `DepositAsset`, `SetTopic`) to Bridge Hub can trigger this repeatedly, bounded only by `MaxMessagesPerBlock` and available payload/weight budget, making it a highly repeatable, low-cost griefing vector.

## Recommendation
Enforce a minimum fee/reward — e.g., an existential-deposit-equivalent floor in WETH as specified in `bridges/snowbridge/docs/v2.md` — either in `XcmConverter::extract_remote_fee` (`convert.rs`), or in `SendMessage::validate` / `do_process_message` in `outbound-queue-v2`, rejecting messages whose `fee` is below the floor, mirroring the non-zero-reward invariant enforced by `PricingParameters::validate` in V1.

## Proof of Concept
1. Construct a V2-pattern XCM: `WithdrawAsset(ETH, 1)`, `PayFees(ETH, 1)`, `WithdrawAsset(ENA, amount)`, `AliasOrigin(origin)`, `DepositAsset(...)`, `SetTopic(topic)`.
2. Route it via `pallet_xcm::send`/`execute` from an authorized origin through Asset Hub to Bridge Hub's `ExportMessage`.
3. `XcmConverter::convert`/`extract_remote_fee` accepts it since it only checks asset ID, not amount (`convert.rs` L106-117).
4. `SendMessage::validate` accepts it (size-only check).
5. `do_process_message` enqueues the message, appends the hash to `MessageLeaves`, and inserts `PendingOrder { fee: 1, ... }` into `PendingOrders`.
6. Repeat up to `MaxMessagesPerBlock` per block; no relayer calls `submit_delivery_receipt` for these since it's unprofitable, so entries remain in `PendingOrders` indefinitely while consuming block weight/storage each block. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

```rust
	fn extract_remote_fee(&mut self) -> Result<u128, XcmConverterError> {
		use XcmConverterError::*;
		let reserved_fee_assets = match_expression!(self.next()?, WithdrawAsset(fee), fee)
			.ok_or(WithdrawAssetExpected)?;
		ensure!(reserved_fee_assets.len() == 1, AssetResolutionFailed);
		let reserved_fee_asset =
			reserved_fee_assets.inner().first().cloned().ok_or(AssetResolutionFailed)?;
		let (reserved_fee_asset_id, reserved_fee_amount) = match reserved_fee_asset {
			Asset { id: asset_id, fun: Fungible(amount) } => Ok((asset_id, amount)),
			_ => Err(AssetResolutionFailed),
		}?;
		let fee_asset =
			match_expression!(self.next()?, PayFees { asset: fee }, fee).ok_or(InvalidFeeAsset)?;
		let (fee_asset_id, fee_amount) = match fee_asset {
			Asset { id: asset_id, fun: Fungible(amount) } => Ok((asset_id, *amount)),
			_ => Err(AssetResolutionFailed),
		}?;
		// Check the fee asset is Ether (XCM is evaluated in Ethereum context).
		ensure!(fee_asset_id.0 == Here.into(), InvalidFeeAsset);
		ensure!(reserved_fee_asset_id.0 == Here.into(), InvalidFeeAsset);
		ensure!(reserved_fee_amount >= fee_amount, InvalidFeeAsset);
		Ok(fee_amount)
	}
```

```rust
		pub(crate) fn do_process_message(
			_: ProcessMessageOriginOf<T>,
			mut message: &[u8],
		) -> Result<bool, ProcessMessageError> {
			use ProcessMessageError::*;

			// Yield if the maximum number of messages has been processed this block.
			// This ensures that the weight of `on_finalize` has a known maximum bound.
			let current_len = MessageLeaves::<T>::decode_len().unwrap_or(0);
			if current_len >= T::MaxMessagesPerBlock::get() as usize {
				Self::deposit_event(Event::MessagePostponed {
					payload: message.to_vec(),
					reason: Yield,
				});
				return Err(Yield);
			}

			// Decode bytes into Message
			let Message { origin, id, fee, commands } =
				Message::decode(&mut message).map_err(|_| {
					Self::deposit_event(Event::MessageRejected {
						id: None,
						payload: message.to_vec(),
						error: Corrupt,
					});
					Corrupt
				})?;

			// Convert it to OutboundMessage and save into Messages storage
			let commands: Vec<OutboundCommandWrapper> = commands
				.into_iter()
				.map(|command| OutboundCommandWrapper {
					kind: command.index(),
					gas: T::GasMeter::maximum_dispatch_gas_used_at_most(&command),
					payload: command.abi_encode(),
				})
				.collect();

			let nonce = <Nonce<T>>::get().checked_add(1).ok_or_else(|| {
				Self::deposit_event(Event::MessageRejected {
					id: None,
					payload: message.to_vec(),
					error: Unsupported,
				});
				Unsupported
			})?;

			let outbound_message = OutboundMessage {
				origin,
				nonce,
				topic: id,
				commands: commands.clone().try_into().map_err(|_| {
					Self::deposit_event(Event::MessageRejected {
						id: Some(id),
						payload: message.to_vec(),
						error: Corrupt,
					});
					Corrupt
				})?,
			};
			Messages::<T>::append(outbound_message);

			// Convert it to an OutboundMessageWrapper (in ABI format), hash it using Keccak256 to
			// generate a committed hash, and store it in MessageLeaves storage which can be
			// verified on Ethereum later.
			let abi_commands: Vec<CommandWrapper> = commands
				.into_iter()
				.map(|command| CommandWrapper {
					kind: command.kind,
					gas: command.gas,
					payload: Bytes::from(command.payload),
				})
				.collect();
			let committed_message = OutboundMessageWrapper {
				origin: FixedBytes::from(origin.as_fixed_bytes()),
				nonce,
				topic: FixedBytes::from(id.as_fixed_bytes()),
				commands: abi_commands,
			};
			let message_abi_encoded_hash =
				<T as Config>::Hashing::hash(&committed_message.abi_encode());
			MessageLeaves::<T>::append(message_abi_encoded_hash);

			// Generate `PendingOrder` with fee attached in the message, stored
			// into the `PendingOrders` map storage, with assigned nonce as the key.
			// When the message is processed on ethereum side, the relayer will send the nonce
			// back with delivery proof, only after that the order can
			// be resolved and the fee will be rewarded to the relayer.
			let order = PendingOrder {
				nonce,
				fee,
				block_number: frame_system::Pallet::<T>::current_block_number(),
			};
			<PendingOrders<T>>::insert(nonce, order);

			<Nonce<T>>::set(nonce);

			Self::deposit_event(Event::MessageAccepted { id, nonce });

			Ok(true)
		}
```

```rust
		pub fn process_delivery_receipt(
			relayer: <T as frame_system::Config>::AccountId,
			receipt: DeliveryReceipt,
		) -> DispatchResult
		where
			<T as frame_system::Config>::AccountId: From<[u8; 32]>,
		{
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == receipt.gateway, Error::<T>::InvalidGateway);

			let reward_account = if receipt.reward_address == [0u8; 32] {
				relayer
			} else {
				receipt.reward_address.into()
			};

			let nonce = receipt.nonce;

			let order = <PendingOrders<T>>::get(nonce).ok_or(Error::<T>::InvalidPendingNonce)?;

			if order.fee > 0 {
				// Pay relayer reward
				T::RewardPayment::register_reward(
					&reward_account,
					T::DefaultRewardKind::get(),
					order.fee,
				);
			}

			<PendingOrders<T>>::remove(nonce);

			Self::deposit_event(Event::MessageDelivered { nonce });

			Ok(())
		}
```
