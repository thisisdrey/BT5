## Title
Unprotected first-caller initialization of the global `FeeState` PDA allows permanent hijack of protocol fee admin - (File: `programs/marginfi/src/instructions/marginfi_group/init_global_fee_state.rs`)

### Summary
`init_global_fee_state` initializes the program-wide singleton `FeeState` PDA (seeded only by `FEE_STATE_SEED`, i.e. one instance for the entire program) and sets `global_fee_admin` and `global_fee_wallet` directly from caller-supplied arguments, with no check that the caller is the deployer/authority. [1](#0-0)  The account struct only requires a generic `Signer` as `payer`; there is no admin allowlist, program-upgrade-authority check, or any other access control. [2](#0-1)  This mirrors the reported bug class: an implementation/singleton state object that is meant to be initialized exactly once by a trusted party, but is actually initializable by anyone in a race against the legitimate initializer.

### Finding Description
`FeeState` is derived from a fixed seed with no per-caller component:
```rust
seeds = [FEE_STATE_SEED.as_bytes()],
```
so there is exactly one `FeeState` PDA for the whole deployed program, and Anchor's `init` constraint means whoever's transaction lands first succeeds; every subsequent attempt (including the legitimate deployer's) fails with "already in use". [3](#0-2) 

The instruction handler blindly trusts the caller-supplied `admin_key`/`fee_wallet` and all fee parameters:
```rust
let mut fee_state = ctx.accounts.fee_state.load_init()?;
fee_state.global_fee_admin = admin_key;
fee_state.global_fee_wallet = fee_wallet;
...
``` [4](#0-3) 

There is no `close_fee_state` or equivalent recovery instruction anywhere in the codebase, so if an attacker wins the initialization race, the state is permanent and unrecoverable. From that point on:
- `global_fee_admin` is the attacker's key, who alone can call `edit_global_fee_state` to set arbitrary fees, redirect `global_fee_wallet`, or set a `pause_delegate_admin`. [5](#0-4) 
- Every `MarginfiGroup` created afterwards reads `fee_state.global_fee_wallet`/fees directly from this attacker-controlled PDA into its `fee_state_cache` at group-init time, meaning all program fees for every future group flow to the attacker's wallet. [6](#0-5) 

This is functionally identical to the reported analog: the "implementation"-equivalent singleton in marginfi (the global fee state) can be initialized by anyone, and the resulting corrupted/hostile state propagates to every downstream user of that singleton (every group, bank, and fee/liquidation flow), with no path to remediate.

### Impact Explanation
An unprivileged attacker who front-runs the deployer's `init_global_fee_state` call becomes the permanent `global_fee_admin` and can:
- Redirect all protocol-wide SOL/program fees (bank-init fees, liquidation flat fees, order-init fees, program fee fixed/rate, liquidation/order max fees) to a wallet they control.
- Set `pause_delegate_admin` to themselves, gaining the ability to pause the protocol.
- Cause the legitimate team's own `init_global_fee_state` transaction to permanently fail, since the PDA can never be closed/reinitialized.

This is a fund-diversion (fee theft) and irrecoverable state-hijack vulnerability affecting every group and bank created under the program, satisfying the "unauthorized state change" / "theft" criteria.

### Likelihood Explanation
This is a front-running/race condition exploitable immediately after program deployment and before the legitimate initialization transaction confirms. It requires only observing (or guessing) the deployment and submitting a competing transaction with a higher priority fee — a standard MEV/front-running technique on Solana. No special privileges, insider access, or complex preconditions are required.

### Recommendation
Restrict `init_global_fee_state` to a trusted key, e.g., require the signer to match the program's upgrade authority (via `bpf_loader_upgradeable` program-data check) or a hardcoded/known deployer pubkey, rather than accepting an arbitrary `admin_key` argument from any signer. Alternatively, gate this instruction so it can only be invoked once by the deploy script in the same transaction bundle as program deployment (e.g., via a CPI-only or same-transaction guard), and add a `close_fee_state`/`reset_fee_state` recovery path callable by the program's true upgrade authority in case of a takeover attempt.

### Proof of Concept
1. Deployer deploys the marginfi program.
2. Before the deployer submits `init_global_fee_state(admin=deployer, fee_wallet=deployer_wallet, ...)`, an attacker observes the deployment and submits their own `init_global_fee_state(admin=attacker, fee_wallet=attacker_wallet, program_fee_rate=high_value, ...)` with a higher priority fee.
3. The attacker's transaction lands first; the `FeeState` PDA is now initialized with `global_fee_admin = attacker` and `global_fee_wallet = attacker_wallet`. [4](#0-3) 
4. The deployer's original transaction fails ("already in use") since the PDA seed only depends on `FEE_STATE_SEED`.
5. Every subsequent `marginfi_group_initialize` call caches the attacker's fee wallet/rates into each group's `fee_state_cache`, routing protocol fees to the attacker indefinitely, with no instruction available to close or reset the PDA. [6](#0-5)

// Runs once per program to init the global fee state.
use anchor_lang::prelude::*;
use marginfi_type_crate::{
    constants::FEE_STATE_SEED,
    types::{FeeState, WrappedI80F48},
};

#[allow(unused_variables)]
pub fn initialize_fee_state(
    ctx: Context<InitFeeState>,
    admin_key: Pubkey,
    fee_wallet: Pubkey,
    bank_init_flat_sol_fee: u32,
    liquidation_flat_sol_fee: u32,
    order_init_flat_sol_fee: u32,
    program_fee_fixed: WrappedI80F48,
    program_fee_rate: WrappedI80F48,
    liquidation_max_fee: WrappedI80F48,
    order_execution_max_fee: WrappedI80F48,
) -> Result<()> {
    let mut fee_state = ctx.accounts.fee_state.load_init()?;
    fee_state.global_fee_admin = admin_key;
    fee_state.global_fee_wallet = fee_wallet;
    fee_state.key = ctx.accounts.fee_state.key();
    fee_state.bank_init_flat_sol_fee = bank_init_flat_sol_fee;
    fee_state.bump_seed = ctx.bumps.fee_state;
    fee_state.program_fee_fixed = program_fee_fixed;
    fee_state.program_fee_rate = program_fee_rate;
    fee_state.liquidation_max_fee = liquidation_max_fee;
    fee_state.liquidation_flat_sol_fee = liquidation_flat_sol_fee;
    fee_state.order_execution_max_fee = order_execution_max_fee;
    fee_state.order_init_flat_sol_fee = order_init_flat_sol_fee;

    Ok(())
}
