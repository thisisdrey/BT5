### Title
Object pool linking accepts an unrelated pool repository without verifying fork/origin relationship, enabling cross-repository object disclosure - (File: internal/gitaly/service/objectpool/link.go)

### Summary
`LinkRepositoryToObjectPool` mirrors the `ReferralFeeReceiver` bug class: it trusts a caller-supplied "pool" reference (the `object_pool` field) without verifying that it was actually derived from ("deployed by") the target repository's own fork network, just as `ReferralFeeReceiver` trusted a caller-supplied `mooniswap` address without verifying it came from the trusted `MooniswapFactory`.

### Finding Description
`LinkRepositoryToObjectPool` resolves the pool purely from the client-supplied `ObjectPool.Repository` proto field via `poolForRequest`/`objectpool.FromProto`, which only checks two shallow properties: that the path exists on disk (`locator.GetRepoPath`) and that it matches a naming-pattern regex, `storage.IsPoolRepository`, implemented by `IsRailsPoolRepository`/`IsPraefectPoolRepository` in [1](#0-0) , plus `IsValid` which only checks the path is a valid git repository [2](#0-1) . None of these checks establish that the pool was actually created from ("belongs to") the specific repository being linked — there is no cryptographic or structural binding between a pool and its intended origin repository, analogous to the missing "deployed by factory" check in the report.

`Link` then simply writes whatever pool path it resolved into the target repository's `objects/info/alternates` file [3](#0-2) , and the RPC handler performs no additional authorization against project/fork relationships [4](#0-3) . Once linked, Git object lookups against the target repository transparently resolve OIDs through the alternates object directory, so any object present in the pool (e.g., objects from the pool's original source repository, added via `CreateObjectPool`'s clone step [5](#0-4)  or later `FetchIntoObjectPool` updates) becomes reachable by SHA from the linked repository, even without any ref pointing to it, exactly like `_transferTokenShare` in the report which paid out attacker-requested tokens regardless of whether those tokens were the ones originally frozen.

### Impact Explanation
If a caller is able to invoke `LinkRepositoryToObjectPool` supplying an `object_pool` value pointing at a pool that was created from a repository the caller does not control (but that matches the pool path/naming convention and exists on the same storage), the caller's own repository becomes an alternate-object consumer of that pool. Any Gitaly RPC that resolves objects by OID (e.g., blob/commit/tree retrieval) rather than by ref reachability will then serve objects belonging to the unrelated source repository through the attacker-linked repository, resulting in cross-repository object disclosure of potentially private repository contents — the concrete "cross-repository object access" outcome called out as acceptable impact in this scan's Validate criteria.

### Likelihood Explanation
Exploitation requires only a single crafted RPC field (`object_pool.repository`) in `LinkRepositoryToObjectPoolRequest`; no privileged or out-of-band access to the pool's storage is required beyond knowing/guessing a valid pool relative path, which follows a predictable/derivable naming scheme (`@pools/<hh>/<hh>/<sha256>.git` or the Praefect-derived `@cluster/pools/...` format built from the pool repository's ID). Whether this is fully exploitable in production depends on whether the calling layer (e.g., GitLab Rails) independently enforces the fork/pool membership relationship before issuing this RPC — Gitaly itself, as shown, performs no such check, which is the same gap identified in the referenced report (the ReferralFeeReceiver contract also relied on the caller to have used a trusted factory-deployed contract, and did not itself verify this).

### Recommendation
Do not trust the caller-supplied pool repository reference in isolation. `LinkRepositoryToObjectPool` (and `FetchIntoObjectPool`) should verify that the object pool is actually associated with the target repository's fork network/origin — for example by persisting and checking an origin binding recorded at `CreateObjectPool` time, rather than relying solely on path pattern matching (`IsPoolRepository`) and generic repository validity (`IsValid`). Consider requiring an explicit, tamper-evident linkage (e.g., a stored pool-to-origin mapping checked at link time) so that arbitrary existing pools cannot be linked to unrelated repositories via a crafted RPC field.

### Proof of Concept
1. Actor A causes a pool to be created from repository R (e.g., by forking/importing a project that triggers `CreateObjectPool` with `Origin=R`), yielding pool path `P` per the naming convention in `internal/gitaly/storage/repository_path.go`.
2. Actor B, who has RPC access but no relationship to R or P, calls `LinkRepositoryToObjectPool` with `repository = B's own repo` and `object_pool.repository = P`.
3. `objectpool.FromProto` accepts `P` because it passes `IsPoolRepository` and `IsValid`, with no check that `P` originated from a repository B is authorized to access [6](#0-5) .
4. `Link` writes `P`'s objects directory into B's repo's alternates file [7](#0-6) .
5. Actor B, knowing or brute-forcing an OID from R (e.g., leaked commit SHA), issues an object-lookup RPC (blob/commit/tree) against their own now-linked repository; Git resolves the OID via the alternates path into P's object store, disclosing R's object content to B.

Note: I could not fully verify within available context whether Gitaly's low-level blob/commit RPCs (`GetBlob`, `ReadCommit`, etc.) perform any additional ref-reachability check that would block step 5 — this would need to be confirmed by tracing `internal/gitaly/service/blob/get_blob.go` and `internal/git/localrepo/commit.go` further than the index allowed me to inspect in this session.

```go
// FromProto returns an object pool object from its Protobuf representation. This function verifies
// that the object pool exists and is a valid pool repository.
func FromProto(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	proto *gitalypb.ObjectPool,
) (*ObjectPool, error) {
	poolPath, err := locator.GetRepoPath(ctx, proto.GetRepository(), storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	if !storage.IsPoolRepository(proto.GetRepository()) {
		// When creating repositories in the ObjectPool service we will first create the
		// repository in a temporary directory. So we need to check whether the path we see
		// here is in such a temporary directory and let it pass.
		tempDir, err := locator.TempDir(proto.GetRepository().GetStorageName())
		if err != nil {
			return nil, fmt.Errorf("getting temporary storage directory: %w", err)
		}

		if !strings.HasPrefix(poolPath, tempDir) {
			return nil, ErrInvalidPoolDir
		}
	}

	pool := &ObjectPool{
		Repo:                localrepo.New(logger, locator, gitCmdFactory, catfileCache, proto.GetRepository()),
		logger:              logger,
		locator:             locator,
		gitCmdFactory:       gitCmdFactory,
		txManager:           txManager,
		housekeepingManager: housekeepingManager,
	}

	if !pool.IsValid(ctx) {
		return nil, ErrInvalidPoolRepository
	}

	return pool, nil
}
```

```go
func (s *server) LinkRepositoryToObjectPool(ctx context.Context, req *gitalypb.LinkRepositoryToObjectPoolRequest) (*gitalypb.LinkRepositoryToObjectPoolResponse, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return nil, structerr.NewInvalidArgument("%w", err)
	}

	pool, err := s.poolForRequest(ctx, req)
	if err != nil {
		return nil, err
	}

	repo := s.localRepoFactory.Build(repository)

	if err := pool.Link(ctx, repo); err != nil {
		return nil, structerr.NewInternal("%w", err)
	}

	return &gitalypb.LinkRepositoryToObjectPoolResponse{}, nil
```

```go
func Create(
	ctx context.Context,
	logger log.Logger,
	locator storage.Locator,
	gitCmdFactory gitcmd.CommandFactory,
	catfileCache catfile.Cache,
	txManager transaction.Manager,
	housekeepingManager housekeepingmgr.Manager,
	proto *gitalypb.ObjectPool,
	sourceRepo *localrepo.Repo,
) (*ObjectPool, error) {
	objectPoolPath, err := locator.GetRepoPath(ctx, proto.GetRepository(), storage.WithRepositoryVerificationSkipped())
	if err != nil {
		return nil, err
	}

	if _, err := os.Stat(objectPoolPath); err == nil {
		return nil, structerr.NewFailedPrecondition("target path exists already").
			WithMetadata("object_pool_path", objectPoolPath)
	} else if !errors.Is(err, os.ErrNotExist) {
		return nil, structerr.NewInternal("checking object pool existence: %w", err).
			WithMetadata("object_pool_path", objectPoolPath)
	}

	sourceRepoPath, err := sourceRepo.Path(ctx)
	if err != nil {
		return nil, fmt.Errorf("getting source repository path: %w", err)
	}

	objectHash, err := sourceRepo.ObjectHash(ctx)
	if err != nil {
		return nil, fmt.Errorf("detecting source repo object hash: %w", err)
	}

	var stderr bytes.Buffer
	cmd, err := gitCmdFactory.NewWithoutRepo(ctx,
		gitcmd.Command{
			Name: "clone",
			Flags: []gitcmd.Option{
				gitcmd.Flag{Name: "--quiet"},
				gitcmd.Flag{Name: "--bare"},
				gitcmd.Flag{Name: "--local"},
			},
			Args: []string{sourceRepoPath, objectPoolPath},
		},
		gitcmd.WithRefTxHook(objectHash, sourceRepo),
		gitcmd.WithStderr(&stderr),
		// When cloning an empty repository then Git isn't capable to figure out the correct
		// object hash that the new repository needs to use and just uses the default object
		// format. To work around this shortcoming we thus set the default object hash to
		// match the source repository's object hash.
		gitcmd.WithEnv("GIT_DEFAULT_HASH="+objectHash.Format),
	)
	if err != nil {
		return nil, fmt.Errorf("spawning clone: %w", err)
	}

	if err := cmd.Wait(); err != nil {
		return nil, fmt.Errorf("cloning to pool: %w, stderr: %q", err, stderr.String())
	}

	objectPool, err := FromProto(ctx, logger, locator, gitCmdFactory, catfileCache, txManager, housekeepingManager, proto)
	if err != nil {
		return nil, err
	}
```
