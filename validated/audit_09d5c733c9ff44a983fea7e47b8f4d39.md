### Title
Missing negotiation timeout in `PostUploadPackWithSidechannel` allows time-of-check-to-time-of-use bypass of access checks - (File: internal/gitaly/service/smarthttp/upload_pack.go)

### Summary
The external report's root cause is a value (Uniswap slot0 price) that is validated/measured once, then used later in the transaction to compute a consequential result (fee ratio), without re-validating that the state hasn't changed in the interim — a classic time-of-check-to-time-of-use (TOCTOU) bug. Gitaly has documented and mitigated exactly this bug class for the SSH `upload-pack` path via `pktline.ReadMonitor`, but the analogous smart-HTTP RPC `PostUploadPackWithSidechannel` does not apply the same mitigation.

### Finding Description
Gitaly explicitly documents a "use-after-check" / TOCTOU class of vulnerability: access checks for a git command (e.g., whether the requesting user is still permitted to fetch from the repository) happen once at the start of the RPC, but the actual data-serving negotiation with the client can be arbitrarily delayed by the client controlling stdin. If the client holds the connection open without completing negotiation, the server may serve the pack file long after the original access check, using permissions that may since have changed.

For SSH, this is mitigated in `internal/gitaly/service/ssh/upload_command.go`'s `runUploadCommand`, which wraps stdin with `pktline.NewReadMonitor` and installs a negotiation timeout [1](#0-0) , cancelling the git process if the "done"/flush boundary packet is not observed in time [2](#0-1) . The `ReadMonitor` type itself documents this exact rationale: "This timeout prevents a class of 'use-after-check' security issue when the access check for a git command is run before the command itself" [3](#0-2) .

In contrast, `internal/gitaly/service/smarthttp/upload_pack.go`'s `runUploadPack` (invoked by `PostUploadPackWithSidechannel`) spawns `git-upload-pack --stateless-rpc` and feeds it stdin directly, with no `ReadMonitor`, no negotiation-phase timeout, and no boundary-packet detection [4](#0-3) . Access is validated once via `validateUploadPackRequest` at the very start of the RPC [5](#0-4) , and then the negotiation and pack generation can proceed for however long the caller (or an upstream proxy holding the sidechannel/HTTP connection open) chooses to stretch it, with no independent bound on the negotiation phase analogous to the SSH path's `timeoutTicker`.

### Impact Explanation
An ordinary authenticated user who fetches/clones over smart HTTP can open a `PostUploadPackWithSidechannel` request, have it pass the access check while permission still holds, and then stall the negotiation phase indefinitely (e.g., not sending the flush/"done" packet promptly). If their access is revoked in the interim (e.g., branch/permission change, project made private, user removed from project), the smart HTTP path has no equivalent mechanism to re-validate or bound this window, unlike SSH. This can let a user retain access to repository contents past the point their authorization should have been revoked — an auth-bypass-adjacent issue directly analogous to the "price moves during execution but the fee/amount calculated on stale state is used anyway" flaw in the source report.

### Likelihood Explanation
Likelihood is moderate: it requires precise timing between a permission-revocation event and an in-flight `PostUploadPackWithSidechannel` request, but this is entirely within the capability of an ordinary client (no privileged actor, no malicious peer, no leaked token needed) — the client simply needs to open the request and delay completing negotiation, which is a client-controlled stdin stream over the sidechannel.

### Recommendation
Apply the same `pktline.ReadMonitor`/negotiation-timeout mitigation used in `internal/gitaly/service/ssh/upload_command.go` to the smart HTTP `runUploadPack` path in `internal/gitaly/service/smarthttp/upload_pack.go`, bounding the time between the RPC's access check and the end of the negotiation phase (e.g., watching for the pack-protocol "done"/flush boundary packet and cancelling the `git-upload-pack --stateless-rpc` process if it is not observed within a fixed window).

### Proof of Concept
1. User with fetch access opens `PostUploadPackWithSidechannel` for a repository; `validateUploadPackRequest` succeeds [5](#0-4) .
2. `runUploadPack` spawns `git-upload-pack --stateless-rpc` and begins streaming stdin to it with no timeout on the negotiation phase [6](#0-5) .
3. The client withholds the terminating "done"/flush packet indefinitely while, out-of-band, its access to the repository is revoked.
4. Once revoked, the client completes negotiation and receives the full packfile from `git-upload-pack`, since no per-negotiation re-check or timeout exists on this code path (compare to `runUploadCommand`'s explicit handling of this exact scenario [2](#0-1) ).

func (s *server) validateUploadPackRequest(ctx context.Context, req *gitalypb.PostUploadPackWithSidechannelRequest) (string, []gitcmd.ConfigPair, error) {
	repository := req.GetRepository()
	if err := s.locator.ValidateRepository(ctx, repository); err != nil {
		return "", nil, err
	}
	repoPath, err := s.locator.GetRepoPath(ctx, repository)
	if err != nil {
		return "", nil, err
	}

	gitcmd.WarnIfTooManyBitmaps(ctx, s.logger, s.locator, repository.GetStorageName(), repoPath)

	config, err := gitcmd.ConvertConfigOptions(req.GetGitConfigOptions())
	if err != nil {
		return "", nil, err
	}

	return repoPath, config, nil
}

func (s *server) runUploadPack(ctx context.Context, req *gitalypb.PostUploadPackWithSidechannelRequest, repoPath string, gitConfig []gitcmd.ConfigPair, stdin io.Reader, stdout io.Writer) (stats *stats.PackfileNegotiation, _ error) {
	h := sha1.New()

	stdin = io.TeeReader(stdin, h)
	stdin, collector := s.runStatsCollector(ctx, stdin)
	defer func() {
		if stats == nil {
			stats = collector.finish()
		}
	}()

	repo := s.localRepoFactory.Build(req.GetRepository())
	if s.bundleURIManager != nil {
		// Bundle generation is an optimization that is transparent to users.
		// If it fails, we log the error but continue with the regular upload-pack
		// operation without the bundle optimization.
		// If successful, a goroutine is spawned to generate the bundle, in which case
		// the bundle generation becomes independent of the RPC request.
		if err := s.bundleURIManager.GenerateWithStrategy(ctx, repo); err != nil {
			s.logger.WithError(err).Error("failed generating bundle")
		}
		gitConfig = append(gitConfig, s.bundleURIManager.UploadPackGitConfig(ctx, req.GetRepository())...)
	} else {
		gitConfig = append(gitConfig, bundleuri.CapabilitiesGitConfig(ctx, false)...)
	}

	objectHash, err := repo.ObjectHash(ctx)
	if err != nil {
		return nil, fmt.Errorf("detecting object hash: %w", err)
	}

	commandOpts := []gitcmd.CmdOpt{
		gitcmd.WithStdin(stdin),
		gitcmd.WithSetupStdout(),
		gitcmd.WithGitProtocol(s.logger, req),
		gitcmd.WithConfig(gitConfig...),
		gitcmd.WithPackObjectsHookEnv(objectHash, req.GetRepository(), "http"),
	}

	if s.cfg.Hooks.PackObjectsHookMaxProc > 0 {
		commandOpts = append(commandOpts, gitcmd.WithEnv("GOMAXPROCS="+strconv.Itoa(int(s.cfg.Hooks.PackObjectsHookMaxProc))))
	}

	cmd, err := repo.Exec(ctx, gitcmd.Command{
		Name:  "upload-pack",
		Flags: []gitcmd.Option{gitcmd.Flag{Name: "--stateless-rpc"}},
		Args:  []string{repoPath},
	}, commandOpts...)
	if err != nil {
		return nil, structerr.NewFailedPrecondition("spawning upload-pack: %w", err)
	}
