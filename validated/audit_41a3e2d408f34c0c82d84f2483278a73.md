### Title
Missing length validation of attacker-controlled `sellTokenId`/`buyTokenId` causes buffer-overflow crash in market order key construction - (File: `chainbase/src/main/java/org/tron/core/capsule/utils/MarketUtils.java`)

### Summary
`MarketSellAssetActuator` accepts a `MarketSellAssetContract` from any unprivileged, signed transaction and only checks that `sellTokenId`/`buyTokenId` are valid ASCII-digit byte strings via `TransactionUtil.isNumber()`, which enforces no length limit. These attacker-controlled byte arrays are then copied with `System.arraycopy` into fixed-size buffers in `MarketUtils.calculateOrderId()` and `MarketUtils.doCreatePairPriceKey()` that assume a maximum token-id length of 19 bytes (`TOKEN_ID_LENGTH`). An overly long numeric token id causes `ArrayIndexOutOfBoundsException`, which is not caught by `MarketSellAssetActuator.execute()`'s catch block, crashing the executing thread while a block is being applied.

### Finding Description
`TransactionUtil.isNumber()` only checks that every byte is an ASCII digit and that there's no leading zero — it imposes **no upper bound on length**: [1](#0-0) 

`MarketSellAssetActuator.validate()` uses exactly this check (and an equality check against `"_"`) to accept `sellTokenId`/`buyTokenId` taken directly from the deserialized `MarketSellAssetContract`: [2](#0-1) 

Once validated, `execute()` calls `createAndSaveOrder()`, which calls `MarketUtils.calculateOrderId()`: [3](#0-2) 

`calculateOrderId` allocates a result buffer sized as `address.length + TOKEN_ID_LENGTH + TOKEN_ID_LENGTH + countByteArray.length` (`TOKEN_ID_LENGTH` is hardcoded to 19, the length of `Long.MAX_VALUE` as a string), but then copies the **actual** (unbounded) length of `sellTokenId`/`buyTokenId` into that buffer: [4](#0-3) 

The same unsafe pattern exists in `doCreatePairPriceKey()`, used for building the order-book price key: [5](#0-4) 

If `sellTokenId` and/or `buyTokenId` are numeric strings sufficiently longer than 19 bytes (e.g., a 40+ digit all-numeric byte string, which `isNumber()` happily accepts), the successive `System.arraycopy` calls write past the end of the pre-sized `result` array, throwing `ArrayIndexOutOfBoundsException`.

`MarketSellAssetActuator.execute()` only catches a specific, narrow set of exception types: [6](#0-5) 

`ArrayIndexOutOfBoundsException` is not among them, so it propagates as an unchecked `RuntimeException` out of the actuator during block application in `Manager`. This is the direct analog of the PocketMine-MP issue: a piece of attacker-supplied, deserialized data whose *type* is nominally validated (here "is it a valid decimal token id") but whose *size/shape* is not, is then fed into low-level buffer-construction code that assumes a bounded size, producing a crash.

### Impact Explanation
Any account can broadcast a single `MarketSellAssetContract` transaction (provided market transactions are enabled, i.e. `dynamicStore.supportAllowMarketTransaction()`) with a crafted `sellTokenId`/`buyTokenId` byte string of many ASCII digits. Because the check in `validate()` accepts any all-digit string regardless of length, the transaction passes validation and is executed. Execution deterministically throws an uncaught `ArrayIndexOutOfBoundsException` inside `calculateOrderId`/`doCreatePairPriceKey`, on every full node and SR that processes the transaction/block. This is a reachable node crash/halt vector triggerable by a single unprivileged transaction, matching the "node crash or halt" impact category.

### Likelihood Explanation
Likelihood is high: the vulnerable code path is reached by a normal, signed transaction type (`MarketSellAssetContract`) available to any account once market transactions are enabled on the network (this is a standard mainnet feature, not testnet-only). No special privileges, precompiles, or non-standard flags are required — only crafting a large all-digit token-id byte string, which `isNumber()` explicitly permits.

### Recommendation
Add an explicit length bound (≤ `MarketUtils.TOKEN_ID_LENGTH`, i.e., 19 bytes) check for `sellTokenId` and `buyTokenId` in `MarketSellAssetActuator.validate()` (and any other callers of `MarketUtils.checkTokenValid`/`checkPairValid`), and/or make `MarketUtils.calculateOrderId` / `doCreatePairPriceKey` defensively validate/truncate input lengths before performing `System.arraycopy`, throwing a `ContractValidateException` instead of allowing an unchecked buffer overflow.

### Proof of Concept
1. Build a `MarketSellAssetContract` with:
   - `owner_address` = a funded, valid account address
   - `sell_token_id` = a byte string of, e.g., 40 ASCII digit characters (all digits `'0'`-`'9'`, no leading zero) — passes `TransactionUtil.isNumber()`
   - `buy_token_id` = similarly a long ASCII-digit string different from `sell_token_id`
   - `sell_token_quantity` / `buy_token_quantity` = valid positive values within `dynamicStore.getMarketQuantityLimit()`
2. Sign and broadcast the transaction on a network with `supportAllowMarketTransaction()` enabled.
3. `MarketSellAssetActuator.validate()` passes (both token ids satisfy `isNumber()`).
4. `MarketSellAssetActuator.execute()` calls `createAndSaveOrder()` → `MarketUtils.calculateOrderId()`, where the `System.arraycopy` calls write past the bounds of the `result` array (sized assuming 19-byte token ids), throwing `ArrayIndexOutOfBoundsException` that is not caught by the actuator's catch clause, propagating out during block application on every node that processes this transaction.   public static final int TOKEN_ID_LENGTH = ByteArray
      .fromString(Long.toString(Long.MAX_VALUE)).length; // 19

  public static byte[] calculateOrderId(ByteString address, byte[] sellTokenId,
      byte[] buyTokenId, long count) {

    byte[] addressByteArray = address.toByteArray();
    byte[] countByteArray = ByteArray.fromLong(count);

    byte[] result = new byte[addressByteArray.length + TOKEN_ID_LENGTH
        + TOKEN_ID_LENGTH + countByteArray.length];

    System.arraycopy(addressByteArray, 0, result, 0, addressByteArray.length);
    System.arraycopy(sellTokenId, 0, result, addressByteArray.length, sellTokenId.length);
    System.arraycopy(buyTokenId, 0, result, addressByteArray.length + TOKEN_ID_LENGTH,
        buyTokenId.length);
    System.arraycopy(countByteArray, 0, result, addressByteArray.length
        + TOKEN_ID_LENGTH + TOKEN_ID_LENGTH, countByteArray.length);

    return Hash.sha3(result);
  }
