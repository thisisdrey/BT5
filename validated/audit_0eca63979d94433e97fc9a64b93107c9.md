# No vulnerability found for this question.

**Reasoning**

The described "double counting" behavior is the intended, documented design of `ReshardingV3`, not a bug:

- After a split, the left child copies the parent's full `CongestionInfo` verbatim, including `delayed_receipts_gas` (`get_child_congestion_info_not_finalized`, `chain/chain/src/resharding/manager.rs:335-337`): *"The left child contains all the delayed and buffered receipts from the parent so it should have identical congestion info."* The right child keeps the same `delayed_receipts_gas` too (only `buffered_receipts_gas` is subtracted, since buffered receipts are not duplicated) — [1](#0-0) .
- Both children therefore start with an *upper bound*, not an exact value, for their `delayed_receipts_gas`, which is explicitly documented on `DelayedReceiptQueueWrapper::upper_bound_len`: *"During resharding, we duplicate the delayed receipt queue across both child shards, which means it's possible that the child shards contain delayed receipts that don't belong to them"* — [2](#0-1) .
- `DelayedReceiptQueueWrapper::pop` intentionally decrements gas/bytes for every popped receipt regardless of `receipt_filter_fn` match, precisely so that each child's own independent copy of the queue converges to the correct value as it drains, while still filtering out execution of receipts belonging to the sibling — [3](#0-2) .
- This mechanism is deterministic: every validator/chunk-producer runs the identical `process_delayed_receipts` / `DelayedReceiptQueueWrapper::pop` logic over identical chunk and state data (`runtime/runtime/src/lib.rs:2464-2556`), so there is no attacker-controllable divergence between nodes — all nodes compute the same (temporarily inflated) `delayed_receipts_gas` for both children and converge identically over time. There is no code path where `receipt_filter_fn`'s behavior depends on non-deterministic or attacker-observable-only state.
- `CongestionInfo` add/remove operations use `checked_add`/`checked_sub` with explicit overflow/underflow error propagation (`RuntimeError::UnexpectedIntegerOverflow`), so this accounting cannot silently corrupt state even in adversarial conditions [4](#0-3) .

The attacker's described sequence (a `promise_yield_create` call plus many delayed receipts near the boundary) is ordinary transaction/receipt traffic that any user could generate to increase congestion; it does not give the attacker any special leverage over `receipt_filter_fn` or the gas/byte accounting, and does not create double-spend, fund loss, or state-root divergence — the "over-counting" is a known, bounded, self-correcting artifact of duplicating the delayed queue across children, not an invariant the protocol claims to hold exactly at the split boundary.

    // With ReshardingV3, it's possible for a chunk to have delayed receipts that technically
    // belong to the sibling shard before a resharding event.
    // Here, we filter all the receipts that don't belong to the current shard_id.
    //
    // The function follows the guidelines of standard iterator filter function
    // We return true if we should retain the receipt and false if we should filter it.
    fn receipt_filter_fn(&self, receipt: &ReceiptOrStateStoredReceipt) -> bool {
        let shard_layout = self.epoch_info_provider.shard_layout(&self.epoch_id).unwrap();
        let receipt_shard_id = receipt.get_receipt().receiver_shard_id(&shard_layout).unwrap();
        receipt_shard_id == self.shard_id
    }

    pub(crate) fn pop(
        &mut self,
        trie_update: &mut TrieUpdate,
        config: &RuntimeConfig,
    ) -> Result<Option<ReceiptOrStateStoredReceipt<'_>>, RuntimeError> {
        // While processing receipts, we need to keep track of the gas and bytes
        // even for receipts that may be filtered out due to a resharding event
        loop {
            // Check proof size limit before each receipt is popped.
            if trie_update.trie.check_proof_size_limit_exceed() {
                break;
            }
            let Some(receipt) = self.queue.pop_front(trie_update)? else {
                break;
            };
            let delayed_gas = receipt_congestion_gas(&receipt, &config)?;
            let delayed_bytes = receipt_size(&receipt)? as u64;
            self.removed_delayed_gas =
                self.removed_delayed_gas.checked_add(delayed_gas).ok_or(IntegerOverflowError)?;
            self.removed_delayed_bytes = self
                .removed_delayed_bytes
                .checked_add(delayed_bytes)
                .ok_or(IntegerOverflowError)?;

            // Track gas and bytes for receipt above and return only receipt that belong to the shard.
            if self.receipt_filter_fn(&receipt) {
                return Ok(Some(receipt));
            }
        }
        Ok(None)
    }
