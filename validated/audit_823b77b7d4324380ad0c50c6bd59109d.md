### Title
Zero fee on NEP245/IMT transfers with `|delta| <= 1` allows complete protocol-fee bypass by splitting any amount into unit legs - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` returns `Pips::ZERO` for `Nep245`/`Imt` token deltas whenever `amount <= 1`, regardless of the configured `protocol_fee`. Since a `TokenDiff` intent applies a single signed delta per token id, an unprivileged signer can always replace one `TokenDiff` with `delta = -N` (which pays `protocol_fee.fee_ceil(N) > 0` for any `N > 1`) with `N` separately-signed `TokenDiff` intents each carrying `delta = -1` on the same token, each of which pays exactly `0`, netted together in the same `MultiPayload` batch.

### Finding Description
The binding that should hold is: `fee_collector`'s credit for moving `N` units of a NEP245/IMT token `T` should be independent of how the move is decomposed, i.e. `Pips::fee_ceil(N) == sum_of_fees(unit legs summing to N)`. The code breaks this: [1](#0-0) 

For a single intent with `delta = -N`, `amount > 1` selects the `_ if amount > 1 => {}` arm so `fee = protocol_fee`, and the fee actually collected is `protocol_fee.fee_ceil(N)`: [2](#0-1) 

For `N` intents each with `delta = -1`, `amount == 1` falls into the `TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO` arm, so each leg's `fee = Pips::ZERO.fee_ceil(1) = 0`, for a total of `0` regardless of `N` or `protocol_fee`.

Because a single `TokenDiff` can carry only one delta per `TokenId` (`diff: TokenDeltas` is a `BTreeMap<TokenId, i128>`), an attacker moving `N` units cannot avoid this by packing everything into one intent — but nothing prevents signing `N` distinct `TokenDiff` intents (different nonces, same signer) that are submitted together in one `MultiPayload` to `execute_intents`/`simulate_intents`. The `TransferMatcher::finalize` logic in `contracts/defuse/core/src/engine/state/deltas.rs` matches deposits/withdrawals across all intents in the batch purely by summed amount per token/account — it has no concept of "the same trade" and does not re-aggregate deltas before fee calculation, since fees are computed per-intent in `TokenDiff::execute_intent` before the matcher ever runs. No nonce, signature, lock, or invariant check inspects the *split* structure; each unit-leg intent is fully valid on its own (`amount=1`, `fee=0`), and their sum still nets to zero across the batch, so `TransferMatcher::finalize` succeeds and the trade completes exactly as if a single `N`-delta intent had executed, except without any of the fee.

For example, with `protocol_fee = Pips::ONE_PIP`, a single `delta=-2` move pays `fee_ceil(2) = ceil(2 * 1 / 1_000_000) = 1` unit of fee, while two `delta=-1` legs pay `0 + 0 = 0`. This generalizes to arbitrary `N`: splitting into `N` unit legs always yields `0` total fee versus `protocol_fee.fee_ceil(N) > 0` for the combined move, for any nonzero `protocol_fee`.

### Impact Explanation
The `fee_collector` (protocol) under-collects fees on every NEP245/IMT (multi-token/semi-fungible) trade whose signer chooses to split it into unit-amount `TokenDiff` legs instead of one bulk delta — a strategy fully available to any unprivileged signer trading their own balances. This is a complete, unconditional bypass of protocol fees for this asset class, independent of `protocol_fee` magnitude, matching the "protocol fees bypassed" Critical impact category. It affects the fee_collector's revenue on every NEP245/IMT trade in the protocol and is repeatable indefinitely by any signer, for any token, for any amount.

### Likelihood Explanation
No special privileges, roles, or balances beyond the attacker's own tokens are required — only the ability to sign multiple `TokenDiff` intents with different nonces and submit them together in one `MultiPayload` to `execute_intents`/`simulate_intents`, which is standard unprivileged usage. The attacker's cost is simply constructing `N` small intents instead of 1 (more payload/gas per trade), which the audit scope explicitly does not penalize as a mitigating "resource exhaustion" cost since the attack's benefit (100% fee bypass) is unconditional and directly proportional to fee saved, not resource spent. This is trivially and repeatably exploitable for any counterparty-matched or self-matched (via a second controlled account) NEP245/IMT swap.

### Recommendation
Compute the NEP245/IMT fee threshold based on the token's actual fungibility characteristics, not solely on the per-intent delta magnitude. Practical mitigation: track and aggregate a signer's total per-token/per-block (or per-batch) delta magnitude before applying the `amount <= 1` exemption, or restrict the exemption strictly to genuinely non-fungible token ids (amount is always and forever 1 for that id, e.g., true NFTs), removing it for `Imt`/semi-fungible `Nep245` ids whose `amount` can be legitimately > 1, so fee cannot be reduced by decomposing a single logical transfer into multiple unit-sized intents.

### Proof of Concept
```rust
// cargo test -p defuse-core (or in tests/src/tests/defuse/intents/token_diff.rs)
// Parametrize over N in [2, 10, 1000] and fee in [Pips::ONE_PIP, Pips::ONE_PERCENT]

#[rstest]
fn fee_bypass_via_unit_split(
    #[values(2u128, 10, 1000)] n: u128,
    #[values(Pips::ONE_PIP, Pips::ONE_PERCENT)] fee: Pips,
) {
    let token_id = TokenId::from(Nep245TokenId::new(
        "mt.near".parse().unwrap(), "unit1".to_string(),
    ));

    // Side A: single TokenDiff intent moving N units at once
    let fee_single = TokenDiff::token_fee(&token_id, n, fee).fee_ceil(n);
    assert!(fee_single > 0, "single N-delta move should owe nonzero fee for N={n}");

    // Side B: N separate TokenDiff intents, each delta=-1 on the same token id
    let fee_split: u128 = (0..n)
        .map(|_| TokenDiff::token_fee(&token_id, 1, fee).fee_ceil(1))
        .sum();
    assert_eq!(fee_split, 0, "unit-leg split always yields zero fee");

    // The binding fee_single == fee_split fails for every N > 1
    assert_ne!(fee_single, fee_split);
}
```
A full end-to-end proof (via `near-workspaces`/sandbox, mirroring `tests/src/tests/defuse/intents/token_diff.rs::swap_many`) should additionally: deposit `N` MT units to two accounts, execute one `MultiPayload` containing a single `TokenDiff{delta: -N}` intent plus a matching counter-intent, and compare `fee_collector`'s post-balance to a second run using `N` separate `TokenDiff{delta: -1}` intents matched against `N` separate `+1` counter-intents — showing the collector's credited balance is `protocol_fee.fee_ceil(N)` in the first case and `0` in the second, for every `N` in `[2, 10, 1000]`.
