### Title
Unauthenticated `RecvError` packet allows a no-cert attacker to tear down an established Nebula tunnel - (`File: outside.go`)

### Summary
`handleRecvError` in `outside.go` accepts a `header.RecvError` packet before any certificate/handshake validation and calls `f.closeTunnel(hostinfo)` if the sender's UDP `netip.AddrPort` matches `hostinfo.GetRemote()`. Like `updateTokenPool`, which trusted an entrypoint call without checking whether the true expected caller (the token contract) sent it, `handleRecvError` "authenticates" the request using only a value (source IP:port) that an off-path/on-path attacker can spoof or observe, not a value that proves possession of the peer's cryptographic identity.

### Finding Description
`readOutsidePackets` dispatches `header.RecvError` packets straight to `f.handleRecvError(via.UdpAddr, h)` before any decryption or cert check: [1](#0-0) 

`handleRecvError` then looks up the hostinfo purely by the 32-bit `RemoteIndex` in the cleartext header, and its only "authentication" check is comparing the UDP source address of the packet to the address currently recorded for that tunnel: [2](#0-1) 

If the comparison passes, it unconditionally calls `f.closeTunnel(hostinfo)` and deletes the pending handshake state, tearing down a live, mutually-authenticated tunnel. Neither the `RemoteIndex` nor the source `netip.AddrPort` are values requiring possession of the peer's Noise session keys or CA-signed certificate — `RemoteIndex` is a 32-bit value transmitted unencrypted in every packet header, and UDP source addresses are trivially spoofable over UDP (and even without spoofing, are learnable by any observer on path, e.g. a NAT/network intermediary, since Nebula operates over plain UDP).

### Impact Explanation
An attacker with no CA-signed certificate — i.e., someone who has never completed the Noise handshake and is not a "valid-cert-holder" peer — can send a single crafted `RecvError` UDP packet to force termination of another node's active tunnel, provided they can guess/observe the `RemoteIndex` (visible on the wire in every packet from that tunnel) and spoof/replay the current remote UDP address. This is a remote state-poisoning/denial-of-service primitive directly analogous to Dexter's `updateTokenPool`: a state-mutating operation gated on a weak, attacker-influenceable signal instead of genuine authentication of the claimed party.

### Likelihood Explanation
Reaching this code requires no certificate and no prior handshake with the victim — the packet is processed in the same unauthenticated branch as `Handshake` packets. The `RemoteIndex` is observable from any packet capture on the path (e.g., anyone who can sniff or is positioned as a NAT/relay for that traffic), and the source `netip.AddrPort` check does not defend against UDP source-address spoofing. Likelihood is elevated for on-path or NAT-adjacent attackers, though pure off-path blind spoofing still requires guessing/observing the 32-bit index and current remote address.

### Recommendation
Do not allow `RecvError` (or any unauthenticated packet type) to unilaterally tear down an established tunnel. At minimum, require the tunnel to be re-validated (e.g., via a challenge/response using the existing session keys, or requiring a valid MAC/AEAD tag over the `RecvError` payload) before calling `closeTunnel`, or downgrade the action to a soft signal (e.g., trigger a re-handshake attempt rather than an immediate teardown) so a spoofed packet cannot unilaterally kill a live session. Consider rate-limiting/logging repeated `RecvError` receipt per remote index.

### Proof of Concept
1. Node A and Node B complete a normal Nebula handshake, establishing an active tunnel; observe A's `RemoteIndex` (call it `idx`) and current remote `AddrPort` (call it `addrPort`) on the wire (e.g., by sniffing traffic in a position between them or on shared infrastructure).
2. From an unauthenticated host with no Nebula certificate, craft a UDP packet: `header.Encode(..., header.RecvError, 0, idx, 0)` and send it to A's listening UDP port, spoofing the source address to `addrPort`.
3. A's `handleRecvError` finds `hostinfo` via `QueryReverseIndex(idx)`, sees `hr == addr`, and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, terminating the live, authenticated tunnel — achieved without ever presenting a certificate or completing a handshake. func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
