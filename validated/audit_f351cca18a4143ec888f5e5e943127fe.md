### Title
Deactivated collateral still counted in `debtPositionOf`, allowing issuance and withdrawals against a disabled deposit token - (File: contracts/Pool.sol)

### Summary
`DepositToken.toggleIsActive()` lets the governor disable a collateral so that no new deposits/mints occur (`_mint` is gated by `onlyIfDepositTokenIsActive`). However, `Pool.depositOf()` iterates `depositTokensOfAccount` and sums the USD value of every listed deposit token without checking `isActive`. Since `debtPositionOf()` derives `_issuableLimitInUsd`/`_issuableInUsd` from `depositOf()`, previously deposited balances of a deactivated collateral continue to collateralize new debt (`DebtToken.issue`) and continue to count toward `unlockedBalanceOf` when withdrawing other assets — the exact bug class from the reference report. ### Finding Description
- `DepositToken` has an `isActive` flag toggled via `toggleIsActive()` (DepositToken.sol:559-563). When inactive, `_mint` reverts via `onlyIfDepositTokenIsActive` (DepositToken.sol:115-118, 472), blocking `deposit()` — but nothing removes existing balances from `depositTokensOfAccount` or excludes them from valuation.
- `Pool.depositOf()` (Pool.sol:274-288) loops over `depositTokensOfAccount.at(account_, i)` and adds `quoteTokenToUsd(underlying, balanceOf) * collateralFactor` to `_issuableLimitInUsd` with no `isActive` check.
- `debtPositionOf()` (Pool.sol:248-266) marks the position healthy and computes `_issuableInUsd` from that limit. `DebtToken.issue()` (DebtToken.sol:254-260) permits minting synths up to `_issuableInUsd`, and `DepositToken.unlockedBalanceOf()` (DepositToken.sol:383-398) uses the same numbers to decide how much can be withdrawn/transferred.
- `Pool.liquidate()` also relies on `debtPositionOf` (Pool.sol:559-563), so an account propped up solely by a deactivated collateral cannot be liquidated even though the asset was disabled precisely because it is deemed risky.

### Impact Explanation
If a collateral is deactivated because it is risky, compromised, or being sunset, its existing balances still count at full `collateralFactor` toward borrowing power. A holder can issue new synth debt against the disabled asset, and can withdraw every still-active collateral, leaving the position backed only by the deactivated token. If that collateral's price collapses (the reason for disabling), the protocol is left with bad debt — synthetic supply exceeds recoverable collateral value, i.e. protocol insolvency. Additionally, accounts collateralized only by the disabled asset are immune to liquidation (`PositionIsHealthy` cannot be reached), blocking bad-debt cleanup.

### Likelihood Explanation
Requires a governor deactivation as a precondition (same as the original finding — the flaw is that the flag is not honored, not that an attacker controls it). Once `toggleIsActive()` is called on any deposit token, every existing holder of that token can immediately call `DebtToken.issue()` / `DepositToken.withdraw()` through normal public entry points; no privileged access is needed for the exploitation leg. Likelihood depends on governance ever disabling a collateral while balances exist, which is the intended use of the flag.

### Recommendation
Exclude inactive deposit tokens from collateral valuation in `Pool.depositOf()`:

```solidity
IDepositToken _depositToken = IDepositToken(depositTokensOfAccount.at(account_, i));
if (!_depositToken.isActive()) continue;
```

Alternatively, keep counting it for liquidation purposes but use a zero `collateralFactor` for inactive tokens so `_issuableInUsd`/`unlockedBalanceOf` no longer treat it as borrowing power. Care is needed: fully excluding it makes positions instantly liquidatable (arguably acceptable and similar to setting CF to 0), whereas zeroing only the issuable limit preserves seizure value for liquidators.

### Proof of Concept
Hardhat-style sketch against the existing test setup (`test/Pool.test.ts` pattern):

```ts
// alice deposits MET via msdMET and mints some msETH (healthy position)
await msdMET.deposit(parseEther('10'), alice.address)
await msEthDebtToken.issue(aliceMint, alice.address)

// governor disables the collateral
await msdMET.connect(governor).toggleIsActive()  // isActive = false

// deposit is now blocked
await expect(msdMET.deposit(parseEther('1'), alice.address))
  .revertedWithCustomError(msdMET, 'DepositTokenIsInactive')

// BUG: disabled collateral still counts toward issuable limit
const {_issuableInUsd} = await pool.debtPositionOf(alice.address)
expect(_issuableInUsd).gt(0)   // should be 0 if MET were excluded

// alice issues new debt against the disabled collateral
const extra = await masterOracle.quoteUsdToToken(msEth.address, _issuableInUsd)
await msEthDebtToken.connect(alice).issue(extra, alice.address) // succeeds

// and can withdraw all other collateral, leaving only disabled MET backing the debt
// (unlockedBalanceOf on other deposit tokens still uses the disabled MET in depositOf)
```

Also verifiable: after disabling, `pool.liquidate(...)` on a position backed only by the disabled token reverts with `PositionIsHealthy` while the collateral price is intact, showing the deactivation has no effect on health accounting.

        uint256 _length = depositTokensOfAccount.length(account_);

                _depositToken.balanceOf(account_)
            );

        }
    }
