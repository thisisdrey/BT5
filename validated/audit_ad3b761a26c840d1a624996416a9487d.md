### Title
Zip-slip path traversal in ijar's `zipper` extractor bypasses output-directory containment check via prefix comparison without separator boundary - (File: third_party/ijar/zip_main.cc)

### Summary
`UnzipProcessor::Process` in `third_party/ijar/zip_main.cc` is meant to prevent zip entries from escaping the extraction root, but its containment check is a raw string-prefix comparison that does not verify a path-separator boundary. A crafted zip entry name containing `..` segments can normalize to a sibling directory that merely shares the same string prefix as the intended output root, letting an attacker-supplied archive write files outside the designated extraction directory.

### Finding Description
`UnzipProcessor::Process` builds the destination path by concatenating the (attacker-controlled) zip entry name onto `output_root_`, then attempts to enforce containment: [1](#0-0) 

The check is:
```
normalized.compare(0, normalized_root.size(), normalized_root) != 0
```
This only verifies that `normalized` starts with the same characters as `normalized_root` — it never checks that the next character is a path separator (or that `normalized_root` itself ends in one). `normalize_path` resolves `..`/`.` segments through `blaze_util::Path`, whose constructor calls `NormalizeAbsPath(MakeAbsolute(path))`: [2](#0-1) [3](#0-2) 

Given `output_root_ = "/tmp/out"` and an entry named `../outevil/evil.txt`, `concat_path` produces `/tmp/out/../outevil/evil.txt`. `NormalizeAbsPath` pops the `out` segment for the `..` and pushes `outevil`, yielding `/tmp/outevil/evil.txt`. Comparing the first 8 characters of that string (`/tmp/out`) against `normalized_root` (`/tmp/out`) succeeds even though `/tmp/outevil` is a sibling directory, not a subdirectory of `/tmp/out`. The subsequent `make_dirs`/`write_file` calls then create and write the file entirely outside the intended output root: [4](#0-3) 

This breaks the "containment holds" invariant for archive extraction: the check exists specifically to stop `..`-based zip-slip, but the missing separator boundary makes it bypassable whenever the crafted sibling path happens to share the output root's textual prefix (which an attacker who names the zip entry can engineer, since they control the suffix appended after the traversal).

### Impact Explanation
An attacker who supplies a zip archive that Bazel extracts with this `zipper` tool (e.g., an archive consumed as build input/action data) can escape the designated extraction/output directory and write attacker-controlled file content to a sibling path in the exec root/output base tree, a concrete "write outside the extraction directory" as covered by the analog rules.

### Likelihood Explanation
Exploitation only requires the attacker to control a single zip entry's filename to contain `..` components that normalize into a sibling directory sharing the output root's prefix. No credentials, MITM position, or trusted-repo BUILD access is needed — only that the victim's build extracts an attacker-supplied/served zip through this code path with `extract_ == true`.

### Recommendation
Fix the containment check in `UnzipProcessor::Process` to require a proper path-separator boundary, e.g. ensure `normalized_root` is canonicalized with a trailing separator and compare against `normalized.substr(0, normalized_root.size())` plus verify `normalized[normalized_root.size()]` is `'/'` (or that `normalized == normalized_root`), rather than a bare prefix compare.

### Proof of Concept
A `src/test/shell/bazel`-style test can demonstrate the bypass:
1. Create `evil.zip` containing a single entry named `../outevil/evil.txt` with attacker content.
2. Run the `zipper` binary: `zipper x evil.zip -d out` from a working directory containing (or about to contain) `out`.
3. Observe that `evil.txt` is written to `../outevil/evil.txt` (a sibling of `out/`), i.e., outside the `out` extraction directory, while the existing check at [5](#0-4)  incorrectly reports the path as contained and does not abort.

static std::string NormalizeAbsPath(const std::string &p) {
  if (p.empty() || p[0] != '/') {
    return "";
  }
  typedef std::string::size_type index;
  std::vector<std::pair<index, index> > segments;
  for (index s = 0; s < p.size();) {
    index e = p.find_first_of('/', s);
    if (e == std::string::npos) {
      e = p.size();
    }
    if (e > s) {
      if (p.compare(s, e - s, "..") == 0) {
        if (!segments.empty()) {
          segments.pop_back();
        }
      } else if (p.compare(s, e - s, ".") != 0) {
        segments.push_back(std::make_pair(s, e - s));
      }
    }
    s = e + 1;
  }
  if (segments.empty()) {
    return "/";
  } else {
    std::stringstream r;
    for (const auto &s : segments) {
      r << "/" << p.substr(s.first, s.second);
    }
    if (p[p.size() - 1] == '/') {
      r << "/";
    }
    return r.str();
  }
}
