### Title
Zero-value remote fee bypasses relayer reward/gas-refund charge in Snowbridge outbound queue - (File: `bridges/snowbridge/pallets/outbound-queue/src/lib.rs`)

### Summary
`Pallet::<T>::calculate_fee` in `bridges/snowbridge/pallets/outbound-queue/src/lib.rs` computes the ETH-denominated `remote` fee that is meant to reimburse relayers for gas and pay the cross-chain reward. Like the `latestAnswer`-style oracle bug in the external report (a value computation that can silently collapse to `0` and is then trusted downstream without a sanity check), this function performs fixed-point math with `checked_div`/downcasts and integer-division decimal conversion that can round the `remote` fee to exactly `0` even when the configured `PricingParameters` (`exchange_rate`, `fee_per_gas`, `rewards`) are all validated as non-zero by `PricingParameters::validate` in `bridges/snowbridge/primitives/core/src/pricing.rs`. The zero result is returned as `Ok`/`Some`-equivalent (`Fee { local, remote: 0 }`) with no revert or bounds check, and is consumed directly by `SendMessage::validate` in `send_message_impl.rs` to determine what fee is charged to the message sender.

### Finding Description
`calculate_fee` (`bridges/snowbridge/pallets/outbound-queue/src/lib.rs:368-393`) computes:
```
let fee = FixedU128::from_inner(fee)
    .saturating_mul(params.multiplier)
    .checked_div(&params.exchange_rate)
    .expect("exchange rate is not zero; qed")
    .into_inner();
let fee = Self::convert_from_ether_decimals(fee);
```
`convert_from_ether_decimals` (lines 414-418) performs `value.checked_div(denom)` where `denom = 10^(ETHER_DECIMALS - T::Decimals)`, i.e. plain integer division that truncates toward zero. Because `gas_used_at_most` for cheap commands and small `fee_per_gas`/`reward` combinations can produce an intermediate wei value smaller than `denom` (10^8 for DOT with 10 decimals, 10^6 for KSM with 12 decimals), the truncating division yields `remote = 0` — this is reproduced verbatim by the pallet's own test, `test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero` (`bridges/snowbridge/pallets/outbound-queue/src/test.rs:303-319`), whose comment states: *"Though none zero pricing params the remote fee calculated here is invalid which should be avoided"* while asserting `fee.remote == 0`.

Unlike the external Boba report where `latestAnswer` silently returns 0 on stale/failed oracle reads, here the "oracle" is the locally-configured `PricingParameters` and the corrupted value is the derived `Fee.remote` field. There is no guard anywhere in `calculate_fee`, `send_message_impl::validate`, or the runtime API (`api::calculate_fee`) that checks `fee.remote != 0` before it is returned to the caller and used to charge the message sender (e.g., via `pallet_xcm`/`EthereumBlobExporter` fee-withdrawal logic that trusts the `Fee` tuple from `SendMessage::validate`). `PricingParameters::validate` (`bridges/snowbridge/primitives/core/src/pricing.rs:39-56`) only checks that the *input* parameters (`exchange_rate`, `fee_per_gas`, `rewards.local/remote`, `multiplier`) are individually non-zero — it does not, and cannot, guarantee that the *derived* per-message fee after all multiplications/divisions and decimal truncation is non-zero for every possible `gas_used_at_most` value produced by `GasMeter::maximum_gas_used_at_most(&message.command)`.

### Impact Explanation
Because `gas_used_at_most` is derived from the attacker-supplied `Command` in an XCM message routed to Ethereum (any user can construct a `Message` with a low-gas command via `SendMessage::validate`), an unprivileged user can craft messages that land in the truncation-to-zero regime. This causes the relayer to receive `reward = 0` for delivering the message on Ethereum and the local fee charged still proceeds, but the ETH-side incentive collapses to zero — degrading relayer participation and enabling underpriced (free) message delivery on the bridge's remote leg, which matches "public underpriced work that degrades... stalls bridge processing" in the impact gate. This does not require a malicious relayer, validator, governance actor, or leaked key — it is triggered purely by normal parameter configuration plus attacker-chosen message content.

### Likelihood Explanation
High under specific but plausible pricing-parameter configurations: any parameter set where `fee_per_gas * gas_used_at_most + reward`, after multiplier/exchange-rate adjustment and decimal conversion, falls below the smallest representable unit in the local currency's decimals will always yield `remote = 0` for messages using the minimum-gas command. This is not a rare edge case — the pallet's own regression test was written specifically to document this exact scenario, indicating the maintainers were aware but left no runtime guard against it.

### Recommendation
In `calculate_fee` (`bridges/snowbridge/pallets/outbound-queue/src/lib.rs`), after computing the final `remote` fee, explicitly reject or round up to a minimum non-zero value when the computed `remote` fee is `0`, mirroring the fix recommended in the external report (validate the derived output, don't trust a computation that can silently degrade to zero). Concretely: return an error from `SendMessage::validate` (propagating up through `EthereumBlobExporter`) if `fee.remote.is_zero()`, or use `checked_div`/round-up division in `convert_from_ether_decimals` and enforce a configurable minimum reward floor, so that low-gas commands cannot bypass relayer compensation entirely.

fn test_calculate_fees_with_valid_exchange_rate_but_remote_fee_calculated_as_zero() {
    new_tester().execute_with(|| {
        let gas_used: u64 = 250000;

		/// Calculate total fee in native currency to cover all costs of delivering a message to the
		/// remote destination. See module-level documentation for more details.
		pub(crate) fn calculate_fee(
			gas_used_at_most: u64,
			params: PricingParameters<T::Balance>,
		) -> Fee<T::Balance> {
			// Remote fee in ether
			let fee = Self::calculate_remote_fee(
				gas_used_at_most,
				params.fee_per_gas,
				params.rewards.remote,
			);

			// downcast to u128
			let fee: u128 = fee.try_into().defensive_unwrap_or(u128::MAX);

			// multiply by multiplier and convert to local currency
			let fee = FixedU128::from_inner(fee)
				.saturating_mul(params.multiplier)
				.checked_div(&params.exchange_rate)
				.expect("exchange rate is not zero; qed")
				.into_inner();

			// adjust fixed point to match local currency
			let fee = Self::convert_from_ether_decimals(fee);

			Fee::from((Self::calculate_local_fee(), fee))
		}

		/// Calculate fee in remote currency for dispatching a message on Ethereum
		pub(crate) fn calculate_remote_fee(
			gas_used_at_most: u64,
			fee_per_gas: U256,
			reward: U256,
		) -> U256 {
			fee_per_gas.saturating_mul(gas_used_at_most.into()).saturating_add(reward)
		}

		/// The local component of the message processing fees in native currency
		pub(crate) fn calculate_local_fee() -> T::Balance {
			T::WeightToFee::weight_to_fee(
				&T::WeightInfo::do_process_message().saturating_add(T::WeightInfo::commit_single()),
			)
		}

		// 1 DOT has 10 digits of precision
		// 1 KSM has 12 digits of precision
		// 1 ETH has 18 digits of precision
		pub(crate) fn convert_from_ether_decimals(value: u128) -> T::Balance {
			let decimals = ETHER_DECIMALS.saturating_sub(T::Decimals::get()) as u32;
			let denom = 10u128.saturating_pow(decimals);
			value.checked_div(denom).expect("divisor is non-zero; qed").into()
		}

impl<Balance> PricingParameters<Balance>
where
	Balance: BaseArithmetic + Unsigned + Copy,
{
	pub fn validate(&self) -> Result<(), InvalidPricingParameters> {
		if self.exchange_rate == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.fee_per_gas == U256::zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.local.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.rewards.remote.is_zero() {
			return Err(InvalidPricingParameters);
		}
		if self.multiplier == FixedU128::zero() {
			return Err(InvalidPricingParameters);
		}
		Ok(())
	}
}

	fn validate(
		message: &Message,
	) -> Result<(Self::Ticket, Fee<<Self as SendMessageFeeProvider>::Balance>), SendError> {
		// The inner payload should not be too large
		let payload = message.command.abi_encode();
		ensure!(
			payload.len() < T::MaxMessagePayloadSize::get() as usize,
			SendError::MessageTooLarge
		);

		// Ensure there is a registered channel we can transmit this message on
		ensure!(T::Channels::contains(&message.channel_id), SendError::InvalidChannel);

		// Generate a unique message id unless one is provided
		let message_id: H256 = message
			.id
			.unwrap_or_else(|| unique((message.channel_id, &message.command)).into());

		let gas_used_at_most = T::GasMeter::maximum_gas_used_at_most(&message.command);
		let fee = Self::calculate_fee(gas_used_at_most, T::PricingParameters::get());

		let queued_message: VersionedQueuedMessage = QueuedMessage {
			id: message_id,
			channel_id: message.channel_id,
			command: message.command.clone(),
		}
		.into();
		// The whole message should not be too large
		let encoded = queued_message.encode().try_into().map_err(|_| SendError::MessageTooLarge)?;

		let ticket = Ticket { message_id, channel_id: message.channel_id, message: encoded };

		Ok((ticket, fee))
	}
