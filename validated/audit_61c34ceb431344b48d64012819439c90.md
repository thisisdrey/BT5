The closest analog in this repository is `net/http`'s static file serving code, but it already implements the exact defenses the `serve-lite` advisory says are missing. `http.ServeFile`/`ServeFileFS` explicitly reject any request whose `r.URL.Path` contains a `..` element via `containsDotDot(r.URL.Path)` before ever touching the filesystem [1](#0-0) , and the doc comments even call out the exact `path.Join`/`filepath.Join`-on-raw-URL-path misuse pattern from the advisory as the thing this check protects against [2](#0-1) . The `FileServer` handler (`fileHandler.ServeHTTP`) additionally runs `path.Clean` on the incoming path before dispatching to `serveFile`, normalizing `..` segments rather than passing raw user input to a join/open call [3](#0-2) . Test coverage (`TestServeFile_DotDot`, `TestFileServerCleans`) confirms `..`-laden paths are rejected or normalized rather than escaping the served root [4](#0-3) [5](#0-4) .

Separately, `cmd/go/internal/vcweb/auth.go`'s test-only auth handler does call `fs.Open(urlPath)` and `path.Join(accessDir, ...)` directly on `req.URL.Path` [6](#0-5) , which superficially resembles the `serve-lite` pattern, but this lives under `src/cmd/go/internal/vcweb`, a test-fixture HTTP server used only by the Go toolchain's own module-proxy test suite (not a production server reachable by unauthenticated attackers in a real deployment), so it falls outside the "production" and "not test/mock" scope required by the rules.

No unmitigated, production, unauthenticated-reachable directory-traversal primitive analogous to the `serve-lite` CVE exists in this repository's file-serving code.

```go
func ServeFile(w ResponseWriter, r *Request, name string) {
	if containsDotDot(r.URL.Path) {
		// Too many programs use r.URL.Path to construct the argument to
		// serveFile. Reject the request under the assumption that happened
		// here and ".." may not be wanted.
		// Note that name might not contain "..", for example if code (still
		// incorrectly) used filepath.Join(myDir, r.URL.Path).
		serveError(w, "invalid URL path", StatusBadRequest)
		return
	}
	dir, file := filepath.Split(name)
	serveFile(w, r, Dir(dir), file, false)
}
```
