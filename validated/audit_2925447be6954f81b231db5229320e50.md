### Title
Unauthenticated non-broadcast block upload triggers network-wide relay via `set_relay_message` - (File: stackslib/src/net/api/postblock_v3.rs)

### Summary
`RPCPostBlockRequestHandler::try_parse_request` only requires authentication when the caller sets `broadcast=1`; without that query parameter, `self.broadcast` is `Some(false)` and no `authorization` header is checked at all. In `try_handle_request`, the decision to call `node.set_relay_message(...)` is gated solely on `data_resp.accepted`, which comes from `Relayer::process_new_nakamoto_block_ext`'s chainstate-validation result, not on `self.broadcast`.

### Finding Description
The intended invariant is "relay-to-peers requires `broadcast==true`, which requires authentication." The code, however, decouples these: [1](#0-0) 
shows `broadcast` defaults to `false` and authentication is only enforced `if broadcast && !authenticated`; an attacker simply omits the `broadcast=1` query arg and the `authorization` header entirely, and the request is accepted with `self.broadcast = Some(false)`.

Then in `try_handle_request`: [2](#0-1) 
`self.broadcast.unwrap_or(false)` is passed into `Relayer::process_new_nakamoto_block_ext` (its role there is bookkeeping for `NakamotoBlockObtainMethod`/staging DB, not a relay gate), and separately, the block is set for network relay via `node.set_relay_message(StacksMessageType::NakamotoBlocks(...))` whenever `data_resp.accepted` is `true` — with no check of `self.broadcast` at that call site at all.

Thus any unauthenticated remote peer that posts a structurally/consensus-valid Nakamoto block to `/v3/blocks/upload/` (no `broadcast=1`, no `authorization` header) will have that block validated by chainstate; if chainstate accepts it, the node unconditionally queues it for relay to the P2P network, exactly as if it had come from an authenticated broadcaster.

### Impact Explanation
This breaks the intended "broadcast requires auth" boundary: any remote, unauthenticated caller who can produce or replay a block that passes chainstate validation (e.g., a block it obtained by other means, or one it constructed itself if it's a miner/signer that produced a valid block) can force the node to propagate it network-wide, bypassing the RPC secret gate entirely. This matches "network-wide propagation of an unauthenticated/unauthorized data" — Critical impact — since the RPC secret was specifically designed to restrict who can trigger relay.

Note: the practical severity is bounded by the fact that `data_resp.accepted` still requires the block to pass full chainstate/consensus validation (signatures, sortition tie-in, etc.), which is out of scope per the rules ("consensus block-validation internals"). The vulnerability here is specifically that the `broadcast`/auth flag has **no effect** on the relay decision, only on `process_new_nakamoto_block_ext`'s bookkeeping — meaning the auth gate is decorative with respect to relay.

### Likelihood Explanation
- The `/v3/blocks/upload/` RPC endpoint is remotely reachable by any unprivileged peer with no auth needed for the non-broadcast path.
- The only precondition is that the attacker's posted block passes chainstate validation as "accepted" — which is a real constraint but is unrelated to the `broadcast`/authorization flag being bypassed.
- Repeatable per valid block; no rate limiting on this decision inside this handler.

### Recommendation
Gate the `node.set_relay_message(...)` call in `try_handle_request` on `self.broadcast == Some(true)` (i.e., only relay when the request was both authenticated and explicitly asked to broadcast), matching the documented invariant enforced in `try_parse_request`.

### Proof of Concept
Rust test in `stackslib::net::api::tests::postblock_v3`:
1. Construct `RPCPostBlockRequestHandler::new(Some("secret".into()))`.
2. Build an HTTP POST to `/v3/blocks/upload/` with a valid, chainstate-acceptable `NakamotoBlock` body, `application/octet-stream` content type, no `authorization` header, and no `broadcast` query parameter.
3. Call `try_parse_request` — assert it succeeds (no 401) and `self.broadcast == Some(false)`.
4. Call `try_handle_request` against a `StacksNodeState` whose chainstate will accept the block; assert `data_resp.accepted == true`.
5. Assert `node.set_relay_message` was invoked with `StacksMessageType::NakamotoBlocks` containing the block — demonstrating relay occurred despite `broadcast=false`/no authentication, confirming the bypass at [3](#0-2) .
