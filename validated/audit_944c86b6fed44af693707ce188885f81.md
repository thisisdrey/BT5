## Analysis

The external Astaria bug's core invariant is: **a "last processed" timestamp field is unconditionally advanced to `now` even when the payment/settlement only partially covers what was owed for the elapsed period**, permanently corrupting the bookkeeping for the un-settled remainder.

The exact analog exists in `pallet-dap`'s issuance-drip hook.### Title
`pallet-dap` permanently drops issuance beyond `MaxElapsedPerDrip` because `LastIssuanceTimestamp` is unconditionally advanced to `now` on every drip, even when elapsed time is clamped - (File: `substrate/frame/dap/src/lib.rs`)

### Summary
`pallet-dap`'s `drip_issuance` hook mints protocol inflation based on elapsed time since `LastIssuanceTimestamp`. When the real elapsed time exceeds the safety ceiling `MaxElapsedPerDrip`, the pallet clamps the *minted* amount to the ceiling but still writes `LastIssuanceTimestamp = now`, discarding the un-minted remainder forever with no way to recover it. This is the same broken invariant as the Astaria bug: a "last settled" timestamp is advanced to `now` even though the settlement only partially covered the elapsed/owed period, permanently corrupting downstream accounting for the unsettled remainder.

### Finding Description
In `drip_issuance`: [1](#0-0) 

The sequence is:
1. `elapsed = now - last`.
2. If `elapsed > max_elapsed` (`MaxElapsedPerDrip`), an `ElapsedClamped` event is emitted and `elapsed` is capped to `max_elapsed`.
3. Regardless of clamping, `LastIssuanceTimestamp::<T>::put(now)` is executed unconditionally — the same pattern as `lien.last = block.timestamp` in the Astaria bug being set even on partial settlement.
4. `mint_and_distribute(elapsed)` only mints for the clamped `elapsed`, never for the true `now - last` window.

Because `last` is snapped to `now` in step 3, the difference `(true_elapsed - max_elapsed)` is not carried over to the next drip and is never mintable again — the deficit is silently and permanently lost.

The pallet's own migration code independently documents and fixes exactly this defect, but only for the one-time V1→V2 upgrade path: [2](#0-1) [3](#0-2) 

The prdoc explicitly states the bug class: "That elapsed is then clamped by `MaxElapsedPerDrip`, so only up to one cap's worth of inflation is actually credited on the first drip, and the rest is silently dropped." The migration adds a bespoke catch-up drip to solve this *only for the initial seeding case*. The recurring `drip_issuance` hook that runs every block via `on_initialize` still has the identical unconditional advance-to-`now` logic with no catch-up mechanism: [4](#0-3) 

The `integrity_test` only asserts `MaxElapsedPerDrip > IssuanceCadence`, which prevents clamping during *normal* per-block cadence, but does nothing to protect against any interruption in `on_initialize` execution (chain halts, long syncing gaps, migrations/blocking upgrades, or any period exceeding `MaxElapsedPerDrip` between successful drips): [5](#0-4) 

No other guard exists to detect or compensate for a skipped/delayed drip window; the deficit is not stored, not carried forward, and not recoverable through any extrinsic.

### Impact Explanation
`pallet-dap` is wired into `asset-hub-westend-runtime` as the chain's inflation/reward-distribution engine, feeding budget recipients such as staking rewards and the treasury/buffer: [6](#0-5) 

Any time the gap between two `on_initialize` executions of the DAP hook exceeds `MaxElapsedPerDrip` (e.g., a chain-wide production stall, a long parachain block-import gap, or a runtime upgrade window where blocks are produced but the hook's clamp ceiling is exceeded due to timestamp jumps), the protocol permanently under-mints the intended issuance for that window. This silently and irreversibly reduces staking rewards / treasury inflow relative to the protocol's designed issuance curve — a runtime bug that compromises intended economic behavior of the chain, matching the "runtime bugs that compromise intended behavior" and "permanent ... fund lock" impact classes (in this case, permanent loss of the pallet's intended payout rather than recovery via any catch-up).

### Likelihood Explanation
This is deterministic, not probabilistic: whenever `now - last > MaxElapsedPerDrip` at the moment `drip_issuance` runs, the loss occurs unconditionally on every such occurrence, with no attacker action required beyond the pre-existing conditions of a block-production gap. The Parity team itself identified and fixed this exact defect for the one-off migration seeding path (`pr_11809`), demonstrating the bug class is real and already acknowledged as a genuine defect in this codebase — but the fix was not applied to the recurring `drip_issuance` code path, which remains vulnerable to the same "silently dropped" issuance loss for any post-genesis gap exceeding the ceiling.

### Recommendation
In `drip_issuance`, do not reset `LastIssuanceTimestamp` to the full `now` when `elapsed` is clamped. Instead, advance it only by the clamped `elapsed` (i.e., `LastIssuanceTimestamp::<T>::put(last.saturating_add(elapsed))`), so the un-minted remainder is retained and gets picked up (and eventually minted, subject to the same ceiling) on subsequent drips — mirroring the catch-up-safe approach already implemented for the migration path.

### Proof of Concept
1. Configure `IssuanceCadence = 60_000` ms and `MaxElapsedPerDrip = 3_600_000` ms (1 hour), a typical setup satisfying the `integrity_test`.
2. Let `LastIssuanceTimestamp = T0` after a normal drip.
3. Suppose block production stalls (e.g., due to a long parachain-collator outage or blocked finality) such that the next successful `on_initialize` call occurs at `now = T0 + 10_800_000` ms (3 hours later) — 3x the ceiling.
4. `drip_issuance` computes `elapsed = 10_800_000`, clamps it to `3_600_000`, emits `ElapsedClamped`, mints issuance for only 1 hour worth of inflation via `mint_and_distribute(3_600_000)`, and then executes `LastIssuanceTimestamp::<T>::put(now)` — setting `last = T0 + 10_800_000`.
5. The remaining 2 hours of intended inflation (`7_200_000` ms worth) is permanently lost: it is neither minted now nor recoverable on any future drip, since `last` has already jumped past that window. [7](#0-6)

		pub(crate) fn drip_issuance() -> Weight {
			let now_moment = T::Time::now();
			let now: u64 = now_moment.saturated_into();
			let last = LastIssuanceTimestamp::<T>::get();
			let mut elapsed = now.saturating_sub(last);

			let cadence = T::IssuanceCadence::get();
			if cadence > 0 && elapsed < cadence {
				return T::DbWeight::get().reads(2);
			}

			// First block after genesis: initialize timestamp, don't drip.
			// For existing chains, use `migrations::MigrateV1ToV2` to seed this
			// value from ActiveEra.start so this branch is never hit post-upgrade.
			if last == 0 {
				LastIssuanceTimestamp::<T>::put(now);
				return T::DbWeight::get().reads_writes(2, 2);
			}

			// Apply safety ceiling on elapsed time.
			let max_elapsed = T::MaxElapsedPerDrip::get();
			if elapsed > max_elapsed {
				Self::deposit_event(Event::Unexpected(UnexpectedKind::ElapsedClamped {
					actual_elapsed: elapsed,
					ceiling: max_elapsed,
				}));
				elapsed = max_elapsed;
			}

			// Always advance the clock so elapsed time doesn't accumulate across skipped drips.
			LastIssuanceTimestamp::<T>::put(now);

			let _ = Self::mint_and_distribute(elapsed);

		pub(crate) fn mint_and_distribute(elapsed: u64) -> BalanceOf<T> {
			let total_issuance = T::Currency::total_issuance();
			let issuance = T::IssuanceCurve::issue(total_issuance, elapsed);

			if issuance.is_zero() {
				return BalanceOf::<T>::zero();
			}

			let budget = BudgetAllocation::<T>::get();
			if budget.is_empty() {
				// TODO: Add defensive! panic once budget is always configured.
				log::warn!(
					target: LOG_TARGET,
					"BudgetAllocation is empty — no issuance will be distributed"
				);
				return BalanceOf::<T>::zero();
			}
			let recipients = T::BudgetRecipients::recipients();
			let mut total_minted = BalanceOf::<T>::zero();

			let buffer = Self::buffer_account();
			for (key, account) in &recipients {
				let perbill = budget.get(key).copied().unwrap_or(Perbill::zero());
				let amount = perbill.mul_floor(issuance);
				if !amount.is_zero() {
					if let Err(_) = T::Currency::mint_into(account, amount) {
						Self::deposit_event(Event::Unexpected(UnexpectedKind::MintFailed));
						defensive!("Issuance mint should not fail");
					} else {
						total_minted = total_minted.saturating_add(amount);
						if *account == buffer {
							Self::deactivate_buffer_funds(amount);
						}
					}
				}
			}

			// Rounding dust from Perbill::mul_floor is not minted.

			Self::deposit_event(Event::IssuanceMinted { total_minted, elapsed_millis: elapsed });
