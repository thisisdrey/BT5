### Title
Firewall conntrack fast-path allows traffic to bypass certificate/group-based rules after a peer rotates to a non-conforming certificate - (File: firewall.go)

### Summary
The Sherlock finding describes a "swap-without-recheck" pattern: a security decision is made once (checking that a Safe owner still holds a valid signer hat), the outcome is cached/trusted, and a later state change (owner swap) that should invalidate that trust is never re-verified post-flight. The reachable analog in this Nebula codebase is the firewall's connection-tracking ("conntrack") fast path, where a flow's initial certificate/group-based authorization decision is cached and reused for the lifetime of the conntrack entry, without ever being re-validated against the peer's *current* certificate identity when that identity changes (e.g., via rehandshake/cert rotation), only against the firewall *ruleset* version.

### Finding Description
`Firewall.Drop` performs group/CA/CIDR-based authorization once per new flow by calling `table.match(fp, incoming, h.ConnectionState.peerCert, caPool)` [1](#0-0) . Once a flow passes, it is recorded in a conntrack table keyed purely by the 4-tuple `firewall.Packet` (local/remote IP and port), together with only the `rulesVersion` that authorized it [2](#0-1) .

On every subsequent packet for that same 4-tuple, `Firewall.inConns` is consulted first, and if the entry's `rulesVersion` still equals the firewall's current `rulesVersion`, the packet is allowed immediately — no re-check against the peer's certificate or group membership is performed at all: [3](#0-2) 

The stale-conntrack-entry re-validation logic explicitly only fires "if `c.rulesVersion != f.rulesVersion`" (i.e., only when the *firewall configuration* is reloaded), and it re-checks using whatever `h.ConnectionState.peerCert` is at that time [4](#0-3) . `rulesVersion` is only incremented by `AddFirewallRulesFromConfig`, i.e., on a config/SIGHUP reload — not on certificate rotation, rehandshake, or primary-tunnel swap. `Firewall` is a single per-`Interface` object shared across all peers/tunnels, and its `Conntrack` map is keyed only by IP/port tuple [5](#0-4) , so the record has no binding to which certificate/identity actually authorized the flow.

Meanwhile, certificate rotation is an expected, normal event: a peer's `HostInfo.ConnectionState.peerCert` is replaced whenever a rehandshake completes (`continueHandshake` sets `hostinfo.ConnectionState = newConnectionStateFromResult(result)` with the newly verified cert) [6](#0-5) , and the VPN address(es)/tuple typically remain the same across this rotation (this is exactly the scenario the `TestRehandshaking`/`TestRehandshakingLoser` e2e tests exercise, showing a cert with a *different set of groups* can replace the old one on the same host pair) [7](#0-6) .

Put together: a peer can initially handshake with a certificate whose groups satisfy a firewall rule, open a flow that gets conntrack-cached as allowed, then rotate (or be swapped, e.g., via a compromised/renewed cert with different/broader groups or even a different CA-signed identity within the same trust domain) to a certificate that would *not* pass `table.match` under the current rules — yet continue sending/receiving packets on the already-established 4-tuple indefinitely, because `inConns` never re-runs `table.match` unless an administrator happens to reload the firewall config in between.

### Impact Explanation
This allows firewall (authorization) rules based on certificate groups, CA name, or CA SHA to be silently bypassed for any already-established flow once the underlying peer identity/certificate changes, without requiring any firewall config change. This is a genuine authorization-bypass condition: traffic that should be dropped under the currently-configured rules is passed simply because it matches a pre-existing conntrack entry created under a different, no-longer-valid identity — directly mirroring the root cause of the referenced Sherlock finding (stale pre-flight authorization decisions never re-validated post-flight against a changed principal).

### Likelihood Explanation
Reachable by any two mutually-trusted-CA peers that can complete a normal handshake and later rehandshake/rotate certificates (a routine, attacker-triggerable operation — nothing requires special privileges, only a certificate signed by an already-trusted CA, i.e., no CA-signed-certificate requirement is violated). The rehandshake path is exercised by the existing `TestRehandshaking` tests, confirming the identity/group swap on an existing tunnel is a normal, reachable state transition; the gap is only that the firewall's cached decision is not re-verified when this happens.

### Recommendation
Re-validate the cached conntrack authorization against the *current* `h.ConnectionState.peerCert` whenever the associated `HostInfo`'s certificate/fingerprint has changed since the entry was created (not only when `rulesVersion` changes), analogous to the recommendation in the source report: perform a "pre- and post-flight" comparison of the authorizing identity. Concretely, track the certificate fingerprint (or a monotonically incremented per-hostinfo cert generation counter) alongside `rulesVersion` in the `conn` struct, and force re-validation in `inConns` when either changes.

### Proof of Concept
1. Peer A and Peer B share a trusted CA. Peer B's certificate `cert1` belongs to `group-allowed`; the firewall's inbound rule permits `group-allowed` only.
2. B handshakes with A using `cert1`; a flow is established and passes `Firewall.Drop`, creating a conntrack entry tagged with the firewall's current `rulesVersion` [2](#0-1) .
3. Without any firewall config reload on A's side, B rotates to `cert2` (same CA, different/broader groups not in `group-allowed`) and rehandshakes; A's `HostInfo.ConnectionState.peerCert` is updated to `cert2` [6](#0-5) .
4. B continues sending packets on the same 4-tuple. `Firewall.Drop` calls `inConns` first; since `c.rulesVersion == f.rulesVersion` (no reload happened), the entry is treated as still valid and the packet is allowed without ever calling `table.match` against `cert2` [8](#0-7) [4](#0-3) .
5. Result: traffic from a peer now holding a certificate that should be denied by the configured group rule continues to be forwarded, bypassing the firewall policy.

func (f *Firewall) inConns(fp firewall.Packet, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) bool {
	if localCache != nil {
		if _, ok := localCache[fp]; ok {
			return true
		}
	}
	conntrack := f.Conntrack
	conntrack.Lock()

	// Purge every time we test
	ep, has := conntrack.TimerWheel.Purge()
	if has {
		f.evict(ep)
	}

	c, ok := conntrack.Conns[fp]

	if !ok {
		conntrack.Unlock()
		return false
	}

	if c.rulesVersion != f.rulesVersion {
		// This conntrack entry was for an older rule set, validate
		// it still passes with the current rule set
		table := f.OutRules
		if c.incoming {
			table = f.InRules
		}

		// We now know which firewall table to check against
		if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("dropping old conntrack entry, does not match new ruleset",
					"fwPacket", fp,
					"incoming", c.incoming,
					"rulesVersion", f.rulesVersion,
					"oldRulesVersion", c.rulesVersion,
				)
			}
			delete(conntrack.Conns, fp)
			conntrack.Unlock()
			return false
		}

		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			h.logger(f.l).Debug("keeping old conntrack entry, does match new ruleset",
				"fwPacket", fp,
				"incoming", c.incoming,
				"rulesVersion", f.rulesVersion,
				"oldRulesVersion", c.rulesVersion,
			)
		}

		c.rulesVersion = f.rulesVersion
	}

func (f *Firewall) addConn(fp firewall.Packet, incoming bool) {
	var timeout time.Duration
	c := &conn{}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		timeout = f.TCPTimeout
	case firewall.ProtoUDP:
		timeout = f.UDPTimeout
	default:
		timeout = f.DefaultTimeout
	}

	conntrack := f.Conntrack
	conntrack.Lock()
	if _, ok := conntrack.Conns[fp]; !ok {
		conntrack.TimerWheel.Advance(time.Now())
		conntrack.TimerWheel.Add(fp, timeout)
	}

	// Record which rulesVersion allowed this connection, so we can retest after
	// firewall reload
	c.incoming = incoming
	c.rulesVersion = f.rulesVersion
	c.Expires = time.Now().Add(timeout)
	conntrack.Conns[fp] = c
	conntrack.Unlock()

func TestRehandshaking(t *testing.T) {
	t.Parallel()
	ca, _, caKey, _ := cert_test.NewTestCaCert(cert.Version1, cert.Curve_CURVE25519, time.Now(), time.Now().Add(10*time.Minute), nil, nil, []string{})
	myControl, myVpnIpNet, myUdpAddr, myConfig := newSimpleServer(cert.Version1, ca, caKey, "me  ", "10.128.0.2/24", nil)
	theirControl, theirVpnIpNet, theirUdpAddr, theirConfig := newSimpleServer(cert.Version1, ca, caKey, "them", "10.128.0.1/24", nil)

	// Put their info in our lighthouse and vice versa
	myControl.InjectLightHouseAddr(theirVpnIpNet[0].Addr(), theirUdpAddr)
	theirControl.InjectLightHouseAddr(myVpnIpNet[0].Addr(), myUdpAddr)

	// Build a router so we don't have to reason who gets which packet
	r := router.NewR(t, myControl, theirControl)
	defer r.RenderFlow()

	// Start the servers
	myControl.Start()
	theirControl.Start()

	t.Log("Stand up a tunnel between me and them")
	assertTunnel(t, myVpnIpNet[0].Addr(), theirVpnIpNet[0].Addr(), myControl, theirControl, r)

	r.RenderHostmaps("Starting hostmaps", myControl, theirControl)

	r.Log("Renew my certificate and spin until their sees it")
	_, _, myNextPrivKey, myNextPEM := cert_test.NewTestCert(cert.Version1, cert.Curve_CURVE25519, ca, caKey, "me", time.Now(), time.Now().Add(5*time.Minute), myVpnIpNet, nil, []string{"new group"})

	caB, err := ca.MarshalPEM()
	if err != nil {
		panic(err)
	}

	myConfig.Settings["pki"] = m{
		"ca":   string(caB),
		"cert": string(myNextPEM),
		"key":  string(myNextPrivKey),
	}
	rc, err := yaml.Marshal(myConfig.Settings)
	require.NoError(t, err)
	myConfig.ReloadConfigString(string(rc))

	for {
		assertTunnel(t, myVpnIpNet[0].Addr(), theirVpnIpNet[0].Addr(), myControl, theirControl, r)
		c := theirControl.GetHostInfoByVpnAddr(myVpnIpNet[0].Addr(), false)
		if len(c.Cert.Groups()) != 0 {
			// We have a new certificate now
			break
		}

		time.Sleep(time.Second)
	}

	r.Log("Got the new cert")
	// Flip their firewall to only allowing the new group to catch the tunnels reverting incorrectly
	rc, err = yaml.Marshal(theirConfig.Settings)
	require.NoError(t, err)

		"port":  "any",
		"group": "new group",
	}}

	require.NoError(t, err)
