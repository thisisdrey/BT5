### Title
Protocol fee bypass on NEP-245/IMT `TokenDiff` intents via unit-delta splitting - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` returns `Pips::ZERO` for any `TokenIdType::Nep245`/`TokenIdType::Imt` leg whose `amount <= 1`, while charging the full `protocol_fee` when `amount > 1`. Because fees are computed independently per `TokenDiff` intent and per-token entry, a signer can split a single large negative delta on an NEP-245/IMT token into many `delta == -1` legs across multiple signed `TokenDiff` intents in one `execute_intents` batch, causing the total fee credited to `fee_collector` to be zero instead of `protocol_fee.fee_ceil(total_amount)`.

### Finding Description
The broken binding is:
`sum(Pips::fee_ceil applied to each negative delta of token T across the batch) == protocol_fee.fee_ceil(total |negative delta| of T)`

In [1](#0-0)  the fee for a given `(token_id, amount)` pair is computed independently:
```
TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
```
This is evaluated per intent, per token entry, inside `execute_intent` at [2](#0-1)  where `fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` is accumulated into `fees_collected` and later added to `fee_collector` via `internal_add_balance` at [3](#0-2) .

Because `execute_signed_intents` processes an arbitrary `Vec<MultiPayload>` and calls `execute_signed_intent` for each one independently ( [4](#0-3) ), a signer (or a signer colluding with a counterparty account they also control) can submit N separate signed `TokenDiff` payloads, each containing `delta = -1` on the same NEP-245/IMT `TokenId`, instead of one payload with `delta = -N`. Each unit leg hits `amount == 1`, which falls into the zero-fee arm, so `fees_collected` for that token is `0` per leg and `0` in total, whereas a single non-split `delta = -N` (N > 1) would compute `protocol_fee.fee_ceil(N) > 0`.

The batch-wide invariant enforced by `TransferMatcher::finalize` ( [5](#0-4) ) only checks that total deltas per token across the whole batch net to zero (token conservation for transfer/event bookkeeping); it does not recompute or re-validate the fee amount, so it does not prevent this. `verify_intent_nonce`/`commit_nonce` only guard against nonce replay, not against splitting a single logical trade into many nonces ( [6](#0-5) ). No other guard recomputes an aggregate fee across intents in the batch.

### Impact Explanation
`fee_collector` is under-credited: for any batch involving NEP-245/IMT token legs, the protocol fee can be reduced to exactly `0` regardless of the notional amount transacted, by splitting into unit legs paired with matching counter-legs elsewhere in the same batch (self-dealing across two attacker-controlled accounts, or with a cooperating/automated counterparty). This is a direct, repeatable "protocol fees bypassed" condition (explicitly listed as Critical impact) with no bound on the amount evaded other than the number of unit legs the attacker is willing to sign and submit. It affects every NEP-245/IMT token registered in the Verifier and is repeatable indefinitely across accounts/tokens/batches.

### Likelihood Explanation
Preconditions are modest: the attacker needs Verifier balance in an NEP-245/IMT token (`amount > 1` intended trade size) and `engine.state.fee() != 0`. The attacker needs to produce N signed `TokenDiff` payloads instead of 1 (cheap client-side signing, no privileged role required) and submit them together via `execute_intents`/`simulate_intents`, which any unprivileged account can call. Splitting into N legs is entirely under the attacker's control; if only one side is required to self-trade (e.g., attacker uses two of their own accounts), no counterparty cooperation is needed at all. This is fully feasible without any relayer key, DAO/role, or upgrade privilege.

### Recommendation
Do not compute the NEP-245/IMT fee waiver per-leg based on the individual intent's `amount`; instead aggregate the negative delta for each `(token_id)` across the whole execution/batch (or at minimum, only waive the fee for truly indivisible `amount == 1` transfers of a token whose max supply per id is 1, akin to NFTs), and compute `fee_ceil` once on the aggregated amount. Alternatively, apply the fee to NEP-245/IMT tokens the same way as NEP-141 (always fee, using `fee_ceil`), removing the `amount > 1` carve-out, or track cumulative fee-exempt volume per token per signer per batch and only exempt genuine `amount == 1` unsplittable transfers rather than allowing repeated `amount == 1` legs to add up to an arbitrarily large notional.

### Proof of Concept
Add a `cargo test` in `contracts/defuse/core/src/intents/token_diff.rs` (or an integration test using `Engine::execute_signed_intents`) that:
1. Sets `protocol_fee = Pips::ONE_PERCENT` (or any nonzero `Pips`) and an NEP-245 `TokenId` (e.g., via `Nep245TokenId::new(...)`).
2. Case A (single, non-split): construct one `TokenDiff` with `diff = {token: -100}` (paired with an offsetting `+100` counter-intent from a second signer/account to satisfy `TransferMatcher::finalize`), execute via the engine, and record `fees_collected` for `token` — expect `protocol_fee.fee_ceil(100) > 0`.
3. Case B (split batch): construct 100 separate signed `TokenDiff` intents each with `diff = {token: -1}` (paired with 100 matching `+1` counter-intents from the second account, or a single aggregated `+100` diff on the other side), execute the whole `Vec<MultiPayload>` via `execute_signed_intents`, and sum `fees_collected` for `token` across all `TokenDiffEvent`s — expect the sum to equal `0`.
4. Assert `fees_collected_case_B < fees_collected_case_A`, demonstrating `Pips::fee_ceil` over the aggregate exceeds the sum of `Pips::fee_ceil` over the unit-split legs, confirming the fee-bypass.

        mut self,

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }

    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
