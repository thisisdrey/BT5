### Title
Missing `Offloading.Enabled` check allows rehydration when the offloading feature is administratively disabled - (File: internal/gitaly/service/repository/optimize.go)

### Summary
`OptimizeRepository`'s `STRATEGY_OFFLOADING` branch guards execution with `s.cfg.Offloading.Enabled`, but the `STRATEGY_REHYDRATION` branch omits this same guard, mirroring the reported bug class where a privileged action's "enabled" check exists on one code path but is missing on a functionally paired path that performs an equally sensitive operation.

### Finding Description
`s.cfg.Offloading.Enabled` is the administrator-controlled switch intended to gate the entire offloading feature (moving/restoring repository objects to/from an external `GoCloudURL` sink). The `STRATEGY_OFFLOADING` branch correctly enforces it: [1](#0-0) 

However, the `STRATEGY_REHYDRATION` branch — which reads back repository objects from the external `GoCloudURL` sink and rewrites the local repository — never checks `s.cfg.Offloading.Enabled`; it only validates that `GoCloudURL` is configured: [2](#0-1) 

The test suite documents this explicitly as an intentional-looking behavior ("rehydrate is still callable when offloading feature is not enabled in config"), showing the omission was deliberate rather than accidental, but it is precisely the kind of asymmetric enablement check the Trail of Bits report class targets: [3](#0-2) 

Because `OptimizeRepository` is reachable directly via the gRPC `RepositoryService` by any caller authorized to call `OptimizeRepository` on a repository (a MAINTENANCE-scoped RPC, not gated by any additional authorization layer beyond normal repository-scoped auth), an ordinary caller can invoke `STRATEGY_REHYDRATION` even when an administrator has turned off offloading (`Offloading.Enabled = false`), so long as `GoCloudURL` remains configured in Gitaly's config and the target repository has a `remote.offload.url` set (e.g., from a prior offloading operation performed before the feature was disabled, or through any path that can set this git config value).

### Impact Explanation
This allows a caller to invoke a network/external-storage operation (fetching objects from an external sink and rehydrating them into the local repository) that the administrator explicitly disabled by turning off the offloading feature. Depending on deployment, this can:
- Cause outbound network calls to external storage buckets/URLs (`GoCloudURL`) that operators intended to fully disable, undermining a feature kill-switch used for cost, compliance, or security control.
- Trigger unexpected disk/storage writes and repository mutation despite the feature being turned off, which the config flag is meant to prevent as an operational safety mechanism.

### Likelihood Explanation
Likelihood is moderate: exploitation requires (1) `GoCloudURL` still configured (common if offloading was enabled at some point and later disabled without clearing the URL), and (2) the target repository already carries `remote.offload.url` from a prior offload. Both conditions are realistic in real deployments transitioning the feature on/off, and the RPC is reachable through the standard `OptimizeRepository` gRPC call available to any client with repository access.

### Recommendation
Add the same `s.cfg.Offloading.Enabled` check to the `STRATEGY_REHYDRATION` branch that already exists in `STRATEGY_OFFLOADING`, so that both directions of the offloading feature are gated by the single administrative switch, consistent with the fix recommended in the analog report (apply the missing guard, and audit for any other caller of `RehydrateRepository`/`OffloadRepository` for the same asymmetry).

### Proof of Concept
1. Administrator sets `Offloading.Enabled = false` but leaves `Offloading.GoCloudURL` configured (e.g., after disabling offloading post-migration).
2. A repository previously offloaded (or one where `remote.offload.url` is otherwise set) still has a valid `remote.offload.url` git config entry pointing into the configured `GoCloudURL` bucket.
3. A caller sends `OptimizeRepository` with `Strategy: STRATEGY_REHYDRATION` against that repository.
4. The `STRATEGY_OFFLOADING` guard (`s.cfg.Offloading.Enabled`) is never evaluated for this branch; the rehydration proceeds via `s.housekeepingManager.RehydrateRepository`, fetching objects from the external sink and mutating the repository — despite offloading being administratively disabled.

	case gitalypb.OptimizeRepositoryRequest_STRATEGY_REHYDRATION:
		if s.cfg.Offloading.GoCloudURL == "" {
			return nil, structerr.NewInvalidArgument("offloading configuration missing sink URL")
		}

		// offloadRemoteURL is the url stored in git config remote.offload.url
		isOffloaded, offloadRemoteURL, err := repo.IsOffloaded(ctx)
		if !isOffloaded {
			if err == nil {
				return nil, structerr.NewFailedPrecondition("repository is not offloaded")
			}
			return nil, structerr.NewFailedPrecondition("invalid offloaded repository state: %w", err)
		}

		parsedRemoteURL, err := url.Parse(offloadRemoteURL)
		if err != nil {
			return nil, structerr.NewInvalidArgument("invalid URL: %w", err)
		}

		storageURL, err := url.Parse(s.cfg.Offloading.GoCloudURL)
		if err != nil {
			return nil, structerr.NewInvalidArgument("invalid URL: %w", err)
		}

		// Prefix is derived by removing the storage URL path prefix from the remote URL path.
		// For example:
		// - In the Git config: remote.offload.url = "gcp://my_bucket/@hash/11/22/112233abc.git/my_uuid"
		// - In the Gitaly config: GoCloudURL = "gcp://my_bucket"
		// The resulting prefix will be: "@hash/11/22/112233abc.git/my_uuid"
		prefix := strings.TrimSpace(strings.TrimPrefix(parsedRemoteURL.Path, storageURL.Path+"/"))
		if prefix == "" || prefix == parsedRemoteURL.Path {
			return nil, structerr.NewInvalidArgument("extract object prefix from URLs")
		}

		if err := s.housekeepingManager.RehydrateRepository(ctx, repo, prefix); err != nil {
			return nil, structerr.NewInternal("%w", err)
		}
