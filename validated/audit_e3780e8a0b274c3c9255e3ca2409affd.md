### Title
Mid-session peer-identity swap via unauthenticated re-handshake bypasses key-continuity check - (File: `stackslib/src/net/chat.rs`)

### Summary
`ConversationP2P::validate_handshake` only re-verifies the signature of an inbound `Handshake` against the *newly claimed* key when no public key is yet pinned for the conversation; once a key is already pinned (`self.connection.get_public_key() == Some(cur_pubk)`), it performs *no* signature check against `cur_pubk` at all for inbound sessions, and `update_from_handshake_data` then unconditionally calls `self.connection.set_public_key(Some(pubk))`, silently swapping the trusted identity to any new self-signed key sent by the same peer.

### Finding Description
The broken invariant: "the public key trusted for a `ConversationP2P` after a re-key `Handshake` must equal a key whose transition was authorized by the previously-trusted key" is not enforced.

`validate_handshake` (`stackslib/src/net/chat.rs:1047-1127`):
- If `self.connection.get_public_key()` is `None`, it verifies the message is signed by the *claimed new* key (`handshake_data.node_public_key`) — this is fine for a first handshake, but proves nothing about trust continuity. [1](#0-0) 
- If a key is already pinned (`Some(_)` branch), the **only** check performed is an address/port match, and only for **outbound** conversations. There is no call to `verify_secp256k1` against `cur_pubk`, and inbound conversations (the attacker-reachable case) get no check whatsoever in this branch. [2](#0-1) 

`update_from_handshake_data` then unconditionally overwrites session state and swaps the pinned key regardless of whether the new key was ever endorsed by the old one: [3](#0-2) 

The function's own doc-comment on the caller claims the guarantee that the audit expects but the code does not implement: "A handshake will only be accepted if we do not yet know the public key of this remote peer, or if it is signed by the current public key." — the "signed by the current public key" branch simply does not exist in `validate_handshake`. [4](#0-3) 

Exploit flow: attacker opens a TCP connection to a node's P2P port, completes a normal `Handshake`/`HandshakeAccept` with key `A` (self-signed, valid per the `None` branch), then sends a second `Handshake` on the same socket/conversation self-signed with a fresh, unrelated key `B`. Because `self.connection.get_public_key()` is now `Some(A)`, `validate_handshake` skips signature verification entirely (inbound case) and only checks address for outbound; the message is accepted, `handle_handshake` calls `update_from_handshake_data`, and `self.connection.set_public_key(Some(B))` replaces `A` with `B` with no proof `B` was ever authorized by `A`.

### Impact Explanation
Any logic elsewhere in the node that relies on "this `ConversationP2P`/socket has consistently spoken as key `K`" (e.g., neighbor trust bookkeeping, allow/deny decisions keyed by the conversation's pinned public key, StackerDB peer authorization tied to the conversation identity) can be silently defeated: the attacker swaps the identity bound to an already-open, possibly-privileged conversation to an arbitrary key it controls, without ever proving continuity of trust. This is a session-identity/auth-bypass class issue reachable with a couple of crafted messages from an unprivileged remote peer, matching the Critical "auth bypass" category.

### Likelihood Explanation
No special privileges, secrets, or non-network access are required: any remote party can open a P2P connection, perform one legitimate self-signed handshake, then immediately send a second self-signed handshake with a different key on the same connection. The attack is deterministic and repeatable per-connection at negligible cost (two small signed messages).

### Recommendation
In `validate_handshake`, when `self.connection.get_public_key()` is `Some(cur_pubk)`, require that the incoming `Handshake` message be verified against `cur_pubk` (i.e., `message.verify_secp256k1(&cur_pubk)`) before allowing any key change, or require an explicit, separately-signed key-rotation attestation from the old key. Reject re-handshakes whose new key is not endorsed by the previously-trusted key rather than only checking address/port.

### Proof of Concept
Rust test plan (in `stackslib/src/net/chat.rs` test module, using existing `ConversationP2P` test scaffolding used elsewhere in that file):
1. Construct a `ConversationP2P` for an inbound peer; build and send `Handshake` #1 self-signed with private key `A`; call `handle_handshake`/`update_from_handshake_data` and assert `self.connection.get_public_key() == Some(pubkey_A)`.
2. Build `Handshake` #2 with `node_public_key = pubkey_B`, self-signed with private key `B` (not `A`), same conversation/connection object (no address change needed for inbound).
3. Call `validate_handshake` then `update_from_handshake_data` (or the full `handle_handshake` path) with message #2.
4. Assert `self.connection.get_public_key() == Some(pubkey_B)` and that no `net_error` was returned — demonstrating the identity swap succeeds without any signature from `A` endorsing the transition to `B`.

    pub fn update_from_handshake_data(
        &mut self,
        preamble: &Preamble,
        handshake_data: &HandshakeData,
    ) -> Result<bool, net_error> {
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;

        self.peer_version = preamble.peer_version;
        self.peer_network_id = preamble.network_id;
        self.peer_services = handshake_data.services;
        self.peer_expire_block_height = handshake_data.expire_block_height;
        self.handshake_addrbytes = handshake_data.addrbytes.clone();
        self.handshake_port = handshake_data.port;
        self.data_url = handshake_data.data_url.clone();

        let mut updated = false;
        let cur_pubk_opt = self.connection.get_public_key();
        if let Some(cur_pubk) = cur_pubk_opt {
            if pubk != cur_pubk {
                debug!(
                    "{:?}: Upgrade key {:?} to {:?} expires {:?}",
                    &self,
                    &to_hex(&cur_pubk.to_bytes_compressed()),
                    &to_hex(&pubk.to_bytes_compressed()),
                    self.peer_expire_block_height
                );
                updated = true;
            }
        }

        self.connection.set_public_key(Some(pubk.clone()));

        Ok(updated)
    }
