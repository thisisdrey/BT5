### Title
Unauthenticated `POST /v3/blocks/upload/` triggers network-wide peer relay regardless of `broadcast` flag or authentication - ([File: stackslib/src/net/api/postblock_v3.rs])

### Summary
`RPCPostBlockRequestHandler::try_handle_request` gates relay-to-peers solely on `data_resp.accepted`, ignoring `self.broadcast` (and by extension the authentication state that `try_parse_request` enforces only when `broadcast=1`). Any unauthenticated caller who posts a block that chainstate accepts causes `node.set_relay_message(StacksMessageType::NakamotoBlocks(...))` to fire, which queues the block for relay to this node's peers exactly as if it had passed the authenticated broadcast path.

### Finding Description
The intended equality per the dual-security design is: relay-to-peers should require `broadcast == true` (which itself requires `authenticated == true`, enforced at `stackslib/src/net/api/postblock_v3.rs` lines 99-122: `if broadcast && !authenticated { return Err(Error::Http(401, ...)) }`). But the actual relay trigger in `try_handle_request` is:

```
if data_resp.accepted {
    node.set_relay_message(StacksMessageType::NakamotoBlocks(NakamotoBlocksData {
        blocks: vec![block],
    }));
}
``` [1](#0-0) 

This condition depends only on whether `Relayer::process_new_nakamoto_block_ext` reports the block as accepted by chainstate — it does not consult `self.broadcast` or any authentication flag at all. `self.broadcast.unwrap_or(false)` is passed into `process_new_nakamoto_block_ext` [2](#0-1) , but whatever that internal parameter does inside chainstate processing, it has no bearing on the RPC handler's own decision to call `set_relay_message`. Consequently, an unauthenticated POST (no `broadcast=1`, no `authorization` header — a completely legal request per lines 99-122, since the 401 check only fires when `broadcast=true`) that happens to contain a block chainstate deems acceptable (e.g., a block for a fork/tenure the node has already validated by other means, or any structurally/cryptographically valid Nakamoto block) will still be queued for relay to the node's own peers.

### Impact Explanation
This breaks the auth gate's purpose: the `broadcast=1` + `authorization` requirement is meant to be the sole path by which an external caller can force this node to push a block onward to its peer set. Because the relay decision is keyed only on chainstate acceptance, any unprivileged remote caller can cause network propagation without ever authenticating, matching the "network-wide propagation of forged/unauthorized data" / "auth bypass" Critical category. Repeatable per valid block the attacker can obtain or construct that chainstate will accept.

### Likelihood Explanation
Precondition: attacker needs a block that local chainstate validation will accept (this still requires a validly formed/signed Nakamoto block — the vulnerability is the missing authorization check on the relay trigger, not a chainstate validation bypass). No secret, no peer key, no privileged role is needed — only network reachability to the RPC port, which is the documented attacker capability. Cost is a single HTTP POST per triggered relay, fully repeatable.

### Recommendation
Change the relay condition to also require `self.broadcast == Some(true)` (and thus, by construction, authentication), e.g.:
```
if data_resp.accepted && self.broadcast.unwrap_or(false) {
    node.set_relay_message(...);
}
```
so that unauthenticated/non-broadcast uploads are only stored, never queued for peer relay.

### Proof of Concept
Rust net test plan:
1. Instantiate `RPCPostBlockRequestHandler::new(Some("secret".into()))`.
2. Construct a `HttpRequestPreamble` with no `authorization` header and no `broadcast` query param, content-type `application/octet-stream`, body = a `consensus_serialize`d `NakamotoBlock` known to be acceptable by a test `StacksNodeState`/chainstate fixture (e.g., a block already staged/known-valid in the test harness).
3. Call `try_parse_request` — assert it succeeds (no 401) and `self.broadcast == Some(false)`.
4. Call `try_handle_request` with a `StacksNodeState` wired to a chainstate that will accept the block.
5. Assert `data_resp.accepted == true`, then inspect `node`'s pending relay message state (`StacksNodeState::relay_message` / whatever internal field `set_relay_message` populates) and assert it is `Some(StacksMessageType::NakamotoBlocks(...))` despite `broadcast == false` and no authentication — demonstrating the broken equality at `stackslib/src/net/api/postblock_v3.rs` lines 197-202.
