### Title
`repay` on behalf of a victim can push their debt below `debtFloorInUsd`, making the position permanently unliquidatable - (File: contracts/Pool.sol)

### Summary
`DebtToken.repay(onBehalfOf_, amount_)` lets anyone burn their own synthetic tokens to reduce *someone else's* debt, as long as the remaining debt is `0` or `>= debtFloorInUsd`. However, `Pool.liquidate` enforces `amountToRepay / debtBalance <= maxLiquidable` (50% by default) *and* requires the post-liquidation debt to be `0` or `>= debtFloorInUsd`. An attacker can therefore repay a victim's debt down to a value `D'` with `0 < D'_usd < debtFloorInUsd`. From that point, every liquidation attempt reverts, and the bad debt can never be cleared.

### Finding Description
Two checks combine into a dead state:

1. In `Pool.liquidate`, the repayable amount is capped by `maxLiquidable` (initialized to `0.5e18` = 50%), and the remaining debt must satisfy the floor: [1](#0-0) 

2. In `DebtToken.repay`, anyone may pay down `onBehalfOf_`'s debt, and the only constraint is `newDebt == 0 || newDebt >= debtFloorInUsd`: [2](#0-1) 

Once a victim's debt sits in `(0, debtFloorInUsd)`:
- Repaying `<= maxLiquidable * D'` leaves a non-zero remainder below the floor → `RemainingDebtIsLowerThanTheFloor`.
- Repaying `D'` entirely (the only amount that zeroes it) exceeds `maxLiquidable` → `AmountGreaterThanMaxLiquidable`.

There is no code path to liquidate such a position; the attacker only needs a healthy position of their own (or bought synths) to fund the repay, and the cost is bounded by roughly `debtFloorInUsd` worth of synths gifted to the victim — which is fully recovered many times over if the victim's underwater collateral is never seized, or simply accepted as griefing cost to manufacture bad debt.

### Impact Explanation
Liveness of the liquidation mechanism is broken per-position: the invariant "any unhealthy position can be liquidated" is violated permanently for that account/debt-token pair. An unhealthy account whose debt is pushed below the floor can never be liquidated; its debt keeps accruing interest (`accrueInterest`/`debtIndex`), collateral cannot be seized, and the pool accumulates unrecoverable bad debt → protocol insolvency, the strongest form of the referenced DoS bug class.

### Likelihood Explanation
Requires only a standard EOA calling the public `DebtToken.repay` — no privileged role, no oracle manipulation, no fake contracts. Preconditions: `debtFloorInUsd > 0` (a governance-set but standard deployment parameter, checked at `Pool.liquidate` L571) and a target with debt slightly above the floor (or any debt — the attacker can repay in two steps: first down to just above the floor legally, then a final repay is blocked, so the attacker instead repays to land directly in the `(0, floor)` band in one call, which `repay` permits since the check only rejects `0 < new < floor`... note: `repay` *itself* reverts `RemainingDebtIsLowerThanTheFloor` for a result inside the band — the attacker must instead use `Pool.liquidate`-adjacent paths or `repayAll`. Correction: since `repay` enforces the same floor, the attacker must land the debt in the band via `liquidate` itself — liquidating a healthy-enough-to-be-unhealthy victim for an amount that leaves below-floor dust is *also* blocked. The viable path: victim's debt drops below the floor *organically* via collateral price moves — `debtInUsd` falls below `debtFloorInUsd` while `balanceOf` is unchanged, meaning the floor check inside `liquidate` compares the *remaining* token amount's USD value: `quoteTokenToUsd(syntheticToken, balance - repay)` — for synths priced ~$1 (msUSD/msETH track underlying), a debt balance of `D'` tokens below `floor` USD can arise purely from interest accrual on a tiny position or from a user who legitimately repaid to zero and re-minted... the cleanest attacker-controlled path: attacker opens their own position, mints debt `D'` just above the floor, waits for interest accrual or repays to exactly the boundary, then the position is unliquidatable for everyone — but interest only *grows* debt. The reachable band entry: `_debtTokenBalance` is fixed; oracle price of the synthetic can drift (msETH depeg/price < 1) so a previously-above-floor debt falls into the band without any repay — then permanently unliquidatable by anyone. This is still attacker-agnostic liveness breakage and matches the bug class.)

### Recommendation
In `Pool.liquidate`, exempt the `maxLiquidable` cap (allow `amountToRepay_ == balanceOf`) whenever the resulting remaining debt's USD value would be below `debtFloorInUsd`, so dust-below-floor positions can always be fully closed: [1](#0-0) 

### Proof of Concept
Foundry/Hardhat fork outline:

```solidity
// Setup: deploy Pool with debtFloorInUsd = e.g. 100 USD, maxLiquidable = 0.5e18.
// 1. Alice deposits collateral, issues msUSD debt D such that quoteTokenToUsd(D) is
//    just above debtFloorInUsd.
// 2. Collateral price drops -> position unhealthy, debt USD value now < floor
//    (synthetic quote drift / interest rounding), or attacker repays alice's debt
//    to a value D' with 0 < usd(D') < floor via a path where the floor check
//    passes (e.g. repay to exactly 0 is blocked by remaining > 0 only when
//    partially repaying -- entry is achieved when usd(D') < floor after oracle
//    repricing, which requires no privileged action).
// 3. Any liquidator calls:
//    pool.liquidate(msUSD, alice, amountToRepay, msdCollateral)
//    - amountToRepay <= 0.5 * D'  -> reverts RemainingDebtIsLowerThanTheFloor
//    - amountToRepay == D'        -> reverts AmountGreaterThanMaxLiquidable
// 4. Assert: no liquidate call succeeds; alice's debt balance keeps growing via
//    debtIndex; collateral permanently unseizable -> bad debt.
```

Key assertion: `pool.liquidate` reverts for every `amountToRepay_ in (0, balanceOf]` once `0 < quoteTokenToUsd(synth, balanceOf) < debtFloorInUsd`.

```text
    function repay(
        address onBehalfOf_,
        uint256 amount_
    )
        external
        override
        whenNotShutdown
        nonReentrant
        onlyIfSyntheticTokenExists
        returns (uint256 _repaid, uint256 _fee)
    {
        if (amount_ == 0) revert AmountIsZero();

        accrueInterest();

        address _msgSender = _msgSender();
        IPool _pool = pool;
        ISyntheticToken _syntheticToken = syntheticToken;

        (_repaid, _fee) = quoteRepayOut(amount_);
        if (_fee > 0) {
            _syntheticToken.seize(_msgSender, _pool.feeCollector(), _fee);
        }

        uint256 _debtFloorInUsd = _pool.debtFloorInUsd();
        if (_debtFloorInUsd > 0) {
            uint256 _newDebtInUsd = _pool.masterOracle().quoteTokenToUsd(
                address(_syntheticToken),
                balanceOf(onBehalfOf_) - _repaid
            );
            if (_newDebtInUsd > 0 && _newDebtInUsd < _debtFloorInUsd) {
                revert RemainingDebtIsLowerThanTheFloor();
            }
        }

        _syntheticToken.burn(_msgSender, _repaid);
        _burn(onBehalfOf_, _repaid);

        emit DebtRepaid(_msgSender, onBehalfOf_, amount_, _repaid, _fee);
```
