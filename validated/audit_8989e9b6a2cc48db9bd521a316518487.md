### Title
Unauthenticated `/shutdown` HTTP endpoint permanently halts the signer's event receiver - (`libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event()` treats any POST to `/shutdown` as a legitimate stop signal with no authentication, sender check, or secret verification. Any TCP client that can reach the signer's event-listener port can permanently terminate the signer's event receiver main loop with a single HTTP request.

### Finding Description
The claimed equality is: "the identity of whoever is allowed to stop the receiver == the process's own `SignerStopSignaler`." Tracing the code shows this equality is never enforced. In `libsigner/src/events.rs`, `SignerEventReceiver::next_event()` dispatches on `request.url()`: [1](#0-0) 

There is no check of the request body, no shared secret, no origin/IP allow-list, and no correlation to the internal `SignerStopSignaler` (`libsigner/src/events.rs:361-396`), which is the only *intended* caller of this path. Any HTTP client — including an unrelated third party who can open a TCP connection to the bound address — can send:

```
POST /shutdown HTTP/1.1\r\nHost: <addr>\r\nContent-Length: 0\r\n\r\n
```

This sets `event_receiver.stop_signal` to `true` and returns `Err(EventError::Terminated)`. That error is caught by `EventReceiver::main_loop()`'s dedicated branch, which unconditionally `break`s the loop forever: [2](#0-1) 

Once the loop exits, the thread spawned in `Signer::spawn()` (`libsigner/src/runloop.rs:229-236`) ends, and the event receiver never calls `next_event()` again — permanently stopping ingestion of `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events from the actual Stacks node. No existing guard (auth-gate, secret, signature, per-field cap) applies to this route, unlike `/stackerdb_chunks` etc. which at least deserialize signed chunk data; `/shutdown` performs a privileged action with zero validation.

### Impact Explanation
A single unauthenticated message from any TCP client that can reach the signer's event-listener bind address permanently disables that signer's event pipeline (StackerDB chunk events, burn/stacks block events, proposal responses). This is a targeted denial of service against the signer's transport layer — the signer process keeps running but stops receiving/acting on any new node-pushed events until manually restarted. This matches "Critical - remote crash/unauthenticated DoS from few messages" in effect (permanent halt from one message), scoped specifically to the event-receiver component (not the signing/consensus logic itself, and not general connection exhaustion).

### Likelihood Explanation
Preconditions: the attacker only needs network (TCP) reachability to the signer's bound event-listener address/port — no RPC secret, no peer key, no StackerDB slot ownership, and no admin role are required. The attack costs a single crafted HTTP request and is deterministic and repeatable (any signer that exposes this listener beyond strict localhost/loopback is vulnerable; the bind address is operator-configured and is not inherently restricted to localhost in code — `bind()` accepts any `SocketAddr` passed by the operator, so misconfiguration or firewall gaps expose it directly). No legitimate `SignerStopSignaler::send()` from the owning process is required.

### Recommendation
Require an authenticated/secret-bearing shutdown mechanism instead of a bare, unauthenticated HTTP path: e.g., use a locally generated per-run token that `SignerStopSignaler` includes in the request (compared in constant time), bind the listener strictly to loopback by default, or replace the HTTP-based stop mechanism with a proper inter-thread/OS-level signal not reachable over the network. At minimum, validate that `/shutdown` requests originate from `127.0.0.1`/the local process and carry a shared secret set at startup.

### Proof of Concept
Rust test in `libsigner`'s test module (alongside `test_status_endpoint` in `libsigner/src/tests/mod.rs:199-230`):
1. Construct a `SignerEventReceiver::new(false)`, wrap in `Signer::new(...)`, and `spawn()` it bound to `127.0.0.1:<port>`.
2. From a separate thread simulating an "attacker" (not the process's own `SignerStopSignaler`), open a raw `TcpStream::connect(endpoint)` and write:
   `POST /shutdown HTTP/1.1\r\nHost: <endpoint>\r\nConnection: close\r\nContent-Length: 0\r\n\r\n`
3. Sleep briefly, then assert `running_signer` event thread has exited (e.g., via `is_stopped()` on a cloned stop flag, or by observing `RunningSigner::stop()`/`join()` returns immediately without hanging).
4. Separately, attempt to send a legitimate `/stackerdb_chunks` event afterward and confirm it is never forwarded (channel receives nothing), proving the receiver is permanently dead — matching the exact `Err(EventError::Terminated)` branch at `libsigner/src/events.rs:296-300`.

    fn main_loop(&mut self) {

                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }
