Confirmed: `receipt.success` is decoded but never referenced anywhere in `outbound-queue-v2`, and `process_delivery_receipt` unconditionally pays the reward and removes the `PendingOrder` regardless of the flag's value.

Audit Report

## Title
Relayer reward is paid and pending order is finalized on delivery receipts without checking the `success` flag - (File: `bridges/snowbridge/pallets/outbound-queue-v2/src/lib.rs`)

## Summary
`DeliveryReceipt::success` is decoded from the Ethereum `InboundMessageDispatched(nonce, topic, success, reward_address)` event log via `TryFrom<&Log>` [1](#0-0) , but `process_delivery_receipt` never reads this field before paying the relayer reward and removing the `PendingOrder` [2](#0-1) . This causes bridge settlement state (`PendingOrders`, `MessageDelivered`) and relayer payout to advance as if the underlying Ethereum command execution succeeded, even when it reverted/failed.

## Finding Description
`submit_delivery_receipt` verifies the proof, decodes the receipt, and calls `process_delivery_receipt` unconditionally on a successful decode [3](#0-2) . Inside `process_delivery_receipt`, the code checks only `receipt.gateway` against `T::GatewayAddress`, fetches the `PendingOrder` by `receipt.nonce`, pays `order.fee` to the reward account if positive, removes the order, and emits `Event::MessageDelivered` — at no point is `receipt.success` inspected [4](#0-3) . A grep across the pallet confirms `receipt.success`/`.success` is never referenced anywhere in `outbound-queue-v2`'s logic or tests, confirming the field is decoded and then dropped. The Solidity event signature explicitly carries a distinct `success: bool` alongside `nonce`/`topic`/`reward_address` <cite repo="Lauraivanka/polkadot-sdk--002" path="bridges/snowbridge/primitives/outbound-queue/src/v2/delivery_receipt.rs" start="10-27" end="27" />, indicating the protocol design intends for dispatch outcome to be distinguishable from dispatch occurrence, but the consuming pallet does not act on that distinction.

## Impact Explanation
Because `PendingOrders` is unconditionally removed and the reward unconditionally paid regardless of `success`, a delivery whose on-chain command execution failed (e.g. a value-moving command that reverted on the Ethereum side) is nonetheless recorded as `MessageDelivered`, permanently closing the settlement window with no retry path, while the relayer still collects `order.fee`. This matches the required pivot that message/receipt/payout state must only advance after execution and settlement succeed atomically, and falls under "duplicate settlement or payout" / "permanent... bridge-state lock" impact categories.

## Likelihood Explanation
`submit_delivery_receipt` is a public extrinsic requiring only `ensure_signed` [5](#0-4) ; any relayer holding a valid inclusion proof for a genuine `InboundMessageDispatched` log — including one with `success = false` — can trigger payout and order removal with no additional privilege or governance action needed.

## Recommendation
Branch on `receipt.success` in `process_delivery_receipt`: on `false`, withhold or reduce the reward and avoid removing the `PendingOrder` (or route to a distinct failure-handling/retry path), so that only genuinely successful executions are settled and rewarded.

## Proof of Concept
1. A message with fee-bearing `PendingOrder` (nonce `N`) is queued via `do_process_message` [6](#0-5) .
2. Ethereum emits `InboundMessageDispatched(N, topic, success=false, reward_address)` because the dispatched command execution failed.
3. A relayer builds a proof for this log and calls `submit_delivery_receipt`; `DeliveryReceipt::try_from` decodes `success = false` [7](#0-6) .
4. `process_delivery_receipt` ignores `success`, pays `order.fee`, removes `PendingOrders[N]`, and emits `MessageDelivered` [8](#0-7) .
5. A unit test asserting `PendingOrders::<Test>::get(nonce).is_none()` and reward registration after submitting a mock event log with `success = false` would demonstrate the unconditional settlement, analogous to the existing `submit_delivery_receipt_succeeds_after_unhalt` test pattern [9](#0-8) .

```rust
impl TryFrom<&Log> for DeliveryReceipt {
	type Error = DeliveryReceiptDecodeError;

	fn try_from(log: &Log) -> Result<Self, Self::Error> {
		let topics: Vec<B256> = log.topics.iter().map(|x| B256::from_slice(x.as_ref())).collect();

		let event = InboundMessageDispatched::decode_raw_log_validate(topics, &log.data)
			.map_err(|_| DeliveryReceiptDecodeError::DecodeLogFailed)?;

		Ok(Self {
			gateway: log.address,
			nonce: event.nonce,
			topic: H256::from_slice(event.topic.as_ref()),
			success: event.success,
			reward_address: event.reward_address.0,
		})
	}
```

```rust
		pub fn process_delivery_receipt(
			relayer: <T as frame_system::Config>::AccountId,
			receipt: DeliveryReceipt,
		) -> DispatchResult
		where
			<T as frame_system::Config>::AccountId: From<[u8; 32]>,
		{
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == receipt.gateway, Error::<T>::InvalidGateway);

			let reward_account = if receipt.reward_address == [0u8; 32] {
				relayer
			} else {
				receipt.reward_address.into()
			};

			let nonce = receipt.nonce;

			let order = <PendingOrders<T>>::get(nonce).ok_or(Error::<T>::InvalidPendingNonce)?;

			if order.fee > 0 {
				// Pay relayer reward
				T::RewardPayment::register_reward(
					&reward_account,
					T::DefaultRewardKind::get(),
					order.fee,
				);
			}

			<PendingOrders<T>>::remove(nonce);

			Self::deposit_event(Event::MessageDelivered { nonce });

			Ok(())
		}
```

```rust
#[test]
fn submit_delivery_receipt_succeeds_after_unhalt() {
	new_tester().execute_with(|| {
		let nonce = 0;
		let fee: u128 = 1_000_000;
		let order = PendingOrder { nonce, fee, block_number: System::block_number() };
		PendingOrders::<Test>::insert(nonce, order);

		let relayer: AccountId32 = [7u8; 32].into();
		let origin = RuntimeOrigin::signed(relayer);
		let event = Box::new(mock_valid_event_proof());

		// Bridge halted — receipt rejected, order untouched.
		set_verifier_halted(true);
		assert_noop!(
			OutboundQueue::submit_delivery_receipt(origin.clone(), event.clone()),
			Error::<Test>::Verification(VerificationError::Halted)
		);
		assert!(PendingOrders::<Test>::get(nonce).is_some());

		// Bridge resumed — same receipt succeeds and the order is settled.
		set_verifier_halted(false);
		assert_ok!(OutboundQueue::submit_delivery_receipt(origin, event));
		assert!(PendingOrders::<Test>::get(nonce).is_none());

		System::assert_has_event(mock::RuntimeEvent::OutboundQueue(Event::MessageDelivered {
			nonce,
		}));
	});
```
