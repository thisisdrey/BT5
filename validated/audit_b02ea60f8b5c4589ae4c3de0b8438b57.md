### Title
Unauthenticated `/shutdown` HTTP request terminates the signer's `SignerEventReceiver` main loop - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` treats any `POST /shutdown` request as a valid stop command, setting `stop_signal` to `true` and returning `EventError::Terminated`, which causes `EventReceiver::main_loop` to exit permanently. There is no authentication, secret, or origin check on this code path, so anyone able to reach the signer's event-receiver listening socket can end the signer's ability to receive further node-pushed events with a single HTTP request.

### Finding Description
In `libsigner/src/events.rs`, `SignerEventReceiver::next_event` dispatches based solely on `request.url()`: [1](#0-0) 
Reaching `/shutdown` requires only a valid HTTP `POST` to that path — no signature, token, or IP allow-list check is performed anywhere in `next_event`, `with_server`, or `bind`. Compare with the legitimate stop path in `SignerStopSignaler::send`, which is only invoked in-process (by the runloop on `main_loop` exit, or by `set_runloop_signal_handler` on OS signals) and constructs the identical unauthenticated `POST /shutdown` request purely as an inter-thread wakeup mechanism: [2](#0-1) 
Once `stop_signal` is set to `true`, `is_stopped()` returns `true` and the shared `EventReceiver::main_loop` breaks out of its loop, permanently ending event processing for that signer instance: [3](#0-2) 
This is the same server socket the Stacks node uses to push `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events to the signer, as exercised in the test harness's mock node client, which connects with a plain `TcpStream` and no credentials.

### Impact Explanation
Any TCP peer that can reach the signer's event-receiver bind address can permanently stop the `SignerEventReceiver` thread with one HTTP request, after which `RunningSigner`'s event thread has exited and the signer stops receiving StackerDB chunk pushes, block-validation responses, and burn-block/tip notifications from its node — degrading or halting that signer's participation in signing rounds. This matches "Critical - remote crash/unauthenticated DoS from few messages" for the signer process's event pipeline, though it does not corrupt node consensus state and only affects the signer that exposes this listener.

### Likelihood Explanation
No secret, peer identity, StackerDB slot ownership, or privileged role is needed — a bare `POST /shutdown` over TCP suffices, and it's a single message, fully repeatable (an attacker can send it again after any restart/reconnect). The precondition is that the event-receiver's bind address (configured via the signer's `endpoint` config, e.g. `stacks-signer/src/config.rs`) is reachable from the attacker's network position; if operators bind it only to `127.0.0.1`/an internal interface, the practical exposure is limited to that network segment, but the code itself enforces no authentication regardless of interface.

### Recommendation
Do not expose a `/shutdown` HTTP path for the same listener used for external event ingestion. Options: require a shared secret/HMAC known only to the local node and signer, restrict the shutdown mechanism to a local-only channel (e.g. Unix domain socket, in-process channel, or check the connecting peer is loopback), and reject `/shutdown` when the request doesn't originate from `127.0.0.1`/an explicitly trusted address.

    fn main_loop(&mut self) {
        loop {
            if self.is_stopped() {
                info!("Event receiver stopped");
                break;
            }
            let next_event = match self.next_event() {
                Ok(event) => event,
                Err(EventError::UnrecognizedEvent(..)) => {
                    // got an event that we don't care about (not a problem)
                    continue;
                }
                Err(EventError::Terminated) => {
                    // we're done
                    info!("Caught termination signal");
                    break;
                }
                Err(e) => {
                    warn!("Failed to receive next event: {:?}", &e);
                    continue;
                }
            };
            if !self.forward_event(next_event) {
                info!("Failed to forward event");
                break;
            }
        }
        info!("Event receiver main loop exit");
    }
