Audit Report

## Title
`reap_stash` permissionlessly kills a staking ledger without notifying `OnStakingUpdate::on_withdraw`, permanently desyncing nomination-pool `TotalValueLocked` accounting - (File: `substrate/frame/staking/src/pallet/impls.rs`, `substrate/frame/staking-async/src/pallet/impls.rs`)

## Summary
`pallet-staking`'s `kill_stash` removes a stash's ledger, bonded map entry, and payee/prefs but never invokes `T::EventListeners::on_withdraw`, unlike `do_withdraw_unbonded`, which explicitly notifies listeners of the residual amount being removed before/through calling `kill_stash`. `reap_stash` is a permissionless, unprivileged extrinsic that calls `kill_stash` directly, bypassing the notification entirely, which can leave `pallet-nomination-pools::TotalValueLocked` permanently inflated relative to actual bonded balances for the affected pool.

## Finding Description
`do_withdraw_unbonded` computes `old_total` vs `new_total` around the ledger consolidation/kill and fires `T::EventListeners::on_withdraw(controller, value)` whenever `new_total < old_total`, including in the branch where it calls `Self::kill_stash(&ledger.stash, num_slashing_spans)?` [1](#0-0) . In contrast, `kill_stash` itself only clears slashing metadata, the ledger, the bonded map, and validator/nominator prefs — it contains no call to `T::EventListeners::on_withdraw` or any equivalent hook [2](#0-1) . `reap_stash` calls `Self::kill_stash(&stash, num_slashing_spans)` directly as a permissionless, signed-only extrinsic once `ledger.total < ED` or zero, with no route through `do_withdraw_unbonded` and thus no notification of the residual `ledger.total` being wiped.

`pallet-nomination-pools::TotalValueLocked` is only decremented via the `OnStakingUpdate::on_withdraw`/`on_slash` hooks (confirmed by the pool's `on_withdraw` implementation reducing `TotalValueLocked` by exactly the reported amount) and is never re-derived from the live staking ledger during normal operation — only via an explicit, admin-triggered `TotalValueLockedSync` runtime-upgrade migration. This means any residual balance destroyed by `reap_stash` on a pool's bonded stash is permanently unaccounted for until a migration is run, contradicting the documented invariant that `TotalValueLocked` should never exceed the real sum of staked balances.

The delegated-staking path is also relevant: when nomination pools use `DelegateStake`, the staking pallet's `EventListeners` target is `pallet-delegated-staking`, whose `on_withdraw` implementation adds the amount to the agent's `unclaimed_withdrawals` ledger rather than directly notifying `pallet-nomination-pools`. This suggests the exact severity/mechanics of the desync (i.e., whether it's `TotalValueLocked` directly or `AgentLedger` bookkeeping that goes stale) depends on which stake strategy (`Transfer` vs `Delegate`) the pool uses — the report acknowledges this uncertainty itself and I was unable to fully trace this interaction across all runtime configurations within the available investigation budget.

The identical structural gap exists in `pallet-staking-async`: `do_withdraw_unbonded` calls `T::EventListeners::on_withdraw`, while `kill_stash` and the `force_unstake`/`reap_stash` call sites that invoke it do not.

## Impact Explanation
This is a state-accounting integrity bug: `pallet-nomination-pools::TotalValueLocked` can become permanently inflated relative to the real bonded/staked balance of the affected pool, violating the pallet's own documented invariant that this value must never exceed the sum of members' `total_balance`. This falls into the "runtime bugs that compromise intended behavior" impact category, since downstream logic (exit calculations, PPS, TVL caps, and any governance decisions gated on TVL) relies on this value being accurate, and it is corrupted without any privileged action.

## Likelihood Explanation
`reap_stash` is explicitly permissionless — callable by anyone once the target stash's `ledger.total` or free balance falls under the existential deposit — a state reachable through ordinary partial slashing/unbonding of a pool's bonded account. No elevated privileges, malicious peer, or compromised-relayer assumption is required, making this reachable by an ordinary user with a public extrinsic call, consistent with the accepted "unprivileged external attacker using public extrinsics" threat model.

## Recommendation
Route the residual `ledger.total` removed by `kill_stash` through the same `T::EventListeners::on_withdraw` (or an equivalent explicit "on_unstake") notification that `do_withdraw_unbonded` uses, so this fires uniformly regardless of whether stash removal occurs via `withdraw_unbonded`, `reap_stash`, or `force_unstake`. This should be added to both `pallet-staking` and `pallet-staking-async`.

## Proof of Concept
1. Create a nomination pool; its bonded account's stake is tracked in `pallet_nomination_pools::TotalValueLocked`.
2. Drive the pool's bonded stash `ledger.total` below the existential deposit via partial unbonding/slashing while leaving a small residual balance.
3. Call `Staking::reap_stash(RuntimeOrigin::signed(anyone), pool_bonded_account, num_slashing_spans)`; this succeeds since the reapable conditions (`ledger.total < ED`) are met.
4. `kill_stash` removes the ledger/bonded map entries with no call to `T::EventListeners::on_withdraw`, so `TotalValueLocked` is not decremented by the residual amount.
5. Assert `TotalValueLocked::<Runtime>::get()` still includes the destroyed residual stake, exceeding the real total staked balance of remaining pools — a unit/integration test in `pallet-staking`'s or `pallet-nomination-pools`' test harness comparing `TotalValueLocked` before/after `reap_stash` demonstrates the divergence directly.

	pub(super) fn do_withdraw_unbonded(
		controller: &T::AccountId,
		num_slashing_spans: u32,
	) -> Result<Weight, DispatchError> {
		let mut ledger = Self::ledger(Controller(controller.clone()))?;
		let (stash, old_total) = (ledger.stash.clone(), ledger.total);
		if let Some(current_era) = CurrentEra::<T>::get() {
			ledger = ledger.consolidate_unlocked(current_era)
		}
		let new_total = ledger.total;

		let ed = asset::existential_deposit::<T>();
		let used_weight =
			if ledger.unlocking.is_empty() && (ledger.active < ed || ledger.active.is_zero()) {
				// This account must have called `unbond()` with some value that caused the active
				// portion to fall below existential deposit + will have no more unlocking chunks
				// left. We can now safely remove all staking-related information.
				Self::kill_stash(&ledger.stash, num_slashing_spans)?;

				T::WeightInfo::withdraw_unbonded_kill(num_slashing_spans)
			} else {
				// This was the consequence of a partial unbond. just update the ledger and move on.
				ledger.update()?;

				// This is only an update, so we use less overall weight.
				T::WeightInfo::withdraw_unbonded_update(num_slashing_spans)
			};

		// `old_total` should never be less than the new total because
		// `consolidate_unlocked` strictly subtracts balance.
		if new_total < old_total {
			// Already checked that this won't overflow by entry condition.
			let value = old_total.defensive_saturating_sub(new_total);
			Self::deposit_event(Event::<T>::Withdrawn { stash, amount: value });

			// notify listeners.
			T::EventListeners::on_withdraw(controller, value);
		}

		Ok(used_weight)
	}

	/// Remove all associated data of a stash account from the staking system.
	///
	/// Assumes storage is upgraded before calling.
	///
	/// This is called:
	/// - after a `withdraw_unbonded()` call that frees all of a stash's bonded balance.
	/// - through `reap_stash()` if the balance has fallen to zero (through slashing).
	pub(crate) fn kill_stash(stash: &T::AccountId, num_slashing_spans: u32) -> DispatchResult {
		slashing::clear_stash_metadata::<T>(&stash, num_slashing_spans)?;

		// removes controller from `Bonded` and staking ledger from `Ledger`, as well as reward
		// setting of the stash in `Payee`.
		StakingLedger::<T>::kill(&stash)?;

		Self::do_remove_validator(&stash);
		Self::do_remove_nominator(&stash);

		Ok(())
	}
