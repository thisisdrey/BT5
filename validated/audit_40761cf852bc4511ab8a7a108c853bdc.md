The bug class is asymmetric emergency controls: a flag disables a borrower's defense path while `liquidate` stays enabled. Let me verify Metronome's modifiers on `deposit`, `withdraw`, `flashWithdraw`, `repay`, and `liquidate`.### Title
While `Pool` is paused or a `DepositToken` is deactivated, borrowers cannot add collateral to restore health, but `Pool.liquidate` remains fully enabled - (contracts/Pool.sol, contracts/DepositToken.sol)

### Summary
Metronome's emergency flags are asymmetric: `DepositToken.deposit` is guarded by `whenNotPaused` (and its `_mint` by `onlyIfDepositTokenIsActive`), while `Pool.liquidate` is guarded only by `whenNotShutdown`. When the governor pauses a `Pool`/`PoolRegistry` (deposit suspension — `pause()` only "Suspends deposit feature") or toggles a `DepositToken`'s `isActive` off, borrowers whose positions turn unhealthy cannot top up collateral to avoid liquidation, yet any third party holding the synthetic token can still liquidate them and collect the liquidation incentive. This mirrors the JUSDExchange-closed scenario: a defensive path for borrowers is disabled while liquidations proceed. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

### Finding Description
- `DepositToken.deposit` reverts when the pool (or `PoolRegistry`) is paused via `whenNotPaused`, and always reverts when `isActive == false` because `_mint` enforces `onlyIfDepositTokenIsActive`. `toggleIsActive()` is a governor-only per-collateral switch.
- `Pool.liquidate` (`contracts/Pool.sol:537-596`) has no `whenNotPaused` and no `onlyIfDepositTokenIsActive` check — the seize path goes through `DepositToken.seize` → `_transfer`, which is not gated by `isActive`. The test suite explicitly asserts `liquidate` "should not revert if paused" (`test/Pool.test.ts:353-365`).
- The same asymmetry holds for the repay side only partially: `DebtToken.repay`/`repayAll` are `whenNotShutdown` only, so they stay live during pause — but a borrower who holds no synthetic tokens and whose only defense is adding collateral (or who lacks the liquidity to buy synth) has no recourse. Notably `flashRepay` also remains available during a *pool* pause, but if the trigger is `DepositToken.isActive = false`, new deposits into that collateral are blocked while liquidations against it continue; and if `SmartFarmingManager` itself is shutdown, `flashRepay` is blocked while `Pool.liquidate` is still live.
- Unlike JOJO, `Pool.liquidate` takes no attacker-supplied callback contract (no `afterOperationParam`), so the second half of the original attack (custom flashloan-liquidate contract) does not apply — but it isn't needed: `liquidate` directly burns the liquidator's own synth and seizes collateral.

### Impact Explanation
During a paused/inactive-collateral window, borrowers who become unhealthy (e.g., via a collateral price drop or interest accrual) cannot deposit additional collateral to restore their position. Any liquidator holding msAssets can liquidate them up to `maxLiquidable`, seizing collateral plus the liquidation incentive. Borrowers lose funds they could have protected had the deposit path been symmetric with liquidation.

### Likelihood Explanation
Requires a governor-triggered pause or `toggleIsActive` (a legitimate emergency action, e.g., a collateral depeg/exploit response — precisely the scenario where positions are likeliest to fall underwater simultaneously). The liquidator is a fully unprivileged actor who only needs the synthetic token. Severity is Medium: it depends on an admin flag state, but the design inconsistency guarantees borrower harm whenever that state coincides with unhealthy positions.

### Recommendation
- Apply `whenNotPaused` to `Pool.liquidate` (or introduce a dedicated `liquidateEnabled` flag) so liquidations are suspended whenever deposits are suspended.
- Alternatively/additionally, have `Pool.liquidate` check `depositToken_.isActive()` before seizing that collateral.
- Document in `docs/emergency-flags.md` that pausing a pool should be paired with a liquidation freeze when the intent is to protect users during market stress.

### Proof of Concept
Hardhat test sketch (extends `test/Pool.test.ts`):

```ts
it('liquidate works while deposits are blocked (pause)', async function () {
  // alice has unhealthy position (collateral price dropped), as in existing setup
  await pool.pause()

  // borrower cannot add collateral to restore health
  await expect(
    msdMET.connect(alice).deposit(parseEther('10'), alice.address)
  ).to.be.revertedWithCustomError(msdMET, 'IsPaused')

  // liquidator can still liquidate alice
  const amountToRepay = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)
  await expect(
    pool.connect(liquidator).liquidate(msEth.address, alice.address, amountToRepay, msdMET.address)
  ).to.emit(pool, 'PositionLiquidated')
})

it('liquidate works while deposits are blocked (depositToken inactive)', async function () {
  await msdMET.toggleIsActive() // governor disables collateral

  await expect(
    msdMET.connect(alice).deposit(parseEther('10'), alice.address)
  ).to.be.revertedWithCustomError(msdMET, 'DepositTokenIsInactive')

  const amountToRepay = await pool.quoteLiquidateMax(msEth.address, alice.address, msdMET.address)
  await expect(
    pool.connect(liquidator).liquidate(msEth.address, alice.address, amountToRepay, msdMET.address)
  ).to.emit(pool, 'PositionLiquidated') // seize path bypasses isActive
})
```

Note: the existing test `test/Pool.test.ts:353` ("should not revert if paused") already confirms the liquidation half; only the deposit revert assertion needs to be added.
