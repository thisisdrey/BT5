### Title
SSRF: Node resolves and connects to a peer-supplied `data_url` without any private/loopback-range check - (File: stackslib/src/net/chat.rs)

### Summary
Every remote P2P peer supplies an arbitrary `data_url` string as part of its `HandshakeData` message. When the local node needs to fetch data (blocks, microblocks, StackerDB chunks, mempool contents, attachments) from that peer, it resolves this `data_url` — via a literal IP/hostname parse or a full DNS lookup — and then opens an outbound HTTP connection to whatever address results, without ever checking that address against the node's own private/loopback-range filter. This is the same bug class as the reported `link-preview-js` SSRF: an attacker-controlled hostname/IP is trusted and fetched from, allowing the node to be steered into contacting internal-only services.

### Finding Description
`ConversationP2P::try_resolve_data_url_host` in `stackslib/src/net/chat.rs` (around lines 2780-2914) takes the conversation's `data_url` — set directly from the peer-supplied `HandshakeData.data_url` field, which is fully attacker-controlled (`stackslib/src/net/mod.rs:1041-1048`) — and either:
- Immediately decodes a literal IPv4/IPv6 host via `try_decode_data_url_ipaddr` (`stackslib/src/net/chat.rs:2780-2798`), or
- Queues a DNS lookup for a domain host and stores whatever `SocketAddr` the resolver returns (`stackslib/src/net/chat.rs:2882-2910`).

In both cases the resulting `self.data_ip` is stored with **no call to `PeerAddress::is_in_private_range()` or `is_loopback()`**, unlike the codebase's other DNS/URL consumers (`stackslib/src/net/mempool/mod.rs:488-498`, `stackslib/src/net/stackerdb/sync.rs:119-123`, `stackslib/src/net/stackerdb/config.rs:356-362`, `stackslib/src/net/api/liststackerdbreplicas.rs:135-138`), all of which explicitly filter out private-range addresses unless `connection_opts.private_neighbors` is set.

That unchecked `data_ip` is then handed directly to `NetworkState`/`connect_or_send_http_request` to open a real outbound TCP+HTTP connection:
- `NeighborRPC::send_request` in `stackslib/src/net/neighbors/rpc.rs:191-241` reads `convo.data_ip` and calls `http.connect_http(..., data_addr, ...)` with no range check.
- The same unguarded pattern (accept literal IPv4/IPv6 host, or accept whatever DNS returns, then connect) recurs in `stackslib/src/net/download/epoch2x.rs:308-362` (`dns_lookups_begin`) and `stackslib/src/net/atlas/download.rs:672-810` (`BatchedDNSLookupsState::try_proceed`), both of which feed into `PeerNetwork::begin_request` (`stackslib/src/net/download/epoch2x.rs:1916-1976`) → `PeerNetwork::connect_or_send_http_request` (`stackslib/src/net/httpcore.rs:1877-1911`) → `HttpPeer::connect_http` (`stackslib/src/net/server.rs:118-150`), none of which re-validate the target address.

The `private_neighbors`/`is_in_private_range` filter that exists elsewhere protects only the *P2P TCP peer address* used in `PeerNetwork::can_register_peer` (`stackslib/src/net/p2p.rs:1917-1924`) — i.e., the address the peer connected *from*. It does not constrain the *HTTP data_url* the peer *advertises*, which can point anywhere (e.g., `http://127.0.0.1:<admin-port>`, `http://169.254.169.254/`, or an attacker-controlled DNS name that resolves to an internal address at lookup time — classic DNS-rebinding). This breaks the equality the rest of the codebase enforces: "only talk to publicly-routable addresses unless explicitly configured otherwise."

### Impact Explanation
A remote, unauthenticated-to-privileged party (any peer that can complete a P2P handshake, which requires no special access) can cause the victim node to issue outbound HTTP requests to arbitrary internal/loopback addresses of its choosing, including services bound only to `127.0.0.1` on the host, cloud metadata endpoints, or other hosts on the node's private network. Because this reach is exercised through core data-fetch paths (block/microblock download, mempool sync HTTP send, StackerDB chunk fetch, Atlas attachment download), it is a network-reachable SSRF primitive with no traffic-volume requirement — a single malicious `data_url` in one `HandshakeData` message is sufficient to trigger a request. This matches the "High" impact bar (bounded compute/read-endpoint abuse against internal targets) via a genuine equality violation (the private-range check is applied inconsistently and is absent on the most commonly hit code path).

### Likelihood Explanation
Likelihood is high: any node that can open a P2P connection to the victim (default network policy) can send a `Handshake` with a crafted `data_url`, and no authentication beyond a normal handshake is required. The bug requires no privileged credentials, no signer key, and no traffic volume — a single crafted message is enough to arm the SSRF; it is triggered as soon as the local node's block/mempool/attachment/StackerDB-sync logic decides to fetch data from that peer.

### Recommendation
After resolving `data_url` to a `SocketAddr` (both the literal-IP fast path and the DNS-resolved path) in `ConversationP2P::try_resolve_data_url_host` (`stackslib/src/net/chat.rs`), and again at each DNS-lookup consumer (`stackslib/src/net/atlas/download.rs::BatchedDNSLookupsState`, `stackslib/src/net/download/epoch2x.rs::dns_lookups_begin`), apply the same `!connection_opts.private_neighbors && PeerAddress::from_socketaddr(addr).is_in_private_range()` check already used in `stackslib/src/net/mempool/mod.rs:488-498` before storing/using the address, and reject (drop to `None`/skip) any resolved address that falls in a private/loopback range unless `private_neighbors` is explicitly enabled. Apply the check at resolution time so that DNS-rebinding (address changing between resolution and use) cannot bypass a later-only check, and re-validate immediately before the outbound `connect_http` call as defense in depth.

### Proof of Concept
1. Run a malicious peer node and complete a normal P2P handshake with the victim node.
2. In the `Handshake` message, set `HandshakeData.data_url` to `http://127.0.0.1:<internal-service-port>/` (or a domain the attacker controls, whose DNS record is later rebound to `127.0.0.1`/an internal IP after the initial handshake).
3. Wait for the victim's block-download, mempool-sync, StackerDB-sync, or Atlas-attachment logic to decide it needs data from this peer (this happens automatically as part of normal peer housekeeping).
4. Observe that `try_resolve_data_url_host` (`stackslib/src/net/chat.rs`) resolves and stores the internal address in `data_ip` with no filtering, and `NeighborRPC::send_request` / `PeerNetwork::connect_or_send_http_request` subsequently opens a real TCP+HTTP connection from the victim node to the internal target, sending it a Stacks HTTP request (e.g. mempool sync POST, StackerDB GET) — demonstrating SSRF into the victim's local network.     pub fn dns_lookups_begin(
        &mut self,
        pox_id: &PoxId,
        dns_client: &mut DNSClient,
        urls: Vec<UrlString>,
    ) -> Result<(), net_error> {
        assert_eq!(self.state, BlockDownloaderState::DNSLookupBegin);

        // optimistic concurrency control: remember the current PoX Id
        self.pox_id = pox_id.clone();
        self.dns_lookups.clear();
        for url_str in urls.into_iter() {
            if url_str.is_empty() {
                continue;
            }
            let url = url_str.parse_to_block_url()?; // NOTE: should always succeed, since a UrlString shouldn't decode unless it's a valid URL or the empty string
            let port = match url.port_or_known_default() {
                Some(p) => p,
                None => {
                    warn!("Unsupported URL {:?}: unknown port", &url);
                    continue;
                }
            };
            match url.host() {
                Some(url::Host::Domain(domain)) => {
                    match dns_client.queue_lookup(
                        domain,
                        port,
                        get_epoch_time_ms() + self.dns_timeout,
                    ) {
                        Ok(_) => {}
                        Err(_) => continue,
                    }
                    self.dns_lookups.insert(url_str.clone(), None);
                    self.parsed_urls
                        .insert(url_str, DNSRequest::new(domain.to_string(), port, 0));
                }
                Some(url::Host::Ipv4(addr)) => {
                    self.dns_lookups
                        .insert(url_str, Some(vec![SocketAddr::new(IpAddr::V4(addr), port)]));
                }
                Some(url::Host::Ipv6(addr)) => {
                    self.dns_lookups
                        .insert(url_str, Some(vec![SocketAddr::new(IpAddr::V6(addr), port)]));
                }
                None => {
                    warn!("Unsupported URL {:?}", &url_str);
                }
            }
        }

        self.state = BlockDownloaderState::DNSLookupFinish;
        Ok(())
    }

    pub fn connect_or_send_http_request(
        &mut self,
        data_url: UrlString,
        addr: SocketAddr,
        request: StacksHttpRequest,
    ) -> Result<usize, NetError> {
        PeerNetwork::with_network_state(self, |ref mut network, ref mut network_state| {
            PeerNetwork::with_http(network, |ref mut network, ref mut http| {
                match http.connect_http(
                    network_state,
                    network,
                    data_url.clone(),
                    addr,
                    Some(request.clone()),
                ) {
                    Ok(event_id) => Ok(event_id),
                    Err(NetError::AlreadyConnected(event_id, _)) => {
                        if let (Some(ref mut convo), Some(ref mut socket)) =
                            http.get_conversation_and_socket(event_id)
                        {
                            convo.send_request(request)?;
                            HttpPeer::saturate_http_socket(socket, convo)?;
                            Ok(event_id)
                        } else {
                            debug!("HTTP failed to connect to {data_url}, {addr:?}");
                            Err(NetError::PeerNotConnected(format!(
                                "HTTP failed to connect to {data_url}, {addr:?}",
                            )))
                        }
                    }
                    Err(e) => Err(e),
                }
            })
        })
    }
