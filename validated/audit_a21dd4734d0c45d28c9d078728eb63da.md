### Title
First depositor can capture an entire rewards period with a 1-wei deposit - ([File: contracts/RewardsDistributor.sol](contracts/RewardsDistributor.sol))

### Summary
`RewardsDistributor` divides newly emitted rewards by `token_.totalSupply()`, while `DepositToken.deposit()` permits a net mint of one wei of deposit-token supply. An attacker can therefore become the sole supplier with a dust position immediately after rewards become active, allow the reward index to rise against a total supply of `1`, and later claim the entire emission for that interval. [1](#0-0) [2](#0-1) 

### Finding Description
`DepositToken.deposit()` only rejects a zero input and has no minimum minted amount; an attacker can use `quoteDepositIn(1)` to determine the gross collateral amount needed for a net deposit of one wei. [2](#0-1) [3](#0-2) 

Before minting, `_mint()` calls `updateBeforeMintOrBurn`, which stores the attacker’s current account index. [4](#0-3) [5](#0-4) 

Afterward, the next index update calculates:

```solidity
deltaIndex = deltaTime * tokenSpeed / totalSupply
```

With `totalSupply == 1`, the resulting per-token index increase is `deltaTime * tokenSpeed`, scaled by one wad. [1](#0-0) 

The attacker’s accrued reward is then `balance * deltaIndex`, which equals `deltaTime * tokenSpeed` for a one-wei balance; in other words, the attacker receives all rewards emitted while they were the only holder. [6](#0-5) 

`claimRewards()` is publicly callable and transfers the accrued reward whenever the distributor has enough reward tokens. [7](#0-6) [8](#0-7) 

### Impact Explanation
The attacker can capture unclaimed emissions that should have been distributed across economically meaningful suppliers. The stolen amount is `tokenSpeed * elapsedTime`; the impact is substantive whenever the configured reward rate or the delay before the next deposit is substantive. [1](#0-0) [8](#0-7) 

This also applies after the deposit-token supply returns to zero while a nonzero speed remains configured. The next depositor can recreate a total supply of one wei and again receive all emissions until another holder mints. [1](#0-0) [9](#0-8) 

### Likelihood Explanation
The attack requires a reward-bearing `DepositToken` whose supply is zero or near-zero and a delay before another supplier mints. Those conditions can occur when rewards are enabled before a new deposit market receives liquidity, when all suppliers withdraw while rewards remain enabled, or when an attacker front-runs normal deposits after reward activation. [10](#0-9) [9](#0-8) 

No privileged attacker action, oracle manipulation, reentrancy, or invalid token is required: `deposit()` is public, the mint hook updates reward state atomically, and `claimRewards()` can be called for the attacker’s account. [2](#0-1) [11](#0-10) 

### Recommendation
Enforce a minimum minted deposit amount materially larger than one wei, such as `MIN_DEPOSIT_SUPPLY = 1e18`, after applying the deposit fee. [2](#0-1) 

When `totalSupply` would transition from zero, either require the first mint to meet the minimum or seed the first deposit together with reward activation. Optionally prevent withdrawals or transfers that leave a nonzero total supply below the same minimum. [9](#0-8) [12](#0-11) 

### Proof of Concept
A reproducible Hardhat fork test can follow this sequence:

```ts
// Preconditions on a fork:
// - depositToken is registered in pool
// - rewardDistributor is registered in pool
// - rewardDistributor.tokenSpeeds(depositToken) > 0
// - depositToken.totalSupply() == 0
// - rewardDistributor holds enough rewardToken

const depositAmount = await depositToken.quoteDepositIn(1);
await underlying.approve(depositToken.address, depositAmount.amount);

// Alice becomes the sole depositor with one wei of supply.
await depositToken.connect(alice).deposit(
  depositAmount.amount,
  alice.address
);
expect(await depositToken.totalSupply()).eq(1);
expect(await depositToken.balanceOf(alice.address)).eq(1);

// Let rewards accrue while Alice represents 100% of supply.
await time.increase(300);

// Bob mints normally; updating the index against totalSupply == 1.
const bobAmount = await depositToken.quoteDepositIn(parseEther("100"));
await underlying.connect(bob).approve(
  depositToken.address,
  bobAmount.amount
);
await depositToken.connect(bob).deposit(
  bobAmount.amount,
  bob.address
);

// Alice can claim all rewards emitted during the 300 seconds.
const speed = await rewardsDistributor.tokenSpeeds(depositToken.address);
const expected = speed.mul(300);

await rewardsDistributor.claimRewards(
  alice.address,
  [depositToken.address]
);

expect(await rewardToken.balanceOf(alice.address)).eq(expected);
```

The expected value follows directly from `_tokensAccrued = deltaTime * speed` and `_tokensDelta = balance * (_tokensAccrued / totalSupply)`; with `balance == totalSupply == 1`, Alice receives the full `deltaTime * speed`. [13](#0-12)
