### Title
No zero-address check on `new_authority` permanently locks migrated marginfi account funds - (File: `programs/marginfi/src/instructions/marginfi_account/transfer_account.rs`)

### Summary
`transfer_to_new_account` and `transfer_to_new_account_pda` accept a `new_authority` account that is explicitly documented as "completely unchecked" and is never validated to be non-zero (i.e., not `Pubkey::default()`), mirroring the reported bug class where an unchecked `_to`/owner-style parameter can be set to the zero address, permanently disabling downstream functionality.

### Finding Description
Both instructions take `new_authority: UncheckedAccount<'info>` with no constraint at all: [1](#0-0) [2](#0-1) 

The handler unconditionally uses `ctx.accounts.new_authority.key()` as the authority of the freshly initialized `new_marginfi_account`, and then permanently disables the old account (zeroing its lending balances and setting `ACCOUNT_DISABLED`) as part of `finalize_migrated_old_account`: [3](#0-2) [4](#0-3) 

If `new_authority` is `Pubkey::default()` (the zero/system-program address, which can never sign a transaction), the new account is initialized with an authority that can never authorize any future instruction against it (withdraw, transfer, close, emissions update, etc.), while the old account has already had its `lending_account` zeroed and is flagged `ACCOUNT_DISABLED`, meaning the migrated collateral/asset positions are now bound to an account nobody can ever control.

### Impact Explanation
This produces a permanent lock/freeze of user funds: the assets that were in the old marginfi account are moved into a new account whose `authority` field is the zero address, and since no wallet can ever sign as `Pubkey::default()`, no withdraw, repay, close, or transfer instruction can ever be executed against the new account. The old account is simultaneously disabled and its lending account zeroed, so there is no path to recover the funds. This matches the required impact bar of "permanent lock/freeze."

### Likelihood Explanation
The call requires the caller to pass `authority` that satisfies `is_signer_authorized` for the old account (the account authority or an authorized delegate) — this is an unprivileged-user-reachable path, not an admin-only path. Whether this is exploitable against a victim (e.g., a delegate maliciously locking a user's account) or is purely self-inflicted (owner accidentally supplying a bad `new_authority`) depends on the exact semantics of `is_signer_authorized`/delegate permissions, which I could not fully confirm from the available code (the function body in `programs/marginfi/src/state/marginfi_account.rs` was not retrieved before the tool budget ran out). At minimum, this is a straightforward user error path with no on-chain safeguard, and the code's own `WARN` comment acknowledges the danger.

### Recommendation
Add a check that `new_authority.key() != Pubkey::default()` (and ideally is not otherwise a non-signable/system account) before allowing `transfer_to_new_account` / `transfer_to_new_account_pda` to proceed, similar to the recommendation in the original report of validating a destination/owner parameter for zero before using it.

### Proof of Concept
1. Caller (the marginfi account authority or authorized delegate) invokes `transfer_to_new_account_pda` (or `transfer_to_new_account`), supplying `new_authority = Pubkey::default()`.
2. The instruction succeeds: `new_marginfi_account.authority` is set to `Pubkey::default()` via `initialize_migrated_account` [5](#0-4) , and `old_marginfi_account` is disabled/zeroed via `finalize_migrated_old_account` [4](#0-3) .
3. Any subsequent instruction requiring `authority: Signer<'info>` matching the new account's authority (withdraw, borrow, close, etc.) can never be signed, since no keypair corresponds to `Pubkey::default()`.
4. Funds credited to the new account are permanently unreachable, and the old account no longer holds them (it is disabled with a zeroed `lending_account`).

fn finalize_migrated_old_account(
    old_account: &mut MarginfiAccount,
    new_account_key: Pubkey,
    current_timestamp: u64,
) {
    old_account.migrated_to = new_account_key;
    old_account.last_update = current_timestamp;
    old_account.lending_account = LendingAccount::zeroed();
    old_account.set_flag(ACCOUNT_DISABLED, true);
    old_account.sync_indexer_flags();
}
