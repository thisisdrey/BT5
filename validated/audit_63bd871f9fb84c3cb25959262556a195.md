### Title
Protocol fee bypass on NEP-245 swaps structured as unit-amount (`|delta| ≤ 1`) transfers - (`contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` unconditionally sets the protocol fee to `Pips::ZERO` for any `Nep245` (or `Imt`) leg whose absolute delta is `≤ 1`, regardless of the token's actual value. Since a `Nep245TokenId` is just `(contract_id, mt_token_id)` — an arbitrary NEP-245 contract and token id fully controlled by any unprivileged user — an attacker can deploy their own MT contract in which "1 unit" represents an arbitrarily large economic value, then execute a `TokenDiff` swap where their outgoing (negative-delta) leg is exactly `1` unit of that MT token. The fee on that leg is computed as `Pips::ZERO`, while the counterparty's outgoing `Nep141` leg is charged the full protocol fee, breaking the intended binding that `fee_ceil` applied to a leg's economic value should be proportional to `protocol_fee` regardless of token standard.

### Finding Description
The broken binding: for any negative-delta leg of a `TokenDiff`, the fee charged should satisfy `fee ≈ protocol_fee.fee_ceil(economic_value_of(amount, token_id))`, independent of which token standard is used to represent that value. Instead, the code enforces:

```rust
// contracts/defuse/core/src/intents/token_diff.rs:206-217
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
```

This is invoked from `TokenDiff::execute_intent` (lines 56-78): for every negative delta in the signer's diff, `fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount)` is added to `fees_collected`, which is later credited to `fee_collector` via `internal_add_balance`. The exemption for `|delta| ≤ 1` was designed for genuine NFT/MT items (atomic, non-fungible-like tokens), but nothing in `Nep245TokenId::new(contract_id, mt_token_id)` (`crates/primitives/token-id/src/nep245.rs:20-27`) restricts `contract_id` to a vetted registry or enforces any relationship between "1 unit" and real value — the attacker deploys and controls the MT contract.

Exploit flow:
1. Attacker deploys their own NEP-245 contract `evilmt.near` and mints itself a token id, e.g. `"jackpot"`, representing (by the attacker's own design/documentation) an equivalent of, say, 1,000,000 USDC.
2. Attacker deposits 1 unit of `evilmt.near:jackpot` into the Verifier and signs a `TokenDiff` intent: `{ Nep245("evilmt.near","jackpot"): -1, Nep141("usdc.near"): +1_000_000 }`.
3. A counterparty (victim/solver) signs the matching `TokenDiff`: `{ Nep245("evilmt.near","jackpot"): +1, Nep141("usdc.near"): -1_000_000 }`.
4. On execution, the attacker's leg has `amount = 1`, `TokenIdType::Nep245`, so `token_fee` returns `Pips::ZERO` → fee = 0. The counterparty's leg has `amount = 1_000_000`, `TokenIdType::Nep141` → fee = `protocol_fee.fee_ceil(1_000_000)` (nonzero).
5. Result: the attacker's economically-equivalent-or-larger leg is completely fee-exempt, while the counterparty pays the full fee on their leg — a real, repeatable divergence from the intended fee model, entirely attacker-controlled since they choose the MT contract's unit economics and always trade in `delta = ±1` lots.

No existing guard (`MultiPayload::verify`, `Lock`, `TransferMatcher::finalize`, `checked_*` arithmetic) inspects the *value* represented by an MT unit; the fee waiver is keyed purely on `TokenIdType` and raw integer `amount`, which the attacker fully controls by choosing their own MT contract's token-id granularity.

### Impact Explanation
This under-collects protocol fees (`fee_collector` receives less than the protocol rate should yield) on the MT side of any swap the attacker structures this way, matching the Critical category "protocol fees bypassed or over-collected." It is fully repeatable: the attacker can wrap any Nep141/other asset into their own MT with arbitrarily coarse unit granularity and always transact in single-unit deltas, systematically avoiding the fee on their side of every swap while forcing the fee cost asymmetrically onto whichever counterparty transacts in the un-exempted token standard (e.g., Nep141). Blast radius is protocol-wide revenue leakage across any MT-based swap route, at no cost to the attacker beyond deploying a trivial MT contract.

### Likelihood Explanation
Preconditions are minimal and fully within an unprivileged attacker's control: deploy an MT contract (no special permissions needed on NEAR), deposit/wrap into a single unit of a self-chosen token id, and sign a normal `TokenDiff` intent. No DAO/role/relayer access is required. The attacker needs only a counterparty willing to trade (which could be a normal solver/user unaware their leg pays full fee while the attacker's leg is fee-exempt), making this highly feasible and repeatable across accounts, tokens, and batches.

### Recommendation
Remove or restrict the `|delta| ≤ 1` fee exemption for `Nep245`/`Imt` so it does not apply uniformly to all MT contracts — e.g., only waive fees for a curated allowlist of true NFT-semantics token ids (verified 1-of-1 supply), or base the fee waiver on verified token metadata/supply rather than the raw transferred integer amount, which is entirely attacker-defined per MT contract.

```rust
impl ExecutableIntent for TokenDiff {
    fn execute_intent<S, I>(
        self,
        signer_id: &AccountIdRef,
        engine: &mut Engine<S, I>,
        intent_hash: [u8; 32],
    ) -> Result<()>
    where
        S: State,
        I: Inspector,
    {
        if self.diff.is_empty() {
            return Err(DefuseError::InvalidIntent);
        }

        let protocol_fee = engine.state.fee();
        let mut fees_collected: Amounts = Amounts::default();

        for (token_id, delta) in &self.diff {
            if *delta == 0 {
                return Err(DefuseError::InvalidIntent);
            }

            // add delta to signer's account
            engine
                .state
                .internal_apply_deltas(signer_id, [(token_id.clone(), *delta)])?;

            // take fees only from negative deltas (i.e. token_in)
            if *delta < 0 {
                let amount = delta.unsigned_abs();
                let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);

                // collect fee
                fees_collected
                    .add(token_id.clone(), fee)
                    .ok_or(DefuseError::BalanceOverflow)?;
            }
        }

        engine.inspector.on_event(DefuseEvent::TokenDiff(
            [MaybeIntentEvent::new_intent(
                AccountEvent::new(
                    signer_id,
                    TokenDiffEvent {
                        diff: Cow::Borrowed(&self),
                        fees_collected: fees_collected.clone(),
                    },
                ),
                intent_hash,
            )]
            .as_slice()
            .into(),
        ));

        // deposit fees to collector
        if !fees_collected.is_empty() {
            engine
                .state
                .internal_add_balance(engine.state.fee_collector().into_owned(), fees_collected)?;
        }

        Ok(())
    }
```
