### Title
Unauthenticated `RecvError` packets allow spoofed tunnel teardown (remote state poisoning) - ([File: outside.go])

### Summary
The `gulp` bug report describes a class of vulnerability where an unauthenticated/attacker-influenced trigger (an arbitrary caller supplying a slippage parameter) is allowed to force a state-changing action on a victim's behalf, with the only "authorization" being a loosely-checked, attacker-controllable condition (reasonable-looking slippage). The nebula analog is the `header.RecvError` control message: it is processed **before any AEAD decryption or handshake authentication**, and the only check gating whether it can tear down an active tunnel is a comparison against a value (the source UDP address) that an off-path/unauthenticated attacker can trivially spoof.

### Finding Description
Inbound UDP packets are dispatched in `readOutsidePackets` before decryption for two message types, one of which is `header.RecvError`: [1](#0-0) 

`handleRecvError` is invoked directly on this unauthenticated, unencrypted packet type: [2](#0-1) 

The only "authorization" check performed is:
```go
hr := hostinfo.GetRemote()
if hr.IsValid() && hr != addr {
    f.l.Info("Someone spoofing recv_errors?", ...)
    return
}
f.closeTunnel(hostinfo)
```
This check compares the packet's source `netip.AddrPort` (`addr`, taken from the UDP datagram's source address, which is not cryptographically bound to anything) against the hostinfo's currently recorded remote address. There is no certificate, no MAC, no handshake state, no nonce/replay protection tied to this packet — an attacker who can spoof (or is on-path/NAT-shared for) the victim's UDP source address, with **no CA-signed certificate and no established tunnel of their own**, can send a bare `RecvError` header packet carrying the victim's `RemoteIndex` and force `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, immediately terminating a legitimate, already-authenticated tunnel.

This mirrors the `gulp` sandwich pattern: a party with no proper authorization (no `onlyOwner`/oracle-checked slippage; here, no valid Noise/cert handshake) is nonetheless able to unilaterally force a state transition (a bad trade execution; here, tunnel teardown) on a legitimate session, because the guarding check is either absent or trivially bypassable/spoofable rather than cryptographically enforced.

### Impact Explanation
An attacker without any CA-signed certificate can force premature teardown of any nebula tunnel whose remote index they can guess or observe (`RemoteIndex` is a 32-bit value transmitted in cleartext on every packet, so it is trivially observable on-path or via traffic analysis) and whose peer UDP `AddrPort` they can spoof. This is a remote state-poisoning/denial-of-service primitive: repeated forged `RecvError` packets can be used to continuously sever tunnels between legitimate, mutually-authenticated peers, forcing constant re-handshakes and degrading or denying service — without ever holding a valid certificate.

### Likelihood Explanation
Exploitability depends on the attacker's ability to spoof UDP source addresses (common over UDP where transport-layer spoofing is well known and remains widely exploitable outside of networks that enforce strict egress/ingress filtering) and to learn the target's `RemoteIndex`, which is sent unencrypted in the header of every packet and is thus observable to any on-path observer or to a peer that previously communicated with the target. No cryptographic material is required. `ShouldRecvError`/rate-limiting in `interface.go` may throttle repeated `RecvError` acceptance from a given endpoint, but this does not address the core issue that acceptance is gated only by a spoofable address comparison rather than any authenticated binding to the tunnel.

### Recommendation
Do not allow an unauthenticated, unencrypted control packet to trigger destructive state changes on an established, authenticated tunnel. At minimum:
- Require `RecvError` handling to additionally validate the message against something not attacker-spoofable over UDP (e.g., only accept `RecvError` correlated with a locally-sent packet transaction / require it be authenticated with the tunnel's derived keys, or rate-limit and treat it as advisory rather than authoritative for teardown).
- Consider removing automatic `closeTunnel` on `RecvError` receipt entirely in favor of relying on the (encrypted, authenticated) `CloseTunnel` message and dead-tunnel detection via `connectionManager`, using `RecvError` only as a soft hint to retry/re-handshake rather than an immediate teardown trigger.

### Proof of Concept
1. Establish two legitimate nebula nodes A and B with a valid tunnel (valid CA-signed certs), and observe/derive B's `RemoteIndex` value as sent to A in cleartext packet headers (observable on-path or by a node that had previously handshaked and was later revoked/disconnected).
2. As an attacker C possessing no CA-signed certificate, craft a raw UDP packet: `header.Encode(buf, header.Version, header.RecvError, 0, <B's index on A>, 0)` and send it to A, spoofing the source address to match A's currently recorded remote address for B (`hostinfo.GetRemote()`).
3. Observe that A's `handleRecvError` (`outside.go:541-574`) passes the `hr != addr` check (since the spoofed source matches), calls `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, tearing down the legitimate A↔B tunnel — with no certificate or cryptographic proof of authorization from C.

```go
func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
```
