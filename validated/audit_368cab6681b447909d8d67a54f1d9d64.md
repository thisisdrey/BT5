### Title
`interest-rate` returns rate `u0` instead of the last configured point's rate once utilization exceeds a DAO curve with fewer than 8 points, freezing supplier yield accrual - (File: `mainnet/contracts/vault/v0-vault-sbtc.clar`)

### Summary
When the DAO configures an interest-rate curve with fewer than 8 points (a fully supported, legitimate configuration), `unpack-u16` still returns a fixed 8-element list padded with trailing `u0` entries for the unused slots. `resolve-and-interpolate`/`resolve-interpolation-points` iterate over these 8 pairs in order and never distinguish "real" points from zero-padding, so once utilization is driven at or above the last real point's util, the fold keeps matching the trailing `(util: u0, rate: u0)` padding points (since `target >= u0` is always true) and overwrites the previously-held last-real-point candidate with `{util: u0, rate: u0}`, never setting `found` to `true`. The final result returned is the zero padding rate, not the intended last real point's rate.

### Finding Description
`interpolate-rate`/`resolve-and-interpolate` build the point list via: [1](#0-0) 

`zip` unconditionally maps over `ITER-UINT-8` (8 fixed slots) using `combine-elements`, so the resulting list always has 8 `{util, rate}` pairs, regardless of how many points the DAO actually packed. `unpack-u16` always returns exactly 8 elements padded with `u0` for any slot the DAO didn't set: [2](#0-1) 

The fold logic in `resolve-interpolation-points` treats every point in the list identically: [3](#0-2) 

If `target >= util` for the current point, the accumulator's `prev`/`result` are overwritten with the current point's values and `found` stays `false` — this is meant to just "advance" through real points. Because trailing padding points have `util = u0`, and `target` (utilization, a `uint`) is always `>= u0`, every padding slot after the real points also satisfies this branch. This means after the real last point is processed (correctly recording its `util`/`rate` in `prev`/`result`), the very next padding slot (`util: u0, rate: u0`) overwrites `prev` and `result` with zeros, and this repeats for all remaining padding slots. `found` never flips to `true` for any point after the real segment, so the fold ends with `result = u0` — the rate of the last processed (padding) point, not the last real point's rate.

This is reachable whenever:
1. The DAO configures the curve via `set-points-util`/`set-points-rate` with fewer than 8 real points (padding the remainder implicitly with zeros to satisfy the fixed-length pack routine) — a documented, in-scope legitimate configuration: [4](#0-3) 
2. Normal borrowing activity (via the market/deposit path, no special privilege needed) drives `utilization()` at or above the util of the last configured real point but below `BPS` (a state fully reachable by ordinary supply/borrow within the configured `cap-debt`): [5](#0-4) 
3. Any subsequent call that triggers `accrue` (e.g. `repay`, `borrow`, `deposit`, `redeem`) invokes `interest-rate()` through `next-index`/`next-liquidity-index`: [6](#0-5) 

No existing check (`check-caller-auth`, pause states, caps) prevents this — the bug is purely in the point-list zip/fold logic and fires regardless of caller identity once the utilization/curve-length precondition holds.

### Impact Explanation
Once `interest-rate()` collapses to `u0`, `calc-multiplier-delta`/`calc-index-next` produce no growth for the borrow `index`, and `calc-liquidity-rate` (which multiplies by the borrow rate) also becomes `u0`, so `lindex` (the liquidity/yield index for suppliers) stops growing entirely while utilization remains at or above the last curve point. This is a temporary freezing of unclaimed supplier yield — matching the in-scope **High** impact category ("temporary freezing of funds" / freezing of unclaimed yield), since depositors accrue no interest for as long as utilization stays in this zone, until utilization drops back below the last real point or the DAO reconfigures the curve.

### Likelihood Explanation
- Precondition: DAO configures an interest curve with fewer than 8 points, which is an explicitly supported and common configuration (e.g., a classic two-segment curve with a kink below 100% utilization).
- Trigger: any ordinary, unprivileged borrowing activity that pushes utilization at/above the last configured point but below `BPS` — no special permission, collusion, or DAO misconfiguration is required beyond the normal act of using fewer than 8 points.
- Capital cost: only the cost of supplying/borrowing enough to move utilization into the affected range, which is standard usage, not an exotic attack — fully repeatable any time utilization sits in that band.

### Recommendation
Track the actual number of real points packed (e.g., store a count alongside the packed word, or use a sentinel/`MAX-U16` value for unused slots and have `resolve-interpolation-points` treat `util == MAX-U16`/unset slots as "no more points" so the fold sets `found: true` using the last real point's rate instead of continuing to match zero-padding). Alternatively, filter out trailing padding pairs in `zip`/`resolve-and-interpolate` before folding, based on the known count of configured points, so the algorithm's "ran out of points" fallback correctly uses the last real point instead of the zero pad.

### Proof of Concept
Clarinet/vitest simnet test plan:
1. Deploy `v0-vault-sbtc` and call `initialize`.
2. As DAO executor, call `set-points-util` with a 4-real-point curve padded to 8 entries, e.g. `[u0, u3000, u6000, u9000, u0, u0, u0, u0]`, and `set-points-rate` with corresponding rates `[R0, R1, R2, R3, u0, u0, u0, u0]` where `R3 > u0`.
3. Supply liquidity via `deposit`.
4. Drive utilization above `u9000` (the last real point) but below `BPS` via `system-borrow`/borrow path (through an authorized market mock or by registering the test contract as authorized via `set-authorized-contract`), keeping `amount <= cap-debt`.
5. Call `get-interest-rate` (read-only) or trigger `system-repay` (which calls `accrue` → `interest-rate`).
6. Assert: expected `interest-rate()` == `R3` (last real point's rate, or extrapolated value based on intended design), but observed result == `u0`, confirming the padding-zero collapse.
7. Additionally assert `get-liquidity-index`/`get-next-index` do not grow across a `stacks-block-time` delta while utilization remains above `u9000`, demonstrating frozen yield accrual for suppliers.

(define-private (resolve-and-interpolate (target uint) (utils (list 8 uint)) (rates (list 8 uint)))
  (let ((result (fold resolve-interpolation-points 
                      (zip utils rates)
                      {target: target, prev: {util: MAX-U128, rate: MAX-U128}, result: MAX-U128, found: false})))
    (get result result)))

(define-private (resolve-interpolation-points 
  (point {util: uint, rate: uint}) 
  (acc {target: uint, found: bool, result: uint, prev: {util: uint, rate: uint}}))
  (if (get found acc)
      acc
      (let ((util (get util point))
            (rate (get rate point)))
        (if (>= (get target acc) util)
            {target: (get target acc), prev: {util: util, rate: rate}, result: rate, found: false}
            (if (is-eq (get util (get prev acc)) MAX-U128)
                {target: (get target acc), prev: {util: util, rate: rate}, result: rate, found: true}
                (let ((interpolated (linear-interpolate (get target acc) 
                                                       (get util (get prev acc)) (get rate (get prev acc))
                                                       util rate)))
                  {target: (get target acc), prev: {util: util, rate: rate}, result: interpolated, found: true}))))))

(define-private (linear-interpolate (x uint) (x1 uint) (y1 uint) (x2 uint) (y2 uint))
  (if (is-eq x1 x2)
      y1
      (+ y1 (mul-div-down (- x x1) (- y2 y1) (- x2 x1)))))

(define-private (zip (util (list 8 uint)) (rate (list 8 uint)))
  (map combine-elements ITER-UINT-8 util rate))

(define-private (combine-elements (iter uint) (util uint) (rate uint))

(define-private (unpack-u16 (word uint))
  (let ((init { word: word, fields: (list) })
        (out (fold iter-unpack-u16 ITER-UINT-8 init)))
    (get fields out)))

(define-private (unpack-u16-at (word uint) (pos uint))
  (let ((offset (* pos BIT-U16))
        (div (pow u2 offset))
        (shiftr (/ word div)))
    (mod shiftr MASK-U16)))

(define-private (iter-unpack-u16 (pos uint) (acc {word: uint, fields: (list 8 uint)}))
  (let ((word (get word acc))
        (fields (get fields acc))
        (unpack (unpack-u16-at word pos))
        (new (as-max-len? (append fields unpack) u8)))
    { word: word, fields: (unwrap-panic new) }))
