### Title
Unbounded `paths`/`attributes` count and unbounded `.gitattributes` pattern set cause CPU-bound synchronous blocking in `GetFileAttributes` - (File: internal/gitaly/service/repository/file_attributes.go)

### Summary
`validateGetFileAttributesRequest` only checks that `Paths`, `Attributes`, and `Revision` are non-empty, without any upper bound on the number of paths/attributes requested, and `gitattributes.CheckAttrCmd.Check` performs one blocking, synchronous round-trip to a `git check-attr --stdin -z` subprocess per path in the request. Combined with a repository-controlled `.gitattributes` file containing a large number of overlapping patterns (which increases per-path matching cost inside `git check-attr`), an attacker who controls both repository content and the RPC's `paths`/`attributes` lists can force the Gitaly worker to spend large, attacker-scaled CPU time and wall-clock time inside a single RPC call.

### Finding Description
In `internal/gitaly/service/repository/file_attributes.go`, `validateGetFileAttributesRequest` performs only presence checks: [1](#0-0) 

`GetFileAttributes` then loops over every entry in `in.GetPaths()` and calls `checkAttrCmd.Check(path)` synchronously, one at a time: [2](#0-1) 

`CheckAttrCmd.Check` writes the path to the `check-attr` subprocess's stdin and blocks on `c.stdout.ReadBytes('\000')` in a loop until `c.count` (`len(names)`, i.e. the number of requested attributes) NUL-delimited words have been read back: [3](#0-2) 

Because the git subprocess is started once per RPC with `--stdin` and stays alive for the whole handler (`gitcmd.WithSetupStdin()`/`WithSetupStdout()`), the per-request cost is `O(len(Paths) * len(Attributes) * pattern-matching-cost)`, and the `.gitattributes` content is entirely attacker-controlled repository content — there is no cap on file size or pattern count enforced anywhere in this call chain. No repository size limit, path count limit, or attribute count limit exists in `validateGetFileAttributesRequest`, and the RPC handler runs this loop synchronously on the goroutine handling the gRPC request, holding it for the full duration.

### Impact Explanation
This causes a single Gitaly worker goroutine/subprocess to be pinned doing CPU/IO-bound work for a duration proportional to attacker-controlled input size (number of paths × number of attributes × `.gitattributes` complexity), which is a DoS-of-RPC-handler condition: it degrades responsiveness for other RPCs sharing the same Gitaly node's resources (CPU contention, subprocess/file-descriptor usage) for the life of the request. This matches the DoS-of-RPC-handler impact class explicitly called out as in-scope.

### Likelihood Explanation
The preconditions are within reach of an unprivileged repository owner: pushing/committing an arbitrarily large `.gitattributes` file requires no elevated privileges, and repeatedly issuing `GetFileAttributesRequest` with large `paths`/`attributes` arrays (bounded only by default gRPC message size limits, which still permit many thousands of short path strings) requires only the ability to invoke this RPC path. The attack is fully repeatable and requires no race conditions or non-default configuration — it depends only on the absence of any count/size validation in `validateGetFileAttributesRequest`.

### Recommendation
Add explicit upper bounds in `validateGetFileAttributesRequest` on `len(in.GetPaths())` and `len(in.GetAttributes())` (e.g. reject requests exceeding a small, fixed maximum such as a few hundred entries), and consider capping the total request payload independent of the general gRPC message-size limit. Additionally, consider bounding `.gitattributes` size/complexity that Gitaly will process for this RPC (e.g. via `core.attributesFile`/`GIT_ATTR_...` limits or a manual scan/size check before invoking `check-attr`), and/or applying the existing concurrency/adaptive limiter (`internal/limiter`) with a cost function proportional to `len(Paths) * len(Attributes)` for this RPC.

```go
func TestGetFileAttributes_DoS(t *testing.T) {
    ctx := testhelper.Context(t)
    cfg, client := setupRepositoryService(t)
    repoProto, repoPath := gittest.CreateRepository(t, ctx, cfg)

    // Pathological .gitattributes: thousands of overlapping glob patterns.
    var sb strings.Builder
    for i := 0; i < 50000; i++ {
        fmt.Fprintf(&sb, "*.ext%d diff=go text -foo\n", i)
    }
    gittest.WriteCommit(t, cfg, repoPath,
        gittest.WithBranch("main"),
        gittest.WithTreeEntries(
            gittest.TreeEntry{Path: ".gitattributes", Mode: "100644", Content: sb.String()},
        ))

    // Large paths list.
    paths := make([]string, 50000)
    for i := range paths {
        paths[i] = fmt.Sprintf("file%d.ext%d", i, i%50000)
    }

    start := time.Now()
    _, err := client.GetFileAttributes(ctx, &gitalypb.GetFileAttributesRequest{
        Repository: repoProto,
        Revision:   []byte("main"),
        Attributes: []string{"diff", "text", "foo"},
        Paths:      paths,
    })
    require.NoError(t, err)
    t.Logf("elapsed: %s", time.Since(start)) // measure vs. small baseline request
}
```
Assert that `validateGetFileAttributesRequest` does not reject this request (no `InvalidArgument` for path/attribute count), and that latency/CPU scale linearly with `len(paths) * len(attributes)` and `.gitattributes` pattern count, confirming no server-side cap exists.

```go
func (c CheckAttrCmd) Check(path string) (Attributes, error) {
	if strings.Contains(path, "\000") {
		return nil, fmt.Errorf("path with NUL byte not allowed")
	}

	c.m.Lock()
	defer c.m.Unlock()

	if _, err := c.stdin.WriteString(path + "\000"); err != nil {
		return nil, fmt.Errorf("write path: %w", err)
	}
	if err := c.stdin.Flush(); err != nil {
		return nil, fmt.Errorf("flush: %w", err)
	}

	attrs := Attributes{}
	buf := make([]string, 0, 3)

	// Using git-check-attr(1) with -z will return data in the format:
	// <path> NUL <attribute> NUL <info> NUL ...
	for i := 0; i < c.count; {
		word, err := c.stdout.ReadBytes('\000')
		if err != nil {
			return nil, fmt.Errorf("read line: %w", err)
		}

		buf = append(buf, string(bytes.TrimSuffix(word, []byte{0})))

		if len(buf) < 3 {
			continue // Keep going until we have 3 words
		}

		if buf[0] != path {
			return nil, fmt.Errorf("wrong path name detected, expected %q, got %q", path, buf[0])
		}
		if buf[2] != Unspecified {
			attrs = append(attrs, Attribute{Name: buf[1], State: buf[2]})
		}

		i++
		buf = buf[:0]
	}

	return attrs, nil
```
