### Title
Fee bypass via TokenDiff delta-splitting on `Nep245`/`Imt` tokens (`amount<=1` threshold) - (File: `contracts/defuse/core/src/intents/token_diff.rs`)

### Summary
`TokenDiff::token_fee` charges `Pips::ZERO` on any `Nep245`/`Imt` negative delta whose absolute value is `<= 1`, and this check is applied independently per `TokenDiff` intent rather than on the net position across a batch. A signer can split a single `delta = -2` swap into two `TokenDiff` intents each with `delta = -1` on the same `Nep245` `token_id`, in the same `MultiPayload` batch, and pay zero fee instead of `Pips::fee_ceil(2, fee)`.

### Finding Description
The intended binding (fee owed for a negative position of size `N` on token `T` should not depend on how many separate intents that position is split across) does not hold. The actual code in `contracts/defuse/core/src/intents/token_diff.rs`:

```
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}

is invoked per-token, per-`TokenDiff::execute_intent` call, purely on the `amount` present in *that* intent's delta:

```
if *delta < 0 {
    let amount = delta.unsigned_abs();

    fees_collected.add(token_id.clone(), fee).ok_or(DefuseError::BalanceOverflow)?;

``` [2](#0-1) 

There is no aggregation of deltas for the same `(signer, token_id)` across multiple `TokenDiff` intents in the same batch before the `amount > 1` check is evaluated — each intent is processed independently in `ExecutableIntent::execute_intent` (`contracts/defuse/core/src/intents/mod.rs:115-147`) via `Engine::execute_intents`, and only afterward are net deltas reconciled by `TransferMatcher::finalize` for the balance-invariant check, not for fees.

Exploit: signer holding `>=2` units of a `Nep245` token signs two `TokenDiff` intents (in one or two payloads, both included in one `MultiPayload`), each `{token_id: -1, counter_token: +X}` such that the two legs sum to the same net effect as a single `{token_id: -2, counter_token: +2X}` diff (matched by a counterparty's positive delta on `token_id` and negative delta on `counter_token`, as verified by `TransferMatcher::finalize`, `contracts/defuse/core/src/engine/state/deltas.rs:267-283`). Each leg computes `token_fee(Nep245, 1, fee) == Pips::ZERO`, so `fees_collected` for `token_id` is `0` for both intents, vs. `Pips::fee_ceil(2, fee)` that a single combined `delta=-2` intent would owe.

None of the existing guards (`MultiPayload::verify`, nonce checks, `TransferMatcher::finalize`'s zero-sum invariant) address this, because they validate signatures/nonces/balance-conservation, not fee-neutrality with respect to intent granularity. This is a documented behavior of `token_fee` for `Nep171`/`Nep245`/`Imt` ("do not take fees on NFTs and MTs with |delta| <= 1"), evidently intended for genuine single-unit NFT transfers, but it is not restricted to `Nep171` (true NFTs), and it is not evaluated on the aggregated position, so it can be trivially gamed for `Nep245`/`Imt` multi-token balances of any size by decomposing the trade into unit-sized legs.

### Impact Explanation
`fee_collector` is under-collected on `Nep245`/`Imt` token trades: any signer can decompose a trade of `N` units into `N` unit-delta `TokenDiff` intents to reduce the fee on that token from `Pips::fee_ceil(N, fee)` to `0`, provided a counterparty exists willing to net the position (which does not need to be aware of, or complicit in, the fee-avoidance). This directly matches the Critical category "protocol fees bypassed," and is repeatable per account, per token, per batch, with the only cost being the (excluded) gas/signature overhead of additional intents.

### Likelihood Explanation
Preconditions are minimal: an unprivileged signer with `>=2` units of any `Nep245` (or `Imt`) token and any counterparty willing to trade at the equivalent unmatched-delta price. No special roles, relayer keys, or DAO privileges are required — only ordinary `execute_intents`/`simulate_intents` calls with self-crafted `MultiPayload` batches. The 2-leg case is the minimal, cheapest demonstration; a well-resourced actor can extend this to N legs for any trade size to fully zero out `Nep245`/`Imt` fees.

### Recommendation
Compute `token_fee` based on the net negative delta per `(signer_id, token_id)` aggregated across all `TokenDiff` intents in the batch (or globally per execution context) before applying the `amount > 1` threshold, rather than per individual intent. Alternatively, restrict the "no fee for |delta|<=1" carve-out strictly to `Nep171` (true NFTs, where amount is always 1) and always charge `fee` on `Nep245`/`Imt` regardless of amount, since these token types can represent arbitrarily large fungible balances.

### Proof of Concept
`cargo test` in `contracts/defuse/core` (extending `contracts/defuse/core/src/intents/token_diff.rs` tests) or a `near-workspaces`/sandbox test mirroring `tests/src/tests/defuse/intents/token_diff.rs::swap_p2p`:

1. Setup: two users, `fee = Pips::ONE_PERCENT` (or any `fee > Pips::ZERO`), a `Nep245` `token_id` where signer holds `2` units and counterparty holds a matching amount of `counter_token`.
2. Case A (combined): signer signs one `TokenDiff{ diff: {token_id: -2, counter_token: closure_delta(counter_token, ...)} }`; counterparty signs matching intent; execute via `execute_intents`; record `fees_collected` for `token_id` — assert `== Pips::fee_ceil(2, fee)` (`> 0`).
3. Case B (split): signer signs two `TokenDiff` intents each `{token_id: -1, counter_token: ...}` summing to the same net effect; counterparty signs matching counter-intent(s); execute via `execute_intents`; record total `fees_collected` for `token_id` across both intents — assert `== 0`.
4. Assert `Case A fees_collected(token_id) != Case B fees_collected(token_id)` (specifically `Case B == 0 < Case A`), proving the fee is bypassed purely by intent-splitting despite identical net economic transfer. [3](#0-2)

impl ExecutableIntent for TokenDiff {
    fn execute_intent<S, I>(
        self,
        signer_id: &AccountIdRef,
        engine: &mut Engine<S, I>,
        intent_hash: [u8; 32],
    ) -> Result<()>
    where
        S: State,
        I: Inspector,
    {
        if self.diff.is_empty() {
            return Err(DefuseError::InvalidIntent);
        }

        let protocol_fee = engine.state.fee();
        let mut fees_collected: Amounts = Amounts::default();

        for (token_id, delta) in &self.diff {
            if *delta == 0 {
                return Err(DefuseError::InvalidIntent);
            }

            // add delta to signer's account
            engine
                .state
                .internal_apply_deltas(signer_id, [(token_id.clone(), *delta)])?;

            // take fees only from negative deltas (i.e. token_in)
            if *delta < 0 {
                let amount = delta.unsigned_abs();
                let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);

                // collect fee
                fees_collected
                    .add(token_id.clone(), fee)
                    .ok_or(DefuseError::BalanceOverflow)?;
            }
        }

        engine.inspector.on_event(DefuseEvent::TokenDiff(
            [MaybeIntentEvent::new_intent(
                AccountEvent::new(
                    signer_id,
                    TokenDiffEvent {
                        diff: Cow::Borrowed(&self),
                        fees_collected: fees_collected.clone(),
                    },
                ),
                intent_hash,
            )]
            .as_slice()
            .into(),
        ));

        // deposit fees to collector
        if !fees_collected.is_empty() {
            engine
                .state
                .internal_add_balance(engine.state.fee_collector().into_owned(), fees_collected)?;
        }

        Ok(())
    }
