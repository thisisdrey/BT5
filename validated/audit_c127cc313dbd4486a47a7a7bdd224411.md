### Title
Praefect repository-creation routing panics with slice index out of range when replication factor exceeds healthy secondary node count - (File: internal/praefect/router_per_repository.go)

### Summary
`assignRepositoryToNodes` computes the set of secondary nodes for a newly created repository by shuffling all non-primary connections configured for a virtual storage and then slicing the shuffled slice down to `replicationFactor-1` entries. The slice bound is taken from operator/administrator configuration (`defaultReplicationFactors`) rather than from the actual size of the collection being sliced (`secondaryNodes`, which is derived from currently healthy/connected nodes), so if the number of available secondary connections drops below `replicationFactor-1`, the slice expression panics.

### Finding Description
In the `default` branch of `assignRepositoryToNodes` [1](#0-0) , `secondaryNodes` is built by iterating `r.conns[virtualStorage]` and excluding the primary:
```go
var secondaryNodes []RouterNode
for storage, conn := range r.conns[virtualStorage] {
    if storage == primary.Storage {
        continue
    }
    secondaryNodes = append(secondaryNodes, RouterNode{Storage: storage, Connection: conn})
}

if replicationFactor > 0 {
    r.rand.Shuffle(len(secondaryNodes), func(i, j int) {
        secondaryNodes[i], secondaryNodes[j] = secondaryNodes[j], secondaryNodes[i]
    })
    secondaryNodes = secondaryNodes[:replicationFactor-1]
}
```
`replicationFactor` comes from `r.defaultReplicationFactors[virtualStorage]`, a value fixed at Praefect configuration time and unrelated to the actual number of entries in `r.conns[virtualStorage]` at request time (note `r.conns` reflects configured storage nodes, not currently healthy ones — health filtering happens separately via `healthyNodes()`). If `replicationFactor-1 > len(secondaryNodes)`, the slice expression `secondaryNodes[:replicationFactor-1]` panics with "slice bounds out of range."

This is structurally the same bug class as the reported `quoteDeliveryPrice`/`parseTransceiverInstructions` issue: a size/bound value taken from one collection (the "enabled"/configured count) is used to index or slice a differently-sized array (built from a filtered/live/healthy subset), causing an out-of-bounds access when the live subset shrinks below the assumed size.

Reachability: this code path is exercised by `RouteRepositoryCreation`, called for every repository-creation RPC (e.g. `CreateRepository`, `CreateFork`, `ReplicateRepository` initial creation, `PostReceivePack`-triggered new-repo pushes, project import) that goes through Praefect with the per-repository router and no `additionalRepoMetadata` [2](#0-1) . Any ordinary user creating a new project/fork/import in a Praefect-fronted virtual storage triggers `assignRepositoryToNodes`.

Note: `len(r.conns[virtualStorage])` is the count of *configured* storage nodes for that virtual storage, which is normally static, but it can be smaller than `replicationFactor` if an administrator has removed a node or reduced storages without adjusting `replication_factor`, or in single/degraded-storage virtual storage configurations. There is no defensive check comparing `replicationFactor` against `len(secondaryNodes)+1` before slicing.

### Impact Explanation
A misconfiguration (or a runtime change in the number of configured storage nodes for a virtual storage) where `replicationFactor` exceeds the number of available secondaries causes every repository-creation request routed through `PerRepositoryRouter` to panic in the Praefect process. Depending on how the gRPC server recovers panics, this can manifest as request failures for all repository-creation RPCs on that virtual storage, i.e. a denial-of-service condition triggerable by ordinary repository-creation traffic once the misconfiguration/degraded state exists.

### Likelihood Explanation
This requires a specific but plausible configuration state: `defaultReplicationFactors[virtualStorage]` set to a value greater than `len(r.conns[virtualStorage])` (e.g., after removing a storage node from `[[praefect.virtual_storage]]` without lowering `replication_factor`, or during rolling storage-node decommissioning). This is an operational/config-drift scenario rather than something a remote, unprivileged actor can directly trigger, but any ordinary user's repository-creation request will hit the panic once that state exists — no privileged action or malicious peer is needed to trigger the crash itself.

### Recommendation
Clamp the slice bound to the actual size of `secondaryNodes` before slicing, e.g.:
```go
if replicationFactor > 0 {
    r.rand.Shuffle(len(secondaryNodes), func(i, j int) {
        secondaryNodes[i], secondaryNodes[j] = secondaryNodes[j], secondaryNodes[i]
    })

    limit := replicationFactor - 1
    if limit > len(secondaryNodes) {
        limit = len(secondaryNodes)
    }
    secondaryNodes = secondaryNodes[:limit]
}
```
Additionally, validate `replication_factor` against the number of configured nodes per virtual storage at Praefect startup/config-reload time and reject or warn on invalid configurations.

### Proof of Concept
Configure Praefect with a virtual storage that has 2 nodes (1 primary-eligible + 1 secondary) but `default_replication_factor: 3`. Then issue any repository-creation RPC (e.g. `CreateRepository`) routed through `PerRepositoryRouter.RouteRepositoryCreation`:
1. `assignRepositoryToNodes` picks a random primary from the 2 healthy nodes.
2. `secondaryNodes` is built from `r.conns[virtualStorage]` minus the primary → length 1.
3. `replicationFactor > 0` branch executes `secondaryNodes[:replicationFactor-1]` = `secondaryNodes[:2]`.
4. Since `len(secondaryNodes) == 1 < 2`, Go panics with "slice bounds out of range [:2] with capacity 1", crashing the request handling goroutine. [3](#0-2)

// RouteRepositoryCreation routes an incoming repository creation to a set of target nodes that will
// be designated to hold the new repository.
func (r *PerRepositoryRouter) RouteRepositoryCreation(ctx context.Context, virtualStorage, relativePath, additionalRelativePath string) (RepositoryMutatorRoute, error) {
	var additionalRepoMetadata *datastore.RepositoryMetadata
	var additionalReplicaPath string
	if additionalRelativePath != "" {
		metadata, err := r.rs.GetRepositoryMetadataByPath(ctx, virtualStorage, additionalRelativePath)
		if err != nil {
			if errors.Is(err, datastore.ErrRepositoryNotFound) {
				return RepositoryMutatorRoute{}, additionalRepositoryNotFoundError{
					storageName:  virtualStorage,
					relativePath: additionalRelativePath,
				}
			}

			return RepositoryMutatorRoute{}, fmt.Errorf("resolve additional replica metadata: %w", err)
		}

		additionalRepoMetadata = &metadata
		additionalReplicaPath = metadata.ReplicaPath
	}

	assignedNodes, err := r.assignRepositoryToNodes(virtualStorage, additionalRepoMetadata)
	if err != nil {
		return RepositoryMutatorRoute{}, err
	}

	id, err := r.rs.ReserveRepositoryID(ctx, virtualStorage, relativePath)
	if err != nil {
		return RepositoryMutatorRoute{}, fmt.Errorf("reserve repository id: %w", err)
	}

	replicaPath := storage.DeriveReplicaPath(id)
	if storage.IsRailsPoolRepository(&gitalypb.Repository{
		StorageName:  virtualStorage,
		RelativePath: relativePath,
	}) {
		replicaPath = storage.DerivePoolPath(id)
	}

	return RepositoryMutatorRoute{
		RepositoryID:          id,
		ReplicaPath:           replicaPath,
		AdditionalReplicaPath: additionalReplicaPath,
		Primary:               assignedNodes.primary,
		Secondaries:           assignedNodes.secondaries,
		ReplicationTargets:    assignedNodes.replicationTargets,
	}, nil
}
