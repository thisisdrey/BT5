### Title
Unvalidated `SubstituteNameOffset`/`SubstituteNameLength` in Windows reparse-point parsing causes out-of-bounds heap read - ([File: src/internal/syscall/windows/reparse_windows.go])

### Summary
`SymbolicLinkReparseBuffer.Path()` and `MountPointReparseBuffer.Path()` compute slice indices directly from the `SubstituteNameOffset`/`SubstituteNameLength` fields of a `REPARSE_DATA_BUFFER` returned by `FSCTL_GET_REPARSE_POINT`, without validating them against the actual returned data length. This mirrors the ntfs3 kernel bug's root cause: an on-disk/attacker-influenced offset field is trusted and used to index a buffer without a bounds check, producing an out-of-bounds read.

### Finding Description
The reparse buffer's contents (including `SubstituteNameOffset` and `SubstituteNameLength`, both `uint16`) are set by whoever wrote the reparse point on disk via `FSCTL_SET_REPARSE_POINT` (an unprivileged operation that any user with write access to a file/directory — e.g., a shared temp directory — can perform for symlinks/junctions they own). [1](#0-0) 

When a victim process later resolves that path — via `os.Readlink`, `filepath.EvalSymlinks`, `os.Lstat`, or the `os.Root` API — Go calls `readReparseLinkHandle`, which issues `FSCTL_GET_REPARSE_POINT` into a fixed `MAXIMUM_REPARSE_DATA_BUFFER_SIZE` (16 KiB) buffer and dispatches on `ReparseTag`: [2](#0-1) 

For `IO_REPARSE_TAG_SYMLINK`/mount points, `Path()` computes:
```go
n1 := rb.SubstituteNameOffset / 2
n2 := (rb.SubstituteNameOffset + rb.SubstituteNameLength) / 2
return syscall.UTF16ToString((*[0xffff]uint16)(unsafe.Pointer(&rb.PathBuffer[0]))[n1:n2:n2])
``` [3](#0-2) 

There is no check that `SubstituteNameOffset + SubstituteNameLength` fits within the bytes actually returned by the kernel (`bytesReturned`/`ReparseDataLength`) or within the 16 KiB `rdbbuf` allocation. Because the fields are attacker-controlled `uint16` values, `n2` can be as large as 32767 (65534 bytes), while the real underlying Go slice (`rdbbuf`) is only 16384 bytes. The cast `(*[0xffff]uint16)(unsafe.Pointer(...))` creates an unchecked fixed-size array view over the heap that extends well past the actual allocation, and the subsequent Go slice expression `[n1:n2:n2]` on that fake array bypasses Go's normal slice-bounds safety (the bounds check only validates against the declared array length `0xffff`, not the real buffer size). The identical unvalidated pattern also exists in the legacy `syscall.Readlink` implementation. [4](#0-3) 

### Impact Explanation
This is an out-of-bounds heap read whose result (adjacent process heap memory, reinterpreted as UTF-16 and converted to a string) is returned to the caller as the "symlink target" path. That leaked memory can be surfaced to an attacker through logs, error messages, or subsequent filesystem/network operations that use the resolved path, constituting cross-context memory disclosure. In the worst case, reading far enough past the allocation could hit an unmapped page and crash the process (DoS). Under Go's severity model this would be a PUBLIC-track memory-safety/information-disclosure issue, analogous in class (untrusted on-disk offset trusted without bounds validation) to the ntfs3 CVE, though the primitive here is a heap over-read/info-leak in userspace rather than a kernel OOB read.

### Likelihood Explanation
Any unprivileged local user who can write a reparse point (symlink or junction) into a directory that a higher-privileged or victim process will later traverse (a very common pattern: shared temp directories, extraction targets, build tool intermediate directories) can set crafted `SubstituteNameOffset`/`SubstituteNameLength` values via `DeviceIoControl(FSCTL_SET_REPARSE_POINT, ...)`, since creating raw reparse data does not require the same privilege as the `CreateSymbolicLink` Win32 API. The victim workflow is simply resolving/reading that reparse point (`os.Readlink`, `filepath.EvalSymlinks`, `os.Lstat` on it, or the new `os.Root` symlink-handling paths). [5](#0-4) 

### Recommendation
Validate `SubstituteNameOffset` and `SubstituteNameLength` (and `PrintNameOffset`/`PrintNameLength`) against the actual `bytesReturned`/`ReparseDataLength` before slicing, and bound the array cast to the real buffer size (or use a safe `unsafe.Slice`-based approach sized to the returned byte count) instead of an unconditioned `[0xffff]uint16` cast, returning an error (e.g., analogous to the kernel's now-added sanity checks) when the computed range exceeds the actual data.

### Proof of Concept
Because reproducing this requires an actual malformed on-disk reparse point read back via `DeviceIoControl`, a minimal unit test isolates the vulnerable arithmetic/indexing logic directly:

```go
package windows_test

import (
	"internal/syscall/windows"
	"testing"
	"unsafe"
)

func TestSymbolicLinkReparseBuffer_OOBOffset(t *testing.T) {
	// Simulate a small, legitimately-sized reparse buffer allocation
	// (much smaller than the 0xffff-element array the Path() method casts to).
	const bufLen = 64 // bytes
	buf := make([]byte, bufLen)

	rb := (*windows.SymbolicLinkReparseBuffer)(unsafe.Pointer(&buf[0]))
	// Attacker-controlled fields: offset/length far beyond the real buffer.
	rb.SubstituteNameOffset = 40000 // bytes
	rb.SubstituteNameLength = 2000  // bytes

	// This indexes far past the 64-byte allocation via the unchecked
	// (*[0xffff]uint16) cast in Path(), reading unrelated heap memory
	// instead of returning an error.
	got := rb.Path()
	t.Logf("leaked/garbage path (len=%d): %q", len(got), got)

	// Expected (post-fix) behavior: Path() / its caller should detect that
	// SubstituteNameOffset+SubstituteNameLength exceeds the actual reparse
	// data length and return an error instead of silently reading OOB memory.
}
```
Expected assertion after a fix: the parsing function should reject the buffer with an error such as `errors.New("invalid reparse point: substitute name range exceeds buffer size")` rather than returning a string built from out-of-bounds memory.

type SymbolicLinkReparseBuffer struct {
	// The integer that contains the offset, in bytes,
	// of the substitute name string in the PathBuffer array,
	// computed as an offset from byte 0 of PathBuffer. Note that
	// this offset must be divided by 2 to get the array index.
	SubstituteNameOffset uint16
	// The integer that contains the length, in bytes, of the
	// substitute name string. If this string is null-terminated,
	// SubstituteNameLength does not include the Unicode null character.
	SubstituteNameLength uint16
	// PrintNameOffset is similar to SubstituteNameOffset.
	PrintNameOffset uint16
	// PrintNameLength is similar to SubstituteNameLength.
	PrintNameLength uint16
	// Flags specifies whether the substitute name is a full path name or
	// a path name relative to the directory containing the symbolic link.
	Flags      uint32
	PathBuffer [1]uint16
}

// Path returns path stored in rb.
func (rb *SymbolicLinkReparseBuffer) Path() string {
	n1 := rb.SubstituteNameOffset / 2
	n2 := (rb.SubstituteNameOffset + rb.SubstituteNameLength) / 2
	return syscall.UTF16ToString((*[0xffff]uint16)(unsafe.Pointer(&rb.PathBuffer[0]))[n1:n2:n2])
}

func readReparseLinkHandle(h syscall.Handle) (string, error) {
	rdbbuf := make([]byte, syscall.MAXIMUM_REPARSE_DATA_BUFFER_SIZE)
	var bytesReturned uint32
	err := syscall.DeviceIoControl(h, syscall.FSCTL_GET_REPARSE_POINT, nil, 0, &rdbbuf[0], uint32(len(rdbbuf)), &bytesReturned, nil)
	if err != nil {
		return "", err
	}

	rdb := (*windows.REPARSE_DATA_BUFFER)(unsafe.Pointer(&rdbbuf[0]))
	switch rdb.ReparseTag {
	case syscall.IO_REPARSE_TAG_SYMLINK:
		rb := (*windows.SymbolicLinkReparseBuffer)(unsafe.Pointer(&rdb.DUMMYUNIONNAME))
		s := rb.Path()
		if rb.Flags&windows.SYMLINK_FLAG_RELATIVE != 0 {
			return s, nil
		}
		return normaliseLinkPath(s)
	case windows.IO_REPARSE_TAG_MOUNT_POINT:
		return normaliseLinkPath((*windows.MountPointReparseBuffer)(unsafe.Pointer(&rdb.DUMMYUNIONNAME)).Path())
	default:
		// the path is not a symlink or junction but another type of reparse
		// point
		return "", syscall.ENOENT
	}
}

func readReparseLinkAt(dirfd syscall.Handle, name string) (string, error) {
	objectName, err := windows.NewNTUnicodeString(name)
	if err != nil {
		return "", err
	}
	objAttrs := &windows.OBJECT_ATTRIBUTES{
		ObjectName: objectName,
	}
	if dirfd != syscall.InvalidHandle {
		objAttrs.RootDirectory = dirfd
	}
	objAttrs.Length = uint32(unsafe.Sizeof(*objAttrs))
	var h syscall.Handle
	err = windows.NtCreateFile(
		&h,
		windows.FILE_GENERIC_READ,
		objAttrs,
		&windows.IO_STATUS_BLOCK{},
		nil,
		uint32(syscall.FILE_ATTRIBUTE_NORMAL),
		syscall.FILE_SHARE_READ|syscall.FILE_SHARE_WRITE|syscall.FILE_SHARE_DELETE,
		windows.FILE_OPEN,
		windows.FILE_SYNCHRONOUS_IO_NONALERT|windows.FILE_OPEN_REPARSE_POINT,
		nil,
		0,
	)
	if err != nil {
		return "", err
	}
	defer syscall.CloseHandle(h)
	return readReparseLinkHandle(h)
}
