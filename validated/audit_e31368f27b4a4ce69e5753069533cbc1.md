### Title
Unsigned integer underflow in reftable block parsing leads to out-of-bounds panic/DoS - ([File: internal/git/reftable/reftable.go])

### Summary
The Gitaly reftable parser computes `RestartStart` for each reference block using an unchecked subtraction of unsigned integers. If a `.ref` table file has a smaller `currentBS` (block size) or larger `RestartCount` than expected, the subtraction wraps around (Go `uint` arithmetic does not panic, it wraps modulo 2^64), producing a huge bogus offset. This corrupted offset is later used to bound a loop that indexes directly into the in-memory `src` byte slice, which panics with an out-of-range index. This is the same bug class as the reported smart-contract issue: an unchecked corner case in an offset/size computation that is assumed always positive/in-range, causing the consuming logic to fail (there, a revert; here, a Go runtime panic that can crash the serving goroutine/process).

### Finding Description
`parseRefBlock` reads the block length (`currentBS`) and then computes the restart-table start offset as: [1](#0-0) 

`b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)` has no validation that `currentBS >= 2` or that `3*RestartCount <= (blockStart+currentBS-2)`. Both `currentBS` (a 24-bit big-endian value taken directly from file bytes via `extractBlockLen`) and `RestartCount` (a `uint16` read directly from file bytes) are attacker/corruption-controlled inputs from the on-disk table file: [2](#0-1) 

If the subtraction underflows, `RestartStart` becomes an enormous value close to `math.MaxUint`. This value is then used as the loop bound in `getRefsFromBlock`: [3](#0-2) 

Because `idx < b.RestartStart` remains true far beyond the actual buffer length, the subsequent slice expressions `src[idx:idx+suffixLength]`, `src[idx:idx+hashSize]`, etc. will eventually index past `len(src)`, causing a Go runtime panic (`slice bounds out of range`). Unlike the reported Solidity bug (a `require`/SafeMath revert), Go's unsigned wraparound does not immediately fail — it silently produces a wrong value that later corrupts memory-safety-checked slice bounds, turning a purely arithmetic corner case into a hard crash rather than a graceful error.

### Impact Explanation
A crafted or corrupted reftable block (undersized `currentBS` relative to its `RestartCount`) causes a panic while Gitaly parses reference data. Depending on whether the panic occurs inside a goroutine without a `recover()` in the calling gRPC/replication/housekeeping path, this can crash the Gitaly process, denying service to all repositories served by that instance — analogous to the reported "blocking the contract" impact, but manifesting as a process-level DoS instead of a reverted transaction.

### Likelihood Explanation
Reftable files are normally written by Git itself, so a compliant client generally cannot supply arbitrary bytes for `currentBS`/`RestartCount` through normal ref updates. However, this code path becomes concretely reachable and hazardous whenever Gitaly parses on-disk reftable files that did not originate from a strictly-validated local `git-update-ref` write on the same host — e.g. replicated/restored repository data (backups, snapshot import, `ReplicateRepository`) or corruption from partial/torn writes/crashes. `ParseTable`/`GetReferences` are exercised outside of unit tests in stats/repository-info collection and housekeeping/replication flows, both of which run on data that traveled over the network or through backup/restore, giving this at least a plausible unprivileged path even though it is not as direct as a push-controlled corner case in the original report. I could not fully confirm every production call-site because of index size limits, so likelihood should be validated further against the full call graph.

### Recommendation
Add explicit bounds validation before performing the subtraction in `parseRefBlock`: verify `currentBS >= 2 + 3*uint(RestartCount)` and that the resulting `RestartStart` lies within `[blockStart, blockEnd]` before use, returning a parse error instead of continuing. Likewise, validate `idx`, `idx+suffixLength`, `idx+hashSize`, and `idx+size` against `len(src)` in `getRefsFromBlock` before slicing, and add a `recover()` guard around reftable parsing so a malformed/corrupted table degrades to an error response rather than crashing the process.

### Proof of Concept
1. Construct a `.ref` file with a valid header/footer but with a reference block whose 3-byte big-endian block length (`currentBS`) is set to `2` (or `0`/`1`) while the 2-byte restart count trailer stored at `blockStart+currentBS-2` encodes a nonzero `RestartCount` (e.g. `1`).
2. Compute: `RestartStart = blockStart + 2 - 2 - 3*1 = blockStart - 3`, which underflows to a value near `math.MaxUint` when `blockStart` is small (e.g. header offset only).
3. Call `reftable.ParseTable(path)` followed by `table.GetReferences()`.
4. `getRefsFromBlock`'s loop condition `idx < b.RestartStart` never becomes false before `idx` exceeds `len(src)`, and one of `src[idx:...]` accesses panics with `slice bounds out of range`, terminating the goroutine/process instead of returning a parse error. [4](#0-3)

// getVarInt parses a variable int and increases the index.
func (t *Table) getVarInt(src []byte, start uint, blockEnd uint) (uint, uint, error) {
	var val uint

	val = uint(src[start]) & 0x7f

	for (uint(src[start]) & 0x80) > 0 {
		start++
		if start > blockEnd {
			return 0, 0, fmt.Errorf("exceeded block length")
		}

		val = ((val + 1) << 7) | (uint(src[start]) & 0x7f)
	}

	return start + 1, val, nil
}

// parseRefBlock parses a block and if it is a ref block, provides
// all the reference updates.
func (t *Table) parseRefBlock(src []byte, headerOffset, blockStart, blockEnd uint) ([]git.Reference, error) {
	currentBS := t.extractBlockLen(src, blockStart+headerOffset)

	fullBlockSize := t.blockSize
	if fullBlockSize == 0 {
		fullBlockSize = currentBS
	} else if currentBS < fullBlockSize && currentBS < (blockEnd-blockStart) && src[blockStart+currentBS] != 0 {
		fullBlockSize = currentBS
	}

	b := &block{
		BlockStart:    blockStart + headerOffset,
		FullBlockSize: fullBlockSize,
	}

	if err := binary.Read(bytes.NewBuffer(src[blockStart+currentBS-2:]), binary.BigEndian, &b.RestartCount); err != nil {
		return nil, fmt.Errorf("reading restart count: %w", err)
	}

	b.RestartStart = blockStart + currentBS - 2 - 3*uint(b.RestartCount)

	return t.getRefsFromBlock(src, b)
}
