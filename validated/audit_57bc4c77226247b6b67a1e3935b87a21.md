### Title
Predictable, Sequential Repository/Pool Disk Paths Allow Unprivileged Path-Squatting DoS Against Repository, Fork, and Object-Pool Creation - (File: internal/gitaly/storage/repository_path.go)

### Summary
Praefect's `ReserveRepositoryID` (`internal/praefect/datastore/repository_store.go:884-904`) allocates repository IDs from a single, global, monotonically increasing Postgres sequence (`nextval('repositories_repository_id_seq')`), and `PerRepositoryRouter.RouteRepositoryCreation` (`internal/praefect/router_per_repository.go:452-500`) immediately derives the on-disk replica/pool path from that ID via `storage.DeriveReplicaPath`/`storage.DerivePoolPath` (`internal/gitaly/storage/repository_path.go:45-69`) *before* the corresponding Gitaly-side `repoutil.Create` call is even issued. Because the derivation is a pure, secret-free function of a small sequential integer (`SHA256(strconv.Itoa(id))`, using only the first two hash bytes for sharding), any client capable of creating repositories can trivially predict the exact disk path (e.g. `@cluster/repositories/ab/cd/<id>`) that will be assigned to the *next* repository, fork, or object pool created by anyone in the cluster.

### Finding Description
This is the same bug class as the reported Folks-Finance issue: a resource is keyed by a client-influenced/predictable identifier, and account/resource *creation* races ahead of the intended owner because the ID space is guessable rather than randomized or access-controlled. In Folks-Finance, `accountId` was attacker-chosen and the hub-chain balance keyed off it, letting an attacker front-run creation and redirect fees. In Gitaly/Praefect, the repository ID is not attacker-chosen but is fully *predictable* (sequential counter, deterministic hash-to-path mapping with no per-repository secret), which is functionally equivalent for path-squatting purposes: an attacker doesn't need to guess the victim's ID, they only need to observe the current sequence value (e.g. from IDs assigned to their own recent repository creations, which are directly reflected in the derived replica path visible on disk/in metadata) and then race to occupy `DeriveReplicaPath(id+1)`, `DeriveReplicaPath(id+2)`, etc. on the physical Gitaly storage before Praefect's coordinator issues the real `CreateRepository`/`CreateFork`/`CreateObjectPool` RPC for that ID.

`repoutil.Create` (`internal/gitaly/repoutil/create.go:96-104` and again at `198-208`) is explicitly documented as "race-free" against *concurrent Gitaly-mediated creation attempts*, but it has no defense against a path that is *already occupied by unrelated content that got there via a different, out-of-band route* (e.g., a directly-targeted Gitaly RPC using the predicted future path, or another RPC that happens to write to that same predicted path first): it simply does `os.Stat(targetPath)` and returns `AlreadyExists` if anything is there — pre-lock and post-lock. The `objectpool` package has an even weaker check and an already-acknowledged gap: its own test comment states "We currently allow creating object pools when the target path is an empty directory. This can be considered a bug, but for now we abide" (`internal/git/objectpool/create_test.go:82-88`), and `objectpool.Create` (`internal/git/objectpool/create.go:42-48`) only checks `os.Stat(objectPoolPath) == nil` to fail, meaning an attacker-created empty directory at the predicted pool path is treated the same as "target exists" and blocks legitimate creation, but a non-empty stray directory could also confuse the on-disk/DB consistency invariants Praefect relies on (the `repositories`/`storage_repositories` tables in `doc/virtual_storage.md` assume 1:1 mapping between the reserved ID's path and actual on-disk content).

### Impact Explanation
An unprivileged, ordinary user who can create repositories at all (a baseline capability, not a privileged actor) can:
1. Determine the current value of the shared, cluster-wide `repositories_repository_id_seq` (trivially, by creating a throwaway repo/fork and reading its resulting replica/pool path, or repository ID exposed in Rails/GitLab APIs), then
2. Pre-create/populate arbitrary content directly at `DeriveReplicaPath(id+k)` (or `DerivePoolPath(id+k)`) on a Gitaly storage for a small window of `k`, ahead of any other user in the whole cluster whose `CreateRepository`, `CreateFork`, or `CreateObjectPool` call is about to consume that same ID.

Because `ReserveRepositoryID` reserves the ID in Postgres independently of, and prior to, the actual Gitaly-side directory creation, there is a race window in which the ID is committed to the `repositories` table but the on-disk path has not yet been created by `repoutil.Create`. If the attacker wins the race to create the target directory first, the legitimate victim's repository/fork/pool creation RPC will unconditionally fail with `AlreadyExists` (see `repoutil.Create`'s pre-lock/post-lock stat checks, and `internal/gitaly/service/objectpool/create_test.go:251-257` "pool exists" behavior), causing denial of service for that specific project/fork/pool creation, while the reserved repository ID/DB row remains inconsistent with the actual disk state. This can be repeated for every repository ID a victim's operation is about to consume, effectively letting an attacker deny repository, fork, or object-pool creation cluster-wide at will, and it can corrupt the assumed invariant that a `repositories` row's replica path always corresponds to content actually created via the sanctioned `repoutil.Create`/`objectpool.Create` code paths (relevant to storage-path resolution and object-pool isolation guarantees the whole design otherwise depends on).

### Likelihood Explanation
The repository ID sequence and the path-derivation function are both simple and fully deterministic with no entropy or per-tenant secret (`internal/gitaly/storage/repository_path.go:61-68`, confirmed deterministic by `TestDeriveReplicaPath`/`TestDerivePoolPath` fixed expected outputs at `internal/gitaly/storage/repository_path_test.go:12-20`). Any authenticated user who can trigger repository/fork/pool creation (a very common, low-privilege capability) can observe recent IDs and compute near-future ones. The only obstacle is winning a narrow timing race between `ReserveRepositoryID` and the subsequent Gitaly-side directory creation, which is a standard, well-understood exploitation technique (directly analogous to the front-running technique described in the reference report) and does not require any privileged access, leaked token, or malicious peer/node — it is exploitable purely from ordinary client-facing RPCs.

### Recommendation
- Do not derive on-disk repository/pool paths purely from a small, sequential, unsalted integer; either add a per-repository random component (e.g. a UUID or a random salt combined with the ID before hashing) so that the disk path is not guessable ahead of creation, or
- Perform an atomic reservation on the *physical* storage (e.g., via the existing `Lock`/temp-directory-then-rename technique in `repoutil.Create`) *before* the ID/path pair is considered valid anywhere else, and make `ReserveRepositoryID` and the physical path creation atomic/transactional with respect to each other so no external actor can observe or act on a reserved-but-unmaterialized path.
- Harden `objectpool.Create`'s pre-existence check to reject any pre-existing directory (not just allow "empty directory" as a permitted target), closing the acknowledged gap flagged in `internal/git/objectpool/create_test.go:86-87`.
- Add detection/alerting for `repositories` DB rows whose replica path exists on disk but was not created through the expected creation RPCs, to catch exploitation attempts.

### Proof of Concept
1. As an unprivileged user, repeatedly call `CreateRepository` (or observe project creation via the normal API) to learn the current `repository_id`/derived replica path, e.g. `@cluster/repositories/6b/86/1`.
2. Compute `DeriveReplicaPath(id+1)` through `DeriveReplicaPath(id+N)` locally (pure function, no secrets needed — see `internal/gitaly/storage/repository_path.go:61-68`).
3. Race to issue a request (or, where a direct path can be targeted, any Gitaly-facing repository-creation call with an explicit `RelativePath` on those predicted values) so that a directory/repository is created at `DeriveReplicaPath(id+k)` before the real Praefect-issued `CreateRepository`/`CreateFork`/`CreateObjectPool` call for that soon-to-be-reserved ID reaches Gitaly.
4. When the victim's operation that would consume `id+k` executes, Gitaly's `repoutil.Create` pre-lock/post-lock `os.Stat` check (`internal/gitaly/repoutil/create.go:96-104,198-208`) finds the path already occupied and returns `AlreadyExists`, denying the legitimate creation, while Praefect's `repositories` row for `id+k` may already be committed, leaving a persistent DB/disk inconsistency. // DeriveReplicaPath derives a repository's disk storage path from its repository ID. The repository ID
// is hashed with SHA256 and the first four hex digits of the hash are used as the two subdirectories to
// ensure even distribution into subdirectories. The format is @cluster/repositories/ab/cd/<repository-id>.
func DeriveReplicaPath(repositoryID int64) string {
	return deriveDiskPath(praefectRepositoryPathPrefix, repositoryID)
}

// DerivePoolPath derives an object pools's disk storage path from its repository ID. The repository ID
// is hashed with SHA256 and the first four hex digits of the hash are used as the two subdirectories to
// ensure even distribution into subdirectories. The format is @cluster/pools/ab/cd/<repository-id>. The pools
// have a different directory prefix from other repositories so Gitaly can identify them in OptimizeRepository
// and avoid pruning them.
func DerivePoolPath(repositoryID int64) string {
	return deriveDiskPath(praefectPoolPathPrefix, repositoryID)
}

func deriveDiskPath(prefixDir string, repositoryID int64) string {
	hasher := sha256.New()
	// String representation of the ID is used to make it easier to derive the replica paths with
	// external tools. The error is ignored as the hash.Hash interface is documented to never return
	// an error.
	hasher.Write([]byte(strconv.FormatInt(repositoryID, 10)))
	hash := hasher.Sum(nil)
	return filepath.Join(prefixDir, fmt.Sprintf("%x/%x/%d", hash[0:1], hash[1:2], repositoryID))
}

// ReserveRepositoryID reserves an ID for a repository that is about to be created and returns it. If a repository already
// exists with the given virtual storage and relative path combination, an error is returned.
func (rs *PostgresRepositoryStore) ReserveRepositoryID(ctx context.Context, virtualStorage, relativePath string) (int64, error) {
	var id int64
	if err := rs.db.QueryRowContext(ctx, `
SELECT nextval('repositories_repository_id_seq')
WHERE NOT EXISTS (
	SELECT FROM repositories
	WHERE virtual_storage = $1
	AND   relative_path   = $2
)
	`, virtualStorage, relativePath).Scan(&id); err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return 0, ErrRepositoryAlreadyExists
		}

		return 0, fmt.Errorf("scan: %w", err)
	}

	return id, nil
}

// RouteRepositoryCreation routes an incoming repository creation to a set of target nodes that will
// be designated to hold the new repository.
func (r *PerRepositoryRouter) RouteRepositoryCreation(ctx context.Context, virtualStorage, relativePath, additionalRelativePath string) (RepositoryMutatorRoute, error) {
	var additionalRepoMetadata *datastore.RepositoryMetadata
	var additionalReplicaPath string
	if additionalRelativePath != "" {
		metadata, err := r.rs.GetRepositoryMetadataByPath(ctx, virtualStorage, additionalRelativePath)
		if err != nil {
			if errors.Is(err, datastore.ErrRepositoryNotFound) {
				return RepositoryMutatorRoute{}, additionalRepositoryNotFoundError{
					storageName:  virtualStorage,
					relativePath: additionalRelativePath,
				}
			}

			return RepositoryMutatorRoute{}, fmt.Errorf("resolve additional replica metadata: %w", err)
		}

		additionalRepoMetadata = &metadata
		additionalReplicaPath = metadata.ReplicaPath
	}

	assignedNodes, err := r.assignRepositoryToNodes(virtualStorage, additionalRepoMetadata)
	if err != nil {
		return RepositoryMutatorRoute{}, err
	}

	id, err := r.rs.ReserveRepositoryID(ctx, virtualStorage, relativePath)
	if err != nil {
		return RepositoryMutatorRoute{}, fmt.Errorf("reserve repository id: %w", err)
	}

	replicaPath := storage.DeriveReplicaPath(id)
	if storage.IsRailsPoolRepository(&gitalypb.Repository{
		StorageName:  virtualStorage,
		RelativePath: relativePath,
	}) {
		replicaPath = storage.DerivePoolPath(id)
	}

	return RepositoryMutatorRoute{
		RepositoryID:          id,
		ReplicaPath:           replicaPath,
		AdditionalReplicaPath: additionalReplicaPath,
		Primary:               assignedNodes.primary,
		Secondaries:           assignedNodes.secondaries,
		ReplicationTargets:    assignedNodes.replicationTargets,
	}, nil
}
