### Title
Unauthenticated `RecvError` packet with attacker-controlled index allows remote termination of another host's tunnel - ([File: outside.go])

### Summary
`Interface.handleRecvError` processes the unencrypted, unauthenticated `header.RecvError` packet type and uses an attacker-supplied `RemoteIndex` value to look up and tear down an arbitrary victim `HostInfo`, without requiring the sender to hold any CA-signed certificate or have completed a handshake.

### Finding Description
In `readOutsidePackets`, `RecvError` is dispatched before any certificate/session validation, in the same "Unencrypted packets" branch as `Handshake`: [1](#0-0) 

The handler, `handleRecvError`, takes the caller-controlled `h.RemoteIndex` from the packet header and uses it to resolve an existing tunnel via `QueryReverseIndex`, then unconditionally closes it: [2](#0-1) 

The only guard against forgery is `hr.IsValid() && hr != addr` — i.e. it checks that the UDP source address of the packet matches the victim's currently known remote endpoint. Because UDP is connectionless and unauthenticated at this layer (no cert, no handshake, no MAC/AEAD check — this packet type carries no encrypted payload at all), an attacker who can spoof the victim's source IP/port (or simply send from a network path where such spoofing is possible) can send this single, tiny (`header.Len`-only) `RecvError` packet toward any node. The "index" parameter here plays the same role as the arbitrary-address parameter in `USDToken::burn`: it is attacker-supplied and directly determines whose state gets destroyed, with the only restriction being an easily-spoofed source-IP check rather than genuine possession of a valid certificate or completed Noise handshake.

This mirrors the report's bug class exactly — a state-mutating operation reachable by any network peer (1) with no access control gate tied to identity/certificate ownership, and (2) taking an arbitrary target parameter (the remote index) instead of deriving the target from the caller's own authenticated identity.

### Impact Explanation
A successful forged `RecvError` results in `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)`, tearing down an established, encrypted tunnel between two legitimate, fully-certificate-authenticated peers. This is a remote state-poisoning / denial-of-service primitive: with knowledge (or brute-force / observation) of a victim's `RemoteIndex` and the ability to spoof its expected remote UDP source address, a completely uncertified attacker can repeatedly sever tunnels between arbitrary Nebula nodes, forcing costly re-handshakes and disrupting connectivity network-wide, without ever obtaining a valid Nebula certificate.

### Likelihood Explanation
Exploitability depends on: (a) learning/guessing a 32-bit `RemoteIndex` for a target session, and (b) spoofing UDP source address/port to match the victim's currently-known remote. Indexes can potentially be observed on-path or via traffic analysis in shared/untrusted network segments (the primary threat model for this class of finding, since no certificate is required to send arbitrary UDP packets to a node's listening port). The `acceptRecvErrorConfig.ShouldRecvError(addr)` gate limits which peers `RecvError` is honored from (config-controlled allow-list), which reduces exposure in default configurations that restrict this to known lighthouse/peer subnets, but does not restrict based on cryptographic identity, only network address — which is exactly what's being spoofed. This keeps likelihood in the "reachable but requires some conditions" range rather than trivially exploitable against arbitrary internet hosts.

### Recommendation
Two options analogous to the referenced fix:
1) Require `RecvError` to be authenticated (e.g., MAC/AEAD-protected using the session's negotiated keys, or require it be delivered over an already-established encrypted channel) so only a party holding the actual session state can trigger tunnel teardown.
2) Strengthen the existing address check into a full binding check that cannot be satisfied by spoofing alone — e.g., require a matching secret/nonce known only to the two session participants (similar to a signed teardown token), rather than relying solely on comparing the observed UDP source address to the last-known remote.

### Proof of Concept
1. Attacker observes/derives the `RemoteIndex` (`h.RemoteIndex`) used by Node A for its session with Node B (e.g., via traffic analysis on a shared network segment where spoofing is feasible).
2. Attacker crafts a minimal UDP packet with `header.Version`, `header.Type = header.RecvError`, and `RemoteIndex` set to the observed value, and sends it to Node A's listening UDP port with a spoofed source address/port equal to Node B's currently known remote endpoint — see packet construction in `sendRecvError`: [3](#0-2) 
3. Node A's `readOutsidePackets` routes the packet type directly to `handleRecvError` without any decryption or certificate check: [4](#0-3) 
4. `handleRecvError` resolves Node A's `HostInfo` for the tunnel with Node B via `QueryReverseIndex(h.RemoteIndex)`, finds `hr == addr` (spoofed match), and calls `f.closeTunnel(hostinfo)` plus `f.handshakeManager.DeleteHostInfo(hostinfo)`, terminating the legitimate tunnel between A and B — despite the attacker never having presented a valid Nebula certificate or completed any handshake: [5](#0-4)

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
