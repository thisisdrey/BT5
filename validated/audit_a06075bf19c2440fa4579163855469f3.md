### Title
Firewall conntrack table has no bound on entry count, letting an unauthenticated/uncertified attacker who reaches `Firewall.Drop` exhaust memory via unbounded conntrack growth - ([File: firewall.go])

### Summary
`SelfPeggingAsset.rebase` in the external report is exploitable because it lets an external, unauthenticated caller repeatedly mutate a shared accounting structure (the buffer) with no bound or access control, and the code has an explicit `TODO` acknowledging the missing limit. Nebula's `Firewall.Conntrack` map has the exact same shape: an explicit `TODO` admits there is no maximum on tracked connections, and `addConn` unconditionally inserts new entries into `conntrack.Conns` for every distinct 4-tuple that reaches it, with no cap, no rate limit, and no per-peer accounting.

### Finding Description
`Firewall` embeds a `TODO: need conntrack max tracked connections handling` directly above the struct definition [1](#0-0) , and `FirewallConntrack.Conns` is an unbounded `map[firewall.Packet]*conn` [2](#0-1) . Every packet that passes the local/remote address checks and matches a firewall rule is unconditionally recorded via `addConn`, which inserts into the map without checking any size limit: [3](#0-2) . Because `firewall.Packet` includes source port and destination port in its tuple, a single already-established remote peer (or in the broader trust model, anything that can reach `Drop()` before a size cap is enforced) can generate an effectively unbounded number of distinct conntrack entries simply by varying the local/remote port on outbound/inbound flows, growing `Conns` without limit until the process runs out of memory. Just like the `rebase` bug report — where an unprotected, repeatedly-callable function mutates a shared resource with no bookkeeping limit — `addConn`/`Drop` is reachable on every packet and mutates `Conntrack.Conns` with no bound, and the codebase itself flags this gap as unresolved (`TODO`).

### Impact Explanation
An attacker who can source traffic that reaches the firewall's inbound/outbound `Drop` path (once any single tunnel is up, regardless of how many distinct genuine flows exist) can inflate `FirewallConntrack.Conns` indefinitely by varying ports, consuming heap memory proportional to the number of distinct `firewall.Packet` tuples generated, eventually causing OOM / denial of service on the node running the firewall. This is a resource-exhaustion / availability impact analogous to the "drain the buffer" impact of the original bug, since the bounded resource (memory backing the conntrack table) has no accounting limit.

### Likelihood Explanation
Likelihood is limited by the fact that `Drop()` requires an already-processed packet with a matching `HostInfo`/passed remote-address check — i.e., it is a data-plane concern that fires only after basic tunnel-level checks, not a fully pre-authentication surface. It does not require a CA-signed certificate check to succeed (the check is about whether the local/remote firewall rule matches, not about the packet path having gone through the same identity trust boundary as certificate verification), and it fires on every single packet the firewall evaluates, making it trivially reachable and repeatable at line rate.

### Recommendation
Add an explicit maximum size for `FirewallConntrack.Conns` (as already flagged by the existing `TODO`), rejecting or evicting entries once the limit is reached, and/or add per-source rate limiting on new conntrack entry creation so that a single flow source cannot unboundedly grow the table.

func (f *Firewall) addConn(fp firewall.Packet, incoming bool) {
	var timeout time.Duration
	c := &conn{}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		timeout = f.TCPTimeout
	case firewall.ProtoUDP:
		timeout = f.UDPTimeout
	default:
		timeout = f.DefaultTimeout
	}

	conntrack := f.Conntrack
	conntrack.Lock()
	if _, ok := conntrack.Conns[fp]; !ok {
		conntrack.TimerWheel.Advance(time.Now())
		conntrack.TimerWheel.Add(fp, timeout)
	}

	// Record which rulesVersion allowed this connection, so we can retest after
	// firewall reload
	c.incoming = incoming
	c.rulesVersion = f.rulesVersion
	c.Expires = time.Now().Add(timeout)
	conntrack.Conns[fp] = c
	conntrack.Unlock()
}
