### Title
Unstaked-peer connection squatting via perpetual `last_update` refresh defeats oldest-connection pruning in the QUIC streamer - (File: `streamer/src/nonblocking/swqos.rs`, `streamer/src/nonblocking/quic.rs`)

### Summary
The Velodrome finding describes a griefing pattern where an unprivileged caller repeatedly invokes a cheap operation to keep resetting a state variable that governs eviction/expiry, thereby entrenching itself and denying the intended lifecycle behavior. The agave QUIC streamer has an analogous pattern: an unstaked (unprivileged, unauthenticated-by-stake) peer can keep its connection's `last_update` timestamp perpetually fresh by opening trivial streams, which makes `ConnectionTable::prune_oldest` never select it for eviction, allowing it to permanently occupy connection-table slots that are supposed to be reclaimed from stale/idle peers.

### Finding Description
The unstaked connection table is size-bounded (`DEFAULT_MAX_UNSTAKED_CONNECTIONS`) [1](#0-0) . When it fills up, new connections are admitted by first pruning the *oldest* entries via `prune_unstaked_connection_table`, which calls `ConnectionTable::prune_oldest` [2](#0-1) .

`prune_oldest` selects the connection group with the minimum `last_update` timestamp among all entries and evicts it, regardless of which peer it belongs to [3](#0-2) .

The `last_update` value is refreshed every time any stream on that connection finishes, via `on_stream_finished`, which simply stores the current timestamp with no cost or rate check tied to actual useful work: [4](#0-3) 

An unstaked peer only needs to open and immediately finish trivial (near-zero-byte) unidirectional streams periodically to keep calling `on_stream_finished` and refresh `last_update`, at negligible bandwidth/CPU cost, well within the per-connection stream-throttling limits (`on_new_stream`/`throttle_stream` throttle *rate* of streams, not whether a stream is "useful") [5](#0-4) . As long as its `last_update` stays newer than that of any other connection in the table, `prune_oldest` will always prefer to evict some other (potentially legitimate, more idle) connection instead of the attacker's.

This mirrors the reported bug class precisely: a permissionless function/state-refresh path (`on_stream_finished` updating `last_update`, analogous to `notifyRewardAmount` extending `periodFinish`) is callable indefinitely and cheaply by any unprivileged party to keep a duration-governed accounting value (the connection's "freshness"/eviction priority, analogous to reward-period duration) perpetually extended, subverting the mechanism's fairness/rotation guarantee.

### Impact Explanation
By opening the maximum allowed connections per source (`DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER`) from many distinct source addresses/pubkeys (a Sybil pattern, still fully unprivileged — no stake, no validator role required) and continuously refreshing each connection's `last_update` with cheap trivial streams, an attacker can occupy and permanently retain a disproportionate share of the fixed unstaked connection-table capacity (`DEFAULT_MAX_UNSTAKED_CONNECTIONS`). Because `prune_oldest` always evicts based on staleness rather than any notion of fairness/rotation among equally low-value peers, legitimate unstaked senders attempting to submit transactions are preferentially evicted or denied a slot, causing a denial-of-service / QoS evasion condition against ordinary unstaked transaction submission via the TPU QUIC endpoint.

### Likelihood Explanation
The attack requires no special privilege, no stake, and no validator/operator role — only the ability to open QUIC connections to the TPU port and send minimal streams, which is exactly the unstaked/unprivileged-client surface the streamer is designed to serve. The cost is low (small trivial streams, bounded by per-connection stream throttling, but that throttle only limits rate, not the ability to keep refreshing timestamps). This is reachable purely from the network without cooperation from validators or other privileged actors.

### Recommendation
Do not let arbitrary, cheap stream completions from unstaked peers indefinitely reset eviction priority. Options include: bounding the effective "freshness window" a connection can accumulate credit toward (e.g., cap how much `last_update` refresh benefits a connection within a rolling period), incorporating stake or per-peer historical usefulness into the pruning key rather than purely last-activity time for unstaked/no-stake peers, or applying per-IP/per-pubkey fairness constraints in `prune_oldest`/`prune_unstaked_connection_table` so a single actor (or Sybil cluster) cannot monopolize table slots regardless of how often it refreshes activity.

### Proof of Concept
1. Fill the unstaked connection table close to `DEFAULT_MAX_UNSTAKED_CONNECTIONS` using connections from N distinct source IPs/pubkeys, each up to `DEFAULT_MAX_QUIC_CONNECTIONS_PER_UNSTAKED_PEER`.
2. From each attacker connection, periodically open a 0/1-byte unidirectional stream and finish it (respecting the stream-rate throttle), triggering `on_stream_finished` → `last_update` refresh, as exercised in the streamer's own test showing `last_update` is bumped on connection add/stream events [6](#0-5) .
3. Have a legitimate unstaked client attempt to connect once the table is near capacity; observe via `prune_unstaked_connection_table` → `prune_oldest` that only genuinely idle (non-attacker) connections are chosen for eviction because the attacker's `last_update` values are never the minimum, so the legitimate client is dropped/rejected (`CONNECTION_CLOSE_CODE_TOO_MANY`) instead [7](#0-6) .

        }
    }

    pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }
