### Title
StackerDB `MinerMessages` events accepted by the signer's event receiver with no signature/ownership verification, from an unauthenticated, network-reachable HTTP endpoint - ([File: libsigner/src/events.rs])

### Summary
The `stacks-signer`'s `SignerEventReceiver` HTTP server, which the sample configs bind to `0.0.0.0:<port>` (e.g. `endpoint = "0.0.0.0:30000"` in `sample/conf/signer/mainnet-signer-conf.toml`), accepts unauthenticated POST requests on `/stackerdb_chunks` and converts them into `SignerEvent`s. For chunks belonging to the miners' StackerDB contract, the conversion path performs **no signature check and no slot-ownership check** at all, unlike the parallel signer-message path which at least calls `chunk.recover_pk()`. Any host that can reach this port can therefore inject arbitrary `MinerMessages` into the signer's runloop.

### Finding Description
`SignerEventReceiver::next_event` in `libsigner/src/events.rs` dispatches any POST to `/stackerdb_chunks` straight into `process_event::<T, StackerDBChunksEvent>(request)` with no authentication check (no token/password comparison, no peer allow‑list) on this inbound HTTP path: [1](#0-0) 

`process_event` merely deserializes the JSON body into a `StackerDBChunksEvent` and hands it to `TryFrom<StackerDBChunksEvent> for SignerEvent<T>`: [2](#0-1) 

In that `TryFrom` implementation, the code branches on `event.contract_id`:
- For the **signers-XXX-YYY** contract, each chunk's signature is recovered via `chunk.recover_pk()` and the resulting `StacksPublicKey` is attached to the message, which downstream code checks against the known signer set (`is_valid_signer`) before acting on it.
- For the **miners** contract (`contract_id.name.as_str() == MINERS_NAME`), chunks are deserialized directly with **no signature recovery, no owner check, nothing** - they are pushed straight into `SignerEvent::MinerMessages`: [3](#0-2) 

This breaks the equality that should hold throughout this codebase for StackerDB data: "a chunk is only accepted/acted upon if its `SlotMetadata`/`StackerDBChunkData` signature recovers to the slot's registered owner." That equality is enforced everywhere else in this repo — e.g. `StackerDBs::try_replace_chunk` and `PeerNetwork::validate_received_chunk` explicitly call `slot_desc.verify(&slot_validation.signer)` / `slot_metadata.verify(&addr)` before storing or accepting a chunk: [4](#0-3) [5](#0-4) 

But the signer's local event-ingestion path for `MinerMessages` has no equivalent check, and — critically — this path is fed by an HTTP listener with no authentication gate, contrary to the intended trust model documented in `docs/signing.md`, which states the `auth_token`/`auth_password` pair "must match" between node and signer: [6](#0-5) 
That `auth_token`/`auth_password` pair is only used for the node's `/v3/block_proposal` RPC (signer → node direction); it is never checked by `SignerEventReceiver` on the node → signer event push direction, and the sample signer config binds the receiver to `0.0.0.0`: [7](#0-6) 

### Impact Explanation
Any remote, unprivileged party with network access to the signer's event-receiver port can POST a crafted `StackerDBChunksEvent` for the miners' boot contract and have it accepted as genuine `MinerMessages`, with zero cryptographic verification that the data actually came from the winning miner (or from the node at all). This is a direct analog of the "security policy bypassed"/"unauthenticated write accepted as authentic" bug class in the reported advisory: an auth gate (the `auth_token`, and implicitly "only the node may push StackerDB events") that fails open for this specific message path, letting forged data be relayed into the signer's runloop as if it were validated StackerDB state. Depending on how `MinerMessages` are consumed by the signer's runloop, this can feed spoofed miner activity data into signing decisions.

### Likelihood Explanation
High, if the signer's `endpoint` is bound to a non-loopback address, which the shipped sample configs (`mainnet-signer-conf.toml`) explicitly recommend (`endpoint = "0.0.0.0:30000"`). No credentials, keys, or prior handshake are required — a single crafted HTTP POST suffices.

### Recommendation
- Require and verify the `auth_token`/`auth_password` (or an equivalent shared secret / mTLS) on every inbound request to the `SignerEventReceiver`'s HTTP server, not just for the node's outbound RPC calls.
- For the `MinerMessages` branch in `TryFrom<StackerDBChunksEvent> for SignerEvent<T>`, apply the same signature-recovery and slot-ownership validation used for the signer-message branch (`chunk.recover_pk()` plus a check that the recovered key matches the expected miner/slot owner) before constructing `SignerEvent::MinerMessages`.
- Document/enforce that the signer's event-receiver endpoint should default to loopback-only unless explicitly overridden, and warn operators against binding it to `0.0.0.0` without additional network-level protections.

2. From a remote host, send:
```

Host: <signer-ip>:30000
Content-Type: application/json
Content-Length: <n>

{"contract_id": {"issuer": ["boot","addr-version"], "name": "miners"}, "modified_slots": [{"slot_id":0,"slot_version":1,"sig":"00...","data":"<attacker-controlled bytes>"}]}
```

3. Observe that `next_event()` accepts the POST without any auth check, `process_event` deserializes it, and because the contract matches `MINERS_NAME`, `TryFrom<StackerDBChunksEvent>` deserializes `data` into `SignerEvent::MinerMessages` with no signature verification, regardless of the (empty/invalid) `sig` field's validity — confirmed by the code paths cited in `libsigner/src/events.rs` lines 413-458 and 544-567.

```rust
    fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
