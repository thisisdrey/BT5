### Title
Unauthenticated `RecvError` packet lets an off-path attacker with no CA-signed certificate reset/tear down an established tunnel - (File: outside.go)

### Summary
Nebula processes `header.RecvError` packets before any decryption, certificate check, or handshake, based solely on the plaintext `RemoteIndex` field and a source-address comparison. An attacker who has never completed a handshake and holds no CA-signed certificate can forge such a packet to force `closeTunnel`/`DeleteHostInfo` on a victim's active session, mirroring the reported `StakedExa` bug class where a low-cost, attacker-controlled action resets time/state belonging to another party and destroys accumulated progress (there: `avgStart`/rewards; here: an established, authenticated tunnel and its roaming/connection-manager state).

### Finding Description
`readOutsidePackets` dispatches unencrypted packet types, including `RecvError`, before the packet is authenticated by AEAD decryption: [1](#0-0) 

`handleRecvError` then looks up the hostinfo purely from the plaintext `RemoteIndex` (a 32-bit value carried unencrypted in every header) and only checks that the packet's source address equals the hostinfo's currently known remote address: [2](#0-1) 

There is no cryptographic proof that the sender: (a) ever completed a handshake, (b) holds a CA-signed certificate, or (c) is the actual peer at that UDP address. The only gate is `f.acceptRecvErrorConfig.ShouldRecvError(addr)` (rate/allow-listing) and the `hr != addr` equality check, both trivially satisfiable by UDP source spoofing since UDP has no source-address authentication and the comparison is on a value (`addr`) supplied by the packet's transport layer, not by any signed content. The log line itself acknowledges the gap: `"Someone spoofing recv_errors?"`.

This is directly analogous to the `StakedExa::_update()` issue: in both cases, an actor who need not hold the "privileged" credential (a CA cert in Nebula; being the affected staker in `StakedExa`) can perform a cheap, externally-triggerable action targeting another party's identifier (VPN index / `to` address) that resets or destroys that party's accumulated state (`avgStart` / an established, roamed, connection-tracked tunnel), forcing the victim to restart from scratch (re-handshake / re-stake) and lose whatever benefit had accrued (uninterrupted tunnel, `RoamingSuppressSeconds` state, connection-manager liveness tracking / reward vesting).

### Impact Explanation
A successful forged `RecvError` immediately calls `f.closeTunnel(hostinfo)` and `hm.DeleteHostInfo(hostinfo)`, tearing down the victim's established, authenticated tunnel: [3](#0-2) 
This is a remote state-poisoning/denial-of-service primitive that requires no certificate, no successful handshake, and no possession of any Nebula CA material — only observation or guessing of the plaintext `RemoteIndex` and the ability to spoof the victim's known remote UDP source address. Repeated abuse can be used to indefinitely disrupt tunnels between legitimate, properly certificated peers, analogous to indefinitely "resetting" a victim so they never accumulate the benefit of an established session (paralleling the `avgStart` reset that perpetually zeroes rewards).

### Likelihood Explanation
`RemoteIndex` is sent in cleartext on every packet header (both directions), so anyone able to observe traffic between the peers (on-path, shared network segment, or with visibility into the UDP flow) obtains the needed index without breaking any cryptography. UDP source-address spoofing to match `hr` is a standard low-effort technique when the attacker is not purely blind. `ShouldRecvError`/`acceptRecvErrorConfig` provide only rate-limiting/allow-list style gating (in `interface.go`), not authentication, so the core lack of cryptographic binding remains the root cause.

### Recommendation
Do not honor `RecvError` (or any control signal that tears down/mutates hostinfo state) unless it is delivered inside the authenticated tunnel (i.e., decrypted with the session's AEAD key) or otherwise cryptographically bound to the session, rather than trusting a plaintext index plus a spoofable source-address comparison. At minimum, require a matching random nonce/challenge established during the handshake and carried only over the encrypted channel before acting on `RecvError`.

### Proof of Concept
1. Establish (or observe) a legitimate tunnel between host `A` (victim) and host `B`, noting `B`'s `RemoteIndex` value from the cleartext Nebula header of any packet A sends to B (or vice versa) — no cert or key material is needed to read this.
2. From attacker host `E` (no CA-signed certificate, no completed handshake with `A`), craft a UDP packet with header `Type = header.RecvError`, `RemoteIndex` set to the observed value, and source address spoofed to match `A`'s current remote address as known to `B` (`hostinfo.GetRemote()`).
3. Send the crafted packet to `B`.
4. `B` executes `handleRecvError`: `f.acceptRecvErrorConfig.ShouldRecvError(addr)` passes (default allow), `hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)` resolves to the real tunnel, `hr == addr` (spoofed) passes, and `B` calls `closeTunnel(hostinfo)` + `DeleteHostInfo(hostinfo)`, destroying the established session without any certificate or handshake from `E`.

Note: I was not able to fully inspect `interface.go`'s `acceptRecvErrorConfig`/`ShouldRecvError` implementation details (default policy, rate limiting specifics) or the exact randomness/space of `generateIndex()` within the available indexing window before this session ended; a full engagement with the repository would be needed to confirm default enablement and precisely quantify index-guessing difficulty.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
