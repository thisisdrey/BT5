Based on the investigation, the closest reachable analog to the C4 finding ("attacker constructs data that satisfies only a shallow, insufficient check to produce an unauthorized effect") in this Nebula codebase is the unauthenticated `RecvError` handling path.

### Title
Unauthenticated `RecvError` packets can tear down established tunnels via a spoofable source-address check - (`outside.go`)

### Summary
`header.RecvError` packets are processed by `Interface.handleRecvError` *before* any certificate, handshake, or AEAD verification occurs — this packet type is dispatched straight from `readOutsidePackets` alongside `header.Handshake`, i.e. from an attacker who has never presented a CA-signed certificate. The only gate against forgery is a comparison of the UDP source `netip.AddrPort` against the hostinfo's last-known remote address, which is not cryptographically bound to anything and can be spoofed over UDP.

### Finding Description
In `outside.go`, `RecvError` is handled in the unencrypted/pre-authentication branch of `readOutsidePackets`, alongside `Handshake`: [1](#0-0) 

`handleRecvError` looks up the hostinfo purely from the attacker-supplied `h.RemoteIndex` field (via `QueryReverseIndex`) and then performs a single, coarse check — that the packet's source `AddrPort` equals the hostinfo's currently known remote address — before tearing the tunnel down and deleting the pending handshake state: [2](#0-1) 

This mirrors the structure of the original finding: a security-relevant action (there: an arbitrary swap; here: destructive tunnel teardown / state poisoning) is gated by a check that is *necessary but not sufficient* to prove the request is legitimate. Just as the liquidator only needed to satisfy "amountReceived is enough to repay," an attacker here only needs to satisfy "source address matches the last known remote address" — a value that is not authenticated in any way (UDP has no source-address integrity) and is often observable on-path or via the lighthouse discovery protocol. No CA-signed certificate, handshake, or symmetric key is required to reach or satisfy this check.

`RemoteIndex` itself is generated by `generateIndex` and is a 32-bit value; while not trivially guessable at scale, any attacker able to observe a single legitimate packet (on-path, e.g. wifi, ISP, or misrouted traffic) or brute-force across active tunnels can learn/guess a valid `(RemoteIndex, RemoteAddr)` pair and forge this control packet without ever completing (or being capable of completing) the mutually-authenticated Noise handshake.

### Impact Explanation
An unauthenticated attacker can force termination of any legitimate, already-established Nebula tunnel between two valid peers by forging a single unencrypted `RecvError` packet with a guessed/observed `RemoteIndex` and a spoofed source `AddrPort`. This is a remote state-poisoning / denial-of-service primitive against the control plane: `f.closeTunnel(hostinfo)` and `f.handshakeManager.DeleteHostInfo(hostinfo)` are both invoked, forcing the pair to renegotiate. Repeated forgery can be used to continuously disrupt tunnels.

### Likelihood Explanation
The codebase already acknowledges this attack surface exists — `acceptRecvErrorConfig` supports `never`/`private`/`always` modes specifically to bound exposure to this packet type (`interface.go:459-480`, `CHANGELOG.md:130,190`), and the CHANGELOG documents disabling `recv_error` sends outside the replay window as a related mitigation. This confirms the packet type is treated as inherently spoofable/untrusted by design, but the default configuration (`recvErrorAlways`) still accepts it from any source, so the weak address-match check is the only defense in the default configuration.

### Recommendation
Do not accept teardown-triggering signals from unauthenticated, unencrypted packets. At minimum, require the `RecvError` acknowledgment to be authenticated (e.g., bound to a recent AEAD-protected message the responder actually sent, or gated by a cryptographic proof tied to the connection's negotiated keys) rather than relying solely on a spoofable source `AddrPort` match against `hostinfo.GetRemote()`.

### Proof of Concept
1. Observe or infer a legitimate tunnel's `(RemoteIndex, RemoteAddr)` pair for hosts A and B (e.g., by passively observing UDP traffic on a shared network segment, or via lighthouse-advertised addresses).
2. Without possessing any CA-signed certificate or completing a handshake, craft a UDP packet with `header.RecvError` type and the observed `RemoteIndex`, spoofing the source address to equal B's known remote `AddrPort`, and send it to A.
3. `readOutsidePackets` dispatches it directly to `handleRecvError` without any decryption or cert check.
4. `QueryReverseIndex` finds A's hostinfo for the tunnel to B; the `hr != addr` check passes because the spoofed source matches.
5. A calls `f.closeTunnel(hostinfo)` and deletes the pending handshake state, tearing down the legitimate tunnel — achieved purely by an attacker holding no valid Nebula certificate.

func (f *Interface) handleRecvError(addr netip.AddrPort, h *header.H) {
	if !f.acceptRecvErrorConfig.ShouldRecvError(addr) {
		f.l.Debug("Recv error received, ignoring",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
		return
	}

	if f.l.Enabled(context.Background(), slog.LevelDebug) {
		f.l.Debug("Recv error received",
			"index", h.RemoteIndex,
			"udpAddr", addr,
		)
	}

	hostinfo := f.hostMap.QueryReverseIndex(h.RemoteIndex)
	if hostinfo == nil {
		f.l.Debug("Did not find remote index in main hostmap", "remoteIndex", h.RemoteIndex)
		return
	}

	hr := hostinfo.GetRemote()
	if hr.IsValid() && hr != addr {
		f.l.Info("Someone spoofing recv_errors?",
			"addr", addr,
			"hostinfoRemote", hr,
		)
		return
	}

	f.closeTunnel(hostinfo)
	// We also delete it from pending hostmap to allow for fast reconnect.
	f.handshakeManager.DeleteHostInfo(hostinfo)
}
