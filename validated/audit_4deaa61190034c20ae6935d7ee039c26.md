### Title
Unauthenticated key-rotation via `Handshake` on an already-keyed outbound connection persists an unproven public key into PeerDB - (File: `stackslib/src/net/chat.rs`)

### Summary
`ConversationP2P::validate_handshake` only calls `message.verify_secp256k1(...)` when the conversation does **not yet** know a public key for the peer; when a key is already known (`Some(cur_pubk)` branch), it performs **no signature check at all** — only an address/port sanity check for outbound sockets. Combined with `handle_handshake`'s re-keying block (`if updated && self.stats.outbound { ... Neighbor::load_and_update(...); neighbor.save_update(&tx, None)?; }`), an already-connected outbound peer can push an arbitrary new `node_public_key` that gets persisted into the PeerDB frontier with no proof that the old key authorized the rotation.

### Finding Description
`validate_handshake` (`stackslib/src/net/chat.rs:1047-1092`) branches on `self.connection.get_public_key()`:
- `None` branch: verifies the message was signed by the *new* key declared in the handshake payload (self-certifying, correct for first contact) — `message.verify_secp256k1(&handshake_data.node_public_key)` at line 1063.
- `Some(_)` branch (lines 1072-1091): only checks that, for outbound sockets, the reported `addrbytes`/`port` match the socket peer — **there is no call to `verify_secp256k1` or any other signature/continuity check here**, despite the function's doc comment claiming "A handshake will only be accepted if we do not yet know the public key of this remote peer, or if it is signed by the current public key" (lines 1210-1211).

`handle_handshake` (`stackslib/src/net/chat.rs:1214-1296`) calls `validate_handshake`, then `update_from_handshake_data` (`chat.rs:1131-1167`), which unconditionally does `self.connection.set_public_key(Some(pubk.clone()))` (line 1164) whenever the embedded key differs from the currently known one, setting `updated = true` with no check that the old key co-signed the change. If `updated && self.stats.outbound`, the code persists this to disk:
```
stackslib/src/net/chat.rs:1275-1295
let (mut neighbor, _) = Neighbor::load_and_update(&tx, ..., &handshake_data)?;
neighbor.save_update(&tx, None)?;
tx.commit()...
```
`Neighbor::load_and_update`/`handshake_update` (`chat.rs:435-516`) simply overwrite `self.public_key = pubk` from the wire data with no cryptographic continuity requirement either.

Reachability: for the `Handshake` message type, `handle_unauthenticated_control_message` (`chat.rs:2617-2624`) dispatches to `handle_handshake` unconditionally regardless of any "solicited" state — there is no gate requiring the message to correspond to an outstanding request or to be signed by the previously trusted key. Since the connection already has `cur_pubk = Some(...)` from the original TOFU handshake, `validate_handshake` takes the no-signature-check branch, so the message needs no valid signature at all (not even self-certified by the new key) to reach the re-key/persist block. Note on the question's exact wiring: the question describes the call chain as `handle_handshake_accept -> update_from_handshake_data -> Neighbor::load_and_update/save_update`. In the actual code, `handle_handshake_accept` (`chat.rs:1338-1391`) only calls `update_from_handshake_data` and updates the in-memory `ConversationP2P` state — it never touches `PeerDB` (no `Neighbor::load_and_update`/`save_update` calls there). The DB-persisting re-key block is in `handle_handshake` (triggered by a `Handshake` message, not a `HandshakeAccept`), gated on `self.stats.outbound`. The underlying fault — accepting a new public key with no proof the old key authorized it — is real and reachable under the exact precondition stated (`convo.stats.outbound == true`, attacker is the party the victim dialed), just via an inbound `Handshake` message on the established outbound connection rather than via a `HandshakeAccept`.

### Impact Explanation
An attacker who is the listening side of a victim's outbound connection can send a plain `Handshake` message carrying any `node_public_key` they choose. Because `validate_handshake`'s already-known-key branch performs no signature verification, this message is accepted, `updated` becomes `true`, and since `self.stats.outbound` is true for this connection, the victim writes the attacker-chosen key into its `PeerDB` for that neighbor (`Neighbor::load_and_update` + `save_update`). This corrupts the victim's on-disk frontier/identity record for a previously-known peer with no continuity proof, is repeatable per session, and matches the Critical category "unauthenticated/unauthorized write to state."

### Likelihood Explanation
Preconditions are modest and attacker-controllable: any peer that a victim dials out to (`stats.outbound == true`) and that completes an initial (TOFU) handshake can later send a follow-up `Handshake` message with a different key. No secret, admin role, or privileged access is required — this is exactly the unprivileged "own peer, gossip messages" actor described. The cost is a single crafted, cheaply constructed message on an already-open P2P socket.

### Recommendation
In `validate_handshake`'s `Some(cur_pubk)` branch, require the incoming `Handshake` message to be verified against the *currently known* public key (`message.verify_secp256k1(&cur_pubk)` or equivalent) before allowing any key rotation, and additionally require the new key to be co-signed/authorized by the old key (e.g., a rotation certificate signed by `cur_pubk`) rather than trusting a bare claim in `handshake_data.node_public_key`.

    fn validate_handshake(
        &mut self,
        local_peer: &LocalPeer,
        chain_view: &BurnchainView,
        message: &mut StacksMessage,
    ) -> Result<(), net_error> {
        let handshake_data = match message.payload {
            StacksMessageType::Handshake(ref mut data) => data.clone(),
            _ => panic!("Message is not a handshake"),
        };

        match self.connection.get_public_key() {
            None => {
                // if we don't yet have a public key for this node, verify the message.
                // if it's improperly signed, it's probably a poorly-timed re-key request (but either way the message should be rejected)
                message
                    .verify_secp256k1(&handshake_data.node_public_key)
                    .map_err(|_e| {
                        debug!(
                            "{:?}: invalid handshake: not signed with given public key",
                            &self
                        );
                        net_error::InvalidMessage
                    })?;
            }
            Some(_) => {
                // for outbound connections, the self-reported address must match socket address if we already have a public key.
                // (not the case for inbound connections, since the peer socket address we see may
                // not be the same as the address the remote peer thinks it has).
                // The only exception to this is if the remote peer does not yet know its own
                // public IP address, in which case, its handshake addrbytes will be the
                // any-network bind address (0.0.0.0 or ::)
                if self.stats.outbound
                    && (!handshake_data.addrbytes.is_anynet()
                        && (self.peer_addrbytes != handshake_data.addrbytes
                            || self.peer_port != handshake_data.port))
                {
                    // wrong peer address
                    debug!(
                        "{:?}: invalid handshake -- wrong addr/port ({:?}:{:?})",
                        &self, &handshake_data.addrbytes, handshake_data.port
                    );
                    return Err(net_error::InvalidHandshake);
                }
            }
        };

    pub fn update_from_handshake_data(
        &mut self,
        preamble: &Preamble,
        handshake_data: &HandshakeData,
    ) -> Result<bool, net_error> {
        let pubk = handshake_data
            .node_public_key
            .to_public_key()
            .map_err(|e| net_error::DeserializeError(e.into()))?;

        self.peer_version = preamble.peer_version;
        self.peer_network_id = preamble.network_id;
        self.peer_services = handshake_data.services;
        self.peer_expire_block_height = handshake_data.expire_block_height;
        self.handshake_addrbytes = handshake_data.addrbytes.clone();
        self.handshake_port = handshake_data.port;
        self.data_url = handshake_data.data_url.clone();

        let mut updated = false;
        let cur_pubk_opt = self.connection.get_public_key();
        if let Some(cur_pubk) = cur_pubk_opt {
            if pubk != cur_pubk {
                debug!(
                    "{:?}: Upgrade key {:?} to {:?} expires {:?}",
                    &self,
                    &to_hex(&cur_pubk.to_bytes_compressed()),
                    &to_hex(&pubk.to_bytes_compressed()),
                    self.peer_expire_block_height
                );
                updated = true;
            }
        }

        self.connection.set_public_key(Some(pubk.clone()));

        Ok(updated)
    }
