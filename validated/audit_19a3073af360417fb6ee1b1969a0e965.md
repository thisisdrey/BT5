### Title
StackerDB chunk signature does not bind to the contract/"realm" it is posted to, enabling cross-StackerDB (cross-context) replay of validly signed chunks - (File: `libstackerdb/src/libstackerdb.rs`)

### Summary
`SlotMetadata::auth_digest`, which is the only content actually authenticated by a StackerDB chunk's signature, commits solely to `slot_id`, `slot_version`, and `data_hash` [1](#0-0) . It never includes the `smart_contract_id` ("StackerDB name"/realm) that the chunk is destined for. `PeerNetwork::validate_received_chunk` and the HTTP POST-chunk path only use the `smart_contract_id` to *look up* the expected signer address via `get_slot_signer`, then hand the digest-only signature to `SlotMetadata::verify` [2](#0-1) . Because the contract identity never enters the signed material, a signature that is valid for slot X in StackerDB contract A is equally valid for slot X in StackerDB contract B whenever the same address is registered as the owner of slot X in both contracts — exactly the "issuer not checked against configured realm" bug class from the report, applied to StackerDB's slot-owner authentication instead of a JWT issuer claim.

### Finding Description
1. The digest that is actually signed/verified never encodes which contract (StackerDB) the chunk belongs to: [3](#0-2) 

2. `validate_received_chunk` (used both for pulled chunks in sync and for unsolicited pushed chunks) resolves the expected signer purely from `smart_contract_id` + `slot_id`, then calls `slot_metadata.verify(&addr)`, which — per the code above — checks nothing about which contract the metadata was intended for: [4](#0-3) 

3. The same fault exists on the direct write path: `RPCPostStackerDBChunkRequestHandler::try_handle_request` passes the client-supplied `contract_identifier` to `try_replace_chunk`, which stores the chunk if `SlotMetadata::verify` succeeds against that contract's registered signer — again never checking that the signature itself was scoped to that contract: [5](#0-4) 

4. Signer-slot ownership is frequently *identical* across multiple distinct StackerDB contracts in the actual boot code: for a given signer set (`0` or `1`), the exact same `{signer, slot}` assignment list (`stackerdb-signer-slots-0` / `stackerdb-signer-slots-1`) is shared by every per-message-type StackerDB contract (`signers-0-1`, `signers-0-2`, `signers-0-3`, …, one per `MessageSlotID`): [6](#0-5) [7](#0-6) 
and each contract is instantiated as `signers-{set}-{message_id}` sharing that page's slot list: [8](#0-7) [9](#0-8) 

Consequently, the same signer address `S` owns slot `N` in the `BlockResponse` StackerDB (`signers-0-1`), the `StateMachineUpdate` StackerDB (`signers-0-2`), and the `BlockPreCommit` StackerDB (`signers-0-3`) simultaneously [10](#0-9) . Since the signature covers only `(slot_id, slot_version, data_hash)` — never the contract — a chunk that `S` validly signed and posted to one message-type StackerDB is *also* a validly-signed chunk for the same slot in every other message-type StackerDB for that signer set, as long as `slot_version`/`max_writes`/staleness constraints happen to be satisfiable there too (fully attacker-influenced, since the attacker chooses which already-observed valid chunk to replay and where).

An unprivileged, unauthenticated remote party — anyone who can read a chunk from one of these public, unauthenticated StackerDB replicas (chunk reads require no auth) or observe it over the p2p gossip/push path — can therefore submit that byte-identical chunk+signature into a *different* message-type StackerDB slot and have it accepted as validly signed and written to state, without ever holding `S`'s private key. This breaks the "authenticated vs. intended context" equality that the report's analog is about: the signature (like the JWT) is valid, but it is accepted outside the scope (contract/"realm") it was actually authorized for.

### Impact Explanation
This yields an **unauthorized write to StackerDB state**: an attacker can inject a chunk into a StackerDB slot/contract other than the one its legitimate signer intended, without needing that signer's key, the node's secret, or any privileged role — only a copy of a validly-signed chunk that is already public/observable. Depending on how consumers of a given message-type StackerDB parse the raw bytes (e.g., signer runloop consuming `signers-0-2` StateMachineUpdate data that is actually a replayed `BlockResponse`/`BlockPreCommit` payload), this can corrupt or desynchronize the signer network's shared state for slots that downstream logic assumes are scoped per-message-type, satisfying the "unauthenticated/unauthorized write to state or StackerDB" Critical-impact category in the rules.

### Likelihood Explanation
High feasibility: no cryptographic material is needed beyond a chunk that is already publicly readable (StackerDB reads are unauthenticated) or observable over gossip; the attacker just re-POSTs it (or replays it via the p2p push path) against a different contract ID for which the same address happens to own the same slot — which, per the shared `signers-0/1` slot-assignment logic, is the normal, expected situation for every signer across all of that signer-set's message-type StackerDBs. No race condition or privileged access is required; only version/max-writes bookkeeping in the target slot must currently permit the replayed version, which an attacker can influence by choosing which historical valid chunk to replay.

### Recommendation
Bind the signed digest to the destination context, not just the slot metadata: include the `smart_contract_id` (and ideally a network/chain identifier) inside `SlotMetadata::auth_digest` in `libstackerdb/src/libstackerdb.rs`, and thread the contract identifier through `sign()`/`verify()` calls in `libstackerdb.rs`, `stackslib/src/net/stackerdb/mod.rs::validate_received_chunk`, and `stackslib/src/net/stackerdb/db.rs::try_replace_chunk`, so that a signature is cryptographically scoped to one specific StackerDB contract and cannot be replayed into another.

### Proof of Concept
1. Let signer address `S` (private key held by a legitimate signer) own slot `N` in both `signers-0-1` (BlockResponse) and `signers-0-2` (StateMachineUpdate) — the default configuration per `signers.clar`'s shared `stackerdb-signer-slots-0` list.
2. `S` legitimately posts and signs a `BlockResponse` chunk to `signers-0-1`, slot `N`, version `V`, yielding `(slot_id=N, slot_version=V, data_hash=H, sig)` where `sig` only commits to `(N, V, H)` per `SlotMetadata::auth_digest`.
3. An unprivileged attacker reads this chunk from any public replica (unauthenticated `GET` chunk endpoint) or observes it on the p2p wire.
4. The attacker issues `POST .../v2/stackerdb/{signers-0-2 contract}/chunks` with the identical `slot_id=N`, `slot_version=V'` (≥ current version in `signers-0-2`), the same `data`/`data_hash=H`, and the same `sig`.
5. `RPCPostStackerDBChunkRequestHandler` resolves the expected signer for `signers-0-2` slot `N` to `S` (same address, per shared slot list), calls `SlotMetadata::verify(&S_addr)`, which succeeds because the digest never referenced `signers-0-1` vs `signers-0-2`, and `try_replace_chunk` stores the chunk into `signers-0-2` — a write `S` never authorized for that contract.

    /// Get the digest to sign that authenticates this chunk data and metadata
    fn auth_digest(&self) -> Sha512Trunc256Sum {
        let mut hasher = Sha512_256::new();
        hasher.update(self.slot_id.to_be_bytes());
        hasher.update(self.slot_version.to_be_bytes());
        hasher.update(self.data_hash.0);
        Sha512Trunc256Sum::from_hasher(hasher)
    }

    /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

    pub fn validate_received_chunk(
        &self,
        smart_contract_id: &QualifiedContractIdentifier,
        config: &StackerDBConfig,
        data: &StackerDBChunkData,
        expected_versions: &[u32],
    ) -> Result<bool, net_error> {
        // validate -- must not exceed this replica's configured chunk size.
        if (data.data.len() as u64) > config.chunk_size {
            info!(
                "Received StackerDBChunk for {} ID {}, which is oversized: {} bytes (max {} bytes)",
                smart_contract_id,
                data.slot_id,
                data.data.len(),
                config.chunk_size
            );
            return Ok(false);
        }

        // validate -- must be a valid chunk
        let Some(expected_version) = expected_versions.get(data.slot_id as usize) else {
            info!(
                "Received StackerDBChunk for {} ID {}, which is too big ({})",
                smart_contract_id,
                data.slot_id,
                expected_versions.len()
            );
            return Ok(false);
        };

        // validate -- must be signed by the expected author
        let addr = match self
            .stackerdbs
            .get_slot_signer(smart_contract_id, data.slot_id)?
        {
            Some(addr) => addr,
            None => {
                return Ok(false);
            }
        };

        let slot_metadata = data.get_slot_metadata();
        if !slot_metadata.verify(&addr)? {
            info!(
                "StackerDBChunk for {} ID {} is not signed by {}",
                smart_contract_id, data.slot_id, &addr
            );
            return Ok(false);
        }
