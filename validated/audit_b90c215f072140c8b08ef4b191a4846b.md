### Title
Push-Payment DoS in `vesting::distribute` — Any Shareholder Can Permanently Block All Distributions - (File: `aptos-move/framework/aptos-framework/sources/vesting.move`)

---

### Summary

`vesting::distribute` uses a push-payment loop that calls `aptos_account::deposit_coins` for every shareholder in a single atomic transaction. If any single recipient causes `deposit_coins` to abort — by opting out of direct coin transfers while lacking a registered `CoinStore<AptosCoin>` — the entire transaction reverts. Every other shareholder is blocked from receiving their vested APT, and the admin's `terminate_vesting_contract` call (which internally calls `distribute`) is also permanently wedged.

---

### Finding Description

`vesting::distribute` iterates over all shareholders in the vesting contract's `grant_pool` and pushes coins to each recipient in a single atomic loop: [1](#0-0) 

Each iteration calls `aptos_account::deposit_coins(recipient_address, share_of_coins)`: [2](#0-1) 

Inside `deposit_coins`, if the recipient account exists but has **not** registered a `CoinStore<AptosCoin>` (only a primary fungible store, which is the post-FA-migration default), the function checks `can_receive_direct_coin_transfers`: [3](#0-2) 

`can_receive_direct_coin_transfers` returns `false` when the account has explicitly called `set_allow_direct_coin_transfers(false)`: [4](#0-3) 

This causes `deposit_coins` to abort with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`, reverting the entire `distribute` transaction. All other shareholders receive nothing.

Additionally, `terminate_vesting_contract` calls `distribute` internally before terminating: [5](#0-4) 

If `distribute` reverts, `terminate_vesting_contract` also reverts, permanently blocking the admin from terminating the contract.

The same pattern exists in `staking_contract::distribute_internal`, which also iterates over all distribution pool recipients and calls `aptos_account::deposit_coins` for each: [6](#0-5) 

The formal verifier explicitly acknowledges it cannot reason about aborts in this loop: [7](#0-6) 

---

### Impact Explanation

**Affected functions (all `public entry`):**
- `vesting::distribute` — callable by anyone
- `vesting::distribute_many` — callable by anyone
- `vesting::terminate_vesting_contract` — callable by admin

A single shareholder (or their assigned beneficiary) can block all distributions to all other shareholders by calling `set_allow_direct_coin_transfers(false)` on their account, provided they have not registered a legacy `CoinStore<AptosCoin>`. This:

1. Prevents all other shareholders from receiving their vested APT.
2. Prevents the admin from terminating the vesting contract (since `terminate_vesting_contract` calls `distribute` first).
3. Locks the vested APT inside the contract until the blocking party reverses their setting.

The `MAXIMUM_SHAREHOLDERS` constant is 30: [8](#0-7) 

With up to 30 shareholders, any one of them can grief the other 29.

---

### Likelihood Explanation

- **Unprivileged trigger**: `set_allow_direct_coin_transfers` is a standard public entry function callable by any account holder. No special role or privilege is required.
- **Post-FA-migration relevance**: Accounts created after the APT fungible asset migration have a primary fungible store but no `CoinStore<AptosCoin>` by default, making `coin::is_account_registered<AptosCoin>` return `false` and activating the `can_receive_direct_coin_transfers` check.
- **Griefing incentive**: A departing or malicious shareholder can block all others from receiving distributions.
- **Termination blocking**: An adversarial shareholder can prevent the admin from ever terminating the contract.

---

### Recommendation

Replace the push-payment loop in `vesting::distribute` with a pull-payment model, analogous to the fix applied to the original PaymentSplitter report:

1. **Add a per-shareholder `claim` entry function** that allows each shareholder to independently withdraw their own share. This eliminates the dependency on all recipients being reachable in a single transaction.
2. **Track claimable balances** per shareholder in the `VestingContract` state, updated when `withdraw_stake` is called.
3. **Remove or guard the push loop** in `distribute` — if a push loop is retained for convenience, wrap each `deposit_coins` call in a way that skips (rather than aborts on) recipients that cannot receive coins, and accumulates unclaimed amounts for later pull-based withdrawal.
4. Apply the same fix to `staking_contract::distribute_internal`. [9](#0-8) 

---

### Proof of Concept

**Setup:**
1. Admin creates a vesting contract with shareholders `[Alice, Bob]`.
2. Bob creates his account post-FA-migration (has primary fungible store, no `CoinStore<AptosCoin>`).
3. Bob calls `aptos_account::set_allow_direct_coin_transfers(false)`.

**Attack:**
4. Time passes; stake unlocks; anyone calls `vesting::distribute(contract_address)`.
5. The loop reaches Bob's entry: `aptos_account::deposit_coins(bob_address, bob_share)`.
6. `coin::is_account_registered<AptosCoin>(bob_address)` → `false` (no `CoinStore`).
7. `can_receive_direct_coin_transfers(bob_address)` → `false` (opted out).
8. Transaction aborts with `EACCOUNT_DOES_NOT_ACCEPT_DIRECT_COIN_TRANSFERS`.
9. Alice receives nothing. The vested APT remains locked in the contract.
10. Admin calls `terminate_vesting_contract` → internally calls `distribute` → same abort → admin cannot terminate. [10](#0-9) [11](#0-10)

    /// Distribute any withdrawable stake from the stake pool.
    public entry fun distribute(contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        let coins = withdraw_stake(vesting_contract, contract_address);
        let total_distribution_amount = coin::value(&coins);
        if (total_distribution_amount == 0) {
            coin::destroy_zero(coins);
            return
        };

        // Distribute coins to all shareholders in the vesting contract.
        let grant_pool = &vesting_contract.grant_pool;
        let shareholders = &grant_pool.shareholders();
        shareholders.for_each_ref(|shareholder| {
            let shareholder = *shareholder;
            let shares = pool_u64::shares(grant_pool, shareholder);
            let amount = pool_u64::shares_to_amount_with_total_coins(grant_pool, shares, total_distribution_amount);
            let share_of_coins = coin::extract(&mut coins, amount);
            let recipient_address = get_beneficiary(vesting_contract, shareholder);
            aptos_account::deposit_coins(recipient_address, share_of_coins);
        });

        // Send any remaining "dust" (leftover due to rounding error) to the withdrawal address.
        if (coin::value(&coins) > 0) {
            aptos_account::deposit_coins(vesting_contract.withdrawal_address, coins);
        } else {
            coin::destroy_zero(coins);
        };

        emit(
            Distribute {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
                amount: total_distribution_amount,
            },
        );
    }

    public entry fun terminate_vesting_contract(admin: &signer, contract_address: address) acquires VestingContract {
        assert_active_vesting_contract(contract_address);

        // Distribute all withdrawable coins, which should have been from previous rewards withdrawal or vest.
        distribute(contract_address);

        let vesting_contract = borrow_global_mut<VestingContract>(contract_address);
        verify_admin(admin, vesting_contract);
        let (active_stake, _, pending_active_stake, _) = stake::get_stake(vesting_contract.staking.pool_address);
        assert!(pending_active_stake == 0, error::invalid_state(EPENDING_STAKE_FOUND));

        // Unlock all remaining active stake.
        vesting_contract.state = VESTING_POOL_TERMINATED;
        vesting_contract.remaining_grant = 0;
        unlock_stake(vesting_contract, active_stake);

        emit(
            Terminate {
                admin: vesting_contract.admin,
                vesting_contract_address: contract_address,
            },
        );
    }
