### Title
`SlotMetadata` signatures omit the StackerDB contract identity, enabling cross-contract chunk replay - ([File: libstackerdb/src/libstackerdb.rs])

### Summary
The signature that authorizes a StackerDB chunk write commits only to `(slot_id, slot_version, data_hash)` and never to the `QualifiedContractIdentifier` (the specific StackerDB/smart contract) the chunk belongs to.

### Finding Description
`SlotMetadata::auth_digest` hashes only `slot_id`, `slot_version`, and `data_hash`: [1](#0-0) 

`sign`/`verify` operate solely over this digest: [2](#0-1) 

The write-path check in `StackerDBTx::try_replace_chunk` resolves the expected signer strictly from `(smart_contract, slot_id)` via `get_slot_validation`, then calls `slot_desc.verify(&slot_validation.signer)`, but the verified digest itself carries no binding to `smart_contract`: [3](#0-2) 

The gossip-received path `StackerDBs::validate_received_chunk` has the identical structure: it looks up the signer for `(smart_contract_id, data.slot_id)`, then verifies the chunk's `SlotMetadata` against that address, again without the digest binding to `smart_contract_id`: [4](#0-3) 

This is directly analogous to the reported bug class: the same signed message (here, `sig` over `(slot_id, slot_version, data_hash)`) is valid proof of authorization for *any* StackerDB contract in which the signer happens to own the same `slot_id`, not just the one it was originally produced for. Because slot assignment across the many boot-contract StackerDBs (the `miners` contract, and multiple `signers-N-M` contracts per reward cycle/message lane) is derived from the same underlying reward-set ordering, the same signer key routinely occupies the *same* `slot_id` across multiple distinct contracts. An attacker who observes a legitimately signed `StackerDBChunkData` from contract A (e.g., via network capture or an inventory download) can resubmit it — unmodified — to contract B if the same address owns the same `slot_id` there and the local replica's version/size checks happen to line up (`slot_version > local`, `data.len() <= chunk_size`). Since `slot_version` is a per-slot Lamport counter that legitimately starts at 0/1 and increments, replay across contracts with coincidentally overlapping counters is a realistic, low-effort occurrence, not a contrived edge case.

### Impact Explanation
This breaks the intended equality "a chunk write is authorized by the owning signer *for this specific StackerDB instance*" into "a chunk write is authorized by the owning signer for *any* StackerDB instance where they hold the same slot index." An attacker can cause a chunk to be written into a StackerDB contract other than the one the signer intended, without the node validating that the signer intended that specific contract — this is an unauthorized/forged write of state into a StackerDB replica and can propagate over the P2P gossip layer to other nodes via `handle_unsolicited_StackerDBPushChunk`/`StackerDBSync`, i.e., network-wide propagation of data the signer never authorized for that contract.

### Likelihood Explanation
Medium: the primary constraint is that the chunk's `slot_version` must be `>` the target replica's currently stored version for that slot, and the chunk size must fit; both are plausible to satisfy opportunistically given how Lamport counters and StackerDB configs are structured, and no cryptographic secret is needed by the attacker — only observation of a previously broadcast, validly-signed chunk.

### Recommendation
Bind the StackerDB contract identity into the signed digest, e.g. add the `QualifiedContractIdentifier` (or a stable numeric contract/DB identifier) as an additional field hashed into `SlotMetadata::auth_digest`:
```rust
fn auth_digest(&self, contract_id: &QualifiedContractIdentifier) -> Sha512Trunc256Sum {
    let mut hasher = Sha512_256::new();
    hasher.update(contract_id.serialize_to_vec());
    hasher.update(self.slot_id.to_be_bytes());
    hasher.update(self.slot_version.to_be_bytes());
    hasher.update(self.data_hash.0);
    Sha512Trunc256Sum::from_hasher(hasher)
}
```
and thread the contract id through `sign`/`verify` call sites (`StackerDBChunkData::sign`/`verify`, `try_replace_chunk`, `validate_received_chunk`).

### Proof of Concept
1. Configure two StackerDB contracts, A and B, such that signer `S` (private key `sk`) owns `slot_id = 3` in both (this naturally occurs, e.g., across `signers-N-M` contracts for the same reward cycle/signer set).
2. Signer `S` legitimately signs and pushes `StackerDBChunkData { slot_id: 3, slot_version: 5, data: D }` to contract A; this is broadcast over gossip and observed by an attacker.
3. Attacker resubmits the identical, unmodified `StackerDBChunkData` (same `slot_id`, `slot_version`, `sig`, `data`) to contract B via `POST /v2/stackerdb/.../chunks` or via unsolicited push.
4. `StackerDBs::validate_received_chunk`/`StackerDBTx::try_replace_chunk` for contract B looks up the signer for `(B, slot_id=3)` — which is also `S` — and calls `slot_metadata.verify(&addr)`; since the digest never included the contract id, verification succeeds and the chunk is accepted/stored/re-gossiped in contract B, even though `S` never authorized writing this data there.     /// Sign this slot metadata, committing to slot_id, slot_version, and
    /// data_hash.  Sets self.signature to the signature.
    /// Fails if the underlying crypto library fails
    pub fn sign(&mut self, privkey: &StacksPrivateKey) -> Result<(), Error> {
        let auth_digest = self.auth_digest();
        let sig = privkey
            .sign(&auth_digest.0)
            .map_err(|se| Error::SigningError(se.to_string()))?;

        self.signature = sig;
        Ok(())
    }

    /// Verify that a given principal signed this chunk metadata.
    /// Note that the address version is ignored.
    pub fn verify(&self, principal: &StacksAddress) -> Result<bool, Error> {
        let sigh = self.auth_digest();
        let pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            sigh.as_bytes(),
            &self.signature,
        )
        .map_err(|ve| Error::VerifyingError(ve.to_string()))?;

        let pubkh = Hash160::from_node_public_key(&pubk);
        Ok(pubkh == *principal.bytes())
    }

        // Check per-replica chunk-size cap.

            return Err(net_error::BadSlotSigner(
                slot_validation.signer,
