### Title
Malformed ZIP/JAR central directory entry causes out-of-bounds read via integer-underflow bypass of bounds check in ijar's `InputZipFile::EnsureRemaining` — (File: `third_party/ijar/zip.cc`)

### Summary
The `ijar` tool, which Bazel automatically runs on every input/dependency jar (including externally-fetched, attacker-influenced jars) to produce interface/header jars via `java_common.run_ijar` and the `JavaToolchain`, contains a ZIP central-directory parser that is overly tolerant of malformed fields. This is directly analogous to the reported MongoDB KMIP-response bug class: an attacker-supplied, well-formed-enough packet is parsed without adequate bounds validation into an object (a cursor/pointer) that is invalid, and a later read through that object causes a read access violation.

### Finding Description
`InputZipFile::ProcessCentralDirEntry` in [1](#0-0)  reads `file_name_length`, `extra_field_length`, `file_comment_length`, and (crucially) a `local_header_offset` ("`offset`") directly from attacker-controlled bytes with **no bounds checking at all** (unlike its sibling `ProcessLocalFileEntry`, which calls `EnsureRemaining` before every variable-length read, see [2](#0-1) ). If the entry is ZIP64, this `offset` field can be replaced by an attacker-controlled 8-byte value read via `get_u8le(extra)` inside the unchecked extra-field loop at [3](#0-2) .

That attacker-controlled `offset` is then used unconditionally to recompute the read cursor in `ProcessNext`: [4](#0-3) 
```
if (!ProcessCentralDirEntry(central_dir_current_, &compressed, &uncompressed,
                            filename, PATH_MAX, &attr, &offset)) {
  return false;
}
p = zipdata_in_ + in_offset_ + offset;
if (EnsureRemaining(4, "signature") < 0) {
  return false;
}
```

The only guard is `EnsureRemaining`, defined at [5](#0-4) :
```
int EnsureRemaining(size_t n, const char *state) {
  size_t in_offset = p - zipdata_in_;
  size_t remaining = input_file_->Length() - in_offset;
  if (n > remaining) {
    return error(...);
  }
  return 0;
}
```
Because `in_offset` and `remaining` are unsigned `size_t`, if the attacker-supplied `offset` pushes `p` past `zipdata_in_ + Length()`, the subtraction `Length() - in_offset` **underflows**, wrapping to a huge unsigned value. The subsequent check `n > remaining` then evaluates false (bounds check silently passes) even though `p` points far outside the mapped file buffer. The code then proceeds to dereference `p` via `get_u4le(p)` and further reads (`ProcessLocalFileEntry`), causing an out-of-bounds/read access violation on invalid memory — the same fundamental failure mode as the MongoDB KMIP parser: a lenient parser converts malformed input into an invalid object (here, an out-of-range pointer) that a subsequent read dereferences unsafely.

### Impact Explanation
This is invoked by the `ijar` binary that Bazel's Java toolchain runs on essentially every compile-time jar dependency (`java_common.run_ijar`, `pack_sources`, etc. — see [6](#0-5)  and [7](#0-6) ). A jar dependency that is fetched from an external/attacker-influenced source (e.g., a Maven artifact or `http_jar`/`http_archive` target whose declared checksum was computed by the attacker over their own crafted archive, which is the normal trust model for a first-observed dependency) can trigger a read access violation/crash in the Bazel-invoked `ijar` process during the build, which is a memory-safety/DoS impact on the build worker process consuming untrusted archive bytes.

### Likelihood Explanation
Exploitation only requires crafting a ZIP/JAR file with a central directory entry whose (optionally ZIP64-extended) local-header offset is large enough to make `zipdata_in_ + in_offset_ + offset` exceed the mapped file's end. No credentials or MITM are needed — the attacker only needs to be the origin of a jar dependency that Bazel's build fetches and then feeds into `ijar`, which happens automatically for ordinary Java build/dependency graphs.

### Recommendation
Add explicit, non-underflowing bounds validation before dereferencing `p` in `ProcessCentralDirEntry` and after computing `p = zipdata_in_ + in_offset_ + offset` in `ProcessNext`: verify `p` lies within `[zipdata_in_, zipdata_in_ + input_file_->Length())` using unsigned-safe comparisons that don't rely on subtraction that can underflow, and reject the central directory entry (and the whole file) with an error rather than continuing to parse. Apply the same `EnsureRemaining`-style checks used in `ProcessLocalFileEntry` to `ProcessCentralDirEntry`'s reads of `file_name_length`, `extra_field_length`, `file_comment_length`, and the ZIP64 extra field loop.

### Proof of Concept
A `BuildIntegrationTestCase`/native C++ unit test (mirroring the existing `MalformedExtraField` singlejar test at [8](#0-7) ) can be constructed for `ijar`:
1. Build a minimal valid ZIP with one entry.
2. Patch its Central Directory Header's `local_header_offset` (and/or inject a ZIP64 extra field with an 8-byte offset) to a value such as `Length() + large_delta` so that `p = zipdata_in_ + in_offset_ + offset` lands outside the mapped buffer.
3. Run `ZipExtractor::Create`/`ProcessAll` (as `third_party/ijar/zip_main.cc`'s `extract()` does) against this file.
4. Observe that `EnsureRemaining` fails to reject the read due to the `size_t` underflow in `Length() - in_offset`, and the subsequent `get_u4le(p)` dereferences out-of-bounds memory, producing a crash (ASan heap-buffer-overflow / SIGSEGV) rather than a controlled `error(...)` return.

bool InputZipFile::ProcessCentralDirEntry(const u1 *&p, u8 *compressed_size,
                                          u8 *uncompressed_size, char *filename,
                                          size_t filename_size, u4 *attr,
                                          u8 *offset) {
  u4 signature = get_u4le(p);

  if (signature != CENTRAL_FILE_HEADER_SIGNATURE) {
    if (signature != DIGITAL_SIGNATURE && signature != EOCD_SIGNATURE &&
        signature != ZIP64_EOCD_SIGNATURE) {
      error("invalid central file header signature: 0x%x\n", signature);
    }
    return false;
  }

  p += 16;  // skip to 'compressed size' field
  *compressed_size = get_u4le(p);
  *uncompressed_size = get_u4le(p);
  u2 file_name_length = get_u2le(p);
  u2 extra_field_length = get_u2le(p);
  u2 file_comment_length = get_u2le(p);
  p += 4;  // skip to external file attributes field
  *attr = get_u4le(p);
  *offset = get_u4le(p);
  {
    size_t len = (file_name_length < filename_size)
      ? file_name_length
      : (filename_size - 1);
    memcpy(reinterpret_cast<void*>(filename), p, len);
    filename[len] = 0;
  }
  p += file_name_length;
  const u1 *extra_p = p;
  p += extra_field_length;
  while (extra_p != p) {
    const u2 header_id = get_u2le(extra_p);
    const u2 data_size = get_u2le(extra_p);
    const u1 *extra = extra_p;
    extra_p += data_size;
    if (header_id == ZIP64_EXTRA_FIELD_TAG) {
      if (*uncompressed_size == U4_MAX) {
        *uncompressed_size = get_u8le(extra);
      }
      if (*compressed_size == U4_MAX) {
        *compressed_size = get_u8le(extra);
      }
      if (*offset == U4_MAX) {
        *offset = get_u8le(extra);
      }
    }
  }
  p += file_comment_length;
  return true;
}

std::string CreateZipWithMalformedExtraField() {
  std::string zip_data;
  const std::string filename = "evil.bin";

  // 1. Local File Header (LFH)
  size_t lh_offset = zip_data.size();
  size_t lh_size = sizeof(LH) + filename.size();
  zip_data.resize(lh_offset + lh_size, 0);
  auto* lh = reinterpret_cast<LH*>(&zip_data[lh_offset]);
  lh->signature();
  lh->version(10);
  lh->file_name(filename.data(), filename.size());

  // 2. Extra field payload containing an oversized payload_size
  uint8_t ef_buffer[8] = {0};
  auto* ef1 = reinterpret_cast<ExtraField*>(ef_buffer);
  ef1->signature(0x000d);
  ef1->payload_size(0);

  auto* ef2 = reinterpret_cast<ExtraField*>(ef_buffer + ef1->size());
  ef2->signature(0xdead);
  ef2->payload_size(0xf000);  // Malformed size exceeding extra field buffer

  // 3. Central Directory Header (CDH)
  size_t cdh_offset = zip_data.size();
  size_t cdh_size = sizeof(CDH) + filename.size() + sizeof(ef_buffer);
  zip_data.resize(cdh_offset + cdh_size, 0);
  auto* cdh = reinterpret_cast<CDH*>(&zip_data[cdh_offset]);
  cdh->signature();
  cdh->version(20);
  cdh->version_to_extract(10);
  cdh->local_header_offset32(lh_offset);
  cdh->file_name(filename.data(), filename.size());
  cdh->extra_fields(ef_buffer, sizeof(ef_buffer));

  // 4. End of Central Directory (EOCD)
  size_t ecd_offset = zip_data.size();
  zip_data.resize(ecd_offset + sizeof(ECD), 0);
  auto* ecd = reinterpret_cast<ECD*>(&zip_data[ecd_offset]);
  ecd->signature();
  ecd->this_disk_entries16(1);
  ecd->total_entries16(1);
  ecd->cen_size32(cdh_size);
  ecd->cen_offset32(cdh_offset);

  return zip_data;
}
