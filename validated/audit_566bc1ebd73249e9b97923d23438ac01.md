Based on the code, this reported issue does not hold up.

**Key mechanism (why the "abort after balance change" scenario can't occur):**

1. In `Contract::deposit` (mint step, called from `mt_on_transfer`), all balance mutations happen *and then* `MtEvent::MtMint(...).check_refund()?.emit()` is called [1](#0-0) . If `check_refund()` fails, `deposit()` returns `Err`, which is `.unwrap_or_else(|err| err.panic())`'d in `mt_on_transfer` [2](#0-1) . A panic in this receipt causes the whole receipt (including the in-memory balance/state mutations) to be discarded by the NEAR runtime — nothing is persisted, so no balance change survives a failed emission at this stage.

2. `check_refund()` doesn't just check the current log size — it explicitly computes the size delta that would result if the memo were later swapped for the fixed `REFUND_MEMO` string, via `refund_log_delta`/`compute_refund_delta` [3](#0-2) . This is precisely designed to pre-validate that the *eventual refund event* (emitted later in `mt_resolve_deposit`) will also fit in the log limit.

3. In `resolve_deposit_internal` (used by `mt_resolve_deposit`), the resulting `MtBurn` refund event is emitted **without** calling `check_refund()` again, with the code comment explicitly stating why: *"No need for `check_refund()` here since this IS the refund. The refund memo size was already accounted for in the original mint."* [4](#0-3) 

4. The refund event's `token_ids`/`amounts` are always a **subset** of the original mint's token_ids/amounts (capped by `deposited` and `balance_left`, `refund_amount = requested_refund.min(*deposited).min(balance_left)`) [5](#0-4) , and the token_id strings themselves are the exact same strings used at mint time (passed through unchanged from `mt_on_transfer` to `mt_resolve_deposit`) [6](#0-5) , which were already bounded by `MAX_TOKEN_ID_LEN` at mint time [7](#0-6) . The refund memo is always the fixed constant `REFUND_MEMO`, never attacker-controlled. So the burn log at resolve time can only be smaller than or equal to what was already validated to fit at mint time — it can never exceed the limit.

5. An attacker's malicious receiver contract can only influence numeric `requested_refund` values (`Vec<U128>`) via the promise result JSON, and these are clamped by `.min(*deposited).min(balance_left)`, so they can't inflate the event beyond what was already accounted for; malformed JSON just falls back to the already-bounded `deposited` amounts [8](#0-7) .

This exact invariant is also covered by dedicated tests validating mint/burn log sizes and gas limits across token counts and token-id lengths [9](#0-8) .

Because the mint-time `check_refund()` provably bounds the size of any later refund/burn emission, and a failed mint-time check reverts the whole receipt (no balance change persists), the claimed divergence — balances changed but event emission aborts — cannot be constructed.

    let Some(m) = memo else {
        return RefundLogDelta {
            overhead: REFUND_EXTRA_BYTES,
            savings: 0,
        };
    };
    RefundLogDelta::new(REFUND_STR_LEN, m.len())
}

impl MtEvent<'_> {
    /// Validates that the event log (including potential refund overhead) fits within limits.
    /// Returns a [`CheckedMtEvent`] that can be emitted.
    pub fn check_refund(self) -> Result<CheckedMtEvent, ErrorLogTooLong> {
        let log = self.to_nep297_event().to_event_log();
        let delta = self.compute_refund_delta();
        let refund_len = log
            .len()
            .saturating_add(delta.overhead())
            .saturating_sub(delta.savings());

        if refund_len > defuse_near_utils::TOTAL_LOG_LENGTH_LIMIT {
            return Err(ErrorLogTooLong);
        }
        Ok(CheckedMtEvent(log))
    }

    fn compute_refund_delta(&self) -> RefundLogDelta {
        match self {
            MtEvent::MtMint(events) => events
                .iter()
                .map(|e| refund_log_delta(e.memo.as_deref()))
                .fold(RefundLogDelta::default(), RefundLogDelta::saturating_add),
            MtEvent::MtBurn(events) => events
                .iter()
                .map(|e| refund_log_delta(e.memo.as_deref()))
                .fold(RefundLogDelta::default(), RefundLogDelta::saturating_add),
            MtEvent::MtTransfer(events) => events
                .iter()
                .map(|e| refund_log_delta(e.memo.as_deref()))
                .fold(RefundLogDelta::default(), RefundLogDelta::saturating_add),
        }
    }

fn validate_mt_event_log_size(
    owner_id: &AccountId,
    token_ids: &[String],
    amounts: &[u128],
) -> anyhow::Result<()> {
    let mt_mint_event = MtEvent::MtMint(Cow::Owned(vec![MtMintEvent {
        owner_id: Cow::Borrowed(owner_id),
        token_ids: Cow::Owned(token_ids.to_vec()),
        amounts: Cow::Borrowed(amounts),
        memo: None,
    }]));

    let mt_burn_event = MtEvent::MtBurn(Cow::Owned(vec![MtBurnEvent {
        owner_id: Cow::Borrowed(owner_id),
        authorized_id: None,
        token_ids: Cow::Owned(token_ids.to_vec()),
        amounts: Cow::Borrowed(amounts),
        memo: Some(Cow::Borrowed(REFUND_MEMO)),
    }]));

    let mint_log = mt_mint_event.to_nep297_event().to_event_log();
    let burn_log = mt_burn_event.to_nep297_event().to_event_log();

        mint_log.len() <= TOTAL_LOG_LENGTH_LIMIT,
        "mint log will exceed maximum log limit"
    );

        burn_log.len() <= TOTAL_LOG_LENGTH_LIMIT,
        "burn log will exceed maximum log limit"
    );
    Ok(())
}
