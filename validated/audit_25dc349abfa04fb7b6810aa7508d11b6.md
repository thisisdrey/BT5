### Title
Priority-floor check parses and cost-computes every packet before sigverify, letting unstaked attackers spend cheap CPU-asymmetric work exactly under saturation - ([File: core/src/sigverify.rs])

### Summary
When the banking-stage scheduler is saturated and publishes a nonzero `SchedulerPriorityFloor`, `SigVerifyWorkerPool::run_transaction_task` calls `apply_priority_floor_to_batch` on every surviving (non-duplicate, non-discarded) packet in a batch, *before* `sigverify::ed25519_verify_serial` runs. `apply_priority_floor_to_batch` calls `calculate_priority_from_bytes`, which fully parses the transaction (`SanitizedTransactionView::try_new_sanitized`), builds a `RuntimeTransaction`, derives its `TransactionConfiguration`, and runs the full `CostModel`/fee-reward computation — none of which requires a valid signature. An unstaked attacker can therefore send structurally well-formed but unsigned/garbage-signed, minimum-fee packets that are cheap to generate but force the leader to pay full parse+cost-model work per packet, specifically during the congestion window when the floor mechanism is meant to shed load cheaply.

### Finding Description
- `SigVerifyWorkerPool::run_transaction_task` (`core/src/sigverify.rs:266-375`) dedups the batch first (`deduper::dedup_packets_and_count_discards`), then, if `state.priority_floor` is `Some` and `floor > 0`, calls `apply_priority_floor_to_batch(&mut batch, floor, &working_bank)` (`core/src/sigverify.rs:302-324`) **before** `sigverify::ed25519_verify_serial` is ever invoked (`core/src/sigverify.rs:326-331`).
- `apply_priority_floor_to_batch` (`core/src/sigverify.rs:413-440`) iterates every non-discarded packet and calls `calculate_priority_from_bytes(bank, data)` on each one that isn't already marked discarded.
- `calculate_priority_from_bytes` (`core/src/transaction_priority.rs:73-88`) does real, non-trivial work per packet: `SanitizedTransactionView::try_new_sanitized`, `RuntimeTransaction::try_new`, `transaction_configuration()`, and `calculate_priority_and_cost` which runs `CostModel::calculate_cost_for_executed_transaction` and `solana_fee::calculate_fee_details` plus a bank fee/reward calculation. None of this validates the transaction's ed25519 signatures — signature verification happens strictly afterward and only for packets that survive the floor filter.
- The only upstream filter is `Deduper` (`perf/src/deduper.rs`), a bloom-filter keyed on raw packet bytes hash. This only catches byte-identical duplicates; an attacker can trivially mutate a single byte (e.g., a garbage signature byte or fee/priority field) per packet to produce unique packets that bypass the dedup filter for negligible cost, while each unique packet still costs the leader a full parse + cost-model computation.
- Because this only triggers when `SchedulerPriorityFloor` is `Some(floor) > 0` — i.e., exactly when the scheduler's retained buffer is already >99% full (`SATURATION_BUFFER_PCT` in `core/src/banking_stage/transaction_scheduler/scheduler_controller.rs:39-44`) — the added per-packet parsing cost lands precisely during congestion, when sigverify worker CPU is the scarcest resource and the floor mechanism is supposed to *reduce* load, not add parsing overhead ahead of the cheap discard path.
- Crucially, the attacker's packets need not carry any real fee-payer balance or valid signature to incur this cost, since neither is checked by `calculate_priority_from_bytes` — only message-decoding validity (compact-array/varint structure, instruction encoding, compute-budget instruction if present) is required. This is disproportionate/underpriced pre-fee work: cheap-to-generate packets force expensive-to-run leader-side parsing and cost-model evaluation with zero chance of ever being included (since they're constructed to fall below the floor or fail sigverify anyway).

### Impact Explanation
This is a CPU-exhaustion / load-amplification issue in the sigverify worker pool, matching Agave's "grossly underpriced pre-fee work" / DoS bounty category. It doesn't cause a crash, panic, or consensus divergence, but it degrades exactly the mitigation (`SchedulerPriorityFloor`) meant to protect the leader from overload, by inserting non-trivial parsing/cost-model work ahead of the cheap `discard()` bit-check for every distinct packet, at a stage where signatures haven't been checked yet.

### Likelihood Explanation
Preconditions are realistic and reachable by an unstaked remote attacker: (1) the network/leader must already be under load such that the scheduler's buffer saturates and publishes a nonzero floor (`SATURATION_BUFFER_PCT = 99`), and (2) the attacker must be able to submit a sustained stream of distinct, minimally-valid-structure packets to the TPU. Both conditions are attacker-influenceable — an attacker (or the ambient congestion itself) can drive saturation, and once saturated, the attacker's own flood of unique low/zero-priority packets is cheap to produce (mutate one byte per packet) via QUIC/UDP to the public TPU port, requiring no stake, valid signature, or funded account. This makes the finding repeatable and independent of a single leader-slot budget.

### Recommendation
Reorder or cheapen the floor check so that expensive parsing happens only after cheap, signature-independent load-shedding: 
1. Perform `ed25519_verify_serial` (or at least a coarse packet-size/format sanity check) before invoking `calculate_priority_from_bytes`, so garbage/invalid-signature packets are discarded at native sigverify cost rather than parsed and cost-modeled.
2. Alternatively, add a lightweight pre-check (e.g., cached/memoized priority extraction, or bounding the number of `calculate_priority_from_bytes` calls per batch/time-window) so the per-packet floor-check cost is bounded independent of how many unique low-priority packets an attacker can generate.
3. Consider extracting priority more cheaply (e.g., directly reading the compute-unit-price instruction bytes without building a full `RuntimeTransaction`/cost-model pass) for the sole purpose of the floor comparison.

### Proof of Concept
```rust
// core/src/sigverify.rs (bench-style test)
//
// Goal: show apply_priority_floor_to_batch's per-packet cost is NOT bounded/independent
// of batch content, and is materially higher than a plain discard-bit check, even when
// every packet is doomed to fail sigverify (e.g. corrupted signature bytes).
#[test]
fn priority_floor_parses_unsigned_garbage_packets_at_full_cost() {
    use std::time::Instant;

    let (bank, mint) = test_bank_with_lamports_per_signature(5_000);

    // Build N structurally-valid, minimum-priority transactions with corrupted
    // signature bytes (so ed25519 verification would fail if it ran first).
    let mut batch = PacketBatch::default();
    for i in 0..10_000 {
        let mut bytes = make_tx_bytes(&mint, bank.last_blockhash(), 1 /* min priority */);
        // Corrupt the signature so it would never pass ed25519_verify_serial.
        bytes[1] ^= 0xFF;
        // Vary a byte so each packet is unique and bypasses the Deduper bloom filter.
        bytes[2] = (i % 256) as u8;
        batch.push(make_packet_from_bytes(&bytes));
    }

    let baseline_start = Instant::now();
    // Baseline: what a "cheap discard" would cost (just flipping discard bits).
    for mut p in batch.iter_mut() {
        p.meta_mut().set_discard(true);
    }
    let baseline_us = baseline_start.elapsed().as_micros();

    // Reset discard bits, then measure the real floor-check cost.
    for mut p in batch.iter_mut() {
        p.meta_mut().set_discard(false);
    }
    let floor = 1_000_000; // above every packet's priority -> all dropped
    let start = Instant::now();
    let (dropped, all_below) = apply_priority_floor_to_batch(&mut batch, floor, &bank);
    let floor_us = start.elapsed().as_micros();

    assert!(all_below);
    assert_eq!(dropped, batch.len());
    // Expect the floor-check path to cost orders of magnitude more per packet
    // than the trivial discard baseline, demonstrating unbounded/disproportionate
    // pre-fee CPU work paid for zero-fee, unsigned, doomed-to-fail packets.
    assert!(
        floor_us > baseline_us * 50,
        "floor check cost {floor_us}us should not be comparable to baseline discard cost {baseline_us}us"
    );
}
```
This demonstrates that `apply_priority_floor_to_batch` (via `calculate_priority_from_bytes`) performs full transaction parsing and cost-model computation on packets that never needed a valid signature to reach that cost, and that this cost scales linearly with attacker-supplied unique garbage packets rather than being bounded independent of batch content — confirming the underpriced pre-fee work described in the question. ```rust
fn apply_priority_floor_to_batch(
    batch: &mut PacketBatch,
    floor: u64,
    bank: &Bank,
) -> (usize, bool) {
    let mut dropped: usize = 0;
    let mut any_kept = false;
    for mut packet in batch.iter_mut() {
        if packet.meta().discard() {
            continue;
        }
        let Some(data) = packet.data(..) else {
            // Zero-length or otherwise unreadable: leave to downstream
            // stages to reject.
            any_kept = true;
            continue;
        };
        // Unparseable packets are kept and left for downstream rejection.
        match calculate_priority_from_bytes(bank, data) {
            Some(priority) if priority <= floor => {
                packet.meta_mut().set_discard(true);
                dropped = dropped.saturating_add(1);
            }
            _ => any_kept = true,
        }
    }
    (dropped, !any_kept)
}

pub(crate) fn calculate_priority_from_bytes(bank: &Bank, data: &[u8]) -> Option<u64> {
    let view = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()).ok()?;
    let runtime_tx = RuntimeTransaction::<SanitizedTransactionView<_>>::try_new(
        view,
        MessageHash::Compute,
        None,
    )
    .ok()?;
    let transaction_configuration = runtime_tx
        .transaction_configuration(&bank.feature_set)
        .ok()?;
    let (priority, _cost) =
        calculate_priority_and_cost(bank, &runtime_tx, &transaction_configuration);

    Some(priority)
}
