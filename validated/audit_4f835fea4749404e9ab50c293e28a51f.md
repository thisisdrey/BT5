Audit Report

## Title
Permanently unrecoverable relayer tip funds via `Tips` storage with no cancel/refund path - (File: bridges/snowbridge/pallets/inbound-queue-v2/src/lib.rs)

## Summary
`pallet-inbound-queue-v2`'s `AddTip::add_tip` accepts a tip for any `nonce` as long as that nonce has not already been consumed, with no check that the nonce corresponds to a real, already-emitted Ethereum event. The tip is stored keyed only by `nonce` in `Tips<T>` and is only ever released inside `process_message` when that exact nonce is later submitted and processed; there is no extrinsic, expiry, or refund path to recover it otherwise. Because the underlying value is actually burned before the tip is registered (confirmed in the caller pallet), a tip added for a nonce that never resolves is permanently and unrecoverably lost.

## Finding Description
`Tips<T>` is a `StorageMap<u64, u128>` keyed purely by nonce, with no payer tracking: [1](#0-0) 

`AddTip::add_tip` only validates `amount > 0` and that the nonce is not already consumed via `Nonce::<T>::get(nonce)`; it performs no check that the nonce corresponds to an existing/expected pending message: [2](#0-1) 

This is in stark contrast to the sibling `outbound-queue-v2` pallet's `AddTip` implementation, which requires an existing `PendingOrders` entry for the nonce and explicitly returns `AddTipError::UnknownMessage` otherwise: [3](#0-2) 

For inbound messages, `Tips` is only drained inside `process_message`, which `take()`s the tip and pays it out to whichever relayer submits that exact nonce: [4](#0-3) 

Real value is confirmed to back the tip: the caller-facing extrinsic in `pallet-system-frontend::add_tip` swaps the user's tip asset for Ether and then burns it via `swap_fee_asset_and_burn`/`burn_for_teleport` *before* forwarding the tip amount by XCM `Transact` to `pallet-system-v2::add_tip` on BridgeHub, which then calls into `InboundQueue::add_tip`: [5](#0-4) [6](#0-5) [7](#0-6) 

If `InboundQueue::add_tip` returns an error (e.g. `NonceConsumed`), `pallet-system-v2` records the amount in `LostTips` as an acknowledged-lost-fund bucket: [8](#0-7)  However, this only covers the "already consumed" failure case. When `add_tip` *succeeds* (nonce not yet consumed, because it may never be — e.g. it does not correspond to a real Ethereum event, or the corresponding event's relay permanently fails verification), the burned value is stored in `Tips<T>` indefinitely with no equivalent "lost tip" recovery, no cancellation extrinsic, and no expiry. The prior fix in `pr_9746` addressed a different failure mode (tip burnt but reward never registered due to an ordering bug) and did not add any mechanism to reclaim a tip for a nonce that never resolves.

## Impact Explanation
This matches the "permanent user-fund lock" category. Real, already-burned value (Ether obtained via swap-and-burn in `system-frontend`) is registered against an inbound nonce with no on-chain guarantee that nonce will ever be submitted/relayed, and no code path anywhere in `pallet-inbound-queue-v2` to cancel, refund, or expire the `Tips<T>` entry.

## Likelihood Explanation
Reachable by any unprivileged signed account via the public `pallet-system-frontend::add_tip` extrinsic → XCM Transact → `pallet-system-v2::add_tip` → `InboundQueue::add_tip`, with no special privileges required. The nonce need only fail to be validated against a real, already-committed Ethereum event, which the inbound pallet does not check (unlike the outbound pallet's `PendingOrders` existence check).

## Recommendation
Track the original tipper's account alongside the amount in `Tips<T>` (e.g. `StorageMap<u64, (AccountId, u128)>`), and add an explicit cancellation/refund extrinsic or a bounded expiry mechanism allowing the original tipper to reclaim the tip if the nonce is not consumed within a reasonable window, mirroring the recovery intent already scaffolded by `LostTips` in `pallet-system-v2`.

## Proof of Concept
1. Call `pallet-system-frontend::add_tip` with a `message_id::Inbound(nonce)` where `nonce` does not correspond to any Ethereum-side event that will ever be emitted (or corresponds to an event whose relay will permanently fail verification). The tip asset is swapped/burned in `swap_fee_asset_and_burn`.
2. The XCM `Transact` call reaches `pallet-system-v2::add_tip`, which calls `InboundQueue::add_tip(nonce, amount)`.
3. Since `Nonce::<T>::get(nonce)` is `false`, `add_tip` succeeds and `Tips::<T>::mutate(nonce, ...)` stores the amount.
4. Because the Ethereum-side event for `nonce` never occurs (or its relay is never successfully verified), `process_message` for that nonce is never executed, so `Tips::<T>::take(nonce)` is never called.
5. `Tips::<T>::get(nonce)` remains populated forever; the burned value backing it cannot be recovered by any code path in the pallet.

		pub fn process_message(relayer: T::AccountId, message: Message) -> DispatchResult {
			// Verify that the message was submitted from the known Gateway contract
			ensure!(T::GatewayAddress::get() == message.gateway, Error::<T>::InvalidGateway);

			let (nonce, relayer_fee) = (message.nonce, message.relayer_fee);

			// Verify the message has not been processed
			ensure!(!Nonce::<T>::get(nonce), Error::<T>::InvalidNonce);

			// Mark message as received
			Nonce::<T>::set(nonce);

			let message_id = T::MessageProcessor::process_message(relayer.clone(), message)
				.map_err(|e| match e {
					MessageProcessorError::ProcessMessage(e) => e,
					MessageProcessorError::ConvertMessage(e) => Error::<T>::from(e).into(),
					MessageProcessorError::SendMessage(e) => Error::<T>::from(e).into(),
				})?;

			// Pay relayer reward
			let tip = Tips::<T>::take(nonce).unwrap_or_default();
			let total_tip = relayer_fee.saturating_add(tip);
			if total_tip > 0 {
				T::RewardPayment::register_reward(&relayer, T::DefaultRewardKind::get(), total_tip);
			}

			// Emit event with the message_id
			Self::deposit_event(Event::MessageReceived { nonce, message_id });

			Ok(())
		}

		fn add_tip(nonce: u64, amount: u128) -> Result<(), AddTipError> {
			ensure!(amount > 0, AddTipError::AmountZero);
			// If the nonce is already processed, return an error
			ensure!(!Nonce::<T>::get(nonce.into()), AddTipError::NonceConsumed);
			// Otherwise add the tip.
			Tips::<T>::mutate(nonce, |tip| {
				*tip = Some(tip.unwrap_or_default().saturating_add(amount));
			});

		fn swap_fee_asset_and_burn(
			origin: Location,
			fee_asset: Asset,
		) -> Result<u128, DispatchError> {
			let ether_location = T::EthereumLocation::get();
			let (fee_asset_location, fee_amount) = match fee_asset {
				Asset { id: AssetId(ref loc), fun: Fungible(amount) } => (loc, amount),
				_ => {
					tracing::debug!(target: LOG_TARGET, ?fee_asset, "error matching fee asset");
					return Err(Error::<T>::UnsupportedAsset.into());
				},
			};
			if fee_amount == 0 {
				return Ok(0);
			}

			let ether_gained = if *fee_asset_location != ether_location {
				Self::swap_and_burn(
					origin.clone(),
					fee_asset_location.clone(),
					ether_location,
					fee_amount,
				)
				.inspect_err(|&e| {
					tracing::debug!(target: LOG_TARGET, ?e, "error swapping asset");
				})?
			} else {
				burn_for_teleport::<T::AssetTransactor>(&origin, &fee_asset)
					.map_err(|_| Error::<T>::BurnError)?;
				fee_amount
			};
			Ok(ether_gained)
		}
