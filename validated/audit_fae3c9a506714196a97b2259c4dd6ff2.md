Based on the investigation, the closest reachable analog in this Nebula codebase is not a full exploitable bypass but a documented trust-revocation gap: an already-established tunnel is not required to be torn down when the peer's certificate becomes untrusted (e.g., its issuing CA is removed/rotated from `pki.ca`), unless the operator explicitly opts in via `pki.disconnect_invalid`.

### Title
Stale peer trust survives CA/ownership rotation unless `pki.disconnect_invalid` is enabled - (File: connection_manager.go)

### Summary
Nebula's certificate authority pool can be hot-reloaded (CA rotated/removed, fingerprints blocklisted) via `PKI.reload` → `reloadCAPool`, but this reload does not by itself revoke already-established tunnels whose peer certificate was signed by the now-removed/rotated CA. Revalidation of live tunnels against the new CA pool only happens periodically in `connectionManager.isInvalidCertificate`, and even when that check detects the certificate is no longer valid, the tunnel is only torn down if the operator has set `pki.disconnect_invalid: true` (default `false`). This mirrors the reported bug class: a credential ("full access key" / here, an established remote peer's trusted session) tied to a prior trust root ("owner") keeps working after the trust root changes.

### Finding Description
`PKI.reloadCAPool` (pki.go) atomically swaps `p.caPool` with a freshly loaded pool built from `pki.ca` and `pki.blocklist`: [1](#0-0) 

However, nothing forces existing `HostInfo` tunnels to be re-verified immediately. The only place that re-checks a live peer's cached certificate against the current CA pool is `connectionManager.isInvalidCertificate`, which calls `caPool.VerifyCachedCertificate`: [2](#0-1) 

Critically, if the certificate is blocklisted, the tunnel is always torn down, but if it merely became untrusted because its signing CA was removed/rotated (i.e., "ownership" of trust changed) or expired, the tunnel is torn down **only** when `cm.intf.disconnectInvalid.Load()` is true — otherwise the function explicitly returns `false` and leaves the tunnel intact: [3](#0-2) 

This is corroborated by the CHANGELOG entry introducing this flag, which defaults to `false` and even notes a further limitation — it does not detect when a remote has swapped certificates since the last handshake: [4](#0-3) 

The `cert.CAPool.verify` logic itself does correctly detect a CA-fingerprint mismatch for a cached certificate (`ErrFingerprintMismatch`) when the signer is rotated: [5](#0-4) 

but this detection is only *consumed* by `isInvalidCertificate`, whose remediation (tunnel teardown) is gated behind an opt-in configuration flag rather than being enforced by default.

### Impact Explanation
When an operator rotates or revokes a CA (the "ownership change" analog) to cut off a compromised or departing peer's trust, any tunnel that peer already established before the rotation continues to operate with full data-plane access (firewall rules, routed traffic, encrypted tunnel) until it is otherwise closed (inactivity, restart, etc.), because `pki.disconnect_invalid` defaults to `false`. This is effectively the "old owner still has control because the credential was not removed" scenario: the mechanism to invalidate trust exists (`VerifyCachedCertificate`) but is not applied to already-open sessions unless explicitly configured.

### Likelihood Explanation
Any operator relying solely on CA rotation/removal (without also enabling `pki.disconnect_invalid` and without restarting all nodes) to revoke a peer's access will be exposed, since the default configuration silently preserves existing sessions. No malicious peer collusion, invalid certificate holder, or special privilege is required — this is a default-configuration gap reachable purely through normal operational CA management.

### Recommendation
- Default `pki.disconnect_invalid` to `true` (or otherwise ensure existing tunnels are proactively re-verified and torn down whenever the CA pool is reloaded, not just periodically and only opt-in).
- On every `reloadCAPool` call, iterate active `HostInfo`s and immediately re-run `VerifyCachedCertificate` against the newly loaded pool, tearing down any tunnel whose signer is no longer present/trusted, regardless of the `disconnect_invalid` setting when the CA (not just the leaf cert) was rotated.
- Document clearly that CA rotation alone does not revoke already-established sessions unless this setting is enabled.

### Proof of Concept
1. Configure two nebula nodes trusting CA `A`; establish a tunnel between them (host certificate signed by CA `A`).
2. Leave `pki.disconnect_invalid` at its default (`false`).
3. Operator rotates trust: reload `pki.ca` on the local node to a new CA `B` that no longer includes CA `A` (analogous to changing "ownership").
4. `PKI.reloadCAPool` swaps in the new pool; the existing tunnel to the peer signed by CA `A` is not torn down.
5. `connectionManager.isInvalidCertificate` will eventually detect `ErrCaNotFound`/verification failure for the peer's cached certificate, but because `disconnectInvalid` is `false`, it returns `false` at [6](#0-5) , and the tunnel — and the peer's access through it — remains active indefinitely.

// isInvalidCertificate decides if we should destroy a tunnel.
// returns true if pki.disconnect_invalid is true and the certificate is no longer valid.
// Blocklisted certificates will skip the pki.disconnect_invalid check and return true.
func (cm *connectionManager) isInvalidCertificate(now time.Time, hostinfo *HostInfo) bool {
	remoteCert := hostinfo.GetCert()
	if remoteCert == nil {
		return false //don't tear down tunnels for handshakes in progress
	}

	caPool := cm.intf.pki.GetCAPool()
	err := caPool.VerifyCachedCertificate(now, remoteCert)
	if err == nil {
		return false //cert is still valid! yay!
	} else if err == cert.ErrBlockListed { //avoiding errors.Is for speed
		// Block listed certificates should always be disconnected
		hostinfo.logger(cm.l).Info("Remote certificate is blocked, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else if cm.intf.disconnectInvalid.Load() {
		hostinfo.logger(cm.l).Info("Remote certificate is no longer valid, tearing down the tunnel",
			"error", err,
			"fingerprint", remoteCert.Fingerprint,
		)
		return true
	} else {
		//if we reach here, the cert is no longer valid, but we're configured to keep tunnels from now-invalid certs open
		return false
	}
}
