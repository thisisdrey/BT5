### Title
Witness reward tokens are permanently lost when a witness has zero votes in a cycle - (File: chainbase/src/main/java/org/tron/core/store/DelegationStore.java)

### Summary
Block/transaction-fee rewards paid to a Super Representative (SR) are accrued per-cycle via `DelegationStore.addReward()` regardless of whether the SR has any votes in that cycle. The accrued reward is only ever converted into a claimable per-vote value index (`Vi`) by `accumulateWitnessVi()` / `RewardViCalService.accumulateWitnessVi()`. When the vote count for that cycle is `0`, this function explicitly skips the accumulation step ("just forward the previous Vi"), which silently discards the reward amount that was already recorded for that cycle. This mirrors the reported Velodromo `Reward.sol` bug: value credited to an epoch/cycle with no depositors (voters) becomes permanently unclaimable.

### Finding Description
`MortgageService.payReward()` unconditionally stores rewards for the current cycle keyed by witness address, independent of whether that witness has any current voters: [1](#0-0) 

That reward is later converted into the value-index used to compute each voter's share in `DelegationStore.accumulateWitnessVi()` (invoked once per maintenance cycle from `MaintenanceManager.doMaintenance()`): [2](#0-1) [3](#0-2) 

If `voteCount == 0` for that cycle, the branch simply forwards the previous `Vi` without folding in the reward — the `reward` value that was already persisted via `addReward()` for that cycle/address is never used to increase `Vi`, and since voter payouts are strictly a function of `deltaVi * userVote`, no voter can ever claim it. The identical logic exists in the TVM-native path used by `VoteWitnessProcessor`/`VoteRewardUtil` for stake-2.0 voting: [4](#0-3) 

and in `RewardViCalService.accumulateWitnessVi()`, used for the historical/backfilled cycles: [5](#0-4) 

For the legacy (pre-Vi) reward algorithm, the analogous skip happens in `MortgageService.computeReward(cycle, votes)`, where a cycle's `totalReward` is simply dropped if `totalVote == 0` or `REMARK`: [6](#0-5) 

Since votes are only re-tallied for the *next* cycle at the end of `doMaintenance()` (`delegationStore.setWitnessVote(nextCycle, ...)`), any unprivileged holder can trigger this condition by casting a `VoteWitnessContract` transaction (or the TVM `vote` native contract) that withdraws all votes from an SR within the same cycle it produces blocks, or by targeting a newly promoted SR that has not yet accumulated recorded votes for the cycle. Once the cycle rolls over via `MaintenanceManager.doMaintenance()`, the reward recorded for that address/cycle is orphaned permanently — it stays in `DelegationStore`'s per-cycle reward slot but is never referenced by any subsequent `Vi` computation, and no voter's `AccountCapsule` votes list can retroactively claim it.

### Impact Explanation
This is a High-impact fund-freezing bug: TRX block/transaction-fee reward inflation credited for a given cycle becomes permanently unclaimable by any account, matching the "permanent freezing/loss of funds" criteria. The lost amount is bounded by per-block/per-cycle rewards for that SR, which recur every ~3 seconds (block production) and are meaningful over a full maintenance cycle.

### Likelihood Explanation
Medium/low-medium, mirroring the original report's likelihood assessment: it requires a cycle to elapse in which a specific witness (already receiving block/fee rewards) has zero recorded votes at maintenance time — reachable via ordinary `VoteWitnessContract` (or TVM `vote`) transactions from unprivileged accounts (e.g., mass unvoting, or timing votes so a witness is counted with `voteCount == 0` for the affected cycle) rather than any privileged/witness-only action.

### Recommendation
When `voteCount == 0` (or `reward == 0` from stale/zero vote state) in `DelegationStore.accumulateWitnessVi()` / `RewardViCalService.accumulateWitnessVi()` / `MortgageService.computeReward()`, do not silently discard the recorded reward. Instead, roll the undistributed reward forward into the next cycle's reward bucket for that address (re-adding it via `addReward(nextCycle, address, reward)`) so it becomes claimable once votes exist again, analogous to the suggested `renotifyRewardAmount` fix in the referenced report.

### Proof of Concept
1. SR `W` is in the active/standby set and receives block/tx-fee rewards each block via `MortgageService.payBlockReward`/`payTransactionFeeReward`, which call `delegationStore.addReward(currentCycle, W, value)` (`MortgageService.java:69-87`).
2. Before `MaintenanceManager.doMaintenance()` executes for `currentCycle`, all voters send `VoteWitnessContract` transactions removing their votes from `W` (or `W` only recently became active with `voteCount` not yet updated for `currentCycle`), so `delegationStore.getWitnessVote(currentCycle, W)` is `0`.
3. `doMaintenance()` calls `delegationStore.accumulateWitnessVi(currentCycle, W, 0)` (`MaintenanceManager.java:96-101`), which takes the `voteCount == 0` branch and forwards `preVi` unchanged (`DelegationStore.java:133-146`), discarding the reward recorded in step 1.
4. No account can subsequently claim this reward through `MortgageService.withdrawReward`/`queryReward`, since all payout math derives from `deltaVi` which was never incremented for that cycle — the reward is permanently lost.

  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }

  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }

  private static long computeReward(long beginCycle, long endCycle,
                                    AccountCapsule accountCapsule, Repository repository) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    for (Protocol.Vote vote : accountCapsule.getVotesList()) {
      byte[] srAddress = vote.getVoteAddress().toByteArray();
      BigInteger beginVi = repository.getDelegationStore().getWitnessVi(beginCycle - 1, srAddress);
      BigInteger endVi = repository.getDelegationStore().getWitnessVi(endCycle - 1, srAddress);
      BigInteger deltaVi = endVi.subtract(beginVi);
      if (deltaVi.signum() <= 0) {
        continue;
      }
      long userVote = vote.getVoteCount();
      reward += deltaVi.multiply(BigInteger.valueOf(userVote))
          .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
    }
    return reward;
  }
