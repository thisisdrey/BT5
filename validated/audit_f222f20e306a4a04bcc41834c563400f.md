### Title

`Pool.liquidate` can permanently block liquidation of small unhealthy positions - (`contracts/Pool.sol`)

### Summary

`Pool.liquidate` enforces both a `maxLiquidable` fraction and a minimum remaining `debtFloorInUsd`. For an unhealthy account whose debt `D` satisfies `D < 2 * debtFloorInUsd`, every allowed repayment either exceeds the liquidation cap or leaves forbidden non-zero debt below the floor. These positions therefore become unliquidatable even though liquidators can repay them in full economically.

### Finding Description

`liquidate` first rejects repayments where `amountToRepay / debtBalance > maxLiquidable`, defaulting to `0.5e18` at initialization. [1](#0-0)  It then computes the post-liquidation debt and rejects any non-zero remainder below `debtFloorInUsd`. [2](#0-1) 

For `D < 2F`, where `F = debtFloorInUsd`:

- `amountToRepay <= D / 2` satisfies the 50% liquidation cap, but leaves `D - amountToRepay` in `(0, F)`, causing `RemainingDebtIsLowerThanTheFloor`.
- `amountToRepay = D` leaves zero debt and would pass the floor check, but has ratio `1` and fails `AmountGreaterThanMaxLiquidable`.

Thus, when `maxLiquidable <= 50%`, no valid `amountToRepay` exists.

This also makes `quoteLiquidateMax` misleading: it may return up to `D * maxLiquidable`, but calling `liquidate` with that quoted amount reverts due to the floor check. [3](#0-2) 

### Impact Explanation

An attacker can intentionally establish a debt position in the range `[debtFloorInUsd, 2 * debtFloorInUsd)`, funded with just enough collateral to borrow. If the collateral later falls below the liquidation threshold, the position cannot be liquidated by any third-party liquidator despite `Pool.liquidate` being public and available while the pool is not shut down. [4](#0-3) 

This temporarily—or permanently when debt interest does not push the balance back to at least `2 * debtFloorInUsd`—freezes the collateral-seizure path and allows underwater debt to remain in the protocol. The broken invariant is liquidation liveness/solvency.

### Likelihood Explanation

The attack is reachable by an unprivileged borrower because `DebtToken.issue` is public and permits any new position whose resulting debt is at least `debtFloorInUsd`. [5](#0-4)  The `_mint` path explicitly validates only that `balance + amount` is at or above the floor; it does not prevent debts below `2 * debtFloorInUsd` that later become unliquidatable. [6](#0-5) 

No privileged call, malicious oracle response, malformed token, or reentrancy is required. A borrower only needs to open the boundary-sized debt and later have the position become unhealthy through normal collateral price movement or accrued interest.

### Recommendation

Allow a liquidation to fully repay a position when partial liquidation would otherwise create debt below the floor. For example:

```solidity
uint256 maxRepay = _debtTokenBalance.wadMul(maxLiquidable);
uint256 floorRemaining = _debtTokenBalance - amountToRepay_;

if (
    amountToRepay_ > maxRepay &&
    !(amountToRepay_ == _debtTokenBalance && _debtTokenBalance - maxRepay < debtFloorInUsd)
) {
    revert AmountGreaterThanMaxLiquidable();
}
```

More generally, derive the permitted liquidation range as “either no remaining debt or at least the floor,” and cap it by `maxLiquidable` only when that cap does not make the position impossible to liquidate. `quoteLiquidateMax` should implement the same rule so its result is executable.

### Proof of Concept

```ts
import {expect} from 'chai'
import {parseEther} from 'ethers/lib/utils'

it('cannot liquidate debt below twice the debt floor', async () => {
  // Existing pool setup:
  // - met/msdMET is valid collateral
  // - msUSD/msUSDDebtToken is valid debt
  // - masterOracle is the test oracle
  const debtFloor = parseEther('100') // $100
  await pool.connect(governor).updateDebtFloor(debtFloor)

  // Alice deposits collateral sufficient to issue exactly $100 of debt.
  await met.connect(alice).approve(msdMET.address, ethers.constants.MaxUint256)
  await msdMET.connect(alice).deposit(parseEther('1000'), alice.address)

  // Valid because new debt == floor.
  await msUSDDebtToken.connect(alice).issue(debtFloor, alice.address)

  // Bob obtains msUSD to act as liquidator.
  await met.connect(bob).approve(msdMET.address, ethers.constants.MaxUint256)
  await msdMET.connect(bob).deposit(parseEther('1000'), bob.address)
  await msUSDDebtToken.connect(bob).issue(parseEther('500'), bob.address)

  // Normal market movement makes Alice unhealthy.
  await masterOracle.updatePrice(met.address, unhealthyMetPrice)
  expect((await pool.debtPositionOf(alice.address))._isHealthy).to.equal(false)

  const debt = await msUSDDebtToken.balanceOf(alice.address)
  expect(debt).to.equal(debtFloor)

  // Maximum permissible partial liquidation is 50%.
  const partialRepay = debt.div(2)

  // quoteLiquidateMax reports an executable amount...
  expect(
    await pool.quoteLiquidateMax(msUSD.address, alice.address, msdMET.address)
  ).to.equal(partialRepay)

  // ...but liquidation rejects it because the $50 remainder is below the floor.
  await expect(
    pool.connect(bob).liquidate(
      msUSD.address,
      alice.address,
      partialRepay,
      msdMET.address
    )
  ).to.be.revertedWithCustomError(pool, 'RemainingDebtIsLowerThanTheFloor')

  // Full repayment would leave zero debt, but exceeds maxLiquidable.
  await expect(
    pool.connect(bob).liquidate(
      msUSD.address,
      alice.address,
      debt,
      msdMET.address
    )
  ).to.be.revertedWithCustomError(pool, 'AmountGreaterThanMaxLiquidable')

  // Therefore no amount exists that can liquidate Alice.
})
```
