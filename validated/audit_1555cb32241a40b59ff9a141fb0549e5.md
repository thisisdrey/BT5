### Title
Unauthenticated remote DoS via `POST /shutdown` permanently kills the signer's event receiver - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` dispatches any HTTP POST to `/shutdown` by unconditionally calling `stop_signal.store(true, Ordering::SeqCst)` and returning `Err(EventError::Terminated)`, with no check that the request originated from the local `SignerStopSignaler`. Any TCP client that can reach the signer's configured event-receiver endpoint can send this request and permanently stop `main_loop`, cutting the signer off from all future StackerDB/block/burn events.

### Finding Description
The dispatcher in `next_event` matches on `request.url()` alone [1](#0-0) , with no signature, token, or source-address check distinguishing a legitimate `SignerStopSignaler::send()` call from an arbitrary remote sender. `SignerStopSignaler::send` itself just connects to `self.local_addr` and writes a plain `POST /shutdown` request with no secret or MAC [2](#0-1) , so the "authorized caller" is defined only by convention (same-process stop signaler), not enforced by the protocol. Once `stop_signal` is set, `is_stopped()` returns `true` [3](#0-2) , and `main_loop` treats `Err(EventError::Terminated)` as a terminal condition and `break`s out permanently [4](#0-3) . There is no re-arm path; the receiver thread exits for good.

Whether this is remotely exploitable by an "unprivileged remote attacker" (per the ruleset, a "P2P or RPC port" is normally required for that role) depends on the operator's configured `config.endpoint`, which is used directly as the bind address in `SpawnedSigner::new` [5](#0-4) . This is not the node's P2P/RPC port but the signer's own event-receiver socket — the code itself flags this as an externally-configurable, non-localhost-enforced setting, warning operators: "It's important to exercise caution if you are communicating with an external node... if additional proper security checks are not integrated" [6](#0-5) . There is no code-level enforcement of loopback-only binding or an allow-list on `bind()` [7](#0-6) .

### Impact Explanation
If the event-receiver endpoint is reachable by a remote party (operator-dependent, not enforced in code), a single unauthenticated `POST /shutdown` permanently halts `main_loop`, meaning the signer stops receiving `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` events from the node it is paired with. This is a denial-of-service against the *signer's* event stream, not the node's P2P/RPC surface, and requires the endpoint to be non-loopback in the operator's deployment — a configuration precondition, since the default/documented topology binds this locally.

### Likelihood Explanation
Reachability strictly depends on how the operator configures `config.endpoint` for the signer's event receiver; there is no enforced localhost-only binding in `bind()`. Given the ruleset's definition of "unprivileged remote attacker" as one who reaches "a node's P2P or RPC port," and this endpoint is neither of those (it's the signer's separate event-listener socket, which the code explicitly warns should not be exposed externally), this finding sits at the edge of the defined attacker model. Within the code's own threat framing, the missing authentication is real, but it is documented behavior/known limitation rather than a broken guarantee about the P2P/RPC surface.

### Recommendation
Authenticate the `/shutdown` request (e.g., shared secret/token known only to the local `SignerStopSignaler`, or restrict `bind()`/accepted connections to loopback) instead of trusting the URL path alone.

### Proof of Concept
```rust
// libsigner/src/events.rs (test module)
#[test]
fn unauthenticated_shutdown_terminates_receiver() {
    let mut receiver: SignerEventReceiver<StacksBlockEvent> = SignerEventReceiver::new(false);
    let addr = receiver.bind("127.0.0.1:0".parse().unwrap()).unwrap();

    // Attacker: arbitrary TcpStream, NOT SignerStopSignaler
    let mut stream = std::net::TcpStream::connect(addr).unwrap();
    let body = "attacker";
    let req = format!(
        "POST /shutdown HTTP/1.1\r\nHost: {addr}\r\nConnection: close\r\nContent-Length: {}\r\n\r\n{body}",
        body.len()
    );
    stream.write_all(req.as_bytes()).unwrap();

    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());
}
```
This confirms `next_event` returns `Err(EventError::Terminated)` from an arbitrary connection, which per `main_loop`'s match arm causes the loop to `break` permanently [4](#0-3) .
