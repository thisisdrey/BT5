### Title
Off-by-one boundary in `parseEnergyFee` causes JSON-RPC to misreport `effectiveGasPrice` for transactions at exact price-change timestamps - (File: framework/src/main/java/org/tron/core/services/jsonrpc/JsonRpcApiUtil.java)

### Summary
`JsonRpcApiUtil.parseEnergyFee(long timestamp, String energyPriceHistory)` selects the applicable historical energy price for a given timestamp using a **strict** `timestamp > time` comparison, mirroring the exact bug class in the external report (strict `<`/`>` instead of inclusive `<=`/`>=` at a sale/price-period boundary). Because the boundary entry is the exact activation time of a new `ENERGY_FEE` (taken from `ProposalCapsule.getExpirationTime()`), a query for a timestamp that equals that activation time incorrectly falls through to the **previous (stale)** price bucket instead of the newly active one.

### Finding Description
`parseEnergyFee` iterates the price history from newest to oldest and returns the first bucket whose activation time is strictly less than the queried timestamp: [1](#0-0) 

The `energyPriceHistory` string is built by `EnergyPriceHistoryLoader.parseProposalsToStr()`, which stores `proposalCapsule.getExpirationTime()` as the activation timestamp for each new energy price: [2](#0-1) 

This function is used by the JSON-RPC query path to compute `effectiveGasPrice` for historical blocks/receipts, reachable by any anonymous JSON-RPC client: [3](#0-2) [4](#0-3) [5](#0-4) 

When a block's timestamp is exactly equal to the activation timestamp of a new energy-fee bucket, `timestamp > time` evaluates to `false` for that bucket, so the loop skips it and returns the **previous, stale** price instead of the price that is actually in effect for that block.

### Impact Explanation
This causes the JSON-RPC API (`eth_getBlockReceipts` and related consumers of `Wallet.getEnergyFee(timestamp)` / `BlockEventGet.getEnergyPrice`) to report an incorrect `effectiveGasPrice`/energy price for any block/transaction whose timestamp exactly equals an `ENERGY_FEE` proposal's `expirationTime`. Any external client, exchange, or tooling relying on this JSON-RPC data for gas-price accounting, indexing, or reconciliation for that specific boundary block would receive systematically wrong price data. This is a data-integrity/API-correctness bug in a public query path rather than a bug that moves on-chain funds, since the actual `ENERGY_FEE` used to charge users during execution is read live from `DynamicPropertiesStore.getEnergyFee()` (not from this historical parser), so no unauthorized transfer of TRX/tokens or freezing of funds results directly from this defect.

### Likelihood Explanation
Low likelihood of occurring for any specific block (requires the queried block's timestamp to exactly coincide with a proposal's `expirationTime`, which is a maintenance-cycle-aligned value), but deterministic and reproducible whenever it does occur, and reachable by any unauthenticated JSON-RPC client performing a read query — no privileged access required.

### Recommendation
Change the comparison in `parseEnergyFee` (and audit `parseBandwidthFee`/`BandwidthPriceHistoryLoader` for the same pattern) from `timestamp > time` to `timestamp >= time`, matching how the price/parameter change actually takes effect at the maintenance boundary.

### Proof of Concept
1. Configure a `ENERGY_FEE` proposal so that `EnergyPriceHistoryLoader` produces a history entry `"...,<T>:<newPrice>"` where `T` is the proposal's `expirationTime` (see `EnergyPriceHistoryLoader.parseProposalsToStr`, lines 44-55).
2. Call `JsonRpcApiUtil.parseEnergyFee(T, energyPriceHistory)`.
3. Observe the strict `timestamp > time` check at line 610 fails for `timestamp == T`, causing the loop to continue past the new bucket and return the old, pre-change price instead of `newPrice`.
4. Any JSON-RPC client calling `eth_getBlockReceipts` for the block whose timestamp equals `T` receives an `effectiveGasPrice` computed from the stale price via `Wallet.getEnergyFee(blockCapsule.getTimeStamp())` (`TronJsonRpcImpl.getBlockReceipts`, lines 950-964; `Wallet.getEnergyFee(long timestamp)`, lines 4481-4496).

```java
  public static long parseEnergyFee(long timestamp, String energyPriceHistory) {
    String[] priceList = energyPriceHistory.split(",");

    for (int i = priceList.length - 1; i >= 0; i--) {
      String[] priceArray = priceList[i].split(":");
      long time = Long.parseLong(priceArray[0]);
      long price = Long.parseLong(priceArray[1]);
      if (timestamp > time) {
        return price;
      }
    }

    return -1;
  }
```

```java
  public String parseProposalsToStr() {
    StringBuilder builder = new StringBuilder(DynamicPropertiesStore.DEFAULT_ENERGY_PRICE_HISTORY);

    for (ProposalCapsule proposalCapsule : proposalCapsuleList) {
      builder.append(",")
          .append(proposalCapsule.getExpirationTime())
          .append(":")
          .append(proposalCapsule.getParameters().get(ProposalType.ENERGY_FEE.getCode()));
    }

    return builder.toString();
  }
```
