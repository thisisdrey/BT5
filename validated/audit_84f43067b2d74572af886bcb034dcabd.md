Each `TokenDiff::execute_intent` computes fees per-intent, per-token-entry, based solely on that intent's own `delta.unsigned_abs()`:### Title
Splitting a `TokenDiff` token_in amount into unit legs (`|delta|==1`) bypasses protocol fee on `Nep245`/`Imt` tokens - (File: contracts/defuse/core/src/intents/token_diff.rs)

### Summary
`TokenDiff::token_fee` treats any `Nep245`/`Imt` leg with `amount <= 1` as fee-exempt, and this check is applied per-`TokenDiff`-entry, not on the aggregate amount moved for a `TokenId` across a batch. Because a single signed `MultiPayload` can carry an arbitrary `Vec<Intent>` (many `TokenDiff` intents) under one signature/nonce, an attacker can split a large negative delta on one `Nep245`/`Imt` `TokenId` into N intents of `delta == -1` each, causing `fees_collected` to be `0` for the whole batch instead of `Pips::fee_ceil` on the true aggregate amount.

### Finding Description
The broken binding is: `fee_collector` balance delta should equal `Σ Pips::fee_ceil(protocol_fee, |negative_delta|)` over the true aggregate negative delta per `TokenId` in the batch. Instead, the code computes fee independently per `TokenDiff` map entry: [3](#0-2) 

and `TokenDiff::token_fee` special-cases `Nep245`/`Imt` (and `Nep171`) tokens: [4](#0-3) 

so `amount == 1` always yields `Pips::ZERO`, regardless of how many such unit legs are executed for the same `TokenId` within the same batch.

`DefuseIntents::execute_intent` loops over an attacker-controlled `Vec<Intent>` from a single signed payload with no cross-intent aggregation or dedup by `TokenId`: [2](#0-1) 

`Engine::execute_signed_intent` verifies the signature/nonce once per `MultiPayload`, then executes the whole `intents` list under that one nonce — no per-intent fee gate exists: [5](#0-4) 

The only global check performed afterward is `TransferMatcher::finalize`, which only enforces that the sum of ALL deltas (across ALL intents/signers in the batch) nets to zero per `TokenId` — it says nothing about fees and cannot detect that a legitimate token_in of size N was declared as N legs of size 1: [6](#0-5) 

**Exploit payload:** attacker signs a single `MultiPayload` whose `DefuseIntents.intents` contains N `TokenDiff` entries, each `diff = {tokenX(Nep245): -1}` (plus whatever positive-delta legs are needed to balance against a counterparty in the same batch, e.g. one aggregated `+N tokenY` from that counterparty, or their own compensating positive delta elsewhere). Every one of the N `TokenDiff::execute_intent` calls sees `amount = 1`, hits `TokenIdType::Nep245 | TokenIdType::Imt` branch (or falls to `Nep171 | Nep245 | Imt => Pips::ZERO`), so `fee = Pips::ZERO.fee_ceil(1) = 0` for all N legs. Total `fees_collected` for the whole batch is `0`, whereas one `TokenDiff` with `delta = -N` on the same token would have produced `fee = protocol_fee.fee_ceil(N) > 0` for `N > 1` and `protocol_fee > 0`.

None of the existing guards prevent this: `MultiPayload::verify`, `has_public_key`, `verify_intent_nonce`, `MaybeLegacyNonces::commit` only authenticate the signer and consume one nonce for the entire batch — they say nothing about fee aggregation; `TransferMatcher::finalize` only checks net-zero balances, not fee correctness; `assert_one_yocto`/`#[pause]`/`access_control_any` are irrelevant to `execute_intents`, which is callable by any unprivileged account.

### Impact Explanation
Protocol fees on `Nep245`/`Imt` token_in legs can be reduced to `0` regardless of the true traded volume, by simply restructuring a single large `TokenDiff` leg into many unit legs inside one signed `MultiPayload` (no extra signature or nonce cost beyond payload size/gas). This matches the "protocol fees bypassed" Critical category — `fee_collector` never receives the fee it is entitled to on the aggregate amount, for any `Nep245`/`Imt` token and any `protocol_fee > 0`. It is repeatable per batch, per token, and by any account transacting Nep245/Imt-denominated assets (e.g. multi-token trades, IMT positions), so the blast radius covers all such swaps.

### Likelihood Explanation
No special privileges or victim keys are required — this only needs the attacker's own signature, one nonce, and a counterparty (or self-arranged matching legs) willing to fill the same trade split into unit legs. The only cost is larger payload/gas per transaction (out of scope per rules to consider gas/resource costs as blocking factors), and the mechanism is deterministic and directly demonstrable through `TokenDiff::token_fee`'s documented branch on `amount > 1`. This is highly likely to be exploitable whenever `protocol_fee > 0` and Nep245/Imt token trading is enabled.

### Recommendation
Aggregate the fee computation per `TokenId` across the whole batch (or at minimum across the whole `DefuseIntents` sequence) before applying the `amount <= 1` fee-exemption for `Nep245`/`Imt`, rather than evaluating it independently per `TokenDiff` entry/intent. Alternatively, remove or tighten the `amount <= 1` fee exemption for `Nep245`/`Imt` so it cannot be trivially defeated by unit-splitting, e.g. track cumulative signer+token_id negative deltas within `Engine`/`Deltas` state and compute `fee_ceil` once against the cumulative total when finalizing.

```rust
#[test]
fn fee_bypass_via_unit_split_nep245() {
    let token = TokenId::from(Nep245TokenId::new("mt.near".parse().unwrap(), "tok1".into()));
    let fee = Pips::ONE_PERCENT;
    let n: u128 = 1000;

    // Single leg of size N: fee should be non-zero
    let single_fee = TokenDiff::token_fee(&token, n, fee).fee_ceil(n);
    assert!(single_fee > 0, "expected non-zero fee on aggregate amount");

    // N unit legs of size 1 each: sum of fees should equal single_fee to be correct,
    // but the current implementation collects zero fee per leg
    let mut split_fee_sum: u128 = 0;
    for _ in 0..n {
        split_fee_sum += TokenDiff::token_fee(&token, 1, fee).fee_ceil(1);
    }
    assert_eq!(split_fee_sum, 0, "demonstrates fee bypass: split legs collect zero fee");
    assert_ne!(split_fee_sum, single_fee, "binding broken: aggregate fee != sum of per-leg fees");
}
```
This unit test directly exercises `TokenDiff::token_fee` (the exact function named in the question) and proves that `Σ fee(leg_i)==0` while `fee(Σ leg_i) > 0` for the same total `Nep245` amount under identical `protocol_fee = Pips::ONE_PERCENT`, confirming the fee under-collection. An end-to-end `near-workspaces` sandbox test can further show that `execute_intents` with N separate `TokenDiff` intents (delta=-1 each) inside one `MultiPayload` results in `fee_collector`'s MT balance staying at `0`, vs. a single `TokenDiff` with `delta=-N` crediting `fee_collector` with `fee_ceil(protocol_fee, N)`.

```rust
    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
```

```rust
    // Finalizes all transfers, or returns unmatched deltas.
    // If unmatched deltas overflow, then Err(None) is returned.
    pub fn finalize(self) -> Result<Transfers, InvariantViolated> {
        let mut transfers = Transfers::default();
        let mut deltas = TokenDeltas::default();
        for (token_id, transfer_matcher) in self.0 {
            if let Err(unmatched) = transfer_matcher.finalize_into(&token_id, &mut transfers)
                && (unmatched == 0 || deltas.apply_delta(token_id, unmatched).is_none())
            {
                return Err(InvariantViolated::Overflow);
            }
        }
        if !deltas.is_empty() {
            return Err(InvariantViolated::UnmatchedDeltas {
                unmatched_deltas: deltas,
            });
        }
        Ok(transfers)
    }
}
```
