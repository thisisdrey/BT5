### Title
`add_gas_key` unconditionally reseeds all gas-key nonce rows to `initial_nonce_value(block_height)`, allowing nonce rollback and replay of an already-executed gas-key transaction within the same block - ([File: runtime/runtime/src/access_keys.rs])

### Summary
`add_gas_key` re-seeds every nonce-index row for a re-added gas key to `initial_nonce_value(block_height) = (block_height-1)*ACCESS_KEY_NONCE_RANGE_MULTIPLIER`, with no comparison to the nonce values already written for that public key/index earlier in the same block. If an account owner submits a `GasKeyNonce` transaction on index `i` and, in the same block, submits `DeleteKey(K)+AddKey(K, GasKeyFullAccess)`, the reseed value lands below the nonce just consumed by index `i`, breaking the "nonce monotonicity prevents replay" invariant for that row.

### Finding Description
`action_add_key` routes to `add_gas_key` when the new key is a gas key [1](#0-0) . `add_gas_key` derives the seed purely from the current `block_height` and writes it to every `NonceIndex` row with `set_gas_key_nonce`, with no read of, or comparison against, any pre-existing nonce value for that index/public key: [2](#0-1) . `initial_nonce_value` is `(block_height-1) * ACCESS_KEY_NONCE_RANGE_MULTIPLIER` [3](#0-2) .

A gas-key-signed transaction's nonce for index `i` is validated against the per-index stored nonce (`get_gas_key_nonce`) via `verify_nonce`, using `NonceMode::Monotonic` (`tx_nonce > current_nonce`) or `Strict` [4](#0-3) , and this is what backs the "nonce monotonicity prevents replay" invariant documented for the file. The nonce check uses `effective_nonce = max(current_nonce, pending.max_nonce)` computed fresh at verification time from trie state [5](#0-4) , so whatever value is currently stored for the index governs validity — there is no additional "high-water-mark" check independent of the stored row.

Exploit flow, all within block `h`:
1. `tx_a`: a `GasKeyNonce{nonce: (h-1)*1e6 + k, nonce_index: i}` transaction signed by gas key `K` executes first, and `set_gas_key_nonce` writes `(h-1)*1e6+k` to index `i`'s row.
2. `tx_b`: a transaction (signed with the account's regular/full-access key, actor must equal account owner per `check_actor_permissions` for `AddKey`/`DeleteKey`) with actions `[DeleteKey(K), AddKey(K, GasKeyFullAccess{...})]` executes later in the same block `h`. `DeleteKey(K)` succeeds only if `gas_key_info.balance <= MAX_BALANCE_TO_BURN` (the remainder is burned, not refunded) [6](#0-5) , after which `AddKey(K, ...)` succeeds because the access key row no longer exists (the `AddKeyAlreadyExists` guard only checks current existence) [7](#0-6) . `add_gas_key` then reseeds every nonce row, including index `i`, to `initial_nonce_value(h) = (h-1)*1e6`, which is strictly less than the `(h-1)*1e6+k` written by `tx_a` moments earlier.
3. Because `k < ACCESS_KEY_NONCE_RANGE_MULTIPLIER` and the reseed uses the same block height `h`, `(h-1)*1e6 < (h-1)*1e6+k`. Index `i`'s stored nonce has moved backward. Any subsequent `GasKeyNonce` transaction for index `i` with nonce in `((h-1)*1e6, (h-1)*1e6+k]` — including the exact previously-broadcast `tx_a` bytes, which remain a validly-signed transaction against the same public key `K` — will pass `verify_nonce` and `verify_nonce`'s upper-bound check (`tx_nonce >= block_height*MULTIPLIER`) since it grows with `block_height` and does not reject reuse in a future block. This defeats the row's replay protection.

This only works if `tx_b` executes in the *same* block as `tx_a` (a later block gives `initial_nonce_value` a strictly higher seed than any nonce usable in the earlier block, since `(h'-1)*1e6 ≥ h*1e6 > (h-1)*1e6+999999` for `h' > h`), so the attacker needs both transactions ordered correctly within one block/chunk — feasible but not fully attacker-guaranteed, and repeatable across attempts at negligible cost.

Practical monetization requires a third party ("gas sponsor") funding the gas key's balance via `TransferToGasKey`, which any actor may call on any account's gas key with no `actor_id` restriction [8](#0-7) [9](#0-8) . Because the key's balance is reset to zero on re-add, replaying the exact `tx_a` bytes requires the sponsor to refund the same public key again before the replay executes (gas-key balance checks in `verify_and_charge_gas_key_tx_ephemeral` would otherwise reject it for insufficient balance) [10](#0-9) .

### Impact Explanation
This breaks nonce monotonicity/replay prevention for gas-key nonce rows — a core invariant this file is documented to guarantee. Concretely it allows a previously-executed, already-signed gas-key transaction (e.g. a `Transfer` or `WithdrawFromGasKey`) to be validly re-submitted and re-executed a second time against the same nonce_index, after the account owner reseeds the row via a same-block `DeleteKey`+`AddKey` of the same public key. This maps to the "double-spend/replay" bounty category. The concrete monetary damage is bounded and situational: `delete_gas_key` caps the account's own leftover gas-key balance that can be destroyed during the reseed at `MAX_BALANCE_TO_BURN` (documented as ≤ 1 NEAR), so it does not by itself create theft; the attacker who controls `K` could always sign brand-new valid transactions to drain funds they hold. Genuine loss to a third party requires a "gas-sponsorship" pattern where an external funder tops up the gas key via `TransferToGasKey` and re-funds it a second time before the replay lands, letting the account owner double-charge the sponsor's gas allocation for one signed action.

### Likelihood Explanation
Preconditions: attacker is the account owner (only the account owner can invoke `AddKey`/`DeleteKey` on their own key, per `check_actor_permissions`), has a gas key `K` with `num_nonces ≥ 1` and some prepaid gas-key balance, and can get two transactions (`tx_a` signed by `K`, `tx_b` signed by the owner's key) included and executed in that order within the same block. Cost to the attacker is only ordinary transaction fees, and the attempt is repeatable across blocks until an ordering that lands both txs in one block succeeds (no validator/node privilege is used). The scenario requiring an external sponsor to be double-charged adds a further precondition (a co-operating or automated funder) that is not guaranteed in general but is a plausible design for gas-sponsorship/meta-transaction relayers, which this feature is explicitly built to support.

### Recommendation
In `add_gas_key`, do not blindly overwrite existing gas-key nonce rows with `initial_nonce_value(block_height)`. Either: (a) when the public key limit for the account tracks a "high-water mark" nonce independent of block height (e.g., persist the max nonce ever used per account/public key and seed new rows to at least that value), or (b) prevent immediate re-use of a just-deleted public key by permanently retiring deleted public keys (or nonce indices) rather than allowing `AddKey` to recreate an identical public key with fresh nonce state in the same block. At minimum, seed each nonce row to `max(initial_nonce_value(block_height), previous_max_nonce_for_this_pubkey_index)` if such history is available, or reject `AddKey` for a public key that was deleted within a configurable number of recent blocks/heights.

### Proof of Concept
Unit test in `runtime/runtime/src/access_keys.rs` test module, modeled after existing `test_add_gas_key`/`test_delete_gas_key`:
1. Set up an account and add a gas key `K` via `action_add_key` at block height `h` with `num_nonces ≥ 1`, `gas_key_info.balance = 0` (or ≤ `MAX_BALANCE_TO_BURN`).
2. Simulate `tx_a`: call `set_gas_key_nonce(state_update, account_id, K, index=i, nonce=(h-1)*ACCESS_KEY_NONCE_RANGE_MULTIPLIER + k)` directly (mirroring what the gas-key-tx apply path does), for some `k > 0`.
3. Call `action_delete_key` for `K` (assert it succeeds because balance ≤ `MAX_BALANCE_TO_BURN`), then call `action_add_key` again for `K` with a fresh `GasKeyFullAccess` at the same block height `h`.
4. Read back `get_gas_key_nonce(state_update, account_id, K, i)` and assert it equals `(h-1)*ACCESS_KEY_NONCE_RANGE_MULTIPLIER`, which is `< (h-1)*ACCESS_KEY_NONCE_RANGE_MULTIPLIER + k` — i.e., strictly less than the value written in step 2.
5. (Integration extension in `test-loop-tests/src/tests/gas_keys.rs`) Drive this end-to-end: submit the real `tx_a` GasKeyNonce transaction, then in the same block submit `DeleteKey(K)+AddKey(K, GasKeyFullAccess)`, fund `K` again via `TransferToGasKey`, and rebroadcast the identical `tx_a` bytes; assert it is accepted (no `InvalidNonce`) and its receipt executes a second time.

```rust
pub(crate) fn initial_nonce_value(block_height: BlockHeight) -> Nonce {
    // Set default nonce for newly created access key to avoid transaction hash collision.
    // See <https://github.com/near/nearcore/issues/3779>.
    (block_height - 1) * near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER
```

```rust
fn add_gas_key(
    fee_config: &RuntimeFeesConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    gas_key_info: &GasKeyInfo,
    block_height: BlockHeight,
) -> Result<(), StorageError> {
    // For gas keys, nonce stored on access key is not used and should always be zero
    let mut access_key = access_key.clone();
    access_key.nonce = 0;
    set_access_key(state_update, account_id.clone(), public_key.clone(), &access_key);

    // Set up nonces for gas key
    let num_nonces = gas_key_info.num_nonces;
    let nonce = initial_nonce_value(block_height);
    for i in 0..num_nonces {
        set_gas_key_nonce(state_update, account_id.clone(), public_key.clone(), i, nonce);
    }

    account.set_storage_usage(
        account
            .storage_usage()
            .checked_add(gas_key_storage_cost(fee_config, public_key, &access_key, num_nonces))
            .ok_or_else(|| {
                StorageError::StorageInconsistentState(format!(
                    "Storage usage integer overflow for account {}",
                    account_id
                ))
            })?,
    );
    Ok(())
}
```

```rust
pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &TransferToGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
}
```

```rust
fn verify_nonce(
    tx_nonce: Nonce,
    current_nonce: Nonce,
    block_height: Option<BlockHeight>,
    nonce_mode: NonceMode,
) -> Result<(), InvalidTxError> {
    match nonce_mode {
        NonceMode::Monotonic => {
            if tx_nonce <= current_nonce {
                return Err(InvalidTxError::InvalidNonce { tx_nonce, ak_nonce: current_nonce });
            }
        }
        NonceMode::Strict => {
            if !current_nonce.checked_add(1).is_some_and(|expected| tx_nonce == expected) {
                return Err(InvalidTxError::InvalidNonce { tx_nonce, ak_nonce: current_nonce });
            }
        }
    }
    if let Some(height) = block_height {
        let upper_bound = height
            .saturating_mul(near_primitives::account::AccessKey::ACCESS_KEY_NONCE_RANGE_MULTIPLIER);
        if tx_nonce >= upper_bound {
            return Err(InvalidTxError::NonceTooLarge { tx_nonce, upper_bound });
        }
    }
    Ok(())
}
```
