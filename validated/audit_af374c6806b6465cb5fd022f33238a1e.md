### Title
Orphan instantiated Atlas attachments are never evicted, causing permanent unbounded disk growth - (File: stackslib/src/net/atlas/download.rs)

### Summary
`AttachmentsDownloader::run` stores every peer-returned attachment blob as an instantiated row in `AtlasDB.attachments`, even when no committed `AttachmentInstance` references that content hash. [1](#0-0)  The only eviction paths in `AtlasDB` delete `was_instantiated = 0` rows or unresolved `attachment_instances` rows, so a `was_instantiated = 1` orphan is never removed. [2](#0-1) [3](#0-2)  This makes the storage exhaustion permanent rather than bounded by the configured expiration windows.

### Finding Description
The broken invariant is: every row in `AtlasDB.attachments` with `was_instantiated = 1` must correspond to a `content_hash` referenced by at least one committed `AttachmentInstance`, but nothing enforces or later repairs this invariant. [4](#0-3)  `insert_instantiated_attachment` simply `INSERT OR REPLACE`s the blob with `was_instantiated = 1` and then updates `attachment_instances` where `content_hash` matches; if no instance matches, the attachment row is still written. [5](#0-4) 

The reachable remote path is:

1. The victim node builds an `AttachmentsBatch` from checked, unresolved `AttachmentInstance`s produced by canonical block processing. [6](#0-5) 
2. It issues HTTP `GET /v2/attachments/{content_hash}` to a peer for each missing hash. [7](#0-6) 
3. The attacker-controlled peer returns a `GetAttachmentResponse` containing an arbitrary `Attachment` blob whose `hash()` does not equal the requested `content_hash` and is not referenced by any on-chain instance.
4. `extend_with_attachments` decodes the response and inserts `response.attachment` into `context.attachments` without comparing `attachment.hash()` to `request.content_hash`. [8](#0-7) 
5. When the state machine reaches `Done`, it drains `context.attachments` and calls `insert_instantiated_attachment` for each one, regardless of whether `find_all_attachment_instances(&attachment.hash())` returned anything. [1](#0-0) 
6. The resulting row has `was_instantiated = 1`, so `evict_expired_uninstantiated_attachments` (`was_instantiated = 0`) and `evict_expired_unresolved_attachment_instances` (`attachment_instances` with `is_available = 0`) both skip it. [2](#0-1) [3](#0-2) 

No signature, RPC secret, canonical-tip check, or `will_admit_mempool_tx` gate is applied to the downloaded attachment content before it is persisted. `MAX_MESSAGE_LEN`/`MAX_PAYLOAD_LEN` may bound the size of a single blob, but they do not limit the number of distinct orphan hashes an attacker can introduce, and there is no row-count or TTL cap on instantiated attachments.

### Impact Explanation
An unprivileged remote peer can write forged, attacker-controlled blobs into the victim's persistent `AtlasDB` `attachments` table. [9](#0-8)  Each crafted response creates a permanent row that is never evicted, so disk usage grows unboundedly until the node runs out of storage. [2](#0-1) [3](#0-2)  This is a remote, unauthenticated write to node state that causes permanent disk-exhaustion DoS, matching the Critical severity category.

### Likelihood Explanation
Preconditions are low: the attacker only needs to be a peer selected for Atlas sync (run a public peer the victim connects to, or connect to the victim's P2P port and be chosen as an outbound sync peer) and the victim must have at least one unresolved `AttachmentInstance`, which is the normal state during chain sync. [10](#0-9)  The attack is repeatable on every unresolved instance and every retry cycle, with no rate limit or cleanup, so disk growth is cumulative and remote reachable without any secret or privileged role.

### Recommendation
Before persisting a downloaded attachment, verify that `attachment.hash()` equals the `content_hash` of the `AttachmentRequest` that fetched it, and only call `insert_instantiated_attachment` when `find_all_attachment_instances(&attachment.hash())` returns a non-empty list. [1](#0-0) [11](#0-10)  Additionally, add a periodic `evict_orphan_instantiated_attachments` that deletes `attachments` rows with `was_instantiated = 1` whose `hash` is not referenced by any `attachment_instances` row and whose `created_at` exceeds a configured TTL, mirroring the existing uninstantiated/unresolved eviction logic. [2](#0-1) [3](#0-2) 

### Proof of Concept
Add a Rust net test in `stackslib/src/net/atlas/tests.rs` that:

1. Opens an in-memory `AtlasDB`, queues an `AttachmentInstance` with `content_hash = H`, and marks it checked but not available. [12](#0-11) [13](#0-12) 
2. Builds an `AttachmentsBatch` tracking that instance and pushes it into an `AttachmentsDownloader`.
3. Runs a local HTTP server on the peer's data URL that responds to `GET /v2/attachments/{H}` with a `GetAttachmentResponse` encoding `Attachment { content: vec![0xde; 1024] }`, whose hash `H'` is not `H` and is not in any `AttachmentInstance`.
4. Runs `AttachmentsDownloader::run` until the state machine reaches `Done`.
5. Calls `atlasdb.evict_expired_uninstantiated_attachments()` and `atlasdb.evict_expired_unresolved_attachment_instances()`.
6. Computes `let orphan_hash = attachment.hash();` and asserts:

```rust
assert!(atlasdb.find_attachment(&orphan_hash).unwrap().is_some());
assert!(atlasdb.find_all_attachment_instances(&orphan_hash).unwrap().is_empty());
```

The first assertion proves the orphan instantiated row persists after all eviction passes; the second proves no committed instance references it. [14](#0-13) [11](#0-10)

    pub fn extend_with_attachments(
        mut self,
        results: &mut BatchedRequestsResult<AttachmentRequest>,
    ) -> AttachmentsBatchStateContext {
        for (request, response) in results.succeeded.drain() {
            let report = self
                .peers
                .get_mut(request.get_url())
                .expect("Atlas: unable to retrieve reliability report for peer");

            let response = if let Some(r) = response {
                r
            } else {
                report.bump_failed_requests();
                continue;
            };

            if let Ok(response) = response.decode_atlas_get_attachment() {
                self.attachments.insert(response.attachment);
                report.bump_successful_requests();
            } else {
                report.bump_failed_requests();
            }
        }
        let mut events_ids = results.faulty_peers.keys().copied().collect::<Vec<usize>>();
        self.events_to_deregister.append(&mut events_ids);

        self
    }

    pub fn evict_expired_uninstantiated_attachments(&mut self) -> Result<(), db_error> {
        let now = util::get_epoch_time_secs() as i64;
        let cut_off = now - self.atlas_config.uninstantiated_attachments_expire_after as i64;
        let tx = self.tx_begin()?;
        let res = tx.execute(
            "DELETE FROM attachments WHERE was_instantiated = 0 AND created_at < ?",
            params![cut_off],
        );
        res.map_err(db_error::SqliteError)?;
        tx.commit().map_err(db_error::SqliteError)?;
        Ok(())
    }
