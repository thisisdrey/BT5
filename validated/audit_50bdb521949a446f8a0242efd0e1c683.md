### Title
Conntrack fast-path in `Firewall.inConns` allows continued traffic from peers whose certificate/CA has been blocklisted, without re-checking `caPool` - (File: `firewall.go`)

### Summary
The external report describes a class of bug where one state-mutating/consuming path (`registerAccountWeight()`) fails to re-check an "active" condition that sibling paths (`vote()`, `registerAccountWeightAndVote()`) enforce, allowing continued use of a receiver after it was marked inactive. The same bug class exists in Nebula's firewall packet-decision logic: the conntrack ("fast path") lookup in `Firewall.inConns` only re-validates an already-established flow against the current ruleset (and therefore against `caPool`) when the stored `rulesVersion` differs from the firewall's current `rulesVersion`. It never re-checks `caPool` blocklist status independent of a firewall-rule reload, even though the full match path (`table.match`) is invoked with `caPool` and is expected to enforce `ca_name`/`ca_sha` and blocklist constraints.

### Finding Description
`Firewall.Drop` first calls `f.inConns(fp, h, caPool, localCache)` [1](#0-0)  to see if the packet's flow tuple is already conntracked; if so, it is allowed immediately without going through firewall table matching again in the common case.

Inside `inConns`, the *only* trigger for re-validating an existing conntrack entry against `caPool`/the current rules is a version mismatch:
```go
if c.rulesVersion != f.rulesVersion {
    // ...
    if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
        // drop and remove entry
    }
    // ...
}
``` [2](#0-1) 

If `c.rulesVersion == f.rulesVersion`, the function unconditionally refreshes the expiry and returns `true` (allow), *never calling `table.match` and never consulting `caPool` at all* for that packet.

`rulesVersion` is only incremented when the firewall configuration itself changes and `reloadFirewall` runs:
```go
fw.rulesVersion = oldFw.rulesVersion + 1
``` [3](#0-2) 

However, CA/certificate blocklisting is reloaded through an entirely separate path, `PKI.reloadCAPool`, which swaps the `caPool` but does **not** touch `Firewall.rulesVersion`:
```go
func (p *PKI) reloadCAPool(c *config.C) *util.ContextualError {
	caPool, err := loadCAPoolFromConfig(p.l, c)
	// ...
	p.caPool.Store(caPool)
	// ...
}
``` [4](#0-3) 

Because these two reload mechanisms are decoupled, blocklisting a CA/cert (e.g. adding it to `pki.blocklist`) does not bump `f.rulesVersion`, so any already-conntracked flow from a host whose certificate/issuing CA was just blocklisted keeps being allowed by the firewall fast path — the exact same "stale state persists because a downstream check wasn't re-run" pattern as `registerAccountWeight()` skipping the active-receiver check that `_storeAccountVotes` enforces elsewhere.

### Impact Explanation
An attacker whose certificate is later revoked/blocklisted by the operator (e.g., a compromised or departed node's cert added to `pki.blocklist`) can continue sending/receiving already-permitted traffic through the firewall's conntrack fast path indefinitely, as long as no unrelated firewall-rule reload occurs to bump `rulesVersion`. This is a firewall-bypass / stale-trust issue: the intended effect of blocklisting (immediately cutting off traffic matched by `ca_name`/`ca_sha` rules) is not enforced for already-established flows until an unrelated config change happens to occur. Separately, `connection_manager.isInvalidCertificate` does periodically tear down the *tunnel* itself when a blocklisted cert is detected, which bounds the exposure window for the overlay tunnel, but the firewall-layer re-check for already-permitted flows is not tied to that teardown and can be argued to remain vulnerable to attacker-controlled timing (heavy already-established traffic keeps refreshing expiry inside the `TCPTimeout`/`UDPTimeout`/`DefaultTimeout` window) before the connection manager's next scheduled traffic-decision check invalidates the hostinfo.

### Likelihood Explanation
Reachable without any privileged access beyond having previously established a legitimate, matched flow with a peer under a certificate that is later blocklisted — this matches the requirement of "no CA-signed certificate" for the *attacker's future state* (their cert is being revoked/blocklisted, i.e., they no longer hold valid trust) while still exploiting stale conntrack state. The bug requires only normal certificate-lifecycle events (CA/cert blocklisting) that operators are expected to perform for exactly this kind of enforcement, and no lighthouse/relay/malicious-peer collusion is needed — it is a pure firewall-state-poisoning/staleness bug rooted in the decoupling of `rulesVersion` bumps from `caPool` reloads.

### Recommendation
Tie CA-pool/blocklist reloads to firewall conntrack revalidation the same way rule-table reloads are: increment `Firewall.rulesVersion` (or an equivalent independent "trust version" checked by `inConns`) whenever `PKI.reloadCAPool` swaps in a new `caPool`, so that all already-conntracked flows are forced through `table.match` (and thus `caPool`/blocklist checks) on the next packet after a blocklist change, rather than only after a firewall-rule change.

### Proof of Concept
1. Peer A and Peer B establish a tunnel and start exchanging UDP traffic matched by an inbound/outbound rule; `Firewall.addConn` records `rulesVersion = f.rulesVersion` for the flow tuple [5](#0-4) .
2. Operator adds Peer A's certificate fingerprint (or its issuing CA) to `pki.blocklist` and triggers a config reload; `PKI.reloadCAPool` swaps `caPool` but does not change `f.rulesVersion` [4](#0-3) .
3. Peer A continues sending packets on the same flow tuple before `TCPTimeout`/`UDPTimeout` expiry and before `connection_manager`'s periodic `isInvalidCertificate` check fires; `Firewall.Drop` → `inConns` sees `c.rulesVersion == f.rulesVersion`, skips `table.match`/`caPool` entirely, refreshes the conntrack expiry, and allows the packet [6](#0-5) .
4. Compare with `TestFirewall_DropConntrackReload`, which demonstrates that conntrack entries are only re-validated when `fw.rulesVersion` is explicitly bumped — showing no equivalent re-validation trigger exists for CA-pool/blocklist changes [7](#0-6) .

func (f *Firewall) inConns(fp firewall.Packet, h *HostInfo, caPool *cert.CAPool, localCache firewall.ConntrackCache) bool {
	if localCache != nil {
		if _, ok := localCache[fp]; ok {
			return true
		}
	}
	conntrack := f.Conntrack
	conntrack.Lock()

	// Purge every time we test
	ep, has := conntrack.TimerWheel.Purge()
	if has {
		f.evict(ep)
	}

	c, ok := conntrack.Conns[fp]

	if !ok {
		conntrack.Unlock()
		return false
	}

	if c.rulesVersion != f.rulesVersion {
		// This conntrack entry was for an older rule set, validate
		// it still passes with the current rule set
		table := f.OutRules
		if c.incoming {
			table = f.InRules
		}

		// We now know which firewall table to check against
		if !table.match(fp, c.incoming, h.ConnectionState.peerCert, caPool) {
			if f.l.Enabled(context.Background(), slog.LevelDebug) {
				h.logger(f.l).Debug("dropping old conntrack entry, does not match new ruleset",
					"fwPacket", fp,
					"incoming", c.incoming,
					"rulesVersion", f.rulesVersion,
					"oldRulesVersion", c.rulesVersion,
				)
			}
			delete(conntrack.Conns, fp)
			conntrack.Unlock()
			return false
		}

		if f.l.Enabled(context.Background(), slog.LevelDebug) {
			h.logger(f.l).Debug("keeping old conntrack entry, does match new ruleset",
				"fwPacket", fp,
				"incoming", c.incoming,
				"rulesVersion", f.rulesVersion,
				"oldRulesVersion", c.rulesVersion,
			)
		}

		c.rulesVersion = f.rulesVersion
	}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		c.Expires = time.Now().Add(f.TCPTimeout)
	case firewall.ProtoUDP:
		c.Expires = time.Now().Add(f.UDPTimeout)
	default:
		c.Expires = time.Now().Add(f.DefaultTimeout)
	}

	conntrack.Unlock()

	if localCache != nil {
		localCache[fp] = struct{}{}
	}

	return true
}

func (f *Firewall) addConn(fp firewall.Packet, incoming bool) {
	var timeout time.Duration
	c := &conn{}

	switch fp.Protocol {
	case firewall.ProtoTCP:
		timeout = f.TCPTimeout
	case firewall.ProtoUDP:
		timeout = f.UDPTimeout
	default:
		timeout = f.DefaultTimeout
	}

	conntrack := f.Conntrack
	conntrack.Lock()
	if _, ok := conntrack.Conns[fp]; !ok {
		conntrack.TimerWheel.Advance(time.Now())
		conntrack.TimerWheel.Add(fp, timeout)
	}

	// Record which rulesVersion allowed this connection, so we can retest after
	// firewall reload
	c.incoming = incoming
	c.rulesVersion = f.rulesVersion
	c.Expires = time.Now().Add(timeout)
	conntrack.Conns[fp] = c
	conntrack.Unlock()
}

func TestFirewall_DropConntrackReload(t *testing.T) {
	ob := &bytes.Buffer{}
	l := test.NewLoggerWithOutput(ob)
	myVpnNetworksTable := new(bart.Lite)
	myVpnNetworksTable.Insert(netip.MustParsePrefix("1.1.1.1/8"))

	p := firewall.Packet{
		LocalAddr:  netip.MustParseAddr("1.2.3.4"),
		RemoteAddr: netip.MustParseAddr("1.2.3.4"),
		LocalPort:  10,
		RemotePort: 90,
		Protocol:   firewall.ProtoUDP,
		Fragment:   false,
	}
	network := netip.MustParsePrefix("1.2.3.4/24")

	c := cert.CachedCertificate{
		Certificate: &dummyCert{
			name:     "host1",
			networks: []netip.Prefix{network},
			groups:   []string{"default-group"},
			issuer:   "signer-shasum",
		},
		InvertedGroups: map[string]struct{}{"default-group": {}},
	}
	h := HostInfo{
		ConnectionState: &ConnectionState{
			peerCert: &c,
		},
		vpnAddrs: []netip.Addr{network.Addr()},
	}
	h.buildNetworks(myVpnNetworksTable, c.Certificate)

	fw := NewFirewall(l, time.Second, time.Minute, time.Hour, c.Certificate)
	require.NoError(t, fw.AddRule(true, firewall.ProtoAny, 0, 0, []string{"any"}, "", "", "", "", ""))
	cp := cert.NewCAPool()

	// Drop outbound
	assert.Equal(t, fw.Drop(p, false, &h, cp, nil), ErrNoMatchingRule)
	// Allow inbound
	resetConntrack(fw)
	require.NoError(t, fw.Drop(p, true, &h, cp, nil))
	// Allow outbound because conntrack
	require.NoError(t, fw.Drop(p, false, &h, cp, nil))

	oldFw := fw
	fw = NewFirewall(l, time.Second, time.Minute, time.Hour, c.Certificate)
	require.NoError(t, fw.AddRule(true, firewall.ProtoAny, 10, 10, []string{"any"}, "", "", "", "", ""))
	fw.Conntrack = oldFw.Conntrack
	fw.rulesVersion = oldFw.rulesVersion + 1

	// Allow outbound because conntrack and new rules allow port 10
	require.NoError(t, fw.Drop(p, false, &h, cp, nil))

	oldFw = fw
	fw = NewFirewall(l, time.Second, time.Minute, time.Hour, c.Certificate)
	require.NoError(t, fw.AddRule(true, firewall.ProtoAny, 11, 11, []string{"any"}, "", "", "", "", ""))
	fw.Conntrack = oldFw.Conntrack
	fw.rulesVersion = oldFw.rulesVersion + 1

	// Drop outbound because conntrack doesn't match new ruleset
	assert.Equal(t, fw.Drop(p, false, &h, cp, nil), ErrNoMatchingRule)
}
