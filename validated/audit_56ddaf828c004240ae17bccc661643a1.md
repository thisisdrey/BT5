### Title
Unbounded disk write via CreateRepositoryFromBundle bundle streaming causes storage-wide disk exhaustion - ([File: internal/gitaly/service/repository/create_repository_from_bundle.go])

### Summary
`CreateRepositoryFromBundle` streams client-supplied `Data` chunks directly into `Repo.createTempBundle`, which performs `io.Copy(file, reader)` with no maximum size, no context-based rate/size limiting, and no disk-space pre-check. Because this RPC creates a repository directly from an uploaded bundle rather than via `git-receive-pack`, it never triggers the `PreReceiveHook` / Rails `/internal/allowed` quota check that normally gates push-based repository growth, so an attacker-controlled arbitrarily-sized stream is written unchecked to the shared storage.

### Finding Description
The RPC handler `server.CreateRepositoryFromBundle` reads the first request to get `Repository`, validates it with `s.locator.ValidateRepository`, then wraps the remaining stream in a `streamio.NewReader` (`bundleReader`) with no length cap, and passes it into `repoutil.Create(...)` -> `Repo.CloneBundle` -> `Repo.createTempBundle`: [1](#0-0) 

`createTempBundle` creates a temp file under the target storage's temp directory and does an unbounded `io.Copy(file, reader)`: [2](#0-1) 

Unlike the standard git push path (`SSHReceivePack`/`PostReceivePack`), which invokes `GitLabHookManager.PreReceiveHook` to call Rails' `/internal/allowed` endpoint (where repository/namespace storage-size quotas are normally enforced) before objects are migrated out of quarantine, `CreateRepositoryFromBundle` performs no such call — it writes the bundle straight to a temp file and then `git clone --mirror`s it into place via `repoutil.Create`. See the hook-checked path for comparison: [3](#0-2) 

There is no gRPC `MaxRecvMsgSize` limiting total streamed bytes (repo has no such config), and `LimiterMiddleware`'s stream interceptor only throttles *concurrency* per repository/RPC, not the volume of bytes within a single stream: [4](#0-3) 

Thus an authenticated but otherwise unprivileged user who can invoke `CreateRepositoryFromBundle` for a repository path they are allowed to create can send an effectively unbounded amount of `Data` in a single RPC call, filling the shared storage's temp and repository directories, with no size cap, deadline-based abort, or disk-quota check intercepting the write.

### Impact Explanation
Filling the shared filesystem underlying a Gitaly storage causes subsequent writes to fail for every repository hosted on that storage/node (other users' pushes, replication, housekeeping, etc.), i.e. a storage-wide denial of service. This matches GitLab's DoS impact class for resource-exhaustion of a shared service component.

### Likelihood Explanation
The only precondition is the ability to call `RepositoryService.CreateRepositoryFromBundle` for a repository path the caller is authorized to create (e.g. via project import/fork flows that expose bundle import), which is available to any authenticated GitLab user with project-creation rights. The exploit requires no privilege escalation, no secrets, and is fully repeatable — the attacker just keeps streaming `Data` frames without closing the request stream.

### Recommendation
Enforce a maximum bundle/stream size (and/or a running disk-space check) before or during `createTempBundle`'s `io.Copy`, e.g. wrap the reader with `io.LimitReader` bound to a configurable maximum, check `unix.Statfs` free space periodically during the copy, and/or apply a request byte-rate/size limit in the gRPC stream interceptor for streaming write RPCs such as `CreateRepositoryFromBundle`, `CreateRepositoryFromSnapshot`, and `FetchBundle`.

func TestCreateRepositoryFromBundle_unboundedSize(t *testing.T) {
    ctx := testhelper.Context(t)
    cfg, client := setupRepositoryService(t)

    repo := &gitalypb.Repository{StorageName: cfg.Storages[0].Name, RelativePath: "attacker/repo.git"}

    stream, err := client.CreateRepositoryFromBundle(ctx)
    require.NoError(t, err)
    require.NoError(t, stream.Send(&gitalypb.CreateRepositoryFromBundleRequest{Repository: repo}))

    chunk := make([]byte, 4*1024*1024) // 4MB chunks
    for i := 0; i < 5000; i++ {        // stream ~20GB with no cap enforced
        require.NoError(t, stream.Send(&gitalypb.CreateRepositoryFromBundleRequest{Data: chunk}))

func (repo *Repo) createTempBundle(ctx context.Context, reader io.Reader) (bundlPath string, cleanup func(), returnErr error) {
	tmpDir, cleanup, err := tempdir.New(ctx, repo.GetStorageName(), repo.logger, repo.locator)
	if err != nil {
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}

	bundlePath := filepath.Join(tmpDir.Path(), "repo.bundle")

	file, err := os.Create(bundlePath)
	if err != nil {
		cleanup() // Clean up if we fail after creating the temp directory
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}
	defer func() {
		if err := file.Close(); err != nil && returnErr == nil {
			returnErr = fmt.Errorf("create temp bundle: %w", err)
		}
	}()

	if _, err = io.Copy(file, reader); err != nil {
		cleanup() // Clean up if we fail after creating the temp directory
		return "", nil, fmt.Errorf("create temp bundle: %w", err)
	}

	return bundlePath, cleanup, nil
}

func (w *wrappedStream) RecvMsg(m interface{}) error {
	if err := w.ServerStream.RecvMsg(m); err != nil {
		return err
	}

	// Only perform limiting on the first request of a stream
	if !w.initial {
		return nil
	}

	w.initial = false

	ctx := w.Context()

	lockKey := w.limiterMiddleware.getLockKey(ctx)
	if lockKey == "" {
		return nil
	}

	// Check if request is authenticated
	limiter := w.limiterMiddleware.methodLimiters[w.info.FullMethod]
	unauthLimiter, ok := w.limiterMiddleware.methodLimitersUnauthenticated[w.info.FullMethod]
	if !auth.IsAuthenticated(ctx) && ok {
		limiter = unauthLimiter
	}

	if limiter == nil {
		// No concurrency limiting
		return nil
	}
