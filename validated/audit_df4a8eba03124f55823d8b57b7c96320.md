### Title
Replayable proof-authenticated `set_personal_id_account`/`set_alias_account` transactions allow account-hijack of a person's dispatch origin - (File: `substrate/frame/people/src/extension.rs`)

### Summary
The `AsPerson` transaction extension authorizes `RawOrigin::None` extrinsics that call `set_personal_id_account` or `set_alias_account` using a cryptographic proof/signature bound only to the encoded call and a `call_valid_at` block number, with no nonce or single-use marker on the proof itself. Replay protection is implemented as a state-equality check ("is the target account already the stored account?") rather than a consumed/used-proof check, so any previously broadcast, still-in-window transaction can be resubmitted by anyone to flip a person's linked account back to an older value, hijacking the ability to dispatch as that person's `PersonalIdentity`/`PersonalAlias` origin.

### Finding Description
The extension defines two proof-authenticated variants: [1](#0-0) 

For `AsPersonalIdentityWithProof`, validation recovers a signature over `inherited_implication` (which commits to the call and other extensions), then applies this replay guard: [2](#0-1) 

The guard only rejects the transaction as `Stale` if the account currently stored for that `PersonalId` **already equals** the target `account` in the call. It does not track whether this specific proof/signature has ever been consumed. Consequently, if the record has since been changed to a different account, the exact same historical `(signature, index)` payload can be resubmitted (as long as `now <= call_valid_at + account_setup_time_tolerance`, checked here): [3](#0-2) 

The same pattern exists for `AsPersonalAliasWithProof`: [4](#0-3) 

Because these extrinsics use `RawOrigin::None` (no signer, no `CheckNonce`), the origin-authorization is carried entirely by the proof, and the proof carries no single-use nonce of its own — only a coarse block-range validity window shared by potentially many rebroadcasts. Any relayer, bystander, or MEV-style observer who has seen the original broadcast transaction (which is public, permissionless, and requires no fee since it can pay `Pays::No`) can resubmit it verbatim at any later point inside the tolerance window, and it will re-execute successfully in `set_personal_id_account`/`set_alias_account`: [5](#0-4) [6](#0-5) 

The repository's own tests confirm this is exploitable, not just theoretical: transaction 1 sets the account to `10`, transaction 2 (for a later time) sets it to `11`; after transaction 2 executes, replaying transaction 1 succeeds and resets the mapping back to `10`, and this toggling can repeat as long as both transactions remain within the tolerance window: [7](#0-6) [8](#0-7) 

The doc comments on the enum acknowledge a version of this weakness but understate the impact: they frame it as "reset to a previously-set account", without flagging that this directly re-grants that previous account the authority to dispatch calls as `Origin::PersonalIdentity`/`Origin::PersonalAlias` for that person — an unauthorized-origin outcome, since accounts are meant to be revocable when the person moves to a new controlling key/account.

### Impact Explanation
`AccountToPersonalId` / `AccountToAlias` control which `T::AccountId` may transact with the special `PersonalIdentity`/`PersonalAlias` origins via the account-based branches of the same extension: [9](#0-8) 

If a person rotates away from a compromised or no-longer-trusted account (e.g., after key exposure, or intentionally revoking a delegate/relayer), an attacker who retained a copy of the old proof-authenticated `set_personal_id_account`/`set_alias_account` transaction can replay it during the tolerance window to reinstate the old account's binding — effectively an unauthorized origin-escalation: the old account regains the capability to sign transactions "as" that person's identity/alias origin, which other pallets rely on for uniqueness/personhood guarantees (governance, sybil-resistance use-cases, etc., per the pallet's stated purpose). This matches the "unauthorized execution or origin escalation" impact category from the required-impacts gate, achieved purely via a public, permissionless extrinsic replay with no privileged actor involved.

### Likelihood Explanation
Exploitation requires no validator, collator, relayer trust, or governance action — only that the attacker previously observed a proof-bearing extrinsic (which is broadcast publicly, unsigned, and stored verbatim in blocks/mempool) and that the tolerance window (`account_setup_time_tolerance`, a runtime-configurable constant) has not fully elapsed relative to the transaction being replayed. Since these are `Pays::No`-eligible for the first association, an attacker bears little to no cost to keep resubmitting captured payloads whenever they observe the target performing a legitimate account rotation.

### Recommendation
Bind proof-authenticated account-setting extrinsics to a single-use domain, e.g., a monotonically increasing per-`PersonalId`/per-alias "setup nonce" or generation counter that is incremented on every successful `set_personal_id_account`/`set_alias_account`/`unset_*` call, and require the signed/proved message to include that counter (in addition to `call_valid_at`). Reject any proof whose embedded counter does not match the currently expected value, rather than only comparing the resulting stored account. This mirrors the `EIP-712`-style nonce fix recommended in the external report, adapted to this proof-based origin-authorization scheme.

### Proof of Concept
The existing test suite already demonstrates the mechanics of the replay; it treats the replay as accepted behavior, but the sequence itself is the PoC: [10](#0-9) 
1. Alice's `PersonalIdentity` proof-signs `set_personal_id_account(account=X)` at block `N` (`call_valid_at = N`), broadcast and included — attacker captures this extrinsic.
2. Alice legitimately rotates to `account=Y` with a new proof-signed transaction (`call_valid_at = N+1`), included after `account_setup_time_tolerance` elapses.
3. Attacker resubmits the captured extrinsic from step 1; because `People::<T>::get(index).account == Some(Y) != Some(X)`, the replay guard does not trigger `Stale`, and `set_personal_id_account` executes again, rebinding Alice's `PersonalIdentity` origin authority to `account=X`.
4. Attacker (controlling `account=X`) can now dispatch transactions with `Origin::PersonalIdentity(alice_index)` until Alice notices and rotates again, at which point the attacker can repeat the replay as long as it remains inside the tolerance window.

		pub fn set_alias_account(
			origin: OriginFor<T>,
			account: T::AccountId,
			call_valid_at: BlockNumberFor<T>,
		) -> DispatchResultWithPostInfo {
			let rev_ca = Self::ensure_revised_personal_alias(origin)?;
			let now = frame_system::Pallet::<T>::block_number();
			let time_tolerance = Self::account_setup_time_tolerance();
			ensure!(
				call_valid_at <= now && now <= call_valid_at.saturating_add(time_tolerance),
				Error::<T>::TimeOutOfRange
			);
			ensure!(T::AccountContexts::contains(&rev_ca.ca.context), Error::<T>::InvalidContext);
			ensure!(!AccountToPersonalId::<T>::contains_key(&account), Error::<T>::AccountInUse);

			let old_account = AliasToAccount::<T>::get(&rev_ca.ca);
			let old_rev_ca = old_account.as_ref().and_then(AccountToAlias::<T>::get);

			let needs_revision = old_rev_ca.is_some_and(|old_rev_ca| {
				old_rev_ca.revision != rev_ca.revision || old_rev_ca.ring != rev_ca.ring
			});

			// Ensure it changes the account associated, or it needs revision.
			ensure!(
				old_account.as_ref() != Some(&account) || needs_revision,
				Error::<T>::AliasAccountAlreadySet
			);

			// If the old account is different from the new one:
			// * decrease the sufficients of the old account
			// * increase the sufficients of the new account
			// * check new account is not already in use
			if old_account.as_ref() != Some(&account) {
				ensure!(!AccountToAlias::<T>::contains_key(&account), Error::<T>::AccountInUse);
				if let Some(old_account) = &old_account {
					frame_system::Pallet::<T>::dec_sufficients(old_account);
					AccountToAlias::<T>::remove(old_account);
				}
				frame_system::Pallet::<T>::inc_sufficients(&account);
			}

			AccountToAlias::<T>::insert(&account, &rev_ca);
			AliasToAccount::<T>::insert(&rev_ca.ca, &account);

			origin: OriginFor<T>,
			account: T::AccountId,
			call_valid_at: BlockNumberFor<T>,
		) -> DispatchResultWithPostInfo {
			let id = Self::ensure_personal_identity(origin)?;
			let now = frame_system::Pallet::<T>::block_number();
			let time_tolerance = Self::account_setup_time_tolerance();
			ensure!(
				call_valid_at <= now && now <= call_valid_at.saturating_add(time_tolerance),
				Error::<T>::TimeOutOfRange
			);
			ensure!(!AccountToPersonalId::<T>::contains_key(&account), Error::<T>::AccountInUse);
			ensure!(!AccountToAlias::<T>::contains_key(&account), Error::<T>::AccountInUse);
			let mut record = People::<T>::get(id).ok_or(Error::<T>::NotPerson)?;
			let pays = if let Some(old_account) = record.account {
				frame_system::Pallet::<T>::dec_sufficients(&old_account);
				AccountToPersonalId::<T>::remove(&old_account);
				Pays::Yes
			} else {
				Pays::No
			};
			record.account = Some(account.clone());
			frame_system::Pallet::<T>::inc_sufficients(&account);
			AccountToPersonalId::<T>::insert(&account, id);
			People::<T>::insert(id, &record);

#[test]
fn replay_protection_for_identity() {
	new_test_ext().execute_with(|| {
		const EXTENSION_VERSION: u8 = 0;
		// Setup alice as a member.
		let alice_sec = Simple::new_secret([1u8; 32]);
		let alice_pub = Simple::member_from_secret(&alice_sec);
		let alice_index = PeoplePallet::reserve_new_id();
		PeoplePallet::recognize_personhood(alice_index, Some(alice_pub)).unwrap();
		let generate_setup_account_tx_ext_for_call = |call: RuntimeCall| {
			let other_tx_ext = (frame_system::CheckNonce::<Test>::from(0),);
			// Here we simply ignore implicit as they are null.
			let msg = (&EXTENSION_VERSION, &call, &other_tx_ext)
				.using_encoded(sp_io::hashing::blake2_256);
			let signature = Simple::sign(&alice_sec, &msg).unwrap();
			(
				AsPerson::<Test>::new(Some(AsPersonInfo::AsPersonalIdentityWithProof(
					signature,
					alice_index,
				))),
				other_tx_ext.0,
			)
		};
		// Transaction 1: Alice sets its personal id account to 10.
		let call = RuntimeCall::PeoplePallet(crate::Call::set_personal_id_account {
			account: 10,
			call_valid_at: System::block_number(),
		});
		let tx_ext = generate_setup_account_tx_ext_for_call(call.clone());
		assert_ok!(exec_tx(None, tx_ext.clone(), call.clone()));
		assert_eq!(crate::People::<Test>::get(alice_index).unwrap().account, Some(10));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(10), Some(alice_index));
		// Somebody tries to replay the transaction, it must fail, replay is protected.
		assert_noop!(exec_tx(None, tx_ext.clone(), call.clone()), InvalidTransaction::Stale);
		// Transaction 2: Alice sets its personal id account to 11, with call valid only in the
		// future.
		let call_2 = RuntimeCall::PeoplePallet(crate::Call::set_personal_id_account {
			account: 11,
			call_valid_at: System::block_number() + 1,
		});
		let tx_ext_2 = generate_setup_account_tx_ext_for_call(call_2.clone());
		// Transaction 2 is not valid yet.
		assert_noop!(exec_tx(None, tx_ext_2.clone(), call_2.clone()), InvalidTransaction::Future);
		assert_eq!(crate::People::<Test>::get(alice_index).unwrap().account, Some(10));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(10), Some(alice_index));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(11), None);
		// Advance some time. Transaction 1 is still valid, transaction 2 becomes valid.
		mock::advance_to(System::block_number() + PeoplePallet::account_setup_time_tolerance());
		// Transaction 2 is now valid.
		assert_ok!(exec_tx(None, tx_ext_2.clone(), call_2.clone()));
		assert_eq!(crate::People::<Test>::get(alice_index).unwrap().account, Some(11));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(11), Some(alice_index));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(10), None);
		// Somebody replays the transaction 1, it must succeed. It is within time tolerance.
		assert_ok!(exec_tx(None, tx_ext.clone(), call.clone()));
		assert_eq!(crate::People::<Test>::get(alice_index).unwrap().account, Some(10));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(10), Some(alice_index));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(11), None);
		// Replay the transaction 2.
		assert_ok!(exec_tx(None, tx_ext_2.clone(), call_2.clone()));
		assert_eq!(crate::People::<Test>::get(alice_index).unwrap().account, Some(11));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(11), Some(alice_index));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(10), None);
		// Advance some time, Now time tolerance is exceeded for transaction 1.
		mock::advance_to(System::block_number() + 1);
		// Somebody replays the first transaction, it is invalid.
		assert_noop!(exec_tx(None, tx_ext, call), InvalidTransaction::Stale);
		assert_eq!(crate::People::<Test>::get(alice_index).unwrap().account, Some(11));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(11), Some(alice_index));
		assert_eq!(crate::AccountToPersonalId::<Test>::get(10), None);
	});
}
