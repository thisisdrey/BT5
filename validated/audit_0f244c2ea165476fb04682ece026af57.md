Confirmed: `libsigner/src/events.rs` contains no `Authorization`/`auth_token` check anywhere in `SignerEventReceiver`, `next_event`, or `process_event`. Authentication of the node↔signer channel exists only for the *node's* RPC surface (`auth_token`/`auth_password` in `[connection_options]`), not for this inbound HTTP listener that the signer binds to receive event-observer pushes.

### Title
Unauthenticated `/new_block` HTTP endpoint lets any TCP peer forge a "processed block" event that is written into signer state - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` routes any POST to `/new_block` straight into `process_event::<T, StacksBlockEvent>`, which JSON-deserializes attacker-controlled fields and maps them verbatim via `TryFrom<StacksBlockEvent> for SignerEvent<T>` into `SignerEvent::NewBlock`, with no signature, secret, or chainstate-consistency check anywhere in the path. The signer runloop (`stacks-signer/src/v0/signer.rs`) consumes this event and unconditionally calls `signer_db.block_lookup(signer_sighash)` / `block_info.mark_globally_accepted()` / `signer_db.insert_block(...)`, writing attacker-asserted "globally accepted" status into local signer state.

### Finding Description
The broken equality: the runloop treats `(block_id, consensus_hash, signer_sighash)` in a `NewBlock` event as proof that the local node's chainstate actually processed that block, but `TryFrom<StacksBlockEvent> for SignerEvent<T>` at `libsigner/src/events.rs:708-720` copies these fields directly from attacker JSON with zero validation:
```
libsigner/src/events.rs:711-719
fn try_from(block_event: StacksBlockEvent) -> Result<Self, Self::Error> {
    Ok(SignerEvent::NewBlock {
        signer_sighash: block_event.signer_signature_hash,
        block_id: block_event.index_block_hash,
        consensus_hash: block_event.consensus_hash,
        block_height: block_event.block_height,
        transactions: block_event.transactions,
    })
}
```
`process_event` (`libsigner/src/events.rs:519-542`) performs no authentication check before this conversion — it only reads the body, ACKs, and calls `serde_json::from_slice`. `next_event` (`libsigner/src/events.rs:413-459`) dispatches `POST /new_block` to `process_event::<T, StacksBlockEvent>` with the same lack of gating as every other route on this listener; there is no bearer-token/secret check anywhere in `SignerEventReceiver`.

Downstream, `stacks-signer/src/v0/signer.rs:675-726` treats a delivered `NewBlock` event as ground truth: it calls `self.local_state_machine.stacks_block_arrival(...)` (updating the tracked parent-tenure/last-block view) and, if `signer_db.block_lookup(signer_sighash)` finds a matching entry (e.g. a block this signer previously proposed/validated but has not yet seen finalized), it calls `block_info.mark_globally_accepted()` and persists it via `signer_db.insert_block(&block_info)`. `signer_sighash` values are not secret — they are gossiped in cleartext over the public `.miners`/signer StackerDB contracts, so any party who can observe those chunks can learn a valid, in-flight sighash to forge.

Exploit flow: attacker connects to the signer's event-receiver TCP port and POSTs a JSON body shaped as `StacksBlockEvent` (`index_block_hash`, `consensus_hash`, `block_hash`, `block_height`, `signer_signature_hash` copied from an observed real block proposal, `transactions: []`) to `/new_block`. This is accepted, converted into `SignerEvent::NewBlock`, forwarded to the runloop, and marks the corresponding block as `GloballyAccepted` in `signerdb` without the node ever having actually processed it.

Existing guards fail because: (1) there is no `MAX_MESSAGE_LEN`-style or auth check on this listener at all — the `auth_token` mechanism protects the node's outbound RPC calls, not this inbound push endpoint; (2) there is no cross-check between `index_block_hash`/`consensus_hash` and any locally-verified chainstate header before constructing `SignerEvent::NewBlock`; (3) the only gate downstream (`block_lookup(signer_sighash)`) uses a value that is public knowledge, not a secret.

### Impact Explanation
An unauthenticated remote party who can reach the signer's event-receiver socket can force the signer to write a false "globally accepted" status for a real, pending, but not-yet-confirmed block into `signerdb`, and to update its `LocalStateMachine`'s view of the current tenure's last block. This is an unauthenticated write to signer state that misrepresents non-canonical/unconfirmed information as node-confirmed canonical fact, matching the High/"serving non-canonical state as canonical" category (arguably Critical as it is an unauthenticated write to persistent state). It is trivially repeatable per message and requires no per-attempt cost beyond one HTTP POST.

### Likelihood Explanation
Preconditions: TCP reachability to the signer's bound event-receiver address and knowledge of one currently-outstanding `signer_signature_hash` (obtainable by observing public StackerDB block-proposal gossip). No node RPC secret, peer key, or StackerDB slot ownership is required for the `/new_block` write itself. Reachability depends on deployment: sample configs (`sample/conf/*-signer.toml`, `mainnet-signer.toml`) bind this endpoint to `127.0.0.1:30000` by default, so exploitation from a genuinely remote, unprivileged network attacker is deployment-dependent (it requires the operator to expose this port beyond loopback, e.g. running node and signer on separate hosts with the listener bound to a non-loopback interface). Where that condition holds, the attack is fully unauthenticated and repeatable.

### Recommendation
Require an authenticated channel for the signer's event-receiver HTTP server (e.g., shared-secret bearer token checked in `next_event`/`process_event`, mirroring the node's `auth_token`), and/or bind by default strictly to loopback with an explicit opt-in warning for non-loopback exposure. Additionally, before trusting a `NewBlock` event, cross-check `index_block_hash`/`consensus_hash`/`block_height` against the signer's own view of chainstate obtained via authenticated RPC to the paired node, rather than trusting the pushed payload verbatim.

fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
