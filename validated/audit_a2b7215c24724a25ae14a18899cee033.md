### Title
Zero-Vote Cycle Rewards Are Silently Forfeited With No Recovery Mechanism - (File: chainbase/src/main/java/org/tron/core/store/DelegationStore.java)

### Summary
Analogous to the Debita `DebitaIncentives.sol` bug where incentive tokens deposited for a future epoch become permanently unclaimable if that epoch sees zero qualifying activity, java-tron's Super Representative (SR) vote-reward accounting permanently forfeits a witness's per-cycle voter reward whenever the witness has zero recorded votes in that cycle. The reward amount is committed to the cycle's reward bucket via `DelegationStore.addReward` [1](#0-0) , but `accumulateWitnessVi` simply skips folding that reward into the running Vi index when `voteCount == 0`, causing the reward to be dropped forever rather than rolled forward or otherwise redistributed [2](#0-1) .

### Finding Description
Block and transaction-fee rewards for a witness are recorded per-cycle in `MortgageService.payReward`, which reduces the reward by a brokerage cut (paid out immediately to the witness) and stores the remainder for voters via `delegationStore.addReward(cycle, witnessAddress, value)` [3](#0-2) .

Voters later claim their share of this reward through a "Vi" (value-index) accumulation model. `DelegationStore.accumulateWitnessVi` (and its duplicate implementation in `RewardViCalService.accumulateWitnessVi`) computes the delta-Vi for a cycle by dividing the recorded reward by the number of votes cast for that witness in that cycle:

```java
public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
  BigInteger preVi = getWitnessVi(cycle - 1, address);
  long reward = getReward(cycle, address);
  if (reward == 0 || voteCount == 0) { // Just forward pre vi
    if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
      setWitnessVi(cycle, address, preVi);
    }
  } else { // Accumulate delta vi
    ...
  }
}
``` [2](#0-1) 

When `voteCount == 0` for that cycle — i.e., "zero activity" analogous to the Debita epoch with no lending/borrowing — the reward previously credited via `addReward` is never folded into the Vi index. It is neither carried forward to a future cycle nor made claimable by any account; the `preVi` is simply forwarded unchanged, and the specific `reward` value for that cycle becomes permanently orphaned in the `DelegationStore`. `VoteRewardUtil.withdrawReward` (the TVM-facing withdrawal path for smart-contract-based voting) and `MortgageService.withdrawReward` (the wallet/API-facing path) both compute claimable rewards purely from the delta between `beginVi` and `endVi` [4](#0-3) [5](#0-4) , so a cycle whose Vi delta is zero because of the zero-vote skip can never be recovered by any voter or the SR itself, and there is no administrative or automatic reallocation mechanism for the stranded reward key (`cycle-address-reward` in `DelegationStore`).

This is directly reachable by unprivileged flow: any account can vote for/against an SR via the standard vote actuator, any account's transaction generates fees that feed `payTransactionFeeReward`, and any account can withdraw rewards via `WithdrawRewardContract`/`WithdrawRewardProcessor` [6](#0-5) . No privileged/malicious-SR action is required — the condition (a witness having zero recorded votes in a given cycle, e.g., right after election or after all voters unvote) can occur under normal network activity.

### Impact Explanation
The affected value is real economic value: block rewards and transaction fee rewards that have already been allocated (deducted from the fee/reward pool) to a specific witness's cycle bucket. When the zero-vote condition triggers, that value is stranded in the store forever — it does not return to any account's balance, is not burned through the accounted burn path, and is not credited to the witness or the SR's brokerage. This constitutes a permanent, protocol-level freezing/loss of reward funds with no code path to recover them, matching the "permanent freezing of funds" impact criteria.

### Likelihood Explanation
The zero-vote-in-a-cycle condition is a realistic operating scenario rather than an adversarial edge case: it occurs whenever a witness produces blocks (and thus accrues cycle rewards) in a cycle where it temporarily has zero votes recorded (e.g., right after all voters withdrew/re-cast votes, or timing edge cases around the maintenance/cycle boundary where `getWitnessVote` returns 0 for that specific cycle key). No special privileges, malicious actors, or unusual configuration are required to reach this state — it flows naturally out of ordinary voting/reward operations executed by unprivileged accounts.

### Recommendation
Add a recovery/redistribution mechanism for cycle rewards whose `voteCount` is zero: either (a) roll the un-distributable reward forward into the next cycle's reward pool for the same witness instead of discarding it, or (b) redirect it to a community/burn pool with an auditable trail, ensuring the sum of `addReward` calls always remains fully backed and eventually reachable by some claimable path.

### Proof of Concept
Conceptual trace (backed by code, not executed):
1. Witness `W` produces a block; `MortgageService.payBlockReward` calls `payReward`, which calls `delegationStore.addReward(cycle=N, W, value)` [3](#0-2) .
2. No account has a recorded vote for `W` in cycle `N` (`getWitnessVote(N, W) == 0`).
3. During Vi accumulation for cycle `N`, `accumulateWitnessVi` hits `voteCount == 0` branch and does not fold `reward` into Vi [2](#0-1) .
4. Any future voter's `withdrawReward`/`queryReward` call computes rewards strictly from Vi deltas across cycles they voted, so the cycle-`N` reward for `W` can never be included in any computation [5](#0-4) .
5. The `cycle-N-W-reward` entry remains in `DelegationStore` indefinitely with no consumer — funds permanently stranded.

  private long computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    long newAlgorithmCycle = dynamicPropertiesStore.getNewRewardAlgorithmEffectiveCycle();
    List<Pair<byte[], Long>> srAddresses = accountCapsule.getVotesList().stream()
        .map(vote -> new Pair<>(vote.getVoteAddress().toByteArray(), vote.getVoteCount()))
        .collect(Collectors.toList());
    if (beginCycle < newAlgorithmCycle) {
      long oldEndCycle = min(endCycle, newAlgorithmCycle,
          dynamicPropertiesStore.disableJavaLangMath());
      reward = getOldReward(beginCycle, oldEndCycle, srAddresses);
      beginCycle = oldEndCycle;
    }
    if (beginCycle < endCycle) {
      for (Pair<byte[], Long>  vote : srAddresses) {
        byte[] srAddress = vote.getKey();
        BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
        BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
        BigInteger deltaVi = endVi.subtract(beginVi);
        if (deltaVi.signum() <= 0) {
          continue;
        }
        long userVote = vote.getValue();
        reward += deltaVi.multiply(BigInteger.valueOf(userVote))
            .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
      }
    }
    return reward;
  }

  private static long computeReward(long beginCycle, long endCycle,
                                    AccountCapsule accountCapsule, Repository repository) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    for (Protocol.Vote vote : accountCapsule.getVotesList()) {
      byte[] srAddress = vote.getVoteAddress().toByteArray();
      BigInteger beginVi = repository.getDelegationStore().getWitnessVi(beginCycle - 1, srAddress);
      BigInteger endVi = repository.getDelegationStore().getWitnessVi(endCycle - 1, srAddress);
      BigInteger deltaVi = endVi.subtract(beginVi);
      if (deltaVi.signum() <= 0) {
        continue;
      }
      long userVote = vote.getVoteCount();
      reward += deltaVi.multiply(BigInteger.valueOf(userVote))
          .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
    }
    return reward;
  }

  public long execute(WithdrawRewardParam param, Repository repo) throws ContractExeException {
    byte[] ownerAddress = param.getOwnerAddress();

    VoteRewardUtil.withdrawReward(ownerAddress, repo);

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    long oldBalance = accountCapsule.getBalance();
    long allowance = accountCapsule.getAllowance();
    long newBalance = 0;

    try {
      newBalance = LongMath.checkedAdd(oldBalance, allowance);
    } catch (ArithmeticException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractExeException(e.getMessage());
    }

    // If no allowance, do nothing and just return zero.
    if (allowance <= 0) {
      return 0;
    }

    accountCapsule.setInstance(accountCapsule.getInstance().toBuilder()
        .setBalance(newBalance)
        .setAllowance(0L)
        .setLatestWithdrawTime(param.getNowInMs())
        .build());

    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
    return allowance;
  }
