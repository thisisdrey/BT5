### Title
Unstaked connection cap bypass via self-signed-pubkey churn lets a single attacker monopolize the unstaked `ConnectionTable`, starving legitimate unstaked senders' TPU ingress - ([File: streamer/src/nonblocking/swqos.rs])

### Finding Description
`SwQos::prune_unstaked_connections_and_add_new_connection` calls `prune_unstaked_connection_table`, which only prunes when `unstaked_connection_table.total_size >= max_unstaked_connections`, evicting down to 90% capacity via `ConnectionTable::prune_oldest`. [1](#0-0) 

`prune_oldest` removes the entire keyed group (`self.table` entry) whose connections have the globally-minimum `last_update`, i.e. an LRU-style eviction across all keys in the table: [2](#0-1) 

Critically, `try_add_connection` indexes entries by `ConnectionTableKey::new(ip, remote_pubkey)`, which resolves to `Pubkey(pubkey)` whenever a client presents a pubkey (Solana QUIC clients always present a self-signed TLS certificate, from which a pubkey is extracted regardless of stake), falling back to `IP(ip)` only if no pubkey is available: [3](#0-2) 

The per-peer connection cap (`max_connections_per_unstaked_peer`) is enforced only *within* a single key's `Vec<ConnectionEntry>` in `try_add_connection`: [4](#0-3) 

This means the "per source" cap is actually "per self-signed pubkey," not per network identity. The repo's own test `test_prune_table_with_unique_pubkeys` demonstrates this: 15 connections using 15 distinct, freely-generated pubkeys are *all* accepted even though `max_connections_per_peer = 10`, because each pubkey gets its own key/slot in the table: [5](#0-4) 

An unprivileged, unstaked attacker can generate a fresh Ed25519 keypair for every QUIC connection attempt at negligible cost, present it as the client's self-signed cert, connect, and immediately drop the connection. Each new connection creates a brand-new keyed entry with `last_update = timing::timestamp()` set to "now" at connect time: [6](#0-5) 

Because `prune_oldest` always evicts the group with the *oldest* `last_update`, and the attacker's freshly-churned entries are always the newest in the table, the attacker's own entries are never selected for eviction. Instead, every time the table is pruned to 90% capacity, legitimate unstaked peers' older/less-frequently-refreshed entries are evicted first — even though those legitimate peers may hold far fewer connections in aggregate than the attacker has churned through over time. The `max_connections_per_unstaked_peer` guard does not stop this because it is scoped to a single pubkey/IP key, not the actual originating network identity, and pubkey identity is free and unauthenticated for unstaked clients.

### Impact Explanation
This is a QoS-evasion / connection-table-residency denial issue: a single unprivileged, unstaked attacker can, by rotating self-signed pubkeys per connection, occupy or repeatedly clear out slots in the shared unstaked `ConnectionTable` faster than the per-peer cap intends, causing legitimate unstaked senders' `ConnectionEntry`s to be preferentially evicted by `prune_oldest`. This denies legitimate unstaked transaction senders admission to the TPU QUIC pipeline, preventing their transactions from reaching sigverify/banking and ultimately `Poh::record`. It matches the "QoS evasion" bounty category: connection/stream limits meant to be enforced per network source can be evaded through connection identity churn.

### Likelihood Explanation
Fully feasible for an unstaked, unprivileged attacker: no stake, no special network position, and no leaked keys are required — only the ability to generate new keypairs (essentially free) and open/drop QUIC connections faster than legitimate unstaked peers reconnect or refresh activity. This requires sustained connection churn from the attacker but no cooperation from any validator/operator and no config changes.

### Recommendation
Key `ConnectionTable` entries (and enforce `max_connections_per_unstaked_peer`) by the actual network source (e.g., IP address) rather than by an unauthenticated, freely-rotatable self-signed pubkey for unstaked connections, since pubkey identity carries no stake/authentication weight for unstaked peers. Additionally, consider rate-limiting new-connection admission per source IP independent of the per-key connection count, and/or weighting `prune_oldest`/`prune_random` selection to account for total connections contributed by a given IP over a recent time window rather than only the most recent `last_update` timestamp of each key group.

### Proof of Concept
Extend the existing `test_prune_table_with_unique_pubkeys` test in `streamer/src/nonblocking/quic.rs` (test module, lines ~1732-1770) into an eviction-fairness test:

```rust
#[test]
fn test_prune_oldest_pubkey_churn_evasion() {
    agave_logger::setup();
    let cancel = CancellationToken::new();
    let mut table = ConnectionTable::new(ConnectionTableType::Unstaked, cancel);
    let stats = Arc::new(StreamerStats::default());
    let max_connections_per_peer = 10;

    // Legitimate peer: connects once early, with an old last_update timestamp.
    let legit_pubkey = Pubkey::new_unique();
    table.try_add_connection(
        ConnectionTableKey::Pubkey(legit_pubkey), 0,
        ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
        None, ConnectionPeerType::Unstaked,
        Arc::new(AtomicU64::new(0)), // oldest timestamp
        max_connections_per_peer, || Arc::new(NullStreamerCounter {}),
    ).unwrap();

    // Attacker churns: repeatedly adds a NEW pubkey with a strictly increasing
    // (newer) last_update, simulating open-and-drop connection churn.
    for i in 1..=50u64 {
        let churn_pubkey = Pubkey::new_unique();
        table.try_add_connection(
            ConnectionTableKey::Pubkey(churn_pubkey), 0,
            ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
            None, ConnectionPeerType::Unstaked,
            Arc::new(AtomicU64::new(i)), // always newest
            max_connections_per_peer, || Arc::new(NullStreamerCounter {}),
        ).unwrap();
    }

    // Simulate prune_unstaked_connection_table triggering at capacity.
    let max_unstaked_connections = 30;
    let target = (0.90_f64 * max_unstaked_connections as f64) as usize;
    table.prune_oldest(target);

    // Assertion demonstrating the bug: the single legitimate long-standing
    // peer is evicted first, despite the attacker holding many more total
    // slots (one per churned pubkey) than any single legitimate sender.
    assert!(
        table.table.get(&ConnectionTableKey::Pubkey(legit_pubkey)).is_none(),
        "legitimate unstaked peer was evicted first due to attacker pubkey churn, \
         even though attacker occupies far more table slots overall"
    );
}
```

Expected result: the assertion passes, confirming that `prune_oldest`'s pure LRU-by-`last_update` semantics combined with per-pubkey keying in `try_add_connection` let an attacker's continuously-refreshed churned entries survive while a legitimate, less-active unstaked peer's entry is evicted — demonstrating the QoS/cap evasion described.

    pub(crate) fn prune_oldest(&mut self, max_size: usize) -> usize {
        let mut num_pruned = 0;
        let key = |(_, connections): &(_, &Vec<_>)| {
            connections.iter().map(ConnectionEntry::last_update).min()
        };
        while self.total_size.saturating_sub(num_pruned) > max_size {
            match self.table.values().enumerate().min_by_key(key) {
                None => break,
                Some((index, connections)) => {
                    num_pruned += connections.len();
                    self.table.swap_remove_index(index);
                }
            }
        }
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

    #[test]
    fn test_prune_table_with_unique_pubkeys() {
        agave_logger::setup();
        let cancel = CancellationToken::new();
        let mut table = ConnectionTable::new(ConnectionTableType::Unstaked, cancel);

        // We should be able to add more entries than max_connections_per_peer, since each entry is
        // from a different peer pubkey.
        let num_entries = 15;
        let max_connections_per_peer = 10;
        let stats = Arc::new(StreamerStats::default());

        let pubkeys: Vec<_> = (0..num_entries).map(|_| Pubkey::new_unique()).collect();
        for (i, pubkey) in pubkeys.iter().enumerate() {
            table
                .try_add_connection(
                    ConnectionTableKey::Pubkey(*pubkey),
                    0,
                    ClientConnectionTracker::new(stats.clone(), 1000).unwrap(),
                    None,
                    ConnectionPeerType::Unstaked,
                    Arc::new(AtomicU64::new(i as u64)),
                    max_connections_per_peer,
                    || Arc::new(NullStreamerCounter {}),
                )
                .unwrap();
        }

        let new_size = 3;
        let pruned = table.prune_oldest(new_size);
        assert_eq!(pruned, num_entries as usize - new_size);
        assert_eq!(table.table.len(), new_size);
        assert_eq!(table.total_size, new_size);
