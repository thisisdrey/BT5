### Title
No Origin/Authentication Check on the Signer's Event-Receiver HTTP Endpoint — Forged Node Events Accepted - (File: `libsigner/src/events.rs`)

### Summary
`SignerEventReceiver::next_event` (`libsigner/src/events.rs:413-459`) accepts any HTTP POST to `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block` and deserializes the body directly into a `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` with no check of who sent the request. [1](#0-0)  This is the analog of the droppy CSRF class: a privileged listener performs a state-changing action (forwarding "authoritative" node events into the signer's decision pipeline) purely on the basis of "a POST arrived at this path," with no equality check between "came from my paired stacks-node" and "came from anyone who can reach the socket."

### Finding Description
The event flow is: `stacks-node`'s `EventDispatcher` POSTs JSON payloads to the configured `events_observer.endpoint` (e.g. `send_stackerdb_chunks`, which POSTs to `PATH_STACKERDB_CHUNKS`) [2](#0-1) . The receiving side is `SignerEventReceiver`, a bare `tiny_http::HttpServer` bound to the configured `endpoint` [3](#0-2) .

`next_event` only branches on `request.url()` and `request.method()`; there is no header, token, or peer-address check anywhere in this function or in `process_event`: [4](#0-3) 
`process_event` reads the raw body and deserializes it straight into the event type, then converts it into a `SignerEvent` and forwards it to the signer runloop via channel — again with no authentication step: [5](#0-4) 

Compare this to the *node*-side endpoint that receives requests *from* the signer (`postblock_proposal.rs`), which the `sample/conf/*.toml` files describe as being protected by a shared `auth_token`/`auth_password` pair configured under `[connection_options]` / signer's `auth_password` [6](#0-5) [7](#0-6) . That token exists specifically to authenticate the signer→node direction of block-proposal-validation requests. There is no equivalent mechanism protecting the node→signer direction (the event-observer POSTs handled by `SignerEventReceiver`): the signer's listener has no shared-secret or token check at all in `libsigner/src/events.rs`.

The reference `endpoint` value for the signer's own listener in the shipped sample config is not loopback-restricted: `endpoint = "0.0.0.0:30000"` in `sample/conf/signer/mainnet-signer-conf.toml`, meaning the listener is documented/expected to potentially be reachable beyond localhost [8](#0-7) .

This breaks the equality "message purportedly from the paired stacks-node" vs. "message actually originated from the paired stacks-node" — any host that can reach the signer's bound TCP port can submit forged `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `new_block` payloads that are treated identically to genuine ones from the node, and fed straight into the signer's downstream processing.

### Impact Explanation
An unauthenticated remote party who can reach the signer's event port can inject arbitrary, attacker-controlled `SignerEvent`s (forged StackerDB chunk notifications, forged block-validation responses, forged burn-block/new-block notifications) into the signer's processing pipeline as if they came from the legitimate node. Because these events are the primary inputs that drive the signer's subsequent behavior, this is an unauthenticated write into the signer's event stream — the network-facing analog of "unauthenticated/unauthorized write to state." The exact downstream consequence of a forged event (e.g., how it influences a signing decision) lives in the signer decision logic, which is explicitly out of scope for this analysis, so I cannot assert a specific vote/signature outcome — but the root-cause transport defect (unauthenticated acceptance of privileged event payloads) is squarely in scope and is High/Critical-adjacent depending on deployment (bind address).

### Likelihood Explanation
This requires no privileged credentials and no knowledge of any secret — only network reachability to the signer's HTTP listener port, which per the sample/reference config is documented as bound to `0.0.0.0` rather than `127.0.0.1`. Any deployment following the reference config without an additional firewall/reverse-proxy in front of the signer's event port is exposed. This is not a volumetric/DDoS issue; a single crafted POST suffices.

### Recommendation
Add an authentication check to `SignerEventReceiver`/`process_event` analogous to the `auth_token` mechanism already used to protect the node's `postblock_proposal` endpoint — e.g., require and verify a shared-secret header (or HMAC over the body) on every incoming POST before deserializing/forwarding the payload, and reject/log unauthenticated requests. Additionally, default the sample/reference signer `endpoint` to a loopback address and document that binding to `0.0.0.0` requires equivalent network-level access control.

### Proof of Concept
1. Configure a signer per `sample/conf/signer/mainnet-signer-conf.toml` with `endpoint = "0.0.0.0:30000"`.
2. From a remote host, `curl -X POST http://<signer-ip>:30000/stackerdb_chunks -d '<forged StackerDBChunksEvent JSON>'`.
3. `SignerEventReceiver::next_event` accepts the request (no auth check), `process_event::<T, StackerDBChunksEvent>` deserializes it, and `forward_event` places the forged `SignerEvent` on the channel consumed by the signer runloop — indistinguishable from an event genuinely sent by the paired stacks-node.     fn next_event(&mut self) -> Result<SignerEvent<T>, EventError> {
```rust
        self.with_server(|event_receiver, http_server, _is_mainnet| {
            // were we asked to terminate?
            if event_receiver.is_stopped() {
                return Err(EventError::Terminated);
            }
            debug!("Request handling");
            let request = http_server.recv()?;
            debug!("Got request"; "method" => %request.method(), "path" => request.url());

            if request.url() == "/status" {
                request
                .respond(HttpResponse::from_string("OK"))
                .expect("response failed");
                return Ok(SignerEvent::StatusCheck);
            }

            if request.method() != &HttpMethod::Post {
                return Err(EventError::MalformedRequest(format!(
                    "Unrecognized method '{}'",
                    request.method(),
                )));
            }
            debug!("Processing {} event", request.url());
            if request.url() == "/stackerdb_chunks" {
                process_event::<T, StackerDBChunksEvent>(request)
            } else if request.url() == "/proposal_response" {
                process_event::<T, BlockValidateResponse>(request)
            } else if request.url() == "/new_burn_block" {
                process_event::<T, BurnBlockEvent>(request)
            } else if request.url() == "/shutdown" {
                event_receiver.stop_signal.store(true, Ordering::SeqCst);
                Err(EventError::Terminated)
            } else if request.url() == "/new_block" {
                process_event::<T, StacksBlockEvent>(request)
            } else {
                let url = request.url().to_string();
                debug!(
                    "[{:?}] next_event got request with unexpected url {}, return OK so other side doesn't keep sending this",
                    event_receiver.local_addr,
                    url
                );
                ack_dispatcher(request);
                Err(EventError::UnrecognizedEvent(url))
            }
        })?
    }
```

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
