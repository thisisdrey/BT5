### Title
Unauthenticated `/shutdown` request permanently kills `SignerEventReceiver::main_loop` - ([File: libsigner/src/events.rs])

### Summary
`SignerEventReceiver::next_event` treats any HTTP POST to `/shutdown` on the signer's event-receiver socket as a legitimate stop command, with no check that the sender is the trusted node. Since the endpoint address is configured to accept connections from the network, any remote party that can reach the port can send a single unauthenticated request to permanently terminate the receiver's `main_loop`, cutting off all future StackerDB chunks, burn block events, and proposal responses.

### Finding Description
In `libsigner/src/events.rs`, the `next_event` match arm for `/shutdown` performs the control action unconditionally: [1](#0-0) 

There is no verification of source IP, no shared secret, no signature, and no session/auth token gating this branch — contrast this with the legitimate `SignerStopSignaler::send`, which is only ever invoked in-process by the signer's own shutdown logic and just happens to use the same unauthenticated HTTP request format to signal itself over loopback: [2](#0-1) 

Once `stop_signal` is set, `next_event` returns `Err(EventError::Terminated)`, which is the *only* error variant in `EventReceiver::main_loop` that causes an unconditional `break` (all other errors just `continue` the loop): [3](#0-2) 

There is no restart logic elsewhere that respawns `main_loop` after this break — the thread simply exits, and the event receiver is dead for the lifetime of the process. The `/status` endpoint check ahead of this branch confirms unauthenticated GET/POST traffic is expected to reach this handler, and there is no earlier middleware or gate in `next_event` that filters by peer identity before dispatching on `request.url()`.

### Impact Explanation
A single unauthenticated TCP client that can reach the signer's event-receiver port can permanently stop the signer from receiving any further events forwarded by the node: StackerDB chunk updates (signer/miner messages), new burn block notifications, and block proposal validation responses. This effectively removes the signer from Nakamoto block signing without any further attacker interaction, and is not self-healing since there is no watchdog to restart `main_loop`. This matches the Critical category ("remote crash/unauthenticated DoS from few messages") since it is a single-message, unauthenticated denial of service against a control-plane action.

### Likelihood Explanation
The only precondition is TCP reachability to the signer's configured event-receiver listen address/port — no secret, peer key, or StackerDB slot ownership is required. The attack is a single raw HTTP POST with no body, so attacker cost is negligible and the action is trivially repeatable (though a single successful message is sufficient to cause permanent effect). Whether this is practically remotely exploitable depends on whether the signer's operator binds this endpoint to `0.0.0.0`/a routable interface versus `127.0.0.1`; the code itself enforces no binding restriction or authentication, so exploitability is solely a function of deployment/network exposure, which is out of this file's control but is a realistic default risk for any operator that exposes the endpoint beyond loopback (e.g., in containerized/multi-host signer deployments where the node and signer run on separate hosts, which is a supported and common configuration).

### Recommendation
Require authentication before honoring `/shutdown` (and ideally all state-mutating endpoints): e.g., check the request's source against a configured trusted node address, or require a shared secret/HMAC header that only the paired node knows, mirroring the auth mechanisms used elsewhere in the RPC surface. At minimum, restrict the shutdown action to loopback-originated requests when the local stop-signaler pattern is used, and document/enforce that operators bind the event-receiver port to a private/loopback interface only.

### Proof of Concept
```rust
// libsigner/src/events.rs (or a new integration test)
use std::io::Write;
use std::net::{SocketAddr, TcpStream};
use std::sync::mpsc::channel;

use crate::{EventReceiver, SignerEventReceiver, SignerEvent, EventError};

#[test]
fn unauthenticated_shutdown_kills_receiver() {
    let mut receiver: SignerEventReceiver<SomeSignerMessageType> = SignerEventReceiver::new(false);
    let addr: SocketAddr = "127.0.0.1:0".parse().unwrap();
    let bound = receiver.bind(addr).unwrap();

    // Attacker: bare POST /shutdown, no auth header, no body
    let mut stream = TcpStream::connect(bound).unwrap();
    let req = "POST /shutdown HTTP/1.1\r\nHost: x\r\nConnection: close\r\nContent-Length: 0\r\n\r\n";
    stream.write_all(req.as_bytes()).unwrap();

    // Drive next_event once: should return Err(Terminated) and set stop_signal
    let result = receiver.next_event();
    assert!(matches!(result, Err(EventError::Terminated)));
    assert!(receiver.is_stopped());

    // Subsequent legitimate /stackerdb_chunks POST is never delivered because
    // main_loop would already have broken; forward_event is never reached.
    let (tx, rx) = channel::<SignerEvent<SomeSignerMessageType>>();
    receiver.add_consumer(tx);
    // main_loop() would break immediately here due to is_stopped() == true
    receiver.main_loop();
    assert!(rx.try_recv().is_err(), "no legitimate events should ever be forwarded again");
}
```
This demonstrates that a single, unauthenticated, bodyless POST to `/shutdown` permanently disables the event receiver's `main_loop`, matching the exact fault described: an authentication-gap in the control-plane `/shutdown` branch of `next_event`.

                }
