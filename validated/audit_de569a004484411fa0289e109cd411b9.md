### Title
Call-depth limit (`MAX_DEPTH`) not enforced for CREATE2 when hard-fork `VERSION_4_8_1_1` is inactive - (File: `actuator/src/main/java/org/tron/core/vm/program/Program.java`)

### Summary
Every internal-call opcode in the TVM enforces the `MAX_DEPTH = 64` call-stack depth limit by pushing zero and returning once `getCallDeep() == MAX_DEPTH`, except `createContract2` (the `CREATE2` opcode). Its depth check is gated behind the `allowTvmCompatibleEvm` / `allowTvmOsaka` feature flags; when neither is enabled, the code instead calls `MUtil.checkCPUTimeForCreate2()`, which is not a depth guard but a separate hard-fork activation gate (`VERSION_4_8_1_1`) that no-ops until that fork is activated. In that state, `createContract2` falls through and unconditionally invokes `createContractImpl`, allowing recursive CREATE2 self-calls to exceed the intended 64-frame depth limit — directly mirroring the Tezos "proxy call not respecting depth limit" bug class, where a specific call path failed to enforce the stack-depth check that other call paths correctly enforced.

### Finding Description
`Program.createContract`, `Program.callToAddress`, and `Program.callToPrecompiledAddress` all uniformly stop execution at `MAX_DEPTH` by pushing zero onto the stack and returning [7](#0-6) . `Program.createContract2` instead conditions this early-return on VM configuration flags: [8](#0-7) 
When both `allowTvmCompatibleEvm` and `allowTvmOsaka` are disabled (i.e., the legacy code path, which is the default/pre-upgrade behavior), the `getCallDeep() == MAX_DEPTH` branch calls `MUtil.checkCPUTimeForCreate2()`, which only throws if the unrelated hard fork `VERSION_4_8_1_1` has been activated on the network [5](#0-4) . If that fork is not active, execution silently continues into `createContractImpl`, which recurses into the interpreter for the newly created contract's constructor bytecode — permitting the call depth to exceed 64 without limit, bounded only by available energy/fee, not by the JVM call-stack safety margin that `MAX_DEPTH` was designed to protect.

### Impact Explanation
Uncontrolled recursion depth in a JVM interpreter risks a `StackOverflowError` (an unchecked `Error`, not a catchable `Exception` in the VM's normal exception-handling path), which can crash or halt the node process executing the block — a chain-halting/node-crash condition reachable by any account that can deploy a contract invoking `CREATE2` recursively with sufficient fee/energy budget. This satisfies the "node crash or halt" impact criterion.

### Likelihood Explanation
Reachable from an unprivileged, ordinary contract deployer: any account can deploy a contract that repeatedly self-invokes `CREATE2` and fund the call with enough `feeLimit`/energy to reach a depth safely below what triggers the same protection given to `CREATE`/`CALL`. The precondition (fork `VERSION_4_8_1_1` not yet activated) is a network-wide state that legitimately exists prior to that fork's activation and is exactly what test `testCreate2MaxDepthWithNeitherFlag` demonstrates.

### Recommendation
Make `createContract2`'s depth-limit enforcement unconditional and identical to `createContract`/`callToAddress`/`callToPrecompiledAddress`: push zero and return immediately once `getCallDeep() == MAX_DEPTH`, regardless of `allowTvmCompatibleEvm`/`allowTvmOsaka` flags, instead of relying on the unrelated `checkCPUTimeForCreate2()` fork-gated CPU-timeout mechanism as a stand-in depth guard.

### Proof of Concept
The project's own regression test demonstrates the bypass directly: with `allowTvmCompatibleEvm=0`, `allowTvmOsaka=0`, and `getCallDeep()` mocked to return `64` (`MAX_DEPTH`), calling `program.createContract2(...)` does not short-circuit — it proceeds to record an internal transaction and pushes a non-zero contract address, proving the depth limit was not enforced on this path: [6](#0-5)

    if (VMConfig.allowTvmOsaka()) {
      returnDataBuffer = null; // reset return buffer right before the call
    }

    byte[] senderAddress;

        && getCallDeep() == MAX_DEPTH) {
      stackPushZero();
      return;
    }
    if (getCallDeep() == MAX_DEPTH) {
