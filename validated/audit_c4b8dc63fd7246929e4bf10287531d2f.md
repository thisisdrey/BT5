### Title
Protocol fees bypassed on NEP-245/IMT `TokenDiff` legs by splitting a large negative delta into many unit-size (`|delta| == 1`) intents - ([File: contracts/defuse/core/src/intents/token_diff.rs])

### Summary
`TokenDiff::execute_intent` charges a fee only when `TokenDiff::token_fee` returns a non-zero `Pips` value, and for `Nep245`/`Imt` token types that function explicitly returns `Pips::ZERO` whenever the per-intent `amount <= 1` [1](#0-0) . Because the fee decision is evaluated per individual `TokenDiff` intent rather than per cumulative account movement, an unprivileged signer can split one large negative NEP-245/IMT delta (e.g. `-1000`) into many separate `TokenDiff` intents each with `delta == -1` on the same token, driving `sum(fees_collected)` to `0` instead of `Pips::fee_ceil(fee, 1000)`.

### Finding Description
The binding that should hold is:
`sum(fees_collected across all TokenDiff legs on token T in a batch) == Pips::fee_ceil(fee, total_negative_amount(T))`

In `TokenDiff::execute_intent`, for each `(token_id, delta)` pair with `delta < 0`, the fee is computed as:
```
let amount = delta.unsigned_abs();
let fee = Self::token_fee(token_id, amount, protocol_fee).fee_ceil(amount);
``` [2](#0-1) 

`token_fee` is defined as:
```rust
pub fn token_fee(token_id: impl Into<TokenIdType>, amount: u128, fee: Pips) -> Pips {
    let token_id = token_id.into();
    match token_id {
        TokenIdType::Nep141 => {}
        TokenIdType::Nep245 | TokenIdType::Imt if amount > 1 => {}
        // do not take fees on NFTs and MTs with |delta| <= 1
        TokenIdType::Nep171 | TokenIdType::Nep245 | TokenIdType::Imt => return Pips::ZERO,
    }
    fee
}
``` [1](#0-0) 

For `Nep141` tokens, the fee is always applied regardless of amount. But for `Nep245`/`Imt` tokens, the `amount > 1` guard is evaluated per single `TokenDiff` intent's own `delta`, not against any account- or batch-level aggregate. Nothing in `Engine::execute_signed_intent` or `TransferMatcher`/`Deltas::finalize` aggregates amounts across intents before the fee computation — deltas and fee deposits are only checked for net-zero balancing after the fact [3](#0-2) [4](#0-3) .

Exploit: an attacker holding 1000 units of a NEP-245 token signs 1000 separate `TokenDiff` intents (in one or more `MultiPayload`s under the same `signer_id`, submitted together to `execute_intents`), each with `diff = {token: -1}`, and balances the batch's netting requirement (`TransferMatcher::finalize`) with a matching aggregate `+1000` inflow to the same or another controlled account (e.g., a positive-delta leg, which is never fee'd regardless of size). Each of the 1000 legs computes `token_fee(token_id, 1, fee) == Pips::ZERO`, so `fee_ceil(0-pips, 1) == 0` for every leg, and the batch-wide `fees_collected` total is `0`, whereas a single `TokenDiff` with `delta == -1000` would have produced `fee_ceil(fee, 1000) > 0` for any `fee > 0`.

None of the existing guards (`MultiPayload::verify`, nonce/`VersionedNonce` checks, `SaltRegistry::is_valid`, `TransferMatcher::finalize`) address this because they only validate signature/nonce validity and that token deltas net to zero across the batch — they do not re-aggregate per-token withdrawal amounts for fee purposes.

### Impact Explanation
The `fee_collector` account receives strictly less than the protocol-intended fee for any NEP-245/IMT-denominated outflow, for every trade routed through this contract where the negative-delta leg is on a `Nep245`/`Imt` token. This is repeatable indefinitely (any account, any NEP-245/IMT token, any batch size) at zero marginal cost beyond gas for extra intents/signatures, and directly matches the listed Critical impact category "protocol fees bypassed" since value that should flow to `fee_collector` never leaves the trading legs. The blast radius is every NEP-245/IMT-denominated swap or diff processed by the Verifier.

### Likelihood Explanation
Preconditions are minimal: the attacker needs (a) any positive `mt`/`imt` balance in the Verifier, (b) `fee > 0` configured for the market, and (c) the ability to sign multiple `TokenDiff` intents with the same key (trivial, no privileged role). The only extra cost versus a single legitimate intent is producing/signing `N` intents instead of one and paying incrementally more gas for `N` calls — negligible relative to the fee saved on any nontrivial amount, and fully repeatable across accounts/tokens/batches.

### Recommendation
Compute the fee-exemption threshold (`amount > 1`) against the total negative delta accumulated per `(signer_id, token_id)` across the entire batch/intent set (or apply an intent-count-independent aggregation before fee waiver), rather than per individual `TokenDiff` intent. Alternatively, remove or tighten the NEP-245/IMT fee waiver so it cannot be trivially defeated by amount-splitting (e.g., only waive fees on intents whose token type is NFT-like/`Nep171`, since those inherently always carry `amount == 1` and cannot be split to bypass an intended larger fee).

### Proof of Concept
```rust
// contracts/defuse/core/src/intents/token_diff.rs (new #[test])
#[test]
fn fee_bypass_via_splitting_nep245() {
    let token_id = TokenId::from(Nep245TokenId::new("mt.near".parse().unwrap(), "t1".to_string()));
    let fee = Pips::ONE_PERCENT; // nonzero fee

    // Baseline: single large diff of -1000
    let baseline_fee = TokenDiff::token_fee(&token_id, 1000, fee).fee_ceil(1000);
    assert!(baseline_fee > 0);

    // Split into 1000 legs of -1 each
    let mut split_fee_total: u128 = 0;
    for _ in 0..1000 {
        split_fee_total += TokenDiff::token_fee(&token_id, 1, fee).fee_ceil(1);
    }

    // Binding sum(fees_collected) == Pips::fee_ceil(fee, 1000) is broken:
    assert_eq!(split_fee_total, 0);
    assert_ne!(split_fee_total, baseline_fee);
}
```
For an end-to-end demonstration (recommended as a `near-workspaces`/sandbox integration test alongside `tests/src/tests/defuse/intents/token_diff.rs`): deposit 1000 units of a NEP-245 token to attacker account A, execute one `MultiPayload` with a single `TokenDiff{-1000}` against a matching counter-intent, record `fee_collector` balance delta; reset state, repeat with 1000 separate signed `TokenDiff{-1}` intents (same signer, same nonoverlapping nonces) balanced by an equivalent aggregate positive leg, and compare the resulting `fee_collector` balance delta — it will be `0` versus `fee_ceil(fee, 1000) > 0` in the baseline case.

    fn execute_signed_intent(&mut self, signed: MultiPayload) -> Result<()> {
        // verify signed payload and get public key
        let public_key = signed.verify().ok_or(DefuseError::InvalidSignature)?;

        // calculate intent hash
        let hash = signed.hash();

        // extract NEP-413 payload
        let DefusePayload::<DefuseIntents> {
            signer_id,
            verifying_contract,
            deadline,
            nonce,
            message: intents,
        } = signed.extract_defuse_payload()?;

        // check recipient
        if verifying_contract != *self.state.verifying_contract() {
            return Err(DefuseError::WrongVerifyingContract);
        }

        self.inspector.on_deadline(deadline);

        // make sure message is still valid
        if deadline < Timestamp::now() {
            return Err(DefuseError::DeadlineExpired);
        }

        // make sure the account has this public key
        if !self.state.has_public_key(&signer_id, &public_key) {
            return Err(DefuseError::PublicKeyNotExist(signer_id, public_key));
        }

        // commit nonce
        self.verify_intent_nonce(nonce, deadline)?;
        self.state.commit_nonce(signer_id.clone(), nonce)?;

        intents.execute_intent(&signer_id, self, hash)?;
        self.inspector.on_intent_executed(&signer_id, hash, nonce);

        Ok(())
    }
