### Title
Unauthenticated event-receiver HTTP endpoint accepts forged StackerDBChunksEvent/BlockValidateResponse/BurnBlockEvent/StacksBlockEvent from any TCP peer - (File: libsigner/src/events.rs)

### Summary
`SignerEventReceiver::next_event` dispatches purely on `request.url()` string equality and never checks the requester's peer/source IP or any shared secret before deserializing the POST body into `StackerDBChunksEvent`, `BlockValidateResponse`, `BurnBlockEvent`, or `StacksBlockEvent` and forwarding it as an authentic `SignerEvent` to the signer runloop. The sample/reference signer configuration (`sample/conf/signer/mainnet-signer-conf.toml`) explicitly binds this listener to `0.0.0.0:30000`, so this is not merely a theoretical loopback-only exposure.

### Finding Description
In `libsigner/src/events.rs`, `next_event` (lines 413-459) accepts any TCP connection reaching the bound `HttpServer`, reads the request, and branches solely on `request.url()`: [1](#0-0) 
For `/stackerdb_chunks`, `/proposal_response`, `/new_burn_block`, and `/new_block`, it calls `process_event::<T, E>(request)`, which reads the body, ACKs the sender, and does `serde_json::from_slice` directly into the target event type before `TryInto<SignerEvent<T>>`: [2](#0-1) 
There is no check of the connecting peer's address, no `Authorization`/token header validation, and no TLS/mTLS — `bind()` simply opens `HttpServer::http(listener)` with no allowlist: [3](#0-2) 
The `auth_password`/`auth_token` pairing documented in the signer/node configs is used only for the signer's outbound calls to the node's RPC/block-proposal endpoint, not for validating inbound POSTs to this event-receiver listener — no such check exists anywhere in `libsigner/src/events.rs`.

The equality that should hold — "event accepted by `next_event`" == "event genuinely originated from the paired stacks-node's event dispatcher" — is not enforced in this file at all; it is enforced (if at all) only by network placement/firewalling outside this code. The reference configuration itself (`endpoint = "0.0.0.0:30000"` in `sample/conf/signer/mainnet-signer-conf.toml`) shows this listener is documented to potentially be reachable beyond loopback, contradicting the audit's own precondition that this is "typically loopback by convention" — the shipped example config binds all interfaces.

### Impact Explanation
Any remote TCP peer that can reach the bound port can:
- POST a crafted `/stackerdb_chunks` JSON body matching `StackerDBChunksEvent`'s schema, which after `TryFrom<StackerDBChunksEvent>` becomes a `SignerEvent::MinerMessages` or `SignerEvent::SignerMessages` forwarded to the runloop as if legitimately read from StackerDB.
- POST `/proposal_response`, `/new_burn_block`, or `/new_block` to inject a forged `BlockValidateResponse`, burn-block event, or Stacks block event.

Each of these events is subsequently trusted by the signer's decision/runloop logic as node-authenticated truth (the internal decision logic itself is out of scope for this question, but the *entry point authenticity* is squarely in scope and is broken). This allows unauthenticated, repeatable injection of fabricated node/StackerDB state into the signer process — matching the Critical category ("unauthenticated/unauthorized write to state ... network-wide propagation of forged data").

### Likelihood Explanation
Preconditions: the attacker needs TCP reachability to the signer's event-receiver bind address. This is configuration-dependent, but the shipped `mainnet-signer-conf.toml` example explicitly sets `endpoint = "0.0.0.0:30000"`, and nothing in `libsigner/src/events.rs` enforces a stricter binding or peer check regardless of how the operator configures it. No secret, key, or privileged role is required — cost is a single TCP connection and a crafted JSON POST, and the attack is fully repeatable per message.

### Recommendation
Add transport-layer authentication to `SignerEventReceiver`: e.g., require a shared-secret/HMAC or the existing `auth_password`/`auth_token` value in an `Authorization` header on every inbound POST, verified in `next_event`/`process_event` before deserialization, and/or bind by default to loopback only with an explicit opt-in and warning for non-loopback binds. Reject requests lacking a valid token with 401 before reading/deserializing the body.

### Proof of Concept

1. Construct a `SignerEventReceiver::<SomeT>::new(false)` and call `bind("127.0.0.1:0".parse().unwrap())`, capturing the returned port.
2. Spawn a thread calling `next_event()`.
3. From a plain `std::net::TcpStream::connect` (not going through any node/dispatcher code), send:
   ```
   POST /new_burn_block HTTP/1.1\r\nHost: 127.0.0.1\r\nContent-Length: <n>\r\nContent-Type: application/json\r\nConnection: close\r\n\r\n{"burn_block_hash":"...", "burn_block_height":999999, "consensus_hash":"...", "parent_burn_block_hash":"..."}
   ```
   with fully attacker-chosen field values matching `BurnBlockEvent`'s `Deserialize` schema.
4. Assert the spawned thread's `next_event()` call returns `Ok(SignerEvent::NewBurnBlock { burn_height: 999999, .. })`, proving the attacker-chosen fields were accepted with no peer/identity verification performed by `SignerEventReceiver::next_event` in `libsigner/src/events.rs` lines 413-459.

```rust
fn process_event<T, E>(mut request: HttpRequest) -> Result<SignerEvent<T>, EventError>
where
    T: SignerEventTrait,
    E: serde::de::DeserializeOwned + TryInto<SignerEvent<T>, Error = EventError>,
{
    let mut body = String::new();

    if let Err(e) = request.as_reader().read_to_string(&mut body) {
        error!("Failed to read body: {:?}", &e);
        ack_dispatcher(request);
        return Err(EventError::MalformedRequest(format!(
            "Failed to read body: {:?}",
            e
        )));
    }
    // Regardless of whether we successfully deserialize, we should ack the dispatcher so they don't keep resending it
    ack_dispatcher(request);
    let json_event: E = serde_json::from_slice(body.as_bytes())
        .map_err(|e| EventError::Deserialize(format!("Could not decode body to JSON: {:?}", e)))?;

    let signer_event: SignerEvent<T> = json_event.try_into()?;

    Ok(signer_event)
}
```
